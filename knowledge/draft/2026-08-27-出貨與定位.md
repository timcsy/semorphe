# 出貨與定位——先講 app 還是先講零件

> 日期：2026-08-27
> 怎麼冒出來的：使用者「要如何發佈 demo 版？**我不希望後端負擔太重**。
> 我也有買一個網址 `semorphe.com`，我希望也能弄一個元件庫，像 npm 或 pip 一樣，
> 然後我也希望有教材的分享，然後老師上課也方便使用」
> ＋「我是希望可以**各個組件拆開來用**，也可以有類似 app 這樣的**預組裝組件**，
> 然後會有一個**官方網站，可以有 demo**」
>
> **狀態：設計 ＋ 決定，未升格。**

## 一、今天已經有的（量過）

```
GitHub Pages 部署   .github/workflows/deploy.yml（on push/PR: main）
vite base           '/semorphe/'
SDK                 dist-sdk/semorphe.mjs ＋ .d.mts（build:sdk 已經在建）
可執行的例子         examples/bring-your-own-view/（自帶視圖 ＋ 即時互轉）
package.json        private: true · 沒有 files · 沒有 exports
```

🔴 所以「demo 上線」的成本比想像低：**改 DNS ＋ 改一行 `base`**。
而 `offline` 與 `shipped-assets` 兩支 e2e 會告訴你有沒有弄壞——**這個改動有網子**。

## 二、網域：apex 給誰

使用者提議 `app.semorphe.com` = 靜態站、`semorphe.com` = 有登入的後端。

### 🟢 那個切法有一個很強的理由，而它來自你們自己的護欄

`e2e/offline.spec.ts:61` 逐字：「**這一頁自己的主機。其餘都是外部。**」

```
app 與 api 同一個 origin   → 護欄【看不見】後端相依
app 與 api 不同主機        → 每一次後端呼叫都會變紅
```

> **把後端放在不同的主機上，等於請第四十五條護欄替你盯著
> 「這個工具還是不是離線可用的」。**

### 🔴 而名字那一半與需求打架

需求是「**老師給學生一條網址就可以開始使用**」，
而在那個方案裡，那條網址是 `app.semorphe.com`——**比較長，而且不是買的那一個**。

```
SaaS 慣例   landing 在 apex、app 在 app.   （Notion／Linear／Figma——都是【登入才有東西】）
工具慣例    apex 就是工具                  （scratch.mit.edu · desmos.com/calculator）
```

**Semorphe 屬於後者**：不登入就能用，而那正是賣點。

> **把最短的網址留給還不存在的東西，
> 而把每天要用的那個放進子網域——那是在替一個假設付租金。**

建議的形狀：

```
semorphe.com        靜態 —— 首頁【和】編輯器（同一個部署，首頁不需要後端）
api.semorphe.com    將來的後端（今天【不要】開）
next.semorphe.com   demo／預覽（deploy.yml 已經吃 PR，改成兩個目標）
```

⚠️ 若 apex 要留給商業落地頁，那 app 要用**更短的**（`go.` / `s.`）
——那條連結會被貼在黑板上、被學生用手打。

## 三、三頁，對三種人

```
semorphe.com        「這是什麼」＋【直接可以玩的編輯器】
                     ⚠️ 不要做成落地頁再點「試用」——現在每一個訪客都很貴
/teach               給老師 —— ⚠️【今天還沒有東西可寫】，等第二個老師出現
/dev                 給開發者 —— 🟢【今天就寫得出來】，而且有量測撐著
```

### `/dev` 用數字，不用形容詞

```
❌  「高度模組化的架構」
🟢  視圖之間互相 import：0（有一條護欄在擋）
    82 條護欄 · 5875 支單元測試 · 49 支 e2e
```

> **這個 repo 最不尋常的地方是它會量自己
> ——而那是開發者信得過的唯一一種宣稱。**

🟢 而文案不用寫，`examples/bring-your-own-view/README.md` 第一句就是：
> 「你已經有自己的編輯器（Blockly、節點圖、純文字，都行），只想加上
> 『程式碼 ↔ 語義樹』的即時互轉——**不必用我們的面板，也不必用我們的建置工具。**」

**而它是可執行的**（`node examples/bring-your-own-view/build.mjs`）。

## 四、🔴 先講 app，後講零件——理由是【回饋的種類】

```
先講 app        來的是老師與學生 → 回饋是「小學生看不看得懂」
先講 components 來的是開發者     → 回饋是「我能不能只用抬升器」
```

**後者你答得出來，前者答不出來——而前者才是這個專案賭的東西。**
（而現況是：教材 0 · 用過的學生 0 · 第二個走課的人還沒出現。）

## 五、元件庫：**不要自己做 npm**

npm／pip 十幾年在解的不是「放檔案」，是命名爭議、版本解析、相依地獄、
資安通報、棄置套件、typosquatting。

```
套件名   @someone/semorphe-robot   （npm 的 scope 天生就是你們的 scope 語義）
索引     npm search API → 建置期抓一份 JSON 當目錄
CDN      unpkg / jsdelivr
```

🟢 `concepts/元件.md:138` 已經對上：scope 是套件擁有者，`@someone:boost_vector`。
- [ ] ⚠️ **只差一個決定：`@someone` 是不是就等於 npm 的 scope？**
      是的話，命名爭議整塊由 npm 承擔。

🔴 而離線那條要切一刀：**「安裝」不是「載入」**——抓一次、存進 `.sem`，之後離線可用。
使用者主動安裝與啟動時偷偷抓是兩件事，**而第四十五條今天的判準分不出來**。

## 六、🔴 拆開來賣的成本，不在建它

`package.json` 今天是 `private: true`、沒有 `files`、沒有 `exports`
——**`dist-sdk` 建得出來而沒有發布**。

> **一個 registry 的成本不在建它，在【你從此不能改名字】。**

而這個專案每天都在改名字（同一天內：`edit:blocks` → `edit:tree`、
`flow-panel` 的 viewId 對齊、`SemanticUpdateEvent` 加 `originViewId`）。

⚠️ 而 `dist-sdk/semorphe.d.mts` 今天只有一行 `export * from './types/sdk/index'`
——**SDK 的表面等於「型別目錄裡有什麼就是什麼」，沒有人挑過**。
發版之前必須挑一遍，否則會不小心承諾一堆內部型別。

→ **建議：`/dev` 頁先寫，SDK 先不發版。** 頁上老實寫「API 尚未穩定，
想接請開 issue 聊」——那句話會**篩掉錯的早期使用者，留下願意一起改的**。

## 七、「預組裝」這個詞要換掉

```
「預組裝的 app」   聽起來像「元件的其中一種用法」
                   ——而它其實是【產品】，其餘是【它的零件】
```

Blockly 是零件、MakeCode 是產品，而多數人只知道後者。
**Blockly 撐得住是因為 Google 一直在維護它。**

> **一個「零件 ＋ 產品」的雙軌，要有人維護兩條軌道。而你現在是一個人。**

→ **架構繼續拆**（對品質有好處，護欄在守），
  **而對外先只承諾 app**；零件那一頁寫成「這是我們怎麼做的」，
  不是「這是你可以用的 API」。

## 八、SOTA：其他領域把這件事切成【打包】與【啟動】兩件

`rusticisoftware` / `forasoft` 兩篇一致：

> **內容要能在對方的環境裡跑（就算離線、就算你不在了）→ 打包它（SCORM／cmi5）。
> 它是一個你持續更新、很多機構接進來的活工具 → 啟動它（LTI）。**

LTI 逐字：「does not package or track content; **it launches your externally hosted tool**」。

```
打包   SCORM · Common Cartridge · cmi5 · H5P
啟動   LTI
```

### H5P 幾乎就是「教材帶元件庫」

`.h5p` 是一個 zip，裡面有 `content.json` **以及內容執行所需的 code libraries**
——「教材帶著自己的元件庫」在 H5P 不是提案，是格式的一部分，跑了十幾年。
🟢 `h5p-standalone`：不需要 H5P 伺服器就顯示得出來。
⚠️ 代價：**library 被打進每一個包**，同一個 library 十份副本 → 相依地獄。
**那正是 `元件套件管理` 的「名字 ＋ 版本」要解的。**

### 而 Desmos／GeoGebra 選擇【不讓老師擴充工具】

```
Desmos／GeoGebra   活動 = 組態 ＋ 順序 ＋ 題目     工具【不可擴充】
H5P                內容 = 資料 ＋ 要跑的 library   內容【可以帶程式碼】
```

🔴 「教材搭配自己的擴充元件庫」＝ 選了後者。
**而 Desmos 不跨那條線，是一個被大規模驗證過的選項，值得認真考慮一次再否決。**

### 結論：一份宣告，兩條交付

> **「一條網址」與「離線 ＋ 帶元件庫」在標準界是兩個不同的機制，
> 沒有人用一個機制同時做到。**

```
啟動（連結）   輕量、活的、要網路      → 老師日常給學生
打包（檔案）   自足、離線、可帶元件庫   → 沒網路的教室／要保存的課程
```

🟢 而檔案那一端**已經承諾了**：`vision.md:722`「匯出 zip／匯入解壓；離線可用」。
**教案與元件庫是那個 zip 裡多兩樣東西。**

## 九、建議的順序（後端全程為零）

```
1  semorphe.com 指到靜態站 · vite base 改 '/' · next. 當 demo
2  ?l=<壓縮的宣告> → 「老師給一條網址」成立（輕教案）
3  教案宣告格式定案 —— 欄位要留得下「我帶一個元件庫」與 derivedFrom
4  元件庫 = npm scope ＋「安裝」語義  ⚠️ 第四十五條的判準要先切一刀
5  dist-sdk 發版 —— 晚到詞彙穩定為止
```

🔴 而需要後端的**第一個**理由可能不是「老師看全班進度」，是
**學生的程式換一台電腦就沒了**——見
[教案是一個宣告 §零](2026-08-27-教案是一個宣告.md) 最後一條。
組態跟著連結走（零後端），**而學生自己寫的東西跟不了**。

而「老師看全班進度」是第二個。
它一旦存在，這個專案就從「一個工具」變成「一個服務」
——要備份、要隱私政策、要處理未成年人資料。

> **那不是技術決定，而且它不可逆：有了學生資料之後，
> 你不能再說「我只是一個編輯器」。**

→ **網域先切好（可逆），後端晚一點決定（不可逆）。**
