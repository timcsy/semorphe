## 三、⚠️ 第六種形狀：**產生器依 `style` 的閉包**

`registerStatementGenerators` 裡：

```ts
const openBrace = style.brace_style === 'Allman'
  ? (ctx) => `\n${indent(ctx)}{`
  : () => ' {'
```

**它是捕獲 `style` 的閉包**，`statements.ts` 那 24 顆全部依賴它。
剪出去的膠囊拿不到閉包，只能自己從 `style` 算——所以
`componentGenerateRegistrars()` 的呼叫要**把 `style` 一起傳進去**。

⚠️ **少傳不會紅**：排版差異多數測試不比。症狀是
「膠囊化之後大括號的位置變了」，而沒有任何東西會說話。

## 四、⚠️ 一個 NUL 位元組讓 grep 對整個檔失明

`core/generators/statements.ts:2629` 有一個**字面 NUL**（當複合鍵的分隔字元）：

```ts
const key = `${n.conceptId}\x00${normalizeHeader(...)}`
```

git 因此把整個檔判為 binary，`git grep` 只回「Binary file matches」、
shell `grep` 也不列行。**我因此連續得出三個錯誤結論**
（「`openBrace` 不存在」→「檔案被我寫壞了」→ 差點以為是資料損毀）。

✅ **護欄沒有被蒙蔽**：它們走 Node 的 `readFileSync(..., 'utf8')`，NUL 照樣讀得到
（`tests/helpers/component-scan.ts:269`）。瞎掉的只有 shell 工具。

> **一個位元組可以讓一整個檔案從命令列的世界消失，而測試完全正常。**

處置未定：改成 `\0` 逸出（等價、可 grep）看起來是免費的，
但那一行是**熱路徑上的鍵**，要確認沒有人依賴位元組長度。

## 四之二、⚠️ **`strategies.ts` 那 41 顆不是「分派表的一列」**——估計要修

`specs/104` 的形狀表把 `core/lifters/strategies.ts` 的 41 顆列為
「lift 是共用分派表裡的一列 → 登錄呼叫」，而那個結論來自**一個樣本**
（`cpp:vector_declare`，它確實是 container-template 的一列）。

2026-08-11 打開來看其餘的：

```ts
// cpp:cast 與 cpp:malloc 在**同一個函式**裡
if (…) return createNode('cpp:malloc', …)
return createNode('cpp:cast', …)            ← 同一個 strategy 的兩個出口

// cpp:constructor 與 cpp:destructor 同上
if (nameNode?.type === 'destructor_name') return createNode('cpp:destructor', …)
return createNode('cpp:constructor', …)
```

> **它們是真的手寫辨識邏輯，不是資料。**
> 而且**一個函式產出多個身分**——那不是「剪一段出來」的問題，
> 是**要先把函式拆開**，而拆的判準是語法而不是元件。

→ **第七種形狀：一個 lift 函式產出多個身分。**
  處置未定。最小的做法是讓那個函式留在共用檔、由多顆膠囊「共同擁有」
  ——但那違反就近性護欄（身分不得出現在自己資料夾外）。
  另一條是拆成 `if` 前置判斷 ＋ 各自的 `createNode`，各自登錄。

⚠️ **這一條把 83 顆「可立即批次」的估計打掉一大塊**——
`strategies.ts` 那 25 顆（15 ＋ 10）要先解第七種形狀。

## 十、第十一批**整批回退**——三顆都卡在同一件事的三種面貌

`expressions.ts`／`statements.ts` 裡有三個 AST 型別**只產一顆身分**
（`update_expression`→`increment`、`comma_expression`→`comma_expr`、
`switch_statement`→`switch`），看起來是最單純的「整段搬」。搬完全部紅：

| 顆 | 卡在 |
|---|---|
| `cpp:increment` | 身分還被 `core/storage-version.ts`（**改名表**）與 `statements.ts` 提到 |
| `cpp:comma_expr` | 外洩三處，而且**一個積木都沒有** → 沒有標籤 → 護欄指名「UI 上是空白的」 |
| `cpp:switch` | 它的 lift 裡提到 `cpp:default`（case 標籤族）→ 反向護欄：**膠囊裡混進別顆元件** |

> **「這個 AST 型別只產一顆身分」不等於「這顆元件只被這個 AST 型別提到」。**
> 前者是**產出**的單一性，後者是**引用**的單一性——搬得動要的是後者。

### 這一條把可搬性的判準補完整了

一顆元件搬得動，要同時滿足**四件事**：

1. 它的五路都切得出來（工具的事）
2. 它的 lift 不與別顆共用一個不可分割的函式（**產出**單一）
3. **沒有別的共用檔還提到它的身分**（**引用**單一）
4. 它有積木、因此有標籤（沒有積木的元件搬進膠囊會被判為「UI 空白」）

前三條這一天都踩過；第四條是 `comma_expr` 這次新增的
——**一顆沒有積木的元件，膠囊契約沒有為它設計過位置。**
