## 地基：這一題已經被判過一半

主控台那一刀（[history/202](../history/202-十字退場而主控台回到它本來的位置.md)）
的結論逐字：

> **主控台不是投影，是【執行的輸出】。**

而那一刀的理由是「**不要被餵」是投影的規矩，而執行的輸出是資料流
——它本來就只有一個源頭**。

⟹ 面板至少有兩種，而那個判決已經定案。這一份是把它**填滿**。

---

## 四種，而分界是**驅動源**

| 種類 | 驅動源 | **什麼時候變** | 例子 |
|---|---|---|---|
| **真實的投影** | 語義樹 | 編輯時 | 積木 · 程式碼 · 流程 · **3D 模型** |
| **執行的輸出** | 這一次執行 | 跑的時候 | 主控台 · 變數 · **遊戲畫面** |
| 🔴 **外部的觀測** | **外部世界** | **你什麼都沒做也會變** | 遙測 · 感測器 · **實體機器人** |
| 登錄表的視圖 | 登錄表 | 裝／移除套件時 | 工具箱 · 課程選單 |

### 🔴 第三種是新的，而它的性質沒有一個既有面板有

```
積木面板    你不編輯,它不變
主控台      你不跑,它不變
🔴 遙測面板  你【什麼都不做】,它也在變 —— 因為【世界】變了
```

⟹ 它**繼承了 IoT 那個域填出來的全部**
（見 [元件宣告的契約化](2026-09-22-元件宣告的契約化.md) §十二之⑧）：

```
延遲 · 會斷線 · 🔴 沒有全域時鐘（事件只有偏序）
```

🔴 **而匯流排上要多一種事件**：今天的事件是「編輯了」「跑到第幾步」，
遙測要的是「**外面傳來一筆，而時間戳是它的不是我的**」。

### 第四種早就判過

`concepts/元件.md` 的 E 步記著：**課程清單是登錄表的視圖，不是碎裂**。
工具箱同理。它們顯示的是「**有什麼可用**」，不是「**是什麼**」。

### 🔴 而「驅動源是一個」是錯的——它是**內容 ＋ 疊加**（2026-09-25 下午修正）

上面那張表假設一個面板有**一個**驅動源。流程面板打臉了一半：
它被**語義樹**驅動（第一種），**同時**吃執行事件。積木面板的分步播放也是。

```
內容     被語義樹驅動     編輯時變          ← 它是哪一種,看這個
🔴 疊加   被執行驅動       跑的時候變        ← 它【疊在內容上】,不取代內容
```

```
主控台      內容 100% 來自執行      ⟹ 純第二種
流程面板    內容來自語義樹 ＋ 執行疊加層   ⟹ 第一種,而它有一層
遙測面板    內容來自外部 ＋ ？         ⟹ 第三種,疊加層是什麼還沒想
```

⟹ **分類的鍵是「內容被誰驅動」，而疊加層是正交的一欄。**

> **一個只問「誰驅動它」的分類，會在一個面板同時被兩個東西驅動的時候
> 把它塞進其中一格——而塞進哪一格會變成品味問題。**

## 逐一看四個情境

### ① 3D 面板 —— 🟢 它是投影，幾乎免費

```
語義樹 ──render──▶ 積木       形態軸：role ／ container_kind
       ──render──▶ 🟢 3D 模型  形態軸：LOD ／ 用途 ／ 表現法
```

**和積木同一個機制**（`render` 那一路）。

⚠️ 而它會踩到一個已知的債：**3D 的形態軸要笛卡兒積**
（`detailed × 列印` 是 watertight、`detailed × 顯示` 是低面數——
**兩個真的不同的網格**），而 `selectForm` 今天**取一個**。
那條債寫在 `src/core/projection/form-selection.ts` 的註解裡。

### ② 遊戲面板 —— 🟡 是執行輸出，而它逼出兩件新的

```
🔴 ① 輸出是【影格流】不是文字流
     主控台是 append-only 的文字;遊戲是每秒 60 次整張重畫
🔴 ② 輸入是【事件驅動】不是行導向
     主控台的 stdin 是「讀一行,阻塞」;遊戲要鍵盤／滑鼠事件回灌
```

🟢 **而逐步播放在這裡反而是賣點**：一格一格走**遊戲迴圈**，
看每一幀裡變數怎麼變——那是教遊戲程式最好的畫面，**而那個機制本來就有**。

⚠️ 真正的難點不是面板，是**執行器**：要跑得夠快，而且要有「一幀」這個概念。

### ③ 機器人面板 —— 🔴 它跨過一條線，而那條線是這一題最重要的東西

```
模擬的機器人   執行輸出          🟡 與遊戲同一格
🔴 實體的機器人 外部的觀測        而如果面板【能按】,它就變成【控制】
```

**而控制是不可逆的**（[契約化](2026-09-22-元件宣告的契約化.md) §十二之⑨）：

> **L1 的價值前提是「違反了還能重來」。**

⟹ **一個能寫回實體的面板，需要別的面板都不需要的東西**：

```
🔴 解除／鎖定（arm ／ disarm）   預設是鎖的
🔴 死人開關                     放開就停
🔴 界限                         行程／力矩上限,而且它是一條【契約】
🔴 而契約的 severity: irreversible 要讓【面板】知道,不只是讓驗證知道
```

🟢 **而這是契約框架第一次有一個【使用者看得見】的消費者**
——`severity` 不是一個給驗證用的欄位，**它決定那顆按鈕長什麼樣**。

> **我們一整天在設計的契約，第一個看得見的消費者可能不是診斷，
> 是一顆按鈕能不能按。**

### ④ 🔴 流程面板 —— 它是唯一已經畫出邊的那一個，而邊上什麼都沒流

（2026-09-25 使用者提的情境：「拿來展示機器學習的**學習過程**」，
而他接著說「我認為這是很適合用**流程面板**來看的情境」。查了產品之後——
不是「適合」，是**只有它做得到**。）

#### 已經有的，比想像的多

`src/core/flow/node-graph.ts` 已經有埠與線，而且是**導出**的不是另宣告的：

```ts
export interface GraphPort { kind: 'exec' | 'data'; side: 'in' | 'out'; … }
export interface GraphWire { from, to, kind }
```

⚠️ 所以 [組裝](../concepts/組裝.md) 那句「`ports` 0 / 349、邊 0 顆」要加一句限定：
**宣告上是 0，而投影上早就有了。**而那個方向是對的（導出不要並存）——
`exec` 與 `data` 的分界來自膠囊的 `slots` 宣告，視圖不判斷。

#### 🔴 而缺口有逐字的位置，是兩行

`src/ui/panels/flow-panel.ts`：

```ts
onExecutionState(_event: ExecutionStateEvent): void {}              // :978  空的
onExecutionAtNode(event): void { this.highlighted = event.nodeId }  // :984  只點亮節點
```

> **線就在那裡，執行事件也已經送到面板了，而它只拿來點亮一顆節點。**

⟹ [元件](../concepts/元件.md) 說行為投影的宿主今天只有元件——**那句話有一個逐字的位置，就是這兩行。**

#### 🔴 而 ML 是第一個真的打破那個豁免的域

`concepts/連接.md` 對「用組合編碼資訊流」給過一個豁免，條件寫得很清楚：

> **運算式樹是 DAG 在「無共享」時的無損編碼。**
> 它變成真問題只在兩種情況：同一子運算式要餵兩處，或跨元件接線。

**ResNet 的 skip connection 就是第一種。**同一個張量餵進下一層、又跳過去餵進後面
——樹編不了，只能複製一份，而那就是降級。

```
積木面板   巢狀,邊是【相鄰關係】    ❌ 畫不出 skip
流程面板   邊是【有端點的線】       🟢 畫得出,而且值可以畫在線上
```

**這是流程面板第一次有一個積木面板結構上做不到的情境。**
之前它是「另一種看法」，在這裡它是**唯一的看法**。

#### 🔴 三個尺度，而流程面板在第一格——它沒有畫錯

（使用者問：「可是這裡的連接就變成**組合**之間而不是元件**組裝**之間，如何處理？」）

先查證：`core/flow/node-graph.ts` 的線只有三個來源，**沒有第四種**：

```
:273   前一句 → 下一句          兄弟      exec
:278   分支／迴圈 → 身體第一句   父子      exec
:287   子運算式 → 父的插槽       父子      data
```

⟹ **今天的線 100% 是樹關係。**而它**沒有錯**，因為根公理就是這樣說的：

```
檔案內   樹      組合就夠了              🟢 流程面板在這一格
檔案間   圖      要真的資訊邊             ❌ 沒有
系統間   超圖    組裝（DRC · 預算 · 全網） ❌ 沒有
```

**流程面板不是把組裝畫成組合，它是在一個本來就是樹的範圍裡工作。**
缺口不在它的邊語義，在**另外兩個尺度上什麼都沒有**。

#### 🔴 而缺口的真正位置是第三軸：直接 vs 導出

「檔案內是樹」有一個例外——**共享**，而 C++ 用**名字**表達它：

```cpp
auto x = layer1(input);
auto y = layer2(x);
auto z = x + y;        // ← skip connection：x 餵了兩處
```

樹還是樹（`x` 的兩次使用是兩片獨立的葉子），而**資訊邊藏在名字裡**。

```
一份檔案   語義樹是【樹】     ← 真實,lift 直接產出 —— 流程面板今天投這個
          資料流是【DAG】    ← 同一份真實的【導出】視圖 —— ML 要這個
```

**兩個都是同一份真實的投影**，一個直接一個算的——「唯一真實，各式投影」逐字成立。

🟢 **而算它的那支模組，流程面板已經匯入了**：

```ts
// flow-panel.ts:38
import { isRenamingADefinition, renameReferences, scopeOf } from '../../core/rename-variable'
// :848-849   而它只用在【改名】
```

> **「定義→使用」那條邊今天已經在被計算，只是算完拿去改名字，沒有拿去畫線。**

⟹ 第一條真正的資訊邊，成本不是「新增一條真實的軸」，是**把已經算得出來的東西畫出來**。

🟢 **而它有一個免費的驗收眼測**：

```
今天      每個輸出接點【恰好一條線】出去   —— 樹的定義
🔴 之後   一個輸出接點【兩條線】出去       —— fan-out,skip connection 長這樣
```

**畫面上出現分岔，就代表它不再是樹的投影了。**

⚠️ 順帶：那一問的第二半（「不同粒度關注不同連接形態」）**一半是錯的**，
而更正記在 [連接](../concepts/連接.md)——粒度換的是**結構**，不是**關係**，
而那是「結構⊥關係」一年內第二次想塌回去。

#### 三個缺口，而只有兩個是真的新

```
🟡 線上顯示這一次流過的值     事件已經在面板手上了 ⟹ 接起來就有
🔴 聚合的觀察單位            今天一次一步;loss 曲線要的是【全部步驟】
🔴 張量的形態                `x: 0→1` 畫得出來,一塊 128×128 畫不出來 —— 要熱圖
   反向傳播的線              🟢 不算新的 —— 伴隨圖是前向圖的函數,【算的】
```

⚠️ **反向邊不要宣告**。手接反向邊就是第 N 次雙重真相，症狀照舊：
**兩張圖安靜地說了兩句不同的話。**這條與 `requires`／`abstractComponent`／
`evidence` 同一條紀律——算得出來的不要宣告。

🔴 **而「聚合的觀察單位」不是 ML 特例，四個不相干的域都在要同一件事：**

```
ML     loss 曲線        Σ over steps
C++    效能             Σ 指令數
熱流   暫態 C·dT/dt     ∫ over time
硬體   功耗             ∫ I dt
```

> **今天的行為投影把「觀察的單位」綁死在一步上。**

⚠️ 而這與 [契約](../concepts/契約.md) 的超性質那一格是**同一個形狀的兩面**：
那裡說「取樣對超性質不是證據」，這裡說「一步對趨勢不是觀察」。
**兩邊的根都是「單次／單步裡沒有那個東西」。**

#### 而契約在這個情境只有一半

```
建圖    🟢 契約很強    張量形狀相容 —— 依值型別的主場,cella 有主場
訓練    🔴 沒有契約    「收斂了」不是布林謂詞,而且沒有判定者
```

⟹ 這個情境是對**形態／行為**那兩族的壓力，**不是**對契約的。
（而那是好消息：它不必等契約做完。）

## 🔴 後端與面板是**正交**的

與 ROS 那個「結構 × 關係正交」同一個形狀：

```
同一個後端 → 餵多個面板     實體板子 → 主控台（序列埠）＋ 遙測圖表
同一個面板 ← 由不同後端餵    主控台 ← 直譯器的輸出  或  實體板子的序列埠
```

⟹ **不要把面板綁在後端上。** 中間要有一條匯流排——
**而我們已經有了**（`SemanticBus` ／ `ViewHost`，Phase 0 解耦那一刀）。

```
執行器後端   直譯器 · g++ · 硬體模擬 · 實體板子 · debugger ·（cella）
     ↓ 事件
   匯流排
     ↓
面板        主控台 · 變數 · 遊戲畫面 · 遙測 · 3D
```

## 剪枝力：什麼**不是**面板

```
❌ 設定對話框    它不顯示任何一種真實,它【改】宣告
🟡 錯誤清單      邊緣 —— 它是【診斷】的投影,而診斷掛在語義樹上 ⟹ 算第一種
🟢 工具箱       是,而它是第四種 —— 這個早就判過
```

> **一個面板要說得出「我被什麼驅動、我什麼時候變」。
> 說不出的，它是控制項不是面板。**

### 🔴 而剪枝力有第二條，它問的是【動作】不是【內容】（2026-09-25）

上面那條問「我被什麼驅動」——那是**內容**那一軸。
而兩個都被語義樹驅動的視圖（積木 · 流程 · 程式碼）靠它分不開，
因為它們的內容**是同一棵樹**。

```
積木   原子動作 = 把一顆元件放進一個槽     ⟹ 蘊含「恰好一個父」＝ 組合律
流程   原子動作 = 從一個接點拉一條線       ⟹ 沒有那個限制
程式碼 原子動作 = 打字                    ⟹ 什麼都不蘊含（所以要 parse 回來）
```

> **一個視圖的第一等公民，是它的【編輯動作】操作的東西，
> 不是它畫面上最大的東西。**

🟢 **這條有剪枝力**：拿它去問「這是不是一個新視圖」，
答案就從品味變成可檢驗的——**它的原子動作跟現有的不一樣嗎？**

```
「深色主題的積木面板」    動作一樣 ⟹ 不是新視圖,是主題
「唯讀的流程面板」        沒有動作 ⟹ 🟡 邊緣（它是一個模式）
「接線圖」               動作 = 拉線 ⟹ 🔴 與流程面板【同一個】—— 不要開第二個
```

⚠️ 而它順帶量出兩件：**組合律是積木拖放動作的直接具現**（不是渲染的性質），
以及**今天流程面板的拉線被真實擋回組合**——兩件都記在
[concepts/連接](../concepts/連接.md)。

## 代價不平均

```
🟢 3D 面板    便宜 —— 它是 render 那一路,機制都在（而形態軸要補笛卡兒積）
🟡 遊戲面板    中等 —— 面板容易,【執行器】要有影格與事件輸入
🔴 機器人面板  貴 —— 不是因為畫面,是因為它跨過【不可逆】那條線
🟡 流程面板    分三段 —— 線上的值【便宜】（事件已經在手上）;
              聚合的觀察單位【中等】(要一個新的事件形狀);張量的形態【另一族】
```

## 尚未表態的

- **遙測事件要不要進語義匯流排**，還是走一條獨立的通道。
  進去的話，匯流排上就有了「不是使用者造成的事件」，而那會影響復原（undo）的語義。
- **「外部觀測」算不算投影**。它不是語義樹的投影，而它是**某個外部真實**的投影
  ——那讓「投影」這個詞有兩個賓語，可能該分開命名。
- **控制面板的安全閘要不要是契約的投影**，還是純 UI 的東西。
  前者比較一致（severity 驅動 UI），而它讓 UI 依賴契約框架——今天採用率是 0。
