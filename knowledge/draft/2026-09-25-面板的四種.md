# 面板的四種（而分界是驅動源）

> 日期：2026-09-25
> 怎麼冒出來的：使用者問「如果今天是遊戲的話有辦法有『遊戲面板』嗎？
> 還有像是『3D 面板』『機器人面板』等等的情境面板，甚至還要對接到
> 外面的執行器或是實體」。
>
> 🟡 **狀態：未承諾的設計庫存。** 不寫完成條件。
> ⚠️ 而它**該蒸餾進 `concepts/`**（面板的分類是一個本體論上的東西，
> 不是一次改動），而蒸餾要人拍板——本檔先放著。

---

## 地基：這一題已經被判過一半

主控台那一刀（[history/202](../history/202-十字退場而主控台回到它本來的位置.md)）
的結論逐字：

> **主控台不是投影，是【執行的輸出】。**

而那一刀的理由是「**不要被餵」是投影的規矩，而執行的輸出是資料流
——它本來就只有一個源頭**。

⟹ 面板至少有兩種，而那個判決已經定案。這一份是把它**填滿**。

---

## 四種，而分界是**驅動源**

| 種類 | 驅動源 | **什麼時候變** | 例子 |
|---|---|---|---|
| **真實的投影** | 語義樹 | 編輯時 | 積木 · 程式碼 · 流程 · **3D 模型** |
| **執行的輸出** | 這一次執行 | 跑的時候 | 主控台 · 變數 · **遊戲畫面** |
| 🔴 **外部的觀測** | **外部世界** | **你什麼都沒做也會變** | 遙測 · 感測器 · **實體機器人** |
| 登錄表的視圖 | 登錄表 | 裝／移除套件時 | 工具箱 · 課程選單 |

### 🔴 第三種是新的，而它的性質沒有一個既有面板有

```
積木面板    你不編輯,它不變
主控台      你不跑,它不變
🔴 遙測面板  你【什麼都不做】,它也在變 —— 因為【世界】變了
```

⟹ 它**繼承了 IoT 那個域填出來的全部**
（見 [元件宣告的契約化](2026-09-22-元件宣告的契約化.md) §十二之⑧）：

```
延遲 · 會斷線 · 🔴 沒有全域時鐘（事件只有偏序）
```

🔴 **而匯流排上要多一種事件**：今天的事件是「編輯了」「跑到第幾步」，
遙測要的是「**外面傳來一筆，而時間戳是它的不是我的**」。

### 第四種早就判過

`concepts/元件.md` 的 E 步記著：**課程清單是登錄表的視圖，不是碎裂**。
工具箱同理。它們顯示的是「**有什麼可用**」，不是「**是什麼**」。

## 逐一看三個情境

### ① 3D 面板 —— 🟢 它是投影，幾乎免費

```
語義樹 ──render──▶ 積木       形態軸：role ／ container_kind
       ──render──▶ 🟢 3D 模型  形態軸：LOD ／ 用途 ／ 表現法
```

**和積木同一個機制**（`render` 那一路）。

⚠️ 而它會踩到一個已知的債：**3D 的形態軸要笛卡兒積**
（`detailed × 列印` 是 watertight、`detailed × 顯示` 是低面數——
**兩個真的不同的網格**），而 `selectForm` 今天**取一個**。
那條債寫在 `src/core/projection/form-selection.ts` 的註解裡。

### ② 遊戲面板 —— 🟡 是執行輸出，而它逼出兩件新的

```
🔴 ① 輸出是【影格流】不是文字流
     主控台是 append-only 的文字;遊戲是每秒 60 次整張重畫
🔴 ② 輸入是【事件驅動】不是行導向
     主控台的 stdin 是「讀一行,阻塞」;遊戲要鍵盤／滑鼠事件回灌
```

🟢 **而逐步播放在這裡反而是賣點**：一格一格走**遊戲迴圈**，
看每一幀裡變數怎麼變——那是教遊戲程式最好的畫面，**而那個機制本來就有**。

⚠️ 真正的難點不是面板，是**執行器**：要跑得夠快，而且要有「一幀」這個概念。

### ③ 機器人面板 —— 🔴 它跨過一條線，而那條線是這一題最重要的東西

```
模擬的機器人   執行輸出          🟡 與遊戲同一格
🔴 實體的機器人 外部的觀測        而如果面板【能按】,它就變成【控制】
```

**而控制是不可逆的**（[契約化](2026-09-22-元件宣告的契約化.md) §十二之⑨）：

> **L1 的價值前提是「違反了還能重來」。**

⟹ **一個能寫回實體的面板，需要別的面板都不需要的東西**：

```
🔴 解除／鎖定（arm ／ disarm）   預設是鎖的
🔴 死人開關                     放開就停
🔴 界限                         行程／力矩上限,而且它是一條【契約】
🔴 而契約的 severity: irreversible 要讓【面板】知道,不只是讓驗證知道
```

🟢 **而這是契約框架第一次有一個【使用者看得見】的消費者**
——`severity` 不是一個給驗證用的欄位，**它決定那顆按鈕長什麼樣**。

> **我們一整天在設計的契約，第一個看得見的消費者可能不是診斷，
> 是一顆按鈕能不能按。**

## 🔴 後端與面板是**正交**的

與 ROS 那個「結構 × 關係正交」同一個形狀：

```
同一個後端 → 餵多個面板     實體板子 → 主控台（序列埠）＋ 遙測圖表
同一個面板 ← 由不同後端餵    主控台 ← 直譯器的輸出  或  實體板子的序列埠
```

⟹ **不要把面板綁在後端上。** 中間要有一條匯流排——
**而我們已經有了**（`SemanticBus` ／ `ViewHost`，Phase 0 解耦那一刀）。

```
執行器後端   直譯器 · g++ · 硬體模擬 · 實體板子 · debugger ·（cella）
     ↓ 事件
   匯流排
     ↓
面板        主控台 · 變數 · 遊戲畫面 · 遙測 · 3D
```

## 剪枝力：什麼**不是**面板

```
❌ 設定對話框    它不顯示任何一種真實,它【改】宣告
🟡 錯誤清單      邊緣 —— 它是【診斷】的投影,而診斷掛在語義樹上 ⟹ 算第一種
🟢 工具箱       是,而它是第四種 —— 這個早就判過
```

> **一個面板要說得出「我被什麼驅動、我什麼時候變」。
> 說不出的，它是控制項不是面板。**

---

## 代價不平均

```
🟢 3D 面板    便宜 —— 它是 render 那一路,機制都在（而形態軸要補笛卡兒積）
🟡 遊戲面板    中等 —— 面板容易,【執行器】要有影格與事件輸入
🔴 機器人面板  貴 —— 不是因為畫面,是因為它跨過【不可逆】那條線
```

---

## 尚未表態的

- **遙測事件要不要進語義匯流排**，還是走一條獨立的通道。
  進去的話，匯流排上就有了「不是使用者造成的事件」，而那會影響復原（undo）的語義。
- **「外部觀測」算不算投影**。它不是語義樹的投影，而它是**某個外部真實**的投影
  ——那讓「投影」這個詞有兩個賓語，可能該分開命名。
- **控制面板的安全閘要不要是契約的投影**，還是純 UI 的東西。
  前者比較一致（severity 驅動 UI），而它讓 UI 依賴契約框架——今天採用率是 0。
