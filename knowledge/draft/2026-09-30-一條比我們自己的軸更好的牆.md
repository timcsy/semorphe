# 一條比我們自己的軸更好的牆——而它還沒蓋到 ε 住哪裡

> 日期：2026-09-30
> 怎麼冒出來的：與姊妹專案 cella 一輪五封的跨 session 交換。他們的使用者把
> 「凡是形式化驗證相關都放 Cella」定成原則，而那條原則逼出了一個**比我們自己
> 的軸更高階的分界**。
>
> 🟡 **狀態：外部輸入已收，張力已記，未決。** 本檔記的是**那個張力**與
> **我們推導出來的三個對照組**，不是一次改動的決議。
> ⚠️ 照本庫的體例不寫完成條件。

---

## 一、那條牆，以及它為什麼比我們的軸好

我們在 [元件宣告的契約化](2026-09-22-元件宣告的契約化.md) §八定的軸是：

> **局部／全域決定的是【誰宣告它】，不決定【誰判它】。
> 真正的軸是：數得出來 → cella；算得出來 → 求解器。**

cella 那側（他們的 history 187，2026-09-30）把牆從「領域」改成：

```
牆內   從前提推得出的主張,不分領域    應力、電路、誤差界的傳播都算
牆外   前提本身符不符合世界          材料、量測、元件的 ε
跨牆   量測讀數以【帶來源、帶日期、會過期的假設】進去
       —— Cella 驗的是「給定這些量測,結論成立」
```

🔴 **而它吃得下我們的軸。** 我們問的是「**哪一種機器**」（數 vs 算），
他們問的是「**哪一種主張**」（演繹 vs 經驗）。後者高一層，而「數得出來／
算得出來」退位成**牆內的子分別**——那正好對上我們自己已經說過的一句：
求解器搬進 Cella 之後，那條軸從跨專案的邊界變成 Cella 內部的邊界，它還在。

**而它做到一件我們沒做到的事。** 我們的 §九把「誤差／漂移」拆成三層：

```
① 教學層    元件宣告誤差特性 → 漸進揭露        🟢 今天做得起,有消費者
② 界的傳播   ε ＋ 增益 → 組合算得出總界        🟡 要引擎
③ 對答案    與實體量測,而讀數【會過期】        🔴 硬體進來才有意義
```

在我們的框架裡那是**三個特例**。在那條牆底下它是**同一條線切在三個位置**：
① 連牆都不在 · ② 演繹，牆內 · ③ 經驗，牆外，跨牆進來當假設。

> **一個抽象賺得起位置的證據，是它把你原本列成特例的那幾格變成同一件事的三個切面。**

## 二、🔴 而那條牆還沒蓋到一件事：ε 住哪裡

`ε` 的宣告**有兩個消費者，而其中一個完全在那個框架之外**：

```
② 界的傳播      演繹 → 牆內 → 驗證器讀它
① 漸進揭露      🔴 不是驗證,連牆都不在 —— 課文讀它,給學生看
```

⟹ **那個欄位的家是元件膠囊，不是驗證器。** 驗證器以「跨牆假設」的身分讀它
——完全符合那條牆的規則，而**「跨牆」講的是它怎麼進去，沒有講它住哪裡**。

住哪裡有後果：`ε` 若被當成驗證器的輸入格式來定義，第一個消費者（課文）
就得去讀一個驗證器的資料結構，而它只想知道「`delay(1000)` 不是剛好一秒」。

而 §九選 ① 當第一步的理由逐字是「**它過得了規則②**」——有消費者。
區間引擎今天沒有消費者。

## 三、硬體族的第一組義務：三個對照組

這一節是從 [連接](../concepts/連接.md) 的 `shared` 律推出來的**最小具體例子**，
給的時候是回答「克希荷夫的義務長什麼樣」。三顆元件：理想電壓源 `V1`，
電阻 `R1`、`R2` 並聯。

```
        ┌──── R1 ────┐
V1.+ ───┤            ├─── V1.−
        └──── R2 ────┘

net N1 = { V1.+, R1.a, R2.a }        net N2 = { V1.−, R1.b, R2.b }
```

接點律（`shared`）給的，每個 net 兩條：

```
across 相等   N1: v(V1.+) = v(R1.a) = v(R2.a) ≜ u₁      N2: … ≜ u₂
through 歸零  N1: i(V1.+) + i(R1.a) + i(R2.a) = 0       N2: …
```

元件自己的本構關係（來自元件宣告，**不是**接點律）：

```
V1:  u₁ − u₂ = E           i(V1.+) + i(V1.−) = 0
R1:  u₁ − u₂ = R₁·i(R1.a)   i(R1.a) + i(R1.b) = 0
R2:  u₁ − u₂ = R₂·i(R2.a)   i(R2.a) + i(R2.b) = 0
```

全部是**有理數上的線性方程**——精確的高斯消去做得完，不需要 SMT。

### 🔴 而它少一條，而那一條是新資訊

克希荷夫只定得出**電位差**，所以上面那組的係數矩陣是**奇異的**：
解存在而**不唯一**（整組電位可以一起平移）。要補一條參考點：

```
u₂ = 0        ← 接地。這條不是律給的,是【使用者要放一顆地】
```

⚠️ **而「欠定」與「無解」在判決上是兩件事，不可以長得一樣**：

| 例子 | 方程的狀態 | 判決該說什麼 |
|---|---|---|
| 缺接地 | 係數矩陣奇異 | **欠定**——不是違反 |
| `V1 ‖ V2`，`E₁ ≠ E₂` | 不一致 | **Reject**（最小負向對照） |
| 物理模型下同一個並聯 | 有解而電流爆掉 | **帶界的 Accept**——超出額定 |

第三列的出處是 [連接](../concepts/連接.md) 那張表：`shared` 在物理模型下
**永遠可滿足**（短路也有解，只是電流很大），違反長成「解出來的值比額定」；
在理想化模型下才是「方程不一致，無解」。

⟹ **憑證要說得出「在什麼模型、什麼額定底下」**，否則後兩列在判決上分不開。

🟢 這三例已經被 cella 收成他們路線圖的第一組正負對照（他們的 history 188 那一輪，
前置是一個吐憑證的有理數線性方程判定程序，尚未開工）。

## 四、⚠️ 而「會過期」他們還缺一半

他們的新規則要求跨牆的假設**帶來源、帶日期**，而假設沿依賴傳染、看得見。

而我們 §九量過的形狀多一件事：

```
對照圖帶 engineHash → 引擎變了就紅
誤差界同一套        → 模型變了、元件版本變了、或超過 N 天沒對過 ⟹ 界過期
```

> **一份過期的誤差界，讀起來與一份有效的完全一樣。**

⟹ **「帶日期」不夠，要有東西會紅。** 一個帶著三個月前日期的假設，
在傳染鏈上長得跟今天的一模一樣。

## 五、未決的是什麼

```
🟡 上層那條軸要不要換成「演繹／經驗」      比加一個子欄位大得多,要走設計流程
🟡 §八那張分工表的 judge 欄位要不要加子欄位  「判定程序的種類」
   （對方那側對應到 solver 假設裡的 backend 欄位）
```

⚠️ **而「先不動」是拍過板的**（使用者，2026-09-30）：那張表的 `judge` 欄位
存在的理由是讓「有幾條不變量沒有判官」成為一個數得出來的數字，
而把兩格都寫成同一個名字會讓那個數字**失去解析度**。
