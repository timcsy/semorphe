# 待確認的教訓（2026-10-20～10-31）

> 日期：2026-10-31
> 怎麼冒出來的：knowie-judge 量到這三件事只存在於對話、draft 或 memory，沒有反流進 `experience.md`。
> 🟡 **狀態：起草，等使用者點頭才寫進 experience**（captured ≠ committed）。

## 一、沒討論就以專案名義推薦

- **情境**：2026-10-20 使用者定「semorphe 的 generate 要改名，新名字由 semorphe 提」。我整理了四個候選，**附上「推薦 unparse」就送給 cella**。
- **錯在哪**：「由 semorphe 提」是「由使用者與我討論後提」，不是「由我提」。使用者：「等等，改名的部分你還沒跟我討論」。撤回後，使用者自己提出的「所有東西都是 render 與 lift」比四個候選都好。
- **教訓**：**替專案對外表態之前，先問「這是不是使用者還沒看過的判斷」**——候選表可以先寫，但「推薦」兩個字要等使用者。
- **怎麼用**：跨專案訊息裡出現「我們推薦」「semorphe 的立場」時，先確認那個立場有使用者的話撐著；沒有就寫成「我這側整理的、使用者未看過」。

## 二、轉告會失真，而失真的方向是「把願景講成決定」

- **情境**：2026-10-31 第 15 題，使用者補一句「以後官網改用 Cella 語言寫，順便驗收他在 Web Component 這領域的效果」。我轉告成「官網改用 Cella 語言寫」；cella 那側也一度理解成「用 Cella 寫應用」。實際是：**Web Component 是 Cella 深嵌入的一個新領域**，官網照舊用現有框架。
- **教訓**：**轉告使用者的話時，原話附上，詮釋另起一行標「我的理解」**——兩個 session 各自詮釋一次，誤差會疊加。
- **怎麼用**：跨 session 轉告決定時，第一行放逐字引文。

## 三、別人要照我們的回答去設計時，照理想計劃答

- **情境**：2026-10-06 cella 問「現在怎麼把迴圈和變數翻成 Cella」，我差點照現況答（走訪器只認兩種形狀）。使用者：「我們是不是其實還沒實作很多，所以你應該照**理想的計劃**來回應」。
- **教訓**：**回答的用途決定回答的基準**——對方要拿去設計的，答理想計劃並標出現況與未決；對方要拿去除錯的，才答現況。
- **怎麼用**：今天只存在於 memory（`feedback_design_source_is_draft_not_code`）；進 experience 之後 memory 只留指標。

## 四、🔴 護欄驗的是一條產品不走的路（同一天五次）

- **情境**：2026-10-31 大掃除，盤點「產品走不到、只有測試在用」的模組，一天量到五個實例：
  - `field-write`：helper 產品 08-26 起零呼叫，兩支注入只在測它自己；
  - `cpp/module.ts`：三筆非元件宣告只在這裡，產品從不載入，護欄看到的世界與產品不同；
  - `identity`：護欄驗嚴格的 `isValidComponentId`，產品的門只問 `includes(':')`；
  - `ComponentRegistry`：抽象元件的測試驗的是它，產品用的是 `abstractComponentOf`；
  - `TemplateGenerator`：五支測試把它塞進 ctx 產碼，`judges` 裡 generate 判定者有 87 顆的「覆蓋」靠它——全是假的。
- **教訓**：**綠燈只證明「被測的那份程式碼」是對的；要先問它是不是產品執行的那一份**。
- **怎麼用**：寫或審一支測試時，看它 import 的東西產品走不走得到；走不到的，要嘛改驗產品那一份，要嘛刪。
- **推薦（要人定）**：立一條護欄——`tests/` import 的 `src/` 模組必須是產品入口可達的（白名單只放刻意的護欄工具，如命名詞彙表）。
  量測方法已經有了（TS compiler API ＋ 展開 `import.meta.glob`，見 `memory/project_dead_exports`）。

## 五、第二份真相會蓋住缺陷

- **情境**：google 風格（`namespace_style: explicit`）在產碼端從沒實作，課文 86 份 C++ 解答 70 份編不過——而沒人發現，
  因為第二套產碼路徑的模板寫死了 `std::`。拆掉模板的那一刀，缺陷才現形（第 384 → 386 刀）。
- **教訓**：**兩份實作並存時，測試走哪一份，缺陷就藏在另一份**；而「兩份都有人測」常常是錯覺。
- **怎麼用**：拆第二份真相之前，先列「它替誰蓋住了什麼」——用產品路徑把那份覆蓋重量一次。
