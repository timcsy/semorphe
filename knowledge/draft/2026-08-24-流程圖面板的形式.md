## 一、SOTA 的樣子（2026-08-24 查證）

### 🔴 這個領域有【兩套互不相容的視覺語言】

| | 教育流程圖傳統 | 現代節點編輯器 |
|---|---|---|
| 代表 | RAPTOR · Flowgorithm | React Flow · n8n · Blender · ComfyUI · Node-RED |
| 判斷 | **菱形** | 圓角矩形 ＋ 兩個 port |
| I/O | **平行四邊形** | 同上，靠顏色／圖示分 |
| 目的 | 讓學生學會**那套符號** | 讓人看懂**資料流** |

RAPTOR 的定位逐字：「help students visualize their algorithms and
**avoid syntactic baggage**」。而現代節點 UI 的慣例是形狀集合小、**靠顏色與 port**。

### 佈局：產生型工具偏自動，而研究說「別讓邊交叉」

- `code2flow` 首頁逐字打的是「**No more messy drag & drop editing**」
  ＋「generate optimal, beautiful and readable diagrams automatically」。
- React Flow 的 layouting 指南把選擇收斂成三個引擎：**dagre 是 drop-in、適合樹狀**；
  **ELK 最可配置也最複雜**（dagre 已停維護、ELK 接手）。
- 讀圖研究：使用者最在意**減少邊交叉**（其次才是彎折、對稱）；
  **正交佈局**被點名特別適合流程圖這類「要一眼追得到路徑」的圖。

### 導覽三件套幾乎是不成文標準

**MiniMap · Controls（縮放 ＋ fit view）· Background（格線）**——React Flow 內建。
互動基本盤：節點可拖、畫布可縮放平移、標籤配 tooltip；節點多時走
**progressive disclosure**（縮放／過濾／聚類的 detail-on-demand ＋ smart truncation）。

### 🟢 兩格 SOTA 反而弱——而它們正好是我們已經有的

```
雙向同步    查到的 VS Code 擴充（CodeMap · Code Flow · FlowCraft · CodeVisualizer）
            多半【單向】：點圖跳到程式碼。沒有一個宣稱做雙向游標同步。
執行視覺化  文獻逐字：block-based 環境多採預防式設計、
            **Scratch 完全不支援追蹤執行**（"offers no support to trace executions"）。
            有做的是少數：Snap! 可暫停 · MakeCode 有中斷點 ·
            PencilCode 的實驗擴充用箭頭高亮執行中的積木。
```

> **我們已經有雙向對應與 `execution:at-node`——
> 流程圖上高亮「現在走到哪」是幾乎沒有人做到的那一格，而它是教學價值最高的一格。**
> （學生問的是「它為什麼跑到 else？」）

## 二、三個拍板（使用者，2026-08-24）

> 「**沿用積木的顏色語彙**」
> 「**一開始就手拖 ＋ 記住，也可以一鍵自動排版**」
> 「**粒度可以給使用者選**之類的」

### ① 沿用積木的顏色語彙——它推得出兩件事

🔴 **顏色的來源必須是同一張分類表**（`languages/*/toolbox-categories` 的
`CATEGORY_COLORS`），流程圖**不准自己複製一份**——複製就是一筆新的雙重真相，
而這個 repo 有一條護欄專門在看那個。

⚠️ **而它換出一個新問題**：不用菱形的話，「這裡會分岔」**靠什麼看出來**？
候選：邊上的**真／假標籤**、port 的位置（下／右）、節點右緣的兩個出口。
**未決 ①** 見下。

### ② 手拖 ＋ 記住 ＋ 一鍵自動排版

🟢 **判準已經有先例**（2026-08-24 的空行那次）：**拖曳的是排版，不是程式**
——所以它住在**投影層**（per-panel 私有狀態），不進語義樹。
那正是路線圖那條護欄要守的界線：**改面板私有狀態之後，語義樹的雜湊不變。**

🔴 **而「記住」買到了第一個硬問題**：佈局要記在**哪個鍵**上？
節點的身分是 `nodeId`——**而 nodeId 穩不穩定？**
（`vision.md` 的 9.2 逐字：「SemanticDiff 增量更新（**前置：階段 5b nodeId 穩定性**）」）
樹重建之後 nodeId 若會變，**佈局就對不回去**。
**這是這個決定買到的那個貴東西，也是它值得先做的理由。**

🟢 **「一鍵自動排版」是一個【動作】，不是一個【模式】**——這一點要寫死：
模式化的話會出現「自動模式下拖不動」的困惑，而那是節點編輯器最常見的抱怨之一。
按下去＝重排一次（dagre 起步，需要正交再換 ELK），之後照樣拖。

### ③ 粒度可選

候選：**整個檔案** ／ **一個函式一張** ／ **跟著游標所在的那個函式**。

🔴 而第三個候選正好接上同一天的另一句話
（[面板協定 §八](2026-08-20-面板協定的三個頻道.md)）：
**「共同真相是大家現在關注什麼」**——粒度選擇本身很可能就是一個
**per-panel 狀態**，而「跟著游標」是「關注」這個詞在面板層的第一個實例。

⚠️ **代價**：每個粒度要不要**各記一份佈局**？要的話，③ 的 key
就從 `uri × 面板種類` 再多一維（`× 粒度`）。**未決 ②**。

## 四、④ 這是 **flow-based**，不是 **flow chart**（動工當天補拍板）

> 使用者（2026-08-24，我把第一版做成教科書流程圖之後）：
> 「你好像有點誤解我流程圖的意思，我要的比較像是 **Node 然後有 Flow 可以接線
> 可以呈現資料流**的那種，**不是傳統意義上的『Flow Chart』**。」
> 隨後又補一句，把名字也定了：「**因為是 Flow-based，而不是傳統的 Flow Chart**。」

### 🔴 而這一段的 SOTA 調查**早就把兩套語言列出來了**（§一的那張表）

左欄是「教育流程圖傳統（RAPTOR／Flowgorithm，菱形）」，右欄是
「現代節點編輯器（React Flow／ComfyUI／Node-RED，port ＋ 顏色）」。
我照著這份研究去做，**做成了左欄**——而使用者要的是右欄。

> **三個拍板都在講細節（顏色、拖曳、粒度），而「選哪一欄」那個更上位的問題
> 沒有被問出口——於是它被實作者默默地選了，選錯了。**
>
> 判準：**一份把選項並排列出來的研究，如果沒有在最後寫下「我們選哪一欄」，
> 那它就把那個決定留給了動手的人**——而那是最不該決定它的位置。

### 兩欄的差別不在畫風，在**誰是節點**

```
流程圖   一個語句一格，「x > 3」是格子裡的一串字
節點圖   「>」自己是一顆節點，left／right 兩條資料線接進來
```

而語義樹本來就是後者的形狀（`python:compare` 有 `left`／`right` 兩個子槽）。

> **投影不該把真實壓扁成它自己的形狀——那樣它投的是自己。**

### 落地的形式（2026-08-24 交付）

| | 做法 |
|---|---|
| 節點 | 每一顆語義節點一張卡；標頭是身分、身體是宣告的 `properties` |
| 資料接點 | 子槽宣告**不是** `statements` 的 → 左邊的圓點，標籤是插槽名 |
| 執行接點 | 子槽宣告**是** `statements` 的 → 右邊的箭頭，依 `control_flow` 分色 |
| 兩種線 | 執行＝白色實線；資料＝細藍線。**貝茲，方向看得出來** |
| 空插槽 | **不長接點**——這張圖是導出的不是接出來的，空接點只會是雜訊 |

⚠️ **命名也一起改了**：tab 叫「流程」、檔案叫 `flow-panel.ts`、CSS 前綴 `fc-`／`.flow-`。
理由是使用者的第二句話——**一個叫 `flowchart-panel` 的檔案，會一直教下一個讀它的人做流程圖。**

## 三、未決

- [x] ~~**① 分岔怎麼看出來**（不用菱形之後）~~ → **具名的執行出口**：
      `if` 的 `body`／`else_body` 各一個接點，名字寫在接點旁邊（2026-08-24 落地）
- [ ] **①′ 接點的名字現在是插槽的內部名**（`body`／`else_body`／`values[0]`）。
      它**誠實**（那是膠囊宣告的名字）而**不是給學生看的字**。

      🔴 **2026-08-24 查證：字已經有了，而【對應關係】沒有。**
      `python/if/labels/zh-TW.json` 逐字有 `PYTHON_IF_THEN: "則"`、`PYTHON_IF_ELSE: "否則"`
      ——**而沒有任何地方說 `body` 配 `PYTHON_IF_THEN`**。
      那份對應今天只活在積木的 `message1/message2` 與 `args` 的**位置**裡，
      而位置是給 Blockly 讀的，不是給第二個視圖讀的。

      > **一個只有位置沒有名字的對應，第二個消費者接不上。**

      所以這一條要的是**一個新宣告**（膠囊說「這個插槽的標籤是這個鍵」），
      而它與 `draft/開放值域的下拉` 是**同一個家族**：
      兩者都是「**宣告的內部名 vs 使用者看的字**」，
      而兩者的解法都不是在視圖裡寫一張對照表。

      ⚠️ **判準**：加這個宣告之前先問「除了流程面板，還有誰要用它？」
      ——今天只有一個消費者，而 `vision.md:513`「每一步剛好買一個貴的決定，
      **而消費者都已到場**」說的正是這個門檻。第二個消費者可能是
      2D 接線視圖（腳位的名字）或語義診斷（訊息要指名哪一格）。
- [ ] **② 佈局的鍵**：`nodeId` 穩定嗎？不穩的話用什麼對回去？
      而粒度要不要各記一份（③ 的 key 再多一維）？
- [ ] **③ 自動排版引擎**：dagre（快、樹狀、已停維護）vs ELK（可配置、正交、複雜）
      ——先 dagre、需要正交再換？
- [ ] **④ 節點太多時**：SOTA 的答案是 progressive disclosure；
      而我們的粒度選單可能已經吃掉一半——剩下的那一半（一個函式內部太長）還沒答
- [ ] **⑤ 唯讀到什麼程度**：`concepts/投影.md:62` 逐字「**R0-R1 是可編輯視圖；
      R2-R4 是唯讀視圖**」，而流程圖那一類（`state_machine`／`data_flow`）列在 **R2**
      → 不能從流程圖改程式。**而拖曳排版不算改程式**（見 ②）——這條界線要寫進實作。
