# 內部狀態要怎麼顯示——而第一個對象不是圖片，是液晶

**日期**：2026-08-31 ｜ **狀態**：設計（未決）
**起點**：使用者「流程資料流、內部狀態顯示」→「例如說圖片等等」

## 一、🔴 路由規則：不能印到 stdout 的狀態，就必須有自己的視圖

`components/cpp/lcd_print/execute.ts` 逐字：

> 「🔴 **不進 `ctx.io`**——那是**程式的輸出**（學生的 `Serial.println` 走同一條），
>  把液晶的內容寫進去會讓程式的輸出變成錯的。與蜂鳴器同一條判準。」

於是畫面上有一條結構性的分界，而它已經被畫出來了：

```
程式的輸出   Serial.println → 主控台        ← 有出口
裝置的狀態   LCD／伺服／EEPROM → 【沒有出口】  ← 缺口
```

> **一個「不能印到 stdout」的狀態，就是一個【必須有自己的視圖】的狀態
> ——沒有中間選項。**

⚠️ 這條與 [模擬的誠實](../concepts/模擬的誠實.md) 是**互補的兩條**，別混：

```
模擬的誠實   模擬器【不准編數字】          ← 資料從哪來
本條         誠實的狀態【該去哪】          ← 資料往哪去
```

🟢 而那一份第 81 行已經說了另一半：「所以『板子視圖』要做的時候，**資料已經在那裡了**。」

## 二、量到的：六顆元件同一句自白，同一個缺口

```
tone（蜂鳴器）  「按執行時蜂鳴器什麼都不會發生」
lcd_print       「學生按執行，液晶什麼都不會顯示」
touch_read      「if (touchRead(4) < 40) 這條分支【永遠走不到】」
wifi_read       「連線失敗的處理分支永遠走不到」
arduino-pins    同上
                → 全部：「那是視圖層的缺口（板子視圖，已推遲）」
```

而狀態物件已經在維護：`ServoState{angle}`、`LcdState{cols,rows,cursor,lines}`、`EEPROM: Uint8Array`。

🟡 **而路線圖那一項的措辭比缺口窄**：`vision.md:293` 寫「板子視圖**顯示腳位狀態**」，
而實際要顯示的含**液晶畫面、蜂鳴器頻率、伺服角度、觸摸讀數、WiFi 狀態**。
**這是一個提案，不是一個修改**——改路線圖要人拍板。

## 三、🔴 設計約束：每個視圖回答一個它獨有的問題

```
程式碼    這一行在做什麼
積木      這個結構長什麼樣
變數面板  現在有哪些值            ← 已經有了，做得也對
流程      這個值【從哪來】、【影響了什麼】   ← 只有圖答得出來
裝置視圖  這台機器現在長什麼樣     ← 沒有別的地方放得下
```

> **圖的價值不在顯示值，在顯示【值的來源與去向】。
> 那是表格結構上做不到的事。**

⚠️ **這條有剪枝力**：它擋掉「流程視圖也印一份變數」——那些數字變數面板已經有了，
而且排得更整齊。一個只是重複別人答案的視圖，**增加的是雜訊不是資訊**。

🔴 **這條可能該進 `concepts/投影.md`**（多視圖住在那裡），而那要人拍板。

## 四、SOTA：三個工具，三個不同的問題

| | 做法 | 它回答什麼 |
|---|---|---|
| **Unreal Blueprint** | 執行時走過的線**脈動**；pin 右鍵「Watch this value」；Debug 分頁有執行過節點的 trace stack | 現在走到哪、這條線上是什麼 |
| **Python Tutor** | 堆疊／堆積圖，**可往前也可往回**；6 種語言（教育界標竿） | 這一步的記憶體長什麼樣 |
| **Pernosco** | 全知除錯；dataflow 面板可「跨時間與跨堆疊瞬移」，把結果追回原因 | **這個值是怎麼變成這樣的** |

🔴 **而 Pernosco 那句話，在 2026-08-31 的公理決定之後變成了架構性質**：

> 「Pernosco 聚焦在**視覺化狀態跨越時間**的樣子，而傳統除錯器多半只渲染某一個時間點。」

過程升格成時間軸上的真實之後，**「跨時間」是預設，「某一時刻」才是要用游標切出來的特例**。

## 五、三個做法，按「只有圖做得到」排序

`GraphWire{from,to,kind:'exec'|'data'}` **已經分開了 exec 與 data**，
所以下面全部是「把值接上既有的邊」，不是新的圖結構。

### ① 值長在**資料線**上，不是節點上
`kind:'data'` 的線就是資料流邊。畫在線上，畫面直接回答「這個 3 從哪一顆流到哪一顆」。
⚠️ **畫在節點上會退化成變數面板**——節點旁一個 `3` 不告訴你它要去哪。

### ② 走過的語句線留下痕跡（Blueprint 的脈動）
沒走到的分支保持暗的，一眼回答「為什麼沒進 else」。
🟢 已有一半：`onExecutionAtNode` 知道現在在哪；缺的是「走過的邊」——而在事件記錄裡那是免費的。

### ③ 🟢 迴圈裡的節點顯示「它每一次的值」，不是「現在的值」

**三個 SOTA 沒有一個有這個**（Blueprint 只有上一次、Python Tutor 是單一時刻、
Pernosco 有跨時間而不長在圖上）：

```
total = total + i     0 → 1 → 3 → 6 → 10
```

那一串是教學上最需要看到的東西，而它今天要靠學生在腦裡跑五遍。
⚠️ 誠實邊界：**數字才畫得成 sparkline**；字串／物件只能列最後 N 個或「變了 5 次」。
**別為了畫得漂亮而假裝所有型別都可以。**

## 六、圖片那一類：誰決定一個值長什麼樣？

`RuntimeType` 是**封閉詞彙的 11 個型別**（`int|float|double|char|string|bool|void|array|pointer|object|function`）
——**沒有圖片、張量、資料表**。所以這一節是為**還不存在的執行器**設計的，要誠實標記。

```
❌ 視圖硬編     「是圖片就畫 img」→ 核心認識了 PNG，中立性破了
🟡 元件宣告     接近既有形狀（宣告登記處）
🟢 值自帶表示   Jupyter 的 MIME bundle
```

第三個是**誠實降級套在顯示上**：

```
值提供   { 'image/png': …, 'text/plain': '<Image 640×480>' }
視圖挑   畫得出 png → 畫；畫不出 → 退到 text/plain，【並且說出自己退了】
```

核心永遠不需要知道 PNG 是什麼，只需要知道「一個值可以提供幾種表示」——那是 P3 開放擴充。

### 顯示的粒度取決於型別，不能用一條通則蓋過去

| 型別 | 你要的是 | 放哪 |
|---|---|---|
| 數字 | 精確值 | 資料線上 |
| 字串 | 精確值（可截斷） | 資料線上 |
| **圖片** | **認得出來**，不是讀它 | 節點縮圖（Houdini／TouchDesigner 有效正因如此） |
| 張量 | **形狀**，不是內容 | `(32,3,224,224) float32` ＋ 可選熱圖 |
| 資料表 | 抽樣 | 前幾列 |
| LCD | 整個畫面 | 裝置視圖 |

**「顯示內部狀態」不是一個功能，是一族按型別分開的決定。**
Jupyter 撐得住，正是因為它把這一族**外包給值自己**，而不是內建一張表。

## 七、順序建議（🔴 而它是反直覺的）

```
先做  裝置視圖      有真實對象（六顆元件的自白）、狀態小、缺口已經寫在程式碼裡
後做  圖片／張量    要等執行器外包（ML runner 才產得出來）
```

> **用一個今天就存在的小案例（LCD），把之後要給圖片與張量用的協定先驗一次
> ——而不是為了想像中的張量設計一個沒有使用者的協定。**

LCD 就是第一個「不是純量、需要自己的畫法」的值。

## 八、限制

節點量到 **218×127 px**，手機 **390px**。所以值要小、要能截斷；手機大概只放得下當下那一顆。

🔴 **而「太多資訊」比「沒有資訊」更糟**——每顆節點都掛數字的圖會失去可讀性，
而可讀性正是圖唯一的優勢。**建議預設只顯示游標所在那條路徑上的值。**
