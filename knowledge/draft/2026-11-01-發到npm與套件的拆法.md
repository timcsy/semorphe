## 二、cella-lang 怎麼拆（對照）

```
cella-lang              引擎（wasm）＋ 標準庫 ＋ 主機（host、dap）
@cella-lang/cfamily     C 家族共用的深嵌入核心
@cella-lang/c、cpp、arduino   各分支
@cella-lang/python      Python
@cella-lang/machine     共用的機器模型
```

**依語意的邊界拆**：每個套件是一套可以單獨判決的語言；版本一起發（同一個時間戳）。
我們的五層與它的對應：cella 的「分支」≈ 我們的③元件套件（依語言）；cella 沒有①④⑤（它沒有視圖、沒有應用）。

## 三、推薦的拆法——分三期，跟著阻斷走

| 期 | 套件 | 給誰 | 前置 |
|---|---|---|---|
| **1（現在）** | `semorphe` | 老師、學生：`npx semorphe` 在本機起一份（離線、教室自架）；線上 semorphe.com 的資源從 jsDelivr 抓同一個版本 | 只要 npm 帳號與 CI 的發布 token |
| 1 | （Cella 不重發） | 線上直接抓 `cella-lang@<釘死的版本>` | 無 |
| **2** | `@semorphe/core` | 想把「積木 ↔ 程式碼」嵌進自己網站的人（LMS、cella 的網站、教材平台） | 公開介面要先凍結一版（`src/sdk/index.ts` 那張清單） |
| 2 | `@semorphe/lessons` | 課程與題目當資料——老師可以 fork、第三方可以出自己的課 | 課文格式（`lesson.json`）要有版本 |
| **3** | `@semorphe/lang-cpp`、`@semorphe/lang-python`…（③） | 只要某個語言的人；第三方加語言 | **登錄表改成執行期註冊**（今天的第一個阻斷） |
| 3 | `@semorphe/view-*`（④） | 只要某個視圖的人 | 視圖獨立性已有護欄；要的是打包方式 |

**為什麼不一開始就照五層拆**：今天元件在建置時就被 glob 打包進核心——現在拆③，等於先做一次登錄表的大改，而沒有任何一個使用者在等它。
cella 能一開始就依語言拆，是因為它每個語言本來就是獨立的語意套件；我們的膠囊雖然在資料夾上已經分好，登錄還沒分。

## 四、生態系

- **命名**：官方用 `@semorphe/*`（要先在 npm 建 org，保留名字）；第三方用 `semorphe-*` 或 `@作者/semorphe-*`。
- **登錄處就是 npm**：不自建 registry。發現機制先用 npm 的 keyword（`semorphe-package`）。
- **版本**：照〈套件協定〉的傾向——課文釘精確版本＋內容雜湊（「學生兩台電腦上看到的積木不一樣」買不到任何東西）。
- **🔴 還沒有人想過的**：第三方的膠囊裡有 TypeScript（`generate`、`lift`），裝了就會在學生的瀏覽器裡跑——信任與沙箱。
  這一條在第 3 期之前一定要有答案。

## 五、要使用者定的

1. 官方 scope 要不要叫 `@semorphe`（像 `@cella-lang`）？——推薦要，現在就在 npm 建 org 保留。
2. 第一期的範圍：只發 `semorphe`（應用＋CLI），還是連 `@semorphe/core` 一起？——推薦只發 `semorphe`，core 等公開介面凍結。
3. 課程要不要獨立成 `@semorphe/lessons`？——推薦要，第二期。
4. 元件依語言拆（第三期）要不要排進 vision 階段 8？——推薦要，掛在「登錄表執行期註冊」之後。
