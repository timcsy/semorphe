## 二、cella-lang 怎麼拆（對照）

```
cella-lang              引擎（wasm）＋ 標準庫 ＋ 主機（host、dap）
@cella-lang/cfamily     C 家族共用的深嵌入核心
@cella-lang/c、cpp、arduino   各分支
@cella-lang/python      Python
@cella-lang/machine     共用的機器模型
```

**依語意的邊界拆**：每個套件是一套可以單獨判決的語言；版本一起發（同一個時間戳）。
我們的五層與它的對應：cella 的「分支」≈ 我們的③元件套件（依語言）；cella 沒有①④⑤（它沒有視圖、沒有應用）。

## 三、推薦的拆法——分三期，跟著阻斷走

| 期 | 套件 | 給誰 | 前置 |
|---|---|---|---|
| **1（現在）** | `semorphe` | 老師、學生：`npx semorphe` 在本機起一份（離線、教室自架）；線上 semorphe.com 的資源從 jsDelivr 抓同一個版本 | 只要 npm 帳號與 CI 的發布 token |
| 1 | （Cella 不重發） | 線上直接抓 `cella-lang@<釘死的版本>` | 無 |
| **2** | `@semorphe/core` | 想把「積木 ↔ 程式碼」嵌進自己網站的人（LMS、cella 的網站、教材平台） | 公開介面要先凍結一版（`src/sdk/index.ts` 那張清單） |
| 2 | `@semorphe/lessons` | 課程與題目當資料——老師可以 fork、第三方可以出自己的課 | 課文格式（`lesson.json`）要有版本 |
| **3** | `@semorphe/lang-cpp`、`@semorphe/lang-python`…（③） | 只要某個語言的人；第三方加語言 | **登錄表改成執行期註冊**（今天的第一個阻斷） |
| 3 | `@semorphe/view-*`（④） | 只要某個視圖的人 | 視圖獨立性已有護欄；要的是打包方式 |

**為什麼不一開始就照五層拆**：今天元件在建置時就被 glob 打包進核心——現在拆③，等於先做一次登錄表的大改，而沒有任何一個使用者在等它。
cella 能一開始就依語言拆，是因為它每個語言本來就是獨立的語意套件；我們的膠囊雖然在資料夾上已經分好，登錄還沒分。

## 四、生態系

- **命名**：官方用 `@semorphe/*`（要先在 npm 建 org，保留名字）；第三方用 `semorphe-*` 或 `@作者/semorphe-*`。
- **登錄處就是 npm**：不自建 registry。發現機制先用 npm 的 keyword（`semorphe-package`）。
- **版本**：照〈套件協定〉的傾向——課文釘精確版本＋內容雜湊（「學生兩台電腦上看到的積木不一樣」買不到任何東西）。
- **🔴 還沒有人想過的**：第三方的膠囊裡有 TypeScript（`generate`、`lift`），裝了就會在學生的瀏覽器裡跑——信任與沙箱。
  這一條在第 3 期之前一定要有答案。

## 五、使用者定的與還在想的（2026-11-01）

- 🟢 **官方 scope 叫 `@semorphe`**——要使用者在 npm 建 organization `semorphe` 保留名字。
- 🟢 **第一期只發 `semorphe`**（應用＋CLI，也是 semorphe.com 從 jsDelivr 抓的那一份）；`@semorphe/core` 等公開介面凍結。
- 🟡 **課程的定位**——使用者：「還在思考，是要跟著 semorphe，還是要跟著各個領域套件」。整理給思考用的事實：
  - 一份課依賴三樣東西：它用到的**元件**（領域套件）、應用的**功能**（骨架、判題、預測）、判題的**語意**（Cella 的版本）。
  - 一個語言對**很多**課程（入門、競賽、Arduino 專題、老師自編的），而一份課只對一個語言——課程跟著領域套件的話，
    第三方的課要附在別人的領域套件裡；獨立成課程套件、依賴領域套件（釘版本）的話，一對多自然成立。
  - 也可以兩者並存：領域套件附一份「官方入門課」當預設，其餘課程是獨立套件。
- 🟡 **semorphe 領域套件與 cella 領域套件的關係**——使用者：「還要思考」。整理給思考用的事實：
  - 分工的盟約（[history/305](../history/305-與Cella的分工從Cella是答案到盟約與深嵌入.md)）：semorphe 管呈現與編輯、Cella 管語意；中間的橋是 **formalize**（語義樹 → Cella 的程式 JSON）。
  - 🔴 **今天的橋放在兩個不同的地方**：C 家族的 formalize 寫在我們的膠囊裡（`formalize.ts`，第 389 刀），
    Python 的卻是 cella 維護的對照表（`packages/python/docs/components.json`），我們同步過來（spec 195）。
  - 三種可能的關係：① `@semorphe/lang-cpp` 依賴 `@cella-lang/cpp`、自己帶 formalize（今天 C 的形狀）；
    ② cella 的領域套件帶「元件 → 語法」的對照、semorphe 的只管投影（今天 Python 的形狀）；③ 一個領域一個套件，兩邊聯合發版。
  - 不論哪一種，**版本要成對釘**：formalize 送的是某一版 Cella 語法的 JSON（今天 `audit-cella-pinned` 守著）。

## 五之二、🟡 使用者的構想：COSMOS（CellOSMorphOS）——2026-11-02

使用者：「要不要有一個整合的作業系統，取名叫 CellOSMorphOS，小名叫 COSMOS，然後一個應用會是 cella 套件和 semorphe 套件合在一起，
然後再做這整合套件時會自行處理 cella 和 semorphe 的發佈等等」。

**它解決的**：① 一個領域的語意（Cella）與投影（semorphe）分在兩個套件、作者要發兩次；② formalize 送的是某一版 Cella 語法——兩半在同一個應用裡版本天生成對；
③ 今天 formalize 放在兩個地方（C 在我們的膠囊、Python 在 cella 的對照表）——在 COSMOS 裡它屬於那個應用。

**理解的三層**（待使用者確認）：核心（Cella 引擎＋semorphe 核心）／系統服務（判題、執行、硬體時間軸、套件管理）／應用（一個領域：Cella 那一半＋semorphe 那一半＋也許課程）。
整合工具把一個應用拆成兩半各自發，也能整包發。

**推薦守住的一條**：cella 與 semorphe 各自仍可單獨使用——COSMOS 站在兩者之上，不讓兩邊互相依賴（合乎 [history/305](../history/305-與Cella的分工從Cella是答案到盟約與深嵌入.md) 的分工、〈重構〉的能力介面）。

**還要想的**：① 一個應用發成一個套件（兩半都在）還是兩個套件＋一個綁定清單；② 課程算應用還是應用的內容；③ COSMOS 住在哪個 repo（牽涉 cella）；
④ 名字——npm 的 `cosmos` 已被用、另有 C# 的 COSMOS 作業系統與 Cosmos SDK。

**推薦的第一步**：先當「應用的格式＋工具」，拿一個真實領域（例如一個 Arduino 感測器：語意、積木、formalize、一份小課）做出第一個應用驗證，再長其他部分。
這有一半是 cella 的事——要不要徵詢 cella 由使用者決定。

### 五之三、名字與 registry（2026-11-02）

- 使用者想叫 `cosmos-app`：npm 上同名套件已被佔（`cosmos-app@0.0.1`，空的）；「Cosmos App」在區塊鏈圈是既有說法（`create-cosmos-app`、Ledger 的 Cosmos App）。
- 使用者要「registry 的感覺」，並定：**官方套件放在 npm**。⟹ 官方 COSMOS 應用收在**一個專屬 scope** 底下——scope 本身就是官方 registry（只有我們能發）：
  ```
  @cella-lang/*            Cella 自己的（語言、語意；不需要積木也能用）
  @semorphe/*              semorphe 自己的（應用、核心）
  @<COSMOS 的 scope>/*     官方 COSMOS 應用（Cella 那一半＋semorphe 那一半），整合工具發到這裡
  第三方                    自己的名字發 npm；要進目錄就在索引登記（在 npm 之上放一份索引，之後再做）
  ```
- scope 名字：建 org 時先試 `cosmos-app`（使用者取的名字），拿不到或在意區塊鏈的聯想就用 `cellosmorphos`，對外仍叫 COSMOS。
  ⚠️ npm 網站擋掉自動查詢（連已知存在的 `@cella-lang` 也回 403），**scope 是否可用只能在建 org 時確認**。

### 五之四、🟢 名字定了：**cos-mos**（2026-11-02 使用者定）

```
CellOSMorphOS  →  Cell-OS ＋ Morph-OS  →  C-OS ＋ M-OS  →  cos-mos
```

- **COS**：Cella OS，也讀成 **Contract OS**——使用者要的「契約作業系統的感覺」（每個應用帶著它的契約，系統守住契約；
  對應 vision 的總目標「事前說得出保證」、與 Cella 分工的「盟約」）。**MOS**：Morph OS（semorphe 那一半）。連起來唸是 COSMOS。
- **書寫約定**：一律帶槓（`cos-mos`、`COS-MOS`）——口頭說「cosmos」容易被打成沒槓的、跑到擁擠的 cosmos（Azure Cosmos DB、Cosmos SDK）。
- npm：`cos-mos` 沒人用（2026-11-02 查）；官方 scope `@cos-mos` 由使用者建 org 時確認。
- 走過的候選（留著，因為「為什麼不是它」是名字的一部分）：`cosmos-app`（套件名被佔、區塊鏈的「Cosmos App」）、
  `cosmos-program`（和學生的「程式」、語義樹的 `program` 撞在一起）、`cosmorph`、`Kosmonomos`、`Syntheke`、`Diatheke`、`CosmoPact`。
