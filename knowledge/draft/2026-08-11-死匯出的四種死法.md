# 死匯出的四種死法——而只有一種是「垃圾」

> 日期：2026-08-11
> 怎麼冒出來的：F 完成之後的大清掃第 5 步。原本要做的是「刪掉沒人用的匯出」，
> 而**這個專案有一條規則擋住了那個動作**：
>
> > 「機制有了沒人接上」已有**八個實例**——一個零呼叫者的匯出可能是垃圾，
> > **也可能是一個 bug，而刪掉等於把 bug 藏起來**。
>
> 所以這一步的產出是**一張分類表**，不是 diff。

## 四種死法

型別／介面（94 筆）先擱著——匯出一個沒有外部消費者的型別是噪音，不是機制沒接上。
剩下 120 筆的值：

| | 筆數 | 是什麼 | 處置 |
|---|---|---|---|
| **A. 檔內有用，export 多餘** | 34 | `registerCppExecutors` 在自己檔裡被 `registerCppLanguage` 呼叫 | 拿掉 `export` 即可，**低風險** |
| **B. 測試綠、產品沒走** | 42 | `serializeTree`／`deserializeTree`／`walkNodes`… | ⚠️ **最危險**，見下 |
| **C. 連自己的檔都沒碰** | 28 | 見下面逐筆 | 要分「真死」與「沒接上」 |
| D. 型別 | 94 | — | 噪音 |

## ⚠️ B 最危險：一條沒有人走的路上，測試是綠的

`src/core/semantic-tree.ts` 一個檔就有 **11 個**這種：`addChild`／`removeChild`／
`updateProperty`／`findById`／`serializeTree`／`deserializeTree`／`nodeEquals`／
`semanticEquals`／`walkNodes`／`serializeModel`／`deserializeModel`。

每一個都有測試，**而產品一個都沒呼叫**。

> **一支綠的測試證明的是「這段程式碼做了它宣稱的事」，
> 不是「有人需要它做那件事」。**

而專案記憶裡已經有這一族的旗艦案例：`generateCode` **384 次測試引用、
不在 production 路徑上**。

⚠️ **這一類不能靠「刪掉」處理**——刪掉會連測試一起刪，而那些測試可能是
某條路唯一的規格。要問的是：**這條路是被取代了，還是從來沒接上？**

## C 的逐筆判定（28 筆）

### ⚠️ C-1：**8 個「測試用重置」，而沒有任何測試呼叫**

```
resetComponentCache      resetLanguageExecutors   resetLiftPostProcessors
resetIdCounter           resetSkipDeclarations    resetAnnotations
resetDefinedMacros       resetCommentSyntax（有 1 次）
```

它們存在的唯一理由是「讓測試把全域狀態清乾淨」，而**測試沒有在清**。

兩種可能，處置完全不同：

- 測試**不需要**清（每支測試自己建 registry）→ 這 8 個是垃圾
- 測試**應該清而沒清** → 那是**測試之間有隱藏耦合**，而它今天沒有出事
  只是因為執行順序剛好

→ **這一條要驗，不能推。** 驗法：隨機化測試順序跑一次。

✅ **已驗（2026-08-11）**：`npx vitest run --sequence.shuffle` **3931 全綠**。
所以測試之間沒有靠這 8 個重置維持隔離——**它們是垃圾，不是防線**。

⚠️ 而「垃圾」不代表「刪掉就好」：它們的存在說明**當初有人擔心過狀態洩漏**。
刪之前值得問一句「那個擔心今天為什麼不成立了」——答案大概是
「每支測試自己建 registry」，而那是一個**沒有被宣告的約定**。
→ 刪掉重置函式的同時，該把那個約定寫進 `tests/helpers` 的檔頭。

### ⚠️ C-2：**6 個「護欄用」的來源查詢，而沒有護欄用**

```ts
/** 護欄用：每一筆是誰登錄的。過渡表的筆數應該只降不升。 */
export function singleArgFunctionSources() { … }
```

同族還有 `methodConceptSources`／`containerTemplateSources`／
`liftBranchSources`／`astBranchSources`／`componentLiftPatternSources`。

**註解寫著「護欄用」，而沒有任何護欄呼叫它們。**

> **一句「這是給 X 用的」註解，不會讓 X 出現。**

⚠️ 而這幾個**是我在 F 期間寫的**——我一邊建機制一邊想著「之後要蓋一條護欄
盯著這張表只降不升」，然後沒有蓋。這正是「機制有了沒人接上」的第九到十四個實例，
**而它們是這一輪新增的**。

→ 處置：**要嘛蓋那條護欄，要嘛刪掉它們並把那句註解一起刪**。
留著「給護欄用」而沒有護欄，比沒有它更糟——它讓人以為有防線。
