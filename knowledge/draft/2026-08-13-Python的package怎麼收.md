# Python 的 package 怎麼收——而「沒收錄」不是問題，「收錯」才是

> 日期：2026-08-13
> 怎麼冒出來的：使用者說「**會想使用 Python 主要原因應該是有很多 package 可以用**，
> 那要如何處理這些 package 的行為？應該也用不到全部功能，就是選幾個來用，
> 但是會不會出現一些沒有收錄的狀況？遇到這狀況如何處理？」
> **狀態：三條已定（已寫入 `concepts/元件.md`），A/B/C 那一格未決。** captured ≠ committed。

## 一、這件事已經做過一次，而數字在

```
C++ 標準庫        ~100 個標頭
semorphe 收了      17 個          ← requires 欄位實測，收錄率約 17%
lang-library 膠囊   70 顆
```

收了的：`<string>`(18) `<cstring>`(10) `<cstdlib>`(6) `<algorithm>`(6) `<numeric>`(5)
`<queue>`(5) `<cctype>`(4) `<vector>`(4) `<cmath>`(3) `<iostream>`(3) `<map>`(3)
`<cstdio>`(2) `<stack>`(2) `<utility>`(2) `<set>`(2) `<fstream>`(2) `<sstream>`(1)。

**所以「選幾個來用」不是新問題。** 新的是量級。

## 二、Python 的差別是三個量級，不是一個

| | C++ `std` | Python package |
|---|---|---|
| **數量** | ~100 個，**一個委員會定的封閉集合** | PyPI 50 萬個，**沒有邊界** |
| **行為可模擬性** | `std::sort` 手寫得出來 | `numpy.einsum` **手寫不出來** |
| **版本** | `<vector>` 的行為十年不變 | pandas 兩個小版本之間 API 就會變 |

⚠️ **第三個最少被討論而最麻煩**——它讓「行為」變成一個**有時間維度**的東西。
C++ 從來不用回答「你支援哪個版本的 `<vector>`」。

## 三、「沒收錄」已經有機制，而且它的設計是對的

`src/components/cpp/raw_code/execute.ts` 的檔頭逐字：

> 「執行它等於執行一段沒有語義的文字，而那件事做不到——所以它丟一個可被
> `unknownConceptHandler` 接管的錯誤……**使用者可以選擇跳過或中止，但不會不知道。**」

**殘差通道已經存在，而且它出聲。** Python 的未收錄 package 走同一條路，不必發明新東西。

## 四、🔴 而真正該先定的是收錄門檻的**方向**——它與直覺相反

`tests/integration/audit-behavior-error.test.ts` 的檔頭逐字：

> 「⚠️ 這不是殘差。**誤差高＝模型是錯的**（系統會騙人）；
> **殘差高＝模型還沒長到那裡**（系統仍然正確）。**兩者不可合併**。」

套到 package：

```
不支援 numpy                → 殘差   學生看到「我不認得這個」   不會害他
支援了但 broadcasting 算錯   → 誤差   學生得到一個錯的答案     而他不知道
```

> **一個沒收錄的 package 不會騙人，一個收錯的會。**

⚠️ **所以門檻應該高，不是低**——「多支援一點總是好的」在這裡是錯的：
**多支援一顆算錯的，比少支援十顆傷害大。**

**→ 這一條現在就定得下來，不必等 Python 進來。**

## 五、⚠️ 真正沒答的：行為要不要自己寫（A／B／C）

| | 怎麼做 | 代價 |
|---|---|---|
| **A 手寫模擬** | 像 `std` 一樣，每顆寫 `execute.ts` | 覆蓋得很少；numpy 這種寫不出來 |
| **B 真的跑** | Pyodide（CPython 編到 WASM） | ⚠️ 見下 |
| **C 不執行** | 只做形態（積木↔程式碼） | 失去 semorphe 最有價值的東西之一 |

**B 誘人的地方是它讓行為「免費」**——裝了 Pyodide，numpy 直接就對了。

⚠️ **而它的代價是可觀察性**：semorphe 的直譯器可以逐步、可以看變數、
可以高亮到節點。**Pyodide 是黑箱**——而那個黑箱正好吃掉了教學價值。

### 而答案大概不是三選一——這個形狀專案已經有了

第三十二條護欄（`audit-behavior-error`）在量「semorphe 直譯器 vs 參照編譯器」的誤差。
**那就是兩條軌並存，而差距被量出來。**

```
教學軌   手寫、可觀察、少而精        ← A
驗證軌   真的跑，當 oracle          ← B
差距     被量出來，只准下降
```

**B 不是取代 A，是 A 的 oracle。** 而那正是使用者談硬體數位孿生時說的同一條原則
（見 [一致是量出來的不是保證的](2026-08-12-一致是量出來的不是保證的.md)）。

⚠️ **未決**：這是產品決定不是技術決定——B 要不要做、什麼時候做。

## 六、收錄判準的候選：**可觀察性**，不是常用度

> **這個 package 的操作，「一步」是什麼？**

`list.append` 有一步。`pd.merge` 沒有——它是一個原子的黑箱，
**逐步執行它等於沒有逐步**。

⚠️ 而這個判準**與硬體那邊是同一個未解問題**：
[一致是量出來的](2026-08-12-一致是量出來的不是保證的.md) §四 問
「`behavior` 宣告成資料的邊界在哪——簡單元件可行，PID 與通訊協定不行，
**而那個分界今天不知道**」。

> **同一條分界線，兩個領域各撞到一次。**
> 那是它值得被單獨想清楚的訊號——而不是在兩邊各猜一次。

## 七、階層規則（三條已定，寫進 `concepts/元件.md`）

1. **`numpy` 在 `python` 底下**——「scope ＝ 擁有者」的推論；讓 numpy 自己當 scope
   會讓同名 package 跨語言撞（`json`／`math`／`random` 是常態不是邊角）
2. **階層只能來自語言語義**，不准表達我們的分類（`history/047` 的坑）
3. **`.` 是真實**，`/`（目錄）與 `_`（Blockly type）是投影
   ——決定性理由是**核心不准認識語言**，所以分隔符必須統一

⚠️ 使用者的直覺（numpy 在 python 底下）**推翻了我第一版的建議**（numpy 自己當 scope），
而他給的理由正是那個模型會壞的地方：「**萬一其他語言也有類似的套件呢**」。

### 要改的地方（實作時的清單）

⚠️ **不要現在改**——今天 0 顆需要階層，而 `experience` 的判準是
「**邊界現在定，介面等**」，而映射規則是**介面**。等 numpy 第一顆進來。

## 出口條件

- **Python 的第一顆概念進來** → §七 的清單實作，§五 的 A／B／C 必須先有答案
- **B（Pyodide）做過一次實驗** → §五 有實證，可能升格成「兩條軌」的通則
- **`behavior` 宣告成資料的邊界被劃出來** → §六 的判準有答案，
  **而它同時解掉硬體那邊的同一個問題**
- ⚠️ **收錄門檻那一條（§四）不必等**——它現在就定得下來，
  而它該在第一顆 Python package 進來之前就寫在規範裡，否則收錄會憑感覺
