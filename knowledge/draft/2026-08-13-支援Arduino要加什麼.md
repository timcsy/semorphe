## 一、語言那一半幾乎是免費的（實測）

**Arduino 就是 C++**，177 顆膠囊直接可用。差異只有四個：

| 差異 | 成本 | 依據 |
|---|---|---|
| 沒有 `main`，有 `setup()`／`loop()` | ⚪ **幾乎零** | `cpp:program` 的 children 就是 `{"body": "statements"}`——**它本來就沒有 main 的概念**，setup/loop 只是兩個 `func_def` |
| 自動函式原型宣告 | ⚪ 零 | 我們產生的程式碼本來就完整，不依賴那個便利 |
| `.ino` 多檔合併 | 🟡 小 | 可以先只支援單檔 |
| `byte`／`word`／`String`（大寫） | 🟡 小 | 型別表加幾筆 |

⚠️ 教學上可能想要一顆 `sketch` 概念（**強制有 setup／loop**，學生不會忘記寫），
而那是**產品決定不是技術需求**——結構上不需要它。

### 🆕 2026-08-17 的量測：**辨識全過，而執行一段都沒動**

`scenario-corpus` 的十段 Arduino 程式，跑一次完整管線：

```
殘差節點   0/10    🟢 十段【全部辨識得出來】——上表「幾乎免費」成立
輸出       ""×10   🔴 而一段都【沒有真的執行】
```

**沒有 `main`，所以 `setup()`／`loop()` 沒有任何人呼叫**——
直譯器走完一棵只有兩個 `func_def` 的樹，然後結束。

⚠️ **而「跑完」在量測裡長得像成功**：我第一次讀那個數字時說成
「10/10 跑得完」，**而它的意思是「沒有丟錯」，不是「做了事」**。

> **一個「沒有失敗」的訊號，與一個「成功」的訊號，在報表上長得一模一樣
> ——而區分它們的是【有沒有產生任何可觀察的結果】。**

🔴 **這證實了 §五 的順序**：第 1 項（執行模型）是**唯一「不做就什麼都做不了」的**
——而它不是推論，是量出來的。

## 二、函式庫已經被分類過了

`concepts/元件.md:196` 逐字：

> 「`digitalWrite`／`analogWrite` 是**資訊→守恆**，
> `digitalRead`／`analogRead`／`pulseIn` 是**守恆→資訊的投影**」

## 三、🔴 而整件事的關鍵簡化：模擬不需要知道接了什麼

> **`digitalWrite(13, HIGH)` 在模擬裡只是「13 腳 ＝ HIGH」。**
> 它是一個**狀態**，不是一個電路。

**→ 第一階段可以只做腳位狀態，完全不碰電氣求解。**

而那已經有教學價值：一張板子圖 ＋ 腳位亮起來。
**學生看得到自己的程式在做什麼**——而那正是 Arduino 教學最痛的地方
（今天他們要盯著真的 LED 猜程式跑到哪）。

⚠️ **這一條決定了整份清單的順序**：最貴的那塊（電氣求解）**不在前四項的路徑上**。

### ⚠️ 而它修正了姊妹 draft 的一欄

[硬體不是一個階段是兩類](2026-08-12-硬體不是一個階段是兩類.md) §二 把
「守恆網」整格排在「等 2D 接線 ＋ 全網求解」之後。**對讀取側那是對的**
（`analogRead` 要知道分壓才有值），**而對寫入側過於保守**：

```
digitalWrite  是「資訊→守恆」沒錯，而模擬它只要記下腳位狀態
              ——那個守恆網要不要被求解，是【下游】的問題
```

> **一個關係是守恆的，不代表你現在就得解那張網。
> 寫入端只要記錄意圖，求解可以晚一步。**

## 四、唯一真的新東西：執行模型

```
今天       跑完就結束；maxSteps = 100000 是「防當機的保護」
Arduino    loop() 永遠跑，直到使用者按停
```

⚠️ **那不是加一個功能，是 `maxSteps` 的語義從「保護」變成「正常運作」。**

零件全都在（`src/interpreter/interpreter.ts` 實測）：
`abort()`（`:115`）、`stepRecordCallback`（`:59`）、
而它已經是 async（`:327` 有 `await new Promise(r => setTimeout(r, 0))` 讓出）。

### ⚠️ 未決①：模擬時鐘還是真實時間

`delay()`／`millis()` 逼出一個現在就該決定的事：

| | 優點 | 代價 |
|---|---|---|
| **真實時間** | `delay(1000)` 真的等一秒，直觀 | 🔴 **執行不再可重現**——而 fuzz 與 roundtrip 全靠可重現 |
| **模擬時鐘** | 可重現、可加速、可倒帶 | 學生看到的「一秒」是假的 |

**傾向：模擬時鐘 ＋ 一個播放速率**（1× 時看起來像真的，底層仍可重現）。
~~⚠️ 而這是產品決定，未拍板。~~

#### ✅ **已拍板（2026-08-17）：模擬為主，而可以切成真實時間。**

使用者在看到下面這個代價之後仍然選了它——**所以它是接受過的代價，不是疏忽**：

```
🔴 兩條路 ＝ 兩份行為，而【只有一條會被測到】
```

⚠️ **因此這個決定帶一條硬性要求**：

> **兩條路都要有測試，或者【明說】哪一條沒被測到。**
> 一條沒有人跑的路，與一條不存在的路，在報表上長得一樣
> ——而這一條**會被學生跑到**（他想看真的閃爍）。

判準（`build-guardrail` 6.5 的同一條）：**縮分母比修分子容易。**
只測模擬那條的話，「執行可重現」這個性質**在真實時間那條上根本沒有被主張過**。

### 🔴 而 2026-08-17 前面多了一項第 0 項

使用者：「**我想要先把它至少視為不同風格或是不同語言，而不是純粹 C++**」。

```
0  target 機制（visible／io／provides／reference 四個欄位）   🟡 中
   設計已存在：C 和 C++ 難分難捨 §三，而它【一直缺一個硬消費者】
```

⚠️ **而這動搖了本節「語言那一半幾乎是免費的」那句話** ——
免費的是**膠囊**（177 顆直接可用，實測殘差 0/10），
**而「它是另一個目標」這件事本身不免費**。

🔴 **兩者不衝突，而它們常被混在一起**：

```
語言那一半（膠囊）    ⚪ 免費
把它【說成】另一個東西  🟡 一個機制——而它不是 Arduino 專用的
```

**`target` 同時解掉 C99、C++11/17、以及競賽班的 printf/cout 不一致**
——那是它值得的地方，**也是它會膨脹的地方**。

### ⚠️ 而順序與直覺相反：不要從板子或接線開始

**從 1 開始**，三個理由：

1. 它是唯一「**不做就什麼都做不了**」的
2. **它是純軟體**——今天就能做，不必等任何硬體決定
3. **1–4 做完就有一個能教 Arduino 的工具了，而一塊板子都還沒接**

> 🔴 **1–4 全部不需要電氣求解，而那正是最貴的那一塊。**

⚠️ 而 ArduinoCAD 併入的硬條件是「就近性先做完」——**那個條件已經解除**
（`notEncapsulated: 0`）。**第 5 項的門開了，而我仍建議先做 1–4。**

### ⚠️ 而第 4 項的價值不只是 Arduino——它是**面板層的探針**

使用者 2026-08-13 的觀察：「**現在面板還沒有開始為了新的視圖鋪路**」。
量出來的結果是**三件事只鋪好一件**：

| | 狀態 | 證據 |
|---|---|---|
| **事件分發**（視圖收到什麼） | ✅ | `ViewHost` ＋ `view-registry` ＋ bus |
| **組裝**（怎麼被建立） | 🟡 **本輪修掉一半** | 見下 |
| **佈局**（有幾個位置） | ❌ **沒鋪** | `split-pane.ts` 只有 `leftPanel`／`rightPanel`；`mobile-tab-bar.ts:1` `TabId = 'blocks' \| 'code' \| 'console'` 是**型別層級**寫死 |

加一個板子視圖今天要動：`app-shell.ts`（import ＋ 介面欄位 ＋ 建立 ＋ 塞進佈局）、
`split-pane.ts`（沒有第三個位置）、`mobile-tab-bar.ts`（型別）、`style.css`。

**而「要幾個位置」是 UX 決定不是技術決定**（第三欄？分頁？浮動視窗？）
——在它之前重構佈局是猜。`experience`：**邊界現在定，介面等**，而佈局的形狀是介面。

> **所以不要先設計一個通用佈局，先做一個真的新視圖，讓它把需求逼出來。**

⚠️ 而板子視圖特別適合當探針，因為它可能是**第一個同時吃兩種投影對象**的視圖：

```
腳位狀態      跟著執行變  → 當前程式的投影   ✅ ViewHost 認識
板子本身的樣子  與程式無關   → 登錄表的投影     ❌ 契約今天不認識
```

（兩種投影對象見 [完整願景與它的邊界](2026-08-12-完整願景與它的邊界.md) §六。）

前例是 `src/views/semantic-tree-view.ts`⟨曾經⟩——它的檔頭逐字「Used to **verify** that…」，
**它成功了，然後在 `specs/117` 退休**。

## 六、⚠️ 未決②：scope 怎麼給

按 [concepts/元件](../concepts/元件.md) 剛定的階層規則：

```
cpp:arduino.digital_write    軟體側——它是 C++ 的一個 package
hw:led                        硬體側——實體元件
```

而**那兩者的關係正是這個專案最核心的未答問題**：
`digitalWrite(13, HIGH)` 與「13 腳接了一顆 LED」怎麼連起來。
**第 5 項才會逼出答案**——而那也正是它該排在後面的理由之一。

⚠️ 另一個讀法：Arduino 不完全是 C++（它有自己的預處理與建置模型），
所以 `arduino:` 可能該是**自己的 scope**。**未決**——而它與「scope ＝ 擁有者」
的定案不衝突，因為第一方 scope 的命名慣例本來就沒說死。

#### ⚠️ 而 2026-08-17 有一個**相關但不同**的決定：Serial 放哪一層

**已拍板：語言套件的 `ioStyle` trait**（`languages/cpp/core/node-traits.ts:195`
的 `'iostream' | 'cstdio'` 加第三個成員），**而不是**核心的
`io_style`（`src/core/types.ts:596`）。

> **同一個概念在兩層各有一份宣告，而只有其中一層加得起新成員。**

🟢 理由是 P9：「拔掉 C++……**核心無 `languages/cpp/` import**」
——核心的 `io_style` 加 `'serial'` 等於**讓核心認識一個 Arduino 專屬的字**。

⚠️ **而這【不等於】`arduino:` 該不該是自己的 scope**（本節的未決②）。
兩件事都與「Arduino 有多不像 C++」有關，**而它們的答案可以不同**：
I/O 風格是一條**等價邊**（`print`／`print_formatted`／`Serial.println` 同一個
`ioRole`），而 scope 是**擁有權**。**未決②仍然開著。**

## 七、🔴 一個順帶抓到的洞：白名單不存在

`concepts/元件.md:113` 逐字：

> 「這與 scope 白名單是同一個機制（**明列清單，不是任何冒號前的東西**）」

**而程式碼裡沒有白名單。** `src/core/component/registry.ts` 只驗
`<scope>/<name>` 的格式（`:49`／`:52`／`:63`），**不驗 scope 是誰**。

> 又一個宣告了而沒有執行機構的東西——而它今天不會出事（只有 `cpp` 一個 scope），
> **會在加第二個 scope 的那天靜靜地放行任何拼錯的名字。**

→ **前置**：加 `arduino`／`hw` 之前先蓋白名單護欄。
理由是 `build-guardrail` 6.5 逐字：

> 「**護欄先蓋，功能後做。**……把重構先做完，違規會被重構『順便』修掉
> ——**一個被順便修掉的缺陷不會留下任何紀錄，而它的同類還會再來。**」

⚠️ 而這條護欄**第一次跑會是綠的**（今天只有 `cpp`，它合法）。
按 6.5 那是個警訊——**所以它要靠注入證明自己會紅**（餵一個 `xxx:foo` 的合成路徑），
而不是靠第一次的紅。這正是第三十五條護欄那次的情形。
