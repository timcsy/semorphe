# 擴充的形狀（VSCode ／ Arduino IDE）

> 日期：2026-08-17
> 怎麼冒出來的：Arduino IDE 吃 VSCode 擴充（[history/080](../history/080-ArduinoIDE吃VSCode擴充而那不是一個平台是一個位置.md)），
> 而那讓「宿主獨立性」從抽象閘門變成**有使用者的東西**。
> ✅ **已退場（2026-08-18）。** 設計全數拍板並交付：spec 138（第一刀）→
> 139（雙向同步）→ 140（面板就是網頁版本身）。
> 轉變見 [history/081](../history/081-第一刀畫得出積木而三個坑都不會拋錯.md)。
> ⚠️ 本檔原本寫「狀態：設計未決」——**那句話在 2026-08-17 交付之後就過期了，
> 而它掛了一整天沒有人改**。留作當初的設計理由，別刪。

## 一、🔴 先劃一條線：TextBlockly 是**可行性字典**，不是設計來源

使用者逐字（2026-08-17）：

> 「**TextBlockly 基本上就不用再理他了，設計等等還是都以原本的 Semorphe 為主，
> 除非遇到什麼不可行的地方**」

⚠️ **這比我原本說的「PoC 的殼 ＋ Semorphe 的核」更嚴格**：

```
我原本的說法   把 PoC 的殼搬過來，換掉它的核
使用者的意思   🔴 設計【全部】照 Semorphe。TextBlockly 只回答一種問題：
               「這件事在 VSCode／Theia 裡【做得到嗎】」
```

**它是一本字典，不是一份藍圖。**

> **一個能跑的原型最危險的地方，是它會讓「它怎麼做的」變成「應該怎麼做」。**

而 `history/069`§四 逐字說過同一件事：

> 「**一個原型的用途是回答一個問題。答案過期之後，它剩下的只有維護債
> ——而它會偽裝成『已經有基礎』。**」

**查得到的可行性事實**（用完就不必再開）：

```
Webview 載 Blockly     localResourceRoots → node_modules/blockly ＋ resources
TextDocument 寫回      editor.edit(range, text) ／ WorkspaceEdit ＋ applyEdit
安裝                   .vsix → ~/.arduinoIDE/plugins，重開 IDE
語言 id                Arduino IDE 認得 `arduino`
側邊欄                 viewsContainers ＋ views 可用（textbricks 證實）
```

## 二、🔴 而真正的工作是這個：**31 個欄位，哪些是 per-document**

`history/069`§三② 說「六個單例」。⚠️ **今天數 `src/ui/app.ts` 的 `App` 類別：31 個欄位。**
而**沒有人分類過**。

⚠️ 而 spec 136 讓它**變大了**：`targetRegistry`（per-app）與 **`currentTarget`（per-document）**。

> **一個「只有一個 X」的假設，不會出現在任何介面上——它出現在【誰持有狀態】上。**

### 分類（本檔的主要產出，⚠️ 而三筆標了不確定）

**per-app（全域共用，N 個文件共一份）**

```
blockSpecRegistry    積木定義——與哪份文件無關
blockRegistrar       同上
topicRegistry        課程清單登錄表
targetRegistry       目標登錄表
localeLoader         語言包
patternRenderer      渲染策略
currentBlockStyleId  積木外觀＝使用者偏好
currentLocale        語言＝使用者偏好
mobileMenu           UI 外殼
```

**per-document（每份文件一份）**

```
bus                  這份文件的語義事件流
blocklyPanel         這份文件的積木視圖
monacoPanel          🔴 而在 VSCode 裡它【不存在】——程式碼那一側是原生 TextEditor
syncController       這份文件的同步狀態
executionController  這份文件的執行
currentTree          語義樹
currentTarget        🔴 spec 136 新增——.ino 是 Arduino，.cpp 是 C++
currentTopic         同上，由 target 決定
enabledBranches      同上
currentStylePreset   由 target 決定
currentIoPreference  由 style 導出
blocksDirty / codeDirty / autoSync / codeToBlocksTimer      同步狀態
_codeToBlocksInProgress / _restoringState                   同步守衛
codeParserCache      它快取「上一棵樹」
```

**⚠️ 不確定的三筆**

```
storageService   ⚠️ key 是【固定的】`'semorphe-state'`（core/storage.ts:4）
                 → 在 VSCode 裡它要變成 per-uri，而那不只是「多一份」，
                   是【存哪裡】也要換（workspaceState？還是不存？）
cppParser        ⚠️ tree-sitter 的 parser 是【有狀態的】——共用要確認可重入。
                 共用得了就是 per-app（它貴），共用不了就是 per-document
styleSelector    ⚠️ 工具列在 VSCode 裡是全域的還是每個面板一份？
topicSelector    這是 UX 決定，不是技術決定
```

### 數字

```
per-app        9
per-document  18
不確定         4
```

🔴 **不是六個，是十八個。** `history/069` 那個數字是**看得見的那些**
（面板與樹），⚠️ 而同步狀態與守衛那一批**沒有被數進去**。

> **一個假設的成本，第一次估的時候只會數到它顯眼的部分。**

## 三、而 `monacoPanel` 那一格值得單獨講

`vision.md:116` 逐字：

> 「VSCode 中 blocks = WebviewPanel、code = **原生 TextEditor**、console = Terminal」

🟢 **所以 `monacoPanel` 在擴充裡不是「per-document 的一份」，是【零份】** ——
它被宿主的編輯器取代。而它今天在 `app.ts` 裡被用了 **21 次**。

⚠️ 那 21 處**不是 21 個 bug**，是「這一層綁死了一個具體的編輯器」的 21 個證據。
**抽掉它是這條路最有形的一塊工作。**

## 四、合流的形狀（**未決**）

```
(a) 同一個 repo，加一個目錄        semorphe/vscode/
(b) monorepo（PoC 用的形狀）        packages/{core,web,vscode}/
(c) 另一個 repo                     semorphe-vscode
```

⚠️ **而有一個硬條件**（`history/069`①）：
「膠囊登錄表用 `import.meta.glob`（**Vite 的轉換**），所以**那個宿主也必須用 Vite 建置**」
——🟢 **已實測可行**，而它排除不了任何一個選項，只是三個都要用 Vite。

### ✅ 拍板（2026-08-17）：**(a) 同一個 repo 加一個目錄**

使用者逐字：「**同一個 repo 加一個目錄**」。

理由（我提的，而它是負面的）：(b) 與 (c) 都會製造「兩份會漂移的東西」，
而這個專案付過那個學費（`history/072`§三：`c-style-parity` 10/10 全綠，
**而瀏覽器上仍然產出 `<iostream>`**）。

### 🔴 而「放哪一個目錄」還有一刀，因為它決定護欄看不看得到

```
src/vscode/     🟢 在 `src` 底下 ⟹ 【護欄掃得到】
                   tsconfig `"include": ["src"]`（tsconfig.json:25）
                   ~~3 支~~ → 🔴 **實測 6 條 ＋ 1 個共用 helper**（2026-08-17）
vscode/（根）    🔴 在 `src` 外 ⟹ 47 條護欄【一條都看不到它】
```

✅ **已拍板 `src/vscode/`**（2026-08-17，spec 138）。
而它**當場就付了回報**：`erasableSyntaxOnly` 抓到一個建構子參數屬性，
而 `npm test`（esbuild）與 `npm run build:vscode`（Vite）**兩個都放行**。

> **一份程式碼有幾個檢查器，就有幾種「通過」的意思。**

**建議 `src/vscode/`，而理由與合流形狀是同一條**：

> **一條檢查如果自己維護一份「要看哪些檔」的清單，那份清單就是它的盲點。**
> （2026-08-17 才因為課程清單護欄手寫兩個 import 而付過一次。）

**把新程式碼放在護欄看不到的地方，等於替它辦一張免檢證。**

⚠️ **而它有兩個具體代價，兩個都便宜**：

```
① @types/vscode 要進 devDependencies    否則 `tsc --noEmit`（build 的第一步）會紅
② 第二份 Vite 設定                       擴充要 CommonJS 的 `dist/extension.js`，
                                        而網頁版是 ESM bundle
                                        🟢 而「必須用 Vite」本來就是硬條件（history/069①）
```

🟢 **而 `src/vscode/` 不在 `NEUTRAL_DIRS`**（`['src/core','src/ui','src/interpreter','src/views']`）
——**那是對的**：宿主層本來就要認識具體的宿主。

⚠️ **這一刀未拍板。**

## 五、第一刀該做什麼（**未決**）

🔴 **最早的否證點是「Webview 畫布在 Arduino IDE 裡跑得順不順」**
——`.vsix` 被 `deployedPlugins` 解開只證明它**載入了**，不證明畫布好用。

```
最小的第一刀   打得開一個面板，畫得出【一顆積木】
               ⚠️ 而它【不必】接語義樹、不必雙向同步
               → 如果畫布在 Arduino IDE 裡就卡，後面全部不必談
```

> **第一刀要選【否證最快的那一刀】，不是【最像成品的那一刀】。**
