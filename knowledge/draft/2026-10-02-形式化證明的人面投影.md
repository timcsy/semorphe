# 形式化證明的人面投影——而第一個不是圖，是中文

> 日期：2026-10-02
> 怎麼冒出來的：使用者問「之後用 Cella 或 Lean 4 當形式化證明／驗證的教學語言，
> 這些類型論有沒有辦法有直觀的形態？」。
> ⚠️ 而他第二則更正了我的讀法：**問的不是「要不要做成積木」，
> 是「要不要用某種形態面板呈現」**——形態是一根軸，所以問的是哪幾個投影。
>
> 🟡 **狀態：方向未決。** 本檔記的是**拆開之後的三個問題與各自的答案形狀**。
> ⚠️ 照本庫的體例不寫完成條件。

---

## 一、它為什麼算一個題目：我們自己的設計說它是缺的那一半

[事前說得出保證](2026-09-26-事前說得出保證.md) 逐字：

> Vericoding 有的：規格 · 驗證器 · 可驗證的程式碼
> 🔴 Vericoding 缺的：**給【人】看的那一面**
>
> **Dafny 滿是 invariant 的程式碼讀不下去，不是因為它太嚴謹，
> 是因為它沒有人面的投影。**

⟹ 所以這不是一個新方向，是那份設計已經指名的空格。

## 二、🔴 第一個拆分：「看得懂」與「寫得出」要的不是同一個投影

```
看得懂   讀一段別人（或自己昨天）寫的證明
寫得出   在一個目標面前,知道【現在能做什麼】
```

兩者的瓶頸不同，所以答案也不同。而把它們混成「一個證明面板」會兩邊都不好。

## 三、「看得懂」的答案可能不是圖，是**中文**

證明比程式碼**更適合**被投影成自然語言，因為 tactic 有正規的讀法：

```
intro h        假設 h
cases n        n 只可能是 0 或「某個數加一」,分兩種情況
induction n    對 n 做歸納
exact h        這就是我們手上的 h
simp           把兩邊化簡
omega          這是一條線性算術,交給算的
```

逐行換掉之後得到的，**就是數學家平常寫的那種證明**。

⚠️ **而這一招對程式碼不太成立**（「把 x 加一」沒有比 `x++` 好懂），
**對證明成立**——因為證明本來就是論證，而論證的母語是自然語言。

> **一個投影值不值得做，要看那個域的母語是什麼。
> 程式的母語是符號，證明的母語是句子。**

🟢 機制是現成的：`tactic → 句型` 與我們的 `元件 → 積木標籤` 是同一張表。
不需要新模型，只需要一張詞彙表。

## 四、「寫得出」的答案是：**讓工具箱隨目標變**

寫證明難在哪？**不是語法，是不知道現在能做什麼。**
寫程式愛寫什麼都行；證明在每一刻只有少數幾招適用，而初學者分不出來。

🟢 而那正好是既有機制換一個詞彙表：

```
今天   工具箱 ＝ 這一課拿得到的元件      fitsSlot：這顆放得進這一格嗎
證明   工具箱 ＝ 這個【目標】現在能用的招  fitsSlot：這一招套得上這個目標嗎
```

差別只有一個：**課程的工具箱是靜態的，目標的工具箱是動態的**（走一步換一批）。

⟹ 它直接解掉初學者最大的障礙：**畫面上出現的每一招都是真的套得上的。**

## 五、三個候選面板，與它們的排序

```
① 目標盤（主要）
   ┌─ 手上有 ──────────┬─ 要證 ──────────┐
   │ n : Nat           │ n + 0 = n       │
   │ h : n > 0         │                 │
   └───────────────────┴─────────────────┘
   ⚠️ 它【不是圖,是結構化的文字】（＝ Lean 的 infoview）
   而初學者讀得懂「線的左邊是我有的,右邊是我要的」

② 步驟鏈 —— 流程面板的形狀
   一招一個節點,顯示【做之前的目標】→【做之後的目標】
   🟢 它讓「有在前進」看得見,而那是證明教學裡最大的動機來源

③ 洞 —— 積木真的有用的那一格
   一個洞是一個【有型別的槽】,填它＝從套得上的那些裡挑
   而那是一塊積木,不是一門語言
```

**①＋② 是主幹，③ 是怎麼寫。** 而「把整個 Cella 畫成積木」不在這條路上。

### 🔴 為什麼「把證明項畫成積木」是錯的那一格

```
項（term）    證明的【結構】   λ、應用、match、遞迴子
目標（goal）  證明的【狀態】   context ⊢ goal,以及它怎麼一步步變
```

**證明項基本上是 write-only 的。** 沒有人在讀
`Nat.rec (motive := …) h₀ (fun n ih => …)`。而人在證明時腦子裡跑的是
「我現在要證 X，手上有 Y」。

而積木天然是**項**的表示 ⟹ 最直覺的那個想法，視覺化了教學價值最低的那一半。

## 六、⚠️ 而最有效的那一招不是面板

近年最成功的證明教學工具（Lean 的 **Natural Number Game**）**幾乎沒有圖**。
它贏在**分階段**：一次只開一個 tactic、一次只有一個目標、下一關的目標是
上一關的結論。

那是 [漸進揭露](../concepts/漸進揭露.md)，而我們 2026-10-01 剛把課程的工具箱
改成嚴格累積——同一個東西。

⟹ **面板①②③ 加起來的價值，可能還比不上「課程怎麼排」。**
而①②是課程排得起來的前提——沒有目標盤，學生連現在要證什麼都不知道。

> **這一題上，「分階段」的證據比「視覺化」的證據強得多。**

## 七、型別論裡哪些東西有隱喻，哪些沒有

```
🟢 歸納型別   「它只可能用這幾種方式造出來」→ 建構子就是下拉選單／mutator
🟢 match      「每一種造法各給一個分支」→ 窮盡性變成【看得見的缺口】
🟢 Π／→       一台有插槽的機器（我們的函式積木已經是了）
🟢 Σ／record  有格子的盒子
🟢 cubical    唯一自己就帶幾何隱喻的：路徑就是路徑、方塊就是方塊

🔴 相依型別   沒有現成隱喻,而它會【頂到我們的實作】——見下
❌ 隱式參數 · universe level · instance resolution
   它們沒有隱喻,因為【它們本來就不是給人看的】
   ⟹ 要藏起來,放在抽象度軸的另一端,不是畫出來
```

### 🔴 相依型別頂到的那一格：`fitsSlot` 的 `allowed` 是靜態字串

```
我們今天      allowed: string[]              一串固定的名字
相依型別需要   allowed: f(兄弟槽裡的那個值)    一個函數
```

`Vec A n` 的型別**提到了一個值**。Blockly 的接點檢查是靜態字串，
**它表達不出「這一格能接什麼，取決於隔壁那一格填了什麼」**。

⚠️ 這不是工作量問題，是**模型要不要長一根新軸**。所以它該排在後面，
而且要單獨決定。

## 八、Lean 4 與 Cella 的不對稱

```
Lean 4   🟢 Mathlib、社群、Natural Number Game、infoview 成熟
         🔴 瀏覽器裡重;錯誤訊息對初學者是災難;而【我們改不動它】

Cella    🔴 幾乎沒有函式庫
         🟢 瀏覽器裡約 100 ms;而最關鍵的是作者就在隔壁
```

🔴 **而證明教學真正的瓶頸不是語言的表達力，是錯誤訊息與目標呈現。**
2026-10-01～02 那一輪我們就改了對方四次輸出格式
（見 [一條比我們自己的軸更好的牆](2026-09-30-一條比我們自己的軸更好的牆.md)）。

⟹ **那個不對稱，在教學的前兩年比 Mathlib 重要。**

## 九、未決的是什麼

```
🟡 要不要在形態軸上多開「目標盤」與「步驟鏈」兩個投影
🟡 動態工具箱（隨目標變）要不要做 —— 它改的是工具箱的契約,不只是內容
🟡 相依型別要不要讓 allowed 從字串變成函數 —— 模型的新軸,單獨決定
🟢 而 tactic → 中文的詞彙表是【現成機制】,不欠前置
```
