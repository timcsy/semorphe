# 面板模組化：一種投影 ＝ 一份宣告

> 日期：2026-09-01
> 狀態：**骨架已落地，形狀未決**（2026-09-03 判官更新）。
> 🟢 spec 170 已經把宣告那一層做出來：`core/host/panel-spec.ts`（PanelSpec／
> PanelAction／PanelInstance）· `panel-registry.ts`（allPanels／panelsOfLayer／
> assertPanelsSane）· `load-panels.ts`（`import.meta.glob`，與課程／範例同一招）。
> ⚠️ **而下面那張「加一種投影要改七八個地方」的清單還沒有歸零**——四個面板
> 仍是四個手寫類別。所以這份**不退場**：它現在是「剩下那幾處的在飛設計」。
> 🔴 出口仍是 vision 路線圖（要人拍板），不是直接清償——⚠️ 而 vision 今天
> **一行都沒有指它**（判官掃出來的雙向落差），要嘛在路線圖上開一格，
> 要嘛承認它只是一份構想。
> 怎麼冒出來的：VSCode 的面板獨立成三個分頁之後，使用者說
> 「面板可以模組化就更好了，說不定也可以**像元件那樣有可擴充性**」，
> 接著補了一句判準：「**我的重點是要好維護管理**」。

## 一、問題：加一種投影今天要改七八個地方

四個面板是四個**手寫的類別**（`BlocklyPanel`／`FlowPanel`／`ConsolePanel`／
`VscodeCodeView`），它們沒有共同的宣告。於是「加第五種投影」要動：

```
LAYER_ORDER                     多一層
core/host/layout-presets.ts     四張版面的 areas 都要重排
ui/app-shell.ts 的 SLOT_BARS    多一列（元素／格子／那條頭的選擇器）
四個 grid-area 與 display 分支   多一格
i18n 的 LAYER_* 鍵              兩個語系各一
controlSurfaces                 它的控制項投影到哪
它自己的那條頭                   再寫一份（今天四份寫了三個底色）
```

🔴 而最後那一項今天已經被量到了：四份各自寫的樣式長出了**三個底色與三個
間距**，而其中一份是「統一了三格之後才發現漏掉」的。

> **一個東西如果要在七個地方各寫一次，那七個地方遲早會有一個沒跟上
> ——而它不會報錯。**

## 二、🟢 而這個 repo 已經有兩塊拼圖

**① 層已經是宣告的。** `LAYER_ORDER` ＋ `layout-presets` 的 `areas` 只認**層**
不認面板，`profile.layers` 決定一個視窗畫哪幾層。**版面已經不知道面板是誰了。**

**② 元件協定已經定案**（`concepts/元件.md` 的五槽／關係律）。面板要的是
**同一個形狀的另一份**，不是一個新發明。

⚠️ 缺的是第三塊：**面板自己的宣告**。

## 三、宣告的形狀（草案）

```
id          'blocks'
layer       'space'                 這一格是哪一層  ← 今天寫死在 SLOT_BARS
nameKey     'LAYER_SPACE'           i18n 鍵
head        [ …這一格的動作宣告… ]    今天是各自手寫的一條列
mount       (container) => View      🔴 唯一還該是程式碼的那一格
projection  'space'                  它投影的是語義樹的哪一面
```

有了它，`app-shell` 的四個手寫分支收成**一張表跑迴圈**，而「加一種投影」＝
**多一份宣告**。

⚠️ `mount` 為什麼不宣告化：一個面板真正獨特的是**它怎麼畫**（Blockly／SVG／
文字）。把那個也塞進宣告，宣告就會變成一個難懂的 DSL。

> **宣告該吃掉的是【重複的那些】，不是【真的不一樣的那個】。**

## 四、驗收要照使用者的判準走：**可量的維護成本**

使用者說的是「好維護管理」，所以驗收不該是「架構比較漂亮」，而是：

```
加一種投影要改幾個檔          今天 7～8  →  1 份宣告 ＋ 1 個 mount
app-shell 裡的手寫面板分支     今天 4 個   →  0
四條頭的樣式定義              今天 1 份（2026-09-01 已清）→ 保持 1
```

🔴 **而第一條要有一支「真的加一種」的測試**——不然它只是一句話。
候選：合成一種 `probe` 投影（只畫一段文字），驗它不改任何既有檔就進得來
——與 `assembly-speaks-up.test.ts`「組裝漏了一步時要出聲」同一個形狀。

## 五、⚠️ 明說不做

**第三方外掛。** 這份宣告是 **build-time** 的（跟元件宣告一樣，靠 glob 收），
執行期載入別人的面板是**另一刀**（膠囊那條路）。

> **「可擴充」有兩種：我們自己加很便宜、與別人加得進來。
> 先做到前者，而不要在講前者的時候用後者的詞。**

## 六、前置（今天已完成，2026-09-01）

- 四格的頭收成**一份** CSS 定義 ＋ 兩條 e2e 護欄（底色／內距／間距／下緣線
  四項一致；每一格都要有頭）。**那是「一種東西」的第一步：先讓它們長得一樣，
  才談讓它們由同一份宣告產生。**
- `identity` 那個軸的進退（見 history 的墓碑）給了一條判準：
  **與自己一致優先於與宿主一致**——而它會直接影響 `head` 該宣告什麼。

## 七、還沒決的

- [ ] `head` 的動作要不要進 `CONTROLS` 登錄表？（進了就能投影到宿主標題列，
      而 2026-09-01 的判準說**不該為了省高度那樣做**——那這一格宣告什麼？）
- [ ] `state` 那一格是**一層兩個分頁**（主控台／變數）。宣告要不要支援
      「一層多個內容」，還是那兩個各自是一種投影而層相同？
- [ ] 版面宣告今天用**層**當格子的名字。改成用**面板 id** 的話，
      「兩個積木面板」就宣告得出來（使用者 2026-09-01 要過「可以選重複的」）
      ——而那會讓 `areas` 不再是 `LAYER_ORDER` 的子序列（第八十一條護欄盯著）。
