# 結構化編輯器的外部座標系

> 2026-08-20　使用者：「現在有沒有人做類似的？」
> ⚠️ **狀態：掃描完成，而核心主張（第七節）未被證明**

這一篇的軸和 [競品的積木與分類](2026-08-18-競品的積木與分類.md) **不同**：
那篇查的是教育積木產品怎麼分類（MakeCode／Open Roberta／Tinkercad），
這篇查的是**誰把「結構是唯一真實」當地基**。

## 一、主張幾乎相同的三個

| 誰 | 主張 | 差在哪 |
|---|---|---|
| **JetBrains MPS** | AST 是唯一真實，文字／表格／圖／數學式都是 notation | 🔴 **沒有 parser** |
| **Hybrid Structured Editing**（HPI, 2026） | 結構 IR 是權威，**parse 不掉的文字片段保留在 IR 裡** | 不是教育，單語言 |
| **Mixing Visual and Textual Code**（Northeastern, 2026） | 結構是單一真實，視覺與文字都導出 | 同上 |

- Beckmann / Thiede / Lincke / Hirschfeld，*The Programming Journal* 2026 vol.11
  （[arXiv 2603.05644](https://arxiv.org/pdf/2603.05644)）
- Andersen / Ballantyne / Moy / Felleisen / Chang
  （[arXiv 2603.15855](https://arxiv.org/pdf/2603.15855)）

🔴 **HPI 那篇的「保留 unparsed 片段」就是 `raw_code` 降級**，同一個設計，今年發表。
見 [降級與認知邊界](../concepts/降級與認知邊界.md)。

## 二、🔴 而最有價值的一條：`lift()` 是 MPS 二十年可用性問題的解藥

MPS 已經做了近二十年，工業級，而它最有名的抱怨是可用性
（搜尋結果原文：*"serious usability issues"*）。

```
MPS       直接編輯 AST，沒有 parser  →  貼不進既有的 Java
Semorphe  lift()：貼進去就有積木     →  不認識的部分走 raw_code
```

> **使用者被鎖在投影裡，任何一個系統不認識的寫法都沒有入口
> ——那就是「沒有 parser」的代價，而它長得像可用性問題。**

⚠️ **這是一個新主張，而且可否證**：如果 MPS 的可用性抱怨主要來自別的地方
（游標行為、編輯手勢、語言組合的心智負擔），這條就不成立。
**要驗證得去讀 MPS 的使用者研究，還沒讀。**

而它給 `lift()` 一個原本沒有的正當性：不只是「方便匯入」，是**投影式編輯能不能被一般人用**的前提。

## 三、2026 有兩篇獨立工作推到同一個地基——這是收斂證據

HPI 是 Smalltalk 系（Sandblocks 那一脈），Northeastern 是 Racket 系。
不同學派、同一年、同一個結論。

> **不是「你太晚」也不是「別人抄你」——同一個設計在同一時間被多方獨立推出來，
> 那通常表示它是對的。**

## 四、雙向但停在語法層的那一派（教育導向的前輩）

| 系統 | 誰 | 差在哪 |
|---|---|---|
| **Pencil Code / droplet.js** | David Bau | 🔴 見下 |
| **BlockPy** | Bart et al. | Python 雙向 ＋ 回饋，單語言、語法層 |
| **Stride / BlueJ** | Michael Kölling | frame-based——第三種表示，不是投影 |
| **Tiled Grace** | Michael Homer | 同一程式兩視圖 ＋ 動畫轉場，語法層 |

Pencil Code 那一族的描述值得逐字留著：

> *"the text code is the primary representation of the program,
> and blocks are a projected user interface view derived by parsing."*

**「文字是真實，積木是投影」——這正是我們拒絕的那半步。**
文字為真實時只能有一個文字；語義為真實時，
`code:same_lang` / `code:restyle` / `code:cross_lang` 是三個不同的投影
（見 [投影](../concepts/投影.md) 的 R0-R4 表）。

## 五、對兩條 roadmap 的現成前輩

使用者 2026-08-20 定調：Node-Flow 與自然語言＋SDD **都要做但不是現在**，
現在專心磨協定。而兩條都有前輩：

| 要做的 | 誰做過 | 看什麼 |
|---|---|---|
| Node-Flow 視圖 | **Enso**（前 Luna） | text ↔ node graph **雙向**，dual representation |
| 投影是開放集合 | **Glamorous Toolkit**（feenk） | moldable development，**已出貨有人用** |
| 自然語言 ＋ SDD | **SysML v2** | textual／graphical notation 是同一模型的兩個投影 |

## 六、⚠️ Modelica 可能就是「守恆的兩種律」——未查證

[元件](../concepts/元件.md) 寫的「接點的關係律：三種，不是一種」「守恆的兩種律」
「守恆＝有基質」——**Modelica 的 `connector` 用 `flow`（和為零）與 potential（相等）
兩種變數做了三十年，跨機械／電／熱／控制。**

🔴 **如果屬實，ArduinoCAD 合流吃硬體時不用重推，那是被工業驗證過的座標系。**

⚠️ **這一條是憑記憶說的，沒有查證。** 要用之前必須讀 Modelica spec 的 connector 章節，
確認 `flow`／potential 的語義是否真的對應「守恆／相等」兩律。

## 七、🔴 獨特的是交集，而交集的價值還沒被證明

```
MPS                投影 ✅   parser ❌   教育 ❌
Pencil Code        雙向 ✅   語義層 ❌   教育 ✅
HPI / Northeastern 結構真實 ✅ 容錯 ✅   教育 ❌  單語言
Enso               text↔graph ✅         教育 ❌
Modelica           元件協定 ✅           不碰程式教育
```

我們的位置是那個交集：**語義層雙向（含 parser 與容錯降級）＋ 教育鷹架
＋ 跨域元件協定 ＋ 可機械驗證的內容管線**。

⚠️ **而「四個都做」也可能是「四個都做不深」**——上面每一格的專門選手，
在自己那一格都比我們深。

> **交集的價值只有一種證明方式：那四樣互相【需要】對方才成立。**

目前看起來確實互相需要（教材可驗證 ⟵ 執行 ⟵ 語義樹 ⟵ lift），
**而這個論證沒有被寫下來過。** 這比「和 TextBricks 的差別」更值得寫成一篇。
