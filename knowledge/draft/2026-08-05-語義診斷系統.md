# 語義診斷系統（Diagnostic as Projection）

> 日期：2026-08-05
> 怎麼冒出來的：整理願景文件時列為「創意構想」——尚未排入 Roadmap、尚未有完整設計。

## 核心洞察

**錯誤訊息本質上也是語義結構的一種投影**——它是對「語義結構與預期之間差距」的結構化呈現。

如果這個看法成立，診斷就不需要另一套資料結構：Diagnostic 掛在語義節點上。

```
SemanticNode
  ├── conceptId, props, children
  └── diagnostics: [
        { rule, severity, anchor: { nodeId, field? }, suggestions: [...] }
      ]
```

## 分析三層

1. **概念自身 constraint** — 節點層級，「我自己合不合法」（如：name 不可為空）
2. **關係規則** — 樹層級，「我和 parent/sibling 的關係對不對」（如：return 必須在 function 內）
3. **語言特有規則** — 語言模組層級（如：C++ const 語義）

核心只負責遍歷語義樹、依序執行三層、收集 Diagnostic。

## C++ 這種複雜語言怎麼辦：分層委派

- **Level 1 我們自己做** — 語義樹上就能判斷的結構性錯誤（缺 main、return 在函式外、break 不在 loop 內）。成本低、教育價值高。
- **Level 2 委派編譯器** — generate 出程式碼 → 餵給編譯器 → 用 `_lineBox` line tracking 映射回語義節點。型別系統、overload resolution 不需自己做。
- **Level 3 翻譯層** — 把編譯器 diagnostic 用 pattern matching 轉譯成分級教育訊息。社群可貢獻翻譯表，沒匹配到就 fallback 顯示原始訊息。

## 投影與漸進揭露

同一個 Diagnostic 在不同面板有不同呈現：程式碼面板紅色波浪底線、積木面板邊框變色、語義樹 badge、獨立錯誤清單面板。

訊息深度跟著 Level 走：

```
L0：「『加法』需要兩個數字，但右邊放的是文字」
L1：「型別不符：+ 的右運算元期望 int，收到 string」
L2+：「type mismatch: binary operator+ expects int operand, got const char*」
```

**修正建議**：Suggestion 是語義樹的 patch（SemanticPatch），不是文字。可投影成程式碼 diff 或積木面板的「點擊套用」按鈕。

## 架構位置

插在 lift 之後、投影之前。Diagnostic 只是語義樹上多掛了資料，現有 renderer 不認識就忽略。

```
程式碼 ──lift──→ SemanticTree ──analyze──→ SemanticTree + Diagnostics
                                              │
                        ┌───────────────┬──────┴──────┬──────────┐
                     code投影        block投影     tree投影   問題清單投影
```

## 缺一層：全樹流敏感約束（2026-08-05 補）

上面三層**裝不下 borrow check**。第 2 層是**局部結構**檢查（return 在不在 function 內、break 在不在 loop 內），但借用檢查是**流敏感**的——第 3 行的 move 殺掉第 5 行的 use，那是順序與生命週期，不是父子關係。

這條在加 Rust 時會變成阻斷（使用者已確認會加）。而且它和硬體 DRC 是**同一台機器**——電氣傳播也是流敏感的（誰在驅動、驅動到哪、有沒有衝突），且兩者的錯誤形狀一一對應：

| | 電氣 | Rust |
|---|---|---|
| 多重驅動 | `CONFLICT` | cannot borrow as mutable more than once |
| 無驅動 | `FLOATING` | use of moved / uninitialized value |

推導見 [concepts/元件](../concepts/元件.md)「守恆的兩種律」。**架構後果**：這一層屬於 kernel 的一條脊椎，**per-元件的膠囊裝不下全樹約束**——見 [元件膠囊重構](2026-08-05-元件膠囊重構.md)。

## 還沒想清楚的

- Level 2 需要在瀏覽器中跑編譯器（WASM clang？）還是遠端服務？前者體積成本高，後者破壞離線使用。
- 「現有 renderer 不認識就忽略」被寫成「向後相容」——但專案原則是[不做向後相容](../principles.md)。這裡該說的其實是「annotation 是開放集合，未知 key 忽略」，兩者不是同一件事，措辭需要修。
- 與 `confidence` / `degradationCause` 的關係未定：降級也是一種「與預期的差距」，是否該統一為 Diagnostic 的一種？
