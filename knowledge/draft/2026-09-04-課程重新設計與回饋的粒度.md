# 課程重新設計，與回饋的粒度

> 日期：2026-09-04
> 狀態：**設計未決**——出口是 vision 路線圖（要人拍板），不是直接清償。
> 怎麼冒出來的：使用者：「目前的課程好像都沒有用到積木或是流程，或是說連一個
> 截圖畫面都沒有，只有純文字描述，**這樣跟其他教材有什麼不一樣**？」
> 接著：「我希望課程對學生是有幫助的，**讓學生從小地方就知道自己做對做錯**」。

## 一、問題不是缺圖，是課文與工具【平行】

拿第 11 課看：讀完「for 把三樣東西放在同一行」＋一段程式碼，學生其實
**可以在記事本裡做完整堂課**。課文從頭到尾沒有一步需要三邊同步。

> **如果一堂課在紙上做得完，那它就是一本書；工具只是它旁邊的裝飾。**

🔴 所以判準不是「要不要加截圖」，而是：
**每一段課文都要問——這一段在紙上做得到嗎？做得到，它就不該是課文的主體。**

⚠️ 而**截圖是最糟的補法**：會腐爛、不是工具本身、而且製造 split attention（見 §三）。

## 二、工具給得起而紙給不起的，只有四樣

```
同一個東西的三種表徵，而且【即時連動】
執行看得見（主控台 · 變數 · 逐步 · 節點高亮）
鷹架可調（隱藏／淡的／完整）
接不住時誠實降級（灰積木保留原文）
```

課文的主體應該**只由這四樣構成**，其餘壓到最少。

## 三、理論——而它有一半在警告我們

### 支持的

- **認知負荷理論（Sweller）** 的三個推論剛好排成一條線：
  worked example（新手看範例勝過直接解題）→ **completion problem**（挖一塊的半成品，
  van Merriënboer）→ **faded worked example**（一步一步抽掉鷹架）。
  🔴 那三段**就是輔助輪的三段**，而鷹架三態已經是它的載體。
- **notional machine（du Boulay）**：新手最大的錯誤來源是**沒有可用的機器心智模型**。
  🟢 流程視圖 ＋ 變數面板 ＋ 逐步，**就是把那台想像中的機器畫出來**
  ——這是這個工具最被低估的教學價值。
- **PRIMM（Sentance & Waite）**：Predict → Run → Investigate → Modify → Make。
  中間三步**正是紙做不到的那三步**。
- **多重表徵（Ainsworth 的 DeFT）**：多表徵有效的**前提是它們被連結**
  ——而「即時同步」就是那個連結。

### ⚠️ 而理論給的兩個警告，我們現在正踩在上面

- **split-attention**：兩份要在腦中拼起來的資訊應該在空間上整合。
  「對照」把程式碼與積木並排而**不指出對應關係**，那不是幫助是負擔。
  🟢 跨視圖反白已經有了——**而課文從來沒教學生用它**。
- **redundancy**：同一件事用兩種形式**同時**呈現，在一種就夠時是**有害的**。
  → 第 1～3 課「三欄全開」可能是傷害。
- **expertise reversal**：對新手有效的鷹架，對已經會的人是干擾
  → **不撤的鷹架會從幫助變成傷害**（拆輪子的理論版本）。

> **三個視圖不是越多越好，而是【在對的時候各出現一次】。**

## 四、~~課程骨架~~ **語意波**（2026-09-05 重寫，見十八）

> 🪦 **這一節原本叫「課程骨架」，而那個名字在這個專案裡是壞的**：
> `骨架` 已經是「哪幾段組成程式」（`src/` 39 處），`鷹架` 是「骨架露多少」
> （37 處），而 `core/lesson.ts` 有一整段註解在教人別把那兩個搞混。
> **再塞一個「課程骨架」進去，是把一個已經很貴的區分再攪一次。**
>
> 撞號量過的還有：`流程`(42) `步驟`(15，而 `stepRecords` 是除錯的單步)
> `階段`(23) `路徑`(90) `章節`(＝一堂課，狀態列那顆 picker 逐字寫著「選擇章節」)。

### 原本的七步（保留為素材，而它不再是這一格的形狀）

```
① 完成的樣子   worked example
② 預測         PRIMM · 逼出投入      ✅ 已交付，而且是【執行閘門】不是課文步驟
③ 執行         立即回饋              ✅ 本來就有
④ 追蹤         notional machine      ✅ 變數面板／逐步本來就有
⑤ 改一處       低負荷的遷移
⑥ 完成題       completion problem    🟢 → 它有名字，叫 Parsons 題（見十八）
⑦ 自己做       transfer              ✅ 66 課的〈換你了〉
```

🔴 **扣掉已經內建的，這一格剩下的其實只有一件事**：課程說得出**版面**
——今天只有使用者切得動（[[拆輪子的曲線]] 量過）。

> **一個原本要靠「課程編排」才成立的教學步驟，變成了工具本身的行為
> ——那一步就不再需要被編排。**

### 而「什麼時候換一種看法」有一個比 PRIMM 更好的理由

**語意波**（Maton 的 LCT；已被英國 NCCE 列為十條教學原則之一）：
有效的課會**下沉（unpack）再上浮（repack）**，而**平的語意曲線教學效果差**。

🟢 而我們的三種投影**天生就是一條語意軸**：

```
程式碼      抽象、語意密度高
積木        中間——結構看得見
流程／執行   具體——它在跑什麼看得見
```

> **所以這一格不是「七個步驟」，是【一條波】：每個概念下沉一次、再上浮一次。**

而它給了一個**可檢查**的驗收判準：**這一課有沒有下沉再上浮？**
——比「七步都要有」好驗得多。

## 五、回饋的粒度——而三個空格的資料都已經在了

| 粒度 | 現在 | 它能說什麼 |
|---|---|---|
| 打字當下 | 🟢 語法錯、紅線 | 「這一行不合語法」 |
| 一行寫完 | 🟢 診斷 → Problems | 「`n` 沒有宣告」 |
| 🔴 積木有沒有長出來 | **有訊號、沒說法** | 「這一行我看不懂」——灰積木就是它 |
| 改一處之後 | 🟢 三邊同步本身 | 「你改的是不是你以為的那個」 |
| 按執行之前 | ✗ | 預測 → 比對 |
| 🔴 執行中 | **有資料、沒回饋** | 「這一步 `i` 變 3」「這一段從來沒跑到」 |
| 🔴 執行後 | **`check` 在，學生看不到** | 「你的輸出少了一行」 |
| 一整課之後 | ✗ | 「你這一課有 6 次是直接改程式碼的」 |

### 🔴 查證：`check` 比「沒有出口」更嚴重——它連型別都沒進來

```
lessons/*/lesson.json      每一課都有 "check": { "stdout": …, "stdin": [] }
src/core/lesson.ts         🔴 `Lesson` 介面裡【沒有 check】→ parseLesson 直接丟掉
唯二的讀者                 e2e/lessons.spec.ts:63 · audit-lessons（都從原始 JSON 讀）
```

**也就是說 app 根本不知道它存在。**
（形狀與「13 萬字課文沒有讀者」一模一樣：**東西在，缺的只是出口**。）

## 六、理論給回饋的兩條硬規矩

- **Hattie & Timperley** 的四個層次：針對**人**的回饋（讚美、分數、星星）**效果最差**；
  針對**任務**與**過程**的最好。
- **Kluger & DeNisi**：回饋介入**有時候讓表現變差**——而變差的幾乎都是把注意力
  引到「我這個人如何」。

> **回饋要說的是「你的迴圈少跑了一次」，不是「你答錯了」，更不是「再加油」。**

＋ **Shute**：新手要**直接**（directive）、進階要**提示**（facilitative）
→ 🟢 **回饋本身也是一個會退場的鷹架**，掛在拆輪子的曲線上。

⚠️ 用詞：初學者的多數「錯」其實是**還沒完成**。用「**還沒**」不要用「**錯**」
——前者指向下一步，後者指向自己。

## 七、最值錢的三個（照投報率）

### ① 裁判 ＋ 輸出 diff

不要 ✅／❌，要並排：

```
你的輸出        這一課要的
1 2 3          1 2 3
4 5 6          4 5 6
               ← 少了這一行
```

🔴 **裁判只判輸出。結構（用 while 還是 for）只能給建議、不能判對錯**
——否則變成「猜老師心裡的答案」，那是自動評分最經典的失敗。

> **輸出對了就是對了。你用了不一樣的寫法，那是另一個話題，不是錯。**

### ② 🔴 執行覆蓋：跑完之後，**沒被跑到的積木標出來**

初學者的 bug 有壓倒性比例是這兩種：**這一段從來沒跑到**、**跑的次數不對**。
而逐節點的執行事件已經有了（`CodeView.onExecutionAtNode`）。

`return` 後面的程式碼、永遠不成立的 `if`、根本沒進去的迴圈——**一眼就看見**。
我認為這是這個工具給得起、而其他教材給不了的回饋裡**最強的一個**。

### ③ 迴圈跑了幾次

執行完在迴圈積木旁標一個小數字 `×4`。預期 5 而看到 4，
**那一瞬間就懂了什麼叫差一錯誤**——notional machine 最便宜的一種形式。

## 八、再上一層：預測要有介面

現在 Predict 只能寫在課文裡，而**沒有地方接住那個猜測**。

一格「你猜輸出是什麼」→ 按執行 → 直接比對，好處是三個：
它本身是**提取練習** · 它把回饋從「對／錯」變成「**你以為的與實際的差**」·
⚠️ 而它必須在執行**之前**——猜完才准跑，否則變成抄答案。

> **最有價值的回饋不是「答案是什麼」，是「你的想法與實際差在哪」。**

## 九、⚠️ 三個刻意不做

1. **分數／星星／連續天數**——見 §六，它把注意力從程式移到自己
2. **紅色 ✕ 淹沒畫面**——對初學者是勸退，不是資訊
3. **自動幫他改**——那是把學習拿走。可以說「第 4 行的 `i` 沒有變」，
   不要說「我幫你加上 `i++` 了」

## 十、🔴 它們是同一份資料，所以要一起設計

```
執行事件（哪個節點跑過、幾次）  → 執行覆蓋 · 迴圈次數
編輯來源（積木還是程式碼）      → 拆輪子的指標 · 就地提示
題目通過                       → 裁判 · 進度 · 下一題
```

**該有一層薄的「學習訊號」**，而不是各做各的——否則會長出三套各自統計、
各自存檔、各自過期的東西。
⚠️ 而它**只留在本機**（送出去就破〈離線可用〉的硬性零）。

### 🟡 而第三個先落地了（2026-09-04），刻意**沒有**一次抽象成那一層

`core/progress.ts` 只做「哪幾題過了」，自己一格 `localStorage`
（key：`semorphe-progress`，與 `SavedState` 分開——匯出一份作品給同學，
不該把「你第 3 題還沒過」一起送出去）。

🔴 **先只做第三個**：把三件事一次抽象成「學習訊號」會長出一個什麼都裝得下的
介面，而那是**假的父概念**（沒有剪枝力，見 knowie 的判準）。
第二個（編輯來源）落地時再看它們像不像。

⚠️ 而它必須**清得掉**——一台電腦換一班學生是這個工具最可能的部署方式。
機制在（`clearProgress()`），**入口還沒有**（見十二.5）。

第五刀  ~~課程骨架 ＋ 前 5 課試點~~  🔄 **2026-09-05 換掉了**（見十八）

每一刀都要問一句：**它說的是任務、過程，還是這個人？** 說到人就砍掉。

## 十三、🔴 第一刀交出去之後，使用者當場推翻了它的形狀（2026-09-04 稍晚）

> 「課程應該除了課程題目之外，還會有一些練習題，
> **這樣去比對結果不就沒有辦法做練習題了**？」

一課一個 `check` 的時候，學生一開始做練習題，寫的就是**另一支程式**：

```
學生：認真在做練習 2
裁判：還沒對——你的輸出是「1 2 3」，這一課要的是「Hello!」
```

> **一個會在學生做對事情時說他錯的裁判，比沒有裁判更糟**
> ——它教會學生「這個勾沒有意義」。

⚠️ 所以這**不是**「之後再加練習題」，是**第一刀那個設計本身就不成立**。

### 使用者給的解法，與它真正的成本

> 「就是在開始執行前先問他是對應到哪一題，還是先不選擇題目純練習」

問他，就解掉了「系統分不出【卡住】與【在玩】」——而**問在執行前**太貴：
執行是整個工具裡按最多次的按鈕（一堂課幾十次），每次跳框他會開始亂選。

> **同一個問題，問一次而答案一直看得見，
> 與每次都問，拿到的資訊一樣而成本差一個數量級。**

🟢 落點：狀態列上一格——目標 → 課程 → 章節 → **題目**，四格同形。
使用者拍板：**只有選了課程與章節才畫，預設是「跟著做」那一題**。

### 由此長出的一條界線（⚠️ 它想升格成 derived principle，而那要人拍板）

```
「有 1 塊積木這一次沒有被跑到」   描述。只是在說發生了什麼 → 永遠給
「還沒對——你少了第 2 行」        評價。在說對錯      → 選了題目才給
```

> **描述性的回饋永遠可以給；評價性的回饋要先問過。**

它答得出一個原本沒有答案的問題：**「沒有命中任何一題」是兩種意思**
（他卡住了／他只是在玩），而**系統分不出來**——所以由他釘的那一題決定要不要開口。

### 三個「回饋的形狀」上的決定（都已落地）

- **只標最外層那一塊**：`cout << "never" << endl;` 在樹裡是三顆節點，
  第一版說「有 3 塊沒跑到」——**而學生眼裡那是一句話**。
  > 回饋的計數單位要跟**使用者的知覺**一致，不是跟資料結構一致。
- **祝賀要說出是哪一題**：「✅ 你完成了〈練習 1〉」比「✅ 對了」多了一件事
  ——他知道自己完成的是什麼。
- **不自動切下一題**：自動切會讓他下一次執行**突然被另一題評價**，
  而他不知道何時換的。
  > 一個會自己改變「我現在在做什麼」的系統，會讓使用者失去對回饋的信任
  > ——因為他不知道那句話在對誰說。

### 🪦 而開瀏覽器截圖抓到了第二刀的一個假警報

一支**完全正確**的 `sum = sum + n;` 被標了兩塊——因為**指定的左邊那顆變數
不走執行，走的是 lvalue 解析**（`interpreter/lvalue.ts` 的 `resolvePlace`），
於是它從來不會進 `visited`。

> **`visited` 記的是「執行器走過誰」，而那不等於「這一段跑了沒有」
> ——有些節點是被【解析】的，不是被【執行】的。**

⚠️ 而修法**不在直譯器那側**（再補一個記錄點，下一個非執行路徑仍會漏），
在**粒度**：只標**語句**，不標運算式。`return` 後面的程式碼、不成立的 `if`、
沒進去的迴圈——初學者的那三種 bug **全部是語句**。

> **一個在正確的程式上發出警告的警告，比沒有那個警告更糟
> ——它教會學生把警告當背景雜訊。**

🔴 **而它是全套 6176 綠 ＋ 250 條 e2e 綠之後，靠一張截圖抓到的**
——那正是 `feedback_browser_check_after_refactor` 說的那件事。

### 🔴 而它逼出一條新的護欄：期望輸出要有人跑過

一份手打的 `check.stdout` 錯一個空格，那一題的裁判就會對每一個做對的學生說他錯。

> **一個沒有人跑過的期望輸出，是一個還沒被發現的、會說錯話的裁判。**

落地成 `lessons/<課>/solutions/<題目 id>.<副檔名>`（**不進課文、學生點不到**）
＋ 兩道護欄：`audit-lessons` 驗檔案在不在，`e2e/lessons.spec.ts` 真的跑一次。

## 十四、第三刀：迴圈跑了幾次（2026-09-04）

初學者的另一種 bug 是「跑的次數不對」（差一錯誤），而那是**看不見的**：
程式跑完了、沒有錯誤、輸出少一行，而他只能一行一行讀。

### 🔴 迴圈【自己】只被走一次

```
while 那一顆     executeNode 只走一次     → 1
它身體裡的兩句   每一圈都走               → 5
「跑了幾次」     身體 ÷ 自己              → ×5
巢狀的內層       自己 3 · 身體 12         → ×4   ← 倍數才對
                                           ×12 會讓學生想「我明明寫 4」
```

### 🟢 而這一刀【一份新的判斷都沒寫】

```
哪一塊是迴圈    component.json 的 control_flow: "loop"（五顆都有宣告）
哪一格是身體    bodySlotsOf()（它還認得 41 顆用物件寫法宣告的）
```

⚠️ 我第一版兩份都自己判了一次，而**兩份都錯**：

- 「一個孩子跑得比自己多的節點就是重複器」——會把**被呼叫 5 次的函式**
  標成 `×5`。那句話不假，卻不是「迴圈跑了幾次」。
- `slot === 'condition'`——而 `for` 的槽名是 `cond`，`loop_count` 是 `from`／`to`。
  症狀不是報錯：巢狀 `for` 標成 `×5`／`×4`（正確是 3／4）
  ——**一個看起來很合理的錯數字**。

> **一份「哪些格子裝語句」的清單，只要寫第二份，
> 第二份就會漏掉那 41 顆用另一種寫法宣告的。**

### ⚠️ 而「畫在哪」改了三次，每一次都是開瀏覽器看出來的

```
① 積木右邊（width + 6）   飄在空白處——那個 width 是整塊 C 形積木的寬
② 標題列左邊              巢狀時正好蓋在父迴圈畫「執行」的地方
③ 左邊的一條槽（像行號）  ✅ 垂直對齊自己那一列，水平排在整塊程式左邊
```

外加一次顏色：琥珀色的字落在**橘色的迴圈積木**上，而迴圈正是這個功能
**唯一會標的積木**——外層那顆落在深色畫布上看得一清二楚，內層那顆等於沒畫。

> **一個只在「它旁邊剛好是背景色」時才看得見的標註，
> 在它最該出現的地方——巢狀的內層——正好看不見。**

🔴 三次都是**單元測試與 e2e 全綠**的情況下，靠**看**發現的。

### ⚠️ 主控台【不再說一次】

數字已經標在那顆迴圈上了。重複說一遍會讓主控台變成一份沒有人讀的日誌
——而「沒跑到」那一句留著，因為它指的東西**可能在畫面外**。

## 十五、第四刀：跑之前先猜一下（2026-09-04）

使用者：「預測的介面或許可以是選擇題、填充題或是直接全預測題，
**總之目的是要使用者想過就是**」。

🔴 那句話把設計推掉了一半：**不是評量，是承諾**。沒有分數、沒有猜對率、
沒有全班統計——那三樣都會把「想過」變成「被評」。

### 🟢 而預測不是新功能，是【已經有的每一種回饋的前半段】

```
輸出        → 猜輸出        揭曉：主控台 ＋ compareOutput   ✅ 這一刀
跑幾次      → 猜跑幾次      揭曉：×N 徽章                   ✅ 這一刀
哪些沒跑到  → 猜哪些沒跑到  揭曉：琥珀虛線框                 還沒接
變數的值    → 猜最後的值    揭曉：變數面板                   還沒接
```

前三刀把「揭曉」那一半都做完了，所以這一刀**製作成本是零**：
答案分別是 `check.stdout` 與執行時本來就在數的次數，**66 課一個字都沒改**。

### 三種形式是【難度】不是口味

```
選擇題   最低承諾   一次點擊   新手 · 輸出很長 · 這個概念第一次出現
填充題   中
全預測   最高承諾   輸出短（≤ 3 行）· 他已經熟了
```

⚠️ 而**選擇題不在這一刀**：它的價值全在「這個干擾項是哪個誤解」
（`1 2 3 4 5` ＝ 以為 endl 是空格；`1 2 3 4` ＝ 差一），而那要一課一課想。
一個自動生成的干擾項只是一個隨機的錯答案，學生選完你也不知道要跟他說什麼。

### 自動判定的三條

```
恰好一顆迴圈       → 猜跑幾次   答案是一個數字，而它正是差一錯誤住的地方
沒有迴圈、輸出短   → 猜輸出
其餘               → 不問
```

🔴 **多顆迴圈不問「跑幾次」**：「哪一顆」本身有歧義，而一個有歧義的問句
拿到的答案沒有意義。
🔴 **輸出超過三行不問**：那不是預測，那是抄寫——工作記憶會爆掉，
而他學到的是「這個框很煩」。

### ⚠️ 而「不強迫」是刻意的

跳過的按鈕一直在，而且**不准藏起來**。強迫產生的是 `aaa`，不是思考
——而那比不問更糟：它教會學生「這個框是一個要繞過的關卡」。

能做的是讓猜**極便宜**（一個數字），與讓報酬**看得見**：

```
猜對了   「🎯 你猜對了——你腦子裡那台機器是對的」
          🔴 它【比程式跑對更值得慶祝】
猜錯了   並排，而【不說「錯」】：「機器做的跟你想的不一樣——差在這裡」
```

> **一個預測錯了的學生，比一個沒有預測的學生更接近學會。**

### 🪦 而它讓【66 支既有的課程測試】同時變紅

按了執行就等輸出的測試，現在會卡在問句上。

> **一個「開跑之前先問人」的機制，會讓每一個【按了執行就等結果】的既有測試
> 同時失效——而它們紅得看起來像是那 66 堂課壞了。**

⚠️ 修法**不是把機制關掉**，是給它們一支 `skipPredictionIfAsked`
——也就是讓那些測試**明說「我不是在扮演一個學生」**。
真的在驗預測的那三支會自己填答案，不走那一支。

### 三個接線上的決定

- **問在主控台，不是跳一個框**：答案等一下就出現在那裡，
  **問題與揭曉在同一個地方**，diff 才會落在他剛才寫的那句話底下
- **執行器多一個可省略的 `beforeRun` 鉤子**，形狀抄 `pauseForUnrecognized`
  > **要停下來問人的事，用一個鉤子，不是把那件事搬進執行器。**
  執行器仍然不知道有「課程」「題目」「預測」這些東西
- **只在程式改過之後的第一次執行問**：跑過一次他就知道答案了，
  再問是儀式，而學生一眼看穿（`programSignature`，⚠️ 屬性值要算進去——
  `i < 3` 改成 `i < 4` 是另一支程式，而差一錯誤正住在那裡）

## 十七、程式碼 ↔ 積木的對照（2026-09-05）

使用者：「我比較在意的是程式碼跟積木或是節點的對照，
**目前使用者幾乎沒有辦法從課程了解積木長怎樣**」。

### 🔴 而查證的結果是：那個對照【早就做好了】

```
點一顆積木        → 程式碼那幾行反白 ＋ 流程圖那個節點亮
游標移到某一行    → 那顆積木亮 ＋ 流程圖亮
點流程圖一個節點  → 另外兩邊亮

`app.ts` 的 `linkNode`。而**66 份課文裡提到這件事的有 0 份**（grep 過）。

> **這個專案第四次遇到同一個形狀**：13 萬字的課文沒有出口、`check.stdout`
> 沒進型別、`control_flow: loop` 沒有消費者——**而現在是「三向連動做好了，

### 理論：並排 ≠ 對照

多重表徵（Ainsworth 的 DeFT）：

> **兩個表徵並排放著，不會自己教會任何人它們是同一個東西。**

學習者需要**被支持著做那個翻譯**。

### 交付

```

② 第 1 課的預測改成選擇題，而干擾項問的是【引號會不會被印出來】
③ 靜態頁的逐行對照圖（64 課，建置期產生 ＋ 第一百零二條護欄）

### ⚠️ 而 ③ 撞到一條硬性零，那一撞讓它變好了

課文頁**不得載入任何 JavaScript**（`audit-lesson-pages` ④）。
我原本做的是「滑過一行 → 那塊積木亮」，而它需要一小段腳本。**我沒有繞過那條規矩。**

🟢 換成**把行號直接畫進積木旁邊**（❶❷❸…），讀者用編號配對。

> **一個需要滑鼠才成立的對照，在紙上、在手機上、在讀螢幕的人那裡
> 都不成立——而編號到處都成立。**

而它正是 split-attention 研究說的 integrated format——**規矩把設計逼好了**。

### 三個踩到的坑

- **opacity 在巢狀群組上會相乘**：「其餘變淡」讓要亮的那一塊也淡掉
  （它住在其餘裡面）。改成只給光圈，最後連光圈都不需要了
- **一顆積木一個號碼，而那個號碼是它【開始】的那一行**：
  第一版每行各標一次、後蓋前，於是 `main` 被標成 ⑧——它收尾的大括號那一行
- **內聯 SVG 的 `class` 與 `id` 都要拿掉**：class 名裡的 `blockly` 會讓
  「課文頁不得提到編輯器的包」當場紅（而規矩擋的是**載入**，不是字串）；
  自動 id 則會在一頁多圖時**重複**——那是不合法的 HTML，而瀏覽器不會抱怨

### 🔴 而它翻出了第三個缺陷：兩課的積木畫面是【空白的】

  宣告了 renderMapping.dynamicRules 的 inputPattern: "CTOR_{i}"
  而【沒有任何人照著它建那些 input】

  → 整個工作區載入失敗 ⟹ 學生看到一張空白的積木畫布

> **一顆積木少了一個宣告好的插槽，壞掉的不是那一顆——是整張畫布。**

⚠️ 整套測試看不到它：那兩課的 e2e 驗的是「樹對不對」與「跑出來對不對」，
**兩者都不看積木**。第一百零二條護欄的棘輪是它今天唯一的哨兵（缺 2，只准下降）。

### ✅ 修好了（66/66），而它在同一天被**驗錯了兩次**

```
第一次   「修好了」   → 量在舊的 preview 上（reuseExistingServer 接上還沒收掉的）
第二次   「沒修好」   → 也量在舊的 preview 上，於是我把對的改動收回去了

### 🔴 而它露出一個【本來看不到】的缺陷：`0x27` 變成 `39`

`LiquidCrystal_I2C lcd(0x27, 16, 2);` 產回去是 `lcd(39, 16, 2);`

⚠️ 它**在此之前看不到**：那顆積木根本畫不出來，所以沒有人走過那一趟。
而 `0x27` 是 I2C 位址的標準寫法，換成 `39` 學生會認不得自己的程式。

> **一個「不記得原文形式」的 round-trip，會在使用者沒有要求的時候改掉他的檔案**
> ——這是那顆膠囊的 `decl_type` 註解裡寫過的同一條，而這次是數字的進位。

🪦 舊的分析（保留，因為它記著一個我犯過的推理錯誤）：

我加了 `builder: "variadic"`，量到「14 塊積木、round-trip 逐字相同」，
於是把護欄寫成硬性零並宣告修復。**乾淨重來之後：仍然 0 塊積木。**

> **一個「我剛剛量到它好了」的結論，如果沒有先確認量的是新的那一份，
> 它會讓一個沒修好的東西帶著「已修復」的標籤上線。**

🔴 已收回那個改動（留著會讓第一百零三條護欄回報 0 個孤兒，而那三顆還壞著），
護欄退成棘輪（3，只准下降），對照的棘輪回到 2。

我在這裡寫過「修法**不是**加 `builder: "variadic"`，那個建構器會把 `NAME` 與
`DECL_TYPE` 弄丟」。去讀那份實作之後發現：`block-registrar` 有**兩支**——

```

args0 是空   從零建整顆                                    ← cpp_vector_declare 的坑

> **一條「這個修法行不通」的筆記，如果沒有去讀那份實作，
> 它擋掉的可能是唯一對的那一條路。**

### 🔴 而那一刀當場引入了另一個缺陷，被第五十九條護欄抓住

`builder` 那條路的 `continue` **跳過了**「下拉不得靜默丟掉不認得的值」

（`LiquidCrystal` vs `LiquidCrystal_I2C`，建構參數完全不同）。

> **一個「在最後一條路上做的收尾」，會被每一個提前 `continue` 的分支跳過
> ——而那些分支正是特別的那幾顆。**

⚠️ 而那是一個**既有的洞**，四個分支全部有（`branchList`／`altLayout`／
`paramList`／`variadic`）——只是今天才第一次有一顆帶著開放值域的下拉走進去。
四段收成一支 `jsonInitFor`，順帶把腳位常數的綁定也補回那四條路。

🟢 **第一百零三條護欄**（硬性零）：宣告了 `dynamicRules.inputPattern` 而沒有人建
那些 input 的，一顆都不准有。而第一百零二條的棘輪同時**推到 0**（66/66 課有對照）。

## 十八、🔴 去查了研究，而它把第五刀換掉了（2026-09-05）

## 十六、🔴 而寫練習題【翻出了兩個直譯器缺陷】（2026-09-04）

兩個都是寫 `c-bridge` 的練習時撞到的，而兩個的症狀都**不指向真正的原因**：

```
swap(&x, &y)      「這個東西不能被指定值」
                  真因：使用者自己定義的 swap 被 lift 成內建的 cpp:var_swap
                  ——他的函式從頭到尾沒有被呼叫過

struct Point ps[3]  「變數 '（不是一個結構）' 尚未宣告」
                    真因：每一格是 defaultValue('struct Point') ＝ 一個 0
                    ——那句話指向的東西根本不存在於程式裡
```

> **一個名字樣式如果不看「這個名字在這支程式裡有沒有被使用者自己定義」，
> 它就會把使用者的函式偷換成內建的那一顆。**

> **一個「型別名我不認得，那就給 0」的預設值，
> 會在後面某一步炸出一個【與真正原因無關】的訊息。**

⚠️ 第一個的修法擋在**路由器**（`tryCallBranches`），不是在 28 個名字樣式裡
各寫一次——**名字的解析順序是「去問誰」，那是路由器的知識**。

🟢 而它們是怎麼被發現的：**去寫那 42 份參考解答，然後真的跑一次**。
兩個都活了很久，而 66 堂課的課文從來沒有踩到——因為課文示範的是
「單一結構」與「內建的 swap」。

> **一份「學生會寫、而課文沒寫」的程式，是這個專案最好的測試語料
> ——而練習題正好就是那種程式。**：機制在了，而 66 課裡只有 3 課宣告了 `tasks`
   （cpp-beginner 的 01／02／10）。其餘是**課程的工作**，不是機制的工作
