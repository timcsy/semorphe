# 已知的工程待解問題

> 日期：2026-03-11
> 怎麼冒出來的：第一性原理附錄累積下來的清單。**邏輯硬邊界**（語用分析精確度、巨集、語義阻抗）已定案並移入 [降級與認知邊界](../concepts/降級與認知邊界.md) 和 [元件代數](../concepts/元件代數.md)；留在這裡的是**還沒有定論**的工程問題。

## 註解歸屬歧義

拖拽積木時相鄰註解是否自動跟隨？需要 Block Style 層的吸附邏輯。

獨立註解已定為平級節點（見 [墓碑目錄](../history/014-墓碑目錄.md)），但「使用者拖走一個語句時，上面那行註解該不該跟著走」仍未決——這是 UX 判斷，不是結構問題。

## 符號表的汙染追蹤

`SemanticNode.taint` 欄位已定義，但**執行時 raw_code 的汙染擴散尚未在語義結構中顯式標記傳播路徑**。目前只有靜態的 `propagatedFrom`，執行期的擴散還是隱式的。

## lift() 效能

目前轉換是使用者主動觸發，全量 lift 在教學場景不構成瓶頸。未來可考慮增量 parse + 延遲 lift。**尚未有實測數據支撐任何優化決定**。

## Scope 3-5 的狀態空間爆炸

增量更新演算法是效能瓶頸。實作優先序：Scope 0-2（已實現）→ Scope 3 → Scope 4-5。

可能需要**語義快取層**：對穩定子圖（未修改的模組）快取語義結構和索引，只對變更傳播路徑執行增量 lift。快取失效粒度以**模組**為單位，避免節點級失效帶來的追蹤開銷。

## 語義契約的驗證成本

初期只覆蓋 L0-L1 概念，L2 按需補充，跨語言 constraints 可由 LLM 輔助生成初稿。**「初稿由 LLM 生成」與三維錨定的 Agency 簽署要求如何具體結合，尚未設計流程。**

## 執行後端的橋接開銷

WASM 有序列化開銷，Remote 有網路延遲，WebGPU 有 GPU 同步代價。**正確的粒度是「子樹」而非「節點」**——這一點已有共識，但切分子樹的判準未定。JS native 因零 bridge 開銷特別適合大量小型運算。

## 語義套件的工程約束

- 執行他人的程式需要**沙箱隔離**
- 語義契約需要驗證機制（屬性測試）
- 執行體應受**語義沙箱**約束——副作用必須符合語義契約的宣告，否則拒絕執行，以保護時空旅行除錯的完整性（與 Virtual I/O Layer 統一為執行驗證層）

## 語義套件的版本一致性

多個使用者引用同一套件的不同版本時（老師更新 v1→v2，學生仍引用 v1），需要**語義契約的相容性檢查**——比文字原始碼的版本管理更難，因為要比較的是契約而非 diff。

## 語義 Diff 與版本控制

傳統版本控制基於文字行 diff，但 R1 投影變動（Code Style 切換）會產生大量文字差異而語義差異為零。語義層的版本控制應基於**語義樹 diff**，使 style 變更 = diff 0。

挑戰：序列化格式需要穩定（**節點 ID 不隨重新 lift 而改變**）、merge 演算法需要理解樹結構而非行結構。

> 節點 ID 穩定性在階段 5b（`021-semantic-node-identity`）已部分完成，SemanticDiff 演算法原型延後至階段 9.2。

## 不透明節點的錯誤回溯（Error Projection）

opaque 節點的 runtime error 發生在編譯執行的內部——錯誤堆疊只有底層細節（WASM trap、segfault），無法直接映射回語義節點。

需要一個**錯誤投影層**：執行體在語義契約中宣告可能的錯誤類型，runtime error 透過錯誤映射表歸因到語義節點，再投影到 L0 積木視圖提供有意義的建議（而非「WASM unreachable executed」）。

## Pattern 依賴的教育反噬

降級視覺必須區分原因（錯誤 / 系統能力不足 / 非標準但正確），防止鷹架變成認知牢籠——**這條已定案**，見 [降級與認知邊界](../concepts/降級與認知邊界.md)。

留在這裡的是長期方向：**LLM 輔助的語用分析可擴大 pattern 覆蓋率**，但擴大到什麼程度才算夠、以及擴大後如何避免 pattern 庫變成無人維護的殭屍規則，尚無答案。

### 診斷升級（同日）：不是「容差用錯情境」，是**降級這條路上沒有量測點**

第一版的診斷寫「情境容差被用到別的用途去」。更準的說法是控制上的：

> **降級是開環的。** 它**刻意產生一個不等於真實的東西**，
> 而**沒有任何地方量那個差**。

沒有量測 → 沒有回饋 → 誤差一路累積到執行才炸。

而 semorphe 其餘部分是**閉環**的：雙向投影就是誤差量測，「⇄ 自動」把回饋
週期壓到每次編輯——**這正是它敢用有損轉換而不出事的原因**。降級是少數
幾條開環的路之一（另一條是存檔）。

### 成因比「開環」還糟：**降級就地改寫了真實**（2026-08-09 查到）

`sync-controller.ts` 的 `downgradeConceptsForLevel` 是**就地改寫**的，
而 `this.currentTree` 指向同一個物件。所以降級不只是沒被量——
**它把真實覆寫掉了**。執行拿到的就是 `int v;`。

> 根公理是「唯一真實，各式投影」。而這裡是**投影寫回了真實**。

**修法**（2026-08-09）：降級只作用在顯示用的**深拷貝**上，原樹保持真實。
瀏覽器實測確認：原本 `RUNTIME_ERR_TYPE_MISMATCH`，現在輸出 `42 42 42`。

釘住它的測試：`tests/integration/degrade-does-not-mutate-truth.test.ts`，
含一支**反向**測試（刻意示範就地降級會破壞真實）——沒有那一支，
「拷貝」會在某次重構中被當成多餘的開銷刪掉。

見 [等價的觀察集與回饋](../episodes/2026-08-08-等價的觀察集與回饋.md)。

### ⚠️ 2026-08-11 實測：**那個修法沒有涵蓋存檔這條路**

`spec 116` 的 T004 在瀏覽器裡錄一份真實存檔（用「初學 C++」課程 ＋ `vector`），
存檔後重載，按執行——**又是 `RUNTIME_ERR_TYPE_MISMATCH: array`**。

而根因不在投影，**在存檔本身**：

```
存檔的 tree ：cpp:var_declare        ← 不是 cpp:vector_declare
存檔的 code ：int v;                  ← 不是 vector<int> v;
```

> **降級的結果被寫進了存檔。**
> 使用者存了一份用到 `vector` 的程式，**真實就永久地遺失了**
> ——重載之後不論換什麼課程都救不回來。

**根因比「修法沒覆蓋存檔」更準**（2026-08-11 追查）：

`sync-controller.ts` 的 **code→blocks** 方向是對的——第 270 行
`this.currentTree = tree` 存的是**真實**，降級只作用在 `cloneTree` 出來的顯示樹上。

而 **blocks→code** 方向（第 179-180 行）：

```ts

this.currentTree = tree            // ← 它成為真實
```

> **降級的視圖被使用者動一下，就變成了真實。**

#### ✅ 已修（2026-08-11 同日）

可行是因為 `_blockIdToNodeId` 本來就在來回轉換保住原 nodeId。

⚠️ **還原有一條界線**：只還原「當初真的被降級過、而且現在仍然是那個降級目標」的節點

### 仍未決：降級本身該不該閉環

**未決的是設計問題，不是修法**：

| 選項 | 代價 |
|---|---|
| 降級到父概念（現況） | 語義不等價，產出的程式跑不動——**使用者看到的是一個壞掉的東西** |
| 拒絕降級、顯示 raw_code | 誠實，但學生看到一坨看不懂的原始碼 |
| 自動解鎖用到的關卡 | 破壞漸進揭露的意圖 |
| 降級但標記「這裡不完整」 | 要有一套「不完整」的視覺語彙 |

`concepts/降級與認知邊界.md` 有降級的原則，但它談的是**辨識不出來**時的降級，
沒有涵蓋**刻意隱藏**造成的降級。那兩者的正確行為可能不同——
辨識不出來時 raw_code 是誠實的；刻意隱藏時 raw_code 等於「這一關你看不懂」。

> **一個護欄的空白**：現行 30 條護欄沒有一條在「課程可見集合」下跑完備性。
> 換句話說——**沒有人在那個觀察集下觀察過**。「全綠」只說明在現有觀察集下
> 沒有差別，而測試的作用正是**定義「相同」的解析度**。
> 那正是這顆 bug 活下來的原因。
