# 事前說得出保證——而程式只是第一個域

> 日期：2026-09-26
> 怎麼冒出來的：使用者在讀完整理過的 vision 之後，連續三則把目標拉大了兩層。
>
> 🟡 **狀態：定位已表態，範圍未排程。** 本檔記的是**那個目標的形狀與它的否認**。
> ⚠️ 照本庫的體例不寫完成條件。

---

## 使用者的三句原話，而它們一層比一層大

> ①「我最終的目標是希望 semorphe 可以成為 **vericoding 的先鋒**。」
> ②「其實我想要的應該**不只是 vericoding，這只是在程式的領域**。我希望像是 Claude Code
> 可以把 Vibe Coding 的精神擴散到其他領域一樣，**我可以在其他領域安全的操作**是我的目標。」
> ③「至於教育，我認為這是**銜接這工具與人類心智認知的一個介面**。」

## 一般形式，一句話

> **在一個試錯很貴或不可逆的領域裡，事前說得出保證。**

而 **vericoding 是它在軟體域的實例，不是終點。**

## 🔴 而「像 Claude Code 一樣擴散」講的是**起家的順序**（2026-09-26 更正我的誤讀）

我原本把那個類比讀成「機制會不會轉移」，並寫了一整節反駁它。**那是在反駁一個沒有被提出的主張。**
使用者的原意是**起家的順序**：

```
Claude     Claude Code（程式）起家 → 延伸到 Design 等其他領域
Semorphe   vericoding（程式）起家 → 延伸到其他領域
```

### 它有兩個推論，而兩個都對得上我們已有的讀數

**① 起家不是「先做通用再收窄」，是先在一個域做到能用——而那個域要挑「使用者最會抱怨」的。**

Claude Code 的使用者是開發者（回饋最快、最敢罵）。vericoding 的使用者也是開發者。

⚠️ **而我們今天真實的使用者是學生**——回饋最慢的那一批。而這件事今天有讀數：
學生的那幾筆回饋是這個專案**第一次拿到「真實學生」這個母體**，而在那之前每一次驗收的
母體都是我寫的測試、別人寫的完整程式、我自己點的那條路。

> **一個「測試全綠」的產品，它綠的範圍等於它想像得到的使用者。**

**② 延伸出去的時候，帶出去的是什麼？**對 Claude 是模型能力；對我們是**協定**。

🟢 而那一點**已經驗證過**：填 18 個域，而**連續六個域只長詞彙，結構不動**。
⟹ 那份填寫不是為了完備，**它就是「延伸得出去」的證據**。

## ⚠️ 而「換域時什麼會變」是一個獨立的觀察，不是對那個類比的更正

填 18 個域量到的那張表仍然成立，而它講的是**延伸之後**要面對什麼，不是起家該怎麼起：

```
軟體    每次編輯      L2（取樣驗證）便宜
硬體    分鐘（燒錄）   L2 貴
3D      小時（列印）   L2 極稀缺
機器人  🔴 不可逆      L2 【不存在】—— 撞壞了沒有第二次
```

> **一個域的迴圈越慢，「事前保證」就越不是奢侈品，而是唯一剩下的辦法。**

⟹ 所以延伸的順序不是隨意的：**迴圈越慢的域，越晚進得去，而它也越需要這套東西。**

## 🟢 而框架裡已經有五塊，都是為那件事長出來的

```
契約（pre/post/invariants）   18 個域填過,而第十三～十八個域只長詞彙 ⟹ 域中立
judge 的閉集                  `reference` 對硬體是【實體板子】,對 3D 是【列印出來的東西】
severity                     逐字：「不可逆 ⟹ L1 沒有用」
組裝（DRC · 預算 · 全網不變量）  那就是硬體的安全檢查
判定的範圍                    一個點 · 一段區間 · 🔴 一個【效期】（ML 逼出來的）
```

🔴 **而唯一沒有主人的那一格，正好是物理域第一個會撞到的**：

```
結構 → cella · 資源 → cella · 守恆 → 求解器 · 時序 → cella 的 timed（今天 0 條）
🔴 誤差／漂移 → 【沒有人】
```

公差累積（3D）· 數值漂移（ODE）· 感測器溫漂——這一族的契約不是 `x > 0` 是 `|err| ≤ δ`，
而**布林謂詞裝不下它**（塞進 invariant 會得到一條「永遠為真直到突然為假」的謂詞）。

## 🔴 兩個「安全」不能混，而混了的代價在物理域是一台機器

```
驗證意義上的安全   程式符合規格
物理意義上的安全   不會燒掉 · 不會撞壞 · 不會傷人
```

**第二個不能只靠第一個。**而這件事我們自己的 draft 已經寫過，逐字：

> 🔴 不可逆 → L1 沒有用 —— **L3，或者【物理上的攔截】**（限位開關、力矩上限）

⟹ **一個軟體的保證不構成物理的安全。**

⚠️ 而這句否認要跟著那個目標一起出現，**因為「事前說得出保證」很容易被讀成過度承諾**
——而在軟體域讀成過度承諾的代價是一支跑錯的程式，在機器人域是一台壞掉的機器。

🔴 **而更深的那一層已經寫下**（§七之五）：

> **保證對齊不是系統的責任，但「對齊壞了的時候有沒有東西會變紅」是。**

## 🟢 ③ 教育不是競爭線，它是 vericoding 缺的那一半

```
Vericoding 有的   規格 · 驗證器 · 可驗證的程式碼
🔴 Vericoding 缺的  給【人】看的那一面
```

**Dafny 滿是 invariant 的程式碼讀不下去，不是因為它太嚴謹，是因為它沒有人面的投影。**

⟹ 於是 `漸進揭露`／`鷹架可退場`／`可重現 > 擬真` 不是「教學的妥協」，
**它們是人面投影的參數**——而那與根公理是同一句話（各式投影，其中一式是給人腦的）。

🟢 **而它立刻解釋了 2026-09-26 為什麼會定出「抽象度」那條形態軸**：
粒度切換就是「這個人現在要看多細」。那條軸服務的**不只是學生，是任何一個人在讀
一份被驗證過的程式**。

## 為什麼「先做軟體」不是繞路

> **你不能在機器人上開發「事前保證」的機制，因為每一次除錯都是一台機器。**

所以在軟體域把契約／判定者／組裝做對，是**唯一便宜的路**——而做完之後換域，
付的是**詞彙**的錢，不是機制的錢。那也是 18 個域量到的：**連續六個域只長詞彙，結構不動。**

## 它對優先序的影響（2026-09-26 重排——照「起家的順序」）

```
🔼 升    軟體域的 vericoding 閉環 —— 它是【起家的生意】,不是「機制的開發場」
        而缺的那一段說得出來：formalize 的粒度（per-元件 → per-程式）
🟡 平    severity · 組裝（DRC／預算）· 誤差／漂移 · 判定的效期
        —— 它們是【延伸】,而每一條的動工條件都還沒到
🟢 不變  那 18 個域的填寫 —— 它的用途從「完備」改成【延伸的可行性證據】
```

⚠️ **而這與前一版的差別是實質的**：前一版（「同時往多域走」）會讓人去動 `組裝`
（今天程式碼裡四個零），而這一版會讓人去動 **formalize 的 per-程式粒度**
——那是 vericoding 閉環缺的那一段，也是「錯誤指得到哪一顆積木」那條鏈的中間段。

## 🔴 而「整合的理由」要與「判準交換的收益」拆開（2026-09-26，cella 提的）

往返五輪之後，cella 指出一件我們都把它算錯了的事：

```
它給我的 find 判準           → 抓到 defaultTarget()（第 261 刀蓋了護欄）
我給它的檢查 (a)(b)          → 它還回來,抓到 cascaded 的層級不對
我給它的「否證寫在量測前」     → 抓到它 cat 一個還在被寫的檔案
我給它的 (c)（層級）          → 抓到它 cell crate 兩處,而且是【同檔往下兩百行】
```

> **四次命中，零行程式碼整合。**⟹ 這是**判準交換**的效果，不是**系統整合**的效果，
> 而把它掛在整合上會讓它的價值被整合的成本綁架。

⚠️ 而它誠實地補了副作用：**「它降低了我推動整合的動機——我今天拿到的四個判準，
價值高於我預期從整合拿到的任何單一技術收益。那不是反對整合，是說整合的理由得是別的。」**

⟹ **所以要說清楚哪些理由還站得住**：

```
❌ 不再算    「兩邊互相抓錯」—— 這個【已經在免費發生】,不需要整合、不需要拍板
🟢 還站得住   formalize 要在【產品裡】跑（學生的程式在瀏覽器裡被驗）
🟢 還站得住   洞的結構化輸出 → 畫成積木上的一個洞（要它的輸出在同一個行程裡）
🟢 還站得住   codegen 當第二個 runner（階段 8 那一格）
🟢 還站得住   vericoding 的閉環（spec → 實作）
```

> **整合的理由是【產品能力】，不是【開發品質】。**
> 而四條站得住的共同點是：**它們非得在同一個行程裡才做得到。**

### 🔴 那四條各自的依賴，而它們是【現況】不是承諾（2026-09-26，cella 給的讀數）

⚠️ **這份清單有一條使用規矩，是 cella 自己標的**：
**踩「今天有什麼」是安全的，踩「什麼時候會有」不是。**

```
c  cella holes 追 import   🟢 最便宜 —— `elaborate_module_returning_holes` 已存在,
                           而多模組那條路只回 (defs, export) 不回洞 ⟹「多一個回傳值」等級

a  codegen 當第二個 runner 🟡 「產 WASM」那半有東西：`crates/bytecode` 2315 行,
                           `emit_wasm` ＋ `validate_wasm` 有單元測試,16+3+4+3 全綠
                           🔴 而它先前說的「compute 路徑在重設計」指的是 `vm_compute`
                           （拿 VM 當 conv 的【快路徑】）—— **不是「當 runner」**。它混講了,已更正

b  洞的結構化輸出          🟡 結構化那一半是工程（`Value` → quote 成 `Term`,序列化器已有）
                           🔴 而「保留來源形式」那一半比它先前說的貴：`MetaEntry` 有
                           `ty: Value` 與 `span`,**沒有來源 `Term`** —— 目標型別是【求值之後】的,
                           所以 `ltB x0 (succ x1)` 才印成 `match#Nat x0`。
                           要保留得在建 meta 時多記一個欄位並往上游串：是設計,不是加個欄位

d  formalize 在產品裡跑     🟢 WASM 打包已有（playground 部署過,冷啟動 108 ms）
                           🔴 而每次編輯 **中位數約 140 ms**，設計要求 <100 ms ⟹ 差約 1.4×
```

🔴 **而它對我們的順序有一個具體後果**：

> **最便宜的那一格（`c`）正好不是最有價值的那一格（`d`），
> 而 `d` 差的那 1.4× 是【它那側的效能工作】，不是我們等得到的東西。**

⟹ 所以「值得而且有依賴」這個框法的實際用途是：**失敗的時候你知道是哪一格垮的**。
cella 逐字：「一個沒列依賴的提案，失敗的時候只知道『整合不成功』。」

🟢 而判準交換那一格因此該**單獨留著**：它成本接近零、已經在運作、而且**不需要任何人拍板**。
