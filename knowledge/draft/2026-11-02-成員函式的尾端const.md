# 成員函式的尾端 `const`：要不要、怎麼放進積木

> 狀態：🟢 **已定（2026-11-02 使用者選 B：另立類別成員函式元件）**——進了 vision〈重構〉第 6 項（6c 之前做）→ [history/326](../history/326-使用者定的五題之三.md)；做完回流退場。2026-11-02 第 213 刀補 formalize 時撞到的。
> 怎麼冒出來的：想讓 `struct P { int sum() { … } };` 這種一般成員函式翻得出來（現在照實標「這顆類別成員還沒有對應」），
> 一翻就發現樹裡沒有尾端 `const`。

## 現況（查證過的）

- 一般成員函式在 lift 時走 `ctx.lift(node)`，變成 `cpp:func_def`（`src/languages/cpp/lang/lifters/strategies.ts` 的「Regular member function → lift as func_def」）。
  **尾端的 `const` 在這裡丟掉了**：`func_def` 的屬性只有 `name`、`return_type`。
- 產碼也不寫它。所以 `int area() const { … }` 來回一趟會變成 `int area() { … }`，
  一旦有人在 `const P&` 上呼叫它，**產出的程式碼編不過**。這是既有的來回一趟缺陷，不是 formalize 帶進來的。
- `operator_overload` 在 spec 201 修過同一件事：新屬性 `is_const`（enum，預設 `'false'`，舊存檔相容）、積木上的下拉
  （「（會改自己）」／「const（不改自己）」）、lift 讀 `function_declarator` 的 `type_qualifier`、產碼補 ` const`。

## 為什麼第 213 刀沒有順手翻它

試過讓 `func_def` 也註冊成類別成員（`mbMethod` 包同一個 `fdef`）：

```
int sum() { … }                                    accept、輸出對
int area() const { … } 在 const P& 上呼叫            reject「'this' argument … is const, but the function is not marked const」
```

樹裡分不出有沒有 `const`，硬翻就會讓 const 方法**被誤判 reject**。這比照實標「判不出來」更糟，所以撤回了。

## 選項

| | 做法 | 代價 |
|---|---|---|
| A | `func_def` 加 `is_const` ＋ 積木下拉，比照 `operator_overload` | `func_def` 是最常用的積木（`main` 就是它）：所有課文的對照圖要重產、e2e 要重跑；頂層函式也會看到一個不合法的選項 |
| B | 類別成員的函式改用一顆**新元件**（例如 `cpp:method_def`），帶 `is_const`；頂層函式維持 `func_def` | 多一顆元件（五路、積木、課程清單）；而類別裡已經有 `method_virtual`／`method_override` 兩顆同族，命名一致 |
| C | 不做，維持 unknown | 學生語料目前沒有一支卡在這裡（StudyCpp 0 支），課文也沒有；而來回一趟丟 `const` 的缺陷留著 |

## 推薦：B

- 它和既有的 `method_virtual`／`method_override` 同族：類別裡的函式本來就有自己的積木，只有「一般的」那種借用了頂層的 `func_def`。
- `const` 只在類別成員上合法。放在只出現在類別裡的那顆積木上，頂層的 `func_def` 就不會多一個不合法的選項。
- 修掉的不只是 formalize，還有那個既有的來回一趟缺陷。

不急：學生語料與課文目前都沒碰到，排在 6c 之前做即可。

## 做了之後量到的（第 218 刀，roundtrip 階段）

- 🔴 **類別裡的 `static` 成員函式仍走頂層函式那顆，`static` 掉了**（main 上就有）：`static int zero()` 產回去是 `int zero()`，
  呼叫端 `P::zero()` 編不過；JS 直譯器也不認 `P::zero()`。method_def 刻意只接形狀單純的（沒有地方放 static）。
  推薦：下一刀把 method_def 的修飾做成互斥的三選一（一般／const／static），而不是再加一個布林——const 與 static 本來就不能同時成立。
  測試：`roundtrip-cpp-oop` 的 `it.todo`（修好改成 it）。
- 🟢 順手修了：方法裡不帶限定地呼叫同類別的方法（隱含的 `this->get()`），JS 直譯器原本說「沒有這個函式」（`func_call` 的執行器先找自己類別的方法）。
- 🟢 模糊測試（資訊隔離 10 支）：main 上 9 支產回來編不過 → 218 之後 6 支輸出與原始相同。順手修了**回傳參考／指標的成員函式**（`Counter& tick()` 原本產成 `Counter tick()() {`）。
- 🔴 模糊測試量到、還在的既有缺陷（建構子與宣告那一族，不是這顆的範圍；`fuzz-cpp-oop` 的 todo）：
  建構子的預設引數掉了（`Time(int h = 0, int m = 0)`）、初始化列只留第一個引數（`sz(n, 1)`）、const 物件的建構引數只留第一個（`const Rect c(7, 1)`）。
  推薦：下一刀「建構子的參數與初始化列」一起修——三個都是「多於一個的東西只留第一個」的同一個形狀。
- 🟡 覆蓋缺口：`this` 沒有元件認領（降級成原文，輸出不受影響，但用到 `this` 的方法翻不成 Cella）。推薦另立一顆 `this` 元件。
