# 套件的物件在執行期是什麼

> 日期：2026-08-17
> 怎麼冒出來的：量完「典型 Arduino 程式轉不轉得動」之後補量執行
> ——**雙向轉換 🟢 0.07% 殘差，而執行 🔴 12/20 拋錯**，
> 而 12 筆裡 **10 筆是同一個根因**。
> **狀態：設計未決。** 使用者已確認「執行也要做，先開 draft 答這個設計問題」。

## 一、地面真相：lift 那一側**全部是對的**

```
Servo myServo;         →  cpp:var_declare{ name:'myServo', type:'Servo' }
DHT dht(2, 11);        →  cpp:var_declare{ ..., init_style:'constructor' }
EEPROM.write(0, 42);   →  cpp:method_call{ obj:'EEPROM', method:'write' }
```

🔴 **沒有一個新概念需要被加。** 樹已經是對的形狀，殘差 0。

**問題只在 execute**：
- `execVarDeclare`（`interpreter/executors/variables.ts:34`）查 `ctx.structs.has(type)`
  ——`Servo` 沒登記，於是它不是一個物件
- `method_call`（`components/cpp/method_call/execute.ts:20`）因此丟
  「`myServo`（**不是一個物件**）」

> **機制已經在了（`ctx.structs`），缺的是【誰來登記】。**

## 二、三種形狀，而它們共用同一個缺口

```
① Type name;             Servo myServo;
② Type name(args);       DHT dht(2,11);  LiquidCrystal lcd(12,11,5,4,3,2);
                         Adafruit_SSD1306 display(W,H,&Wire,-1);  MFRC522 mfrc522(SS,RST);
③ 全域單例                EEPROM / WiFi / SPI / IrReceiver
④ 【已支援】的單例        Serial → cpp:serial_open ／ cpp:serial_print（專屬概念）
```

⚠️ **④ 是我們自己做過的那一種**——而它花了兩顆膠囊 ＋ 兩個 obj 感知的 lift 分支。
**套件有幾百個。** 這條路走不完。

## 三、三個選項

### (A) 一顆膠囊一個套件方法（`cpp:servo_write`／`cpp:lcd_print`…）

🔴 **否決。** lift 那一側**已經對了**——加概念**不會讓任何東西變好**，
而它會製造身分變動（`method_call` → `servo_write`），
⚠️ **反而讓現在 0.07% 的殘差與 0/20 的漂移面臨風險**。

> **一個已經是對的形狀，不需要一個更專屬的名字。**

### (B) 完全通用：**任何**未知型別的宣告都變成一個記錄狀態的空殼

⚪ **最便宜**——一段程式碼，零清單。

🔴 **而它有一個真的問題**：`Srevo myServo;`（打錯字）也會變成一個合法物件。
**一個不存在的東西被靜默地當成存在**——那是第三十三條護欄在看的方向的反面。

### (C) 宣告式：套件宣告它提供哪些類別／方法／全域物件

🟢 **打錯字仍然出聲**（`Srevo` 不在任何清單裡）。
⚠️ 而它要維護清單。

#### 🔴 而它剛好是 `target` 那一格等了很久的消費者

`draft/2026-08-13-C和C++難分難捨.md`§三 的四欄設計：

```
provides   → ["arduino"]    pinMode／digitalWrite 的 requires 對它求解
```

而 `history/077` 以為它的消費者是**板子型號**。**補量之後看起來是【套件】**
——`#include <Servo.h>` 這一行**就是**「我要用這個套件提供的東西」的宣告，
而它**已經在程式碼裡了**，不必使用者另外選。

> **`#include` 那一行本來就是一份 `provides` 的申請書。**

## 四、傾向（**未拍板**）：(C) 的清單 ＋ (B) 的行為

```
清單    套件宣告它有哪些類別與全域物件         → 打錯字出聲
行為    清單裡的東西 → 一個記錄狀態的空殼      → 不必一個一個寫方法
```

**而空殼記狀態，不是什麼都不做**——照 `arduino-pins.ts` 今天對 `digitalWrite` 的形狀
（記在 `WeakMap`，而顯示是之後的事）。

⚠️ **那條界線就是使用者這一輪往後推的東西**：

```
物件存在 ＋ 方法不拋錯 ＋ 記錄狀態      ⚪ 便宜   ← 本輪
方法有【可觀察的效果】（馬達轉、LCD 顯示）🔴 貴   ← 虛擬硬體，已往後推
```

## 五、🔴 而有一個問題還沒有答案：**方法要回傳什麼**

```
float h = dht.readHumidity();      → 空殼回什麼？
int v = EEPROM.read(0);            → 空殼回什麼？
if (digitalRead(2) == HIGH)        ← 這個有答案（腳位狀態機）
```

**回 `undefined`／`NaN` 是最糟的**——它會一路傳下去，
而錯誤出現在離根因很遠的地方（`experience`「一個回 `NaN` 而不出聲的求值」，
那一則正是今天新增的）。

三種可能，**都沒拍板**：

| | 做法 | 代價 |
|---|---|---|
| **出聲** | 有回傳值的方法一律丟錯 | 🔴 一半的程式還是跑不完（`readHumidity` 太常見） |
| **宣告預設值** | 清單裡寫 `readHumidity → float 0` | ⚠️ 清單變大，而 0 是不是「誠實」要想 |
| **記錄 ＋ 回預設** | 呼叫記下來，回宣告的預設 | 🟢 而它需要「呼叫紀錄有人讀」——**今天沒有消費者** |

> ⚠️ **「先記下來、之後才有人讀」是「機制有了沒人接上」的溫床**
> ——而那個病在這個專案有**十一個實例**。

## 六、⚠️ 還有一個順帶的缺口，而它不是這一題

```
dht.begin()  →  cpp:container_iter{ obj:'dht', which:'begin' }
```

`begin` 被容器迭代器認走——**每個 Arduino 套件都有 `begin()`**，
而 2026-08-17 只為 `Serial` 加了 obj 感知的分支。
🟢 **而 (C) 的清單剛好答得了它**：`dht` 是 `DHT`，而 `DHT` 宣告了 `begin`
→ 那就不是迭代器。**這是清單的第二個用途，而它是免費的。**
