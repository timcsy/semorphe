# 教案是一個宣告——而「選一堂課」取代「勾一堆層級」

> 日期：2026-08-27
> 怎麼冒出來的：使用者逐字——
>
> > 「現在的層級基本上是**沒有實質被使用**的，實際上不是全有就是全無，
> > 這全部都是因為**沒有搭配教材或是使用情境**」
> >
> > 「我在想教案如何搭配編輯器，這應該要有一個 **API 或是 json 的宣告**，
> > 就是說只要教案定好**哪些積木的 id**，然後有什麼**特殊的要求**，
> > 編輯器就會可以**選那堂課**，而不是像現在用打勾的方式選層級」
>
> **狀態：設計，未升格。** 出口是 vision 路線圖，而那道閘在人。

## 零、🔴 真正的動機不是「內容管理」，是【替使用者做決定】（2026-08-27 補，而它改寫本檔的重點）

> 使用者：「我真正擔心的點好像是**如果沒有使用者狀態儲存，是無狀態的應用，
> 那麼太多選單選擇會造成使用者認知負擔**」

### ⚠️ 前提有一半不成立——它不是無狀態的

```
user      styleId · blockStyleId · locale        換一個檔案不該變
context   topicId · targetId · enabledBranches   換一個【課程】才該變
document  code · language
sideCar   blocklyState · codeHash · flowLayout
```

而全新瀏覽器開起來**六個控制項全部有預設**（`app.ts:228` 的 `defaultTarget()`
一路推出 topic）。**所以「一開始要選很多東西」今天就不成立。**

### 而真正的形狀更難

```
擔心的      無狀態 → 每次重選 → 負擔
實際的      有狀態 → 而那個狀態是【使用者自己選出來的】
                   → 而他【沒有能力做那些選擇】
```

> **認知負擔不是來自「選單有幾個」，是來自「有幾個選單是他【沒有意見】的」。**
> 一個他有意見的選項（介面語言）不是負擔，是尊重。
> 一個他沒有意見的選項（APCS 風格 vs Google 風格）
> **每一次出現都在問一個他答不出來的問題。**

🔴 而這是 [漸進揭露把選項轉嫁給了老師](2026-08-12-漸進揭露把選項轉嫁給了老師.md)
的同一個形狀，往上一層：**把一個沒有判斷依據的決定丟給一個沒有判斷依據的人，
他會用一個不假思索的答案打發它**（「我會乾脆叫學生把全部都打勾」）。

### 🎯 所以教案的價值要重寫

```
本檔原本的重點   教案【限制了什麼】（哪些積木可用）
真正的重點       教案【替使用者答完了那幾個問題】
```

一條 `?l=…` 連結，學生點進去看到的是：對的目標、對的層級、對的風格、對的版面
——**而他一個選單都沒碰過**。

> **一個好的預設不是「猜對了」，
> 是「有人替你決定過，而那個人知道你在上哪一堂課」。**

### 🟢 一條可以拿來掃描的判準

> **每一個留在畫面上的選項，都要說得出「誰有意見」。
> 說不出來的，就該有一個替他決定的人——課程、宿主、或預設。**

拿它掃今天的六個控制項（`core/host/controls.ts`）：

```
locale       學生有意見        → 留
layout       學生有意見        → 留
blockStyle   學生半有意見      → 留（而它可以被課程釘住）
target       老師有意見        → 🔴 該由課程決定
style        老師有意見        → 🔴 該由課程決定
branches     🔴【沒有人有意見】——老師也答不出來
```

**最後一格最刺眼**：`branches` 是六個裡唯一一個**連老師都沒有判斷依據**的，
而它正是漸進揭露的入口。（那是 §三「`L2a` 給不出理由」的同一件事。）

🎯 → **它該被「選一堂課」取代，而不是被「選得更好」。**

### ⚠️ 而釘住的控制項應該【消失】，不是變灰

```
變灰   「這裡有一個你不能碰的東西」→ 仍然是負擔，而且更糟（它在嘲笑你）
消失   這一堂課裡，那不是一個問題
```

🟢 而這個機制**已經存在**：`host-profile.ts:87` 逐字
「⚠️ 鍵必須與 `features` 裡為 `false` 的那些**一模一樣**」
——宿主藏控制項的那條路，教案可以走同一條。

### 🔴 而它反過來解掉「沒有後端就沒有狀態」那個憂慮

```
有後端       狀態跟著【人】走 → 換裝置也記得 → 而要帳號、隱私政策
連結帶組態   狀態跟著【課】走 → 換裝置也記得 → 🟢 零後端
```

**連結本身就是那個狀態。** 學生換一台電腦，老師再貼一次連結。

- [ ] ⚠️ **而有一個真缺口：學生自己的程式不在連結裡。**
      他換電腦，程式沒了。答案在 `vision.md:722` 的匯出／匯入 zip
      ——⚠️ 而對小學生來說「記得存檔」是一個負擔。
      🔴 **那可能才是真正需要後端的第一個理由，而不是「老師看進度」。**
      （見 [出貨與定位 §九](2026-08-27-出貨與定位.md)：後端是不可逆的決定。）

## 一、診斷成立，而三個事實是量出來的（2026-08-27）

```
① 層級樹是真的        cpp-beginner：180 顆分成 10 個節點，L0 只有 19 顆
② 預設只開 L0         app.ts:230  enabledBranches = new Set([levelTree.id])
③ 而【沒有 defaultEnabled】十個節點全部沒有這一欄
```

所以「全有或全無」**不是機制做不到，是機制沒有被任何東西驅動**。
今天決定層級的只有一件事：使用者在下拉選單裡點了什麼。

而使用者 2026-08-12 那句話是這個結構的必然結果：

> 「我會乾脆叫學生把全部都打勾，那有沒有這個漸進揭露是沒用的」

> **一個把決定丟給老師、而沒有給他任何判斷依據的介面，
> 會被理性地選成「全開」。**

## 二、🔴 而這個問題庫裡記過——在一份【已退場】的 draft 裡

`draft/retired/2026-08-14-教材要如何呈現.md:36` 逐字：

> ⚠️ **而今天是反過來的**：`topics/*.json` 把 175 顆概念**逐一列舉**在關卡裡
> ——**175 個歸屬判斷，而它們沒有一個說得出理由。**

那句話今天仍然成立（現在是 180 顆）。

🟢 那則**洞察**有落點（`concepts/元件.md:51`「教材宣告目標，元件集合是它的外延」）。
🔴 而那個**問題**在 `vision.md` 上**零筆**（grep 過）。

> **一則洞察被存下來，不等於它指出的問題被追蹤。
> 存的是「我們知道這件事」，而不是「我們要處理它」。**

⚠️ 那份 draft 退場是**正確的**（它的路線圖項「第一課」做完了），
而退場時反流了四條教訓、一筆 history、一則 episode
——**唯獨這個還沒解的問題跟著它一起下架了**。

## 三、🔴 而使用者的做法推翻了我原本的建議

我照著那份 draft 推薦「別列舉，用**算的**（目標 → 元件集合）」。
而使用者說的是「**教案定好哪些積木的 id**」——直接列舉。

**那不是退回今天的做法。** 差別在**那些 id 掛在哪個名詞上**：

```
今天    L2a  →  40 顆 id        「為什麼 map_at 屬於 L2a？」——【答不出來】
提案    第七課：查字典 → 那些 id  「為什麼 map_at 在這裡？」——【因為這一課在教它】
```

> **那 180 個歸屬判斷缺的不是「用算的」，是【一個說得出理由的名詞】。
> `L2a` 是一個沒有內容的層，它 justify 不了任何東西；一堂課有內容，它可以。**

⚠️ `L2a`／`L3b` 這種 id 本身就是症狀——庫裡甚至有一份
[Ln 的 n 只是排序](2026-08-13-Ln的n只是排序.md)。
**一個「只是排序」的東西，當然給不出歸屬的理由。**

🟢 而它與 `concepts/元件.md:51` **不衝突**：那條說「教材是內涵、元件是外延」，
而一堂課**有內容**（說明、練習、範例）——內容就是內涵。
今天的 `L2a` 沒有內容，所以它兩邊都不是。

## 四、「特殊的要求」已經有現成的載體

`src/core/host/controls.ts` 的控制項是**宣告出來的**：

```
target · branches · style · blockStyle · locale · layout
```

所以教案可以**釘住登錄表裡已經有的東西**，不必發明新詞彙：

```jsonc
{
  "id": "lesson-07-map",
  "title": "查字典",
  "components": ["cpp:map_declare", "cpp:map_at", "cpp:map_assign"],
  "pins": { "target": "cpp", "style": "apcs", "blockStyle": "zelos" }
}
```

🟢 加一個釘得住的東西**不用改教案格式**——控制項登錄表多一列就好。
⚠️ 而那也是風險：`pins` 的值域開放，**寫錯一個 id 不會有人發現**。
→ 需要一條護欄「教案釘的每一個控制項都要在登錄表裡」，
   而這個 repo 有現成的樣式（第五十四條「每個宣告都要有落點」）。

## 五、🟢 它順帶結掉一格「歸屬待判」

`src/core/storage-version.ts:104` 逐字：

> 🔴 【教學情境】——**歸屬待判**：換檔案不該換課程，而換課程時它要換

那三格是 `topicId` / `targetId` / `enabledBranches`。
教案成為單位之後它們**塌成一格 `lessonId`**，而那句話也有答案了：
**課程跟著人走，不跟著檔案走。**

      硬釘    改不動 → 那個控制項變成一顆按了沒反應的按鈕（本 repo 有前科）
      軟釘    只是預設值 → 與今天的「預設 L0」差別在哪？

      ⚠️ 它決定「教案」是一個**限制**還是一個**起點**——兩者的介面完全不同。
- [ ] **② 學生打開一個不屬於任何課的檔案**

      ——而它會在這一刀上**第一次真的撞到人**。
- [ ] **③ 🔴 教案住哪裡**
      ```
      在 repo 裡      改一課要發一版；老師改不了
      在 .sem 裡      跟著專案走；而那是【每個班自己一份】
      外部 URL／檔案   老師改得動；而【離線可用是硬條件】（e2e/offline.spec.ts）
      ```
      ⚠️ 這與「[.sem 該不該有專案根](2026-08-24-版面與檔案.md)」是**同一個決定的兩面**
      ——教案若是專案級的東西，`.sem` 就更像 `.git` 了。

## 六之二、🔴 先問「誰會用」，而數據推翻了「自編 vs 用現成」這個二分

> 使用者（2026-08-27）：「我覺得先討論**老師們會想自己自編教材的比例有多大**，
> 再來看看需要哪些機制呢？」

這一步對，而它對上 `draft/教材要如何呈現 §十` 的判準：
「**一個「更好」與一個「走不下去」，在待辦清單上長得一樣。**」

⚠️ 而這個 repo 不知道答案——那份 draft 的起點逐字是
「元件 189／護欄 43／experience 111，而**教材 0、用過的學生 0**」。

### RAND 的 AIRS 調查（K-12，2019–2024 持續追蹤）

```
25%   自編教材【全部或大部分時間】
45%   混用——幾套現成的 ＋ 加一些自己做的
30%   只用一套    └ ⅔ 大致照用、⅓ 大幅改編
平均  2 套核心課程 ＋ 5 個補充資源
```

RAND 逐字：老師**不把自己看成課程的實施者，而是 curator／modifier／creator**；
「老師只用一套教材而且完全不改，**這件事相當罕見**。」

**換算：完全照用的只有 30% × ⅔ ≈ 20%。剩下 80% 都在改。**

🟢 佐證：TPT 有 **7 百萬老師（85% 的 K-12）· 7 百萬份資源**，
而賣家收入是長尾——**絕大多數人在那裡是「拿」而不是「賣」，拿了之後改**。

### 🔴 所以問題該換一個問法

```
原本的二分   自編（要編輯器）  vs  用現成（要目錄）
實際的分佈   80% 在【改別人的】——而中間那一格兩端的機制都不服務
```

| 行為 | 比例 | 需要的機制 |
|---|---|---|
| 完全照用 | ~20% | 一條連結、一份目錄 |
| **改編別人的** | **~80%** | **複製一份 → 改幾格 → 再分享** |
| 從零自編 | 25% 的一部分 | 完整的教材編輯器 |

推出三個排序：

- 🟢 **「複製一份來改」比「從零編輯」重要，而它便宜非常多。**
  一堂課如果是一份宣告，改編就是「拿到 → 改幾個 id → 拿到新連結」
  ——**不需要教材編輯器**。而 `?l=` 那條路天生可 fork。
- 🟢 **目錄（找得到別人的課）比創作工具更早需要**，因為 80% 的人要先找到
  一個可以改的東西。而目錄可以是一個 repo ＋ 靜態索引，**零後端**。
- 🔴 **「歸屬」會比預期早出現**：改編別人的課就會有「這是誰做的」。
  → 宣告要留一個 `derivedFrom` 欄位。**現在留是免費的，事後補是痛的。**

### ⚠️ 而這份數據夠格決定「優先序」，不夠格決定「要不要做」

那些數字是**美國 K-12 全學科**。而處境是**台灣 · 程式教育 · 一個還沒有人用過的工具**。
程式教育的老師**更少現成教材可改**（自編比例可能更高），而**工具鎖定更強**
（Scratch 的教材搬不到 Semorphe）。

> **在第一個不是自己人的老師用過它之前，
> 任何關於「老師會不會自編」的推論都是推論。**

🔴 而真正能回答的是那份 draft 自己寫的出口條件——
**「第二個人走過一遍」到今天還沒有發生**。

## 六之三、VSCode 那側——它幾乎不需要發明任何東西

| | 網頁版 | VSCode |
|---|---|---|
| 一條網址開始 | `semorphe.com/?l=…` | `vscode://` URI handler（⚠️ 體驗差，多半是一個指令） |
| 教案住哪 | `.sem` / localStorage | 🟢 **就是工作區資料夾** |
| 元件庫怎麼裝 | 抓一次存起來 | 🟢 **`node_modules` 或工作區資料夾** |
| 離線 | 要自己保證 | 🟢 **本來就是本機的** |

> **網頁版缺的每一樣東西，VSCode 都已經有一個原生的對應物。
> 所以設計要從網頁版出發——受限的那一側才問得出真正的形狀。**

⚠️ 這與 `版面與檔案 §五` 那條「一個宿主看起來比較受限，而它的限制正好替我們
回答了共同真相住在哪」是同一條，**而這次受限的是網頁版**。

🔴 **一個現在就要決定的分歧**：

```
網頁版   元件庫必須是【資料】（膠囊 JSON ＋ 宣告式策略）
VSCode   元件庫【可以】是程式（node_modules 裡的 JS）
```

兩邊走不同的路 ＝ 兩套元件格式，而那正是 P9 宿主獨立性要擋的。
→ **以網頁版為準：元件庫是資料。**
🟢 而這剛好兌現了 `retire-imperative-block` 那整個工作的價值
（命令式積木定義已歸零）：**宣告式的東西可以當資料傳，命令式的不行。**

- [ ] **⑥ 教案要不要能宣告「我只在某個宿主上跑」？**
      例如 Arduino 燒錄在網頁版做不到。`HostProfile.features` 今天已經是宣告式的
      → 教案可以寫 `requires: ['serialPort']`，網頁版就說「這一課需要 VSCode 版」。
      🟢 那比「開起來才發現不能用」誠實得多（P6 同一條線）。

## 六之四、層級要依照什麼——兩個候選已被實驗否證

```
① 深度         ❌ `Ln的n只是排序 §五之五` 實驗否證：一個關卡橫跨所有深度
                  （func_def 深度 0 在 L1a、if_else 深度 3 在 L0）
② 元件自報難度  ❌ `concepts/元件.md:57`：「一顆元件不該知道自己屬於哪一課
                  ——那會讓『換一套教材』變成『改 189 顆元件』」
③ 教案的偏序    🟢 而那個實驗給了它精確的形狀
```

那個實驗量出兩個界：

```
下界   必需集合 ＝ 傳遞閉包          print/if/loop_while → 6 顆
上界   ＋「免費的鄰居」（前置已全在）→ 19 顆（＝實際的 L0），中間 13 顆免費
```

→ **層級 ＝「我上到第幾課」，而可見集合是算出來的。**

🔴 而它修好實驗抓到的**真破洞**：`array_assign` 在 L1a 而它需要的
`array_declare` 在 L2a——**手列的清單會有這種洞，傳遞閉包在定義上不會。**

## 六之五、預設全開，而理由不是「方便」

> 使用者：「要不要預設全開，風格那些都可以自己調整，然後如果有特別選課程就再依照課程」

🟢 同意，而理由更硬：**沒有課程的時候，這個系統真的沒有依據去限制任何東西。**
今天預設開 L0（arduino 目標實測 27 顆，全開 215 顆），**而那 27 顆憑什麼？**

> **一個沒有依據的限制，比不限制更糟——因為它看起來像一個決定。**

⚠️ 而它與 P4 表面打架，**那個打架是假的**：

```
semorphe.com 的訪客   好奇的大人／評估中的老師   → 全開才看得到它會什麼
從連結進來的學生       小學生，上第七課           → 課程說了算
```

**P4 管的是後者，而後者一定有課程。** → ⚠️ 這要寫進 P4 的說明，
否則下一個人會以為預設全開是違規。

🎯 而首頁應該有**一顆課程連結按鈕**（「看看小學生的第一課長什麼樣」）
——它讓訪客親眼看到 215 → 19，**那就是漸進揭露這個賣點的示範**。

## 六之六、離開課程：單一值可還原，集合只能加

> 使用者選第三條路（可改，而看得見自己離開了課程），並問
> 「離開課程那元件的數目怎麼訂？」

🔴 **那個問題暴露一個類型錯誤**（我第一版把兩種東西塞進同一個介面）：

```
風格 · 目標 · 版面   單一值   「離開」＝ 換掉 → 一個旗標 ＋ 一個「還原」
元件                 集合     「離開」＝ ？  → 🔴 換不了，只能【加】
```

因為 `principles.md:77` 逐字：**「層級切換只增不減，已建立的心智模型不被破壞。」**
學生看過 `vector` 之後把它收回去，就是破壞那個模型。

> **一個單一值的「離開」是可逆的；一個集合的「離開」是不可逆的。
> 而把它們塞進同一個介面，會讓其中一個說謊。**

三個候選：

```
A 一步到全開    19 → 215 是懸崖，而按下去回不來（P4 不准減）
B 往下一課推進  🟢 每一步小、每一步【說得出理由】（那是課程的順序）
C 借一顆        要一個「挑元件」的介面——正是要殺掉的那個沒人有意見的選單
```

**建議 B**，理由不是最方便，是**唯一說得出理由的**：A 的 215 顆與 C 的那一顆
都答不出「為什麼是這些」，而 B 的答案現成：**因為那是下一課**。

介面變成一句人話：

```
今天   ☐ L0  ☐ L1a  ☐ L2a …          （沒有人有意見）
之後   「第七課 · 查字典」
       ⚠️ 你已經開了「第八課」的積木   [回到第七課]
```

而那顆按鈕**不收積木**（P4 不准），是**回到那一課的組態**——
風格／版面／目標回去，**積木留著**。

> **可逆的那些還原，不可逆的那些留下——而介面要說清楚哪些是哪些。**

- [ ] ⚠️ **一句要用教學直覺判斷的**：學生看到「你已經多開了下一課的積木」，
      會不會覺得自己做錯事？會的話那句話要換講法（「你正在提前學」？）。
- [ ] ⚠️ **B 要求課程有順序**，而 `levelTree` 本來就是樹（課程會分岔）。
      🟢 分岔時**問一次**（「你想往哪邊走？」）——而那是學生有意見的問題，
      通過那條掃描判準。
- 🟢 **B 順帶是逃生口**：課程的集合若是錯的（那個 `array_assign` 破洞），
      學生推進到下一課就自己繞過去了。
      ⚠️ **而一個靠逃生口掩蓋的缺陷不會被回報**——真正的修法仍然是傳遞閉包。

## 六之七、🪦 程式風格併進目標——【已經做完了，缺介面收尾】

> 使用者：「程式風格現在先跟目標合併好了，先選目標再選課程，然後積木風格怎麼選不影響」

**查證：`Target` 已經宣告 `style`**（`core/types.ts:873`），而 13 個目標全部填了：

```
cpp → apcs · c → c · cpp-competitive → competitive
arduino* (8 個) → google · python → python
```

而 `tests/unit/core/storage-version.test.ts:72` 的註解逐字寫著意圖：
**「目標取代了『課程清單 ＋ 風格』兩次分開的選擇」**。

🔴 **沒收尾的地方在狀態列**：`controls.ts` 仍然有一顆 `style` picker，
而它已經由 target 決定了。症狀不是「多一顆按鈕」：

```
選 arduino-uno  → style 自動變 google
手動改 style     → 🔴 目標仍然說它該是 google
                   → 兩個東西不一致，而那個狀態【沒有名字】
```

> **一個宣告了預設值、而又留著一顆手動選單的欄位，
> 會產生「宣告說 A、實際是 B」的狀態——而它沒有名字。**

🟢 **退場不失去能力**：5 個風格，每一個都有目標指到它。

⚠️ 而它是一次**歸屬遷移**：`styleId` 從 `user` 搬到 `context`
（第六十一條護欄在看，`migrate-storage` 第 1 步「先分歸屬，再改欄位」）。

### 而積木風格為什麼是另一族

用 `concepts/投影.md:607` 的判準（「它換一個投影還存在嗎」）：

```
程式風格   APCS 的命名慣例 → 換到程式碼投影【還在】 → 真實的一部分
積木風格   Scratch 的圓角  → 換到程式碼投影【不存在】 → 排版
```

🟢 所以它與版面、介面語言同族：使用者的偏好，跟著人走
（存檔的歸屬已經是對的：`blockStyleId: 'user'`）。
⚠️ 課程可以**軟釘**它（低年級用 Scratch 風格）——建議而非限制，
**因為它不影響真實，所以不必第三條路**。

## 六之八、狀態列最右那格「C++」——抄了位置，沒抄能力

> 使用者：「網頁版最右邊的 C++ 不能切換語言也很怪，感覺有點多餘」

`app-shell.ts:239` 的註解逐字：**「⚠️ 語言掛在最右，那是 VSCode 擺語言模式的位置。」**
而 VSCode 那一格**可以點**，這裡不能。

> **抄了位置，沒抄它的能力——於是它看起來像一顆壞掉的按鈕。**

🔴 而它是不是多餘，答案是「看情況」，因為 `FIELD_OWNERSHIP` 把兩者分在兩邊：

```
targetId  context   「我在教什麼」
language  document  「這個檔案是什麼語言」

目標 = C++（預設）  → 語言 C++     🔴 重複
目標 = Arduino UNO  → 語言 C++     🟢 有資訊（Arduino 寫的是 C++）
目標 = Python 入門  → 語言 Python  🟢 有資訊
```

> **一格資訊在一種情境下重複、在另一種情境下必要
> ——而它今天用同一種方式呈現兩者。**

→ **條件顯示**：目標名稱已經說出語言時，不畫那一格。而判準是那條掃描判準的唯讀版：

> 選項：每一個留在畫面上的**選項**，都要說得出「誰有意見」。
> 資訊：每一個留在畫面上的**資訊**，都要說得出「它在什麼時候不是廢話」。

### 🪦 而它順手挖到一個真的殘骸

`src/ui/layout/status-bar.ts` 的 `StatusBar` class 畫的是**四格**
（`language | 風格 | 課程 | 語系 | Sync`），而畫面上是**七格**
——那七格是 `status-bar-controls.ts` 畫的（2026-08-25「控制項離開積木面板」的產物）。

**查證：零產品呼叫者、零測試引用。**

> **一個渲染器，畫的東西與畫面上的不一樣，而沒有人發現
> ——因為沒有人在看它。**
