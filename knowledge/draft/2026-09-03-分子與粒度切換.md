# 分子與粒度切換

> 日期：2026-09-03
> 狀態：**設計未決**——出口是 vision 路線圖（要人拍板），不是直接清償。
> 怎麼冒出來的：使用者：「目前我們在做的很像是『**原子**』元件，但是大部分的
> 基本要素都是由原子組成的『**分子**』元件…有沒有可能到時候有一個**模組之間的
> 訊息傳遞**之類的畫面（對應流程），還有**模組之間的組合包含關係**（例如車子裡面
> 有輪子），到時候要**如何在這些粒度切換**？UI/UX 如何才能最順？」

## 一、你要的兩個畫面，就是你已經宣告過的兩種關係

```
擁有（containment）  車子【有】輪子       → 一棵【樹】 → 積木巢狀／3D 組裝／UI 版面樹
連接（connection）   模組【傳訊息】給模組  → 一張【圖】 → 流程圖／2D 接線
```

而這條線 `concepts/元件.md:286` 已經畫過，逐字：

> 「埠 ＝ 關係為守恆或資訊的接點——對等、可 Link、雙方獨立存活。
> **組合接點（積木的 `body` 槽、UI 的 `slots`）是【擁有】不是【連接】，不是埠。**」

而 `:272` 也已經說了連接那一半的地位：

> 「**組裝**（哪些實例經哪些接點相接）也是真實，但它不屬於單一元件，
> 屬於元件之間。」

🟢 **所以骨架是「一棵樹 ＋ 一張圖 ＝ 一個系統」，而兩個視圖都已經有了**
——要做的不是發明第三種視圖，是讓這兩個**認得階層**。

## 二、分子不是新概念，它是「定義與使用」在另外兩個域的樣子

分子 ＝ **一群東西 ＋ 一個邊界 ＋ 一組對外的槽**。而要拍板的是：

> **分子是「一個新的身分」，還是「展開就消失的巨集」？**

| | 巨集式（展開） | 真身分（型別／實例） |
|---|---|---|
| 例子 | Scratch 自訂積木、C 的 `#define` | 函式／class、Figma 的 component |
| 車子的四個輪子 | 四份**複製**——改一個不影響其他 | 四個**實例**——改型別四個一起變 |
| 自己的狀態 | 沒有 | 有 |

🔴 **使用者的例子自己就要求了右邊那個。** 而右邊那個**已經有了**：
它就是**函式定義與呼叫**。`concepts/元件.md:444` 也早就把詞定好了
——「具現進組裝的個體 ＝ **實例**（`Instance`）」。

> **分子不是第三種概念，是同一個概念在硬體與 UI 的樣子。**

⚠️ Unreal Blueprints 提醒了一件事：它有**三種**封裝
（純整理的 Collapsed Graph／可重用的 Function／有狀態的 Macro & Component）。
**封裝的語義不只一種**，而使用者會需要「我只是想收乾淨」與「我要做一個可重用
的東西」兩件事。第一刀可以只做一種，但要知道另外兩種存在。

## 三、🔴 最急的一件事：跨層路徑語法，而它會撞既有的命名階層

```
car.wheelFL.speed      ← 【實例】路徑（誰的誰的什麼）
python:numpy.linalg.solve  ← 【身分】階層（`concepts/元件.md:184`，規則已定未實作）
```

**兩個都用 `.`，而它們是完全不同的東西。** 一個是「這顆零件是誰」，
一個是「這個系統裡的哪一個」。

⚠️ 而實例路徑會**同時**出現在程式碼、接線、UI 綁定裡——**三個地方各自發明一套
就完了**。這是我認為要第一個定、而且最容易被拖到最後才發現的東西。

（既有的相關決定：`concepts/元件.md:269`「**階層是選用的，不是強制的。
一致性不值那個價。**」——那句話講的是**身分**階層，別誤用到實例路徑上：
實例路徑不是選用的，它是「哪一個輪子」唯一說得出口的方式。）

## 四、粒度切換的 UX：鑽入，不要用縮放

| 做法 | 誰在用 | 評價 |
|---|---|---|
| **鑽入 ＋ 麵包屑** | Simulink、LabVIEW、Blender 節點群組、Node-RED subflow | 🟢 唯一在三層以上還不會迷路的 |
| 原地展開 | 少數視覺工具 | 🟡 兩層還行，三層版面爆炸 |
| 語意縮放（zoom 夠近就露出內部） | Google Maps 是原型 | 🔴 展示很美，實用很痛 |
| 側欄顯示內部 | Unity prefab 隔離模式 | 🟡 適合輔助，不適合當主動線 |

**為什麼不用語意縮放**：縮放這個手勢會同時代表「我要看大一點」與
「我要看深一層」，使用者永遠不知道自己在哪一層。

> **一個手勢管一件事：縮放管大小，鑽入管深淺。**

畫面配置（CAD 的標準配置，使用者自己在用 Onshape）：

```
┌──────────┬────────────────────────────┐
│ 裝配樹    │  麵包屑：車子 › 前輪組 › 輪子 │
│（擁有）   │                            │
│ ▾ 車子    │      畫布（連接：那一層的圖） │
│   ▾ 前輪組│                            │
│      輪子 │                            │
└──────────┴────────────────────────────┘
```

🟢 選取**雙向連動**（樹上選 → 圖上亮；圖上選 → 樹上定位）——跨視圖反白那套
機器已經有了。

## 五、真正難的不是切換，是**邊界穿越**——而它有標準答案

鑽進一個分子時，從外面連進來的線要變成什麼？所有工具的答案一模一樣：
**它們變成邊界上的埠。**

```
LabVIEW      connector pane
Simulink     In / Out 埠
Blender      Group Input / Group Output 節點
Unreal       Function 的 Inputs / Outputs
Verilog      module 的 port list
```

推論出**最值得做的第一個互動**：

> **建立一個分子 ＝ 選一群東西 → 切一刀 → 被切斷的每一條邊自動變成一個埠。**

（Simulink 的 Create Subsystem、Blender 的 `Ctrl+G`、Unreal 的 Collapse Nodes
都是這一個動作。）

🔴 它關鍵在於：**使用者先做出一團東西，再決定哪裡是邊界**
——那才是初學者真實的工作方式，而「先設計介面再實作」不是。

## 六、可以偷的產品（附「偷什麼」）

| 產品 | 偷這個 |
|---|---|
| **Simulink** | 邊界埠、Create Subsystem、**mask**（分子對外的參數面板） |
| **LabVIEW** | 一個分子要有**自己的圖示與接線板**——外觀是它的一部分，不是自動生成 |
| **Blender 節點群組** | 進出的手勢（`Tab` 進、`Ctrl+G` 成組）、Group I/O 節點 |
| **Node-RED subflow** | 「模組之間傳訊息」的心智模型最接近；還有 debug 節點——**看得到訊息在跑** |
| **Figma component/instance** | 🔴 **實例可覆寫個別屬性，而仍然跟著母體更新**（「四個輪子，左前輪是紅的」） |
| **Onshape / Fusion 裝配樹** | 樹 ＋ 約束（mate）的 UX；「零件 vs 裝配」的檔案級區分 |
| **Modelica** | 文字端怎麼同時表達階層（class）與連接（`connect()`）——**文字真相**的先例 |
| Scratch 自訂積木 | 初學者的下限；而它**沒有實例語義**，正好標出「簡單」的代價 |

只看兩個的話：**Simulink**（階層與埠的正確性）＋ **Figma**（實例與覆寫的 UX）。

## 七、粒度切換與〈漸進揭露〉是同一族

初學者看到一顆「馬達模組」，進階者鑽進去看到 H 橋。

> **粒度切換 ＝ 結構維度上的漸進揭露。**

鷹架三態（隱藏／淡的／可編輯）與「鑽入深度」是同一種東西——都在回答
「這個學生現在該看到多細」。推論：**課程可以釘住粒度**，就像它今天釘住鷹架。

## 八、三個會咬人的地方

1. **多個實例 → 狀態各自獨立**。執行追蹤要說得出「是**哪一個**輪子」
   ——而變數面板與執行器目前的作用域**沒有實例路徑這一維**。
2. 🔴 **跨層路徑語法**（見 §三）。
3. **來回一致性在階層下更難**：展開與收合**不得改變語義**。
   護欄的形狀已經很熟：`分子 → 展開 → 收合 → 分子` 逐字相同。

## 九、第一刀

1. **定「定義 vs 實例」與跨層路徑語法**（不寫任何 UI）
2. **Collapse-to-molecule**：選一群 → 切一刀 → 斷掉的邊變埠
3. **麵包屑 ＋ 裝配樹 ＋ 鑽入**（縮放不碰）
4. 護欄：展開收合來回一致 · 邊界埠一個都不得遺失

第 1 步排最前面，因為它是**唯一一個三個域都會用到、而且錯了要全改**的東西。
