# 一個可以寫程式操控的世界

> 日期：2026-09-07
> 狀態：**設計未決**——出口是 vision 路線圖（要人拍板），不是直接清償。
> 怎麼冒出來的：使用者先分享了六個 Steam 上的程式遊戲，接著說：
>
> 「我的構想裡面遊戲化是可以有一個**世界觀**，然後**可以寫程式操控**，
> 我舉個例子，像是在虛擬世界**模擬交通**，然後要如何控制交通才能達到目標
> 之類的遊戲，當然**不只這種**，我只是隨便舉例的。我覺得現在的 AI 模型
> 在 3D 建模已經日趨成熟，到時候做出這樣的遊戲世界應該是可以
> **很快速且模組化**的。」

## 一、它不是新架構，是「虛擬硬體」那一刀的一般化

```
Arduino 那一軌   腳位 · LED · 伺服馬達 · 感測器    真硬體
虛擬硬體         同一批東西，而它是模擬的          ← 已在路線圖上（被推遲）
交通世界         紅綠燈 · 車流 · 路口 · 佇列長度    同一個形狀，換一個世界
```

三者的結構相同：**一組會回話的東西 ＋ 一個控制它們的程式**。

而 `concepts/元件.md:517` 的軸表裡，**域**的值已經是
`software / hardware / UI`——一個交通世界要的不是第四個域，
是把 `hardware` 那一格從「真的板子」放寬成「**一個模擬器**」。

🟢 **所以它接得上，而且接得比看起來近。**
⚠️ 而它的**前置是虛擬硬體那一刀**（[history/077](../history/077-虛擬硬體往後推而先做寬度.md)
推遲的那一項）：先有一個「東西會動、而學生看得見」的機制。

## 二、🔴 難的不是 3D

使用者的觀察（資產生成的成本在掉）**成立**，而它讓瓶頸換位置：

> **如果做一個路口變便宜了，那「一個世界」的稀缺性就不在資產上，
> 在【那個世界的規則能不能教會人東西】。**

而規則是**設計**工作，不是生成工作：

```
可預測   學生推理得出來「我改這個，那邊會怎樣」
有張力   不同策略有不同結果，而最好的那個不明顯
可量     達成了沒有——而它要能用一個裁判判
可教     🔴 這一關【非用某個概念不可】，而不是「用什麼都行」
```

⚠️ 最後那一條最難，而它正是 Zachtronics 那批遊戲真正值錢的地方。
**SHENZHEN I/O 是 2D 的**，而它是那一類裡設計得最好的之一
——它的成本幾乎全在關卡，不在美術。

## 三、保真度要跟著「它承載的資訊」走

理論：Mayer 那一系的 **seductive details**——與學習目標無關的生動細節
會**降低**理解，因為它們吃掉工作記憶。而 CLT 是
[concepts/認知鷹架.md](../concepts/認知鷹架.md) 的地基之一。

```
🟢 承載資訊   「這條路塞了」→ 一條線變紅、一個數字往上跳
⚠️ 不承載     車子的建模精緻度、路面材質、天氣
```

🔴 **而這不是「不要做 3D」**——是每一個視覺元素要說得出
**它在傳達哪一個變數**。一個 2D 俯視的路口如果把佇列長度畫得比 3D 清楚，
那它就是對的選擇。

## 四、🟢 如果要做，那個世界該是宣告驅動的

這個專案的每一樣東西都是宣告驅動的——工具箱、課程、面板、互動片段、骨架。
**一個世界也該是**：

```
世界宣告   有哪些東西 · 它們有哪些動作與感測 · 規則怎麼跑 · 怎麼算贏
```

三個後果：

- **交通只是第一個世界**——使用者自己說了「不只這種」，
  而宣告驅動讓那句話成真而**不用改架構**
- 🟢 它接上**第三方 scope**（`@someone:*`，2026-09-06 驗過三層本來就成立）：
  **別人可以做世界**
- ⚠️ 而它逼我們先答一個問題：**世界的規則要不要也用積木寫？**
  如果要，學生與世界作者用的是**同一套工具**——那是這個專案獨有的形狀

## 五、🔴 而定位那條篩子仍然適用

使用者對 Semorphe 的定位逐字：「我希望這成為學生的**輔助輪**，
最終是可以看懂程式碼的」。而那些遊戲要的是娛樂，**通關本身就是獎賞**。

> **一個好玩到讓人不想離開積木的系統，違反的是它自己的定位。**

所以每一關要問：**它讓他更想留在積木裡，還是更想自己打字？**

⚠️ 舉一個會踩線的例子：做「積木關卡」而程式碼那一格鎖著，
那是把三輪車做得更舒服。反過來，「這一關的紅綠燈邏輯**只能用打字寫**」
——同一個機制，方向相反。

🟢 而 [課程重新設計與回饋的粒度](2026-09-04-課程重新設計與回饋的粒度.md) §十一
已經有一條更鋒利的篩子：

> 每一刀都要問一句：**它說的是任務、過程，還是這個人？** 說到人就砍掉。

而多數被叫做「遊戲化」的東西（等級 · 徽章 · 排行榜 · 連續天數）
說的**正是這個人**。⚠️ 而〈離線可用〉那條硬性零**順手擋掉了最有害的那一種**：
排行榜要伺服器。

## 六、而已經在裡面的比看起來多

```
Parsons 題（排回去）      拼圖
除錯題（修好它）          找碴
猜輸出／猜跑幾次          🔴 預測 → 行動 → 揭曉，那是遊戲的核心迴圈
執行覆蓋（琥珀虛線）      看得見的後果
迴圈次數 ×N               即時的量表
裁判 ＋ 輸出 diff         立即回饋
拆輪子的曲線              能力隨關卡解鎖
```

**那已經是一個遊戲的骨架**：目標、障礙、預測、回饋、逐步揭露。
缺的只有兩樣——**一個世界**，和**效率壓力**。

⚠️ 而**沒有一個地方告訴學生這件事**。那可能比再加一個機制更划算。

## 七、兩個 Semorphe 有而那些遊戲沒有的東西

**① 三向同步本身就是一個揭曉機制。**「用積木做出來，然後看它變成的程式碼」
是一個 reveal——而「排回去」那個題型已經在用它了。
那些遊戲只有一種表徵，做不到這件事。

**② 關卡是資料，不是寫死的。** Zachtronics 的關卡是它自己寫的；
我們的是 `lesson.json`。而世界如果也是宣告，那**任何人都做得出關卡**。

## 八、待決

1. 🔴 **第一步是不是虛擬硬體？** 我的判斷是**是**——那一刀會逼我們答完
   所有的結構問題（世界怎麼宣告、東西怎麼回話、裁判怎麼判），
   而它的題材（燈、馬達、感測器）**已經有 14 課的教材在等**。
   ⚠️ 而如果第一個世界是寫死的，第二個就要重寫一次。
2. **離線那條線在哪**——應用已經載 Blockly ＋ tree-sitter wasm ＋ Monaco，
   加一個 3D 引擎與資產是另一個量級。🔴 **那要量，不能猜。**
3. **世界的規則用什麼寫**——積木？宣告？還是一份 JS？
   （⚠️ 第三個會讓「世界」變成一個外掛，而那與元件系統的形狀不一樣）
4. **效率壓力怎麼進來**——「跑了幾步」的資料已經在（執行事件），
   而 `cpp-advanced` 第 1 課**教的就是複雜度而沒有回饋**
5. ⚠️ **一個人維護**：遊戲要美術、關卡設計、數值平衡，
   而那是另一種工作量——**它會吃掉教材本身的時間**
