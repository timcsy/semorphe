# 膠囊要怎麼離開這個 repo

> 2026-08-20　從「老師能不能自己加東西」的一次判錯裡分出來的
> ⚠️ **狀態：問題已定位，解法未定**

## 一、先記那個判錯，因為它是這一篇的來源

我（AI）在比較 TextBricks 時列了一條「Semorphe 輸的地方」：

> ❌ 「加一顆元件要跑 component-pipeline 五個 skill，這是給開發者的路徑，不是給老師的。」

使用者一句話推翻：**「其實 Semorphe 已經把 skill 準備好了，老師隨時可以用。」**

而它錯在兩層：

```
① skill 就是介面      老師打的是 /component-pipeline cpp <algorithm>，不是 JSON
                      「會不會寫 TypeScript」這個門檻【不存在】
② 更糟的一層          我把它列成【劣勢】，但它是可驗證性的【價格】
```

## 二、而那個價格收在對的地方

`component-pipeline` 的規則 2：

> **五個階段缺一不可。** 不可以因為「概念很簡單」、「已經有類似概念」、
> 「時間不夠」等理由省略任何階段。

對照 TextBricks：老師可以隨手加一個模板——**也可以隨手加一個錯的**，
而沒有任何東西會擋。它的「開放」和它的「沒有測試」是同一件事。

```
TextBricks   創作容易，品質無關卡
Semorphe     創作被包成一個指令，關卡不可跳過
```

> **把品質關卡編進創作動作裡，於是「讓非開發者貢獻」不必用「降低品質」來換。**

⚠️ **而這只有在內容是結構、可以被機械驗證時才成立。**
TextBricks 的模板是字面文字，沒有東西可以驗——所以它**不能**做這件事，不是不想做。

（這條教訓的長期歸宿是 `experience`，本檔只留來源。）

## 三、🔴 所以剩下的不是創作，是分發

`component-pipeline` 階段零是 `git checkout -b {NNN}-{lang}-{short_name}`
——產物落在 `src/components/` 的一條 feature branch 上。

| 情境 | 今天 |
|---|---|
| 一個老師為自己的班加概念、自己部署 | 🟢 **已經可以**，skill 走完就有 |
| 老師把一顆元件**發給另一個老師** | ❌ 沒有那個單位 |
| 學生裝一個「某某老師的補充包」 | ❌ 同上 |

而 [元件](../concepts/元件.md) 已經標好缺口在哪：

> 現行 scope：`lang`（32 顆）、`cpp`（145 顆）。
> **未落地：`hw`（硬體）、`@<user>`（第三方）。**

`@<user>` 就是那個位置。

## 四、而膠囊化已經把可搬移的單位做出來了

177/177 膠囊化（P9 的「碎裂」歸零）讓「一顆元件 = 一個目錄」成立
——**可搬移的單位已經存在**，缺的是它能不能離開這個 repo。

> **驗收條件：一顆膠囊要怎麼離開這個 git repo，
> 然後在另一個人的 Semorphe 裡被載入？**

🔴 **而這正是膠囊化那一刀的驗收條件，只是場地從「這個 repo 裡」換到「repo 之外」。**
如果搬不走，代表膠囊的邊界還不夠乾淨——而那件事在 repo 內測不出來。

## 五、⚠️ 而它撞到一條已知的邊界

[開放擴充](../concepts/開放擴充.md) §「這個架構今天只去得了 Vite 的宿主」：
Layer 3 仍然是 TS 函式。一顆含 Layer 3 strategy 的膠囊，
**搬走之後要怎麼被載入**是未解的——純 JSON 的 Layer 1（~80%）沒這問題。

於是分發可能天生分兩級：

```
Layer 1 純 JSON 的膠囊   可以是【資料】，發得出去
含 Layer 2/3 的膠囊       是【程式碼】，要走 build
```

⚠️ **而這個切法還沒被驗證**——要先量「一顆典型的教學用膠囊落在哪一級」。
