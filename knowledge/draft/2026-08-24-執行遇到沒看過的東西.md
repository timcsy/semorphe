# 執行遇到沒看過的東西——不准繼續，而出口有三條

> 2026-08-24　使用者：「執行的部分，我是想要誠實，**如果沒看過的東西就不要執行下去了，
> 要誠實的說沒看過**，有三種方式：第一是使用者**親手去修改 Runtime 的狀態**（透過變數等等的面板），
> 第二是**連線外部 Runtime**（例如 Debugger 或是我們有提供或是合作的外部元件），
> 第三是**停止執行**。」
>
> 🟢 **第二刀已交付（2026-08-26）**：出口①（親手改狀態）＋ ③（停止）做完了
> ——跑到認不出來的東西會**停在那裡**，變數面板在暫停中改得動，然後繼續或停止。
> ⚠️ 而下面「未決」的第一、二、三題**被實作繞過而不是答掉了**：
> 新 `reason` 叫 `'unknown-component'`（沒有新的 `SkipReason`）；
> 手填的值直接落進 `scope`（**沒有**進「這次執行的輸入」，所以**重播不出來**）；
> 可見性只做到主控台兩行。🔴 **重播那一題仍然開著，而它是 `模擬的誠實` 第一條。**
> → [history/174](../history/174-規範立錯了半天而使用者一句話把它翻過來.md)
>
> 🟢 **第一刀已交付（2026-08-26）**：`'skip'` 退場——「不繼續」這一半做完了，
> 三條出口一條都還沒做（下面的「未決」五題仍然全開）。
> → [history/173](../history/173-拿掉錯的那個答案問題也跟著消失.md)
> 🟡 **狀態：已升格（2026-08-24）**——路線圖項目 `vision.md` 階段 8「**執行的誠實：沒看過就不繼續**」。
> **這一份是它的 in-flight 設計理據，做完才反流退場。**

## 一、今天的實況——而它的兩個答案裡有一個正是要拿掉的

```ts
// src/ui/execution-controller.ts:303（另外兩處同形）
const skip = confirm('Unknown component "X" encountered.\n' +
                     'Click OK to skip it and continue, or Cancel to stop execution.')
return skip ? 'skip' : 'abort'
```

```ts
// src/interpreter/interpreter.ts:309
const action = await this.unknownComponentHandler(component)
if (action === 'abort') throw new RuntimeError(UNKNOWN_COMPONENT, { component })
// 'skip' — 繼續執行
return
```

🔴 **`'skip'` 不是「跳過一行」，是「帶著錯的狀態繼續跑」**：那一行本來要指派一個變數，
現在沒有，而後面每一行都建立在那個沒發生的事情上。使用者按下 OK 時看到的是
「skip it and continue」，**而他不會知道自己同意了什麼**。

### ⚠️ 而靜默繼續有**兩條**路，不是一條

| 路 | 觸發 | 今天的行為 |
|---|---|---|
| `unknownComponentHandler → 'skip'` | 沒有執行器 | 使用者按 OK → 靜默繼續 |
| `isSkipped(component, 'execute')` | 概念**宣告**了刻意不執行 | **直接靜默 return**，使用者完全不知情 |

第二條更隱蔽：`python:with` 宣告了「這個直譯器沒有 `__enter__`／`__exit__` 也沒有檔案系統」
——那個理由寫得很好，**而它從來沒有被拿給使用者看過**。

> 🟢 **推論（免費的收穫）**：這一刀會讓 `declareSkips` 的理由**第一次被投影出來**。
> 一份寫了很久的宣告，它的第一個消費者是使用者的眼睛。

## 二、三條出口，逐條看它在這個架構裡是什麼

### ① 使用者親手改 Runtime 狀態

🟢 **它與 `inputProvider` 是同一個形狀**（`interpreter.ts:61`）：

```ts
private inputProvider: (() => Promise<string>) | null = null   // cin / input() 用的
```

直譯器**已經會**為了要一個值而暫停（`ExecutionReason = 'awaiting-input'`）。
「你來告訴我這個運算的結果」與「你來告訴我 `cin` 要讀什麼」在機制上是同一件事。

🔴 **而這推出一條硬要求**：手填的值**必須進「這一次執行的輸入」**，與 stdin 同一類。
理由是 `concepts/模擬的誠實.md` 的第一條：**可重現 > 擬真**。
一個沒有被記下來的手填值，會讓同一份程式跑兩次得到不同答案——
**那正是這個系統拿來量正確性的東西壞掉**。

⚠️ **而它有一個教育上的風險**：學生手填答案就能讓程式「跑對」。
所以手填的值要**看得見**（在輸出／時間軸上標記），
否則我們是在教「不會就自己填一個」——那與 P6 誠實降級是反的。

### ② 連線外部 Runtime——🔴 它其實是**兩件事**，而它們的難度差一個數量級

| | 什麼時候決定 | 例子 | 難點 |
|---|---|---|---|
| **②a 單一呼叫委派** | **執行中** | 讀一個感測器、呼叫一個外部元件 | 狀態不用搬——只是一個值回來 |
| **②b 整段執行委派** | **執行前** | 外部 Debugger、真板子 | **跑到一半交不出去**：狀態、堆疊、行號都要搬 |

②a 正是 `draft/硬體不是一個階段是兩類` §三 那一則：
「**常駐服務的真正角色是 adapter，不是通訊管道**」。
②b 是 `draft/執行器是可插拔的` 的 Runner 契約。

> **把兩者混成「連線外部 Runtime」一句話，會讓人以為②b 也可以在執行中做——而它不行。**

### ③ 停止執行

已經有（`abort` → `RUNTIME_ERR_UNKNOWN_COMPONENT`）。要改的只有**訊息**：
今天說的是我們的內部詞彙（「未知概念」），而該說的是那個概念的宣告理由。

## 三、詞彙：這其實是「**暫停 ＋ 問人**」，不是三個新狀態

`ExecutionStatus`／`ExecutionReason` 是**封閉詞彙**，而 `concepts/執行機構.md:279` 的門檻是
「**第三個值就是在替『還沒做』找一個體面的名字**」。所以先問：這需要幾個新值？

```
狀態    paused          ← 它就是暫停：程式沒有結束，在等一個決定
reason  ？（新的一個）   ← 「遇到一個我沒看過的東西」
動作    ①②③            ← 那是【暫停狀態上的三個動作】，不是三個狀態
```

🎯 **推論：可能只需要一個新的 `reason`**，而 ①②③ 是 UI 在那個暫停上給的三個按鈕。
⚠️ 而它與既有四個的性質確實不同：
`refused` ＝ 根本沒開始 · `aborted` ＝ 使用者喊停 · 這個 ＝ **跑到一半遇到不會的**。

## 四、🔴 `confirm()` 必須退場——沒有 DOM 的宿主答不了

今天這個決定是用**瀏覽器的 `confirm()`** 問的，而它住在 `execution-controller` 裡。
那讓「遇到沒看過的東西」變成**視圖層的一個對話框**，於是：

- VSCode 那側不能用（它有自己的 UI）
- `examples/bring-your-own-view/` 那種 Node 宿主**根本沒有 `confirm`**
- 外部 Runner（②b）接進來時，這個問題會問到一個不存在的地方

→ **它要變成匯流排上的一個請求／回應**，與 `execution:*` 同一族
（見 `draft/執行器是可插拔的`）。**宿主決定怎麼問，執行器只知道自己在等一個答案。**

## 五、還有一件今天就做得到的：**執行前先說**

「沒看過」有一半是**靜態就算得出來的**：一棵樹裡有哪些概念沒有執行器、
哪些宣告了刻意不執行——`declareSkips` ＋ 執行器登錄表今天就答得出來。

> **在按下執行之前就說「這段我不會跑」，比跑到一半停下來好。**
> 教育場景尤其：學生要的是「哪裡不行」，不是「跑到哪裡停了」。

所以是**兩層**：**執行前的清單**（靜態）＋ **執行中的攔截**（動態才知道的，
例如某個方法呼叫的接收者型別）。

## 六、⚠️ 「沒看過」有兩種，而它們的處置不同

| | 例子 | 能不能有第①條出口 |
|---|---|---|
| **我沒有實作** | `with`、某個沒做的方法 | ✅ 手填一個結果是合理的 |
| **我不可能知道** | 真板子的感測器、檔案內容、亂數 | ✅ 但它已經被 `模擬的誠實` 管著：**不准編一個數字** |

第二類不是這一刀新增的——`concepts/模擬的誠實.md` 三條規則已經定案。
這一刀是把**第一類**從「靜默跳過」搬到同一條線上。
