## Cella 那邊理解的現實（cella 窗口整理）

- 兩邊都成立的照轉。
- Lean 用到而 Cella 沒有的公理（證明唯一、排中律、選擇）轉進 Cella 時，變成**看得見的 assume**。
- Cella 用到 univalence 的標成**翻不了**。
- Cella 端的 Lean 互通排在發表之後（長期推薦）。

## 與既有方向的關係（不衝突，是同一條線往前）

[意思歸 Cella、轉換與呈現歸 semorphe](2026-11-05-意思歸Cella-轉換與呈現歸semorphe.md) 的判準照舊：
- **轉換本身在 semorphe**：產道地的目標語言寫法（形式），學生讀得懂——不讓 Cella 把中間表示反譯成目標語言。
- **意思由 Cella 給或標出**：兩邊各判一次當裁判；意思會變的地方（溢位、負數除法、別名、公理）逐行標出；翻不過去的照 P6 誠實降級在那一行。
這次的新東西只有兩件：**範圍**（從「要不要排」變成「盡量互轉」）與**多一個語言**（Lean 4）。

## 做法（推薦）

1. **互轉的機制**：來源程式 → semorphe 語意樹 → 目標語言的道地寫法（semorphe 的產生器與等價邊，`cross-language-equivalence` 已在量哪些元件跨語言是同一個角色）。
   驗收：來源與目標各自 formalize、交給 Cella 判，**判決相同（含 `assumes`）才算沒失真**；不同的地方標在那一行。
2. **Lean 4 課**：Lean 4 當成 semorphe 的一個新語言（`add-language` skill：文法、元件、積木、課程）。
   🟡 判決怎麼來是關鍵前提：Cella 的 Lean 互通在發表之後——在那之前 Lean 課的程式沒有裁判，只能做形式（讀、寫、積木），**不能說對或錯**（P6）。
3. **Cella 課**：照 [回覆](2026-11-07-Cella-語法的投影與課程——回覆探詢.md)——程式碼英文標準格式、中文在積木上，新語法定案後才寫。

## 進度（第一對 C → C++）

### 第一刀（334，2026-11-07 晚）：I/O 換成 C++ 的寫法
- 轉換：`src/languages/cpp/c-to-cpp.ts`。`printf`／`scanf` → `cout`／`cin`，**格式與 Cella 給的型別對得上才換**（spec 215 的型別表反過來用）；
  對不上就保留（printf 本來就是合法的 C++，P6）：寬度／精度、`%f`（printf 印 6 位小數、cout 印 `%g`）、`%c` 配 int、scanf 格式裡的逗號、用到回傳值的 scanf。
  原文寫的 C 標頭換成 C++ 的名字（`<stdio.h>` → `<cstdio>`）。
- 入口：使用者在選單上把 C 切到 C++ 時換，提示「換了幾行、保留幾行（換了會變意思）」。課文釘目標那條路不換（接著會放進那一課自己的程式碼）。
- 驗收（就是這份 draft 定的那條）：護欄 `tests/integration/c-to-cpp-verdict.test.ts`——c-bridge 課文的 8 支 C 解答與 7 支「該保留」的例子，兩邊交給 Cella 判，判決、輸出、`assumes` 相同。
- 這一刀掀出來的既有缺陷（都已修）：舊的 printf → cout 風格規則只搬引數、丟掉格式字串的文字與換行；運算式位置的 scanf 會被換成語句；
  還有 printf 時仍提議把 cstdio 換成 iostream；多宣告子 `int a = 7, b = 3;` 執行後被標「沒跑到」。

### 下一刀的候選（照「最便宜、學生最常見」排）
1. 🟢 **（336 已做：先補轉型）** 量到的結果：C 慣用的不轉型寫法連 C 本身都判不出、來回一趟還會變成 `(void)malloc`（335 修了）；換到 C++ 時補 `(int*)`（336），兩邊判決相同。🟢 **換成 `new[]`／`delete[]`：348 做了（第四刀，2026-11-08）**——整支程式全有或全無：每個 malloc 都是指標宣告的初值且元素型別對得上、每個 free 的對象都在名單上、那些指標只被 free 或透過它取位置（`p[i]`、`*p`、`p->x`）；別名、`p++`、型別對不上 ⟹ 整支保留（換錯是 UB）。c-bridge 第 4 課兩支解答換成 `new int[n]`／`delete[] a`、兩邊 Cella 判決相同。原本的這一條：**`malloc`／`free` → `new[]`／`delete[]`**：c-bridge 第 4 課整課在講它。⚠️ C 慣用的 `int *a = malloc(n * sizeof(int));`（沒有轉型）在 C++ 裡**不合法**
   ——今天課文的解答剛好寫了 `(int*)`，所以沒露出來。先量 Cella（lang cpp）收不收沒轉型的那種：收的話是 Cella 的缺口（回報），不收的話這一刀就是必要的不是美化。
2. 🟢 **（337 已做：第三刀）`struct Point p;` → `Point p;`**：只動型別、只動程式自己宣告的 struct（936ffbad）。C++ 不需要 `struct` 關鍵字（合法但不道地）——純形式，Cella 判決不受影響。
3. 🟢 **（349 做了：第五刀，2026-11-08）`%.2f` → `fixed << setprecision(2)`**：沒有去追「改了串流狀態會影響後面每一行」——改成**每一次浮點輸出都明寫自己要的狀態**（`fixed << setprecision(N) << x`；`%f` 是 N＝6、`%lf` 同 `%f`）。原本的 C 程式全是 printf，換完之後每個浮點輸出都自帶狀態、保留下來的 printf 不受 cout 狀態影響、整數不受 fixed／精度影響 ⟹ 不用追蹤。唯一會被影響的是換成預設 cout 的 `%g`：整支程式有 fixed 時 `%g` 那幾行保留 printf。兩邊 Cella 判決的輸出逐字相同。
   ⟹ 第一對 C → C++ 剩下的失真都是**故意保留**的：寬度（`%5.2f`）、`%c` 配 int、scanf 格式裡的逗號、用到回傳值的 scanf（換了會變意思）。
4. 🟢 **（357 做了，2026-11-08）反方向 C++ → C**：原本寫「已經有（C 目標，spec 146／215）」——量到不成立：c-bridge 11 支 C 解答走 C → C++ → C 一趟 11/11 reject（`using namespace std;` 留著、`new int[n]` 不是 C）。補 new／delete → malloc／free（整支全有或全無）、C 目標不印 std 的 using、struct 標籤；「來回一趟判決不變」收成護欄 `cpp-to-c-verdict` → [351](../history/351-整合359四刀與三個被翻不出蓋住的改寫.md)。⟹ 第一對兩個方向都齊。
