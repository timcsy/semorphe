## 一、cpp Library 的分工會成為通則

「C++ 的語義住 Library、積木對應住膠囊」推廣出去就是同一個模式的重複：

```
cella-lib-cpp        int 的寬度、溢位、除以零           ← 第一個實例（2026-10-05）
cella-lib-units      物理量的量綱（V × A ＝ W）
cella-lib-circuit    克希荷夫、一條網只有一個 driver、腳位電流上限
cella-lib-mech       力矩、行程範圍
```

那正是套件協定的「② 詞彙套件」（從 ROS `.msg`、Maven BOM 推出來的）。
🟢 **量綱大概是最划算的第二個**：跨所有領域、純計算、錯了代價大（火星氣候探測者號）。

## 二、價值與風險同時放大

**價值**：回饋迴路逐域變慢（軟體每次編輯 → 硬體分鐘 → 3D 小時 → 機器人不可逆）。
軟體裡 L1（執行期檢查）便宜，cella 是錦上添花；機器人裡 L1 是**太晚**，
除了物理攔截（限位開關、力矩上限），事前證明是唯一的防線。
⟹ **cella 最有價值的地方，正好是 Semorphe 要去的那些領域。**

**風險**：`Nat` 那一課會更危險。用 `Nat` 代表 `int` 證的是另一支程式；
在物理領域，模型與現實的落差更大——「電流 ≤ 40 mA」是相對於**理想元件**的模型，
而摩擦、雜訊、負載下失速、材料強度不是演繹出來的。

這就是**演繹／經驗之牆**。推廣之後每條契約要說得出它的判定是哪一種：

```
formal      cella 證得出來           克希荷夫、量綱、RAM 加總 ≤ 2048
reference   對照真實環境或模擬器      馬達在負載下的轉速
human       要人判斷                 這個結構看起來穩不穩
```

> **把經驗性的東西寫成形式證明，會在一個理想化的模型上得到 0 個洞——那是最危險的綠燈。**

## 三、組裝約束第一次有判官

「這條網只有一個 driver」「Σ RAM ≤ 2048」「這一格能接什麼取決於隔壁那一格」——
Blockly 的接點檢查是靜態字串，表達不出來；在依值型別裡是**組裝層的義務**
（也正是「組裝」被拆成獨立主體的原因：就近性說它們不屬於任何一顆元件）。

## 四、跨投影的保證——Semorphe 獨有的位置

一個 Arduino 專案同時是程式（`cpp.avr`）與電路（`circuit`）。
「程式設成輸出的腳，電路上的負載電流不超過腳位上限」這種命題，**任何單一領域的工具都說不出來**
——編譯器不懂電路，EDA 不懂程式。Semorphe 手上有兩邊的語義樹，配上 cella 就證得出
**跨投影的一致性**。這是 ArduinoCAD 合流最有價值的理由之一。

## 五、代價

1. **誰寫每個領域的 Library**：要懂那個領域的人 ⟹ cella 說的「第二個發布者」——
   套件管理與簽章兩個觸發同時被拉到；「教材帶的元件庫要不要被信任」從理論變現實。
2. **錯誤訊息要講領域的話**：不是 `InRange 16 60000`，是「13 號腳 62 mA，超過 40 mA」
   ⟹ 人面投影從「翻 C++ 的前置條件」變成每個領域一套詞彙表。
3. **速度**：每多一個 Library 多一份載入與重驗，瀏覽器裡要量。
4. **不是每件事都該證**：由嚴重度決定——可重來的用 L1，不可逆的才值得 L3。

## 六、對形式化證明課程的意義

題材不必是抽象的數學命題：

> 「證明你的電路不會燒掉 LED」·「證明手臂不會轉出行程」·
> 「這個證明為什麼證不出來？——因為摩擦力不是演繹出來的」

最後那一句——**學生親眼看到證明的邊界在哪**——可能是整門課最有價值的一課。
