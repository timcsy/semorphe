# 操作說明要「會過期就變紅」

> 日期：2026-09-04
> 狀態：**設計未決**——出口是 vision 路線圖（要人拍板），不是直接清償。
> 怎麼冒出來的：使用者：「能不能重新規劃一下所有課程，加入 Semorphe 怎麼使用，
> 讓使用者習慣，不知道是否可以搭配腳本錄製 GIF 說明，這樣使用者比較知道要拉哪裡。
> 還有，點擊時滑鼠是可以被錄製到的嗎？」

## 一、先回答滑鼠：預設錄不到，而我們可以自己畫

Playwright 錄的是**頁面內容**，作業系統的游標不在裡面——所以現有那四支示範
畫面會自己動，而看不到誰在動它。

🟢 解法：**把游標畫在頁面裡**。`mouse.move`／`click` 送的是真的 DOM 事件，
所以注入一小段 listener 就收得到座標，畫一個小箭頭跟著跑、按下時畫一圈漣漪。

```
withCursor(page)   ← 一支 helper，每支錄影開頭呼叫一次
                     不必改任何一支既有腳本的內容
```

⚠️ 兩個實作要點：`mouse.move` 要帶 `steps`（不然是瞬移，看起來像跳格）；
那顆假游標必須 `pointer-events: none`，否則它會擋住真正要點的東西。

🔴 **待實測**：它在 Blockly 的 SVG 與拖曳層上會不會被吃掉。

## 二、🔴 不要把「怎麼用」抹在 66 堂課上

兩個理由，而第二個比較重要：

1. **會腐爛**：UI 改一次，66 課的操作說明就有一部分變成謊話
2. **它與輔助輪的定位衝突**（`concepts/認知鷹架.md`「三輪車不是輔助輪」）
   ——**一個需要被教的工具，是在增加認知負荷**。我們在教程式，不是在教 Semorphe

所以分三層，而**只有一層在課文裡**：

| 層 | 放哪 | 內容 |
|---|---|---|
| 一次性的入門 | 一堂「第 0 課」或一條很短的軌道 | 三邊同步是什麼 · 怎麼拖 · 怎麼執行 · 骨架為什麼是淡的 |
| **可重用的互動片段** | 課文頁自動插入 | 6～8 個 3 秒的小片段（拖積木、切對照、按執行…） |
| **就地提示** | **在 app 裡**，不在課文裡 | 第一次遇到某個互動時畫面上一句話 |

🔴 **第三層才是真正解決「不知道要拉哪裡」的東西**：

> **課文是靜態的，而卡住是動態的。**
> 只有 app 知道他現在停在哪一步、拖了幾次沒成功。

## 三、用腳本錄的真正理由，不是省時間

> **一張手工截的圖是死的；一支腳本錄的片段是【活的】——按鈕搬家時它會紅。**

這個機制已經有了（`tools/demo/record*.spec.ts` 每一支都有斷言，錄壞會失敗
——2026-09-03 那次「錄壞三次」就是它擋下來的）。把操作說明做成腳本錄製，
等於**讓文件變成會過期就變紅的東西**。

## 四、宣告驅動：課程說它用到哪些互動

```json
{ "title": "for迴圈",
  "interactions": ["drag-block", "edit-code"] }
```

→ 產生器在課文頁自動插入那幾個片段
→ 護欄**兩個方向**：宣告的互動都要有錄製檔 · 有錄製檔的互動都要有人用

⚠️ 形狀與既有的一致（工具箱、課程、面板都是宣告驅動）——**不要為它發明第二種
宣告方式**。

## 五、⚠️ 它與「秒開」有真的衝突

課文頁現在是 **7.5KB、零外部請求**，那是它的體驗與排名的基礎。三張 GIF 進去，
一頁會變成 MB 級。

兩個緩解，建議都做：

- **用 webm 不用 GIF**：同樣 3 秒的 UI 動畫，webm 約是 GIF 的 **1/5～1/10**
  （`muted autoplay loop playsinline`，行為與 GIF 一樣）
- **`loading="lazy"` ＋ 只放在需要的那幾課**

🟢 護欄第 ④ 條（課文頁不得載入任何 JS）**不受影響**——影片是媒體不是程式碼。
🔴 而要**新增一條「一頁的媒體總量上限」**，否則秒開會被慢慢吃掉。

⚠️ 而 README 與課文頁要**不同格式**：GitHub 會把 webm 變成一個播放器（不自動播），
所以 README 用 GIF、課文頁用 webm——**同一支影片轉兩種**。

## 六、建議的第一刀（小、可驗、不動 66 課）

1. `withCursor()` helper——假游標 ＋ 點擊漣漪
2. 錄 **3 個片段**：拖一顆積木進畫布 · 切「對照」· 按執行看主控台
3. 第 1 課的課文加一段「開始之前」，嵌那三個片段
4. 護欄：宣告的互動要有檔、有檔的互動要有人用
5. **看效果再決定**要不要做第 0 課／整條軌道

🔴 **不建議現在重寫 66 課**——先讓那三個片段活一陣子，看使用者是不是真的卡在那裡。

## 七、待決／待查

1. 假游標在 Blockly 的 SVG 與拖曳層上會不會被吃掉（實測）
2. webm 在課文頁的實際大小與自動播行為（各瀏覽器）
3. 「就地提示」要怎麼知道使用者卡住了——時間？失敗的拖曳次數？
   ⚠️ 而它與「本地的成效指標」（[[拆輪子的曲線]]）用的是**同一份資料**：
   誰在編輯、編輯了幾次。兩者可能該一起設計
4. 第 0 課要不要存在，還是「開始之前」那一段就夠
