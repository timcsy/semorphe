# 工具箱裡的範例

> 日期：2026-08-20
> 怎麼冒出來的：使用者要我研究 <https://ai-ky.github.io/blocks/>
> （「長得像原始碼的積木」，單人維護的教學站，Python ＋ Arduino 兩個 Blockly 編輯器）。
> 調研列出六條可參考的東西，而經過兩輪收斂之後**只剩這一條**。
> **狀態：機制未決，內容未決。** captured ≠ committed。

## 一、他們做了什麼

2487 個 `<block>` 條目手寫在一份 247KB 的 `py/code/index.html` 裡，
而其中大量**不是單顆零件，是整串接好的範例**——前面預先掛著中文註解積木，
拖一次出來就能跑。點某些分類還會即時跳出對應的 YouTube 教學連結。

一個「邏輯判斷」分類裡的條目，展開之後是：

```
import random  →  #隨機生成0~3的整數指定給i  →  i = random.randint(0,3)
               →  #如果i等於0  →  if i==0: print("i等於0")
               →  #否則如果i等於1  →  elif …  →  #否則  →  else …
```

**一個條目 ＝ 一課的份量。**

## 二、🔴 而它與我們已經有的兩樣東西都不一樣

```
預組   一組【總是緊鄰出現】的呼叫，折成一個 flyout 項目   防【裝錯】   相鄰出現率決定
教材   線性、有順序、有目標、人寫的散文                   給【路徑】   lessons/<課名>/
範例   一段完整、可跑、有註解的程式，從工具箱拖出來        給【動機】   ？
```

- **預組** → [套件積木的粒度與預組](2026-08-17-套件積木的粒度與預組.md)。
  它的判準逐字是「**一組預設要進工具箱，理由必須是「學生自己組會裝錯」，
  不是「這樣比較快」**」。
  ⚠️ **而範例過不了那條判準**——沒有人會「裝錯」一個範例，範例的價值不在防錯。
- **教材** → `lessons/`，兩課已經寫完（spec `124`／`125`）。
  而 [教材要如何呈現](2026-08-14-教材要如何呈現.md) §七 已經切過一刀
  （教材線性 vs 圖鑑可查），**而範例是第三種：拿去改。**

> 🔴 所以它不是那兩者的擴充，是第三種東西——
> **而第三種東西要先證明自己賺得起一個新機制。**

## 三、真實來源存成什麼（開放問題一，🟢 而公理幾乎已經答了）

ai-ky **只能**手寫 XML，因為他們的 lift 是 regex 玩具。
`py/code/python2xml.html` 的 `parseBlock()` 逐字：

```js
if (content.includes('=') && !/^(if|elif|while|for|def|try|except|finally|with)/.test(content) && !content.startsWith('#'))
```

含 `=` 就當賦值，而產出幾乎全是 `python_any` 文字塊。**他們沒有選擇。**

🟢 **我們有真 lift** → 範例可以就是一個小的 `.cpp`／`.py` 檔，積木形態是投影出來的。

> **一份範例如果存成積木樹，它就是第二個真相來源。**

而這正是 [預組](2026-08-17-套件積木的粒度與預組.md) §三 記過的病，逐字：

> 「一份『登錄表推不出來所以手寫』的清單，加到第二筆的時候還好，
> 加到第二十筆的時候它就是第二個真相來源。」

⚠️ **而範例是最容易長到第二十筆的那一種**——它只會越加越多。

⚠️ 而 `lessons/` **沒有**提供先例：第一課只有 `lesson.md` ＋ `goal.txt` ＋ `images/`，
**沒有 `start.json`，學生自己打**。
所以「範例存成什麼」在這個 repo 裡**一次都還沒被決定過**。

## 四、與 Topic 的咬合（開放問題二，🔴 真正未決的那個）

`src/languages/cpp/topics/*.json` 今天純粹是**詞彙可見性**——
`levelTree` ＋ 每層的 `components` 清單，**一段程式都沒有**。

> **Topic 說「你這一層認得哪些字」，範例說「這些字拼起來能做出什麼」。**

三種咬合：

```
① 完全獨立       範例自己一個 registry，Topic 不管它
                 ⚠️ 學生會看到用了他還沒學到的概念的範例

② Topic 過濾     範例宣告用到哪些 componentId，由 level 決定看不看得到
                 🟢 便宜，而它只要求範例宣告自己的外延——【那是算得出來的】

③ 範例反推 Topic  由範例導出 topic.json 該包含哪些概念
                 🟢 順帶解掉 arduino.json 描述裡那句自承的「⚠️ 手寫」
                 🔴 而它把兩個系統綁死
```

🔴 **而 ② 不是新機制**——它與 [教材要如何呈現](2026-08-14-教材要如何呈現.md) §一
是**同一個形狀**，那條已經 dispatch 進 [concepts/元件](../concepts/元件.md)：

> 「**教材宣告目標，元件集合是它的外延。**」

> **一條規則有第二個實例，比它只有一個實例時可信。**
> 而那本身就是判斷 ② 對不對的證據。

## 五、⚠️ 兩個風險都是繼承來的，不是新的

1. **選項爆炸** → [漸進揭露把選項轉嫁給了老師](2026-08-12-漸進揭露把選項轉嫁給了老師.md)。
   一個塞滿範例的工具箱，「該拉哪一個」的負擔就從系統轉給學生。
   ⚠️ **而範例比預組更佔位置**——它是一整段。
2. **手寫清單 → 第二個真相來源**（§三）。

## 六、而內容【也】要等資料——與預組同一個理由

「哪些範例值得收」等的是同一批東西：
[history/077](../history/077-虛擬硬體往後推而先做寬度.md) 決定的那批 AI 生成語料。

⚠️ **而範例還多等一樣**：
[教材要如何呈現](2026-08-14-教材要如何呈現.md) §九／§十 的出口條件
「**第二個人走過一遍**」——到今天**還沒有發生**。

> **一個給動機的東西值不值得做，取決於今天卡住學生的是不是動機
> ——而我們沒有那個資料。**

## 七、順手撿的一個 UX（與本題無關，記在這裡免得掉）

ai-ky 的 flyout（`py/code/index.html` 的 `handleClick` 逐字）：

> 「(按住shift鍵拖曳可維持選單,按住ctrl鍵可拖曳單一方塊)」

解決「連拖五顆要重開五次分類」。
⚪ 便宜、可逆、與範例庫無關——**想到就做，不做也不損失什麼。**
