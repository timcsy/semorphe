# 線上載入有時候二十幾秒——量出來是託管，不是程式碼

**日期**：2026-09-16
**觸發**：使用者：「我發現有時候在正式網頁載入的時候，js 會載十幾秒到二十幾秒」
**狀態**：🟠 **已量測、已定位、刻意先不修**（使用者拍板：先記錄）

## 量到什麼

線上冷開五次（Playwright，`semorphe.com`，每次新的瀏覽器情境）：

```
#0  19.2 秒   （monaco 18.1 秒）
#1  27.2 秒   （monaco 26.0 秒）
#2   1.1 秒
#3   1.0 秒
#4   1.0 秒
```

而 `curl` 對同一個檔重複量，同一分鐘內 **0.5 秒 … 11.2 秒**：

```
首位元組      0.22–0.55 秒      ← 伺服器回得很快，不是延遲
整包傳完      0.5 … 27 秒       ← 約四成的請求掉到 ~35 KB/s
x-served-by   cache-sin-…       ← GitHub Pages ／ Fastly 新加坡節點
```

> **一個「有時候很慢」的回報，先分開【延遲】與【吞吐】——
> 首位元組快而總時間慢，那不是伺服器在想，是位元組在滴。**

## 🔴 根因有兩個，而第二個是可以指著的

```
① 吞吐不穩          GitHub Pages 的邊緣節點對台灣約四成請求掉到 35 KB/s
② cache-control: max-age=600    對【所有】檔案，包括檔名帶雜湊的那些
```

②才是真正該生氣的那一個：`index-DsvbotmI.js` 這種檔名**內容永遠不會變**，
本來該是 `immutable, max-age=31536000`。而 GitHub Pages **不讓你設標頭**。

於是：**每過十分鐘，每個學生的瀏覽器就重抓一次那 1.6 MB**
（index 745 KB ＋ monaco 837 KB，都是 gzip 後）。撞上①就是二十幾秒。

⚠️ 而我們這邊**沒有 service worker** 接得住——`e2e/offline.spec.ts` 守的是
「不得向外部主機要東西」，不是離線快取。兩件事名字像而不是同一件。

## 三條路（都沒做）

| 做法 | 省下什麼 | 代價 |
|---|---|---|
| 🟢 換 Cloudflare Pages | 雜湊檔案拿得到 immutable ⟹ 每次部署只付一次；吞吐也穩 | 要改 DNS 與開帳號——**不是我做得到的** |
| 🟠 service worker 預快取 | 第二次之後 0 秒；教室裡三十台共用一條 wifi 特別有感 | 更新流程要設計好，**做壞的症狀是學生卡在舊版而不知道**——比慢更糟 |
| 🟠 Monaco 延後載 | 首次 1.6 MB → 0.75 MB，壞尾巴約減半（27 → 13 秒） | 它是靜態 import，要動開機順序；而[history/239]才剛修好一個開機的競態 |

🔴 **第三條只是減半，不是解決**——而它動的正是今天出過事的那一段。
判準：**先換託管，再談要不要瘦身**。在①②還在的時候瘦身，省下的會被吞掉。
