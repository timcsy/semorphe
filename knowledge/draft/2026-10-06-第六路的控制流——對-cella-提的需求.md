## 一、答案站在三條已定的設計上

```
洞 → 積木          vision〈第六路〉：每一個前置條件對得回語義樹的節點（nodeId）
對應住膠囊          每顆元件把自己投影成 cella 的項——逐節點、可組合
過程是一等公民       執行是一條帶 nodeId 的狀態軸；執行器可插拔（vision〈執行器〉）
```

## 二、我們提的四條（cella 已照排）

1. **形狀**：每一個敘述元件投影成「狀態 → 結果」，區域變數是帶型別的狀態，
   每個運算的前置條件留在**它自己那個節點**上成為一個洞。
2. **終止——分層**：計數迴圈（StudyCpp 77%）上界已知 ⟹ 遞減量機械推出、**直接證**；
   while（44%）先用燃料，用完是 unknown 而理由說得出「不一定會停」；給得出遞減量的升級成證明。
   ⚠️ C++ 規定沒有副作用的無窮迴圈是 UB（forward progress）⟹「會停嗎」本身可以是一個真實的洞
   （教學上要不要強調、何時教，是使用者的決定）。
3. **break／continue／中途 return／修改參數**：模型本身有——敘述結果四種（normal／break／continue／return v），
   傳值參數是可改的區域變數；參考參數（`int&`，13 次）等指標那一階段的記憶體模型。
4. **兩層都要**：
   - **組合子**（`cpp.seq`、`cpp.loop`…，前置條件是明確引數）——給我們產生的項，每個節點的義務各自成洞。**最先需要。**
   - **小步語意**——cella 那側「C++ 是什麼意思」的唯一定義，組合子對它證一致；可逐步執行、步驟帶外部標籤
     ⟹ 對得上「過程是一等公民」的時間軸，也能逐步比對我們的直譯器（對齊測試的 β，不只比最後輸出）。

另外兩個需求：**節點標籤**（項上掛不透明標籤、判決回報洞時帶回——今天的洞名從運算式組出來，
巢狀就組不成只能擲例外）；**效能**（帶型別的運算每個約 100 ms，20 個運算的函式就是 2 秒）。

## 三、🔴 未決的，照實標成未決

**「cella 的語意要不要成為我們的執行器」**——vision 逐字記著「`execute` 屬於誰」**未拍板**。
所以對小步語意的請求只到「可逐步執行、步驟可帶外部標籤」為止，**不預設它會被當成執行器**。

## 四、cella 的排程（2026-10-06）

```
1. 節點標籤（形狀做出來先給我們確認）
2. 帶型別運算的效能（因為 2 秒那個估算而優先）
3. 組合子：計數迴圈直接證、while 燃料、四種敘述結果、傳值參數可改
4. 小步語意 ＋ 與組合子的一致性證明（只到可逐步執行，不預設是執行器）
```

## 四之一、🪦 一個被撤回的提案：翻譯搬到 cella、交界面用 CST（2026-10-11）

cella 的另一個 session 提議：① 翻譯規則放進 cella 的領域套件（理由：翻譯錯判決就錯，分兩個 repo 會不同步）、
② 交界面是「tree-sitter 樹＋原始碼」、③ 快的前段給型別查詢、④ 多領域同一協定、⑤ 只有積木的領域也定義文字形式。

我只回事實與設計依據，**決定權留給使用者**；而 cella 讀完之後**自己撤回了 ①②⑤**：

```
① 撤回   使用者 2026-10-05 拍板：語言語義住 Library、對應住膠囊（DDD：Published Language ＋ ACL）
         ——而「不同步」的風險是真的（cpp.rem 弄壞過一次），但 merkle 當天就指出是哪兩個定義
② 撤回   根公理「唯一真實，各式投影」：真相是語意樹不是文字，程式可能整支是積木拼的
         ⟹ CST 交界面要「積木 → 產碼 → 再 parse」才看得到，結果還要經過文字範圍才對回 nodeId
⑤ 撤回   文字只是可有可無的一種投影
④ 同意   cella 的領域套件 ＝ 套件協定的「詞彙套件」；協定的結構（元件／連接／組裝）在我們這邊
```

cella 改提三件補的事，我依設計目標排：

```
① 差分（下一件）   同一棵語意樹：generate → clang＋sanitizer ／ formalize → cella，比 UB 與輸出
                   ——「翻譯忠實」是「子集沒有 UB」四個前提裡最難自證的，而翻錯的症狀是全綠
                   案例由我們出（三份語料＋fuzz），比對工具由 cella 給（以編譯產物交付）
② 標籤型別查詢     ＝ C2 資訊軸／語義診斷的第一個消費者；等 formalize 對缺的槽產生洞
                   吸附兩個都要，主角是「這一格期待的型別」；標籤要能指名 `<nodeId>#槽名`
③ 冷啟動           cella 還沒進產品的編輯迴圈，等那一天才擋路
```

⚠️ cella 預告：模型**比標準嚴**的地方（qsort 的比較函式、讀未初始化的元素）以後證不出時是 **Unknown 附理由**，不是 Reject。

## 四之二、cella 當「第二個 runner」的量測與推薦（2026-10-11，🔴 未拍板）

使用者想知道：經過這幾輪優化，cella 有沒有條件連 `execute` 也接手？cella 先問我、再量。
我只給事實與設計依據——vision〈執行器可插拔〉逐字：2026-09-25 選了 A（可插拔是永久架構，
「我到時候也有可能要對接外部 debugger、實際硬體」），cella codegen 是「預期中的第二個 runner」，
而 **B（由一份特定實作取代）未拍板**。

**我們直譯器的數字**（Node、M3、跑完模式）：約每秒 200 萬步（節點拜訪）；整數迴圈 10⁶ 次 2.0 秒、
vector 10⁶ 次 6.2 秒。課文解答 86 支步數中位數 50、p90 278、最大 2348（fib）。

**cella 的數字**（原生 wasmtime、M3、手寫小步語意、扣固定成本 0.33 秒）：

```
整數迴圈   10⁶ 0.55 秒（我們 2.0）  10⁷ 4.4 秒
fib(25)   約 25 萬次呼叫 0.22 秒
vector    10³ 0.1 秒   10⁴ 2.6 秒   10⁵ 48 秒未完成   ← 模型底下是串列，每次存取 O(n)
課文規模   毫秒級
未量       瀏覽器 V8、CPU 4×（要等宿主介面）
```

**cella 的推薦**（寫進他們的 draft、待使用者決定）：只做第二個 runner、整支程式換、不談取代；
逐顆元件切換已撤回（runner 收的是一整棵樹，混跑要每個節點跨 runtime 交接狀態）；
Python 與硬體模擬不在範圍。第一段：UB 停下（帶標籤與理由）＋ 宿主介面（step、變數快照、
暫停時改變數、cin 暫停），在課文解答上比分歧數；第二段：O(1)／O(log n) 的陣列表示。

我補的四點（cella 已全部寫入）：

```
① 第一段卡在【我們】   語意樹要先被 formalize 翻成 cella 程式，而走訪器只認得兩種形狀
                      ⟹ 分歧數的母體是「產得出項的那幾支」，與產不出的【分開報】
                        （否則「0 個分歧」可能只是「0 支被比到」——StudyCpp 那次的形狀）
② 變數快照的解碼       要 formalize 產項時一起輸出（狀態欄位 ↔ 變數名與型別）
③ I/O 是前提           解答 88 支裡 61 支用 cout、17 支用 cin；cella 模型早有 cout／cin，
                      缺的是小步語意裡「cin 要輸入時暫停」——⟹ 真正的前提是我們 formalize 的「陣列與 I/O」
④ 分歧分三類           cella 停在 UB、我們照跑 → 【我們直譯器的發現】（模擬的誠實）
                      都沒 UB 而輸出不同 → 查誰錯（棘輪只盯這一類）
                      只有一邊能跑 → 覆蓋，不是行為
```

⟹ 決定前最需要的兩個數字是**瀏覽器 V8 與 CPU 4×**，要等宿主介面才量得到。

## 四之三、🔴 走訪器產出的形狀要改：前置條件從「證明引數」變成「帶檢查的計算」（2026-10-11）

起因：網頁版的執行器改由 Cella 接手（[history/304](../history/304-網頁版的執行器從可插拔的位置到一律是Cella.md)），
而**執行時證明不參與計算**——`cpp.add a b ok` 的 `ok` 不會被求值，UB 偵測不到。

cella 給兩條路，我選 B：

```
A 守衛敘述   每個運算前插一個 sCheck；運算用不帶證明的版本
             ⟹ 守衛與運算是兩個節點，漏了守衛型別抓不到——正是 JS 直譯器的病（靜默降級那一族）
B 帶檢查     前置條件放進節點本身，執行時算出來、不成立就停；運算拿不到證明就寫不出來
             ⟹ 驗證與執行是【同一個項】（唯一真實）；漏寫是型別錯誤
```

我附的兩個要求（cella 已照做）：

```
① 粒度到【運算】   x = a + b * c 在積木上是巢狀三塊，學生要看到「* 那一塊溢位」
                   ⟹ 每個前置條件帶它所屬運算節點的標籤，不是外層敘述的
② 不得攤平         i < n && a[i] > 0 —— a[i] 的 inBounds 只在左邊為真時才是義務
                   攤平成整行的合取會把正確的程式誤判成 UB
```

cella 的定案形狀：

```
運算式   Ck A ＝ 值 ｜ undef why
         checked label pre why k   執行時算 pre，成立才把證明交給 k；不成立停在 undef，帶【這個運算】的標籤
         && ／ || ／ ?:            bind ＋ 分支——短路由語意保證，不靠 formalize
敘述     sAssignC (f : S -> Ck S)；條件 S -> Ck Bool；Flow 多 undef why
驗證     判決 ＝「exec 不會停在 undef」；每個 checked 各一個帶自己標籤的洞
why      前置條件名 · 標準條文 · 參與的值（含型別）· 失敗運算的標籤 · sanitizer 類別名（不帶語氣）
例外     與 Ck 合成「值／丟出／undef」三種結果
狀態 S   區域變數的 record——產生慣例由 cella 提供
```

⟹ 我們這邊：今天的 `cpp.add a b ?noovf_add_a_b` 要改成 `checked <nodeId> pre why k` 的形狀；
等 cella 第一版（含測試與示範程式）的項形狀與範例到了再改。
教學語氣、中文、near-miss 由我們從 `why` 投影。

## 五、我們這側接的時候要做的（還沒排程）

- 「洞 → 積木」那張 map：判決帶回的標籤 → 積木上的標示

- 差分：把三份語料接上 cella 的比對工具；分類名稱對齊 `audit-sanitizer-verdict`（cella 開工前會問）
- 🔴 **第二個 runner 的第一段由我們卡住**：formalize 要長到「陣列與 I/O」，並一起產變數快照的解碼
