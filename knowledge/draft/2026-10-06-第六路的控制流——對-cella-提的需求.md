## 一、答案站在三條已定的設計上

```
洞 → 積木          vision〈第六路〉：每一個前置條件對得回語義樹的節點（nodeId）
對應住膠囊          每顆元件把自己投影成 cella 的項——逐節點、可組合
過程是一等公民       執行是一條帶 nodeId 的狀態軸；執行器可插拔（vision〈執行器〉）
```

## 二、我們提的四條（cella 已照排）

1. **形狀**：每一個敘述元件投影成「狀態 → 結果」，區域變數是帶型別的狀態，
   每個運算的前置條件留在**它自己那個節點**上成為一個洞。
2. **終止——分層**：計數迴圈（StudyCpp 77%）上界已知 ⟹ 遞減量機械推出、**直接證**；
   while（44%）先用燃料，用完是 unknown 而理由說得出「不一定會停」；給得出遞減量的升級成證明。
   ⚠️ C++ 規定沒有副作用的無窮迴圈是 UB（forward progress）⟹「會停嗎」本身可以是一個真實的洞
   （教學上要不要強調、何時教，是使用者的決定）。
3. **break／continue／中途 return／修改參數**：模型本身有——敘述結果四種（normal／break／continue／return v），
   傳值參數是可改的區域變數；參考參數（`int&`，13 次）等指標那一階段的記憶體模型。
4. **兩層都要**：
   - **組合子**（`cpp.seq`、`cpp.loop`…，前置條件是明確引數）——給我們產生的項，每個節點的義務各自成洞。**最先需要。**
   - **小步語意**——cella 那側「C++ 是什麼意思」的唯一定義，組合子對它證一致；可逐步執行、步驟帶外部標籤
     ⟹ 對得上「過程是一等公民」的時間軸，也能逐步比對我們的直譯器（對齊測試的 β，不只比最後輸出）。

另外兩個需求：**節點標籤**（項上掛不透明標籤、判決回報洞時帶回——今天的洞名從運算式組出來，
巢狀就組不成只能擲例外）；**效能**（帶型別的運算每個約 100 ms，20 個運算的函式就是 2 秒）。

## 三、🔴 未決的，照實標成未決

**「cella 的語意要不要成為我們的執行器」**——vision 逐字記著「`execute` 屬於誰」**未拍板**。
所以對小步語意的請求只到「可逐步執行、步驟可帶外部標籤」為止，**不預設它會被當成執行器**。

```

2. 帶型別運算的效能（因為 2 秒那個估算而優先）
3. 組合子：計數迴圈直接證、while 燃料、四種敘述結果、傳值參數可改
4. 小步語意 ＋ 與組合子的一致性證明（只到可逐步執行，不預設是執行器）
```

## 四之三、🔴 走訪器產出的形狀要改：前置條件從「證明引數」變成「帶檢查的計算」（2026-10-11）

起因：網頁版的執行器改由 Cella 接手（[history/304](../history/304-網頁版的執行器從可插拔的位置到一律是Cella.md)），
而**執行時證明不參與計算**——`cpp.add a b ok` 的 `ok` 不會被求值，UB 偵測不到。

cella 給兩條路，我選 B：

```
A 守衛敘述   每個運算前插一個 sCheck；運算用不帶證明的版本
             ⟹ 守衛與運算是兩個節點，漏了守衛型別抓不到——正是 JS 直譯器的病（靜默降級那一族）
B 帶檢查     前置條件放進節點本身，執行時算出來、不成立就停；運算拿不到證明就寫不出來
             ⟹ 驗證與執行是【同一個項】（唯一真實）；漏寫是型別錯誤
```

我附的兩個要求（cella 已照做）：

```
① 粒度到【運算】   x = a + b * c 在積木上是巢狀三塊，學生要看到「* 那一塊溢位」
                   ⟹ 每個前置條件帶它所屬運算節點的標籤，不是外層敘述的
② 不得攤平         i < n && a[i] > 0 —— a[i] 的 inBounds 只在左邊為真時才是義務
                   攤平成整行的合取會把正確的程式誤判成 UB
```

cella 的定案形狀：

```
運算式   Ck A ＝ 值 ｜ undef why
         checked label pre why k   執行時算 pre，成立才把證明交給 k；不成立停在 undef，帶【這個運算】的標籤
         && ／ || ／ ?:            bind ＋ 分支——短路由語意保證，不靠 formalize
敘述     sAssignC (f : S -> Ck S)；條件 S -> Ck Bool；Flow 多 undef why
驗證     判決 ＝「exec 不會停在 undef」；每個 checked 各一個帶自己標籤的洞
why      前置條件名 · 標準條文 · 參與的值 · 失敗運算的標籤（不帶語氣；sanitizer 名後來拿掉了，見下）
例外     與 Ck 合成「值／丟出／undef」三種結果
狀態 S   區域變數的 record——產生慣例由 cella 提供
```

**2026-10-11 更新（核對 cella 的 UB 對照表之後）**：

- 🔴 **`why` 拿掉 sanitizer 名，剩四欄**：`cpp.mkWhy 前置條件名 條文 值 標籤`。
  理由是實測：同一個 `vector::operator[]` 越界，macOS 開 hardening 是靜默中止、不開是 `container-overflow`、
  Linux CI 預設**完全不報**（我們加了 `_GLIBCXX_ASSERTIONS` 才讀得到，第 331 刀）。
  ⟹ **身分是前置條件名加條文；sanitizer 名只是「某個工具在某組旗標下怎麼報」的證據**，
  放在對照表與差分工具，不放進語意。兩邊的分類詞約定用 clang 自己的名字（第 330 刀）。
- **整數的檢查版本**：`cpp.addC p lab a b`、`subC`、`mulC`、`divC`、`remC`、`negC`、`shlC`、`shrC`，結果是 `Ck (Val _)`；
  前置條件依序檢查（除法先 nonZero 再 noOverflow；左移先 shiftAmount 再 shiftBase）。
- ⚠️ **產生項時要用檢查版本**：直接呼叫帶 `common` 的 `addV p a b ok`，elaborator 會把隱式引數的解
  存成展開後的正規形式（每出現一次約 40 KB；cella 第一版的 `remC` 單一定義 2.5 MB）。`addC` 這些不付這個成本。
- **語言標準也是參數**：負數左移、左移結果超出範圍只在 C++17（含）以前是 UB。產品預設哪個標準，**待問使用者**。

⟹ 我們這邊：今天的 `cpp.add a b ?noovf_add_a_b` 要改成 `cpp.addC p <nodeId> a b` 這類檢查版本（在 `Ck` 裡）；
等 cella 第一版（含測試與示範程式）的項形狀與範例到了再改。
教學語氣、中文、near-miss 由我們從 `why` 投影。

## 四之四、產生的程式碼會撞名、撞關鍵字——兩個語法層的約定（2026-10-11）

cella 要把 stdlib 與 c/cpp 重寫成可讀的形式並統一改名（使用者定的：先整理再長）。我提的六件裡，
最痛的是**產生的程式碼的名字來自學生的 C++**：`int add(…)` 遮蔽 stdlib 的 `add`；C++ 合法而 Cella 是關鍵字的識別字。

實測（tree-sitter 掃課文解答＋課文片段＋StudyCpp，567 支、17,325 個識別字，對 cella 的 59 個硬關鍵字＋上下文＋保留字）：

```
end   52 次 / 39 支   ← 多半是 v.end()（STL 的名字本身就是關鍵字）
fun   23 次 /  4 支
in    13 次 /  5 支
其餘（含單獨的 _）0
```

cella 定案：

```
跳脫          r#名字 ＝ 名字叫那個字的普通識別字（r#in、r#data）；r#_ 是名字叫 _ 的識別字，單獨 _ 仍是萬用字元
限定名稱      後段可以是關鍵字：Vector.end、v.end 直接寫；只有單獨出現或第一段才要 r#
產生碼        放在我們自己的 namespace：裡面遮蔽匯入不警告；未限定名稱先找本 namespace（Lean 的規則）
點記法        純語法糖；產生的項照寫完整名稱
```

⟹ 走訪器輸出識別字的規則：**C++ 識別字是 cella 關鍵字、或就是 `_` 時，加 `r#`**；
關鍵字清單之後會由 cella 的 JS API 提供（有測試守著與 lexer 一致），不在我們這邊手列。

**已實作（2026-10-11，隨下一版 npm 發佈）**：匯出 `keywords()` → `{"hard":[…],"contextual":[…],"reserved":[…]}`。
走訪器的規則落成：名字在 `hard` 裡、或就是 `_` → 寫 `r#名字`（上下文關鍵字 `by`、`mode`… 寫成 `r#by` 也一定是名字，
要保證就一律加，不會錯）。點後段（`v.end`、`(f x).end`）不加；在 namespace 裡定義寫 `def r#end`。
訊息裡名字是關鍵字的會印成 `r#名字`——洞的標示若要回顯給學生，要把 `r#` 去掉。

## 四之五、Cella 直譯器第一段：我們要的宿主形狀（2026-10-13）

cella 要做第一段剩下的部分（try 進小步語意 → 輸入暫停 → 宿主介面），先問我們要什麼形狀。照理想計劃答：

```
敘述標籤      每個可停的敘述都對得回一個 nodeId（at-node 與斷點都講 nodeId，不講行號）
解碼表        formalize 產項時一起輸出：狀態欄位 ↔ C++ 變數名、型別、所在 scope
try           handler : Exc -> Maybe stmt；沒接住的 throw 是 terminate（帶型別名），不能和 UB 混在一起
io 欄位       學生的 `int io;` 會撞名 ⟹ S = { io : IOS, vars : Vars } 分兩層（推薦），或改收 getIO／setIO
```

第一批宿主呼叫＝**畫面上現在真的有的按鈕**（`DebugAction`＋`execution:set-variable`＋`awaiting-input`）：
launch＋setBreakpoints＋continue、pause、step（＝stepIn，畫面上沒有分 next）、stepOut、terminate、
scopes＋variables（名字、型別、值的字串）、setVariable（改不了要回理由）、自訂的輸入暫停／補輸入、output event。
停止原因：breakpoint／step／pause／awaiting-input／UB（標籤＋why）／terminate／exited。
stepBack 不在第一批（畫面上沒有那顆按鈕）。

⚠️ 未拍板：變數是 push 還是 pull（〈執行器是可插拔的〉§三兩種都寫）；第一批照 DAP 做成 pull，我們配合。

cella 定成 spec 563：`sAt nodeId body`、`sTryC`、`St V = { io : IOS, vars : V }`、斷點／單步／停止原因是對 Conf 的純函數、
WasmGC 函式庫模式＋JS 包 DAP。變數的呈現與修改由 **formalize 產的 Cella 函數**提供，我們對它的形狀提了三點：

```
依 frame 分組   每個 record（全域、各函式的區域）一個 show 由 formalize 產；走 frame 堆疊的由 cpp 提供
鍵是欄位 id     同函式兩個 x、遞迴同名多層 ⟹ show 每筆 {id, name, type, value, declNode}；
                setVar frame id text → Either 理由 St（對照表＝解碼表，兩邊同一份）
值與理由        C++ 印法；未初始化可分辨（不印 0）；Left 分得出「讀不懂」與「超出型別範圍」（用 cpp.InRange）
```

cella 做完的形狀（2026-10-13，formalize 之後要產的）：

```
呼叫         sCall fn site enter body leave ／ sCallT … restore
             fn ＝ 函式定義的 nodeId；site ＝ 呼叫運算式（cpp:func_call）的 nodeId，由我們明確傳
             leave saved callee r：io 與全域取 callee 的，呼叫端區域取 saved 的；restore 同形
```

### Python generator（spec 572，2026-10-13，main 0827b3f4，未發佈）

照談定的分工：**formalize 產結構化本體，Cella 攤平**。

- 本體是 `python.GStmt V`：`gPlain`（不含 yield 的敘述，原樣保留 nodeId）、`gSeq`、`gIf node c t e`、`gWhile node c body`、

  `gTry body hs`（`gHCons types bind body rest … gHNil`）、`gFinally body fin tE`（fin 是 `PStmt`）。
  攤平產生的分派敘述不帶節點，**不是可停的點**——學生單步不會停在看不見的地方。
- 呼叫 generator 函式時不跑本體：prologue 之後
  `pReturn node (python.eNewGen (python.eMakeFn name [自由變數的 cell]) (python.eLocalsOf [g_x, …]))`。
- 續行另外登記一個函式，名字是原名加 `"\x02"`，本體 `python.genBody pcTmp (eLocalsOf 同一串) rt <GStmt>`；

- 變數面板：`python.varJsonGen` 讓 generator 值多 `"state"`（GEN_CREATED／RUNNING／SUSPENDED／FINISHED）

- generator 運算式：在 cella 的測試工具裡是名為 `<genexpr>` 的 generator 函式；直接交給 sum／list／sorted／min／max／join 時仍當推導式。

🟢 **finally 裡的 return／break／continue 已支援**（main c2939810）：`gFinally` 形狀不變，區域裡的 `gReturn`／`gBreak`／`gContinue`

⚠️ **仍不支援的只有「fin 本身含 yield」**（fin 是 `PStmt`，型別上放不進 `gYield`）——CPython 允許，學生寫得出來，
formalize 遇到時要**出聲、不產生項**（P6）。`GEnv` 多了 `ret` 欄位，只有 `genBody` 內部會建，formalize 不碰。

🟢 **send／throw／close（使用者 2026-10-13 拍板：現在做**，趁 npm 未發佈、Python formalize 未開工時改簽名；我們的課文與語料今天零個 `yield`）。
cella 推薦、我們接受的形狀：`GStmt` 多 `gYieldTo node e set`（`x = yield v`，`set : PE V -> PStmt V` 收送進來的值）；
`genBody` 多收一個暫存（**不相容**），續行函式多兩格引數（恢復方式與值）；每個 yield 有一個同在一個 try 區域裡的恢復區塊——

- 恢復區塊不帶節點；只有從恢復區塊丟出例外（throw／close）時，那個 raise 標的是 yield（`gYield`／`gYieldTo`）的 node。
