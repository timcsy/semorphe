# 可嵌入與可插拔的四個軸——而「語言」只是其中一個軸的一種值

> 2026-08-24　怎麼冒出來的：使用者說「我想把面板做得更去耦合，甚至**其他專案可以
> 直接引用某幾個面板**」，接著列了四個真實情境，然後補一句
> 「ArduinoCAD 流進來之後，**不只 lang-\* 要考慮了，還有硬體**」。
>
> 🟡 **狀態：已升格（2026-08-24，使用者「我點頭」）**——路線圖項目
> `vision.md` 階段 8「**核心可獨立出貨**」。
> **這一份是它的 in-flight 設計理據，做完才反流退場。**

## 一、四個情境，而它們要的東西不一樣

| 情境（使用者逐字） | 他真正要的 | 出貨單位 |
|---|---|---|
| 教學網站的 coding 編輯器「套用我們的」，**積木要選子集** | 全套 ＋ 課程設定 | `app` |
| 「積木與程式碼即時互轉」 | 引擎 ＋ 一個域 ＋ 積木面板 | `core` + `domain-*` + `panel-blockly` |
| 「流程與程式碼即時互轉」 | 同上，換面板 | `core` + `domain-*` + `panel-flow` |
| **「本身就有 Blockly 或 Flow 了，想加入程式碼即時互轉」** | **只要引擎**——他自己實作 `ViewHost` | **`core` + `domain-*`** |

🎯 **第四列一個面板都不需要，而它是最重要的訊號**：主力產品是**引擎**，面板是參考實作。

它也是 `ViewHost` 協定的**第一次真考試**——今天三個實作全是我們自己寫的，那不算考試。

## 二、🔴 修正：② 是「域」，不是「語言」

我第一版把分層寫成 `core / lang-* / panel-*`，而使用者當場點出硬體。
**協定那側早就預留了，是分層的名字沒跟上**：

> `src/core/view-registry.ts:138`
> `viewsWith('needsLanguageProjection')  // 哪些視圖需要語言投影（硬體視圖不需要）`

```
① 核心      真相 ＋ 同步 ＋ 登錄表 ＋ 協定
② 元件套件  lang-python · lang-cpp · hardware-arduino …
③ 視圖      panel-blockly · panel-monaco · panel-flow · panel-wiring2d · panel-assembly3d
④ 應用      code-editor · hardware-lab · 教學網站
```

### 🔴 而 ② 的命名，我第一版寫錯了兩次——`concepts/元件.md` 兩處都已經答過

**錯一：把 `domain-python` / `domain-arduino` 併成同一層。**
`元件.md:502`「元件住在哪：域／語言／layer **三軸正交**」逐字說：

> 「`layer` 是語言內部的階；**硬體不是「更深的 layer」，它沒有 lang-core 可以依賴**。
> 把硬體塞進 layer 序列或塞進 `languages/` 底下，兩種都是類別錯誤。」

域的值是 **software / hardware / UI**；**語言只在 software 域內有意義**。
所以 python 與 cpp 是「software 域裡的兩個語言」，arduino 是**另一個域**——
**把三者排成同一層 `domain-*`，就是把三軸疊起來**，那正是那一節禁止的事。
→ 套件名要帶它所在的軸，不是壓平成一個字。

**錯二：說 `componentId` 的前綴是「域」。**
`元件.md:138`「⚠️ scope 是**套件擁有者**，不是語言（2026-08-09 修正）」：

> 「我們一路把 `cpp:` 讀成『C++ 這個語言』。**不對**——它是『**第一方的 C++ 套件**』。」

🟢 **而這對可嵌入是大好消息**：第三方套件的命名**早就設計過了**。
`@someone:boost_vector` 宣告一條轉換邊到 `cpp:vector_declare`，
就自動進同一個抽象元件、同一個圖鑑條目，**不需要第一方批准**。

> 那一節的收尾正是這一份要的東西：
> **「『方便大家擴充』的實際樣子不是給人一個地方塞東西，
> 是讓他塞進去的東西自己接得上既有的意義。」**

⚠️ **判準也要用原話**，不是我編的那句：
**域決定「有哪些接點與關係律」**（`元件.md:502` 的軸表），
不是「五槽宣告得出來就是一個域」——後者連 UI 域都分不出來。

### 兩條規則，而兩條今天都被違反

| 規則 | 今天的違反 |
|---|---|
| **① 不得 import ② 與 ③** | `registerCppSkipDeclarations()` 掃全部膠囊、順帶把語言中立的宣告推進核心（[history/121](../history/121-Python的執行期而十七顆執行器第一次被跑過.md)）。單一 app 看不出來；**可插拔之後，只裝 Python 的人就沒有人推那些宣告** |
| **③ 只 import 協定** | `flow-panel` import 了 `Blockly`（只為 `Msg`）、`BlockSpecRegistry`、`core/component/traits` |

## 三、`ViewConfig` 該長出的三個 port

`ViewConfig` 已經存在而幾乎沒用。讓依賴反轉走它：

| Port | 取代掉 | 效果 |
|---|---|---|
| `t(key, fallback)` | `Blockly.Msg` | 流程面板**整包 Blockly 依賴消失** |
| `appearance.colourOf(componentId)` | `BlockSpecRegistry` | 顏色仍來自同一張表，而面板不知道那是 Blockly 的表 |
| `schema.slotsOf / roleOf / annotationOf` | `core/component/traits` | 面板對著**任何**語義提供者都能跑 |

## 四、兩個登錄表——今天只有一個

`registerViewsIn(elements)` 今天同時決定**有哪些面板**與**它們在哪一格**。拆開：

- **視圖登錄表**（有了）：誰在匯流排上
- **版面登錄表**（沒有）：`viewId → slot`。面板宣告**偏好**（`{ slot, title, defaultOpen }`），**不宣告位置**

版面本身變成**資料**（區域樹），宿主各自提供渲染器：
網頁版吃一棵、手機版吃另一棵（分頁列）、VSCode **整棵忽略**（它有自己的分頁）。

> ⚠️ **別做可拖曳的 docking 系統。** 兩個宿主、五個面板，slot map 就夠。

## 五、三個硬阻礙——都不在面板那側

**A. `import.meta.glob` 是 Vite 專屬。** 膠囊登錄靠它（`src/core/component/registry.ts:54`），
而那個檔頭自己記著 esbuild → CJS 會炸（`import_meta.glob is not a function`）。
→ **今天「別的專案直接引用」只有 Vite 專案做得到。** 要出貨得改成**建置期產生的靜態清單**。

**B. 全域 singleton。** registry、宣告登記處、`registerLanguage` 全是模組全域。
教學網站**一頁多題**就是兩個實例 → 互相污染。要收進一個 runtime 實例。

**C. P8 的豁免範圍要重畫。** 「不做向後相容」今天涵蓋投影與程式碼（[history/026](../history/026-P8-的範圍不含語義詞彙本身.md) 釐清過）。
一旦有外部使用者，**`ViewHost` 協定與 `componentId` 詞彙就變成公開介面**，P8 的豁免不再適用於它們。
🔴 **這是政策改動，要人拍板。**

## 六、🟢 好消息：積木子集已經做完了

topics ／課程清單／`getVisibleComponents(topic, branches)`／工具箱由 45 段有序來源產生／
第十九條「可拿性」護欄——**都在了**。
「選子集」不是新架構，是**把既有的 topic 機制變成公開 API ＋ 寫文件**。四個情境裡最省力的賣點。

## 七、⚠️ 一條要先說清楚的界線

「他已經有 Blockly」——**他的積木不是我們的積木**（不同 blockDef、不同 id）。

| 他的期待 | 真相 |
|---|---|
| 「把**任何** Blockly 轉成程式碼」 | **做不到**——中間那層（他的積木 → 語義樹）必須有人寫，那正是膠囊的 render/extract 兩路 |
| 「我用你的積木定義，塞進我自己的工作區」 | **做得到**，P3 已經在做（Layer 1 純 JSON 生 blockDef）——出一個「積木定義產生器」就成立 |

> **賣點要寫成第二種。第一種寫出去，會變成每個客戶各要一份 extractor。**

## 八、提議的順序

1. **`examples/bring-your-own-view/`**——50 行用 textarea 實作一個假 `ViewHost`，
   證明「自帶視圖 ＋ 即時互轉」成立。**它同時是規格、demo 與護欄**（編不過就紅）。
   🔴 這一招不是新的：`目錄結構對硬體的適配` §六 記著同一招（假的實作用來否證結構假設），
   而那一次成功了（`semantic-tree-view` 逼出了 `ViewHost` 契約）。
2. ① 的三個硬阻礙：glob → 靜態清單 · 宣告推送去語言化 · runtime 實例化
3. `ViewConfig` 三個 port，拿 `flow-panel` 當第一個零核心 import 的面板
4. 版面登錄表 ＋ 68 個直呼收成能力介面（`editable` / `highlightable` / …）
5. topic 子集 API 公開化 ＋ 文件
6. 真的拆 package——**這時候邊界不是猜的，是 1~5 逼出來的**
