# 開放值域的下拉——`int**` 選不到，而那不是漏一個選項

> 2026-08-24　使用者：「我發現 C++ 那邊的 function return type 是不是無法自訂？
> 例如我要 `int**` 就找不到了。**幫我看看還有哪些地方可能這樣**，然後要如何設計？」
>
> 🟡 **狀態：判準已清楚，設計未定。** 出口是路線圖。

## 一、實測：卡在哪一段

```
程式碼   → 語義樹          ✔ int** / unsigned long 收得下
語義樹   → 積木狀態(JSON)   ✔ 收得下（就是字串）
積木狀態 → Blockly          靜態下拉【拒收】→ 退回預設（field-write 記一筆）
                            動態下拉【保留】（設計如此，見下）
使用者手動選                🔴 兩種都選不到
```

🎯 **所以精確的說法是：讀得回來，寫不出去。**
程式碼帶進來的 `int**` 活著，而使用者**造不出一個新的**。

`field_dynamic_dropdown` 保值的理由逐字寫在它的檔頭，而它正是這一族的解法之一：

> 「**一個會把它不認得的值換掉的下拉，等於在使用者沒看的時候改掉他的程式。**」

## 二、同一族有多大（2026-08-24 實測）

| | 數量 |
|---|---|
| 膠囊裡的靜態 `field_dropdown` | **62 個**，分佈在 51 顆元件 |
| 其中值域**在現實中開放** | **29 個，涵蓋 26 顆元件** |
| 值域封閉（運算子、`public/private`、`begin/end`…） | 33 個 ← 這些下拉是**對的** |
| 動態來源裡的封閉清單 | 3 個：`cpp_param_types`／`cpp_return_types`／`python_types` |

最極端的幾個：

```
cpp/include        HEADER     20 個選項   任何第三方 header 都寫不出來
cpp/math_unary     FUNC       17 個選項   <cmath> 的函式比這多
cpp/pin_attach     DEVICE     10 個選項   硬體元件是開放集合
cpp/exception_make KIND        6 個選項   自訂例外類別呢
cpp/var_declare    TYPE        7 個選項   unsigned / vector<T> / 自訂類別
cpp/map_declare    KEY+VALUE   3 ＋ 4     巢狀容器整個表達不出來
```

## 三、🔴 判準：這個欄位的值域，在現實中封閉嗎？

```
封閉（+ - * / · > < == · public/private · begin/end）
   → 下拉是【限制】，正確。清單外的值本來就不該存在

開放（型別 · 標頭檔 · 函式名 · 例外類別 · 裝置 · 任何名字）
   → 下拉只能是【建議】，不能是限制
```

### ⚠️ 定位要精確：這**不是** R 分級的問題（第一版我講錯了）

第一版我說「它偷偷降成 R2」。**不對**——R 分級的定義是 `lift(project(T)) ≡ T`，
量的是**來回一趟會不會走樣**：

| | 來回走樣？ | 造得出來？ |
|---|---|---|
| `unsigned long` 被**靜態**下拉改掉 | **會** ← 這才是 R 違反 | ✗ |
| `int**` 被**動態**下拉保住但選不到 | **不會**（完美 R0） | ✗ |

第二列是**完美可逆的**，而使用者永遠造不出第一個 `int**`。

> **一個投影可以完全可逆，而同時是一個不完備的編輯器。**

所以這是**第二條軸：可寫性**，已寫進 [concepts/投影.md](../concepts/投影.md)。
🔴 連帶的推論：**只做「保住不認得的值」修的是第一列，可寫性那條缺口原封不動**
——症狀會變成「從程式碼來的沒事、自己拉積木做不出來」，也就是使用者回報的那個形狀。

## 四、四層設計，成本遞增

### ① 正確性（必做，是 bug）：清單外的值不得被改掉

動態下拉已經是這個行為，靜態那 29 個不是。
🟢 **而已經有東西在數**：`src/ui/field-write.ts` 把寫入失敗記進棘輪
（`audit-field-writes`）——可以直接查有幾筆屬於這一族。

### ② 可寫性：一個機制解 29 個欄位

`field_dynamic_dropdown` 加 `allowCustom`：清單末端一個「自訂…」。
⚠️ 順帶要答：自訂值要不要驗合法性？**主張不驗**（P6：我們不是編譯器），
但要**看得出來它不在選單裡**（樣式或圖示）。

### ③ 選項跟著程式長——導出的，不是宣告的

像 `vars`／`funcs`／`arrays` 那樣：型別下拉把「**這份程式已經用過的型別**」列進來。
`int**` 一旦出現在程式裡，其他積木的下拉就有它。
（`concepts/元件.md`：外延該是**導出的**，不是宣告的。）

②③ 互補：③ 讓常用的方便，② 讓沒用過的也造得出來。

### ④ 型別變成結構（型別積木 `int` ＋ `*` ＋ `*`）——**別現在做**

這才是 C++ 型別的本質（指標／const／參考／模板是一套文法），
而 `param_decl` 已經是 `{type, name}` 結構化的先例。
但它屬於「指標與參考 UX」那個家族。
**判準**：等「使用者要組合型別」變成常見操作再說；②③ 先拿掉 90% 的痛。

## 五、🔴 順帶抓到兩個真的資料遺失（與下拉無關，是 bug）

```
int** p;          → cpp:pointer_declare{ name: "ptr", type: "int" }
                    名字掉了（退成預設 "ptr"）、一顆星也掉了
int** f(int** a)  → param_decl{ type: "int*", name: "" }
                    參數掉一顆星、名字是空的
```

回傳型別 `int**` 是**對的**；壞的是宣告與參數那兩條。
這是 `CLAUDE.md` 點名的「**靜默降級反模式**」——多層 fallback 用同一個預設值，
於是資料遺失與正常路徑長得一樣。
