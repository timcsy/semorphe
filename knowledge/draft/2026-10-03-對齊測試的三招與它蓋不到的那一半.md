# 對齊測試的三招，與它蓋不到的那一半

> 日期：2026-10-03
> 怎麼冒出來的：使用者提出用 **λ 演算的三個基本運算**（α／β／η）當
> 「一顆元件的**意圖**與它的**形式**對不對齊」的測試框架，並問
> 「類型論身為 λ 演算的延伸，加進來會不會有新的看見」。
>
> 🟡 **狀態：框架未決，而它的涵蓋率量過了。** 本檔記的是**那個框架、
> 量到的讀數、以及它蓋不到的三族**。
> ⚠️ 照本庫的體例不寫完成條件。

---

## 一、三招，以及它們在五槽上的位置

```
α  換名不算數      一顆元件的身分,不隨【槽名／參數名／nodeId】而變   → 身分
β  填了會算出什麼   槽填滿 → execute／generate,跨 runtime 對答案    → 行為
η  從外面看不出差   同一個身分的多個形態,觀察不出差別                → 形態
```

🔴 **而 η 就是這個產品標語的形式版本：**

> 「唯一真實，各式投影。」——**各式投影之間，從外面看不出差別。**

而 [等價與觀察集](../concepts/等價與觀察集.md) 對等價的定義（「在精度要求 ε、
回饋週期 T 底下，能不能視為相同」）**就是帶參數的 η**。

⟹ 所以 λ 演算的三個基本運算**剛好蓋住五槽的真實三槽**：身分 · 行為 · 形態。
另外兩槽（接點、參數）是 α 與 β 的**定義域**——接點是「有哪些槽」，
參數是「填什麼進去」。

🟡 而這個對應是漂亮的，**而漂亮不是它賺得起位置的理由**。下面是量測。

## 二、🔴 量測：三招蓋得到我們的多少

母體＝141 條護欄裡的 1131 個 `it`。判準**不是斷言長什麼樣**（硬性零是本庫的
通用寫法，會把所有東西吸進「不變」那一桶），而是**正確答案從哪裡來**。

```
落在三類裡的      657
🔴 三類裝不下的   474   （42%）
一個桶都沒進的      5   （0.4%，其中 2 個是【報表】——它們什麼都沒斷言）
```

而那 474 不是雜訊，是**三個有名字的族**（命中數相加會超過 474，一個 `it` 可命中多桶）：

```
463  自證·注入／反向    「拿掉修正,這條護欄要紅」「乾淨的東西不得被報」
241  存在·入口條件      「母體不是空的」「語料真的讀進來了」
142  🔴 快照·前一次的自己  棘輪的參考值、engineHash、toolbox 的「一字不差」
```

**三個都不是在問「算得對不對」：**

```
對偶／不變／協變   答案從【系統的另一個方向／另一個實作／一條宣告的性質】來
自證              答案是「這個偵測器本身還活著嗎」
存在              答案是「有沒有東西可以量」
🔴 快照            答案來自【我們自己上一次的輸出】
```

🔴 **「快照」那一族是量出來才冒出來的，而它在我們這裡是主力機制**
（棘輪、基線、`engineHash`、346 張對照圖）。它跟三類都不同：**它比的不是真理，
是「跟上一次一樣不一樣」。**

### 而有一個不用跑程式的獨立證據

`JUDGE_KINDS` 七值對到三類：

```
equality                    → 對偶
reference · grammar · renderer → 協變
runtime · formal            → 不變
🔴 human                     → 無家
```

而 `human` 的註解逐字是「**寫明，不留白**——『這顆積木好懂』的判定者就是這個」。
那正好是「對齊」最原始的那個問題（**人看一眼說「這不是我要的意思」**），
而三類一條都接不住。

## 三、型別論加進來，多出什麼

α／β／η 比的都是**項 ↔ 項**。型別論加進第二種東西，於是有了**項 ↔ 型別**
——而「意圖與形式對齊」**本來就是後面那一句**（意圖是型別，形式是項）。

```
typing       宣告的型別 vs 推出來的型別              🟡 部分
preservation 走過五路之後,它宣告的契約還成立嗎        ❌ 沒有
progress     滿足宣告 ⟹ 不會卡在中間                ❌ 沒有,而 canExecute 的兩個
                                                   cause 就是兩種卡住
canonicity   宣告的位置要有標準形態,不得退成逃生艙    🟢 有,而我們沒叫它這個名字
             （`audit-expression-form`：`cpp:input_line` 宣告了 expression
               而沒做形態 ⟹ 退成灰積木 —— 那就是 canonicity 壞掉）
parametricity 型別本身蘊含的不變量                   🔴 見下,這條路是死的
```

### 🔴 parametricity 那條路，查證之後是死的

原本的想法是：**free theorem 是「自行發現不變量」的正解**——不是從樣本推
（那會繼承語料的形狀，見 `audit-corpus-shapes`），是從型別導出，它是定理。

而我們手上剛好有一條手寫的：`multi-form-container` 的 **CK-3**
（「執行器 MUST NOT 讀 `container_kind`——改成錯的值，行為不變」）。

⚠️ **而 2026-10-03 向 cella 查證的結果是：Cella 內部證不出來。**

```
沒有 internal parametricity（要像 Agda 的 --bridges,不在他們路線圖上）
F171（定義上的證明無關）2026-09-30 已因【不健全】刻意移除
  反例：Box Nat ≡ Box Empty 可以推出 Empty
```

⟹ **那表示「讓測試從宣告長出來」的那個宣告，不會是 `contract.cella`，
是我們自己的 `component.json`。** 而那一族是**可否證的經驗檢查**
（改一個值、跑一遍、比輸出），不是定理——把它叫 free theorem 是抬舉了它。

## 四、未決的是什麼

```
🔴 我們自己的探針讀 `checker` 零次 —— 而它【拿不到】
   `cella-formalize-guard` 走 `cella holes`（文字版）,而 checker 只在
   `check --json` 裡（實測：{name, version, hash, covers}）
   ⟹ 這幾個月它是對著「機器上剛好是哪一支」在綠的,沒有任何紀錄說那是哪一支
   🟢 修法不用等對方：beforeAll 多叫一次 check --json,把 hash 記進報表
🟡 這個框架要不要補成六類（＋自證·存在·快照）再談
🟡 α 要拆成兩條嗎
   α₀ 換名不變（最小的那一條,而我們【有一半不滿足】—— nodeId 不穩）
   α₁ 宣告的不變量（`invariants` 欄位等的就是這個,而它今天幾乎全空）
🟡 β 逐元件跨 runtime —— 貴（要參照編譯器）,而 execute 今天是 125/210
🔴 而「正確答案從哪裡來」這條軸,本身是不是一個【概念】
   它問的是「一個判準的權威來源」,而我們已經有一個七值閉集在回答它
   —— 但那個閉集少了三族（自證·存在·快照）
```

## 五、已經做掉的一格

🟢 **η 的第一條護欄蓋好了**（`audit-form-agreement`，2026-10-03）。
而它補的缺口比預想的窄：既有的 `roundtrip-all` 只驗「對的積木型別」與
「對的 componentId」，**不比 `properties`／`slots`**——兩個形態各自知道
自己叫什麼，而沒有人問它們**內容說的是不是同一件事**。

母體 23 顆（宣告 `role` 軸的身分），判過的例外 1 顆（`cpp:var_declare`
是命令式積木定義）。
