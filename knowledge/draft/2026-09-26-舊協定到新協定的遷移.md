# 舊協定到新協定的遷移

> 日期：2026-09-26
> 怎麼冒出來的：使用者讀了整理過的 vision 之後說「**目前整體的設計也是舊的**」，
> 並要求「**規劃如何把舊的程式轉化成新的的遷移計劃**」。
>
> 🟡 **狀態：未承諾的排程。** 本檔記的是**順序與動工條件**，不是承諾。
> ⚠️ 照本庫的體例**不寫完成條件**。

---

## 先量：協定說的，與程式碼有的

（2026-09-26，349 顆元件逐一數。）

```
協定的欄位            今天           判讀
ports                 0 / 349      🔴 埠還不存在（`slots` 是組合接點，不是埠）
relation              0 / 349      🔴 邊還不存在
invariants            0 / 349      🔴
preconditions         0 / 349      🔴
postconditions        2 / 349      🟡 而那兩顆只寫了 `formalize` 那一路
contract.cella        2 / 349      🟡 形式那一族才剛落地
requires            103 / 349      🟡 一個欄位裝著六路的依賴
abstractComponent   331 / 349      🟡 而【有值的只有 40 顆】,其餘是 null
                                   ⚠️ 是陣列的 0 顆 —— 三個獨立來源說它該是複數
_why 家族的欄位        657 段        🟡 約 384 段可翻成契約（§十五量過）
slots · properties · paths  349/349  🟢 三個滿的
```

## 🔴 判準：不要遷移 349 顆，要讓**預設**涵蓋它們

這是整份計劃最重要的一句。第 245／248 刀已經走過這條路一次：

```
❌ 錯的做法   349 顆各寫一次「generate 的判定者是 grammar」
🟢 對的做法   一張 per-路的預設表（`PATH_JUDGE`），而 per-元件只寫【它不同】的時候
```

`compare` 與 `array_at` 就是那個形狀：它們有 `postconditions.formalize`，
**因為它們不同**（判定版 vs 布林版 · `ubsan` 而不是 `g++`）。其餘 347 顆吃預設。

> **一次「把新欄位填滿」的遷移，填的是 349 份雙重真相。
> 而一次「讓預設成立」的遷移，填的是一張表。**

⟹ **每一格遷移的第一個問題都是：它導得出來嗎？** 導得出來就不遷。

## 三批，而分批的判準是**消費者在不在**

判準逐字來自 `vision.md`：「**每一步剛好買一個貴的決定，而消費者都已到場。**」

### 第一批 —— 消費者已到場，可以動

**① `postconditions` 的預設表**（延續第 245／248 刀）
　現況：`PATH_JUDGE` 已經有六路的 `kind`／`evidence`／`judges`／`coverage`。
　缺的是那一路的 **`claim`**（「它保證什麼」），而它今天散在各條護欄的檔頭裡。
　🟢 消費者：判定者覆蓋率那條棘輪（已在跑）。
　⚠️ **不逐顆填**——填的是那張表，而 per-元件只寫例外。

**② `_why` → 契約，而只翻【需要理由的那一邊】**
　現況：657 段 `_why`，而 §十八 量到方向是**反的**——99 段寫在不需要理由的
　`abstractComponent = null` 那一欄，而需要理由的 40 段裡**只有 1 段寫了**。
　🟢 消費者：`declareNonComponent` 那條「沒理由就丟例外」的紀律已經在跑。
　⟹ 第一刀是**那 39 段**，不是 657 段。

**③ `abstractComponent` 複數化**（40 顆有值 → 陣列）
　🟢 三個獨立來源：Debian `Provides`（多對多）· CEM `mixins[]`（陣列）·
　draft §十二之④（等價要帶問題集合，布林指標裝不下）。
　⚠️ 而它動的是**40 顆**不是 331 顆——`null` 那 291 顆不必碰。
　⏳ 動工條件：**第一個需要「一顆對多個抽象」的實例**。今天還沒有 ⟹ 排在①②之後。

### 第二批 —— 等一個寫得出來的條件

**④ `requires` 分六路**
　⏳ 條件：**第三方套件進來**（今天唯一的實例——formalize 的依賴順序——已經用
　「算拓樸序」解決了，那是一個沒有痛的痛）。
　⚠️ 而它動 103 顆 ⟹ 要 `test:guard`。

**⑤ 形式那一族擴散**（`contract.cella` 2 → N）
　⏳ 條件：**每一批都要先有語料驅動的需要**。`compare` 的 `_byOperator_why` 逐字寫著
　「今天只有 `<` 一個，而那是刻意的…多填幾個運算子不會讓那個讀數更可信，
　只會讓**沒有被量過的宣告**變多」。**同一條規矩適用於整族。**

### 第三批 —— 正確地在等，條件已寫死

**⑥ 埠 · 邊（`ports` / `relation`）**
　⏳ 條件逐字：**出現第一條導不出來的邊**——接線圖的 `D13 → LED+`。
　⚠️ 而「資訊軸出現了四次」**不算**——ML 的 skip connection 已證明它**導得出來**
　（`scopeOf`）。「有人提到過」≠「有人在問」。

**⑦ `invariants` · 組裝**
　⏳ 條件：**⑥ 先落地**（沒有邊就沒有網，沒有網就沒有全網約束）。
　而 `src/` 裡 `Edge`／`Net`／`Assembly` 型別今天是 0。

**⑧ `preconditions`**
　⏳ 條件：**它的判定者要宣告，而宣告出來的欄位會說謊**（draft §十一之四）。
　處方是「強迫提問」不是驗證 ⟹ 它要與一個**會問人的機制**一起來，不能單獨加欄位。

## ⚠️ 明確不做的

```
❌ 把 349 顆都補上新欄位          那是 349 份雙重真相
❌ 為了「協定完整」而加沒有消費者的欄位  憲章 I 明文禁止
❌ 一次改名（slots → ports）      slots 是【組合】接點,ports 是【守恆／資訊】的
                                 兩者不是同一個東西的新舊名,不是改名是【加一軸】
❌ 把「三層宣告」與「契約」混用      同一個詞兩個意思,2026-09-26 已改名分開
```

## 🔴 一條貫穿整份計劃的風險

這個庫今年反覆踩的那一族：**一個機制加了而沒有人接上**。
`concepts/執行機構.md` 已有**十個**實例，而第十個（漸進揭露）的形狀最貼近本計劃：

> **機制接上了、每天都在跑，而使用它的人有動機繞過它。**

⟹ 每一格遷移的驗收**不是「欄位填了幾顆」，是「有幾條會因為它假了而變紅」**。
那正是 `judge` 那條棘輪在數的東西。
