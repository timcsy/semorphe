# 每個槽自己選視圖，而復原不屬於任何一個槽

> 🪦 **已退場（2026-09-01）** — 那一刀做完了（spec 169）。
> 結論與轉變見 [history/200](../../history/200-復原早就不是積木的動作了，而錯的是它的位置.md)，
> 教訓見 `experience.md`。**留在這裡的是「當時為什麼這樣想」。**

> 2026-09-01。使用者：「我覺得現在工具列的邏輯有點怪怪的，**為何復原按鈕只跟積木**？
> 然後我希望**每個面板可以去選擇要哪一種視圖**，而不是現在只能用 tab 切換積木跟流程」。

## 一、🔴 復原早就不是積木的動作了——錯的是它的位置

`app.ts` 逐字：

```ts
private doUndo(): void {
  if (this.lastEditor === 'code' && this.codeView?.undo) { this.codeView.undo(); return }
  if (this.lastEditor === 'flow' && this.syncController?.undoTree()) return
  this.blocklyPanel?.undo()          // ← 積木只是【最後那條 fallback】
}
```

它問的是 `lastEditor`（程式碼／流程／積木），三條路都走。
**行為是全域的，而位置在積木那一欄的快速列裡。**

> **一個動作如果對三個視圖都成立，它就不該住在其中一個視圖裡。**

🟢 而**行動版已經把它當成全域的了**（`app-shell.ts:268`）：

> 「桌面版**不建也不顯示**——那時 ↩↪ 住在快速列的 `#undo-slot` 裡」

行動版把 ↩↪ 搬到全域標頭，桌機留在面板裡。
⚠️ **兩個宿主對同一個動作有兩種歸屬，而行動版那個是對的。**

🪦 而 2026-09-01 我還加了一段補丁「快速列跟著看得見的那一欄走」——**那是在治症狀**。
搬家之後那段該刪掉。

⚠️ **「清空」不一起搬**：它今天是 `blocklyPanel.clear()`，那**真的是**積木的動作。
（而它是不是也該變成「清空語義樹」，是另一個問題，不在這一刀。）

## 二、每個槽自己選視圖

`draft/retired/版面的四張圖` 的未決第一條逐字：

> 「**每個槽都有一模一樣的分頁列**（程式碼／流程／積木）——分頁不是問題，
>  **不對稱的分頁**才是。⚠️ 順序：**先有對稱的槽，再談槽裡放什麼**」

對稱的槽在 2026-08-31 做完了（spec 168），可以做了。

### 🔴 它會把一條不變式降級

```
今天   areas 同時決定【幾個槽】與【哪一格放哪一層】
       I3（每列每欄都是 LAYER_ORDER 的子序列）擋掉鏡像版面

之後   版面決定【幾個槽、槽的形狀】     ← 老師說得出「左邊那一欄」
       使用者決定【每個槽看哪一層】     ← 沒有任何投影被寫死成「主的」
       ⟹ I3 從【不變式】降級成【預設值的性質】
```

⚠️ 代價：使用者可以把積木放左邊、程式碼放右邊。
「左右是語義」會變成「**預設**是語義」。

🟢 而我認為那是對的取捨——這一整條線的起點就是「程式碼面板變得比較特別了」，
而「不准使用者換」本身就是一種特別待遇。**但它是教學判斷，要人拍板。**
