## 〇、三份參考材料的定位（它們不是同一種東西）

```
lectures/C語言教學.pdf     一門完整入門課（22 節手寫）——順序的【骨幹】
lectures/AP325_v1.3.pdf   進階演算法，假設入門已修——【另一個起點】

lectures/Python教學.pdf    （15 頁，本次未逐頁讀）
```

🔴 **使用者手寫筆記的順序有一個不常見而刻意的地方**：
**資料型態在最前、輸入輸出在變數之前**。多數教材是「hello world → 變數 → 型態」，
而這裡是「**什麼是資料 → 怎麼進出 → 怎麼存**」。

## 一、三層結構（拍板 2026-08-27）

> 使用者：「每一個目標都可以**預設從頭來**，然後還有一些銜接或是進階的目標另外處理」

```
目標 (target)   「我從哪裡開始」    13 個 · 各自帶一門預設課
課程 (course)   「我要走哪條路」    一串教案
教案 (lesson)   「這一堂教什麼」    元件集合 ＋ pins（含目標）
```

> **目標回答「我從哪裡開始」，而不是「我學到哪裡」。**

🟢 **而這個結構今天已經有一半**（量測 2026-08-27）：

```
13 個目標 → 5 門課（多對一）
  arduino         ← 9 個板子共用同一門課   🟢 板子不同，課一樣
  cpp / c / python / cpp-competitive  各 1
```

而 `cpp-competitive` **也是從頭來的**（根關卡 23 顆 vs `cpp-beginner` 的 19 顆）
——**它不是入門的延伸，是競程學生的第一門課**。

## 二、五個起點 ＋ 兩條銜接

```
起點（目標自帶的預設課）
  ① cpp             → C++ 入門 15 章
  ② arduino(×9)     → Arduino 專題 14 單元   entryShell=none，零概念債
  ③ cpp-competitive → AP325 13 章
  ④ c               → C 入門（⚠️ 見 §七①）
  ⑤ python          → Python 入門（⚠️ 見 §七①）

另外處理（跨目標）
  ⑥ C++ → C        pin cpp → pin c        5 章  🟢 能按一下切換
  ⑦ C++ → Python   pin cpp → pin python   6 章  🔴 切不過去，靠對照
```

⚠️ **① 與 ② 是兩條平行的主線，不是先後**（使用者拍板：「Arduino 自己就是入門」）。
⚠️ **先 C++ 後 C**（使用者拍板），所以 ⑥ 是主要的銜接方向；
   `C → C++` 那條**先不做**——學生不會從 C 進來。

## 三、軌道 ①：C++ 入門（15 章）

依手寫筆記的骨架，而**三處因為 C++ 而改變**（見表後）。

| # | 章節 | 主要元件 | 新增 |
|---|---|---|---|
| 1 | 程式是什麼（狀態／流程／輸入／輸出） | `program` `func_def` `print` `literal_string` `endl` `include` `using_namespace` | 7 |
| 2 | 資料與型態（二進位・整數・小數・文字） | `literal_number` `literal_char` `var_declare` `sizeof` | 4 |
| 3 | 輸入輸出 | `input` | 1 |
| 4 | 變數（宣告／賦值／初始化／命名） | `var_assign` `var_ref` `var_declare_const` | 3 |
| 5 | 運算式（四則・比較・邏輯） | `arithmetic` `compare` `logic` `logic_not` `negate` `math_pow` `math_abs` | 7 |
| 6 | **字串** | `string_declare` `string_size` `string_at` `string_append` `string_make` | 5 |
| 7 | 運算子組合技 | `var_assign_compound` `increment` | 2 |
| 8 | 選擇 | `if` `if_else` `block` `ternary` | 4 |
| 9 | 重複（while） | `loop_while` `loop_do_while` | 2 |
| 10 | for 迴圈 | `loop_count` `loop_for` `break` `continue` | 4 |
| 11 | 演算法入門（猜數字・二分搜・複雜度） | *（無新元件）* | 0 |
| 12 | 陣列 | `array_declare` `array_at` `array_assign` | 3 |
| 13 | `vector` | `vector_declare` `vector_size` `vector_back` `vector_pop` `container_push` `loop_range` | 6 |
| 14 | 多層迴圈（九九乘法・星星塔） | `array_2d_declare` `array_2d_at` `array_2d_assign` | 3 |
| 15 | 函式 ＋ 遞迴 | `func_call` `return` `forward_decl` `math_gcd`(對照) | 4 |

**累計約 55 顆。**

### 🔴 三處因為換成 C++ 而改變的（對照手寫筆記）

```
輸入輸出   C 版是一整章（%d %f %c %s、scanf 要加 &）
           C++ 是 cin >> x —— 沒有格式字串、沒有 &
           → 從一整章【縮成一句話】

字串       C 版在陣列【之後】（char 陣列、'\0' 結尾）
           C++ 是 string，不必先懂陣列
           → 從第 13 章【提前到第 6 章】，而且變簡單

指標       C 版必須早講（malloc・scanf 的 &・字串）
           C++ 入門【完全不必講】——string / vector 把它藏起來
           → 移出入門，進【銜接課】
```

> **C++ 入門拿掉的東西，就是 C 銜接課要補回來的東西
> ——而那不是巧合，那就是這兩個語言的差別。**

## 四、軌道 ②：Arduino 專題（14 單元）

🎯 **`entryShell: 'none'`（量測確認）讓它成為零概念債的起點**：

```
cpp / c    entryShell = main   → 要先解釋 int main() { } 才寫得出第一行
arduino    entryShell = none   → setup/loop 是【鷹架】，學生看不到
```

> **所以交織的方向是反的：不是「入門課穿插硬體」，
> 是【硬體當情境，而程式概念被做不出來的東西逼出來】。**

| # | 單元 | 主要元件 | 逼出什麼概念 |
|---|---|---|---|
| A1 | 腳位與數位輸出（LED 閃爍） | `pin_mode` `digital_write` `delay` `pin_constant` `builtin_constant` | **零**（loop 是鷹架給的） |
| A2 | PWM 與呼吸燈 | `analog_write` `pwm_open` `pwm_attach` `pwm_write` | **迴圈**（0→255 掃一遍） |
| A3 | 序列埠（文字輸入輸出） | `serial_open` `serial_print` `serial_read` `serial_count` | 輸出／輸入 |
| A4 | 數位輸入（按鈕・上下拉） | `digital_read` | **選擇**（按下就亮） |
| A5 | 類比輸入（光敏電阻） | `analog_read` `analog_resolution` `range_remap` `math_constrain` | **變數 ＋ 運算式** |
| A6 | 聲音（蜂鳴器・超現代樂器） | `tone` `tone_stop` | 對應關係 |
| A7 | 距離（超音波） | `ultrasonic_trigger` `pulse_read` `micros` | **函式**（測距要重複用） |
| A8 | 伺服馬達（角度・掃描） | `servo_declare` `servo_attach` `servo_write` `servo_read` | 迴圈（深化） |
| A9 | 直流馬達與驅動（L298N・正反轉） | *（組合 A1＋A2，無新元件）* | 組合 |
| A10 | 🆕 **不阻塞的時間**（millis 取代 delay） | `millis` `var_declare_static` | **狀態** |
| A11 | 通訊（WiFi） | `wifi_open` `wifi_read` | ⚠️ 需要 ESP32 |
| A12 | 顯示（液晶） | `lcd_declare` `lcd_open` `lcd_at` `lcd_print` `lcd_clear` | 陣列（行列） |
| A13 | 環境感測（溫濕度） | `dht_declare` `dht_open` `dht_read` | 資料型態 |
| A14 | 記住設定（EEPROM） | `eeprom_read` `eeprom_write` | 持久化 |

🟢 **A1–A8 對得上使用者那份規劃的第 2–5 堂。** A9–A14 是依現有元件延伸的。

⚠️ **A10 是本檔加的，而它該在**：第 4 堂之後學生要做自走車，而 `delay` 會讓一切卡住
——**那是所有 Arduino 課的第一個真正的坑**。

### 🔴 量出來的缺口

```
deque      第 20 章要，而【沒有這顆元件】
           而 container_push/pop 的形態軸只有 queue／stack 兩個值
           🟢 → 加 deque 是「多一個形態」，不是「多一顆元件」（便宜）

巢狀 vector  圖論的鄰接串列要 vector<vector<int>>
           ⚠️ vector_declare 撐不撐得住巢狀，【未驗】
```

## 六、軌道 ⑥⑦：兩條銜接課

### ⑥ C++ → C（5 章）🟢 **這是這個工具的招牌**

量測（2026-08-27）：C 與 C++ **在這個系統裡不是兩個語言**——
兩個 target 都指向 `cpp:` 的元件，差別是**投影 ＋ 過濾**。

```
只是投影（同一顆元件換個樣子）—— 🎯 學生可以【當場按一下】看到
  printf("%d", x)  ↔  cout << x      同一顆 print，換 io_style
  snake_case       ↔  camelCase      同一個名字，換命名慣例

真的換概念（不同元件）—— 🔴 切不過去，而那正是要教的
  char name[20]    ↔  string name    cstring_* vs string_*
  malloc/free      ↔  new/delete     手動 vs 物件
  struct + 函式    ↔  class          struct_declare vs class_def
```

> **銜接課的內容就是：哪一半是換衣服，哪一半是換骨頭。
> 而這個工具能讓學生親手按一下看到差別——那是課本做不到的。**

| # | 章節 | 主要元件 |
|---|---|---|
| B1 | 同一份程式，兩種說法（切 target 看 printf ↔ cout） | *（無新元件——這一課的內容是【那個動作】）* |
| B2 | 字串沒有了 | `cstring_size` `cstring_copy` `cstring_compare` `cstring_find` `literal_char` |
| B3 | 指標 | `pointer_declare` `address_of` `pointer_deref` `pointer_assign` |
| B4 | 自己管記憶體 | `malloc` `free` `sizeof` `memory_copy` `memory_fill` |
| B5 | 結構與 typedef | `struct_declare` `struct_at_member` `struct_at_ptr` `typedef` |

⚠️ **方向不對稱，而 ⑥ 這個方向更難講**：

```
C → C++   「你以前要寫 20 行，現在一行」   減法，學生開心
C++ → C   「你以前一行，現在要寫 20 行」   加法，而【為什麼要退步】要有理由
```

🟢 而這個工具能給一個**比「因為考試考 C」更好的理由**：
讓學生看到 `string` 底下其實就是 `char[]`——**C 不是退步，是拆開來看**。

### ⑦ C++ → Python（6 章）🔴 **它不是銜接，是重新學一次（只是學得快）**

量測（`history/019`）：**跨語言抽象層四分之三是破的**
（98 條指標：30 條改指、68 條移除）。今天的等價邊**只有 I/O 那一族**。

```
🟢 C ↔ C++      同一批 cpp: 元件，切 target 就換投影 —— 真的可以按一下
🔴 C++ ↔ Python  兩批不同的元件（cpp: 233 顆 vs python: 99 顆）—— 切不過去
```

> **C++ → C 教的是「哪些是投影」（工具能演給你看）。
> C++ → Python 教的是「哪些是你以為的語言、其實是概念」（工具演不出來，靠對照）。**

| # | 章節 | 主要元件（`python:`） |
|---|---|---|
| P1 | 沒有型別宣告、沒有 main | `program` `print` `var_assign` `literal_number` `literal_string` `input` |
| P2 | 縮排就是區塊 | `if` `logic` `compare` `compare_chain` ⚠️ `compare_chain` 是 C++ 沒有的 |
| P3 | 迴圈與可迭代 | `loop_for` `loop_iter` `loop_while` `range_make` `container_enumerate` |
| P4 | 容器（list／dict／set／tuple） | `array_make` `map_make` `set_make` `tuple_make` `container_at` `container_append` `container_size` |
| P5 | 推導式（comprehension） | `array_make_for` `map_make_for` `container_filter` `container_apply` |
| P6 | 函式與例外 | `func_def` `func_call_named` `splat` `lambda` `try_catch` `with` |

🎯 **P5 是 Python 特有的思考方式**，而 C++ 那邊沒有對應物——
**它是「你以為的語言、其實是概念」的反例：那真的是語言的差別。**

⚠️ **本檔對這一軌最沒把握**：第二語言教學的文獻說遷移是雙面的
（正遷移幫你、負遷移害你），而**哪些會負遷移要真的教過才知道**。

## 七、🔴 這份地圖換出來的機制需求（都有具體消費者了）

- [ ] **① 一個目標可以有【多門】課**
      使用者同時說了「每個目標預設從頭來」與「Python 是第二語言」
      ——那代表 `python` 目標要有兩門課（從頭來 · 第二語言）。
      而今天 `Target.topic` 是**一對一**。
      🟢 修法很小：`Target.topic` 變成「**預設**課程」，課程清單另外一份。
      > **目標是起點，不是圍牆。**

- [ ] **② 教案要能 `pin` 目標，而銜接課會 pin 兩個**
      ```
      bridge-01  pins: { target: cpp }   「同一份程式，兩種說法」
      bridge-02  pins: { target: c }     「切過去看看」
      ```
      🎯 **而這順帶解掉一個原本要新通道的問題**：
      2026-08-27 稍早的結論是「教案沒辦法說『這一步請切目標』，
      所以老師用嘴巴說」（見 [假設教室裡有老師](../2026-08-27-假設教室裡有老師.md)）。
      **而如果教案 pin 目標，切換就是「進到下一課」的副作用。**
      > 一個原本需要新通道的教學動作，變成了「換一堂課」的自然結果。

- [ ] **③ 切目標時的降級【必須說話】**
      ```
      學生在 cpp 寫 string name;  → 切到 c 目標
                                    c-beginner 沒有 string_declare → 降級
      ```
      ⚠️ 這是[粒度](../2026-08-27-粒度屬於投影.md)那一題**第一次真的撞到人**，
      而且是在一門**刻意要讓它發生**的課上。
      🟢 那反而是好消息：**降級不是缺陷，是教材**
      ——⚠️ 但它必須說得出話（P6），不能安靜變成 `raw_code`。

- [ ] **④ `requires` 與目標的 `provides` 對不上時要明說**
      9 個 Arduino 板子共用一門課，而 `provides` 不同
      （esp32 有 WiFi／touch_read，uno 沒有）。
      今天的機制是「工具箱可見集合 ＝ 課程清單 ∩ 目標提供的」（`types.ts:833`）
      ——**所以它會自動少掉，而且會【安靜地】少掉**。
      🟢 教案宣告 `requires: ['wifi']`，目標不提供就說「這一課需要 ESP32」。

- [ ] **⑤ 缺一顆 `deque`（一個形態值）＋ 巢狀 vector 未驗**

## 🔴 實測改掉的地方（2026-08-27／28 生 52 堂課時）

這份地圖的元件清單原本是**推**出來的。全部實際跑過一次之後，三處是錯的：

| 章 | 地圖寫 | 實測是 |
|---|---|---|
| C++ 6 字串 | `string_size` | **`vector_size`**（`name.size()` 與 vector 共用一顆） |
| C++ 13 vector | `container_push` | **`container_append`** |
| C++ 8 選擇 | `if` ＋ `if_else` | 只有 **`cpp:if`**（else 是它的形態，不是另一顆） |

另外每一章都多一顆 **`literal_number`**——`return 0;` 的那個 `0`。

> **一份憑印象列的元件清單，與一份量出來的長得一模一樣
> ——直到有人照著它上課。**

### Arduino 軌道釘的是【板子】，不是 `arduino`

`arduino.json` 的 `board` 是 `null`，所以 `LED_BUILTIN`／`A0`／`HIGH`
這些常數一個都沒有——**A1 的第一課會直接說「變數尚未宣告」**。
14 個單元全部釘 `arduino-uno`（A11 釘 `esp32`）。

### 🟢 Linked List 修好了，而且進了進階軌的第 6 課

它原本因為三件事跑不動，**三件都修了**（2026-08-28）：

```
new Node        用 defaultValue 建 → 那不認得結構     → 改問 ctx.structs
p->val          `->` 只認【符號式】指標（value 是名字）→ 加上實體式那條路
p != NULL       toNumber 對陣列回 0 → 走訪一圈都不跑   → 配好的儲存體不是空指標
```

**位置**：不放最後，放在「佇列與堆疊」之後——
你剛用過標準函式庫給的容器，這一課自己做一個，
而它同時是「圖」和「樹」的地基（**那兩種也是節點 ＋ 指標**）。

⚠️ 它的前置是**指標**，而指標住在 C 銜接軌。課文開頭明講並附連結。

## 🔴 軌道結構（2026-08-28 拍板）

原本的地圖把 Python 當成一條軌，而**寫出來之後發現它是銜接不是入門**
——通篇「這和 C++ 差在哪」。而拍板過的原則是
**「每一個目標都可以預設從頭來，銜接與進階另外處理」**。

所以拆成六軌：

| 軌道 | 章數 | 給誰 |
|---|---|---|
| `cpp-beginner` | 15 | 從頭學程式（C++） |
| `python-beginner` | 12 | **從頭學程式（Python）** ← 新寫 |
| `arduino` | 14 | 硬體專題，自己就是入門 |
| `cpp-advanced` | 13 | 進階（含 Linked List） |
| `c-bridge` | 5 | C++ → C |
| `python-bridge` | 6 | **C++ → Python** ← 原本那 6 章改的家 |

### `cpp-competitive` → `cpp-advanced`

那一軌教的是排序、二分搜、STL、圖、DP——**競賽與資料結構共用的那一層**，
而「競賽」這個名字把它窄化成一種比賽。顯示名改「C++ 進階」。

🔴 `targetId` 住在存檔裡，所以附了 P8 要求的一次性轉換（**存檔 v17 → v18**）。

### 編號

每一軌各自從 `01` 開始、兩位數、不加字母前綴。
跨軌引用要寫全（`C++ 入門第 5 課`）——**兩個「入門」軌並存之後，
「入門第 5 課」是有歧義的。**

**已交付 65 章**，全部量測過、有護欄、有 e2e。
