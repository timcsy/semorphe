# 主控台回到 panel 區，而十字退場

> 日期：2026-09-02
> 狀態：🪦 **已交付並退場**（2026-09-02，spec 171）——結論與三個未決的答案
> 記在 [history/202](../../history/202-十字退場而主控台回到它本來的位置.md)。
> 怎麼冒出來的：使用者在 Arduino IDE 按「三欄」與「十字」，得到四條擠在
> 一起的窄欄，說「**好像沒有比較好**」，接著給了這個提案。

## 一、使用者逐字

> 「我們**捨棄十字**，然後讓最底下水平**完全展開**是放主控台（不同於現在
> 沒有完全展開），像是 VSCode 那樣，然後其他面板就在上面分割畫面，
> 這樣在**三個宿主環境都可以比較一致**。然後主控台可以**關閉或是開啟**，
> 行為跟 VSCode 那邊類似，然後把我們的主控台跟原生的綁在一起，
> 就是**多塞幾個 tab**，而不是走編輯視窗」

## 二、🔴 它解掉的是我一直在繞的那個問題

Theia 沒有 `vscode.setEditorLayout`（查證過：Arduino IDE 的 bundle 裡**零筆**）。
我花了兩輪在找「**怎麼讓 Theia 做垂直分割**」——寫了退路、寫了能力探測。

而**十字是唯一需要編輯區有第二列的版面**。拿掉它之後：

```
專注 / 對照 / 三欄   全部是【純欄】
⟹ reveal(ViewColumn) 就排得出來，三個宿主都做得到
⟹ setEditorLayout、arrangeBySplitting、能力探測【全部可以刪】
```

> **我一直在問「怎麼讓這個宿主做到 X」，而正確的問題是「為什麼我們需要 X」。**

而答案在自己的概念裡：**主控台不是一種投影，是執行的輸出**
（三維錨定：執行追蹤屬於**情境**，不屬於投影——
[history/198](../history/198-執行追蹤不是投影而護欄早就這樣對待它了.md)）。
**它本來就不該待在編輯區。**

## 三、🟢 而這是兩種一致第一次指向同一邊

```
網頁版現在        底下一條全寬的 bottom-container（主控台／變數兩個分頁）
                  上面的編輯區分欄
VSCode 的 panel   逐字就是這個
```

2026-09-01 學到「一致性有兩個方向——與宿主一致、與自己一致」，而那一次它們
互相衝突（`experience`）。**這一次不必選**。

## 四、⚠️ 我先前收回主控台的理由，在這裡不成立

`vscode-profile.ts` 上寫著（2026-08-25）：「終端機，不是 Output 面板
——我們的程式會讀 `cin`，而一個唯讀的輸出格會讓『輸入』沒有家。」

🔴 **那句話的對手是 Output channel，不是 panel 區。** panel 區放的是
`WebviewView`——**那是我們自己的 webview，它有輸入框**。

> **一個「因為 A 不行所以選 B」的理由，在 C 出現時要重新問一次
> ——而不是把 B 當成結論。**

## 五、已查證：Theia 支援 panel 區的 WebviewView

```
registerWebviewViewProvider               ✅ 在 bundle 裡
resolveWebviewView                        ✅
"views.container.panel"                   ✅ 一個明確的貢獻點
vscode.extension.contributes.view.webview ✅
registerViewContainer(location, spec)     ← panel 是它認得的 location
```

⚠️ 而這一次是查**實作**不是查字串——上一輪我在 bundle 裡 grep 到
`splitEditorDown` 就說「它有」，而那證明不了它註冊成指令（實測退路失敗）。

> **一個字串出現在 bundle 裡，可能只是鍵盤設定或選單標籤。**

## 六、要拍板的三件

### ① 分頁：一個 WebviewView 還是兩個

```
甲  一個 WebviewView，裡面畫我們自己的「主控台／變數」分頁
乙  兩個 WebviewView，與終端機並排成 native 分頁   ← 使用者說「多塞幾個 tab」
```

⚠️ 乙 是兩個 webview context——除非**兩個都是真的投影**（各自從文件 lift），
否則就回到「被餵的薄視圖」那個形狀（而那個形狀的傷 2026-09-01 記過：
餵它的面板關掉之後沒有人清它）。

### ② 第八十一條護欄的 I4 要反轉

今天逐字（`tests/integration/audit-layout-presets.test.ts:142`）：

> 「🔴 I4 硬性零：`state` 必須在【每一個】版面裡恰好一個連續矩形**——不得缺席**」

而新的規範是「**可以關，而它必須叫得回來；有輸出時它自己會回來**」。
🔴 那是一次**明確的反轉**，要記成轉變（`history/`），不是安靜改掉。

### ③ 十字退場要有承接處

它當初的理念是使用者 2026-08-31 說的：「四格，每一層一格」「**沒有任何一層
是特別的**」。

🟢 由「**上面三欄平等**」承接：程式碼、流程、積木在編輯區裡誰都不特別，
而主控台**不在那個比較裡**——因為它不是一種投影。

## 七、這一刀刪掉的比加的多

```
🪦 setEditorLayout 那條路
🪦 arrangeBySplitting（分割退路）
🪦 detectLayoutCaps（能力探測）
🪦 十字的 2×2 推導
🪦 state 在 areas 裡的所有特例（reduceAreas／normalizeShape 都變簡單）
🪦 第八十一條的 I4（改寫）

＋ 一個（或兩個）panel 區的 WebviewView
＋ 「有輸出時自己回來」的那一句
```
