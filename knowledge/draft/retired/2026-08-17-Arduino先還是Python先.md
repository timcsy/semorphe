## 一、兩者的門今天都開著

階段 6.5（格式收斂）做完之後，`vision` 那個「都該等格式收斂」的前置解除了。
而 `支援Arduino`§五 逐字：

> 「⚠️ 而 ArduinoCAD 併入的硬條件是『就近性先做完』——**那個條件已經解除**
> （`notEncapsulated: 0`）。」

**所以這不是「誰被擋住」的問題，是「先做哪個比較划算」。**

## 二、第一步的性質完全不同

```
Arduino 的第一步   執行模型（持續執行 ＋ 模擬時鐘）
                   ❌ 不需要硬體　🟡 中　而【沒有任何未決】

Python  的第一步   🔴 收錄門檻在哪（PyPI 50 萬個套件，沒有邊界）
                   而 `Python的package怎麼收`§五 自己說【還沒答】
```

> **兩件事都「可以做」的時候，問的不是哪個重要，
> 是【哪一個的第一步沒有未決】。**

⚠️ **而那不是一條通則，是這一次的判準**——它成不成立要看第五節那個事實。

## 三、而 Arduino 的「語言那一半」是量過的

2026-08-17 對十段 Arduino 程式跑完整管線
（記錄在 [支援 Arduino 要加什麼](../2026-08-13-支援Arduino要加什麼.md)§一）：

```
殘差節點  0/10   🟢 全部辨識得出來
輸出      ""×10  🔴 而一段都沒有真的執行——沒有 main，setup/loop 沒人呼叫
```

**兩件事同時成立**：語言那一半確實幾乎免費，
**而第 1 項（執行模型）是唯一「不做就什麼都做不了」的**——量出來的，不是推論的。

## 四、🔴 而反方的理由是真的，不要弱化

`vision` 記著 Python 的角色（階段 7）：

> 「Python……是**驗證階段 6.5 修好的架構**，並回答膠囊格式唯一需要第二語言的
> 問題——**universal 元件是一顆膠囊還是每語言一顆**」

```
Arduino 驗的   面板／新槽／執行模型      而【不驗語言無關性】——因為它就是 C++
Python  驗的   🔴 語言無關性（P9）       四項獨立性之一
```

⚠️ **所以先做 Arduino 的代價是**：膠囊格式的語言無關性晚一輪被驗，
而**在那之前加的每一顆 Arduino 膠囊，都是在一個沒被驗過的格式上加的**。

## 五、🔴 決定順序的那個事實——而它沒有被查

> **「Arduino 的 1–4 項會不會新增 `universal` 元件？」**

```
不會   → 代價很小　　→ 先 Arduino
會     → 那些膠囊可能要跟著 universal 的答案重做一次
```

⚠️ **這一題十分鐘查得出來**（1–4 要加的是腳位狀態機、`Serial`、
`pinMode` 那些——直覺上全是 cpp 專屬），**而它沒有被查**。

> **一個「先做哪個」的問題，常常不是靠比較兩邊的價值決定的，
> 是靠找出【那個會讓其中一邊變貴的事實】。**

## 六、傾向（而它有條件）

**先 Arduino** ——理由是第二節（第一步沒有未決）＋ 第三節（語言那一半量過了），
⚠️ **而它的前提是第五節那個事實是「不會」**。

**還有一個附帶好處**：`支援Arduino`§「第 4 項的價值不只是 Arduino」記過
板子視圖是**面板層的探針**，而使用者 2026-08-13 觀察到
「面板還沒有為新視圖鋪路」（量出來三件事只鋪好一件）
——**那個問題今天沒有任何東西在推動它**。

## 七、🔴 而 2026-08-17 下午的一則，**削弱了第二節那個理由**

使用者：「**我想要先把它至少視為不同風格或是不同語言，而不是純粹 C++**」。

而它落在 `target` 那一格（見
[C 和 C++ 難分難捨](../2026-08-13-C和C++難分難捨.md)§三 的新增段）。**後果**：

```
第二節說的   Arduino 的第一步【沒有任何未決】
而現在       第一步變成【一個機制】——target 的四個欄位
```

⚠️ **所以「哪一個的第一步沒有未決」這個判準，兩邊的差距縮小了。**

```
Arduino   第 0 項是一個機制，而【設計已經寫好了】（C和C++ §三）
Python    第一步是一個【還沒有答案】的門檻問題（PyPI 50 萬個）
```

**差距仍在，而它從「一個有／一個沒有」變成「一個有設計／一個沒有答案」。**

🔴 **而反過來看，它也給了 Arduino 一個新理由**：`target` **不是 Arduino 專用的**
——它同時解掉 C99／C++11/17／競賽班的 printf-cout 不一致，
而那三件事今天**都沒有東西在推動**。

> **一個機制被三個消費者同時需要，而只有一個消費者是「不做就繞不過去」的
> ——那個消費者就是它該被做的時機。**

## 出口條件

- ~~🔴 **§五那個事實被查**~~ ✅ **已查**（2026-08-17）：
  `src/components/universal/` **不存在**，189 顆全部是 `cpp` scope，
  `universal-concepts.json`／`universal-blocks.json` **都是 0 筆**。
  **答案是「不會」——而理由不是「大概不會」，是「那個 scope 是空的」。**
  ⚠️ 而查證換出一個更準的風險：第 1 項要改 `src/interpreter/`（在中立性護欄的
  `NEUTRAL_DIRS` 裡），🟢 而那條護欄的基線是 `total: 0`，會擋住耦合。
- 🔴 **而 §七 出現之後，新的阻斷是**：`target` 這個機制要不要先做
  → 它不只服務 Arduino，所以那是一個**比排序更大的決定**
- ⚠️ 或者使用者直接拍板 → 那時把**沒被採用的那一邊的理由**留在
  `history/`（`capture` 的「Rejected option → tombstone」）
- ⚠️ **而「在那之前不要開始任何一邊」這句要收回一半**：
  §五 的阻斷解了，🔴 **而 §七 換上一個更大的**。
  **兩個阻斷的性質不同**：前一個是「查一下就知道」，後一個是「要你決定」。

> **一個阻斷被解開之後，換上來的那一個常常更大——
> 而『還在等』這三個字會讓它看起來像同一件事。**
