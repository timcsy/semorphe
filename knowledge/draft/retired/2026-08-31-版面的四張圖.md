# 版面：四張示意圖，而十字是第一個沒有任何一層特別的排法

> 🪦 **已退場（2026-09-01）** — 那一刀做完了（spec 168）。
> 結論與轉變見 [history/199](../../history/199-版面說了根公理的反話，而修它動到一條一維的硬性零.md)，
> 教訓見 `experience.md`。**留在這裡的是「當時為什麼這樣想」——包括被否決的那個排法。**

> 2026-08-31。起點是使用者一句話：「你現在把積木和流程用 tab 切換我不太喜歡，
> **因為這樣程式碼面板就變得比較特別了**」。

## 一、🔴 那個不對稱說了根公理的反話

```
程式碼   永久佔一欄
流程 ┐
積木 ┘  共用一欄，用分頁互斥
```

三個都是投影，而只有一個不必跟別人搶位子——**而被特別對待的那一個，
正是整個專案存在的理由要說「它不特別」的那一個**。

> **唯一真實，各式投影**——而版面說的是「程式碼是主的，另外兩個是配的」。

⚠️ 它也違反了自己的宣告：`compare` 宣告 `[element, space]`，
而那一欄實際是「space **或** relation」——分頁把兩層塞進一格，
而 `layout-presets.ts` 檔頭明文說「預設列的是**看見哪幾層**」。

## 二、🟩 定案的四張圖

```
專注             對照              三欄               十字
┌────────┐   ┌─────┬─────┐   ┌────┬────┬────┐   ┌─────┬─────┐
│        │   │     │     │   │    │    │    │   │程式碼│ 積木 │
│ 程式碼  │   │程式碼│ 積木 │   │程式碼│流程│積木│   ├─────┼─────┤
│        │   │     │     │   │    │    │    │   │ 流程 │主控台│
├────────┤   ├─────┴─────┤   ├────┴────┴────┤   └─────┴─────┘
│ 主控台  │   │   主控台   │   │    主控台     │
└────────┘   └───────────┘   └──────────────┘

主控台那一格內部：主控台／變數**分頁**（與今天的底部一致，不發明第二種切法）
```

四張各自有不重疊的定位：**專注＝小螢幕 · 對照＝預設 · 三欄＝寬螢幕 · 十字＝大螢幕看全貌**。

⚠️ **上限就是四張**，理由是這個專案自己的判準（`layout-presets` 檔頭）：
「老師說『看左邊那一欄』時，那句話要對每個人都成立」——**圖越多，那句話越不成立**。

### 🟢 十字為什麼是「程式碼｜積木 ／ 流程｜主控台」

使用者拍板的排法，而它買到一個性質：

```
對照   程式碼 │ 積木
十字   程式碼 │ 積木
       流程   │ 主控台
```

**從「對照」切到「十字」，程式碼與積木一格都不動——只是底下長出兩格。**

> **一個切換版面時「你正在看的東西不會跳走」的版面組，
> 比一個每一格都重排的版面組好用得多。**

而二維的排法有它自己的說法（一維那條規則在二維上沒有定義）：

```
上排   程式碼 · 積木     同一段程式的兩個【可編輯】投影，最常對照的一對
下排   流程 · 主控台     一個講「怎麼走」、一個講「跑起來說了什麼」
```

🪦 **被否決的排法**：`程式碼｜流程 ／ 積木｜主控台`。
它的賣點是「閱讀順序恰好等於 `LAYER_ORDER`」，而那是**一個被過度加權的巧合**
——代價是切版面時積木會從右上跳到左下，**每次都要重新找積木在哪**。

## 三、🟩 已拍板

- **主控台格內用分頁**（不是再切一半）
- **左右是語義，不是偏好**（不提供鏡像版）
  ⚠️ 理由不是 `LAYER_ORDER`（見上面的墓碑），是**四張圖之間的一致性**：
  一旦可鏡像，「切版面時東西不跳走」這個性質就沒了
- **三欄維持 `程式碼│流程│積木`**（流程夾在中間）
  🟡 已知的小不一致：切到十字時積木從第三欄跳到右上。**使用者判定不改**
  ——把三欄改成 `程式碼│積木│流程` 會弄丟「流程是連接兩者的那一層」這個理由

## 四、🔴 它動到一條既有規則，而是「改準」不是「推翻」

`layout-presets.ts` 檔頭逐字：

> 「`state`（主控台／變數）**不在這裡**：它的家是下方的面板區，三個預設都一樣。
>  **列它進來會讓「面板區」變成一個可以被佈局關掉的東西**，而那與
>  『程式在講話的地方』衝突。」

而十字**沒有把它關掉，是給了它一個對等的格子**。所以：

```
舊  state 不進佈局宣告
新  state 不得被【關掉】，但它的【位置】可以由佈局決定
```

🟢 這反而更誠實：今天四張圖裡三張把它放底部、一張放右下，
**那本來就是佈局在決定的事**，只是以前被寫成「不歸佈局管」。

## 五、實作事實（量過的）

```
🔴 專案今天只有 showQuickPick（文字列），沒有任何「圖示網格」元件
   → 示意圖選單是一個【新元件】，不是換一份資料

🟢 而 layout-presets 已經是宣告式的（id / layers / nameKey）
   → 圖可以【從宣告產生】，不用手畫四張 SVG
   ⚠️ 這讓「加一個版面」仍然只改一份宣告——不會回到手寫圖的老路
   ⚠️ 而十字是二維的，`layers: []` 這個一維欄位表達不出它
      → 宣告要能表達「幾列幾欄、哪一格放哪一層」

🔴 第七十八條護欄：不得把 id 印上畫面 → 圖上的字要走 i18n 鍵
🟢 行動版今天【沒有流程分頁】（`app-shell.ts:714`：「流程從來沒有進來過」）
   → 走「每個槽都有一樣的分頁列」的話，這個缺口會自動被填上
```

## 未決

- [ ] **每個槽都有一模一樣的分頁列**（程式碼／流程／積木）——分頁不是問題，
      **不對稱的分頁**才是。⚠️ 順序：**先有對稱的槽，再談槽裡放什麼**
- [ ] 兩個槽能不能顯示同一層（例如左右都放程式碼）
- [ ] 選了版面之後，槽的內容是**套用該版面的預設**還是**保留使用者上次換過的**
      （不講清楚的話，示意圖上的字會與畫面不符——**圖在說謊**）
- [ ] 十字在 13 吋筆電上每格約 600×350，Blockly 與流程圖能用但轉圜小
      → 它不該當預設，而「該不該在小螢幕上把它藏起來」還沒決定
