## 一、cella 不是探針——那只是走訪器今天住哪

vision〈第六路〉寫的是「**洞 → 積木**」（cella 回報的位置對回 `nodeId`，使用者：「可以指明
程式哪個位置錯」）與「**說不出保證的時候要出聲**」——那是**使用者編輯時**的事，不是測試。

「探針」只描述走訪器今天在 `tests/probes/`；它的搬家條件寫在檔頭：「有產品消費者」。

⚠️ **而我把那個暫時狀態寫成了一條斷言**（第 315 刀：`@cella-lang/cpp` 必須在 devDependencies，
訊息寫「它只有探針用」）——走到設計要去的地方時，它會擋路。已改成只守精確釘選。

> **一條斷言守住了「今天它住哪」，就會在設計要它搬家的那天擋路。**

走到產品還缺三件：① 瀏覽器內的延遲重量（上一次 1.38 秒是預載 10 個模組時，
加上 int 4 MB＋cpp 1.1 MB 之後沒人量過，要量上界不只中位數）· ② 洞 → `nodeId` 的 map ·
③ 走訪器搬進 `src/`（每顆元件自己的 `formalize.ts`＋登錄表）。

## 二、accept 而 0 個洞，保證的是什麼

**每一個寫成前置條件的義務都被證明了**——今天是：

```
cpp:arithmetic   有號溢位、除以零、INT_MIN / -1
cpp:array_at     索引越界（負數或 ≥ 長度）
```

⟹ 保證的是「**這幾種** UB 不會發生」，不是「沒有 UB」。

## 三、「子集沒有 UB」的四個前提

```
① 契約完整     每顆元件會造成的 UB 都寫成了前置條件     cella 判斷不了 —— 我們的責任
② 翻譯忠實     走訪器產的項就是那支程式                 錯了就是「驗另一支程式」（Nat 那次）
③ postulate 對  decLt、arrayAt 與 C++ 的語義一致          我們自己扛的、沒人查過
④ 平台         保證相對於資料模型（lp64／avr）與編譯器符合標準
```

①是離得最遠的：讀未初始化、位移超過寬度、空指標、迭代器失效、求值順序、生命週期……
任何一顆漏寫，cella 對那種 UB 就是**沉默**的。今天的覆蓋是 3 / 65 顆。

🟡 **提案**：每顆元件宣告「它可能造成哪些 UB、各由哪個前置條件擋住」，漏了就紅。

## 四、可靠而不完備

```
可靠（sound）   accept 的一定沒有那幾種 UB      ← 前提是 ①②③④
不完備          沒有 UB 的程式也可能有洞        ← 要範圍推理、迴圈不變量
```

**有洞 ≠ 有 UB**。`return a + b;` 的洞說的是「沒有人保證輸入小」。洞的正確讀法是
**義務往外推**：「只要呼叫者保證 `a + b` 不溢位，這段就安全」——對教學比 accept／reject 有用：
它告訴學生**該在哪裡檢查輸入**。

## 五、不是 UB 的那兩類

- **做的是不是對的事**：accept 不說這件事。要寫後置條件（規格），今天的契約只有前置條件。
- **實作定義／未指定**：不是 UB，cella 不擋（`nan` 的正負號在 libc++ 與 libstdc++ 不同——CI 撞過）。

## 六、如果 cella 的子集語義站在 SOTA 上

```
① 契約完整    Cerberus 那類語義有完整的 UB 目錄（C 標準附錄 J 約兩百條）
              ⟹ 「元件會造成哪些 UB」由語義推出，護欄變成「每顆元件對得到子集裡一個構造」
② 翻譯忠實    語義定義在 C 的語法樹上 ⟹ 走訪器只做【語法對應】，可以用來回轉換驗
③ postulate   decLt、arrayAt 變成定理，「我們自己扛的」那一欄歸零
附帶          可執行的語義 ＝ 直譯器的第三個對照（直譯器 ↔ 形式語義 ↔ g++）
```

它還打開兩扇門：**分離邏輯**（Iris／VST／CN／RefinedC）給的記憶體與效果模型
——正是那 90 個碰 I/O 的函式與 `find`／`unite`／`dfs` 缺的；以及**規格語言**（後置條件、不變量）。

⚠️ 補不了的兩件：

- **C++ 的 STL**：SOTA 幾乎都是 C，C++ 最接近的是 BedRock 的 BRiCk（Coq＋Iris）；
  而課文大量用 `vector`／`stack`／`string`／`map`。子集實際上會先是「C 風格的 C++ ＋ 少數有規格的容器」。
- **速度與錯誤訊息**：SOTA 的證明要人寫輔助引理、跑秒到分鐘、訊息給專家看；
  我們要的是學生拉積木時、瀏覽器內、一秒以內——那是 cella 的定位（作者在隔壁、輸出改得動）。

## 七、那會讓我們的角色變清楚

語義的權威若是一套驗證過的子集語義，我們不必再是半個語義學家，剩下別人做不了的三件：

1. **積木 ↔ 構造的對應**（膠囊的工作——「語言語義住 Library、對應住膠囊」）
2. **證明投影給人看**：洞對回積木、前置條件翻成中文、說得出「哪一段沒有保證、為什麼」
3. **教學順序**：哪些構造先開放，工具箱標出哪些積木有保證

⟹ 一個對外說得出、能被檢驗的承諾：
**「工具箱裡標了保證的積木，組出來的程式在指定平台上不會有未定義行為。」**
它的可信度建立在那套語義上，不是我們的走訪器上。
