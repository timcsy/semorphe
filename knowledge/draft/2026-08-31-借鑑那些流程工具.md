# 借鑑那些流程工具——而多數「值得學的」其實已經在了

**日期**：2026-08-31 ｜ **狀態**：勘查（多數結論是「不做」，理由在下面）
**起點**：使用者「看看 BlocklyFlow／Grapycal／Ryven／LangGraph 有哪些可以採納」

⚠️ **這一份記的主要是【被否決的選項】與否決的理由。** 那是最容易丟、也最貴的東西——
沒寫下來的話，半年後同一個提案會被當成新想法重推一次。

🔴 **而這些否決是 AI 的分析，不是人的拍板**——所以它們在 `draft/`，不在 `history/`。
真的要定案，要人點頭並且進 `history/` 當墓碑。

---

## 一、BlocklyFlow（自家 2026-02 的實驗，2.5 週、106 個 TS 檔）

**它是 Semorphe 的祖先**：`docs/first-principles.md` 的 P1 投影定理／P2 概念代數／
P3 開放擴充／P4 漸進揭露，就是今天 `principles.md` 那四條。

| 它的設計 | Semorphe 今天 |
|---|---|
| 分級可逆性 `structured_info ≡` / `total_info ⊇` | `concepts/投影.md:57` 的 R1，一字不差 |
| 三類資訊（語義／呈現／元資訊） | 散在 principles／投影／元件代數／認知鷹架 |
| 註解＝平級節點、行尾註解跟著宿主 | **更遠**：註解是元件，`comment-syntax.ts` 是登記處，還有「核心層零註解語法」護欄 |
| 工具箱分類展開 | 工具箱由登錄表導出 |

### 🪦 否決①：接點型別系統

它有 `TypeId` ＋ `isCompatible()` ＋ `getCoercionPath()`；Semorphe 的接點只有
`"check": "Expression"`（207 處）與 `"Statement"`（29 處）——**接點上沒有型別資訊**。

**而否決它的四個理由**：

1. **它會在該說話的地方剛好啞掉**——`var_declare_auto`／`template_function`／`typedef`／
   `using_alias`／`struct_declare`／`class_def` ＋ 31 顆指標容器，每一顆都讓型別變「不知道」；
   降級的 `raw_code` 連型別欄位都沒有。不知道只能放行（誠實降級要求的）。
   **簡單情境萬無一失、困難情境沉默。**
2. **它跟「吃真的程式碼」打架**——接點會拒絕 ⟹ 真實程式碼 lift 進來可能畫不出來。
3. **課程裡真的會發生的轉換全部合法**——實測 `lessons/`：
   `int 362 ｜ string 17 ｜ char 16 ｜ double 15 ｜ long long 11 ｜ float 11 ｜ bool 11 ｜ auto 2`，
   而 int→double／char→int／int→bool 在 C++ 全合法。coercion graph 會對每件事說「可以」。
4. **「不讓學生做錯事」已經有機構了：工具箱**——它按課給積木，第 3 課拿不到字串。
   那是**課程層**的約束，比型別層更符合漸進揭露。

> 🔴 **而我推薦它的方式本身是錯的**：理由是「BlocklyFlow 有而 Semorphe 沒有」，
> 那是**從缺席論證**，不是從傷害論證。這個 repo 的每一條護欄後面都有一次具體的翻車，
> 型別這條一次都沒有。

**改口的條件**（不是「有人覺得該做」）：

> 量得到「學生的程式有多少比例因為型別而執行失敗」。
> 而現在答不出來——`src/interpreter/errors.ts` 裡**一個型別相關的錯誤訊息都沒有**。
> **所以真要動，第一刀不是型別系統，是讓直譯器說得出「這裡是型別問題」，然後量它。**

### 🪦 否決②：Prompt 當成一個語言（17 種區段 ＋ 39 模板 ＋ 三格式）

用這個專案自己的刀測——`concepts/元件.md:5`：「填得出就白拿整套機器，**填不出就代表那個域不是元件，剪掉**」。

```
接點那一格（要帶關係律）：
  tool-declaration / examples / variables / chain   ✅ 有型別、有成對、有資料流
  system / context / instruction / safety / persona … 🔴 彼此只有「順序」＝排版，不是關係律
```

**17 種裡約 4 種過得了。其餘 13 種是 markdown 的標題。**

而另外兩格也擋：

- **lift 不對稱**：XML／JSON 可逆（是解析），**plain 是散文、沒有文法** ⟹ 三個格式不對等，
  是「一對可逆投影 ＋ 一個有損匯出」。
- **行為撞硬性零**：送 LLM ＝ 要網路 ＋ 非決定性（`e2e/offline.spec.ts:2` 第四十五條）。
  🟢 有解：**行為 ＝ 渲染成最終文字**（決定性、離線）；**呼叫 LLM 站在管線外**。

🟡 **縮小後的版本是有東西的**：不是「把 prompt 做成積木」，是「**agent／工具規格當元件**」
（工具簽名、範例對、變數綁定、步驟圖），而流程視圖是它最強的一格。
⚠️ **而那正是 LangFlow／Flowise／Dify 的位置**——資金充足、產品成熟。
**方向是：從一個罕見的位置走進一個擁擠的位置。**

### 🪦 否決③：自然語言 → 積木（LLM 生積木）

它會破壞**這個專案唯一真正稀有的性質**：投影是決定性、可逆、可驗證的
（`code → blocks → code` 逐字相同有測試守著）。

🟢 **界線**：LLM 產出**程式碼**貼進程式碼那一格，走既有 lift。
**那樣它是一個輸入法，不是一條新的真相來源。** 這條界線值得寫進原則。

## 二、🟢 自然語言元件：它已經存在，只是拿不到

`cpp:comment` 是完整元件（`role: statement`、五路跑四路、lift／generate 都在），
而 **沒有任何 topic 的工具箱給它**、**流程視圖完全不畫它**。

它是誠實降級的**對稱面**：

```
raw_code   程式碼在這裡，而系統還不理解它   ← 系統能力的邊界
意圖節點    意圖在這裡，而程式碼還不存在     ← 作者進度的邊界
```

而 `concepts/降級與認知邊界.md:68` 已經寫著 D2 是「**結構在、意圖沒了**」——意圖節點是反過來那一格。

⚠️ 缺的三件小事：工具箱給它一格、流程視圖畫得出它、**一個「未兌現的意圖有幾個」的可見數字**
（沒有它，學生會寫一堆中文然後永遠不換掉，而系統會安靜地接受）。

## 三、Ryven／Grapycal：一個決定一切的差別

**它們都沒有 `lift()`。** 圖**就是**程式（Ryven 的節點是你寫的 Python class），
你不能拿一個現成的 `.py` 變成圖。而 Semorphe 的流程視圖是**一段真實程式的投影**。

| | 判斷 |
|---|---|
| **Grapycal：節點上的資料視覺化** | 🟢 **最便宜、教學價值最高**——`flow-panel.ts` 的 `onExecutionAtNode` 今天只設 `highlighted`，註解自己承認「先亮起來」 |
| 節點套件 ＝ pip 套件 | 🟡 驗證了 `concepts/元件.md` 那格 `@<user>` scope（宣告了未落地）是**真的缺口**。⚠️ 難度高一階：它們的節點只要能跑，我們的元件要**五路完備** |
| Ryven `ryvencore` / `ryvencore-qt` 分離 | 🟡 驗證——我們是 Core/Bus/View ＋ 第三十九條護欄 |
| Ryven data connection vs exec connection | 🟡 驗證——流程視圖的資料線 vs 語句線，**獨立長出同一個區分** |
| Ryven 的 push（data flow）vs pull（exec flow）**模式** | 🔴 不適用。求值順序由**程式語義**決定，不是連線模式。**它們需要那個開關，正是因為沒有 AST** |
| 「終止一個迴圈」 | 🟡 已有：`maxSteps` 100000 ＋ `aborted` |
| Grapycal 的 client-server ＋ 即時協作 | 🔴 撞第四十五條硬性零。⚠️ **而教室協作是真需求**——要動硬性零，要人拍板 |

### 而最深的一課是它們的取捨

```
Ryven／Grapycal   圖即程式  → 擴充容易 ／ 東西被鎖在工具裡，沒有 .py 可以帶走
Semorphe          圖是投影  → 擴充貴（五路完備）／ 使用者的東西永遠是一份真的原始碼
```

⚠️ **所以借鑑它們的擴充機制時要小心**：`@<user>` 那格如果為了容易而放寬五路完備，
換到的就是它們那一邊的位置。

## 四、LangGraph

### (a) 借鑑設計——只有一個值得拿

state channels／reducers 🔴 不需要 · conditional edges 一等公民 🔴 那是**沒有 AST** 才需要 ·
human-in-the-loop 🟡 已有（斷點 ＋ 行內輸入）· super-step/BSP 🔴 無關 ·
**每一步存檔 → 時光旅行 🟢** ← 見 [過程是一等公民](2026-08-31-過程是一等公民.md)

### (b) 🟡 支援 LangGraph 當目標——比「Prompt 當語言」好一個量級

**LangGraph 程式就是 Python 程式**，所以它不是加語言，是在既有 Python 套件上
加一批函式庫元件（走現成的 `component-discover` → `generate` → `integrate`）。
lift 全可逆、五槽填得出、流程視圖天然適配。

**三個真問題**：
① 執行撞硬性零 —— 🟢 有解：`FakeListLLM` 那類**決定性樁**（教學上反而更好），
   ⚠️ 但那是一個**新的行為種類**（今天只有直譯執行）
② **API 變動快**，而沒有機制讓元件對到函式庫版本 → 元件會腐爛，症狀是「照課本打，跑不動」
③ **受眾**：66 堂課打 108 課綱／APCS，學 LangGraph 的是職業開發者

🟡 **形狀建議**：如果要做，是**加一條 `python-agent` 軌道**（軌道機制本來就支援多條並存），
不是改主線。

## 五、ML／訓練那條——而它讓一句話被推翻

需求要拆成兩個：

```
A  資料／預處理很貴，改一下模型不想從頭跑   ← 真痛、天天發生
B  訓練跑到一半把某一層換掉繼續練          ← 罕見，且語義可疑
```

**B 可疑**：換層之後 optimizer state 與 loss 曲線**不再對應同一個模型**——同一個
「軌跡對應不到一支程式」的問題，而在 ML 更糟，因為**那些曲線會被發表**。

🟢 **而 A 根本不需要熱抽換**：

> **Grapycal 招牌那句「run different parts of the graph in arbitrary order」，
> 真身不是「執行中改圖」，是「知道哪些節點髒了，只重跑那些」。**

那有成熟的名字：**增量重算**（Make／Bazel／Salsa／Adapton）。
⚠️ **而 Jupyter 做不到**——cell 之間的相依透過全域命名空間，**不可見**。

> **流程圖真正的優勢不是好看，是它讓「誰依賴誰」變成可計算的。**

⚠️ 而**增量重算對教學情境沒有價值**：程式跑 20 毫秒，重跑免費。它的價值只在長時程執行的世界。

### 🔴 而「這是另一個產品」那句話被執行器可插拔推翻了

初版判斷：「不要把 ML 塞進 Semorphe，那是另一個產品」。
**在執行器可插拔的框架下那是錯的**：

```
當時的假設  執行是內建的 ⟹ 換執行體制 ＝ 換產品
實際的形狀  執行是一個埠 ⟹ 換執行體制 ＝ 換一個 runner ＋ 誠實宣告能力
```

**分叉線不在產品層，在能力宣告層。** 詳見 [執行器是可插拔的](2026-08-24-執行器是可插拔的.md)。

## 六、四個世界收斂到同一招（🔴 概念候選，待人拍板）

| 世界 | 機制 |
|---|---|
| Erlang | `code_change/3` |
| CLOS | `update-instance-for-redefined-class`（捕捉被丟棄的槽） |
| PyTorch | `load_state_dict(strict=False)`（按名字與形狀配） |
| **Semorphe** | `core/flow/layout-key.ts` 的三把鑰匙配對器 |

> **四個不相干的世界收斂到同一招：按鑰匙配對，配得上的遷移，配不上的必須有明確處置。**

而其中三個學到同一個教訓：**`strict=False` 那個旗標很危險**——它安靜地丟掉一半的權重。
所以**配不上的時候必須出聲**。

🔴 **這可能該是一個 `concepts/` 檔**，而那要人拍板（長期層）。
