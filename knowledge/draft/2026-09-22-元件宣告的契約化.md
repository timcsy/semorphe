## 起點：一個感覺，與一個對得上它的數字

使用者對五路（lift／generate／render／extract／execute）的評語逐字是
「**很沒有最終標準的感覺**」。

而完備性護欄的基線上有一欄正好是那個感覺：

```
implemented  1585
declared       37

shell           0
missing         2
```

> **一條有明確標準的規範，不會有「判不出來」這一欄。**

## 一、元件宣告今天已經是契約，只是三個欄位的名字沒統一

把 `component.json` 的欄位逐個問「它其實是哪一種契約」：

| 今天的欄位 | 它其實是 |
|---|---|
| `positions: ["statement","expression"]` | **pre**（脈絡：我能出現在哪） |
| `slots.allowed` / `min` / `max` | **pre**（子節點：誰能放進來、幾個） |
| `ports.accepts` | **pre**（邊：我能參與哪些關係） |
| `params.kind` / `values` / `required` | **pre**（參數）＝ refinement type |
| `requires: ["<vector>"]` | **pre**（程式全域：這個標頭要在） |
| `consumed-by-parent` | **pre**（脈絡）——而它今天寫成「**跳過的理由**」 |
| `role` | 🔴 **post**（generate 產出什麼）——文件裡就叫「**產生器契約**」 |
| `law: shared \| exclusive` | **invariant** |
| `relation: 組合` 的「恰好一個父、刪父連子一起死」 | **invariant**（結構） |

```
pre         擠滿了，六種
post        🔴 只有一個，而且它已經叫「契約」
invariant   兩條，而它們的定義寫在 .md 的散文裡
```

> **元件系統今天把「什麼時候可以用我」講得非常細，
> 把「我保證什麼」講得幾乎沒有。**

而這個不對稱正好對得上完備性護欄的兩個病灶：post 只驗「產出非空」、121 格判不出來。

🔴 **所以要改的不是用詞，是那三欄的分佈。**

## 二、🔴 閉集 vs 謂詞：本檔最重要的取捨

使用者的原始想法是把 `shared` 這類用詞換成形式化的原語言。方向對，而**不能換成自由謂詞**。

### 列舉值有剪枝力，謂詞沒有

`law` 今天恰好兩個值。正因為它是閉集，填五槽的時候才量得出
「**UI 是三域中唯一沒有守恆關係的**」——而那句話解釋了為什麼 UI 最好教、硬體最難教。

**那個觀察來自列舉，不來自謂詞。** 換成 `invariant: <任意謂詞>` 之後：

```
沒有人知道總共有幾種律
跨域那張地圖（三域 × 三關係）畫不出來
「加一種律」從顯式決定變成一次 commit
```

⚠️ 這條與 `concepts/元件.md` 的既有規則同一條：**各域自己的是封閉詞彙表，而加字是顯式動作。**

### 🟢 兩者可以同時要：具名不變量（named invariant）

列舉留著，而每個值的定義從散文換成一條寫得出來的謂詞：

```
今天   law: "shared"   而 shared 的意思在 concepts/元件.md 的一段文字裡
改後   law: "shared"   而 shared 指向一條寫在表裡的不變量
```

```
exclusive   ∀t. |{ holders(r, t) }| ≤ 1
shared      Σ through(e) = 0  ∧  ∀ e,e′. across(e) = across(e′)     （e ∈ edges(n)）
```

寫出來之後有一件事自己浮現：**它們不是同一種東西。**

```
exclusive   持有者的基數限制    → 型別檢查得掉（線性【邏輯】）
shared      網上的方程組        → 要求解器（線性【代數】）
```

🔴 **兩個「線性」不是同一個。** 而它們今天並列在同一個 `law` 欄位裡，
消化它們的機器卻不同。這是具名不變量第一個會逼出來的東西。

🟢 而這正好兌現 [history/232](../history/232-一個好名字會讓它的判準變成同義反覆.md)
那句話——**具名不變量讓「名字＝判準」字面成立**。

### ⚠️ 同一條規則對 `pre` 也成立，而這裡更危險

`positions` / `slots.allowed` / `ports.accepts` 今天都是閉集，而**讀它們的不只一個消費者**：

```
positions      渲染器（挑形態）· 第 126 條護欄
slots.allowed  工具箱（能不能拖進去）· 積木定義產生器
accepts        連接層（能不能連）
params.values  下拉選單的選項來源
```

**換成自由謂詞，只有求解器讀得懂。** 工具箱沒辦法從一條全稱命題生出一個下拉選單。

🟢 所以要兩層，而規則是既有的**導出，不要並存**：

```
L1  結構化的 pre    閉集、多消費者讀得懂        ← 源，人寫
L2  謂詞形式的 pre   求解器讀得懂               ← 由 L1 導出，不手寫
                   ＋ L1 表達不出來的才手寫（逃生艙）
```

⚠️ 兩層各自手寫就是第三次踩雙重真相，而前兩次的症狀都是**安靜地說了兩句不同的話**。

## 三、守恆有兩個宿主，而第二個不在五槽裡

使用者指出 `shared` 可以由 invariant 處理——對，我原先把「形式化」預設成 QTT 的多重性，
因此得出「換掉硬體那一半」的結論，**那條說窄了**。

而剩下一個真的殘差，不是表達力問題，是**宿主問題**：

```
守恆的【律】   「我這幾支腳的電流加起來是零」      局部  → ✅ 元件的 invariant 放得下
守恆的【網】   「這條 net 沒有多重驅動／沒有浮接」   全域  → ❌ 不屬於任何一顆元件
```

而這件事專案已經獨立撞到兩次：

> 「per-元件的膠囊**裝不下全樹約束**」——borrow check 與電氣 DRC 是同一台機器
> 「**硬體診斷掛在邊上**」——「LED 的陽極接到 GND」不屬於 LED 也不屬於 GND

| | 住哪 | 誰消掉它 |
|---|---|---|
| 元件的 invariant | 五槽裡 | 型別檢查／局部推理 |
| **組裝的 invariant** | 🔴 **組裝**（真實，但不屬於任何一顆元件） | **求解器**，不是型別檢查器 |

⚠️ `shared` 連分離邏輯都不對口：分離邏輯處理**互斥**的資源（`*` 要求 disjoint），
而 `shared` 的定義逐字是「**多方可同時持有同一份**」。它既不要線性，也不要分離。

🟢 **組裝**本來就是五槽沒有的那一格，而契約聚合與 blame assignment 也住這裡。

## 四、五路是 DbC 的骨架，而契約的內容從來沒寫進去

DbC 有兩層，對照一下：

| DbC | 五路今天有什麼 |
|---|---|
| **五個 routine** | 🟢 完整 |
| 每一路的 **post** | 🟡 只有「產出非空、非佔位、非 raw_code」——最弱的那種 post |
| 每一路的 **pre** | ❌ 沒有（見 §五） |
| **class invariant** | ❌ 護欄裡不存在。`①→②→③→④→① ≡ identity` 只寫在散文裡 |

> **五路是一份 DbC 規格的 routine 清單，而契約的內容從來沒有寫進去。
> 「沒有最終標準」的感覺來自這裡，不是來自那五個名字。**

### 名字本身：逐個過專案的判準，只有一個弱

判準是 2026-09-13 立的那條（殺掉 `balance` 的）：**廣泛使用，而且它的常見意思就是你要的那個意思**。

| 名字 | | |
|---|---|---|
| `lift` | 🟢 反編譯／二進位分析的標準詞（machine code → IR 就叫 lifting），方向與意思都對 | 留 |
| `generate` | 🟢 | 留 |
| `render` | 🟢 | 留 |
| `execute` | 🟢 | 留 |
| `extract` | 🟡 **唯一弱的**：常見意思是「抽出來」，這裡要的是「render 的逆」 | 留，記理由 |

⚠️ `extract` 沒有現成好名字是有結構性原因的：**UI 領域是單向的，render 沒有逆。**
那個逆的標準名字在雙向轉換（BX）領域，是 `put`——而 `put` 更泛（put 什麼？放到哪？），
換過去是拿一個準確的名字去換一個泛用的。**淨損。**

🟢 **而改名的成本其實很低**：路徑名沒有進存檔，依 `concepts/元件.md` 的 bound／free 判準
它是 **bound 變數，α 轉換免費**（不像 componentId）。所以「留著」是**因為不值得**，
不是因為改不動。

### 🔴 真正該引進標準用詞的是定律那一層，因為它今天是空的

五路不是五個獨立操作，是**兩對雙向轉換 ＋ 一個觀察**：

```
真實（語義樹） ── generate ──▶ 程式碼        真實 → 投影 ＝ get
              ◀── lift ─────                投影 → 真實 ＝ put

              ── render ───▶ 積木
              ◀── extract ──

              ── execute ──▶ 行為           單向，有外部 oracle
```

lens 有三條定律，而它們正好是「最終標準」該長的樣子：

| lens 定律 | 意思 | Semorphe 今天叫什麼 |
|---|---|---|
| **GetPut** | 拿出來原樣放回去，真實不變 | 「語義的不動點」（面向②）·「走一趟積木回來」（面向④） |
| **PutGet** | 放進去再拿出來，拿到你放的那個 | P1 投影定理「來回轉換無損」 |
| **PutPut** | 連改兩次 ＝ 只做後面那次 | 🔴 **沒有名字，也沒有人檢查** |

第五路不是 lens，它的標準名是 **refinement／觀察等價**——而這個詞這個 repo
**已經在用了**（`concepts/等價與觀察集.md`）。

#### PutPut 不是「漏了一條」，是「從來沒有表態」

PutPut 對**保存資訊**的 lens 常常不成立，而 Semorphe 的 lift 正是保存資訊的
（`raw_code` 殘差、`annotations`、註解）。所以它很可能**應該明確地不要**。

> **一組標準的定律，真正的回報不是多幾條要通過的測試
> ——是它會告訴你哪幾條你決定過、哪幾條你還沒表態。**

## 五、undecidable 121 是「缺 precondition 的見證輸入」

判成 `undecidable` 的實際理由（`audit-completeness.test.ts`）逐字有四種：

```
① generate 由父概念消費，合成流程產不出程式碼——lift 沒有輸入可測
② 量測用的是 C++ 解析器——非 C++ 的元件在這裡碰不到
③ 合成樣本不是合法的獨立程式（此概念需要父節點才成立）
④ 概念宣告了 consumed-by-parent——它只在父節點裡出現，單獨量不到
```

**①③④ 是同一件事**：護欄用 `synthMinimalNode` 自己捏一份最小樣本，
而捏出來的東西不滿足那顆元件成立的條件（`case 1:` 脫離 switch、類別成員脫離類別）。

**那個「成立的條件」就是 precondition，而缺的是滿足它的見證輸入。**

🔴 而宣告機制**已經存在**：護欄裡那行

```ts
if (skipReason(id, 'execute') === 'consumed-by-parent') → undecidable
```

`consumed-by-parent` 就是一條前置條件，只是它被寫成「跳過的理由」而不是「成立的條件」：

```
跳過的理由        →  從分母移出去    →  undecidable（判不出來）
成立的條件＋見證   →  用那份見證去量  →  implemented 或 shell（判得出來）
```

> **一句「這個東西只在父節點裡出現」，當成豁免就讓量測閉嘴，
> 當成前置條件就讓量測有輸入。**

⚠️ ② 不同族——量測工具用錯解析器（Python 元件送去給 C++ 文法），契約救不了它，
要逐語言解析器。所以 121 不會歸零。

## 六、形式化語言能接管哪幾格

使用者問過「能不能用契約式設計和形式化驗證的語言取代從 ArduinoCAD 整理過來的那一套」。逐格驗：

| 槽／關係 | 宿主 | 形式機制 |
|---|---|---|
| 身分 | JSON | — （形式化對「叫什麼」沒有話說） |
| 形態 | JSON | — （🔴 結構上沒有外部 oracle） |
| 參數 | JSON 宣告形狀 ＋ 謂詞 | refinement type |
| 接點・組合 | JSON | 歸納結構／擁有權 |
| 接點・資訊 | 形式核 | 多重性 `ω` |
| 接點・守恆 `exclusive` | 形式核 | 多重性 `1` |
| 接點・守恆 `shared` | 形式核 | **invariant ＋ 求解器**（§二、§三） |
| 行為 | 形式核 | Hoare → Guarded |
| **組裝** | 🔴 新的一格 | 全網 invariant ＋ 契約聚合 |

🔴 **結論：五槽不是要被形式化語言取代的東西——它是那張模式圖本身。**

三值 `relation` 在這張表裡沒有被吸收掉，**它變成選哪一列的那個鍵**。

⚠️ 而這也是使用者自己筆記裡 MTT 的結論（「不要大一統空間，要微型宇宙網絡」）
與本 repo「**合併是錯的目標**」的同一條線——兩邊各自到達，而它們說的是同一件事。

### ⚠️ 表達力越強，剪枝力越弱

五槽的價值在它**排除**什麼（`concepts/元件.md` 開宗明義：填不出就不是元件）。
而依值型別論什麼都編碼得進去——那是它作為驗證工具的長處，
**也是它作為本體論的致命傷：一個能表達一切的詞彙，對「這不是元件」說不出口。**

## 七、宿主與分工

### JSON 外殼 ＋ 形式核那一刀，與「真實／投影」不是同一刀

```
專案的切法    真實（身分・接點・參數）  ｜  投影（形態・行為）
使用者的切法   JSON（身分・形態・元資料） ｜  形式核（邏輯）
                     ↑                        ↑
               接點與參數落在哪？——兩邊都要
```

- JSON 那側要它們：登錄表、工具箱、渲染器今天就在讀
- 形式核那側要它們：契約的謂詞要指得到那些接點與參數

🔴 **這正是本 repo 的頭號架構陷阱**（雙重真相）。處方同 §二：**導出，不要並存**。

⚠️ **那條護欄要先於拆分存在，不是之後補**——這個 repo 的疤都是同一個形狀：
一條沒有人檢查的縫不會出聲。（最近一次：`role: expression` 被 `buildFormSets`
摺進 `container_kind`，第 219 刀才修掉。）

### Lean 4 與 cella 驗的不是同一層

| | Lean 4 | cella |
|---|---|---|
| 在五槽裡的位置 | **外部 oracle**——像 `g++`，**不在登錄表裡** | **第 N 種投影**——在登錄表裡 |
| 驗什麼 | 投影管線的定律（**後設層**） | 學生程式的資源／時序性質（**對象層**） |
| 風險 | 語義樹編碼進 Lean，**那層對映會漂** | **兩個未完成的系統互相依賴** |

🟢 **而「證明義務是第六條投影」這句話白拿三樣東西**：五路變六路（缺的護欄叫得出來）、
可逆性分級 R0–R4 直接適用（證明義務是 R4）、
以及第 126 條護欄那個形狀可複製（「宣告說得出的，證明就要做得出來」）。

⚠️ Guarded TT 的第一個消費者**已經在產品裡**——Arduino 那一軌的
`10-不要用delay`（`millis()` vs `delay()` 是標準的時序性質）。不是未來的硬體。

### 🔴 第一個值得證的東西不是學生的程式

是**投影管線本身**。那是關於**我們的程式**的全稱命題，而它今天全部靠取樣：

| 要證的 | 今天怎麼量 |
|---|---|
| 語義的不動點 | 218 支語料取樣（而 144 支轉一圈回來不是同一棵樹） |
| 行為等價 `execute ≡ g++` | 91 支 |
| 走一趟積木回來 | 第 118 條護欄，53 條形狀 |

**證明失敗比證明成功更有用**：卡住的位置就是缺的那條不變量，而那正是 CEGIR。

## 八、階梯：契約怎麼從「寫了」走到「證了」

```
L0  沒宣告            →  「不可驗證」，計入分母
L1  宣告了，執行期檢查   →  直譯器跑到就檢查，違反 = 一條診斷
L2  宣告了，取樣驗證     →  語料 ＋ fuzz ＋ g++ 對答案（🟢 今天就有）
L3  宣告了，證明過       →  出一張證書
```

**這道階梯同時是解耦器**：形式核還沒好，契約停在 L1／L2；好了就升到 L3，
**宣告一個字都不用改**。於是 cella 的進度不會變成 Semorphe 的阻斷。

兩條不可合併，都是既有護欄的形狀：

```
L0（沒寫）    ≠  L1 違反了    ← 第三十二條護欄：「還不會檢查」≠「錯了」
契約違反      ≠  拒絕組合     ← 使用者自己那條：錯了要顯示，不是不給組合
```

🔴 **證明不進存檔。** 語義樹與契約是真實、要存；證明是導出物，
用 `engineHash` 那個已經在跑的機制——契約變了或驗證器版本變了，證書就過期。

> ⚠️ 而第 218／219 刀那個教訓在這裡會再出現一次：
> **一個修好了的缺陷，在它的產物重產之前，讀數上與沒修一模一樣。**

## 九、邊界：形式化到不了的地方

### 🔴 形態那一維結構上沒有 oracle

`render` 的 post 寫得出「產出的 state 載得進工作區」（＝面向③），
**寫不出「這顆積木的標籤沒有說謊」**。

這不是還沒建，是結構性的（`concepts/等價與觀察集.md` 已定案）。
而那正是 stack／queue 的 push 標籤說謊那次——**十八條護欄一條都不叫，學生第一眼看出來**。

⟹ 契約化之後，**render 會是唯一一路，它的 post 蓋不住它的真實風險**。

### ⚠️ 空洞為真的契約 ＝ 這個 repo 踩過五次的假綠

前置條件永遠不可滿足 ⟹ 後置條件恆真。這是形式化版本的假綠，
而形狀與今年九月那五次逐字相同（最近一次：整個 `main` 降級成 `raw_code`，
於是「沒有註解積木」與「註解在行末」同時為真）。

🟢 處方照抄：**每一條 pre 都要附一個滿足它的見證輸入**——
而那同時就是 §五 消掉 undecidable 的那個東西。**一件事付兩次帳。**

> **一份「全部證明通過」的報告，先問那些命題裡有幾條是空洞為真的。**

### 累積性那一欄，契約（布林謂詞）蓋不住

`concepts/等價與觀察集.md` §四 已經分好：

| | 結構性的差別 | 累積性的差別 |
|---|---|---|
| 該用 | 鄰域取樣（fuzz） | **界**（誤差上界、傳播分析） |

而文件註明「硬體／數位孿生進來時**第一個撐不住的就是這裡**」。
右欄的契約不是 `x > 0`，是 `|err| ≤ δ`——使用者說的「連續函數當導航員、
邏輯當守門人」在這一欄才有位置。

## 尚未表態的

- **PutPut 要不要**（§四）。傾向「明確地不要」，而沒有論證過。
- **`extract` 留不留**（§四）。目前判「留，記理由」，而理由是「不值得」不是「它對」。
- **形態那一維要不要有【人的 oracle】的機制**（§九）。今天是零——
  標籤說謊只能靠使用者看到。而它與 `認知鷹架`／`漸進揭露` 可能有關，沒查。
- **契約要不要進存檔**（§八 只說了證明不進）。契約是真實，照理要進，
  而它一旦進存檔就變成自由變數——**改一條 pre 就要遷移表**。沒想清楚。
- **三張登錄表那一列**（`concepts/元件.md` 待拍板）與本檔的 L1／L2 兩層有沒有關係。沒對過。
