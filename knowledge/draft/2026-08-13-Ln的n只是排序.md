# `Ln` 的 n 只是排序——而它假裝自己是一個維度

> 日期：2026-08-13
> 怎麼冒出來的：使用者說「**我覺得現在分 L 幾很沒有系統性，沒什麼根據，
> 然後 Ln 的 n 也沒有本質意義，除了排序之外**」。
> **狀態：問題，未決。** captured ≠ committed。

## 一、證據：同一層的節點沒有共同性質

`cpp-beginner.json` 的 `levelTree`（實測）：

```
L1a  函式與迴圈       L1b  控制流進階       L1c  型別系統
L2a  陣列與字串       L2b  指標與記憶體     L2c  結構與類別
L3a  STL 容器操作     L3b  OOP 進階         L3c  例外與進階
```

**「函式與迴圈」與「型別系統」都是 L1，而它們沒有任何共同的認知性質。**
`L1c` 只有 5 顆概念（`const`／`constexpr`／`auto`／`typedef`／`using`），
`L1a` 有 21 顆——**唯一的共同點是「都掛在 L0 底下」**。

所以 n 承載的只有一件事：**深度 = 前置關係的長度**。

⚠️ **而 `a/b/c` 後綴本身就是症狀**：它是為了在同一深度區分不同分支而加的。
**如果 n 真的是「認知層級」，同一層的東西就不需要用字母分開。**

## 三、三個候選，而③最誠實

| | n 的意思 | 檢驗方式 | 代價 |
|---|---|---|---|
| **① 前置深度** | 「學這個之前要先會 n 個東西」 | 從**概念之間的依賴**算出來 | ⚠️ 見 §四，護欄已經反駁過 |
| **② 認知負荷** | 「這一組同時要記幾個新東西」 | 概念數 ＋ 互相引用密度 | 是經驗值，不是推導 |
| **③ 就是課程順序** | 沒有本質，就是第 n 課 | 不用檢驗 | **誠實，但要改名** |

⚠️ **①與③不是對立的**（2026-08-13 補）：①答的是「n **怎麼算**」，
③答的是「n **叫什麼**」。兩個可以同時成立
——n 由邊算出來，而它的名字誠實地叫 `lesson`。

> **一個欄位叫 `level` 而實際上是 `order`，
> 會讓每個讀它的人以為那裡有一個理論。**

⚠️ 如果是③，那 `levelTree` 該叫 `curriculum`，`level` 該叫 `lesson`，
而**它與 [教材那份 draft](2026-08-12-漸進揭露把選項轉嫁給了老師.md) 的
`progression` 是同一個東西**——那時就不需要兩份清單。

## 四、⚠️ 而候選①已經被一條護欄預先反駁了

`tests/integration/audit-curriculum-coverage.test.ts` 的檔頭逐字：

> 「那是**一條教學漸進線**。『`vector` 屬於 L3a 而不是 L0』是人的判斷，
> **導不出來——導出它等於用演算法決定教學順序**。
>
> 所以工具箱全導出、課程清單**不導出**，判準同一條：
> **問「登錄表知道嗎」，不問「這是不是一份清單」。**」

**那條護欄已經想過「能不能算出來」並且否決了。** 而它的理由不是技術的，是：

> 「不檢測層級分得對不對（`vector` 該不該在 L3a）——**那是教學判斷**。」

⚠️ **所以①與那條護欄的立場衝突**，而衝突的點很精確：

- 護欄說：**成員**（哪顆概念在哪一關）是人的判斷，導不出來
- 而①想說：**深度**（n 是多少）可以從依賴算出來

**這兩件事不是同一件。** 一顆概念屬於哪一關是策展；而「這一關的概念需要哪些
前置」是事實。→ **①可能仍然成立，但它只能算 n，不能算成員。**

## 五、而更根本的分岔：「前置」有兩種

| | 例子 | 算得出來嗎 |
|---|---|---|
| **語法前置** | 用 `array_at` 之前必須先有 `array_declare` | ✅ 從 lift-pattern／執行器的依賴 |
| **教學前置** | 教 `pointer` 之前該先教 `array` | ❌ **教學判斷** |

⚠️ 而它們會打架：`switch` **語法上不需要 `if`**，但教學上一定先教 `if`。

> **一個只反映語法前置的 n，會在每一個「教學上該先教」的地方與直覺相反。**

→ 那可能意味著**需要兩個欄位**：一個算出來的（語法前置）、一個人寫的（教學順序）。
**而它們不一致的地方，正是教學設計的所在**——那些地方值得被看見，
而不是被一個混合的 n 抹平。

⚠️ 這與 `等價與觀察集` 的形狀相同：**算出來的是外延，人寫的是內涵，
而兩者不一致時要記對應，不要合併**。

## 五之二、⚠️ 「主觀但又不完全主觀」——先把主觀拆成兩種

使用者：「不論 n 是這三種哪一個，都沒有絕對標準答案，感覺都有主觀成分在，
**但是又不完全是主觀的**」。

| | 意思 | 處置 |
|---|---|---|
| **真的主觀** | 沒有事實可言（喜歡藍色還是綠色） | 記錄選擇，不必逼近 |
| **看起來主觀** | **有事實，但觀察太貴**，所以現在用判斷代替 | ⚠️ **可以逐步逼近** |

「教 `pointer` 之前該先教 `array`」屬於第二種——**它有答案**
（哪種順序讓學生學得比較好），只是那個觀察要教一學期、要對照組、要夠多學生。

> **主觀性不是來自「沒有事實」，是來自「觀察太貴」。**

而 `concepts/等價與觀察集.md` 的第一句正是這個結構：

> 「『這兩個東西一樣嗎』——**沒有無條件的答案**。答案取決於**你允許誰去看**、
> **要求多準**、以及**多久能對一次答案**。」

→ 而「觀察太貴」那一類的處置，正好是
[一致是量出來的不是保證的](2026-08-12-一致是量出來的不是保證的.md)
那條原則的適用對象：**一次次回饋慢慢逼近**。

## 五之三、回到第一性原理：n 是投影，真實是一張圖

根公理是「唯一真實，各式投影」。所以要問：**n 是真實還是投影？**

```
真實   一張概念關係圖，邊有多種：
         語法前置    array_at 需要 array_declare      ← 可算
         教學前置    pointer 之前先 array             ← 經驗，可修訂
         同族        push／pop／size 是一組            ← 等價類，可算

投影   n = 在【某組邊】上、用【某個排序準則】走出來的深度
```

**這一刀把主觀的部分隔離成兩個明確的宣告**：**哪些邊算數**、**什麼排序準則**。
其餘全部是算出來的。

> **主觀的東西不會消失，但它可以被搬到一個地方
> ——而那個地方是可以被討論、被否證、被版本控制的。**

⚠️ 而今天的 `levelTree` 是相反的：**主觀性散在 175 顆概念的每一個歸屬判斷裡**，
所以沒有人能討論它——**你只能整棵接受或整棵重寫**。

### 這個形狀這個專案已經用過兩次

- [圖解形態與資料結構圖鑑](2026-08-05-圖解形態與資料結構圖鑑.md)：
  「**一個抽象元件 = 某個容差底下的等價類。名字、解釋、容差是人寫的；成員不是。**」
- [等價與觀察集](../concepts/等價與觀察集.md)：內涵是宣告（人寫），外延是量測（算的）

**套到 n：邊與準則是人寫的；n 是算的。**

### 而它解掉 §四 那條護欄的擔憂

護欄說「導出它等於**用演算法決定教學順序**」——而在這個形狀下，
**演算法沒有決定教學順序，它只是執行了人宣告的邊**。
教學判斷仍然在人手上，只是**被寫成邊而不是寫成歸屬**。

⚠️ 而 §五 的兩種前置衝突（`switch` 語法上不需要 `if`，教學上必須）
在圖裡是**兩條不同的邊**——**它們不一致的地方正是教學設計的所在**，
值得被看見而不是被一個混合的 n 抹平。

## 五之四、⚠️ 判準：算出來之後，有沒有人會因此改變決定

這個方向有一個立刻的成本：**要為 175 顆概念宣告邊**，而那比宣告「屬於哪一關」
更多工（一顆概念可能有 3 條邊，但只有 1 個關卡）。

⚠️ **除非邊可以部分算出來**：語法前置那一種可以從 lift-pattern 或執行器的依賴推。
所以人要寫的只有**教學前置**，而它只在「與語法不一致時」才需要寫。

而判斷這整件事值不值得做的判準是：

> **一個東西該不該被算出來，看的不是「算不算得出來」，
> 是「算出來之後有沒有人會因此改變決定」。**

**如果宣告了邊之後，排課的方式不會改變，那條邊就不值得存在。**

→ 所以驗證這個方向最便宜的實驗是：**先為 L0 與 L1a 那 40 顆概念宣告邊，
看算出來的 n 與今天的 `levelTree` 差在哪**。
⚠️ 差異為零 → 這整套沒有回報；差異很大 → 那些差異本身就是發現。

## 五之五、⚠️ 實驗做了（2026-08-13），而它推翻了前三個候選

§五之四 說的 40 顆實驗（L0 ＋ L1a）做了。**人列 40 條前置邊**
（判準：`X requires Y ⟺ 一個只用 X 而不用 Y 的合法程式不存在`），
然後算兩件事。

### 結果①：深度不能當 n——候選①直接被否證

```
L0   內含的深度：[0, 1, 2, 3]
L1a  內含的深度：[0, 1, 2, 3]
```

`func_def` 深度 0 卻在 L1a；`if_else` 深度 3 卻在 L0。
**一個關卡橫跨所有深度**——所以 n 不是「前置深度」。

### 結果②：🔴 一個真的破洞

```
array_assign  在 L1a       而它需要 array_declare
array_declare 在 L2a       ← 更後面的關卡
```

**一個 L1a 的學生拿得到「設定陣列元素」的積木，卻拿不到「宣告陣列」的積木。**

⚠️ 而它是**單獨一個關卡的問題**，不是「兩個湊起來壞了」：
`L0` 自己完整，`L1a` 自己不完整。

### 結果③：L0 = 必需集合 ＋ 一圈「免費的」

「必需集合」＝ 把前置遞迴拉進來（圖論的**傳遞閉包**，
⚠️ **與拓撲學的閉包不是同一個東西**，只是同名）：

```
必需({print, if, loop_while})  =  6 顆
實際的 L0                       = 19 顆
                                  ────
多出來的                          13 顆
```

而那 13 顆有一個一致的性質——**它們的前置全部已經在那 6 顆裡**
（`arithmetic`／`endl`／`if_else`／`logic`／`negate`／`literal_string`／
`var_declare` 那一組）。

> **它們不是必需的，但加進來不需要再拉任何新東西——「免費的鄰居」。**

### 所以一課的範圍有兩個界，而它們用兩個不同的量

| | 圖論上是什麼 | 給什麼 |
|---|---|---|
| **下界** | 目標的傳遞閉包 | 不能再少——少了跑不起來 |
| **上界** | 「前置已滿足」的那一圈 | 再多就要拉新前置 |

**而在那個區間裡選多大，是教學判斷。**

⚠️ **這比「n = 第 n 個閉包」準確**：L0 不是最小必需集合（那只有 6 顆），
它是必需集合**再擴一圈**。

### 而 `a/b/c` 後綴終於有解釋了

```
L1a  往「函式與迴圈」方向擴一步
L1b  往「控制流進階」方向擴一步
L1c  往「型別系統」方向擴一步
```

它們同為 L1 不是因為難度相同，是因為**距離 L0 都是一步**。

> **n 是步數，字母是方向——而它今天被寫成一個看起來像難度的數字。**

**那可能就是「沒有本質意義」的來源**：n 有意義（步數），
只是那個意義沒有被說出來，而它看起來像難度。

### ⚠️ 而模型答不了的部分，該留給人

`math_pow`／`random_next` 那些在 L1a，而它們的前置只有 `include` 與
`literal_number`——**它們距離 L0 也只有一步**。那為什麼不在 L0？

答案是「教學上不急」——**那是純粹的主觀，而且該是主觀**。

> **模型不消滅判斷，它把判斷從「175 個歸屬決定」壓縮成
> 「幾個目標 ＋ 幾個步數 ＋ 一些例外」。**

### ⚠️ 一個方法論的教訓（同一次對話）

我在解釋這個模型時把它形式化成拓撲學（Alexandrov 拓撲、開集、內部、
連續映射）。使用者的判斷：

> 「只用圖論語言，不要用拓撲語言，**這樣過度抽象，沒有任何解釋力**」

而用本檔自己的判準檢查，那個判斷是對的——三個拓撲操作
（`int(A)`／開集併封閉／T0 分離）**用圖論講一樣清楚，甚至更清楚**，
它們只換了名字，沒有換來新操作。

> **一個抽象如果只是換個名字，它沒有剪枝力。**

⚠️ 留一句話當註腳而不是刪掉：**若哪天要問「跨語言的關卡對齊」**
（C++ 的一個關卡對映到 Python 之後還是不是關卡），那時
「保結構的映射」會變成反覆要問的問題，**那才是形式化開始付租金的時候**。
今天只有一個語言，那個問題不存在。

## 五之六、⚠️ 「拓撲排序」不是答案——它是同一個病的另一條線（2026-08-14）

使用者：「**我現在很想把 Level 拿掉，變成類似拓撲排序那樣，或是有更自然的認知方式。**」

🔴 **拓撲排序給的是一條線**，而 §五之五 已經否證過相近的東西：

```
L0   內含的深度：[0, 1, 2, 3]
L1a  內含的深度：[0, 1, 2, 3]
```

而更根本的理由是 2026-08-14 那條 `experience`：
**讀的人手上是一個集合，集合壓不進一條數線。**
換掉編號但保留線性，病沒好——只是換了一條線。

### 而要的東西在拓撲排序【底下】

一個 DAG 有**很多個**合法的線性化。所以：

```
真實   概念之間的邊（偏序）    ← 唯一
投影   任何一個線性化          ← 各式
```

**這就是根公理。** `level` 的錯不是它存在，是它今天**被當成真實**（§五之三）。

⚠️ 而現成的證據：`topics/` 底下**已經有兩棵樹**（`cpp-beginner`／`cpp-competitive`）。
今天它們是兩份各自手維護的清單；在這個模型下它們是**同一張圖的兩個排序準則**。

## 五之七、🔴 所以 `level` 這個欄位最後長什麼樣——拆成三件事

> 本檔問了「n 是什麼」，但一直沒回答「那**欄位**最後變成什麼」。

今天 `L2a` 這個節點**同時扛三件事，而它們是同一個欄位**：

| 今天扛的 | 之後 | 誰決定 |
|---|---|---|
| **成員**（哪些概念屬於它） | 兩個界之間（§五之五 的下界／上界） | **算的**；人只宣告「這課的目標是能寫出 XXX」 |
| **順序**（在 L1a 之後） | 圖的一個線性化——**可以有很多份** | 人選排序準則 |
| **名字**（「陣列與字串」） | 從**主題**變成**能力**：「學完能寫出 XXX」 | 人寫，而它因此**可驗收** |
| **數字 `n`** | 🔴 **不存了** | 它已經有解釋（步數，§五之五），**有解釋的東西可以算，不必存** |

### 而「一個學生是 L2 等級」這句話會消失

```
今天    student.level   = 2            一個點
之後    student.reached = {…概念…}     一個集合
```

**P4 的「可見集合」本來就要一個集合**，`level` 只是它的一個有損壓縮。
（判準見 `experience`「一個座標可以描述節點，不代表它描述得了走到這裡的人」。）

### ⚠️ 字串 `"L2a"` 大概還會在 JSON 裡，但它變成 ID 不是宣稱

就像 `cpp:vector_declare` 不宣稱任何東西。而按 §三 的判準
（「一個欄位叫 `level` 而實際上是 `order`，會讓每個讀它的人以為那裡有一個理論」），
**要改名**。`lesson`／`unit` 都行，重點是不叫 `level`。

## 五之八、而「好不好」現在量得出來——語料已經在了

`tests/probes/scenario-coverage.test.ts` 有 **53 段真實程式**
（競賽 25／APCS 18／Arduino 10，見 [history/057](../history/057-缺陷清單只包含被記下來的缺陷.md)）。
每一段用到一個概念集合，所以可以直接算：

## 五之九、🔴 §七 的排期判定要翻案

§七 緩做的決定性理由逐字：

> 「**修一個沒有人在用的東西，改善不會兌現。**」

**那句話 2026-08-14 不成立了**——三個消費者出現了：

```
① 診斷訊息的可用詞彙集     ← 2026-08-14 新增，§七 判定時不存在
② 兩棵課程樹               ← 已存在，今天各自手維護
③ 缺陷的嚴重性排序         ← experience 那條已經在用 levelTree
```

⚠️ **但這不等於「現在重構」**。③ 最近，而它只需要這套機制的**一小塊**
（給定一組概念，算傳遞閉包）——**不需要重建 `levelTree`**。

> **很可能的路徑：診斷先用掉那塊計算，等它證明自己能跑，
> 重構才有一個已經驗證過的地基。**

### 而最小實驗比 §五之五 那次更便宜

§五之四 說語法前置**可以部分算出來**，而**那一步今天還沒做過**。

> 先從 `lift-pattern` 與執行器的依賴**自動抽一版邊**，
> 跟 §五之五 人列的那 40 條對照。
> **重合的不必再人工列；差異的就是「教學前置 ≠ 語法前置」的所在。**

⚠️ 那個差集本身就是產出——§五 說要兩個欄位，而**差集正是第二個欄位的內容**，
不必憑空寫 175 顆。

⚠️ **方法論的自我約束**（§五之五 末尾那條教訓）：本節只用圖論，
而每一步都對應一個**能跑的計算**（傳遞閉包、線性化、差集、53 段的命中數）。
**如果哪一步只是換名字沒換操作，它就該被刪掉。**

## 七、排期：現在不重構，而「等」需要一個會響的條件（2026-08-13 決）

使用者問「現在有沒有必要重構 Level，還是等以後也不遲」。三條判準過完的結論是**等**：

| 判準 | 結果 |
|---|---|
| `experience.md`「成本會隨推遲增加嗎」 | **只有「列前置邊」會漲價**——`levelTree` 只有 10 個節點，改結構與改名都不會 |
| §五之四「算出來之後有人會因此改變決定嗎」 | ❌ **今天不會**——關卡制被全打勾繞過（見姊妹 draft） |
| `build-guardrail` 6.5「別為了修一筆而先做重構」 | 破洞單獨修掉，**不搭重構的便車** |

第二條是決定性的：

> **修一個沒有人在用的東西，改善不會兌現。**

所以順序是 **教材（`progression`）→ 然後才是 `levelTree` 的重構**，
而反過來做的話第二步收益是零。

### ⚠️ 而「等」必須有觸發條件，否則它會變成永遠

（`元件套件管理` 連十二輪標熟而未升格——理由早就失效了，項目還留在原地。）

```
① Python 的第一顆概念進來    → 那時要建第二棵 levelTree，模型的價值翻倍
② progression 有了第一課      → 那時關卡制真的被用，重構的收益開始兌現
```

⚠️ **①比較急**：那時如果還沒有模型，就會憑感覺再建一棵，
然後**有兩棵都沒有根據的樹**——而它們之間還會互相參照。
