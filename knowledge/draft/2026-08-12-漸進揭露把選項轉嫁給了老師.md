# 漸進揭露把選項轉嫁給了老師——一個來自教室的否證

> 日期：2026-08-12
> 怎麼冒出來的：談硬體與 VSCode 的架構邊界時，使用者補了一句教學視圖，
> 然後說出**實際運作時他怎麼用漸進揭露**——而那個做法否證了機制的前提。

## 使用者的原話（兩段，第二段是關鍵）

> 「教學內容才會真正讓漸進揭露有實際用處，不然漸進揭露反而會成為一鍵開啟這個
> 工具的時候很麻煩的一件事，還要手動把那些東西打勾，然後我實際在運作的時候
> **我會乾脆叫學生把全部都打勾，那有沒有這個漸進揭露是沒用的**」

> 「在現在沒有教學內容的時候，我通常會這樣做：先讓學生用全部打勾的基本的，
> 然後讓學生打一個勾的，然後全勾的，因為我覺得在沒有教材輔助的前提下，
> **要想哪一個需要被打勾其實選擇太多，會選擇障礙**」

## 兩個機制，而它們不同

| | 症狀 | 老師的**理性**反應 |
|---|---|---|
| **① 收益不可見** | 打勾的好處看不到，成本（設定）看得到 | 「反正都給他們用」 |
| **② 選項太多** | **9 個可選節點 = 512 種組合**，而沒有依據 | **找一條不用想的規則** |

②的數字是實測（`cpp-beginner.json` 的 `levelTree`）：

```
L0（19 顆概念）
  L1a（21）→ L2a（38）→ L3a（27）
  L1b（17）→ L2b（15）
             L2c（17）→ L3b（7）、L3c（10）
  L1c（5）
可選節點 9 → 2^9 = 512 種組合
```

**使用者的三階段（基礎全開 → 讓學生自己勾一個 → 全開）就是那條不用想的規則。**
不是偷懶——是在一個沒有預設路徑的空間裡，用最低認知成本走出一條可重複的路。

## ⚠️ 而這是「機制有了沒人接上」的**第十種形狀**

`concepts/執行機構.md` 已有九個實例，而**前九個都是「沒有人呼叫」**
（grep 得到、零呼叫者、空樁）。這一個不同：

> **機制接上了、每天都在跑，而使用它的人有動機繞過它。**

> **一個機制如果它的成本由 A 付、收益由 B 得，A 就會找到繞過它的路
> ——而那不是 A 的錯。**

⚠️ 它比前九個難發現：那九個是零呼叫者（工具看得到），這一個**每天都在執行，
只是永遠全開**。程式碼看起來完全健康，護欄一條都不會紅。

## 教材的角色，講精確一點

不只是「讓收益可見」：

```
關卡樹  =  一個 512 條路徑的空間
教材    =  那個空間裡一條【已經有人走過並驗證】的路徑
```

而**使用者的三階段就是第一條已驗證的路徑**——它已經存在，只是存在他腦裡
而不在 `cpp-beginner.json` 裡。

| | 今天 | 該有的 |
|---|---|---|
| 老師看到的 | 一份要打勾的積木清單 | 一份**教材** |
| 打勾的意思 | 「不給學生用這些」 | 「這節課教這個」 |
| 不打勾的代價 | 沒有 | **失去那一課的講解、圖解、練習** |

**它同時解掉①和②**：讓打勾變成選課（收益可見），也讓 512 降到 1（選項減少）。

## `progression` 的草稿——⚠️ 而它現在不進產品 JSON

原本的計畫是把三階段寫成 `cpp-beginner.json` 的一個 `progression` 欄位
（純資料，不寫程式）。**而那會踩到這個專案的頭號病**：`Topic` 這個型別今天有
**10+ 個消費者含一條護欄**，加一個沒有人讀的欄位就是第十一個「機制有了沒人接上」。

> **一個為了「先卡位」而加的欄位，與一個沒接上的機制，在程式碼裡長得一樣。**

所以草稿留在這裡：

```jsonc
// cpp-beginner.json 的第二層（草稿，未落地）
"progression": [
  { "lesson": 1, "levels": ["L0"],
    "why": "先讓學生用全部打勾的基本的——輸出、變數、條件、迴圈一次到位，
            因為這一組彼此需要（印東西要有變數、迴圈要有條件）",
    "teach": "…", "practice": "…" },
  { "lesson": 2, "levels": ["L0", "?"],
    "why": "讓學生自己挑一個加進來——**選擇本身是學習**，
            而範圍已經被縮到 3 個候選（L1a／L1b／L1c）",
    "teach": "…", "practice": "…" },
  { "lesson": 3, "levels": ["*"],
    "why": "全開。這時學生已經有心智模型，工具箱的長度不再是障礙",
    "teach": "…", "practice": "…" }
]
```

⚠️ **注意第 2 課**：使用者的做法是「讓**學生**打一個勾」——那與「老師選」不同。
**選擇權被下放給學生，而範圍被縮到 3 個。** 那本身可能是一個教學設計，
不只是省事——值得問一句是不是刻意的。

### 它進產品 JSON 的條件

**要有一個消費者**。最小的消費者是：介面上一個「照教材走」的模式
——載入 topic 時預設套用 `progression[0]`，而不是套用全部。

在那之前它留在這裡。

## 還沒問的

- **教材的粒度**：一課一個 `progression` 項目，還是一課多個 checkpoint？
- **教學內容住哪**：元件說明（膠囊）與課程敘事（Topic）是**兩份不同的東西**
  ——前者答「`for` 是什麼」，後者答「為什麼現在教 `for`」
- **第 2 課讓學生自選**是刻意的教學設計，還是省事？答案不同，`progression` 的
  形狀就不同（要不要支援「這一課的可選集合」）

## ⚠️ 姊妹問題：`Ln` 的 n 本身也沒有根據（2026-08-13）

本檔問的是「關卡制**被繞過**」；而使用者隔天說
「**分 L 幾很沒有系統性，Ln 的 n 除了排序之外沒有本質意義**」
——那問的是「關卡的**分法本身**沒有根據」。

**兩份指向同一件事：`levelTree` 需要重新設計。而順序有意義：**

> **先答「n 是什麼」，才知道 `progression` 該長什麼樣。**
> 如果 n 本來就是課程順序，那兩者是同一個東西，**不該有兩份清單**。

見 [Ln 的 n 只是排序](2026-08-13-Ln的n只是排序.md)。
