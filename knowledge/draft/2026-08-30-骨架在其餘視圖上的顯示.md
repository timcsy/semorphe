# 骨架在其餘視圖上的顯示——而流程視圖今天是一句謊話

> 日期：2026-08-30
> 怎麼冒出來的：使用者 2026-08-28 在接鷹架控制項時說
> 「**我想說程式碼的部分還是要顯示完整，但是其他視圖可以有相對應的顯示，
> 可能要做更多的設計**」——而那句話當時沒有被捕捉，做完的只有積木那一側。
>
> **狀態：已升格**（2026-08-30，人拍板「做完」）→ vision 路線圖。
> 本檔留作**在建的設計理由**，做完才反流退場。

## 一、量出來的現況（`/knowie-next` 對著程式碼查的）

```
grep -rn "ghost|scaffold" src/ui/panels/flow-panel.ts src/core/flow/*.ts   →  0 筆
```

實測三個模式在流程視圖上：

```
hidden    include · using_namespace · func_def · print · literal_string · endl · return · literal_number
ghost     （逐字相同）
editable  （逐字相同）
```

🔴 **連 `hidden` 都照樣把整組骨架畫出來**——那個模式在這裡是一句謊話。
而 console **零筆錯誤**：它不是壞掉，是從來沒做過。

## 二、🔴 而這是同一個形狀的第二次

2026-08-28 使用者說「淡的好像失效了」，查下去是**積木側從來沒實作過** `ghost`。
兩天後同一句話在流程視圖上一字不改地成立。

> **一個模式如果在某個視圖上與另一個模式長得一樣，
> 那個視圖就沒有實作它——而選單仍然讓人選得到。**

⚠️ 所以這一刀的產物**不只是流程視圖**，還要有一條護欄
——否則第三個視圖進來的那天會有第三次。

## 三、三個模式在流程視圖上各該長什麼樣

| 模式 | 積木側（已做） | 流程側（這一刀） | 判準 |
|---|---|---|---|
| `hidden` | 剝掉，畫布上沒有 | **同樣剝掉** | 「只留你自己的邏輯」跨視圖同一句話 |
| `ghost` | 淡的 ＋ 拖不動 ＋ 學生的積木插得進去 | 淡的 ＋ **拖得動，而接法鎖著** | 「看得到、拆不壞」 |
| `editable` | 全部可編輯 | 不變 | — |

🔴 **而 `ghost` 在流程視圖上不是積木的翻版**（2026-08-30 使用者更正）：

> 「我是希望**淡的還是能移動**，只不過**彼此關係不能變**」

```
積木視圖   位置【就是】結構——拖一塊積木會改變程式
流程視圖   位置只是【排版】——拖一顆節點程式一個字都不會變（存進 flowLayout）
```

> **同一句「不能動」，在兩個視圖上禁的不是同一件事。**

所以流程視圖鎖的是 `commitWire`（關係），而**拖曳照樣可以**。
判準是「**被搬的那一顆**是不是骨架」——學生接**進**骨架合法。

## 四、機制：骨架是**真相的一個性質**，不是某個面板的功能

今天積木那側是**組裝點直接呼叫面板**（`app.markScaffoldBlocks(...)`），
而那一筆算在第三十九條的「直接呼叫視圖」裡（基線 21）。

🟢 正解是走匯流排：`SemanticUpdateEvent` 帶上

```ts
scaffold?: { nodeIds: string[]; mode: 'hidden' | 'ghost' | 'editable' }
```

**每個視圖自己決定怎麼畫**——那正是「唯一真實，各式投影」：
真相說「這幾顆是骨架」，投影決定它長什麼樣。

⚠️ 而**積木那側先不搬**（它已經會動了，搬它是另一次重構的風險）。
這一刀只讓流程視圖走新的路，並把「積木側也該搬過來」記成一筆債。

## 五、明確不做

- **積木側改走匯流排**——留成債，理由見上
- `history/189` 尾巴那條（`preamble` 混了「約定」與「慣例」）
- Arduino 空 sketch 不會自己長出 `setup`／`loop`
- 程式碼視圖：它**已經有** `.ghost-line`，而且使用者說過「程式碼要顯示完整」
