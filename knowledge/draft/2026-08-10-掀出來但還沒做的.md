## 一、`block-registrar.ts` 有十二對 `plus_`／`minus_`，落成三個家族

2026-08-10 實測（`src/ui/block-registrar.ts`）：

| 家族 | 積木 | 加什麼 |
|---|---|---|
| **A 參數列** | `u_func_def`、`c_forward_decl` | dummy input ＋ 型別下拉 ＋（名字輸入） |
| **B 運算式列** | `u_print`、`u_func_call`、`u_func_call_expr`、`u_var_declare`、`u_if` | value input |
| **C 變數選擇列** | `u_input`、`u_input_expr`、`c_printf`、`c_scanf`、`c_scanf_expr` | `SEL_n` 欄位 |

### A **已經是兩份拷貝，而且已經漂移**

| 方法 | 相似度 |
|---|---|
| `loadExtraState` | **100%** |
| `minusParam_` | 96% |
| `saveExtraState` | 92% |
| `plusParam_` | 89% |
| `rebuildParamLabels_` | 33% |

三個變異點**全部是資料不是邏輯**：

1. **要不要名字欄位**——`int a` vs `int f(int, int);` ⇒ 一個布林
2. **括號的標籤**——⚠️ **`c_forward_decl` 的括號沒有走 i18n**（寫死 `"("`／`")"`），
   而 `u_func_def` 走 `Blockly.Msg`。**那是抄過去時漏掉的，不是設計**
3. **插在哪個 input 之前**（`'BODY'` vs `'PARAMS_END'`）

`rebuildParamLabels_` 那 33% 有一半是**假的差異**——分支順序調換、中間變數內聯。
那是抄完之後各自微調留下的漂移。

> **抽出工廠不是為了讓 lambda 好升級，是因為它已經重複了。**
> 而重複的兩份已經開始漂移——i18n 那筆就是證據。
> 判準是 `history/033` 的那條：**重做時會不會漏掉上次學到的東西**。抄的時候就漏了。

### 未決

- **A 抽（2 → 1）是確定該做的**，B（5 份）與 C（5 份）收益更大但動作也更大
- **lambda 那六顆要不要從文字欄位升級成 A**，仍然是**教學決定**。
  抽出工廠之後成本從「82 行 × 6」降到「六行宣告」，
  **但成本降低不構成該做的理由**——判準仍是 `specs/105` 寫下的三個訊號

## 二、積木型別與元件身分是**兩份會漂移的命名**

2026-08-10 實測：

```
186 顆積木型別：  c_ 92 ｜ cpp_ 67 ｜ u_ 27
id 與 blockDef.type 相同 120 顆，**不同 66 顆**

  cpp:stack_peek     →  blockDef.type = cpp_stack_top      ← 名字本身不同
  cpp:char_is_alpha  →  blockDef.type = cpp_isalpha
```

那 66 顆是 **G 改了身分而積木型別沒跟上**留下的。

### 而前綴本身也是化石

`u_`／`c_`／`cpp_` 對應「universal / cpp core / cpp std」，
而 **D 之後 177 顆身分全部是 `cpp:`**——那個三分法在身分層已經不存在。

它與概念宣告的 `layer` 欄位是**兩份分類，而邊界不一樣**：

```
u_ 前綴          27 顆
layer: universal  29 顆
```

差 2 顆。**那個差就是雙重真相在漂移的證據。**

### ⚠️ 改積木型別名 = 一次存檔遷移

`SavedState` 存 `{ tree, blocklyState, code, … }`，而載入時
**`blocklyState` 是主要來源**（`app.ts:566` 先 `setState`，再「generate code from
restored blocks」）。`blocklyState` 裡每顆積木帶著 `type: "u_if"`。

> G 那條「**趁還沒有版本的時候改名是免費的**」**在這裡不適用**
> ——`blocklyState` 已經在 v9 的版本鏈裡了（`storage-version.ts` 的 upgrade
> 有 `blocklyState` 欄位）。

### 未決（而我有一個明確的建議）

「刪掉 `u_` 還是改名」有第三個答案：**讓積木型別從 conceptId 導出**
（`cpp:stack_peek` → `cpp_stack_peek`），一個名字而不是兩個。
那正是第一顆膠囊已經在做的事（`forms/blocks.json` 的 `id` 就是 conceptId）。

> **但不要現在單獨做。** 它會與 F（膠囊搬家）撞在一起——每顆元件搬進膠囊時
> 本來就要碰它的 `forms/`。**兩件事合成一次做，遷移只付一次**；
> 分開做要付兩次，而且中間那段時間有一半元件是新名一半是舊名。
