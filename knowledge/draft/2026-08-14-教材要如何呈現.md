## 一、元件與教材：是**內涵與外延**的關係

一課裡有四樣東西，而它們的性質完全不同：

```
目標    「學完你能寫出 XXX」     人寫    ← 內涵
概念    這一課引入哪些           算的    ← 外延
說明    為什麼、怎麼用           人寫
練習    做什麼                  人寫，而【可驗證】
```

「概念集合是算的」不是新發明——[`Ln` 的 n](2026-08-13-Ln的n只是排序.md) §五之五
的 40 顆實驗已經量出兩個界（下界＝傳遞閉包／上界＝前置已滿足的那一圈），
**而在區間裡選多大是教學判斷**。

> **教材宣告目標，元件集合是它的外延。**

⚠️ **而今天是反過來的**：`topics/*.json` 把 175 顆概念**逐一列舉**在關卡裡
——175 個歸屬判斷，而它們沒有一個說得出理由。
改成「宣告目標」之後，主觀性壓縮成「幾個目標 ＋ 幾個例外」。

🔴 **而元件不該知道教材**——今天也確實不知道（`component.json` 沒有課程欄位）。
**這個方向是對的，不要破壞它。**

## 二、一課的單位**不是段落，是「請注意這裡」**

```
一般教材   「輸入這段程式碼」                 學生只看到文字
這裡       「看程式碼第 4 行 → 現在看積木那顆
             → 按執行，看變數怎麼變」          同一個節點，三個投影同時亮
```

**一般教材的單位在這裡是浪費的**——這個產品的整個論點就是同一件事有多個投影。

🔴 **而那個機制已經存在**：`execution:at-node` 廣播一個 `nodeId`，
每個視圖自己決定怎麼亮。

⚠️ **而它不該直接重用那個通道**——那是「執行走到哪裡」，教材要的是「請看這裡」。
**同一個形狀，不同的通道。**
（[history/062](../history/062-把使用者的錯歸進了我們的殘差.md)：
殘差與診斷共用一個通道，剛翻過車。）

## 三、目標檢查：用**輸出**，不要用**樹**

```
太嚴   樹要一模一樣        只有一種寫法算對 —— 那是【錯的教學】
太鬆   有沒有寫東西        沒有意義
🟢     執行的輸出對不對     而直譯器【已經在跑】
```

[等價與觀察集](../concepts/等價與觀察集.md) 開頭逐字：

> 「『這兩個東西一樣嗎』——**沒有無條件的答案**。
> 答案取決於你允許誰去看、要求多準。」

> **一課的目標檢查，就是選一個 ε。**
> 而輸出是最便宜、最不武斷的那一個——它讓學生用任何寫法達成都算對。

⚠️ **明確的邊界**：這個 ε **教不出「寫法好不好」**
（「用迴圈而不是複製三次」）。那需要另一種 ε，**第一課不要碰**。

## 四、一課 = **一個資料夾**

```
lessons/<課名>/
  lesson.md      說明（人寫）
  start.json     起始狀態——就是一份存檔，載入機制現成
  goal.txt       期望的輸出
```

**這是這個專案自己的形狀。** `src/core/component/registry.ts` 檔頭逐字：

> 「**碎裂的痛不在「碰幾個檔」，在碰幾個既有的共用檔。**
> 掃描之後，加一顆元件 ＝ **新增一個資料夾，零編輯**。」

🔴 **而這正是 `levelTree` 死掉的方式的反面**——它把 175 個歸屬判斷寫進共用 JSON，
於是**沒有人能加一課而不動別人的東西**。

**加一課 ＝ 新增一個資料夾，零編輯。**

⚠️ 而這一條**與課的內容無關**，是四點裡**唯一不依賴猜測**的。

## 五、螢幕上放哪（未決）

```
覆蓋層   ❌ 學生要【同時】看到教材與工作區
底部     🟡 已有 console／variables 分頁，而散文需要高度
側邊     🟢 可收合，而它與積木／程式碼是並排的第三個投影
```

⚠️ 而側邊欄的代價是**橫向空間**（積木本來就寬）——**那要實測，不能推**。

## 六、🔴 一條現在就該記下的界線

> **教材可以「請求」（發一個「請看這裡」），
> 但不可以「持有」（存自己的一份程式狀態）。**

一旦教材存了自己的樹，它就變成**第二個真相來源**——而根公理是
「唯一真實，各式投影」。

⚠️ **那條線在寫第一課時不會痛，在做面板時會很痛。**

---

## 七、而圖鑑是**材料**，不是教材的一段

```
教材   線性、有順序、有目標    「接下來做這個」      引導
圖鑑   隨機、可查、沒有順序    「這個東西是什麼」    參考
```

**兩種模式的失敗方式相反**：教材塞太多參考會失去節奏；
圖鑑排出順序會變成一本讀不完的書。

⚠️ 而這有一個實際後果：

```
圖鑑   從既有宣告【導出】（標籤／tooltip／形態／requires 都在膠囊裡）
       → 它是唯一可以【先做】的機制，因為它不是猜的
教材   必須手寫，而且【猜不出來】要什麼面板
```

**而我仍然建議先寫課**——理由不是成本，是
**一份沒有課的圖鑑，不知道每一顆該講多深**。

（[圖解形態與資料結構圖鑑](2026-08-05-圖解形態與資料結構圖鑑.md) 逐字：
「一個抽象概念 ＝ 某個容差底下的等價類。**名字、解釋、容差是人寫的；成員不是。**」
套到圖鑑：分類與解釋是人寫的，成員是算的——而人寫的那一半要有課才知道寫什麼。）

## 八、⚠️ 而上面有三點是【猜的】

```
① 一課的單位是「指節點」   ← 而學生可能根本不需要被指，他自己找得到
② 目標檢查用輸出          ← 而學生可能卡在打不出那段程式，根本沒到檢查
③ 一課是一個資料夾        ← 🟢 這一條不依賴猜測
```

> **一課寫完之後，①②哪個先做會自己浮出來——而那時它不是猜的。**

## 出口條件

- **第一課寫出來（純 markdown 就好）** → ①②從猜測變成觀察；
  ⚠️ 而**撞到的每一個坑就是面板需求的第一手資料**——那份資料今天**一筆都沒有**
- **有人照著它走完一次** → 目標檢查的 ε 選得對不對第一次被檢驗
- **圖鑑做了** → 「分類與解釋」那一半有沒有被課決定

## 九、🔴 第一課走完了，而它撞到的第一件事是產品的核心宣稱

（2026-08-14，spec `124`。完整清單在 `specs/124-first-lesson/findings.md`。）

```
打上 int main() { return 0; }  → 按同步 → 積木數 = 0
再加一行 cout                   → 積木 = [print, literal_string, endl]
                                  🔴 沒有 main、沒有 return
```

**積木側只呈現【語句】，骨架不呈現。** 而那是刻意的設計。

⚠️ **但它讓「同一個程式的兩種樣子」這句話在第一課的第一步就不完全成立**
——程式碼側有 `main`，積木側沒有。

> **第一課撞到最核心的宣稱，不是巧合——第一課本來就會撞到最基本的東西。**

**課本的處置**：`main` 不當第一個概念教，改成「先照抄的骨架」，
而「兩種樣子」延到第二步（那時積木真的出現）。

### 而這一輪【沒有】暴露面板需求

⚠️ 走一次只暴露了**說明的缺陷**（第一步寫錯、沒說輸出在哪裡）。
**「需要一個教材面板」一次都沒有浮出來。**

> **而那本身是資訊**：§八 猜的那兩點（指節點／輸出檢查），
> **第一課一條都用不上**。

🔴 **要暴露面板需求，需要的是【第二個人】走一遍**——
而 `findings.md` 已經標了四處「我因為知道答案而跳過的地方」。

## 出口條件（第九節新增）

- **第二個人走過一遍** → 面板需求第一次有非作者的資料
- **`main` 不在 L0** 那條被處理 → 見 [`Ln` 的 n](2026-08-13-Ln的n只是排序.md) 的出口條件
- ⚠️ **在那之前不要做教材面板**——今天的證據**只指向說明，不指向工具**

## 十、🔴 使用者走過一遍了——而回饋的【性質】比內容重要

> 逐字：「我走過一遍了，**OK**，不過如果可以有**圖片支援**更好，
> 或是到時候如果直接跟 UI 結合，可能可以**直接用指的**」

```
「OK」          ✅ 一次都沒有真正卡住——課走得完
圖片支援        增益，而【我完全沒預測到】（本檔八節一次都沒提）
直接用指的      增益 ＋ 未來式，而它命中了 §二 那個【被標為猜測】的設計
```

### ⚠️ 而兩個回饋都是「更好」，不是「走不下去」

> **一個「更好」與一個「走不下去」，在待辦清單上長得一樣，
> 而它們的優先序差一個數量級。**

🔴 **所以這不構成「該做教材面板了」的證據。**
它構成的是：**做了會更好，而它今天仍然不是瓶頸。**

### 而「用指的」被獨立提出，證明的是什麼

§八 把「指節點」標為猜的（「學生可能根本不需要被指」）。
使用者獨立提出了同一件事——

> **一個猜測被獨立提出，證明的是它【想得到】，不是它【必要】。**

### 🆕 而圖片是最便宜的那一個

```
lessons/<課名>/images/…     不影響任何既有檔案，markdown 語法就夠
```

**三個候選裡唯一今天就能做、零風險、而且是使用者主動提的。**
⚠️ 而它**不需要進 roadmap**——它是課的內容，不是機制。

## 出口條件（第十節新增）

- **第二課寫的時候用了圖片** → 「圖片支援」從願望變成實際需求
- **有人因為找不到東西而【卡住】** → 那時「用指的」才從增益變成瓶頸
- ⚠️ **「漏分號會怎樣」仍未被任何人實測** → 那是第一課唯一還開著的空白

## 十一、圖片的過時問題，答案是「不要用截的」

> 使用者：「**怕圖片在版本更新之後很容易過時，要如何處理比較好？**」

**兩種圖，過時風險完全不同**：

```
UI 截圖      🔴 隨介面改版過時   → 讓端對端走查【順手產生】
概念示意圖   🟢 不隨介面過時     → 手畫就好（它畫的是領域不是工具）
```

⚠️ 而第二種正是本檔前面說的**圖解**——**那一格本來就該手畫**。

🔴 **而副作用比圖片本身值錢**：

> **一份會自己重新截圖的教材，同時是一支「這一課還走得通嗎」的測試。**

→ 已做（`e2e/lesson-01.spec.ts`，spec `125`）。
⚠️ 而**就算永遠不加圖片，那支測試都該在**——寫完第一課時我有過一支，**然後刪了**。

## 出口條件（第十一節新增）

- **第二課寫的時候** → 走查測試是不是每一課都要有一支（今天是一課一支，
  ⚠️ 而那可能會變成**每加一課就要寫一支**——那時要想清楚它該不該被導出）
- **有一張圖真的需要構圖** → 那時「手畫並標明示意圖」這條規則第一次被用

## 十二、🔴 探針：第一課的學生犯錯時，畫面上出現的是**代號**

（2026-08-15。9 種第一課學生會犯的錯，逐條實測。）

```
                      診斷  閘門    學生看到什麼
對照（正確）             0   放行   跑完，輸出 "Hello!\n"
① cout 那行漏分號        1   🟢擋下
② return 0 漏分號        1   🟢擋下
③ 漏右大括號             1   🟢擋下
④ 全形分號 ；            1   🟢擋下   🆕 沒預期到會被抓到
⑤ 全形引號 “”           1   🟢擋下   🆕 同上
⑥ 引號沒關              1   🟢擋下
⑨ 全形括號 （）          1   🟢擋下   🆕 同上
⑦ Cout 大小寫錯         0   🔴放行   RUNTIME_ERR_UNDECLARED_VAR: {"%1":"Cout"}
⑧ << 寫成 <             0   🔴放行   RUNTIME_ERR_UNDECLARED_VAR: {"%1":"cout"}
```

### 一、🟢 「漏分號會怎樣」終於有答案了——**擋得住**

那一條被記下**四次**沒做。而順帶量到三件沒預期的：**全形分號、全形引號、
全形括號都被擋下**——⚠️ 而那是中文使用者最常犯的錯，這個專案一次都沒測過。

### 二、🔴 而放行的那兩種，學生看到的是**原始代號**

`execution-controller.ts:355` 逐字 `this.broadcastOutput(e.message, 'stderr')`，
而 `interpreter/errors.ts:8` 的 `message` 是 `key + JSON.stringify(params)`。

**這是 `spec 121` 一天前修過的同一個病**（`monaco-panel` 查 `window.Blockly?.Msg`
永遠走 fallback，把 `DIAG_MISSING_CONDITION` 顯示給使用者）。

### 三、🔴 而護欄沒接住，理由比「漏了一族」更深

第四十二條（`audit-diagnostic-labels`）`:93` 硬寫 `DIAG_${rule}_${panel}`
——只涵蓋 `DIAG_` 那一族。**而就算把 `RUNTIME_ERR_` 加進去也接不住**：

```
護欄量的      文案【在不在】        ✅ RUNTIME_ERR_UNDECLARED_VAR 在 blocks.json:134
缺陷是        顯示端【有沒有查】     🔴 broadcastOutput 從來不查
```

> **文案齊全，而沒有人查它。**

⚠️ 那與「機制有了沒人接上」是**同一個病**（`mappings` 零接收者、
23 筆 `min` 零消費者、`children.allowed` 41 筆）——第四次。

> **一條護欄如果只涵蓋「上次出事的那一族」，它防的是上一次，不是這一類。**

### 四、⚠️ 而探針有一欄不算數，寫出來

參照編譯器那一欄**連對照組都編不過**（`use of undeclared identifier 'cout'`）
——探針餵的是原始碼，沒有走系統的 auto-include。
**那一欄不能用來下任何結論**（`build-guardrail` 6.5「紅的是世界還是語料」）。

## 出口條件（第十二節新增）

- **代號被翻譯** ＋ **一條「不得顯示代號」的護欄** → 第二課才寫得出
  「你會看到什麼」（否則課文要照抄一串代號，等於**把缺陷寫進教材**）
- ⚠️ **⑦⑧ 放行是對的**——它們不是語法錯誤（`cout < "x"` 語法合法）。
  那是階段 6.6 ⑤／6.7 的地盤，**不在本輪**
