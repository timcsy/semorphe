# 課文的出口，與「被找到」

> 日期：2026-09-03
> 狀態：🪦 **已交付並退場**（2026-09-03，0.14.0）——四條驗收全綠。
> 結論與那四個順帶翻出來的既有缺陷記在
> [history/205](../history/205-課文有了出口而它一直都在那裡.md)；
> 「零外部資源」那條判準的例外記在
> [history/206](../history/206-零外部資源有了一個具名的例外.md)。
> 這份保留為**當時的設計脈絡**（為什麼是行導向的網址、為什麼產生器不得自己讀檔）。
> 怎麼冒出來的：使用者問「**如何提升 semorphe.com 的 SEO？或是更容易被瀏覽器找到？**」
> 而查下去發現這根本不是 SEO 題。

## 一、量到的：13 萬字的課文，產品裡沒有讀者

```
6 軌 · 66 課 · lesson.md 共 129,368 字（繁中，含 ```cpp 區塊）
每課 1,276 ～ 3,074 字
```

而 `src/core/load-lessons.ts:8` 逐字寫著：

> 「⚠️ **課文（`lesson.md`）不在這裡**。這一刀只讀宣告；
> 課文的呈現牽到還沒拍板的互動教材形式。」

`src/core/lesson.ts:35` 同一句。全 repo 只有**兩個消費者，都是測試**：
`e2e/lessons.spec.ts:53`（從「完成的樣子」抽程式碼去跑）、
`tests/integration/audit-lessons.test.ts:76/115`（段落齊不齊）。

🔴 **所以使用者一個字都看不到。** 靜態頁不是「為了搜尋引擎多做一層」，
它是那 13 萬字**第一個真正的出口**——SEO 只是順帶的結果。

⚠️ 而那句註解是 2026-08-27 寫的。它當時是誠實的（形式沒拍板），
而**沒有人接手它，於是「這一刀不做」慢慢變成「不做」**。
（這一條可能該進 experience，見文末「要拍板的」。）

## 二、為什麼 SEO 的答案不是 meta tag

Semorphe 是**自創詞**：品牌搜尋量趨近於零。所以成敗不在
「semorphe.com 排不排得上 semorphe」，而在**有沒有頁面吃得到問題型關鍵字**
（「for 迴圈 教學」「APCS 練習」「Scratch 轉 C++」「積木轉程式碼」）。

而站上今天只有一個編輯器：Google 進來看到的幾乎沒有文字。
**這是排序【之前】的問題，不是排序的問題。**

## 三、設計：產生器走同一份登錄表

🔴 **最重要的一條**：產生器**不得**自己 `fs.readdir('lessons/**')`
——那會長出「第二個讀同一份宣告的人」，而這個 repo 被這個形狀咬過
（`universal.json` 與 `app.ts` 的雙重真相）。症狀是：宣告多一個欄位，
編輯器懂、靜態頁不懂，而**兩邊都不會壞，所以沒有人發現**。

> **一份宣告的第二個讀者，不會在它讀錯的那天出聲——
> 它會在它讀漏的那天沉默。**

形狀：**`vite.config.ts` 裡一個 plugin**，`closeBundle` 時輸出。
它 import 的是同一支 `load-lessons`（軌道順序、`order`、`track.name` 都在裡面），
課文用同一次 `import.meta.glob('/lessons/*/*/lesson.md', { as: 'raw' })` 吃進來。

🪦 考慮過而否決的兩個：
- **Vite 多頁入口（`rollupOptions.input`）**——課程是動態清單，要先產一堆入口檔，繞遠路
- **靜態頁 hydrate 成編輯器**——那是兩個受眾（讀／做），混在一起 LCP 會很難看，
  而那正是 SEO 扣分的地方

檔案位置：`tools/build-lessons/`（與 `tools/demo/`、`tools/vscode-preflight/` 同層
——都是建置期的東西），plugin 本體十幾行掛進 `vite.config.ts`。

## 四、網址：讀與做是兩個網址，而它們互相指

```
/lessons/                     全部課程（＝選課選單的同一份清單）
/lessons/<軌道>/              一條軌道 ＝ 一個章節頁（track.json 有 name/description/order）
/lessons/<軌道>/<課>/         純 HTML、不載 Blockly／wasm，秒開
/?lesson=<軌道>/<課>          編輯器（這個參數今天就有）
```

雙向連結是「配合編輯器操作」的實際答案：

- 靜態頁 →「**在編輯器打開這一課**」（`target="_blank"`，別把讀到一半的人踢走）
- 編輯器 →「選擇課程」選單裡給一條「**看課文**」；帶 `?lesson=` 進來的人
  要看得到回去讀的路
- 有步驟的話 `&step=3` 對到靜態頁的 `#step-3`——**讀與做同一個座標系**

而選單與索引頁**不會漂**，因為兩者都是同一份登錄表的視圖
（與工具箱在階段 6.5 E 步的做法相同）。

## 五、護欄（形狀與既有的一樣）

```
① 登錄表裡的每一課，dist/ 裡都要有它的頁            硬性零
② 每一頁「在編輯器打開」連到的 lesson id 必須存在    硬性零（反向）
③ 每一頁的 title / description 互不相同             ← SEO 最常見的失分
④ 靜態頁的 HTML 裡不得出現 blockly 的 bundle 名稱    ← 防「哪天有人順手 import」
```

④ 看起來瑣碎，而它守的是這整件事的價值：一旦有人在課文頁 import 了什麼，
秒開就沒了，而**沒有任何測試會紅**。

① 幾乎是既有 `audit-lessons`「沒有課文」那條的延伸一格。

⚠️ **不要動「完成的樣子」那段的格式**：`e2e/lessons.spec.ts:56` 的註解
「**程式碼只有一份，住在課文裡**」——那是唯一抽取點，重排或換 fence 會讓 e2e 抽不到。
🟢 反過來說這是好事：網站上顯示的程式碼**就是真的能跑的那一份**。

## 六、其餘的 SEO（順序在後，因為便宜）

先確認「進得來、只有一份」：Search Console ＋ sitemap · `semorphe.com` 與
`timcsy.github.io/semorphe/` 只留一個正本（301 或 canonical）·
⚠️ **Vite 的 `base` 今天是 `/semorphe/`**，掛自訂網域之後應該是 `/`。

之後：每頁不同的 title/description/H1 · `Course` 的 JSON-LD · OG image ·
sitemap 帶 lastmod。

站外通常更有效：VSCode Marketplace 那一頁的標題與前兩行 · GitHub topics ·
一篇面向老師的文章。

## 要拍板的

1. **這一格進不進路線圖**（帶驗收標準：66 課全部有頁 ＋ 四條護欄）
2. **一條 experience 教訓要不要寫**：
   > 一句「這一刀不做 X，因為 X 還沒拍板」的註解，如果沒有人接手 X，
   > 它會安靜地變成「X 不做」的理由——而寫下它的那天，它是誠實的。
   （證據：`load-lessons.ts:8` ＋ `lesson.ts:35`，2026-08-27 寫下，
   13 萬字的課文因此躺了一週沒有出口。）
3. 課文的呈現**要不要順便解決「互動教材形式」那個懸案**，還是先只做「讀」的那一半
   （我傾向後者：靜態頁不需要那個答案，而它一天就能有東西看）
