# 元件命名重新設計：名字不該命名投影

> 日期：2026-08-08
> 怎麼冒出來的：D 項（命名空間遷移）只換了名字的**容器**（`cpp_` → `cpp:`），
> 名字本身一個字都沒動。使用者問「能不能有系統地重新設計，不沿用舊的」。
> **狀態：未決，等人拍板。** 依 knowie 的規矩，設計要先成為路線圖項目才動手。

> ## ⚠️ 以下的判定已被推翻一次，**保留不刪**（見文末「翻轉」）
>
> 「① ／ ② ／ ③ 四堆」是在**只看得到 C++** 的情況下判的，而那個前提不成立。
> 保留它是因為**它錯的方式**比它的結論有價值。

## 判準

根公理是「唯一真實，各式投影」。推論：**名字要命名語義，不能命名任何一種投影。**

檢驗：換一個語言，這個名字還說得通嗎？

- `lang:endl` — C++ 的 token 名，Python 沒有。**不及格**
- `lang:count_loop` — 沒說 `for`，說的是「數著跑」。**及格**（現有最好的一顆）
- `cpp:ternary` — 「三個運算元」是怎麼寫，不是做什麼
- `cpp:comma_expr` — 命名了一個標點符號

### 導出的三條

1. **主體用抽象資料型別，不用具體容器**——`vector` 是拼法，語義是「可增長的序列」。
   但 `stack`／`queue` 保留，它們的語義**真的不同**（LIFO vs FIFO）。
2. **操作用語義動詞，不用 std 方法名**——`push_back` → `append`。
3. **分不出來就是同一顆，差異變成參數**——判準就是 B 項與 C1 反覆撞到的那個：
   **差異能寫成參數而執行器只是分支，那它就是參數不是身分。**

## 實測：177 顆分四堆

| 堆 | 顆數 | 意思 |
|---|---|---|
| **① 通用化零風險** | **40** | C++ 只有一種拼法（`string_length` → `.length()` 永遠是它） |
| **② 需要語義參數軸** | **42** | 多種拼法，但說得出語義意圖 |
| **③ 不該通用化** | **67** | 說不出語義意圖，語言特定性是**真的** |
| **④ 已經對了** | **28** | 通用層既有元件 |

**① ＋ ② = 82 顆（46%）目前掛在 `cpp:`，而語義是通用的。**
那是 scope 劃分錯的規模——現在的 scope 記錄的是「這顆從哪個語言長出來的」，
不是「它屬於誰」，而 D 的設計文件白紙黑字寫著 scope 是所有權。**名字沒改，
那條決定只落實了一半。**

**③ 有 67 顆（38%）不用動**——指標／手動記憶體、四種轉型、前處理器、
C 字串函式、C++ 物件模型、`printf`/`scanf`。這是好消息：大部分不必碰。

### 順帶抓到三顆掛錯的

- **`lang:endl`** —— 命名了 C++ token，卻掛在 `lang:`
- **`lang:forward_decl`** —— 前向宣告是 C/C++ 編譯模型的東西，不該在 `lang:`
- **`lang:builtin_constant`** —— 值域混了通用（`true`/`false`）與 C 家族（`EOF`/`NULL`/`nullptr`）

## 歧義風險：只有兩組，7 顆

「通用化之後轉回來會不會有歧義」是這個設計唯一會出事的地方。實測合併族
在合併後對到幾種 C++ 拼法：

| 合併族 | 顆數 → 拼法數 | 判定 |
|---|---|---|
| 空否 / 清空 / 加到尾端 / 索引取值 | 2 → 1 | ✅ 拼法相同，合併零歧義 |
| 容器宣告 | 6 → 6 | 🟡 差異本來就要寫進參數（存取紀律），參數自己選得出來 |
| 字串搜尋 | 3 → 3 | 🟡 同上（方向／否定） |
| **大小** | **2 → 2** | 🔴 `.size()` vs `.length()` |
| **看某一端** | **5 → 3** | 🔴 `.back()` / `.top()` / `.front()` |

**只有這兩組（7 顆）需要靠上下文才選得出拼法**，而上下文是**接收者的型別**。

> ⚠️ 而那套型別追蹤**已經存在**——`TYPED_METHOD_TO_CONCEPT` 在 lift 方向用著
> （`string.clear` → `cpp:string_clear`）。缺的是**把它接到 generate 方向**。
> 那是一件具體的工程，不是未知數。

## 真正的陷阱不是歧義，是耦合搬家

`lang:sequence_declare` 帶一個參數 `impl: vector|deque|list` —— **一個 `lang:`
元件的參數值域是 C++ 詞彙。** 耦合沒有消失，它從身分搬到了參數。

而**中立性護欄量不到這一維**：它掃元件身分字串，不掃參數的允許值。

這與 `history/021` 是同一個形狀（「中立性的數字只量身分那一維」）。
照著做下去，我們會把耦合搬到一個**沒有護欄的維度**上，然後數字看起來更漂亮。
**那比不通用化更糟。**

→ 參數必須是**語義軸**（`discipline: sequence|lifo|fifo|priority`），
不是實作軸（`impl: vector|stack|queue`）。而這需要一條新護欄：
**`lang:` 元件的參數值域不得出現語言專屬詞彙。**

## 一個要避開的錯答案

把原始拼法塞進 `metadata` 保 round-trip。**不要。** metadata 不是真實，
靠它保 round-trip 等於承認真實不在語義樹裡——那正是 P8 推導自的
「投影可重建」在講的東西。要嘛進參數（是真實），要嘛不通用化。

## 時機

**必須在 F（膠囊搬家）之前。** F 讓每顆元件搬進自己的目錄，而**目錄名會從
元件名來**。名字晚一步改，F 就得做兩次。

## 安全網

- **來回轉換測試**——通用化如果丟了資訊，`vector<int>` 轉一圈變成別的，當場紅
- **概念身分驗證**——roundtrip 測試會驗語義樹用的是正確的 conceptId
- **存檔轉換**——D 已經把 `registerIdMigration()` 的機制建好，這次是沿用

做錯的通用化**會被抓到**，風險從「安靜地壞掉」降到「會紅」。

## 未決的

1. **要不要做**——82 顆改名 ＋ 兩組型別上下文接線，換到的是 P9 真的成立、
   Python 進來時不用再叫一次 `py:list_declare`
2. **`lang:if_else` 是 `lang:if` 的形態還是身分**——B 項合併過同型的東西
3. **語義軸的詞彙要怎麼定**——`discipline`、`end`、`direction` 這些軸名本身
   要有人拍板，而拍錯了會像 `impl:` 那樣把耦合藏起來

# 翻轉（2026-08-08 同日，「假設已經支援多種語言」重看）

## 上面那份分類是從一個樣本判的

假設 Python／JS 現在就在，重看「③ 不該通用」那 67 顆：

| 我的判定 | 我當時寫的理由 | 三語言在場時 |
|---|---|---|
| `cpp:try_catch`／`throw` | 「catch 型別是 C++ 的」 | Python `try/except/raise`、JS `try/catch`。**catch 型別是參數不是身分** |
| `cpp:lambda` | 「capture 是 C++ 的」 | Python lambda、JS arrow。**capture 是只有 C++ 會填的參數** |
| `cpp:range_for` | 「介面是 C++ 的」 | Python 的 `for x in xs` 是**主要**迴圈，比 `count_loop` 更通用 |
| `cpp:class_def`／`constructor` | 「C++ 風味的物件模型」 | Python `class`／`__init__`。C++ 味的是 `virtual`／`operator_overload`，不是整族 |
| `cpp:printf` | 「格式字串是 C 家族特有的介面」 | Python 的 `%` 格式化**就是從 C 繼承的** |
| `cpp:switch`／`enum` | 「C 家族語法構造」 | Python 3.10 `match`、`enum.Enum` |

至少十幾顆。而錯的方向**一致**：只看得到 C++ 時，什麼都像 C++ 特有的。

> **這是「已知答案的樣本必須是查過的」的又一個實例**——我當時沒有第二個樣本可查，
> 於是用內省代替了查證，而內省產出的數字看起來與查證產出的一模一樣。

## 更關鍵：這個劃分本身不穩定

如果 scope 表達「通用還是特定」，它的值**會隨語言增加而改變**：

```
今天（只有 C++）    cpp:try_catch
Python 進來那天     lang:try_catch     ← id 變了 → 存檔要遷移
```

而 D 自己拒絕過這件事：

> Go／Modelica 走另一條：**id ＝ 位置**。買到「就近性不可能違反」，
> 代價是**搬家＝改名＝存檔遷移**。不採。
> ——`2026-08-07-元件目錄與膠囊契約.md:81`

**我們拒絕了 id＝位置，卻做了 id＝通用性——而通用性和位置一樣會變。**
只有一個語言時看不出來，因為它從來沒被迫改過。

## 而「怎麼取一個通用的名字」是一個錯問題

（這一條來自 `等價的觀察集與回饋.md` 的內涵／外延之分）

**名字是內涵的**——它只需要對得起自己的定義。而「通用」是**外延的**，
它根本不住在名字裡。

`cpp:string_find_first_not_of` 這個名字**沒有錯**，它誠實地命名了一個 C++ 的東西。
錯的是我期待名字同時宣告它的外延範圍。

於是命名規則只剩一條，而且很低調：

> **名字要說得出這顆元件自己是什麼，不必宣稱它跟誰一樣。**

## 選項改了

| | | |
|---|---|---|
| **(A)** | 表達通用性，但凍結（命名時掛什麼就永遠是什麼） | `cpp:try_catch` 會永遠掛著一個假的語言歸屬 |
| **(B)** | **不表達——全部 `lang:`，語言特定性當資料** | Python 進來時**零重新命名**；「誰實作它」本來就記在套件裡 |
| **(C)** | 等第二個語言再定案 | 判定從「我覺得」變成「幾個套件投影它」，是機械的。代價是 F 要等 |

**我傾向 (B)**，理由不是它便宜，是**它沒有問那個問不了的問題**：
`lang:`／`cpp:` 的劃分要求你現在就宣告每顆元件通不通用，而那正是
只有一個語言時說不出口的話。

D 拒絕 `universal:` 的理由是「硬體進來那天會被讀成所有域通用」——
而 `lang:` 這個名字已經把那個歧義解掉了：它說的是**語言域**，
不是「所有語言都有」。

## 不受翻轉影響的

`lang:endl`、`lang:forward_decl`、`lang:builtin_constant` 三顆。
它們不是「掛錯 scope」，是**名字命名了投影**——不管選 A／B／C 都該修。
