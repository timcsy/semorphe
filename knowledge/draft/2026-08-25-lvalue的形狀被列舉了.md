# lvalue 的形狀被**列舉**了，而它是一個開放的文法

> 2026-08-25 使用者：「我的意思是 **lvalue 的型態應該百百種吧，這樣不就寫死了？**」
>
> 起因：那天修好「`a[i] += 2` 的索引掉了」之後，我報告「範圍是所有容器的下標複合指定」
> ——⚠️ **而那個回答答錯了層次**：問題不是「還有哪些容器」，是**賦值的左邊是一個文法**。

## 一、現況：三顆元件在表示同一個文法

```
cpp:var_assign          obj  = 字串
cpp:array_assign        obj  = 字串  ＋ index          ← 一層下標
cpp:array_2d_assign     obj  = 字串  ＋ row, col       ← 兩層下標，另開一顆元件
cpp:var_assign_compound name = 字串  ＋ index
cpp:increment           name = 字串  ＋ index
```

**五顆元件，target 全部是【字串屬性】，而下標的層數被寫進元件的身分裡。**

🔴 三層下標沒有第三顆元件——它會被塞進那個字串。

## 二、量測（2026-08-25，語料 = 整合測試裡的樣本）

```
cpp:var_assign             純識別字 107  ｜ 塞了別的東西 12 種   r.x · p.first · s.side · v.i …
cpp:array_assign           純識別字  69  ｜ 塞了別的東西  0 種
cpp:array_2d_assign        純識別字   2  ｜ 塞了別的東西  0 種
cpp:var_assign_compound    純識別字  29  ｜ 塞了別的東西  0 種
cpp:increment              純識別字  23  ｜ 塞了別的東西  0 種
```

### 🔴 而「0 種」不是好消息

同一天在瀏覽器裡**三十秒**就做出四種語料沒有的：

```
a[i][j] += 1   →  name = "a[i]"   index = j     ← 第一層下標被烤進字串
o.x    += 1    →  name = "o.x"
p->x   += 1    →  name = "p->x"
*q     += 1    →  name = "*q"
```

> **語料乾淨不代表模型對——它代表語料是照著模型長出來的。**

而 `cpp:var_assign` 的 **12 種**是這個專案自己的測試裡**已經存在**的證據。

## 三、症狀不是「壞掉」，是**假裝結構化**

那些都**來回得回去**——因為產生器是**字串串接**。所以：

- 測試綠、殘差不動、`audit-block-instantiable` 硬性零也是 0
- 而積木上那顆欄位是 `field_dynamic_dropdown`（`source: vars`）
- **點開它，看到的是工作區的變數清單**。學生在 `o.x += 1` 上點一下改成 `i`，
  那個成員存取就沒了——**沒有任何東西會出聲**

> **一個看起來結構化、實際上是字串的欄位，比一個誠實的 `raw_code` 更危險
> ——`raw_code` 至少長得像降級。**

## 四、🔴 而今天補的 `altLayout` 是這個病的症狀

`hasIndex` 之所以要變成「同一顆積木的第二種佈局」，**正是因為 target 不是一個接點**。

```
今天    var_assign_compound { name: 字串, index?: 運算式, value: 運算式 }
應該    compound_assign     { target: 運算式, op, value: 運算式 }

b[i]  += 1   target = array_access(b, i)
a[i][j] += 1 target = array_access(array_access(a, i), j)
o.x   += 1   target = member_access(o, x)
p->x  += 1   target = arrow_access(p, x)
*q    += 1   target = deref(q)
```

**一種佈局、沒有旗標、而 lvalue 的文法是開的。**

> **`hasIndex` 不是「缺一個機制」——它是「target 不是節點」漏出來的症狀。
> 而我今天做的機制讓一個錯的模型更好表達，不是讓它變對。**

⚠️ 所以 `altLayout` **留著**（它修好了一個活了五天的缺陷，`cpp_increment` 的退場也靠它），
而**把它記成一個過渡機制**：target 變成接點的那天，它才該退。

## 五、它服務的原則

- **P3 開放擴充**：一個文法該由組合表達，不由列舉表達
- **[[元件代數]]**：`array_2d_assign` 存在的唯一理由是「兩層下標」——那不是一個身分，是一個組合
- **P6 誠實降級**：現在的做法**既不誠實也沒降級**——它看起來成功了

## 六、⚠️ 而這一刀的成本要先講清楚

**它動的是語義詞彙本身**，`principles.md:158` 逐字：

> 「**但語義詞彙本身的變更不在此列**（例如 `componentId` 改名）：那動的是真實，
> **沒有東西可以重建它**，推導鏈對它不成立。這種變更 MUST 附**一次性的轉換**」

所以它**必須附一次性轉換**：舊存檔的 `name: "o.x"` 要被解析成
`member_access(o, x)` 節點——⚠️ **而那需要一個 parser**，因為那個字串裡裝的是程式碼。

🟡 好消息是那個 parser 已經在（tree-sitter）；壞消息是轉換要在**載入時**跑。
