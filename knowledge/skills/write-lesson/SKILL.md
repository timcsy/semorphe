# 生一堂課（write-lesson）

## 這把刀先問一句

> **這堂課的程式碼，我跑過了嗎？**

沒有 → **先跑，再寫課文**。一堂課文是對學生的承諾（「你會看到 `Hello!`」），
而一句沒驗過的承諾在課堂上會當著全班的面破掉。

（緣起：2026-08-27 生前四堂 C++ 入門課，**同一輪之內犯了兩次靜默錯誤**——
兩次都是「東西看起來完全正常，而學生照著做會卡住」。）

## 先問這堂課屬於哪一軌

```
從頭來    不假設會別的語言       cpp-beginner · python-beginner · arduino
銜接      假設已經會另一個語言   c-bridge · python-bridge
進階      假設已經走完入門       cpp-advanced
```

🔴 **這兩種課寫出來會完全不一樣**，而**寫著寫著會偏**。

2026-08-28 的實例：Python 那六章原本掛在 `python-beginner`，
而它通篇是「這和 C++ 差在哪」——**那是銜接**。
改掛 `python-bridge`，另外從頭寫了 12 章入門。

判準：**把課文裡所有提到另一個語言的句子刪掉，它還站得住嗎？**
站得住 → 入門。垮掉 → 銜接。

### 編號與跨課引用

每一軌各自從 `01` 開始、兩位數、**不加字母前綴**（資料夾名已經說明軌道）。

```
同一軌   第 5 課
跨軌     C++ 入門第 5 課 · Arduino 第 5 課 · C 銜接第 3 課
```

⚠️ **不要用中文數字**（「第五課」）。兩種寫法混用時，
批次改號一定會漏掉其中一種——而漏掉的那些會**指到錯的課**，
且不會有任何東西變紅。

⚠️ **跨軌引用要寫全軌道名。** 「入門第 5 課」在只有一個入門軌時沒問題，
而多一軌的那天它就有歧義了——**而舊課文不會自己改。**

## 一條軌道也是一份宣告

```
lessons/<軌道>/track.json     { name, target, order, description }
```

它是「課程」那顆選單讀的東西。⚠️ **新開一條軌道就要有它**——
沒有的話那條軌道**不會出現在選單裡**，而資料夾看起來一切正常
（第八十四條護欄擋著）。

三層的分工：

```
目標   語言／板子    ← 目標宣告（`group` / `order` / `listed`）
課程   軌道          ← track.json
章節   課            ← lesson.json
```

🔴 **`listed: false` 的目標只由課程進得去**——`cpp-advanced` 是一條軌道不是語言，
`arduino`（不指定板子）是一個陷阱。

## 交付物——一堂課是兩個檔

```
lessons/<軌道>/<編號>-<課名>/
    lesson.json    宣告：要開哪些積木、釘住什麼組態、跑出來該是什麼
    lesson.md      課文：學生讀的那一份，**也是程式碼唯一住的地方**
```

🔴 **`lesson.json` 不放程式碼。** 護欄從 `lesson.md` 的 `## 完成的樣子`
抽 fenced block 去跑。一份寫在兩處的程式碼遲早會有一處是舊的，
而**學生看到的永遠是舊的那一處**。

## 步驟

### 1. 🔴 用 Playwright 量，**元件與輸出兩樣都量**

**不要用瀏覽器 MCP 一段段點**（2026-08-27 試過：CDP 45 秒逾時、
回傳讀在半路上、狀態互相踩，一小時量不完十段）。

用 **`e2e/measure-lesson-codes.spec.ts`**（留在 repo 裡的工具）：
餵它 `.lesson-measure/codes.json`（`{ 名: { target, code } }`），
它逐段同步、走語義樹、**再按執行讀主控台**，寫出
`.lesson-measure/measured.json`。50 段大約三分鐘。

⚠️ **沒有那個輸入檔它就整支跳過**，所以留在 `e2e/` 裡不影響全套。

🔴 **暫存檔放 `.lesson-measure/`（已 gitignore），不要放 `tools/`。**
`tools/` 是**產品建置腳本的家**——2026-08-28 我把暫存寫進去，
收尾 `rm -rf tools` 把整個目錄刪了，第五十八條護欄當場紅在
「Cannot find module tools/build-sdk.mjs」。

> **一個「我建的」目錄，與一個「本來就在、而我剛好也寫了東西進去」的目錄，
> 在 `ls` 底下長得一模一樣。**

⚠️ **`check.stdout` 也要量，不要猜。** 它是課文對學生的承諾
（「你會看到 `Hello!`」），而一個猜出來的承諾與一個量出來的長得一模一樣。

#### 🔴 練習題（2026-09-04 起）

一課的裁判從**一個 `check`** 變成 **`tasks` 一題一個**（格式見 `lessons/README.md`）。
寫練習題時多兩件事：

```
① 題目宣告在 lesson.json 的 tasks 裡，敘述留在課文的〈換你了〉
② 有裁判的練習題 ⟹ 一定要附 solutions/<題目 id>.<副檔名>
   ——⚠️ 它【不進課文】，靜態頁不產它，學生點不到
```

> **一個沒有人跑過的期望輸出，是一個還沒被發現的、會說錯話的裁判。**

#### 🔴 選擇題的干擾項（`predict: "choice"`）

每一個錯的選項**必須**附上 `why`——它是那個選項對應的**具體誤解**：

```
"1 2 3 4 5"    以為 endl 是空格
"1 2 3 4"      差一——條件是 <= 還是 <
"（什麼都沒印）" 以為條件一開始就不成立
```

> **選擇題的價值全在干擾項，而干擾項的價值全在它說得出哪一個誤解。**

寫干擾項的方法：**去看那一課〈如果卡住了〉那張表**——它本來就是一張
「症狀／原因」對照表，而每一行都是一個現成的干擾項。

⚠️ 而**判不了的題目就不要給它 `check`**（「改用 `while` 寫」的輸出一模一樣）
——那種題目該做的是**沉默**，不是說「對了」。一個永遠說對的勾會讓所有的勾貶值。

#### 這支量測器有四個坑，每一個都真的撞到過

| 坑 | 症狀 | 做法 |
|---|---|---|
| **同步還沒完成** | 量到的是**上一段的樹**——一份看起來很合理的錯清單 | 每段之前先同步一個**空程式**，讓「沒更新」露出空樹 |
| **執行狀態殘留** | 每一批**只有第一段印得出東西** | 每段之前 `freshApp(page)` **重新載入**。`handleStop()` 救不了 |
| **解析器懶載入** | 切到 Python 之後量到 **0 顆元件** | 切目標後等 2500 ms；**並斷言「一段真程式不可能零元件」** |
| **`trim()` 吃掉空白** | 「印了一串空行」與「什麼都沒印」分不開 | 空字串而原文非空時，印成「只有 N 個空白字元」 |

> **一個把自己的狀態殘留算進結果的量測器，
> 產出的是一份看起來像發現的東西。**
>
> 2026-08-27 因為第二個坑，我差一點把 `analogWrite` 寫成產品缺陷
> ——`x1` 印了 20 行、`x2`（更簡單）什麼都沒印。
> **結果與假設相反而不自洽，那就是工具壞了，不是世界長那樣。**

**實測改過我兩次**（2026-08-27，前四課）：

| 憑印象 | 實測多出來 |
|---|---|
| 第一課「`func_def` ＋ `print` ＋ `literal_string`」 | ➕ `cpp:literal_number`——`return 0;` 的那個 `0` |
| 第二課以為 `1.72` 有自己的浮點元件 | 沒有，它與 `95` 同一顆 `literal_number` |

> **一份憑印象列的元件清單，與一份量出來的長得一模一樣
> ——直到有人照著它上課。**

同時確認 **`raw_code` 是零**。有 `raw_code` 代表系統讀不懂這段程式碼，
那堂課在積木那一側是壞的——而課文照樣寫得出來。

#### ⚠️ 結構節點**不是**元件

語義樹裡有一類節點（`core/non-components.ts` 宣告的 `structural`，
例如 `param_decl`）是**別人的子節點，不會單獨成為一顆積木**
——學生在積木盤上看不到它們，所以一堂課不該宣告要開它們。

判準：**真元件的身分都是 `語言:名字`**（實測 332/332 都帶冒號）。
量測與護欄都照這條濾。

### 1.5 🔴 量到「跑不動」的時候，先分清楚是三種裡的哪一種

```
① 課文的程式碼用錯 API      → 改課文（例：lcd.init() 這個工具只認 .begin()）
② 目標選錯                  → 改 pins（例：LED_BUILTIN 只在【板子】目標上有）
③ 產品真的有缺陷            → **修它**，而且補一條護欄
```

⚠️ **第三種要真的修。** 2026-08-27 生課的過程抓到**六個**，
而它們全部是「lift 乾淨、積木正常、執行時才錯」——
**5890 支單元測試全綠，沒有一支看得到它們。**

> **生教材是一次覆蓋率很不一樣的走查**：它逼你把每一個語言、
> 每一個目標、從最簡單到最進階各走一遍，而那正是單元測試最薄的地方。

### 2. ⚠️ `pins.target` 要填**目標**的 id，不是主題的

```
主題（topic）   cpp-beginner · c-beginner · python-beginner · cpp-competitive · arduino
目標（target）  cpp · c · python · cpp-competitive · arduino · arduino-uno · esp32 · …
```

2026-08-27 我把 `cpp-beginner` 填進 `pins.target`——**它是主題**，
而目標叫 `cpp`。JSON 合法、檔案存在、編輯器開得起來，**而組態根本沒套用**。

查法（不要背）：

```bash
for f in src/languages/*/targets/*.json; do
  python3 -c "import json;d=json.load(open('$f'));print(d['id'],'| topic:',d.get('topic'))"
done
```

### 3. 課文骨架——七段，而「三件事」是刻意的上限

```
# <課名>
> <一句話：這堂課做出什麼>  ·  ⏱ <時間>
## 你會學到三件事      ← 剛好三件
## 開始之前            ← 接上一課的成果
## 一、二、三…         ← 有編號的步驟，每步一小段程式碼
## 完成的樣子          ← 🔴 護欄抽這一段去跑
## 換你了              ← 一個改造題，不給答案
## 這一課你做了什麼
## 如果卡住了          ← 症狀／原因對照表
```

**寫第四件的時候，那多半是下一課。** 這條上限是在逼你切課，不是在限制內容。

「如果卡住了」那張表**寫症狀，不寫錯誤訊息全文**——學生看得懂的是
「主控台是空的」，不是 `error: expected ';' before '}' token`。

### 4. 課文裡每一段程式碼都要能單獨成立

步驟中間那些片段，護欄**不會**去跑（它只抽 `## 完成的樣子`）。
所以那些片段是**人要負責**的部分——寫完自己讀一遍：
這一段貼進去跑得起來嗎？它用到的東西前面教過嗎？

### 5. 兩條護欄，缺一不可

| | 問什麼 | 抓得到什麼 |
|---|---|---|
| `tests/integration/audit-lessons.test.ts` | 這顆元件**存不存在** | 懸空引用、骨架殘缺、第四件事 |
| `e2e/lessons.spec.ts` | 這段程式碼**真的用到它嗎** | 清單漏一顆／多一顆、跑出來不符 |

🔴 **靜態那條答不出第二個問題**。憑印象漏掉的 `literal_number`
是一顆**存在的**元件，靜態護欄完全看不到。

e2e 那條是**資料驅動**的：新增一堂課不必新增測試檔，掃到就會跑。

### 6. 要輸入的課，用**真的輸入框**餵，不灌 API

```ts
await page.locator('#run-btn').click()
const box = page.locator('.console-inline-input')
await expect(box).toBeVisible()      // ← 這一行順便驗了「程式真的停下來等人」
await box.fill(line); await box.press('Enter')
```

灌 `setReplayInputs` 會繞過那一半——而課文寫著「程式會停住」，
那句話也是一個承諾。

## 明確否決

| 做法 | 為什麼不行 |
|---|---|
| 程式碼同時寫進 `lesson.json` 和 `lesson.md` | 雙重真相；學生看到的是舊的那一份 |
| 元件清單憑印象列 | 存在的元件漏掉了，靜態護欄看不到 |
| 一堂課配一支 e2e | 五十堂就是五十支。**資料驅動一支就夠** |
| 「先寫課文，程式碼之後補跑」 | 課文是承諾。沒驗過的承諾會在課堂上破 |
| 「三件事」寫成四件 | 那是兩堂課被壓成一堂 |

## ⚠️ 而我自己違反過一次順序

`build-guardrail` 第 6.5 步要求「**護欄先蓋，功能後做**」——
而 2026-08-27 我是**先修掉 `cpp-beginner` 那個缺陷、才蓋護欄**的。
於是護欄的第一次跑沒有抓到它，靠的是注入那一支。

> **一個被順便修掉的缺陷不會留下任何紀錄，而它的同類還會再來。**

下一次生課：**先蓋護欄、讓它紅、逐項指名，才動手修。**

## 一堂課跑不動而修不了的時候

**不要出貨一堂跑不動的課。** 三個選擇，照這個順序試：

```
① 換一個【一樣在教那件事】而跑得動的寫法
② 修產品                      ← 多半比想像的近
③ 真的修不動 → 這一章先不寫，把缺口記下來
```

⚠️ **不要太快跳到 ③。** 2026-08-27 我把 Linked List 判成「設計層的缺口，
不是一個小修」而略過了它。隔天真的去看，是**三個各自很小的修法**
（`new` 不認得結構 · `->` 只認一半的指標 · 配好的儲存體被當成空指標）。

> **「這看起來是架構問題」是一個假設，不是一個結論
> ——而它讓人停止去看。**

判它之前，至少把**錯誤訊息追到丟出它的那一行**。

## ⚠️ 而課寫完之後，還要在畫面上真的走一次

2026-08-28 接產品那一刀，**三個假設各自撐不過一次真的使用**：

| 我做的 | 使用者看著畫面說 |
|---|---|
| 釘住的控制項**消失** | 「我發現選了課程之後目標就不見了」 |
| 選了課才藏「教學層級」 | 「層級那邊還是沒變？」（沒選課時它還在） |
| 可見集合 ＝ 課宣告的那幾顆 | 「為何積木變這麼暗？」（鷹架被打成灰的） |
| 預設全開只會改到可見元件 | （測試抓到）斷點停得住，**而變數面板是空的** |

前三個都**測試全綠**；第四個是 e2e 抓到的，而**症狀離原因很遠**
——根因是 `enabledBranches` 同時扛著「哪些元件看得到」與「鷹架露到第幾層」。

> **兩個決定共用一個載體時，改動其中一個永遠會偷偷改到另一個。**

> **一份宣告對不對，只有把它放上畫面才問得出來。**

→ 生完一批課之後，**開瀏覽器把三層走一遍**：選目標 → 選課程 → 選章節 →
看狀態列剩什麼、看畫布有沒有東西被打暗。
