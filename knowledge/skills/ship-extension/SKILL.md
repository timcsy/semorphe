# 交付一次擴充改動（ship-extension）

## 這個 skill 做什麼

把 `src/vscode/` 的一次改動，交到 **VSCode 與 Arduino IDE** 兩個宿主手上。

緣起：2026-08-18 這一串（specs 139／140）**這條流程跑了九次**，
而其中**三次的災難是流程本身的洞造成的**：

```
版本號沒換 → VSCode 以 (id, version) 快取 contributes，改了不生效而不報錯
Theia 的解壓快取以【名字】為鍵 → 覆蓋 vsix 不會重新解，差點測到四版以前的東西
只跑預檢沒跑全套 → 網頁版退步不會被發現
```

> **一條每次都靠記憶重跑的流程，它的洞會在最不方便的時候現形。**

## 先問一句

> **「這一步如果錯了，使用者會不會失去他的檔案？」**

🔴 擴充與網頁版**不是同一種東西**：網頁版寫的是 localStorage，擴充寫的是**使用者真的檔案**。
所以這條流程的每一關都要能回答上面那句。

## 步驟

### 1. 換版本號 —— **不是可選的**

`src/vscode/manifest.ts` 的 `EXTENSION_VERSION`。

⚠️ VSCode 以 `(id, version)` 為鍵快取 `contributes`；**版本不變就不重建**，
而症狀是「改了圖示／選單而畫面沒變，且零錯誤」。

### 2. `npm run build:vscode`

⚠️ 建置腳本裡的錯誤**可能不會讓指令失敗**——回頭確認產出物真的換了：

```bash
grep -c '<你這次加的字串>' build/vscode/dist/webview.js
```

### 3. 預檢 —— `node tools/vscode-preflight/run.mjs`

它在 Chromium 裡跑一個**會回話的假宿主**。目前問六件事：
畫布看得見／lift 通了／連續兩筆編輯都收得下／鏡像對帳一致／
開 `.ino` 面板檔案一個字都不改／積木自動出現。

🔴 **而它有三層天花板**（見 experience「模擬環境有三層天花板」）：
它驗得到「我送了什麼」，驗不到「對面怎麼處理」，更驗不到 Theia 與 Chromium 的差異。
⚠️ **預檢綠不等於能用。**

### 4. `npm test` 全套 —— **不可省**

擴充那一刀會動到 `src/ui/`（網頁版的核心）。
🔴 專案的病歷是「一條路徑全綠而另一條安靜地錯」（`history/072`）。

### 5. 網頁版零變化 —— 有動到 `src/ui/` 時**截圖比對**

```bash
npm run dev   # 截圖 → 與上一次的 MD5 比
```

> **測試綠不代表使用者看到的是對的。**

### 6. `npm run install:ide`

兩邊都先刪舊版再裝，**並清掉 Theia 的解壓快取**
（`~/.arduinoIDE/deployedPlugins/<名字>/` 不含版本，不刪就不會重新解）。

### 7. 交棒 —— 說清楚**驗到哪裡**

⚠️ 交棒時要分三欄，不要只說「做好了」：

```
🟢 我驗過的        （測試／預檢／截圖 MD5）
🟠 只有你驗得到的  （在 IDE 裡按鍵拖曳的那些）
🔴 還開著的        （已知而沒修的）
```

🔴 **不得為了讓這一刀「完成」而換一個更弱的驗收。**

## 出事的時候：先停止推理

連續兩次「修好了又壞」時，**不要再看截圖猜**。先交付三樣：

```
① 安全網   讓錯誤的後果小於一次重試（例如：一次同步不得刪掉大半個檔案）
② 流水帳   哪一次操作造成的，而不只是結果長怎樣
③ 出聲     把靜默的失敗變成看得見的失敗（刪掉那些 `catch {}`）
```

> **一個沒有紀錄的系統，只能被推理；
> 而推理出來的修法，要靠下一次災難來驗證對不對。**

（實測：這一輪七次回報裡有三次的症狀是**上一次的修法造成的**，
換成①②③之後才收斂。見 [[history/083]]。）

## 🤖 而 CI 會替你做前兩步（2026-08-30）

`.github/workflows/vsix.yml`：

```
每次推送     npm run build:vscode → 產物體檢 → 上傳 artifact
打 v* 的 tag  再加：tag 與版本對帳 → GitHub Release（＋市集，有祕密才發）
```

🔴 **發佈綁 tag，不綁每次推送**——版本號必須唯一且遞增，每次推送都發等於
每個 WIP commit 都變成一個公開版本，而 Marketplace **不能刪版本**。

> **打 tag 是「我認為這一版可以給人用」的那個明確動作。**

### 那個「產物體檢」擋的是這支 skill 自己記過的洞

§2 逐字：「建置腳本裡的錯誤**可能不會讓指令失敗**」。所以 CI 量三件事：

```
大小 > 300 KB    一個 0 位元組的 vsix 會讓後面每一步都「成功」
檔數 > 10
裡面有 webview   少了它擴充裝得起來而【畫面是空的】
```

### 🔴 而 tag 對帳擋的是一個不會出聲的災難

```
tag 說 v0.11.0，而包裡是 0.10.4
→ 使用者以為裝到新版，實際裝到舊的，而【沒有任何東西會出聲】
```

那是 §1「換版本號不是可選的」在發佈這一側的投影。

### ⚠️ 兩個祕密要人去建，我建不了

```
VSCE_PAT   Marketplace——設了它，VSCode 的自動更新就【免費拿到】
OVSX_PAT   Open VSX——VSCodium／Theia 那一族
```

🟢 **沒設就跳過，而跳過會在 CI 的紀錄裡出聲**（`::notice::`）
——不是靜靜地不做。一個靜靜跳過的發佈步驟，會讓「我發佈了」變成
一句沒有人驗證過的話。

## ⚠️ Arduino IDE：沒有支援的通道（2026-08-30 記）

Arduino IDE 2.x 是 Theia 做的，吃 VS Code 的擴充格式，**而它把擴充市集
對使用者關掉了**。

```
從市集安裝    ❌ 沒有那個 UI
自動檢查更新  ❌ 沒有那個機制
手動放 vsix   ⚠️ 有一個 plugins 目錄，而那不是官方支援的介面
```

🔴 **而這支 skill 的 §6 已經踩過那條路的坑**：
「Theia 的解壓快取以**名字**為鍵 → 覆蓋 vsix 不會重新解，
差點測到四版以前的東西」。

⚠️ **下一步是量測，不是實作**：拿一台裝著**目前版本**的 Arduino IDE
實測那個目錄到底怎麼運作。在那之前不要寫自我更新器——

> **一個寫進 IDE 自己安裝目錄的自我更新器，壞掉的時候
> 使用者會變成「我的 Arduino IDE 開不起來了」——
> 那比「沒有自動更新」糟得多。**

🟢 而**還有一個常被忽略的選項**：這個專案已經有網頁版。對 Arduino IDE 的
使用者來說，「打開瀏覽器」可能比「維護一條沒有人承諾的安裝通道」好得多。
那是產品決定，不是技術限制。
