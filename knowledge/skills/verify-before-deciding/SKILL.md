# 先驗再決定（verify-before-deciding）

## 這個 skill 做什麼

拿到一筆「還沒做的事」時，**先花幾分鐘對著程式碼驗它**，再決定要不要做。

理論地基是 [[紀錄的腐壞]]：
> **一份紀錄與現實的落差，不會自己出聲。**

## 為什麼要有這一支——三輪的命中率

```
2026-09-06 第一輪   八筆   五筆與現實不符
2026-09-06 第二輪   兩筆   一筆推翻了一句「三條共用同一個前置」
2026-09-07 第三輪   一筆   那件事【三天前就做完了】，而 draft 還寫著「設計未決」
```

🔴 **六成**。而它們沒有一筆是「寫錯了」——全部是「**寫的時候對，而後來變了**」。

## 這把刀先問一句

> **「這句話是什麼時候寫的，而它描述的東西後來動過嗎？」**

⚠️ 而**不要憑印象回答**——印象正是那份紀錄本身。

## 步驟

### 1. 把那一筆的**宣稱**抄下來，逐字

不要改寫成自己的話。改寫會順手把它變成「我以為它在說什麼」，
而腐壞的位置經常就在那個差異裡。

### 2. 問它三個問題，而順序有意義

```
① 它指的東西還在嗎？        → grep 那個檔／函式／欄位／id
② 它說的數字現在是多少？     → 真的跑一次量測，不要看註解裡的數字
③ 它擋住的那條路，真的被擋住嗎？ → ⚠️ 這一問最容易漏
```

🔴 **③ 是命中率最高的一問**。標本：「上面**三條**未做的驗收共用同一個前置：
真的檔案，卡在 FSA 驗不到」——而其中一條走的是 `<a download>`，**根本不碰 FSA**。

> **一個「這幾條共用同一個前置」的判斷，
> 在沒有逐條驗過的時候，記的是【它們寫在一起】。**

### 3. 🔴 一次只驗一條——「這一批都是同一個情況」是最貴的假設

⚠️ 一份清單上的相鄰兩項，寫的時候可能相隔幾個月。

### 4. 分類，而每一類的動作不同

| 驗出來 | 動作 |
|---|---|
| **從來不存在**（量它的範例寫錯了） | 刪掉那一筆 ＋ 記一句「它為什麼看起來像一筆債」 |
| **早就完成了** | 🔴 贖回：反流 `history/`、收成一行里程碑，**並補上缺的轉變記錄** |
| **只在一個宿主／一種輸入下成立** | 那不是完成——把範圍寫進去，並蓋一條護欄盯著另一邊 |
| **前置已經解了** | 動工 |
| **前置真的還在** | ⏳ **把動工條件寫成可以 grep 的東西**，不是「等有空」 |
| **理由是猜測** | 去做那件事一次。⚠️ 猜的對象是**使用者**時特別容易錯 |

### 5. ⚠️ 更正要寫進紀錄，而不是只寫進這次的對話

一筆被推翻的宣稱，**留一個墓碑**（`🪦` ＋ 為什麼它當初看起來是對的）。

> **那個較寬的說法很吸引人，而下一個人很可能會再想到一次。**

### 6. 🟢 而如果那個數字重要——讓它住進護欄的基線

那是 [[紀錄的腐壞]] 說的**唯一有效的機制**：散文裡的數字沒有失效條件，
基線裡的數字有。走 [[build-guardrail]]。

## 這把刀不做什麼

- **不做「順手修掉」**——驗出來是一筆真的債，那是**另一次工作**，
  它可能要走 spec。⚠️ 驗證與清償混在一起，會讓驗證停在第一筆
- **不驗那些程式碼自己說得出來的事**（結構、歷史）——那些 grep 一下就有，
  這把刀針對的是**沒有 oracle 的那些**：意圖、前置、範圍、動工條件

## 自己的失效條件

⚠️ 這一支如果連續三輪**一筆都沒驗出來**，代表紀錄的品質已經改善到不需要它
——那時該退場，而不是留著假裝在把關。
