# 讓一顆命令式的積木定義退場

## 這把刀先問一句

> **「這一顆的形狀，宣告表達得完嗎？」**

答不出來 → **先看比對報表**（`npx vitest run tests/integration/audit-block-def-parity.test.ts`）。
報表把每一顆的落差逐項印出來：插槽、欄位、output、statement、顏色。

## ⚠️ 為什麼不能直接刪

命令式那份**沒有守衛**（`Blockly.Blocks['x'] = {...}` 直接賦值、後跑）
→ **使用者看到的是它**；宣告式那份有守衛且先跑 → **它躺著**。

> **所以「刪掉命令式」＝「換成宣告式」——那是一次行為改動，不是清理。**

而躺著的那份可能是**錯的**：spec 164 發現 `cpp_func_call` 與
`cpp_func_call_expression` 的宣告**完全對調**，而使用者看不到。

## 步驟

### 1. 看報表，判**哪一邊對**——用這一顆的語義，不是「哪一份比較新」

⚠️ 兩個方向都有實例：

```
cpp_break     宣告多了 nextStatement    → 命令式對（break 之後是不可達的程式碼）
cpp_var_ref   宣告只有死文字框           → 命令式對（它的下拉跟著工作區長）
cpp_func_call 宣告與另一顆對調           → 兩邊都錯
```

🔴 **我判反過一次**（把 `cpp_break` 寫成「命令式才是錯的」）。
**先問「這顆積木在語義上該長怎樣」，再看兩份定義。**

### 2. 補齊對的那一份

```
宣告錯了      → 修宣告（多數）
宣告表達不完  → 先補【機制】，例如 `field_dynamic_dropdown`、`builder: "variadic"`
              ⚠️ 補機制是另一件事，可能該是自己的一刀
```

> **不是「刪掉就降」——是「把對的那一份補齊，另一份才變成多餘的」。**

### 2.5 🔴 **先確認比對器沒有在指控宣告——也沒有在【不看】它**

spec 163→165 之間它**四次**說「宣告寫錯了」，而四次都是**比對器自己缺東西**：
膠囊標籤沒載 · `src/i18n` 沒載 · `field_multilinetext` 沒註冊 · `field_dynamic_dropdown` 沒註冊。
第五、六次是同一個形狀（建構子沒接上、`altLayout` 沒接上）。

> **比對之前，要先把【產品那側需要的每一樣東西】都備齊；少一樣，比對就會指控宣告。**

⚠️ 而它的代價是方向性的：**它會讓人以為「宣告式那條路走不通」**。

#### 🔴 第七次的失敗模式是**新的**，而它不會變紅（2026-08-26）

```
前六次   比對器缺一樣東西 → 【指控宣告】       → 報表上多一行，會紅
第七次   比對器【直接不看】那一類            → 報表上【少】一行，什麼都不會發生
```

`audit-block-def-parity` 的建置函式第一行是 `if (!def.message0) return null`。
而**用宣告式建構子的積木本來就沒有 `message0`**（形狀由建構子長出來），
於是它們被歸進「沒有 message0 或建不起來」那一桶——**而那一桶不進比對**。

> **一條護欄的能力邊界，如果剛好切掉它要驗的那一類，
> 它的綠燈就與「沒有人在看」等價。**

⚠️ 而這一類**正是這把刀的產物**：每退一顆命令式定義，就多一顆「只有建構子」的宣告。
也就是說：**這把刀用得越成功，那條護欄看得到的就越少。**

→ **機制**（散文擋不住第七次，`build-guardrail` 的教訓）：那條護欄要有一支
**入口斷言**——「用建構子的宣告有 N 顆，而它們必須**全部**進得了比對」。
`N` 錨在**合成量**（宣告了 `builder`／`branchList`／`paramList` 的顆數），
而它不會因為缺陷被修好而變小。

### 3. 比對護欄說「一模一樣」了，才刪

#### 🔴 **先問：這個差異，是不是這一刀的目的？**

這道閘假設「宣告是對的，只是躺著」。而第 1 步允許另一種判：**命令式那份錯了**。
那時宣告與它**本來就不該一樣**，閘永遠過不了——

```
差異不是目的   → 閘照舊：比對說一模一樣了才刪
差異【就是】目的 → 那不是「比對沒過」，是**一次行為改動**
                （這把刀開頭那句話已經說了：「刪掉命令式＝換成宣告式」）
```

**差異是目的時，驗收換成三樣**（缺一不可）：

1. **把差異寫下來**——哪一格、為什麼那一邊才對。寫不出來就是還沒判清楚。
2. **對照組**：來回轉換逐字相同（`declaration-change-parity`）＋ 全套綠。
   🔴 2026-08-26 抓到 `cin >> a;` 來回變成 `cin >> x;` 的就是它，不是型別檢查。
3. **開瀏覽器**，並且**釘死環境**（第 5 步）。

⚠️ **而「差異是目的」不是萬用鑰匙**：能修到一樣的就要修到一樣。
2026-08-26 有一顆的差異只是**啞輸入的名字**（`HEAD` vs `FORMAT_ROW`）
——那種要讓建構子能指定，不是拿這條出口繞過去。

#### ⚠️ 而「一模一樣」只在**這條護欄看得到的範圍內**成立

`cpp_raw_code` 比對通過**而它不能刪**：`loadExtraState` 會依 `degradationCause`
換顏色與 tooltip，**而比對只比「剛建好的樣子」**。

**刪之前多問一句**：**「它有沒有一段只在別的時機才跑的邏輯？」**
—— `loadExtraState`、`onchange`、`mutator` 都是那種時機。

##### 🪦 而它 2026-08-26 刪掉了——**問法要再往前一步**

它卡了三輪，而解法**不是**「讓宣告表達得出依 extraState 換視覺」。
拆開來看那是兩件事，而**兩件都不該由那顆積木做**：

```
套用視覺   面板本來就對【每一顆】積木在做（降級／信心兩段都在那裡）
           ——只有「認不得的那一段」留在積木自己身上
保存狀態   Blockly 對【沒有 save／load 鉤子的積木不留 extraState】（實測 `{}`）
           ——那是一個藏著的缺陷，不是這顆積木的需求
```

> **一個機制搬家的時候，留在原地的那一半會看起來像「它需要特別處理」。**

→ 所以上面那句「它有沒有一段只在別的時機才跑的邏輯」問完之後，
**再問一句「那段邏輯該由它做嗎」**。多半不該——而那時刪它是**便宜的**。

🟢 **`loadExtraState` 那一半，護欄已經會問了**（spec 166 的第五維）
——它比命令式 `saveExtraState` **真的會吐出的鍵**與宣告**表達得出的鍵**。
⚠️ 而 `onchange`／`mutator` **還是要人問**。

刪除時**留一個墓碑註解**（`🪦 …已於 spec N 刪除，理由是…`）——
下一個人會問「這裡本來有東西嗎」。

### 4. 順手檢查：注入契約裡有沒有變成孤兒的欄位

`setLanguageInputNames` 的 `arrayAccess`（163）與 `returnBlock`（164）
都是**唯一消費者退場後留下的孤兒**。

> **一個沒有消費者的注入欄位，會讓組裝點以為它還要提供那份資料**
> ——而那份資料從此沒有人驗。

### 5. 🔴 開瀏覽器看——**沒有任何測試在看標籤**

工具箱快照只比 id 與順序。所以：

```
① 明確切到那顆積木所屬的目標    ← ⚠️ 不釘死環境的話會誤判（見下）
② 貼一段真的會用到它的程式碼
③ 看【標籤文字】與【欄位型別】  ← 下拉要真的還是下拉，不是文字框
④ 切一次 Block Style           ← CLAUDE.md：JSON 名稱錯誤只在這裡暴露
⑤ 截圖
```

⚠️ **量測本身最容易出錯的兩處**（各踩過一次）：

- **環境沒釘死**：目標停在別的語言時，整段會降級成 `raw_code`
  ——症狀看起來像「你把它弄壞了」
- **拿著舊參照**：切 Block Style 會**重建工作區**，
  切換前存的 `ws` 之後量到的是一個已經不存在的東西
  → 寫成 `snap()` 每次現查

### 6. 基線是三份，一起更新並註明原因

```
tests/baselines/block-def-parity.json   落差數 ＋ hollowDeclaration
tests/baselines/neutrality.json         第二維（積木型別）
tests/baselines/dual-truth.json         兩處都有定義的數量
```

### 7. 🔴 落差歸零那天，**先確認母體沒有縮水**

2026-08-26 報表說「一模一樣 0 顆／有差異 0 顆」，而檔案裡還有 10 顆命令式定義
——其中 **7 顆兩份定義都有，而它們的宣告是空殼**（連 `message0` 都沒有），
於是比對器把它們**略過**。

> **「有差異 0 顆」不等於「清乾淨了」——那幾顆是從母體裡消失的，
> 而消失與沒問題長得一模一樣。**

`block-def-parity.json` 的 `hollowDeclaration` 逐顆指名它們。
⚠️ 兩個數字**必須一起看**：一顆的宣告從「有內容但不一樣」退成「空殼」，
會讓 `differ` 下降而看起來像進步。

### 8. ⚠️ 這顆積木的形狀，是不是別的地方在靠它分辨事情

`cpp_var_assign` 的 `NAME` 下拉退場（左值接點化）之後，
「讀的下拉列變數 ∪ 板子常數、寫的只列變數」這個區別**失去了它的載體**
——賦值的左邊現在裝的就是一顆讀取用的積木，於是學生選得到 `HIGH = 5`。

**5749 支單元測試全綠**，抓到它的是三天前寫的 e2e。

> **一個靠「你是哪一種積木」成立的區別，
> 在那兩種積木合而為一的那天會安靜地消失。**

→ 併掉一顆積木的形狀之前，`grep` 一次它的**型別名**與**欄位名**：
有人拿它當判準嗎？有 → 那個判準要先搬到別的載體上（多半是**位置**，
而位置的意思通常已經在 `traits` 裡宣告過了）。

## 明確否決

| 做法 | 為什麼不行 |
|---|---|
| 把宣告改成跟命令式一樣，讓比對變綠 | 那是假設命令式是對的——而它有時候是錯的 |
| 一次刪好幾顆 | 紅了無法歸因；而每一顆的判都不一樣 |
| 只跑測試不開瀏覽器 | **沒有任何測試在看標籤** |
| 直接刪「形狀差很多」的那幾顆 | 它們的宣告**真的表達不完**，刪了會壞 |
