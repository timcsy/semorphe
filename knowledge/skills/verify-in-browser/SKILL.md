# 收工前的瀏覽器驗收

## 什麼時候用

一刀做完、測試全綠、**還沒有人真的看過它**的時候。

⚠️ **與 [[diagnose-in-browser]] 的差別**：

```
diagnose-in-browser   已知有問題 → 先讀 console、量 DOM、做對照實驗
verify-in-browser     不知道有沒有問題 → 去看
```

**入口不同、順序不同，所以是兩支不是一支帶兩個模式。**

## 🔴 為什麼測試綠了還要開

專案實測，這三種缺陷**測試全綠而使用者一看就發現**：

```
新積木拿不到          忘了加進課程清單——可拿性護欄量不到（它只問「宣告了拿不拿得到」）
積木插槽不夠          液晶的建構參數只放得下第一個——lift 與 generate 兩側都綠
分類名不再描述內容    一格塞了 20 顆之後，「腳位與時間」不再是那格的內容
```

> **一個只在【某一條投影】上壞掉的缺陷，
> 任何不經過那條投影的測試都會是綠的。**

## 順序

```
1. npm run dev → 開新分頁 → ⚠️ 先清 localStorage
2. 切到要驗的目標／課程清單
3. 🔴 用【問的】列出工具箱內容，不要用眼睛數
4. 🔴 **打開每一個分類截圖，並拖一顆出來看**（見下面「第 4 步」）
5. 貼一段真實程式碼 → 轉積木 → 斷言【專屬身分】不是「看起來對」
6. 轉回程式碼 → 比對【形式一字不差】
7. 需要「使用者操作」才觸發的東西 → 真的拖曳
8. 截圖存檔給使用者
```

### 🔴 第 4 步——這一步 2026-08-21 才加，而它補的是這支 skill 自己的盲點

原本的 description 寫著「**它的價值全在『用問的，不用眼睛數』**」。
第 3 步（列舉）用問的是**對的**（①② 那兩個坑）——**而它被讀成了一條通則**。

那天使用者連續回報五件事，全部測試全綠、而我每一件都「用問的確認過」：

| 使用者看到的 | 問得出來嗎 |
|---|---|
| 工具箱裡找不到 | 🟢 第 3 步就會抓到——**而我問的是分類數，不是內容** |
| 顏色與同族不一致 | 🟢 `block.getColour()` |
| 工具箱該有三個入口只有一個 | 🟢 `getContents().length`——**而我先多一顆、再少一顆** |
| **少了 mutation（±）** | 🔴 除非你**已經知道**要找它 |
| **mutation 按鈕的位置與同族不同** | 🔴 **沒有任何 API 問得出它** |

> **`length` 答得出「有幾個」，答不出「長對了沒」。**
> **去了瀏覽器而不看畫面，等於把它當成另一個測試框架。**

🟢 **積木類的改動固定截三張**：

```
① 工具箱的【每一個】分類          分類數對 ≠ 內容對
② 拖一顆出來的樣子                欄位、按鈕、插槽——這一張只有眼睛看得出來
③ 同一顆積木在另一個語言／同族那側  一致性只有【並排】看得出來
```

### 第 3 步的做法

```js
// 走 production 的組裝函式，不要自己走 flyout
const tb = window.__app.callBuildToolbox()
new Set(tb.contents.flatMap(c => (c.contents||[]).map(b => b.type)))
```

⚠️ **而它有一個會讓你判錯的陷阱**（2026-08-19 撞到）：
工具箱的內容是 `課程清單 ∩ 已啟用分支`。只開根分支的話，
**深層的積木一顆都不會出現**——那看起來像「過濾把它們濾掉了」，
而其實是你沒開那些分支。

```js
function allBranchIds(n, acc=[]) { acc.push(n.id); for (const c of n.children||[]) allBranchIds(c, acc); return acc }
```

> **一個「東西不見了」的讀數，要先排除「你根本沒開它」。**

## ⚠️ 六個實際踩過的坑

| | 坑 | 症狀長什麼樣 |
|---|---|---|
| ① | 工具箱分類是 **toggle** | 連點兩次會關掉，而畫面看起來只是「沒開」 |
| ② | flyout 要捲 | 積木在畫面外（`y=733`），看起來像不存在 |
| ③ | **localStorage 會殘留** | 上一次的工作區狀態蓋掉你貼進去的程式碼 |
| ④ | 長腳本會 CDP 逾時（45 秒） | 設定／點擊／讀結果要**分三次呼叫** |
| ⑤ | 程式化 `newBlock` **不發事件** | 「使用者操作才觸發」的東西驗不到，必須真的拖曳 |
| ⑥ | dev server 要先起 | 改完程式碼要 **reload**，不是只等 HMR |

### 🔴 把一段程式碼灌進網頁版的編輯器——**打字是不行的**（2026-08-24，手做十次之後）

打字會被編輯器的自動縮排毀掉，而症狀是**它產生一段合法但不同的程式**：

```
你想貼          實際變成
if x > 3:       if x > 3:
    print(..)   print("big")else:      ← 縮排被吃掉、行被併起來
else:
```

⚠️ 而 `navigator.clipboard.writeText` 會**掛住**（權限提示），
`cmd+v` 則要那個權限已經給過。

🟢 **穩定的作法是合成一個 `paste` 事件**：

```js
const ta = document.querySelector('.monaco-editor textarea')
ta.focus()                                   // ⚠️ 有時要先用滑鼠真的點一下編輯器
const dt = new DataTransfer()
dt.setData('text/plain', code)
ta.dispatchEvent(new ClipboardEvent('paste', { clipboardData: dt, bubbles: true, cancelable: true }))
```

⚠️ **兩個附帶條件**：
- **貼之前先 `cmd+a`**，否則它接在既有骨架後面 → 出現**兩個 `main`**，
  而執行的是空的那一個（症狀：跑完沒有輸出）
- **改完程式碼會觸發 HMR reload**，reload 中途貼會沒反應——先等頁面穩定

### 🔴 不要觸發瀏覽器的原生對話框（`alert`／`confirm`／`prompt`）

它們**凍住整個頁面**，自動化工具從此收不到任何事件。
⚠️ 而這也是一個**產品的判準**：`window.prompt` 在 **VSCode 的 webview 裡是停用的**
——一個用它問問題的功能，在擴充裡是「點了沒反應」。
2026-08-24 因此做了 `src/ui/prompt-dialog.ts`（頁內對話框）。

⚠️ **⑦（2026-08-19 新增）**：`window.__app` 的方法名在某些橋接下會被遮蔽成
`[BLOCKED: Base64 encoded data]`。**那時就改用真的 UI**
——而那本來就是人工驗收該做的事，不是退路。

## 判準：什麼時候可以收工

**每一條負向觀察前面都要有一個正向錨點。**
「Uno 看不到那五顆」單獨不算數——要先證明「ESP32 看得到那五顆」，
否則你量到的可能是**整個工具箱沒組起來**。
