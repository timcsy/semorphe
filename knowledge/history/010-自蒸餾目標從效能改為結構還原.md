# 010：從「自蒸餾＝效能最大化」到「映射還原＝結構還原度最大化」

> 日期：2026-03-11

## 轉移

- **舊**：系統自舉優化 Topic 層級樹時，目標是**效能最大化**——學習者達到目標的速度最快 = 最好。類比 AI 自蒸餾優化參數。
- **新**：目標改為**結構還原度最大化**——映射越接近知識的內在結構 = 越好。同時引入**不可變原形（Static Prototype）**作為不隨迭代改變的參照基準。

## 為什麼變

效能最大化有一個內建的失效模式：**過度適應使用者偏好，偏離知識的客觀結構**。如果指標是「學習者多快通過」，系統會逐步演化出一條讓人感覺順暢但實際上繞過困難的路徑——把增生負荷（建立心智模型的有益負荷）也一併消除了。這與 CLT 的原意相反。

更根本的問題是它與「發現大於發明」的立場矛盾。如果語義結構是被**發現**的客觀秩序，那教學路徑也是——優化層級樹不是「發明更好的教學法」，而是「更精確地映射知識本來的結構」。目標一旦設成效能，系統就在發明；設成還原度，系統才是在發現。

**不可變原形**是為了防止自蒸餾漂移而引入的固定點：

```
不可變原形 ≡ 元件代數的路徑完備性
lift → render → extract → generate 閉合
  → 不隨 Topic 層級樹的優化而改變
  → 若某次迭代的結果違反完備性 → 回退（不是放寬約束）
```

配套的檢查點是三維錨定的直接應用：Protocol 對齊（不違反完備性）+ Data 驗證（學習數據不劣於前代）+ Agency 簽署（專家審查接受）。缺任一維度就拒絕迭代。

**關鍵差異**：AI 自蒸餾優化的是參數（Weights），趨近同一個目標；這裡優化的是結構（Structure），並利用這個結構管理自身的複雜度。

## 狀態

✅ 已採用（理論層）。**尚未實作**——自舉需要累積足夠的 User Context 學習數據才有意義。目前 Topic 層級樹是第 1 代：教育專家手動設計的初始映射。

同批修訂還把責任三分重構為三維互設模型（Protocol / Data / Agency 不是層級關係而是互設關係），見 [三維錨定](../concepts/三維錨定.md)。
