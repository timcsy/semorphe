# 169 · 宣告的是「層」，不是位置——而路線圖寫的「偏好」不夠

**日期**：2026-08-26

## 起點：同一件事寫在路線圖的兩個項目裡

```
vision.md:483   版面登錄表（viewId → slot）：面板宣告**偏好**不宣告位置
vision.md:655   slot 詞彙落地……面板宣告**偏好**不宣告位置
```

一個在「核心可獨立出貨」底下、一個在「版面」底下。**做一次關掉兩行**
——而分開看會以為是兩件事。

## 🔴 而「偏好」那兩個字不夠

`ui/layout/mobile-tab-bar.ts` 的四元素陣列上頭寫著順序的理由
（使用者 2026-08-24 逐字：「代表理解的不同層次……**不是誰比較重要**」），
而那是**註解**。

> **一個寫在註解裡的理由，擋不住下一個人在陣列中間插一格。**

而如果照字面做成「每個面板宣告自己的偏好」，那個有意義的排列會變成一場協商：

> **一份「各自宣告偏好」的機制，會把一個有意義的排列變成一場協商。**

## 做法：分成兩層

```
語義（這個系統的）   面板宣告【我在哪一層】     element · relation · space · state
                     順序由 LAYER_ORDER 決定    ← 封閉的列舉，不是字串
呈現（那個宿主的）   宿主決定「那一層長怎樣」   手機是圖示＋字；VSCode 是別的
```

> **一個宣告如果用了宿主的詞彙（`activityBar`／`panel`），
> 那它就只對那一個宿主成立。**

⚠️ `layer` 是**選用**的——一個不屬於任何理解層次的視圖（將來的設定面板）
不必假裝有，而那正是 `undefined` 該說的話。

## 🔴 而兩份從同一個詞彙長出來的東西，不會自動對得上

分頁列從 `LAYER_ORDER` 長出來，視圖各自宣告層——**沒有人保證兩邊對得上**，
而漏掉的症狀是**一個點了沒反應的分頁**，不是錯誤。

於是組裝點在登記完之後檢查一次，缺哪一層就出聲並指名。

**瀏覽器注入驗過**：拿掉 `flow-panel` 的 `layer` 之後重新整理，主控台印出

```
手機分頁列有這幾層，而沒有任何視圖宣告自己在那裡：relation
```
