# 283 — 一個結構上必為零的分子，與「做完了」長得一樣

**2026-09-26** · 第 245 刀 · 契約化的第一刀

[282](282-協定從一個主體變成三個而拆的過程量到兩件看不見的.md) 把協定拆成三個主體之後，
`/knowie-next` 判出下一步是**契約的第一刀**，而它的判準逐字是
[draft](../draft/2026-09-22-元件宣告的契約化.md) §十一之七：

> 第一刀是**【把既有的判定者接上去】，不是加一個新欄位**。

## ① 判定者的值是「種類」，不是工具名——而那是原則逼出來的

draft 原本列的是 `tree-sitter` ／ `blockly` ／ `reference:g++` ／ `cella`。
**那些是工具名，而這個欄位要住在 `src/core/`。**

```
P9 核心純淨性   core 不 import view      ⟹ blockly 不能寫進核心
P9 語言獨立性   拔掉 C++ 之後還要成立     ⟹ g++ 不能寫進核心
```

> **一個判定者的【種類】跨域成立；它的【實作】屬於那個域。**

⟹ 核心存七種（`grammar` · `renderer` · `equality` · `reference` · `runtime` ·
`formal` · `human`），閉集，加值是顯式動作；具體綁定走 `judgeBy`
（`array_at` 的 `reference` ＋ `judgeBy: "ubsan"`——**不是 g++，因為越界是
未定義行為而 g++ 照跑，拿它當參照會得到「沒問題」**）。

🟢 順帶把兩顆元件的 `oracle` 欄位改名成 `judge`——**那個欄位一直就是判定者，
只是叫了另一個名字。**

## ② 🔴 而護欄的第一版問錯了問題，抓到它的是它自己的自我否證聲明

填完預設之後，護欄問「有幾格沒有判定者」——**第一次跑：0 格。**

而工具沒壞：**加上預設之後，「有沒有判定者」結構上必為真。**

```
第 240 刀   分母是零的硬性零   它永遠成立
🔴 本刀      分子結構上為零     它永遠是 0
```

🟢 **抓到它的是那句寫在量測之前的話**：「如果『有判定者』的比例是 100%，
**代表工具壞了**」——它第一次跑就兌現了。

> **一條判準的數字若不可能變壞，它量的不是系統，是那條判準自己。**

⟹ 改問：**那個判定者【看過這一顆】嗎。**
