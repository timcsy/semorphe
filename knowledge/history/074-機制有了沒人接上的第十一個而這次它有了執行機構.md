## 一、指名的是我上一輪的交付

```
grep -rn "targetRegistry" src e2e   →   只有它自己，其餘 0 筆
```

11 個登錄表裡**恰好 1 個**是 0。判準不需要例外清單。

> **一條記在文件裡的規範，與一條沒有人遵守的規範，
> 在下一次違規發生時是同一件事——因為兩者都不會出聲。**

⚠️ 而 `vision:612` 說的「差一點發生」講的是**風格** `styles/c.json`
（那句對，風格確實接上了選單）。**目標自己沒有，而沒有人看得出來。**

## 二、🔴 而最貴的產出是一次誤診

開瀏覽器看到選 C 之後產出仍是 `#include <iostream>`。
判定：「顯式的 include 節點走元件自己的 `generate`，那裡沒問過風格」
——與 [history/072](072-target的兩個假設都倒了而它反而證明了target.md)§三 同族，
**聽起來完全成立**，於是我為它寫了程式碼。

**而 build 產物與全新啟動的 dev server，在沒有那個修正的情況下就已經是
`<stdio.h>`。** 那個 dev server 是我在好幾個編輯之前啟動的。

> 🔴 **一個開著沒關的 dev server，會讓「開瀏覽器實測」測到一個不存在的世界。**

⚠️ 而它**反過來限縮了** `experience`「重構後開瀏覽器實測」：
上一輪它救了人，這一輪它**製造了一個假缺陷**
——**而假缺陷比沒抓到更貴，因為我為它寫了程式碼。**

🔴 **而驗那個修正的注入證明也是假的**：`reuseExistingServer` 讓它測到舊 build
——那是 `experience`「e2e 測的是 build 產物」的**第二次命中**，
而那條的原文說「還原原始碼之後必須重 build」**寫得對而不夠**：
**重 build 了，而請求沒有打到新的那一份。**

## 三、而 SC-001 這次真的兌現了

```
spec 134   cpp.json 與 c.json 的 topic【同一個】→ 只省了選風格那一次
spec 136   c-beginner（179 → 92 顆）→ 選一次，而不是三次
```

⚠️ 而反目標成立：**選擇器數量 4 → 4**。
> **一個「收攏三個選擇」的機制，如果自己是第四個選擇器，它什麼都沒收攏。**

## 四、判準只涵蓋一半，而那一半是宣告看不見的

`requires` 推得出 59 顆函式庫層的，**而 `class`／`virtual`／`try` 一顆都推不出**
——它們**不需要任何標頭**。

> **判準的涵蓋範圍等於宣告的涵蓋範圍，而那兩件事很容易被混為一談。**

具名清單 35 顆 ＋ **兩道獨立交叉驗證**。⚠️ 而其中 9 顆是**該由推導抓到而漏宣告**的，
**正確的修法是補宣告**——本輪沒修（`requires` 是驅動自動 include 的資料，要驗行為）。
