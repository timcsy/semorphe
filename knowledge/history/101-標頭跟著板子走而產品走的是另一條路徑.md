# 101 — 標頭跟著板子走，而產品走的是另一條路徑

**日期**：2026-08-19 · **spec**：`150-board-library-headers` · **狀態**：完成

## 轉變

```
之前   Uno 的學生看得到、拿得到 WiFi 積木——而板子上沒有 WiFi
       D1 mini 的產出是 #include <WiFi.h>——編不過
之後   Uno／Nano 工具箱 219 → 212（wifi×2 ＋ pwm×4 ＋ touch×1 都關掉）
       D1 mini 的產出是 #include <ESP8266WiFi.h>，而積木上仍是 WiFi.h
```

**語義沒變，變的是投影**——`<WiFi.h>` 從來不是語義，語義是「這段程式要連無線網路」。

## 查證過的事實（每一列附上游）

| | AVR（Uno／Nano） | ESP32 全系列 | ESP8266 |
|---|---|---|---|
| WiFi | 🔴 核心沒有 | 🟢 `WiFi` | 🔴 沒有 `WiFi`，是 `ESP8266WiFi` |
| Servo | 核心沒有（IDE 附） | 🔴 核心沒有 | 🟢 核心裡有 |

來源：三個核心 repo 的 `libraries/` 目錄。

🔴 **Servo 量到了而【不在這一刀】**：三個核心都沒有 `Servo.h`，
IDE 附的那份支援 AVR／ESP8266，ESP32 要裝第三方。
> **「核心沒有」不等於「不能用」——那是一個【政策】決定，不是機械修法。**

## 🔴 而瀏覽器照出兩件測試沒看到的事

### ① 產品走的是【鷹架】那條路徑，而我改的是另一條

`program/generate.ts` 有兩條產出路徑：**鷹架**（有進入點模板）與
**legacy fallback**（沒有鷹架時）。第一版的替換寫在 legacy 那條，
**而測試沒裝鷹架，所以也走 legacy**——單元測試全綠，瀏覽器裡完全沒作用。

> **一個有兩條路徑的產出點，修其中一條的測試會綠
> ——而使用者走的是另一條。**

🟢 修法：替換器提到函式頂端，**三個產出點各套一次**
（鷹架的自動引入、鷹架的手寫引入、legacy）。
⚠️ 而**注入實測**顯示「自動引入」那個出口原本沒有測試覆蓋
——補了一個**沒有手寫 include** 的案例才紅。

### ② 一個下拉靜默改掉了學生的程式碼

貼 `#include <WiFi.h>`，而積木上出現 **`stdio.h`**。
`cpp_include` 的 `HEADER` 是 JSON 的 `field_dropdown`，清單 20 個標頭沒有 `WiFi.h`
——**Blockly 換成第一項，而沒有任何訊息**。

> **一個會把它不認得的值換掉的下拉，等於在使用者沒看的時候改掉他的程式。**

🟢 正解（`doClassValidation_` 把不認得的值加進選項）**早就在專案裡**
（spec 148 用過），只是原本只有命令式註冊的那幾顆在用。
現在**所有 JSON 下拉**都拿得到。

## 三個換標頭的問題，三段程式碼

```
toCHeader        這個標頭在 C 裡【叫什麼】       cmath → math.h
cIoHeaderFor     C 裡【什麼標頭】滿足這個需求     iostream → stdio.h
headerAliases    【這塊板子】上它叫什麼          WiFi.h → ESP8266WiFi.h
```

⚠️ spec 146 在這裡踩過一次（把第二個塞進第一個），所以這次**一開始就分開**。

## 一條護欄的判準被改寫（而不是它的意圖）

spec 147 寫著「兩塊 ESP8266 `provides` 必須是 `[]`」。加上 `wifi` 之後它紅了。
🟢 意圖是「**不得宣告 ESP32 才有的能力**」，而 ESP8266 **有它自己的能力**。
判準改成逐項點名（`ledc-pwm`／`touch` 不得出現）＋ 反向錨點（`wifi` 必須在）。

> **一條把「今天剛好是空的」寫進判準的護欄，
> 會在集合第一次合理長大的時候擋住它。**

## 已知缺口（明確不做）

- **反向不成立**：ESP8266 的產出經過一次 round-trip 之後，`ESP8266WiFi.h` 成為
  語義樹裡的值；再切回 ESP32 **不會換回 `<WiFi.h>`**。
  🔴 補「每塊板子列出所有別塊的標頭」**不 scale**——正解是「一個能力有一個
  正典標頭」，而那是更大的設計。
- **積木上顯示的仍是 `WiFi.h`**：與 `io_style` 同一個形狀（積木顯示概念，
  程式碼顯示投影）——而它在這裡看起來比較刺眼，因為那顆積木顯示的**就是一個標頭名**。
- **`ESP8266WiFi.h` 與 `WiFi.h` 的 API 差異**——這一刀只換標頭，沒有人量過更深的差異。
