## 為什麼變（只記跟 semorphe 有關的理由）

- **Q14**：交換語意樹，應用與 cos-mos 就得依賴 semorphe 的內部形狀（違反 cos-mos 衍生原則 3）；詞彙套件已是三方共用的純資料（原則 6），用它的結構當協定，真實不屬於任何一方。代價由 semorphe 付：多一層投影。
- **Q15**：`ub…` 前綴同時用在未定義與未指定行為，光看名字分不出；semorphe 的對應表（`src/core/verdict-diagnostics.ts` 的 `KINDS`）會過期，一份判決有多種問題時也容易歸錯。hole 是學生還沒寫完，歸成「系統還不會」就是 Q6 要避免的錯置（semorphe 指出）。
- **Q16**：今天真的出過事——Cella 的迴圈計數是「圈數＋進入次數」，semorphe 照舊定義去除，算成 0 圈且沒有任何錯誤（spec 205 的 D1，教訓在 experience「兩個執行器對『次數』的定義不同」）。

## semorphe 這邊的待辦（等 Cella 在判決 JSON 加上 class）

- 診斷改讀 class，`KINDS` 表退成「class 之內的細分文案」，不再決定歸類
- 🔴 **護欄**：沒有 class 的問題要**明說**（顯示「判決沒有說明類別」並帶原文），不得安靜地歸進某一類——今天 `KINDS` 之外的種類落到 `CELLA_OTHER`，嚴重度依判決推，那正是要拿掉的「接收端自己猜」
- termination 照實顯示「程式怎麼結束、停在哪一行」（`abort`、`uncaught`）
- incomplete（hole）不能跟「系統還不會」共用文案
- 詞彙結構 → 語意樹的投影：等 cos-mos 階段 3 立項時一起排
