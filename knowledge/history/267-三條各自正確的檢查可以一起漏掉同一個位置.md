# 三條各自正確的檢查，可以一起漏掉同一個位置

2026-09-20｜第 204 刀（瀏覽器驗收抓到的兩件事）

## 一句話

> **一顆積木「拿得到」不是一個性質，是一個【在哪裡】的問題
> ——而三條各自正確的檢查，可以一起漏掉同一個位置。**

## 事情

語料收尾三刀（201／202／203）做完，**7000+ 支測試全綠、e2e 441 綠、
語料四個面向零缺口**。開瀏覽器問使用者自己提的那個問題
——「相對應的積木是不是都有做」「實際的畫面是不是有漏掉任何積木」
——量到兩顆**只在進階軌缺席**的積木：

```
cpp:string_at    s[i]——最基本的字串索引。而 L2a 有【33 顆】字串元件
cpp:queue_back   q.back()——而 L2a 有 cpp:queue_front，進階軌還有一課「05-佇列與堆疊」
```

## 🔴 為什麼三層機構都看不見它

```
可拿性護欄（第十九條）  問「有沒有【某個】分類收它」  → 有（入門軌收了）🟢
studycpp-has-blocks    問「這顆身分有沒有積木」      → 有 🟢
課程清單快照            問「清單有沒有被改掉」        → 沒有 🟢
```

**三個問題都是對的**，而沒有一個問「**換一條軌之後還在不在**」。

⚠️ 而它對使用者是實的：`s[i]` 是進階題目的日常寫法，語料裡到處都是。
一個學生在進階軌寫 `s[i]`，程式碼那一側好好的、積木畫得出來，
**而他在工具箱裡找不到那塊積木**。

## 處置：一條單向的包含關係

進階軌的定位逐字是「**會 C++ 之後**」。所以：

```
🔴 cpp-advanced ⊇ cpp-beginner     學生切過去不得【弄丟】他已經會用的積木
🟢 反過來不成立                     入門當然可以少——那正是漸進揭露
```

實測：補上那兩顆之後，差集**剛好是 0**。
而護欄的反向錨點問「進階有沒有多出來的東西」（多 22 顆），
否則那條包含關係可能是一句空話。

⚠️ 驗過它會紅：把那兩顆拿掉，護欄**逐字指名它們**。

## 同一關的第二件：兩條各自誠實的修復，組合起來是兩條都讓開

```cpp
#define rep(i,n) for(int i=0;i<n;i++)
#define z -'0'
rep(i,2) x = x*10+(s[i]z);      整句掉進 raw_code
```

函式形那條修復會把整句**重解一次**，而那段文字裡還有 `z`
——解不乾淨就讓開（`ast-repairs.ts` 契約②）。

🟢 **而它是誠實的**：程式碼一字不差、積木上是一塊灰色的「直接寫程式碼」、
主控台指名那一行說「這一塊我還不會執行」、變數面板有值、可以改了再繼續。

> **兩條各自誠實的修復，組合起來的預設是【兩條都讓開】
> ——而那比其中一條猜錯好，所以它是對的預設，不是一個 bug。**

🔴 **而語料量不到它**：4 支用 `rep` 的不用 `z`，用 `z` 的那支不用 `rep`。

> **一份語料量得到「每一種寫法」，量不到「兩種寫法同時出現」。**

## ⚠️ 這一關我自己犯的兩個量測錯

### ① 把觀察到的相關當成因果，而且說出口了

切成英文之後程式碼從 `cout` 變成 `printf`，我先寫下「**切換介面語言改掉了
產出的 I/O 風格**」。而決定性的對照（重載、中文、什麼都還沒做）顯示
`io` **本來就是 `cstdio`**、風格本來就是 `competitive`。

> **一個「A 之後 B 變了」的觀察，在你還沒問「B 在 A 之前是什麼」以前，
> 它說的只有「B 現在是這樣」。**

⚠️ 而這支 skill 的參數裡**我自己寫過**「先確認 I/O 風格」——寫過不等於做過。

### ② 貼程式碼沒先 `cmd+a`，於是骨架把它包成兩層 `main`

坑清單上就有這一條。症狀在畫面上很明顯（`int main(){ … int main(){ … } }`），
而如果我只讀程式化的讀數就不會看到。

## 判準

- 問「拿得到嗎」時，**把「在哪裡」一起問**：哪一個主題、哪一條軌、哪一課
- 一族檢查全綠的時候，列出它們各自**問的是什麼**——三個對的問題可以留同一個洞
- 開瀏覽器的價值不在「再跑一次測試」，在**問測試沒有問的那個維度**
- 說因果之前，先量「在那之前它是什麼」
