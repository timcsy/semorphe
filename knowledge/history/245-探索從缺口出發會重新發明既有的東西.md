# 245 · 一次探索如果只從缺口出發，它會把既有的東西重新發明一次

**日期**：2026-09-17
**觸發**：三個互不相關的量測同時指向迭代器——語料的錯誤分族（46 支裡 ≈16 支）、
語料的方法直方圖（`begin` 33 ＋ `end` 30）、以及一個看不到原始碼的出題者（10 支裡 7 支）。

## 而探索報告的核心結論，被抄的那顆元件自己早就寫過了

我在報告裡花了一整節回答「迭代器是不是第三種指標」，結論是
**「它就是實體式指標，不發明第三種表示」**——而 `cpp:container_iter`
（2026-08-13 做的、已經在課程清單裡）的檔頭逐字寫著：

> **不為迭代器發明第三種表示。** 指標算術（`it + 1`）、解參考（`*it`）、
> 相減（`it - v.begin()`）在那個表示上全都已經能跑。

> **一次探索如果只從缺口出發，它會把既有的東西重新發明一次
> ——而重新發明出來的東西，與原來的那個【長得很像但不完全一樣】。**

⚠️ 線索一路都在：命名詞彙表的 `iter` 條目寫著
「`cpp:container_iter`（`v.begin()`／`v.end()`）……**哪一端是參數**」。
**我是為了查別的事讀到那一行才發現的。**

🟢 **判準**：探索的第一步不該是「語料缺什麼」，該是「**這一族已經有誰**」
——而問法不是 grep 身分（它有三類合法命中），是**問詞彙表與登錄表**。

## 真正缺的東西，與我報告寫的完全不同

| 症狀 | 根因 | 修法 |
|---|---|---|
| `for (auto it = v.begin(); …)` 整段掉進 raw code | **自動型別的宣告沒有宣告 `forLoopPart`**，而同族那顆一般的宣告有 | **一個宣告** |
| `++it` 把指標寫成一個 double | `toNumber(一串格子)` 回 1，加一之後寫回去 | 一條分支 |
| `it != it2` 恆等於「相等」 | 同上——兩個指標都變成 1 | 一條分支 |
| `find`／`lower_bound`／`upper_bound` | 方法名沒登錄，而 `find` **已經有主人**（字串的搜尋） | 一顆膠囊 ＋ 容器自己宣告 `associative` |
| `erase(位置)` 刪成全部 | 同一個方法名的第三條分岔 | 依引數種類分岔 |

🔴 **第一個最值得記，而它不是迭代器的問題**：

> **同一族的兩顆元件，一顆宣告了某個性質而另一顆沒有——
> 那個差別不會有人發現，直到有人寫出只有後者能表達的程式。**

而錯誤訊息指著整段 `auto it=v.begin()`，學生會以為是 `begin()` 不支援。

## 🔴 `toNumber` 壓平了幾種型別，就有幾個這樣的缺陷等著

`cpp:compare` 的檔案裡，字串那一段的註解逐字寫著：

> 原本一律走 `toNumber`，而 `Number('abc') || 0` 是 0——**兩個字串都變成 0，
> 於是 `==` 恆真、`!=` 恆假**。

**指標是下一個。** 而 `toNumber` 對一串格子回 1 是**刻意的**
（少了它，`while (p != NULL)` 對剛配好的節點是假，「整條 Linked List 的走訪一圈都不跑」）
——所以修的地方不是 `toNumber`，是**比較與遞增那一側先問「兩邊都是位置嗎」**。

> **一個把不同種類的值都壓成同一個數字的函式，
> 會讓每一個「拿它們互相比較」的地方同時失效——而每一處看起來都像自己的錯。**

## 反向迭代器：報告判「不做」，實作時改判「做」

報告的理由是「要在值上加一個方向旗標，**每一個運算子都要認它**」。
實作時發現那被高估了：**只有「往哪邊移」那一個地方要認它**
（解參考、比較、相減都與方向無關）。加起來是一個欄位 ＋ 一行。

而語料替我做掉另一半決策：`rbegin` 只出現在 3 支，而**每一處都是 `*s.rbegin()`**
——它們在問「最大的那一個」，沒有一處拿它走訪。

> **一個名字出現七次，不代表那是七次同一件事。**

🟢 最後兩邊都做了：`rbegin`／`rend` 成為既有那顆元件 `which` 屬性的兩個新值
（「哪一端是參數」本來就涵蓋得了它們），而**不做的代價會是靜默的**
——`++rit` 往後走的話，由大到小的走訪會安靜地變成由小到大。

## 護欄自己的三個缺陷（同一輪抓到）

① 🔴 **`GENERATE_BASELINE=1` 產出的東西，護欄自己不接受**：
   `component-move-parity` 產生時不過濾、驗證時只看 `cpp:` 開頭的
   ——重產一次，下一輪就紅，訊息說「搬家搬丟了 98 個 python 身分」。
   > **一個「重產基線」的模式，如果產出的東西護欄自己不收，那個模式是壞的
   > ——而它只在有人真的用它的那天才會被發現。**

② 🔴 **顏色護欄的「歸屬」是「第一個對得上的抽屜」**：而**函式**那一格為了收
   通用的方法呼叫列了 `(core)+containers`，於是每一顆容器積木都被判成屬於函式那一格。
   **那 50 筆既有的不一致全部是這麼來的。**
   🟢 做了對照實驗（換兩種顏色都是 51）才確定那一筆與顏色無關。

③ 我自己的：**基線的鍵名要從讀它的那一行抄，不要從失敗訊息的標籤抄**。
   我寫了一個 `真實身分數` 頂層鍵，而護欄讀的是 `scanned.trueIdentityCount`
   ——檔案裡多了一個看起來很合理而沒有人讀的數字，護欄照樣紅。

⚠️ 還有一個操作上的：**基線要單獨重產**。第一次我同時跑了三個測試檔，
其中一個會載入 Python 套件，於是基準錄進了不該有的東西。

## 抄既有的那顆，要先驗它

我抄了 `container_iter` 的顏色（`#4A90A4`），而**它自己就是那 50 個不一致之一**
——量出來 `containers` 這一格 **49 顆是 `#4C97FF`**，`#4A90A4` 只有 3 顆。

> **「照抄一顆既有的」有一個前提：被抄的那顆是對的。**
> ——`component-generate` 的 skill 逐字寫過這一句，而我還是踩了。

## 量到而這一刀不做的

🟠 `set<int> s{1,2,3}` 的大括號初始值被丟掉（size 0，而 `vector` 的可以）。
🟠 `new int(5)` 的初始值被丟掉（`*p` 給 0）。
   ⚠️ 兩者**語料 0 處、課文 0 處**——我的測試是自己編的。
   而它們是同一個形狀：**lift 把一個初始值整個丟掉，而執行時看起來像「預設值」**。
