## 主要機制：性狀

十五次以上的同一個處置疊出了一個新概念，詞彙地基寫在
[concepts/性狀](../concepts/性狀.md)。這裡只記**它改變了什麼既有結論**。

### 改變一：「碎裂」原本被當成一種病，而它其實是兩種

階段 6.5 的三個病是「碎裂／殼／條件性正確」，而碎裂被定義成
「一個元件的實作散在太多檔」。實測之後：

| | 症狀相同 | 處置完全不同 |
|---|---|---|
| **實作散落** | 就近性數字高 | 把實作剪回膠囊 |
| **被別人認得** | 就近性數字高 | **把「我是什麼」變成宣告** |

第二種**不是碎裂**——消費者有它自己的家，把它搬走是錯的。
而兩者在護欄的數字上長得一模一樣。

### 改變二：可搬性有六個條件，不是「切得出來」一個

搬家 skill 原本只講「怎麼剪」。實測補完的判準：

1. 五路都切得出來（工具的事）
2. lift 不與別顆共用一個不可分割的函式（**產出**單一）
3. 沒有別的共用檔還提到它的身分（**引用**單一）
4. 它有積木、因此有標籤（**沒有積木的元件膠囊契約沒有為它設計過位置**）
5. 五路實作不是另一顆元件實作的別名
6. 沒有一族消費者依它的身分分派（執行／產生／辨識三路各一個）

第 2 與第 3 的差別是這一輪最貴的一課：**產出單一不等於引用單一**，
而搬得動要的是後者。

### 改變三：`concepts/元件.md` 的五槽可能少一格

五槽講的是「這顆元件**會做什麼**」（lift / generate / render / extract / execute）。
性狀講的是「這顆元件**是什麼**」，而它是被 167 顆搬不動的元件逼出來的。

⚠️ **這裡不下結論**——性狀今天只在 C++ 一個域驗過，而五槽是跨域的模板。
要不要進五槽，等第二個語言或硬體域再說。

## 四次整批回退，而兩次的真因不在被搬的元件身上

| 批 | 症狀 | 真因 |
|---|---|---|
| OOP 六顆 | 三個消費者都指名 | **我自己**：批次中途 `git checkout` 把同批已剪掉的產生器一起還原 |
| ternary 五顆 | `x += 5` 辨識不出來 | `cpp:pointer_assign` 的 astPattern 宣告 `constraints: []`，**而它是假的** |
| if_else + 四顆 | 越補越多 | `ifGenerator` 是 `cpp:if` 與 `cpp:if_else` 共用的閉包（可搬性第 5 條）|
| var_declare | 類別成員名字全變成 `x` | `loadFromSplit` 的「第一個勝出」**沒有擋住「該贏的那個排第二」** |

> **回退整批比留一個半成品便宜**——而第四次不是為了紀律，
> 是因為那個半成品會**改壞使用者的程式碼**。

## 三次「順序是一個沒有被宣告的判別」

```
doc_comment vs block_comment   `/**` 也 startsWith `/*`，兩者優先權相同 → 靠陣列順序
pointer_assign vs var_assign_compound  兩者同報 0 條約束 → 靠陣列順序
loadFromSplit 的「第一個勝出」  註解擋住了覆寫，沒擋住「中性的排在變體後面」
```

前兩次的修法是**補上顯式宣告**（priority、constraints）；
第三次的修法是**讓順序不再有影響**（登錄時先把中性排到前面）。

> **「第一個勝出」只在「該贏的那個排第一」時才是規則，
> 否則它只是把順序偽裝成規則。**

## 順帶修掉的使用者可見缺陷

| 缺陷 | 誰抓到的 |
|---|---|
