# 068　護欄全綠，而三個缺陷一直在——量測能力的自我認知被推翻

> 日期：2026-08-16
> 觸發：使用者「**所以這帶來什麼訊息？**」
> 本檔記的是**這個專案對自己量測能力的認知變了**，不是交付了什麼。

## 轉變

```
old  這個專案的量測能力很強——45 條護欄、4175 支測試、基線只准下降
new  🔴 它量【我們說過的話】很強，量【現況】很弱
     而那三輪抓到的缺陷存在期間，護欄【全部是綠的】
```

## 一、三輪，而最有價值的發現一次都不是護欄給的

| 輪 | 計畫要做的 | 而量測發現的 |
|---|---|---|
| `126` | 修訊息、寫第二課 | 「漏分號會怎樣」**四次被記下沒做** → 有答案了；🆕 全形符號；🆕 **代號洩漏** |
| `127` | —（本來沒排） | 🔴 `vision` 說「需要型別資訊」→ **實測是一行**，爆炸半徑 = 1 |
| `128` | 驗 COOP/COEP | 🔴 **每個使用者都在向 Google 的 demo 伺服器要一張圖** |

而那三個缺陷是：

```
學生看到 RUNTIME_ERR_UNDECLARED_VAR: {"%1":"Cout"}   而不是一句話
score = 90;（忘了 int）跑得完並輸出 90                而 C++ 拒絕它
離線時 Blockly 的圖示會壞掉                           而沒有人會回報它
```

**在它們存在的整段期間，43～44 條護欄全部是綠的。**

## 二、而那不是護欄壞了

護欄量的是**我們宣告過的規範**。要求它抓到上面三筆，
等於要求一份規範涵蓋它自己沒想到的事。

> **護欄的價值在防止退步，探針的價值在發現現況。
> 一個只有護欄的專案，會非常穩定地維持一個沒有人檢查過的現況。**

⚠️ **而「愈擅長蓋護欄，愈危險」**：45 條全綠是一個很強的訊號，
而它說的是「**沒有退步**」，不是「**現況是對的**」。
一個團隊很容易把前者讀成後者。

## 三、🔴 而兩次錯的是我前一天親手寫的分類

```
「score = 90 需要型別資訊」        → 實測只需要已存在的符號表
「它屬於 6.7 第三個缺口那一族」    → 於是它繼承了那一族的阻斷（委派編譯器）
```

**一個沒有量過的成本分類，一旦寫進路線圖，就繼承了那個類別的所有阻斷。**

→ 已進 [experience](../experience.md)：
**在把一筆缺陷寫成「大／需要某某前置」之前，先量一次。**
⚠️ 而量完要**寫進驗收而不是寫成前提**。

## 四、於是這個專案的工具箱少了一格

```
護欄   有完整方法論 ＋ 一個 skill（build-guardrail）    45 條
探針   🔴 沒有 skill、臨時起意、【用完就刪】            這幾輪建 4 個刪 3 個
教材   有 lessons/ 與走查測試                          2 課
```

**我們把「防止退步」制度化了，沒有把「發現現況」制度化。**

→ 概念寫在 [執行機構](../concepts/執行機構.md)「量測工具有三種」，
含**拿哪一把**的判準與「探針與護欄怎麼分」。

⚠️ **探針 skill 是候選，而不在本輪決定**——`build-guardrail` 的成形花了
七條護欄與四次翻車，探針今天只有三次樣本。

## 五、⚠️ 而要誠實的反面

探針這三輪的高產出，**可能只是因為未量測的表面還很大**，而它會遞減。
**今天沒有辦法分辨「探針本質上高產」與「我們欠很多」**
——而分辨得出來的方法只有一個：**繼續跑，看回報率掉不掉**。

> **一個「這招很有效」的結論，在樣本數是三的時候，
> 與「我們剛好欠很多」長得一模一樣。**
