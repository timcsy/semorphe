# 198 — 執行追蹤不是投影，而護欄早就這樣對待它了

> 2026-08-31。動的是根公理**例子**裡的一個分類標籤，不是公理本文。
> 而它之所以能動，是因為**四件已經發生的事**同時指向同一個答案。

## 轉變

```
舊   x: 0→1   ← 行為投影（執行追蹤）        追蹤被歸類成第三種投影
新   x: 0→1   ← 情境維度的【觀測】          它不是投影
```

## 為什麼

### 論證：按 P1 自己的公式，它本來就不是投影

`concepts/投影.md` 的 P1：`view = project(structure, scope, viewType, viewParams)`
——一個**純函數**。而**追蹤需要「結構以外的輸入」才算得出來**。

> **語義樹決定的是一個【函數】，不是一個值。**
>
> ```
> 公理維度   語義樹 ↦ f : 輸入 → 行為       先驗、確定性
> 情境維度   執行 ＝ f(世界給的那組輸入)     後驗、經驗性
>            追蹤 ＝ 那一次套用的【觀測紀錄】
> ```

投影是把 f **換一種寫法**（資訊量相同）；執行是把 f **用掉一次**。

### 🟢 四件已經發生的事（回溯驗證，不是預測）

| 既有事實 | 這個分類怎麼解釋它 |
|---|---|
| `audit-behavior-error` 語料第一欄「不可判定（讀輸入／亂數）99 段」排除在分子外 | 那一欄就是**世界進來的地方**——護欄的實踐**早就**把執行當情境維度處理 |
| clang vs gcc 在 UB 上的分歧（macOS 1 筆、CI 0 筆） | **UB ＝ 語義樹在那裡沒有決定一個函數**；公理維度不完整，只有觀測說得出發生了什麼 |
| 追蹤沒有輸入就不可重現 | 觀測沒記下條件就不是觀測——經驗科學的形狀 |
| P1 的公式算不出追蹤 | 它是純函數，而觀測不是 |

**四件事，一個說法。** 而這正是「可以動」的理由——不是因為新說法比較漂亮，
是因為**舊分類解釋不了這四件，而它們早就在那裡了**。

## 被否決的兩個選項（墓碑）

`draft/2026-08-31-過程是一等公民.md` §三 原本擺出兩個讀法，**兩個都被否決**：

```
❌ 保守   「過程是元資訊，可丟」        解釋不了為什麼護欄要把它另立一欄
❌ 激進   「過程是真實，T 只是切片」    要動根公理本文，而 churn 該趨近零
```

> **它們都錯在同一件事：都預設答案在【公理維度】裡。**
> 而 `concepts/三維錨定.md:12` 早就寫著第三個位置——
> 「情境（Data）｜環境反饋與觀測數據｜**經驗性、後驗**」。

那也解釋了為什麼「真實還是元資訊」這個問法會卡住整整一天：**答案不在那條軸上。**

## 🟢 附帶推論：「過程可不可丟」也因此有了非任意的答案

過程是觀測 ⟹「一次觀測要不要留下來」⟹「要重現或要比較的時候才留」。
**而 `tests/baselines/*.json` 就是這個專案已經維護了 20 幾份的「被保存的觀測」。**

🟢 這繞開了原本擔心的 event schema versioning：基線不是事件流，是
**觀測的快照 ＋ 一段散文**。要補的只有「值的型別要容得下結構」。
