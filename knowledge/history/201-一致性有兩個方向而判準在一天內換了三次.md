# 201 — 一致性有兩個方向，而判準在一天內換了三次

> 2026-09-01。使用者在 VSCode 裡看著三個獨立出來的面板：
> 「現在是好了，只是**有標籤列跟工具列感覺很厚重**，不知道你能不能有一些
> 解決方法？可以來討論一下」。

## 這一筆記的是【判準的轉變】，不是那幾刀的交付

厚重是真的，而且量得出來：每一格有**兩條**列——VSCode 的分頁列（~38px）
與我們自己的頭（~30px）。而最上面那兩個**說的是同一件事**：

```
┌ Semorphe 流程 ✕ ┐            ← 分頁列：這一格是誰
│ 流程 ▾  ⤢自動排版  − 100% + │  ← 我們的頭：這一格是誰 ＋ 動作
```

⚠️ 積木那一格更明顯——它的列上**只有**「積木 ▾」，整條列為了一個已經寫在
分頁上的名字而存在。

## 轉變：判準換了三次，而每一次都是被推翻的

```
① chrome 屬於宿主，所以分岔是對的
   🔴 太寬——它可以正當化【任何】差異

② 不畫的理由只有一個：宿主已經做了那件事
   （使用者：「網頁版和 IDE 版如果不是非必要越接近越好」）
   ✅ 它當場否決了一個提案（見下）
   🔴 而它只管「與宿主」那一個方向

③ 與【自己】一致，優先於與宿主一致
   （使用者：「把積木的工具列加回來，面板統一好像更重要一點」）
   ⟹ `ControlKind` 的 `identity` 軸整個退場
```

> **一個判準如果只管一個方向，它會在另一個方向上給出自信的錯誤答案。**

## 🪦 被否決的選項（這一筆最有價值的部分）

### 甲｜面板不畫名字（`identity: 'hostTitleBar'`）

**做過，而且交付了**（commit `b26f49c7`）：積木那一格整條列消失，
第六十三條護欄還跟著多盯一條義務（宿主必須替每一種面板取名字且不得重複）。

**被 ③ 推翻**。理由不是「它沒效果」——它確實少了一條列——而是
**它讓我們自己的三格長得不一樣**，而那三格是同時出現在使用者眼前的。

⚠️ 而那個軸**兩個宿主都會填同一個值**（都是 `panelToolbar`）。

> **一個沒有人會填不同值的宣告軸，不是宣告，是雜訊。**

### 乙｜把流程的自動排版與縮放搬上宿主的標題列

**沒做**。它會再省一條列（流程那格），而 ② 那條判準當場擋掉它：
**VSCode 沒有提供自動排版與縮放**，搬上去的理由只剩「省 34px」與
「比較原生」——**而那正是 ② 要擋掉的那種理由**。

🟢 它們留在原地，兩邊逐字相同。

### 丙｜主控台／變數的分頁也上標題列

**沒做**，理由不同：那兩個是**內容導覽**不是動作，變成標題列的兩顆按鈕之後，
使用者會失去「這裡有兩頁」的暗示。

## 🟢 而最後真正解決問題的，是一個不需要判準的做法

四條頭本來在**四個地方各自定義**，長出了三個底色與三個間距：

```
.panel-head           #2d2d2d  gap 4  padding 2px 8px
.quick-access-bar     #2d2d2d  gap 4  padding 2px 8px
.bottom-panel-tabs    #252526  gap 0  padding 0
.flow-toolbar         #252526  gap 8  padding 6px 10px
.monaco-clipboard-bar #1e1e1e  gap 4  padding 6px 8px   ← 統一了三格之後才量到
```

收成**一份**定義之後，**網頁版與 IDE 版同時變薄，而且仍然一模一樣**
——它不需要回答「哪一邊該不一樣」，所以它比甲乙丙都乾淨。

> **一個沒有人決定過的差異，不是設計，是漂移
> ——而在動手處理「該不該不一樣」之前，要先把「不小心不一樣」清掉。**
