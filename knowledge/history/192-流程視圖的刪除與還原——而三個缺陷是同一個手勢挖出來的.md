# 192 · 流程視圖的刪除與還原——而三個缺陷是同一個手勢挖出來的

**日期**：2026-08-30
**前一步**：[191](191-骨架在流程視圖上是一句謊話.md)

## 轉折

使用者：「可不可以幫流程視圖加上刪除功能？包含節點和邊，還有還原功能」。

量出來的：`doUndo()` 就是 `blocklyPanel.undo()`——**流程視圖改的每一格都不可還原**
（實測：改一個變數名，按還原，程式碼一個字都沒退回去）。

> **一個編輯得動而還原不了的視圖，比一個唯讀的視圖更危險
> ——使用者會以為他隨時可以退回去。**

🟢 所以刪除與還原是**同一刀**：**一個不能還原的刪除，使用者按下去之前要想三秒；
一個能還原的刪除，他敢試。**

## 一、刪除的範圍是量出來的

把單一插槽裡的值拿掉，產出的東西**不一定合法**：

```
宣告的初始值  int total;      ✅ 合法
if 的條件     if () { }       🔴 壞的
算式的一邊    int a = + 2;    🔴 編得過而【意思變了】
```

分不出這三種，因為「這一格可不可以是空的」**沒有人宣告過**
——vision 債表的 `ParamSpec` 那一列。判準因此是**那一格會不會變成空的**：

```
語句插槽（body）        ✅ 刪——body 可以是空的 `{ }`
其他插槽而還剩 > 0 個   ✅ 刪——那一格不會變空
其他插槽而會變空        🔴 拒絕，並說出為什麼
```

⚠️ 而**業界怎麼做**（研究了一輪）：Blender／Blueprint／Shader Graph
**敢讓邊懸空，不是因為圖比較寬容，是因為每個輸入都有一個「沒接線時我是什麼」**。
🟢 所以我們的正解不是放寬，是**把預設值宣告出來**——那條債擋著一個具體的功能。

## 二、🔴 使用者第一次用就踩到：刪一顆值，整句不見了

「為何我只是把換行節點刪掉，就整個不見？」

```
語句的線   from = 父（main）    to = 子（那一句）    → 子是 to
資料的線   from = 值（換行）    to = 消費者（輸出）  → 子是 from ⚠️
```

我一律刪 `w.to.node`。

> **線的方向講的是「資料往哪裡流」，
> 而包含關係講的是「誰住在誰裡面」——兩者在資料線上是相反的。**

⚠️ 而**我原本的三支 e2e 抓不到它**：它們驗「刪語句」與「刪值被拒」，
**沒有一支點過資料線的 ✕**。

> **我釘的是我想到的那幾條路，而使用者點的是我沒想到的那一條。**

## 三、追它的時候挖出的另外兩個

**① 線上的 ✕ 點不到。** 節點畫在線之後，實測那條線的中點底下是 `fc-field-hit`。
SVG 沒有 z-index，順序就是圖層——所以 ✕ 收進一個**最後才貼**的圖層。

**② 而修好之後它變成一台誤刪製造機。** ✕ 貼在線上，於是滑過去的那一刻
它**正好彈在游標底下**：「想選那條線」的那一按直接刪掉了它。抬離 16px。

> **一個因為 hover 而出現、又出現在游標正下方的按鈕，是一台誤刪製造機。**

## 四、而診斷本身有一個轉折

真實滑鼠按 ✕ 毫無反應，**用 JS 直接派送 `click` 卻成功刪掉**。

> **一個「用 JS 派送有效、用滑鼠按沒效」的處理器，
> 說的不是它壞了，是它掛在一個不會發生的事件上。**

🔴 而 `flow-panel.ts:664` **早就寫著**「⚠️ 用 `pointerdown` 而不是 `click`：
拖節點時 `click` 不會發生」——**我讀過那一行，然後在同一個檔案裡犯了它。**

## 五、順手照出的兩個既有缺陷

- **流程面板一直在就地改控制器手上那一棵樹**（同一個物件參考）。症狀不是畫錯，
  是**歷史拍不到照**：「改動前」的快照拍到的已經是改動後。
  > **一個視圖如果就地改真相，那個真相就沒有「之前」。**
- **在流程視圖改任何一格，`using namespace std;` 就會不見**（程式從此編不過），
  而積木那條路不會。兩條路走同一支 `handleEditTree`，差別在**樹**：
  積木送的是剝過骨架的樹，走鷹架路徑由骨架宣告補回 preamble；
  流程送的樹有 `main`，走 legacy 路徑。根因再深一層——
  > **`using namespace std;` 只活在程式碼文字裡**（補丁器加的，從來沒被 lift 回樹）。
  > **一個只存在於某一個投影上的東西，在下一次「從真相重新投影」時就會消失。**
