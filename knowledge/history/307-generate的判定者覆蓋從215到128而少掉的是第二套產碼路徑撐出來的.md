# 307 · generate 的判定者覆蓋：從 215 到 128——少掉的 87 顆是第二套產碼路徑撐出來的

> 日期：2026-10-31（第 384～387 刀）
> 轉變：`src/core/component/judges.ts` 記「generate 那一路的判定者」覆蓋 215 / 349 顆，其中一半的證據是 `roundtrip-all`
> 的「Code generation coverage」——它對有 `codeTemplate` 的 101 顆跑 `TemplateGenerator`。而**產品從不安裝 `TemplateGenerator`**
>（`setTemplateGenerator` 在 `src/` 零呼叫）。拆掉這第二套產碼路徑之後，誠實的覆蓋是 **128 / 349**。

## 它還蓋住了一個使用者選得到的缺陷

`namespace_style: 'explicit'`（google、c 風格）在產碼端從沒實作：產生器寫 `vector`、`cout`，補丁器（正確地）不補 `using`。
課文 86 份 C++ 解答用 google 風格產回來，**70 份編不過**。沒有人發現，因為模板寫死了 `std::`，而測試走的是模板。
修法在補丁器的 explicit 分支加 `std::`（`languages/cpp/std-qualify.ts`，第 386 刀）：0 份編不過。

## 同一個形狀，那一天量到五次

`field-write`、`cpp/module.ts`、`identity`、`ComponentRegistry`、`TemplateGenerator`——都是「測試或護欄 import 一個產品走不到的模組」。
⟹ 立了一條護欄 `audit-tests-import-reachable`（第 387 刀）：測試 import 的 `src/` 模組必須是產品入口可達的，例外列名單附理由。

## 被否決的

- **把 87 顆的模板產碼補回產品路徑**（讓覆蓋回到 215）：那是把第二份真相轉正，而產品已經有膠囊自己的產生器——兩份會漂移。
- **只修 explicit 風格、留著模板**：模板會繼續讓 generate 那一路看起來比實際健康。
