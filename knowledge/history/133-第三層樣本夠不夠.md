# 133　第三層：樣本夠不夠

**日期**：2026-08-22 ｜ **交付**：第五十三條護欄（語料的形狀覆蓋）
**前一則**：[132](132-語料是我寫的所以它沒有我不會寫的形狀.md)
**觸發**：使用者——「我想要的是一個有系統的方法論，可以避免這件事情」

## 轉變：把「取樣」也放進執行機構

[132](132-語料是我寫的所以它沒有我不會寫的形狀.md) 查出來的是**一次**的洞
（語料沒有括號）。而問題是**下一個洞在哪**——而那個問題，靠再想像十段程式答不出來。

這個 repo 的量測分層，到昨天為止是兩層：

```
第一層  實作對不對    護欄            判準是【我們】定的
第二層  判準對不對    參照直譯器      答案是【第三方】定的（`python3`）
```

第二層是 [127](127-驗收改成跟真的直譯器對答案.md) 補的，而它治的是「三個零合起來
也答不出答案對不對」。**而它答不出「這段程式在不在語料裡」。**

```
第三層  樣本夠不夠    ← 這一則        全集是【第三方】定的（文法本身）
```

🔴 **全集刻意不是我們列的**：`node_modules/tree-sitter-python/src/node-types.json`
——那是**文法自己宣告**的節點型別。我們列一份的話，它會漏掉我們沒想到的，
而那正是這條護欄要治的病。

> **一個由我們列出來的「全集」，會與我們的盲點同形。**

## 而這個作法**不是新發明**——它是這個 repo 的家法，只是漏了一個取樣點

| 取樣點 | 全集 | 具名判定 |
|---|---|---|
| 積木在不在工具箱 | 宣告的元件 | 可拿性護欄 |
| 元件在不在課程 | 元件登錄表 | 「未收錄 MUST 不得是忘了」 |
| 接點宣告得完整嗎 | lift 產出的接點 | `declared-slots-decisions.json` |
| 回退是不是靜默 | 帶值的 return | `silent-fallback-decisions.json` |
| **語料** | **（沒有）** | **（沒有）** ← 就是這裡 |

> **語料是唯一一個「取樣而沒有全集」的地方，所以它是唯一一個
> 「零可以是【沒想到】而不是【判過】」的地方。**

## 第一次跑的結果

```
全集 122 個具體形狀｜98 段語料碰到 66｜沒碰到 56
  🔴 該補進語料          20   ← 棘輪盯這一欄
     語言有而這個工具不做 33   ← 具名豁免，各自帶理由
     Python 2 的語法      3
  ⚠️ 還沒判定            0    ← 硬性零
```

最刺眼的一筆：**`comment`**——我們有 `python:comment` 元件，
而 98 段語料**一段註解都沒有**。其次是 `escape_sequence`（沒有一個字串含 `\n`）
與 `typed_parameter`（AI 生的 Python 到處都是型別註記）。

⚠️ **反證**：把那三段公式語料拿掉，`parenthesized_expression` 就回到「沒碰到」裡
——**這條護欄會在使用者之前抓到它**。

## 判準（可以套到別的取樣點）

> **任何用「一組樣本」量出來的零，都要再問一次：這組樣本自己覆蓋了什麼？
> 而覆蓋率必須對著一個【不是我們定義的】全集量。**

而零的那一格必須是**判過的**，不是**沒想到的**——判定的詞彙是封閉的，
**刻意沒有「還沒想到」**。

> **從「我想到了什麼」變成「這個全集裡的每一格，我對它做過決定」。**
