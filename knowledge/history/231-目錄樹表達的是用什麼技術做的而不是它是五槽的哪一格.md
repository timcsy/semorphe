# 231 · 目錄樹表達的是「用什麼技術做的」，而不是「它是五槽的哪一格」

> 2026-09-13 · 使用者：「我還是覺得現在的資料夾和檔案結構沒有跟上模組結構，
> 請你幫我嚴格的檢查」，接著問「如果要考量之後還有硬體、外部的執行器、
> 更多形態的面板，那要怎麼做會更好？」

## 量到的六處脫節

不是看名字，是把 import 圖算出來。

| | 證據 |
|---|---|
| `core` ↔ `interpreter` 是一個**環** | interpreter→core 15 條，core→interpreter 4 條 |
| `core/` 根目錄是**抽屜** | 61 個 `.ts` 平鋪，而底下已經有 6 個子目錄 |
| `cpp/core` 與 `src/core` 撞號 | 前者是「核心語言」，後者是「引擎核心」 |
| 四個**零內聚**目錄 | `interpreter/executors`、`cpp/core/runtime`、`ui/toolbar`、`migrations` |
| 單檔目錄 | `sdk/`、`cpp/extractors/`、`cpp/renderers/`… |
| `src/panels/` 零實例 | 見 [230](230-一個資料夾如果說不出它與內容的關係.md) |

🔴 而全庫有 **131 個檔「住在 A 而只有 B 用它」**——`cpp/core/runtime/*` 幾乎全在裡面
（16 個檔、0% 內聚、60 處被 `components/` 用）。

## 🔴 而真正的發現是：「域」那一軸在程式碼裡不存在

`concepts/元件.md` 定過「域／語言／layer **三軸正交**」，並標注
「2026-08-24 起這三軸也是**出貨**的軸——於是它從內部不變式變成公開形狀」。

查證：

```
src/ 出現 domain              21 處，全是控制項的另一個意思（session/workspace）
'hardware' / 'software' 當值  24 處，全是工具箱的分類名
component.json 有 domain 的    0 個
```

**那一軸只寫在文件裡。** 而唯一的擴充點 `LanguagePack` 有一整族只有軟體域填得出的欄位：

```
grammar · createParser · liftPatterns · liftSkipNodeTypes · liftTransforms
programRoot · fileExtension · styleExceptions · createCodeShaping
```

一塊 Arduino 板子沒有文法、沒有解析器、沒有程式根、沒有副檔名。

> **一個擴充點如果它的必填欄位只有一個域填得出來，
> 那它不是擴充點，是那個域的建構式。**

⚠️ 所以硬體今天**不是「還沒做」，是型別描述不了它**。

## 而三件要加的東西是同一個形狀

| 要加的 | 它是五槽的哪一格 | 今天住哪 |
|---|---|---|
| 硬體 | 一整個**域**（新的接點與關係律） | 無家可歸 |
| 外部執行器 | **行為**（投影） | 寫死在 `src/interpreter/` |
| 更多面板 | **形態**（投影） | 登錄表在，而零實例 |

🟢 後兩個都是投影的實作，而這個專案**已經有一套機制在做那件事**——
`core/host/` 那十個埠（`code-view`／`console-surface`／`key-value-store`…）：
**核心宣告角色，宿主插實作。**

> **現在的目錄樹表達的是「用什麼技術做的」（`languages`／`interpreter`／`ui/panels`），
> 而模組結構的真正分界是「它是五槽的哪一格」。
> 前者在加第二個語言的時候還成立，加第二個【域】的時候就不成立了。**

## 這一輪做掉的三刀

### ① 環：四個型別搬家

`ExecutionStatus`／`ExecutionSpeed`／`RuntimeType`／`StepInfo`
從 `interpreter/types.ts` 搬到 `core/execution.ts`。

判準不是「誰先定義的」，是**誰在講這些字**：講 `ExecutionStatus` 的是匯流排與視圖，
直譯器只是它的**第一個實作**。

⚠️ 而分層護欄**看不到那個環**：`FORBIDDEN.core` 列的是
`ui／languages／components／vscode`，沒有 `interpreter`。

> **一張「誰不准 import 誰」的表，漏掉的那一格就是環長出來的地方。**

🟢 `interpreter` 加進那張表；`interpreter/types.ts` 原樣再匯出，
500 多處既有 import 一行都沒動。
🟢 這也是**外部執行器進得來的前提**：它要說得出同一組狀態，
而不必 import 內建的直譯器。

### ② `cpp/core` → `cpp/lang`

它的意思是「核心語言」（相對於 `cpp/std` 標準函式庫），那個區分是對的，
壞的是那個字與引擎核心撞號。改名之後與 `cpp/std` 對稱。162 個檔跟著改。

### ③ `Pack` 與 `LanguagePack` 拆兩層

```
Pack           id · name · order · declarations · install · topics · targets · categories
 └ LanguagePack  ＋ grammar · parser · lift · 產碼 · 風格 · 副檔名 · programRoot
```

⚠️ `targets` 留在 `Pack`：**軟體域填方言，硬體域填板子——同一格，不同域填不同東西。**

🔴 **第一百二十四條護欄 `pack-contract`** 釘住它，而它擋的不是今天，
是**拆完之後慢慢漂回去**：下一個人在 `Pack` 加一格語言專屬的欄位，
在硬體套件進來之前沒有任何東西會出聲。注入驗證過（塞 `grammar` 進 `Pack` → 紅）。

### ④ 面板登錄表接上了——而它停住過一次，所以這次有東西數著

五份 `src/panels/⟨每一種⟩/panel.ts`（code／flow／blocks／console／variables）
＋ `loadPanels()` 接進組裝點（健檢結果印出來）
＋ **「狀態」那一層的分頁真的去問登錄表**（名字與順序來自宣告，不再是兩處字面）。

⚠️ **`mount` 那一半沒搬，而那是有理由的**——理由是 `app-shell.ts` 自己留下的：

> 那四格的**建構**與各自的相依糾纏在一起……先把**格子**收掉，建構留在原地
> ——**一次抽象如果同時搬走「容器」與「內容」，它壞掉時你分不出是哪一半。**

🔴 而 spec 170 就是在那裡停住的，**而那個停住看不見**（零宣告、零呼叫者、
README 引用的測試不存在）。所以這次由 `mountedByShell` 說出來，
由**第一百二十五條護欄**棘輪數著。

> **一個分階段的搬遷，如果沒有東西數著還剩幾個，它會停在第一階段。**

### ⑤ `core/` 的 61 個平鋪檔分成四群

```
lesson/   12   課、章節、關卡、預測、步數、語意波、範例
blocks/   14   積木投影的共用件（含 toolbox-builder）
sync/      6   匯流排、同步、視圖契約、步進
storage/   3   存檔、版本升級、帶得走的匯出
根目錄    27   所有群都在用的地基（types／semantic-tree／identity…）
```

🟢 **分群之前先算過會不會製造新的環**：唯一一條回邊是
`toolbox-builder → block-spec-registry`，而 `toolbox-builder` 本來就屬於積木那一群
——把它一起搬，回邊消失。

⚠️ 根目錄**刻意留下 27 個**：把地基也塞進某一群，會讓那一群變成
「大家都要 import 的那一個」——那是另一種抽屜。

🔴 而搬家時編譯器**只抓得到一半**：`from '...'` 它管得到，
而 `import('...')` 的動態載入、以及測試裡 `path.resolve(..., 'src/core/x.ts')`
那種**字串形式的路徑**它一個都看不到（43 個檔）。
那是 `children → slots` 那一刀同一族的第五、第六種盲區。

## 還沒做的（順序有理由）

```
面板的 mount 搬進宣告      5 個，棘輪數著（第一百二十五條）
interpreter 收進埠後面     行為變成跟形態同級的一格
硬體 pack                 前面做完之後，它只是第三個 pack
```

⚠️ 而路線圖現在寫的是「Python 功能寫完 → 流程圖面板逼出 per-panel → ArduinoCAD 合流」，
③ 就是那個 per-panel——**順序一致**。①②③ 插在它前面的理由是：
硬體來的時候再拆 `LanguagePack` 會很貴（那時有三個實作，而第三個正在被寫）。
