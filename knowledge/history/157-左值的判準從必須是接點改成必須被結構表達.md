# 157 · 左值的判準從「必須是接點」改成「必須被結構表達」

**日期**：2026-08-26　**拍板**：使用者

## 轉變

```
舊（2026-08-25 蓋第七十三條時）   一顆會寫入的元件，它的左值【必須是接點】
新（2026-08-26 使用者拍板）        一顆會寫入的元件，它的左值【必須被結構表達】
```

使用者逐字：「**應該是左值必須被結構表達吧**」。

## 為什麼舊的那句話不對

它把**一個特定的表達方式**當成了規範本身。而 `obj + index` 兩格合起來
**也是結構**——`cpp:array_assign` 的 `obj: 'a'`（一個真的原子）＋ `index` 接點，
完整表達了 `a[i]` 這個左值，一個字都沒有被壓扁。

舊判準會把那四顆（`array_assign`／`array_2d_assign`／`map_assign`／`pointer_assign`）
判成違規，而**「轉換」與「退場」在它們身上是同一個結果**：兩條路都會失去
「把陣列 a 的第 [i] 格 設成 [v]」那顆**複合積木**，而它在三個課程清單裡。

> **一條規範如果只認得一種形狀，它會把「另一種同樣誠實的形狀」判成缺陷。**

## 🔴 而新判準不是放寬，它換了量測方式

舊的第七十三條**讀宣告**：`writesTo` 指到 `children` 就過。那對新判準沒有用
——`kind: 'identifier'` 只是一句**主張**，而 `cpp:var_assign.obj` 曾經
宣告成 identifier 而語料上裝著 `r.x`（第七十二條量到的）。

拍板當天實測，兩顆**當場漏**：

```
*(p + 1) = 1     →  cpp:pointer_assign { obj: "(p + 1)" }   🔴 一整個運算式
obj.arr[i] = 1   →  cpp:array_assign   { obj: "obj.arr" }   🔴 一個成員存取
```

⚠️ **第七十二條看不到它們**——語料裡沒有那兩種寫法。那正是它自己的基線
寫著的：「**語料乾淨不代表模型對：它代表語料是照著模型長的**」。

→ 所以第七十三條從**被動讀宣告**改成**主動探測**：餵一組刻意合成的左值
（名字 · 下標 · 二維 · 成員 · 指標成員 · 解參考 · 以及它們的**巢狀組合**），
看有沒有哪一格收到非原子的值。

> **「這一格是原子」是一句主張，而主張要有人去試著推翻它。**

## 代價與收穫

- 🟢 那四顆複合元件**留下**，而它們現在有一條**真的在驗**的規範
- 🟢 判準從「一種形狀」變成「一個性質」，於是它管得到未來的新形狀
- 🔴 而它抓到的兩筆是**真的缺陷**，舊判準用「反正要退場」把它們蓋掉了

## 回流（2026-08-26，使用者拍板）

八條教訓進了 [experience](../experience.md)：規範寫性質不寫形狀 · 主張要有人推翻 ·
落差也可能是「收不下」 · 宣告被另一份撐著 · 釘死的環境不只有語言 ·
快取該失效不該搬運 · 混合形狀會長出空的一半 · 靠位置的推斷會換答案。
