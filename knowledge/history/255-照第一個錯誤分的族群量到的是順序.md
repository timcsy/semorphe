# 255 — 一個照「第一個錯誤」分的族群，量到的是順序不是分佈

**2026-09-18／19** · 管線 189（I/O 操縱子）

## 一、這一刀的前提被自己的先決問題推翻

語料的錯誤清單長這樣：

```
2 支  RUNTIME_ERR_UNDECLARED_VAR ｜ flush
2 支  RUNTIME_ERR_UNDEFINED_FUNC ｜ setw
1 支  RUNTIME_ERR_UNDECLARED_VAR ｜ fixed
```

而「`flush` 在語料裡有幾支」用 grep 量出來是 **5 支**——於是這一刀被開成
「`flush` 那一族（5 支）」。

探索階段的第一題是「**這五支修完就跑得完了嗎**」，而逐支實測的結果是：

```
13_toj15.cpp      我們 OK      （參照編譯器自己編不過）
13_toj15_2.cpp    我們 OK
19_c123.cpp       我們 OK
19_e155.cpp       我們 OK
21_d518.cpp       我們 OK
```

**五支全部跑得完。** 它們的 `flush` 在一個「讀到輸入才進去」的分支裡，
而語料探針**餵了輸入**，所以那裡才走得到——空輸入下根本走不到。

> **一個「這一族有 N 支」的讀數，如果 N 是照【第一個錯誤】分的，
> 那它量到的是錯誤的順序，不是缺陷的分佈。**

⚠️ 而 grep 量出來的 5 支也不是那個意思：它量的是「檔案裡有沒有這個字」，
與「執行時走不走得到」是兩件事。**兩個讀數都對，而它們回答的不是同一個問題。**

## 二、而重估之後這一刀【變大了】不是變小

去查「`setprecision` 要改數字怎麼變成文字——那一段在哪裡」的時候，
發現**那一段本身是錯的**，而且是四個錯疊在一起：

```
                g++          我們（舊）
1e9             1e+09        1.00000e+9      ① 科學記號的尾數沒去尾零
123456789.0     1.23457e+08  1.23457e+8      ② 指數沒補成兩位
0.000012345     1.2345e-05   0.000012345     ③ 切換門檻用 JS 的不是 C 的 %g
999999.5        1e+06        1000000         ④ 指數在【四捨五入之前】算
2.5 → 0 位      2            3               ⑤ 平手時 C 逢五取偶、JS 逢五進位
```

而舊碼的註解逐字寫著「**直接沿用**」。

> **一個「直接沿用」的註解，說的是「我沒有比對過」。**

🔴 **母體不是一支語料**——是**每一支印大數或小數的程式**。
語料量到的那一支只是第一個被看見的。

### ⑤ 特別值得記住：它有一半的時間是對的

```
2.5  → 0 位   g++ 2   JS 3    🔴 不同
3.5  → 0 位   g++ 4   JS 4    🟢 一樣
0.35 → 1 位   g++ 0.3 JS 0.3  🟢 一樣（0.35 在二進位裡略小於 0.35）
```

> **一個只在「剛好一半」時才不同的規則，
> 測資裡沒有整齊的數字就永遠不會紅。**

## 三、`match` 不是正規式——而它讓正向錨點紅了

新元件的 lift 樣式寫了 `constraints: [{ field: '$text', match: '^(fixed|scientific)$' }]`。
而 `match` 在這個引擎裡是**比較方式**（`startsWith`），要與 `text` 一起用
——單獨寫一個正規式等於**沒有限制**，於是**每一個識別字**都被認成那顆操縱子。

症狀是正向錨點紅了（`cout << a << ' ' << d` 印出 `" "`）。

> **一個不存在的欄位不會報錯，它只會讓你以為那個限制生效了。**
> **而當一個新的檢查連【正向錨點】都紅的時候，先懷疑那個檢查。**

⚠️ 而 `builtin_constant` 那幾筆還多用了一個 `notDeclared: true`
——**擋使用者自己的變數**。`fixed`／`flush` 都是很普通的名字，
少了它的話 `int flush = 4;` 之後那個變數就被搶走了。

## 四、詞彙表逼出了更好的名字

探索報告定的名字是 `cpp:stream_flush`／`stream_setting`／`stream_number_style`
——而 `stream`／`setting`／`style` **三個字都不在詞彙表裡**。

去查表的時候才看到 **`io` 早就是主體**，而且 `cpp:io_sync`／`cpp:io_tie`
（`ios::sync_with_stdio`／`cin.tie`）**就是同一族**。

換成 `cpp:io_flush`／`cpp:io_mode`／`cpp:io_mode_number` 之後：
名字對得上同族、**只補了一個新詞**（`flush`）、而 `mode`／`number` 都是現成的。

> **一個逼你用既有詞彙的限制，會在你找不到詞的時候問你：
> 是這個詞不夠，還是這顆元件不該長這樣？**（`元件代數.md`）

而這一次的答案是第三種：**它該長這樣，只是我把它放錯家族了**。
