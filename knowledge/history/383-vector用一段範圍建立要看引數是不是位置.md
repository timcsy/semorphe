# 383 · vector 用一段範圍建立，要看兩個引數是不是位置

> 日期：2026-11-11（409）
> 轉變：`vector<int> v(a, a + 4)` 一律讀成「幾個、每個是什麼」，積木寫著「大小 a、每格填 a+4」。Cella 照型別判，所以執行結果是對的，只有積木畫錯。
> 改成：vector 與 deque 多一個接點 `source_end`、一個範圍形態（軸 `range_init`，和 403 的 set 同一條軸）。只有兩個引數**都確定是位置**時才放進 `source`／`source_end`；其餘照舊讀成大小與填值。

## 為什麼 set 不必猜、vector 要

set／multiset 沒有「n 個 x」的建構子，兩個引數只可能是一段範圍（403）。vector、deque 兩種建構子都有，而 `v(a, a + 4)` 和 `v(n, n + 1)` 的語法樹形狀完全一樣，只差 `a` 是陣列、`n` 是整數。

## 什麼算「確定是位置」

- `.begin()`／`.end()`／`rbegin`……一族的成員呼叫，或 `begin(a)` 這種自由函式
- 宣告成陣列、指標、迭代器的名字（lift 時記下的型別）
- 上面這些加減一個數、加括號

`a[0]`、`v.size()`、沒宣告過的名字都不算。認不出來的照舊當成大小與填值，那是原本的讀法，不會比今天更錯。`auto it = v.begin()` 記下的型別是 `auto`，所以 `v(it, v.end())` 目前還是讀成大小與填值。這種寫法語料裡還沒出現，先不處理。

## 沒做的

- `string s(p, p + 3)`：string 的兩引數建構子還有 `(const char*, n)`、`(n, ch)`，三種讀法，另一刀。
- 三個引數（帶配置器）：照舊。
