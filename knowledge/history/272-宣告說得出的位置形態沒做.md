# 272 — 一個宣告說得出、而形態沒做的位置

**2026-09-20** · 第 210 刀 · 分支 `210-getline-expression-form`

## 起點：瀏覽器驗收，不是測試

第 209 刀把 `while (getline(cin, s))` 修得**跑得動**了（執行印出 `[ab] [cd]`）。
而開瀏覽器貼那一段，積木上是：

```
當  ⟨直接寫運算式：getline(cin, s)⟩  持續執行      ← 一顆灰色的逃生艙
```

樹是**對的**（`cpp:loop_while` → `cpp:input_line`），產碼也是**對的**。
只有積木那一條投影退化了。

追下去：`cpp:input_line` 的 `component.json` **早就宣告了**

```jsonc
"positions": ["statement", "expression"],
"_positions_why": "getline(cin, s) —— 回傳 istream&，同上。…"
```

而 `forms/blocks.json` 只做了語句那一個 ⟹ 渲染在運算式位置**挑不到形態**
⟹ 退成 `raw_expression`。

> **一個宣告說得出、而形態沒做的位置，渲染時不會出聲——它會退成逃生艙。**

## 🔴 而沒有任何既有的檢查看得到它

```
五路完備性   🟢 render 那一路【有檔案】——它不問「有幾個形態」
可拿性       🟢 工具箱裡有那顆積木——它不問「在運算式位置拿不拿得到」
比對護欄     🟢 blockDef 與元件對得上——對得上的是【語句那一個】
```

而三條最像的路都是對的（`while (cin >> n)`、`while (cin >> a >> b)`、
語句位置的 `getline`）——**兄弟的綠讓這一顆不會被注意到**。
這與第 209 刀（執行器不回值）是**同一族的第二次**。

## 不是修一顆，是問整族

掃描「`positions` 含 `expression` 而沒有任何運算式形態」的元件：**17 顆宣告、8 顆缺**
（`cpp:input_line` 修掉之後）。

```
cpp:array_2d_assign · cpp:array_assign · cpp:container_append · cpp:container_erase
cpp:container_push  · cpp:map_assign   · cpp:print            · cpp:var_assign
```

⚠️ **那 8 顆不是八個「馬上要做」**——每一顆有兩種修法，而選哪一種要逐顆判斷：

```
補形態    那個位置真的會出現（`while ((x = f()) != 0)` 這種很常見）
改宣告    positions 寫寬了，那個位置其實不會出現 → 拿掉 expression
```

> **一條新規則落地時先拿它掃一遍現有的資料，而掃出來的是【起點】不是缺陷帳。**

🟢 落點：第一百二十六條護欄 `audit-expression-form`（棘輪，起點 8），
外加一條**指名的** `cpp:input_line`——棘輪只說「不要更多」，說不出「這一顆修好了沒」。

## ⚠️ 那支測試自己踩了一次「用名字形狀過濾」

`roundtrip-cpp-read-as-condition` 的第一版用 `/raw_code|unresolved/` 判斷逃生艙，
**而真正出現的那一個叫 `raw_expression`**（沒有 `cpp_` 前綴、也不含 `raw_code`）。
於是那條負向斷言在缺陷還在的時候**照樣是綠的**。

第二版列了一張清單，**而那只是把同一個問題往後推一格**（清單會過期）。
🟢 第三版問**產品自己那一份**：`core/component/slot-check.ts` 的 `isDynamic`。

> **一個用名字形狀過濾的探針，會漏掉同一族裡名字不像的那一顆
> ——而列一張自己的清單，只是把過期的時間往後挪。**

## 🔴 沒做完的一半：走一趟積木回來，第 208 刀的誠實閘失效

同一次驗收量到的（**這一刀沒有修**）：

```
貼進去            int x = 1 ⏎ cout << x;
lift 之後         var_declare cause=syntax_error raw="int x = 1⏎cout << x;"   產碼 🟢 誠實
render → extract  var_declare（metadata 整個不見）                            再產碼 🔴 int x = cout << x;
```

誠實閘（`honestly`）靠 `metadata.rawCode`，而**積木上存不下它**。

⚠️ 而它的修法**不明**，試過五種判準每一種都誤傷（見 [270](270-產出不得比使用者寫的少.md)
「而這把尺第一版是錯的」那一節）。三個方向：

```
A 讓積木存得下 metadata     一個新的存檔契約
B lift 時就整段降級成 raw_code   兩側都誠實，而「什麼時候降級」正是那個不明的判準
C 維持現狀                   積木本身顯示的就已經是錯的語義，程式碼只是忠實跟著它
```

🔴 **何時該修**：B 的判準想清楚的那一刀。釘子在
`tests/integration/codegen-honest-syntax-error.test.ts`。
