## 兩個要記得的選擇

1. **函式指標不新開元件，用 C 的抽象宣告子當型別文字。** `int (*f)(int, int)` lift 成「名字 `f`、型別 `int (*)(int, int)`」——那是 C 標準本來就有的寫法（`sizeof(int (*)(int))` 裡的那個），積木上型別與名字仍是兩格，產碼時把名字放回 `(*` 之後。
   formalize 的 `type()` 認 `R (*)(P…)` → `tPtr(tFunc{ret, params})`；呼叫變數走既有的 `eCallE`、函式名當值送 `eName`（Cella 解析成 eFunc）——這兩條本來就在（lambda 那時候建的）。
   只認一層：函式指標陣列、回傳函式指標、指向陣列的指標照舊整句照原文（P6）。
   被否決的路：另立 `cpp:func_ptr_declare` 一顆——它與變數宣告的差別只在型別長什麼樣，是**參數不是身分**（[084](084-零件不是身分是參數而那份draft擋的是執行不是積木.md) 那條）。
2. **union 另立元件，不併成 struct 的一個選項。** 欄位長得一樣（名字、成員槽、另名），而語義不同：成員共用儲存、一次只有一個作用中（C 讀別的成員是型別雙關、有定義；C++ 是 UB，Cella 記在 assumes）——一個積木一個語義概念（Sc3）。
   型別名靠新的登記 `definesUnion` → `tUnion`（與 `definesEnum` 對稱）；`typedef union` 走 341 的另名同一條路。

## 盲測抓到的兩個靜默改寫（都是既有教訓的新實例）

- `case X: { int b = …; }` 的大括號被展平 → 兩個 case 各宣告一次 `int b`，編不過。核心只把「父節點也是 compound」的 `{…}` 當獨立作用域，case 底下的不算——〈一個作用域少了，症狀不是「變數不見」而是「變數活太久」〉那一條的又一次。
- 結構裡的匿名 union 成員被編上名字 `x`（`union {…} x;`）——`'x'` 那一族預設值的又一次（〈判準：寫 `?? '預設值'` 時停一下問〉）。改成照原文降級。
