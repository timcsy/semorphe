# 233 · 一個欄位同時回答兩個問題

> 2026-09-14 · 起點是一次量測，而它翻出一個使用者按得到的缺陷

## 量到什麼

`component.json` 的 `slots` 一直寫著兩件事，而**沒有人讀**：

```
allowed   332 顆都有        只有【流程接線】一處在讀
min/max   41 個槽宣告了     讀者 0——`slotsOf` 連回傳都沒回傳它
```

注入 60 個違反 `min`／`max` 的樹：**產碼安靜 58/60、積木安靜 60/60**。
把一顆語句塞進只收運算式的 218 個格子：**兩側全部安靜**。

⚠️ `max` 那一族的症狀特別壞——**多出來的子節點不是報錯，是消失**。
學生接了兩顆積木，產出的程式碼只用了一顆，而沒有任何東西出聲。

> **一個宣告了而沒有人讀的型別，與沒有宣告是同一件事。**
> （`traits.ts` 的檔頭 2026-08-26 記過這句，而它只兌現了一次。）

## 🔴 而同一次量測翻出一個使用者按得到的缺陷

`flow/connect.ts` 拿 `roleOf` 當文法判準。而 `role` 的**實際**語意是
**產生器契約**——`roleOf` 自己的檔頭就寫著：

> 「產生器需要知道一個節點出現在語句位置時要不要補分號。」

C++ 裡 `i++`／`a = b`／`cin >> x`／`cout << x` 的 `role` 全是 `statement`
——**因為它們的產生器自己印分號**——而它們在文法上**都是運算式**。

實測 7 個真實世界合法的接法，**7 個全被拒絕**：

```
🔴 for 的 update 接 i++          🔴 while 的條件接 cin >> x
🔴 for 的 init 接 int i = 0      🔴 a[i] 的索引接 i++
🔴 for 的 init 接 i = 0          🔴 return 接 a = b
🔴 宣告串接 vector<int> v
```

**`for (int i = 0; i < n; i++)` ——C++ 最常見的那一行——在流程面板上組不出來。**

> **一個欄位如果同時回答兩個問題，它會在兩個問題的答案分岔的那一天
> 安靜地答錯其中一個——而答錯的那一個沒有名字，所以沒有人去查它。**

## 舊 → 新

```
role        產生器契約  「我自己收尾嗎」        ← 不動，它在那個問題上是對的
positions   文法位置    「我出現在這裡合法嗎」  ← 新的一軸
```

🟢 **預設是導出的**：沒寫 `positions` 就從 `role` 導，所以 332 顆裡只有
**13 顆**需要顯式宣告（那 12 顆「自己收尾的運算式」＋ `func_call`／`comma_expr`
那一類「不收尾而語句位置也合法的」）。

> **預設用導的，例外用宣告的**——反過來的話 332 顆都要填一次，
> 而那 332 次填寫裡會有一批是抄的。

其餘三個修正：

```
判定散兩份 → 一份     `component/slot-check.ts`；`connect.ts` 刪掉 20 行重複實作
「有具名就不看種類」  → 聯集（那判的是優先序，不是聯集）
declarators 收一個身分 → 收一個【族】（trait `declarator`，20 顆宣告）
```

## 量測工具自己的那 405 筆

第一版對 218 支學生程式報告 **412 筆**。逐一拆之後：

```
412
−405   量測工具自己的（漏了「運算式當語句用」、漏了 positions、漏了族）
  −7   降級節點被算成違反——那是動態型別（`?`），不是違反
   1   真的
```

> **一份「有 N 個缺陷」的報告，先問那 N 裡有幾個是量測工具自己的。**

🟢 而**剩下的那 1 筆是學生程式裡一句真的什麼都沒做的話**
（`AP325/3/3_10.cpp:16` 的 `cc[A[i]];`，而第 22 行寫的是 `cc[A[i]]++;`）。
合法的 C++，顯然漏打了 `++`，而編譯器最多給一個沒有人開的 `-Wunused-value`。

> **一條檢查規則最好的驗收，不是「它在我們的語料上是 0」，
> 是「它在別人的語料上剩下的那幾筆，每一筆都講得出為什麼」。**

## ⚠️ 它是報告，不是閘門——而那是刻意的

檢查結果走既有的**診斷**通道（`diagnosticsFromTree`），於是三側同時拿到；
`severity` 是 `warning`，`canExecute` 不看它。

🔴 理由是這個產品的核心承諾：「認不出來的語法不會被丟掉，也不會被猜」。
一個會**拒絕**的檢查器與那條直接衝突，而且這棵樹多數時候是**部分已知**的。

🟢 所以形狀是**漸進式**的：降級節點是動態型別（`?`），與任何宣告相容，
檢查只發生在**兩端都已知**的接縫上。

> **把「我不知道」算成「你錯了」的檢查器，量的是它自己的辨識率，不是使用者的程式。**

⚠️ 而這與型別論的 gradual typing 是同一個設計——**兩邊各自發明過一次**。
這一格是 2026-09-13／14 那場關於 DTT 與線性邏輯的討論的**第一個落地**
（討論裡排出來的階段 0～3，這一刀做完了 0 與 1 的一部分）。

## 收窄：`positions` 不等於「文法允許」

第一版的 `fitsSlot` 寫成「要語句的格子一律收運算式」，理由是 `f(x);` 合法
——而那讓 `cpp:literal_number` 也接得進迴圈身體（`0;`）。
技術上合法，教學上是一顆掉在那裡的積木，而既有的第八十條護欄當場紅了。

> **「文法允許」與「這一格該收」不是同一個問題。
> 前者是語言的事，後者是這個工具要不要讓學生做那件事。**

所以是**一顆一顆宣告**，不是整族放行。
