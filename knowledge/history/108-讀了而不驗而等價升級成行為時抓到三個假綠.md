## 🔴 第六次「宣告了而沒有人查它」，而這次的形狀不同

```
前五次   沒有人【讀】它
這次     讀了，而讀的人【不驗】
```

`componentLiftPatterns()` 用 glob 掃全部語言，把 61 筆樣式餵進 lifter
——其中一筆的 `patternType` 不在合法集合裡，於是**它靜靜地不生效**。

🔴 而 `lift-patterns.ts` 的檔頭**早就寫著這一課**：

> 「⚠️ 它同時是『**照抄已驗證的形狀**』的反例……**照抄之前要先問「它是不是同一類」。**」

**而我昨天正是照著 cpp 的樣式檔抄了一個不同類的東西。**

🟢 修法：把字面聯集提成執行期常數 `PATTERN_TYPES`，讓護欄**用同一份**去驗
——⚠️ **不在測試裡抄第二份**：兩份判準遲早會漂。

## 🔴 而這一刀最貴的教訓是【三個假綠】

### ① 我的護欄第二條誤報了五筆

「每一筆都要說得出它產生哪個概念」——第一版只問 `concept.conceptId`，
而五筆 `operatorDispatch` 的身分在 `routes` 的值裡。

> **一個「每一筆都要有 X」的判準，先要問【X 在每一種形狀裡都在同一個地方嗎】。**

### ② roundtrip 是「因為錯誤理由而通過」的

第一版直接拿**整棵樹**去 generate。而 Python 的 `module` 還沒有樣式
→ 根節點是 `unresolved` → 產出走的是**降級路徑的 `rawCode`**，
**與我的產生器一點關係都沒有**。

⚠️ 把 `fieldMappings` 整個拿掉，那一版**照樣綠**。

> **一個因為錯誤理由而給出正確結果的護欄，看起來與健康的完全一樣。**

🟢 修法：斷言改成「**那顆節點**的 `values` 收到了引數」＋「**那顆節點**產出 `print("hi")`」。

### ③ 只釘了「會報」，沒釘「不亂報」

拿掉 `constraints` 之後樣式會吃下**任何** `call` 節點——而只測 `print(...)`
的話**看不出來**。補了 `foo("hi")` 不得變成 `python:print`。

> **只釘一個方向的護欄，一個「什麼都認」的樣式也能通過。**

## 🟢 而修對之後，它立刻抓到一個真的核心缺陷

`print("hi")` 產出 `print("hi"\n)`：`raw_code` 的產生器**無條件補換行與縮排**，
而降級節點**會落在運算式位置**（`"hi"` 還沒有 Python 元件）。

⚠️ **積木那一側早就處理過同一件事**（`block-renderer` 的「語句位置的降級積木
出現在運算式位置時換成運算式版」）——**而產生器這一側沒有人接**。

> **同一個問題在兩個投影上各要處理一次，而修了一邊很容易以為修完了。**

🟢 修在核心（`ctx.isExpression` 時不縮排不換行），**C++ 的 4744 支一支不變**。

## 🔄 而上一則簡報有一句承諾被收回

我說這一刀可以讓 wasm「重新出貨」。**做不到**：`shipped-assets` 要求
「有人真的去要它」，而瀏覽器只有在**有 Python target** 時才會解析 Python。
🟢 所以 wasm 放在 `tests/assets/`——**測試讀得到、不出貨**。
重開條件：Python 有了 target。
