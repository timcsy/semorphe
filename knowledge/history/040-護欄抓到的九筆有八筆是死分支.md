# 護欄抓到的九筆，有八筆是死分支

**日期**：2026-08-10 ｜ **交付**：`specs/111`，第三十三條護欄分兩欄
**前一則**：[039](039-靜默回退掩蓋辨識歧義.md)

## 轉變：第一次跑紅了，不代表抓到的是東西

`specs/110` 的第三十三條護欄第一次跑抓到 9 筆，我**全部判為「靜默回退」**
並寫進基線。收尾時實測它們的**活性**（415 段語料）：

```
型別不符   if (x.type !== 'array')         上游辨識判錯身分時發生  → **會**發生
缺子節點   if (!v) / (nodes.length === 0)  語義樹本身壞掉時發生    → **0 次**
```

**9 筆裡 8 筆是死分支。** 唯一活的那一筆（`vector_size` 的型別不符）
就是 `s.size()` 那個缺陷，而它已經在 `specs/110` 修掉了。

> **一條數字永遠不動的棘輪，與一條沒有人跑的護欄是同一件事。**

而兩種條件**在語法上長得一模一樣**——都是「檢查失敗就回預設值」。
分開它們的不是寫法，是**什麼情況下那個檢查會失敗**：

| 形狀 | 檢查失敗代表 | 會不會發生 |
|---|---|---|
| 型別不符 | **上游把身分判錯了** | 會——`s.size()` 每次都走到 |
| 缺子節點 | **語義樹本身壞掉了** | 415 段語料 0 次 |

## 這是「一叢共用一個根因」的第二次，而判準是我兩天前寫的

`build-guardrail` 6.5 剛補的那條：

> 「宣稱『這 N 筆是同一個根因』之前，**在其中至少兩筆上分別驗過**。」

我把 9 筆判成同一種病。而**它們有兩種形狀**。

→ 補了一條更前面的判準：**新護欄的每一類命中，問「觸發它的條件在真實語料上
  發生過幾次」**。答案是 0 的那一類不要進棘輪。

## 而「不會發生」不等於「不該存在」

刪掉那 8 個防禦分支很誘人——它們永遠不執行。**但它們防的是未來的壞樹。**
處置是**留著，但記成一個可見的數字，不進棘輪**。

## 數字下降不是改善

```
型別不符   8 → 0     而 8 筆裡有 7 筆**只是換了一欄**
缺子節點   —  → 8
總和       8 → 8     ← 有斷言：只做重新分類時總和不變
```

`_meta` 寫清楚了。沒有那句話的話，下一輪會把它讀成「靜默回退幾乎清光了」。

## 順帶：擴到產生器的計畫被同一個量測否決

`specs/110` 收尾時排進清單第 5 項的「把靜默回退護欄擴到產生器」，
理由是「26 處，比執行器多三倍」。同一支活性量測跑產生器：**觸發 0 次**。

**連續兩輪，我推薦的下一步都被自己的實測否決。**
而兩次都是同一個形狀：**數到了東西，沒問那些東西會不會發生。**
