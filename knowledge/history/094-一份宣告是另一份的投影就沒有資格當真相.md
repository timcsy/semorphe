# 094 — 一份宣告是另一份的投影，就沒有資格當真相

**日期**：2026-08-19 · **spec**：`144-drop-declared-enum-values` · **狀態**：完成

## 轉變

```
之前   enum 屬性的候選值寫在【兩個地方】
       component.json 的 properties[].values     40 個
       forms/blocks.json 的 blockDef.args0[].options
       而【沒有東西在守它們一致】——既有的雙重真相護欄只比 input 名稱

之後   只剩 blockDef.args0[].options，而一條硬性零護欄守著不得再寫第二份
```

## 🔴 方向是被一個數字決定的，不是被偏好

```
blockDef.args0[].options   [顯示文字, 值]   234 個選項，其中 182 個顯示文字是 i18n key
properties[].values        [值]
```

**它們不是重複——`blockDef` 是嚴格超集，`values` 是它的一個投影。**

> **兩份宣告要合併時，先問哪一份是另一份的投影
> ——投影那一份沒有資格當唯一真相，不管它讀起來多像。**

「讓 `values` 當唯一來源」要**額外發明一套標籤慣例**補回那 182 個 i18n key；
「刪掉 `values`」不損失任何被讀取的東西。

## ⚠️ 而「零消費者」我量錯了——是規格裡的安全網接住的

我 grep 過 `src/core`、`src/ui`，宣告「零消費者」。⚠️ **沒 grep 護欄。**

`audit-param-spec` 第 ③ 條就在守 `values` 與下拉一致。刪完之後它紅了
——而規格的 Assumptions 寫著：

> 「⚠️ 而驗收要求 `npm test` 全綠——**若有隱藏消費者，它會紅**」

🟢 **那句話當場兌現。** 而護欄自己的註解也早就寫明了它的處境：

> 「第 ③ 條目前在真實資料上是**由建構保證的綠**——那 29 筆 `values`
> 本來就是從下拉抄出來的。**「綠」在這裡不代表檢查有效，只代表來源同一份。**」

**所以第 ③ 條隨抄件一起刪掉**——它守的是一份不該存在的東西。

## 🟢 而第 ② 條改得更強了

```
舊   default 必須在 properties[].values 裡     ← 比的是【抄件】
新   default 必須在積木下拉裡                   ← 比的是【真來源】
```

> **一個檢查如果比對的是抄件，它證明的是抄得對不對，不是那件事本身對不對。**

⚠️ 而舊注入帶著一個**真的病歷**（`cpp_malloc` 的下拉給 `int` 而產生器退路是 `int*`，
使用者選 `int` 產出不合法的 `(int)malloc(…)`）——**規則刪了，病歷搬到新注入上**。
新規則照樣抓得到，而且更準。
