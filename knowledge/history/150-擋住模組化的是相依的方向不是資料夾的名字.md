# 150 · 擋住模組化的是相依的方向，不是資料夾的名字

> 2026-08-24。使用者問：「有沒有可能把專案的資料夾目錄結構**按照之後要模組化的方式**重新整理？」
> 答案是**可以，但該做的不是搬資料夾**——而那個答案是前兩刀量出來的，不是想出來的。

## 一、證據：`dist-sdk` 是在**完全沒有重整目錄**的情況下出貨的

而真正擋路的兩件事，沒有一件是資料夾的名字：

| 擋住的 | 修法 |
|---|---|
| `import.meta.glob` 是 Vite 專屬 | 出貨打包好的產物——**零檔案移動** |
| `languages/<lang>/pack.ts` → `ui/…` → `blockly` → `jsdom` | **搬一個登記處**——修的是一條**邊** |

> **擋住模組化的是相依的方向，不是資料夾的名字。**

## 二、而使用者自己裝的觸發條件說「還沒」

`draft/2026-08-12-目錄結構對硬體的適配` §五 要求觸發**可機械判定**：
「`languages/` 有 2 個 scope，而 `components/` 有 3 個——**那個不對稱就是改名的觸發**」。

實測今天 **2 vs 2**，對稱。那個不對稱會在**硬體進來**時出現
（`components/` 多一個 `arduino/` 而 `languages/` 不會，**因為硬體不是語言**）。

🟢 所以這一刀把它變成**第六十條護欄的一支測試**——它今天綠，硬體進來那天自己紅。
理由是同一節記的那個教訓：「元件套件管理——連十二輪標熟而未升格」。

> **「等一陣子」如果沒有一個會自己響的鬧鐘，它就是那條教訓。**

## 三、做了什麼

**① 第六十條護欄：相依的方向。** 一張表（誰不准 import 誰）＋ 組裝點具名豁免（**附數字**）。
第一次跑抓到 **6 筆**。它會在 pack→ui 那條邊產生的**當下**抓到它，而不是等一個 Node 專案跑起來——**那條邊上次花了一天**。

**② 七個放錯地方的檔搬進 `core/`。** 判準是量出來的：`src/ui/` 裡**零 DOM、零 Blockly、零 ui/ import** 的檔案。
最刺眼的是 `sync-controller.ts`——**`src/sdk/index.ts` 對外 re-export 它，來源寫著 `../ui/`**，
也就是我們的公開入口在告訴外面的人「即時互轉住在 UI 層」，而那是假的。

**③ 一團兩份真相被拆開一半。** `core/types.ts` 的 `StylePreset`（`'cout'|'printf'`）與
`languages/style.ts` 的 `CodingStyle`（`'iostream'|'cstdio'`）是**兩份描述同一件事的型別**，
中間靠一個轉換函式——而那個函式住在 `sync-controller` 裡。

> **一個轉換函式住在哪一層，那一層就認識兩邊的詞彙。**

搬進語言那側（`detectStyleExceptionsForPreset`）之後，即時互轉的引擎不再認識
`'iostream'`／`'bits'` 這些 C++ 專屬的字。**剩下四個 UI 檔仍直接 import 那個型別**，
而根治要先答「這兩份型別哪一份是真的」——記在基線的 note 裡。

## 四、明確**不做**的

| | 為什麼 |
|---|---|
| `interpreter/` → `runtimes/` | 等第二個 runner（路線圖項已在） |
| `languages/` → `domains/` | 等硬體——觸發器會叫 |
| 深層巢狀 `domains/software/cpp/` | 為一個還沒有的第二個域付結構稅 |
| 拆成真的 package | 消費者還沒到場（`vision.md:513`） |

🟢 **而最重要的那一層早就模組化了**：`src/components/<scope>/<name>/`
——加一顆 `arduino:` 膠囊要改的檔案數是 **0**。
那正是 SDK 能在沒有重整的情況下出貨的原因。
