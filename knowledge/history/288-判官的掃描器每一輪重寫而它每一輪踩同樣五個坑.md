# 288 · 判官的掃描器每一輪重寫，而它每一輪踩同樣五個坑

> 日期：2026-09-26（第二次 `/knowie-judge`）
> 轉變：那些掃描規則從**一次性的 python** 變成 `tools/knowie-scan.py`。
> ⚠️ 它不是新功能——它是一條**早就寫下來的教訓第一次有載體**。

## 這一輪的讀數

一輪掃出七筆，而**前五筆是掃描器自己的缺陷**：

```
① 相對路徑沒有對著所在檔解析         → 80 筆假死連結
② 正則的 [^)\]] 吃掉換行             → 一次貪婪比對吞掉整區,漏判一個檔
③ grep 命中的是一份「路徑清單」       → 誤判 write-lesson 已退休
④ 不認得「history 斜線編號」前綴形    → 「反向邊斷了四天」這個頭條當場垮掉
⑤ 標記詞表沒有「🟡 狀態：」           → 兩份 draft 被誤報沒有升格標記
```

⚠️ **而第六個坑是在修前五個的時候造出來的**：把判準放寬成
「指名是標題的一部分 **或** 標題是指名的一部分」之後，
一個短標題（「元件」）會吞下任何名字，於是 `[[元件套件管理]]` 被判成解析得到。

> **一個放寬過的判準，它漏掉的東西與它抓到的東西長得一樣。**

## 🔴 它為什麼會重複發生

`knowledge/README.md` 在 **2026-08-19**（上一次判官）就寫下了判準：

> 「**一個掃描如果不知道自己在掃什麼命名空間，它的每一筆命中都要人再判一次
> ——而那正是它想省掉的工。**」

那一條**是對的，而且預測到了這一次**。缺的不是教訓，是**它的載體**：
命名空間的知識散在五支跑完就丟的 python 裡，於是下一輪從零重推。

> **一條教訓如果沒有載體，它下一次會以「新發現」的樣子回來
> ——而「新發現」不會觸發「我們是不是已經知道了」這個問題。**

## 載體長什麼樣

`tools/knowie-scan.py`（`--strict` 給 CI）。三個設計判準：

```
每一項都印【母體】          「乾淨」與「路徑寫錯了」在讀數上長得一樣
判不了的分到 🟡 要人再判     舊的「做完才退場」被下面的更正推翻時,兩句都還在檔裡
規則旁邊寫【它擋掉的實例】    否則下一個人會把它「簡化」掉
```

⚠️ 第二條是這一輪逼出來的：把 `通解與特解` 那種**已經被更正過**的檔報成 🔴，
會讓人去改一個已經對的東西。**判不了不等於有問題。**
