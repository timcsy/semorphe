# 064　量出來的東西不是我們要找的——而那個發現比原本要修的東西更有價值

> 日期：2026-08-14
> 觸發：使用者「**寫錯還能順利執行就是不合理的**」。
> 本檔記的是**兩個假設被量測推翻**，不是交付了什麼（那在 `5412f0c`／`51109d6`）。

## 轉變

```
old  那 27 段「只有我們跑得動」的程式，會告訴我們這個病有多大
new  🔴 22/25 是【語料片段缺標頭】——它量的根本不是這件事

old  把語法錯誤擋在執行前，就兌現了「寫錯不能跑」
new  🔴 閘門只擋得住【有標記的】，而四種寫錯的程式只有兩種有標記
```

## 一、第一個假設：那個現成的數字

`behavior-error.json` 有一欄 `onlyInterpreterRuns: 27`——「只有我們跑得動，
參照編譯器跑不動」。看起來正好在量「我們接受了 C++ 拒絕的程式」。

**把它拆開之後**：

```
19  use of undeclared identifier 'cout'    語料片段缺 #include——auto-include 刻意處理的
 3  no template named 'vector' / string    同上
 2  __gcd                                  環境（macOS clang 沒有它）
 1  main cannot be declared as global      🔴 唯一未知的
 2  unclassified
```

⚠️ [history/057](057-缺陷清單只包含被記下來的缺陷.md) **第三次**咬人
——`audit-behavior-error` 的語料來自**我們自己的測試檔的反引號字面**，
而那些多半是片段。

> **一個現成的數字如果正好在你想量的位置上，它更可能是巧合而不是禮物。**

## 二、所以直接量——而答案更嚴重

```
少分號（下一行 cout）    標記 1  →  丟錯，而訊息是「變數 x 未宣告」🔴 完全誤導
少分號（下一行 return）  標記 0  →  跑完，輸出 ""
大括號沒關               標記 0  →  跑完，輸出 "1"
亂碼 @@@                 標記 1  →  跑完，輸出 "1"
正常（對照）             標記 0  →  跑完，輸出 "1"
```

**四種寫錯的程式，三種順利跑完，一種給出誤導性的錯誤。**

⚠️ 那個誤導的最糟——已進 `experience`：
**上游沒攔住的錯誤，會在下游變成一則指著下游的正確訊息。**

## 三、第二個假設：閘門兌現不了那個承諾

閘門做了（三個執行入口、判準沿用 `DIAGNOSTIC_CAUSES`、三個注入都驗過）。
**而它只擋得住有標記的，而四種裡只有兩種有標記。**

> **一個閘門只擋得住它看得見的東西。**

→ 所以**瓶頸在辨識層**（[history/063](063-通道接好了而辨識那一層只認得某些形狀.md)
的第一個缺口），不在閘門。⚠️ 而 `vision` 階段 6.7 因此改寫：
**那三個缺口不是補充，是主體。**

⚠️ **而這句話寫進了四個地方**（spec、`canExecute` 檔頭、閘門註解、e2e 失敗訊息）：

> **不得宣稱「寫錯的程式不能跑了」，只能說「被辨識出來的語法錯誤不能跑了」。**

一句限定條件只寫在一個地方，下一個讀到的人只會讀到其中一個。

## 四、而型別那一半在動手前就被推翻了

spec 把「接收者型別的局部檢查」估成中等成本。查證後**是三件事**：

```
① 元件宣告「我的接收者要是什麼型別」   0 / 25 顆容器方法有
② 一張「變數 → 宣告型別」的表          不存在
③ 接收者是【字串屬性】不是接點          既有架構債（概念代數「屬性的結構化邊界」）
```

🔴 **而 `v.push_back(x)` lift 成的是 `cpp:container_push`——一顆刻意型別無關的元件。**
所以就算給那 25 顆加宣告，**使用者原本舉的那個例子也不會被涵蓋**。

> **硬做會產出一個漏掉使用者原話的版本——而那比不做更糟，
> 因為它看起來像做了。**

## 五、⚠️ 而檢查點是有用的，因為它被寫成了檢查點

`tasks.md` 的 T012 逐字：

> 「**T012 是檢查點，不是任務。** 那 27 段量出來的『程式不合法』數字若是 0，
> **停下來**——而必須在 spec 記下『這個病比想像小』。」

**數字不是 0（25），照字面它應該直接往下做。** 而寫成檢查點逼我去看那 25 筆
的**內容**——那才是發現。

> **「先量再修」如果沒有把「量完要停下來看」寫成一個步驟，
> 它會退化成「量一下，然後照原計畫做」。**

## 六、一個過程上的錯

還原注入時 `git checkout` 把**還沒 commit 的新函式**一起掃掉了，
而 build 因此失敗、preview 服務舊產物、注入②那次**沒有真的驗到**。

→ **先 commit 再注入**。而這與
[experience](../experience.md)「e2e 測的是 build 產物」是同一族：
**還原的單位要與被還原的東西對齊**。
