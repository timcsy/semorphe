# 410：C++ → Python 在函式裡改全域變數要寫 `global`（451）

**之前**：`int g = 0; void f() { g = 5; }` 換成 `def f():` 底下一句 `g = 5`。Python 看到函式裡有指定，就把 g 當成新的區域變數，所以 C++ 印 5、Python 印 0，**兩邊都 accept**，是靜默失真。`g++`、`total += x` 換成 `g += 1`、`total += x`，Python 先讀一個還沒有值的區域變數，丟 UnboundLocalError。`cin >> n` 讀進全域變數也一樣。450 量 map 時發現。

**之後**：
- **問印出來的 Python，不問元件**。Python 的作用域是看 Python 的文字定的：函式裡有 `g = …`、`g += …`、`a, g = …`、`for g in …`，g 就是區域變數。所以 `func_def` 先把本體印成 Python，再掃這幾種行裡出現的全域名字，在本體第一行補 `global g`。這樣不必知道哪一顆元件會印成指定（`cin >>`、`++`、`+=` 都自然涵蓋），也守住就近性（不點名別顆元件）。`g[k] = …`、`g.append(…)` 改的是物件裡面，不必寫。
- **全域變數**由引擎在頂層數一次：有名字、有型別、不是函式（沒有 params 槽），一句宣告多個名字的在 declarators 裡。契約多一個 `isGlobal(name)`。
- **參數與全域同名**：參數本來就是區域的，不寫 `global`（寫了反而是 SyntaxError）。
- **一個名字一行**：`global a, b` 是合法的 Python，而 Cella 1931 判它 untranslated。改成一行一個名字（已告訴 cella）。

**照實保留的兩種**（Python 一個作用域裡同一個名字只能是全域或區域其中一種，C++ 可以用區塊遮住）：
- 函式裡另外宣告了與全域同名的變數。
- main 裡宣告了與全域同名的變數。main 攤平到頂層之後，它的區域變數就是 Python 的全域變數，別的函式讀到的會是 main 那一個（C++ 讀到的是全域那一個）。這也是之前就有的靜默失真。
