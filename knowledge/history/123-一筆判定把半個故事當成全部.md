## 轉變：一筆「合法」的判定被推翻

第三十三條護欄（靜默回退）不自己下結論——它排順序，判定寫在
`tests/assets/silent-fallback-decisions.json`，**由人做**。其中一筆是：

```json
{
  "key": "src/components/cpp/input/execute.ts#1qoepsc",
  "signal": "raw === null → if (raw === null) return { type: 'int', value: 0 }",
  "decision": "合法",
  "reason": "輸入耗盡（EOF）時回 0——C++ 的 cin 失敗語義就是不改變目標值。…"
}
```

**這句話沒有錯，而它只是半個故事。** 它答對了「EOF 時回 0 是不是合法的」，
於是那一行被結案。**它沒有問的是「格式不符時呢」**——而那一側，
本專案吞掉壞掉的 token、給變數一個 0、**繼續讀下一個**，
`while (cin >> x)` 餵 `1 abc 3` 因此多跑兩圈而不出聲。

> **一筆判定的有效範圍，是它實際問過的那個情境，
> 不是它所在的那一行。** 而判定檔記的是行，不是情境。

## 這一刀改了什麼

- 判定 `#1qoepsc` 作廢（它的程式碼已不存在，護欄自己報了「判定過期」），
  換成兩筆，各自寫明**問的是哪個情境**
- 護欄加第四種形狀「**失敗傳遞**」：條件讀的是一個**已經記錄下來的失敗**，
  不是「東西在不在」。`compatible['失敗傳遞'] = ['合法']`——它不可能是防禦性的
- `missingChild` 22 → 19 是**這三筆移欄**，不是少了三處回退。
  兩欄總和的斷言正是為此存在，而它這次說話了

## 順帶暴露的一格

基線的 `scanned` 欄早就漂了（`fileCount` 176 → 244）——Python 那批元件進來時
掃描範圍變大，而**沒有任何斷言看那一欄**，所以沒有人出聲。

> **一個記在基線裡而不被斷言的數字，是一個看起來有人在看的數字。**

今天重產基線時一併修正。⚠️ 而「要不要替 `scanned` 加斷言」**沒有決定**
——它每加一顆元件就會變，斷言它等於把基線變成噪音來源。**記在這裡待判。**

## 同一族的前一半：`spec 173`（2026-08-20，當時沒有留下紀錄）

這一刀的前一天，Python 的 `input()` 修的是**同一句話的另一半**：

- 它用 `ctx.io.read()` 而**不等使用者**——瀏覽器裡按下執行，提示印出來了，
  程式當場拿空字串跑完
- 而「已經沒有輸入了」這件事**沒有自己的錯誤碼**，`UNRECOGNIZED_CODE`
  （「這一段程式我看不懂」）在兼差當它用。使用者看到的訊息是
  **「我看不懂這段程式」**，而程式沒有一個字看不懂

> **一個錯誤碼一旦兼差，畫面上那句話就會在某些路徑下是假的
> ——而它讀起來跟真的一樣有把握。**

處置：新增 `RUNTIME_ERRORS.NO_MORE_INPUT`（Python 在此丟 `EOFError` 的位置）。

⚠️ **C++ 那一側【不】丟錯，而那是對的**：`while (cin >> x)` 讀到底就是靠
輸入耗盡終止的，丟錯會炸掉最常見的慣用法。
**兩個語言在這裡本來就不同，把一刀複製過去才是錯的。**
