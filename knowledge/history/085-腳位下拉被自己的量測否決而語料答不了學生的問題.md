## 那個出口條件

競品調查的 draft 裡，提案①後面我自己寫了一句：

> ⚠️ 而①要先量「腳位打錯」在語料裡發生過幾次

**不量就做，就是照著別人的答案抄。**

## 量的結果

```
140 段語料 · 597 處追得到值的腳位使用 · 四類錯誤 0 筆
  ① 腳位號超出板子範圍                 0
  ② analogWrite 用在沒有 PWM 的腳位        0
  ③ 只能輸入的腳位被當輸出（ESP32 34–39）    0
  ④ 接快閃記憶體的保留腳位（ESP32 6–11）     0
```

⚠️ 而偵測器**驗過**：四類注入都會報、兩個對照組不亂報。**0 是量到的，不是漏掉的。**

## 🔴 而 0 答的不是那個問題

那 140 段是**AI 生成的**。LLM 寫 Arduino 會用教科書腳位（LED 接 13、PWM 接 9）
——**因為它的訓練資料就是那些**。

> **一個量測的效力，上限是它的樣本來自誰
> ——一份沒有學生寫過的語料，量不出學生的錯誤。**

## 而「別人都做了」為什麼不算證據

四家裡三家有板子相依的腳位選單（Mind+ 的 `_menus/` 一塊板子一份）。
⚠️ **而它們是單向工具**：下拉對它們是純粹的輸入輔助。

對我們**還多一件事**：貼進來的程式碼如果用了不在選單裡的值，
**那個值不得被改掉**（見 `style`／`decl_type` 的教訓：
不記形式的 round-trip 會改掉使用者的檔案）。

> **同一個功能，我們的成本比較高，而收益未經證實。**

## 重開的條件

🔴 **「有真實的學生語料」，不是「又想到它了」。**
而那支探針（`tests/probes/pin-validity.test.ts`）**留著當回歸線**
——學生語料進來的那天這個 0 會變，**那才是訊號**。

## 順帶更正的一處過期

`vision` 的「符合性清償」寫著 **12 → 11**，而實際基線是 **1**
——第四十六條護欄（投影遺失）逼出的八個補插槽修法，讓符合性從相反方向一起降。

⚠️ 而**最後那一筆有一個矛盾還沒查**：`slot-roundtrip-first-week` 的 US2
（`int a, b, c` 的其餘變數不得消失）**是綠的**，而符合性說 `declarators`
走完 render → extract 之後不見了。**兩條護欄的答案不一樣**
——照 [065](065-兩條護欄從相反方向量同一件事.md)，先問哪一條在說謊，不要直接修。

## 這一則為什麼是 history 而不是 experience

它記的是**一個提案從「看起來該做」變成「否決」**，而理由可查證、可重開。
⚠️ 而教訓那一半（「量測的效力上限是樣本來自誰」）**另外反流到
[experience](../experience.md)**——兩邊都要有，因為
**下一次會想起這條教訓的人，與下一次想重開這個提案的人，不是同一個人。**
