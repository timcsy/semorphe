# 350 · 規格消歧試驗第一版——題目可以有不只一種讀法，系統告訴老師學生的程式和哪一種一致

> 日期：2026-11-08（spec 218，worktree `semorphe-352`）
> 轉變：一份課文題目只有一份參考解答與一組固定的輸入輸出——學生寫出「另一種合理的讀法」就被判錯，老師看不出是題目的問題還是學生的問題。
> 改成：題目可以宣告候選解讀（`interpretations`），每個解讀一份解答；系統產生一批情境，學生的程式與每份解答都交給判決，回報一致的解讀與第一個不一致的情境；老師在課文頁點選題意，之後只照它判。
> 決定：使用者 11-07 定要做（經 cella-main → semorphe-main 轉達）；第一版 C 與 Arduino、純前端、重環境由 cos-mos 定。11-08 由 knowie-next 升進路線圖、照 speckit 一路做完。設計理由：[draft/規格消歧試驗](../draft/2026-11-07-規格消歧試驗——模糊的題目與候選解讀.md)。

## 四個選擇（與被否決的路）

1. **判決由呼叫端注入**（`Judge = (tree, scenario) => Promise<RunOutcome>`）。比對器住核心、不碰 DOM／檔案系統／提供者——cos-mos 的 Node 批次讀不到瀏覽器的 worker，兩個宿主要跑同一份（P9）。
   瀏覽器的 Judge 也放在核心（`makeCheckJudge`，只依賴 `CheckRequest`）：第一版放在 `providers/cella/`，而 app.ts 原本一個提供者都不 import——UI 直接依賴提供者會讓分層退步。
2. **情境種類由領域套件登記，核心不認得任何一種**。C 的標準輸入（從語意樹的讀取順序產生，原本只存在於測試輔助，搬進產品）、Arduino 的板子時間序列輸入（判決請求多一格 `boardInputs`）。護欄量「核心裡不得出現種類名字」。
3. **解讀的解答檔名 `<題目>~<解讀>.<副檔名>`**，並把 `solutionFor` 收緊成只認 `<題目>.<副檔名>`。草稿原本寫 `<題目>.<解讀>.<副檔名>`——要靠副檔名清單才分得開，脆弱。
4. **Arduino 示範題從「按一下切換」改成「按鈕怎麼接」（外接下拉／內建上拉）**。切換要用到指定與邏輯運算，按鈕課之前都還沒教——硬放會讓解答的用字護欄紅、課文的元件清單與課文程式對不上。接線的分歧是 Arduino 初學者真的會遇到的，而且只用已教的元件寫得出來。

## 量到的

- C 示範題（讀到 0 停／讀到結尾停）：三種學生程式比出 {zero}、{eof}、{}；沒宣告解讀的既有題目照舊是對錯（退化測試）。
- Arduino 示範題：三種學生程式比出 {pulldown}、{pullup}、{}；比的是序列埠輸出與結束時輸出腳的電位——不比腳位變化的時間戳（行為相同的兩支程式差幾微秒很正常）。
- 兩個宿主同結果：測試的 Judge 與產品的 `makeCheckJudge` 比出一模一樣的結果；瀏覽器那一側由 e2e 走完（並排、點選、重新整理後還在、照被選的判）。
- 長測試全套 8478、e2e 343 綠（全套那一輪紅 2 支：C → C++ 的護欄把 `max~eof.c` 當成沒有題目、而且要求它一行都不留——修成認得 `~` 前面的題目 id、用到 scanf 回傳值的照第一刀的規則允許保留）。
- Node 冷啟動一位學生約 3.4 秒；**瀏覽器那一側的 SC-005（10 秒內）還沒量**（記在 `specs/218-spec-disambiguation/quickstart.md`）。

## 順手找到的

- 讀取排程原本只認得 `cin`：`scanf` 的引數在 `args` 槽，於是 C 程式一律被當成「沒有輸入」——搬進產品時補上。
- `for (; x != 0; scanf(…))` 更新格裡的 scanf 今天照實降級成原文（raw_expression）——讀取排程看不到它；另排一刀。
