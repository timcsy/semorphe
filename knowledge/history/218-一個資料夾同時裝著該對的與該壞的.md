# 一個資料夾如果同時裝著「該對的」與「該壞的」

**日期**：2026-09-07 · **路線圖**：課程的第六刀之二「拆輪子的曲線」（除錯那一半）

## 轉變

```
舊  題型只有一種：arrange（把打散的積木排回去）
新  ＋ debug（把壞掉的程式修好）——起點住在 starters/，與 solutions/ 分開
```

## 為什麼

blocks→text 的系統性回顧（2026-09-05 查證）逐字：

> 直接翻譯的工具把積木與程式碼並排顯示——對【對映】有幫助，
> 而它們往往**沒有處理**從拖拉到【**打字與除錯**】的概念轉變。

而「除錯」那一半在這個 repo 幾乎是免費的：**診斷系統早就在了**
（紅字、波浪、修復建議），**裁判也在了**——缺的只是**一段壞掉的程式**。

## 🔴 而它為什麼不能與參考解答放同一個資料夾

```
solutions/   該對的   🔴 有一條 e2e 真的去跑它們，驗它們跑得出宣告的答案
starters/    該壞的   而它要的正是【跑不出】那個答案
```

> **一個資料夾如果同時裝著「該對的」與「該壞的」，
> 那麼任何一條對它的檢查都必須先問「這一份是哪一種」
> ——而那個問題的答案不在檔案裡。**

⚠️ 混在一起的話，那條 e2e 要嘛放寬（於是它守不住正解），
要嘛誤報（於是有人去把壞的改成對的）——**而後者會安靜地毀掉那一題**。

## 🟢 而 e2e 補的那一支，驗的是相反的方向

```
參考解答    跑【得】出宣告的答案   不然裁判會對做對的學生說他錯
壞掉的起點  跑【不】出那個答案     不然那一題已經是對的
```

> **一題「修好它」如果它的起點本來就是對的，
> 學生按一次執行就過關——而他什麼都沒學到，也不會有人發現。**

⚠️ 兩支共用同一段流程（`Exercise` 與同一套比對）——
🔴 **兩份流程各寫一次的話，其中一份遲早會走到另一份不會走的路上。**

注入驗過：把起點改成正解 → 那一支當場紅。

## 第一題除錯題選了什麼

`cpp-beginner/10-重複` 的 `ex2`——一個**差一錯誤**：`n < 5` 而不是 `n <= 5`，
於是 1+2+3+4 = 10 而不是 15。

🔴 **刻意選一個「編得過而輸出不對」的錯**：語法錯有紅波浪指著它，
而這一種要他自己看出來。draft 逐字：
「預期 5 而看到 4，**那一瞬間就懂了什麼叫差一錯誤**」。

⚠️ 而 `seedDebug` **刻意不先驗「這段程式真的壞掉」**——
一段編得過而輸出不對的程式**也是**除錯題，而且是比較難的那一種。
**壞在哪裡不是我們要分類的東西**，由 `check` 去判他修好了沒。

## 🪦 而「打字」那一種刻意還沒進來

研究說的是「從拖拉到**打字與除錯**」，而這一刀只做了除錯。

🔴 **理由**：「他真的敲了那些字」今天**驗不出來**——編輯來源的計數是
per-lesson 的，不是 per-task。加一個 `kind: 'type'` 只會是版面建議的別名。

> **一個沒有機制的題型宣告，是一個標籤——而標籤看起來像功能。**
> （`concepts/執行機構.md`）
