# 270 — 產出不得比使用者寫的少

**2026-09-20** · 第 208 刀 · 分支 `208-honest-syntax-error`

## 起點：一個只在【一條投影】上說謊的節點

一段解不乾淨的程式，兩條投影今天的表現是分開的：

```
執行那一側   canExecute 讀 metadata.degradationCause → 按鈕按不下去   🟢 誠實
程式碼那一側 產生器不讀它 → 印出一棵殘缺的樹                          🔴 說謊
```

而「說謊」有三種形狀，拿七種輸入量出來的：

```
漏分號（下一行是宣告）  int x = 1            → int x = 1;           🟢 順手補回去
漏右大括號              int main(){ …        → 補上 }               🟢 順手補回去
語句位置的亂碼          x @@ 2;              → x @@ ⏎ 2;            🟢 字都在
引數位置的亂碼          f(x, @@)             → f(x, , @@)           🟢 字都在
──
漏分號（下一行是 cout） int x = 1 ⏎ cout<<x; → int x = cout << x;   🔴🔴【另一支程式】
括號運算式裡的亂碼      (x @@ 2)             → (x)                  🔴 弄丟
宣告初值是亂碼          int x = @@@;         → int x;               🔴 弄丟
```

🔴 **最後那三種裡最糟的不是「弄丟」，是第一個**：`int x = cout << x;`
**編得過、看起來合理、而意思完全不同**——使用者寫的那個 `1` 與那句輸出都不見了。

## 判準不是「有沒有語法錯誤」

前四種**也**有語法錯誤，而它們的產出是**對的**。所以一根舊釘子寫的
「修法是原文照抄」是**不能做的**——它會把「補一個分號」這種最常見的幫忙一起拿掉。

那根釘子（`lift-pipeline.test.ts` 的 `[UNSUPPORTED:產生器不讀 degradationCause]`）
把這件事寫得很清楚，而它**擋對了**：

> 「修法是讓產生器在 `degradationCause === 'syntax_error'` 時原文照抄，
>  而那會動到**每一個**語法錯誤的產出——包含少一個分號這種最常見的，
>  今天它被順手補回去。那個改變要整族一起量，不是在巨集這一刀順手做。」

🟢 **整族一起量之後，判準自己浮出來**：

> **一個「這一段我看不懂」的節點，產出可以比原文【多】（補一個分號），
> 不可以比原文【少】——少掉的那幾個字是使用者打的。**

量法是**非空白字元的多重集合包含**：比「字串相等」寬（容得下排版與補進來的字），
比「長度相等」嚴（少一個 `@` 就抓得到）。

## 🔴 而這把尺第一版是錯的，抓到它的是一支既有的測試

`new-style-switching` 當場紅：`cout << x;` 這個**頂層裸片段**被標成
`syntax_error`（它確實不是一份合法的翻譯單元），而它**完全被理解了**
——樹裡是一顆 `print` 帶著 `x`。在 printf 風格下產出 `printf("%d", x)`，
`cout` 與 `<<` 不見了，於是我的尺把**這個產品的核心功能**判成「弄丟」並撤銷它。

```
「產出比原文少」是症狀，而它有【兩個】來源
  ├ 樹弄丟了東西      int x = 1 ⏎ cout << x; 的那個 1 沒有人認領   🔴 要修
  └ 風格換掉了寫法    cout << x; → printf("%d", x);                🟢 是投影
```

⚠️ **兩者在字面上長得一模一樣**，而試過的幾條路都分不開：
「子節點有沒有認領那一段」分不開（`cout` 是 print 自己的語法）、
「原文重新 parse 乾不乾淨」只分得開其中一種、
「只看數字與字串字面值」漏掉 `@@@`。

🟢 分得開的問法只有一個：

> **少掉的字如果換一個風格就回來了，那它是投影，不是弄丟。**

## 🔴 而「換一個風格」不是換 `ctx.style`

第一版就是那樣寫的，**完全沒有用**：

```ts
export function registerGenerate(g: Map<string, NodeGenerator>, style: StylePreset) {
  g.set('cpp:print', (node, ctx) => {
    if (style.io_style === 'cout') { … }   // ← 讀的是【閉包裡】的 style，不是 ctx.style
```

風格是在**建產生器表時**綁進閉包的（`factory(style)`）。

> **一個綁在閉包裡的設定，換掉它要換的是【產它的那張表】，不是那個同名的欄位。**

## ⚠️ 錨點比想像中難找——而那本身是一個讀數

要證「這把尺沒有漏到乾淨的節點上」，需要一支**真的少字**的合法程式。
掃了十個候選：`int main(void)` · `printf` · 冗餘的 `else` · `x += 1` ·
`struct` · 三元運算 · `0x2A` · `'A'` · `while (1)`——**九個一個字都沒少**。

🟢 **這個產生器幾乎不正規化**（`0x2A` 不變成 42、`x += 1` 不拆開，
括號與 `1e9` 有 `layoutHints` 守著）——「唯一真實，各式投影」在這裡的意思是
**拼法也是真相的一部分**。唯一少字的是 `std::vector` → `vector`，
而那正是 `namespace_style: 'using'` 這個風格選擇拿掉的。

## ⚠️ 一個順手的教訓：不要用編不過的雜訊撐大分母

檔頭的示意區塊裡寫了「`int main(void)`」，而 `audit-behavior-error` 的語料掃描器
**收所有含 `int main` 的反引號片語**——那幾個字因此進了母體，
落在「兩邊都不成」那一欄。

> **用編不過的雜訊撐大分母，會讓誤差率自己下降。**

處置：那幾個字的反引號拿掉。而**片段**類的掃描器（殘差、宣告完整性）
收它們是對的，那幾本基線照常上調。
