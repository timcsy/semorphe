## 一、機械掃描抓到的三件事

**① 根公理的變更紀錄，被它自己記錄的那次改名掃掉了**

`principles.md` 寫著「「元件節點／元件身分」→「元件節點／元件身分」」
——**箭頭兩邊一模一樣**。依 [109](109-程式碼追上名詞表而那張表早就定案了.md)
第 8 行「協定的名詞統一成「元件」，`概念` 從詞彙裡退場」還原。

> **一次全域改名會掃過「記錄這次改名的那句話」——
> 而那句話是唯一還知道舊名字的東西。**

⚠️ 它躺在**根公理**那一層，也就是 churn 該趨近零的地方。而沒有任何測試會紅
——抓到它的是「箭頭兩邊相同」這種形狀掃描。

**② 23 筆死連結，全部來自 `retired/` 那次搬家，而每一個目標都還在**

兩個方向都斷：活的 draft 指向搬進 `retired/` 的檔、`retired/` 裡的檔指向
還活著的兄弟。純粹是相對路徑沒跟著改。用「檔名 → 實際位置」表重算路徑修好，
剩 0 筆。

**③ `.agents/skills` 從來沒建過**，而 `.knowie.json` 宣告了 `agents-md`。
補上 18 條 symlink（`component-encapsulate` 是 `status: superseded`，
照 judge §5 **刻意不投影**）。

## 二、🔴 而最嚴重的一件，是判官自己造成的

判官掃出 `README.md` 說「88 條護欄」而實際不是，於是我 `cat >` 建了一條
「新」護欄來守這個數字——**而那個路徑上已經有一條**（`89e96602`、`772fb360`，
2026-08-19 的判官蓋的，判準改過三次），裡面還有一支
`it('🔴 知識庫裡不得把護欄條數宣稱成【現況】')`。

**這條規範早就存在，而我不但毀了它的實作，還去做了它禁止的事。**

⚠️ 而它**一路綠燈**：我的版本自己會過，全套 5959 支也全過
——因為被覆蓋的那 5 支連同檔案一起消失了，而**沒有任何東西會為
「不見了的測試」出聲**。

抓到它的是一個我差點放過的異常：**總測試數 5996 → 5994，加了 3 支卻少了 2 支。**

> **「測試全綠」證明不了「測試還在」——刪掉一支測試永遠是綠的。**

處置：`git checkout HEAD --` 還原，改成**擴充**既有那一條。

## 三、而那條既有護欄有一個真的缺口

它只掃三個核心檔（`principles`／`vision`／`experience`），**README 不在裡面**
——而那是唯一有陌生人會讀的一份。它從 2026-08-19 起就沒被涵蓋過。

```
README 寫       88 條      ← 剛好等於 audit-* 的檔數
權威數字        92 條      （audit-* 88 ＋ 靠期望值認出的 4）
```

> **一條「不准把數字宣稱成現況」的規範，漏掉了對外那一份。**

⚠️ 而 README 的句型沒有「今天／目前」這種現在式標記，所以原本的 `NOW` 判準
抓不到它。新增的斷言用**它自己的句型**，而且**直接比對數字對不對**
——不是禁止它出現。注入驗過：改成 88 當場紅。

🟡 **還開著**：那條護欄只數 `tests/integration/`，而 `e2e/` 裡也有護欄
（`first-run`、`flow-touch-drag`、`mobile-undo-everywhere`、`shipped-assets`…）。
擴大範圍會讓那個數字跳一次，**而那是一個要人決定的事**，不是順手改。
