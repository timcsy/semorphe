# 174 · 一條規範立錯了半天，而使用者一句話把它翻過來

**日期**：2026-08-26

## 起點：我提了一個「先說、不擋、讓它跑」的方案

`knowie-next` 那份簡報建議的是：執行前把「系統認不得」的節點列出來，
**而仍然讓它跑**——理由寫得很像一回事：

> 「`asm` 可能在一條永遠走不到的分支裡——**拒絕會把一個跑得完的程式擋掉**。
>  這一刀是『先說』，不是『先擋』。」

使用者一句話翻掉：

> 「這不能直接跑，而是**跑到那邊要有斷點**，讓使用者**調整完狀態**才能繼續跑下去，
>  或是**直接停止**」

## 🔴 而我錯在哪：把「不擋」誤當成「不停」

那句「拒絕會把跑得完的程式擋掉」**仍然是對的**——錯的是我從它推出的結論。

```
執行【前】就拒絕     ❌ 那條分支可能永遠走不到，這樣會誤擋
跑到那一行才停       ✅ 走到了才停 → 沒有誤擋的問題，而且【停在現場】
```

> **「不要提前拒絕」與「跑到了也不要停」是兩件事，
> 而我把第一件的理由拿去替第二件背書。**

⚠️ 而「跑到了照跑」正是我**同一天上午才拿掉**的 `'skip'`
（[173](173-拿掉錯的那個答案問題也跟著消失.md)）——
我用一個新的包裝把它請了回來。

## 這也讓我前一天蓋的護欄變成錯的

第七十五條上午立的規範是「碰到沒看過的東西，**不得有「繼續」這個答案**」。
使用者的設計裡**繼續是可以的，而它有前提**：

```
舊 'skip'   一個 confirm() 問「要不要跳過」   看不到停在哪 · 看不到變數 · 改不動
現在        停在那一行（與斷點同一條路）      看得到 · 改得動 · 然後【明確】決定
```

> **差別不在那個回答叫什麼，在回答的人有沒有被給到判斷的依據。**

⚠️ **而改寫的時候差一點就用「換個字」矇混過去**：實作改叫 `'continue'`，
那條護欄**當場變綠而一個字都沒改**。

> **一條護欄還在、還是綠的，而它量的東西已經與規範無關了
> ——那是最容易發生的假通過。**

→ 改寫成「不得**無聲地**繼續」，並且把量測從「字串」換成**行為**：
**沒有宿主可問時不得返回** ＋ **暫停要指得出位置**（兩支注入各自驗過會紅）。
舊那條（`'skip'` 不得回來）留著當墓碑。

## 實作：接上斷點，不新做一套

暫停機構全部現成——`animateResolve`、`debugToolbar.setMode('paused')`、
`bottomPanel.showTab('variables')`、`interpreter.abort()`。這一刀只加了
一個**理由**（`reason: 'unknown-component'`）與一個**決定的落點**
（`unknownResolve`，回 `'continue' | 'stop'`）。

**刻意不新做一套**：新做的代價是「繼續」與「停止」要維護兩份，而它們遲早會不一樣。

而「調整狀態」那一半是新的：變數面板的值在**暫停中**可以點開來改，
改動走 `execution:set-variable` 上匯流排（P9：跨層通訊只走 Bus），
落在 `interpreter.setVariableFromHost`——它用**既有的** `parseInputValue`
照那個變數今天的型別轉換。

⚠️ **`capabilities.editable` 不是這件事**：那一格問的是「這個視圖能不能當
**真相來源**」（`viewsWith('editable')` 就是「以此為準」那份清單），
而改一個執行期變數**不動語義樹一個字**。
> **兩件事叫同一個名字，第一個誤會會出現在那份清單上。**

## 🔴 而抓到最後一個缺陷的是瀏覽器，不是測試

單元測試全綠、型別乾淨、直接對 `cpp:raw_code` 呼叫也停得下來
——**而貼一段真的程式進去，它照樣跑到底**。

根因：這一族有**三個註冊點**，我改了兩個。

```
components/cpp/raw_code/execute.ts       改了
components/python/raw_code/execute.ts    改了
interpreter.ts 的 reg('unresolved', …)   🔴 漏了——而樹裡出現的是【它】
```

`asm volatile("nop")` 產出的是 `unresolved`（外層認不出、子節點認得出），
`raw_code` 是它的**子節點**。

> **一族三個註冊點，改了兩個而漏掉的那一個，
> 正好是真實語料唯一會走的那一個。**

⚠️ 而我的第一次探針**看不到它**：我用 `/raw/` 過濾樹裡的身分，
而 `unresolved` 不含那三個字。**一個用名字形狀過濾的探針，
會漏掉同一族裡名字不像的那一顆。**

### 第二個只有瀏覽器抓得到的

停下來了、工具列出來了、積木亮了——**而變數面板是空的**。
因為 `recordStep` 只在標了 `debug_step` 的概念上跑，
而「跑到一個看不懂的東西」不在那條路上，**沒有人替這個暫停送快照**。

> **少了狀態可看，「調整完狀態才能繼續」就是一句空話。**

修法：抽出 `snapshotScope()`，讓暫停自己帶一份走。

## 驗收（瀏覽器實測逐字）

貼一段含 `asm` 的程式、按執行 → 停住、積木亮起、下方切到變數、`total int 0`。
把 `0` 改成 `100`、按繼續：

```
這一塊我還不會執行（asm volatile("nop")）——先停在這裡。你可以在「變數」那一頁調整狀態，然後按繼續；或是直接停止。
（asm volatile("nop") 這一行沒有執行，是你選擇繼續的）
107
```

`107` ＝ 手填的 100 ＋ 7。**狀態真的改進去了，然後才繼續。**
