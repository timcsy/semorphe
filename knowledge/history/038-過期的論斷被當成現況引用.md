# 過期的論斷被當成現況引用——而那與「凍結的讀數」是同一件事

**日期**：2026-08-10 ｜ **交付**：`specs/109-execution-honest-degradation`，誤差 31 → 19
**前一則**：[037](037-模型與實體的距離-兩個刻度.md)

## 轉變一：整份 spec 的前提是一句過期的知識庫論斷

`specs/109` 的第一版圍繞「新增一個『已知不支援』宣告值」設計，
連防洗數字的機制都寫好了（分欄、總和不變、只能宣告已記錄過的缺口）。

**依據是 `concepts/執行機構.md:168`（2026-08-06）**：

> 「其餘 14 個跑起來結果是錯的（**十個是物件導向，直譯器不支援它**）」

而查證的結果是：

```
specs/071-struct-execute  072-class-method-execute  073-oop-slice3   ← 之後實作了
unimplemented.ts 的 OOP_NOT_IMPLEMENTED = []                        ← 現在是空陣列
```

> **一句寫在知識庫裡的論斷，會被當成現況引用，而它記的是寫下當天的世界。**

這與 `specs/108` 那條「**凍結的讀數是宣告，不是量測**」是**同一個形狀**，
只是這次凍結的不是 `g++` 的答案，是**我們自己對系統的判斷**。

→ 教訓：**引用知識庫裡的「現況」時，要像引用外部讀數一樣重新量一次。**
  而救它的是 `grep`——不是讀得更仔細。

**後果是好的**：整套防洗數字機制因此不需要了。
**缺口不必被宣告，它可以被修。**

## 轉變二：五個根因，而「一筆 ≠ 一個工作」兩個方向都成立

31 筆誤差 → 五個根因：

| 根因 | 位置 |
|---|---|
| `char` 轉型取字串首字元（`char c=66` 印 `6`） | `interpreter.ts` |
| 浮點沒有 C++ 的預設六位有效數字 | `types.ts` |
| `catch` 把 RuntimeValue 字串化 → `[object Object]` | `control-flow.ts` |
| `cpp:range_sum` 是回傳 0 的空實作 | `numeric/executors.ts` |
| `A a;` 走 `instantiate`（只建不跑建構式） | `variables.ts` |

**合併與拆分都發生了**：6 筆建構子是同一個根因（合併），
而 5 筆 `cctype` 分成「char 轉型」與別的（拆分，且只修掉一部分）。

### ⚠️ 而「`constructorOf` 零呼叫者」只對了一半

規劃時我用 `grep constructorOf` 得到零個呼叫者，據此說「機制在、沒人呼叫」。
**實際上 `construct()` 有一個呼叫者**（`A a(5)` 那條），零呼叫者的是 accessor。
真正的缺口是 **`A a;` 那條路走 `instantiate()`**。

結論方向對，**證據錯了一格**。而它之所以沒有害到結果，
是因為下一步就去讀了那段程式碼——**grep 只排順序，不下結論**。

### 而不對稱本身是最強的線索

```
解構子   會跑    ← structs.ts:151 呼叫 destructorOf
建構子   不跑
```

**同一顆物件，一邊跑一邊不跑，而少的那一邊沒有任何訊號。**
「類別完全沒作用」這種明顯的線索因此不存在——看起來只是少了一行輸出。

## 轉變三：我自己造成一次回歸，原因是沒照抄已驗證的形狀

`char` 修法第一版寫成 `Number.isFinite(this.toNumber(val))`，
而 `toNumber({type:'string', value:'a'})` 回傳 **0**（不是 NaN）
→ `char s[8]="a"` 每個字元變成 NUL → `strcat` 測試當場變紅。

`std/cctype/executors.ts` 的 `charOf` 早就解過同一題，用的是
`typeof value === 'number'`。

> **照抄已驗證的形狀，不要自己換一個判準。**
> 那個檔案的註解甚至寫著「⚠️ 不能一律 `String(value).charAt(0)`」
> ——我讀過它、引用了它、然後換了一個自己的判準。

而它同時是「**修一條路時要問：同一個缺陷在別的路上長什麼樣**」的實例：
`cctype` 修過 char 的取法，核心的轉型沒有。

## 順帶：殼寫在寫著「不要留殼」那句話的下面兩行

`numeric/executors.ts` 的 `resolveRange` 上方寫著：

> 「**解析不了時擲錯，不回傳「沒事」**——原本的實作是空操作，於是
> `sort(a, a+3)` 靜靜地什麼都不做，學生拿到未排序的陣列而毫無提示。」

而**同一個檔案下面兩行**：

```ts
register('cpp:range_sum', async () => ({ type: 'int' as const, value: 0 }))
```
