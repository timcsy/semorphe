# 170 · 判官缺的那一維，不是掃描器——是寫入的那一步

**日期**：2026-08-26

## 起點：我報了一個缺口，然後真的去跑它

前一輪結束時我報給使用者：**`/knowie-judge` 沒有任何一維在問
「有沒有哪條 `- [ ]` 其實已經做完了」**。下一輪的第一件事不是寫簡報，
是**先把那個掃描真的跑一次**——它的結果會決定該不該蓋那一維。

## 掃描本身踩了它自己在講的坑

第一版偵測器對每一條開著的項目取整塊，然後 `i = end` 跳到下一條。
於是**巢狀的 `- [ ]` 從母體裡消失**——而 `vision.md:534`
（真正過期的那一條）正是被它的父項 `:528` 吃掉的。

> **這與 [`retire-imperative-block` §7](../skills/retire-imperative-block/SKILL.md)
> 是同一個形狀：「有差異 0 顆」不等於「清乾淨了」，
> 從母體裡消失與沒問題長得一模一樣。**

修好之後母體從「若干」變成 **70 條**。

## 🔴 而純機械判準在這個知識庫做不到

判準本來想寫成「內文有完成標記而框沒勾」。三輪縮放：

```
第一版  🟢/✅/已完成 出現在整塊裡        →  9 條，多數是「父項還開著而部分子項完成」＝正常
第二版  只看葉節點自己的內文 ＋ 子項全 x  →  2 條，而【兩條都是誤報】
第三版  再排除內文有 🔴 的                →  5 條，而它把【真的那條】排掉了
```

根因是這個知識庫的**書寫慣例**：

> **🟢 與 🔴 在這裡是【強調】，不是【狀態】。**

`vision.md:586` 內文同時有 🟢（命名已掃乾淨）與 🔴（五列一列都沒動）；
`vision.md:775` 的三個 `[x]` 是**兄弟欄**（provides／board／requires），
不是 `reference` 的子步驟——實測 0/5 個目標宣告有 `reference`，
參照編譯器仍寫死在護欄裡。**兩條都是誤報。**

## 轉移：從「蓋一維」到「一條寫入紀律」

人工查證 70 條的結果：**真正過期的只有 2 條**。

| | |
|---|---|
| `vision.md:534` | 開放值域的驗收——`audit-dropdown-domain` 的棘輪 = 0 |
| `vision.md:691` | QuickPick 來源導出——`app.ts:115` ＋ 第六十二條護欄 |

2/70。而**那 2 條裡的第一條是我自己兩輪前造成的**：查證完、把
🟢「而那個量測已經有了（2026-08-26 查證）」寫進項目的內文、**沒有勾框**。

> **所以缺的不是一個週期性的掃描器，是寫入的那一步：
> 把「查證過、已經有了」寫進某一項的當下，
> 就要在同一次編輯裡決定那個框。**

⚠️ 這與這個 repo 反覆學到的另一條同源
（[`retire-imperative-block` §7.5](../skills/retire-imperative-block/SKILL.md)）：**一句描述現況的話，
不會因為現況改變而自己過期。** 差別只在載體是註解還是核取方塊。

## 被否決的選項：新增一維判官掃描

否決理由留在這裡，因為它是最貴的那一半 why：

- **誤報率壓不下來**——三版判準都靠 🟢/🔴，而它們在這裡是強調不是狀態。
  一個回報 5 條而 4 條是誤報的維度，會被學會忽略
  （[`build-guardrail` §11](../skills/build-guardrail/SKILL.md)：
  「護欄的價值不在它報什麼，在有沒有人讀」）。
- **母體太小**——2/70。判官每一維的成本是「每次跑都要有人讀」，
  而這一維每次只會回報個位數，且多數是誤報。
- ⚠️ **而「掃描不出來」不等於「不用管」**：處置是把它推到**更早**
  （寫入的當下），不是不處置。

## 順帶：同一次查證抓到的第三條過期

`vision.md:691` 的內文寫著「🟢 而那支函式今天**零消費者**」
——它現在有兩個（`app.ts:115`／`:1246`）。
**一條過期的項目，內文裡常常還有第二層過期。**
