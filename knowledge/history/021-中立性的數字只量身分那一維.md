# 021：中立性的數字從「離語言獨立性還有多遠」改為「只量得到耦合的一種形式」

> 日期：2026-08-06

## 轉移

- **舊**：中立性護欄的檔頭寫著「**數字是幾，就是離語言獨立性還有多遠。**」那個數字是階段 6.5 的頭號指標，優先序、進度、以及知識庫裡已經寫下的結論全部建立在它上面。
- **新**：**它只量得到耦合的一種形式。** 護欄找的是**元件身分字串**（`'cpp_vector_declare'`）。核心層寫死**語法符號**（`//`、`/* */`）的地方，它一個字都看不到——那些位置一個元件身分都沒有。

## 為什麼變

因為照它規劃工作時去逐筆查證。

`comment` 那一族被報了六筆。查下去，三筆是誤報（語法樹節點型別、TypeScript 聯集成員、Blockly 欄位的提示文字——**與元件身分撞名的普通英文單字**）。另外三筆是真的，而查證它們的上下文時撞見了這個：

```
// src/core/lift/lifter.ts:152
text: node.text.replace(/^\/\/\s?/, '').replace(/^\/\*\s?|\s?\*\/$/g, ''),
```

**核心層在剝 C 家族的註解符號。** 護欄從來沒有數過它。

繼續往下找，同類共**六處**——產生 `//`、`/** */`、`/* */` 三個概念，行末標註接 ` // text`，認不得的概念退回 `/* unknown concept */`，運算式位置的同類退路，加上上面那個剝除規則（`template-generator.ts` 另有兩處）。Python 要 `#`，Lisp 要 `;`。**六處全部違反 P9，六處全部不在那個數字裡。**

## 這比「量測工具會安靜地量錯」更深一層

那條教訓講的是**工具的第一版會實作錯**——入口用錯、粒度太粗、判準對而自動化錯。修法是修工具。

這裡不一樣：**判定邏輯完全正確**。它精準地數出了核心層有多少元件身分。錯的是**它量的那一維不是規範的全部**。

> P9 說「拔掉 C++，核心無 `languages/cpp/` import」。那句話自己也只寫了一個維度——**import 是耦合的一種形式，身分是另一種，語法是第三種。**

一條規範被機械化之後，機械化的**選了哪一維**這件事就消失在數字裡了。而數字看起來像完整的答案。

## 後果

- 護欄的「本護欄不檢測什麼」新增一條：**不檢測語法層級的語言耦合**
- 新增一支獨立的檢查：`tests/integration/comment-projection-snapshot.test.ts` 的「核心層零註解語法」——它找的是**符號本身**，不是身分
- 六處全部搬進語言套件（`src/core/comment-syntax.ts` 宣告介面，C++ 套件推實作）

## 這條會重演

**其他護欄也各自只看一個維度。** 就近性數檔案數，缺陷帳數停用測試，完備性跑五路——每一條都在自己選定的那一維上正確，而每一條都可能有一整類違規落在維度外面。

判準見 [concepts/執行機構.md](../concepts/執行機構.md)「一條規範被機械化時，選了哪一維會消失在數字裡」。

## 後續：那條護欄已經蓋了（2026-08-06 同日）

`tests/integration/audit-syntax-coupling.test.ts`，第九條。**它一蓋起來就抓到
中立性看不見的東西**——所以上面那段不是論證，是有證據的。

蓋的過程本身又給了兩個實例：

- **偵測器的第一版抓不到 `lifter.ts`**，因為那一處寫在**正則字面**裡而不是
  字串字面。抓到它的是「已知答案的樣本」（git 裡 059 之前的程式碼），不是
  code review。
- **第一次真實量測的 5 處裡有 4 處是它自己的誤報**——`'u_endl'` 含 `endl`、
  `register('endl')` 是概念身分、`| 'endl'` 是型別位置。**與 059 同一個坑的
  第三次。**

判定保守的代價：48 處歸「無法確定」（`int`／`string`／`<<` 同形於核心自己的
東西）。它們單獨報，**不算違規也不算安全**。
