# 260 — `long long` 在這個直譯器裡是一個 double

> 2026-09-19｜「內容真的不同」7 → 3

## 起點：一支競賽最常見的樣板

`AP325/2/2_8_loop.cpp`（模逆元／快速冪）：

```cpp
ll xn(ll x, ll nt, ll P){
    ll ans=1;
    while(nt){
        if(nt & 1) ans = ans*x%P;   // ← x,P ≈ 1e9 ⟹ 乘積 ≈ 1e18
        x = x*x%P;
        nt >>= 1;                   // ← JS 的 >> 是【32 位元】
    }
    return ans;
}
```

**兩個獨立的失真疊在同一行上：**

```
① 乘法超過 2^53（9.0e15）就失真     JS 的數字是 double；long long 精確到 9.2e18
② 位元運算被截成 32 位元            JS 的 & | ^ << >> 一律先轉 int32
```

⚠️ 而症狀是**算出另一個數字**，不是報錯——它落在「內容真的不同」那一欄，
而那一欄是唯一一欄**不會有人來問**的。

## 🔴 不變式：`bigint` 只在中途出現

```
一個整數值：|v| ≤ 2^53 時是 number，超過時是 bigint
```

**不把整數全改成 `BigInt`**——那要動每一條算術路徑，而且會讓每一個下標、
每一次比較、每一處 `Math.*` 都要先轉回來。

這個不變式讓 `bigint` **自我收斂**：`ans*x%P`（P < 2^31）的乘積是 bigint，
而 `% P` 之後立刻收回 number。**一支不取模的程式才會一路帶著 bigint**，
而那正是它需要 64 位元的那一支。

## ⚠️ 而真正花時間的不是 64 位元，是「它為什麼沒生效」

修完 `cpp:arithmetic` 之後語料**一支都沒好**。往下挖出四層：

### ① 同一個運算有二元形式與複合形式

`for(ll jp=1e12; jp>0; jp>>=1)` 的 `jp>>=1` 走的是
`interpreter/executors/mutations.ts`，不是那顆元件。

> **同一個運算有二元形式與複合形式時，修一個不會修到另一個
> ——而它們錯的是同一件事。**（那個檔自己在字串 `+=` 上記過一模一樣的話。）

### ② 字面值在讀進來的那一刻就失真了

`Number('9007199254740993')` 是 **9007199254740992**——少了 1，
而那個 1 不會有任何人出聲。

### ③ `long long` 這個拼法根本沒有被認出來

`coerceType(val, 'long long')` 掉進 `default: return val`，於是
`long long n = 2e9;` 的值**一直是一個 double**。

🟢 處方是 `core/scalar-types.ts`：**核心宣告槽位，語言套件推資料**
（形狀抄 `comment-syntax.ts`／`non-components.ts`）。
⚠️ 而它**必須放在模組頂層**——第一版放在 `module.ts`，
而測試呼叫的是 `registerCppLanguage()`，於是那張表在測試裡是空的。
`generators/index.ts` 裡就有同一個坑的前例（spec 168「搬到模組頂層」）。

### ④ `#define ll long long` 從來沒有進過別名表

那條正則要求「一個字」，而 `long long` 有空白。**語料裡 41 處。**

> **一個「只認一個字」的規則，對語料裡最常見的那個寫法剛好無效
> ——而它不會出聲，因為「查不到就讓開」本來就是它的設計。**

### ⑤ 函式的回傳值完全沒有依宣告型別轉換

`ll DFS(…){ … return 1e9; }` 回傳一個 `double`，於是 `cout` 印 `1e+09`。
⚠️ **連 `int f(){ return 1e9; }` 都是**。

> **宣告的型別如果只在宣告那一行生效，它就不是一個型別，是一句註解。**

## ⚠️ 已知的不同（寫下來，不要假裝沒有）

- **不模擬溢位**：C++ 的 `long long` 溢位是未定義行為，而我們算得比它準
  ——那是**往安全的方向**錯。
- **`unsigned` 不環繞**：那需要寬度，而拼法表沒有寬度。語料裡 0 支依賴它。
  🟠 **何時該面對**：語料或盲測出現第一支依賴 `unsigned` 環繞的程式。
