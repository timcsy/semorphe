# 一份自己造的語料，量的是「我們想到的那些輸入」

**日期**：2026-09-09
**觸發**：使用者交來他學生的練習 repo（`core-keeper/StudyCpp`）當語料
**轉折**：「殘差 0.0%」這個數字**一直是真的**，而它量的不是使用者在意的那件事

---

## 使用者的原話

> 「這是我的學生的練習的 repo，我希望他所有的有用到的東西在 semorphe 都是
> 有被處理好的，你可以把這當作是語料庫來看看我們有沒有什麼缺乏，
> 例如有什麼是**轉成積木轉不回來**的之類的，幫我有系統性的檢查」

218 個 `.cpp`、7327 行。內容是 AP325（吳邦一那本）、TIOJ、zeroJudge、APCS
——**競賽取向的 C++**，與 `cpp-advanced` 那一軌同一個領域。

---

## 🔴 第一個數字很好看，而它量錯了東西

```
解析失敗   0
lift 失敗  0
殘差       9 / 19571 節點 = 0.0%
用到的元件 107 種
```

⚠️ **殘差率**（第三十一條護欄）量的是「有多少原始碼**進不來**」。
而它進得來——**問題在它出不去**：

```
同一棵 74｜走樣 144        ← 218 支裡 144 支轉一圈回來不是同一棵樹
```

> **殘差量的是「我沒認出來」，而它對「我認錯了」保持沉默
> ——而後者才會讓使用者的程式碼變成另一支程式。**

---

## 七族，而其中四族是同一個反模式

```
string A[100];            →  string x;            🔴 陣列、大小、名字一起蒸發
string s, t, u;           →  string s;            🔴 第二、三個變數蒸發
string* p;                →  string x;            🔴 指標與名字蒸發
int a[10], b[20];         →  int a, b;            🔴 兩個大小蒸發
vector<int> v(n);         →  vector<int> x;       🔴 32 個檔這樣寫
ios::sync_with_stdio(0),… →  …(0);⏎, cin.tie(0)   🔴 編不過（136/218 支的第一行）
max({ans, f(l), f(r)})    →  max({…}, 0)          🔴 編不過
lambda 裡的 count++;      →  count++（沒有分號）   🔴 編不過
```

而**全部不出聲**：殘差 0、積木長得很正常、多數產出編得過。

### 四族的共同形狀

```ts
const name = decl?...?.text ?? 'x'          // 具體型別的宣告
const a = aNodes.length > 0 ? … : '0'       // max／min 的運算元
const size = … ?? '10'                       // 陣列大小（2026-08-18 已修過一次）
```

> **一個 `?? '預設值'` 讓「我沒認出來」與「它本來就長這樣」長得一模一樣。**
> （`CLAUDE.md` 的靜默降級反模式——這是它第 N 次現形，而每一次都是別的地方）

---

## ⚠️ 而兩處的修法**不在膠囊裡**

### ①「運算式位置」的契約沒有機械化

`ios::sync_with_stdio(0), cin.tie(0);` 是一個逗號運算式。
`cpp:comma_expr` 老實地把每個 expr 用 `, ` 接起來，而 `cpp:io_sync` 回給它
**語句形**（帶縮排、帶分號與換行）。

量過：**152 個產生器無條件產語句形，只有 7 個看 `ctx.isExpression`**。

> **一個「要記得先檢查」的契約，就是一個等著被忘記的契約
> ——它該由呼叫端執行，因為呼叫端知道自己要的是什麼。**

🟢 而機制的**另一半早就在了**：`asStatement`（運算式出現在語句位置補分號，
2026-08-17 由盲測抓到）。缺的是反面 `asExpression`，而它的判準與那一支
逐字相同：**問宣告，不看產出的形狀**。

### ② 一個旗標穿過了它不再成立的邊界

lambda 是**運算式**，而它的**主體是語句**。`isExpression` 原本會一路傳下去，
於是 lambda 裡的每一句都以為自己在運算式位置——`count++` 產出時沒有分號。

⚠️ **而每一顆膠囊都做對了**：`cpp:increment` 老老實實問了 `ctx.isExpression`，
它只是**被騙了**。

> **一個旗標如果會穿過它不再成立的邊界，
> 那麼下游每一個正確的檢查都會得到錯的答案。**

---

## 🔴 修正確性的時候差點換掉一個身分

`stack<int> inbox, outbox;` 原本產出 `stack<int> inbox;`（第二個蒸發）。
第一版修法是「讓具體型別那幾支**讓開**，走通用的宣告路徑」
——字串當場對了，而 `cpp:stack_declare` 變成 `cpp:var_declare`。

一支既有的 fuzz 測試當場紅，而**它是對的**：

> **一個為了修正確性而放棄身分的修法，是把一個缺陷換成另一個缺陷。**
> （使用者記過的原則：roundtrip 測試必須驗證語義樹用的是正確的 conceptId，
> 不能只驗輸出字串）

🟢 最後的形狀：具體型別那幾支**自己把多宣告子包起來**
——外層是 `cpp:var_declare`（多宣告子本來就長這樣），
而**每一個宣告子保住自己的身分**。

⚠️ 而它值得做，是因為**先量過**：真實語料裡這個形狀 4 筆（`deque<ll> h, t;`
是學生真的寫的）。稀少但真實，不是為一個不存在的形狀加第二份會漂移的邏輯。
