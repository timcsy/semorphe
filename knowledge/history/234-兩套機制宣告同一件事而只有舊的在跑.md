# 234 · 兩套機制宣告同一件事，而只有舊的在跑

> 2026-09-14 · 起點是使用者問「3D 建模的多版本要怎麼管」

## 怎麼走到這裡的

使用者問的是未來：同一顆元件的 3D 模型會有很多版本，怎麼管？

答案的骨架已經在協定裡——`form: { axis, value }`（spec 097，2026-08-07），
而那正是 USD 的 `VariantSet` 獨立走到的同一個形狀。LOD、用途（URDF 的
`visual`／`collision`）、表現法、抽象度，四條軸都通得過「使用者會不會故意挑舊的」這個判準。

而回答時查證了一句我自己說出口的話——「軸值只能由樹給，消費者給不了」
——**那句話是錯的**：`FormSelectionContext` 早就在，註解逐字寫著
「選擇形態時**呼叫端知道、而節點不知道**的脈絡」。

🟢 於是問題從「要設計一個機制」變成「**去量那個機制通不通電**」。

## 量到什麼

```
形態集合             330
其中有軸的             15
  由樹給值（container_kind）    2   🟢 會開火
  由脈絡給值（role）           13   🔴 全部落回中性形態
```

唯一的呼叫點是 `selectForm(formSet, node, {})`——**空脈絡**。

而畫面沒壞，因為有**第二套機制**在做同一件事：

```
新  form: {axis:'role', value:'expression'}   13 顆宣告 · 0 顆讀得到
舊  renderMapping.expressionCounterpart        13 顆宣告 · 產品實際走這一條
```

🔴 **兩邊涵蓋的 13 顆元件，集合差集兩邊都是空的。**
每一顆都把同一件事宣告了兩遍，而只有舊的那一遍被讀。

## 🔴 而它沒被發現，是因為一行【曾經誠實】的註解

```ts
// 位置軸（statement/expression）在本功能中沒有任何積木宣告它——那是 B 項的事。
// 傳 undefined 是誠實的：呼叫端目前不知道呈現位置。
```

那句話在 spec 097 交付當天是真的。今天有 13 顆宣告它了。

> **一句誠實的註解，不會在它變成不誠實的那天自己出聲。**

⚠️ 而它有雙重殺傷力：它不只描述現況，它還**解釋了為什麼不用做**
——所以下一個讀到它的人會直接跳過。（包括我，在量它之前的那一則回答裡。）

## 舊 → 新

```
render(node, ctx)              →  render(node, ctx, position)
renderBlock(node)              →  renderBlock(node, position)
renderExpression: 事後換型別    →  renderBlock(node, 'expression')，選形態時就決定
expressionCounterpart          →  退場（欄位 ＋ getExpressionCounterpart ＋ 13 顆宣告）
```

## ⚠️ 退場的順序，以及它抓到的那條路

```
① 讓渲染端把位置餵下去                        軸才選得到
② 在舊機制那一段放一個 throw，跑全套           確認它 0 次開火
③ 才刪
```

🔴 **而②當場抓到①漏了一條路**：有 `renderStrategy` 的元件在策略成功時就
`return` 了，**形態選擇在那之後**——於是那一族元件永遠拿不到軸，
`cpp:var_declare` 一直靠舊機制活著。

第一次跑②：**開火 6 次**。修完（把形態選擇提到策略之前）再跑：**0 次**。

> **一個「我推論它已經不可達」的結論，要用一次 throw 來驗
> ——而那一次 throw 找到了推論漏掉的那條路。**

而修法本身也是一句可以帶走的話：

> **策略造的是【內容】，軸選的是【哪一個形態】——兩件事，
> 而把後者放在前者的 early return 後面，等於對一整族元件關掉它。**

⚠️ 收窄：只有軸真的選了**變體**（不是落回中性）才換策略產出的型別
——中性時不動它，否則會用中性型別蓋掉策略刻意造的那一個。

## 驗收：渲染逐位元相同

```
69 張課文對照圖重產兩次（① 之後、② 之後）
每一次都是：69 files changed, 69 insertions, 69 deletions
而 diff 裡【只有 engineHash】
```

> **一次「行為保持」的重構，最好的證據不是測試綠，
> 是那份大到沒有人抄得動的產物逐位元相同。**

## 沒做：`lod` 軸

使用者問的 3D 那一條**沒有做**，而理由寫在 `KNOWN_AXES` 自己的註解裡：

> 「加一條軸就是加一列。研究階段刻意否決了『軸的外掛註冊』：目前只有兩條軸，
> 而為想像中的第三條軸建抽象是憲章 I（簡約優先／YAGNI）明文禁止的。」

🟢 而這一刀之後，加 `lod` 真的就是加一列——**因為那條線現在通電了**。
在此之前加它，會加到一條從沒有人驗過的死路上。
