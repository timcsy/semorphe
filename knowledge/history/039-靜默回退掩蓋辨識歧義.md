# 靜默回退掩蓋辨識歧義——一個回 0 讓另一個缺陷躲了很久

**日期**：2026-08-10 ｜ **交付**：第三十三條護欄 ＋ `specs/110`，誤差 19 → 17
**前一則**：[038](038-過期的論斷被當成現況引用.md)

## 轉變一：兩個已命名的病疊在一起，而第二個讓第一個看不見

```
s.length()  →  cpp:string_size{obj:s}   ✅
s.size()    →  cpp:vector_size{obj:s}   ← ① 辨識歧義（規則不看目標型別）
               對非陣列 return { value: 0 }  ← ② 靜默降級反模式
```

`for (int i = 0; i < s.size(); i++)` **一次都不跑**，字串原樣輸出，
**沒有任何地方說出錯了**。19 筆誤差裡的 5 筆整叢是這個。

> **辨識的錯躲在執行的回退後面。**
> 而兩個病單獨看都「只是一個 bug」——**疊起來才變成隱形**。

⚠️ **既有的辨識歧義護欄看不見它**：那條量「有多少規則在搶同一種語法」，
而 `.size()` 只有一條規則。**問題不是兩條規則搶，是一條規則判別不足。**

→ 第三十三條護欄量的不是「這裡有 bug」，是「**這裡藏得住 bug**」。

## 轉變二：修法選在執行層，不在辨識層

兩條路都通：在辨識層多一條「目標是字串 → `cpp:string_size`」的判別，
或在執行層讓 `cpp:vector_size` 認得字串。**選了後者**：

> `.size()` 與 `.length()` 在 C++ 裡**本來就同義**——
> 同一個概念的兩種寫法，不是兩個概念。
> 在執行層收掉比在辨識層多寫一條判別**更靠近真相**。

而 `build-guardrail` 的「照抄已驗證的形狀」在這裡的讀法是：
**先問這兩個到底是不是同一件事**，而不是機械地複製 `.length()` 的規則。

## 轉變三：我在規劃時連續診斷錯兩次，而兩次都是**我的過濾器濾掉了答案**

1. 說「`s.size()` 完全沒有被 lift」——**錯的**。探測腳本用
   `x.includes('string')` 過濾語義節點，剛好把答案（`cpp:vector_size`）濾掉。
2. 據此推薦「蓋一條量得到**靜默丟棄**的護欄」——前提不成立，沒有東西被丟棄。

> **探測的過濾器濾掉了答案，而輸出看起來像一個發現。**

這是「**語料錯看起來像世界的性質**」（`history/037`）的新變形：
**篩選條件也是語料的一部分**，而它比語料更隱形——語料至少會被印出來。

→ 判準：**探測腳本的過濾器，本身要在已知答案的樣本上驗過。**
  「`s.length()` 必須出現在輸出裡」這一句就會當場戳破它。

## 轉變四：判定機制的識別鍵會碰撞

`specs/108` 建的判定落點用「語料前 80 字元」當鍵。`specs/110` 收尾時發現：

```
17 筆明細  →  16 個不同鍵
19 筆判定  →  16 個不同鍵
```

後果是**孤兒檢查與「要看」都不可靠**——一筆新誤差會被同鍵的舊判定遮掉，
而報表上看起來是「已判定」。

> 這與「**以名字為基礎的比對忘了詞界**」是同一族：
> **識別碼必須識別得出那個東西。**

已補上全文雜湊：17 明細 → 17 個不同鍵。
