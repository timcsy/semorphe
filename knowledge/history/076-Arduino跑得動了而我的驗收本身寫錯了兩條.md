# 076　Arduino 跑得動了——而我的驗收**本身**寫錯了兩條

> 日期：2026-08-17（spec `137`，vision 階段 6.11 的第 1–3 項）
> 本檔記的是**三個推翻**：一個閘門不存在、一個做法把使用者的名字搶走、
> 而**兩條驗收用了與被修的缺陷同一個錯誤觀察量**。

## 轉變

```
old  十段 Arduino 語料：辨識殘差 0/10，而執行 out="" err=""
     ——🔴 安靜地什麼都不做（沒有 main，setup／loop 沒人呼叫，而它不拋錯）
new  🟢 10/10 跑得完、0 拋錯、9/10 有可觀察效果，瀏覽器上印得出 blink
```

## 一、🔴 我指認的「閘門」不存在

`/knowie-next` 的 brief 逐字：

> 「🔴 執行路【不知道目標】 `ExecutionContext` 沒有 style、沒有 target
> ← **本輪真正的閘門**」

**而修法是六行，核心一個字都沒動。** 進入點由「**樹裡有哪些函式**」決定。

而那顆元件的檔頭**早就寫著答案**：

> 「哪一個函式是進入點是**這顆（整個程式）的知識**，不是那顆函式的性質。」

⚠️ **我讀過那句話，還把它抄進了規格——而我沒有把它當成答案。**

> **一個被誤判成「缺資訊」的問題，會被答成一條新的傳遞路徑
> ——而那條路徑之後要有人維護。**

## 二、🔴 而最貴的一坑，是既有做法的一次越界

`cpp:pin_constant` 第一版靠**識別字的名字**認 `HIGH`／`LOW`／`OUTPUT`。

```c
enum Level { LOW = -1, MEDIUM = 0, HIGH = 1 };
cout << LOW << endl;      // 參照：-1     我們：0  🔴
```

> **一個名字的意思由【誰宣告它】決定，而樣式比對看不到宣告。**

⚠️ 而既有的 `cpp:builtin_constant` 用**同一個做法**（`EOF`／`NULL` 靠名字 lift）：

> **同一個做法在兩個名字上，一個安全一個不安全
> ——而安全的那個不會告訴你為什麼。**

**處置**：改在 `cpp:var_ref` **查不到宣告之後**才問。
🔴 **代價已接受**：round-trip 時那顆變回變數參照。**correctness 贏 round-trip。**

## 三、🔴 而兩條驗收**本身**寫錯了

### SC-001「十段語料真的印得出東西」

十段裡**四段只有 `pinMode`／`digitalWrite`，本來就不印東西**。

⚠️ **而諷刺的是**：本功能的**起因**正是「沒有輸出被誤判成沒有執行」，
**而我寫驗收時用了同一個錯誤的觀察量，只是方向相反**。

```
起因   沒有輸出 → 被當成「跑完了」      （漏判）
驗收   沒有輸出 → 被當成「沒跑起來」    （誤判）
```

正確的量是**可觀察的效果**：輸出**或**腳位狀態。

### SC-002「`runnable` 從 `false` 翻成 `true`」

`true` 會拿 `g++` 當裁判，而 **`g++` 編不動 Arduino sketch**。

> **`history/071`：裁判的能力邊界不是固定的——它是【目標】的函數。**

→ 加第三態 `'ours-only'`，**而報表標明「無參照可比」**。

> 那份清單就是它的盲點，而盲點不會出聲。**

## 五、⚠️ 而一個流程缺口要說出來

`component-pipeline` 的 ⛔ 規則要求五個階段缺一不可。本輪**只跑了 1、2**
（discover ＋ generate）——**3、4、5 沒有透過 Skill tool 跑**。

替代的是每顆膠囊 `spec.test.ts` 的 38 支斷言（含 round-trip）＋ 全套 4275 綠。
🔴 **而那不等於 `component-fuzz` 的資訊隔離盲測**——它抓的正是
「自己寫的測試看不到的東西」。**這是缺口，不是判斷。**
