# 209 — 五個形狀裡有一筆債從來不存在，而它在報表上長得跟真的一樣

> 2026-09-06。vision「🧾 未清的債」第二筆。它 2026-08-26 留下一句
> **擋著動工的問句**：「這五個裡有幾個是『這個工具本來就不做』？沒有人驗過。」

## 轉變

```
舊   五個語法形狀「該補進語料」（保守桶，因為沒有人驗過）
新   五筆裡【只有兩筆需要真的做事】——而其中一筆的債從來不存在

舊   parenthesized_declarator：void (*f)(int); → void f(int);   （安靜地改變意義）
新   降級成 raw_code：原樣保留，而且說出來

舊   abstract_array_declarator：void f(int[10]) → void f(int)
新   做對了：整段（含大小）接進型別

舊   C++ 語法形狀該補 = 5
新   = 0（兩次顯式下調：5 → 3 → 0）
```

## 為什麼

### 一、🔴 一筆債從來不存在，而它在報表上與真的那些長得一模一樣

第一次量 `structured_binding_declarator` 的範例是：

```cpp
std::pair<int, int> t{1, 2};
auto [a, b] = t;
```

來回之後 `{1, 2}` 掉了 → 報表上那一列寫著 **`structured_binding_declarator` 🔴**。

而換成不需要初值列的範例：

```cpp
struct P { int x; int y; };
P p;
auto [a, b] = p;
```

**來回逐字相同，一個殘差都沒有。** 結構化繫結本來就是對的。
掉的是**初值列**——那是另一件事。

> **一個示範 X 的最小範例，如果它順便用到了 Y，那它量到的是 X 與 Y 的聯集
> ——而報表上那一列會寫著 X 的名字。**

⚠️ 而這不是一個「量錯了」的小事：那筆假債**已經在 vision 裡躺了 11 天**，
而它與真的那兩筆**看起來完全一樣**。

### 二、`literal_suffix` 的判定，連在說哪一件事都是錯的

舊的 reason 寫著「數值字面值的後綴（`1.0f`／`100L`／`3u`）——⚠️ 這一格看起來最不該空，
初學課本就有」。

而實測：**`5LL` 一個 `literal_suffix` 都不產生**（那是 `number_literal` 的一部分）。
這個節點**只**出現在使用者定義字面裡（`42.0_km` 的 `_km`）。

> **一個判定如果建立在「這個節點大概是什麼」的猜測上，
> 那它的桶對不對就沒有意義了——它連在說哪一件事都是錯的。**

🟢 所以它與 `user_defined_literal` 是**同一段程式碼產生的兩個節點**，
舊判定把它們數成兩筆債。

### 三、🔴 而真正的問題不是「語料缺」，是【靜默遺失】

```
void f(int[10])   →  void f(int)        陣列大小沒了
void (*f)(int);   →  void f(int);       🔴 一個變數變成了一個宣告
```

第二個的根因是一行 `nameNode?.text ?? 'f'`：`function_declarator` 底下的
identifier 包在 `parenthesized_declarator` 裡找不到，於是落到**預設值**。

⚠️ 那正是 CLAUDE.md 列的**靜默降級反模式**：
「多層 fallback 都用同一個預設值，會掩蓋真正的資料遺失。」

> **一個誠實的「我不會」，比一個安靜的「我改了你的程式」好。**

🟢 兩條修法都用上了，而**選哪一條有判準**：

```
abstract_array_declarator   做對    它只是清單漏了一個型別——補上就完整
parenthesized_declarator    出聲    把函式指標變成一顆概念（有型別、能當參數、
                                    能呼叫）是另一刀，而在那之前原樣保留
                                    是唯一不說謊的做法
```
