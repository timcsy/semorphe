# 152 · 同步從「方向」變成「來源」，而暫停暴露了第三態

> 2026-08-25。使用者 2026-08-24 提的：「同步按鈕的部分我想要重新設計，
> 因為加入了流程面板，會更加複雜。」
> 而複雜的來源不是面板數量——是**那兩顆按鈕在做兩件事**。

## 一、方向是 N²，來源只有 N

```
(a) 現在同步一下   → 時機   自動同步開著時不必要
(b) 以這一邊為準   → 來源   兩邊分岔時無可取代
```

舊的 `sync-blocks-btn` / `sync-code-btn` 把 (a)(b) 寫成同一顆，於是
**第三個可編輯視圖出現時它要變成六顆**。

> **一份寫在 HTML 裡的「可編輯視圖清單」，與一份寫在程式碼裡的手寫清單
> 是同一個東西——只是沒有人把它看成清單。**

三顆換成一顆「⇄ 同步」，而選單的來源清單由 **`viewsWith('editable')` 導出**
——那支函式在此之前**有三個宣告者而零個讀取點**（與 `control_flow` 同形）。

## 二、🔴 而「來源是導出的」在暫停之後失效

第一版的設計是「誰最後被編輯就是來源」。**使用者追問「會不會想暫停同步？」
之後才看清楚**：暫停 → 兩邊都改 → 解除，那時「最後編輯」是**任意的**。

> **有暫停，就一定要有手動來源；而分岔之後系統該【問】，不該【推】。**

於是三態：`live` · `paused` · **`diverged`**。

⚠️ 而「暫停」今天真正在做的事**不是它的名字**：最硬的場景是
「改一行程式碼 → 積木重 lift → **排版沒了**」，而保住排版要 `nodeId` 穩定（階段 5b）。
**它是 5b 缺席的代償**——5b 之後會縮小，但不會消失（分岔那一個永遠在）。

## 三、我把它範圍錯了一次，而使用者反問糾正

我一度說「VSCode 那側真相是文件，所以不必做」。**理由對，結論錯**：

| | 網頁版 | VSCode／Theia |
|---|---|---|
| 來源是誰 | N 選一 | 文件永遠是來源（**只有這一格**我說對了） |
| 暫停 | 需要 | **同樣需要**：`vscode-code-view.ts:145` 收到 `document` 就重 lift |
| 分岔 | 需要 | **更常見**——文件還會被 git／別人／另一個編輯器改 |

> **「其中一個問題在那邊不存在」推不出「這個機制在那邊不必要」。**

於是機制住 `core/sync-coordinator.ts`，兩個宿主各接一個入口：
網頁版點自己的狀態列，擴充走 **VSCode／Theia 的狀態列項目 ＋ 命令面板**
——**宿主都有的 chrome**，而我們自己畫的工具列不是。

## 四、瀏覽器實測抓到兩件測試看不到的事

**① 分岔永遠偵測不到**，因為 `noteEdit` 被放在殘態守衛**後面**：

```ts
if (this.blocklyPanel?.isStateStale) return   // 擋「不要用殘的工作區覆蓋程式碼」
this.syncCoordinator.noteEdit(...)            // ← 而它也被一起擋掉了
```

暫停時工作區還沒被匯流排畫過（`staleReason === 'not-rendered'`），
於是**暫停期間的積木編輯完全沒被記錄**。

> **「不要拿它去寫」與「不要記得它被改過」是兩件事，
> 而一個 early return 把它們寫成了同一件。**

**② 同一個守衛、兩個呼叫者，而沉默只對其中一個是對的**：
開機時自動寫回不出聲是對的（2026-08-24 才修的誤報）；
**而使用者明確選了「以此為準：積木」卻什麼都沒發生**，他會以為程式壞了。

**③ 順帶**：那條錯誤訊息說「請按『程式碼→積木』重載」——
**而那顆按鈕在同一刀裡被我刪掉了**。
> **一條指向不存在的按鈕的錯誤訊息，比沒有訊息更糟。**

## 五、護欄

**第六十二條**（`audit-sync-entry`）：同步的入口不得有方向按鈕（硬性零）·
來源清單必須從 `viewsWith('editable')` 導出（硬性零）。

⚠️ 而它第一版**假綠**：`viewsWith('editable')` 這個字串出現在 `view-registry.ts`
**自己的註解裡**，被數成一個消費者。排掉宣告處之後才紅。
> **字串剛好出現在某處不算讀取——那可能只是它自己的宣告。**（`annotation-adoption` 的同一條，第二次踩。）
