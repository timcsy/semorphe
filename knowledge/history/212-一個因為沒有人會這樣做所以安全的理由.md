# 212 — 一個「因為沒有人會這樣做所以安全」的理由

> 2026-09-06（spec 174）。從 vision 階段 6.11 最後一條「已知不一致」查下去，
> 而那條**不是待做，是一個帶病歷的決定**——於是去量了那份病歷的**重開條件**。

## 轉變

```
舊   cpp:pin_constant 沒有 lift 路（樣式被拿掉，因為它會搶走使用者宣告的名字）
新   五條樣式回來了，而每一條先問一句：notDeclared ——「這個名字沒有被宣告過」

舊   builtin_constant 的 EOF／NULL 靠名字認人，而【沒有問】
新   同上，也問

舊   enum 成員不進 lift 期的 declarations
新   進了（recordEnumerators）

舊   使用者宣告 enum Marker { EOF = -99 } → 執行時丟「重複宣告」
新   印出 -99
```

## 為什麼

### 一、🔴 那份舊病歷裡有一句話是錯的，而它讀起來很有道理

`pin_constant` 的 `_lift_why` 逐字：

> ⚠️ 既有的 `builtin_constant` 用同一個做法（`EOF`／`NULL` 靠名字 lift），
> 而**那些名字幾乎沒有人會重新宣告**——差別在這裡，不在做法。

去量了。**那句話不成立**：

```
enum Marker { EOF = -99 };  →  EOF 照樣被認成內建常數
cout << EOF                 →  丟 RUNTIME_ERR_DUPLICATE_DECLARATION
```

⚠️ 而那個錯誤訊息**說錯了原因**：使用者只宣告了一次，
而系統啟動時把**全部**內建常數塞進了全域作用域。

> **一個「你重複宣告了」的錯誤訊息，
> 在另一個宣告是系統自己塞的時候，指控的是無辜的那一方。**

> **一個「因為沒有人會這樣做所以安全」的理由，
> 保護的是常見情況——而 bug 住在別的地方。**

### 二、🟢 而那份病歷裡的判準是對的——它只是缺一個地方問

處置逐字：「**沒有人宣告它，它才是環境提供的**」。
而它當時只在**執行期**做得到，所以代價是「**correctness 贏 round-trip**」。

今天 lift 期也問得出來：`LiftContextData` 有 `declare`／`lookup`，
而 `lifter.ts` 真的在餵。缺的只有兩件事：

```
① constraint 表達不出「這個名字必須沒有被宣告」   → 加一格 notDeclared
② enum 成員不進 declarations                     → 加一支 recordEnumerators
```

②的根因值得記：`recordDeclaration` 認的是「一個節點宣告了一個名字」，
而列舉是**一個節點宣告了 N 個名字**（它們住在 `values` 那一格的逗號字串裡）。

> **一個「這個節點宣告了什麼」的收集器，
> 在遇到一個宣告了很多東西的節點時，會安靜地收集到零個。**

### 三、🔴 收益不是 `EOF`，是每一個 Arduino 課的學生

`EOF` 被重宣告確實罕見。而真正的收益是那顆膠囊重開之後：

> 學生從工具箱拖一顆 `HIGH` 積木 → 同步到程式碼 → 再同步回來
> **它還是那顆積木**。

在此之前它會變成「變數參照 HIGH」——而**自動同步一直在跑**。

⚠️ 那個代價 2026 年被明確接受過（「correctness 贏 round-trip」），
而它之所以是一個取捨，是因為當時**兩者互斥**。這一刀讓它們不互斥。

### 四、⚠️ 兩個方向都要驗，而反向那個更容易被忘記

```
有人宣告了   → 不准搶      ← 判例本身
沒有人宣告   → 【一定要認】 ← 那是這些樣式存在的理由
```

> **一個「不要搶」的修法，如果只驗了不搶那一半，
> 那「什麼都不認」也會全綠——而那是把功能刪掉。**

所以測試把**反向那四條寫在前面**。

### 五、🟢 一條刻意留下的界線，而它被釘住了

判斷用的是 lift 當下的作用域，而 lift 是**由上而下的一趟**
——所以「宣告寫在使用**之後**」仍然會被搶。

🟢 那在 C++ 裡本來就不合法（用一個還沒宣告的名字），所以不是真的使用情境。
解掉它要**兩趟掃描**，而那是另一個設計。

> **一條已知的界線如果沒有被釘住，
> 它會在下一個人手上被讀成一個 bug——然後被「修」成一個更大的設計。**

## ⚠️ 四條護欄在這一刀替我說話

| 護欄 | 它說了什麼 |
|---|---|
| `audit-lift-grammar` | `notDeclared` 加進型別而**沒加進它的鍵白名單** → 當場報「不存在的鍵」。🟢 那正是它守的：**JSON 沒有型別檢查，拼錯了沒有人會說** |
| `audit-locality` | `pin_constant` 3 檔（上限 2）→ 顯式上調。⚠️ 三個檔在**同一個目錄**，就近性守的是「散在幾個地方」 |
| `audit-declared-slots` | `cpp:pin_constant` **從「無法確定」畢業了**（140 → 139）——它有 lift 路了，語料驗得到 |
| `component-vocabulary` | 我把函式取名 `conceptOf` → 硬性零當場紅 |

🔴 而 `audit-declared-slots` 那一筆的 reason 值得記：它寫著
「它是 `lift-pattern.json` 的純資料樣式」——**那句話在樣式被拿掉之後就過期了**，
而沒有人回來改。

> **一筆判定的理由如果描述的是「它現在長什麼樣」，
> 那它會在那個樣子變了的那天變成一句錯話——而判定本身照樣通過。**

## 🔴 而它有一個我沒有預期的後果：課程的宣告要跟著動

`HIGH`／`OUTPUT` 從「變數參照」變成「腳位常數」之後，**八堂 Arduino 課的
`components` 宣告全部不對了**——而護欄兩個方向都說了話：

```
用到而沒宣告   8 課要【加】 cpp:pin_constant
              🔴 訊息逐字：「學生在課堂上會找不到這幾顆積木」
宣告了用不到   2 課要【拿掉】 cpp:var_ref
              ——那兩課唯一的「變數參照」就是腳位常數本身
```

⚠️ 而我在中間**撤錯了一次**：以為那兩課是「補多了」，撤回之後照樣紅
——因為多餘的是 `var_ref`，不是 `pin_constant`。

> **一個「宣告與實際不符」的護欄報了兩次紅，
> 而它們指的是【不同的元件】——只讀「紅了」而不讀它報了什麼，會撤錯方向。**

🟢 **課文的對照圖也重產了**（8 張變動）——那正是 2026-09-05 補上
`engineHash` 要抓的那種：**積木的畫法改了，而課文一個字都沒改**。
