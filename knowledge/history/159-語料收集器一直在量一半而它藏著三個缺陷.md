# 159 · 語料收集器一直在量一半，而它藏著三個缺陷

**日期**：2026-08-26

## 起點：兩顆格式化 I/O 退場

`cpp_input_formatted`／`cpp_print_formatted` 改用宣告式的可變參數建構子
（與 `cout <<`／`cin >>` 同一個）。判準是 `retire-imperative-block` 第 1 步
「**判哪一邊對**」——宣告那份把參數擠進一個文字欄位（`ARGS: field_input`），
而 `component.json` 說 `children: ['args']`：**參數在語義上是子節點**。

缺的兩個機制當天補上：`headInputName`（`FORMAT_ROW`——路線圖 2026-08-21
就記著「啞輸入的名字要對得上，建構子要能指定」）與 `slotPrefix`（逗號）。

🪦 而**多模式插槽的整套機制**（93 行 ＋ 三組 mutator）隨之刪除：

> **一個機制的存在理由，可能在另一條線做完的那天消失
> ——而它不會自己出聲，因為它還跑得動。**

## 🔴 而真正的收穫是第三十二條護欄的語料收集器

它的正規式是

```
/`([^`]{4,600})`/g
```

——**把長度條件寫進配對規則裡**。於是一段少於四個字元的反引號片語
（註解或測試名字裡的 `` `&x` ``）**不匹配**，那個開頭的反引號沒有被消耗，
它的結尾反引號變成下一段的**開頭**——從此整個檔案的配對錯開一格，
把後面真正的語料整段吞掉。

> **把一個【內容的條件】寫進【配對的規則】裡，
> 不符合條件的那一段不會被丟掉——它會讓後面的每一段都錯位。**

修好之後語料 **345 → 619 段**（幾乎翻倍）。⚠️ 而它是怎麼被發現的：
我在一支測試的名字裡寫了 `` `&x` ``，語料總段數少了 2，那條護欄紅了。
**如果我沒有剛好寫下那兩個反引號，它會繼續量一半。**

## 它當場照出三個缺陷

```
① freq[c]++ 丟「這個東西不能被指定值」   cpp:map_at 沒宣告左值解法
                                        （2026-08-26 左值接點化的迴歸）
② for (char c : s) 迴圈一次都不跑        cpp:loop_range 只認 array
③ std::map 是有序的，而我們是插入序      mapInsertSorted
```

①**沒有任何測試變紅**。而它與收集器那個缺陷疊在一起：

> **兩個缺陷疊在一起時，上面那個會讓下面那個看不見。**

②的形狀特別值得記：

> **一個「條件沒中就整段跳過」的執行器，
> 把「還沒支援」變成了「安靜地什麼都不做」。**

## 順帶第四個：`scanf("%d", &a[i])` 的 `&` 掉了

產生器問的是「這個參數是不是 `variableRef`」，於是只有 `&x` 加得回 `&`
——而 `&a[i]` 產回去變成 `a[i]`，**編不過**。
它的另一半條件 `!a.properties.noAddr` **從來沒有人設過那個屬性**。

> **一個永遠不會成立的條件，讀起來像一條規則，而它什麼都沒管到。**

🟢 修法是問一個**宣告的性狀**：`traits.addressable`
——而那一組正好就是「宣告了左值解法」的那一組：
**一個取得到位址的東西，就是一個寫得回去的位置。**

## 剩下的一筆誤差

`int` 溢位不繞回（`100000 * 100000` 我們算 10000000000，參照繞成 1410065408）
——**模型的決定**，已具名判定。🟡 而它可以被重新討論：對教學工具來說
「為什麼我的答案變成負的」正是要教的東西之一。
