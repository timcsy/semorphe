# 279 — 宣告說得出而形態沒做的那八顆

**2026-09-21** · 第 217 刀 · 分支 `217-expression-forms`

第一百二十六條護欄（第 210 刀）落地時掃出 **8 顆**，而它的檔頭說那是
**起點不是缺陷帳**：每一顆有兩種修法，選哪一種要逐顆判斷。

```
補形態    那個位置真的會出現（`while ((x = f()) != 0)` 這種）
改宣告    positions 寫寬了 → 拿掉 expression
```

## ① 先查：「改宣告」對八顆**都不成立**

八顆的 `_positions_why` 逐條讀過，**每一條寫的都是文法上的理由**：

```
a = b        回傳左值
v.erase(it)  回傳 iterator
cout << x    回傳 ostream&
m[k] = v     回傳 mapped_type&
```

而 `positions` 的定義就是**文法**（`role` 才是產生器契約）。
拿掉 `expression` 等於在宣告裡說一句假話。

## ② 所以問的是第三個問題，而那要量

> **文法上放得進去 ≠ 我們的 lift 真的會把它放進去，
> 而「lift 放得進去」≠ 渲染那一側畫得出來。**

```
文法上放得進去   八顆都是
lift 真的放進去  八顆都是（探針量到插槽 left／value／exprs）
渲染畫得出來     ❌ 八顆都是 cpp_raw_expression
```

🔴 **所以它們是真缺陷，不是理論上的漏洞**——學生寫
`while ((x = y) != 0)`，積木那一側今天就是一塊灰的。

## 🔴 而探針第一版整批報「畫不出來」——包括語句位置

那不可能（`cout << 1;` 在應用裡顯然畫得出來）。真相是探針**沒有把渲染那一套
註冊起來**（`BlockRegistrar` ＋ `PatternRenderer` ＋ 下拉來源 ＋ 語系）。

> **一份「有 N 個缺陷」的報告，先問那 N 裡有幾個是量測工具自己的。**
>（CLAUDE.md 逐字，而這是今天第四次成立。）

🟢 現在探針**每一列都有「語句位置」那一欄當錨點**，錨點倒了就直說
「這支探針壞了，那一列的讀數不算數」。

⚠️ 還有一次更細的：`cpp_var_assign` 一度顯示「運算式位置 🟢 有」
——而那是被 while **主體裡**那顆語句位置的 `var_assign` 騙了。

> **「某個型別出現在某處」不等於「那顆節點畫成了它」。**

## ③ 補形態：七顆機械、一顆卡在機制上

七顆各複製中性形態、換 `output`、加 `form: {axis:'role', value:'expression'}`
——**沿用同一組標籤與顏色**（第 127 條：同元件同色）。灰塊 1 → 0。

🪦 **`cpp:container_push` 做不到**：`buildFormSets`
（`core/projection/form-selection.ts`）**一個元件只支援一條軸**，
而它已經用了 `container_kind`（stack／queue）。再加 `role` 會把
`expression` 混成 `container_kind` 上的一個值。

> **一個「只差一筆」的清單，那一筆常常不是被漏掉的——是機制裝不下它。**

棘輪 **8 → 1**。

## 🔴 而補完之後，另一條棘輪【退步】了——它的判準是錯的

`audit-category-colour`（第 52 條）從 53 跳到 **56**，而顏色的一致性
一格都沒有變差。原因是它**同一個問題數兩次**：
第 127 條護欄強制同元件同色，所以變體形態**不可能**與中性形態不同色。

> **一條「只准下降」的棘輪，如果它的母體會因為【做對事情】而變大，
> 那它擋的就不是退步，是那件對的事。**

🟢 判準改成「一個元件只數一次」，連帶把既有 6 筆重複也去掉：**53 → 47**。
⚠️ **不是把基線上調**——上調會讓它往後默許真的退步。判準錯了就修判準。
