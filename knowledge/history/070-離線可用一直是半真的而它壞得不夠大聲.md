# 070　「離線可用」一直是半真的——而它壞得不夠大聲

> 日期：2026-08-16（spec `128`）
> 觸發：委派編譯器的 COOP/COEP 探針，**而這不是它要驗的東西**。

## 轉變

```
old  「離線可用」是這個專案的既成事實——沒有伺服器，載完就能跑
new  🔴 執行期有【4 個外部請求】，而離線時 Blockly 的圖示會壞掉
     沒有人發現，因為它壞得很安靜：只是變破圖，功能還在
```

## 一、它是被別的東西掀出來的

為了驗委派編譯器的前置（`coi-serviceworker` 能不能在 GitHub Pages 上
給出 `crossOriginIsolated`），把 semorphe 放進 COEP `require-corp` 環境。
前置驗過了——**而 COEP 順手擋掉四筆**：

```
image  https://blockly-demo.appspot.com/static/media/sprites.png
fetch  .../click.mp3   .../disconnect.mp3   .../delete.mp3
```

⚠️ **而歸因跑過對照組**：同一份 build 不加 COEP → 圖示完全正常。
沒有那個對照組，這會被記成「COEP 弄壞了東西」而不是「COEP 讓一個既有缺陷現形」。

> **一個探針最有價值的產出，常常不是它要驗的那件事。**
> （已進 [experience](../experience.md)）

## 二、為什麼十個月沒有人發現

**因為它壞得不夠大聲。** 離線時圖示變破圖，而**功能全在**——
縮放還能縮放，垃圾桶還能刪。沒有人會為了一張破圖開 issue。

> **一個安靜降級的缺陷，不會被使用者回報，也不會被護欄抓到
> ——因為兩者都在等一個「壞掉」的訊號，而它沒有發出來。**

## 三、第四十五條護欄，而它的量測單位是刻意選的

```
靜態掃網址      🔴 誤報一整片（SVG 的 xmlns、註解裡的連結、schema 字串）
發出去的請求    🟢 沒有誤報的空間——發了就是發了
```

⚠️ **而它住在 `e2e/`，不是 `tests/integration/`**——瀏覽器真的發出去的請求
在 vitest 裡量不到。**那個位置引發了護欄的計數分歧**，
判準寫在 [執行機構](../concepts/執行機構.md)「護欄怎麼數」。

### 🔴 而它配了一條反方向，因為它自己有瞎點

> **一條只斷言「沒有向外要」的護欄，對「根本沒要到」是瞎的。**

一個把資源路徑設成**不存在位置**的實作，一個外部請求都不發
——**照樣綠，而圖示全部消失**。所以補了「自託管的檔案真的要到了幾個」。

## 四、修法選了「建置時複製」而不是「簽進版控」

第一個念頭是把 Blockly 的 16 個媒體檔簽進 `public/`。
⚠️ 而那會讓升級 Blockly 時圖示**停在舊版**——**與原本那個缺陷同一族（安靜地不對）**。

> **複製品的正確性靠人記得同步，而人不會記得。**

→ `vite.config.ts` 從 `node_modules/blockly/media` 複製，`.gitignore` 掉
（它是產物不是原始碼）。⚠️ 而 `media` 這個選項 **`BlocklyPanel` 本來就接好了，
只是從來沒有人傳**——「機制有了沒人接上」的第五個實例。
