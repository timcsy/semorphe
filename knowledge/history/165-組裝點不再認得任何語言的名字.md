# 165 · 組裝點不再認得任何語言的名字

**日期**：2026-08-26

## 結果

```
language-plugin   選單接線 0（硬性零，早就是）｜語言管線 12 → 0
layering          組裝點豁免 9 → 0
four-independences  compositionRootImportsLanguage 10 → 0
```

`app.ts` 裡**一行 `cpp/*` 的 import 都沒有了**。

## 🔴 而 vision 說的「深度交織」查證後不成立

那一項的警告逐字是：

> 「⚠️ 要它歸零得把整個 bootstrap 搬進**安裝鉤**，而那些呼叫與 `app.ts` 自己的物件
>  （`this.scaffold`／`this.syncController`／閉包）**深度交織**。」

而**安裝鉤 2026 年就已經存在**（`language-packs.ts` 的 `install?: () => void`），
C++ 套件也早就在用它。那句話寫的是更早以前的狀態。

真正交織的**不是程式碼，是那份 std 模組登記表沒有主人**：
相依解析、鷹架、程式碼修補、自動引入**四個消費者共用它**，
而組裝點在替它們傳遞。

> **會互相咬住的幾個能力，交出來的是一個裝配好的東西，不是零件。**

→ `createCodeShaping()`：語言套件建一次、裝配好交出來。九處變成六格宣告：

```
installLifters · installExtractStrategies · declarations
diagnosticRules · styleExceptions · createCodeShaping
```

## 🔴 而「數字歸零」不等於「可抽換」——那一條驗收本來沒有人在問

兩個維度都 0，**而它們只證明組裝點沒有寫死語言的名字**。
第三十九條護欄自己踩過同一個坑（它的基線逐字記著）：

> **抽介面讓一個相依【可抽換】，不是讓它【消失】
> ——而一條用名字認耦合的檢查，會把前者報成後者。**

補了兩支：
- **每一格語言能力都必須是可選的**（`?`）——一格必填就等於「每個語言都得有它」
- **Python 今天真的沒有其中三格，而 app 起得來**——釘住事實，不只釘契約

⚠️ 而它逼出一個設計判斷：`createCodeShaping()` **回傳 `null` 是合法的**。
一個沒有 `main` 的語言不必假裝有——**而那正是在此之前沒有人問過的問題**
（組裝點寫死 C++ 那一份，於是切到 Python 時鷹架仍然是 C++ 的）。

## 順帶：一條只擋變差的棘輪

`audit-language-plugin` 的語言管線那一支用的是裸 `toBeLessThanOrEqual`，
**不像其餘棘輪會在改善時要求下調**。於是刪掉注入契約還掉的 3 處（12 → 9）
**沒有任何東西出聲**，基線停在 12——它從此擋不住 9 退回 12。

> **一條只擋變差的棘輪，會讓每一次改善都無聲地離開它的守備範圍。**

換成共用的 `assertRatchet`，它當場報「12 → 9」。
