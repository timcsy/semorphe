# 132　語料是我寫的，所以它沒有「我不會寫的形狀」

**日期**：2026-08-22 ｜ **交付**：括號的 `layoutHint`、語料 95 → 98、來回比對的正規化
**前一則**：[131](131-一個分類裝了一半的積木它就是其餘.md)
**觸發**：使用者截圖——「運算式的括號處理一下」

## 事情

一元二次方程式，教學語料裡最基本的那一種：

```python
x1 = (-b + D)/(2 * a)
```

畫出來是 `設定 x1 為 ⟨直接寫運算式⟩ ÷ ⟨直接寫運算式⟩`——**一半是灰的**。

而那一刻的量測是：**語料 95 段、答案不同 0、執行失敗 0、來回不同 0、降級節點 0**。

## 轉變：五個零說的是「這 95 段」，不是「Python」

查下去：**95 段裡帶括號子運算式的有 0 段。**

護欄沒有壞——帶括號的程式會被算成**降級 ＋ 執行失敗**，兩軸都會說話。
**是語料裡沒有那種程式。**

🔴 而同一段程式當場撞出第二個：`D = b**2 - 4*a*c` 產回 `b ** 2 - 4 * a * c`，
來回那一軸報了差異。**那 95 段之所以全過，是因為它們的空白剛好都是產生器的寫法。**

> **一份由寫實作的人寫的語料，連【空白】都會遵守那個實作的習慣。**

### 為什麼會這樣——而它不是「忘了寫括號」

語料的檔頭防的是一個**相鄰的**病：

> 「一份照著實作挑的語料，量出來的永遠是滿分。」

我確實沒有照元件清單挑。**可是我是照「我對 Python 的想像」挑的**
——而那個想像與寫實作的是同一顆腦。它產出的是**一個一個語言特性**
（`total += i`、`d.get(k, 0)`、`sorted(key=)`），
而人寫教學程式時寫的是**一條公式**，而公式有括號。

```
參照直譯器治的   「這段程式的答案對不對」   ← 累計抓到 27 筆
它治不了的       「這段程式在不在語料裡」
```

## 兩個處置

**① 括號變成可以表達的**：`unwrap` 樣式多一個 `layoutHint`，
把「這裡本來有一對括號」記在被拆出來那顆身上。
⚠️ **只拆不記會改到使用者的碼**：產生器只補回**必要的**括號，
於是 `a + (b * c)` 產回 `a + b * c`。C++ 那側是同一個病，同一刀收掉。

**② 來回的比對分開「縮排」與「行內空白」**：縮排在 Python 是語義，
行內的不是。⚠️ 而**不能一律去掉空白**——`not x` 去掉之後是 `notx`，
於是「產生器漏了一個空格」這種真缺陷會變成看不見。
只去掉**貼著標點／運算子**的那些。

## 而語料的形狀缺口是查得出來的

這一則真正的產出不是那對括號，是一個可以重複跑的動作：

```
對語料做一次語法統計 → 零的那一格就是下一個洞
  有幾段有括號        95 → 0    ← 就是這一個
  有幾段有巢狀
  有幾段的空白不是正規的
```
