# 081　第一刀畫得出積木了——而路上三個坑**一個都不會拋錯**

> 日期：2026-08-17　spec 138（階段 6.13 第一刀）
> 這一刀的性質是**否證**：畫布在 Arduino IDE 裡跑不動的話，後面全部不必談。
> 而它的規格寫了一條前所未有的驗收：**SC-007「畫布跑不動也算成功」**。

## 一、🔴 三個坑，**一個都不會拋錯**

這一刀真正的產出不是那顆積木，是**這張表**：

| # | 坑 | 症狀 | 誰抓到的 |
|---|---|---|---|
| ① | Blockly 的 `media` 少一個尾端斜線 | 縮放鈕／垃圾桶**破圖，功能還在** | 事前推論（`vite.config.ts` 檔頭有病歷） |
| ② | CSP 漏 `img-src data:` | `+`／`-` 按鈕**破圖，功能還在** | 事前推論（`block-registrar.ts:291`） |
| ③ | **CSP 漏 `connect-src`** | 🔴 **音效 `fetch` 被擋，`PAGEERROR Failed to fetch`** | **實測撞出來的** |

### 而 ③ 是新的——PoC 沒遇過，draft 沒記過

```
Fetch API cannot load …/media/click.mp3.
Refused to connect because it violates the document's Content Security Policy.
```

⚠️ **`media-src` 擋不住它**：那條管的是 `<audio>`／`<video>` **元素**，
而 Blockly 走的是 **`fetch` ＋ `AudioContext`**。

> **兩條看起來管同一件事的指令，管的其實是兩條不同的路。**

而它為什麼沒被事前想到：`media-src` 這個名字**看起來就是管媒體的**，
所以它讓人**停止追問**。

> **一個名字對得剛剛好的設定，會讓人以為那一格已經填完了。**

### 🔴 而還有一個坑是**我自己造的**，它同一族

第一版的 HTML 用行內 `<script>` 注入 media 根：

```html
<script>window.__SEMORPHE_BLOCKLY_MEDIA__ = "…";</script>
```

而 `script-src` 用的是 cspSource（沒有 nonce、沒有 `'unsafe-inline'`）
——**行內腳本一個字都不會執行**，而症狀是「畫布一片空白」，
**沒有任何錯誤指向那一行**。

處置：改走 `data-blockly-media` 屬性。**CSP 根本不管 data 屬性。**

> **一個要靠 nonce 才活得下來的東西，就是一個會被忘記加 nonce 的東西。**

## 二、而預檢頁自己噴的錯，反而**證實**了一條推論

預檢頁第一版自己寫了一條寬鬆的 CSP（沒給 `style-src 'unsafe-inline'`），
Chromium 噴出五則「Applying inline style violates…」。

🟢 **那不是壞消息，是一次免費的驗證**：它**實測證實**了
Blockly 確實在執行期注入行內樣式——原本那只是一句從
`Blockly.Css` 推論出來的話。

⚠️ **而它同時暴露了一個真的缺陷**：預檢頁與真面板有**兩份 CSP**。
處置是讓預檢頁呼叫同一個 `csp()` 函式，只換來源。

> **一個「只是拿來預檢」的東西，如果自己有一份設定，
> 那它預檢到的就不是那個要上線的東西。**

## 三、🔴 判準錯了一次，而錯的方向很有代表性

「畫布上那顆積木要**從登錄表挑**」（FR-004）。
第一版的挑法是「**欄位（`args0`）最少的那一顆**」——它挑到 `cpp_array_2d_declare`。

```
我以為   args0 長度 0 = 最簡單
實際     args0 長度 0 = 這份 JSON 根本沒在描述這顆積木
```

那顆的真正定義是**命令式**的，住在 `ui/block-registrar.ts:503`
——動態插槽要 `+`／`-` 按鈕，而宣告式的 `args0` 描述不了。

> **一顆定義住在別處的積木，證明不了「積木來自登錄表」。**

處置：加上第四條「`message0` 必須存在」。209 筆規格裡的候選
從 108 收斂到 **103**，挑到 `cpp_break`。

⚠️ **這個錯的形狀值得記**：我用一個**數量**去代理一個**性質**
（「欄位少」代理「簡單」），而那個數量在「這一格沒填」與
「這一格填了 0」之間**分不出來**。

> **一個把「沒有」與「零」編碼成同一個值的量，遲早會拿零去回答沒有。**

## 四、護欄與規格指向同一件事——**那通常表示判準是對的**

目錄選 `src/vscode/` 的理由是「護欄掃得到」。而它有一個
**立刻生效**的後果：第二十八條（膠囊就近性）反向也問
「資料夾裡的東西都屬於這顆元件嗎」，所以
**`src/vscode/` 裡寫死任何 conceptId 都會紅**。

🟢 **而那正好就是 FR-004 要的**。

> **護欄與規格指向同一件事，那通常表示判準是對的。**

⚠️ 而 draft 說「3 支護欄掃 `src`」是**低估的**——實測 **6 條 ＋ 1 個共用 helper**。

## 五、兩個「本來以為要付、結果沒付」的代價

### ① esbuild／CJS 那個 4.6 KB 的坑——**繞開了**

`registry.ts:22-48` 記著：esbuild 建得出 CJS，**而 189 顆膠囊一顆都沒被打包進去**，
只發一則 warning、執行期才炸。

🟢 **本輪碰不到**：積木畫布住在 **Webview**，那是**瀏覽器環境**，
一個普通的 Vite browser build（ESM）就到位。擴充主行程那一側
（CJS）本輪**不載膠囊**。

```
extension.js   4.25 KB   3 modules   ← 只有 activate ＋ 面板接線
webview.js     2.64 MB   984 modules ← 200 顆膠囊在這裡
```

⚠️ **但它沒有消失**：雙向同步那一刀要在主行程跑 lift／generate，
**它會原封不動地回來**。處置也已經寫在那個檔頭裡（Vite `ssr`＋`lib`＋`cjs`，已實測）。

### ② `tsconfig` 的 `"types": ["vite/client"]` ——**不影響**

事前標成「未驗」，怕它讓 `import 'vscode'` 找不到型別。
🟢 **兩分鐘驗完：不影響。**

> **`types` 陣列管的是「自動載入哪些全域型別」，
> 而 `import 'vscode'` 走的是模組解析——兩條不同的路。**

⚠️ 而**把它排在第一步是對的**：不通的話前面全部要重做。
