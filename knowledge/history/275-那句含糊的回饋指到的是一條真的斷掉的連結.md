# 275 — 那句含糊的回饋，指到的是一條真的斷掉的連結

**2026-09-21** · 第 213 刀 · 分支 `213-lesson-links`

前一則（[274](274-學生上完之後那四條回饋各自指向什麼.md)）處理了老師整理的四條，
而學生原話裡還有一條**沒有結案**：

> 我覺得網站有一些bug**有一些案下去不會到他寫的部分**。
> 網站疑時很完善了只是有一些感覺太擠其他還可。

⚠️ 它含糊到沒辦法直接修——「有一些」可能是任何一顆按鈕，而沒有重現步驟。

## 🟢 而含糊的回饋仍然可以被**窮舉**

不去猜他按的是哪一顆，改問「**這個站上總共有幾條連結，其中有幾條按了沒東西**」：

```
出站的 HTML      78 份
站內連結         977 條
指不到任何檔案   1 條
```

那一條是：

```
cpp-advanced/06-Linked List  →  ../../c-bridge/03-指標/lesson.md
```

## 🔴 兩邊各自都是對的，而它們對的是不同的東西

```
在 repo 裡讀 markdown   那條相對路徑指到另一份 lesson.md      🟢 按得到
出站之後                那個位置是一個資料夾 ＋ index.html    🔴 404
```

課文的作者在編輯器裡按過那條連結，**而它在那裡是通的**。

> **一條在來源裡正確的相對路徑，在投影之後指到的是投影的形狀
> ——而沒有人會去按來源。**

⚠️ 這與這個專案的老問題是同一個形狀：`lessonDocHref`／`lessonIdFromQuery`
那一對的檔頭早就寫著「兩邊分開住的話，中文課名的 encode 遲早會不一樣」。
**這條連結就是「分開住」的第三份**——它住在 markdown 裡。

🟢 修法：產生器多一步 `withLessonLinks`，把 `…/lesson.md` 交給
`lessonDocHref`（唯一那份「課程 id → 出站網址」）。
**來源那一側不動**——在 repo 裡讀 markdown 的人仍然按得到。

## 🔴 而寫護欄時，量測工具自己先錯了一次

第一版把 195 條**正常的**上一課／下一課全報成壞的：
`lessonDocHref` 會把中文課名 percent-encode，而我只 decode 了讀到的那一側。

> **一份「有 N 個缺陷」的報告，先問那 N 裡有幾個是量測工具自己的。**
>（`CLAUDE.md` 逐字，而這是它今天第二次成立。）

⚠️ 第二個更值得記：我本來給 `whyBroken` 加了一條退路
——「repo 根目錄下有這個檔就算數」。而
`/lessons/c-bridge/03-指標/lesson.md` 在 repo 裡**真的存在**，
於是那條退路會讓這條護欄**對它自己的誕生原因瞎掉**。

> **一條為了少報幾筆而加的退路，最容易放過的就是你正在修的那一筆。**

🟢 抓到它的是注入測試（餵合成的那條路徑，要求它被認出來）。

## 落點

- `tools/build-lessons/render.ts` — `withLessonLinks`
- 第一百三十條護欄 `audit-lesson-links`（硬性零，不讀 `dist/`，
  跑產生器自己那幾支純函式）
- 🟢 **規格頁的網址問它自己**（`<link rel=canonical>`）而不是手抄 `/lessons/specs/`
  ——手抄一份的話，它搬家那天這條護欄會說它 404

同一則回饋的後半段（版面太擠）沒有量測方法，也沒有重現。記在這裡，不要假裝結案。
