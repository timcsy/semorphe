# 158 · `cin >>` 改用 `cout <<` 的建構子——而「缺的機制」不缺了

**日期**：2026-08-26

## 轉變

```
舊   cpp_input 缺「多模式的插槽」（一格可以是變數下拉、也可以是接點）
新   不缺——改用與 cpp_print 同一個可變參數建構子，每一格都是接點
```

路線圖那一行逐字寫著：「`cpp_input` 是「**多模式的插槽**」」，
而它是 **2026-08-24** 寫的——**在左值接點化（2026-08-25／26）之前**。

左值接點化之後 `cin >> x` 的語義樹已經是 `values: [cpp:var_ref{x}]`，
而每一顆賦值積木都改成用**接點**裝它的左值。於是那個 select 模式
只剩下一個理由：**少一層巢狀**。而它的代價是：

```
cin  >> x >> y    讀取輸入 → 變數 [x▾] >> [y▾]     ← 下拉
cout << x << y    輸出 [變數 x] [變數 y]            ← 接點
```

> **兩個鏡像的運算，投影不該長得不一樣。**

⚠️ 而變數下拉**沒有消失**——它在 `cpp_var_ref` 積木上。

> **一份路線圖項目寫著「缺的是 X」，而 X 在別的目的下被做出來了
> ——那條就不再是待辦，是誤導。**
> （[history/120](120-一份路線圖寫著缺什麼而那個東西在別的目的下被做出來了.md)，
> 而這是**同一個路線圖項目上的第三次**：2026-08-21 兩次、今天一次。）

## 🔴 而這一刀路上抓到三個東西

### ① 比對護欄看不到它要驗的那一類

`audit-block-def-parity` 的建置函式第一行是 `if (!def.message0) return null`。
而**用建構子的宣告本來就沒有 `message0`**（形狀由建構子長出來）——
於是它們被歸進「沒有 message0 或建不起來」那一桶，**而那一桶不進比對**。

> **一條護欄的能力邊界，如果剛好切掉它要驗的那一類，
> 它的綠燈就與「沒有人在看」等價。**

⚠️ 這是 `retire-imperative-block` 第 2.5 步的**第七次**——前六次都是
「比對器缺一樣東西所以指控宣告」，這一次是「**比對器直接不看**」，
症狀因此更難發現：**報表上少一行，而沒有任何東西變紅**。
修法：照抄產品那條路的分岔（`args0` 非空 → `attachVariadic`，否則 → `defineVariadicBlock`）。

### ② 一支手寫抽取策略，用同一個預設值把資料遺失蓋掉

`extractInput` 讀 `extraState.args`，而那個鍵隨建構子換掉了。它的退路是

```
const singleVar = block.fields.SEL_0 ?? block.fields.NAME ?? 'x'
```

於是 `cin >> a;` 來回轉換之後變成 **`cin >> x;`**。
抓到它的是「來回轉換逐字相同」那個**對照組**，不是型別檢查。
（`experience`「靜默降級是 bug 的藏身之處」的第 N 次。）

### ③ 骨架變了而**一個欄位都沒動**

`compose` 模式的格子連一個欄位都沒有，變的是 `extraState` 的記憶方式
（`{args:[…]}` → `{itemCount}`）。原本的失效判定只看 `fields`，會漏掉一半。

> **一個只看得見欄位的失效判定，看不見「同一顆積木換了記憶方式」。**

→ `ShapeChange` 長出 `retiredExtraState`。

## 順帶

`cpp:input.name` 這個屬性刪除——**lift 從來沒有填過它**
（`cin >> a >> b` 有兩個目標，全在 `values` 接點裡）。
`extractInput` 塞的 `{ variable: … }` 一併消失（第三十四條長年報的「讀了沒宣告」之一）。
標籤 `讀取輸入 → 變數` 改成 `讀取輸入 →`——那個「變數」是下拉的抬頭，
接點化之後會讀成「讀取輸入 → **變數 變數 x**」。
