# 229 · 程式碼早就在使用點把它翻譯成「槽」了

> 2026-09-13 · 使用者拍板：「我還是希望全部改 slots」

## 舊 → 新

```
SemanticNode.children      →  SemanticNode.slots
ComponentDef.children      →  ComponentDef.slots
component.json "children"  →  "slots"
ChildrenAsField            →  SlotAsField（檔案一併更名）
名詞表的 attachments        →  退場，拆成 slots ＋ ports
名詞表的 Link              →  Edge
```

## 為什麼改：那個字在使用點早就被翻譯掉了

查證的時候翻出這一段（`core/component/traits.ts`）：

```ts
export function slotsOf(componentId: string): { slot: string; isBody: boolean; ... }[] {
  const children = (c?.manifest as { children?: ... })?.children
```

**函式叫 `slotsOf`，回傳的東西有一個 `slot` 鍵，而它讀的欄位叫 `children`。**
`extraState` 那一側也早就叫 `childSlot`。

> **一個需要在每一個使用點被翻譯成另一個字的欄位名，
> 說的不是「兩個字都可以」——是那個欄位名選錯了。**

而 `children` 暗示的是**有序的清單**，實際上它是**具名的洞**
（`{ condition, then_body, else_body }`）。W3C 對 `<slot>` 的定義逐字是
「a placeholder inside a Web Component that you can fill with your own markup」
——那正是這個東西。

## ⚠️ 建議過「不要改」，而使用者堅持，這是對的

我當時的理由是價錢：**335 個宣告檔、233 個 `forms/` 目錄旁的膠囊、213 支測試**。
而實際做完之後，那個理由站不住：

```
tsc 抓出來的誤改   7 處（全是 DOM 的 element.children）
執行期才會壞的     29 處（tree-sitter 的 AstNode——見下）
真正的人工判斷     4 個（AstNode／LevelNode／DOM／變數遮蔽）
```

**機械的部分是機械的，而編譯器做掉了絕大多數判別。**

## 🔴 而這一刀真正的教訓：型別檢查不到的那一半在哪裡

`AstNode` 是 **tree-sitter 節點的結構化轉型**——介面是我們寫的，物件是人家給的。
把介面的 `children` 改成 `slots`，**`tsc` 完全滿意，而執行期讀到 `undefined`**。

> **一個結構化轉型的介面，改它的欄位名不會有人攔你
> ——因為編譯器檢查的是你的宣告，不是對面真的長什麼樣。**

🟢 救回來的方法是**把宣告改回去，讓編譯器去指出每一個讀它的地方**：
`AstNode.slots` → `children` 之後，`tsc` 當場列出 29 行。**編譯器當判別器，不當守衛。**

⚠️ 而 `tests/` **不在 `tsconfig.include` 裡**，所以同一招在測試上失效了一輪
（9 個檔的假 AST 節點被改成 `slots`，產品讀 `children` → 十幾支紅）。
臨時開一份含 `tests` 的 tsconfig 之後，同一招又生效。

> **一份沒有被型別檢查的測試，在重構的時候不是「比較寬鬆」，是【看不見】。**

## 三個編譯器抓不到、只能靠跑測試抓到的

```
tests/helpers/toolbox.ts     走 levelTree 的行內結構型別 → 課程清單少 280 顆元件
examples/ 那個獨立範例        不在我掃的目錄裡 → 第五十八條護欄紅
src/languages/*/topics/*.json  levelTree 的 children 是【有序子層】，不是槽
```

最後一個是判斷題不是機械題：**`LevelNode.children` 與 `AstNode.children` 都留著**，
因為它們真的是「子節點」而不是「具名的洞」。

## 順帶退役的一條護欄判準

`audit-lesson-pages` 的「66 筆 lastmod 卻只有 1 種日期 → 那是 checkout 時間」
在這一輪誤報了：前一個 commit 一次改了全部 66 課，日期**真的**只有一種。

它分不出「淺複製壞掉」與「一次合法的大改」。而它守的那個缺陷**上游已經堵死**
（`lastmodFromGit` 淺複製一律不給日期，由「④之六」直接驗那段程式碼在不在）。

> **一個用「結果看起來對不對」當判準的檢查，會在世界合法地長成那個樣子的
> 那天誤報——而誤報過一次之後，它就開始被當成雜訊。**
