# 129　一個插槽，比一個「最多兩層」的欄位多表達了無限層

## 這一則不是「又做了幾顆元件」——是**三次同一個病之後的做法轉變**

### 轉變一：把運算式壓成字串，第三次

| 何時 | 哪裡 | 症狀 |
|---|---|---|
| 2026-08-21 | `obj.method()` 的名字用 `extract: "text"` | 每一種新的接收者變成一道新的解析題 |
| 2026-08-21 | 指派的左邊 `self.name` | 建立了一個名字叫 `self.name` 的區域變數 |
| 2026-08-22 | 指派的左邊 `grid[1][1]` | 正規表示式拆出來的名字是 **`1][1`** |

前兩次都是**在那個字串上多加一段解析**修好的。第三次沒有：
`python:container_assign` 與 `python:member_assign` 把左邊變成一個**接點**，
於是巢狀**自然成立**（`grid[1]` 本身就是一顆「取那一格」）。

> **一個把運算式壓成字串的欄位，修它的方式不是把解析寫得更好——是不要那個字串。**

⚠️ 而那個決定**早就寫在原地了**：一般指派的樣式 `_why` 逐字寫著
「等 `python:array_assign` 那批來收」。**它等了一天。**

### 轉變二：「最多兩層」的欄位 → 一個「再外面一層」的插槽

巢狀推導式（`[x for row in g for x in row]`，攤平二維表）之前整顆降級，
而那**是對的選擇**（收一半會產出一個少了一層迴圈的合法運算式）。

第一版的設計是「加第二組欄位」——像同族的串接比較那樣收兩段、三段以上降級。
而推導式有一個比較的形狀沒有的東西：**每一段的形狀完全一樣**。

於是：一顆 `python:loop_iter`（一段走訪來源）掛在一個 `outer` 插槽上，
**而它自己也有一個 `outer`**。

> **一個「再外面一層」的插槽，比一個「最多兩層」的欄位多表達了無限層
> ——而它們的實作成本一樣。**

⚠️ 判準：**每一層的形狀一樣嗎？** 一樣 → 遞迴的插槽；不一樣（例如串接比較的
運算子是**兩兩之間**的）→ 有界的欄位。

### 轉變三：「未知概念」與「宣告過的降級」不該長得一樣

`unresolved`（子節點認得出、外層認不出）沒有執行器，於是它掉進
**「未知概念」**那條路，而使用者看到的是

```
RUNTIME_ERR_UNKNOWN_COMPONENT: {"component":"unresolved"}
```

——我們的內部詞彙。同族的 `raw_code` 說的是「這一段程式我看不懂」。

補了執行器之後，**孤兒實作護欄報它**——因為那條護欄只認得**一種**宣告
（概念定義檔），看不到 `declareNonComponent` 那一張表。

> **一條「有實作要有宣告」的護欄，如果只認得一種宣告，
> 它會把第二種宣告底下的實作全部叫成孤兒。**

## 而參照直譯器持續在付錢

這一則涵蓋的四輪擴語料，每一輪都再抓到新的**靜默錯答案**：

```
print(1, end=" ")          印出 1 ['__kw__end', ' ']   ← 關鍵字包裝洩漏給使用者
except X as e              「沒有這個變數 e」            ← 型別與名字壓成一個字串
area(h=2, w=5)             「串列不能做 *」             ← 具名引數綁到包裹本身
[0] * 3                    靜靜回 0.0                  ← NaN 走完整個 switch 沒人攔
map(lambda…)               [8, 8, 8, 8]               ← 並行呼叫讓每格看到別格的參數
{n: n*n for n in …}        {'1': 1}                   ← 鍵一律轉成字串，型別丟了
"Hello".count("l")         5                          ← 兩邊都轉成「轉不出來」再比
1 < x < 10                 產出 1 < x                  ← 而它碰巧算出同一個答案
```
