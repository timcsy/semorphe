# 277 — 「感覺太擠」量得出來的那一面

**2026-09-21** · 第 215 刀 · 分支 `215-too-cramped`

一個學生逐字（[episodes](../episodes/2026-09-21-一班學生上完前幾課.md)）：

> 我覺得網站有一些bug有一些按下去不會到他寫的部分。
> 網站疑時很完善了只是**有一些感覺太擠**其他還可。

前半在 [275](275-那句含糊的回饋指到的是一條真的斷掉的連結.md) 結案了。
後半我**寫過兩次「沒有量測方法，不假裝結案」**——而那是放棄得太早。

## 🔴 「擠不擠」很主觀，而它有一面不是

```
擠不擠          主觀，沒有判準
這顆按鈕有沒有 24px   WCAG 2.2 AA · 2.5.8「目標大小（最小）」，別人寫下來的下限
```

> **一個說不出「哪裡擠」的抱怨，先去量那個領域【有標準】的那一面
> ——主觀的部分量不了，而它旁邊往往就有一條寫死的線。**

## 量到的（1366×768，學校筆電最常見的尺寸）

⚠️ **在開發機的大螢幕上量，量到的是我的螢幕**——這班學生是在教室裡上的課。

```
可見的互動元素     34
🔴 低於 24×24      20   （59%）
   最小的：26x18 📋 · 26x19 ✕ · 27x19 ⛶ · 38x18 清除 · 20x30 ▾
文字被裁           0
橫條吃掉的高度     92px（15%）——這一項沒問題
```

🟢 用 `min-height`／`min-width`（不是 `height`）撐開不夠的那些：**20 → 0**，
而文字被裁仍然是 0、版面沒有位移。

## 🔴 而量的過程撞到一個比按鈕更嚴重的——**它沒有修成**

畫面上那條指路的橫條，句子**從中間開始**：

```
畫面上讀到  是你正在用的東西（現在有 3 種積木是淡的）
完整的句子  〈算一算〉教的就是你正在用的東西（現在有 3 種積木是淡的）
```

`.lesson-nudge-bar` 是 `position:absolute; left:0; z-index:6`，
而 Blockly 的工具箱是 **z-index 70、寬 110px**——**前七個中文字被蓋住**。

🔴 **主詞整個不見了。** 而這條列的工作，正是回答兩個學生說的
「不清楚自己下一步要做甚麼」「看不懂他說的步驟應該從哪裡弄出來」。

> **一條被蓋住開頭的句子，讀起來不是「少了幾個字」，是「這句話沒有意義」
> ——而它與一條壞掉的功能長得一樣。**

⚠️ **不用「把 z-index 調高」解**：那只是換成這條列去蓋住工具箱最上面那一格，
把一個遮蔽換成另一個遮蔽。

### 🔴 而「量工具箱多寬、從它右邊開始」這個顯而易見的修法**不成立**

`e2e/flow-selection-link`「切分頁不得把反白清掉」當場紅：
點一塊積木之後，流程那邊**沒有亮**。

對照實驗（三步，每一步都重建）：

```
不改             🟢 綠
只量不設 left    🟢 綠      ← 量測本身無害
量完再設 left    🔴 紅      ← 寫 inline style 就是原因
```

這條列是 `blocklyContainer` 的**第一個子節點**，動它的 inline style 會讓
Blockly 重新量版面，而那一路會**把選取取消掉**——那支測試的檔頭記著同一條
呼叫鏈：「點分頁按鈕就在工作區外面，而 Blockly 對『點外面』的反應是取消選取」。

> **一個「只是改了一下樣式」的動作，如果它動的是別人正在量的那棵樹，
> 那它就不是一個樣式改動。**

🪦 第二版試了「在建構時量好 ＋ `ResizeObserver` 跟著走」——**還是紅**
（觀察器在後面某個時刻仍會寫到樣式）。試到第三次停手，**改動已回退**。

⏳ 留成債，而**下一個人不必重走這三步**：修它要嘛讓那條列不住在
Blockly 的容器裡，要嘛從 Blockly 那一側治「重新量版面就取消選取」。

## ⚠️ 一條共用規則「對大多數有效」不等於對每一個有效

那顆 `▾` 撐不開，因為 `min-width: 20px` 住在 `.run-group .run-mode-arrow`
（特異度 0,2,0），而共用規則只靠 `.exec-btn`（0,1,0）——**輸了**。

> **特異度是逐個元素算的——「我加了一條共用規則」不是一個讀數，
> 量出來的那個數字才是。**

## 落點

- `src/ui/style.css` 末尾「點得到的最小尺寸」那一段
- 🪦 `src/ui/lesson-nudge-bar.ts` —— **試過三版，全部回退**（見上）
- `e2e/touch-target-size.spec.ts`——**e2e 護欄，不佔編號**
  （編號那份清單只數 `tests/integration/`，而這一條要真的版面）。
  棘輪，而基線是 0 ⟹ 今天等同硬性零。

## 🔴 而使用者在這一刀做到一半時喊停

逐字：「**你就別管太擠了，我覺得還好**。」

所以「擠」的**主觀那一面**（版面密度、資訊量）**不列成待辦**——
它不是「還沒做」，是**有人看過畫面之後判斷不需要做**。

> **一個「我還沒量出來」的東西與一個「量了但決定不做」的東西，
> 寫在同一張待辦清單上會長得一樣——而後者該被關掉，不是被繼續盯著。**
>（同一天稍早的教訓：「一個待辦清單如果從來沒有變短，它就已經變成例外清單了。」）

⚠️ 而已經做完並驗綠的兩件事**留著**（使用者拍板）：
按鈕尺寸 20 → 0 ＋ 第 132 條護欄，以及那條被蓋住的句子。
