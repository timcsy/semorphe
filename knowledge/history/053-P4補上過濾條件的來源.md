# 053　P4 補上「過濾條件的來源」，並收回一個沒有證據的正交軸

> 日期：2026-08-13
> 觸發：使用者（一位真的在教的老師）說出他**實際怎麼用**漸進揭露，
> 以及隔天對 `Ln` 的質疑。兩句話各推翻 P4 的一半。

## 轉變一：`f` 的參數誰來決定——原文沒說，而那讓機制失效

**原文**（2026-03 起）：

> 「可見集合 = f(Topic, 概念層級, View Params)，三個維度正交不可混用。」

它說了 `f` 長什麼樣，**沒有說那三個參數誰來決定**。

而在真實教室裡決定它的是老師，面對 **9 個可選節點 = 512 種組合**而沒有依據：

> 「還要手動把那些東西打勾，然後我實際在運作的時候
> **我會乾脆叫學生把全部都打勾，那有沒有這個漸進揭露是沒用的**」

> 「在沒有教材輔助的前提下，**要想哪一個需要被打勾其實選擇太多，會選擇障礙**」

**兩個機制疊在一起**：收益不可見（成本由老師付、收益學生得）＋ 選項太多。
而老師的理性反應是找一條不用想的規則（他的：基礎全開 → 學生自己勾一個 → 全開）。

> **漸進揭露為學生減少選項，而它把那些選項轉嫁給了老師。**

⚠️ **這是解法沒有遞迴地套用自己的原則**：P4 要解「學生面對太多概念會被淹沒」，
而關卡樹製造了同一個問題的另一個實例。

**→ P4 補一條**：過濾機制必須連同「條件從哪來」一起設計，
否則它把認知負荷搬家而不是減少。而那個來源今天缺的是**教材**。

## 轉變二：「概念層級 ↔ Topic」的正交性沒有證據，已收回

**原文**斷言三個維度正交不可混用。而 `cpp-beginner.json` 的實測：

```
L1a 函式與迴圈    L1b 控制流進階    L1c 型別系統
L2a 陣列與字串    L2b 指標與記憶體  L2c 結構與類別
```

「函式與迴圈」與「型別系統」都是 `L1`，**而它們沒有任何共同的認知性質**
（`L1c` 5 顆概念、`L1a` 21 顆）。唯一的共同點是「都掛在 L0 底下」。

> **兩個座標軸如果其中一個是另一個的函數，那不是二維，是一維寫成兩個欄位。**

⚠️ **而 `a/b/c` 後綴本身就是症狀**：它是為了在同一深度區分不同分支而加的
——如果 n 真的是「認知層級」，同一層的東西就不需要用字母分開。

**→ 收回一個軸，不是整句移除。** ⚠️ 而這是**第二版**——第一版把整句正交性都刪了，
逐項查證後發現只有一個軸有問題：

| | 正交嗎 | 證據 |
|---|---|---|
| Topic ↔ View Params | ✅ **仍成立** | `print` 在兩個 Topic 的 L0 都可見，而 `cout`／`printf` 由 Code Style 決定 |
| **概念層級 ↔ Topic** | ❌ **收回** | 概念層級就是 `levelTree` 的深度 |

> **一句話有三個宣稱時，反例只推翻它指到的那一個。**

⚠️ 而 `concepts/漸進揭露.md` 裡還有**另一個**正交宣稱
（概念層級 ↔ 表面形態，`:106`）——**它不受影響**，因為那一組有
F0/F1/F2 與 L0/L1/L2 兩套獨立刻度支撐。
**同一個詞（正交）在同一份文件裡指兩件不同的事，而只有一件被推翻。**

**那一軸要重新宣告的話，得先答「n 的本質是什麼」**（三候選：
前置深度／認知負荷／就是課程順序）。

## 為什麼這是 history 而不只是 draft

刪掉交付與量測的行之後，剩下的是一個明確的 **old → new**：

```
old  可見集合 = f(…)，三個維度正交          ——而沒說參數誰決定
new  f 的參數來源是設計的一部分；正交性收回待證
```

而**未來的讀者會困惑**（「不是說三個維度正交嗎」），所以它要被記下來。
