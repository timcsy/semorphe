# 062　把使用者的錯歸進了我們的殘差——而那是第一週最常見的那個錯

> 日期：2026-08-14
> 觸發：使用者說「**我怎麼覺得現在連分號的錯誤訊息都沒有處理的很好？
> 甚至還不會報出來。這樣更何況是其他錯誤訊息**」。
> 本檔記的是**驗收③ 的一個決定被推翻**，不是修了什麼（修還沒做）。

## 轉變

```
old  降級原因（degradationCause）都是【殘差】——我們還沒長到那裡
new  🔴 其中一個不是：`syntax_error` 是【使用者寫壞了】，不是我們沒長到
```

## 實測：少一個分號今天發生什麼

```
① tree-sitter    → ERROR 節點                                  ✅
② lifter         → cpp:var_declare 標 syntax_error             ✅ tests/unit/core/lift-syntax-error.test.ts 釘住
③ 積木側          → 積木變紅 #FF6B6B ＋ tooltip                 ✅
④ 程式碼側        → 🔴 MarkerSeverity.【Info】／owner semorphe-residual
                     訊息「這一段的語法不完整，積木上會少一塊」
```

**不是沒報，是報成了最低等級的灰色提示，而且說的不是「少一個分號」。**

## 🔴 而它根本不走 `onDiagnostics`

驗收④ 剛做完的整套——`rule` ＋ `params`、兩個面板不同措辭、
第四十二條文案完備性護欄——**一點都沒套到它身上**。

> **我們花了一整輪把「缺少條件」講得很好，
> 而「少一個分號」走的是完全不同的一條路，那條路上什麼都沒有。**

⚠️ 而「缺少條件」是**積木側才存在**的狀態，「少分號」是**每個學生第一週都會撞**的。
**力氣放在稀有的那一個上。**

## 為什麼歸錯：一個對的判準被套寬了一格

`audit-behavior-error` 檔頭那條分法本身是對的：

> 「**殘差高＝模型還沒長到那裡（系統仍然正確）**；**誤差高＝模型是錯的**。」

⚠️ 而它分的是「**我們的**問題有兩種」。`degradationCause` 這個列舉裡混進了第三種：

| cause | 是誰的問題 | 今天走哪 |
|---|---|---|
| `unsupported` | **我們**：還沒長到 | 殘差 ✅ |
| `nonstandard_but_valid` | **我們**：認得但不標準 | 殘差 ✅ |
| `syntax_error` | 🔴 **使用者**：你打錯了 | 殘差 ❌ **錯格** |

## 🔴 而差別當時已經被看見了，只是沒有換頻道

`src/ui/panels/monaco-panel.ts:127` 的註解逐字（**我自己寫的**）：

> 「殘差的訊息——**主詞是「我」，不是「你」**。⚠️ 那不是修辭：
> `syntax_error` 是**使用者寫壞了**，而 `unsupported` 是我們沒長到。」

**看到了兩個主詞不同，換了措辭，沒換通道。**

> **發現兩件東西性質不同的時候，如果只改了它們的說法而沒改它們走的路，
> 那個發現就沒有被兌現——而註解會讓它看起來已經處理過了。**

⚠️ 而 vision 驗收③ 的措辭是這件事的來源：
「`degradationCause` **上得了畫面，而且不長得像錯誤**」。
**「不長得像錯誤」對 `unsupported` 是對的，對 `syntax_error` 是錯的**
——同一句話套了兩種東西。

## 所以是三分，不是二分

```
殘差     我還沒長到那裡     我們的問題，系統仍正確    Info    ← 別嚇學生
誤差     我算錯了           我們的問題，系統是錯的    護欄在看，不上畫面
使用者   你寫壞了           🔴 使用者的問題            Error   ← 該走診斷
```

而第三格在[語義診斷系統](../draft/2026-08-05-語義診斷系統.md)的三分法裡位置很清楚：
它是 **B 類（語言規則，預期屬於編譯器）**。
**所以我們不是「還沒實作 B」，是把 B 吞進了殘差裡。**

## 而這解釋了使用者那句「更何況是其他錯誤訊息」

懷疑成立，**而不是因為工程量大**：

> **我們一直在加規則，而沒有先問「最常見的那個錯誤走哪條路」。**

[history/057](057-缺陷清單只包含被記下來的缺陷.md) 逐字：
「一份缺陷清單只包含**被記下來的缺陷**。」
診斷版是：**一份規則清單只涵蓋被寫成規則的錯誤**——
而分號從來不是一條規則，它是「降級」，
所以它**不在任何清單裡，也不在任何護欄的分母裡**。

## 處置（✅ 2026-08-14 同日做完，spec `119`）

```
severity   Info → Error
owner      semorphe-residual → semorphe
訊息       走 rule + params；程式碼側可以說 expected ';' before 'cout'
           （tree-sitter 知道缺什麼）
```

⚠️ **可否證的驗收**：造一段少分號的程式，程式碼面板要出現 **Error 級**的波浪
——今天是 Info，所以那支測試**現在就會紅**。
**✅ 做了，而它第一次跑紅在【入口條件】上**（一個標記都沒有）——
那條入口條件擋下的不是失敗，是一個**指錯方向的失敗訊息**。
🔴 見 [history/063](063-通道接好了而辨識那一層只認得某些形狀.md)：
通道接好之後才現形，**辨識那一層只認得某些形狀的「少分號」**。

⚠️ 🔴 **而「殘差率的分母會變」這句話是錯的**（2026-08-14 稍後查證）：

```
isResidual(id) = id === 'raw_code' || id === 'unresolved'      ← 護欄只數這兩種 conceptId
syntax_error   標在【被 lift 出來的節點】上（cpp:var_declare）  ← 不是 raw_code
residual2 基線 {charCount: 0, nodeCount: 0, ratePercent: 0}     ← 全零
```

**所以 `syntax_error` 不在 `projection-residual` 的分母裡，
也不在診斷的分母裡（它不走 `runDiagnostics`）——它不在任何護欄的分母裡。**

> **它有畫面，而沒有任何一個護欄在數它。**

⚠️ 這讓 4.5 的理由**更強而不是更弱**：不是「歸錯了桶」，是**沒有桶**。
而搬動它**不會動到任何基線**——風險比原本以為的低。

⚠️ 而這正是 [history/057](057-缺陷清單只包含被記下來的缺陷.md) 那條的又一個實例：
「一份缺陷清單只包含**被記下來的缺陷**」——第一週最常見的錯誤
**從來沒有被任何一份清單記下來過**。
