# 022：護欄的自我否證錨點，從「挑不會修好的東西」改為「根本別錨在真實狀態上」

> 日期：2026-08-06

## 轉移

- **舊**（[concepts/執行機構.md](../concepts/執行機構.md)「錨點要挑『這個功能不會修好的東西』」）：自我否證聲明會過期，所以錨點要挑**這個功能明確不打算修的**東西。
- **新**：**錨在合成輸入上，不錨在真實世界的狀態上。** 「這個功能不打算修」擋不住**下一個**功能。

## 為什麼變

因為同一天又翻車兩次，而舊判準對這兩次都無效。

| | 錨在什麼 | 怎麼爛的 |
|---|---|---|
| 辨識歧義護欄 | 「`declaration` 那 8 條同時盯著宣告語法，沒被判為確定會撞就代表護欄壞了」 | **把那群修好了**（確定會撞 10 → 0），那句話變成「叫未來的讀者不要相信一個正確的結果」 |
| 雙重真相護欄 | 斷言「兩處都有定義 > 10」，理由是「0 代表清單沒取到」 | **消滅雙重真相正是這條護欄存在的目的**——真的清乾淨那天，它會變成一支「斷言病還在」的測試，而修好的人得先刪掉它才能讓套件變綠 |

兩次都符合舊判準（當時確實「不打算修」），兩次都爛了。

## 一句話

> **護欄修好了它要量的東西，就是它的錨點爛掉的時候。**

一條護欄的目的就是讓它量的數字下降。錨在那個數字上的自我否證聲明，**因此註定過期**——這不是意外，是設計上的必然。

## 新判準

錨在**餵給判定函式的合成輸入**上：

```
兩條約束一字不差的假規則  → 必須判「會撞」
兩條判別式互斥的假規則    → 不得誤判為會撞
```

合成輸入不隨真實世界的修復而失效。真實世界的狀態遲早會被你自己修掉。

## 兩次都不是 code review 抓到的

**是數字掉下來時測試自己變紅。** 這一點值得記：改對了東西，護欄自己的健康檢查跟著壞掉，而那個壞是**可見的**——它變紅、擋住 commit、指名是哪一支。

換成印一行報表的話，兩次都會靜靜過去。
