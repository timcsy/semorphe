# 401：`max(字典, key=…)` 照放入的順序找（442）

**之前**：課文 `12-文字處理/ex1` 的 `max(counts, key=lambda w: counts[w])` 保留——`math_max` 只收數字參數，說「max 的參數型別不一致」。

**之後**：字典有了旁邊那一串鍵（[400](400-照放入順序走訪的字典旁邊帶一串鍵.md)），`max`／`min(字典, key=lambda k: …)` 就是「照那串鍵走一遍、留下 key 最大（最小）的那個」——在那一句前面先算好（`hoist`），**只在嚴格大於（小於）時換人**，所以平手取先放進去的（Python 的規則）；空字典兩邊都丟例外。課文 36 支換過去 33 → **34**。

**為什麼這樣做**：
- 那個字典本來就要照放入順序走（Python 的 `max` 走的是 `iter(d)`），所以它在引擎眼裡跟 `for k in d` 是同一種用法——收進同一張「允許的位置」表，不另開一條路。
- key 只收算出 int／float 的 lambda；條件、短路裡不收（先算好會改變求值次數），照實保留。
