`draft/2026-08-18-競品的積木與分類.md` 的提案②（「學生拉了動作積木而沒拉宣告時，
自動長出宣告積木」）從 2026-08-18 起開著，出口條件寫著
「**等使用者實測回報**——今天沒有人抱怨過」。

## 轉移

```
舊   判準 ＝「學生常不常忘記這一步」        出口 ＝ 等抱怨
🔴 新 判準 ＝「這一步是【樣板】還是【概念】」  而②被否決
```

## 為什麼變——兩層，而第二層更強

### ① 出口條件本身是壞的

問使用者「學生有沒有踩過」，回答逐字：「**目前還沒有，因為還沒上到 Arduino**」。

```
沒有人抱怨  ← 零樣本
沒有缺陷    ← 零缺陷
兩個讀數長得一模一樣
```

⚠️ 而**同一頁上的①才剛因為這個理由被否決**（腳位下拉：「那 140 段是 AI 生成的，
一個量測的效力上限是它的樣本來自誰」）。

> **一份文件可以在同一頁上判對一次、又犯同一個錯一次
> ——因為判準寫在①底下，而②沒有人拿它對過。**

### ② 量了之後，理由反了

一次性探針（量完即刪）：

```
🟢 有宣告   沒有丟例外
🔴 沒宣告   丟例外「變數 's' 尚未宣告」—— 直譯器本來就會擋
```

⚠️ 而我一度從 `servo_write/execute.ts` 的檔頭推論成「模擬會**靜默**照跑」。
**那是讀錯了**：那句「沒有 `attach` 就轉，本輪照做」講的是 `attach`
（與 `pinMode` 同類的**啟用動作**），不是宣告。宣告是**變數宣告**，
而查名字那一關先擋下來。

> **兩件事都叫「忘了那一步」，而它們落在直譯器的不同關卡上
> ——一個被放行是刻意的，另一個本來就會擋。**

### 🔴 於是冒出一個比「不需要」更強的理由：做了會有害

`lessons/arduino/08-伺服馬達/lesson.md` 的**第一節整節在教這件事**：

> 「`Servo s;` 這一行和 `int n;` 是**同一個形狀**：型態 ＋ 名字。」

⟹ 自動補上那顆積木，**補掉的正是這一課在教的東西**。

## 新判準，而它分得開既有的那一筆

```
樣板   課文不把它當概念教   🟢 可以補   ← cpp:pin_attach → cpp_pin_mode（今天唯一一筆 companion）
概念   課文正在教它         🔴 不可以補  ← cpp:servo_declare
```

> **伴生積木的判準不是「學生常忘記嗎」，是「這一步是樣板還是概念」。**
