# 011：從「四路完備性」到「五層完備性（含執行層）」

> 日期：2026-03-12

## 轉移

- **舊**：P2 定義概念完備性為四條路徑：lift → render → extract → generate。四路通過 = 概念完整。
  同時 interpreter 對不認識的概念採取 `if (concept.includes(':')) return`——**靜默跳過所有語言特定概念**。
- **新**：完備性擴充為五層，加入 `⑤ execute path (concept → Behavior)`。interpreter 改為查詢 executor registry；宣告性概念註冊 **noop executor**；未知概念透過 `unknownConceptHandler` 通知使用者選擇跳過或中止。

## 為什麼變

`<cmath>` 的概念（`cpp:math_pow`、`cpp:math_unary`、`cpp:math_binary`）完成了四路實作，**round-trip 測試全數通過**。但使用者按「執行」時，`pow()` 算出 0，二次方程式解出錯誤答案。

原因是「執行」按鈕走的不是 C++ 編譯器，而是 `SemanticInterpreter` 直接走訪語義樹。這些概念沒有註冊 executor，於是 `executeNode()` 命中了那行靜默跳過，回傳 `undefined`，經過 `evaluate()` → `defaultValue('void')` → `toNumber()` 一路轉成 `0`。

```
語義樹正確 → round-trip 測試全過 → 使用者執行 → 結果錯誤
                                                  ↑ 沒有任何錯誤訊息
```

兩個獨立的認知在此更新：

1. **四路完備性是「編輯管線」的完備性，不是「執行管線」的完備性。** 概念可以在編輯管線中完全正確，同時在執行管線中完全失效。原本的四路定義隱含假設了「概念正確 = 系統正確」，這個假設在有直譯器之後就不成立了。
2. **宣告性概念也必須註冊 executor（noop）。** 否則系統無法區分「已知不執行」（`#include`、`using namespace`、註解）和「未知」——兩者在「沒有 executor」這件事上長得一模一樣。

`if (concept.includes(':')) return` 這行本身是這次事故最值得記住的東西：它用一個看似合理的規則（「語言特定概念直譯器管不著」）掩蓋了一整類的資料遺失，而且是在**所有測試都綠**的情況下。
