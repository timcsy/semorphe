# 235 · 一顆積木的三個缺陷，疊成一句抱怨

**日期**：2026-09-15
**觸發**：使用者轉述第 5 課（「程式從哪開始」）

> 「目前第五課，那邊 `#include` 好像**不會在拉 `cout` 的時候出來**，
>   如果自己把 include 積木拉出來，又會是**不能調整的 `stdio.h`**」

## 一句話裡有三個缺陷，而它們不是同一個

量出來（`e2e/auto-include-blocks.spec.ts` 的前身探針）：

```
① 拉 cout 沒出現   程式碼那側有 #include <iostream>，積木那側【沒有那顆積木】
                   ——而在程式碼裡打同一行 cout，兩邊都對
② 是 stdio.h       工具箱那顆的下拉第一個選項就是 stdio.h
                   （元件宣告的 default 是 iostream——兩份真相，生效的是下拉那份）
③ 不能調整         接進頂層就被認成骨架、鎖成唯讀
                   ——判定問的是【身分】（你是不是 include），不是【誰放的】
```

> **一句抱怨如果聽起來像一個缺陷，先問「它有幾個」
> ——使用者描述的是一條路徑，而路徑上可以壞好幾次。**

## ① 的根：一個「不重畫我自己的編輯」的規矩

積木面板刻意跳過自己發出的更新（重畫會打斷拖曳、清掉復原堆疊）。
而自動補的那顆 `#include` **不是它畫的**——它由顯示樹增強器補上去，
只有重畫才出得來。

> **一個「不重畫我自己的編輯」的規矩，會把【我沒有畫過的東西】
> 一起擋在外面——而那正是只有重畫才出得來的那些。**

修法是**那條規矩的例外，不是取消它**：只有在推導出來的那一組
真的變了的時候才重畫（`SemanticUpdateEvent.scaffoldChanged`）。
實測一支程式裡大約發生一次。

### 而修好它之後，它把自己弄成了真相

畫上去的那顆 ghost `#include`，下一次抽取**把它讀成學生寫的**
——正是 `identityBeforeDowngrade` 記過的那條（「降級的視圖被動一下就變成真實」）。
配一把摘的刀（`dropDerived`），而摘的判準試過兩版都不成立：

```
🪦 比 nodeId          `setNodeIdLookup` 零個呼叫者 → 抽回來的 id 每次都是新的
🪦 比 id + 全部屬性    往返會正規化（`local` 那一格）→ 逐字不相同
🟢 比身分的多重集相減  推導的補在 body 最前面，扣掉前幾顆就好
```

## ②③ 沒有各自修——使用者一句話把它們一起溶掉了

我原本打算分別修：②改下拉的順序、③把骨架判定從「問身分」改成「問誰放的」。
③做完了，四條 e2e 全綠，而重產對照圖時**18 張的畫面變了**：課文裡的
`#include` 是從**課文的程式碼** lift 回來的、不帶「誰放的」那一格，
於是變成實心的——而第 5 課逐字寫著「淡淡的、拖不動的那幾塊」。

> **一個「誰放的」的判準，在【程式碼是別人給的】那個情境裡答不出來
> ——而課文的對照圖正是那個情境。**

我把它收回去，然後把這個取捨交回去問。使用者的回答不是二選一：

> 「我覺得正確的做法應該是，**ghost 的積木不用出現在工具箱**」

> **與其讓一個拿出來也動不了的東西「動得了」，不如不要給。**

拿不到，②③就都不存在了。而它補的是一條**已經存在而漏了一種情況**的規則：
`toolboxComponents()` 本來就收窄成「這一課宣告的」，理由逐字寫著
「第 1 課不教 `#include`，學生不該拖得到它」——**而第 5 課教它**。

> **「一課宣告了它」與「學生該拿得到它」是兩件事
> ——而一張表同時扛這兩個工作的時候，【教到它的那一課】就是破口。**

⚠️ 判準**綁深度不綁身分**：`editable`（深度 2+）下鷹架動得了，那時它該在。
🟢 而第 5 課的課文有一句「積木盤上它寫著『引入函式庫 …』」——那句話跟著改了
（名字留著，護欄要它；改的是「在積木盤上」那個宣稱）。

### 🪦 而我原本要問的那個問題，問錯了

我準備問的是「課文對照圖裡的 `#include` 要不要維持淡的」——一個二選一。
而正確的第三條路**不在那兩個選項裡**，它在更前面一步。

> **一個「A 還是 B」的問題，先檢查 A 與 B 是不是共用了一個沒有人質疑過的前提
> ——這裡的前提是「那顆積木本來就該拿得到」。**

## 沿路撿到的

- 🔴 `BlocklyPanel.setNodeIdLookup` **零個呼叫者**——「還原原本的 nodeId」
  那一段從來沒跑過。這一刀是它的第一個呼叫者（只餵推導的那幾顆）。
- 🔴 `SkeletonLine` 的剖析器**逐欄挑**，新加的那一格被靜靜丟掉
  ——探針當場抓到（`using namespace std;` 從淡的變成實心的）。
- 🟢 全庫量過：55 個有宣告 `default` 的下拉裡，只有 4 個與畫面上生效的不一致，
  其中兩個的 `default` 是哨兵（`unknown`）。**所以②不是一族，不要寫成通則。**
  （下拉的順序仍然改了：深度 2+ 時那顆積木拿得到，而這是 C++ 的產品。）
- 🔴 **量測打在舊的 bundle 上**：背景還跑著一支 `npm run test:e2e`，
  Playwright **重用了它的 preview 伺服器**，於是接下來三次工具箱量測看到的
  全是改動前的畫面。⚠️ 症狀是「測試跑得比平常快」（4.5 秒 vs 15 秒）。
  > **一個「重用既有伺服器」的設定，會讓你量到【上一次建置】的產品
  > ——而它不報錯，它只是比較快。**
