# 050　識別字不再是中文——一條沒有機制的慣例漂了兩個月

> 日期：2026-08-12
> 觸發：使用者在一次 UI 解耦的回報之後說
> 「**我發現在程式碼裡面變數或函數名稱好像出現了很多中文，應該是用英文才對呀**」

## 轉變

| | 之前 | 之後 |
|---|---|---|
| 識別字語言 | 中英混用（**沒有人決定過**） | **英文**，硬性零 |
| 檢查 | 無 | [第四十條護欄](../../tests/integration/audit-identifier-language.test.ts) |
| 中文的位置 | 到處 | 訊息／註解／**型別的值**（領域詞彙） |

**它為什麼算一次轉變而不是一次清理**：在此之前這個專案**沒有立場**——
不是「決定用中文」也不是「決定用英文」，而是每一次都往阻力最小的方向寫。
使用者這一句是**第一次有人表態**，而表態的內容不是偏好，是一條規範：

> 「中文本來就不應該成為識別字。」

## 量出來的代價

```
618 個不同的中文識別字　3918 次出現　223 個檔案
```

涵蓋兩個月、幾十次提交，最早可追到 spec 053。

> **沒有任何一次是「決定要用中文」。第一次可能只是順手，
> 而後來的每一次都有前例可循。**

⚠️ 而**我自己在被指出的當天還加了 33 個**——那 33 個是在同一輪解耦工作裡寫的，
寫的時候我讀過 `CLAUDE.md` 的「Follow standard conventions」。
**知道一條規範存在，與有東西擋著你違反它，是兩件事。**

## 做法：codemod，不是正則

`vision.md:336` 早就寫過（那是為 `.concept` 改名寫的）：

> 「改名要用**型別層級的 codemod**（ts-morph 之類），**不是正規表示式**」

而我在同一輪的前半用正則改自己那 33 個，當場踩到：

```
`視圖 id「${view.viewId}」被登錄兩次`   →   `views id「…」被登錄兩次`
```

> **一個識別字改名腳本分不出「這個詞在講那個變數」與「這個詞在講那件事」。**

改用 TS LanguageService 的 `findRenameLocations`，分 6 批、每批 `tsc` 驗。

## 五個坑，全部是「型別檢查看不到」

| | 症狀 | 誰抓到 |
|---|---|---|
| 一個名字對應多個符號 | shorthand 被拆一半 | `tsc` |
| **JSON 的鍵 = interface 的欄位名** | 讀到 `undefined` | 測試 |
| **改名造成遮蔽** | **無限遞迴** | 測試 |
| 型別的值 vs 物件的鍵 | 查表回 `undefined` | 測試 |
| 兩份對照表給了不同英文 | 讀到 `undefined` | 測試 |

**五個裡有四個是測試抓到的，`tsc` 只抓到一個。** 而遮蔽那一個
（內層 `跑` → `run` 遮蔽外層同名函式）的症狀離根因非常遠。

三條反流進 `experience.md`；詳細機制見那裡。

## 順帶確立的分界

**這些不算違規，而且不該算**：

```ts
throw new Error('視圖 id 被登錄兩次')     // 訊息是給人看的
type shape = '型別不符' | '缺子節點'       // 型別的**值**是領域詞彙
it('★ 反向：沒登錄的視圖收不到', …)        // 測試標題
```

> **同一個詞在型別的值與物件的鍵上，只有寫法決定它是不是識別字。**

護欄的注入把這條分界釘住了（兩個方向都釘），
而反向那一支不可省——沒有它，一個「掃到中文就報」的實作也會通過正向那支，
**而那正是用正則時犯過的錯**。
