# 105 — 核心層的積木型別歸零，而佔位值差點變成新的靜默降級

**日期**：2026-08-20 · **spec**：`154-core-blocktype-zero` · **狀態**：完成

## 轉變

```
之前   src/core/ 硬編 11 個 cpp 積木型別（護欄第二維 44 筆）
之後   src/core/ 歸零；第二維 44 → 33（只剩 block-registrar 的 33 筆）
       而第一維維持 0／0、「直接呼叫視圖」維持 67——沒有把耦合換地方
```

## 🔴 而那個檔的註解，四十幾支規格之前就寫出了這個決定

`core/block-input-names.ts`（057 寫的）逐字：

> ⚠️ **本模組只涵蓋 universal 積木**……語言專屬積木的插槽名因此仍然寫死
> ——要涵蓋它們，這個模組**得引用語言套件，那與「核心不認識語言」相衝**。
> **那是另一個決定，不在 057 的範圍。不硬湊。**

🟢 **spec 154 就是那個決定**——而查清楚之後，答案不是「涵蓋更多」，是**整個搬走**：

```
那 9 個常數的唯一生產消費者   src/ui/block-registrar.ts
另外兩個匯出                 extractInputNames / getInputs ——只有【測試】在用
```

> **一個只服務單一語言的模組，住在 `core/` 只是位置，不是身分。**

⚠️ 而 `extractInputNames`／`getInputs` **留在核心**——它們是通用工具，
一個語言專屬的字都沒有；搬走它們才會製造匯入循環。

## 🔴 而我在修的過程中造出一個新的靜默降級，測試當場抓到

把九個常數改成注入時，我給了它們**看起來合理的預設值**
（`IF_INPUTS = { value: ['CONDITION'], statement: ['THEN','ELSE'] }`）。

`serialize-roundtrip` 五支當場紅——⚠️ 而它們紅的原因是**匯入路徑變了**，
不是預設值。**真正的問題是那個預設值本身**：

> **一個看起來合理的預設值，會讓「組裝點漏了」與「值本來就是這樣」
> 長得一模一樣。**

🟢 處置：初始值降級成**佔位**，並在 `registerAll` 加一句
「沒注入就當場拋錯」。注入實測：把組裝點那段拿掉 → **e2e 紅**。

## ⚠️ 而驗那一條的時候，我又踩了昨天剛寫進 skill 的坑

第一次驗「沒注入會不會出聲」，探針回報 **🔴 靜默通過**。
**而那是假的**——注入讓 `import` 變成未使用，**建置壞了，測試根本沒跑**。

昨天才把「注入的第四種結局」寫進 `build-guardrail`，
**而我在一個臨時探針裡沒有帶上那個檢查**。

> **一條寫進 skill 的規則，只在你【用那支 skill】的時候保護你
> ——而臨時探針不會自動繼承它。**

## 兩個修法

抽象，等於用猜的決定介面。
