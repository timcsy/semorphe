# 360 · 計數 for 的迴圈變數不是 int 時不再被改成 int

> 日期：2026-11-09
> 轉變：計數迴圈那顆積木（`cpp:loop_count`）沒有「型別」這一格、產碼一律寫 `int`——而判別只看形狀，`for (long long i = …)`、`for (size_t i = …)` 也被它接走。走一趟就變成 `for (int i = …)`：值超過 int 時結果不同，而來回比對兩邊都是同一棵錯的樹，看不出來。
> 改成：計數迴圈只收 `int`；別的型別歸一般的 for（保留宣告的型別）。兩處判別（`strategies.ts` 的策略、`statements.ts` 的手寫 lifter）都加。合併 fd12b89f。
> 決定：AI 照推薦（bug 必修）。給計數迴圈加一格型別要動積木、存檔、對照圖——與修這個錯不成比例。
> 怎麼發現的：spec 225（Python → C++）換出來的 C++ 用了 `for (long long i__ = …)`，「走一趟 C++ 的樹回來一字不差」的斷言撞到。

## 修好之後露出來的

三支 C++ 盲測（類別外定義、運算子類別外定義）寫 `for (size_t i = 0; …)`：**原本判 accept，是因為我們把 `size_t` 改成了 `int` 才送給 Cella**——Cella 判的是一支學生沒寫的程式。照實送之後，只引入 `<iostream>` 時「標頭有沒有宣告 `size_t` 取決於函式庫」，Cella 誠實地判 unknown。釘子照實改了（附理由）。

> 這是〈翻不出是一層遮罩〉的反方向：不是「翻不出」蓋住後面的錯，而是**我們的改寫**讓一個本來該說「不確定」的判決說了「對」。
