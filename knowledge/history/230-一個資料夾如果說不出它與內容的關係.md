# 230 · 一個資料夾如果說不出它與內容的關係

> 2026-09-13 · 使用者：「我想要把這專案資料夾結構重新整理的好看一些
> （至少先把一些冗余難看的歷史包袱刪掉），**準則是要說得出這資料夾或檔案
> 與實際內容結構的關係，否則可能就是放錯地方**。」

那條準則本身就是這一則的全部。底下是拿它掃過一遍之後掉出來的東西。

## 刪掉的（說不出關係）

| | 為什麼 |
|---|---|
| `output.txt` | 0 位元組。它是 `cpp:ofstream_declare` 的**預設檔名**——跑到檔案輸出的測試在根目錄留下的。已加進 `.gitignore`，不然它會再回來 |
| `src/style.css` | 8.8 KB、零引用。`index.html` 載的是 `src/ui/style.css` |
| `tests/scratch/` | 空目錄，零追蹤檔 |
| `specs/114`、`specs/115` | 沒有 `spec.md`，只剩一份零人讀的 `baseline.json` |
| `tests/scripts/` | 7 個檔（`fuzz_phase3.ts`、`roundtrip-phase1.ts`…），零引用。vitest 不掃它、`package.json` 不跑它 |
| `tools/codemod/rename-concept.mjs` | 見下面「紀念品」那一節 |

## 搬走的（放錯地方）

### 🔴 `src/scripts/` ——而 `tsconfig.json` 早就自己招了

```json
"exclude": ["src/scripts", "src/**/*.test.ts"]
```

> **一個必須被排除在建置之外的目錄，它的位置就是錯的。**
> 那行 `exclude` 不是設定，是自白。

`build-vscode.ts` → `tools/`（它是建置工具，而 `tools/` 就是放那種東西的）。

### `verify-component-paths.ts` → `tests/helpers/`

它掛在 `package.json` 的 `verify-components` 底下，**而那個入口早就跑不起來**
——它用 `import.meta.glob`，那是 Vite 的東西，`npx tsx` 沒有。

🟢 而它唯一真實的消費者是一支單元測試；四路完備性真正的護欄是
`audit-completeness`（P2，零容忍）。所以它是**測試的助手**，不是工具。

> **一個放在「工具」底下而沒有人跑得起來的檔案，它的位置在說謊。**

### `scripts/extract-i18n.mjs` → `tools/`

一個檔的 `scripts/` 與 `tools/` 是同一件事的兩個名字。

### `specs/concepts/` → `specs/component-discovery/`

🪦 那是 spec 159 把 `concept` 改成[元件](../concepts/元件.md)**之前**留下的化石
（今天 `src/` 裡 `concept` 剩 4 個）。使用者指出來的。

⚠️ **不叫 `components`**（使用者的提案）：`src/components/` 才是元件本身，
這裡裝的是**關於元件的報告**。兩個同名而層級不同，grep 會混。
🟢 而 `component-discovery` 多說了一件真的事：**這是探索階段的產物，不是規格**
——這個目錄裡沒有 `spec.md`，其餘 141 個都有。

🔴 **而量過之後才知道不能丟**：31 份報告提案 **191 顆元件，只有 76 顆成為膠囊**。
留著它們的理由不是紀念，是那 **115 顆還沒做的**。

⚠️ **`specs/` 底下的歷史紀錄不改寫**——更新引用時誤改了 7 份舊 spec 的
task 清單，當場還原。那些是當時的紀錄。

## 🪦 紀念品：一支在同類問題再度發生時沒有人想起來的工具

`tools/codemod/rename-concept.mjs`（84 行）做的正是**問 TypeScript
「這個 `.concept` 的接收者是什麼型別」**——正則答不出來的那個問題。

而三天前的 `children` → `slots` 那一刀，我重新發明了同一個判斷，
**一次都沒有想到去找它**。

> **一支在同一類問題再度發生時沒有人想起來的工具，它不是工具，是紀念品。**

它退場了（`.concept` 在 `src/` 剩 0），而技巧留在 [229](229-程式碼早就在使用點把它翻譯成槽了.md)
——技巧比那 84 行通用，因為它不綁在哪一個欄位名上。

## 🔴 還沒動的那一個：`src/panels/`

```
src/panels/*/panel.ts                      0 個（目錄裡只有一份 README）
loadPanels() 的產品呼叫者                   0 個
README 引用的 panel-declaration-open.test.ts  不存在
```

spec 170 的 T001–T006 把登錄表蓋好了（262 行，有測試），**宣告與接線那一半沒做**。
而它自己那支測試的檔頭逐字寫著：

> **一個沒有人宣告的登記處【就是殼】，而它綠得跟真的一樣。**

⚠️ 這**不是**「刪掉包袱」那一類——它是半成品，做完還是收掉是產品決定。
所以這一輪只做一件事：**在 README 最上面把現況寫出來**，
讓那個殼不再看起來像已經完成。
