# 321 · 回答 cella 之前先量——而量的時候只看了一層，答錯了一題

> 日期：2026-11-01（spec 197）
> 轉變：cella 要動 C 子集的語法樹，問我們七項構造「現在送什麼、或擋下」。照〈設計問題要讀設計文件〉與「先量再答」，七段 C 程式逐一 lift → formalize。

## 量到的（回給 cella 的那一份）

巨集、指定初始化子、複合字面量、檔案範圍 `static`、區塊內的型別定義、一元 `+`——都是 unknown（有的在 lift 就成了原樣保留）。cella 照他們的推薦做，我們之後補 formalize。

## 量的時候抓到三個我們自己的

1. `int main(void)` 的 `void` 被當成一個參數——**C 最常見的 main 寫法整支翻不出**。課文的 C 解答寫的是 `int main()`，所以判決綁定語料從來沒碰到它。
2. `extern int x;` 的 `extern` 被悄悄丟掉——宣告變成定義（P6 要的是「保留原文」，不是「給一個看起來合理的結構」）。
3. 物件巨集：照 cella 的推薦由前端展開（數字字面量）。

## 答錯的那一題

第 2 項（後綴與進位）我先回「我們悄悄丟掉了」——因為探針印的 `eNum` 只有值。**而 `eNum` 外面包著一層轉型**（`<id>/value` 那個後綴就是線索），後綴的型別是保住的。
十分鐘後發現、更正。

> 一個「它丟了」的結論，要先看完它被包在什麼裡面——讀數只看最內層，等於只量了一半的結構。
