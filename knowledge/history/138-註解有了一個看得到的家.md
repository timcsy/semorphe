## 為什麼 137 的修法還不夠

137 讓註解**活著**——來回一趟一字不差。而使用者的追問指出了另一件事：

```
extraState.annotations   轉得回去 · 積木上【看不到】 · 【改不掉】
```

> **使用者打的字要有一個看得到的家。**
> 「存得住」與「找得到」不是同一個問題，而只有前者被測試量得到。

## ② 的形狀：每個標頭一格欄位，收在齒輪後面

```
如果 [a ≠ 0]              def area(r) ＃[圓面積]
則 ＃[兩個根] ⟨…⟩
否則，如果 [a = 0]        齒輪裡多一個勾選格：顯示註解
則 ＃[一次式] ⟨…⟩
否則 ＃[其他] ⟨…⟩
```

宣告長這樣（`renderMapping`），核心兩端各讀一次：

```jsonc
"annotationFields": { "IF_NOTE": "header", "ELIF_NOTE_{i}": "elif:{i}", "ELSE_NOTE": "else" }
```

🔴 **`{i}` 由 slot 自己帶**，所以分支幾支都行。

### 一條要寫下來的規矩：宣告了欄位，就由欄位說了算

擷取那一路對這種積木**完全不看** `extraState` 裡有 slot 的標註——**包含一格都沒填**。
少了這條的症狀是：使用者把註解刪掉，而上一輪渲染留在 `extraState` 的那份
**把它原封不動地長回來**。

> **一個刪不掉的東西，比一個看不見的東西更糟。**

代價寫在程式碼旁邊：**宣告了 `annotationFields` 的元件，要把自己會產生的 slot 全部宣告**。

### 而「關掉」不可以是「燒掉」——這一條是開瀏覽器才看到的

第一版：齒輪關掉「顯示註解」＝拆掉那幾格＝那些字沒了。測試全綠，
而真的去點一次就發現**「還原」救不回來**（被拆掉的欄位不在 Blockly 的復原事件裡）。

> **一個救不回來的動作，不該藏在一個勾選格後面。**

🟢 改成**寄放**：收起來的字放在 `noteText_`／`blockOptText_`（跟著存檔走），
再勾一次就回來；收著的期間它**不出現在程式碼裡**（擷取只認欄位）。
同一條也回頭套用在昨天做的「型別／預設值／回傳型別」那幾格上。

## 路上撿到的三個洞——全部是【安靜地掉東西】

驗收時順手問了「同一種形狀的其他子句呢」，於是：

| 症狀 | 根因 |
|---|---|
| `except X:  # …`／`finally:  # …` 的註解不見 | 137 只補了 `if` 那一種形狀 |
| 🔴 `for … else:`／`while … else:` **整段 `else` 消失** | 那兩顆元件沒有地方放它，而它被**丟掉**而不是拒收 |
| `class A:  # 類別` 印成 `# 類別  # 類別` | 標頭註解讓整顆走降級（原文逐字留著），而核心又接了一次 |

第二個最重：**那不是註解掉了，那是整段程式碼掉了**，而產出的碼仍然合法。
修法沿用既有的規矩——**收一半就整顆誠實降級**（`for` 在策略裡拒收、
`while` 用 `constraints` 的 `absent`），原文因此逐字留著。

> **「還不支援」與「支援一半」在程式碼上長得一樣，而在使用者的檔案裡差一段。**

第三個的教訓在判準：一開始寫成「原文裡有沒有這句註解就別再接」——
而 `metadata.rawCode` **每一顆節點都有**（那是它的原文範圍），於是
`try:  # 試` 把自己吃掉了。判準要落在**身分**（`raw_code`／`unresolved`），不是文字包含。

## 留下什麼

- `tests/integration/python-note-fields.test.ts`（8 支）——**走真的 Blockly 工作區**：
  註解欄位是 mutator 長出來的，而 Blockly 的載入順序是 `extraState` 先、欄位後；
  少一步的症狀是**它安靜地丟掉那個欄位值**，而一份 JSON 對照的測試看不到。
- `python-comment-roundtrip.test.ts` 多三支（`except` 家族、降級不重印、`for/while … else` 不掉段）。
