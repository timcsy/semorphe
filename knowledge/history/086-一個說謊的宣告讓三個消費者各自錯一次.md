# 086：一個說謊的宣告，讓三個消費者各自錯一次

> 2026-08-19　上游：[085](085-腳位下拉被自己的量測否決而語料答不了學生的問題.md)
> 觸發：`vision` 掛著一句「🔴 兩條護欄的答案不一樣——先問哪一條在說謊」

## 舊 → 新

```
舊   符合性護欄說 cpp:var_declare 的 declarators 走完 render → extract 之後不見了
     而 US2（`int a, b, c` 的其餘變數不得消失）是綠的
     → 判斷：「兩條護欄矛盾，其中一條是殼」

新   🔴 **三條都錯，而根因是同一個【說謊的宣告】**
     `declarators: 'expressions'`   ← 宣告
     lift 真的產出 cpp:var_declare 自己 ← 真相
```

## 那個謊讓三個消費者各自錯一次，而**方向都不同**

```
符合性       合成器照 'expressions' 填一顆 literal_number
             → 渲染策略讀不到 .name → 報「接點不見了」          🔴 假陽性
投影遺失      同一個原因 → 歸進「判不出來」                      ⚪ 誠實地棄權
US2 那支測試  自己餵 cpp:var_ref{name}
             → 型別也錯，只是【碰巧有 .name】而通過              🔴 假陰性
```

> **一個說謊的宣告會讓三個消費者各自錯一次，
> 而它們錯的方向不同——所以看起來像三個不同的問題。**

⚠️ 而 `vision` 當時記的是「兩條護欄矛盾」——**那個框架本身把人引到錯的地方**：
它假設兩條裡有一條對。**實際上兩條都在量一個不存在的東西。**

## 🟢 而真實路徑一直是好的

```
int a, b, c;  →  lift  →  render  →  extract  →  declarators: [a, b, c]
```

2026-08-19 實測。**系統從來沒有這個缺陷**，掛在帳上的是三個量測工具的病。

## 第二個發現：填一個會從【兩個方向】出錯

```
假陰性   積木上只放得下第一個 → 兩邊都是 1，看起來健康（液晶的建構參數，08-18）
假陽性   一個宣告子本來就塌回普通宣告 → 報「declarators 不見了」
         （`int d;` 不是多變數宣告——而那是【對的】行為）
```

> **一個「可以有很多個」的接點，用一個去驗它，
> 驗的是它退化成單數時的行為——而那常常是另一條路。**

處置：`synthMinimalNode` 對可變數量的接點填 **2 個**（投影遺失那條填 3）。

## 處置（三件，而只有一件動到產品）

```
真相      component.json 的 declarators 改成 cpp:var_declare ＋ _children_why
合成器    fillerFor 認得「接點型別指名一顆概念」（不再只有 param_decl 一個特例）
          ＋ 可變數量的接點填 2 個
測試      US2 餵對型別；⚠️ 而**新增一條從【真實程式碼】出發的**
          ——合成節點永遠有「餵錯形狀而碰巧通過」的風險
```

🟢 **符合性：1 → 0。** 而那是**護欄修好了，不是系統修好了**。

## 為什麼這是 history

「符合性還有 1 筆待清償」這個**帳目**被推翻了——它不是待清償，是量錯。
⚠️ 而下一個看到 `conformance.json` 的人會問「為什麼從 1 掉到 0 而沒有人改產品程式碼」
——**這一則就是那個答案**。
