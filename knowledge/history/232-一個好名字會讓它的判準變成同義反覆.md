# 232 · 一個好名字會讓它的判準變成同義反覆

> 2026-09-14 · 使用者：「其實我真正想改名的是 balance，**我一看根本無法望文生義**」

## 舊 → 新

```
relation: 'conserved' 底下的
  law: 'balance' | 'exclusive'   →   law: 'shared' | 'exclusive'
```

⚠️ **`exclusive` 不動。** 這一刀只換一個值。

## 為什麼換：它過不了六天前才立的那條判準

2026-09-13 的名詞表大修（`attachments` 退場、`Link` → `Edge`）立下的判準是：

> **廣泛使用，而且它的常見意思就是你要的那個意思。**

`balance` 兩條都不過：

```
① 常見意思是另外三件事    財務餘額 · work-life · 天平
   ——沒有一個是「through 相加為零、across 相等」

② 它在同一個 repo 裡同音異義   「守恆」讀起來像線性邏輯的「資源不可複製」，
   而 balance 恰恰【允許】多個 driver（open-drain）
   → 讓專業讀者第一時間猜錯，比讓外行看不懂更貴

③ 它和 exclusive 不是一對    名詞 vs 形容詞，讀起來像兩個無關的東西
   被塞進同一個欄位——而一個列舉的值域應該讀起來是【一條軸上的刻度】
```

## 為什麼是 `shared`：那對詞是鎖的詞彙

```
POSIX      flock(LOCK_SH) / flock(LOCK_EX)
資料庫      S lock / X lock
C++        shared_mutex::lock_shared() / lock()
Rust       RwLock::read() / write()
```

每一個的意思都逐字是「多方可同時持有 vs 只有一個能持有」——
**而那正是這條軸要問的問題**：這份守恆的東西，能不能被多方分著持有？

🟢 **不需要教任何人這對詞。**

## 🔴 而這一刀真正的收穫，是那句話變成了同義反覆

在 `balance` 底下，兩律賺得起分家的理由要靠一個反例撐住：

> open-drain／I2C 的多 driver 在 `balance` 下合法，在 `exclusive` 下非法

讀懂它需要讀者**已經知道 KCL**。換名之後同一句話變成：

> 多 driver 在 `shared` 下合法，在 `exclusive` 下非法

——**「多方持有在『多方可持有』下合法」，什麼都不用知道。**

> **一個好名字會讓它的判準變成同義反覆；
> 一個壞名字要靠一個反例才撐得住。**

## 被否決的候選（墓碑）

| 候選 | 為什麼不選 |
|---|---|
| `kirchhoff` | 人名，望文生義 = 0——**使用者的抱怨會原封不動地留著**；而且機械／熱／流體域不用這個字 |
| `flow` | 判準兩條都過（Modelica 關鍵字、bond graph、網路流的 "flow conservation"），**但撞這個 repo 的「流程」面板**——而那是使用者看得見的字 |
| `conservation` | 與父欄位 `conserved` 同義反覆（壞的那一種） |
| `additive` | 精確指向「相加為零」，但日常使用密度差一截。**次佳，記著** |
| `divisible` | 經濟學的 divisible goods 是標準用法，但 `exclusive` 底下的 `&` 也能 fan-out，**軸對不齊** |

⚠️ 也考慮過**攤平成四值**（`composition | shared | exclusive | information`，
取消 `law` 那一層，讓「需要全樹求解」變成導出的）。
**沒有做**——那比換名大一級，而換名的這一刻是唯一不用改兩次的時機，
所以記在這裡，等 `law` 真的要落地那天再一起判。

## 成本：今天是零，而它只會變貴

```
src/         balance 出現 0 次   ← relation / law / conserved 全部都是 0
knowledge/   21 次
```

🟢 **純文件改名，沒有一次性轉換要寫。** P8 那條（「語義詞彙改名必須附一次性轉換」，
見 [history/026](026-P8-的範圍不含語義詞彙本身.md)）在這裡不觸發——
**因為它還沒進過任何人的存檔**。

🔴 **而這是它最後一次這麼便宜。** `law` 落地的那天起，它就在使用者的檔案裡。

> **一個還沒實作的欄位改名是免費的，而那個免費有期限
> ——期限是「第一個人存檔的那一刻」。**

## ⚠️ 兩件跟著這一刀的事

**① 兩層各有一個 `shared`，而它們不是同一件事。**
`&` 的中文俗名正是「共享借用」（shared borrow），而它住在 `exclusive` **律裡面**。
判準是層：`law` 回答「能不能多方分著持有」，`role` 回答「在這條律內你是哪一種參與者」。
已寫進 `concepts/元件.md` 的角色那一節——**因為下一個人一定會問**。

**② 這個詞彙是跨專案協商的產物，而我單方面改了它。**
`shared`／`exclusive` 的分律出自 2026-08-05 與 ArduinoCAD 的五封往返
（見 [episodes/2026-08-05-跨專案敵對協商](../episodes/2026-08-05-跨專案敵對協商.md)）。
**對方那一側仍然叫 `balance`。** 合流之前要對一次帳，否則兩邊會各自演化一個名字
——而那正是本 repo 記過的「兩邊各自把同一份規格翻譯一次」。

## 🟡 一句不好聽的

命名這麼難，有一部分不是名字的錯：

```
兩律差點被判成同一律，救回來的是【一個】反例
而機械那一邊，文件自己標著「設計意圖，不是已實作驗證的現實」
```

> **一個只有一個域被驗過、靠一個反例撐住分界的概念，本來就不容易取到好名字
> ——因為你要命名的那個東西，自己還只有一個半的實例。**

所以 `shared` 在機械域長出閉環（兩馬達一軸、四連桿）之前**算是暫定**。
那不是猶豫，是誠實標記。
