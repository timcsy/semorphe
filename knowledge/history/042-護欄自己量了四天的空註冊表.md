# 護欄自己量了四天的空註冊表——而它的注入一直是綠的

**日期**：2026-08-10 ｜ **交付**：judge 收 `specs/112` 時的三項連鎖修復
**前一則**：[041](041-屬性方向的護欄第一次跑就抓到一個活缺陷.md)

## 轉變一：第七條護欄自 2026-08-06 起量的是一個空的註冊表

```
基線寫的    duplicateConcepts: 0     ← 四天以來一直是這個
真實的數字   4
```

原因是 `audit-executor-duplicates.test.ts` 在量測前**沒有呼叫
`registerCppLanguage()`**——C++ 的執行器一個都沒註冊，重複註冊當然是 0。

**而它有注入測試，而且一直是綠的。** 注入手動 `reg.register()` 同一個名字
兩次再確認被數到——它證明的是「**計數器會數**」。

> **計數器會數 ≠ 註冊表裡有東西。**

### ⚠️ 它的自我否證聲明也寫了，而且**問錯了問題**

> 「⚠️ 這個數字若是 0，先確認計數真的有接上——註冊表在本功能之前完全沒有
> 計數，『0』與『沒接上』產出一樣。**判斷依據是「★ 注入」那支測試**」

那句話把讀者**明確地指向注入**，而注入正好是看不到這個缺口的那一支。

> **一句錯誤的自我否證提示，比沒有提示更糟——它讓人停止懷疑。**

→ 補上「入口條件」健康檢查：**錨在「註冊表裡有幾個概念」**（合成量），
不錨在重複數。而 `experience.md` 早就寫過這個做法，
**它被理解成「注入的補充」，其實是「注入涵蓋不到的另一半」**：

| | 釘住什麼 | 漏掉什麼 |
|---|---|---|
| 注入 | 判定邏輯**會不會報** | 真實輸入**有沒有進來** |
| 入口條件 | 真實輸入**有沒有進來** | 判定邏輯對不對 |

## 轉變二：修好之後第一件事，是抓到四筆真的重複

而其中三筆的註解寫著：

> 「OOP concepts — noop in interpreter (no OOP runtime)」

**那句話在 `specs/071`／`072`／`073` 之後就過期了**（見 [038](038-過期的論斷被當成現況引用.md)）
——那四顆在 `structs.ts` 都有真實作。它們一直沒出事，是因為
**`structs.ts` 載入在後、蓋掉了空操作——靠註冊順序，不是靠設計**。

而 `history/018` 記過同一件事咬人的那次：四個轉型概念有能用的實作，
被清單無聲覆蓋，於是 `static_cast<int>(3.9)` 輸出 `void`。

**刪除四筆之後順帶改善了就近性**——那四顆元件各少一個檔。

## 轉變三：判定詞彙與機器分類，兩個方向都會走散

| | 機器 | 人的詞彙 | 後果 |
|---|---|---|---|
| `#33` | **長出**新類別 | 沒跟上 | 判定檔說 8 個缺陷、護欄說 0 個 |
| `#32` | **接管**了一個類別 | 沒縮回 | 值域裡兩個值永遠不可能被用到 |

**兩個方向的症狀不同，而報表都正常。**
根因相同：**改分類規則時人在想「機器怎麼分」，而判定檔是另一個檔案、
另一個時間寫的——兩邊都合理，合起來才矛盾，而沒有任何一次執行會同時讀到兩邊。**

→ `#33` 已加斷言「人的判定與機器分類必須相容」；`#32` 的死值已刪。

## 一條連鎖

這一輪的三件事是**一條線**：

```
specs/112 掀出 functions.ts 的 noop 註冊（順帶）
  → judge 問「executor-duplicates 為什麼看不到它」
    → 發現那條護欄量的是空註冊表
      → 修好之後抓到 4 筆，其中 3 筆就是那批 noop
        → 刪掉，順帶改善就近性
```

**而起點是一個「順帶掀出、未處置」的旁註。**
