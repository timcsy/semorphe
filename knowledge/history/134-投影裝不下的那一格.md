# 134　投影裝不下的那一格

**日期**：2026-08-23 ｜ **交付**：第五十四條護欄（宣告 → 積木的位置）＋ 第五十一條的 C++ 那一維
**前一則**：[133](133-第三層樣本夠不夠.md)
**觸發**：使用者——「都做，不過要思考未來有其他東西進來的話語料有沒有有系統性的建構？」

## 這一則接在 133 後面：全集補上了，而**方向少了一個**

[133](133-第三層樣本夠不夠.md) 蓋好第五十三條之後，它點名的 20 個形狀當天補了六個
（相鄰字串、型別註記、`from import`／別名、集合與集合推導式、`*` 展開、海象運算子）。
補完那一刻的量測是**語料 105 段、五軸全零、5418 個測試綠**。

然後開瀏覽器按一次「積木→程式碼」，出來的是：

```
def area(r):        ← `: float` 與 `-> float` 都不見了
```

## 🔴 教訓：語義樹裝得下 ≠ 投影裝得下

抬升收了、產生器印得回去、來回轉換的測試也綠——因為那些測試都走
**同一棵樹**。而積木是**另一個投影**，它上面沒有那一格。

> **一個屬性收得進語義樹，卻沒有一格積木裝它
> ——那不是少一個欄位，那是投影會掉東西。**

而它與 #30／#34 是同一條規範的第三個方向：

```
#30  lift 產出的**接點**，宣告裡有嗎        AST → 宣告
#34  lift 產出的**屬性**，宣告裡有嗎        AST → 宣告
#54  宣告的屬性與接點，**積木上有位置嗎**    宣告 → 積木   ← 這一則
```

第一次跑：312 顆膠囊、**25 個宣告沒有位置**。分完形狀之後，
「真的會掉東西」的只有三個——而三個都是真的：

| 掉的東西 | 症狀 |
|---|---|
| `cpp:class_def.base_class`／`.base_access` | `class Dog : public Animal` 來回一趟變成 `class Dog` |
| `cpp:lambda.return_type` | `[](int x) -> double` 的 `-> double` 不見 |

三個當天都補了，棘輪落在 0。其餘 22 個是**具名的判定**
（`Serial` 這種固定接收者、走具名策略的、排版提示、沒有積木的元概念）。

## 而同一天的第二個洞：**一條護欄只跑一個語言的語料**

第五十一條（「語料的每一段，積木狀態都載得進工作區」）從蓋好的第一天就
**只跑 Python 語料**。把 C++ 語料接上去（測試檔裡的反引號片段，515 段語法完整），
第一次跑就抓到 **6 段載不進去**：

- `cpp_class_def` **沒有上下接點**——兩個類別接不起來，整個工作區載入失敗
  （使用者看到的是一條紅色橫幅）。同樣沒有接點的還有 `cpp_struct_declare`／
  `cpp_forward_decl`／`cpp_template_function`。
- `cpp_vector_declare` 的 `SIZE`／`FILL`／`SOURCE`：**宣告的對映表一直指著它們，
  而命令式的 `init` 從來沒有建出來**——`vector<int> v(5, 0)` 投影出的狀態
  指向不存在的插槽。

> **一條護欄只跑一個語言的語料，它就只保護那一個語言。**

⚠️ 而第二筆是[已知的雙重真相](../experience.md)又一次現形：
**宣告式的對映表與命令式的 `init` 是同一顆積木的兩份真相**。

## 語料要怎麼「有系統地」長大（使用者問的那一句）

答案不是「多想幾段程式」，是**每一個新東西進來時，先問它的全集是誰**：

| 步驟 | 問題 | 這一輪的實例 |
|---|---|---|
| ① | 這個新東西有哪些**變化軸**？ | 語法形狀／宣告的元件／積木的位置 |
| ② | 每一軸的全集由**第三方**定得出來嗎？ | `node-types.json`（文法自己宣告的）／登錄表 |
| ③ | 全集的每一格，有**見證**還是有**具名判定**？ | 語料碰到 ＝ 見證；沒碰到 ＝ 一筆帶理由的判定 |
| ④ | 判定的原因是**封閉詞彙**嗎？ | 刻意沒有「還沒想到」這個選項 |
| ⑤ | 這一軸有沒有**另一個方向**？ | #30／#34 有了，#54 是第三個 |
| ⑥ | 同一條護欄，**每個語言都跑了嗎**？ | 51 補上 C++ 那一維 |

> **語料不是想出來的一組程式，是一組全集的見證。**

而 ⑤⑥ 是這一則新加的兩問——它們正是這一天的兩個洞。

## 一起補的 Python 形狀（第五十三條點名的那一批）

`python:import_from`／`python:pass`／`python:set_make`／`python:splat`／
`python:var_assign_expr`，以及既有膠囊的三處：`literal_string` 收相鄰字串
（`layoutHints.verbatim` 保住寫法）、`func_def` 收型別註記、`array_make_for`
的 `generator` 屬性改名 `wrap`（集合推導式進來之後，`generator: 'set'` 會是
一個自相矛盾的值）。

⚠️ 而 `python:literal_string` 的跳脫還原（`\n`）是**被這批語料照出來的舊洞**：
在此之前它把 `\n` 原樣印出來，只是**沒有一段語料的字串裡有跳脫字元**。
