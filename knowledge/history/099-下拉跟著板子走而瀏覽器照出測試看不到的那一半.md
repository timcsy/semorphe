# 099 — 下拉跟著板子走，而瀏覽器照出測試看不到的那一半

**日期**：2026-08-19 · **spec**：`148-board-constant-dropdown` · **狀態**：完成（**而它只完成了一半的問題**）

## 轉變

```
之前   cpp_pin_constant 的下拉：HIGH LOW OUTPUT INPUT INPUT_PULLUP A0   —— 一份 Uno 的世界
之後   八個目標八份名單
       cpp             HIGH LOW OUTPUT INPUT INPUT_PULLUP           （沒有板子）
       arduino-uno     … A0–A7 LED_BUILTIN SDA SCL
       esp32           … A0 A3–A7 A10–A19 …                        （真的沒有 A1／A2）
       esp32c3         … A0–A5 SDA SCL
       wemos-d1-mini   … D0–D8 A0 LED_BUILTIN SDA SCL               （另一套命名體系）
```

## 🟢 這一刀不是發明機制，是接一條線——而前置驗證省掉了兩件事

```
🟢 createOpenDropdown 的選項是【惰性函式】   → 換目標【不必重註冊積木】
🟢 doClassValidation_ 已覆寫                 → 不認得的值會被留著（誠實降級已經建好）
🟢 currentBoard 提供者模式已在執行那側        → 介面層照抄同一份來源
```

**原本以為要做的兩件事都已經有了。** 真正缺的只有「介面層拿不到目前的板子」。

## 🔴 而它避開了一個會製造重複真相的岔路

`boardConstantOptions()` 在**沒有板子**時回 `null`，意思是「用宣告裡原本那份」
——**而不是回一份預設清單**。那份清單會與 `forms/blocks.json` 的 `options`
一模一樣，而兩份一樣的東西遲早有一份會過期。

🟢 於是 `forms/blocks.json` 只刪掉 `A0`（**板子的東西不該寫在沒有板子的宣告裡**），
其餘五個留著當「沒有板子」那些目標的真相。

## 🔴 瀏覽器照出兩件測試看不到的事

### ① 一支假綠的測試

「換板子不得改掉既有的值」第一版是：**在 Uno 設好 `A6`，再切到 C3**。
而把驗證器改壞了它**照樣過**——因為 **Blockly 只在【設值】時驗證，切目標不會重驗**。

> **一個測試如果測的是「狀態改變之後」，而系統只在「改變當下」檢查，
> 那它測到的是【沒有人碰過它】。**

🟢 改成「在 C3 底下把值設成 C3 沒有的 `A6`」——那才是真實情境
（在 Uno 存的檔，在 C3 底下打開）。

### ② 🔴 而學生貼上程式碼時看到的，根本不是這顆積木

```
貼上  pinMode(D1, OUTPUT)
得到  cpp_var_ref（D1）  ＋ cpp_var_ref（OUTPUT）
      而它們的下拉列的是【工作區的變數】——只有一個 x
```

`cpp_pin_constant` **在工具箱「資料」格裡拿得到**，所以這一刀不是白做的
——但**lift 從來不產生它**。

> **一個修好的投影，可能不在使用者走的那條路上。**

⚠️ **這是 spec 148 沒有解決的一半**，而它需要一個**身分**的決定
（`D1` 該 lift 成 `cpp:pin_constant` 還是維持 `cpp:var_ref`），
不是一個下拉的決定——所以**不在這一刀裡偷偷擴張**。

## 注入驗證（四種，逐一確認會紅）

```
提供者沒接上 · 每塊板子回同一份名單 · 不認得的值被丟掉 · A0 又寫回宣告裡
```

⚠️ **而第一輪有兩個注入「沒紅」是假的**——它們讓建置壞掉，
playwright 根本沒跑，而我把「輸出裡沒有 failed」讀成通過。
🟢 第二輪的注入器會分辨「建置壞了」與「真的綠」。
