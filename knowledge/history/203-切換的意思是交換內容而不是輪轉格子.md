# 203 — 「切換」的意思是交換內容，而不是輪轉格子

> 2026-09-02～09-03。使用者在 IDE 的槽上點下拉想換視圖，連續否決了**五種**做法，
> 最後用一句話定案：「**我不是要輪轉，我是要交換**」。

## 轉變

```
舊   槽的下拉＝把那一層【叫到前面來】——它疊上去、或把別人擠走
新   槽的下拉＝把兩個格子的【內容】對調，格數與位置一個都不動
```

⚠️ 這不是 [200](200-復原早就不是積木的動作了，而錯的是它的位置.md)
（「每個槽自己選視圖」）的重述——那一刀決定的是**誰有權選**，
這一刀決定的是**選了之後畫面怎麼變**。兩者可以各自成立，而我把後者
當成前者的自然結果，於是連續交出五個都不對的東西。

## 被否決的五個（逐字保留在 [episodes](../episodes/2026-09-02-五個被否決的切換.md)）

```
① 疊一個新的 webview 上去          使用者：「我覺得疊上來有點怪」
② 喚醒既有的、把它移過來          「切到流程積木就不見了」
③ 讓版面重排                      「三欄的比積木切到流程會只剩兩欄」
④ 依 LAYER_ORDER 輪轉             「我不是要輪轉，我是要交換」
⑤ 交換但走宿主的分組移動指令       「就完全不會動」（Theia 沒有那組指令）
```

## 為什麼是「交換」

使用者自己給了參照系：「**我希望的比較像是我的欄位數不變，但是裡面的內容置換，
就像網頁版那樣的處理**」。

而網頁版早就是這個形狀——`slot-assignment.ts` 的指派是一張**層→層的置換表**
（[200](200-復原早就不是積木的動作了，而錯的是它的位置.md) 立的三條規則：
「同一視圖最多一格／選到別處的就對調／切走再切回來不變」）。

> **兩個宿主上同一個動作要長得一樣時，先問「我們自己那邊它是什麼」
> ——而不是問「這個宿主能做到哪一種」。**

🔴 我先問了後者，於是五個提案裡有三個是「這個宿主做得到什麼」的形狀。

## 而程式碼那一格是宿主的編輯器

積木／流程是我們的 webview，內容說換就換；程式碼那一格是 IDE 自己的編輯器，
換不了內容——只能換**位子**。做法：開一份同一個文件的替身佔住那個槽，
把兩邊移到定位，再把替身收掉（`swapWithEditor`）。

⚠️ 而它會踩到一個 VSCode 的行為：`showTextDocument` **不帶 viewColumn 就會複製一個
編輯器**。同一天踩了兩次——第一次是缺陷，第二次是**故意拿它當工具**。

> **一個你修過兩次的「怪行為」，第三次遇到它時該問的是
> 「它能不能替我做事」，而不是「怎麼繞開它」。**
