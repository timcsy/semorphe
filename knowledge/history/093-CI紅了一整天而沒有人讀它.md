# 093 — CI 紅了一整天，而沒有人讀它

**日期**：2026-08-19 · **狀態**：已修（一半是 repo 設定，未設）

## 發現的經過

使用者一句「CI 沒過」。查下去：**它從 8/18 PR #2 合併就紅了**
——中間推了好幾次，包括我自己的，**而沒有人看**。

```
最後一次綠   2026-08-17 10:52（一個 docs commit）
第一次紅     2026-08-18 12:28（Merge PR #2，84 個 commit）
```

## 根因兩層

```
① App.monacoPanel 改名成 codeView（spec 140，36e1c61）
   而 e2e 五個檔、26 處走 `as any` 拿舊名字
   → tsc 全綠、npm test 4669 全綠、e2e 19/28 紅

② CI 只在 push 到 main 時跑（沒有 pull_request 觸發）
   → 那 84 個 commit【合併之前從來沒跑過 e2e】
```

🔴 **失敗的症狀是逾時不是報錯**——`waitForFunction` 等一個永遠不出現的屬性，
30 秒後放棄。**那讀起來像「環境慢」。**

## 它是 `執行機構` 的第三、四層

```
層一   規範沒有檢查              蓋護欄
層二   檢查沒有人跑              接上 CI（2026-08-08，history 有記）
層三   CI 紅了而沒有人讀          ← 本則
層四   而它跑在合併之後           ← 本則
```

> **一個只在【合併之後】才跑的檢查，擋不住任何東西
> ——它只負責在事後告訴你已經來不及了。**

## 處置

| | |
|---|---|
| 🟢 e2e 改用 `codeView` | 28/28 全綠（原本 9 passed，跑 19.5 分鐘才失敗） |
| 🟢 workflow 加 `pull_request` | ⚠️ `build`／`deploy` 用 `if` 排除——PR 要驗證不要發布 |
| 🟢 `component-rename` 補一節 | 「`__app` 那個把手，型別檢查完全看不到它」 |
| 🔴 **分支保護（CI 沒過不能 merge）** | **未設**——那是 repo 設定，不在程式碼裡。**不設的話層三會再發生。** |

## 教訓的去處

`experience.md` 兩條：
「一個只在合併之後才跑的檢查，擋不住任何東西」
「一個為了測試而開的逃生口，在改名時是型別檢查看不到的引用集合」
