## 一、釘子自己寫的觸發條件到了

2026-09-17 釘上的 `it.fails` 逐字寫著：

> 🟠 **為什麼不現在修**：要讓位置能被「修正」，容器得記下每一次刪除的位置，
> 而每一個讀位置的地方都要先套用那份紀錄。那是一次模型改動，
> 而**語料量到 0 支**用這個寫法。
> 🔴 何時該修：如果盲測或使用者的程式出現這個寫法——**第二個獨立來源**就夠了。

那一天來了，而且是**三個**來源：fuzz_3（`multiset`）、fuzz_6（`map<int,set<int>>`）、
fuzz_9 全部寫 `c.erase(it++)`。**修法就是釘子上寫的那一句**，一字不改。

> **一根釘子如果寫得出「什麼讀數會讓我該被拔掉」，
> 那個讀數出現的那天它就不需要有人記得它。**

## 二、模型：位置自己回頭問，而不是等人通知

```
noteErasure(cells, at)    刪一格時在【那串格子】上記一筆（Symbol 鍵，複製不走）
positionIn(cells, n)      造位置時蓋一個章：「我是在第 era 次刪除之後拿到的」
offsetOf(v)               讀位置時把 era 之後那幾次補算回來
```

⚠️ **未蓋章 ＝ 不修正**（而不是「第 0 次」）。漏蓋一處的後果是「那一處沒修好」，
不是「那一處被算歪」——**一個新機制的預設值要選那個讓遺漏變成沉默的、
不是讓遺漏變成錯答案的**。

## 三、兩種東西在執行期長得一樣，規則就會互相溢出

fuzz_8 的第一個缺陷：`parseExpr(TIt &it, TIt end)` 的 `end` 是**傳值**的迭代器，
而傳值那一路對 `type: 'array'` 做深複製。位置與容器**都是** `type: 'array'`。

於是 `end` 底下那串格子被複製走，`it != end` 的判準（同一個 JS 陣列參考）
**永遠成立**，迴圈在結尾之後解參考：`INDEX_OUT_OF_RANGE: 7`。

> **兩種東西如果在執行期長得一樣，那麼每一條「對其中一種做什麼」的規則
> 都會靜默地套到另一種身上。**

🟢 分得出來的地方是 `offset`：容器本身從來不設它。

## 四、型別規則漏掉一種型別，症狀出現在下游

fuzz_8 的第二個：`char` 不在「整數型別」的清單裡，於是 `*c - '0'` 回 `double`。

**那個減法本身印出來是對的**（195 就是 195）。失真出現在三步之後的
`v /= r`：`100 / 7 / 2 + 1` 印出 `8.14286`。

> **一個型別規則漏掉一種型別，症狀不會出現在那個運算上
> ——它出現在下游第一個「整數與小數不同」的地方。**

## 五、護欄自己的母體會被重構縮掉

`audit-silent-fallback` 的母體是「同一行有 `return` 又有 `value:`」。
17 個 `return { type:'array', value: cells, offset: n }` 換成 `return positionIn(cells, n)`
之後，母體 183 → 167——**那 17 個 return 一個都沒有消失**。

它報的是「語料縮水」，而它同時問對了問題：
「先確認是『東西真的被刪了』還是『掃描器不再吃到它』——後者是缺陷。」
是後者，所以修的是**掃描器**，不是基線。

> **一個用「長什麼樣」定義母體的掃描器，會在那個樣子被重構掉的那天
> 安靜地縮小自己的視野——而它的結論看起來完全正常。**
