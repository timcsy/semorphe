# 127　驗收改成跟真的直譯器對答案

**日期**：2026-08-21～22 ｜ **交付**：`tests/helpers/run-python.ts`、第五十條護欄的第五軸
**前一則**：[126](126-還沒支援的邊界會在別的東西做出來的那天變成擋路的.md)
**觸發**：`126` 把三軸壓到零之後，我以為 Python 那側「教學可用」了。

## 轉變：判準從「跑得動 ＋ 來回一字不差」變成「**與真的 `python3` 同一個答案**」

`126` 收在這三軸：

```
🔴 執行失敗  0 段
🔴 來回不同  0 段
   降級節點  0 個
```

三個零。而它們**合起來也答不出「答案對不對」**——一段程式可以認得出來、
產得回去、跑到最後一行不報錯，而**印出來的東西是錯的**。

發現的方式不是推理，是**手動抽查**：`xs.sort(key=lambda x: x[1])` 排出來的順序
不對。查下去是 `key=` 被靜靜忽略——排序仍然發生、仍然有輸出。

> **一個被忽略的參數不會讓程式停下來，它只會讓答案不一樣。**

## 為什麼上一個判準漏得掉

| 那一軸問的 | 它答得出「答案對不對」嗎 |
|---|---|
| 降級節點 | ❌ 認得出來 ≠ 認對了 |
| 來回不同 | ❌ 產得回去 ≠ 語義一樣 |
| 執行失敗 | ❌ 不報錯 ≠ 答案對 |

三軸都是**投影的自洽**：樹對得起原文、原文對得起樹。而**沒有任何一軸
把答案交給系統外面的東西去審**。

> **一組全部由自己定義的判準，量的是自洽不是正確。**

🟢 而這件事 C++ 那側**早就做對了**（`tests/helpers/run-cpp.ts` 用真的 `g++`），
它住在 `concepts/執行機構.md` 的第八列 #32。**Python 那側只是沒補上**
——所以這一則不是一個新發明，是**一條既有的規則第二次被兌現**。

## 接上去的第一天就抓到四筆，此後每一次擴語料都再抓到新的

```
n[1] = 7             沒寫進那一格（建了一個叫 n[1] 的變數）
d["b"] = 2           字典沒加進去
math.sqrt(16)        給 4 不是 4.0
True + True          給 2.0 不是 2
round(2.5)           給 3（Python 是銀行家捨入，2）
bool([1,2,3])        給 False
if xs:               非空容器判成假（核心的 toBool）
"" == None           給 True
x=10; def f(): x=20  函式裡的指派改到【外面】那個 x
sorted(w, key=len)   說「沒有這個變數 len」（而 Python 的函式是值）
sorted(…, reverse=)  靜靜忽略——順序剛好相反
max(d, key=f)        回傳整個字典（關鍵字包裹被當成一個比大小的候選人）
max("a", "b")        回傳 "a"（字串轉數字是 NaN，而 NaN > NaN 恆假）
list(enumerate(x))   [[0, 9]] 而不是 [(0, 9)]
```

**十四筆，形狀完全一樣：不報錯、有輸出、而答案不一樣。**
沒有一筆是前三軸抓得到的。

## 而修的過程掀出兩個「兩份真相」

- **`builtinCtx.call` 是可選的** → 十三個執行器把裸的 `ctx` 遞進去。
  改成**必要**之後，型別檢查一次點名兩處我自己沒找到的。
- **`withCall` 有兩份**（`func_call` 與 `method_call` 一字不差）→
  「函式當值傳」這條新規則只會被加進其中一份。併成一份之後，
  同一輪又發現**方法分派**（使用者的類別優先）也是兩份。

## 這一則的界線

⚠️ 參照直譯器**不是**「拿 CPython 當實作」。它是**對答案的第三方**：
我們仍然自己解釋語義樹，只是每一段語料的輸出要與它逐字相同。
兩處刻意不同的地方（亂數用固定種子）**具名豁免**，寫在護欄裡。
