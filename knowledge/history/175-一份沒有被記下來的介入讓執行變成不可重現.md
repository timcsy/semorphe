# 175 · 一份沒有被記下來的介入，讓「同一支程式跑兩次」變成兩件事

**日期**：2026-08-26

## 起點：我自己在前一刀造了一個原則違反

那天下午讓使用者在暫停時**手填執行期變數**（`setVariableFromHost`），
而那個值**直接落進 `scope`，沒有進任何紀錄**。我在 commit 訊息裡自己寫下：

> ⚠️ 明說一個【沒做】的：手填的值直接落進 `scope`，沒有進任何輸入紀錄，
> **所以同一支程式跑兩次會得到不同答案**

而 `concepts/模擬的誠實.md:23` 是這個專案關於執行的第一條規則，逐字：

> **一個每次讀到不同值的模擬器，測不出任何東西。**

`:25` 更硬：「🔴 **模擬一律不模那些**——它們讓『同一支程式跑兩次結果不同』，
而那會讓**每一條測試都變成偶然**。」

> **我們自己造了一個那樣的東西。它與 `analogRead` 抖動的差別
> 只在「要有人按按鈕才會發生」——而那不是一個原則上的差別。**

## 量測先於設計：「這次執行的輸入」根本不存在

動手前 grep：`inputHistory`／`recordInput` **零命中**。
`io.ts` 只留 `stdout`（`this.stdout.push`），**輸入一份都沒留過**。

也就是說 vision 那條驗收寫的是「手填的值**進**『這次執行的輸入』」，
而**那份東西要先被造出來**——且它欠的不只是手填，**stdin 一直都沒有被記下來過**。

## 🔴 三個輸入來源，而只有兩個要記

```
🔴 要記   awaitInput()           人現在打的字
🔴 要記   setVariableFromHost    人現在改的狀態
🔴 要記   暫停時的決定            繼續還是停止（它決定後面走哪條路）
✅ 不記   io.read()              跑之前就排好的佇列——【它本身就是一份紀錄】
```

⚠️ 分清楚這一格是關鍵：`io.read()` 讀的是 `stdinQueue`，**本來就重現得出來**。
把它也記一次不會更誠實，只會讓紀錄變成輸出的複本。

> **要記的不是「所有輸入」，是「不可重現的那些」。**

## 轉移：`ExecutionInput` ＋ 重播

一份**有序**的 `ExecutionInput[]`（⚠️ 順序就是語義：同一組值換個順序是另一次執行）。
三個咽喉各記一次；`setReplayInputs()` 讓下一次執行照著吃，**而且不問任何人**。

🟢 而「繼續」與「重播中的繼續」共用同一段套用邏輯（`applyVariable`）
——**刻意不寫兩份轉換**，兩份遲早會不一樣。

⚠️ 紀錄用完之後**回到會問人**：一份短的紀錄不該讓後面的執行變成不可判定。

## 這一刀刻意沒做的：一顆「重播上一次」的按鈕

引擎那一半做完了、有護欄在守。**而觸發它的動作是新的 UI**，那是另一刀。
🔴 更重要的是它不該是預設行為：**學生按第二次執行，期待的是重新打輸入**。

所以生產端先接**可見性**那一半（`principles.md:135`：「降級必須……**必須可見**」）：

```
107
⚠️ 這次執行有 1 筆是你手動填進去的，所以上面的結果不是這支程式單獨跑出來的。
```

⚠️ **只陳述，不問**——前一刀剛學到「別新增一個問句」
（[174](174-規範立錯了半天而使用者一句話把它翻過來.md)）。

## 順帶：兩支合成語料把一個能力缺口從「沒被量到」變成「被量到」

新護欄帶進兩支合法的 C++，於是它們**合法地進了語料**，而三件事跟著動：

| | |
|---|---|
| `gnu_asm_expression`／`gnu_asm_qualifier` | 第一次被語料碰到 → 兩筆「這個工具不做」的判定變成**孤兒**，拔掉 |
| 行為誤差的**不可判定** | 98 → 99（讀 `cin` 而沒有輸入，與既有規則一致） |
| 行為誤差的 **gaps** | 11 → 12：參照跑得動 `asm` 而我們跑不動 |

> **那一筆 gap 是真的能力缺口，而它在此之前只是【沒有被量到】。**
> 語料變大讓一個既有的洞第一次有了編號——那不是退步。

⚠️ 而 `mismatch`（1）與 `environmentDependent`（1）都**沒有動**——
新語料沒有帶進任何行為誤差。
