## 使用者的框架，以及它給出的名字

上一刀（264）的判官量到「`CLAUDE.md` 是經驗的第二個家」，而使用者的回答是一個**模型**：

> **教訓應該在 experience，而 CLAUDE.md 和 memory 應該是快取。**

那比我寫的「投影」準，因為快取多帶兩個東西：**失效**與**可導出**。
而它讓今天的狀態有一個更精確的名字——不是「第二個家」，是
**一個從來沒有 flush 過的 write-back 快取**。那 8 條是**臟行**。

⟹ 而那正好解釋了另一個讀數：`history/262`、`249`、`247` 之所以是孤兒，
因為它們的教訓**只寫到快取**。

## 快取的三個機制，當時三個都沒有

```
flush（寫回）      8 條臟行,從來沒有寫回 experience
invalidate（失效） MEMORY.md 指向 2026-08-05 刪掉的 docs/technical-experiences.md
                  ⚠️ 而【同一個檔的另一行】就記著那次刪除
policy（收哪些）    沒有寫下來 ⟹ 每次靠手感
```

> **沒有失效機制的快取，會在它自己知道該失效的時候繼續供應舊值。**

## 🔴 兩個快取不對稱，而那決定它們能放什麼

```
CLAUDE.md   在 repo 裡          ⟹ 護欄檢查得到  ⟹ 可以放內容
memory/     在使用者機器上,每人一份 ⟹ 護欄永遠看不到 ⟹ 只能放【指標】
```

> **兩個快取裡先爛掉的，正是那個檢查不到的。**

⚠️ memory 那七條技術內容**還沒動**——那是使用者的檔，要他點頭。

## 分法不是長度，是種類

使用者接著說「我甚至希望直接指向 experience.md，這樣更乾脆」。
而純指標有一個**今天量到的代價**：

```
「本機那一台比 CI 那一台寬鬆」只住在 CLAUDE.md,而它在第 264 刀【發動過】
  —— push 完之後我自己去模擬 Linux 的大小寫敏感,沒有人要求那件事
  如果它當時在 experience 隔一跳的地方,我不會在那個時刻打開它
```

🟢 **而使用者的直覺仍然對，因為那句話的角色被我分錯了**：

```
可推廣的那一句（教訓）        → experience.md,唯一真相
「什麼時候會咬人」（觸發條件）  → CLAUDE.md 自己的散文,不是快取
```

逐條套：8 條裡 **6 條是乾淨的教訓**（指過去就好，處方本來就分開寫在列裡），
**2 條其實是操作**（它們界定那一列涵蓋到哪裡）——留下，並改寫成操作的語氣。

## 於是判準比第一版利

第一版是「引言要逐字出現在 experience」。而**那會留下逐字複本，而複本會漂**。

🟢 **最後的判準是「一句蒸餾引言都不留」**——`CLAUDE.md` 裡一個 `> **…**` 區塊，
定義上就是一條被快取的教訓。**於是檢查連文字比對都不需要。**

而失效機制落在指名上：`experience` 那一條改了名字，`CLAUDE.md` 的 `[[…]]` 解析不到 ⟹ 紅。

## ⚠️ 它第一次跑是綠的，而那是合法的例外

8 條臟行在蓋這一項**之前**就寫回去了，所以它沒有經歷「第一次必紅」。
`build-guardrail` 6.5 的例外逐字：「這種情況靠的是**注入**，不是靠第一次的紅。」

⟹ 於是三支注入（合成輸入，不用任何真實教訓標題）＋ 一次端到端實測：
往 `CLAUDE.md` 塞一句引言與一個不存在的指名，**兩項都紅**，還原後綠。
