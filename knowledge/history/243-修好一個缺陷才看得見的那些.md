# 243 · 修好一個缺陷，才看得見的那些

**日期**：2026-09-17
**觸發**：探索報告 `cpp-container-ends` 的第 ③ 項——它排在實作順序的**第 1 位**，
而管線 179 做了 2 和 3 就收工了。理由寫在報告裡：**錯的答案比跑不動危險。**

## 出發時帳面上是一個缺陷，收工時是六個

```
①  multiset 的 insert 無條件去重      ⟹ 少一半元素      語料 13 支    ← 出發時就知道
②  unordered_map 沒登錄成容器樣板     ⟹ m[3]=7 報索引越界  語料 5 支    ← 補量整張表時找到
③  multiset.erase(key) 只刪一個       ⟹ size 多一                    ← 修好 ① 之後才成立
④  map.insert({k,v}) 被擋掉                                          ← 修 ① 時我造出來的
⑤  函式參數的型別沒被登記進 lift 脈絡  ⟹ map 進函式變陣列              ← 盲測 fuzz_3
⑥  a[r][c]=v 列內沒有範圍檢查         ⟹ JS 的洞，下一個走訪的人拿到 TypeError ← 盲測 fuzz_9
```

**①②** 是找來的，**③④** 是修的過程長出來的，**⑤⑥** 是一個看不到原始碼的人問出來的。

## 🔴 ③ 的形狀：一段「只有在另一個缺陷存在時才正確」的程式碼

`container_erase` 寫著「找到第一個相等的，刪掉，回去」。而 C++ 的
`multiset::erase(key)` 刪掉**全部**等於那個鍵的。

那一行在 2026-09-17 之前**是對的**——因為 `multiset` 那時**裝不進兩個 4**。
「刪一個」與「刪全部」在一個不能有重複的容器上是同一件事。

> **兩個缺陷互相遮蔽時，修掉其中一個會讓另一個【第一次】出現，
> 而它看起來像是那次修改造成的迴歸。**

⚠️ 而它的對偶（④）同一天也發生了：我讓「接收者不是集合那一族就丟錯」
——為了不讓 `vector.insert` 被靜默去重排序——而 `insert` 這個方法名
**只有一個主人**，於是對照表也被擋在門外。

**判準**：改一顆共用元件的判斷之前，先列出**所有會走到它的接收者**。
這一次那張清單是 `set`／`multiset`／`map`／`unordered_map`／`vector`／`string`，
而我原本只想了兩種。

## 🔴 ⑤ 的形狀：一張只收宣告的表，看不見任何一個參數

```cpp
void tally(map<char,int>& om){ om['t']++; }   g++ 數一個字母
                                              我們 INDEX_OUT_OF_RANGE: 116
```

`m[k]` 要判成「對照表的鍵」還是「陣列的下標」——**那是兩條不同的律**
（索引超出範圍是錯誤，鍵不存在是插入），而判準是根變數的型別。

那張「名字 → 型別」的表的收集器認的是「這個節點宣告了一個名字」，
也就是 `<x>_declare` 那一族。**函式參數不是宣告節點。**

> **同一段程式在 `main` 裡是對的，搬進函式就壞了
> ——而壞掉的樣子是一個指著使用者沒寫錯的那一行的索引錯誤。**

⚠️ 這個 repo 已經撞過三次同一個形狀：列舉成員（一個節點宣告 N 個名字）、
`#define` 的別名、然後是函式參數。
**任何「掃描宣告」的機制，都要問一次「還有哪裡會產生一個新名字」。**

## 機制：樣板名自己附帶的屬性

「允不允許重複」住在**容器的宣告**上（探索拍板，理由是 C++ 自己的判準：
同一個方法名 `insert`，行為由接收者的型別決定）。

而共用的 lift 檔裡已經有 `templateName === 'map' ? … : templateName === 'pair' ? …`，
旁邊逐字寫著「這是**第二個**特例。第三個出現時該收斂成『從宣告推導』」。

🟢 所以做法是讓 `registerContainerTemplate` 收第四個參數：

```ts
registerContainerTemplate('multiset', 'cpp:set_declare', 'cpp/set_declare', { unique: 'false' })
registerContainerTemplate('unordered_map', 'cpp:map_declare', 'cpp/map_declare', { ordered: 'false' })
```

> **同一個身分在不同樣板名下的差別，是【那個名字】的性質。
> 它屬於登錄那個名字的地方，不屬於讀那張表的人。**

## 🟢 而形狀那三個面向，這一次全程是綠的

①產出的程式碼 ②語義不動點 ③載得進工作區——**修之前也是綠的**。
沒登錄的樣板會掉到一般變數宣告那條路，而那條路**原樣保留型別文字**：
`multiset<int> st;` 進去，`multiset<int> st;` 出來。

> **一個容器被當成別的東西處理時，它的【文字】可以是完美的。
> 分得出來的只有兩樣：語義樹裡的身分，與跑出來的東西。**

## 瀏覽器那一關：兩個標籤把自己叫成一種容器

並排看出來的，而兩個是同一個形狀——**一顆元件服務一整族，標籤寫死了其中一種**：

```
cpp_set_insert   「將 … 加入集合 …」      ← 而我這一刀讓它同時服務 multiset 與 map
cpp_vector_size  「列表 … 的長度」        ← size 這個方法名也只有一個主人
```

🔴 第二個更尖：它在**課文頁上**把一個 `set` 叫成列表，而那一課正在教 set。

⚠️ 而還有第三個，它是我自己造的：課文的正文**逐字引用積木上的字**
（「積木盤上它們寫著『將 … 加入集合 …』」）。改完標籤之後，同一頁上
**正文與它下面那張圖互相矛盾**。

> **一段逐字引用畫面的文字，是一個沒有人在看的依賴
> ——它不會編譯失敗，只會在某一天開始說謊。**

🟠 記著：今天沒有任何機構在看「課文引用的積木字樣」與「實際標籤」是否一致。

## 量測：兩個互不相關的來源指向同一個缺口

盲測十支程式**全部跑不完**，而形狀全部完美。死因攤開之後：

```
迭代器      7 支     ::iterator it = c.begin() / *it / ++it
接收者      2 支     m[1].insert(5) · idx[key].push_back(…)
型別轉換    1 支     string(names[i])
```

出題者看不到原始碼、沒被提示過迭代器。而語料**獨立**量到 `.begin(` 33 次、`.end(` 30 次。

> **兩個互不相關的來源指向同一個缺口，那不是巧合，是下一刀。**
