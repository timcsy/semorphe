# 200 — 復原早就不是積木的動作了，而錯的是它的位置

> 2026-09-01（spec 169）。使用者：「我覺得現在工具列的邏輯有點怪怪的，
> **為何復原按鈕只跟積木**？然後我希望**每個面板可以去選擇要哪一種視圖**」。

## 轉變

```
舊   ↩↪ 住在【積木那一欄】的快速列裡         而 doUndo 早就問 lastEditor 走三條路
新   ↩↪ 住在全域標頭（桌機）                行動版早就這樣了——桌機是那個例外

舊   「積木／流程」是一對互斥的分頁，程式碼沒有分頁
新   每一格一顆下拉，四格【選項完全相同】

舊   areas 同時決定「幾個槽」與「哪一格放哪一層」
新   areas 是【預設】；使用者的覆寫是一張【層 → 層的置換表】
```

## 為什麼

### 復原：行為是全域的，而位置是局部的

```ts
private doUndo(): void {
  if (this.lastEditor === 'code' && this.codeView?.undo) { this.codeView.undo(); return }
  if (this.lastEditor === 'flow' && this.syncController?.undoTree()) return
  this.blocklyPanel?.undo()          // ← 積木只是【最後那條 fallback】
}
```

> **一個動作如果對三個視圖都成立，它就不該住在其中一個視圖裡。**

🟢 而這條原則**程式碼裡早就寫著了**（行動版的 `adoptActionBarSections`）：
「↩↪ 排在最前面，而且**不跟著快速列進積木那一格**：還原動的是語義樹，
不是某一個投影」。**桌機是那個沒有照做的例外。**

⚠️ 而 2026-09-01 稍早我還加過一段補丁「快速列跟著看得見的那一欄走」
——**那是在治症狀**：它讓 ↩↪ 不消失，而沒有讓它不屬於任何一欄。這一刀把它刪掉了。

### 指派是**置換**，不是「槽 → 層」

🔴 **槽沒有穩定的身分**——版面一換槽數就變，`槽索引 → 層` 在切版面時
意義改變 ＝ 資料遺失。而**層有**。

🟢 而置換讓兩條規則變成**定義本身**，不必再寫一次：

```
「同一個視圖最多一個槽」      ＝ 雙射
「選到已在別處的就對調」      ＝ 置換就是對調
「切走版面再切回來不變」      ＝ 置換與版面無關
```

> **把規則寫進資料的形狀裡，就不必再寫一次規則。**

## 🪦 實作時發現兩件事不用做

```
🪦 狀態列加一顆「叫回主控台」   多餘——每一格的下拉都列著主控台，它永遠叫得回來
                                而加了反而讓主控台變成「那個有特權的」
🪦 指派「跟著版面存」           置換與版面無關，一份全域的就夠
```

⚠️ 兩件都是 spec 寫了、而實作時**被更好的形狀吃掉**的。
它們留在 spec 裡當墓碑，而不是被靜靜刪掉。

## 🔴 代價：I3 降級

第八十一條的 I3（每一列每一欄都是 `LAYER_ORDER` 的子序列）現在只對**宣告**成立，
不對**套用後的結果**成立——使用者可以把積木放左邊。

而那與這條線的起點一致：**「不准使用者換」本身就是一種特別待遇。**

## 使用者當場改的兩件事

```
「我希望不是用 tab，而是用下拉式」   分頁列 → 一顆下拉（沿用既有的 QuickPick）
「然後我不想換行」                   下拉【併進那一格既有的工具列】，不自己開一列
                                     ——與行動版那條「只能有一列工具列」同一條規矩
```
