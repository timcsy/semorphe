# 375 · 類別裡帶本體的 friend 變成積木

> 日期：2026-11-10
> 轉變：`friend ostream& operator<<(ostream& os, const P& p) { … }` 這個教科書寫法整段照原文降級，積木上看不到函式本體。
> 改成：新元件 `cpp:friend_def`（類別成員，回傳型別、名字、參數、本體），積木放在同族的朋友宣告旁邊。

## 為什麼不攤平成類別後面的函式

類別裡寫完本體的 friend 看得到類別的型別名字，也只能靠引數的類別找到（ADL）。攤平成頂層函式後，同名的全域變數會被讀到，錯的程式會判對（Cella 的分析）。所以這顆不寫 `formalize.ts`，等 Cella 下下版的 `mbFriendDef { def }`，發版前判決照實回「判不出來」，`audit-formalize-coverage` 的「還沒對應」手動從 35 調到 36，接上之後降回來。

## 只收形狀單純的

本體是一般的大括號區塊才收。限定名（`friend void A::f() { … }`）、參數帶預設值或尾端修飾的照舊降級，這顆沒有地方放。

## 盲測多修的三件事

四支盲測程式抓到的都是類別本身的舊問題，不是這顆元件：

- 類別裡帶名字的 `struct Node { … };` 走到匿名成員那條路，名字被清掉，`Node` 從此不存在。
- 產碼把 public 區排最前面。而成員的【簽名】只看得到寫在前面的型別，`class L { struct Node {…}; public: void f(Node* p); };` 這種預設 private 區宣告型別的寫法就編不過。私有區宣告了型別（新性狀 `declaresTypeName`）時它排最前面，其餘順序不變。
- 類別裡的 `enum Color { RED };`、`class B { … };` 被編出一個叫 `x` 的欄位。現在交給 enum／類別那兩顆；匿名 enum 照實降級。

## 還沒有的

積木拖到最外層時會落進 `main`，與 `cpp:method_def`、`cpp:friend_function` 相同。同一類別內 private 排在 public 前面時，沒有宣告型別的情況下仍會排到後面（積木只有三個分區，寫的先後沒有地方記）。
