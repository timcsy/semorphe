## 一、同一個病出現三次，而第三次才看出它是一族

| 出現 | 症狀 |
|---|---|
| `degradation-blocks` | 一段 Python 降級之後產出 5 顆 `cpp_raw_code` |
| `comment-syntax` | 一段 C++ 的 `// 註解` 被 Python 的規則剝（剝的是 `#`） |
| `PatternLifter` 的「不設文法＝不過濾」 | `python:comment` 贏過 `cpp:comment` |

> **一個「全域只有一份」的登記處，等於宣告了「這個系統只有一個語言」。**

⚠️ 而第三個是**我自己在 spec 167 留下的**，理由是「不要讓 113 個既有測試變成那一刀的範圍」。

> **一個「暫時寬鬆」的預設，會在第二個語言進來的那天變成一個錯的答案。**

🟢 處置不是「每個呼叫端記得先設」——**語言在 `generateCode` 已經是一個參數了**：

> **一個「要記得先呼叫」的前置，就是一個等著被忘記的地方
> ——而如果那個資訊已經在參數裡，它根本不該是前置。**

## 二、🔴 使用者當場回報三個缺陷，而 4916 支測試全綠

```
① 工具箱裡找不到 Python 積木     16 顆的 owner 蓋成 (core)，而來源寫的是 (python)
② 顏色與 C++ 不一致              我按類別自己挑，沒有對照既有元件
③ 有些積木要 mutation            dynamicRules 寫成物件而不是陣列
```

⚠️ **三件都不會讓任何一支測試變紅**：積木定義是合法的、lift 與 generate 都對、
來回轉換一字不差——**壞掉的是「使用者拿不拿得到、看不看得懂」**。

> **投影對不對，與投影【拿不拿得到】，是兩件事——
> 而測試只問得出前者。**

🟢 而 ① 有一個對稱的空白值得記：可拿性護欄看的是「宣告了卻拿不到」，
**沒有人在看「積木長出來了而分類沒跟上」**。

> **「分類多了沒積木」與「積木多了沒分類」是同一條線的兩端，
> 而只有一端有護欄在看。**

## 三、Python 逼出來的三個【核心表達不出來】

| 缺的表達 | 沒有它只能怎麼做 |
|---|---|
| `AstConstraint.absent` | 「這個欄位必須沒有」寫不出來 → 只能寫「沒有限制」，而帶 `elif` 的 if 會被接走、兩個分支靜靜丟掉 |
| `VariadicSpec.leadingField` | 「標籤 ＋ 下拉 ＋ 可變插槽」建不出來 → 只能回去寫命令式定義 |
| `expressionCounterpart` | `form` 說了「有兩種形態」，而**什麼時候用哪一種**沒有宣告 |

> **一個建構子表達不出來的形狀，會變成一筆新的雙重真相。**

🔴 而第三項掀出一個**C++ 既有的缺陷**：`cpp:func_call` 也沒有宣告
`expressionCounterpart`，於是 `x = f(1)` 渲染時挑不到運算式那份。
**兩邊的宣告一比就看見了——那正是第二個語言的價值。**

## 四、兩個「假通過」

```
else_body 的接點【在】、長度是 1、而裡面是 unresolved
```

> **「接點空了」與「接點裡是垃圾」，在斷言 `length === 1` 時完全相同。**

而第二個是量測環境自己：Python 的量測助手**沒有註冊 C++ 的手寫 lifter**，
於是它比產品乾淨，`for i in range(3)` 在瀏覽器裡仍是 `cpp_loop_for` 而護欄說 0
（這一條記在 [history/118](118-文法不是語言而歸屬要用宣告的.md) §三）。
