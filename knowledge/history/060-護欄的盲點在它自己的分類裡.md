# 060　護欄的盲點在它自己的分類裡——四十一條一起漏掉「命令式 vs 命令式」

> 日期：2026-08-14
> 觸發：使用者打開「陣列與列表」只看到**一顆積木**（該有 27 顆）。
> 本檔記的是那個盲點的形狀，不是修了什麼（那在 `040eb01`／`3eaf3ea`）。

## 轉變

```
old  雙重真相 ＝ 「JSON 宣告」與「命令式註冊」定義了同一顆積木
new  還有一種：**兩個命令式註冊**——而那一種是【靜默的覆蓋】
```

## 缺陷長什麼樣

```
block-registrar.ts:604    Blockly.Blocks['cpp_array_declare'] = { … }   ← 新加的
block-registrar.ts:1690   Blockly.Blocks['cpp_array_declare'] = { … }   ← 既有的，後定義的贏
```

新定義**從來沒有生效過**。而舊的那個引用 `ARRAY_DECLARE_INPUTS.value[0]`
——那個常數從 `blocks.json` 的 `args0` 導出，而 `args0` 在同一輪被移除了
→ 空字串 → `appendValueInput('')` 拋錯。

⚠️ **而 console 是乾淨的**：Blockly 把它吞在 flyout 的 inflater 裡，
症狀只剩「那個分類後面的積木都不見了」。

## 🔴 為什麼四十一條護欄一條都沒紅

`audit-dual-truth`（第三十四條）**看的是兩個不同的載體**
——一邊是 `blocks.json` 的宣告，一邊是 `block-registrar.ts` 的命令式註冊。
它比對「同一個型別在兩處都有定義」，而**兩次都在命令式那一側時，它只看到一側**。

> **一條護欄的分類方式，就是它的盲區的形狀。**
> 「JSON vs 命令式」這個切法本身假設了同一側不會重複——
> 而那個假設從來沒有被寫下來過，所以也沒有人檢查它。

→ 第四十一條（`audit-duplicate-block-def`，硬性零）補上那一格。

⚠️ 它**第一次跑是綠的**（缺陷已在前一個 commit 修掉），
所以它靠**注入**證明自己會紅——`build-guardrail` 6.5 的例外情形，
與第三十五條那次相同。

## 而找到它的方法值得單獨記

四個假設錯了三個：`init` 拋錯（**對，而 console 看不到**）、
不是這一輪造成的（**錯**）、flyout 的 layout 壞了（症狀不是原因）、
分類真的只有一顆（排除正確）。

逼出它的是 **`ws.newBlock(type)` 逐顆試建**——把 flyout 一次做的事拆成一顆一顆做。

→ 兩條教訓已進 `experience`（見下方相關）。

## 順帶：一個索引簽名把型別檢查關掉了

同一輪的另一個缺陷：`CATEGORY_COLORS.containers`（正確是 `cpp_containers`），
而 `Record<string, string>` 讓**任何字串**都是合法的鍵，tsc 一聲不吭。
改成 `as const` 之後打錯字就是編譯錯誤（反向驗證過）。

**那是真的缺陷，只是不是這個症狀的原因**——而我一度以為是，
並照著它改了程式碼。見 `experience` 的「改動前後症狀相同」那條。
