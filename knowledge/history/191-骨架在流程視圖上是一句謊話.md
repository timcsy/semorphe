**前一步**：[190](190-一張表扛兩個工作——第 1 課的工具箱裡有「函式」.md)

## 轉折

`/knowie-next` 掃 `draft/` 時發現一句**使用者說過而知識庫裡零筆**的話
（2026-08-28，接鷹架控制項時）：

> 「我想說程式碼的部分還是要顯示完整，而**其他視圖可以有相對應的顯示，
> 可能要做更多的設計**」

當時做完的只有積木那一側。量流程視圖：

```
grep -rn "ghost|scaffold" src/ui/panels/flow-panel.ts src/core/flow/*.ts   →  0 筆

hidden    include · using_namespace · func_def · print · literal_string · endl · return · literal_number
ghost     （逐字相同）
editable  （逐字相同）
```

🔴 **連 `hidden` 都照樣把整組骨架畫出來**，而 console **零筆錯誤**。

## 而它是同一個形狀的第二次

2026-08-28 使用者說「淡的好像失效了」，查下去是**積木側從來沒實作過** `ghost`。
兩天後同一句話在流程視圖上一字不改地成立。

> **一個模式如果在某個視圖上與另一個模式長得一樣，
> 那個視圖就沒有實作它——而選單仍然讓人選得到。**

⚠️ 而它**不會報錯**：症狀只有「我切了而畫面沒變」，
而那很容易被讀成「這個模式本來就這樣」。

## 🔴 所以這一刀的產物不只是流程視圖

第八十八條護欄（`e2e/scaffold-across-views.spec.ts`）：
**每一個投影結構的視圖，切 `ScaffoldMode` 都要看得出差別。**

⚠️ 它有一筆**具名豁免**：**程式碼視圖三個模式本來就該一樣**
（使用者拍板「程式碼的部分還是要顯示完整」）——把它算進來會逼出一個錯的實作。

## 判定搬進 core，而那不是為了整齊

「哪幾顆是骨架」原本是 `ui/app.ts` 的私有方法。流程視圖也要問同一件事，
而 [188](188-Arduino要腳手架而它逼出了「哪一塊是外框」的第六份實作.md) 記著
那個決定曾經有**六份**各自的實作——所以搬進 `core/scaffold-nodes.ts`，
**兩個消費者呼叫同一支**。

🟢 而它走**匯流排**（`SemanticUpdateEvent.scaffold`），不走組裝點直接呼叫：
真相說「這幾顆是骨架」，**每個視圖自己決定怎麼畫**。
⚠️ 積木那側今天還走 `markScaffoldBlocks` 直接呼叫——**搬過來是一筆債，不是這一刀**。

## 🔴 而 `ghost` 在流程視圖上做錯了兩次，第二次是使用者改的

**第一次**（自己抓到）：整顆 `pointer-events: none` 會讓學生**連不進骨架**
——那就是 `setMovable(false)` 的翻版。改成「不掛拖曳、接點活著」。

**第二次**（使用者 2026-08-30 看著畫面說）：

> 「我是希望**淡的還是能移動**，只不過**彼此關係不能變**」

我把積木那一課**直接套過來**了，而那兩個視圖上「位置」的意思根本不同：

```
積木視圖   位置【就是】結構——拖一塊積木會改變程式
流程視圖   位置只是【排版】——拖一顆節點程式一個字都不會變（存進 flowLayout）
```

> **同一句「不能動」，在兩個視圖上禁的不是同一件事。
> 把一個視圖的做法搬到另一個視圖，要先問「這個動作在那裡改變了什麼」。**

🟢 正解：**拖曳照樣可以**，鎖的是 `commitWire`——而判準是
「**被搬的那一顆**是不是骨架」，不是「有沒有碰到骨架」：
學生把自己的節點接**進** `main` 仍然合法，那正是這個模式的用處。

實測：`main` 從 `translate(24,188)` 拖到 `translate(184,308)`，**程式碼逐字相同**；
把「輸出」的 `__next__` 拉到 `main` 的 `__in__` → 拒絕 ＋ 說出理由。

⚠️ 而那次量測順手照出一個**使用者看得到的瑕疵**：我寫的拒絕訊息裡有 Markdown 的
`**`，而通知是純文字——那兩顆星會照字面印出來（其餘四則都沒有）。
**釘進 e2e 了**（`not.toContain('**')`）。
