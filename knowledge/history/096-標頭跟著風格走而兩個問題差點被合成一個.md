# 096 — 標頭跟著風格走，而兩個問題差點被合成一個

**日期**：2026-08-19 · **spec**：`146-header-follows-style` · **狀態**：完成

## 轉變

```
之前   C 目標（style: c → io_style: printf）產出
       #include <iostream>   原文有 include 時原樣保留 → 在 .c 裡編不過
       （沒有標頭）           原文沒有時 → printf 沒有 stdio.h，也編不過

之後   #include <stdio.h>    兩條路都是，而 gcc -x c -fsyntax-only 真的編得過
```

## 使用者拍板「換掉」，而它為什麼不違反 P1

```
語義（真實）   這段程式需要【輸出的能力】
投影（標頭）   iostream 或 stdio.h —— 哪一個，由風格決定
```

> **`<iostream>` 從來不是語義，語義是「需要輸出」
> ——標頭是那個需求在某個風格下的投影。**

⚠️ 換標頭與「把 `cout` 換成 `printf`」是**同一件事**，而後者早就在做了。
**真正的不一致是：語句換了風格，而它的標頭沒有。**

## 🔴 而既有測試抓到一個真的語義碰撞

我第一版把 `iostream → stdio.h` 寫進 `toCHeader`。
`tests/unit/c-topic-derivation.test.ts` **當場紅**——它用
「**名字有沒有被換掉**」判斷「**C 有沒有這個標頭**」，
於是我的改動讓它判成「C 有 iostream」，而 C **真的沒有**。

```
toCHeader      「這個標頭在 C 裡【叫什麼】」    cmath → math.h     同一個標頭的兩個名字
cIoHeaderFor   「C 裡【什麼標頭】滿足這個需求」  iostream → stdio.h  同一個需求的兩個實作
```

> **兩個函式如果回傳同一種型別，很容易被合成一個
> ——而它們答的是不同的問題，合起來之後【每一個消費者都會拿到錯的答案】。**

⚠️ **而我自己的註解就寫著「它與其餘幾十筆不同」，然後我還是把它塞進同一個函式。**

## 兩處我的規格寫錯了，實作中更正

| 規格原文 | 更正 |
|---|---|
| FR-003「與 I/O 無關的標頭 MUST **完全不動**」 | 🔄 **錯的**：`<cmath>` 在 C 裡就叫 `<math.h>`，換名字是對的。改成「不得被換成**別的**標頭」 |
| 邊界案例「`<stdio.h>` 在 C++ → 對稱換成 `<iostream>`」 | 🔄 **否決**：C++ **看得懂** `<stdio.h>`，那不是編不過而是不好看。**這一刀治的是編不過。** |
