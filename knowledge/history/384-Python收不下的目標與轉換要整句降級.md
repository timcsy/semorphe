# 384 · Python 收不下的目標與轉換，要整句降級，不能只收一半

> 日期：2026-11-11（410）
> 轉變：四種寫法以前是「挑認得的收、其餘安靜丟掉」，產出一支合法或不合法、但意思不同的程式：
>
> | 寫法 | 以前產回去 | Cella 的判決 |
> |---|---|---|
> | `for i, (w, c) in enumerate(d):` | `for i in enumerate(d):` | 合法程式被報 NameError |
> | `f'{s!r:<6}'`、`f'{x=}'` | `f"{s:<6}"`、`f"{x}"` | 照跑，印出來不一樣 |
> | `a = b = 0`、`x[0] = x[1] = 7` | `a = `（壞掉） | 送出不合法的 JSON |
> | `x[0], x[1] = 1, 2` | 只剩名字目標 | — |
>
> 改成：收不下就整句誠實降級（P6）。來回轉換逐字不變，Cella 照實說翻不出。

## 怎麼發現的

一輪盲測（出題代理看不到 repo，8 支高中資訊課的 Python 解題程式）。四種都是學生常寫的形狀，而課文裡 0 筆，所以既有測試一支都沒踩到。

## 連鎖指定為什麼要動核心

三顆指定元件（`var_assign`／`container_assign`／`member_assign`）的樣式只問左邊。`a = b = 0` 的右邊又是一個 `assignment`，於是一個**敘述**被當成運算式塞進 value。

要讓它們讓開，就得說「右邊**不是** assignment」，而限制語言只說得出「是」。核心的 `AstConstraint` 加一格 `notNodeType`，與 spec 168 加 `absent` 同一個道理：表達不出「必須不是」，就只能寫成「沒有限制」，而那兩件事執行起來完全不同。

## 為什麼不直接支援

- 連鎖指定：積木的值插槽放不下一顆敘述，要先設計積木形狀。 → **已做**（413，[387](387-連鎖指定是一顆自己的元件.md)）
- `!r`：要在插值那一格加一個轉換欄位（積木、標籤、對照圖都要動），而學生程式裡少見。 → **已做**（412，2026-11-11）：見 [386](386-f-string-的轉換是插值那一格的屬性.md)；`{x=}` 仍降級。
- 巢狀解包：要讓 `targets` 能巢狀，formalize 也要跟著。

三個都留給語料出現時再做。推導式的多變數目標（`[(a, b) for a, b in zip(…)]`，8 支裡 3 支）原本就照實保留，是覆蓋缺口而不是錯，排在下一刀。
