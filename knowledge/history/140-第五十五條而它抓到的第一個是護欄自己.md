# 140　第五十五條護欄，而它第一次跑抓到的第三個是**護欄自己**

**日期**：2026-08-24 ｜ **交付**：第五十五條（沒有一行會安靜消失）＋ 2 個真缺陷 ＋ 4 條空轉的棘輪
**前一則**：[139](139-註解變成一顆看得到的積木.md)
**觸發**：judge 巡檢——139 的教訓自己寫著「**而沒有東西在檢查其餘的元件有沒有照做**」

## 規範 → 可數的量

139 立下的規矩是「**元件遇到自己放不下的子句，要整顆誠實降級，不可以收一半**」。
它的可數形式是：

```
原文的每一個語彙單元（與每一句註解）→ 產出裡都要還在
```

三種結局，只有中間那個是缺陷：**完整收下 🟢／誠實降級 🟢／收一半 🔴**。

🔴 而它與第三十一條（形態的殘差）問的**不是同一件事**：那一條問「有多少碼掉進
raw_code」（模型還沒長到哪裡），這一條問「有沒有碼**兩邊都沒進去**」。
**降級在那一條是分子，在這一條是合格。**

## 量的單位改過一次——而那正是「鍵不要用行號」的同一個病

第一版比的是**行**，第一次跑報了 5 段。逐項看才發現其中 4 段是假報：

| 假報 | 真相 |
|---|---|
| `b**2` → `b ** 2` | **排版** |
| `if (c) continue;` → 補大括號拆成三行 | **排版** |
| `x = 1  # 註記` → 註解搬到自己一行 | **昨天才立的正規化** |

> **一個會因為換行與空白就說「東西不見了」的判準，報的是 diff，不是缺陷。**

改成**語彙單元的計數**（無視排版、只問少了沒有）之後，剩下的都是真的。

## 第一次跑抓到的兩個真缺陷

| 形狀 | 產出 | 為什麼是缺陷 |
|---|---|---|
| `async def f():` | `def f():` | **協程變成普通函式**——`async` 是匿名子節點，沒人讀它 |
| `catch (...)` | `catch (exception& e)` | **捕獲全部縮成只捕獲一種**——`throw 1` 於是接不住 |

第二個特別值得記：`catch (...)` **沒有 `parameter_declaration`**，於是它掉進
兩個預設值（`exception&`／`e`）。那正是 P6 逐字禁止的東西
——「不確定時標記 `raw_code`，**禁止**給出一個『看起來合理』的結構」。

兩個都改成整顆誠實降級（原文逐字留著）。

## 🔴 而第三個抓到的是**護欄自己**

蓋這一條時要呼叫棘輪，於是照抄了鄰居的形狀：

```ts
assertRatchet([['消失', misses.length]], 'no-line-vanishes', { detail: misses })
```

**而這個簽章不存在。** 共用函式收的是 `[名稱, 現值, 基線值]`，第二、三個引數
被 JS 丟掉，`base` 是 `undefined`，`now > undefined` 恆為 false
——於是**棘輪與語料檢查一次都沒有跑過**，而測試全綠。

七個呼叫點、四條護欄（第五十一／五十二／五十四條與這一條）都是這個形狀。

⚠️ **它為什麼活得下來**：`tsconfig.json:25` 的 `include` 只有 `src`
——**測試檔完全不做型別檢查**。一個不存在的簽章在 `src/` 裡活不過三秒，
在 `tests/` 裡活了好幾天。

> **一條護欄失效的方式不是說錯話，是它的斷言根本沒有被執行。**
> 而它與健康的那一條**在終端機上一模一樣：兩個都印綠色的勾。**

🟢 修法：把那個形狀變成真的（共用函式自己查基線），並補上六份缺的基線檔。
硬性零那一層（`expect(...).toEqual([])`）**一直是有效的**，所以缺陷本身沒有溜過去
——空轉的是「語料縮水」與「基線」那一層，也就是**護欄的自我保護**。
