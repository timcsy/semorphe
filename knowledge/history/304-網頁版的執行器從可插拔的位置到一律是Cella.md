# 304 · 網頁版的執行器：從「一個可插拔的位置」到「一律是 Cella」

> 日期：2026-10-11
> 轉變：vision〈執行器可插拔〉那一格原本逐字「B（由一份特定實作取代可插拔的位置）**未拍板**」，
> 2026-09-25 選的是 A（可插拔是永久架構，JS 直譯器是網頁版的 runner）。
> ⟹ **使用者拍板 B 的網頁版那一半：網頁版的執行一律用 Cella；外接執行器用標準工具鏈；不再維護 JS 直譯器。**
> 可插拔的架構還在——只是網頁版的那個 runner 就是 Cella，第二個 runner 是外接的 clang／硬體工具鏈／外部 debugger。

## 推翻它的是一張量測表

cella 量完執行速度（整數、遞迴已經比我們的直譯器快；vector 因模型底下是串列而平方成長）之後，
使用者擔心 JS 直譯器不夠嚴謹，決定「先拿 cella 的差分語料量一次；效果不好就讓 Cella 直接當直譯器」。

`tests/probes/cella-corpus-behaves.test.ts`（第 327 刀）在 4243 支學生形狀的程式上量到：

```
行為有定義   1793 支裡 313 支印錯（17%，而且是下界）
             133  unsigned 不環繞            131  long long 超過 2^53 失準（JS 的 double）
             25   printf 寬度／旗標          13   cout 浮點
標準是 UB    450 支裡 346 支照跑（77%）——直譯器刻意算出精確值（int64.ts「往安全的方向錯」）
不支援       2000 支（1898 支是同一個缺口：`cout << +a`）
```

⚠️ 量測工具自己修過一次：第一輪把「未宣告的變數」歸成「有定義卻停下」（82 支）。
語料每一支都編得過 clang ⟹ 那一定是我們不認得標準函式庫的名字，改歸「不支援」。

## 我給的另一條路，以及它為什麼沒有被選

我的看法是「兩條路不互斥」：直譯器不管換不換都還會在（Python、硬體模擬、formalize 還沒涵蓋的程式），
所以先修 unsigned 與 long long 兩個根因（佔 264／313），UB 偵測交給 Cella 當第二個 runner 並跑。

使用者看完量測，選的是**不維護兩份語意**——呼應根公理「唯一真實」：execute 與 formalize 用同一個定義
（cella 的小步語意與組合子已證一致），execute 對 formalize 的差分可以省掉，只剩對 clang 的差分。

## 三個問題，使用者直接確認（不只依 cella 轉述）

這條會動 vision 的長期層、也會移除一整條執行路徑，所以我在動手前**直接**問了：

```
套用範圍     全部軌道（C／C++、Arduino、Python）
判題         Cella 涵蓋該課之前，暫留 JS 在背景判（不給學生執行／逐步／變數）
切換時點     Cella runner 接上那天一次切，之後不留 JS 執行
```

而使用者經 cella 補了一句，把切換條件講完整：

> 「我是想要先把 cella 的相關東西（Python、Arduino 等等）都收集完再開始，這樣對雙方都好。」

⟹ **切換條件：Cella 涵蓋我們直譯器現在做的所有事**（C/C++、Python、Arduino／ESP32 的硬體模擬、
執行能力清單），**而且我們的 formalize 能把課文翻成 Cella**。屆時一次切換。
**在那之前 JS 直譯器、判題、e2e 照常運作，不會停擺。**

## 這一轉帶出來的

- 我們的關鍵路徑變成 **formalize 的涵蓋**：迴圈、陣列與 I/O、變數快照的解碼、缺的槽產生洞（標籤 `<nodeId>#槽名`）
- 外接 runner 走 **DAP**，`DAP → execution:*` 的轉接在我們這邊；時光旅行對應 DAP 的 stepBack／reverseContinue
- 「網頁版尚未支援這支程式，可用外接的 clang 執行」——還沒涵蓋的程式**誠實顯示**，不退回 JS（模擬的誠實）
- 進度量兩個數字：「formalize＋Cella 能跑的支數」與「其中與 clang 一致的支數」；課文解答是第一個里程碑
