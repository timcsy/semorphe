# 239 · 每一支測試都先把環境洗乾淨，於是使用者走的那條路沒有人走過

**日期**：2026-09-16
**觸發**：使用者附兩張截圖：「我從課程點擊進去，但是**都沒有積木**，只有程式那邊有」

## 症狀：兩個投影在說不一樣的話

```
程式碼欄位   int main() { int age = 16; cout << age << endl; return 0; }   ← 這一題的起點
畫布         一顆都沒有
語義樹       ['cpp:using_namespace', 'cpp:func_def']                       ← 存檔那份【空骨架】
```

而 `task-link-seeds.spec.ts` 那三支**全綠**——它逐字就在測這兩題
（`cpp-beginner/03-變數` 的 `try` 與 `rebuild`）。

## 根因：兩次程式碼→積木同時在飛，而沒有人排序它們

`restoreState()` 的最後一行是**射後不理**的 `syncCodeToBlocks(state.code)`。
它一回傳，組裝點就開始種那一題（`setCode(起點)` ＋ 另一次同步）。
誰後落地誰決定那棵樹：

```
存檔 code   using namespace std; int main() { return 0; }   ← 上一次留下的空骨架
起點 code   int main() { int age = 16; … }

輸掉的時候  程式碼欄位＝起點、語義樹＝空骨架
            而骨架在前幾課是【隱藏】的 ⟹ 畫布上一顆都沒有
```

> **兩個非同步的寫入指向同一份真相，而沒有人排序它們
> ——那不是偶爾錯，那是「誰先回來誰說了算」。**

修法一行：`restoreState` 改成 `async` 並把那次同步 `await` 起來，
組裝點在種之前 `await restored`。

## 🔴 而真正的缺口是測試的第一行

那條路**只在「存檔裡有 `code`」時存在**，而每一支 e2e 的第一行都是把
localStorage 清空。於是：

```
乾淨的存檔   outcome.kind === 'empty' ⟹ 那一行根本不會跑 ⟹ 永遠不會賽跑
使用者       用了一整天，存檔裡有上一次留下的空骨架 ⟹ 每次都在賭
```

> **每一支測試都先把環境洗乾淨，於是「髒的環境」那條路一次都沒有人走過
> ——而使用者永遠走在那一條上。**

⚠️ 這與 [history/234] 那條「只在我測試時走的那條路上成立」**是同一族的下一層**：
上一次修的是「走哪一條路」，這一次是「**帶著什麼狀態**走那條路」。

🟢 新護欄 `e2e/returning-student-seeds.spec.ts`：拿**使用者那一份存檔的逐字複本**
當初始狀態，刻意不清。注入（把 `await restored` 拿掉）重現得逐字相同——
`樹是 ["cpp:using_namespace","cpp:func_def"]`、積木 0。

## 🪦 我在這一輪走錯的兩步

**① 我先猜了「解析失敗」，而那是可以被一個數字否決的。**
使用者主控台印出 `樹: 2` ——樹有東西就代表 lift 成功了。
在那之前我已經寫好一段「主控台會有 `Parse error:`」的說明。

> **一個「哪裡壞了」的假設，要先問「有沒有一個數字可以直接否決它」。**

**② 我一度以為是視窗大小，因為 1000×495 那一次紅了。**
再跑一次就綠——那是 race 的抖動，不是那個變數。
差一點就把一個時序缺陷修成一個排版缺陷。

> **一個只紅過一次的變數，在它紅第二次之前不是原因。**
