# 202 — 十字退場，而主控台回到它本來的位置

> 2026-09-02。使用者在 Arduino IDE 按「三欄」與「十字」，得到四條擠在一起的
> 窄欄，說「**好像沒有比較好**」，接著給了這個提案。

## 轉變

```
舊   版面有四張，而【十字】需要編輯區有第二列
新   十字退場——三張版面全是純欄

舊   state（主控台）是版面 areas 裡的一格，與另外三層平起平坐
新   主控台不在編輯區——它住在宿主的 panel 區（全寬、可開關）

舊   I4 硬性零：「state 必須在【每一個】版面裡恰好一個連續矩形——不得缺席」
新   「可以關，而它必須叫得回來；有輸出時它自己會回來」

舊   VSCode 那側：output → hostTerminal（2026-08-25）→ panelBottom（2026-09-01）
新   → panel 區的 WebviewView
```

## 為什麼

### 一、十字是那個問題的來源，不是受害者

Theia 沒有 `vscode.setEditorLayout`（查證：Arduino IDE 的 bundle 裡**零筆**）。
我花了兩輪在「怎麼讓 Theia 做垂直分割」——退路、能力探測。

而**只有十字需要第二列**。拿掉它，那兩輪的程式碼全部可以刪。

> **我一直在問「怎麼讓這個宿主做到 X」，
> 而正確的問題是「為什麼我們需要 X」。**

### 二、而答案早就在自己的概念裡

`history/198`（2026-08-31）把**執行追蹤**歸給了**情境**，不歸投影。
而主控台正是執行的輸出——**它本來就不該待在編輯區**。

⚠️ 那個分類當時只改了護欄怎麼看它。**這一刀是它第一次改變了版面。**

> **一個分類如果只改標籤而不改任何決定，它還沒有付出代價。**

### 三、🟢 兩種一致第一次指向同一邊

2026-09-01 學到「一致性有兩個方向——與宿主一致、與自己一致」，
而那一次它們**互相衝突**（`identity` 那個軸因此退場）。

這一次不必選：

```
網頁版現在        底下一條全寬的 bottom-container（主控台／變數）＋ 上面分欄
VSCode 的 panel   逐字就是這個
```

## 🪦 被推翻的：「唯讀的輸出格讓 cin 沒有家」

`vscode-profile.ts` 上寫著（2026-08-25）：

> 「🔴 **終端機，不是 Output 面板**——我們的程式會讀 `cin`，
> 而一個唯讀的輸出格會讓『輸入』沒有家。」

🔴 **那句話的對手是 Output channel，不是 panel 區。**
panel 區放的是 `WebviewView`——**那是我們自己的 webview，它有輸入框**。

> **一個「因為 A 不行所以選 B」的理由，在 C 出現時要重新問一次
> ——而不是把 B 當成結論。**

⚠️ 而這一格在 8 天內走了三次：`hostTerminal`（08-25）→ `panelBottom`
（09-01，收回我們自己的面板）→ **panel 區的 WebviewView**（09-02）。
中間那一次是對的方向而**位置錯了**：它把主控台放進了編輯區。

## 十字的理念要有承接處

它當初是使用者 2026-08-31 要的：「四格，每一層一格」「**沒有任何一層是
特別的**」——而那句話是為了擋掉「程式碼面板比較特別」。

🟢 由「**上面三欄平等**」承接：程式碼、流程、積木在編輯區裡誰都不特別。
而主控台**不在那個比較裡**，因為它不是一種投影。

> **「沒有任何一層是特別的」這句話，在發現其中一個根本不是那種東西之後，
> 要說的是【它不參加這個比較】，而不是【硬給它一格】。**

## 這一刀刪掉的比加的多

```
🪦 setEditorLayout 那條路 · arrangeBySplitting · detectLayoutCaps
🪦 十字的 2×2 推導 · state 在 areas 裡的所有特例
🪦 第八十一條的 I4（改寫）

＋ panel 區的 WebviewView
＋ 「有輸出時自己回來」
```

## 交付（2026-09-02，spec 171）

```
版面        四張 → 三張，而三張全是純欄（每一張的 areas 只有一列）
主控台      編輯區的一格 → 編輯區底下一條獨立、全寬、開得關得的底條
VSCode      WebviewPanel（編輯器區） → WebviewView（宿主的 panel 區，與終端機並排）
排版        setEditorLayout／分割退路／能力探測／2×2 推導 → reveal(ViewColumn)
第八十一條  I4「state 不得缺席」 → I4a「state 不得出現」＋ I4b「叫得回來 ＋ 自己回來」
量           src/ ＋ tests/ 刪 714 加 600（SC-003 成立）
```

### 三個未決都在做的時候有了答案

| 當時問的 | 答案 | 為什麼 |
|---|---|---|
| 主控台那一格沒有選擇器之後，它還算不算一個「槽」 | **不算**——槽的下拉扣掉 `state`，四格 → 三格 | 選到它等於把「執行的輸出」塞回一欄投影裡，而那正是這一刀拆掉的形狀 |
| 主控台關掉時執行還跑不跑 | **照跑，而它自己回來** | 規則寫在 `ConsolePanel` 的寫入路徑上（`revealForOutput`），不是各宿主各寫一份 |
| 變數那一頁與主控台同一個 view 還是各自一個 | **同一個** | 兩個 `WebviewView` 是兩個 context，會回到「被餵的薄視圖」那個形狀；而網頁版本來就是「一格兩個分頁」 |

### 🔴 而搬家搬掉了一層保護

主控台在 grid 裡的時候，「這個視窗要不要畫它」是**免費**的——宿主少了
`state` 那一層，縮減就把那一格拿掉了。搬出去之後**沒有人再拿掉它**：
預檢實測 VSCode 的積木視窗與流程視窗**各自長出一條主控台**。

> **把一個東西搬出某個機構的管轄範圍，也就搬出了它的保護。
> 那個機構順手做的事，現在要有人明說。**

⚠️ 而預檢**算出了那一格卻沒有把它放進結論**（印了 🔴 而說「通過」）——
同一天補上（`windowsOk`）。

> **一個算了卻沒有進結論的判準，與沒有算是同一件事。**
