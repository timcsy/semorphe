# 171 · 一條規範落在兩條護欄之間，與沒有護欄是同一件事

**日期**：2026-08-26

## 起點：埠蓋好了兩天，而沒有人搬上去

`history/149` 那一刀為語言套件蓋了訊息埠（`core/messages.ts`），
理由逐字寫在那個檔的第 20 行：

> 「**載入一個語言 ＝ 載入整個 Blockly（連帶 jsdom）**，
>  而那個語言套件與積木沒有任何關係。」

兩天後查「面板只 import 協定」那一項時量到：**同一個病還在，換了宿主。**

```
flow-panel.ts:44     import * as Blockly from 'blockly/core'   ← 只為了第 47 行查一個字
console-panel.ts:1   import * as Blockly from 'blockly'        ← 全包，只為了查三個字
```

把上面那句話的「語言套件」換成「面板」，**一字不改地成立**。

## 🔴 而它為什麼躺了兩天：兩條護欄都刻意不管它

這條規範服務的是 `principles.md:174`
（「**視圖獨立性**：拔掉任一視圖 → 其他不受影響，視圖間零 import」）。
而它今天的機構是第三十九條，那條的兩維**都正確地**放它過：

```
語言獨立性   `audit-four-independences.test.ts:357` 的自我驗證逐字斷言
             isLanguageSpecificImport("import * as Blockly from 'blockly'") === false
             ——那個判斷是【對的】：Blockly 不是一個語言
視圖獨立性   只看「面板互相 import」，不看面板 import 引擎
```

> **兩個都對，而它們之間有一條縫，剛好是這條規範的形狀。**

⚠️ 這與 `retire-imperative-block` §2.5 第七次的失敗模式**同源**：
一條護欄的能力邊界如果切掉它要驗的那一類，綠燈就與「沒有人在看」等價。
差別是那次縫在**一條**護欄內部，這次縫在**兩條之間**——
而後者更難發現，因為兩邊各自看起來都是完整的。

→ 判準：**一條原則有護欄在守 ≠ 它的每一句都有護欄在守。**
   引用原則的某一句時，去問「守它的是哪一條、那一條的能力邊界寫了什麼」。

## 轉移：第七十四條護欄

`audit-panel-engine-import`，硬性零。

```
留一筆規範還成立嗎？   ❌ 「面板只 import 協定」留一個口，那句話就是假的
修一筆要付多少？       便宜——`Blockly.Msg[k] || fb` → `msg(k, fb)`，一行對調
別台機器一樣嗎？       ✅ 純靜態
```

錨在**掃到幾個面板檔（12）／讀進幾個字（138843）**——修好一筆之後
檔案還在、字數還在，**不會因為違規被修好而變小**。
第一次跑**紅**，逐項指名那兩筆；修完 → 0。

具名豁免一筆（`blockly-panel`：它就是積木投影本身），
附一支**孤兒檢查**——豁免指著不存在的檔案時要有人來拔掉它。

## ⚠️ 它自己寫明的一個缺口

> 「**不檢測間接 import**（A → B → `blockly`）——只看面板檔自己的 import 行。
>  所以一個『把 `import * as Blockly` 搬進隔壁 helper』的改法**騙得過它**，
>  而那不是修好，是搬家。」

留著不補，因為補它要做依賴圖、是另一條護欄的體量。
**而寫下來與沒寫下來，差在下一個人知不知道自己在依賴什麼。**

## 順帶：兩句過期的註解

`console-panel.ts` 有三處寫著 `EXEC_STATUS_WAITING` 與 `EXEC_STATUS_ABORTED`
是「**兩個 i18n 鍵不存在**，所以中文介面下一直顯示英文 fallback」。
2026-08-26 查證：**兩個都在**（`i18n/{zh-TW,en}/blocks.json:153,155`）。
補上鍵的那一刀沒有回頭改這段話。

→ 同 [`retire-imperative-block` §7.5](../skills/retire-imperative-block/SKILL.md)、[170](170-查證完要在同一次編輯裡決定那個框.md)：
**一句描述缺陷的註解，不會因為缺陷被修好而過期——它會繼續被相信。**

## 🔴 而開瀏覽器實測抓到了第三件事——**換埠沒抓到，換語言才抓到**

搬到訊息埠之後，第一次驗收看到的是：

```
中文介面   整份程式 ／ ⤢ 自動排版      ✅ 看起來都對
```

**而那證明不了任何事**——`msg(key, fallback)` 的 `fallback` 剛好也是中文。
切成 English 才分得出來：

```
英文介面   Whole program ／ ⤢【自動排版】   🔴 有一格沒跟著換
```

> **一個 fallback 與正解長得一樣的驗收，等於沒有驗收。**
> 要挑一個**兩者會不一樣**的環境。

⚠️ `git stash` 確認**不是迴歸**（`retire-imperative-block` §5 的紀律）——
換埠之前就是這樣。根因：`<option>` 每次 `rebuild()` 都重建，
而那顆按鈕的文字只在 `buildChrome()` 設過一次。

修法是把固定文字收進 `syncLabels()`，掛在每次更新的路徑上。
釘子：`tests/unit/ui/flow-panel-labels.test.ts`（三支，**注入驗過會紅**）。

> **一段「只設一次」的介面文字，會在語言換掉的那天安靜地留在原地。**

⚠️ 而它以前沒有任何測試在看：`panel-independence` 看的是 import，
`mobile-tab-bar` 看的是 `data-tab`——**標籤的文字沒有人看**
（`retire-imperative-block` §5 那句「沒有任何測試在看標籤」的又一個實例）。
