# 一個缺陷修好之後才看得見的缺陷

*2026-09-17 · 管線 180 第四關（模糊測試）*

## 事情

十支隔離出題的 C++ 程式，出題者看不到這個 repo。修完七族缺陷之後，
第三十二條護欄（行為的誤差）突然說「不一致」從 **1 變成 2**。

多出來的那一筆是語料裡早就有的一段：

```cpp
class Vec2 {
public:
    Vec2(double x, double y) : x(x), y(y) {}
    Vec2 operator+(Vec2 other) { return Vec2(x + other.x, y + other.y); }
    void print() { cout << "(" << x << ", " << y << ")" << endl; }
private:
    double x;
    double y;
};
int main() { Vec2 a(1.0, 2.0); Vec2 b(3.0, 4.0); Vec2 c = a + b; c.print(); }
```

g++ 印 `(4, 6)`，我們印 `(0, 0)`。

## 它為什麼今天才出現

在同一輪的稍早，我補了一件事：**一個名字如果是登記過的結構，那個呼叫是建構**
（`return Vec2(…)` 在此之前丟 `UNDEFINED_FUNC: Vec2`）。

在那之前，這段程式**更早就死了**——它從來沒有機會跑到 `print()`，
也就從來沒有機會印出一個錯的答案。

```
修之前   缺口（跑不動）    12 段 ← Vec2 在這裡
修之後   缺口 11 段、不一致 2 筆 ← Vec2 搬到了這裡
```

> **一個缺陷修好之後才看得見的缺陷，在它前面那個缺陷還在的時候是隱形的
> ——而它不在任何「還沒支援」的清單上，因為那個清單記的是【前面那一個】。**

## 底下那個缺陷

C++ 的成員初始化列，兩個名字**查在不同的地方**：

```
Vec2(double x, double y) : x(x), y(y) {}
                            ↑  ↑
                            │  └── 在建構式的作用域裡查 → 參數
                            └───── 永遠是成員
```

而我們把它攤成一串 `cpp:var_assign`（`x = x`），在一個「欄位層 → 本體層（參數）」
的作用域鏈裡跑——**兩邊都解析成參數**，成員從頭到尾沒有被碰到。

⚠️ 而它**只在參數遮蔽成員的時候壞**：`: x(a)` 是對的。
而 `: x(x)` 正是課本教的寫法。

> **參數不遮蔽成員的時候它是對的——而那正是不會有人寫的那一種。**

修法是讓建構式的執行器知道這條規則（**值在現在這個作用域求，寫進欄位**），
不是改樹的形狀：初始化列在語法上就不是一句賦值，而 `inits` 這一格已經說了
「這裡面是成員初始化列」。

## 同一輪的第二個形狀：覆蓋會被修好的缺陷帶走

`const int a[3] = {…}` 原本**誠實降級**成原文。修好它（判準：**`const` 是型別
修飾詞，屬於型別；`static` 是儲存類別，不屬於**）之後，另一條護欄紅了：

```
cpp:raw_code  從「語料碰得到」掉回「語料碰不到」
```

因為整個測試庫裡**唯一會降級成它的片段，就是那個缺陷**。

> **一個降級目標如果只被「還沒修好的缺陷」覆蓋到，
> 那它的覆蓋會在缺陷修好的那天消失。**

補法不是調基線，是替**刻意保留的那一半**（`static ＋ 陣列`）寫一支測試
——而那件事在今天以前**沒有任何測試在釘**：一個刻意的降級，與一個忘了做的功能，
在測試庫裡長得一模一樣。
