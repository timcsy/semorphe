## 為什麼型別不自己推

「意思歸 Cella」：Python 的變數型別是執行時的事，換一組輸入可能不同。所以我們不推，也不假裝這是唯一答案——產出的第一行註解照實寫：

```

```

## 換完再判一次

換語言時，來源判決是 accept 才比；同一份輸入下判決、輸出、assumes 有差，而且學生換完之後沒改過程式 ⟹ 退回原語言並說明（`LANG_DIFFERS`）。

⚠️ 第一版沒有「來源是 accept」這個條件，於是沒有輸入的程式（來源判不出）被誤退回。學生已經動過的也不退：那是學生的程式了。

## 兩個語言語意不同的地方

| Python | C++ 要怎麼寫才一樣 |
|---|---|
| `for i in range(n)` 結束時 `i` 是最後一個值，迴圈內改 `i` 不影響下一輪 | 迴圈後還讀 `i`、或迴圈內賦值 `i` ⟹ 用隱藏計數器 `i__` |
| `//`、`%` 往負無限大取整 | 小函式 `floor_div`／`floor_mod` |

宣告提到每個函式最前面（Python 的變數可以在分支裡才第一次出現）。

## 同一天的第二段：沒跑到的分支（21 → 23）

原本只要有節點在這份輸入下沒跑到，整支保留——於是任何有分支的程式都看輸入的運氣。放行的只有「印字串字面量」：寫法由字面量自己決定，不必看型別。沒跑到的運算式與指定照舊保留，因為放行就等於自己推型別，而且換完再判一次也判不到那一段（同一份輸入沒跑到）。同一刀接上 `elif`。
