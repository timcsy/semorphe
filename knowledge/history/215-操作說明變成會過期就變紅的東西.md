## 為什麼是這個形狀——它來自一句**拒絕**

使用者問的是「能不能重新規劃**所有課程**，加入 Semorphe 怎麼使用……
**這樣使用者比較知道要拉哪裡**」。

而答案的第一句是**不要那樣做**，兩個理由，第二個比較重要：

1. **會腐爛**：UI 改一次，66 課的操作說明就有一部分變成謊話
2. **它與輔助輪的定位衝突**——**一個需要被教的工具，是在增加認知負荷**
   （`concepts/認知鷹架.md`「三輪車不是輔助輪」）。我們在教程式，不是在教 Semorphe

> **一個「把說明寫進每一課」的請求，要先問它會不會讓工具本身變成教材。**

## 🔴 而腳本錄製的真正理由，不是省時間

> **一張手工截的圖是死的；一支腳本錄的片段是【活的】——按鈕搬家時它會紅。**

那個機制本來就在（`tools/demo/record*.spec.ts` 每一支都有斷言）。
把操作說明做成腳本錄製，等於**讓文件變成會過期就變紅的東西**
——而那正是 `concepts/紀錄的腐壞` 說的唯一有效機制。

## 交付

```
withCursor()          把游標畫進頁面裡——Playwright 錄的是頁面內容，
                      而作業系統的游標【不在裡面】
三個片段（webm）       clip-drag · clip-compare · clip-run
src/core/interactions 互動的登錄表——課程只說「我會用到什麼」
audit-lesson-pages    四條新的：兩個方向 ＋ 順序 ＋ 200KB 上限
```

**⚠️ 三個實作上的坑，都寫在 `with-cursor.ts` 的檔頭**：
`pointer-events:none`（不然假游標擋住要點的東西）· `mouse.move` 要帶 `steps`
（不然像跳格）· **capture 階段監聽**（Blockly 與 Monaco 會在冒泡途中攔下事件）。

## 兩個方向的護欄，而第二個方向才是重點

```
宣告的互動要有檔    少了 → 課文頁上是一塊黑方框（看得見）
有檔的互動要有人用   少了 → 一支沒有人看的片段安靜地留著，照樣要維護、照樣會過期
```

> **只驗一個方向的護欄，守得住「缺」，守不住「多」
> ——而多出來的那個不會有人回報，因為它不在任何人的路上。**

## 🔴 而秒開與說明有真的衝突，它由一條數字擋住

課文頁是 **7.5KB、零外部請求**，那是它的體驗基礎。三張 GIF 會讓一頁變成 MB 級。

```
webm 不用 GIF        同樣 3 秒的 UI 動畫約是 GIF 的 1/5～1/10
一頁 200KB 上限       ← 護欄 ④之九
README 那一側仍用 GIF  GitHub 不自動播 webm
```

⚠️ 而「零外部資源」那條硬性零**不受影響**——影片是媒體不是程式碼。

## 只有第 1 課宣告了互動，而那是刻意的

`lessons/cpp-beginner/01-印出一句話/lesson.json` 的 `_interactions_why` 逐字：

> 第 1 課是唯一「他還不知道怎麼操作」的一課。其餘的課不宣告
> ——操作說明抹在 66 課上會腐爛，而且一個需要被教的工具是在增加認知負荷。

## 還開著的

- **第 0 課要不要存在**，還是「開始之前」那一段就夠——⚠️ 這是**待觀察**，
  不是待做：先讓那三個片段活一陣子，看使用者是不是真的卡在那裡
- **「就地提示」**（第三層）——🔴 它才真正解決「不知道要拉哪裡」，因為
  **課文是靜態的，而卡住是動態的**。而它與「本地的學習指標」用**同一份資料**
  → 見〈拆輪子的曲線〉那一項
