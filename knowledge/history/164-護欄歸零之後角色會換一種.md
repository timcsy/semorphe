# 164 · 護欄歸零之後，角色會換一種——而我判反了三次

**日期**：2026-08-26

## 起點

命令式積木定義清到 0（[163](163-命令式積木定義歸零.md)）之後，兩條護欄量的那一側空了：

```
audit-dual-truth        動態註冊 0 ｜ 兩處都有定義 0
audit-block-def-parity  一模一樣 0 ｜ 有差異 0 ｜ 宣告是空殼 0
```

我引 `build-guardrail` 的

> 「一條數字永遠不動的棘輪，與一條沒有人跑的護欄是同一件事。」

在**兩份基線 ＋ vision ＋ skill** 裡寫下「**退不退休是人的決定**」。

## 轉變

```
舊   母體空了 → 這條護欄該不該退休（人來決定）
新   母體空了 → 這條護欄【正在工作】，改成硬性零
```

## 為什麼舊的錯了

那句話講的是**量既有的債**。而債清完之後，同一條護欄的作用會換一種：

```
清償期    溫度計   告訴你還剩幾筆       → 母體空了 ＝ 沒事可做
清完之後  閘門     擋住它再長出第一筆   → 母體空了【正是它在工作】
```

> **母體空掉的護欄，正是唯一擋得住它再長回來的東西。**

明天有人在 `block-registrar.ts` 裡寫一行 `Blockly.Blocks['xx'] = {…}`，
**只有它們會出聲**。

## 判準（給下一條歸零的護欄）

一條護欄的數字歸零時，問：**它量的是一筆債，還是一條規範？**

```
債     可以退休——那筆債不會自己長回來（例如「還有幾個檔沒搬進膠囊」）
規範   改成硬性零——它會長回來，而且是從 0 到 1 那一步最難發現
```

⚠️ 而**留著空轉的棘輪是最糟的第三種**：它擋得住，而它的訊息是
「不得上升」，讀起來像「還在還債」——**真正要說的是「這條線不准再被跨過」**。

## 做了什麼

四支硬性零（逐顆指名），其中**一支是新的**：

```
audit-dual-truth        🔴 同一顆積木不得有兩處定義
                        🔴 那個檔裡不得有命令式的積木定義   ← 新增
audit-block-def-parity  🔴 宣告與命令式不得說不同的話
                        🔴 不得有「兩份定義都有而宣告是空殼」的
```

⚠️ 新增那一支補的是第一支的**盲點**：一顆**只有**命令式定義的積木不在
「兩處都有」的交集裡，於是從它眼下溜過去——**而它更嚴重：連宣告都沒有，
唯一真相就住在視圖層。**

注入驗過：種 `zz_probe_block`（只有命令式）→ 一條紅；種 `cpp_print`
（兩處都有）→ 兩條都紅，並逐項印出形狀差在哪。

⚠️ 兩份基線裡「退不退休是人的決定」那段**沒有刪**，加了墓碑指向更正
——記錄轉變，不是覆蓋狀態。
