# 204 — 身分不准問，除了一個附病歷的檔

> 2026-09-02。這是 [154](154-宿主的能力要用做得到嗎問不是用你是誰猜.md) 的**修訂**，
> 不是推翻：那條規矩仍然是預設，而它現在有一個具名的、只有一個成員的例外。

## 轉變

```
舊   `vscode.env.appName` 一律不准出現在產品程式碼裡（第六十三條護欄，
     掃 `vscode-profile.ts` 一個檔）
新   只准出現在 `src/vscode/host-quirks.ts`，每一筆附【病歷】＋
     一層「實測會降級」的退路；而掃描範圍從一個檔擴大到整個 `src/vscode/`
     ——比原本更嚴
```

## 為什麼 154 不夠用

154 立的判準是「用『做得到嗎』問」，而它的實作形式是**能力探測**：
問宿主有沒有那個方法、或送出去看回呼來不來。

而 2026-09-02 撞到兩件**探測不出來**的事（兩件都查過 Arduino IDE 的 bundle）：

```
① `tabGroups.close` 與 `TabInputText` 都在，而檔案分頁【關不掉】
② `WebviewView.visible` 與 `document.hidden` 【同時】說謊
   （`retainContextWhenHidden` 之下，兩個都說「我看得見」）
```

> **能力探測問的是「你有沒有這個方法」，而那兩題問的是「你做了會怎樣」
> ——後者只有做過一次才知道。**

## 為什麼例外的形狀是「一個檔 ＋ 病歷」

「一律不准」的代價不是零：那兩件事**還是得處理**，而不准具名的結果是它們
變成散落各處的 `try` / 逾時 / 沉默降級——**同一個知識沒有家，就會有很多份影子**。

所以規則從「不准知道」改成「**只有一個地方可以知道，而它必須說明它怎麼知道的**」：

- `CANNOT_CLOSE_EDITORS` / `CANNOT_OBSERVE_PANEL` 各自寫著哪一天、哪一個截圖、
  在哪個 bundle 裡查到什麼
- 每一筆都有第二層：實測失敗時降級，而不是「因為你是 Theia 所以我不做」

⚠️ 而護欄跟著變**嚴**了：以前只看一個檔，現在 `src/vscode/` 底下除了那個檔
一律為零，並且斷言「例外的家必須真的存在」。

> **一條「不准」如果讓真實存在的知識無處安放，
> 它不會消滅那個知識——它會把它打散成沒有人維護的碎片。**
