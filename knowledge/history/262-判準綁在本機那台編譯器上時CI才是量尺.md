2026-09-19｜第 197 刀的第四關與第六關｜而缺陷是第 194 刀留下的

## 判準怎麼修

🔴 **不是把 `nan` 改成 `-nan`**——那只會換一台機器紅。

**先問：這一段的答案有沒有被標準定死？**

```
inf 的拼法        IEEE 754 ＋ iostream 定死了     ⟹ 照舊比字串（除法①③不動）
NaN 的正負號       未指定                         ⟹ 比字串就是把判準綁在實作上
```

換成 C++ 真的保證的那一件事：**那個值不等於它自己**。

```cpp
double a=0.0,b=0.0; double c=a/b; cout << (c != c) << (c == c);   // 兩台機器都印 10
```

## 第二個東西：課文不在 `npm test` 裡

同一刀把輸出從 JavaScript 的 `NaN` 改成 C++ 真正印的 `nan`——**對的改動**。
而課文 `arduino/13-溫濕度` 的 `check.stdout` 寫死了 `"NaN"`，e2e 因此紅。

⚠️ **當時那張觸發表沒有叫我跑 e2e**：那一刀改的不是「會 lift 成哪些元件」，
也不是「使用者按得到的東西」。

> **一次「輸出的文字表示變了」的改動，會讓每一份【寫死了那段文字】的東西過期
> ——而課文是其中一種，它不在 `npm test` 裡。**

🟢 `CLAUDE.md` 的觸發表因此多一列：
**改了「輸出的文字表示」（`nan`／`inf`／數字格式／跳脫字元）→ 跑 e2e。**

**那條護欄只管標頭**，管不到「判準本身寫了一個實作定義的值」。

🟠 **還沒有機構在守這一格**——今天靠的是判斷力：
*拿參照編譯器當權威之前，先問那一段的答案有沒有被標準定死。*
> **一條規範沒有機械化的檢查，它本身就是殼。**
