# 089 — spec 140 的驗收清單：七條按過、一條刪除

**日期**：2026-08-19 · **狀態**：結清 · **擴充**：0.9.4

## 這一則記什麼

一張**人工驗收清單**從「五條測不起來的話」變成「八條按得完的清單」，
再變成「七條 🟢 ＋ 一條墓碑」。⚠️ **值得記的不是結果，是那張清單自己被改了三次**
——而每一次都是因為**條文本身有缺陷**，不是因為系統有缺陷。

| 改的是什麼 | 因為 |
|---|---|
| 補上**基準線** | 原文「按好幾次就是壞的」**沒有對照組**，量到的是「宿主 ＋ 我們」的總和 |
| 補上**這在測什麼** | 使用者逐字：「5b 我不知道是什麼意思」——只寫怎麼按，沒寫為什麼 |
| 更正**按法** | 單步鍵不在 `▶ 執行` 旁邊，要先從 `▾` 選 `🔍 除錯` |
| 更正**版本標示** | 清單押在版本上，而它停在四個版本以前 |
| 新增 **1c** | 1 驗改欄位、1b 驗純移動，**而使用者實際撞到的形狀兩條都沒蓋到** |
| 刪除 **5b** | 前提不成立（見下） |

> **一條驗收條文的前提被改掉時，它就不再是同一條驗收。**

## 🪦 5b（語言覆寫）為什麼刪掉

它宣稱的目的是「`.ino` 與 `.cpp` 用不同的工具箱」。而使用者一句話拆掉前提：
**「`.ino` 在 VSCode 也會顯示 C++」**。

```
Arduino IDE (Theia)   .ino → arduino     🟢 覆寫分得出來
純 VSCode             .ino → cpp         🔴 兩者同一個 id，分不出
```

🔴 **機制本身仍在、仍然正確**（`semorphe.target` 宣告為 `language-overridable`，
`panel.ts` 用 `{uri, languageId}` 當範圍讀）——**只是沒有一條人工驗收在守它**。
這一句必須留著，否則下一個人會以為那個功能沒接。

想在 VSCode 裡分開，得自己貢獻一個 `.ino` 語言——**會接管語法高亮、
可能與官方 Arduino 擴充打架**。沒有做，也沒有決定要做。

## 那張表（留著當下一張清單的範本）

⚠️ **範本的價值在「壞的長什麼樣」那一欄**——沒有它，「看起來還好」會被當成通過。

| # | 按什麼 | 看什麼 |
|---|---|---|
| **1** 🟢 | 🔴 **先量基準線**：在**編輯器裡手打**同樣的改動（把 `x` 改成 `y`），按 `⌘Z`，數要按幾次 ＝ **宿主自己的粒度**。<br>然後**改一顆積木的欄位**，一樣在程式碼那格按 `⌘Z`，數幾次 | 🟢 **不多於基準線**<br>🔴 壞的是**比基準線多**，或中途出現一個**你沒有輸入過的狀態**（例如 `int ;`）<br><br>⚠️ **原條文沒有對照組**（只寫「按好幾次就是壞的」），於是 2026-08-19 量出「要按兩次」時分不出是誰造成的——使用者自己去試才發現 **Arduino IDE 本來就要兩次**。<br>🟢 而途中確實抓到一個真的：欄位清空的瞬間被寫進檔案（`int ;`）→ 已修（0.9.4）。**那一條與宿主粒度無關，它獨立成立。** |
| **1b** 🟢 | 把一顆積木**拖到別的位置**（不改任何欄位），再按 `⌘Z` | 🟢 **什麼都不該發生**（純移動不產生檔案變更）；🔴 壞的是它吃掉你上一個真的改動 |
| **1c** 🟢 | 從工具箱**拖一顆積木進 `setup()`**，放下，再按 `⌘Z` | 🟢 **一次**回到拖之前；🔴 壞的是回到「拖到一半」的狀態（積木在最外層／同一個宣告出現兩次） |
| **2** 🟢 | **點一顆積木** | 🟢 程式碼那一格對應的行**變色並捲到看得見**；🔴 壞的是沒反應或捲錯行 |
| **2b** 🟢 | 在程式碼裡**把游標移到某一行** | 🟢 對應的積木被選取（有外框）；🔴 壞的是選到別顆或沒反應 |
| **3** 🟢 | 🔴 **按法已更正**：按 `▶ 執行` 右邊的 `▾` → 選 `🔍 除錯` → **除錯工具列**才會出現，單步（F10）在那上面。連按 3–5 次 | 🟢 積木**依序**高亮；🔴 壞的是全部一起亮、或第一顆之後就不動 |
| **4** 🟢 | 切到別的分頁再切回來 | 🟢 **捲動位置與縮放還在**；🔴 壞的是回到左上角或縮放重置 |
| **5** 🟢 | `settings.json` 加 `"semorphe.target": "arduino"`，重開面板 | 🟢 面板用 Arduino 的工具箱 |

## 當時的規則（下一張清單照用）

```
哪一條壞了就說哪一條，不必全部按完
沒按的那幾條維持 🟠
🔴 不得因為其他條過了就一起勾掉
```

🟢 這一張是**逐條按出來的**——沒有一條是「順便勾的」。
