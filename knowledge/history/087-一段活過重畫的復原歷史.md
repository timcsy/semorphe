# 087 — 一段活過重畫的復原歷史

**日期**：2026-08-19
**觸發**：使用者在 Arduino IDE 實測回報
**狀態**：已修（`clearUndo` on bus redraw）

## 症狀

在 `setup()` 裡寫 `int x = 1;`，按兩次 Cmd+Z：

```cpp
void setup() { }        ← 空的
void loop()  { }
int x;                  ← 跑到最外層
int x;                  ← 而且兩顆，`= 1` 不見了
```

## 三個假設，全部被實測否決

**而它們每一個聽起來都對**——這是這一則值得記的原因。

| 假設 | 實測 |
|---|---|
| 投影掉資料 | `int x = 1;` 走完 lift→render→extract→generate **一字不差** |
| 載入沒先清空，積木疊上去 | 連續兩次載入 → **1 顆**，不是 2 顆 |
| 反序列化被誤判成使用者編輯 | 真的 `cpp_var_declare`（有 mutator）載入，`onChange` **0 次** |

⚠️ 查的過程中另外抓到一個**死的但無害**的守衛（見 `concepts/投影.md`
「一個沒在做事的守衛」），而**它不是成因**——把它當成成因會結案在錯的地方。

## 轉折：日誌記了「寫了什麼」，答不出「誰叫它寫的」

診斷的寫入紀錄證明了 `int x;` 是**積木面板寫回去的**（鏡像 6 個非空白行 →
寫成 7 行），而查到這裡就斷了。

> **一份只記錄「發生了什麼」而不記錄「因為什麼」的日誌，
> 能證明你的假設是錯的，不能告訴你哪個假設是對的。**

補上「最近被判成使用者編輯的積木事件」之後，使用者再跑一次，答案自己出現：

```
create｜cpp_var_declare｜頂層 2 顆
move  ｜cpp_var_declare｜頂層 2 顆
move  ｜cpp_var_declare｜頂層 1 顆
```

**那是 Blockly 自己的復原在重放事件**——焦點在面板上時，Cmd+Z 走的是那條。

## 成因

```
① 使用者曾經親手拉過積木  → Blockly 的復原堆疊有項目
② 從程式碼重畫工作區      → 復原堆疊【沒有人清它】
③ Cmd+Z                   → 重放【重畫之前】的事件 → 積木憑空長回來
④ 自動同步                → 把那個狀態寫進檔案
```

那顆積木沒有父積木（它的父親屬於舊工作區），所以是**孤兒**
——而孤兒在程式裡的位置就是最後面。按第二次就長第二顆。

## 決定

匯流排重畫之後呼叫 `workspace.clearUndo()`。

**代價說清楚**：重畫之後面板上的 Cmd+Z 不再能還原更早的積木編輯。
自動模式下重畫很頻繁，而**文件那側的復原才是使用者真正在用的**
——用「少一段拿不回來的積木歷史」換「檔案不會被寫壞」。
