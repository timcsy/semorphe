# 276 — 過程圖：一段片段餵進編輯器之後，就不是那段片段了

**2026-09-21** · 第 214 刀 · 分支 `214-step-blockmaps`

現場在 [episodes/一班學生上完前幾課](../episodes/2026-09-21-一班學生上完前幾課.md)。
四條回饋處理完（[274](274-學生上完之後那四條回饋各自指向什麼.md)）、
那條斷掉的連結修完（[275](275-那句含糊的回饋指到的是一條真的斷掉的連結.md））之後，
還剩兩個學生各自要的**圖**：

> 建議:每個動作都應該有一個成品圖，因為光是文字很難理解。
> 可以學到許多東西，但是沒有太多圖片有點難以理解。

授課老師轉述時把它講準了：

> 兩個學生要圖，我想應該是要連**跟著做的過程中拉積木的圖**也要給，
> 不是只有完成品。

## 🟢 而「截圖是最糟的補法」那句判斷，對這裡不成立

草稿 [課程重新設計與回饋的粒度](../draft/2026-09-04-課程重新設計與回饋的粒度.md)
判過「截圖是最糟的補法」——而那句話說的是**手工截圖**。

```
手工截圖   死的。程式碼改了它不會變，而它與課文不一樣的那天沒有人會知道
對照圖     活的。它記著產它的那段程式碼的雜湊與【引擎的指紋】，過期就紅
```

🔴 所以這一刀不是「加截圖」，是**把既有那個機制的母體從 69 擴到 289**。

> **一句「這個做法不好」的判斷，要先問它說的是【那個做法】
> 還是【那個做法的一種實作】。**

## 🔴 而做下去之後，量到一個會讓整個功能靜默壞掉的東西

**編輯器不會原封不動收下一段片段**（實測，這是這一刀最貴的讀數）：

```
第 8 課  int n = 10; …        → 前面補兩行鷹架，片段落在第 3 行
第 1 課  cout << "哈囉";      → 補鷹架【再包進 int main(){…}】，落在第 4 行且多了縮排
Python   for i in range(3):   → 一個字都沒動
```

於是第一版產出來的圖，**課文那一格印著 1 2 3 而積木上的號碼是 3 4 5**。

⚠️ **而畫面上看起來完全正常**——兩邊都有數字、都對齊、都是圓點。
一個學生照著號碼 ③ 去找，會找到一行不存在的程式碼。

> **一份對照表的號碼，要錨在【讀者手上那一份】的行號，
> 不是錨在我們餵進去的那一份。**

🟢 修法：同步之後**當場量位移**（找片段第一行落在第幾行，比對用 `trim()`
——包進 `main` 那一路會加縮排），把號碼校正回去，
而落在窗外的那幾塊（鷹架）**不給號碼**——它們不是這一步的事。
⚠️ 位移**不能假設是 0，也不能假設是 2**：三種課三個答案。

## 🔴 而第一輪產完之後，量到第二個——它比第一個更值得記

277 張圖裡，**30 張帶著紅色的積木**（11%）；而完成品那 69 張是 **0**。

紅色是 `DEGRADATION_VISUALS.syntax_error`——**產品是對的**：
`cout << "Hello!" << endl;` 單獨放在檔案層級，確實不是合法的 C++。

⚠️ **錯的是我的抽取**：課文裡那一步，學生是把它打在 `main` 裡面的。
我把它從那個地方抽出來單獨餵進去，量到的是抽取本身。

> **一段程式碼「是不是錯的」要看它在哪裡——
> 而把它從那個地方抽出來量，量到的是抽取本身。**

🔴 而它有一個更難看見的形狀：**那 30 張看起來完全正常**。
它們有積木、有號碼、有配對——只是其中一塊是紅的。
一個跟著做的學生會看到「你這一步做錯了」，而他什麼都還沒做。

🟢 修法：畫不出乾淨的就**放進那一課的進入點裡再試一次**。
⚠️ 而「放進哪裡」**問產品自己**：課程用哪一份骨架由 `__app.currentSkeletonId` 說，
那份骨架的進入點長什麼樣由它的宣告說（`entryFunctions[].open`／`.close`）。
**沒有寫「cpp 用 main、arduino 用 setup」那張表**——這個 repo 為手寫清單付過三次學費。

⚠️ 而「什麼顏色算降級」也問宣告（`DEGRADATION_VISUALS`），不抄十六進位：
抄一份的話，它改色那天這一支會安靜地不再認得降級。

## ⚠️ 版面：那一欄是讀者唯一讀得到程式碼的地方

步驟圖**把程式碼框換掉**，所以左半不是「第二份」——它是唯一那份。
實測第 8 課：欄寬 287px 而那一行要 316px，`overflow-x:auto` 的結果是
後半段被藏起來，而框裡的橫捲軸沒有人會發現。

> **一個「捲得到就看得到」的版面，前提是讀者知道那裡可以捲。**

🟢 改成換行（續行吊掛在號碼底下）。
🟢 而步驟圖**不破版滿寬**（完成品那張才破）：它坐在一段文字中間，
破出去會把讀者的視線從那一步打斷——而另一個學生逐字說了「感覺太擠」。

## 🔴 兩個「兩邊分開住」的坑，一個躲掉、一個差點沒躲掉

### ① 抽 SVG 的那 200 行——躲掉了

它原本長在 `record-blockmaps.spec.ts` 裡面。複製第二份就是這個 repo
付過三次學費的形狀，所以搬進 `tools/demo/capture-blockmap.ts` 共用。
🟢 **驗過重構前後產物位元組完全相同**（重產第 8 課，`cmp` 一致）。

### ② 「這是第幾段」——第一版踩進去了

第一版在課文頁**重數一次**「這是步驟小節裡的第幾個程式碼框」，
而產生器那一側是從 markdown 數的。兩邊各數一次，遲早會不一樣
——而症狀不是報錯，是**圖配到別段去**（那比沒有圖糟得多）。

🟢 改成**用程式碼內容配對**：每一份步驟圖自己存著「產它的那段程式碼」，
頁面拿內容去查。**計數器整個消失了。**

> **要讓兩份東西不會分岔，最可靠的辦法不是同步它們，是讓其中一份不存在。**

## ⚠️ 畫不乾淨的，產生器當場拒絕寫出去

判準不是 lift 層的預估，是**這一支自己在瀏覽器裡看到的積木型別**。
出現 `raw_code`／`raw_expression`／`unresolved` 就不寫，並記進
`assets/blockmaps/steps/_skipped.json`。

> **一張示範「你這一步要拉什麼」的圖，如果畫出來的是一塊灰的，
> 它示範的是這個工具做不到那件事。**

⚠️ 而**「跳過」要留下痕跡**：一段安靜地沒有圖，與一段「我們判斷它不該有圖」
長得一模一樣。
