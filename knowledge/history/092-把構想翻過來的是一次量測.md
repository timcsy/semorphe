# 092 — 把構想翻過來的是一次量測

**日期**：2026-08-19 · **spec**：`143-syntax-repair-hint` · **狀態**：完成

## 原本要做的，與實際做的

```
原構想   「打錯的關鍵字要說得出【你是不是要打 while】」
         —— 與執行期那半（near-miss.ts）同一個機制
         而「少分號」被寫進【明確排除】：ERROR 節點指不出少在哪

實際做的  「少了什麼、在哪裡」——而「你是不是要打 X」進了【明確排除】
```

**整個對調。** 而對調它的是寫規格**之前**跑的一次量測：

```
whlie (x < 10) {…}   ERROR 節點【不含】"whlie"，只報 ;(MISSING)
retrun 0;            ERROR="0"，不是 "retrun"
int x = 1            MISSING「;」@ 第 2 行第 12 欄        🟢
@@@ ###              ERROR="@@@ ### "
```

🔴 `whlie` 是一個**合法的識別字**，所以 tree-sitter 把它當運算式開頭，
報的是**後面少了分號**。要說「你是不是要打 while」，得自己猜哪個 token 打錯了。

> **`ERROR` 說的是「這一段看不懂」，`MISSING` 說的是「這裡少了這個」
> ——只有後者有位置，而位置正是學生要的東西。**

⚠️ 而那個原構想是**腦中想的**，不是量出來的——同族的既有教訓：
「一個判準如果是照著手上那個實例寫的，它只會涵蓋那個實例」。

## 一個「不存在的東西」怎麼定位

`Diagnostic.nodeId` 的檔頭寫著它是「**唯一真實那一側**」。
而一個 MISSING 的 `;` **不在語義樹裡**——沒有節點，就沒有 id 指得到它。

> **一個「不存在的東西」的位置，只能用它【該出現的地方】來表達
> ——而在一棵樹裡，那不是一個節點，是一個【縫】。**

於是 `Diagnostic` 多一格選用的 `at?: {line, column}`。
被否決的：塞 `params`（那是措辭用的）、用父節點的 `nodeId`
（波浪會畫**整行甚至整個函式**，**比不標更糟**）。

## 順帶消掉一個雙重真相

加 `at` 時 tsc 指出 `view-host.ts` 裡有一份**逐欄抄過來**的 `Diagnostic`。
⚠️ 而**它的註解自己記著那個病**：

> 「這一格 2026-08-14 加上時 tsc 一聲不吭——這個內嵌型別是**另一份宣告**」

**不再補第三次**——改成引用 `Diagnostic`。

> **一份「逐欄抄過來」的型別，它的第一個症狀不是型別錯誤，
> 是【加一格的人以為自己加完了】。**
