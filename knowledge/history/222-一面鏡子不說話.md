# 一面鏡子不說話——而它三天不到就退場了

**日期**：2026-09-08 · 路線圖：課程的第六刀之二「拆輪子的曲線」——待決 D 結案

## 轉變

```
舊  edit-tally 在記「這一課改了哪一邊」——而【零人讀】（機制有了沒人接）
新  章節清單裡每一課一條兩色橫條；走完一軌時主控台畫三段曲線
```

## 🔴 D 開了三輪，卡的不是技術，是一句話

那個數字**本質上是關於這個人的**（他改了哪一邊＝他的行為），
而這個專案的判準是「**它說的是任務、過程，還是這個人？說到人就砍掉**」。
我兩次提的措辭都有「你」：「這一課**你**改了 8 次」。

而 draft 早就寫著為什麼那句話危險：

> 一個「你還在用積木」的數字，寫不好會變成**羞辱**而不是鼓勵。

## 出路：不用字

```
積木 ████░░░░░░ 程式碼        ← 沒有任何一個字在評價
```

> **一面鏡子不說話。** 它在數字好的時候與不好的時候**長得一樣**
> ——所以「沒出現」不會變成一種訊號。

⚠️ 而那條「禁『你』」的測試是一個**代理判準**（「說到人」不好量，所以量
「有沒有『你』」）。它便宜、擋得住大部分，**而它會誤傷**——「你改了 8 次」
說的其實是過程。所以保留它當預設，而 D 這一格用一個**根本不含文字**的形狀。

## 三個決定，而每一個都有理由

**① 放在章節清單，不放狀態列、也不放題目格。**

```
狀態列常駐    「一直在盯著你」——那是監視，不是鏡子
題目格        那一格沒有「這一課」的列，硬塞會變成一個按得下去而沒反應的項目
章節清單      🟢 每一課一列，各自一條橫條——16 條排成一列【就是曲線】
```

而**學生要主動打開才看得到**——一面你自己走過去照的鏡子，與掛在你面前的，
感覺完全不同。

⚠️ 這裡偏離了拍板時說的「題目那一格」——理由在上面那張表，而它是
做到一半才看清楚的：題目格裡沒有「這一課」那一列。

**② 參照系寫在旁邊，而那句話說的是課程。**

第 1 課全是積木是**對的**，第 15 課全是積木才是訊號。所以每一列的
`description` 寫「建議：對照」——那是 `Track.view`／`pins.view` 那條曲線
（上一輪剛做的），而它說的是**課程**，不是他。

**③ 畢業不做門檻，做曲線。**

draft 寫的是「你最後五課有 80% 是直接寫程式碼的」——那句話說的是人，
而且**如果是 20% 呢？** 那句話就變成羞辱，所以它只能在數字好的時候出現
——而選擇性回饋會讓「沒出現」變成訊號。

```
前段（5 課）  積木 ████████░░ 程式碼
中段（6 課）  積木 █████░░░░░ 程式碼
後段（5 課）  積木 ██░░░░░░░░ 程式碼
```

任何方向的變化都畫得出來。⚠️ **往上走的曲線也誠實地畫**——那不是羞辱，
那是一個學生自己看得懂的訊號。

## 兩條硬性零，量的是「鏡子」這件事本身

```
橫條裡不得有任何文字節點          textContent === ''
title 只准是數字                  「還」「才」「只」「已經」「你」「太」「不夠」一個都不准
兩邊都是 0 → 兩塊都是 0 寬        「還沒開始」與「一半一半」是兩件事
```

## 🪦 而它交出去的當天就被問了一句「那一條是什麼意思？」

🔴 **推理的前半是對的**（不用字才不會評價），**而漏掉了後半**：
不用字，它也**不解釋自己**。

`title`（滑鼠停著才看得到的「積木 2 · 程式碼 6」）擋不住這件事
——沒有人會把滑鼠停在一條 52 像素的橫條上，而觸控裝置根本沒有 hover。

> **一個沒有人看得懂的回饋，與一個不存在的回饋，在使用者眼裡是同一件事。**

🟢 修法是**當場說**：清單頂端一列說明（用既有的 `group` 機制），
＋ 把數字寫在說明欄（`積木 0・程式碼 2 · 建議：積木`）。

⚠️ 而**數字不是評語**：它說的是發生過什麼；那條線守的是「還」「才」「只」那種字。

⚠️ 而昨天的 e2e **驗不出這件事**：它驗的是「橫條上沒有字」（鏡子的性質），
不是「有人看得懂它」——**可讀性沒有斷言得出來的形式**。

## 🔴 而它結清的是一個反模式

`edit-tally` 在 2026-09-07 建的時候**零消費者**——只記不讀。
那正是這個 repo 反覆記過的「機制有了沒人接」。
D 不能永遠開著：**要嘛顯示，要嘛讓機制退場**——留一個沒有消費者的機制是最差的選項。

## 🪦 而它 2026-09-08 整條退場——使用者換了一個更直接的答案

> 「我後來覺得弄這條好像沒必要，而是可以在**設計課程的時候提醒
> 可以開始用程式碼寫**。」

🔴 **而那個答案更好，理由不是「比較簡單」**：

```
橫條   被動——他要【自己看出】該換邊了，而那需要一個圖例、一個參照系、一次解釋
提醒   主動——在【該換的那一課】說一句「試試看直接在程式碼那邊寫」
```

而**轉折點早就宣告了**（`Track.view`／`pins.view`，2026-09-07 那一刀）
——所以那句提醒不是新資訊，是**把一個已經存在的宣告講給人聽**。

> **一個要使用者自己解讀的訊號，與一句在對的時機講出來的話
> ——後者不需要圖例。**

⚠️ 而 `edit-tally` 因此**回到零消費者**，所以它跟著走
——那正是這一份自己寫過的判準：**一個沒有消費者的機制是最差的選項**。

🟢 而它留下了兩樣東西：

- **那條曲線的宣告**（`Track.view`／`pins.view`）——提醒就長在它身上
- **一條護欄**：宣告了版面轉折的課，課文要提到它
  > **一個由宣告驅動的改變，如果沒有人在課文裡說一句，
  > 它對使用者就是一件【沒有原因發生的事】。**

### ⚠️ 那三天不是白花的

它走過的三個問題**答案都留下來了**：措辭的代理判準（禁「你」）仍在
`describeSteps`／`describeBudget` 上；「畢業不做門檻」的理由寫在這裡；
而「一個沒有人看得懂的回饋等於不存在」進了 `experience`。

> **一條被推翻的設計，值錢的是它推翻自己的那個理由。**
