## 對位的規則（不猜）

```
元件不同                     → 不對，也不往下
同一個接點                   → 先對整棵子樹形狀相同的（最長共同子序列，保順序）
對上的之間的每一段空隙       → 兩邊數量相同、逐一同元件 ⟹ 逐一對；否則整段換新
```

突變檢查：拿掉「數量相同」那個條件，三支測試紅（刪一句、兩句相同刪一句、有增有刪）——那三種就是「猜」會猜錯的地方。

## 為什麼「換掉」要另外說

身分照形狀沿用之後，一份範例若恰好也有 `main`，指著 `main` 的提議就會**還能套用**——套到一支完全不同的程式上。
「改」與「換」從樹上分不出來（都是一棵新樹），分得出來的是**動作**：App 在那五個地方呼叫 `programReplaced()`，與 spec 219 的 `languageConversionEpoch` 同一組時機。
e2e 的突變檢查：拿掉套範例那一處，那一支紅（原因不再是「套用了範例」）。

## 長測試抓到的

我自己寫的 e2e 有一個競態：接受之後等的是 `int n = 6;` 出現——而那一行**接受之前就在**（是人剛改的），於是等待立刻通過、斷言搶在接受生效之前。
單獨跑綠、長測試在忙碌的機器上紅。改成等**接受造成的改變**（if 不見了）。CLAUDE.md 的判準照舊成立：紅的那一支單獨重跑——這次單獨也綠，而原因是測試自己等錯了東西，不是機器忙。
