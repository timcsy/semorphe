## 這一刀改到的共用處

- formalize 契約新增 `declaresType`：前置宣告的名字要認得成型別（`Helper*` → `tClass`），而 `isStructName` 仍只回答「有定義的」——前置宣告靠那個問題決定「之後有沒有定義」。兩個問題原本是同一張名單，分不開。
- 命名護欄擋下 `forward`（不在操作詞彙）→ 改名 `class_declare`，與 `class_def` 成對（宣告／定義）。
- `tools/bump-formalize-baselines.ts` 把「新元件」當成「既有元件補上 formalize」而把還沒對應減 1——手動改回並寫明（那支工具分不出兩者）。

## Cella 那側量到的（不完整型別）

照 Cella 給的規則兩邊都量：指標宣告／比較／互相指派 accept、取成員與以值宣告變數 reject——對。另外兩個誤判已回報、`knownCellaGap` 釘住：`void touch(Helper* p) { *p; }` 判 reject（只產生左值是合法的）、`void take(Helper h) {}` 判 accept（函式定義的參數必須是完整型別）。Cella 確認、在修（與 tuple、陣列長度運算式同一批）。

## 盲測掀出的（不是前置宣告那顆的，第一次拿「先宣告、後定義」的 OOP 程式量）

修好：R1 回傳指標／參照的函式原型被當成指標變數（`Node* ptr;`，名字與參數全丟）；R2 `new Node{v, head}` 的大括號丟掉；R6 回傳指標的覆寫方法丟了 const 與 override（子類別成了抽象類別）。
誠實降級（原本是安靜地換掉意思）：類別裡的方法／建構子／解構子原型（`int f();`、`int BST();`）、類別外帶 const 或建構子／解構子的定義（`void A::~A()`）、純虛擬函式的指標回傳或尾端 const。要做對得有一顆「宣告方法」的元件 ⟹ 路線圖〈類別外定義成員函式〉。課文與 StudyCpp（306 支）這一族 0 處。

## 瀏覽器驗收量到的

類別外定義成員函式那一族降級成原文之後，走一趟積木會被隱藏骨架包進 `main`（C++ 不准在函式裡定義函式，產回去編不過）。`staysTopLevel` 補一條只看文字的規則：名字帶 `X::` 限定、整段以 `}` 結尾的原文留在最外層（呼叫以 `;` 結尾，不會被認錯）。

## 已知限制

- `for (struct T; ;)`：tree-sitter 容錯解析補了一個 MISSING 識別字，落到一般的變數宣告（文字照樣產得回去）。
- 類別定義把成員依存取分組，沒標存取的成員會被搬到 `private:` 區段（宣告順序改變）——既有設計。
