# 模組是搬家的中途站，不是終點

**日期**：2026-08-11 ｜ **交付**：commit `c06f4c9`／`11e6334`，F 從 4/177 到 **10/177**
**前一則**：[046](046-第四顆膠囊與一個從程式碼到不了的身分.md)

## 轉變一：`<cmath>` 的「五面牆」全空了——而我們曾經說過那是完成

2026-08-06，中立性清償的第四次下降把 58 個執行器從核心層搬進語言套件的模組。
當時的紀錄寫得很清楚（[episodes/中立性從216到0的五次下降](../episodes/2026-08-06-中立性從216到0的五次下降.md)，第 33 行）：

> 「語言套件的模組本來就有 concepts／blocks／generators／lifters 四路，
> 執行那一路住在核心層，**膠囊缺一面牆**。補上之後 8 個標準函式庫模組的
> **五面牆才齊**。」

而 2026-08-11，`<cmath>` 的三顆概念全部進了元件膠囊，這個模組現在：

```
concepts.json   []
blocks.json     []
generators.ts   空函式
lifters.ts      空函式
executors.ts    空函式        ← 五個月前才剛「補齊」的那一面牆
```

**五面牆全空。** 同一路（執行）走了兩趟：**核心 → 模組 → 膠囊。**

### 這不是走錯路，但它會讓未來的讀者困惑

`specs/054` 那一次不是白做的。當時的替代方案是「執行器留在核心層」，
而那違反 P9（語言獨立性）——核心層認識 `cpp:math_pow` 是真的耦合。
搬進模組**確實消掉了那個耦合**，中立性 216 → 0 有它的一份。

轉變在於**終點的位置變了**：

| | 那時候的終點 | 今天的終點 |
|---|---|---|
| 一個元件的五路住在哪 | **模組**（`std/<mod>/`） | **膠囊**（`components/<scope>/<name>/`） |
| 「加一顆元件」要動什麼 | 那個模組的五個檔 | 一個新資料夾 |

> **模組是搬家的中途站，不是終點。**
> 它把耦合從「核心 ↔ 語言」降到「語言內部的模組」，而膠囊再降一級到
> 「元件自己」。中途站不是錯的——**錯的是把中途站當成終點寫進紀錄。**

→ 所以保留空模組而不是刪掉：`<cmath>` 這個標頭仍然是工具箱分類與
`requires` 的錨點，而**顯式的空**讓「這個標頭沒有東西」與
「這個標頭忘了註冊」分得出來（`StdModule` 的同一條紀律）。

## 轉變二：詞彙漂移——「膠囊」曾經指模組

上面那段引文裡的「**膠囊缺一面牆**」，主語是**模組**。
今天 `膠囊` 指的是 `src/components/<scope>/<name>/`——**元件**的資料夾。

同一個詞在五天內指過兩個不同的單位，而**兩次都是對的**：那時候模組確實是
「最小的自足單位」。這一則記下它，是因為未來讀那則 episode 的人會把
「膠囊」讀成今天的意思，然後得到一個錯的結論（「模組本來就該是膠囊」）。

> ⚠️ **一個詞的所指跟著架構往下走，而舊紀錄不會自己更新。**
> 這是 [G 項命名整理](032-G命名整理-詞彙表就是護欄的輸入.md) 那條
> 「詞彙表就是護欄的輸入」在**歷史紀錄**上的版本——護欄管得到程式碼，
> 管不到五天前寫下的散文。

## 轉變三：形狀從三種變五種，而第五種**長得不像表**

[045](045-第三顆膠囊三種形狀全驗過.md) 的標題是「三種形狀全驗過」。這一輪加了兩種：

```
strategies.ts 41 顆       分派表的一列       → 登錄呼叫（container-templates）
io.ts 自由函式             分派表的一列       → 登錄呼叫（call-concepts）
io.ts 方法呼叫             switch 的一個 case → 登錄呼叫（method-concepts）  ← 新
共用產生器 97 顆          一整筆 pattern     → glob 直讀
std/<mod>/lifters.ts     **一個 40 行的函式** → **拆開之後也是登錄呼叫**    ← 新
```

第五種是 `tryCmathLift()`：三個分支、自己組 `createNode`，**看起來完全像實作**。
拆開之後只剩三列「名字 → 身分 ＋ 引數槽名」。

> **一個函式長得像實作，不代表它是實作。**
> 判準：**把它的分支排成表，每一列還剩下什麼？只剩資料 → 它是分派表。**

處置是**擴表而不是開新表**：已被第二顆驗證的 `single-arg-functions`
改名為 `call-concepts`，多帶「引數槽名」與「把函式名記進哪個屬性」，
舊入口 `registerSingleArgFunction` 留著當特例——
**換掉一個已驗證的形狀需要理由。**

三張登錄表（`container-templates`／`call-concepts`／`method-concepts`）
各對**一個語法位置**，不合併：**位置決定形狀**。

## 轉變四：批次的判準被自己的錯誤修正了一次

`specs/113` 把批次條件放寬成「同形狀的可以批次，跨形狀的不要」。
這一輪使用者批准「推完剩下 6 顆」時，我報的前提是**六顆同形狀**——
而那是按**檔案位置**（都在 `std/<mod>/`）判的，實際橫跨三種 lift 形狀。

> **形狀要看 lift 住在哪，不是看檔案位置。**

已寫回 skill。這一條的代價這次是零（發現得早，報告了才動手），
而它會在下一批重演——因為檔案位置是**看得見的**，lift 的住處**要打開才知道**。

## 順帶：兩個掀出來的洞

**① 一條從未存在的投影。** `cpp:string_find_first_not_of` /
`find_last_not_of` 的 `generateCode` 回 `⟨unknown concept⟩`——
`s.find_first_not_of(" ")` 走「程式碼 → 積木 → 程式碼」一圈會變成錯誤訊息。
`git stash` 回到搬家前實測確認**不是搬掉的**。

沒有人發現，是因為身分原本由**樣板字串**組出來，掃描器只認字面字串：
就近性護欄把 2 檔記成 1 檔，而「缺了哪一路」對 35 條護欄全部不可見。
細節見 [experience 的「身分不只以字串字面出現」](../experience.md)。

**② 基準檔的 `note` 會被靜默清掉。** `toolbox-snapshot` 的
`GENERATE_BASELINE` 寫入器直接覆寫整個檔——上一個 commit 剛寫進去的理由，
下一輪重產就沒了。`build-guardrail` 第 7 步說「理由要留在數字旁邊」，
而**一個會靜默清掉它的寫入器，等於把那個約定變成謊話**。已改成保留 `_meta`。
