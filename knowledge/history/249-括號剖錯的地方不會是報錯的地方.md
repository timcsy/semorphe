# 249 — 括號剖錯的地方，不會是報錯的地方

**2026-09-18** · 第 185 刀

## 讀數

語料（218 支學生程式）：**解譯器出錯 40 → 38、兩邊都跑完 134 → 136、一致 121 → 123**，
而「內容真的不同」停在 9。

## 一、錯誤指著一個根本不該被執行的運算式

語料上最大的一族是 `INDEX_OUT_OF_RANGE`（8 支），而其中三支的索引是 **-1**。
索引 -1 不可能來自測資（生成器只給 1..20），所以那是我們自己算出來的。

追到的形狀是併查集的標準寫法：

```cpp
int find(int x){ return (p[x] < 0 ? x : p[x] = find(p[x])); }
```

tree-sitter-cpp 把它剖成 **`(p[x] < 0 ? x : p[x]) = find(p[x])`**，
而 C++ 的文法說三元運算子的**第三個運算元是指定式**，所以正解是
`p[x] < 0 ? x : (p[x] = find(p[x]))`。

⚠️ **症狀分兩種，而兩種都不指向括號**：

```
左邊是三元式          「這個東西不能被指定值（它不是一個位置）」   ← 語料另外 2 支
右邊照樣被求值         find(p[x]) 拿 p[x] ＝ -1 去遞迴 → p[-1]    ← 語料 3 支
```

> **一個結合律剖錯的地方，報出來的錯會落在它讓程式多做的那件事上，
> 不會落在括號本身。**

🟢 修法是**把括號搬回去**（在指定那一路的 lift 重組），不是去改文法。

## 二、同一句話要在四顆元件上各說一次

重組之後 `f(2)` 印出 `void`：`p[x] = find(p[x])` 求值成 `undefined`。

`cpp:var_assign` 的執行器**早就記過**這一句：

> **指派是一個運算式，它求值成被指派的值。**
> 第一版什麼都不回，於是 `while ((p = f()) != 0)` 的比較拿到 undefined。

而 `cpp:array_assign`／`cpp:array_2d_assign`／`cpp:pointer_assign` **三顆都沒跟上**。

> **一個「同一句話要在兩顆元件上各說一次」的規則，
> 第二顆會在第一顆修好之後很久才被發現。**

⚠️ 而它一直沒被發現的原因是**指定通常寫在敘述位置**——那裡不需要回傳值。
只有把它放進運算式位置（三元式、`while` 的條件、鏈式指定）才看得見。

## 三、就近性：一個檔換一個身分

重組的判別（「左邊長成三元式」）是**文法的知識**，留在共用檔；
而 `cpp:ternary` 這個**身分**不該寫在那裡——護欄當場報了
「`cpp:ternary` 洩在 `lifters/declarations.ts:54`」。

加一個 `src/components/cpp/ternary/build.ts`（建構子），檔數上限 3 → 4、目錄仍是 1。

> **把一個檔加進自己的資料夾，換掉一個身分寫在別人家裡——
> 那不是擴散，那正是就近性。**
