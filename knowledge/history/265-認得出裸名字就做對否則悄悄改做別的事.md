# 「認得出裸名字就做對，否則悄悄改做別的事」

2026-09-20｜第 202 刀（讓剩下的語料跑得完）

## 一句話

> **一個「認得出某一種形狀就做對，否則……」的分支，
> 它的正確性等於【使用者只會寫那一種形狀】這個假設
> ——而那個「否則」如果不出聲，假設破掉的那天沒有人會知道。**

## 事情

語料剩下的「內容真的不同 3」裡，`AP325/2/2_5` 整支輸出**全是 0**。
往下縮到最小重現只有三行：

```cpp
void g(int &r){ r = 7; }
int a[3] = {0,0,0};
g(a[1]);  cout << a[1];     g++ 印 7，我們印 0
```

兩個綁定點（`cpp:func_call` 的參照參數、`cpp:var_declare_ref`）**寫的是同一句話**：

```ts
const argVarName = String(argNode.properties.name ?? '')   // 只認一個裸的變數名
if (argVarName) { …declareRef(…); continue }
// 掉下來 ⟹ 傳值
```

而那個「掉下來」**不報錯**。實測五種形狀全中，五種都是**跑得完的錯答案**：

```
g(a[1])          C 陣列的一格
g(v[1])          vector 的一格
g(A[0])          struct 陣列的一格
g(s.a)           struct 的一個成員   ← 這個與陣列無關，一樣壞
int &r = a[1];   綁一個參照變數到一格
void g(int &r){ h(r); }             ← 把出參數再往下傳一層
```

⚠️ **最後一種的原因不同而症狀一樣**：`findOwner` 逐字「只看 `variables`
不看 `refs`」，所以裸名字那條對 `h(r)` 裡的 `r` 答不出擁有者。
🔴 **一個寫著自己限制的註解，不會讓讀到它的人想起那個限制在別處也成立。**

🟢 **修法不是新機制**：`lvalue.ts` 的 `Place`（`swap(a[j],a[j+1])` 在用）
本來就解得出這些位置——缺的是**讓引用也拿得到它**。
`Scope` 的 `refs` 從 `(作用域, 名字)` 放寬成
「`(作用域, 名字)` **或** 一個 `Place`」，兩個呼叫點各接一行。

## 同一刀的另外三件，每一件都是一個「已經在手上而被丟掉」的東西

### ① 那個型別本來就在手上

`d1[i].reset()` 認不出來，既有的釘子逐字寫著它在等
「宣告表記得住陣列的元素型別」的那一天。而 `cpp:array_declare` 的
`properties.type` 逐字**就是** `bitset<26>`——`recordDeclaration` 讓
「從身分推導」贏過它（那是對的，否則容器會被記成 `int`），
然後**把它丟了**。

> **一個「這個值不該放在這一格」的判斷，如果沒有替它找一格，
> 就等於把它刪掉——而刪掉與「本來就沒有」看起來一樣。**

### ② `resetAliases()` 的呼叫者是零

它的檔頭逐字：「⚠️ 每一次執行前要清——別名是那一份程式的，不是這個行程的」。
填表的與讀表的都在執行那一路，所以它是一張**跨程式殘留**的行程級全域表：

```
先跑   #define S second        S → second 留在表裡
再跑   struct S { int a; };    S s;  的型別被解成 second ⟹ s 變成一個 int
```

🔴 **抓到它的不是哪一支測試在紅**——是同一個檔裡 251 條一起跑會紅三條，
而每一條**單獨跑都綠**。

> **一個只在「跑過別的東西之後」才錯的缺陷，
> 單獨重現它的每一次嘗試都會告訴你它不存在。**

⚠️ 而它的回歸測試要小心：我第一版寫的那支**沒修也是綠的**
（它測的是變數名，而洩漏走的是**型別**那條路）。
📌 後來補的兩條也抓不到，所以它們標成 **★ 錨點**不是 🔴
——一支不會紅的測試與一支健康的長得一模一樣。

### ③ `>>` 對 `bool` 只收 `0` 與 `1`

`parseInputValue` 寫的是 `input === 'true' || input === '1'`——**兩處都錯**：
`true` 這個拼法要 `boolalpha`，而 `12` 不是「值為 false」，它是**讀取失敗**。
g++ 實測的表：

```
0                    false，不設 failbit
1                    true， 不設 failbit
2 / 12 / -1（是數字）  true， 設 failbit     ← 標準：「otherwise failbit，而存 true」
abc / true（非數字）   false，設 failbit
```

> **「這個值是 false」與「這一次讀取失敗了」是兩件事，
> 而把後者寫成前者，程式會照常跑完並印出一個錯的答案。**

⚠️ 語料 `AP325/1/1_11` 讀的是一整片 `bool`——**它在這一刀之前看不見**，
因為它撞在步數上限那一桶裡。把預算改成與產品一致之後它才現形。
🔴 **修一個量測工具的參數，會讓一批缺陷第一次被看見。**

### ④ 量測工具比產品嚴五倍

語料探針的步數預算寫 **2,000,000**，而產品（`execution-controller.ts` 三個進入點）
給 **10,000,000**。2M 撞上限的 15 支裡，**4 支在 10M 之下跑得完**。

> **一個量測工具如果比產品嚴，它報出來的「跑不完」
> 有一部分是它自己的帳——而那一部分看起來與缺陷一模一樣。**

⚠️ 而剩下的也不是都該記在解譯器頭上：`basic/13_while_1`／`13_while_2`
的迴圈出口是**哨兵值**（輸入 `-999`／猜中答案），而合成測資永遠給不到
——**兩邊都跑不完**，那是測資的帳。

### ⑤ 兩支測試「永遠等下去」，而那不是它們自己的錯

`sanitizerSaysUB` 用 `spawnSync`、`two-projections-behave` 用 `execSync`
——兩者的 `timeout` 都**送得出訊號而要等那個行程真的死掉**。
兩支都換成同檔已有的 `runShell`（`spawn` ＋ `detached` ＋ 計時器自己 resolve）。

🟢 從「永遠卡住」變成 **8.6 秒**與 **15.9 秒**，而 `tests/probes` 26 個檔
**今天第一次整批跑完**。

## 🔴 而這一天最貴的誤判在機器上，不在程式裡

第 201 刀收尾時，全套測試**四次被砍**，我歸因成「這台機器記憶體不足」。
而那個歸因是錯的一半——`ps` 上留著四次執行的殘骸：

```
a185_127  a16661_127  a30346_127  a71415_127     同一個編號，四次各卡一個
a185_134  a16661_134  a30346_134  a71415_134
twoproj-*/x2c ×5                                  每一次跑那支探針都留一個
```

全部 `STAT = UE`（不可中斷的等待 ＋ 正在離開），**RSS 416 bytes**
——那個行程**根本沒進到使用者程式碼**就卡住了。而同一時刻
`memory_pressure` 說記憶體 **45% 空閒**。

三條**不同的**程式路徑（非同步批次的 `a*`、消毒器的 `s*`、
`two-projections` 的 `x2c`）卡在**同一個狀態**——那不是其中任何一條的缺陷。

> **「記憶體不足」是系統送出的訊息，
> 而它與「我的批次為什麼跑不完」是兩個問題。**

⚠️ 而 `execSync` 的 `timeout` **救不了**一個卡在 `UE` 的行程：
它送得出訊號，而那個行程收不到，於是 `execSync` 一直等。

📌 診斷的判準：**一批一直失敗的時候，先問那一批裡是不是只有一個成員在失敗**
（這一天用到兩次，兩次都對）。

## 判準

- 寫「認得出 X 就……否則……」之前，**先量一次那個「否則」長什麼樣**
- 一個修好了「變數」那一格的修法，會讓其餘每一種左值看起來像是
  「還沒輪到」——而它們走的是**同一條錯的退路**
- 回歸測試寫完要**把修法關掉跑一次**：不會紅的測試與健康的長得一樣
- 量測工具的參數要與**產品**同一個數，否則它報的一部分是它自己的帳
