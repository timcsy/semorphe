# 318 · 手拖的位置掛到隔壁——一支只量「找不找得到」的護欄，量不到「找到的對不對」

> 日期：2026-11-01（第 191 刀）
> 轉變：history 316 修收合時留了一句「流程的手拖位置用同一個配對器，可能也有位移錯配」。這一刀量它、修它。

## 量到的

第八十二條護欄（`audit-layout-key`）從 2026-08-27 起量的是三種編輯之後**鑰匙還找不找得到**——它從來不問**找到的那一顆是不是同一顆**。
拿課文語料、在最前面插一行（補一個 `#include` 就是這個形狀），逐顆對照真正的對應：

```
對 1301｜掉 1163｜對到別顆 758
```

758 顆的手拖位置會掛到**隔壁的節點**上。原因：插一行之後行號鍵與路徑鍵全部位移一格，`cout`、`endl` 的內容鍵又到處重複——
最先命中的那把（行號）指到「新的那一行上的那一顆」，而那是原本上一行的那一顆。

## 修法：三層，各量一次

```
加子樹鍵（認得整塊）＋ 驗證（我的長相還在、命中的卻不一樣 ⟹ 不收）   對 1826｜掉 1051｜錯 345
加上下文鍵（父節點的子樹＋位置——分開兩個 endl）                      對 3033｜掉  168｜錯  21
子節點跟著父節點走                                                     對 3116｜掉   50｜錯  56   ← 變糟
  └ 只在父節點的子樹【一模一樣】時才跟                                 對 3222｜掉    0｜錯   0
```

第三步第一版變糟：根節點在最前面插了一行，**頂層的孩子照索引跟**就全錯開了。只有父節點內部沒變，位置才一一對應。

## 帶走的

- 第八十二條多一條**硬性零**：對到別顆＝0；掉的入棘輪（0）。
- 收合（spec 190）改用同一份子樹鍵與上下文鍵：插一行對不回 121 → 17。
- 存檔相容：舊的 `flowLayout`／`collapsed` 沒有新鑰匙，照舊配對。

> 一支量「還找得到嗎」的護欄全綠了八週——**它的判準裡沒有「找到的是誰」**，所以 758 顆錯配在它底下是綠的。
