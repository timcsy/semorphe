# 075　Arduino 先於 Python——而被否決的那一邊，代價是真的

> 日期：2026-08-17　使用者逐字：「**Arduino 先**」
> 本檔記的是**一個排序決定**，以及**被否決的那一邊的理由**
> ——`capture` 的規矩：「Rejected option → tombstone，**它是最豐富的 why**」。

## 轉變

```
old  未決——而阻斷換過一次：先是一個十分鐘的事實（已查），
     後來是「`target` 這個機制要不要先做」（比排序更大的決定）
new  🟢 阻斷解除（spec 136 做完 target 第二刀）→ 使用者拍板：**Arduino 先**
```

## 一、支持它的兩個理由

**① 第一步沒有未決。**

```
Arduino 的第一步   執行模型（持續執行 ＋ 模擬時鐘）  ❌ 不需要硬體
Python  的第一步   🔴 收錄門檻在哪——PyPI 50 萬個套件，【沒有邊界】
                   而 `Python的package怎麼收`§五 自己說還沒答
```

> **兩件事都「可以做」的時候，問的不是哪個重要，
> 是【哪一個的第一步沒有未決】。**

⚠️ 而 2026-08-17 下午那則（「不是純粹 C++」）**削弱過這個理由**：
Arduino 的第一步一度變成「一個機制」（`target`）。
🟢 **而 spec 134／136 已經把它做掉了**——差距回到「一個沒有未決，一個沒有答案」。

**② 語言那一半是量過的，不是推論的。**

```
殘差節點  0/10   🟢 十段 Arduino 全部辨識得出來，177 顆膠囊直接可用
輸出      ""×10  🔴 而一段都沒有真的執行——沒有 main，setup／loop 沒人呼叫
```

**兩件事同時成立**：膠囊確實幾乎免費，
**而執行模型是唯一「不做就什麼都做不了」的**。

## 二、🔴 而被否決的那一邊，代價是真的——不要弱化它

`vision` 階段 7 逐字寫著 Python 的角色：

> 「Python……是**驗證階段 6.5 修好的架構**，並回答膠囊格式唯一需要第二語言的
> 問題——**universal 元件是一顆膠囊還是每語言一顆**」

```
Arduino 驗的   面板／新槽／執行模型      而【不驗語言無關性】——因為它就是 C++
Python  驗的   🔴 語言無關性（P9）       四項獨立性之一
```

> ⚠️ **所以先做 Arduino 的代價是：膠囊格式的語言無關性晚一輪被驗，
> 而在那之前加的每一顆 Arduino 膠囊，都是在一個【沒被驗過的格式】上加的。**

🔴 **這一段刻意留著。** 未來若 Arduino 膠囊需要為了 Python 重做一次，
**那不是意外，是這個決定當時就標出來的價格。**

## 三、而那個「會讓其中一邊變貴的事實」被查過了

原本的阻斷是一個十分鐘的問題：**「Arduino 的 1–4 項會不會新增 `universal` 元件？」**

```
會   → 那些膠囊可能要跟著 universal 的答案重做一次
不會 → 代價小
```

**已查（2026-08-17）**：`src/components/universal/` **不存在**，
189 顆全部是 `cpp` scope，`universal-concepts.json`／`universal-blocks.json`
**都是 0 筆**。

> **答案是「不會」——而理由不是「大概不會」，是「那個 scope 是空的」。**

⚠️ 所以 §二 那個代價**被限縮了**：晚一輪被驗的是**格式**，
不是「這些膠囊會被重做」。

> **一個「先做哪個」的問題，常常不是靠比較兩邊的價值決定的，
> 是靠找出【那個會讓其中一邊變貴的事實】。**

## 四、順序與直覺相反：不從板子或接線開始

```
1  執行模型（持續執行 ＋ 模擬時鐘）        ❌ 不需硬體  🟡 中
2  腳位狀態機 ＋ pinMode／digitalWrite…    ❌           🟢 小
3  Serial——接的是【現有的主控台】          ❌           🟢 小
4  板子視圖（唯讀，顯示腳位狀態）           🟡 一張圖    🟢 小
─────────────────────────────────────────────────────────
5  接線（2D）＝ ArduinoCAD 併入            ✅           🔴 大
6  真板子（arduino-cli 上傳 ＋ 序列埠）     ✅           🔴 大
```

🔴 **1–4 全部不需要電氣求解，而那正是最貴的那一塊。**
**1–4 做完就有一個能教 Arduino 的工具了，而一塊板子都還沒接。**

⚠️ 而第 5 項的硬條件（就近性）**早就解除**（`notEncapsulated: 0`）
——**門開著，而仍然先做 1–4。**

## 五、而第 4 項的價值不只是 Arduino

板子視圖是**面板層的探針**：佈局那一格今天**沒鋪**
（`split-pane.ts` 只有左右兩個位置、`mobile-tab-bar.ts` 的 `TabId` 是型別層級寫死）。

> **不要先設計一個通用佈局，先做一個真的新視圖，讓它把需求逼出來。**
> （`experience`：**邊界現在定，介面等**——而佈局的形狀是介面。）
