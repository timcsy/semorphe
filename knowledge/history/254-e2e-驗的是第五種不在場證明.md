# 254 — 一個本機量得到的東西，在別人的課文裡是另一個數字

**2026-09-18** · 第 188 刀合併之後，CI 的 e2e 紅了一支（而單元測試 7305 支全綠）

## 讀數

```
本機 npm test           7305 綠      （含第一百一十四／一百二十八條：課文的用字）
本機 npm run test:e2e   一次都沒跑
CI                      e2e (2) 紅   cpp-advanced/08-掃描線
```

## 一、為什麼常駐護欄沒抓到它

第一百一十四條（課文的用字）與第一百二十八條（參考解答的用字）**都跑了，都綠**
——而它們綠是因為它們量的是**課文的程式碼片段與解答檔**，
而 08 那一課用到 `cpp:container_iter` 的地方在**別的位置**。

e2e 的那一條掃的是**課文整份的每一段程式碼**，母體更大。

> **兩個名字很像的檢查，差別常常不在判準，在母體。**

⚠️ 而這一刀改的正是「哪些東西會被 lift 成一顆積木」：
`sort(v.begin(), v.end())` 在此之前 `v.begin()` 是**一串文字**，
之後它是一顆 `cpp:container_iter`。**同一份課文，用到的元件變多了。**

## 二、而修它的時候當場又犯了同一個工作階段記過的錯

第一版的量測是：

```python
needs = ('.begin()' in txt) or ('.end()' in txt) or ('begin(' in txt)
```

於是 **7 課 Arduino** 被判定要補 `cpp:container_iter`——而它們寫的是
`Serial.begin(9600)`。

> **一個「這個寫法有幾處」的讀數，如果只數了寫法而沒有數它作用在什麼上，
> 那它量到的是語法不是語義。**

⚠️ 這句話**是同一個工作階段早上寫下的**（探索報告誤把 `ms.top()` 當成
「綁到使用者自己的結構」），而下午照樣犯。
🟢 抓到它的不是我，是**把那 7 課加進去之後 e2e 仍然全綠**——
一個「宣告了而用不到」的多餘宣告，今天沒有任何東西在看（那一條 2026-09-07 搬走了）。

→ 真正該補的只有 **2 課**（`07-優先佇列`／`08-掃描線`）。

## 三、判準

CLAUDE.md 那一列逐字寫著：

> 🔴 **改了「使用者按得到的東西」**（按鈕、選單、面板結構）→ `npm run test:e2e`

而這一刀改的不是按鈕——**改的是「一段程式碼會變成幾顆積木」**。
那件事會往外傳到：課文的元件宣告、工具箱、可拿性、學生找不找得到那塊積木。

🟢 **那一列要多一個觸發條件**：

```
🔴 改了【一段程式碼會被 lift 成哪些元件】 → npm run test:e2e
   （症狀不在按鈕上，在課文的元件宣告上——而它只有 e2e 的母體看得到）
```
