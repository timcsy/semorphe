# 061　兩條軸的第二條一直沒接上——而那一側顯示的是規則代號

> 日期：2026-08-14
> 觸發：階段 6.6 驗收④（訊息從一個字串改成 `rule` ＋ `params`）。
> 本檔記的是**兩個假設被推翻**，不是改了什麼（那在 `e9c4d5c`）。

## 轉變

```
old  兩個面板拿到同一個 i18n key，所以【說同一句話】
new  🔴 它們說的不是同一句話——程式碼側說的是【DIAG_MISSING_CONDITION】
```

規劃時的地面真相寫著「兩個面板查同一張表 → 同一個字串」，
而那是**讀程式碼推出來的**：

```
blockly-panel.ts:477   Blockly.Msg[d.message] || d.message
monaco-panel.ts:231    window.Blockly?.Msg?.[key] ?? key
```

兩行看起來對稱。**而 `Blockly.Msg` 是 Blockly 模組上的物件**
（`i18n/loader.ts` 的 `injectToBlocklyMsg` 寫進去的那個），
**`window.Blockly` 在打包後的 app 裡不存在**。

於是程式碼面板**一直走 fallback**，把規則代號當訊息顯示給使用者。

> **一個「查不到就回傳 key」的降級，會產出一個看起來像訊息的東西
> ——而沒有人會回報「訊息怪怪的」，因為畫面上確實有一則訊息。**

## 🔴 而它是被**驗收④的測試順序**抓到的，不是被功能抓到的

那支 e2e 要證明的是「兩個面板必須說不同的話」。而在最後那條斷言之前，
我先放了兩條「不得把規則代號當訊息」——

```
✅ 兩邊不同        ← 這一條【會通過】：「缺少條件」≠「DIAG_MISSING_CONDITION」
🔴 不得顯示代號    ← 這一條紅了
```

**如果只寫「兩邊必須不同」，它會用一個缺陷去通過。**

> **一條驗收如果只描述「差異」，一個壞掉的那一側照樣製造得出差異。**

→ 已進 `experience`。

## 第二個被推翻的假設：參數管道是不是「預留擴充」

spec 的檢查清單第三輪把這一條標成憲法疑慮（`constitution` I 簡約優先）：
現有規則都不需要參數，那為什麼要有參數？

**查證後是否定的**——`diagnostics.ts` 的 `varDeclareNames` 逐個掃
`NAME_0`／`NAME_1`／…，**每個空名字各推一則，而每一則長得一模一樣**：

```
int , , ;   →  三則，nodeId 與 message 全同
```

而積木側 `setWarningText` 是**後蓋前**的——**三個問題只看得到一個**。

> **N 個不同的問題產出 N 則無法區分的診斷，那不是「還沒做參數」，
> 是資訊在產出的當下就被丟掉了。**

⚠️ **則數不變**（仍是三則），改變的是它們從此帶著各自的位置。
所以護欄基線一個都沒動——**修的是可區分性，不是觸發**。

## 而一個身分被兩個問題共用，是同一個病的較輕版本

`DIAG_MISSING_VALUE` 同時給 `cpp_print`（沒接東西）與
`cpp_var_declare`（沒填名字）用。

> **一個身分被兩個不同的問題共用，等於承諾了它們永遠要用同一句話。**

而積木側想說「第 2 個變數還沒有名字」時就撞牆了——那句話對 `cpp_print`
毫無意義。→ 拆成 `MISSING_VAR_NAME`。

## 順帶：一個 e2e 的注入驗證跑在錯的產物上

T025 的反向驗證（把兩個面板的組法改成同一個 → e2e 必須紅）做完之後，
我 `git checkout` 還原了原始碼，**然後直接跑下一個瀏覽器檢查**
——而 preview 服務的是**注入版的 bundle**。

症狀是「兩個面板說同一句話」，而它看起來就像修正沒生效。

> **e2e 測的是 build 產物。還原原始碼不等於還原產物。**

⚠️ 而它與 `experience`「改動前後症狀相同」是同一族：
**症狀對得上一個錯誤的因果，而那個因果解釋得通。**
→ 已進 `experience`。
