# 符合性：從「宣告了、沒機制」到七筆還六筆

**日期**：2026-08-10 ｜ **交付**：第二十九條護欄 ＋ `specs/105-conformance-params`
**概念**：[執行機構](../concepts/執行機構.md) 的「宣稱 / 檢查 / 後果」表第六列

> 這一則記的是**兩個轉變**與**一個被連續推翻兩次的量法**。
> 數字在 spec 與基線裡，這裡記為什麼。

## 轉變一：符合性從詞彙表上的一個名字，變成一條會變紅的檢查

`concepts/元件.md:346` 早就給它名字：

> | 投影忠實度不變式 | **符合性** | `conformance` | （原無名） |

而它**一直沒有機制**。後果不是抽象的：

```
[](int a, int b) { return a + b; }   →   []() { return a + b; }
C(int a) {}                          →   C() {}
vector<int> v = {3, 1, 4};           →   vector<int> v;
```

**產出仍是合法的 C++**，所以沒有任何錯誤訊息——程式只是**不再是使用者寫的那一段**。
而任何一次工作區重新序列化（切語言、切風格、存檔重載）都會走那條路。

七筆裡有六筆在此之前**完全沒有訊號**。

## 轉變二：`childrenAsField`——投影的宣告詞彙多了一個

| | `dynamicRules`（既有） | **`childrenAsField`**（新） |
|---|---|---|
| 形態 | 每項一組欄位（`TYPE_{i}`／`PARAM_{i}`） | 全部擠進**一個文字欄位** |
| 例 | `u_func_def` | `c_lambda` 的 `PARAMS` |
| 代價 | 82 行 Blockly 動態積木 | 四行 JSON |

**否決了「照 `u_func_def` 複製 82 行 × 6」**——那是這階段在治的碎裂本身
（「加六顆元件應該是 N 個新宣告，不是 N 次對共用檔的編輯」）。

⚠️ 兩者**並列**而不是把後者塞進前者：兩種形態擠進一個型別，
讀的人要先判斷是哪一種。**並列比較誠實。**

### 這個取捨附了退出條件

它與「需要 parse 回結構才能用的字串，就不該是字串」有張力。處置寫進
`children-as-field.ts` 的檔頭與 `experience.md`：字串只存在於**形態層**，
語義層永遠是結構化的 `param_decl`；三個**可觀察的**升級訊號任一出現就改。

> **一個取捨若沒有寫下退出條件，它就不是取捨，是預設值。**

## 那條護欄的量法被推翻兩次，而兩次都是同一個病

| 版本 | 量什麼 | 報幾筆 | 錯在哪 |
|---|---|---|---|
| 一 | `blockDef` 的 input 名 vs 接點名 | 9 | 看不到動態積木 |
| 二 | ＋ 讀 `block-registrar.ts` 的 `appendValueInput('X')` | 9 | 動態插槽的名字與接點**是不同的詞** |
| **三** | 合成節點 → `renderToBlocklyState` → `extract` → 比對回來的子節點 | **7** | ✅ |

**兩版都在量名字對不對，而那是代理。** 符合性問的是「接點回不回得來」。
第三版**完全不比名字**——`extract` 自己會套用 `renderMapping`。

救它的是 `build-guardrail` 第 6 步要求的動作：**先在已知答案的樣本上驗過**
（`cpp:vector_declare` 必須被報、`cpp:print` 必須不被報）。
沒有那個樣本，**9 筆誤報會被當成真相寫進基線**。

→ 教訓進 `experience.md`（「用代理指標而非本體」的第二個實例，
而它在同一條護欄上連續發生兩次）。

## 兩個刻意的驗收，各自防一種假成功

| 驗收 | 防什麼 |
|---|---|
| **機制在無人宣告時必須是 no-op**（加完型別與消費點，護欄數字一筆未動） | 新機制動到了不該動的東西 |
| **第七顆忘了寫宣告必須被抓到** | 六顆各寫一行修好眼前的問題，而**下一個加元件的人不會知道要寫那一行** |

## 還開著的

1. **`cpp:vector_declare`**（剩下那一筆）——變長初始值，形狀不同，要動態積木
2. **符合性護欄的反方向**——它從**宣告**合成節點，所以「宣告漏了一個接點」看不見。
   `cpp:func_def` 正是這樣逃掉的：宣告把 `params` 寫成**屬性**，而 lift 產出**接點**。
   反方向是「**lift 實際產出的接點，宣告裡有嗎**」
3. **`cpp:func_def` 宣告與實作不一致**——會被上面那條抓到，一起做比較合理
