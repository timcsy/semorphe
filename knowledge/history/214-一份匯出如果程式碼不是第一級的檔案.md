# 一份匯出如果程式碼不是第一級的檔案，那份匯出把投影當成了真相

**日期**：2026-09-06 · **spec**：`specs/177-portable-export/`

## 轉變

```
舊  匯出 ＝ 一份 semorphe-<timestamp>.json，13 個欄位混在同一層
新  匯出 ＝ 一個容器
      <作品>.cpp                  ← 原始碼，任何編輯器打得開
      .semorphe/<作品>.cpp.json   ← 側檔（擺放、佈局、設定）
```

## 為什麼變

**那份 `.json` 只有 Semorphe 打得開。** 學生把作品寄給老師，老師打開看到的是
一堆 `{"version":18,"blocklyState":{…`——**而程式碼是裡面的一個字串欄位**。

🔴 而 P1「**唯一真實，各式投影**」的唯一真實**是程式碼**。

> **一份匯出如果程式碼不是第一級的檔案，那份匯出把投影當成了真相。**

⚠️ 而**歸屬那一半早就做完了**——`FIELD_OWNERSHIP`（2026-08-24）已經宣告了
四種歸屬（`document` / `sideCar` / `user` / `context` / `meta`）。
這一刀只是把那份宣告**投影成檔案的樣子**。

> **一份宣告如果沒有任何產物長成它說的形狀，它記的是打算，不是現況。**

## 🔴 而開刀之前先推翻了 vision 上的一句話

vision 那一項底下逐字寫著：

> 上面三條未做的驗收**共用同一個前置：真的檔案**，而它卡在
> **File System Access API 驗不到**（headless 的 e2e 叫不起 picker）。
> ⏳ **動工條件**：有一個能驗 FSA 的辦法——**不是「等有空」**。

**那句話對這一條是錯的**，而實測只花了幾分鐘：

```
匯出   Blob ＋ <a download>            storage.ts:265
匯入   <input type=file> ＋ FileReader  app-shell.ts:1939
探針   page.waitForEvent('download') → 檔名與 478 bytes 的內容都抓得到
```

**兩者都不碰 FSA。**

> **一個「三條驗收共用同一個前置」的判斷，
> 在沒有逐條驗過的時候，記的是【它們寫在一起】。**

⚠️ 另外兩條**真的**卡著（新檔案選語言要有檔案的概念；`semorphe-state`
遷成檔案要等多檔案落地）——所以那句話不是全錯，它是**把三條當成一條**。

## 界線與判準

**① 核心說「拆成哪幾個檔」，宿主說「怎麼變成一個下載」。**
`core/portable.ts` 連 `.cpp` 這三個字都沒有；壓縮（`fflate`）與
`<a download>` 都在 UI 那一側。🔴 **宿主獨立性的第四個實例**
（前三個：儲存、程式碼視圖、控制項）。

**② 副檔名跟著語言走，而反推是錯的。**
`LanguagePack` 多一格 `fileExtension`，兩個套件各宣告一次。

```
語言 → 副檔名   ✅ 副檔名是【產出的形狀】
副檔名 → 語言   🔴 `.cpp` 對得到【四個】教學語言——連唯一解都沒有
```

⚠️ 而**匯入時判斷「這是不是 zip」也不看副檔名**——看內容的前兩個位元組
（`PK`）。同一條原則。

**③ `code` 不得在容器裡出現兩次。**

> **一份資料如果在容器裡出現兩次，那個容器就有兩個真相
> ——而它們只在有人編輯過其中一份之後才會不一樣。**

**④ 側檔不在的時候，不要猜語言。**
有人在別的編輯器改過、把 `.semorphe/` 刪了 → **保留使用者現在的設定**
（那是他自己選的），只換程式碼、丟掉排版 → 自動排版。

> **不知道的時候，不要猜——用使用者已經說過的那個答案。**

## ⚠️ 兩個踩到的坑

**① e2e 用的是 build 產物**：改完直接跑 → 五支全紅，而產品是對的
（`e2e/aaa-fresh-build.spec.ts` 守的正是這個，但單檔跑時它不在）。

**② 動態建立的 `<input type=file>` 定位不到**：它沒有加進 DOM，
`locator('input[type=file]')` 等 30 秒 timeout——**看起來像匯入壞了**。
正解是攔 `filechooser` 事件。

> **一個看起來像「功能壞了」的 e2e 失敗，
> 第一個要問的是「測試找的東西存在嗎」。**
