# 110：`concept` 家族整族退場——而「改名完成了」這句話說早了兩次

**日期**：2026-08-20 ｜ **spec**：159 ｜ **前一步**：[109](109-程式碼追上名詞表而那張表早就定案了.md)

## 轉變

| | 之前 | 之後 |
|---|---|---|
| 身分鍵 | 🟢 `componentId`（spec 158 已改） | 不變 |
| **周邊命名** | 🔴 **3496 處**散在 656 個檔 | 🟢 **0** |
| 檔名 | 🔴 14 | 🟢 0 |
| 匯出符號 | 🔴 39 | 🟢 0 |
| 混血命名 | 🔴 `componentConcepts`、`componentConceptMappings` | 🟢 0 |
| 護欄擋得住的 | 🔴 只有 `\bconceptId\b`（連 `byConceptId` 都漏） | 🟢 **整個家族，硬性零** |

## 為什麼會有這一刀

spec 158 之後我回報「大改名完成」。**那是第二次說早了**——第一次是 158 自己
（它只改了四個名字），第二次是我在 158 之後的回報。

> **一條擋「四個名字」的規則，擋不住一個【家族】。**
> 而**護欄綠**讓「完成了嗎」這個問題有了一個看起來可信的答案。

翻出它的不是測試，是 2026-08-20 的知識庫逐行審查——文件裡寫著 `ConceptId[]`
而程式碼早就不是那個型別了。

## 這一刀確立的兩件事

**① 概念沒有被廢，它降了一層**（人拍板，寫在 `concepts/元件.md`）：

```
                 元件（跨域的父概念）
                ╱                  ╲
   語言域 → 概念                    硬體域 → 零件／器件
```

推論：`knowledge/concepts/` **不改名**，而護欄要放過這個路徑字面。

**② 本輪不需要存檔遷移，而那是量出來的**：`SAVED_STATE_FIELDS` 沒有任何 concept 欄位。
⚠️ 這條寫成**護欄斷言**而不是口頭聲明——存檔欄位哪天長出 concept，前提就失效。

## 代價與教訓

三條進了 [experience](../experience.md)，兩條進了 `component-rename` skill：
- 分段要按**誰驗收它**切，不是按類型（段落邊界切錯一次，整片紅）
- 「描述過去的東西」有第五類：**別處指向 `specs/` 的路徑字串**
- JSON 鍵改名走文字層正規式，`json.dumps` 會把 643 個沒事的檔一起重排


## 追記（2026-08-20 判官回合）

「3496 → 0」**還是說早了**——同一天的判官掃描又抓到兩批：

| 批 | 量 | 為什麼漏 |
|---|---|---|
| **全大寫形式**（`CONCEPT_IDENTITY`、`UNKNOWN_CONCEPT`…） | **77 處／25 檔** | 家族正規式寫成 `[Cc]oncepts?`——**`CONCEPT` 兩個都不匹配** |
| **`knowledge/skills/` 的 54 處** | 5 支 skill 指名不存在的函式 | 掃描根只有 `src`／`tests`／`e2e`，而 **skill 會照著做** |

🔴 **第一批是 spec 158「`\bconceptId\b` 擋不住 `byConceptId`」的第三次發作**
——每一次都不是「忘了修」，是**規則自己看不見那些拼法**，於是它報零。

護欄因此多了三條，各自說得出理由：
- 家族正規式加上全大寫：`/CONCEPT|[Cc]oncepts?/`
- `knowledge/skills/` 進掃描根，且用**家族**規則不是那五個指名的字
- 🪦 **墓碑豁免**：一行說「這東西已經沒了」的字，必須寫得出它的名字
  （與「宣告退場的那一行」同一個道理；整檔豁免只有兩個——`component-rename`
  本身，與 `status: superseded` 的 skill）

另修 `component-rename` skill 的 JSON 鍵允許清單：`componentId` 出現**兩次**
（spec 158 把清單裡的 `conceptId` 也改掉了），而那正是 skill 自己寫著「漏過四輪」的那一行。
