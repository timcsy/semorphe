# 180 · 版面預設落地——而一條反目標護欄擋了一顆正當的按鈕

**日期**：2026-08-26

## 起點：Stop hook 說「還沒做完」

流程視圖那一輪收尾時我自己列了兩個缺口，而 hook 逐字指出來：

```
(d) 拖 palette 建節點的【真人手勢】未驗（只驗了合成事件）
四個面板整體設計還沒動
```

**兩個都是我自己寫下的，而我停下來了。** 那個 hook 的價值就在這裡。

## 🔴 而第一個缺口不是「自動化的座標問題」——是真的缺陷

我當時寫「看起來是自動化的座標對不上，不是產品缺陷」，並且加了一句
「而『看起來是』不能拿來宣稱它對」。**後半是對的，前半是錯的。**

寫一支用 Playwright 真滑鼠的 e2e 之後，它走到了拖曳那一步而**真的沒作用**，
拒絕訊息逐字：

> 這條線接不上：那一格要的是「一件事」而你接的是「一個值」（或反過來）。

根因：`declarators` 宣告成 `"cpp:var_declare"`，而 `isBody` 對它是 `false`
（它不裝 statements），於是一顆 `cpp:var_declare`（**語句**）被判成 `wrong-kind`。

> **「這一格裝語句還是值」與「這一格要哪一種身分」是兩個問題，
> 而把它們用同一個布林回答，會讓具名的槽永遠接不上。**

→ 具名身分的槽，**種類那一關不判**（身分那一關會判）。

⚠️ 而抓到它的是**那支 e2e 的存在本身**——不是它的斷言，是「為了寫它而必須
把手勢跑完一次」。

## 版面：三個預設，而它們列的是【層】不是【面板】

路線圖驗收逐字：「桌機**佈局預設**（專注／對照／三欄）＋ 可拖分隔線；
**不做自由 docking**」。

🔴 而預設如果列面板名字，**加一個面板就要改三個預設**——那正是
[169](169-宣告的是層不是位置.md) 那一刀要消滅的形狀。

> **預設列的是「看見哪幾層」，而哪個面板在那一層是面板自己說的。**

第八十一條護欄的四條硬性零：層必須是宣告過的 · 順序不得重排（那個順序是
**理解的層次**不是偏好）· `state` 不得進編輯區 · 每個預設要有給人看的名字。

## 五個「只有開瀏覽器看得到」的缺陷

```
① flexDirection 改在【整欄】上   那一欄裡還有工具列與分頁列，它們也跟著橫排
② 狀態列還顯示上一個版面的名字   ——它【在說謊】：畫面已經三欄而它寫著對照
③ palette 壓在積木那一欄上       `position: absolute` 的參照跑到更外層去了
④ 「專注」只收了程式碼那一欄     兩個投影還並排——**「一次一層」變成「三欄少一欄」**
⑤ 收起左欄之後右欄還是原本那一半 畫面右邊留一大片空白
```

它們的共同形狀：

> **一個容器如果裝著「內容」與「操作內容的東西」，
> 改它的排列方向會把兩者一起轉過去。**

→ 給內容一個自己的容器（`projectionRow`），方向改在那上面。
⚠️ 而那一刀又逼出兩處「把東西放回去」的路徑（從手機切回桌機）要跟著改層
——**一個「放回去」的路徑，會在容器變深的那天放到錯的層**。

## 🔴 而一條反目標護欄擋了一顆正當的按鈕

`e2e/c-target.spec.ts` 有一條「選擇器沒有變多」，錨在
**狀態列的控制項 ≤ 5**。加「版面」picker（一個與目標無關的功能）時它就紅了。

那個數字混了兩件事：

```
🔴 這一刀有沒有多加一個【語言／板子】的選擇器   ← 反目標真正在問的
⚪ 狀態列總共有幾個控制項                        ← 一個會隨【任何】新功能上升的量
```

而下調它的人每一次都會做出同一個正確的判斷，**然後那個錨繼續爛**
——`build-guardrail` 那條教訓的又一個實例。

→ 改成**指名**：那三個被收攏掉的選擇器（語言／板子／教學層級）不得回到狀態列。
⚠️ 它在「有人真的把語言選擇器加回來」時仍然會紅，
**而不再因為別的功能加一顆按鈕而紅**。
