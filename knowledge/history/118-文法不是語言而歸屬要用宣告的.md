## 一、🔴 被否決的那一版：從資料夾推導

第一版設計是「從 `src/components/<scope>/` 推導語言」。**使用者當場擋下**，
理由是這個專案自己的規矩（`skills/component-rename` 第 6 步）：

> **命名慣例不是契約。** 要判斷「這顆概念是不是 X」，就宣告一個 X。

而那條規矩背後有**三次靜默災難**：`/^cpp_(\w+?)_declare$/`（型別追蹤靜靜失效）、
以身分裡有沒有冒號判斷（單步除錯完全失效）、`/_declare$/`（一整族從護欄的信號裡消失）。
**三次都不會讓測試變紅。**

⚠️ 而中途有一個**看起來像折衷**的版本：「語言套件宣告它擁有哪些 scope」。
那仍然用資料夾當接合鍵——**只是把推導往上挪了一層**。

## 二、🔴 而正確的軸不是「語言」，是「文法」——今天就已經不是一對一

```
cpp 套件   一個文法（tree-sitter-cpp）
           四個教學語言：c-beginner · cpp-beginner · cpp-competitive · arduino
```

以語言當過濾鍵，`c-beginner` 會拿不到 C++ 的 pattern。

> **語言是教學上的分類；文法是 `astNodeType` 那個字串的命名空間。**

而撞名不是意外：

> **兩個文法各自獨立命名，而它們自然會撞名——因為它們描述的是同一批
> 程式語言概念。撞名不是巧合，是必然。而 pattern 的比對鍵剛好只有那個名字。**

## 三、修的過程掀出四層，而**只有第一層是原本以為的**

| # | 哪一層 | 為什麼護欄看不到 |
|---|---|---|
| ① | pattern 沒有文法 | ← 原本以為只有這個 |
| ② | 組裝點硬編 C++ 的跳過清單 ＋ **寫死 import** C++ 的共用 pattern 檔 | 組裝點是護欄的豁免區 |
| ③ | 🔴 **手寫 lifter 完全繞過 `PatternLifter`** | 過濾器裝在 pattern 那條路上，而 `for_statement` 走另一條 |
| ④ | 🔴 `restoreState` **不走** `handleTargetChange` | 「切目標要做的事」在兩個地方各寫一次 |

> **一條繞過過濾器的路，會讓過濾器的報告變成一份【它看得到的範圍內】的報告。**

### ③ 是瀏覽器實測抓到的，而測試全綠

量測助手沒有註冊 C++ 的手寫 lifter，於是它**比產品乾淨**：
`for i in range(3)` 在瀏覽器裡仍然是 `cpp_loop_for`，而護欄說 0。

> **一個比產品乾淨的量測環境，量到的是一個不存在的系統。**

🟢 處置：助手改成照產品的路走（`registerCppLifters` 也要叫），**護欄立刻紅**。

### ④ 的症狀最兇：一片空白

存檔存的是 Python，重開之後 lifter 停在 C++ 的文法上，
**每一個節點都不匹配 → 整棵樹 `unresolved` → 畫面全空**。

> **一條「只在還原時走」的路，會安靜地漏掉每一件在另一條路上做的事。**

## 四、🟡 揭露而未修：降級積木也是全域單槽

`core/degradation-blocks.ts` 的 `declared` 是**一個值**，
於是 **Python 的降級積木是 `cpp_raw_code`**。

⚠️ **不是這一刀造成的，是這一刀讓它現形**——在此之前那些節點根本沒降級，
它們被套上了 `cpp:if`／`cpp:loop_for` 這些**看起來正常**的身分。

→ 留給下一刀（Python 基本元件）。
