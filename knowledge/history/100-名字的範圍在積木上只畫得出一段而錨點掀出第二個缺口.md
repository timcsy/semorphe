# 100 — 名字的範圍在積木上只畫得出一段，而錨點掀出第二個缺口

**日期**：2026-08-19 · **spec**：`149-var-ref-scope-dropdown` · **狀態**：完成

## 轉變

```
之前   貼上 pinMode(D1, OUTPUT) → 點開 D1 的下拉 → 只有一個 x
之後   speed（學生自己的）· HIGH LOW OUTPUT INPUT INPUT_PULLUP · D0 D1 D2 …
```

## 🔄 這條債原本的問法是錯的

`vision` 昨天把它記成「`D1` 該不該 lift 成 `cpp:pin_constant`」——**是身分問題**。
而查了執行期那側之後（`arduino-pins.ts:166` 逐字）：

> 「**一個名字的意思由誰宣告它決定。**
> → 這張表由 `cpp:var_ref` 在**查不到宣告之後**才問。」

🟢 **身分是對的**：`cpp:var_ref` 是「一個名字的參照」。

```
執行期問的範圍   宣告的變數 ∪ 串流 ∪ 環境提供的具名常數    ← 三段
下拉投影的範圍   宣告的變數                              ← 一段
```

> **同一個「範圍」，執行期看得到三段，而積木上只畫得出一段。**

**於是這一刀從「改身分」（大、要規格辯論）變成「補投影」（小）。**

## 🔴 而共用函式有十個呼叫端，只有一個是「讀」

`getWorkspaceVarOptions()` 被十處使用，而**只有 `cpp_var_ref` 是讀**；
其餘九處（`cpp_var_assign`、遞增、複合指定）是**寫入目標**——`HIGH = 5` 不合法。

> **兩個下拉長得一樣，不代表它們問的是同一個問題。**

🟢 所以新增 `getNameRefOptions()`，**只換那一顆**。

## 🔴 而 US2 的【錨點】掀出第二個缺口

US2 是「使用者自己的宣告要贏，同名只出現一次」。
寫測試時加了一個錨點：**先證明變數那一側真的也提供 `D1`**
——否則「只出現一次」可能只是因為變數那側根本沒認出它。

**錨點當場紅了。** 查下去：

```ts
} else if (isPlainDeclaration(abstractConceptOf(block.type) ?? '')) {
```

`abstractConceptOf` 的鍵是**概念身分**（`cpp:pin_attach`，冒號），
而 `block.type` 是**導出的積木型別**（`cpp_pin_attach`，底線）。

🔴 **那個分支永遠是 `false`——24 顆宣告元件一顆都沒進下拉**
（`vector`／`string`／`map`／`servo_declare`／`pin_attach`…）。

> **兩個字串都長得像識別字，而它們是兩個命名空間
> ——型別系統擋不住，因為兩邊都是 `string`。**

⚠️ **它靜默了很久**：查不到只會讓下拉少幾個名字，**不會拋錯**。
而同一個檔案裡的 `blockTypesDeclaringVariableType()` **早就是對的做法**
（走 spec registry 反查）——**正解一直躺在隔壁**。

## 注入驗證（五種，逐一確認會紅）

```
板子常數沒補進來 · 寫入目標也被汙染 · 同名沒去重 · 常數排到變數前面 · 死分支放回去
```

⚠️ 其中兩個第一版是**注入寫壞了**（一個讓建置失敗、一個沒真的改到相對順序）
——注入器現在會把「建置壞了」印成一個顯眼的字樣，不會被讀成綠的。

## 明確排除

- **套件常數**（`DHT11`／`WL_*`）——不隨板子變，列進 `cpp` 會多出 20 個名字
- **串流的名字**（`cout`／`cin`）——不是值
- **`pinConstantValue` 的 `/^A\d+$/`**——一個看名字形狀的判準，`D` 系進來後沒有對應規則。
  **這一刀不修它，也不在它上面疊新的形狀判斷。**
