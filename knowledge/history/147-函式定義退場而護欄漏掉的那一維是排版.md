## 🔴 一次 re-route：原本要做的不是這一顆

brief 選的是 `cpp_doc_comment`（看起來最小）。**動手前量了一下形狀**：

```
cpp_doc_comment   齒輪 ＋ 兩種小積木（參數／回傳），【沒有 ＋／−】
paramList         ＋／− 管數量、齒輪管形狀
```

兩者形狀不同 → **比對護欄永遠不會說一模一樣**，而 skill 明文禁止
「直接刪形狀差很多的那幾顆」。它缺的是一個**還不存在的建構子**
（齒輪驅動的欄位列）。

> **「最小」要看形狀對不對得上，不是看它有幾行。**

`cpp_func_def` 反而是直球：它的命令式**本來就在用 `registerParamMutatorBlocks`**
——與 `paramList` 同一個函式。

## 逐筆判「哪一邊對」

| 格 | 判定 | 理由 |
|---|---|---|
| 兩個型別下拉 | **命令式對** | 它們是活的；而那兩份清單**住在核心 UI 檔裡**（P9 的債）→ 這一刀把它們搬回語言套件 |
| `PARAMS` 文字欄 | **兩邊都不對** | 與呼叫積木的 `ARGS` 同一類化石 |
| 名字預設 | **命令式對**（`main`，宣告寫 `myFunc`） | 對初學者是有意義的預設 |

🟢 **而「搬回語言套件」不是順手清理**：宣告式的下拉**只拿得到宣告過的來源**，
於是它**逼著**那份清單回家。

> **一個宣告式機制最有用的副作用，是它讓東西沒地方藏。**

## 護欄這一輪漏掉兩件事，兩件都是它「沒在看」

**① 從母體裡消失。** 宣告用了 `cpp_param_types`，而比對器沒宣告那個來源
→ 積木建不起來 → **它從比對母體裡消失**：報表上既不是「一模一樣」也不是
「有差異」，**它就只是不見了**。

> **一個從母體裡消失的項目，看起來與「沒有問題」一模一樣。**

（這是 skill 第 2.5 步逐字列的四種之一：「`field_dynamic_dropdown` 沒註冊」——**第四次**。）

**② `inputsInline` 沒被比。** 命令式有 `setInputsInline(true)`，宣告漏了，
而 `shape` 只收插槽／欄位／output／接點／顏色——**護欄說一模一樣**。
症狀是每一格參數各佔一列，**測試全綠，開瀏覽器才看得到**。

> **一個維度沒有被記進 shape，它的差異就不存在——而不是不重要。**

🟢 兩件都修了：比對器宣告語言套件的來源；`shape` 補上第六維（含注入）。

## 順手補的兩條正規化與一個錨點

- **空的啞插槽不算差異**（命令式永遠建一個空的 `PARAMS_LABEL`）
  ——它使用者看不到、序列化也不留它。⚠️ 而**有欄位的那些一格都不會被吃掉**。
- **`imperativeTypes.size > 20` → `> 5`**：那個錨問的是「掃描有沒有讀到東西」，
  而它錨在「今天有幾顆」——**會在清乾淨的那天說謊**（第三十五條講的正是這個病）。
- 孤兒注入欄位 `funcDef`／`FUNDEF_INPUTS` 清掉（skill 第 4 步，這次又抓到）。
