# 188 · Arduino 要腳手架，而它逼出了「哪一塊是外框」的第六份實作

**日期**：2026-08-28
**前一步**：[187](187-鷹架要淡要固定而學生的積木要插得進去——那是同一個旗標的兩面.md)

## 轉折

使用者：「**我希望 Arduino 系列也有腳手架**」。

當時九個板子目標的 `entryShell` 都是 `'none'`——**而 `'none'` 是「沒有外框」**，
不是「Arduino 的外框」。症狀：切到 Arduino、把顯示切成「淡的」，
畫面上**什麼都不會變**。

而查下去的時候，[draft 那份鷹架宣告](../draft/retired/2026-08-28-鷹架只有有跟沒有兩個值.md)
只解了一半：**外框「長什麼樣」已經是宣告了，而「樹裡哪一塊是外框」還寫死著**。

```
外框印出來長怎樣    preamble / entryPoint / epilogue   🟢 2026-08-28 上午宣告化
樹裡哪一塊是外框    isFunctionDefinition(n) && n.properties.name === 'main'
```

> **一份宣告如果只說得出「外框印出來長怎樣」，
> 那「畫面上哪一塊是外框」就會回去寫死在消費者身上。**

## 🔴 而 Arduino 讓那個寫死錯了**兩次**

```
名字錯   Arduino 的進入點叫 setup／loop，不叫 main
數量錯   它有【兩個】——而 `=== 'main'` 這個形狀連「可以有兩個」都表達不出來
```

所以宣告多一格 `entryFunctions`（每一顆帶自己的理由，與 `ShellLine` 同一條規矩）。

## 🔴 而我只找到三處，護欄找到六處

動手前 `grep` 了一輪，判斷是「三個地方」。蓋完第八十六條之二（硬性零：
不得把外框的辨識寫死成 `main`）第一次跑——**六處**。

多出來的那三處是：

| 第幾份 | 在哪 | 它是什麼 |
|---|---|---|
| ④ | `app.ts` 的 `needsRelift` | **算完就 `void` 掉**——一份沒有人用的實作 |
| ⑤ | `sync-controller.ts` | 「這棵樹是不是 body-only」 |
| ⑥ | `components/cpp/program/generate.ts` | 同上，而它的註解**替自己辯護過** |

⑥ 的註解逐字寫著：「`'main'` 這個名字留在這裡：**「哪一個函式是進入點」
是整個程式的知識**，不是那顆函式的性質」。

> **那句話是對的，而它證明的是「這個知識不屬於元件」——
> 不是「它可以是一個字面值」。一個正確的反面論證，會讓人停在半路上。**

## ⚠️ 而第六處差一點被改壞

⑤⑥ 問的**不是**「這一塊是不是外框」，是「**外框已經生出來了嗎**」
（要不要由我把它包上去）。兩者在寫死 `main` 的世界裡碰巧是同一句話。

🔴 若直接換成「有沒有一顆叫 `setup` 的函式」：Arduino 的樹永遠有 `setup`
→ 判成「外框已經在了」→ **走 legacy 路徑 → 板子的函式庫標頭安靜地不見**。

🟢 正解是 `shellFramePresent`：外框在程式碼裡**是空的**（`entryPoint: []`）時
永遠回 `false`。Arduino 的 `setup`／`loop` 是學生寫的，外框只**認得**它們、不生它們。

> **「這一塊是外框」與「外框已經生出來了」是兩個問題，
> 而寫死成一個名字的時候它們長得一模一樣。**

## 而「隱藏」在 Arduino 上做不到

`hidden` 的作法是把外框剝掉、只留學生的語句。**兩個進入點就剝不掉**
——兩批語句攤平成一串之後分不回去。那不是「藏起來」，是**把資訊弄丟**。

> **「藏起來」的前提是還原得回來。**

所以選單上不端出它（使用者早先說過：「這也會**被你選什麼目標限制有哪些選擇**」）。
⚠️ 而**選單不端出來不等於狀態到不了**——從 C++ 的 `hidden` 切過來就會停在那裡，
於是另外加了一道 `enforceShellDepthFloor`。

## 順手清掉的

- `cppStripInMainScaffold`：**零消費者**，是 [187](187-鷹架要淡要固定而學生的積木要插得進去——那是同一個旗標的兩面.md)
  裡被使用者否決的那條路留下的殘骸。
- `tests/unit/target.test.ts` 把 `entryShell` 的值域寫死成 `['main','none']`
  ——**一個把值域寫死成清單的測試，會在第三種值出現的那天擋住它**。改成問登記處。
- 補丁器讀的是 `currentTarget.entryShell`，而使用者在選單上換外框時它不會變。
