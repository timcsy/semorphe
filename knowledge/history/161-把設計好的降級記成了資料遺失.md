# 161 · 把一次設計好的降級記成了資料遺失

**日期**：2026-08-26

## 起點

退 `cpp_initializer_list` 那一刀的瀏覽器實測裡，我貼了
`vector<int> v = {3, 1, 4};`，而積木上只出現一顆「宣告 int 變數 v」。

我照規矩用 `git stash` 回 HEAD 確認**不是這一刀造成的**（那一步是對的），
然後把它寫進 commit 訊息：

> 「🔴 順帶量到一個不是這一刀造成的**資料遺失**……整個初始值不見了。」

**那句話錯了。** 它不是遺失，是 `downgradeComponentsForLevel` 在做它該做的事。

## 量到的

```
語義樹（app 手上的）   cpp:vector_declare · cpp:array_2d_declare · cpp:initializer_list   ✅ 完整
渲染那一段（無層級）   三段都產出正確的積木型別                                          ✅ 正確
瀏覽器裡的工作區       只有 cpp_var_declare                                              ← 降級
```

`sync-controller.ts:347` 在渲染**之前**呼叫 `downgradeComponentsForLevel`，
而它連原本的身分都留著（`identityBeforeDowngrade`）。

> **P4 的原話：「這是過濾（filtering），不是簡化（simplification）
> ——語義結構始終完整。」而我看到的正是那句話的樣子。**

## 🔴 而讓我判錯的是一個「不一致」，那個不一致其實也是宣告

同一次實測裡，`int a[3] = {1, 2, 3};` **沒有**被降級，而它與
`array_2d_declare` 同樣不在 L0。於是「層級」這個假設被我自己否掉了一次。

真正的規則不是「不可見就降」，是**「不可見 ＋ 自己宣告了父概念」才降**：

```
cpp:array_declare        abstractComponent = null            → 留著
cpp:array_2d_declare     abstractComponent = cpp:var_declare → 降成它
cpp:vector_declare       abstractComponent = cpp:var_declare → 降成它
```

> **一個「有例外」的降級規則，會讓人用那個例外否掉正確的假設。**
> 而那個例外本身也是宣告的——它住在元件自己的 `abstractComponent` 裡。

## ⚠️ 而這個坑我**同一輪剛寫進 experience**

`retire-imperative-block` §5 的警告是「**環境沒釘死**：目標停在別的語言時，
整段會降級成 `raw_code`——症狀看起來像『你把它弄壞了』」。
而我在這一輪稍早把它推廣過：**層級是同一個軸**。

然後我在同一輪踩了它。

> **一條「這個東西會騙你」的教訓，擋不住它在你以為在查別的事情時騙你
> ——因為那時你不是在驗證環境，你是在驗證別的東西，而環境只是背景。**

**判準**（機械的，取代那句提醒）：在瀏覽器裡看到一個積木「少了東西」時，
先問**app 手上的語義樹裡有沒有**。有 → 那是投影在過濾，不是遺失。
一行 `walk(app.currentTree)` 就答得完，而它比 `git stash` 快也更準
——**stash 答的是「是不是我造成的」，答不了「這是不是一個缺陷」**。

## 處置

- `00dc2f8c` 的 commit 訊息含一句錯的描述，**而它沒有被 push**。
  不改寫歷史（八個 commit 疊在上面），改由這一份與後續 commit 指名更正。
- 教訓進 `experience`。
