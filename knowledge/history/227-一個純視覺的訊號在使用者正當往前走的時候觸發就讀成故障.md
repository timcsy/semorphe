# 一個純視覺的訊號，在使用者正當地往前走的時候觸發，就讀成故障

**日期**：2026-09-10
**來源**：使用者轉述學生的畫面（截圖）
**問法**：「有學生沒有切換課程，就變這樣，有什麼方式可以降低這種狀況？」

---

## 畫面上是什麼

學生釘在第 1 課〈印出一句話〉，而程式已經在宣告變數：

```cpp
int age = 16;
double height = 1.72;
char grade = 'A';
```

第 1 課的 `components` 只有三顆（`print`／`literal_string`／`endl`），
於是 `var_declare`／`var_ref`／`literal_number`／`literal_char`
**全部超出範圍 ⟹ 他自己寫的每一塊積木都被打暗**。

```
發生了什麼   六塊積木是淡的      → 看得到
為什麼       釘著第 1 課          → 沒說
怎麼辦       換課，或不選課程     → 藏在最下面那條狀態列的一格下拉裡
```

⚠️ 而**同一個問題被問過兩次**：2026-08-28 使用者自己看著畫面問過
「為何積木變這麼暗？」。那一次修的是「**不該暗的別暗**」
（`.ghost-block` 與 `.out-of-scope-block` 的子代選擇器），
這一次是「**該暗的沒說為什麼、也沒說怎麼辦**」。

> **一個純視覺的訊號，如果它在使用者【正當地往前走】的時候觸發，
> 那它讀起來不是提示，是故障。**

🔴 而學生**沒有做錯任何事**——他只是走得比課快。

---

## 🟢 「該換哪一課」是算得出來的，不是猜的

每一課都宣告了自己的 `components`。所以
「同一軌裡，最早一堂涵蓋得了你正在用的那些元件的課」
是一個**查得到的答案**。

```
被打暗的  var_declare · var_ref · literal_number · literal_char
第 2 課   涵蓋得了全部四顆   → 指向〈記住資料〉
```

新增 `core/lesson-suggest.ts`（純函式，不知道任何語言，也不碰畫面）
＋ `ui/lesson-nudge-bar.ts`（積木面板上方的一條細線）：

```
〈記住資料〉教的就是你正在用的東西（現在有 3 種積木是淡的）
                                      [換過去] [自由練習] [不用]
```

**它把三件事放在同一個地方**：發生了什麼、為什麼、怎麼辦
——而在此之前這三件事分別在畫布上、沒說、和狀態列的一格下拉裡。

---

## 三個刻意的決定

### ① 文案是指路，不是判決

「〈記住資料〉**教的就是**你正在用的東西」，而不是「你不該用這些」。
護欄裡有一條在驗那句話裡沒有「錯／不該／不能／禁止」。

### ② 不建議現在這一課，也不硬推一堂

全部涵蓋得了 → 回**最早**的那一堂（不必跳過頭）。
一堂都不沾邊 → **回 `null`**，畫面只端「自由練習」。

> **一句廢話會讓下一句真話被略過。**

### ③ 按過「不用」就不再說同一句

而**鍵是「建議換到哪一課」**，不是「按過了沒」——學生再往前走到
另一課的範圍時，那是**新的資訊**，該再問一次。

---

## ⚠️ 而 `display: flex` 差點讓它變成一條趕不走的空線

`.lesson-nudge-bar { display: flex }` 與 `[hidden] { display: none }`
**特異度相同，而後寫的贏**。少了 `.lesson-nudge-bar[hidden] { display: none }`
的症狀是：沒有話要說的時候，一條空的琥珀色細線照樣掛在積木上面。

> **一個「沒事就收起來」的元件，如果它的 `display` 比 `[hidden]` 強，
> 那它永遠不會收起來——而空著的樣子看起來像壞掉。**

實測抓到的（第一次開瀏覽器就看到那條空線）。

---

## 考慮過而沒有做的

| 做法 | 為什麼不 |
|---|---|
| 一課做完就問「下一課？」 | 降低發生率，而救不了「還沒做完就先往前探索」的學生——而那正是這一位在做的事 |
| 乾脆不要打暗 | 那個訊號本身有價值（「這一課還沒教到它」），拿掉是用一個問題換另一個 |
| 自動換課 | 與這個 app 自己的原則相衝——「下一題**問過才切**」 |
