# 052　同名不是重複的證據——一個 spec 把自己的四項砍成兩項

> 日期：2026-08-12（`specs/117`）
> 觸發：使用者說「我看 src 目錄之下除了 components 的部分還是一堆東西……
> 而且這些資料夾裡面好像也放很多重複的東西，感覺散在各個地方」

## 轉變：三個「重複」有兩個不是重複

| | 提規格時的判斷 | 查證結果 |
|---|---|---|
| `id-migrations.ts` 有兩份 | 分裂，該合併 | ❌ **防禦性分離**——兩張表的鍵長得幾乎一樣而內容完全不同，放一起會讓下一次改名腳本的誤傷面積加倍 |
| `block-input-names.ts` 有兩份 | 分裂，該合併 | ❌ **P9 的直接後果**——核心那份若要涵蓋語言積木就得 import 語言套件 |
| `types.ts` 有八份 | （沒判成重複） | ✅ 正常分層 |

**而前兩個的理由，都寫在那兩對檔案自己的檔頭裡**，各佔一整節。

> **同名不是重複的證據，它只是重複的一種可能長相。**

⚠️ 這是 `experience.md`「一個名字取得夠好，會讓人以為自己已經讀過它了」的變體
——那次是**從函式名推行為**，這次是**從檔名相同推「同一件事」**。
兩次的共同機制：**名字提供了一個足夠合理的假設，於是沒有人去讀內容。**

## 而它是 spec-kit 的 Phase 0 抓到的

若直接動手，第一個症狀會是**第三十九條護欄變紅**（核心 import 語言套件）
——而那時已經改了兩個檔。

> **一個流程的價值不在它產出的文件，在它強迫你在動手之前查證。**

⚠️ 同一輪還有第三個假設倒了：`ui/` 分層的前提是「兩個 Blockly 專屬檔」，
而 `toolbox-builder.ts` 碰 Blockly **0 次**。只剩一個檔，
而為它建目錄違反 constitution I（YAGNI）——**且理由本身站不住**：
2D 面板的正確位置是 `ui/panels/`，不會落在 `ui/` 頂層。

## 第四個假設倒在實作中，而這次是護欄抓的

spec 的 assumption 寫著 `universal.ts` 搬到 `languages/`（「與既有的
`languages/style.ts` 同層」）。搬完之後中立性護欄報：

> 「核心層直接 import 了語言套件。拔掉 C++ 之後這裡會編不過
> ——P9 的原文就是在講這件事。」

根因是那個 assumption 本身錯了：

> **一個名字裡的「通用」，說的是它不屬於任何一個語言
> ——而不是它屬於「語言」那一層。**

`universal` 正確的位置是 `core/`。**是護欄做了這個判斷，不是我。**

## 實際交付（兩項）

```
src/blocks/  →  消失
  三份凍結明表         → src/migrations/    ⚠️ git 判定 rename 100%、md5 逐字相同
  block-input-names.ts → src/core/          它住核心側是檔頭明說的（specs/057）
  universal.ts + 2 JSON → src/core/         跨語言 = core
src/views/   →  消失（假視圖併進它唯一的測試）
```

而那三支靜態掃描原本守「一個假實作沒 import Blockly」，
**改成守契約本身更強**：若 `view-host.ts` 認識 Blockly，「視圖可抽換」就是假的
——而硬體的 2D／3D 面板正是那個抽換。

## 順帶掀出的三件

**① 路徑字串出現四處，`tsc` 一處都抓不到。**
最麻煩的是護欄的 `forbidden` 陣列與注入用的 `forbiddenPaths` 常數**是兩份**，
搬家時後者落單——而症狀是「注入沒被報出」，**看起來像護欄壞了**。

**② `universal` 的兩個 JSON 今天是 `[]`。** F 完成後 177/177 都進了膠囊。

> **一個「唯一入口」在它守的東西全部搬走之後，仍然是唯一入口
> ——只是入口後面沒有東西了。**

沒有一併刪掉：搬移 spec 就只搬移。

**③ `component-discover` skill 的分層對應表過時了兩層**（judge 2026-08-12 抓到）：
路徑變了，**而那一層本身已經空了**。⚠️ skill 是**會被照著做**的，
所以它比一份過期的文件危險——已改成「新元件的家是膠囊」並把舊表降為歷史參考。
