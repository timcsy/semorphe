# 079　補量執行之後，下一步又換了一次

> 日期：2026-08-17
> 本檔記的是**同一天內第二次推翻自己的排序**——而兩次的原因是同一種：
> **量測的軸沒有涵蓋目標。**

## 轉變

```
old（三小時前，history/078）
     「🔴 而下一步變成【板子型號】，不是修 const 陣列——因為量出來的分佈是這樣說的」
new  🔴 而那個「量出來的分佈」**只量了 lift 與 round-trip**。
     補量執行：8/20 無錯、12/20 拋錯，而 **10 筆是同一個根因**：
     【套件的物件在執行期不存在】——而它與板子型號無關
```

## 一、兩個軸，而我一次只看了一個

```
雙向轉換   🟢 殘差 0.07%｜漂移 0/20        ← 使用者要的那件事，幾乎到了
執行       🔴 8/20 無錯｜12/20 拋錯        ← 而我沒量
```

⚠️ **`history/078` 的探針【刻意不執行】**，理由寫在它的檔頭：
`g++` 編不動 sketch，而 Arduino 的裁判要 `arduino-cli`。**那個理由是對的。**

🔴 **而「不與參照比對」與「完全不執行」是兩件事**——
**我們自己的直譯器跑不跑得完，不需要任何裁判。**

> **一個「因為沒有裁判所以不量」的決定，會連「它有沒有跑完」都不量
> ——而那一格不需要裁判。**

## 二、那 12 筆，10 筆是同一個根因

```
Servo myServo;                    → myServo（不是一個物件）
DHT dht(DHTPIN, DHTTYPE);         → dht
LiquidCrystal lcd(12,11,5,4,3,2); → lcd（不是一個物件）
Adafruit_SSD1306 display(...);    → display
MFRC522 mfrc522(SS_PIN, RST_PIN); → mfrc522
EEPROM / WiFi / SPI / IrReceiver  → 全域物件不存在
─────────────────────────────────────────────────
另外 2 筆                          delayMicroseconds 缺函式／String 物件
```

🔴 **而板子型號那個缺陷連被撞到的機會都沒有**：
ESP32 語料用 `const int sensorPin = 34;`，而 `arduino-pins.ts:36` 是 `MAX_PIN = 19`
——**執行在更早的地方就死了**。

> **排在後面的缺陷，在報表上與「不存在的缺陷」長得一樣。**

## 三、而 lift 那一側**全部是對的**——這件事改變了解法

```
Servo myServo;         →  cpp:var_declare{ name:'myServo', type:'Servo' }
EEPROM.write(0, 42);   →  cpp:method_call{ obj:'EEPROM', method:'write' }
```

**沒有一個新概念需要被加。** 機制也已經在了（`ctx.structs` 類別登記表），
**缺的是誰來登記**。

🔴 **所以「一個套件一顆膠囊」那條路是錯的**——
它不會讓任何東西變好，⚠️ **而它會製造身分變動，反而讓現在 0.07% 的殘差面臨風險**。

> **一個已經是對的形狀，不需要一個更專屬的名字。**

## 四、而 `provides` 的消費者又換了一次

```
最初      消費者是第 5–6 項（接線／真板子）        —— draft §三
history/076  「而板子型號比接線先需要它，且不需要硬體」
🔴 現在   補量之後看起來是【套件】
          ——`#include <Servo.h>` 那一行【就是】一份 provides 的申請書，
          而它已經在程式碼裡了，不必使用者另外選
```

⚠️ **三次都沒錯，而三次的視野不同。** 記在這裡是因為
**下一個讀 draft §三 的人會看到三個不同的「第一個消費者」**。
