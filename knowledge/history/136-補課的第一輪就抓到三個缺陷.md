# 136　補課的第一輪就抓到三個缺陷

**日期**：2026-08-23 ｜ **交付**：C++ 語法形狀的九格補完（該補進語料 9 → 0）
**前一則**：[135](135-通用桶歸零而它一路照出九個執行期的錯.md)
**觸發**：使用者——「把這些做完」（指前一則收尾時列的兩項待辦）

## 起點：九格「沒有人看過」

[133](133-第三層樣本夠不夠.md) 蓋的第五十三條有三個維度，而 C++ 那一維
一直留著九格 `該補進語料`。它們的共同點是**沒有人看過**：

> **「沒人看過」與「看過並降級」在任何數字上長得一模一樣。**

補課的方式是寫一支**同時是語料**的測試（第三十一條與第五十三條都掃
`tests/integration/*.test.ts` 裡的反引號片段），而每一段都要有真的斷言。

## 第一輪就抓到三個缺陷——而它們都在「測試全綠」底下

| 形狀 | 症狀 | 根因 |
|---|---|---|
| `int add(int a, int b = 0)` | 那一格參數**整個不見**，而主體照樣用 `b`——**產出的碼編不過** | 抬升只認 `parameter_declaration`，而帶預設值的是**另一個節點型別** |
| 同上 | `add(1)` 算出 1（真的 C++ 是 11） | 登記函式時**沒有把預設值帶過去**，呼叫端退到型別的零值 |
| `#ifdef X … #endif` | 主體與 `#endif` **產不回去**——來回一趟少了幾行 | 產生那一路只印了第一行；而積木有那個插槽、執行器也會跑它 |

⚠️ 第一個還帶出一件事：**同一個檔裡有兩份「怎麼讀一串參數」**
（`liftParamList` 與 `buildFuncDef` 裡抄的一份），而只修好其中一份時
**另一條路完全不會跟著對**。已收斂成一份。

🔴 而第二個是[135](135-通用桶歸零而它一路照出九個執行期的錯.md)那條教訓的
**第三次現形**：Python 那顆函式定義的 `execute` **兩天前就修過同一個洞**，
它的註解逐字寫著「看起來像 lift 沒認出預設值，其實是登記時掉的」。

> **同一個洞在第二個語言上不會自己好。**

## 而積木那一格也缺——第五十四條看不到它

補完抬升與產生之後，`int b = 10` 仍然**在積木來回之後消失**：
參數那一列只有型別與名字兩個欄位。

⚠️ **第五十四條（宣告的屬性，積木上有沒有一格裝它）掃不到這一格**：
它比對的是**膠囊自己宣告的屬性**，而參數的預設值是 `param_decl` 的屬性
——那是一個**結構節點**，沒有膠囊。

> **一條「每個宣告都要有位置」的護欄，看不到【沒有膠囊的那些宣告】。**

（那一格當天補上了；護欄的這個盲點記在這裡，還沒補。）

## 剩下的三個形狀：**看過並降級**

`#if`／`#elif`／`#else`／`#elifdef` 與 `union` 沒有做，而現在它們
**在語料裡被看過**：灰色方塊、原文一字不差地產得回去，測試把那件事釘住。

## 一個判定詞彙表的缺口

`pure_virtual_clause` 補不進語料——查證之後發現：**裝的這一版
tree-sitter-cpp 不產生那個節點**（`virtual void f() = 0;` 解析出來是
`field_declaration` ＋ `default_value: number_literal`）。

原本的四個原因沒有一個說得出這件事，於是加了第五個：
**`文法宣告了而這個版本不產生`**。

> **文法的宣告與文法的產出不是同一件事——而全集是從宣告來的。**

## 收在哪裡

```
第五十三條  C++ 該補進語料 9 → 0（三個維度全部歸零）
新測試      cpp-shape-coverage.test.ts（7 條，同時是語料）
```

⚠️ 最後留下的具名邊界只剩一個：**預設值是一個呼叫時**
（`def f(x=g())`／`void f(int n = g())`）執行期出聲。兩個語言的訊息
都改成說得出修法，而**結構上的正解**（預設值當成接點而不是字串）
沒有做——理由是積木那一列今天放不下一個插槽（`paramList` 只生欄位），
而硬做會讓常見情形（打一個 `0`）變難。**那是一個決定，不是一個遺漏。**
