# 155 · e2e 驗的是「使用者按得到的東西還在不在」——而它紅了一整天

> 2026-08-25。**慣例的改變**：`CLAUDE.md` 的指令表多一列。

## 一、發生了什麼

一天之內改了六刀 UI（控制項離開面板、網頁版狀態列、流程進 editor、
行動版、主控台→終端機、行動選單）。每一刀都跑了 `npm test`（5600+ 綠）
**＋ 開瀏覽器實測**。而 `npm run test:e2e` **一次都沒跑**。

CI 的 e2e **19 紅**，從當天 00:20 起：

```
15 支  在等 `程式碼→積木`     ← 同步那一刀刪掉的方向按鈕
 3 支  在等 `積木→程式碼`
 4 支  在 select.topic-dropdown 上 selectOption  ← 那幾顆下拉退場了
 1 支  數 .toolbar-select
```

**是使用者發現的。**

## 二、為什麼前面兩層都擋不住

> **`npm test` 驗的是「這些函式做對了嗎」；
> e2e 驗的是「**使用者按得到的東西還在不在**」。
> 而這一天做的每一刀，改的正好都是後者。**

⚠️ 而「開瀏覽器實測」也擋不住——**實測的是剛做的那條路，
不是那些沒有人再去看的舊路**。e2e 在按的是三天前的按鈕。

## 三、轉變

`CLAUDE.md` 的「什麼時候跑什麼」原本只有四列，e2e 屬於「PR 才跑」。
現在多一列：

```
🔴 改了「使用者按得到的東西」（按鈕、選單、面板結構） → npm run test:e2e
```

⚠️ 而同一天又犯了一次變體：兩顆 commit 寫著「這一顆沒跑全套與 e2e」，
然後 CI 紅了兩條棘輪。

> **那句話的正確用法是當作待辦，不是當作免責。**

## 四、順帶讓 e2e 變得比較不脆

新的 QuickPick 的每一列帶 `data-value`——**標籤會隨語系換，值不會**。
在此之前 e2e 只能用中文標籤配對，而那是一個會隨翻譯壞掉的測試。
