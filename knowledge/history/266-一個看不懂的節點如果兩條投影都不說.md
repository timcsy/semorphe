# 一個「看不懂」的節點，如果兩條投影都不說，那它就不是降級

2026-09-20｜第 203 刀（巨集體不是一個值的物件形巨集）

## 一句話

> **一個「這一段我看不懂」的節點，如果兩條投影都不說，
> 那它就不是降級，是一個錯的答案。**

## 事情

語料 `w/APCS/j607_trash` 的第一行是 `#define z -'0'`，用法是 `x = x*10+(s[i]z)`。

`cpp:define` 那條路把物件形巨集記進**別名表**（名字 → 名字），而 `-'0'`
**不是一個名字**，它是一段運算子片段。於是那個位置解不出來：

```
parenthesized_expression ⚠hasError
  subscript_expression  «s[0]»
  ERROR ⚠hasError       «z»
```

而在這一刀之前**兩條投影都錯，而兩條都不出聲**：

```
執行    (s[0]z) 算成 52（把 z 整個忽略）   🔴 錯，而且不出聲
產回去  (s[0]z) → (s[0])                  🔴 z 靜默消失
```

## 為什麼「代入」在這裡不是一個猜測

`ast-repairs.ts` 的契約②逐字：「**只准做『這段文字唯一合法的讀法就是這個』
的重寫**」。而**把一個已定義的物件形巨集換成它的展開文字，正是這個語言
定義的那一步**——不是我對它的理解。

⚠️ 而 repo 對別名的立場（「一個別名的意義就是那個短名字；把它換掉等於把它
拿掉」）**仍然成立**——所以**樹上代入、產出照抄原文**。

🟢 而「照抄原文」的機制**本來就在**：`generateExpression` 的第一個分支
（`layoutHints.verbatim` ＋ `metadata.rawCode`，`"abc" "def"` 那條線在用）。

## 三個踩到的坑，而三個都是「同一件事只做了一半」

### ① 判準第一版太窄——ERROR 蓋在哪裡不由我決定

第一版的判準是「`ERROR` 節點的文字剛好是一個已知的巨集名」。而實測：

```
(s[0]z)     ERROR «z»     ← 蓋在巨集名上
(a plus1)   ERROR «a»     ← 蓋在【前面那個識別字】上，而巨集名是它的兄弟
```

> **照 `ERROR` 蓋在哪裡去認形狀，等於把解析器挑錯誤位置的方式當成規格。**

🟢 換成「代入之後解得乾淨才接手」——判準從**錯誤的位置**移到**代入的結果**。

### ② 「照抄原文」只在運算式那一路生效

`x = x*10+(s[i]z);` 是一個**語句**，而 `generateNode`（語句那一路）
**不讀** `layoutHints.verbatim`。症狀不是「產出錯了」，是**語義不動點破掉**：

```
第一趟   走修復那條路   → 重解 → 查不到型別 → cpp:array_at
產回去   展開後的樣子（因為 verbatim 沒生效）
第二趟   走一般路                        → cpp:string_at
```

> **一個只在其中一條投影上生效的「照抄原文」，
> 會讓那兩條投影對同一段程式給出兩棵不同的樹。**

### ③ 重解出來的那棵樹少了型別上下文——**第二次踩到**

`isStringVar` 是**往 AST 上面走**找宣告的，而重解出來的樹裡只有那一段
——`string s;` 不在上面。

🔴 症狀有兩個，而**第二個比較貴**：不動點破掉，以及**學生看到錯的積木**
（`cpp:array_at` 與 `cpp:string_at` 是兩塊不同的積木）。

🟢 處置：先問型別表（`ctx.data` 跨那棵重解的樹活著），查不到才走 AST。
`lift-context.ts` 的檔頭逐字：「**一個查得到的東西查兩次，比替它開第二張表便宜。**」

⚠️ 第 201 刀已經記過這個形狀一次（那次少的是**巨集表**，修法是把它帶過去）。
這一次少的是**宣告**，而宣告帶不過去（它在別的節點上）——所以換成查表。

> **「重解出來的樹少了原本那棵的上下文」不是一個缺陷，是這個機制的性質。
> 每加一個消費者就要問一次：它靠的那一塊，在新的樹上還在不在。**

## 量到的

```
內容真的不同  3 → 2      一致 162 → 163      同一棵 218／走樣 0
```

🟢 而**剩下的兩支都不是缺陷**：
`basic/2_material`（`sizeof(long double)` 本機 8／CI 16，平台相依）·
`basic/6_count`（`rand()` 的序列標準不規定）。

## 判準

- 一個節點「看不懂」的時候，**兩條投影都要說**——只有一條說的話，另一條就是謊話
- 加一條樹修復之前，先問「這段重寫**寫在標準裡**嗎」；寫在裡面的不是猜測
- 判準不要綁在**解析器挑錯誤位置的方式**上，綁在**重寫之後解不解得乾淨**
- 每加一個「重解一段文字」的消費者，問一次**它靠的上下文在新的樹上還在不在**
