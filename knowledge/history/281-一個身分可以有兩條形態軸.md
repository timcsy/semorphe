# 281 — 一個身分可以有兩條形態軸

**2026-09-21** · 第 219 刀 · 分支 `219-multi-axis-forms`

[279](279-宣告說得出而形態沒做的那八顆.md) 把第一百二十六條護欄的棘輪從
**8 補到 1**，而剩下那一顆的墓碑寫著：

> 🪦 **`cpp:container_push` 做不到**：`buildFormSets` 一個元件只支援一條軸，
> 而它已經用了 `container_kind`（stack／queue）。

使用者這一刀給的指示是一句話：「**先讓 `buildFormSets` 支援多軸**」。

## ① 攔住它的是那一行

```ts
const cur = variant.get(d.componentId) ?? { axis: d.form.axis, values: {} }
cur.values[d.form.value] = d.blockType
```

`axis` 取自**第一筆**變體宣告，而之後不再更新；後面每一條軸的值都倒進
同一個 `values`。所以 `cpp:container_push` 加上 `role: expression` 之後，
形態表長這樣：

```
container_kind → { stack: …, queue: …, expression: … }
                                       ^^^^^^^^^^ 永遠選不到
```

渲染在運算式位置時問的是 `ctx.position`，而這張表的軸是 `container_kind`
⟹ 挑不到形態 ⟹ 退成灰色逃生艙。**沒有任何檢查看得見它**：形態集合是
自洽的，`validateFormSet` 的每一條都過。

> **一個「只記得第一個」的欄位，在第二個出現的那天不會報錯
> ——它會安靜地把第二個當成第一個的一部分。**

## ② 修在哪一層

```
FormSet.axis: FormAxis | null   →   FormSet.axes: FormAxis[]
forms 的鍵：「軸值」             →   「軸名:軸值」（兩條軸可能有同名的值）
                                +   FormAxis.priority
```

`selectForm` 依 `priority` 依序問，**第一個問得出形態的贏**：

```
role            priority 1   決定「放不放得進那個插槽」
container_kind  priority 2   只換標籤
```

> **兩條軸都說得上話的時候，先聽那條決定「放不放得進去」的
> ——標籤說錯是讀起來怪，插槽不合是根本畫不出來。**

⚠️ **降級的條件也跟著改**：原本是「取得到值而沒宣告 → 降級」。
多軸之下**一條軸取不到值是合法狀態**（CK-1：辨識不出型別時刻意不寫該屬性），
所以只有**每一條軸都取得到值、而每一條都沒宣告**才降級。

## ③ 刻意不做笛卡兒積

`stack × expression` 那種組合形態要宣告 6 顆積木，而其中大部分不會有人用
（憲章 I，簡約優先）。代價說在明處：

```
一顆【堆疊】的 push 出現在運算式位置 → 用一般的運算式形態
                                       標籤是中性的「放進」而不是「推入堆疊」
```

**軸的順序就是為了讓那顆組合形態不必存在。**

## ④ 而重產圖的時候，另一格自己回來了

逐段圖棘輪 **13 → 12**，回來的是 `cpp-beginner__12-猜數字__step6`：


而那一刀**沒有重產圖**——所以這一格在帳上多掛了一天。

> **一個修好了的缺陷，在它的產物重產之前，讀數上與沒修一模一樣。**

⚠️ 與 2026-09-05 那次（課文對照圖過期）**不同族**：那次是「產它的那台機器變了」，

而過期的產物是自洽的。
