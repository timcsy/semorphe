# 343 · 錯誤訊息從「說得出有錯」到「看得懂、改得動」

> 日期：2026-11-05～06
> 轉變：341 拿掉 Cella 的原文之後，最常見的編譯錯誤只剩「這一句不合語言的規則」；多數文案只有一個名詞片語，沒說為什麼、怎麼改，也沒用上手上的名字、行號、數值。
> 改成：每一則**指名**（程式碼與行號）、**帶值**（索引、大小、溢位的運算元、步數）、**三層**（一句話；點開看「為什麼／試試看」）；寫程式時的標示與執行停下**同一種說法**；條號收進**詳細資訊**；一頁**例句清單**給人看全貌。
> 決定：使用者 2026-11-05「我覺得現在的錯誤訊息還做得不夠好」→ 推薦的做法；兩題（要不要三層、積木上那一句多長）使用者回「好這樣」（照推薦 A）。其餘照推薦。
> 設計脈絡：[draft/錯誤訊息還不夠好](../draft/retired/2026-11-05-錯誤訊息還不夠好.md)（已退場）。例句：[assets/error-messages/例句.md](../../assets/error-messages/例句.md)。

## 做了什麼（照順序）

1. **指名**：判決指到的那一顆的程式碼與行號放進文案（「「total」還沒有值就拿來用了」）；Cella 指的是左手邊（`/lhs`）時只取等號左邊。
2. **編譯錯誤細分**：Cella 0546 起把 `reject` 細分成六類（不能被指定、引數不合、重複宣告、回傳值、運算元型別、不能轉換），各有中文。
3. **一種說法**：執行停下＝「停在這裡：」＋積木側那一句＋出處（護欄 `audit-one-voice`）；英文五種原本全部不一致。
4. **收起連帶的**：量過、**沒做**——Cella 判編譯錯誤只回報第一則，問題六在 JS 直譯器的年代是真的、換成 Cella 之後不在了；留觸發線。
5. **條號收進詳細資訊**：Monaco 的 hover、VSCode Problems 的 `code`。
6. **例句清單頁**：15 種錯誤各一支最小程式、真的 Cella、產品同一條路；平常比對、看過才重產。**第一次產生就抓到三個護欄量不到的缺陷**（下一節）。
7. **三層**：37 條規則有「為什麼／試試看」；剩 3 條是系統那一側的（invalid、unclassified、other）——不是學生的錯，刻意不寫。
8. **帶值**：Cella 1127 起執行期的問題帶值；「「a[3]」的索引是 3，最後一格是 2（只有 3 格）」。

## 例句清單頁抓到的

- `a + b = 3` 被判「沒問題」——tree-sitter 解成 `a + (b = 3)`（合法），整串交給 Cella 就過了（P6）⟹ 剖析修正第四條。
- 修正過的節點帶著重解那個殼的座標——訊息說「第 1 行」，實際第 3 行；四條修正都有。
- 步數用盡那一則，狀態列的說明是「對不到積木：fuel（step limit reached）」——內部代號加英文原文。

## 估計與實際

- 沒有事先估計（〈錯誤訊息看得懂〉排進路線圖時沒有寫時程）。實際：2026-11-05 下午到 11-06 凌晨，約 12 小時、八刀（其中約 3 小時是長測試空等：一次自我鎖死、一次 Cella 整夜在測）。

## 還開著的

- 第一層沒有指名或帶值的規則 16 條（棘輪 `audit-diagnostic-layers` 數著，只准下降——幾條本來就沒有東西可指）。
- 未初始化、空指標等的變數名 Cella 不帶（停下的地方只知道位址）——`at` 指的運算式就是名字的來源。
- 越界的指名在 Cella 指整句時，靠 `/lhs` 只取等號左邊；指的是右邊時仍是整個運算式。
