# 078　量完之後，階段 6.12 的前提垮了一半

> 日期：2026-08-17（`component-fuzz`，20 段**典型的** Arduino 程式）
> 本檔記的是**第 1 步（量）的結果推翻了第 2 步與第 4 步的理由**
> ——而那正是「先量再做」買到的東西。

## 轉變

```
old  階段 6.12 的順序：量 → 修 const 陣列 → 板子型號 → 收套件
     而第 2 步的理由是「`const byte PINS[3] = {9,10,11};` 是 Arduino 教材的招牌寫法」
new  🔴 實測：`const`／`static` 陣列在 20 段真實程式裡出現 **0 次**
     🔴 而 11 種套件的呼叫【全部辨識得出來】——第 4 步可能不需要
```

## 一、數字

```
語料       20 段（出題者跑在隔離 worktree）｜語法完整 20／片段 0
           板子：Uno 14｜Nano 3｜ESP32 3　　套件 11 種
殘差       1 / 1516 節點 = 0.07%
round-trip 樹漂移 0/20　文字漂移 0/20
```

**學生或 AI 寫的典型 Arduino 程式，貼進來幾乎完全轉得動。**

## 二、⚠️ 而它與前一份報表的「7/20」不矛盾

```
fuzz-cpp-hardware  難度 hard ＋「刻意的陷阱」  → 問「極限在哪」   執行通過 7/20
本輪                典型的、AI 會寫的           → 問「日常會不會壞」殘差 0.07%
```

> **同一個系統，兩個數字，而它們沒有矛盾——因為問的是兩件事。**

🔴 **而我在 `history/077` 寫下的優先序是從錯的那個母體推出來的**：

> 「`const byte PINS[3] = {9,10,11};` 是 Arduino 教材的招牌寫法」

**那句話沒有被真實語料支持。**

> **一個從「刻意找邊界」的語料得出的優先序，會把邊界誤認成中心。**

⚠️ 這**不代表**那 6 筆不用修——它們仍然是真的缺口，
**只是它們不該排在最前面**。

## 三、🔴 而套件那一步的理由也要重看

11 種套件（`Servo`／`LiquidCrystal_I2C`／`DHT`／`Wire`／`SPI`／`EEPROM`／
`IRremote`／`MFRC522`／`WiFi`／`HTTPClient`／`Adafruit_*`）的呼叫**全部辨識得出來**。

**為什麼**：套件的**語法**不特別——它們就是一般的方法呼叫與物件宣告。
特別的是**語義**（`Servo::write` 會轉動一個馬達）。

> **而雙向轉換不需要語義。**

⚠️ 所以「收套件」這一步的內容要重新定義：
它**不是**「讓程式碼轉得動」（已經動了），而是
**「讓積木好懂」**（`concepts/投影.md` 的那條判準）與**「執行時有意義」**（虛擬硬體）。
🔴 **而後者正是使用者這一輪往後推的東西。**

## 四、而修掉的那一個，是我上一輪只修了一半的

```
原始     dht.begin();  lcd.init();
一次產出  "dht.begin()    lcd.init();"      🔴 沒有分號，兩句黏在一起
二次產出  "    dht.begin().init();"         🔴 而第二次把它們合併成方法鏈
```

根因兩層。① `cpp:container_iter` 認走**所有零引數的 `.begin()`**
——而**每個 Arduino 套件都有 `begin()`**，⚠️ 而我上一輪只為 `Serial` 加了 obj 感知的分支。

🔴 ② **而下面這層更基本**：**運算式節點在語句位置，產出沒有分號也沒有換行**
——任何誤判都會產生黏在一起的無效程式碼。

> **一次誤判本來只是「身分不對」，而少了那一層它會變成【產出無效程式碼】
> ——而無效的程式碼在下一次 lift 時會被讀成【另一個意思】。**

**修的是第 2 層。** 第 1 層沒修——沒有型別資訊時 `x.begin()` 真的有歧義。

## 五、⚠️ 而修法試了三版，前兩版都動到了量測工具

```
一版  「產出沒有換行結尾 ⟹ 它是運算式」   🔴 猜的，而且錯——do-while 是語句而它也沒換行
二版  改成問宣告（component.json 的 role） 🔴 完備性護欄的 9 筆判定翻掉：
                                          它把合成節點包進【沒有 int main 的】program，
                                          而在那裡 `-5` 與 `-5;` 都不合法
三版  只在【縮排大於零】時作用             🟢 也就是函式體裡面
```

> **兩種都是壞的合成環境；改動只是換了它壞的方式，而那讓它現形。**

而完備性護欄的檔頭記著「**量測工具的改動也會讓量測變差，而那一樣要被發現**」
——所以**沒有動它**。
