# 313 · 收合第一次有了消費者——流程面板收成一個有埠的框

> 日期：2026-11-01（spec 187，vision〈分子：組合階層與粒度切換〉第 4 格）
> 轉變：`core/molecule.ts`（第 254 刀）與 `core/granularity.ts`（第 257 刀）從 2026-09-26 起就在，**零消費者**。
> 這一刀讓流程面板第一個投影它們：右鍵「收合這一塊」→ 那顆連同整個子樹變成一個虛線框（「收著 N 塊」），只留對外接點。

## 狀態放在哪——量過的那個坑決定的

收合狀態**不是面板私有的**（使用者 2026-09-26：「B 對於階層式元件系統應該是一個重要功能」——收合是「在哪一個粒度看」，屬於真實那一側）。
所以它走匯流排：

```
視圖  ──granularity:request {nodeId, collapsed}──▶  持有者（connectGranularity）
持有者 ──granularity:collapsed {entries: 鑰匙}──▶  每個視圖各自 resolveCollapsed 對回自己那棵樹
```

🔴 **廣播的是鑰匙，不是 `nodeId`**：`nodeId` 每次重新解析都換（`layout-key.ts` 檔頭，2026-08-27 實測 id 相同 0）。
用 id 記的症狀會是「收起來、在程式碼打一個字、全部展開」——手拖位置那個缺陷的第二次。
持有者每次 `semantic:update` 都把鑰匙換成新樹的再廣播一次，所以連改幾次鑰匙也不會與樹漸行漸遠。

⚠️ 持有者要在 `connectViews` **之前**接：同一次 `semantic:update`，它先換好鑰匙，視圖隨後用新鑰匙對回。

## 框的接點與「切斷的邊」

收一整個子樹，`boundaryOf` 只有一個 `in`、零個 `out`，而它等於**獨立算的** `crossingEdges`——框因此只留那顆原本的對外接點
（語句：`__in__`／`__next__`；運算式：`__out__`）。資料輸入與身體接點都在框裡。

## 刻意沒做的

- **不進存檔**：重開後不還原（鑰匙格式已備好，`collapsedToKeys`）——不讓這一刀動存檔格式。
- **積木／程式碼的投影**：它們訂閱同一個 `granularity:collapsed`（`ViewHost.onGranularity` 是可選的），下一格。
- **多選**：`boundaryOf` 單選（一顆連子樹）就夠；多選要 Blockly 插件、會撞中鍵平移的手勢。

## 驗證

e2e `flow-collapse`（vision 原文「今天 e2e 測過收合的條數是 0」——這是第一條）：收合 → 改一個不相干的值仍收著 → 展開回到原樣、程式碼一字不差。
