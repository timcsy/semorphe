## 🔴 第一課撞到的第一件事，是產品的核心宣稱

```
打上 int main() { return 0; }  → 按同步 → 積木數 = 0
再加一行 cout                   → 積木 = [print, literal_string, endl]
                                  🔴 沒有 main、沒有 return
```

積木側**只呈現語句，骨架不呈現**——那是刻意的設計。
⚠️ **而它讓「同一個程式的兩種樣子」在第一課的第一步就不完全成立。**

> **第一課撞到最核心的宣稱，不是巧合——第一課本來就會撞到最基本的東西。**

**處置**：`main` 不當第一個概念教，改成「先照抄的骨架」，
「兩種樣子」延到第二步（那時積木真的出現）。

## 而走一遍【沒有】暴露面板需求——那本身是資訊

設計時猜的兩點（「一課的單位是指節點」「目標檢查用輸出」），
**第一課一條都用不上**。走一次只暴露了**說明的缺陷**。

使用者走完之後的逐字回饋：
> 「我走過一遍了，**OK**，不過如果可以有**圖片支援**更好，
> 或是到時候如果直接跟 UI 結合，可能可以**直接用指的**」

```
「OK」        ✅ 一次都沒有真正卡住
圖片支援      增益，而【本檔八節一次都沒預測到】
直接用指的    增益 ＋ 未來式，而它命中了那個【被標為猜測】的設計
```

🔴 **兩個回饋都是「更好」，不是「走不下去」**——所以它們**不構成**
「該做教材面板了」的證據。

## 圖片的過時問題：答案是「不要用截的」

```
UI 截圖      🔴 隨介面改版過時   → 讓端對端走查【順手產生】
概念示意圖   🟢 不隨介面過時     → 手畫（它畫的是領域，不是工具）
```

🟢 副作用比圖片本身值錢 → `e2e/lesson-01.spec.ts`（spec `125`）。
⚠️ 而**就算永遠不加圖片那支測試都該在**——寫完第一課時有過一支，**然後被刪了**。

## 探針：九種第一課學生會犯的錯

🟢 **七種擋得住**——含**全形分號／全形引號／全形括號**（中文使用者最常犯，
而這個專案在此之前一次都沒測過）。

🔴 **兩種放行，而學生看到的是原始代號**：`Cout` 大小寫錯、`<<` 寫成 `<`
→ `RUNTIME_ERR_UNDECLARED_VAR: {"%1":"Cout"}`。

而護欄沒接住的理由比「漏了一族」更深：
```
護欄量的   文案【在不在】       ✅ 在 blocks.json:134
缺陷是     顯示端【有沒有查】    🔴 broadcastOutput 從來不查
```
⚠️ 那與「機制有了沒人接上」是同一個病的**第四次**。
