# 019：跨語言抽象層，從「假定可用」到「實測 75% 指向不存在的東西」

> 日期：2026-08-06

## 轉移

- **舊**：每個概念可以宣告它的語言中立父概念，那是跨語言映射的地基。路線圖把「跨語言映射視圖（`abstractConcept` 驅動）」列為長期方向，**預設那個地基是在的**。
- **新**：**131 個宣告裡有 98 個（75%）指向根本不存在的概念。** 而且處置之後才看清楚更根本的一件事——**68 個概念在目前的通用概念集裡真的沒有對應物**。抽象層不只是壞的，它**比預期小得多**。

## 為什麼變

因為第一次去檢查那些指標指得到東西。

查詢父概念的函式長這樣：

```
findAbstract(id) {
  if (!concrete?.abstractConcept) return undefined   // 沒有宣告
  return this.concepts.get(concrete.abstractConcept) // 指不到 → 也是 undefined
}
```

**「沒有宣告」與「宣告了但指不到」回傳同一個值。** 所以一個四分之三是破的抽象層，看起來像「大部分概念還沒填父概念」——而後者是完全可以接受的狀態。

那些指向的名字（`map_declare`、`string_declare`、`pointer_declare`……）是**當初想建但沒建的**語言中立層。它們被寫進宣告，然後就停在那裡。

## 處置與它揭露的事

| 處置 | 數量 | 說明 |
|---|---|---|
| 改指向真實存在的父概念 | 30 | `*_declare` → `var_declare`、`printf` → `print`、`method_call` → `func_call` 等 |
| **移除宣告** | 68 | 前處理器、物件導向、各種轉型、字串函式——**目前的通用概念集裡真的沒有對應物** |

**明確拒絕的做法**：把那 98 個目標名都建成概念。那會產生一批五路皆空的殼——用一個病換另一個病。

而 68 這個數字才是真正的訊息：**通用概念只有 27 個**，而 C++ 語言套件有 149 個概念。抽象層原本被寫得像是「大部分東西都有語言中立版本」，實測是**大部分沒有**。

## 對路線圖的影響

- **Phase 7（Python）不能假設抽象層會自動對上。** 第二個語言進來時，`cpp_lambda` 與 Python 的 lambda 要不要共用一個抽象概念，是**那時才會有答案**的問題——而那正是 Phase 7 該回答的東西之一，不是它可以依賴的前提。
- **「跨語言映射視圖」（階段 9.4）的地基現在是誠實的**：63 個宣告，全部指得到。它比原本以為的小，但那 63 個是真的。
- **介面層兩份寫死清單的成因也在這裡**：抽象層指不到東西，所以介面層只好自己寫一份「這些概念是變數宣告」的對照表。修好抽象層之後才拆得掉。
