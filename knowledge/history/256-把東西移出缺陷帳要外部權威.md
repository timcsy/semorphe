# 256 — 把東西移出缺陷帳，要的是外部權威

> 2026-09-19｜語料的「解譯器出錯 26 支」裡，有 5 支不是缺陷

## 發生什麼

語料庫 218 支學生程式，量到「解譯器出錯 26 支」。逐支看的時候
`AP325/7/` 有五支長得一模一樣：

```cpp
int n; cin >> n;
vector<S> A[n];              // ← 長度由輸入決定
int u,v,w;
for (int i=0;i<m;i++) { cin >> u >> v >> w; A[u].push_back({v,w}); }
```

而測資產生器給的 `u` 是 `1 + rnd(20)`，`n` 是 `3 + rnd(6)`。於是 `A[12]`。
**g++ 不檢查所以照跑，我們檢查所以出聲。**

那不是「我們錯了」，也不是「我們對了」——**是那份測資讓那支程式沒有定義的行為**。

## ⚠️ 直覺的修法量過了，而它是一場等價交換

「之後的整數以第一個整數為上界」（競賽題「讀 n 再讀 n 筆」的慣例）。

```
原本的測資      44 支出錯
上界版測資      43 支出錯
  修好了        AP325/7 那四支
  換來了        10_a277 爆堆疊 · 8_toj8／a005 除以零（rnd(bound) 會生 0）· 7_11 負索引
```

> **一個改「測資怎麼生」的改動，如果換掉的支數與修好的支數差不多，
> 它量到的是測資的形狀，不是缺陷的分佈。**

## 🔴 真正的問題不是「怎麼生測資」，是「誰有資格說這不算缺陷」

使用者說過：「語料只是參考，實際 fuzz 錯了就是錯了，**不要迴避**」。

而「這五支是測資的問題」這句話，如果是**我**說的，它與迴避長得一模一樣
——兩者都是「一個做這件事的人，宣布自己不必做這件事」。

🟢 **處方：換一個說話的人。**

```bash
g++ -std=c++17 -fsanitize=address,undefined -g -o bin prog.cpp && ./bin < same-stdin
```

```
runtime error: index 11 out of bounds for type 'vector<S>[n]'
ERROR: AddressSanitizer: stack-buffer-overflow …
```

**UndefinedBehaviorSanitizer 指名了那一行。** 我沒有份量，它有。

> **一個把東西移出缺陷帳的判定，它的效力全在【說話的人不是被告】。**

## ⚠️ 而它只能證實，不能否證

消毒器抓不到未初始化的讀取、抓不到全域陣列的小幅越界、抓不到邏輯錯誤。
所以**回「沒有 UB」的那些仍然算我們的帳**——這一條寫死在 `sanitizerSaysUB` 的檔頭，
因為反過來用（「消毒器沒叫所以我們對了」）會讓這支助手變成一台漂白機。

## 🔴 而這支助手自己差點漏掉一半

第一版用 `execFileSync`，只在**它丟例外的時候**讀 stderr。
而 UBSan 預設**會讓程式繼續跑並且正常退出**（不是 `-fno-sanitize-recover`）
——那一路 `execFileSync` 不丟例外，於是那段 `runtime error:` 被丟掉。
只有 AddressSanitizer 那半會死。

```
會死的那半     ASan（越界寫、use-after-free）      🟢 抓得到
不會死的那半   UBSan（有號溢位、移位過大、越界索引） 🔴 第一版完全看不到
```

> **一個只在「它失敗了」那一路讀 stderr 的偵測器，
> 對「它成功了而且順便印出違規」保持沉默。**

而那一半正好是語料裡最常見的一半（5 支裡有 4 支是純 UBSan）。
改成 `spawnSync` 之後才看得到。

🟢 **而它沒有靜默通過，是因為錨點釘在判定之前**：第一百二十二條護欄
`audit-sanitizer-verdict` 的正向錨點②逐字是「有號整數溢位（純 UBSan，程式不會死）」。

## 讀數

```
              之前   之後
解譯器出錯     26     21
測資走進 UB    —       5   ← 新的一欄，消毒器指名
兩邊都跑完    148    148
🟢 一致       138    138
內容真的不同    7      7
```

⚠️ **沒有一支程式因此變得跑得對**——這一刀動的是**分母的意思**，不是分子。
而它值得做，是因為那 5 支會讓下一刀切錯地方。

## 🔴 順手量到的：`npx tsc --noEmit` 看不到 `tests/`

`tsconfig.json` 的 `include` 是 `["src"]`。於是新加的助手裡
**`spawnSync` 沒有匯入而型別檢查回傳 0**。

> **一個「型別檢查過了」的讀數，先問它檢查了哪些檔。**

⚠️ 還沒修——`tests/` 用 node 全域（`process`），而 production 的 tsconfig
刻意沒有 node types（檔頭自己寫了理由）。要修的話是第二份 tsconfig，
而那是另一刀。**何時該修：下一次有人因為測試檔的型別錯誤而浪費一輪的時候。**
