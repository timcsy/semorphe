# 144　`cpp_if` 退場——而擋路的是比對器自己

**日期**：2026-08-24 ｜ **交付**：`cpp_if` 的命令式定義刪除（第 11 顆）＋ 比對器補上三個建構子
**前一則**：[143](143-程式碼到積木丟失註解而根因是AST的形狀.md)
**觸發**：`/knowie-next` 選的下一步（階段 7「那 10 筆命令式積木」）

## 為什麼是這一顆

證據在程式碼裡，逐字（`ui/branch-list-block.ts:22`）：

> 「`{ elseifCount, hasElse }`——與 `block-registrar` 裡 `cpp_if` 的一字不差。
> 🟢 **那是刻意的**：這個建構子的下一個消費者就是它，
> 而換一個鍵名等於讓那顆退不了場。」

**建構子當初就是為它留的門。**

## 🔴 而第一刀砍下去，擋路的是【比對器】

比對護欄說「宣告少了插槽、宣告表達不出 extraState」。查下去：

```ts
// fromDeclaration()
Blockly.Blocks[probe] = { init() { this.jsonInit(def) } }   // ← 只有這一步
```

**三個宣告式建構子（`branchList`／`paramList`／`variadic`）是接在 `jsonInit`
之後才長出插槽與 `extraState` 的**，而比對器從來沒接上它們。
於是**每一顆用建構子的積木，比對器都在指控宣告**。

> **比對之前，要先把【產品那側需要的每一樣東西】都備齊；
> 少一樣，比對就會指控宣告。**

那條規矩就寫在 `retire-imperative-block` 第 2.5 步，而它自己記著被撞過四次
——**這是第五次**。⚠️ 而它的代價是方向性的：它讓人以為「宣告式那條路走不通」。

同一輪還補了第二個量測缺口：`declarableKeys` 只讀 `renderMapping`，
不知道**建構子自己就存得住那些鍵**。

## 逐筆判「哪一邊對」

| 差異 | 判定 | 理由 |
|---|---|---|
| ⊕⊖／elif／else | **命令式對** | 宣告表達不出 → 補 `branchList` |
| 「則」vs「就」 | **命令式對** | ① 使用者今天看到的就是它 ② 與第二個語言那顆同名積木一致 ③ elif 那幾列本來就需要主體標籤，「就」貼在條件尾巴排不出來 |
| 插槽名 | **命令式對** | `ELSEIF_CONDITION_{i}`／`ELSEIF_THEN_{i}`／`ELSE`／`TAIL` **在使用者的存檔裡**——換掉的話 Blockly 會安靜地把接在上面的積木丟掉 |

🟢 建構子的插槽名本來就是參數化的（尾巴那一格 2026-08-24 才補上 `tailInput`）
——**正是為了接手既有的命令式積木**。

## 那張安全網的第四步真的抓到東西

skill 第 4 步：「順手檢查注入契約裡有沒有變成孤兒的欄位」
——`IF_INPUTS`／`ifBlock` 的唯一消費者退場了，三處一起清掉。

> **一個沒有消費者的注入欄位，會讓組裝點以為它還要提供那份資料。**

## 代價與收穫

```
比對護欄「有差異」   10 → 9          （而 cpp_if 先變成「一模一樣」才被刪）
雙重真相            19 → 18
四項獨立性的母體     2705 → 2648
命令式賦值           31 → 26         （本體 ＋ 別名 ＋ 三顆 mutator 小積木）
```

⚠️ **`cpp_if_else` 原本是它的別名**，現在回到自己的宣告（靜態的如果／則／否則）。
它不在工具箱裡（被三個帶 `extraState` 的 `cpp_if` 入口取代），只剩舊存檔會用到。

🟢 **瀏覽器實測**（skill 第 5 步——沒有任何測試在看標籤）：
`if / else if / else` 三段貼進去，積木長出齒輪 ＋ ⊕⊖ ＋「如果／則／否則，如果／否則」，
切一次 Block Style 之後形狀與標籤都在，轉回程式碼一字不差。
