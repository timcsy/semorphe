## 一、🔴 那個問題的真正代價不是「不能跑」

```
17 顆元件的執行器：存在 · 被登記了 · 而從來沒有被跑過一次
```

因為根節點擋在前面。而它**不會讓任何測試變紅**——
**因為沒有任何測試在跑 Python**。

> **一個「機制有了沒人接上」的實例，它的長度等於「沒有人去用它」的時間。**

而跑起來的當天，那 17 顆立刻吐出四個真缺陷（見下）。

## 二、`python:program` 與 `cpp:program` 的差別，就是兩個語言的差別

```
C++      跑完整棵樹【登記】函式，然後【呼叫進入點】（main，或 setup/loop）
Python   ⚠️ 沒有進入點——模組層的語句【就是】程式，由上而下執行一次
```

> **「哪一個函式是進入點」是【整個程式】的知識，
> 而 Python 的答案是「沒有」——那也是一個答案，不是缺一塊。**

所以那顆執行器只有一行。**它短是因為語言本來就這樣。**

## 三、跑起來之後立刻吐出的四個

| 缺陷 | 症狀 |
|---|---|
| `arithmetic` 全回 `double` | `print(5 + 3)` 印出 **`8.0`** |
| `var_assign`／`loop_for` 用 `declare` | 迴圈第二圈 `DUPLICATE_DECLARATION`——Python 沒有宣告 |
| `return` 用 `return value` | `print(add(2,3))` 印出 **`None`**——值算對了、函式跑完了，**而它從來沒有離開那個函式** |
| `negate` 全回 `double` | `-7 % 3` 印成 `2.0` |

> **一個型別在鏈上的任何一節被放寬，後面每一節都救不回來。**
> （`negate` 那一條：算術的整數規則本身是對的，錯的是它拿到的運算元。）

而 `return` 那一條值得單獨記：

> **「回傳」在語義樹裡表達不出來**——它是一條跳離目前這段的邊，而樹只有父子關係。
> 所以直譯器用**丟訊號**代替（`break`／`continue` 同理）。

## 四、🔴 而 round-trip 的**錨點**抓到第五個

`# 註解` 讓整支程式在執行時掛掉。根因是我**當天早上才寫進 skill 的那組正交宣告**：

```
paths.execute: null ＋ _why    「沒有這個檔」        ← 契約 C3 檢查它
skipPaths ＋ skipReasons       「直譯器別抱怨這顆」  ← skip-declarations 讀它
```

**我自己漏了後者。**

⚠️ 而更深的一層：那個宣告的呼叫點是 `registerCppSkipDeclarations()`
——一個掃**全部**膠囊的 glob，掛在 C++ 名字的函式底下。

> **一個語言中立的登記，如果它的呼叫點掛在某個語言的名字底下，
> 那麼「有沒有被呼叫」就變成那個語言的內部細節。**

## 五、盲測抓到第六、第七個——而第六個是**靜默的錯答案**

```
print("ab" * 3)   →   0.0
```

字串只處理了 `+`，`*` 掉進數值運算 → `toNumber("ab")` 是 `NaN`。

> **一個靜默的錯答案，比一個拋出來的錯誤貴得多——因為使用者會拿它去算下一步。**

⚠️ **十二題裡只有一題碰到它**，而那一題碰到是因為題目在教
「`+` 與 `*` 是兩種完全不同的運算」——**一個實作感知的出題者不會寫那一題。**

第七個是 `break`／`continue` 根本沒做：

> **一個誠實的降級，在【執行】那一路上仍然是一個中止。**

### ⚠️ 而這一輪盲測的隔離**比 skill 設計的弱**

不能用 Agent tool，所以出題的人（我）看得到實作。

```
🟢 保住的   題目按【教學上的典型】挑，不按「我實作了什麼」挑
🔴 失去的   串列／字典／f-string 本輪一題都沒出到
```

> **一個知道實作的出題者，會下意識避開它處理不了的模式。
> 而我們無法知道自己避開了什麼。**

→ 這個限制**寫進報告裡**，而不是讓 11/12 的通過率看起來像結論。
