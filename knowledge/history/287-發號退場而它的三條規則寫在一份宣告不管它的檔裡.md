# 287 · 護欄的「發號」退場，而它的三條規則寫在一份宣告「我不管這個」的檔裡

> 日期：2026-09-26（第二次 `/knowie-judge`）
> 轉變：**護欄的流水號（「第 N 條護欄」）停止發放**，上限凍結在 132。
> 新護欄用**檔名**指稱。已發出的 174 筆引用**留著**——它們是病歷。

## 它原本的規則，與它破掉的三個地方

`tests/integration/audit-guardrail-count.test.ts` 的檔頭逐字：

> 「**不管「第 N 條」那個序號**——⚠️ 它是**發號**，不是條數：只增、不重用、退場留洞。」

而實際的發放史：

```
2026-09-21   發到 127 · 130 · 131 · 132       history/277 278 279
2026-09-26   又發了 128 · 129                  history/283 ＋ audit-declared-uniqueness
             而 129 同時指 g++ 那一支           audit-lesson-answers-vs-compiler
             兩支最新的護欄檔自己沒寫發號
```

**只增（退行了）· 不重用（重用了）· 一號一物（129 指兩個東西）——三條全破。**

## 🔴 而它破得無聲的原因不是漏檢

那三條規則**住在一份逐字宣告「我不管這個」的文件裡**。於是：

- 沒有任何機構在看它 ⟹ 每一次發號都是**從檔數推回來的**，
  而那正是同一份文件說它「不是條數」的那個東西；
- 而「只增、不重用」讀起來像一條有人管的規則。

> **一條規則寫在一份明說「我不管這個」的文件裡，
> 它的違反不會有任何機構出聲——而那不是漏檢，是【宣告了不檢】。**

## 為什麼是退場，不是補一台發號機

判準是[執行機構](../concepts/執行機構.md)那一條的反面問法：**它有哪個用途是檔名做不到的？**

```
指稱一條護欄      檔名做得到,而且它就是身分
排出時間順序      git 做得到
在散文裡好讀      ⟵ 唯一的優勢,而它換來三條規則全破
```

⟹ **發號是第二份身分**，而第二份身分在這個庫已經被判過很多次
（[宣告登記處](../concepts/宣告登記處.md)）。補發號機是給一份多餘的身分加上維護成本。

## 退場也要機械化

「以後不要再發」如果只是一句話，下一個人會發第 133 號。所以上限**凍結在 132**，
由同一支護欄擋（`audit-guardrail-count`）。

⚠️ **而它第一次跑就抓到自己**：注入測試裡那個 `第 133 條護欄` 是字面值，
而那一支掃全 repo——[history/140](140-第五十五條而它抓到的第一個是護欄自己.md) 同一個形狀。
處方是把注入字串**拼**出來，不是把自己排除（排除會留下一個真正的盲點）。

> **一條掃全 repo 的護欄，它自己也在 repo 裡。**
