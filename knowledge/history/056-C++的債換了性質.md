# 056　C++ 的債換了性質——從「缺什麼功能」變成「同一件事有兩個地方在說」

> 日期：2026-08-13
> 觸發：使用者問「現在還有什麼 C++ 想做還沒做的部分？幫我梳理一下」。
> 而梳理的過程發現：**問題本身的形狀變了**。

## 轉變

```
old  C++ 的債 ＝ 「還有哪些語法／函式庫不支援」
new  C++ 的債 ＝ 「同一件事有兩個地方在說」＋ 一小撮進階功能
```

⚠️ **這不是「我們做完了」的記錄**（那種東西住在 commit 裡）。
它是一個**分類的改變**：以前問「還缺什麼」會得到一份語法清單，
今天問同一句話會得到一份**架構清單**——而那兩者要用完全不同的方式處置。

### 支撐這個轉變的四個歸零

```
行為缺口（參照跑得動而我們跑不動）   18 → 0
形態殘差（辨識不出來的語法）          0.22% → 0%
完備性的殼                            0
行為誤差                              14 → 1   ← 唯一一筆是 UB，不是缺陷
```

（過程見 [history/055](055-全修一輪-缺陷的形狀比缺陷本身重複.md)。）

### 而剩下的是什麼

| 類別 | 量 | 性質 |
|---|---|---|
| **進階語言功能** | 8 項，全部有釘子 | 樣板特化／可變參數樣板／`mutable` lambda／多 catch／`ptr->method` 派發… |
| **架構債** | 5 條護欄的非零數字 | 執行器直接呼叫面板 73、雙重真相 33、語法耦合 60、符合性 13、防禦性回退 21 |
| **已修而釘子還在** | 1 筆 | 見下 |

🔴 **架構債那五項與「支援哪些 C++ 語法」完全無關**——它們是
「同一件事有兩個地方在說」。而那正是這個專案追了一整年的頭號病。

## ⚠️ 而那八項進階功能裡，只有一項是初學者會撞到的

`class C { int x = 5; };` 的**成員預設值讀不到**。

其餘七項（樣板特化、可變參數樣板、fold expression、`mutable` lambda、
多 catch ＋ rethrow、`stack<T>&` 參數、指標陣列的動態派發）
**在教學場景裡可能永遠不需要**。

> **一份「還沒做」的清單如果不按「誰會撞到」排序，
> 它會讓最進階的那幾項看起來和最基礎的那一項一樣重要。**

### 那個判準值得單獨拿出來

排一份技術債的優先序時，常見的兩個量是**筆數**與**修的成本**。
而這一輪證明兩者都不夠：

| 判準 | 為什麼不夠 |
|---|---|
| 筆數 | 樣板那一族有 2 筆，成員預設值只有 1 筆 |
| 修的成本 | 成員預設值可能比多 catch 難修 |
| **誰會撞到，多早撞到** | ✅ **`int x = 5;` 是第一週的語法** |

→ ~~**提議進 `experience`**（待人確認）~~ ✅ **已執行**（2026-08-13）——
`experience.md`「排技術債的優先序時，問的不是『有幾筆』或『多難修』」：

> **排技術債的優先序時，問的不是「有幾筆」或「多難修」，
> 是「使用者多早會撞到」——而那個順序常常與前兩者相反。**

⚠️ 這與 P4「漸進揭露」是同一個座標系的兩個用途：P4 用**關卡**決定
學生**看得到什麼**，而這條用**同一個關卡順序**決定我們**先修什麼**。
`cpp:class_def` 在 `L2c`，而樣板那些在 `L3b`／不在任何關卡裡。

> **課程順序不只是給學生的，它也是一份缺陷的嚴重性排序。**

## 🔴 一筆已經修好而釘子還在，且它不會自己出聲

```
it.todo('[BLOCKED:cpp:destructor] should preserve inner block scope for correct destructor ordering')
```

那筆**今天被 `cpp:block` 修掉了**（獨立區塊的作用域），而釘子還在缺陷帳裡。

⚠️ **而它是 `it.todo`——沒有測試本體，所以它永遠不會變紅。**

`experience.md:261` 記過這兩者的差別，而記的是**估算的那一半**：
「把兩種需要完全不同工作量的東西包在一起，讓優先序灌水 3–10 倍」。

**今天露出的是另一半**：

> **`it.skip` 的缺陷被修好時會變紅（它有本體）；
> `it.todo` 的缺陷被修好時什麼都不會發生——它只是繼續躺在那裡，
> 而缺陷帳把它算成「還沒做」。**

→ ~~**提議**（待人確認）~~ ✅ **已執行**——補進 `experience.md` 那條的
「⚠️ 而它有另一半」，並**拔掉了那根釘子**（改成三支真的測試，缺陷帳 34 → **32**——`describe.skip` 一起解掉，多消一筆）。
而 `build-guardrail` 的「❌ 永久紅的測試」那一節已經說了處置
（「要釘住已知缺陷用 `it.fails`」）——**缺的不是處方，是知道 `it.todo` 也算一種殼**。

## ⚠️ 而「還沒做的清單」本身刻意不寫進知識庫

那份清單（8 項功能 ＋ 5 條架構債 ＋ 各自的數字）**是狀態，不是知識**。

`vision.md:284` 逐字：

> 「**表中是「起始」值，不是現況。** 現況看 `tests/baselines/`
> ——那是唯一不會過期的來源。」

同一條適用：清單的來源是 `tests/baselines/*.json` 與缺陷帳的 `byBlocker`，
**兩者都是機器產生、每次跑都重算的**。把它抄進 markdown 只會多一份會腐爛的副本。

→ 本檔記的是**分類的改變**與**排序的判準**，不是清單。
