# 271 — 一個前綴判準對空字串保持沉默（＋同一欄裡的第二個缺陷）

**2026-09-20** · 第 209 刀 · 分支 `209-getline-as-condition`

## 起點：語料報表上「不是缺陷」的那一欄裡，藏著一個缺陷

第五面向的報表把「不一致」分成三欄，而分欄本身是對的設計
（`CLAUDE.md`：**一份「有 N 個缺陷」的報告，先問那 N 裡有幾個是量測工具自己的**）：

```
我們少了尾巴   我們的輸出是參照輸出的【前綴】 ← 多半是測資餵不夠（量測工具的帳）
我們多了尾巴   反過來
內容真的不同   🔴 這一欄才是缺陷
```

而 `AP325/3/3_2.cpp` 是這樣的：

```
g++ ："no"      我們：""
```

**我們一個字都沒印**，而它落在第一欄——因為**空字串是每一個字串的前綴**。

> **一個「前綴就算少了尾巴」的判準，對「我們一個字都沒印」保持沉默
> ——因為空字串通過每一次前綴檢查。**

## 真正的病：`getline` 在運算式位置什麼都不回

```cpp
while (getline(cin, s)) { … }
```

`getline` 回的是 `istream&`，而 `while` 用它的 `operator bool`（＝`!fail()`）。
`cpp:input_line` 的執行器**一個值都不回**，於是條件拿到 `undefined`
⟹ 迴圈**一次都不進去** ⟹ 輸出整個是空的。

🔴 **而三條最像的路都是對的**——這正是它活下來的原因：

```
while (cin >> n)        🟢 `cpp:input` 回 { int, 讀到幾個 }
while (cin >> a >> b)   🟢 同上
getline(cin, s);        🟢 語句位置，沒有人問它回什麼
while (getline(cin,s))  🔴 只有這一條
```

⚠️ 語料裡**16 支**把讀取當迴圈條件（`while(cin >> n)` 15 支 ＋ `getline` 1 支），
所以壞掉的是**十六分之一**——而那十五支的綠替它背書。

## 🔴 順帶量到：測資管線把「空」正規化掉了

寫最小重現時第一版用 `stdin: []` 表達「完全沒有輸入」，而它紅了
——**我們印 `none`（對），g++ 印 `got`**。

因為那個框架餵給參照編譯器的是 `stdin.join('\n') + '\n'`，
所以 `[]` 變成**一個空行**，而 g++ 讀得到那一行。

> **一個把「空」正規化成「一個空的東西」的測資管線，
> 量不出「完全沒有」與「有一個空的」的差別。**

🟢 處置：那一條改成「讀完之後再讀一次」，兩邊都真的走到 EOF。

## ⚠️ 而新加的七條裡，有一條在修好之前也是綠的

`if (undefined)` 與 `if (0)` 一樣是假，所以「讀完之後再讀一次要說假」
**答對了而理由是錯的**。拿掉回傳值重跑，紅的是 ④⑤⑦ 三條。

🟢 它留著（它守的是「EOF 那一路不要順手回成真」），**而標題標了「修好之前也綠」**
——不標的話，下一個人會以為那七條都在守這個缺陷。

## 🔴 同一欄裡的第二個：`for (int i{}; …)` 從 1 開始

「少了尾巴」那一欄裡還有 `AP325/2/2_8_loop` 與 `2_8_re`：

```
g++ ："1 0 0 1 1 0 1 0"      我們："1 0 0 1 1 0 1"      ← 少最後一項
```

那支寫 `for(int i{}; i<n; i++)`。`int i{}` 是**值初始化**（＝0），
而 `from` 拿到的是一顆空的 `cpp:initializer_list`，求值之後是
`{ type: 'array', value: [] }`，而 `toNumber` 對**任何** array 回 **1**
⟹ 迴圈**少跑一次**。

⚠️ **`toNumber` 那一行不能改**，它的註解逐字寫著「一塊存在的儲存體不是空指標」
——`new T` 配出來的節點型別就是 `array`，`while (p != NULL)` 靠它。

> **一個共用的轉換，它對「空」的答案是為【另一個呼叫端】定的。**

🟢 而 `int i{};` 在**語句位置**一直是對的——**又是「一族裡只有一個成員沒處理」**。

⚠️ 第一版順手把 `to` 也套上了，而**上界那一邊沒有任何合法的 C++ 寫法觸發得到**
（`i < {}` 不是合法運算式）。拿掉了：
**一個沒有人讀的宣告，與一個寫錯的宣告長得一模一樣。**
