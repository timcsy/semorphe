# 一條曲線的宣告，寫的是轉折點，不是每一格的值

**日期**：2026-09-07 · **路線圖**：課程的第六刀之二「拆輪子的曲線」（部分交付）

## 轉變

```
舊  三個旋鈕（鷹架深度／版面／工具箱寬度）都在，而【只有鷹架那一軸有曲線】
    版面：只有使用者調得動，課程管不到
新  Track.view ＋ LessonPins.view——軌道給預設，課在【轉折點】覆寫
    ＋ 編輯計數「這一課你改了哪一邊」（只留在本機）
```

使用者原話：「我希望這成為學生的**輔助輪**，最終是可以看懂程式碼的」。
而一個輔助輪要拆得掉，**得先有一條把它拆掉的路**，還要有人**看得到它還在**。

## 🔴 而護欄當場抓到第一版的設計缺陷

第一版寫的是 `pins.view ?? track.view`——一個看起來完全合理的 fallback。
軌道預設 `blocks`、第 4 課轉 `compare`，做出來是：

```
❌  blocks blocks blocks compare blocks blocks blocks …   ← 一根刺
🟢  blocks blocks blocks compare compare compare …       ← 一級階梯
```

> **一條曲線的宣告，寫的是【轉折點】而不是【每一格的值】
> ——而「沒宣告就退回預設」會把轉折變成一根刺。**

🟢 **而它抓得到，是因為護欄與產品共用同一支 `viewForLesson`。**
第一版的護欄自己算了一次（同樣的錯算法），而**改成共用之後那個錯才現形**。

> **一條護欄如果自己重算一次產品的判斷，它守的是自己那一份。**

## 🔴 兩條曲線方向相反，而兩者都對

```
語意波（第一百零四條）   一【課】之內   先下到具體，再回到抽象
拆輪子（第一百一十三條）  一【軌】之間   往程式碼那一頭走，不回頭
```

⚠️ **搞混它們會讓兩條護欄互相打架**：一課之內回到抽象是**學會了**，
而一軌之間回到積木是**鷹架又裝回去了**。

⚠️ 而它們在**第一題那一刻是重疊的**（兩個都在說「這一課的第一個畫面」）
——那時**題目贏**，因為它更近也更具體。

> **兩層預設值重疊的時候，贏的該是【比較近的那一層】
> ——而「它們在不同的軸上」是一句聽起來很整齊、而擋不住任何東西的話。**

## 🪦 而這一刀砍掉了一條我當天稍早自己寫下的驗收

升格時我把「**一層薄的『學習訊號』**，而不是三個消費者各做各的」寫成一條驗收。
用 `verify-before-deciding`（**同一天稍早才立的 skill**）一驗，
就撞上 `progress.ts:23` 已經做過的決定：

> 🔴 **先只做第三個**。把三件事一次抽象成「學習訊號」會長出一個
> 「什麼都裝得下」的介面，而那是假的父概念（沒有剪枝力）。

> **一條「我們該有一層抽象」的驗收，要先問【今天有幾個消費者】
> ——兩個以下，那層抽象裝得下的東西比它擋掉的多。**

🟢 所以 `edit-tally` 與 `progress` 共用的是**那個埠**（`KeyValueStore`），
不是一個介面。

## 計數的三個決定

**① 只留在本機。** 送出去就破〈離線可用〉的硬性零，而且**那個數字的價值在於
它是給學生自己看的進度**，不是給我們看的數據。護欄擋住 `fetch`／`sendBeacon`。

**② `flow` 記成 `blocks`。** 這個計數要回答的是「他還在用圖形介面嗎」，
而流程圖與積木在那個問題上是同一邊。

> **一個計數的值域，要跟著它要回答的那個問題走，不是跟著資料的來源走。**

**③ 與進度一起清。** 換一班學生（電腦教室）時留著上一班的計數，
新學生會從一個不是他的數字開始。護欄驗兩者接在一起、清在一起。

## ⚠️ 還沒做的那一半——而研究說它才是重點

blocks→text 的系統性回顧（2026-09-05 查證）：

> 直接翻譯的工具把積木與程式碼並排顯示——對【對映】有幫助，
> 而它們往往**沒有處理**從拖拉到【**打字與除錯**】的概念轉變。

⚠️ **所以這一刀只做了「版面的曲線」，那是必要而不充分。**
打字與除錯的練習還沒有。而**指標要不要顯示、顯示在哪也還沒拍板**
——一個「你還在用積木」的數字，寫不好會變成**羞辱**而不是鼓勵。

> **一個關於使用者的數字，算得出來與該不該給他看，是兩個決定。**
