# 065　兩條護欄從相反方向量同一件事——而我只看了其中一條

> 日期：2026-08-14
> 觸發：想清償 `audit-conformance` 的違規，判定其中兩筆是「宣告與現實不符」。
> **而那個判定是錯的，已回退。** 本檔記的是**為什麼會錯**。

## 轉變

```
old  一筆符合性違規要嘛是【實作缺口】，要嘛是【宣告與現實不符】
new  🔴 而分辨它們的證據【不能只看一邊】——因為有兩條護欄從相反方向在量
```

## 被否決的路線（連同理由，這是本檔的重點）

我判定這兩筆是假違規並刪掉了宣告：

```
struct_at_member.obj      出處：generate.ts:6 用的是 node.properties.obj
var_declare.declarators   出處：strategies.ts:365-372 多變數 lift 成 _multi_field
```

`audit-conformance` 從 11 → 9，`declaration-change-parity` **逐字相同**（行為沒變）。
**看起來完全成立。**

### 而全套測試紅了五支，其中一支說了實話

```
audit-declared-slots（lift 產出的接點，宣告裡有嗎）：
  ✘ cpp:struct_at_member — 產出 [obj] 而宣告裡沒有
  ✘ cpp:var_declare — 產出 [declarators] 而宣告裡沒有
```

**lift 真的會產生它們。** 我查到的那兩條路徑是**真的**，
而它們**不是唯一的路徑**——另一條會產生那些接點。

## 🔴 根因：兩條護欄是一對，而我只跑了一條

```
audit-conformance     宣告了的，形態表達得出來嗎     ← 刪宣告會讓它【變好】
audit-declared-slots  lift 產出的，宣告裡有嗎        ← 刪宣告會讓它【變壞】
```

> **它們從相反方向量同一件事。而那對關係本身，就是
> 「用宣告刷數字」的機械偵測器——這個專案早就有它，而我沒去跑。**

⚠️ 而 `specs/123` 的 spec **自己寫了那個判準**：

> 「『沒有人走』＝ 沒有產生端（lift 不會造出它）**或**沒有消費端。
> ⚠️ **兩者都要查——只查一邊會漏。**」

**我寫了它，然後只查了消費端。**

## 而「行為沒變」為什麼騙過了我

`declaration-change-parity` 逐字相同——那是真的。
**因為那批對照語料裡沒有一段會走到那條路。**

> **一個對照組只證明「它涵蓋的那些情況沒變」。
> 而我把它讀成了「什麼都沒變」。**

## 出口條件

- **那 9 筆若要再判「假違規」** → 🔴 **必須同時跑 `audit-declared-slots`**，
  而且兩條都要綠才算數
- ⚠️ **在此之前，`conformance` 的 11 筆一律當成真的**
