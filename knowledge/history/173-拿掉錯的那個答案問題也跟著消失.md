# 173 · 拿掉錯的那個答案，問題也跟著消失

**日期**：2026-08-26

## 起點：使用者要的東西，程式碼給的是反過來的

使用者 2026-08-24 逐字（`vision.md:524`）：

> 「**如果沒看過的東西就不要執行下去了，要誠實的說沒看過**」

而在此之前，`execution-controller` 用一個 `confirm()` 問學生：

```
Unknown component "%1" encountered.
Click OK to skip it and continue, or Cancel to stop execution.
```

`interpreter.ts` 那條分支的註解逐字：`// 'skip' — 繼續執行`。

## 🔴 為什麼「跳過」是這個系統裡最貴的一個選項

```
跳過一個【輸出】   少印一行              ← 看得出來
跳過一個【賦值】   後面每行都讀錯的值    ← 看不出來，而且每一步都【正常】
```

它同構於 `concepts/模擬的誠實.md:23`：

> **一個每次讀到不同值的模擬器，測不出任何東西。**

一個跳過就繼續的直譯器，跑出來的輸出**與那支程式無關**——而學生會拿它當答案。

而 `principles.md:206` 的檢驗表更直接：「這裡出錯會有人發現嗎」
答案是「不會」的每一處，**都是等待發生的靜默降級**。

## 轉移：拿掉答案，問題跟著消失

這一刀只做一件事——**把 `'skip'` 這個回答刪掉**。而它的連鎖是免費的：

```
'skip' 沒了      →  handler 沒有東西要問     →  handler 整個退場
handler 退場     →  三段 confirm() 沒有理由  →  24 行【位元組完全相同】的複製消失
```

> **一個問題如果只有一個錯的答案和一個對的答案，
> 拿掉錯的那個之後，就不必再問了。**

`vision.md` 那一項的第三條驗收（「`confirm()` 從 `execution-controller` 消失」）
**因此被付掉一半**：6 處 → 3 處，剩下的三處問的是同步，不是這件事。

⚠️ 而它**沒有**做掉三條出口（手填／委派／停止）——那是同一個路線圖項的後續，
而 draft 的「未決」還有五題開著。**這一刀刻意只到「不繼續」。**

### 順帶：一個孤兒 i18n 鍵

`EXEC_UNKNOWN_COMPONENT_PROMPT` 被查了三次，而**它在兩份 i18n 裡都不存在**
——所以那個對話框從來就是英文的退路字串。它隨著 handler 一起退場。

## 🔴 而「誠實地說沒看過」少了一半：**沒有名字的誠實**

訊息本來是「這一塊我還不會執行——這是系統還沒長到的地方，不是你寫錯了」。
語氣是對的，**而它不說是哪一塊**。拋出點一直有 `{ component }` 這個參數，
**而模板裡沒有任何佔位符**，於是那個參數傳了十幾週、從來沒有被顯示過。

> **一個傳了而模板不用的參數，與沒傳是同一件事——
> 而型別檢查兩邊都看不到。**

補上 `（{component}）` 之後：
「這一塊我還不會執行（`cpp:priority_queue_peek`）——……不是你寫錯了」。

## ⚠️ 而補這個佔位符讓第四十四條護欄變紅，**它指控的是一個正確的訊息**

第四十四條（執行期停下來時說的是人話）掃**拋出點的參數名**，
把每一組 `(身分, 參數)` 餵過顯示路徑，看結果像不像代號。它報：

```
zh-TW  RUNTIME_ERR_UNKNOWN_COMPONENT  參數[無]  → 未替換的具名佔位符
```

而那個「參數[無]」是假的：它的 `topLevelKeys` 只認 `name: value`
——找第一層的 `:`，取前面那個識別字。於是**簡寫屬性**（`component,`）
被讀成「沒有參數」。

⚠️ **而這個檔自己的第 166 行早就寫下了這個顧慮**：

> 「那不會造成假違規（多餘的參數只是被忽略），**而它會讓報表說謊**，
>  而一份說謊的報表推導不出『使用者到底看到什麼』」

它只想到「多算」的方向，**沒想到「少算」會變成假違規**。

實測：`src/` 裡用簡寫屬性的拋出點**只有一處**——就是我今天寫的那一處。
> **這個缺口一直在，而它從來沒有受害者。
> 不是「壞了很久沒發現」，是「第一個踩到的人今天才出現」。**

修法：先用第一層逗號切段，每段各自問「它是 `k: v` 還是一個裸識別字」。
釘子：那條護欄的注入④（含反向：真的沒有參數時仍然回空）。

## 順帶修掉的第三件事：一條會在機器忙的時候不再守的護欄

全套跑到一半：

```
❯ audit-dropdown-domain.test.ts (7 tests | 7 skipped) 10009ms
  Error: Hook timed out in 10000ms.
```

單獨跑 1.4 秒。根因：`vitest.config.ts` 設了 `testTimeout: 60000`，
**而 `hookTimeout` 不會跟著它**，停在預設的 10 秒。
那個檔的 `beforeAll` 要載語言套件 ＋ 註冊欄位 ＋ 建 Blockly 工作區。

⚠️ **訂正**：我第一時間說它「安靜地」不再守——**那是錯的**，
檔案層級確實有一筆 `FAIL`。真正的問題比較窄：那七支被記成 **skipped**，
而摘要的 `Tests` 那一行是 `0 failed`。

> **一個測不到東西的 0，與一個健康的 0，產出一模一樣**
> ——而這次連「幾支跑過」都被記成了「跳過」。

修法：`hookTimeout: 60000`。
