# 057　缺陷清單只包含被記下來的缺陷——而使用情境問出了另一批

> 日期：2026-08-13
> 觸發：使用者說「先讓 C++ 再完善一些，**因為現在好像還有一些 C++ 元件或
> 會用到的概念還沒完成**」，並指定「從**資訊競賽、APCS、Arduino 使用情境**
> 把更多東西補齊」。
> 本檔記的是**那句指定改變了什麼**，不是修了哪幾顆。

## 轉變

```
old  「C++ 還缺什麼」＝ 缺陷帳的 byBlocker ＋ 五條護欄的非零數字
new  那份清單看不到「使用者會寫、而我們從來沒寫過」的東西
```

[history/056](056-C++的債換了性質.md) 前一天才盤點過，結論是
「**8 項進階功能 ＋ 5 條架構債**」，而其中只有一項是初學者會撞到的。

**那個結論在它自己的輸入範圍內是對的**，而輸入是缺陷帳與護欄基線
——兩者都只記錄**已經被發現並寫下來**的缺陷。

> **一份缺陷清單只包含被記下來的缺陷。
> 「使用者會用而我們沒寫過」的東西，不在任何一份清單裡——
> 因為沒有人為它開過票。**

⚠️ 而 056 自己就寫了為什麼清單不進知識庫（「清單是狀態不是知識，
來源是 `tests/baselines/`」）。**那句話仍然對，而它同時是這個盲點的來源**：
基線是機器產生的，機器只數它掃得到的東西。

## 怎麼問出另一批：換語料的來源

既有的兩條護欄（殘差、行為誤差）從**教學文件的程式碼區塊**撈語料。

> **一個語料庫如果來自我們自己的文件，它量不出
> 「使用者會寫而我們沒寫過」的東西。**

新的 `tests/probes/scenario-coverage.test.ts` 反過來：**先想清楚使用者在哪裡
用它**（資訊競賽／APCS／Arduino），照那三個情境寫 53 段，再看通不通。

第一次跑：

```
競賽    25 段｜辨識缺 3｜執行不符 13｜投影不符 2
APCS    18 段｜辨識缺 0｜執行不符  4
Arduino 10 段｜辨識缺 0｜執行不符  0｜投影不符 0     ← 全通
```

**056 的清單裡一項都沒有這些。**

### ⚠️ Arduino 那一欄是一個現成的答案

[支援 Arduino 要加什麼](../draft/2026-08-13-支援Arduino要加什麼.md) §一 逐字
寫著「**語言那一半幾乎是免費的（實測）**」——那句話當時的依據是
「`cpp:program` 的 children 本來就沒有 main 的概念」，屬於**結構推論**。

今天它有了**量測**：10 段真實 Arduino 碼，辨識與投影全通。
`setup`／`loop`／`pinMode`／`Serial.println`／`analogRead`／`byte`／`String`
——一顆硬體元件都還沒有，而語言那一半確實已經在了。

> **一個靠結構推論得到的結論，換一種方法量一次，代價很小而它從此站得住。**
> （與 [C 和 C++ 難分難捨](../draft/2026-08-13-C和C++難分難捨.md) §五
> 的「兩個方法、不同語料、同一個答案」是同一件事的第二次。）

## 🔴 而剩下的缺口，根因高度集中

修掉四個之後，剩下的分成三類，而**第一類是同一個病的三個實例**：

```
array_declare.name    = "a[2]"     維度藏在名字裡
var_swap.a            = "a[j]"     lvalue 是字串
constructor.init_list = "v(x)"     初始化列是字串——執行那一路從未讀它
```

> **表達式被存成字串屬性，於是執行那一路拿不到它。**

三個都要把**屬性升格成接點**，也就都要動積木形態。

⚠️ 🔴 **本檔第一版把它歸給「`vision` 階段 6.5 的 C 步（結構補齊／ParamSpec）」，而那是錯的**
（2026-08-13 的 judge 抓到）：vision 的 `C1` 就是 ParamSpec，**2026-08-07 已完成**；
`C2` 是資訊軸、`C3` 是引用完備性。這三項**不在 A–F 表裡**。

**正確的家早就存在**：[concepts/概念代數](../concepts/概念代數.md)「屬性的結構化邊界」逐字——

> 「判定準則：如果一個屬性值在管線中需要被拆分或解析，它就不該是字串。」

那條規則在此之前的實例（`func_def` 的參數）已於 2026-08-07 查證為**已解決**，
於是它一度看起來像一條沒有現役實例的規則。**今天它有三個**，
其中一個是 APCS 的二維陣列——**初學者第一週的語法**。

> ⚠️ 而這個誤引本身是一個實例：**一個聽起來對的階段代號，比一句沒有出處的話更難被懷疑。**

## 三類剩餘（清單本身住在 probe 的報表裡，不抄進這裡）

| 類 | 性質 | 例 |
|---|---|---|
| **A** | 屬性要升格成接點（**動積木形態**） | 二維陣列、`swap(a[j],a[j+1])`、建構式初始化列 |
| **B** | 純執行器 | 二維 `vector`、`map` 的 range-for、`priority_queue` 的比較器 |
| **C** | 缺元件（走 `component-generate`） | `sort` 帶比較器、`lower_bound`、`max_element`、`__builtin_popcount` |

⚠️ **A 類擋不住 B、C**——三類彼此獨立，可以任何順序做。
而 A 類裡的二維陣列按「誰會撞到、多早撞到」是**第一順位**。

## 順帶：一個講缺陷的註解變成了一筆缺陷

拔釘子時把它的原始寫法照抄進註解，缺陷帳的掃描器照樣數進來
（`titleOnly` 12 → 13，而那看起來像一筆新缺陷）。

**掃描器不分辨程式與註解是刻意的**（否則有人用註解藏缺陷），
所以講一根釘子要用**敘述**，不要照抄它的寫法。

→ 已寫進 `tests/baselines/defect-ledger.json` 的 `note`
（第 7 步：上調／下調的理由留在數字旁邊）。
