# 097 — 八塊板子，而三個錯都是憑印象填的

**日期**：2026-08-19 · **spec**：`147-board-registry` · **狀態**：完成

## 轉變

```
之前   三塊板子（Uno／Nano／ESP32），資料兩份，而其中兩份是錯的
之後   八塊板子，資料一份，每一個值附上游 variant 檔名
```

使用者說出他會教的清單（ESP32 NodeMCU／C3 Supermini／S3／S3 WROOM CAM／
Wemos D1 mini／NodeMCU ESP8266／Uno／Nano），**而查證那份清單的過程
掀出了既有資料的三個病**。

## 🔴 三個病，一個根

| | 病 | 真相 |
|---|---|---|
| ① | 「ESP32 沒有 `A0`」 | `variants/nodemcu-32s`：`A0 = 36` |
| ② | `NANO_BOARD = { ...UNO_BOARD }` | Nano 用 `eightanaloginputs`，多 `A6=20`／`A7=21` |
| ③ | 護欄測 `arduino-pins.ts`，產品讀 `targets/*.json` | 護欄守著一份沒有人在用的副本 |

**根**：`specs/145/research.md:60` 逐字寫著「ESP32 的類比腳位不叫那個名字」
——**而它沒有附任何來源**。一句憑印象的話，長出了一條會紅的護欄。

> **一個沒附來源的事實主張，長出護欄之後就變成不可質疑的
> ——任何人把對的值填回去，測試會紅，然後他會以為自己錯了。**

⚠️ **是使用者發現的**：「我印象中 ESP32C3 有 A0 呀」。

## 🔴 ②特別值得看：我對【測試】設了防線，卻讓【資料】照樣推論

`arduino-pins.ts:59` 的註解逐字：

> 「Nano 與 Uno 同一顆 ATmega328P。⚠️ 而驗收**逐塊斷言**，不從 Uno 推論。」

**下一行就是 `{ ...UNO_BOARD }`。**

## 而機制沒有倒——資料倒了，機制反而更站得住

```
Uno 14 · Nano 14 · ESP32 36 · C3 0 · S3 1 · D1 mini 17 · NodeMCU8266 17
```

**同一個 `A0`，五個值。** spec 145「常數表由板子提供」的判斷是對的，
而真實資料比當時想的更支持它：`A0` 不是「有或沒有」，是
**同一個名字在不同板子上指不同腳位**——一張模組層級的表在這裡
不會拋錯，只會讓燈亮在**錯的腳**上。

## `maxPin` 升成腳位集合

```
之前   pin > board.maxPin        → ESP32 的 digitalWrite(30) 靜靜地過（30 < 39）
之後   board.pins 的區間清單     → 「不在 ESP32 NodeMCU 上——它有 0–19, 21–23, 25–27, 32–39」
```

> **一個用「最大值」表達的集合，會把中間的洞一起收進來。**
> ESP32 沒有 GPIO 20／24／28–31，S3 沒有 22–25。

## ESP8266 帶進來的不是值，是【命名體系】

`D0–D8` → GPIO 16, 5, 4, 0, 2, 14, 12, 13, 15（**不連續**，`D1` 是 GPIO 5）。
🟢 而 `constants: Record<string, number>` **吃得下**——倒的只是資料。

實測（四塊板子逐一按過）：
```
D1 mini    A0→17  D1→5  D0→16
Uno        A0→14  D1→「變數 'D1' 尚未宣告」   ← 🟢 別塊板子的名字看起來就是不存在
```

## 能力也逐塊查證

`esp32c3/soc_caps.h` **完全沒有** `SOC_TOUCH_SENSOR_*` → C3 不宣告 `touch`。
（`esp32s3` 有 `SOC_TOUCH_SENSOR_VERSION (2)`。）

## 已知缺口（明確不做）

- **S3 WROOM CAM 的相機佔掉哪幾支腳**——今天沒有「被佔用」這個概念，不在這裡發明
- **腳位方向**（ESP32 的 34–39 只能輸入、Uno 的 `A6`／`A7` 只能類比）
- **板子拆成獨立的軸**——今天一塊板子 ＝ 一個目標，零機制。
  重開條件是「同一塊板子要配不同語言」真的出現
