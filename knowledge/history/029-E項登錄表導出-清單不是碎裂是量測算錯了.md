# 029：E 項——從「把清單導出」到「清單不是碎裂，是量測算錯了」

> 日期：2026-08-07
> 範圍：階段 6.5 的 E 項，`specs/100-registry-derived-lists`
> commits：`291ea8e`（規劃）→ `48fa1a9`（更正）→ `f93246f`（護欄）→ `ab516ed`（導出）

## 轉移一：驗收標準

- **舊**：「前兩大共用檔（`topics/cpp-beginner.json` 172 顆、`cpp-competitive.json` 170 顆）的元件提及數 → **0**」
- **新**：那兩個數字**不歸零，也不該歸零**（實測 166／164，一顆都沒動）。改成量「工具箱的手寫積木型別 80 → 45 段有序來源」。

### 為什麼變

功能描述自己就自相矛盾：一句寫「提及數 → 0」，另一句寫「`topics` 導出的是**結構**，**選擇**仍是宣告的資料」。

讀了 `topics/cpp-beginner.json` 的實際結構之後，第二句是對的：

```
L0: 基礎          concepts: 19
  L1a: 函式與迴圈   concepts: 20
    L2a: 陣列與字串  concepts: 33
      L3a: STL 容器   concepts: 25
```

**那是一條教學漸進線。**「`vector` 屬於 L3a 而不是 L0」是人的判斷，導不出來——導出它等於用演算法決定教學順序。

**真正錯的是量測**：就近性護欄把課程清單算成「實作擴散」。修法是修量測（把「清單」與「實作」分開計，判準抽到 `tests/helpers/file-classification.ts` 與身分健檢護欄共用），不是刪資料。

與 [020](020-建一個機制不等於它在運作.md) 的完備性 harness 同一個形狀——**量測把不是那件事的東西算了進去**，而修法是修量測。

### 代價：一個數字型的假目標活了兩天沒被發現

它寫在 vision 的驗收欄裡，看起來像已經量過的東西。**數字天生看起來像證據**——這是 [執行機構](../concepts/執行機構.md)「每個量測工具都要帶一句自我否證提示」的同一個根，只是這次沒有工具，只有一個被寫下來的數字。

## 轉移二：歸屬的粒度

- **舊**（`research.md` 決定 3）：「讓 `registryCategories` 支援更細的比對——而**細分規則本身是宣告的資料**」
- **新**：分類宣告**有序的來源段落** `(from, category)`；散開的那幾包由**積木自己**宣告 `toolboxCategory`。

### 為什麼變：舊的那句話**沒有指涉物**

實作時才發現：`containers` 這個 `category` 底下有 **49 顆積木**，手工散進**四個**工具箱分類，而那 49 顆身上**除了 conceptId 之外沒有任何欄位分得開它們**——

而「用 conceptId 前綴比對」正是決定 3 自己否決的做法（把元件身分寫進呈現層）。

> **一個沒有指涉物的設計，讀起來與一個有指涉物的完全一樣。只有去實作它才會發現。**

### 新形狀為什麼成立：既有的順序**本來就是**段落

實測每個工具箱分類的積木順序，是一串**互不重複的連續段落**：

```
文字：<cstring>/strings → <string>/containers → <cctype>/stdlib → <cstdlib>/stdlib
對應與集合：<map>/containers → <set>/containers → <utility>/containers → (core)/containers
```

12 個分類全部如此。所以這不是重新發明一個順序，是把**既有的教學設計寫下來**——12/12 分類產出一字不差。

段落的**順序**是宣告的（教學設計），段落的**成員**是導出的（登錄表知道）。判準：**問「登錄表知道嗎」，不問「這是不是一份清單」。**

### 三包真的散開的，逐顆宣告

`<cstdlib>` 的 `abs` 是運算、`exit` 是控制、`atoi` 是文字——**一個標頭三個教學意圖**，來源決定不了。同時屬於兩個分類是真的（`c_memset` 既是文字也是記憶體操作），所以欄位型別是 `string | string[]`。

## 墓碑：兩個被否決的選項

| 選項 | 為什麼不選 |
|---|---|
| **改積木 JSON 的 `category` 讓它更細** | 那個欄位還有別的消費者；而且會把「這顆屬於 containers」（**登錄表知道的**）和「這顆該放在堆疊與佇列」（**教學決定的**）壓成同一個欄位。**兩種真相不該同名。** |
| **在工具箱建構器裡寫 `if (conceptId.startsWith('cpp_map'))`** | 把元件身分寫進呈現層，中立性護欄會叫 |
| **每顆積木加一個獨立的 `toolboxCategory` 欄位當**唯一**來源** | 那會讓 183 顆積木每顆都要填一次，而其中 156 顆導得出來。最後採用的是**混合**：導不出來的才宣告（27 顆） |

## 順帶落出的三件事（都不是計畫裡的）

1. **三顆積木的宣告是對的，被呈現層吃掉了**——`cpp_getline`／`cpp_ifstream_declare`／`cpp_ofstream_declare` 的 `category` 明明就是 `'io'`，而 `buildIoContents` 把積木分成 `startsWith('u_')` 與 `startsWith('c_')` 兩堆，`cpp_*` 兩邊都不屬於。**症狀與「忘了登記」一模一樣，根因差很遠。**
2. **`buildIoCategoryContents` 是同一段邏輯的第二份拷貝**，零產品呼叫者，有一模一樣的缺陷，而它自己的單元測試通過了三個月。已刪，測試改測真的那條路。
3. **課程清單護欄第一次跑抓到兩筆自 [022](../history/022-護欄的自我否證不得錨在真實狀態.md) 時期就存在的懸空引用**（`cpp:vector_push_back`／`cpp:vector_size`，正確名字同一層都已經有了，解析不到任何元件）。
