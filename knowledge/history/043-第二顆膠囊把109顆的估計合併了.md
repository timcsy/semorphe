## 轉變一：步驟表寫完之後過了五輪才變成 skill

`specs/104` 的切片紀錄開頭寫著：

> 「哪些步驟會**重複 176 次**。沒有它，剩下的 176 顆仍然是憑感覺開票。」

而它寫完之後**過了五輪都沒有被 skill 化**，中間蓋了五條護欄。

> `knowie-next` 的 skill 候選是**預防性**的：
> **在第 176 次手動重做之前 skill 它，不是之後。**
> 而這一次它被錯過了一輪又一輪，因為每一輪都有更急的東西。

## 轉變二：`io.ts` 那 68 顆的估計，實測後可以與 41 顆合併

`specs/104` 的形狀分類把 109 顆 lift 分成兩批，其中 **68 顆標「處方尚未實測」**。
第二顆（`cpp:char_is_alpha`）刻意從那一批挑——**不挑最便宜的 7 顆**：

> 挑最便宜的來「驗證流程」等於沒驗。**第二顆的作用是否證估計。**

實測：`io.ts` 的 `cctypeFuncs` 與 `strategies.ts` 的 `containerConcepts`
**是同一種形狀**——lift 都是**共用分派表裡的一筆資料**，不是函式。

```ts
// 兩顆的 lift.ts 幾乎一樣
export function registerLift(): void {
  register<某種>表('isalpha', 'cpp:char_is_alpha', 'cpp/char_is_alpha')
}
```

→ **109 顆的估計合併。** 而 `specs/104` 自己標的「⚠️ 基於一個樣本」
現在基於兩個，且兩個落在不同的形狀。

## 轉變三：膠囊化順帶還掉別的債

搬完之後第三十三條護欄的「缺子節點」少一筆——共用檔那句
`if (!v) return 0` 隨它搬進膠囊，而**新實作丟錯不回 0**。

> **搬家是重寫那一路的機會，而重寫時既有的護欄清單就是檢查表。**
> ⚠️ 但不要把重寫混進搬家的 diff——**搬移不重寫是預設**，
> 要重寫就在另一個 commit，否則對不出基準。

## 轉變四：判定落點的鍵**第二次**出問題，而這次是行號

`specs/110` 修過一次（前 80 字元會碰撞）。這次是**行號**：

從 `cctype/executors.ts` 刪掉一行之後，底下每一筆的行號全部 −1，
於是**所有判定同時變成孤兒，而程式碼一個字都沒改**。

> **識別碼必須識別得出那個東西**——而行號識別的是**位置**，不是東西。

同一個處方第二次用上：**顯示與識別分開**（`檔名#條件的雜湊`）。

⚠️ 而它提醒了一件事：**這個坑會在每一顆膠囊搬家時重演**——
搬家幾乎必然會刪掉共用檔的某幾行。**第 175 次搬家之前修掉它，
比第 175 次之後便宜 175 倍。**
