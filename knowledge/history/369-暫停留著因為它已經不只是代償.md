# 369 · 「暫停」留著，它已經不只是代償

> 日期：2026-11-10
> 轉變：路線圖記著「暫停是 nodeId 不穩的代償，穩定之後回來重看」。
> 改成：重看過，決定留、不縮，行為不動。AI 照推薦，使用者可改。

[152](152-同步從方向變成來源而暫停暴露了第三態.md) 當時說「它是 5b 缺席的代償——5b 之後會縮小，但不會消失」。[364](364-改程式碼之後手排的積木留在原位.md) 把排版用節點身分保住之後，代償那一塊確實小了。

## 還剩的用途

1. 兩邊都要改一陣子，之後再選哪邊算數：`SyncCoordinator` 的 `diverged` 只有經過暫停才進得去。
2. VS Code／Theia 的文件會被 git 或別的編輯器改，收到就重 lift；暫停讓積木先不動（152 的表）。
3. 排版仍保不住的情況：364 在放回去會改掉程式順序時不套用，新增或大改的節點也沒有舊位置可用。

## 為什麼不縮

第 1、2 項是排版以外的事，拿掉會讓分岔那條路消失。第 3 項是剩下的代償，要縮得先知道有人還在為它按暫停，今天沒有這份資料。要重開：學生或使用者的回饋顯示暫停幾乎沒人用，或被按的原因全在第 3 項。
