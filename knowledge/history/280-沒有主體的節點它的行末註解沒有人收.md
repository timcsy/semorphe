# 280 — 沒有主體的節點，它的行末註解沒有人收

**2026-09-21** · 第 218 刀 · 分支 `218-comment-without-body`

## 它從哪來：追一份**我自己寫錯的**債

過程圖那一刀（第 214）留下 13 段畫不出乾淨積木的片段，而我從報表的
**第一行**替其中三段歸了類，寫進 `vision` 的「未清的債」。

逐段讀過之後，**三筆裡兩筆是錯的**：

```
「const 宣告沒有形態」   ❌ 那段裡有 for (…) { ... } 的 literal 省略號，本來就解不開
「for 迴圈仍然降級」      ❌ 那是一個【故意不閉合】的大括號
「帶尾註解的 include」    🟢 真的，而且比我說的更廣
```

> **一筆「已經歸類好」的債，要嘛附上是怎麼量的，要嘛標成「還沒查」
> ——中間那一種（憑印象歸類、寫得像結論）最難發現。**

🔴 而寫進知識庫的錯比寫在聊天裡的貴：**它會被下一個人當成已經查過的結論。**

## 真的那一筆

```
#include <cstdlib>                    →  cpp:include   🟢
#include <cstdlib>    // rand, srand  →  raw_code      🔴 整行變灰
```

⚠️ **兩種模式都中**（`commentsAsBlocks` 開或關都一樣）——所以它是
**既有缺陷**，不是第 216 刀帶進來的。

### 為什麼

那顆註解在 AST 上是 `preproc_include` 的**子節點**（不是兄弟），所以
`liftStatementsWithContext` 那條「同一列的註解」分支**看不到它**
（它看的是 `results` 裡的前一個兄弟）。

而 `attachHeaderComments` 收的正是「掛在節點自己身上的註解」——
它卻在開頭就讓開：

```ts
const body = lifted.slots.body
if (!body) return          // ← #include 沒有主體
```

沒有人收 ⟹ `commentsLost()` 判「這一句裡有註解沒被收進去」⟹ 誠實降級。

> **一條「沒有東西可放就讓開」的路，讓開之後那個東西不會消失
> ——它會變成別人眼中的「掉了」。**

## 修法

沒有主體時，把行末註解掛成節點自己的 `inline` 標註
（產碼用 `cs.trailing` 貼回行末，一個字都沒少）。

⚠️ **這一條兩種模式都走**，而那不是偷懶：[139](139-註解變成一顆看得到的積木.md)
的規則（「一般的 statement 註解在上面，結構的註解在區塊內」）在這裡
**套用不了**——沒有主體可以放，而兄弟清單在這一支裡拿不到。
今天的行為（整行變灰）比任何一種放法都糟。

## 影響面（量過）

```
課文裡「#include ＋ 行末註解」   2 行（cpp-beginner/12-猜數字）
解答／起點檔                     0 支
```

小——**而學生自己在 `#include` 後面打一句註解就會撞到**，
那才是它值得修的理由。
