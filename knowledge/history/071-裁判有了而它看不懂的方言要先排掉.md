# 071　裁判有了——而它看不懂的方言要先排掉，否則數字會腰斬

> 日期：2026-08-17（階段 6.6 ⑤）
> 觸發：clangd 探針過了之後，第一件用得上它的事。

## 轉變

```
old  ⑤「涵蓋率與假警報兩個數字」卡了三天——而卡的是【分母怎麼定義】
     參照編譯器環境相依（macOS clang vs CI gcc），分母在兩台機器上不一樣
new  🟢 跑在瀏覽器 wasm 裡的 clangd【每台機器都是同一個二進位】
     涵蓋率 78%／假警報 0%
```

## 一、⑤ 卡的不是實作

`build-guardrail` 6.8 逐字：

> 「⚠️ 而還有第三個問題，它在單機開發時永遠是隱形的：
> **這個量在別台機器上一樣嗎？**」

`audit-behavior-error` 的不一致筆數在 macOS 是 1、在 CI 是 0
——因為 macOS 的 `g++` 其實是 Apple clang。**一個環境相依的裁判定義不出分母。**

而 wasm 裡的 clangd 解掉的正是這一條。⚠️ **那個好處不是「離線」**
——離線是便利，**這是分母能不能成立**。

## 二、🔴 而第一次算出來的數字是 35%，那是假的

```
涵蓋率 7/20 = 35%      ← 第一版
涵蓋率 7/9  = 78%      ← 排掉「無法確定」之後
```

**13 個缺口裡有 10 個是 Arduino**，而它們報 `undeclared_var_use`
是因為 **wasi 的 sysroot 沒有 Arduino 的核心標頭**——
**不是程式寫錯，是這個裁判看不懂那個方言。**

> **一個裁判的能力邊界，會偽裝成被判者的缺陷。**

⚠️ 而 35% **看起來像一個發現**（`build-guardrail` 6.5：
「數字錯的症狀不是『數字不合理』，是『數字看起來像一個發現』」）。
**「我們只擋得住三分之一」是一句很有說服力的話，而它是假的。**

→ 處置照 `build-guardrail` 第 5 步：**判不出來的歸「無法確定」，不計入任一邊**，
而**理由逐筆寫出來**（Arduino 核心標頭 10／`__gcd` 1）。

## 三、而真正的缺口正好是已知的那兩筆

```
🔴 ⑦ Cout 大小寫    undeclared_var_use_suggest
🔴 ⑧ << 寫成 <      ovl_unresolvable
```

**它們是 `history/064` 就記下的那兩個「放行是對的」的樣本**
——不是語法錯誤，需要型別資訊。⚠️ **所以 78% 這個數字沒有揭露新的缺口**，
它**確認了缺口清單是完整的**。

> **一個量測最好的結果之一，是它證明你已知的清單沒有漏。**

🟢 **而假警報 0/45** ——我們沒有擋下任何 clang 說合法的程式。
`history/017`「加嚴一個檢查可能比不檢查更糟」擔心的那件事，**今天量出來是 0**。
