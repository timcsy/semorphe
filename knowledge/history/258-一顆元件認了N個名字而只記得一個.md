# 258 — 一顆元件認了 N 個名字，而它只記得一個

> 2026-09-19｜`#define` 取的小名，以及方法名的拼法

## 🔴 起點是三句說不出「誰」的錯誤訊息

語料剩下 18 支「解譯器出錯」時，有三支的訊息長這樣：

```
這個東西不能被指定值（它不是一個位置）
這個接收者（不是一個物件）
（不是一個結構）
```

第三句**連主詞都沒有**。而這三句話各自蓋著**不只一個**根因：

| 訊息 | 語料撞到 | 真正的根因 |
|---|---|---|
| 這個東西不能被指定值 | 2 支 | 一支是解析器誤判（[[257]]），一支是 `cpp:logic` |
| 這個接收者不是一個物件 | 3 支 | `pb` 沒人認領、`bitset` 沒有元件 |
| （不是一個結構） | 2 支 | 二維原生陣列的每一格不是結構實例 |

加上身分之後，同樣的三支**一行就招了**：

```
這個東西不能被指定值（它不是一個位置）：cpp:logic
這個接收者.pb() ——「cpp:array_at」不是一個物件（它是 array）。多半是這個方法名還沒有元件認領它。
cpp:array_2d_at.a —— 接收者不是一個結構（它是 int）
```

> **一個說得出「錯了」而說不出「誰」的訊息，
> 讓每一次重複發生都要從頭查一次。**

⚠️ **而我沒有替它蓋護欄，是量過之後的決定**：130 句 `%1` 訊息裡 22 句
沒有內插而用了代稱，而**多數是結構性的**（「這個下標沒有容器」——那時真的
沒有東西可指名）。一刀切會逼人改 22 句沒問題的訊息。
> **一條會逼人改「沒問題的那些」的護欄，會被改成讓它閉嘴的樣子。**

## 🔴 第一個發現：`#define pb push_back` 從第一天就沒有work過

不是迴歸——連**一般的 `vector`** 都不行（`vector<int> v; v.pb(3);`）。

`interpreter/aliases.ts` 那張別名表是**執行期**建立的（`cpp:define` 的執行器填它），
而**身分是在 lift 決定的**：`pb` 在 lift 當下查不到任何方法名，
整句掉到泛用的 `cpp:method_call`，執行期才說「接收者不是一個物件」。

> **一張在執行期才建立的別名表，對「身分是在 lift 決定的」這件事完全無能為力。**

🟢 處方：`lifter.ts` 加 `recordMacroAlias`，與**早就在那裡**的
`recordTypeAlias`（`typedef X Y` → `declare(Y, X)`）同一張表。
⚠️ **不開第二張表**（`lift-context.ts` 的 `getType` 檔頭逐字：
「一個查得到的東西查兩次，比替它開第二張表便宜」）。

⚠️ **而共用一張表要在查詢端加一道閘**：
**原名查不到、而別名查得到**時才換。少了它，一個叫 `size` 的 `int` 變數
會讓 `v.size()` 去查一個叫 `int` 的方法。

> **兩種東西共用一張表是對的；而共用之後，查詢端要自己說清楚它問的是哪一種。**

## 🔴 第二個發現（順手量到的）：認了 N 個名字而只記得一個

要讓 `v.pb(3)` 產回 `v.pb(3)` 而不是 `v.push_back(3)`，得先問
「這顆元件記得使用者寫的方法名嗎」——**不記得**。而那不只影響小名：

```
寫的                  在此之前產回的
v.emplace_back(3)     v.push_back(3)
s.emplace(3)          s.insert(3)
m.emplace(1,2)        m.insert(1)        ← 連引數都掉了
```

> **一顆元件認了 N 個方法名而只記得其中一個，
> 學生寫的另外 N−1 個會被悄悄改寫。**

全庫掃：24 顆元件登錄方法名，**2 顆登錄了不只一個**——所以範圍是可數的。

🟢 修法是一個 `method` 屬性（記原文），而**積木上刻意沒有那一格**：
第五十四條護欄的判定詞彙裡就有「**排版提示，不給學生編輯**」這一類，
與 `python:container_enumerate.start_style` 同一個理由
——**給學生一格下拉會讓一個拼法看起來像一個語義選擇**。

## 🔴 第三個發現：一條「只認 X」的規則，與「只認我想到的那幾種 X」

`define/execute.ts` 的 `literalValue` 檔頭寫著「只認字面量，不認運算式」
——那條線是對的。而它認不得的那幾個**全部都是字面量**：

```
#define z '0'          字元字面值
#define MAXN 1e7       科學記號
#define M 0x3f3f3f3f   十六進位
#define M 1000000007LL 帶字尾
```

> **一條「只認 X」的規則，與「只認我當時想到的那幾種 X」長得一模一樣
> ——直到有人寫出第五種 X。**

⚠️ 解跳脫用**既有的** `unescapeC`（`'\n'` 是兩個字元），不另寫一份。
⚠️ 字元以**數字碼**存放——要與 `cpp:literal_char` 一致，否則
`s[i] - z` 會拿一個字串去減。

## 🔴 第四個發現：同一個病修在一維而沒有修在二維

```
array_declare    2026-09-04  isStruct ? ctx.structs.instantiate(type) : defaultValue(type)   🟢
array_2d_declare            defaultValue(type)                                              🔴
```

`struct P{int a;}; P g[2][2]; g[1][1].a = 5;` 丟「接收者不是一個結構（它是 int）」。

> **同一個病修在一維而沒有修在二維，那不是「還沒做到」
> ——是那兩個地方各寫了一次同樣的迴圈。**

## ⚠️ 我自己又犯了一次「判準裡放了未定義行為」

新增的最小重現寫了 `P g[2][2]; g[1][1].a=5; cout << g[0][0].b;`
——而區塊範圍的 POD 陣列是**未定值**，g++ 印出 `1`。
那個檔的檔頭**逐字寫過同一件事**（2026-09-16 的 `int n, L, c{}`）。

## 讀數

```
              192 之後   193 之後
解譯器出錯       18        17
兩邊都跑完      151       152
🟢 一致         141       142
內容真的不同      7         7
```

⚠️ **官方分母只掉 1**，而實際修好的支數更多——其餘幾支（`7_12`／`7_9_2t`／
`o713`）落在「編不過／參照跑不完」那兩格，**它們不進分母**。
> **一個「修好了幾支」的讀數，要先問那幾支在不在分母裡。**

## 還開著的

🟠 `m.emplace(k, v)`（兩個引數的 map 版）**仍然只收第一個引數**。
   照元件代數「引數個數不同 ⟹ 是身分」，它該是一顆獨立的元件。
   **語料 0 支**（`.emplace(` 在 218 支裡出現 0 次）。
   **何時該修：語料或盲測出現第一支兩引數的 `emplace`。**

## ⚠️ 而這一刀的驗收過程本身出了兩次同樣的錯

e2e 跑了三輪，**每一輪的紅都不一樣**：

```
第一輪（我同時跑了四次 vitest 探針）    4 紅：debug／execution×2／flow-layout
第二輪（我在第 56 支時跑了 tsc）        3 紅：bad-variable-name／execution:80／flow-layout:93
只重跑那三支（完全不動）                 6 綠，execution:80 從 30.1 秒回到 1.3 秒
```

`playwright.config.ts` 的檔頭**早就寫了原因**：

> **一個用固定秒數等待的測試，它的正確性綁在「機器現在有多閒」上
> ——那既讓它慢，也讓它不能平行。同一個病，兩個症狀。**

🔴 而我讀到那句話**是在犯了第二次之後**。

⚠️ **`--retries` 不是處方**：那個檔刻意設 `retries: CI ? 1 : 0`，
理由是「本機重跑會把『這支測試不穩』藏起來」。繞過一個寫了理由的設定，
等於把那個理由也繞過。

🟢 **處方是把「要安靜」的窗口縮到撐得住的長度**：三支 spec 30 秒，
而三十分鐘我撐不住。

> **一個需要「環境安靜」才可信的量測，
> 要嘛縮短它的窗口，要嘛換一個不需要安靜的量測——不要求自己不呼吸。**
