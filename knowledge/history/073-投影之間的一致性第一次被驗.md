# 073　投影**之間**的一致性，第一次被驗

> 日期：2026-08-17（spec `135`）
> 本檔記的是**根公理有一半從來沒有被檢查過**，而那個半邊今天有了機構。

## 轉變

```
old  「唯一真實，各式投影」——而驗的一直是【每一種投影各自】對不對
     R0–R4 可逆性、roundtrip、c-style-parity（編得過）……全部是【單一投影】的性質
new  🔴 投影【之間】跑起來一不一樣，在 2026-08-17 之前【沒有任何東西在看】
```

## 一、那個問題等了一輪，而等是對的

`draft/2026-08-13-C和C++難分難捨.md`§六 逐字：

> 「**編得過只是門檻。** 真正的對照是把兩邊都跑起來比輸出
> ——而那要**等①②修完**，因為今天有 4/10 段編不過，**分母不夠**。」

```
2026-08-13   4/10 編不過 → 分母不夠 → 問不了
2026-08-17   🟢 10/10（spec 134）→ 分母補齊 → 現在問得了
```

⚠️ **而 §二 的教訓正是為這一刻寫的**：
**「分母不夠時，任何『差異為 0』都不算數。」**
昨天若硬問，那個 0 會是一個**假的好消息**。

## 二、答案

```
兩邊都跑得動  9 / 10
🔴 輸出不一致  0
⚠️ 不可判定    1
```

**同一棵語義樹**投影成 C 與 C++，兩邊都編、都跑、比輸出——**逐字相同**。

🔴 **而做法本身是那個證明的一部分**：**同一個樹物件投影兩次，中間沒有第二次
lift**。

> **「切換不改語義樹」最強的證明不是「比對後相同」，是【根本沒有第二棵樹】。**

## 三、而那 1 筆不可判定，是語料本身壞的

`int main` 三個字——某支測試在驗解析器對**殘缺輸入**的行為，
被「抓測試檔裡的反引號字面」一起撈進來了。

> **一個從測試檔撈出來的語料庫，會撈到那些【刻意壞掉的樣本】。**

🔴 **而處置是留在「不可判定」欄，不是篩掉**：篩掉分母會**安靜地變小**，
而**縮分母比修分子容易**（`build-guardrail` 6.5 的同一條）。

## 四、它今天是探測，而它有一天該是護欄

⚠️ 第一次跑之前不知道那個數字（`build-guardrail` 6.5：先跑、確認、最後才產基線）。

🟢 **而它比多數探測更接近護欄**：目標值明確（0），
而 6.8 的第三個問題（**別台機器一樣嗎**）在這裡**天然成立**——
**兩邊在同一台機器上跑同一批，環境相依性抵銷掉了**。

⚠️ 那與 `audit-behavior-error` 的處境相反：那一條的裁判是**外部**編譯器，
所以 macOS 與 CI 給不同答案。**這一條的兩邊都是我們自己。**
