# 一張別名表如果要每一個消費者記得查它，那它保護的是查過的那幾個

2026-09-20｜語料收尾的三個缺陷｜解譯器出錯 10 → 7

## 一句話

> **一張別名表如果要每一個消費者記得查它，
> 那它保護的是查過的那幾個，不是那一族。**

## 事情

第 199 刀合併之後回頭清語料剩下的失敗，逐支追下去修掉三個，而**三個是同一個形狀**。

### 一、`const ll M = 998244353, MX = 1e7;` ——第二個名字整個蒸發

症狀是 `RUNTIME_ERR_UNDECLARED_VAR ｜ MX`（語料 `template/Cn_k.cpp`）。
錯誤指著**使用**那一行，而問題在**宣告**那一行。

```
一般宣告      node.namedChildren.filter(…)   🟢 收得下多個宣告子
const／constexpr  node.namedChildren.find(…)     🔴 只讀第一個
```

🔴 **而這個 repo 已經修過兩次同一件事，每一次修的都是另一支**：

```
2026-09-10  容器的宣告   vector<int> C(n), V(n);    V 蒸發
2026-09-17  自動型別     auto lo = …, hi = …;       hi 蒸發
2026-09-20  const        const ll M = …, MX = …;    MX 蒸發
```

> **一個只寫得出「一個」的讀取器，在遇到兩個的時候不會出聲
> ——它會安靜地讀完第一個就回去。**（2026-09-10 的原話，第三次用上）

這一次沒有再一支一支修：把那條路抽成 `buildOne`，**差別只有跑幾遍**。

### 二、`vector dp(w+1, vector<int>(n+1));` ——樣板引數整段被省略（CTAD）

型別節點是一個**裸的 `type_identifier`**，而容器那條路要的是 `template_type`。
於是它掉進一般的變數宣告，`dp` 變成純量，`dp[1][2]` 說「dp 不是容器」。

修法只推**證得出來**的：填充值是 `vector<int>(n+1)` 這種**呼叫一個樣板**的形狀時，
那個樣板的原文**就是**型別——不需要推論。其餘形狀讓開。

> **一個推導不出來時會猜的推導器，
> 與一個推導錯了的推導器在型別表上長得一樣。**

⚠️ 產回去會把省略的那一段補上（`vector dp(…)` → `vector<vector<int>> dp(…)`）。
那是**正規化不是缺陷**（判準第三層）。🔴 而它與**別名**不同：
`typedef map<…> Graph;` 的 `Graph` 是學生取的名字，展開它等於把它拿掉；
**CTAD 沒有名字可以拿掉**。

### 三、`#define pii pair<int,int>` ——型別名那一側沒有人查別名表

症狀是 `iter[0]（不是一個結構）`（語料 `AP325/4/4_15_3t.cpp`）。
而隔離之後，**問題根本不在迭代器**：

```
pair<int,int> p = {3,4};  p.first   🟢
pii           p = {3,4};  p.first   🔴 「p（不是一個結構）」
```

`pii` 在 `ctx.structs`、`aggregateShapeOf`、樣板引數三張表裡都查不到，
於是 `{3,4}` 變成一串普通的格子——**錯誤要等到有人讀它的欄位才出現**。

🔴 **而同一個檔案的下面 80 行早就對【成員名】做了這件事**：

```ts
if (v === undefined && hasAlias(member)) { const real = resolveAlias(member) }  // #define F first  🟢
const declaredType = String(node.properties.type || 'int')                      // #define pii …     🔴
```

**同一張表、同一個檔案、相隔八十行——一邊查、一邊不查。**

修在**兩個匯流點**，不是十幾個記錄點：
`execVarDeclare` 的宣告型別，與 `evalInitializer` 的目標型別（十幾顆容器
各自把 `elemType` 記下來，而它們最後都走到那一支去把 `{…}` 變成一個值）。

⚠️ 解的是**執行期的型別查詢**，不是把學生寫的名字換掉：產生器讀的是
`properties.type`，`pii p = {3,4};` 產回去仍然逐字相同。

## 判準

**修一個缺陷之前先問：這一族有幾個消費者，而它們是不是各自記得？**

- 「每一個 X 都要記得做 Y」的設計，**壞掉的永遠是最新加的那一個 X**
- 找得到匯流點就修匯流點；找不到就問「為什麼這件事會散在十幾個地方」
