# 「讓開」不是安全的預設——當今天的行為就是那個病的時候

2026-09-20｜第 201 刀（帶參數的巨集）的第二關與第三關

## 一句話

> **「讓開」與「誠實降級」的差別，不在我做了多少，
> 在使用者的程式碼有沒有被改掉。**

## 事情

`#define rep(i,n) for(int i=0;i<n;i++)` 這一族，語料 218 支裡 4 支在用。

第二關（實作）照 `ast-repairs.ts` 的契約寫了三個接手條件，
**缺一就回 `null`，讓開，走今天的行為**——那是那份契約的第一條，
逐字寫著「**回 null 是預設**」。

第三關（round-trip）逐一量「讓開之後長什麼樣」：

```
學生寫的                  讓開之後產回去
go(i,n) s += i;           go(i, n) += i;      🔴 s 不見了
rep(i) s += i;            rep(i) += i;        🔴 s 不見了
```

🔴 **「今天的行為」就是這一刀在治的病。**

## 為什麼會這樣

tree-sitter 對 `rep(i,m) s += i;` **不給 ERROR**——它給一棵看起來合法的樹：
`assignment_expression`，左邊是那個呼叫，而 `s` 被吃掉。

所以「讓開」不是把問題原封不動地留著，它是**把一個已知的巨集呼叫
交還給一棵解錯的樹**——而那棵樹會靜默少一個名字。

> **一個「回 null 是預設」的契約，它的安全性建立在
> 【讓開之後那條路是誠實的】這個前提上。
> 前提不成立時，最保守的那個選項就是最危險的那個。**

## 處置

開頭是一個**已知的**函式形巨集呼叫而證不出展開時，
把那幾句整段降級成 `raw_code`（原文照抄）：

```
誠實降級   go(i,n) s += i;   🟢 一字不差，而執行時會說「這段我不認得」
```

⚠️ **判準是「這個名字是不是一個已知的巨集」**——一個不認得的名字本來就是
一個函式呼叫，把它降級會弄壞一整族正常的程式。

## 這一刀的另外三件事，每一件都是同一個形狀

### ① 墓碑的理由被證偽了一半，而否決仍然成立

`history/014` 的「模擬 C preprocessor」逐字寫著否決理由，而括號裡那句
「**學生程式碼不會用框架巨集**」是一個關於「使用者會怎麼寫」的假設
——218 支裡 4 支在用。

🟢 而它的**另一半仍然成立**（`#` 字串化／`##`／可變引數／遞迴的正確性成本）。

> **一個以「使用者不會這樣寫」為理由的決定，
> 它的有效期等於那句話沒有被量過的時間。**

📌 處置是**在墓碑上補一筆**，不是安靜地繞過它。而同時
`fuzz-cpp-hardware.test.ts` 那根引用它的釘子也要改——它寫著
「墓碑對函式巨集仍然成立」，而那句話已經只對**運算式位置**成立。

> **一根釘子如果寫著一個【已經不成立的理由】，
> 它會在那個理由被推翻的那天繼續擋著。**

### ② 判別要走文字，因為那棵樹是錯的

同一個巨集用法，樹的形狀**隨它後面接什麼而變**（實測）：

```
rep(i,m) s += i;      →  一個 expression_statement
rep(i,m) cin >> a[i]; →  兩個並列的 expression_statement
rep(k,4){ … }         →  一個 expression_statement ＋ 一個 compound_statement
```

> **一棵解錯的樹，它的每一個子節點都會被正確地辨識成錯誤的東西
> ——而照那些子節點去認形狀，等於把解析器的錯當成規格。**

而預處理器本來就在文字那一層工作，所以判別與它同一層。

### ③ 重解出來的那棵樹少了原本那棵的上下文

修復要把代入後的文字重解一次，而**重解出來的樹裡沒有 `#define` 行**。
症狀只在**巢狀的第二趟**出現：

```
第一趟  rep(i,n) rep(j,n) s += i*j;   兩個表頭是並列的語句，一次吃完   🟢
第二趟  rep(i,n) { rep(j,n) { … } }   內層在重解出來的那棵樹裡
        → 查不到 rep → 被當成一個函式定義 → 產出 `void rep(j, n) { … }`  🔴
```

> **一個「把文字重解一次」的機制，重解出來的那棵樹少了原本那棵的上下文
> ——而少的那一塊只在第二趟才被查。**

## 一字不差怎麼做到的

巨集的拼法住在 `metadata.layoutHints`（`macroHeader: "rep(i,m)"`），
而那一格的檔頭逐字：「**投影記住它，積木看不到它**」「積木改過之後這一格會不在，
那時產出預設的排版——**仍然正確**」。

🟢 **而「改過之後就不在」在這個消費者身上是一個【安全性質】**，
不只是可接受的損失：迴圈的界線一旦在積木那側被改過，
再印 `rep(i,m)` 就是一句謊話。

## 量到的

```
解譯器出錯    7 → 4      兩邊都跑完 163 → 166    一致 157 → 160
內容真的不同  3（未上升）  同一棵 218／走樣 0     身分 123 → 124 缺 0
```

⚠️ 順帶修掉一個**與巨集無關**的真缺陷：`s[s.size()]` 在 C++11 起
**有定義**（回空字元），而我們丟越界——語料那一支因此整支停住。

> **一條「超過長度就是錯」的規則，對【剛好等於長度】那一格說了一個
> 標準沒有說的話——而它比標準嚴格的地方，看起來與缺陷一模一樣。**

## 判準

- 寫「證不出來就讓開」之前，**先量一次「讓開之後長什麼樣」**
- 那條路如果會靜默改掉使用者的程式碼，**讓開就不是預設，誠實降級才是**
- 引用一座墓碑的時候，**把它的理由一起讀**——理由會過期，而結論不一定
