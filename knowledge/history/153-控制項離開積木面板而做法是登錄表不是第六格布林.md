# 153 · 控制項離開積木面板，而做法是登錄表不是第六格布林

> 2026-08-25。使用者看到 IDE 的截圖之後：
> 「**Style、語言等等我想要不放在現在這邊，因為放在現在這邊會進積木面板，
> 這樣在 VSCode 不是很好**」

## 一、直覺的做法會爆炸

`HostProfile.features` 當時有五格布林：`fileButtons`／`mobileLayout`／
`codeKeyboard`／`codeEditorPane`／`statusBar`。要搬四顆 picker 出去，
最短的路是再加四格。

⚠️ 而那條路會變成九格——**而它們講的是同一件事**：

> **這顆控制項，在這個宿主投影到哪裡。**

🔴 這就是「唯一真實，各式投影」用在 chrome 自己身上
（[concepts/投影](../concepts/投影.md)）。

## 二、於是：控制項宣告自己是什麼，宿主宣告每一種投影到哪

```
picker      選一個值        → 宿主的狀態列
action      做一件事        → 宿主的分頁標題列
indicator   看一個狀態      → 宿主的狀態列
output      程式在講話      → 宿主的終端機
inspector   執行時看的東西  → 宿主的 panel 區
```

加一顆控制項 ＝ 登錄表加一列，**不是每個宿主各加一格布林**。
而 `features.statusBar` 收進 `controlSurfaces` ——布林 **5 → 4**。

⚠️ 而 `output` 與 `inspector` 為什麼是兩種：它們在網頁版是同一格
（下方面板），**而在 IDE 不是**。表面由 `kind` 決定，所以
「兩個東西的宿主表面不同」＝它們是兩種。

## 三、🔴 而這一刀被自己的護欄擋了三次

| 擋住什麼 | 誰擋的 |
|---|---|
| 投影出去了，而視圖交不出那個能力 | 第六十三條——**同一天上午才蓋的** |
| 又想用一格布林解決一顆控制項 | 同一條的驗收① |
| 組裝點為了一份清單多 import 一次語言套件 | 第六十條的棘輪 10→11 |

第三次的修法是**問已經有它的那個類別**（`BlockStyleSelector.options()`），
不是舉手要豁免。

> **一條擋得住作者本人的護欄，才算擋得住。**

## 四、順帶清掉的重複

執行模式原本散在三處（選單標記／型別聯集／標籤查表），而宿主那側本來要第四份。

> **一份要被抄到第四個地方的清單，它的問題不是「再抄一次」，
> 是它從來就不該是散的。**
