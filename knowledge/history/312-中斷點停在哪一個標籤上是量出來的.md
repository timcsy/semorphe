# 312 · 中斷點停在哪一個標籤上，是量出來的——而 5b 的 e2e 沒量到

> 日期：2026-11-01（spec 185，重構階段 5d）
> 轉變：5b 把執行交給 Cella 時，中斷點直接用語義樹的 id。做 5d（暫停時的板子、改感測器輸入）時，探針在 `delay` 上設的中斷點**不停**——
> 運算式敘述 formalize 之後外面包了一層 `sExpr <id>/stmt`，Cella 停在那一層。5b 的 e2e 沒抓到：它的中斷點碰巧設在指定敘述上。

## 量到的規則（`tests/probes/cella-dap-cost.test.ts` ⑥，逐一設每個標籤）

```
指定敘述   sExpr <id>/stmt → 不停        eAssign <id> → 停，變數在
運算式敘述 sExpr <id>/stmt → 停           eCall <id>   → 不停
其他後綴   <id>/init、<id>/lhs…          → 停在與那一行不相干、或拿不到呼叫框的位置（變數面板空）
```

⟹ 中斷點＝id ＋（有外殼時）`<id>/stmt`；停點回報時收回成 id。

## 途中兩次猜錯

1. 「把 id 名下的**每個**標籤都設上」——契約綠了，e2e 紅：編輯器的一行連到外層的 `for`，`for` 名下的 `<id>/init` 被設成中斷點。
2. 「只設**敘述**（`s` 開頭的建構子）」——契約紅：指定敘述的 `sExpr` 不是停點，它的停點是 `eAssign`。

兩次都是**用推的**決定規則；第三次是**逐一量**出來的。契約多兩條（函式呼叫、迴圈裡的指定敘述）把它釘住，兩個提供者都跑。
