# 141　反白對不上——而它是一條靠「記得呼叫」維持的契約

**日期**：2026-08-24 ｜ **交付**：Python 九顆複合產生器的行號記帳 ＋ 第五十六條護欄
**前一則**：[140](140-第五十五條而它抓到的第一個是護欄自己.md)
**觸發**：使用者——「我還發現有時候 **HighLight 兩邊對不上**」

## 先讀證據，再提假設

[[diagnose-in-browser]] 的第一條是「**看得到的東西不要用猜的**」。
瀏覽器擴充當時沒連上，所以改用**同樣是實測**的路：把對應表印出來。

```
0| x = 1          MAP var_assign  行 0  ✔
1| if x > 0:      MAP var_assign  行 1  ✘ 那是 `if` 的標頭
2|     y = 2      MAP print       行 2  ✘ 那是 y = 2
3|     print(y)   MAP var_assign  行 3  ✘ 那是 else 的 y = 3
```

**區塊裡的每一顆都往上偏一行。** 按下「設定 y 為 2」，反白跑到 `if x > 0:`。

🟢 **而 C++ 那側量出來是全對的**——這個正向錨點很重要：
它證明機制是好的，破的是某一側的實作，不必去翻共用的行號計數器。

## 根因：一條靠「每個實作者記得呼叫」維持的契約

行號由一個共用計數器記，而它只在 `generateNode` 回來時**事後**數換行。
一顆複合節點（`if`／`for`／`def`…）在產生子節點**之前**必須自己把標頭那一行
算進去（`trackOwnText`），否則子節點看到的起始行還停在標頭上。

```
C++    九顆複合產生器  →  每一顆都呼叫了
Python 九顆複合產生器  →  一顆都沒有
```

> **一條靠「記得呼叫」維持的契約，第二個語言進來的那天就會破。**

而它**不會讓任何既有測試變紅**：產出的程式碼一字不差、來回轉換一字不差、
執行結果一模一樣——**錯的只有「按下積木時反白到哪一行」**。

## 第五十六條：把它變成會紅的東西

不變式一句話：**有主體的節點，它的標頭佔掉一行，所以**

```
標頭的行號  <  主體第一顆的行號
```

⚠️ **根節點除外**——`program` 沒有標頭，它的主體本來就從第 0 行開始。
那不是豁免，是這條不變式的前提。

實測誤報率：全語料 140 個有主體的節點，扣掉根之後**誤報 0**。

🟢 **對照實驗**（[[diagnose-in-browser]] 第 3 步）：把其中一顆的修法退掉，
護欄當場報 5 筆；還原，回到 0。**那才是「這條護欄真的在看」的證據。**

## 順手量了另一個方向

「程式碼那一行 → 哪一顆積木」：726 個有行號對應的節點，**沒有積木對應的是 0**。
所以反方向沒有這個病——這一次的偏移只在行號那一側。

## 🟢 瀏覽器實測（2026-08-24，擴充重連之後）

點區塊**裡面**的積木，反白落在自己那一行：

```
輸出 變數 i        → 行 9   print(i)          （修之前會落在行 8）
註解 圓面積        → 行 4   # 圓面積          （修之前會落在行 3 def）
```

反方向也對：游標放在行 5（`return 3.14 * r * r`）→ `python_return` 反白。

全面對照 14 顆語句積木，**每一顆都對到自己那一行**——含函式裡、迴圈裡、
`if`／`else` 裡三層深度。
