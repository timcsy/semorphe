## 轉變

```
old  一顆畫得出來但什麼都不能做的積木
new  🟢 改積木 → 只重寫那一段；貼程式碼 → 積木跟著出來；
     點一邊 → 另一邊亮；單步 → 積木一顆一顆亮；
     組態進專案設定；工具箱與網頁版逐位元組相同
```

## 一、🔴 規劃期量掉的六題裡，**三題的「架構限制」不成立**

```
切分頁太貴          → 13 ms（parse+lift 4.9 ＋ 畫 76 顆 7.9）
selection 事件太吵  → 反查是微秒級的樹走訪
執行要進主行程      → 不用，直譯器留在 Webview ⟹ CJS 那個坑不會回來
```

> **一個被當成「架構限制」的東西，量完之後常常只是一個沒人量過的假設。**

### 而最有價值的一個推論是從量測導出來的

面板跟著 active editor 走之後，那 18 個 per-document 欄位**拆成兩堆**：

```
從文件重算得出來的   → 切分頁時丟掉重建（13 ms）  ⟹ 它們不是狀態，是快取
導不出來的視圖狀態   → 只有這一堆要 per-uri 保存   ⟹ 而它小得多
```

> **一個「per-document 的欄位」，如果從文件本身重算得出來，
> 那它就不是狀態，是快取。**

🟢 **那讓「拆 18 個欄位」這件被視為前置的大工程，整個不必做。**

## 二、🔴 而三個設計結論是**導出來的**，不是發明的

| 結論 | 從哪導出來 |
|---|---|
| undo 怎麼分 | 「積木位置在 VSCode 裡是**外觀**不是真相」 |
| 原生編輯器怎麼接 | 它只是 `ExecutionAtNodeEvent` 的**第三個視圖**（`view-host.ts:94`） |
| `storageService` 怎麼辦 | 它大部分**不搬家，是消失**——第一類資料在這裡有真相了 |

而 undo 那一條展開是：

```
會改到程式碼的積木操作   → 一個 document undo 項
純外觀的操作（拖位置）    → Blockly 自己的 undo，不進文件
```

> **兩個 undo 堆疊不是問題，「兩個堆疊裝同一種東西」才是。**

## 三、🔴 防迴圈：**兩個問題長得像，而它們的性質不同**

```
文字編輯   用【身分】（version 集合）  —— 兩次相同的編輯是兩件事
選取       用【值相等】               —— 選取是冪等的
```

而文字那條升級了一條舊教訓。`experience.md:2866` 記著
「同步宿主用布林旗標就夠，**非同步宿主要加時間**」，
而 PoC 的四處 `setTimeout` 就是症狀。

🟢 `TextDocument.version`「strictly increase after each change, including undo/redo」
讓它**不必加時間**：

> **非同步宿主要的不是「時間」，是一個身分。
> 加時間是在猜「回音應該多久之內回來」——而那個猜測沒有上界。**

⚠️ 而**必須是集合不是單一變數**：連續編輯產生多個版本，事件非同步送達，
只記「上一個」會把先前的回音誤判成外來變更。

**驗收**：`grep -rn "setTimeout" src/vscode/` → **零筆**。

## 四、🔴 我在規劃期量錯了一件事，而它會**靜默地**壞

我量「一次積木編輯動到幾行」時比的是 `generate(原樹) ↔ generate(突變樹)`。
而實際要寫的是**文件**——兩者不相等（排版差異，`history/080`§三 量過）。

> **我量到的是「第 2 次之後的編輯」，而我把它讀成了「所有編輯」。**

拿錯的座標算出的範圍套到文件上，症狀是**改到不該改的行**，而**它不會拋錯**。
處置：拿 `document.getText()` 比。

⚠️ 而 `rewriteSpan` 的測試因此**主斷言是「套用結果逐字元等於 after」**
——一個檢查「跨距看起來合不合理」的測試會放過所有真正的錯誤。

## 五、🔴 而「零 vs 沒有」那條教訓**同一天又咬了一次**

`RewriteSpan` 第一版用 `text: string`，而 `''.split('\n')` 給 `['']`
——**刪掉一行變成插入一個空行**（三支測試同時紅）。

改成 `lines: string[]`：零行是 `[]`，一個空行是 `['']`。

> **一個把「沒有」與「零」編碼成同一個值的表示法，遲早會拿零去回答沒有。**

⚠️ 那條 2026-08-17 才因為 `args0` 長度被寫進 `experience`，
**而它在同一天又咬了一次**——證明它不是一個特例。

## 六、🔴 一個講得通的解釋，與一個正確的解釋，在數字上長得一樣

Phase 4 量到「一次積木編輯重寫 5 行」，我解釋成
「第一次編輯會重排使用者的排版」——**而那個解釋是錯的**。

真正的原因是 `registerCppLanguage()` 沒被呼叫，產生器沒註冊。
加上之後它變成 **1 行**。

⚠️ 而那個缺失**只在第三個功能上現形**：積木與程式碼那兩個方向
看起來完全正常，直到按下單步才噴 `RUNTIME_ERR_UNKNOWN_CONCEPT: cpp:program`。

> **一個講得通的解釋，與一個正確的解釋，在數字上長得一樣。**

## 七、🔴 而全套回歸抓到一個**既有的**缺口，它一直在

`npm test` 紅了一支：第三十一條護欄（形態的殘差）**0 → 0.02%**。

追下去：**我自己測試檔裡的 fixture** 寫了 `std::cout << x + y;`，而

```
cout << 1;        🟢 clean
std::cout << 1;   🔴 unresolved ＋ raw_code
std::string s;    🟢 clean      ← 所以不是「限定名稱」全壞
```

`cpp_cout_chain` 的 `rootMatch.text` 一直是精確比對 `"cout"`。
⚠️ **而既有語料幾乎都寫 `using namespace std;`**，所以它**從來沒有現形**。

> **一個缺口如果只在「大家都不那樣寫」的地方，
> 它會一直在，而且沒有人會發現。**

### 而處置有三條路，兩條是錯的

```
調基線到 0.02%              🔴 把尺改短
把 fixture 改成不會踩到的寫法 🔴 也是把尺改短——curating the corpus
修鏈的根比對                 🟢 而它只是「最後一段相等」
```

⚠️ **我一度走錯過**：先去改護欄的語料抓取（濾掉含中文的候選），
而那**沒有修好任何東西**——只是我以為污染來自散文。撤回了。

> **一個「改了護欄而沒修好任何東西」的變更，就是把尺改短的前一步。**

修完殘差回到 **0%**，並留下 `tests/integration/cpp-qualified-stream.test.ts`
（含一支「不得過度匹配」：`mycout` 不算）。
