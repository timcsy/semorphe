# 205 — 課文有了出口，而它一直都在那裡

> 2026-09-03。使用者問的是「**如何提升 semorphe.com 的 SEO？**」，
> 而查下去發現那不是 SEO 題。

## 轉變

```
舊   lessons/ 的 66 堂課、129,368 字課文，【產品裡零個讀者】
     唯二讀它的是測試（e2e 抽程式碼去跑、護欄檢查段落齊不齊），而它們讀完就丟
新   66 課 → 66 頁靜態頁（＋6 軌 ＋1 索引 = 73 頁），純 HTML、零 JS
     而編輯器與課文【互相指得回去】
```

## 為什麼這不是 SEO 題

Semorphe 是自創詞，品牌搜尋量趨近於零。所以問題不在「排不排得上 semorphe」，
而在**有沒有頁面吃得到問題型關鍵字**——而站上只有一個編輯器，Google 進來看到的
幾乎沒有文字。

🔴 **而更重要的是它對現在的使用者也不存在**：那 13 萬字寫好一週，沒有任何入口。

> **一句「這一刀不做 X，因為 X 還沒拍板」的註解，如果沒有人接手 X，
> 它會安靜地變成「X 不做」。**（`load-lessons.ts:8`，2026-08-27 寫下時是誠實的）

## 形狀

```
產生器      Vite plugin，走【同一份宣告】（parseTrack／parseLesson／order 排序共用）
            ⚠️ 只有「bytes 怎麼拿進來」不同（glob vs fs），而那個差異由護欄對帳
網址        /lessons/ → /lessons/<軌道>/ → /lessons/<軌道>/<課>/
            ?lesson=<軌道>/<課>  ← 編輯器（早就有的深連結）
雙向        靜態頁「在編輯器打開這一課」 ↔ 章節選單「📖 看這一課的課文」
一對函式    lessonIdFromQuery（網址→id）· lessonDocHref（id→網址）住在一起
```

## 而做的過程翻出四個既有缺陷（都不是這一刀造成的）

```
① ?lesson=arduino/… 開出 int main()   建構子裡換的骨架，三個持有者只有一個在
② 狀態列停在上一次的目標               restoreState 無條件蓋掉課程釘住的那幾格
③ 行動版匯不出檔案                     藏起來之後沒有人接手
④ 首次開啟畫布是空的                   ← 這一刀【沒有】修，記進已知問題
```

①②③ 的教訓各自進了 `experience`；④ 在
[`draft/已知工程待解問題`](../draft/2026-03-11-已知工程待解問題.md)。
