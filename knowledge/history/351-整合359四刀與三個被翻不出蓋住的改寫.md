## 四刀各自的選擇

1. **355 sizeof**：對象是運算式時住在接點 `expr`；型別與單一名字留在文字（語法分不出 `sizeof(T)` 的 T 是型別還是變數）。
   積木多一個運算式形態，而**形態軸看接點、不另記屬性**——第一版記了 `operand_kind` 屬性，要在 component.json 寫被禁的 `values`，
   而「對象住在接點裡」本身就是那個事實；另記一個屬性是同一件事的兩份紀錄。⟹ 核心的 `FormAxis` 多一種來源 `from: 'slot'`。
2. **357 C++ → C**：跨語言互轉第一對的反方向（draft〈Lean4 課程與跨語言互轉〉第 4 條：「反方向已經有了」）。量到那句不成立：
   c-bridge 11 支 C 解答走 C → C++ → C 一趟，11/11 reject。補 new／delete → malloc／free（整支全有或全無，同 C → C++ 的第四刀）、
   C 目標不印 `using namespace std;`、struct 標籤補到指標／malloc／sizeof；新護欄 `cpp-to-c-verdict`（課文來回 11 支判決相同）。
3. **358 Cella 0959**：沒有標籤的定義送合成名字 `(unnamed union at <節點>)`、匿名成員是空名的 fld；共用 lift 只問形狀（「帶成員槽的定義」）不問身分。C++ 類別的匿名 union Cella 沒做 ⟹ 照實 unknown。
4. **360 enum class**：列舉多 `scoped`（none／class／struct）與 `base` 兩格（存檔 V31）；一層的非 std 限定名（`Color::Red`）lift 成帶限定的參照、名字交給 Cella；formalize 送 `iEnumClass`（Cella 22:30 那一版起判得出）。

## 三個被「翻不出」蓋住的靜默改寫

每一個都是**某一刀讓一段程式從翻不出變成翻得出**之後才看見的——之前它們一直在，只是那段程式根本沒送到 Cella：

| 改寫 | 被誰蓋住 | 誰讓它露出來 |
|---|---|---|
| `std::endl`（explicit 寫法）→ `unresolved`，C 目標印成一個值 | 量測時沒走 explicit 寫法 | 357 的探針 |
| `enum class Color` → `enum Color`、`: unsigned char` 蒸發 | 來回比對兩邊都是同一棵錯的樹 | 360 準備 Cella 新版時 |
| `L* L::current = nullptr;` → `L* ptr = nullptr;`；`static L* current;` 的星號黏到名字 | `L::current` 是 unresolved，整支翻不出 | 360 讓限定名翻得出 ⟹ Cella 判出一個**錯的 reject**（fuzz_9） |

第三個是 upgrade-cella skill 那句話的另一面：「一個構造從 unsupported 變成支援之後，它背後的下一個問題才看得見」——**這次變成支援的是我們這一側的翻譯**，而誤判 reject 比 unknown 嚴重（P6）。
