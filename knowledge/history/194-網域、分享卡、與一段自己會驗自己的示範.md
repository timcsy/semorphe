## 一、README 少了它最大的賣點

使用者：「我希望把 README 寫的更容易推廣一些……重點是程式碼、流程、積木的**雙向同步**」。

🔴 而量下去發現：**「流程」在 README 裡出現兩次，兩次都是「開發流程」**
——那個視圖從頭到尾沒有被提過。

> **一個功能做完了而沒有人在對外的門面上提它，
> 它對還沒進門的人等於不存在。**

改寫的判準是**分層**，不是刪內容：

```
第一屏   一句看得到畫面的話 ＋ GIF ＋「馬上試」    給【還在評估】的人
中段     做什麼／給誰／⚠️ 現在做不到什麼           給【想用】的人
開發者   怎麼跑 ＋ 十行架構（那張圖有三個箭頭）    給【想改】的人
Agent    讀什麼、照什麼規矩                        給【要動手】的人
```

🔴 而最後那一段**全部是指標，沒有重寫任何規則**——重寫一份就會得到
兩份會漂移的說法，而那正是這個 repo 有護欄在守的病（`dual-truth`）。

> **README 的職責是路由，不是深度。**

⚠️ 賣點也**刻意寫得比「很少人做」保守**：MakeCode 做過積木 ↔ 文字雙向的一半。
站得住的是三件疊起來——三個畫面都能編輯 · 吃真的程式碼不是子集 ·
接不住時它會說。**被抓到一次的過度宣稱，比保守的宣稱傷更多。**

## 三、自訂網域：一格改錯就整片白

`semorphe.com` 指到 GitHub Pages。而這個 repo 有一格非改不可：

```ts
base: '/semorphe/'   →   base: '/'
```

網站原本住在 `timcsy.github.io/semorphe/`，換到根目錄之後
**每一個 JS／CSS／wasm 都會 404**——而 HTML 本身載得起來，
所以「網站有回應」而畫面是空的。

⚠️ 牽連只有三個檔（量過），比想像中小。

🔴 而 `CNAME` **一定要在 `public/`**：這個 repo 用 Actions 部署，
Pages 收的是 `dist/` 那一包。放在 repo 根目錄不會被複製進去，
症狀是「設定裡填了網域，過幾次部署它自己消失了」。

## 四、分頁標題與分享卡

```
舊  Semorphe — 唯一真實，各式投影      給開發者看的公理
新  Semorphe — 程式碼、流程圖、積木，三邊同步
```

那一行會出現在**搜尋結果、書籤、別人的分頁列**上。

而 `<head>` 裡原本**完全沒有 description 與 OG**——把網址貼到 LINE／Discord，
出來的是一條裸連結。⚠️ 補上 `og:image` 時要注意：**它必須是絕對網址**，
而那件事**有了網域才做得成**。

## 五、擴充的發佈管線

`.github/workflows/vsix.yml`：每次推送打包 ＋ 上傳 artifact；**打 `v*` 的 tag 才發佈**。

🔴 不綁每次推送的理由是機制的：版本號必須唯一遞增，而 Marketplace **不能刪版本**。

三個檢查各擋一個具體的災難（產物體檢 · tag 與版本對帳 · 跳過要出聲），
細節長在 `knowledge/skills/ship-extension` 上，不另起爐灶。

⚠️ **Arduino IDE 沒有寫任何東西**：它把擴充市集對使用者關掉了，
而 `ship-extension` §6 已經踩過那條路的坑（Theia 的解壓快取以名字為鍵）。
下一步標成**量測，不是實作**。
