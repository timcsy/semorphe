## 為什麼不用立即呼叫的 lambda

`[&]() { … }()` 只要一個運算式就裝得下，但我們的 C++ formalize 翻不出來（被當成帶樣板引數的呼叫），Cella 判不了。

## 什麼時候可以先算

把生成式提前，等於改了它被算的次數與先後。只在這些情況提前：

- 它所在的敘述是 print、指定、append、return，或 for 的走訪對象——這些都只算一次。
- 那一句的其他部分沒有副作用（呼叫函式、讀輸入、改容器）。否則 Python 先算左邊、C++ 先算了生成式。
- 它不在 `and`／`or`、三元運算子、if 或 while 的條件裡。

兩層的生成式、產生器運算式、集合生成式照實保留。

## 同一刀修掉的

- 生成式的迴圈變數只活在生成式裡（Python 3）：原本會被當成外面同名的變數一起宣告、型別混在一起。
- `sum([…])` 會把引數寫兩次（`accumulate(x.begin(), x.end())`），暫存的那幾行只插入一次。
- C++ 那側：`for (long long x : v)` 走一趟 lift／產碼回來變成 `for (auto x : v)`。`long long` 在 tree-sitter 是 `sized_type_specifier`，不在 lift 認得的型別節點清單裡；改成從 `type` 欄位拿。走訪 `vector<int>` 時兩者意思不同（`auto` 是 int，乘起來會溢位）。互轉那組測試也加上「換出來的 C++ 走一趟回來一字不差」。
