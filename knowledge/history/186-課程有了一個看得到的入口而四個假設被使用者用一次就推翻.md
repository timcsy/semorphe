# 186 · 課程有了一個看得到的入口——而四個假設被使用者用一次就推翻

**日期**：2026-08-28

## 轉移

- **舊**：`lessons/` 有 65 堂課、662 個元件宣告，而 **`grep -rn "lessons" src/` 是零筆**
  ——產品一個字都讀不到它們。
- **新**：狀態列上是 **目標 → 課程 → 章節** 三層，`?lesson=` 也通。

## 為什麼變

`principles.md:97`（P4 漸進揭露的修訂條①）逐字：

> 「**一個過濾機制若沒有附帶「條件從哪來」，它把認知負荷搬家而不是減少。**
>  而那個來源今天缺的是**教材**」

使用者 2026-08-12 的原話是那條修訂的來源：

> 「我會乾脆叫學生把全部都打勾，**那有沒有這個漸進揭露是沒用的**」

2026-08-28 那個來源存在了。這一刀是把它接上。

## 🔴 而三個假設被使用者**用一次**就推翻了

這是這一條最值得記的部分——**三個都是我照著草稿或自己的推論做的，
而它們各自撐不過一次真的使用**。

### ① 「釘住的控制項應該消失」

`draft/教案是一個宣告` 主張：

```
變灰   「這裡有一個你不能碰的東西」→ 仍然是負擔，而且它在嘲笑你
消失   這一堂課裡，那不是一個問題
```

我照做了。使用者選了一堂課之後：

> 「**我發現選了課程之後目標就不見了**」

兩個毛病：他自己拍板的順序是「先選目標再選課程」，而目標消失之後
**那句話只成立一次**；而且畫面上剩「樹上走訪」，**它沒說自己是哪一軌的**。

> **「這個選項已經被替你決定了」與「你看不到它是什麼」是兩件事，
> 而藏起來同時做了兩件。**

🟢 正解是**換目標就退出課程**（課的清單本來就跟著目標走），不是把目標藏起來。

### ② 「選了課才藏教學層級」

第一版讓 `branches` 在選課時消失。使用者看著畫面：

> 「**層級那邊還是沒變？**」

——**沒選課的時候它還在，而它開機就全開**（`層級 5/5`），
也就是一個**只能讓事情變糟**的控制項。

> **一個「有課才藏起來」的東西，等於承認它沒有課的時候也不該在。**

🪦 它整顆退場，改成**預設全開**（工具箱 20 種 → 186 種）。
而它等了 65 堂課才退——**取代品不存在之前，那顆不能拆**。

### ③ 「課的可見集合就是課宣告的那幾顆」

使用者：「**為何積木變這麼暗？**」

根因是那個交集把**系統自己產的鷹架**（`#include`／`using namespace std;`）
也濾掉了，於是 `markOutOfScopeBlocks` 把它們打成 0.35 透明。

> **畫面在對學生說「這顆不該在這裡」，而那顆是工具自己放的。**

⚠️ 而**第一版的修法也放錯層**：補進 `getVisibleComponents()` 的話工具箱也跟著
多出 `#include`。那個函式有**兩個消費者，而它們要的不是同一件事**：

```
markOutOfScopeBlocks   畫布上哪幾顆被打暗   → 鷹架【要】在（它是工具自己放的）
buildToolboxInner      拖得到什麼           → 鷹架【不要】在（第 1 課不教 #include）
```

🟢 而那個區別 `buildToolboxInner` 的註解**本來就寫著**：
「能力過濾只加在這裡，不加進 `getVisibleComponents()`」。

### ④ 「預設全開只會改到可見元件」

拆掉 `branches` 之後把預設改成全開（使用者拍板過），而 `e2e/debug.spec.ts` 紅了：
**斷點停得住，而變數面板是空的**。

根因是 `enabledBranches` 同時扛了**兩個決定**：

```
哪些元件看得到     ← 使用者說的「預設全開」是這一個
鷹架露到第幾層     ← getScaffoldDepth() 也讀它：0 剝掉 · 1 幽靈 · 2+ 可編輯
```

於是「全開」把鷹架從**剝掉**變成**可編輯**，而那不是任何人要的。

> **兩個決定共用一個載體時，改動其中一個永遠會偷偷改到另一個。**

⚠️ 而它**有兩份實作**（`ui/app.ts` 與 `core/sync-controller.ts` 各一份）
——兩份都讀同一個集合的時候它們碰巧一致，所以那個雙重真相一直沒有出聲。
只修一份的話症狀不會消失，而**看起來像修錯了地方**。

🟢 拆開之後兩邊都固定 0（那本來就是舊的預設），
而**升高它的入口沒有了**——需要露出鷹架的那天，來源要是**課**，
不是一個沒有人答得出來的打勾清單。

⚠️ 順帶：第三十九條的「方法呼叫數」2385 → **2383**。那是**真的少了兩個呼叫**
（走一遍層級樹 → 固定回 0），不是把檔案排除在掃描外。

## 三層是使用者推出來的，不是設計出來的

```
①「課程要去哪裡找？」                        → 補了「課程」那一顆
②「課程可以再拆分成課程和章節，目標可以更單純一些」 → 拆成三層
```

拆完之後：

| | 是什麼 | 幾項 |
|---|---|---|
| **目標** | 語言／板子 | 11（原本 13，混著兩個軸） |
| **課程** | 軌道（`lessons/<軌道>/track.json`） | 6 |
| **章節** | 課 | 那條軌道的 5–15 章 |

🔴 `cpp-advanced` 與 `arduino`（不指定板子）改成 **`listed: false`**
——它們仍然是完整的目標，只是**只由課程進得去**：前者其實是一條軌道，
後者是一個陷阱（`LED_BUILTIN`／`A0` 都不存在，而 Arduino 第一課的第一行就用它）。

## 留下什麼

| | |
|---|---|
| `core/lesson.ts`／`core/load-lessons.ts` | 宣告的解析與載入；不碰 DOM、不碰 `location` |
| **第八十四條** `audit-lesson-loadable` | 65 堂 ＋ 6 條軌道**產品都載得起來**（硬性零） |
| **第八十五條** `audit-target-menu` | 每個目標都宣告過 group／order；**沒有板子的硬體必須有 hint** |
| `e2e/lesson-pins.spec.ts` | 三層選得到、被釘的消失／該留的留、**一顆積木都不打暗** |
| QuickPick 的 `group` | 組名換的時候插一列標題；不可選、不參與搜尋 |
