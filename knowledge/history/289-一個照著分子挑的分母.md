# 289 · 一個照著分子挑的分母，那個比率不回答任何問題

> 日期：2026-09-26（第 265 刀）

> 換成 **`{ covered: 2, of: 64 }`**，而那個 64 是量出來的。
> 新增 `tests/probes/formalize-residual.test.ts`（語料 ＋ 棘輪兩個機制）。

## 原本那個讀數

第六路（`formalize`）落地時（第 245 刀）填的是 **2 / 2 ＝ 100%**。
它不是造假——**那兩顆真的都被 cella 判過**（`cpp:compare`、`cpp:array_at`）。

而那個分母是「**已經寫了形式核的**」。於是：

```
寫第三顆形式核  →  3 / 3  仍然 100%
一顆都不寫      →  2 / 2  仍然 100%
```

> **一個照著分子挑的分母，那個比率不回答任何問題
> ——而它長得跟一個滿分一樣。**

⚠️ 它與同一張表上 `execute` 的 `of: 210`、`generate` 的 `of: 349` **不同體例**：
那兩個的分母是「那一路真的要走的那些」。

## 量出來的

拿課文的 88 支解答（它們就在這個 repo 裡）當母體，跑走訪器：

```
母體 B（宣告）   用到 64 顆 cpp 身分,宣告了 paths.formalize 的 2 顆
母體 A（形狀）   105 個函式,產得出項的 0 個 —— 殘差 100%
```

🔴 **兩個母體刻意分開**，因為它們是兩件事：支援一個新形狀會動 A 不動 B，
寫一顆形式核會動 B 不一定動 A。合起來的話「做完了沒」問不出答案。

## 🔴 而最大那一格原本不指路

95 / 105 落進同一句「今天只認得『一個 if 加一個結尾 return』那個形狀」
——那是**同一個 throw 點**，一句套套邏輯。
`build-guardrail`：**一叢違規看起來像一個根因，而那是假設不是結論。**

拆開之後（看那些函式 body 頂層有什麼）：

```
92 / 95  cpp:return        多個 return / 不在結尾
61 / 95  cpp:print         ← I/O
50 / 95  cpp:var_declare   區域狀態
24 / 95  cpp:loop_count    迴圈 ＝ 要不變式
17 / 95  cpp:input         ← 讀輸入
```

⟹ **課文的解答是「有副作用的 main」，不是「純函式」。**
缺的不是語句形狀，是**效果模型**——而那是原本的驗收標準沒有說到的東西。

🟢 於是又量了一個決策級的數字：**不碰 I/O 的函式 15 / 105**（上界），
而那 15 個**全部接不住**（形狀 10 · 型別 3 · 運算子宣告 2）。
棘輪收的就是它：15 → 0。

## 這一刀改了兩個我自己的判斷

**① 它不該是探針的形狀。** 規劃時我寫「不進 `npm test`，所以不給棘輪」，
而 `vitest.config.ts` 的 `include` 收的是 `tests` 底下**所有**的 `.test.ts`
——`tests/probes/` 本來就在裡面。前例看起來沒人跑，是因為它們缺
`STUDYCPP_DIR`／`CELLA_BIN` 就跳過，而**這一支不需要任何外部工具**。

> **「它是探針」講的是它住哪個目錄，不是有沒有人跑它。**

**② 驗收標準的尺寸。** 第一個框寫「一支完整程式」，而量測說那要效果模型。
🟡 **而那個框沒有改**——一個被量測推翻的驗收標準，改它的人是使用者。
vision 那一格記下了讀數與提案，框留在原處。
