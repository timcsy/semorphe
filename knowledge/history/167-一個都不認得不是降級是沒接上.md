# 167 · 一個都不認得，不是降級，是沒接上

**日期**：2026-08-26

## 起點

「核心可獨立出貨」的子項逐字：

> 「膠囊的 lift 策略、產生器（`pack.install()`）今天都要消費者自己登記，
>  而**漏掉的症狀是降級不是錯誤**：`if` 變 `unresolved`、產出變 `⟨unknown component⟩`」

而 `examples/bring-your-own-view/src/main.ts` 是那個症狀的現場，
它的兩段註解各自寫著「少了這一步……**而程式不會報錯**」。

## ③ 收成一個入口

`componentLiftStrategyRegistrars()` glob 的是 `components/*/*/lift-strategy.ts`
——**所有語言的膠囊**。而它的唯一呼叫點在 `languages/cpp/lifters/index.ts` 裡。

> **一個語言中立的登記掛在 C++ 的名字底下。**

於是只用 Python 的宿主拿不到它，而症狀是 `if` 安靜降級成 `unresolved`。

改由 `LiftStrategyRegistry` 的**建構子**自己長出來。理由不是「這樣比較方便」：

> **一份每個組裝點都要記得做的登記，就是一個還沒收起來的入口。**

⚠️ 而語言**自己的**策略（`registerCppLiftStrategies`）仍然由語言套件註冊
——那本來就該掛在它的名字底下。收的只有**膠囊**那一批。

## ④ 出聲——而第一版做錯了，被一支既有測試擋下來

`⟨unknown component: X⟩` 對**單一節點**是誠實降級（P6：不要弄丟任何節點）。
而**沒有任何產生器**時它會套用在**每一顆節點**上——那時看起來像語義樹壞了，
其實是組裝點忘了 `pack.install()`。

第一版：`if (!factory) throw`。**當場紅**——`comment-projection-snapshot.test.ts`
釘著 FR-014「沒有語言套件時，註解不得無聲消失」，而 throw 把內容**整個弄丟**。

> **一個為了「不要安靜失敗」而加的錯誤，如果它讓內容消失，
> 那它比安靜失敗更糟——那正是 P6 要擋的反面。**

而兩者分得開，分界是**那個語言有沒有套件**：

```
套件不存在        未知語言      → 誠實降級，保住內容（既有契約）
套件在而沒產生器  忘了 install  → 出聲
```

> **一個從來沒被宣告過的語言，與一個宣告了而沒接上的語言，
> 產出同一種字串——而只有後者是缺陷。**

## 驗收

例子的 `main.ts` **刪掉那一行**，而第五十八條護欄（硬性零：非 Vite 的宿主
跑得通雙向轉換）仍然綠。新增 `tests/integration/assembly-speaks-up.test.ts`
釘住那個**分界**（3 支，含反面那一支）。

## ⚠️ 而 ② 沒有做——它是自己一刀

那個例子還照出第三件事：`CodeParser.parse` 是**同步**的，而每個真的 parser
都是非同步的，於是**兩個消費者各做了一份一模一樣的 shim**。

> **一個介面如果每個實作者都要在它前面加同一層轉接，
> 那層轉接就是介面的一部分。**

它動的是同步路徑，而這個 repo 的教訓是那條路上的錯**測試全綠也看不到**。
已開成路線圖項目並附驗收。
