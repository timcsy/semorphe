# 第三個宿主一直都在，而它只讀另一格

**日期**：2026-09-10
**回報**：使用者在 GitHub Codespaces 的截圖
**畫面上**：`command 'semorphe.openBlocks' not found`

---

## 指令不是壞了，是擴充沒有啟動

`ship-extension` 這支流程從頭到尾想著兩個宿主：

```
VSCode 桌面版      main → node 擴充主機
Arduino IDE        同上（Theia）
```

而**第三個一直都在**：

```
vscode.dev · github.dev · 瀏覽器裡的 Codespaces  → web worker 擴充主機
```

它**只讀 `browser` 那一格**。manifest 裡沒有那一格，所以擴充在網頁版裡
從來沒有被啟動過——指令沒有註冊，而使用者看到的只有一句
「找不到那個指令」。

> **一個只宣告了 `main` 的擴充，在網頁版裡不是「壞掉」——
> 它是【不存在】，而畫面上只看得到一句「找不到那個指令」。**

---

## 🟢 而它本來就跑得動

量了一下：`src/vscode/` 底下**一個 node 內建都沒用到**
（`fs`／`path`／`child_process`／`os` 全部是零）。
用到的 VS Code API 只有三種，而它們在網頁版全部支援：

```
Uri.joinPath · asWebviewUri · localResourceRoots
```

所以**這是建置的事，不是重寫**。加第三個 vite 目標（`platform: browser`、
`formats: cjs`、輸出 `extension.web.js`），72 KB，一次就過。

⚠️ 兩份產物**不能共用一個檔**：node 那份是 `platform: node`。
共用的話 worker 裡找不到 `process`／`require`，而那是執行期才炸的。

---

## 🔴 為什麼一直沒有人發現

因為**沒有人在網頁版裡開過**。

桌面版的預檢（`tools/vscode-preflight`）在 Chromium 裡跑一個會回話的假宿主
——它驗得到「面板畫得出來」，而**它連擴充主機都沒有**，所以那一格的缺席
它一個字都說不出來。

> **一個宿主如果沒有人在上面跑過一次，它的問題不會出現在任何一份報表上
> ——它會出現在使用者的截圖裡。**

🟢 而驗它其實很便宜（`@vscode/test-web` 起一個真的網頁版 VS Code）：

```bash
npx @vscode/test-web --extensionDevelopmentPath=build/vscode <一個資料夾>
```

實測走完整條路：指令找得到 → 面板開得起來（工具箱十一類都在）→
開 `.cpp` 檔面板接上 → 編輯器打字，積木那側長出 `Print "web!" newline`。

## 交付

```
manifest       多一格 browser: './dist/extension.web.js'
vite           第三個目標 extension-web（platform browser · cjs）
build script   多跑一次
CI 產物體檢     多 grep 一個 extension.web.js
版本           0.18.0 → 0.19.0（⚠️ VSCode 以 (id, version) 快取 contributes）
```

第一百二十一條護欄 `web-extension-host`，其中一條是**硬性零而它守的是未來**：
`src/vscode/` 不得 import node 內建。今天是零，而下一個人加一行 `import fs`
不會有任何東西出聲——直到有人在網頁版裡打開它。

⚠️ 那條護欄的產物檢查在沒建過時會跳過，而**跳過不是靜默的**：
它會去確認 CI 那一側有守（`vsix.yml` grep `extension.web.js`）。
一條在 CI 上永遠跳過的檢查，與一條不存在的檢查是同一個東西。
