# 168 · 那層轉接就是介面的一部分

**日期**：2026-08-26

## 起點

`CodeParser.parse(code): { rootNode }` 宣告成**同步**，而**每一個真的 parser
都是非同步的**（要抓 wasm）。於是**兩個消費者各做了一份一模一樣的轉接**：

```ts
const shim = { tree: null, parse(_code) { return { rootNode: this.tree } } }
// 先在外面 await 解析 → 把結果塞進去 → 再呼叫
```

一份在 `examples/bring-your-own-view/src/main.ts`，一份在 `src/ui/app.ts:616`。

> **一個介面如果每個實作者都要在它前面加同一層轉接，
> 那層轉接就是介面的一部分。**

## 這一刀不是「把同步改成非同步」

那個非同步**本來就在跑**——`app.ts` 的 wrapper 幾週前就是
`parserFor(語言).then(p => p.parse(code)).then(...)`。這一刀是
**把一段已經在跑的非同步搬進介面裡**，所以順序風險比看起來小。

改動：`parse` 回 `Promise`｜三個呼叫點 `await`｜`handleEditCode`／
`resyncForTopic`／`syncCodeToBlocks` 變 async｜兩份 shim 刪除。

⚠️ `syncing` 這個**重入守衛**的窗口因為 `await` 變長了，而 `try/finally`
本來就包住整段——設定與清除都在外面，不必改。

## 🔴 而它逼出一個真的不對稱

例子原本是 `bus.emit('edit:code', …)` 之後**同步讀樹**。解析變成非同步之後，
那個處理器也是非同步的，而 `emit` **沒有完成訊號**。

> **一個非同步的處理器掛在一個 fire-and-forget 的事件上，
> 發送端就沒有辦法知道它做完了沒。**

處置：要等的人走**可等待的那一支**（`await sync.syncCodeToBlocks(code)`），
`emit` 留給「不需要知道何時完成」的那些。
⚠️ 五支單元測試也是同一個形狀（`emit` 之後同步斷言）——**它們紅了，
而那正是這個改動該逼出來的**：測試裡的 `emit`-then-assert 與例子裡的
是同一個假設。

## 驗收

- 兩個消費者都不再包 shim；第五十八條護欄（硬性零：非 Vite 宿主跑得通
  雙向轉換）**仍然綠**
- 🔴 **瀏覽器實測三條路**（這條路上的錯測試全綠也看不到）：
  ```
  以此為準：程式碼   輸入驗過（9 行、含 cout）→ 十二種積木
  切 Block Style     12 種積木都在、程式碼沒被動
  以此為準：積木     把積木上的 s 改成 total → 程式碼跟著變
  ```

## ⚠️ 而 `app.ts` 的 wrapper 留著

它剩下的職責**不是轉接**：補相依、保游標、清三個旗標——那些是**組裝點的事**。

> **拆掉一層轉接，不等於把那個位置清空。**
