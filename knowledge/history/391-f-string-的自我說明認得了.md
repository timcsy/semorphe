## 為什麼只收名字與屬性鏈

Python 印的是運算式的**原文**：`{x+1=}` 印出 `x+1=`。而我們產回去的文字是從語義樹**重新產生**的，`x+1` 會變成 `x + 1`、單引號會變成雙引號——印出來的東西跟著變。名字與屬性鏈是產碼不做任何正規化的兩種，所以原文與產回去的文字一定相同。

`{` 與運算式之間的空白、`=` 兩側不對稱的空白也會被印出來，而積木的下拉只放得下 `=` 與 ` = ` 兩種，所以其他空白照舊降級，不收一半。

## formalize 怎麼送

CPython 的 AST 本來就把 `f"{x=}"` 拆成兩段：字面 `x=`，接一個插值。沒寫轉換也沒寫格式時，那個插值的轉換預設是 `!r`（所以字串印出來有引號）；寫了格式時預設不轉換。`python.ts` 的 `fstring` 展開照這個規則送，字面那段的原文由語義樹算：名字取 `name`，屬性鏈逐層接 `.member`。

學生在積木上把那一格換成別的運算式時，我們算不出 Python 會印的原文，那一格照實標 unknown，不猜。
