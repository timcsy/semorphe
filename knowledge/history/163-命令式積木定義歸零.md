# 163 · 命令式積木定義歸零——而最後一格機制是「一個看不見的差異」逼出來的

**日期**：2026-08-26

## 結果

```
src/ui/block-registrar.ts 的 `Blockly.Blocks[...] = {`   →  0
block-def-parity   一模一樣 0 ｜ 有差異 0 ｜ 宣告是空殼 0
dual-truth         動態註冊 0 ｜ 兩處都有定義 0
```

最後一顆是 `cpp_var_declare`，連同它的三顆齒輪子積木（`u_var_declare_*`）。

## 這一刀補了三格參數，而**沒有**新建構子

前一天我把它判成「需要一個還不存在的建構子」——那個判斷重了（`history/162`）。
實際差的是 `paramList` 的三格：

```
valueInput            那一段的結尾是【接點】而不是欄位群
  .replacesItem       而且它【取代】那一格本身，不是在後面多一列
itemsAs               存檔照舊寫成 { items: ['var_init','var'] }
defaultOpen           新加出來的那一格預設就是「有初始值」
```

`itemsAs` 是這裡最省事的一格：`{items}` 與 `{paramCount, paramOpts}`
**攜帶同一份資訊**，而用它原本的形狀寫出去，**舊存檔一份都不必遷移**。

## 🔴 `replacesItem` 是被一個「使用者看不見的差異」逼出來的

補完前兩格之後比對報表只剩一行：

```
插槽  HEADER,INIT_0,TAIL   vs   HEADER,VAR_0,INIT_0,TAIL
```

`paramList` 預設會建「那一格 ＋ 選用段」**兩列**，而命令式那份一格
**要嘛是接點要嘛是啞輸入，never both**。而 `inputsInline` 之下**兩者畫面一樣**。

當下有一條便宜的出路：把 `differ` 棘輪從 0 上調到 1，附一句
「這個差異使用者看不見」。而那條路**與「把宣告改成跟命令式一樣讓比對變綠」
是同一件事的鏡像**——前者改宣告去迎合量測，後者改量測去迎合宣告。

> **一個使用者看不見的形狀差異，仍然會讓那顆命令式定義退不了場
> ——而上調棘輪吃掉它，是在把量測改成自己的形狀。**

於是補了 `replacesItem`：那一格的**輸入種類**由齒輪決定，換形態＝重建那一格。

## 🔴 而重建那一格時，第一版把使用者的積木弄丟了

`setOptional_` 第一版只 `disconnect()`——關掉 `x = 1` 之後那顆 `1`
**浮成工作區裡的一顆孤兒積木**，而再打開時是 `x = ?`。
⚠️ 命令式那份更糟：`removeInput` 直接把它 dispose 掉。

而這個檔自己的 `setBlockOption_` 就寫著

> **一個救不回來的動作，不該藏在一個勾選格後面。**

改成**寄放**（序列化存著、關掉時 dispose、再打開時接回來）。
瀏覽器實測：關掉 → `x`（頂層積木數不變，沒有孤兒），再打開 → `x = 1`。

> **一條寫在同一個檔案裡的規則，擋不住三十行以外的自己
> ——它要有一支會紅的測試才擋得住。**（已補，注入驗過）

## 這一輪的六顆之後，第七顆的性質

前六顆（`history/160`）驗證了「宣告的詞彙表封頂了」——只補一格擺法參數。
**第七顆推翻了它**，而推翻的方式是有價值的：缺的不是一個新概念，
是既有機制的三個維度（值的種類、擺法、預設）各差一格。

> **「詞彙表夠不夠」問錯了問題。夠的是【概念】，不夠的是【參數】
> ——而那兩者的成本差一個數量級。**
