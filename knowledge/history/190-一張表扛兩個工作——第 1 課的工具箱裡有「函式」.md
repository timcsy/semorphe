# 190 · 一張表扛兩個工作——第 1 課的工具箱裡有「函式」

**日期**：2026-08-28
**前一步**：[189](189-骨架——把「外框」改名，因為 Arduino 上它名不副實.md)

## 轉折

使用者：「**為何在工具箱還看得到函式？**」（C++ 入門第 1 課）

那一格裝的是 `cpp:func_def` 與 `cpp:return`，而它們在 `lesson.json` 的
`components` 裡。量完之後：**65 堂課每一堂都列著這兩顆**
——因為每支程式都有 `int main(){ … return 0; }`。而**真正在教函式的只有一堂**。

## 根因：一張表扛兩個工作

```
lesson.components  ① 這一課的積木要畫得出來    → 必須含 func_def（不然 main 畫不出來）
                   ② 學生從工具箱拿得到什麼    → 不該含 func_def
```

⚠️ 而**現有機制已經處理了一半**：`getVisibleComponents` 把 `scaffold` 性狀的
元件（`#include`／`using namespace`）放進範圍、擋在工具箱外，那段註解逐字寫著
「第 1 課不教 `#include`，學生不該拖得到它」。

漏的是**性狀答不出來的那兩顆**：

```
cpp:func_def   沒有 scaffold 性狀——它不是「一顆鷹架元件」，
               它只是【剛好是骨架的進入點】
cpp:return     是 scaffoldInMain（只有在 main 裡才是骨架），而那個性狀沒被算進去
```

> **性狀說的是「這顆元件是什麼」，而這裡要問的是
> 「這一塊在【這棵樹的這個位置】上是什麼」——那是節點的事，不是元件的事。**

## 🟢 而它現在第一次答得出來

[188](188-Arduino要腳手架而它逼出了「哪一塊是外框」的第六份實作.md) 讓骨架宣告了
`entryFunctions`，於是 `scaffoldNodeIds()` 已經在算「畫布上哪幾塊是骨架」。
範圍改成 `lesson.components ∪ 骨架節點的元件`，而 `lesson.components`
回到它該有的意思：**學生要動的東西**。

45 堂課的 `components` 因此各少了 1～3 顆（`func_def`／`return`／`literal_number`），
而**一堂都沒有壞**——它們照樣畫得出來，只是拿不到。

⚠️ 判準是從**每一課自己的程式碼**量出來的，不是憑印象刪：
「有沒有一顆不叫 `main`／`setup`／`loop` 的函式定義」「有沒有 `return 0;` 以外的
`return`」「有沒有 `return 0` 以外的數字」。`arduino/07-測距離` 因此保住了
它的 `func_def`（它有一顆 `distance()`）。

## 同一輪的第二個問題，答案是「它是宣告的」

使用者同時問：「**為何我選 C++ 的第一門課骨架不是隱藏的？**」

`track.json` 逐字 `"scaffold": "ghost"`，理由也寫著：「第 1 課教 main」。
而第 1 課的 `lesson.md` 確實有一整節在教它。**那不是漏接，是照著教案挑的。**

拍板（使用者選）：**前三課 hidden，第 4 課才 ghost**，而第 4 課是新寫的
「程式從哪開始」——把 `main`／`#include`／`using`／`return 0` 一次拆開的那一課。
原本第 1 課那一節搬過去了，04～15 課順延成 05～16。

⚠️ 順延動到 **27 處**「第 N 課」引用（含 10 處跨軌道的「C++ 入門第 N 課」），
而其中一處是陷阱：`16-函式與遞迴` 裡的「**Python 銜接第 6 課**」不能動。

> **一個「第 N 課」的引用，指的是哪一條軌道的第 N 課——
> 而那件事只寫在它前面那幾個字裡。**
