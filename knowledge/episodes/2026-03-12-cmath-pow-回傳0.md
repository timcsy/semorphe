# pow() 算出 0：測試全綠的概念，執行起來是空的

> 日期：2026-03-12

## 為何值得回憶

這是「**所有測試通過**」和「**功能正確**」之間那道縫隙的最清楚示範。它改寫了第一性原理對「概念完整」的定義。

## 現象

為 C++ `<cmath>` 新增概念支援，完成 lift、render、extract、generate 四路，round-trip 測試全數通過。使用者按下「執行」，`pow()` 計算結果為 `0`，二次方程式解出錯誤答案。

## 追下去看到什麼

「執行」按鈕不是呼叫 C++ 編譯器——它用 `SemanticInterpreter` 直接走訪語義樹。每個概念需要在 `src/interpreter/executors/` 中有對應的 executor。

`cpp:math_pow`、`cpp:math_unary`、`cpp:math_binary` 三個概念完成了四路，但**沒有註冊 interpreter executor**。而 interpreter 遇到找不到 executor 的節點時，原本的邏輯是：

```typescript
if (concept.includes(':')) return   // ← 靜默跳過所有語言特定概念
```

於是 `pow(discriminant, 0.5)` 在語義樹中被正確提升為 `cpp:math_pow` 節點，執行時回傳 `undefined`，經 `evaluate()` → `defaultValue('void')` → `toNumber()` 轉成 `0`。

```
語義樹正確 → round-trip 測試全過 → 使用者執行 → 結果錯誤
                                                  ↑ 沒有任何錯誤訊息
```

## 權衡過什麼

那行 `if (concept.includes(':')) return` 當初有它的道理：直譯器是通用的，語言特定概念本來就「不歸它管」。問題在於「不歸我管」和「我不知道這是什麼」被寫成了同一件事。

修法有兩個層次的選擇：

**要不要讓未知概念直接拋錯？** 否決了。學習場景中，使用者可能正在寫一段系統還不支援的程式碼——直接中止執行是把系統的能力邊界變成使用者的錯誤。改為透過 `unknownConceptHandler` 通知使用者，**由使用者決定**跳過或中止（這是 Agency 維度的職責）。

**宣告性概念（`#include`、`using namespace`、註解）要不要註冊 executor？** 它們確實不做事，看似可以繼續跳過。但那樣就無法區分「已知不執行」和「未知」——兩者在「沒有 executor」這件事上長得一模一樣。最後決定**註冊 noop executor**：多寫幾行，換到一個可判別的狀態。

## 用了哪些概念

- [元件代數](../concepts/元件代數.md) — 路徑完備性；可執行 / 宣告性 / 未知概念的三分
- [降級與認知邊界](../concepts/降級與認知邊界.md) — 靜默失敗反模式
- [三維錨定](../concepts/三維錨定.md) — 未知概念的處置權屬於 Agency 維度

## 結果

- 四路完備性擴充為五層，第一性原理 §2.2 因此修訂 → [history/011](../history/011-四路完備性擴充為五層.md)
- 教訓「四路完備性不等於可執行」進 [experience.md](../experience.md)
- 新概念的檢查清單加入「每個可執行概念都註冊了 interpreter executor，宣告性概念註冊 noop」

**後續驗證了這條清單的價值**：隔天 `60a6b49` 補上 cmath 遺漏的 trunc/cbrt/hypot executor、`0ffc6e9` 補上 `var_declarator` executor、`a65a267` 為 `<cstring>` 概念一併加上 executor——執行層從此和其他四路一起被記得。
