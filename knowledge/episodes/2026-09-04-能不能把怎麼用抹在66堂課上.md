# 「能不能把怎麼用抹在 66 堂課上」——而答案的第一句是不要

**2026-09-04** · 一個請求，一句拒絕，與一個「腳本錄的東西會過期就變紅」的理由。

> 使用者：「能不能重新規劃**所有課程**，加入 Semorphe 怎麼使用，讓使用者習慣，
> 不知道是否可以搭配腳本錄製 GIF 說明，這樣使用者比較知道要拉哪裡。
> 還有，**點擊時滑鼠是可以被錄製到的嗎**？」

## 先回答滑鼠：預設錄不到，而我們可以自己畫

Playwright 錄的是**頁面內容**，作業系統的游標**不在裡面**——所以在此之前那四支
示範，畫面會自己動而**看不到誰在動它**。讀者只知道「有事情發生了」。

🟢 而 `mouse.move`／`click` 送的是**真的 DOM 事件**，所以頁面裡一個 listener
就收得到座標。一支 `withCursor(page)`，每支錄影開頭呼叫一次，
**不必改腳本其餘的內容**。

⚠️ 三個坑（現在都寫在 `tools/demo/with-cursor.ts` 的檔頭）：
`pointer-events:none` · `mouse.move` 要帶 `steps` · **capture 階段監聽**
（Blockly 與 Monaco 會在冒泡途中攔下事件）。

🔴 而 draft 當時把最後那個列為「**待實測**：假游標在 Blockly 的 SVG 與拖曳層上
會不會被吃掉」——**它真的會**，而解法是 capture 階段。

## 而請求的主體被拒絕了

「重新規劃所有課程、加入怎麼用」——**不要那樣做**。兩個理由：

```
會腐爛            UI 改一次，66 課的操作說明就有一部分變成謊話
與定位衝突         一個需要被教的工具，是在增加認知負荷
                  （concepts/認知鷹架「三輪車不是輔助輪」）
```

> **一個「把說明寫進每一課」的請求，
> 要先問它會不會讓工具本身變成教材。**

## 三層，而只有一層在課文裡

| 層 | 放哪 | 狀態 |
|---|---|---|
| 一次性入門 | 第 0 課或一條短軌道 | ⏳ **待觀察**——先看使用者是不是真的卡在那裡 |
| **可重用片段** | 課文頁自動插入 | 🟢 2026-09-04 交付 |
| **就地提示** | **在 app 裡**，不在課文裡 | ⏳ 與「本地的學習指標」同一份資料 |

🔴 **第三層才是真正解決「不知道要拉哪裡」的東西**：

> **課文是靜態的，而卡住是動態的。**
> 只有 app 知道他現在停在哪一步、拖了幾次沒成功。

## 秒開與說明的衝突，由一個數字擋住

課文頁是 7.5KB、零外部請求。三張 GIF 會讓一頁變成 MB 級。

```
webm 不用 GIF        約是 GIF 的 1/5～1/10
一頁 200KB 上限       ← 護欄，因為「秒開會被慢慢吃掉」
README 那一側用 GIF   GitHub 不自動播 webm——同一支影片轉兩種
```
