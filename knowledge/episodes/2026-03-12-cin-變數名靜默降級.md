# cin >> s 變成 cin >> x：四層防線同時失守

> 日期：2026-03-12

## 為何值得回憶

這不是一個 bug，是**四層獨立的缺陷剛好排成一列**，而且每一層都靜默降級為同一個預設值 `'x'`。任何一層做對了都不會出事；四層都錯了，而且沒有任何一層留下痕跡。

它是「靜默降級」這個反模式最完整的標本。

## 現象

使用者在積木面板建立 `cin >> s` 的輸入積木，點「積木→程式碼」，產生的程式碼是 `cin >> x`。變數名稱在轉換過程中消失了，沒有任何錯誤訊息。

## 四層是怎麼排成一列的

**第一層 — `u_input_expr` 的 `saveExtraState` 與 `u_input` 不一致**

`u_input`（語句版）正確地讀取 Blockly 欄位值：

```typescript
const val = this.getFieldValue(`SEL_${i}`)
args.push({ mode: 'select', text: val })
```

`u_input_expr`（表達式版）是複製貼上再改的，直接複製內部狀態：

```typescript
return { args: this.argSlots_.map(s => ({ ...s })) }
```

而 dropdown validator 寫入的是 `selectedVar`，**不是** `text`：

```typescript
block.argSlots_[idx] = { mode: 'select', selectedVar: newVal }
```

於是 `saveExtraState` 回傳 `{ mode: 'select', selectedVar: 's' }`——有 `selectedVar` 但沒有 `text`。

**第二層 — Extractor 只檢查 `text`**

```typescript
if (a.mode === 'select' && a.text) varNames.push(a.text)
// a.text 是 undefined → 不加入 → varNames 為空
```

**第三層 — Extractor fallback 用了不存在的欄位名**

```typescript
const singleVar = block.getFieldValue('VAR') ?? 'x'
// 積木上沒有 'VAR' 欄位！正確名稱是 'SEL_0'
// getFieldValue 對不存在的欄位回傳 null，不報錯 → 降級為 'x'
```

**第四層 — Generator 硬編碼 fallback**

```typescript
const vars = valueNodes.length > 0
  ? valueNodes.map(v => generateExpression(v, ctx))
  : ['x']   // 不看 node.properties.variable
```

## 權衡過什麼

修哪一層？只修第一層就能解決這個症狀——但另外三層仍然會在下一個類似情境重演。

最後選擇**四層同時修**，而且修法不同：

1. `u_input_expr` 的 `saveExtraState` 改為與 `u_input` 一致，讀 `getFieldValue('SEL_i')`（消除分裂）
2. Extractor 同時檢查 `a.text` 和 `a.selectedVar`（**容錯**，承認歷史資料存在）
3. Extractor fallback 改用正確的欄位名鏈 `'SEL_0'` → `'NAME'` → `'x'`（修正錯誤而非加層）
4. Generator/Renderer fallback 改用 `node.properties.variable ?? 'x'`（先嘗試恢復再降級）

關鍵判斷是第 2 和第 4 層：它們原本也是「fallback」，但改後的 fallback **先嘗試恢復**，只在確實沒有更好選擇時才用預設值。這是「fallback」和「靜默降級」的分界。

## 用了哪些概念

- [元件代數](../concepts/元件代數.md) — 概念角色的語境依賴；statement/expression 雙版本的 extraState 硬契約
- [降級與認知邊界](../concepts/降級與認知邊界.md) — 靜默降級反模式
- [積木投影管線](../concepts/積木投影管線.md) — 全鏈路欄位同步、三模式 argSlot 的 validator 陷阱

## 結果

四層全部修復。蒸餾出三條教訓進 [experience.md](../experience.md)：

- 複製貼上積木定義是序列化契約分裂的溫床
- 靜默降級是 bug 的藏身之處
- Extractor 讀的欄位名必須與積木定義一致

結構性的後續：五天後（2026-03-16）的 [013 extractor 統一為 PatternExtractor](../history/013-extractor-統一為-patternextractor.md) 把「欄位名不同步」這個問題類別從**靠 review 抓**變成**結構上不可能發生**。
