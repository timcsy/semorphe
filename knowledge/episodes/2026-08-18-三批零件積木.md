# 2026-08-18：三批零件積木——六個發現，沒有一個是規劃出來的

> 結論在 [history/084](../history/084-零件不是身分是參數而那份draft擋的是執行不是積木.md)
> 這一篇留的是**過程**：每一個發現是怎麼被逼出來的。

## 為什麼值得記

四批、33 顆概念、26 個 commit。而**六個關鍵發現裡，零個來自規劃**——
三個來自盲測、兩個來自使用者的眼睛、一個來自重讀自己寫的文件。

## 一、判準修正了自己（第 1 批）

探索報告寫「觸發序列 ＋ 距離換算 **7/7 = 100%**，所以兩者一起摺」。

而預組的判準原話是「一組**總是一起出現**的呼叫」——⚠️ **而「總是」要數什麼沒寫清楚**。
語料從 40 段擴到 100 段之後重量：

```
觸發序列（LOW→2µs→HIGH→10µs→LOW，同一根腳）  14/14 = 100%
觸發 ＋ 換算【緊鄰】                            9/14 =  64%
   └ 5 段被 `if (duration == 0) return …;` 隔開
```

原本的 7/7 問的是「這支程式裡**兩者都有**嗎」。而摺起來會把中間那段吃掉——
要問的是「它們**緊鄰**嗎」。

🟢 縮成只摺觸發之後，**14 段全部轉得動**；原設計會讓那 5 段帶守衛的失配。

## 二、⑤ 那張表量出來的，而探針當場抓到我自己的認錯

使用者拍板「關鍵字表要等語料夠了才定」，理由是「那張表會**寫死在程式碼裡**，
而它決定學生貼上之後看到什麼」。

第一次抽取用**名字形狀**（`\w*[Pp]in\w*`），撈到 `i`（21 次）／`brightness`／`freq`
——**根本不是腳位**。改成「它有沒有進到 `pinMode`／`digitalWrite`… 的第一個引數」
之後：113 個腳位變數、命中率 90.2%。

🔴 而**探針第一次跑就抓到我表裡的一個認錯**：`alarmLed` 被判成蜂鳴器
（因為 `alarm` 排在 `led` 前面）。而它是一顆燈。
按「寧可漏不可錯」把歧義詞根**拿掉**，不是往後排。

## 三、盲測的三次（每次都是我沒想到的）

```
第 1 批  41% 的腳位宣告轉不動   #define（10 筆）與裸 int（3 筆）都不認
                                而 #define 是 Arduino 教材最常見的寫法
第 2 批  最令人困惑的解析        `DHT dht(DHTPIN, DHT11)` 被解析成函式宣告
                                （tree-sitter 不做前置處理）——佔語料 30%
第 2 批  I2C 液晶完全不認得      佔語料 20%，而**探索報告第八節自己寫過它**
```

🔴 第三個是「**寫進報告不等於做進去**」的第一個實例。而同一輪它出現了第二次
（`lcd_declare` 的參數要動態——也寫在第八節，也沒做）。

## 四、使用者的眼睛抓到兩個（而測試都是綠的）

```
「函式裡面的參數怎麼漏接了？」   Serial.write(cmd) 的積木括號裡是空的
                                 而語義樹對、產生器對、round-trip 也綠
「你有在 Arduino IDE 那邊裝更新嗎？」  🔴 沒有。26 個 commit 一個都沒打包
                                       而要裝的時候發現腳本清不乾淨快取
```

第二個的形狀特別值得記：**那個問句本身就是缺陷報告**。

## 五、命名護欄逼出兩次合併

第 2 批第一版用了七個新操作詞，硬性零全數擋下。改用既有詞的過程中：

```
dht_humidity ＋ dht_temperature  →  dht_read  ＋ quantity
wifi_state   ＋ wifi_address     →  wifi_read ＋ quantity
```

22 顆 → 19 顆。⚠️ **而合併本來就是對的**——形狀完全相同，只差在讀哪一個量。

## 六、而一顆概念的誠實，靠另一顆概念存在

DHT 讀不到回 `NaN`——查證過是真板子的行為，理由是「學生本來就會 `isnan` 檢查」。

🔴 **測試當場證明那句話是空的**：`isnan` 不存在，程式在檢查那一行就中止。
補了 `cpp:math_is_nan` 之後，那條檢查分支**真的被走到**（斷言 `"no sensor"` 印得出來）。

## 過程的形狀

```
探索 → 產生 → round-trip → 盲測 → 整合     ×4 輪
      ↑                    ↑
   兩次被自己的判準推翻     三次抓到我沒想到的
```

⚠️ 而**每一輪的整合階段都要求開瀏覽器**，那一條抓到了兩個測試看不到的東西
（分類名字不成立、積木插槽不夠）。
