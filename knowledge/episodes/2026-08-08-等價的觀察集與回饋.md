## 探索順序（每一步打掉了什麼）

| 重構 | 打掉了什麼 |
|---|---|
| ① 「假設已經支援多種語言」 | 打掉「我判得出哪些概念是通用的」——只看得到一個語言時，什麼都像那個語言特有的 |
| ② 「通用不是大家一樣，是彼此能轉換」 | 打掉「要有一個絕對元件／正規名字」——**通用性是關係的性質，不是東西的性質** |
| ③ 「這讓我想到內涵相等與外延等價」 | 打掉「合併合法 ⟺ 拆得回來」——那是把可撤回的觀察升格成不可撤回的承諾 |
| ④ 「損失有時無關緊要，取決於精度要求」 | 打掉「無損」的布林形式——**等價相對於觀察集與容差** |
| ⑤ 「都在於回饋、殘差、開放系統」 | 打掉「結構性／累積性」的二分——**累積性是環路的性質，不是那一對的性質** |
| ⑥ 「用相似模型的回饋先做預測」 | 補上冷啟動：先驗可以填量測之間的空隙，但它有相關性陷阱 |

## 一、身分是內涵的，等價是外延的

| | 內涵 | 外延 |
|---|---|---|
| 是什麼 | 這顆元件**被定義成什麼** | 它在某組觀察下**表現成什麼** |
| 誰決定 | 宣告 | 量測 |
| 穩不穩 | **不可撤回**（id 進了存檔） | **可修訂**（觀察集會長大） |
| 相對於誰 | 自己 | 情境 |

這一刀讓「沒有絕對元件」與「id 必須穩定」不再矛盾——**它們講的是不同層**。

> ⚠️ **`concepts/投影.md:135` 已經有「外延等價」了**：
> 「每個執行體只需滿足 ∀ 合法輸入，`A(input) ≡ B(input)`，不要求內部結構相同」。
>
> 而那是**未加索引的版本**——`∀ 合法輸入` 正是不可判定的形式，
> 而且沒有觀察集、沒有容差、沒有回饋週期。這份 draft 要補的就是那三維。

### 由此推翻的一條

我原本說「**合併合法 ⟺ 拆得回來**」。用這組詞看，**合併就是把一個外延觀察升格成內涵承諾**。

而外延觀察是相對於**當前**觀察集的，觀察集會長大（加語言、加精度要求、硬體進來）。
今天分不出來的兩顆，明天可能分得出來，而那時**撤不回來**——id 已經在使用者的存檔裡。

> **外延等價是可以收回的觀察；內涵身分是收不回的承諾。**

→ 正確的傾向是**少合併、多記對應**：身分保持分開（便宜、穩定），
等價當成邊記著（可修訂、可量測、可退步）。

### 它也解掉了命名問題

名字是內涵的，只需要對得起自己的定義。「通用」是外延的，不住在名字裡。
→ **名字要說得出這顆元件自己是什麼，不必宣稱它跟誰一樣。**

## 二、等價的完整形式

不是「A 和 B 相同嗎」，也不是「在情境 C 底下相同嗎」，而是：

> **在精度要求 ε、回饋週期 T 底下，能不能視為相同。**

### 三份素材，判斷用算的

「好多資訊」的擔憂來自 元件² × 情境。但**判斷是算得出來的，不必存**：

```
情境會問的問題  ⊆  對應保住的問題   →   在這個情境下可以視為相同
```

要存的只有兩份，而且各自都小：**對應保住什麼**（邊的數量，不是 N²）、
**情境問什麼**（一個情境一筆）。

這正是專案自己的動作——E 項把工具箱從手寫 80 筆變成 45 段來源導出。
**別存導得出來的東西。**

### 「問題」的詞彙不用發明

完備性護欄的**五路**（lift／generate／render／extract／execute）就是
「系統會對一顆元件問的問題」。先用這五個，不夠再加。

### 規模估算（現在這個專案）

| 要存的 | 筆數 |
|---|---|
| 對應（42 顆意圖相似 → 約 15 族） | ~30 |
| 情境 profile（顯示／執行／來回轉換） | 3 |
| 每條對應保住哪幾路 | **量出來的，不是寫的** |

比 `abstractConcept` 現在已有的 131 個欄位還少。

### 預設要保守

沒宣告 = 不可互換。只在有人真的要主張什麼的時候才寫——
與 `declareNonComponent` 沒寫理由就擲例外同一種紀律。

## 三、累積性是環路的性質

```
總誤差 ≈ 每步誤差 × (經過時間 / 回饋週期) + 量測誤差
```

回饋週期趨近每一步時，右邊塌成 `每步誤差 + 量測誤差`——**累積性消失**。

所以「這個損失要不要緊」不是問這對元件，是問：**多久能拿到一次殘差。**

> 這推翻了我原本畫的「結構性損失／累積性損失」二分。那不是損失的兩類，
> 是同一種損失在不同回饋率下的兩種樣子。

### semorphe 已經是閉環的

雙向投影就是殘差量測；工具列的「⇄ 自動」把回饋週期壓到每次編輯。
**這解釋了為什麼它敢用有損的轉換而不出事——它從來不開環跑很久。**

### 但有兩處是開環的

1. **存檔**——存下去、關掉、一週後打開。中間沒有回饋。D 需要一次性轉換正是因為這段期間記錄與程式碼漂開了
2. **降級——結構上開環**。它**刻意產生一個不等於真實的東西**，而**沒有任何地方量那個差**

第 2 點是 2026-08-08 那顆 `vector` bug 的真正成因（見
[已知工程待解問題](../draft/2026-03-11-已知工程待解問題.md)）。控制的思路給出兩個修法：

- **閉環**：降級之後量一次殘差——「降級後的樹，執行結果還一樣嗎」
- **禁止開環進入需要精度的用途**：降級過的樹不准拿去執行（一行就能加）

### 開放系統：回饋不是優化，是唯一手段

封閉系統（無外界影響）原則上模型可無限逼近，誤差只來自數值與結構。
**開放系統的誤差不是模型不夠好，是原理上消不掉**——有未建模的輸入。

軟體裡這條線也在：`lang:arithmetic` 封閉，`lang:input`／檔案串流／執行時間開放。

→ **封閉的東西，等價可以用推理定；開放的東西，只能用「帶回饋的觀察」定。**

## 四、不可判定 vs 有希望：局部性

外延等價要對所有脈絡量化——一般情況不可判定。而有希望的來源是：

> **區別力是局部的。** 如果 A 和 B 有差別，那個差別會在**碰得到它們差異的觀察**
> 底下暴露，不會在無關的地方暴露。

**這個賭注專案已經下了**：`fuzz-cpp-containers`／`fuzz-cpp-strings` 按模組分組，
就是鄰域取樣。如果區別力不局部，這種分組毫無意義，得跑全組合。

### 而它只涵蓋一半

**累積型的區別是非局部的**：`float` 與 `double` 在單一運算下分不出來，
要累積很多步；數位孿生比對 10 秒吻合、10 小時發散——**能區分它們的觀察
在時間上遠，不在圖上遠，鄰域取樣完全看不到**。

| | 結構性 | 累積性 |
|---|---|---|
| 一步之內看得到 | ✓ | ✗ |
| 區別力 | 局部 | 非局部 |
| 該用 | 鄰域取樣（fuzz、組合測試） | **界**（誤差上界、傳播分析） |

現在系統裡所有「等價」宣稱都是結構性的形狀（`abstractConcept` 是布林的）。
**硬體進來時第一個撐不住的就是這裡。**

### 短路徑是雙面的

小世界的另一半——幾跳可達——**幫你找到，也幫錯誤傳開**。
專案裡那個病有名字：**條件性正確**（單獨測都過，組合才壞）。

### 局部性可測

拿一組**已知不等價**的元件對，量「最近的能分辨它們的觀察離幾跳」。
幾乎都 1–2 跳 → 局部性成立；有長尾 → 那條長尾就是 fuzz 永遠抓不到的。

間接證據：缺陷帳量過阻斷者分佈，結論是**優先序是平的**（22 筆散在 11 個
阻斷者，最大的只有 5）——沒有強烈樞紐結構。對取樣是好消息（沒有一顆節點
主宰一切），也代表**沒有捷徑**。

## 五、冷啟動：借相似者的先驗

新元件零量測，但有鄰居的五路結果、來回轉換穩定度、缺陷史 → 可以預測
「它大概會在哪裡出問題」。

**但預測不會讓誤差變小，它讓誤差變成已知的。** 而如果預測器有偏，
你會漂**而且以為沒漂**。

### 危險來自我們前面說的那個性質

局部性讓鄰域取樣有效——**同一個性質讓借來的先驗不是獨立樣本**。
鄰居高度連通 → 誤差相關 → 整族共用的建模缺陷會被先驗**確認**。
結果不是「不準」，是**高信心的錯值**。

### 三條安全條件

1. **先驗要帶不確定度**，不能是點值（「0.3% ± 0.2%，樣本 4 個」）
2. **第一次真量測必須能否證它**——追「預測的殘差 vs 實際的殘差」，錯了要吵
3. **借來的界要比量到的寬，而且要看得見**——否則沒有人會去量

### 專案已經活過一次

完備性護欄從元件宣告**合成**最小節點跑五路——那就是先驗預測的測試案例。
而它壞過：`synth-node` 原本用名字正則猜屬性值（`compare` 和 `logic` 都拿到 `'+'`）；
087 試著「把運算式包進 `auto __probe`」，**殼從 2 變 13，整個還原**。

C1 做的事本質上就是**換一個更好的先驗來源**（改讀宣告的 `ParamSpec.default`）。

> **先驗的品質直接決定量測的品質，而先驗壞掉時看起來像世界壞掉。**

### 最安全的用法

> **先驗用來決定「先看哪裡」是安全的；用來代替「看過了」是危險的。**

風險與報酬不對稱往安全那邊倒：預測錯了只是測試順序沒最佳化，預測對了省很多。

## 六、順帶的一個重新理解

**測試不是在檢查對錯，是在定義「相同」的解析度。**

加一支測試 = 把觀察集擴大一點 = 某些原本看起來相同的東西會分開。

而這也是為什麼「今天全綠」不代表安全：綠只說明**在現有觀察集下**沒有差別。
2026-08-08 那顆 `vector` bug 就是綠的——因為沒有人在課程可見集合下觀察過。

## 未決

1. **要不要把等價從布林改成帶觀察集的結構**——這會動到 `abstractConcept`
   （現在單向、有損、131 顆裡只有 33 顆指得到）
2. **觀察集的詞彙是不是就用五路**——夠不夠、要不要留擴充空間
3. **降級要不要先閉環**——這一條可以獨立於前兩條先做，因為它有現成的 bug 當驗收
4. **累積型損失要不要現在就設計**——軟體裡還藏得住，硬體一進來就藏不住
