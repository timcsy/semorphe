# 第一課走過三遍——作者、使用者、探針

**日期**：2026-08-14 ～ 08-15（**記於** 2026-08-19，draft 反流時）
**轉變**：[history/098](../history/098-第一課補一筆轉變而它當初撞到的是產品的核心宣稱.md)
**how 的產物**：`specs/124-first-lesson/`（含 `findings.md`）、`specs/125`、`e2e/lesson-01.spec.ts`

## 為什麼記這一段

因為**同一課走三遍，每一遍照出來的東西完全不同**——而那個差異
比任何一遍的結論都值錢。

```
第一遍  作者自己走   照出【說明】的缺陷      而我因為知道答案，跳過了四處
第二遍  使用者走     照出【增益】的方向      「OK」——一次都沒真正卡住
第三遍  探針走九種錯 照出【工具】的缺陷      兩種錯讓學生看到原始代號
```

## 起點是一句話

使用者：「**我有點不知道自己在幹嘛了**」。
查證：元件 189／護欄 43／experience 111，**而教材 0、用過的學生 0**。

> 一個專案可以在每一項可量化的指標上都在成長，
> **而它一個使用者都還沒有**。

## 第一遍：作者走，而第一步就撞到核心宣稱

打上 `int main() { return 0; }` → 同步 → **積木數 = 0**。

那一刻很尷尬：產品的標語是「唯一真實，各式投影」，
而第一課的第一步，兩個投影**長得不一樣**。

⚠️ 而查下去發現**那是刻意的**（積木側只呈現語句），不是 bug。
於是課本改成「先照抄的骨架」，把「兩種樣子」延到第二步。

🔴 **而作者走查有一個結構性的盲點**：`findings.md` 標了**四處**
「我因為知道答案而跳過的地方」。**寫的人走不出讀的人會走的路。**

## 第二遍：使用者走，而回饋的【性質】比內容重要

> 「我走過一遍了，**OK**，不過如果可以有圖片支援更好，
> 或是到時候如果直接跟 UI 結合，可能可以直接用指的」

當下的誘惑是把「圖片」與「用指的」寫進待辦清單，然後開始做教材面板。
**而那會是錯的**：

```
「更好」        做了會更好，而它今天不是瓶頸
「走不下去」    不做就過不去
```

兩者在待辦清單上**長得一模一樣**，而優先序差一個數量級。

⚠️ 更微妙的是「用指的」：設計時把「一課的單位是指節點」**標為猜測**
（「學生可能根本不需要被指」），而使用者**獨立提出了同一件事**。
一度覺得那是「猜對了」的證據——**而它證明的是它【想得到】，不是它【必要】**。

🟢 三個候選裡，**圖片是唯一今天就能做、零風險、而且是使用者主動提的**。
而追問「圖片會不會過時」時，答案翻出一個副作用比圖片本身值錢的東西：

> **一份會自己重新截圖的教材，同時是一支「這一課還走得通嗎」的測試。**

⚠️ 而寫完第一課時**本來有一支走查測試，然後被刪了**——那時覺得它多餘。

## 第三遍：探針走九種錯，而它照出的是工具

逐條實測第一課學生會犯的九種錯：

```
① cout 漏分號  ② return 漏分號  ③ 漏右大括號  ⑥ 引號沒關     🟢 擋下
④ 全形分號 ；  ⑤ 全形引號 “”   ⑨ 全形括號 （）              🟢 擋下（沒預期到）
⑦ Cout 大小寫  ⑧ << 寫成 <                                  🔴 放行，顯示原始代號
```

🆕 **三個全形符號都被擋下**——那是中文使用者最常犯的錯，
而這個專案在此之前**一次都沒測過**。查了才知道自己是對的，這種發現不常有。

🔴 而放行那兩種讓學生看到 `RUNTIME_ERR_UNDECLARED_VAR: {"%1":"Cout"}`
——**與一天前 spec 121 修過的是同一個病**。

而護欄沒接住的理由比「漏了一族」更深：
**文案齊全，而沒有人查它**。護欄量的是供給端，缺陷在消費端。

⚠️ **探針有一欄不算數，當時就寫出來了**：參照編譯器那一欄**連對照組都編不過**
（探針餵原始碼，沒走系統的 auto-include）——那一欄不能用來下任何結論。
