# 最基本的 for 迴圈根本建不出來——而 5312 支測試全綠

**日期**：2026-08-22 ｜ **commit**：`86d1d2e2` `feat(python): 通用桶前十名做成積木…`
**支撐的教訓**：[experience：一整排「渲得出積木」的測試，渲的可能是一份 JSON](../experience.md)
**轉變**：[history/128](../history/128-渲得出積木而渲的是一份JSON.md)

## 為何（why）

那一輪是「把通用桶前十名做成積木」——九顆新元件，一切都很順：
`tsc` 過、35 支新的自證測一次全過、第五十條護欄的三軸維持零、
通用桶 43 → 10、全套 5312 支綠。

照慣例開瀏覽器**看**一眼。那個習慣本身是前一輪付過學費才立的
（[使用者叫我修的那個不是缺陷](2026-08-21-使用者叫我修的那個不是缺陷.md) 那一週，
使用者連續回報五件測試全綠而使用者看得到的事）。

## 怎麼（how）

### ① 貼一段程式，看到一行紅字

```
積木載入失敗：Error: Block "python_loop_for": Message index %2 out of range.
```

第一反應是「兩個迴圈變數（`for k, v in ...`）的 `extraState` 有問題」
——因為錯誤訊息旁邊就寫著 `extraState={"paramCount":2}`。

### ② 而它其實**一顆都建不出來**

```js
ws.newBlock('python_loop_for')   // THROW: Message index %2 out of range.
ws.newBlock('python_loop_while') // ok
```

與 `paramCount` 無關。`message0` 引用了 `%2`，而 `args0` 只有一格。
**每一次建都失敗**，包括工具箱裡那一顆——所以「流程控制」分類點開只有 `if`。

### ③ 「為什麼 4900 支測試沒有一支看到」

這是這一則值得留下來的部分。查了三道防線，**三道都真的在跑，而三道都看不到**：

- 渲染那條路的測試產出的是 `BlockState`——**一份 JSON**。`jsonInit` 從來沒被呼叫。
- 比對護欄**真的**建積木，而它的迴圈裡寫著 `catch { /* 建不起來 */ }`
  ——那行容錯是為了讓比對繼續跑而寫的。
- 可拿性護欄問的是「這顆在不在工具箱的來源清單裡」。**在。**

### ④ 蓋護欄，而它第一次跑抓到 **4** 筆不是 2 筆

`python_lambda` 同一個病，我沒看到——因為 lambda 在「函式」分類的最後一顆，
**它後面沒有東西可以消失**。

### ⑤ 修完之後，第二個只有看得出來的問題

拖出來的 `for` 是「對 ⬤」，中間沒有那個名字。API 問不出這件事
（積木存在、顏色對、插槽對），**而它產不出合法的 Python**。

## 學到（what）

- 三道獨立的防線可以**同時**漏掉同一件事，只要它們都在同一個抽象層上。
- 一個 `catch { }` 的註解寫著「建不起來」——**它知道自己在吃掉什麼**。
- 「開瀏覽器看」這個習慣，這一次的產出不是一個修正，是**一條新的護欄**。
