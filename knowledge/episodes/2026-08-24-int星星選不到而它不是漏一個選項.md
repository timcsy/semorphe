# `int**` 選不到——而它不是漏一個選項

**2026-08-24 ～ 2026-09-06** · 一句使用者回報，走完了四層設計裡的三層。

> 使用者：「我發現 C++ 那邊的 function return type 是不是無法自訂？
> 例如我要 `int**` 就找不到了。**幫我看看還有哪些地方可能這樣**，然後要如何設計？」

⚠️ 「還有哪些地方可能這樣」——**那半句才是這一則值得留下的原因**：
它把一個回報變成一次普查。

## 普查的結果（2026-08-24 實測）

| | 數量 |
|---|---|
| 膠囊裡的靜態 `field_dropdown` | **62 個**，分佈在 51 顆元件 |
| 其中值域**在現實中開放** | **29 個，涵蓋 26 顆元件** |
| 值域封閉（運算子、`public/private`、`begin/end`…） | 33 個 ← 這些下拉是**對的** |

```
cpp/include        HEADER     20 個選項   任何第三方 header 都寫不出來
cpp/math_unary     FUNC       17 個選項   <cmath> 的函式比這多
cpp/pin_attach     DEVICE     10 個選項   硬體元件是開放集合
cpp/var_declare    TYPE        7 個選項   unsigned / vector<T> / 自訂類別
cpp/map_declare    KEY+VALUE   3 ＋ 4     巢狀容器整個表達不出來
```

## 🔴 而第一版的定位是錯的——那個更正是這一則的核心

我第一版說「它偷偷降成 R2」。**不對**：

| | 來回走樣？ | 造得出來？ |
|---|---|---|
| `unsigned long` 被**靜態**下拉改掉 | **會** ← 這才是 R 違反 | ✗ |
| `int**` 被**動態**下拉保住但選不到 | **不會**（完美 R0） | ✗ |

第二列是**完美可逆的**，而使用者永遠造不出第一個 `int**`。

> **一個投影可以完全可逆，而同時是一個不完備的編輯器。**

⚠️ 而那個誤判有**具體的後果**：照它去修，會只做「保住不認得的值」
——那修的是第一列，而症狀會變成「從程式碼來的沒事、自己拉積木做不出來」，
**也就是使用者回報的那個形狀本身**。

判準與這句話已沉澱在 [concepts/投影.md](../concepts/投影.md)（可寫性是第二條軸）。

## 四層設計，成本遞增——而三層做完了

```
① 正確性：清單外的值不得被改掉        2026-08-26 兌現 → history/170
② 可寫性：一個機制解 29 個欄位        2026-08-25 兌現（棘輪 3 → 0）
③ 選項跟著程式長（導出的）            2026-09-06 兌現 → history/213
④ 型別變成結構（`int` ＋ `*` ＋ `*`）  🔴 刻意不做——見下
```

**④ 為什麼別現在做**：它才是 C++ 型別的本質（指標／const／參考／模板是一套文法），
而 `param_decl` 已經是 `{type, name}` 結構化的先例。
但它屬於**指標與參考 UX** 那個家族，而 ②③ 先拿掉 90% 的痛。

> **判準：等「使用者要組合型別」變成常見操作再說。**

## 順帶抓到的兩個真資料遺失（與下拉無關）

```
int** p;          → name 掉了（退成預設 "ptr"）、一顆星也掉了
int** f(int** a)  → 參數掉一顆星、名字是空的
```

`CLAUDE.md` 點名的「**靜默降級反模式**」——多層 fallback 用同一個預設值，
於是資料遺失與正常路徑長得一樣。兩者都在 2026-08-24 修掉。
