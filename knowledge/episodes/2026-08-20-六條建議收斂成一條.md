# 六條建議收斂成一條

> 2026-08-20。使用者：「幫我研究一下這裡有什麼可取和不可取之處，
> 並且如何給我們本身的專案更多靈感」——<https://ai-ky.github.io/blocks/>
>
> **值得記下來的不是調研結論，是它怎麼從六條掉到一條的。**

## 一、對面是什麼

`ai-ky/blocks`（Apache-2.0，4 stars，2022 開站，最後更新 2026-01）。
標題逐字叫「**長的像原始碼的積木**」——問題意識與本專案高度重疊。

```
兩個 Blockly 編輯器      py/code/index.html（247KB）· arduino/code/index.html
兩支 code→XML 轉換頁     python2xml.html · arduino2xml.html
技術棧                   Blockly 舊版 ＋ 靜態 HTML ＋ 全域變數，無建置、無模組、無測試
規模                     45 個分類 · toolbox 裡 2487 個 <block> 條目 · 68 顆核心積木
```

## 二、我列的六條

```
A  raw 逃生艙（他們的 python_any / block_any_line / any_indent_statement）
B  把「積木的字面度」當成一條規範
C  工具箱作為範例庫，不只零件盒
D  flyout 修飾鍵（shift 保持選單）
E  領域廣度換學生動機（45 個分類）
F  快照式積木當反面教材
```

## 三、🔴 而使用者兩句話砍掉了兩條，包括我最有把握的那條

### 「其實 Semorphe 已經有支援 raw 了」

查證：`src/components/cpp/raw_code/` ＋ `raw_expression/` 兩顆完整膠囊
（`component.json` ＋ 五路 ＋ `forms` ＋ `labels`），已接進 `lifter.ts`、
`pattern-lifter.ts`、`code-generator.ts`，還有 `core/degradation-blocks.ts` 專管降級。

⚠️ **A 是我最有把握的一條，而它早就做完了。**

**而我當場又錯了第二次**：我說「Python 還沒有 raw」。
`src/components/python/literal_string/spec.test.ts:6` 逐字：
「在它之前，`print("hi")` 的引數**降級成 `cpp_raw_expression`**」
——Python 一直在用 raw，只是借的是掛在 `cpp:` scope 底下那顆。
🟢 而那與 vision 階段 7 ①「沒有語言中立的字面常數元件」是**同一族問題**，
不是新缺口。

→ 反流成 experience：**一份外部調研在核對自家實作之前，
分不出自己產出的是建議還是重複。**

### 「我覺得長得像程式碼的積木其實不會讓學生更理解現在在幹嘛」

使用者逐字：

> 「所以我刻意用**雙向即時轉換對照**的方式，讓學生可以立即看到兩者對應。」

🔴 **而這一刀比「B 是錯的」更深：B 違反根公理。**

我把「視覺同形」與「對應可見」混成一件事。
ai-ky 用前者去換後者——68 顆積木 61 顆 inline、41 顆同色，
**結構完全不再傳達資訊**：巢狀不靠包容、型別不靠形狀、合法性不靠接點。
那已經不是第二種投影，是同一份文字穿了個可拖曳的外套。

> **對應是一個關係。凍結進形狀（靜態、有損、逼兩邊收斂），
> 或在互動中演出來（動態、無損、兩邊各自最佳化）。**

而「唯一真實，各式投影」的力量正在於投影可以各自最好——
**逼它們互相模仿是在犧牲投影品質，換一個語義樹本來就免費提供的東西。**

→ 反流成 [concepts/投影](../concepts/投影.md) §357「而『不必長得像』還有更強的一句：刻意不要」。
→ 而它逼出一份新 draft：[對照的解析度](../draft/2026-08-20-對照的解析度.md)
（既然對照是核心機制，它今天的行級粒度就是路線的天花板）。

## 四、剩下四條又掉了三條——理由各不相同

```
E 領域廣度   ❌ 不是新提案，是 ArduinoCAD 合流（既定決議）的補強證據
D flyout     ❌ 不是靈感，是順手撿的 UX 小便宜（已記進範例庫那份 draft §七）
F 快照式積木  ❌ 不是靈感，是【警告】——只該當一條具名反模式
C 範例庫     🟢 唯一還開著的
```

使用者自己收的最後一刀逐字：「所以剩下範例庫是值得討論的？」

## 五、🟢 而真正的產出是**負面確認**

四項既有賭注，在對面都能看到「不做會變成什麼樣」的**實物**：

| 我們做過的 | 對面沒做的後果 |
|---|---|
| round-trip 護欄 | `python2xml` 下載 `.xml` 讓人手動 Load，零測試 |
| ParamSpec 解 arity | `block_comma2`…`block_comma10` 九顆，26KB 一個檔 |
| E 步登錄表導出（80 筆 → 45 段） | 2487 個 toolbox 條目手寫在一份 247KB 的 HTML 裡 |
| raw 元件 ＋ 真 lift | `parseBlock()` 用 `content.includes('=')` 判賦值，產出幾乎全是 `python_any` |

> **沒有一樣新東西該抄，而四個既有的賭注被驗證了一次。**

⚠️ 而這件事**本身**是這輪調研最容易被寫漏的：
負面確認不產生待辦事項，於是它在任何一份「建議清單」上都不會出現。

## 六、而它與上一次競品調查連起來了

[draft/競品的積木與分類](../draft/2026-08-18-競品的積木與分類.md)（兩天前）的核心發現是
「單向的工具可以隱式長出物件，我們不行——**不是他們沒想到，是他們不必面對這個約束**」。

這一次撞到同一條線的另一面：**單向 → 只能靠形狀相似做對應；而我們不必。**

→ 反流成 experience：**同一條分界線被兩次獨立的競品調查命中，那不是巧合。**
