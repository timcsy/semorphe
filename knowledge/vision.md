# 願景

## 問題陳述

程式教育有一個根本鴻溝：**理解程式邏輯**和**掌握語法細節**之間的斷層。

傳統工具走兩個極端——Scratch/Blockly 讓學生拼積木但永遠碰不到真正的程式碼；文字教學讓初學者同時面對邏輯和語法的雙重認知負荷。兩者之間缺少一座橋。

**目標使用者：**

- **學生**（主要）：從零基礎到進階，涵蓋 APCS 考試準備、競程訓練、學校課程
- **教師**：設計教學路徑（Topic）、指定練習、追蹤學習軌跡
- **語言開發者**：透過模組化語言套件擴充新程式語言
- **課程設計者**：透過 Topic 系統定制不同教學情境的元件可見性和積木形態

## 核心想法

**程式碼和積木都不是本質——它們是同一個語義結構的不同投影。** 學生可以用積木理解邏輯，同時看到對應的真實程式碼，在兩者之間自由切換，最終過渡到純文字編程。

關鍵不是在程式碼上面疊一層積木——**只有語義層存在**，程式碼和積木都是參數化的投影。

🔴 **而「投影」是三族，不是兩族**（2026-09-25 從兩族改成三族）：

```
形態   長什麼樣        程式碼 · 積木 · 流程 · 3D
行為   做什麼          執行 · 電氣傳播 · 物理模擬
形式   什麼時候成立      🆕 形式核（`contract.cella`）
```

> ⚠️ 2026-10-31：「形式」今天是 **formalize：語義樹 → Cella 的程式 JSON（深嵌入）**，`contract.cella` 隨〈重構〉階段 3 退場；
> 「行為」的語意也交給 Cella，驅動在應用層的執行器（〈重構〉，[history/306](history/306-語意交接從切換那天一次換到有系統的重構計劃.md)）。

🔴 **而「教育」是其中一式，不是一條並行的線**（2026-09-26，使用者：
「教育…是**銜接這工具與人類心智認知的一個介面**」）：

⟹ `漸進揭露`／`鷹架可退場`／`可重現 > 擬真` **不是教學的妥協，是人面投影的參數**。
而那也是 vericoding 缺的那一半——**Dafny 滿是 invariant 的程式碼讀不下去，
不是因為它太嚴謹，是因為它沒有人面的投影。**

理論基礎見 [原則](principles.md)；協定見 [元件](concepts/元件.md) ·
[連接](concepts/連接.md) · [組裝](concepts/組裝.md) · [契約](concepts/契約.md)。

**和現有工具的根本差異：**

| 工具 | 做法 | Semorphe 的不同 |
|------|------|----------------|
| Blockly/Scratch | 積木 → 程式碼（單向，不可逆） | 程式碼 ↔ 積木（雙向，完美 round-trip） |
| Hedy | 每個等級有不同語法 | 同一語義樹，不同投影解析度 |
| 傳統 IDE | 以文字為中心，視覺化為附加 | 以語義為中心，文字和視覺都是投影 |
| Unison | AST hash 內容定址 | hash 語法層 vs hash 語義層 |
| LSP/LSIF | 跨檔案符號索引 | 位置導向 vs 語義導向 |

### 🆕 目標（2026-09-26，使用者表態）

> **在一個試錯很貴或不可逆的領域裡，事前說得出保證。**
> 而**程式是第一個域**，因為它的迴圈快到足以**開發那個機制**。

🔴 **而這句話要帶著它的否認，否則它會被讀成過度承諾**：

> **一個軟體的保證不構成物理的安全。**

不可逆的動作要的是 L3**或者物理上的攔截**（限位開關、力矩上限）——
而在軟體域讀成過度承諾的代價是一支跑錯的程式，**在機器人域是一台壞掉的機器**。

⟹ `vericoding` 是這個目標**在軟體域的實例，不是終點**。

🔴 **而「起家的順序」是明說的**（2026-09-26，使用者）：

```
Claude     Claude Code（程式）起家 → 延伸到 Design 等其他領域
Semorphe   vericoding（程式）起家 → 延伸到其他領域
```

⟹ **軟體域不是「機制的開發場」，它是起家的生意。**而延伸得出去的證據已經有了：
18 個域填過同一張元件模板，而**連續六個域只長詞彙、結構不動**。

⚠️ 而延伸的順序不是隨意的：**迴圈越慢的域（硬體分鐘 · 3D 小時 · 機器人不可逆），
越晚進得去，而它也越需要這套東西。**

形狀與優先序見 [draft/事前說得出保證](draft/2026-09-26-事前說得出保證.md)。

## 架構

### 協定：三個主體

```
元件   身分 · 埠 · 參數 · 形態 · 行為 · 形式  ＋ preconditions／postconditions／invariants
連接   結構（樹 · 有向邊 · 網）× 關係（組合 · 資訊 · 守恆）—— 🔴 兩軸【正交】
組裝   整張網才成立的：全網不變量 · 預算 · blame        —— 🔴 今天程式碼裡是 0
```

[元件](concepts/元件.md) · [連接](concepts/連接.md) · [組裝](concepts/組裝.md) · [契約](concepts/契約.md) · [面板](concepts/面板.md)

🔴 **契約不是第六個槽，是加在槽上的精化**（`{x : T // P x}`）：槽的產物是**剪枝力**
（填不出就不是元件），契約的產物是**棘輪**（填了有沒有人判）。
而**階梯是判定者算出來的，不宣告**——`judge == null` 的筆數是契約的誠實度度量。

### 投影：三族，而它們有機械的簽名

```
形態   成對、可逆    lift ↔ generate · render ↔ extract
行為   單向         execute   → 一條軌跡
形式   單向         formalize → 一個命題
```

**形態成對是因為它保存語義**；另兩族單向，因為它們產出的是**關於**語義的東西。
> ⚠️ 2026-10-20 方向已定、〈重構〉階段 2 落地：形態改成每個視圖一對 `render ↔ lift`；`execute` 的語意併進 `formalize`、驅動移到應用層（[history/305](history/305-與Cella的分工從Cella是答案到盟約與深嵌入.md)）。

### 執行期的堆疊

```
宿主（瀏覽器 / VSCode / Theia）
  ↕ ViewHost
面板（積木 · 程式碼 · 流程 · 主控台 · 變數 · 硬體）  src/panels/<name>/panel.ts
  ↕ SemanticBus
核心（語義樹 · 元件登錄 · 投影引擎 · 能力介面）      零 DOM，Node 跑得起來
  ↕ 能力登錄表
提供者（網頁版：Cella 優先、JS 直譯器接 Cella 不接的；擴充：JS 直譯器）   src/providers/<id>/（核心不得 import）
  ↕ 語言套件介面
語言套件（cpp · python）＋ 膠囊 src/components/<scope>/<name>/
```

⚠️ **Arduino 不是語言套件，是【目標】**（board target）——域／語言／layer 三軸正交，
把它排成第三個語言是本檔〈元件住在哪〉禁止的類別錯誤。

### 出貨：五層（階段 8）

```
① 核心      協定 ＋ 匯流排 ＋ 登錄表        不認得任何 componentId
② 詞彙套件   🆕 關係律 · 組裝約束 · 單位     可被 ③④ 依賴，獨立版本
③ 元件套件   lang-cpp · hardware-arduino   貢獻到工具箱
④ 視圖套件   panel-*                      只依賴 ①
⑤ 應用      組裝 ②③④
```

🔴 **② 是 2026-09-26 加的**，而推翻原本四層的是 ROS 的 `.msg` 與 Maven 的 BOM
**各自獨立地**說同一件事：詞彙／約束要是一個**可以被依賴的單位**。
設計見 [draft/套件協定](draft/2026-09-26-套件協定.md)。

### 三層宣告

⚠️ **這一節 2026-09-26 從「三層契約」改名**——「契約」現在是
`preconditions`／`postconditions`／`invariants`（見 [契約](concepts/契約.md)），
而這三層講的是**宣告給誰看**，不是「什麼時候成立」。同一個詞兩個意思。

- **第一層（語義宣告）**：`component.json` ＋ lift pattern ＋ lifter——**所有消費者可用**
- **第二層（投影提示）**：`forms/blocks.json` ／ `codeTemplate` ／ generator——**僅對應投影消費**
- **第三層（視圖策略）**：視圖讀 annotations 自己決定呈現——加一個唯讀視圖不必改語言套件

### 語言套件目錄結構

```

                                   execute.ts · forms/ · labels/ ·（contract.cella）

src/languages/<lang>/              文法、產生器、抽取器、骨架、診斷、標頭別名
  ├─ manifest.json                 套件中繼資料
  ├─ lift-patterns.json            AST → 語義 pattern 規則
  └─ std/                          標準函式庫（目錄名即 header 名）
```

⚠️ **2026-09-26 更正**：原本這張圖畫著 `languages/{lang}/core/components.json`
——那個集中檔**在膠囊化之後就不存在了**（元件住在 `src/components/`）。

### 長期方向

1. **多語言**：C++ → Python → Java → Go → Rust……同一語義結構，切換語言即切換投影
   🟢 **而「加一個語言」現在有一支 skill**（`add-language`，2026-08-21）——
   Python 那次走了六支 spec，而那條路的清單當時只存在於 `history/118`–`120` 裡。
2. **語義套件市場**：語義契約 + 投影定義 + 多後端執行體（⚠️ 2026-10-31：「多後端」今天的形狀是能力介面的提供者，見〈重構〉）。同一元件可有多個執行體（wasm / js / webgpu / remote），自動基準測試 + 自動後端選擇。教學價值：讓學習者直觀感受演算法複雜度
3. **可插拔執行與時空旅行除錯**：執行即投影；直譯器每步產生語義狀態快照，回溯 = 用歷史快照重新投影（viewParams 多一個 `timeStep`）
4. **硬體教育**：Arduino 接線視圖 + 模擬視圖，從軟體延伸到嵌入式
5. **AI 輔助**：LLM 作為語用分析師，在確定性 guardrails 內提供提示投影——建議下一步，但不自動修改語義結構
6. **自舉**：教學路徑本身成為可分享的語義套件；學習數據回饋優化 Topic 層級樹，目標是**結構還原度最大化**而非效能最大化
