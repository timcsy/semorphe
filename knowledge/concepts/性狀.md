# 性狀——消費者問「這顆是什麼」，不問「這顆叫什麼」

> 誕生於 F（膠囊搬家，2026-08-11）。**它不是一開始設計的，是 167 顆元件搬不動時
> 十五次同一個處置疊出來的形狀。**

## 一句話

一顆元件對外宣告**它是什麼樣的東西**（`traits`），而別的程式碼**問那個性質**，
不寫死它的身分。

```ts
// 之前：消費者認得那顆元件的名字
if (caseNode.conceptId === 'cpp:default') { … }

// 之後：消費者問一個性質
if (isDefaultCase(caseNode.conceptId)) { … }
```

```json
// cpp:default 的 component.json
{ "traits": { "defaultCase": true } }
```

## 它解決的是什麼

膠囊化的目標是「一顆元件的東西都在自己的資料夾裡」。而搬不動的元件裡，
最大一類**不是實作散落**——是**別的程式碼認得它的身分**：

```
cpp:switch 的執行器要知道哪一支是 default:      → 它認得 cpp:default
cout << … 要知道哪些東西需要括號               → 它認得 cpp:ternary / cpp:comma_expr
L0 的積木視圖要濾掉鷹架                        → 它認得 cpp:include / cpp:using_namespace
核心的 createEmptyProgram() 要建一棵空樹        → 它認得 cpp:program
```

> **「另一顆元件需要認得它」是真的耦合，不是碎裂。**
> 處置不是把消費者搬走（消費者有它自己的家），
> 是**把「我是什麼」變成元件自己的宣告**。

## 判準：什麼該是性狀

| 問題 | 答 |
|---|---|
| 消費者在問**這顆元件的性質**嗎？ | 是 → 性狀 |
| 消費者在問**這顆元件的實作**嗎？ | 是 → 那是五路，該搬進膠囊 |
| 消費者在問**這顆元件在某個位置時算什麼**嗎？ | ⚠️ 見下：**只講一半** |

### ⚠️ 性狀只講得出「我是什麼」，講不出「我在哪裡時算什麼」

`#include` 在哪裡都是鷹架（L0 不顯示）；而 `return` **只有在 main 裡**才是。
兩者共用一個 `scaffold` 旗標的話，`return` 在任何函式裡都會消失。

處置是**把條件切成兩半**：

```
scaffoldInMain: true    ← 元件宣告「我是那個會被 main 的鷹架吃掉的東西」
「在不在 main 裡」        ← 留在 cpp-scaffold-filter（消費者的知識）
```

同一個形狀的第二例：`cpp:program` 的執行器裡留著 `'main'` 這個字串，
而**沒有**做成 `func_def` 的性狀——「哪一個函式是進入點」是**整個程式**的知識，
不是那顆函式的性質。一個叫 `main` 的函式在別的語言裡可能什麼都不是。

> **可以宣告的是「我是什麼」，不是「我在哪裡時算什麼」——
> 所以有些性狀只講一半，另一半留在消費者手上。**

## 形狀：函式寫不進 JSON，所以規則要能宣告

優先級隨運算子而變的三顆元件，原本是三個**函式**：

```ts
'cpp:logic': (op) => op === '||' ? 4 : 5
```

性狀要能住在 `component.json` 裡，所以改成**規則表**：

```json
{ "precedenceByOperator": { "default": 5, "rules": [{ "ops": ["||"], "p": 4 }] } }
```

> **同樣的資訊，換一個宣告得出來的形狀。**
> 一個宣告不出來的性質，就不是性狀——那是實作，該待在膠囊裡。

## 三個讀取層，而分層是被 P9 逼出來的

```
core/component/traits.ts          只讀膠囊的 component.json（glob 直讀）
languages/cpp/core/node-traits.ts 在上面疊 C++ 的過渡表
pending-node-traits.json          過渡表——⚠️ **F 完成之後它空了**（見下）
```

⚠️ **分層不是潔癖，是撞到牆才長出來的**：`interpreter/executors/variables.ts`
（核心）要分辨 `A a(5)` 是建構還是求值，改成問性狀之後，
**核心就 import 了語言套件**——中立性護欄當場抓到（P9 的字面違反）。

> **把耦合從「身分」換成「性狀」是對的方向，
> 而換的過程可能換出一條反向依賴。**

已膠囊化的元件在兩層答案相同；差別只有過渡表。

⚠️ **過渡表今天是空的**（2026-08-11，F 完成）。最後刪掉的三筆是
`boolean`／`number`／`string`——**不帶 `cpp:` 前綴的舊通用層身分**，
從 `FOR_LOOP_CONCEPTS` 那個集合照抄過來的，而實查**沒有任何地方產出它們**。

> **一個集合裡的成員不必是活的——照抄一份集合，等於把它的幽靈也抄過來。**

檔案留著是因為**過渡表這個形狀還會再用**（靜態 import 的 JSON、glob 直讀、
沒有登錄呼叫）——下一次是 Python 或硬體域。

## 不要猜

每一個查詢函式在查不到時回 `undefined` 或 `false`，**不給預設值**：

- `ioConceptFor(role, style)` 找不到 → `undefined`。猜一個會讓風格轉換
  產出一顆不存在的元件。
- `conceptWithTrait('variableRef')` 找不到 → 投影宣告的 `wrapTrait` 不生效。
  正確的反應是「這條規則不生效」，不是「包成一顆猜出來的元件」。
- `programRootConcept()` 找不到 → **丟錯**。猜一個名字的話整個編輯器會拿到
  一棵沒有人認得的樹，而症狀出現在很遠的地方。

這與 `concepts/元件.md` 的「拒絕猜，要求宣告」是同一個立場。

## ⚠️ 宣告本身也會寫死身分

第三種「寫死身分」的地方不是程式碼、也不是登錄表，是**投影宣告**：

```json
"dynamicRules": [{ "modes": { "select": { "wrap": "cpp:var_ref" } } }]
```

「把選到的文字包成一顆變數參照」——寫在 `print_formatted` 的
`forms/blocks.json` 裡，於是那顆膠囊**提到了另一顆的身分**。

處置是 `wrapTrait`：

> **一個宣告要指涉另一顆元件時，指它的性質而不是它的名字。**

## 而它不只是一個 `traits` 欄位——它是一個形狀（2026-08-13）

三情境補齊那一輪（[history/058](../history/058-問角色不問身分從一條處方變成一個機制族.md)）
獨立想出這個形狀**四次**，而當時沒有人意識到是同一件事：

| 機制 | 誰宣告 | 核心因此不必知道 |
|---|---|---|
| `core/component/aggregate-nodes.ts` | 語言套件 | 哪個節點是一層 `{…}`、`pair` 的欄位叫什麼 |
| `core/component/lvalue-nodes.ts` | 三顆 lvalue 元件各自 | `a[i]` 是一個下標存取 |
| `RuntimeValue.heapOrder` | `priority_queue_declare` | `greater<T>` 是什麼意思 |
| `RuntimeValue.elemType` | `vector_declare` | 這個容器裝的是什麼 |

> **核心給機制、宣告的一方給資料——而核心裡不多一個 C++ 的名字。**

### ⚠️ 而後兩個是新的一種：資訊必須跟著**值**走

前兩個是**登記處**（宣告在載入時推進去，查詢時問名字）。後兩個不同：

```
greater<T>  寫在【宣告】上
top()       只拿得到【變數名】
```

那個資訊跟著呼叫端走的話，`top()` 會安靜地回傳最大值
——程式跑完、印出一個數字、而它是錯的。`elemType` 同理：
`v.push_back({2,1})` 的 `{2,1}` 要變成什麼，取決於容器裝的是什麼。

> **一個在「宣告處」才知道、而在「使用處」才需要的事實，必須跟著值走
> ——跟著呼叫端走的版本會在某個呼叫點安靜地失去它。**

## ⚠️ 判準：一條性狀是真抽象還是假抽象

> 這一節來自一個外部類比：**性狀在結構上就是 Clean Architecture 的 DIP**
> （依賴反轉）。原本 `cpp:switch` 依賴具體的 `cpp:default`；現在兩者都依賴
> 一個抽象（`defaultCase`），而具體的那一顆指向抽象。**原始碼依賴方向反轉了。**

而 DIP 帶著一個現成的臭味：**「一個介面只有一個實作，而且名字是照那個實作取的」
——那個抽象是假的。**

⚠️ **這條臭味不能照抄**，因為性狀要的不是多型，是**跨語言可替換**。
一顆元件在一個語言裡當然只有一個實作。改成：

> **換一個語言，會不會有另一顆元件宣告它？**
> 會 → 真抽象（機制通用、值不同）
> 不會 → **它只是那顆元件的名字換了個寫法**

⚠️ **而這個判準不是新發明的**——[等價與觀察集](等價與觀察集.md)早就把同一個結構
寫完整了，而且比我這個版本強：

> **在精度要求 ε、回饋週期 T 底下，能不能視為相同。**

我的「換個語言」其實是那裡的**觀察集**換了一組；「會不會有另一顆宣告」
是在問**這個斷言在新的觀察集下還成不成立**。

差別在於那份概念檔還多說了兩件我漏掉的：
- **觀察集有現成的詞彙**——完備性護欄的**五路**就是「系統會對一顆元件問的問題」
- **預設要保守**：沒宣告 = 不可互換。所以 🟡/🔴 的分類不該是我用眼睛判的，
  **該是宣告出來的**（見下面「位置只有兩條錯」的 catch）

### 逐條過（2026-08-11，23 條）

| | 性狀 | 為什麼 |
|---|---|---|
| ✅ **真**（12） | `programRoot` `functionDefinition` `variableRef` `stringLiteral` `namedCall` `indexedAccess` `binaryOperator` `precedence` `precedenceByOperator` `scaffold` `ioRole` `typeSuffix`※ | Python 會宣告同一個鍵、填不同的值 |
| 🟡 **C 家族**（6） | `forLoopPart` `includeDirective` `scaffoldInMain` `defaultCase` `lineBreak` `elseIfChainable` `prefixOperator` | 不是 C++ 獨有，而 Python 沒有（`for x in seq:` 沒有三個格子、`elif` 是一個 token）|
| 🔴 **假**（5） | `parenInCout` `ioStyle` `streamInput` `typeSuffix` `plainDeclaration` | 名字裡就有 `cout`；值域是 `'iostream'\|'cstdio'`；Python 沒有指標、沒有宣告 |

※ `typeSuffix` 兩邊都列是刻意的——機制（型別後綴）通用，而今天唯一的值 `'*'` 是指標。

**⚠️ 一個反直覺的結果**：

```
forLoopPart   19 顆宣告 ← 最多，而它是 C 家族的
programRoot    1 顆宣告 ← 最少，而它是真的
```

**判準真的是「換個語言會不會有人宣告」，不是「現在幾個人宣告」**
——古典 DIP 的臭味測試在這裡會判反。

### 而位置只有兩條錯

23 條裡 **21 條放對了**。住在 `languages/cpp/core/node-traits.ts` 的那些不管真假都對，
因為那個檔本來就是 C++ 的。問題全在 `core/component/traits.ts`（**最內層**）：

```
isNamedCall / isIndexedAccess / programRootConcept / isFunctionDefinition   ✅ 留著
isPlainDeclaration   🔴 已下沉（2026-08-11）
isElseIfChainable    🔴 ⚠️ 下沉修不好它——見下
```

### ⚠️ `elseIfChainable` 的下沉修不好真問題——而真問題不是我一開始說的那個

它的消費者之一是 `core/lift/pattern-lifter.ts:570-573`。

⚠️ **那段程式碼做的不是「摺疊」，是「標記」**（我一開始講反了，2026-08-11 更正）：

```ts
// Mark direct "else if" chains: when an else_clause contains
// a direct if_statement (not wrapped in compound_statement),
// mark the resulting if node with isElseIf so renderer/generator
// can distinguish from "else { if (...) {} }"
```

沒有那個標記，`else if` 與 `else { if }` 會 lift 成**一模一樣的樹**，
來回轉換就把使用者寫的形式改掉了。**它是保住區別的東西，不是合併。**

於是「這個標記該不該存在」這個問題，[等價與觀察集](等價與觀察集.md)已經答了：
觀察集是**五路**，而兩者在 `render` 那一路不等價（積木長得不同）。
「傾向少合併、多記對應」——那個標記就是「記對應」。
用它的詞彙講，`isElseIf` 是**殘差**：語義模型分不出、原始碼分得出的那一點差。

### 而真正在核心的耦合是三個文法節點名

```
src/core/lift/pattern-lifter.ts:570   'else_clause'
src/core/lift/pattern-lifter.ts:571   'if_statement'
src/core/lift/lifter.ts:65            'compound_statement'
```

**三個 tree-sitter 文法節點名硬編在核心**，而三條護欄一條都抓不到：
不是元件身分（身分掃描過）、不是 import（import 檢查過）、不在膠囊裡（就近性過）。

> **耦合的第三維不是「範疇名」，是「別人的文法詞彙」。**

（`if_statement` 湊巧 Python 的 grammar 也有；而「else_clause 裡直接包一個
if_statement」這個**結構**是 C 家族的——Python 有獨立的 `elif_clause`。
所以這段對 Python 不會誤觸發，它只是死的。）

見 [draft/核心硬編了別人的文法詞彙](../draft/2026-08-11-核心硬編了別人的文法詞彙.md)。

## 與別的概念的關係

- [元件](元件.md)——五槽模板。性狀是**第六格的候選**，而它與五路不同：
  五路是「這顆元件會做什麼」，性狀是「這顆元件是什麼」。
  ⚠️ 要不要正式進五槽是**還沒定的事**（它今天只在 C++ 這一個域驗過）。
- [執行機構](執行機構.md)——每一條性狀的落地都有護欄盯著：
  就近性護欄會指名「膠囊裡出現別顆元件的身分」，那正是性狀化的觸發器。
- [開放擴充](開放擴充.md)——性狀讓消費者不必列舉已知元件，
  而列舉式分派是那份文件在講的病。
