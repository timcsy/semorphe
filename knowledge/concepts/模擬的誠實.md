# 模擬的誠實

> **剪枝力**：它回答一個問題——**模擬器什麼時候可以編一個數字出來？**
> 答案是**幾乎不行**，而「幾乎」的那幾個例外要各自說得出理由。

## 為什麼需要這個概念

這個專案有一個語義直譯器，而學生按「執行」時**沒有真的板子**。
於是每一顆碰到硬體的元件都要回答同一個問題：`analogRead(A0)` 回什麼？
`dht.readHumidity()` 回什麼？`WiFi.status()` 回什麼？

⚠️ **而這條判準在 2026-08-18 之前只存在於一個程式碼註解裡**
（`components/cpp/digital_read/execute.ts` 的檔頭），卻被 **12 個檔案**
當成既有的判準引用：「判準是 `digital_read` 檔頭那句：**可重現比擬真重要**」。

> **一個被十二個地方引用的判準，如果只住在其中一個地方的註解裡，
> 那它是靠人記得，不是靠結構。**

## 三條規則，而它們是有序的

### ① 可重現 > 擬真

**一個每次讀到不同值的模擬器，測不出任何東西。**

真板子的 `analogRead` 會抖、`micros()` 會溢位、觸摸感應值會漂。
🔴 **模擬一律不模那些**——它們讓「同一支程式跑兩次結果不同」，
而那會讓每一條測試都變成偶然。

⚠️ 代價說得出來：`micros()` 的低三位永遠是 0（時鐘只有毫秒解析度），
而真板子約 70 分鐘溢位一次——**模擬不模它**。

### ② 回的不是編出來的數字

這一條比①強：不只要可重現，**還要有來源**。

```
🟢 有來源
   servo.read()          回上次寫進去的角度   ← 真板子也是這樣（不是量的）
   EEPROM.read(addr)     一個位元組陣列       ← 它本來就是記憶體，可以【實作】不是模擬
   pulse_read 沒接東西     回 0               ← 與真板子超時的行為一致
   dht.readHumidity()    回 NaN              ← 官方文件寫明的失敗值

🔴 沒有來源
   dht.readHumidity()    回 25               ← 學生會以為他量到了溫度
```

> **一個裝置如果它的本質就是資料，那它不需要被模擬——它可以被實作。**

⚠️ 而「誠實的失敗值」有一個**前提**：要有人接得住它。
`NaN` 的誠實建立在 `isnan` 存在上——不存在的話，程式在檢查那一行就中止，
而學生看到的不是「感測器讀不到」，是「程式壞了」。
見 [[經驗]]「一個『誠實的失敗值』如果沒有配套的檢查函式」。

### ③ 沒有來源時，說出來那是【取捨】不是【模擬】

有些情形沒有誠實的答案，而**擋住整支程式更糟**：

```
WiFi.status()   回 WL_CONNECTED
                🔴 回「未連上」的話，每一支教學程式都卡在
                   `while (WiFi.status() != WL_CONNECTED)` 裡，
                   而學生看到的是「程式當掉」
touchRead(pin)  回固定的 75（未觸碰的典型讀數）
                🔴 已知後果：`if (touchRead(4) < 40)` 這條分支永遠走不到
```

⚠️ **而規則是：那個取捨要寫在該顆元件的 `_execute_why` 或檔頭裡，
並且說出它讓哪一條路徑走不到。**

> **一個沒有說出自己是取捨的取捨，
> 下一個讀到它的人會把它當成模擬。**

## 這條界線與「虛擬硬體」的關係

```
物件存在 ＋ 方法不拋錯 ＋ 記錄狀態      ⚪ 便宜   ← 今天
方法有【可觀察的效果】（馬達轉、液晶顯示）🔴 貴   ← 虛擬硬體，已推遲
```

🔴 **而狀態是記著的**（`arduino-pins.ts`／`arduino-devices.ts`／`arduino-pwm.ts`）——
所以「板子視圖」要做的時候，資料已經在那裡了。
⚠️ 而狀態**不進 `ctx.io`**：那是**程式的輸出**（學生的 `Serial.println` 走同一條），
把模擬器的旁白寫進去會讓程式的輸出變成錯的——而輸出比對是這個專案量正確性的方式之一。

## 三個投影

| | |
|---|---|
| **規範** | 每一顆碰硬體的元件，執行那一路要能指出它的值**從哪來** |
| **情境** | 虛擬硬體之前，「執行」由**真板子**提供（燒錄）；模擬只保證跑得完與可重現 |
| **存在** | 12 個檔頭引用它、而它沒有家，直到 2026-08-18 被 judge 掃出來 |
