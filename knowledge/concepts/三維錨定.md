# 三維錨定（Protocol / Data / Agency）

系統憑什麼聲稱自己在接近真實？答案不是單一權威來源，而是**三個互設且平衡的驗證維度同時成立**。

**三視角投影：**

- **原則**：合法的系統更新 = Protocol ∩ Data ∩ Agency；缺任一維度都有具名的失敗模式
- **願景**：AI 輔助、自舉元教學、語義套件市場的治理規則都從這裡推導
- **經驗**：這不是新增的約束，而是對既有仲裁規則的認識論解釋——它讓「為什麼 LLM 不能自動 merge」有了非任意的答案

## 三個維度

```
            公理維度
           (Protocol)
              ╱╲
             ╱  ╲
            ╱  ≡ ╲
           ╱______╲
   情境維度 ———————— 主體維度
   (Data)            (Agency)
```

| 維度 | 職責 | 性質 | 對應現有機制 |
|------|------|------|------------|
| **公理（Protocol）** | 不可變的邏輯基準 | 確定性、先驗 | 四路完備性、元件代數、投影定理 |
| **情境（Data）** | 環境反饋與觀測數據 | 經驗性、後驗 | AST 解析、round-trip 測試、User Context |
| **主體（Agency）** | 基於責任的價值判斷 | 意圖性、規範 | Correctness 判斷、Topic 設計、根公理定義 |

**交叉驗證規則：**

```
合法的系統更新 = Protocol ∩ Data ∩ Agency

缺少 Protocol 對齊 → 系統幻覺（結構性錯誤）
缺少 Data 驗證   → 空想（未經實證的理論）
缺少 Agency 簽署 → 自動化偏差（無人負責的變更）
```

**三維互設（Co-determination）**——不是層級關係，每個維度都需要其他兩個來完整定義自身：

```
Protocol 沒有 Data    → 不可驗證的空洞公理（形式主義陷阱）
Protocol 沒有 Agency  → 無人維護的殭屍規則
Data 沒有 Protocol    → 無方向的數據漂移（過擬合）
Data 沒有 Agency      → 無人負責的自動化偏差
Agency 沒有 Protocol  → 主觀任意的獨斷
Agency 沒有 Data      → 不顧現實的空想
```

## 架構對應

```
§4.3 架構分層                     三維錨定

語義結構（Symbolic）            ← Protocol（公理維度）
  確定性、可驗證、不可變

Guardrails（確定性驗證）        ← Protocol ∩ Data 交集
  AST constraints、roundtrip

LLM 層（Connectionist）        ← Data（情境維度）
  機率性、可建議、需確認

使用者                          ← Agency（主體維度）
  定義根公理、判斷 correctness
```

## LLM 作為語用分析師

**為什麼 LLM 不能是核心**：語義結構是確定性的，LLM 是機率性的。讓 LLM 當核心引擎，語義結構就從 source of truth 變成「LLM 覺得大概是這樣」。正確定位：**語義結構提供 guardrails，LLM 在 guardrails 內活動**。

**LLM 參與的五個位置：**

1. **強化 lift() 的語用分析**（最高價值）：處理 Pattern Engine 沒覆蓋的慣用語，結果標 `llm_suggested`
2. **語義阻抗顧問**：提供人類可讀的跨語言遷移建議，不做自動翻譯
3. **敘事投影**：語義樹→自然語言解說，LLM 可完全主導（自然語言本身是機率性的）
4. **自動化系統擴充**：LLM 生成 JSON 定義，確定性系統驗證（五路徑 + roundtrip test）
5. **語義搜尋與自然語言建構**（Scope 4-5）：LLM 生成語義結構（不是程式碼），再自動投影

**仲裁規則：**

```
確定性系統 = 自動機（可自動寫入語義結構）
機率性系統 = 顧問（需要人類或確定性系統批准）

優先序：Pattern Engine > 使用者確認 > LLM 建議 > 降級
```

| 場景 | Pattern Engine | LLM | 仲裁結果 | confidence |
|------|---------------|-----|---------|------------|
| 共識 | 匹配成功 | 同意 | 採用 PE | `high` |
| PE 優先 | 匹配成功 | 不同意 | 採用 PE | `high` |
| 人在迴路 | 無法匹配 | 有建議 | 呈現為建議，使用者決定 | `llm_suggested` → 驗證 → `user_confirmed` |
| 安全網 | 無法匹配 | 也沒建議 | 降級 | `raw_code` |

**結構化驗證閘口**（防止 L0 使用者誤認 LLM 錯誤建議）：

```
LLM 建議 → 使用者確認 → 強制 roundtrip test
  → 通過 → user_confirmed（結構化寫入，參與 roundtrip）
  → 不通過 → user_confirmed_unverified（保留但標記，不參與跨語言映射）
            + UI 顯示「此元件未通過自動驗證」
```

**L0 使用者可能不懂 LLM 建議的正確性，但 roundtrip test 不依賴使用者的認知能力。**

## Soundness / Correctness / Adequacy

Guardrails 保證的是**結構健全性**，不是**語義正確性**：

```
Soundness（系統保證——Protocol）：
  LLM 輸出的結構 S' 是合法的語義結構
  → 可無損投影到所有視圖；roundtrip test 通過；元件路徑完備

Correctness（使用者維護——Agency）：
  S' 是否符合使用者意圖
  → 只有使用者能判斷
  → 但使用者的判斷不是任意的——它服務於程式邏輯的內在健全性

Adequacy（數據驗證——Data）：
  S' 是否在實際環境中產生預期行為
  → Round-trip test、執行測試、User Context 數據
  → 客觀可量測，不依賴主觀判斷
```

**管家式職責分工（Stewardship Model）：**

```
人類的角色不是「創造真理」，而是「維護健全性」。
  → 人類不是在「發明」新的程式結構，而是利用元件代數實踐具體目標
  → 「我想讓它做 X」受制於「X 在這個語義結構中是否有意義」

LLM 的角色不是「替代人類判斷」，而是「提供機率性輔助」
  → 它不能動搖系統底層的確定性公理
  → 即使「很有信心」也不能自動寫入
  → 類比：AI reviewer 可以留言，不能 merge PR
```

**可審查性是 correctness 的前提**：系統保證 soundness，使 LLM 的輸出可以被無損投影到使用者理解的視圖中，從而讓使用者**有能力**判斷 correctness。如果投影本身有資訊丟失（如 raw_code 降級），使用者的審查也是不完整的——這是 raw_code 降級的另一層代價。

**confidence 的三維解讀**：`user_confirmed` 不代表「系統驗證為正確」，而是「公理（roundtrip 通過）和主體（使用者接受）都已確認，但情境（長期數據）仍在累積」。

## 自舉與元教學

### 核心同構：教學路徑即語義樹

```
語義樹 (Semantic Tree)     ≅     教學層級樹 (Topic Level Tree)
   ↓                                  ↓
程式的結構                          知識的結構
   ↓                                  ↓
積木/程式碼 = 投影                   課程/練習 = 投影
```

**這不是比喻——它們在數學結構上同構。** 這意味著 P1-P4 不只適用於「程式碼↔積木」轉換，它們是**認知投影的通用公理**。

### 注意力遮罩

P4 的本質是：**語義結構始終完整，只有可見集合隨脈絡改變**。所有「選擇性呈現」都可統一理解為注意力遮罩函數 `mask(context) → VisibleSet`：

| 注意力遮罩類型 | context 參數 | 已實現 |
|---------|-------------|--------|
| 教學注意力 | 學習者的 enabledBranches | 是（Topic Level Tree） |
| 風格注意力 | Code Style 偏好 | 是（Style Preset） |
| 鷹架注意力 | Program Scaffold 層級 | 是（L0 隱藏→L1 ghost→L2+ 手動） |
| ZPD 注意力 | 學習者的近側發展區（自動偵測） | 否 |
| 領域注意力 | 跨學科的語義投射 | 否 |
| 多頭投影 | viewType（積木/程式碼/流程圖/敘事） | 部分（積木+程式碼） |

**與 Transformer 的類比**：固定的 L0→L1→L2 線性解鎖類似 RNN 的步進遞迴，容易卡在局部最佳解。Topic + enabledBranches 架構類似 Transformer 的自注意力——結構從一開始就完整存在，遮罩決定當前可見的子集，任何節點都能直接關注任何其他節點而不受順序限制。多維投影類似 Multi-head Attention。

### 映射還原：優化目標的修正

```
原本：效能最大化（學習者速度最快 = 最好）
  → 風險：過度適應使用者偏好，偏離知識的客觀結構

修正後：結構還原度最大化（映射越接近知識的內在結構 = 越好）
  → 約束：最佳化路徑受公理維度（Protocol）定錨
```

關鍵差異：AI 自蒸餾優化的是**參數（Weights）**，趨近同一個目標；這裡優化的是**結構（Structure）**，並利用這個結構管理自身的複雜度。見 [history/010](../history/010-自蒸餾目標從效能改為結構還原.md)。

**不可變原形（Static Prototype）：**

```
不可變原形 ≡ 元件代數的路徑完備性

lift → render → extract → generate 閉合
  → 這個性質不隨 Topic 層級樹的優化而改變
  → 如果某次自蒸餾的結果違反完備性 → 回退（不是放寬約束）
```

**自蒸餾檢查點（每次迭代）：**

```
1. Protocol 對齊：新層級樹不違反路徑完備性
2. Data 驗證：新層級樹在實際學習數據上表現不劣於前代
3. Agency 簽署：教育專家或系統管理員審查並接受變更

缺少任一維度 → 拒絕本次迭代
```

### 認知外骨骼

系統的最終形態不是替人思考的 AI，而是**認知外骨骼**：

```
┌─────────────────────────────────────────────────┐
│  人類意圖 = 神經訊號（定義「為什麼」）              │
├─────────────────────────────────────────────────┤
│  元教學腳本 = 傳動系統（管理複雜度的輸出）          │
│  ├─ 注意力遮罩（P4）：控制認知負荷                 │
│  ├─ 精密摩擦：製造有效挑戰                        │
│  └─ 自蒸餾：遞迴優化教學路徑                      │
├─────────────────────────────────────────────────┤
│  語義投影 = 感知系統（讓你看見結構）                │
│  ├─ 多維投影：積木/程式碼/流程圖/敘事               │
│  └─ ZPD 自適應：動態調整可見集合                   │
└─────────────────────────────────────────────────┘
```

## 系統的完備性邊界

自舉有一個邏輯極限：**系統可以優化所有分支，但根公理必須由外部預設。** 這不是缺陷，而是設計——類似哥德爾不完備定理：任何足夠強大的系統都無法完全證明自身的一致性。

```
T = Protocol_fixed ∩ Data_dynamic | Agency_responsible
```

**種子層級**：最初的根公理（[principles.md](../principles.md) 本身、Topic Level Tree 的根節點）仍需依賴人類的洞察和教育專業。根公理是人類在主體維度的核心職責，正如路徑完備性是系統在公理維度的核心承諾。

這呼應 Sc2（積木不可引入程式碼中不存在的概念）——**系統不能無中生有。**
