# 左值

> **一顆會【寫入】的元件，它的左值必須被【結構表達】。**

🔄 **2026-08-26 使用者拍板改寫**（舊的那句是「必須是**接點**」）——見
[history/157](../history/157-左值的判準從必須是接點改成必須被結構表達.md)。
舊的那句把**一種特定的表達方式**當成了規範本身。

## 為什麼這是一個概念，不是一顆元件的問題

它在三個視角上都投影得出來：

| 視角 | 投影 |
|---|---|
| **規範** | P3 開放擴充——「一個文法該由組合表達，不由列舉表達」 |
| **情境** | 路線圖「[左值是接點，不是字串](../vision.md)」，棘輪 10 → 0 |
| **存在** | [experience](../experience.md)「列舉已知的，等於保證下一個會被漏掉」 |

## 兩種誠實的形狀

```
接點      target: expression                    `a[i]`／`o.x`／`*q` 任意形狀
名字＋接點 obj: 'a'（真的原子）＋ index: 接點     `a[i]`，而 `a` 本身不是文法
```

**兩格合起來也是結構。** `cpp:array_assign` 的 `obj: 'a'` ＋ `index` 接點
完整表達了 `a[i]`，一個字都沒有被壓扁——那顆複合積木
「把陣列 a 的第 [i] 格 設成 [v]」因此**留下來**。

🔴 **而第二種形狀有一個附帶條件**：那一格必須**真的**是原子。
`kind: 'identifier'` 只是一句**主張**，而 2026-08-26 實測四筆當場漏
（`*(p + 1)`／`obj.arr[i]`／`m[k].y`）。所以第七十三條護欄從
**讀宣告**改成**主動探測**：餵一組刻意合成的左值去試著推翻它。

> **「這一格是原子」是一句主張，而主張要有人去試著推翻它。**

⚠️ 而複合元件因此要有**判別**：容器不是一個名字時，**讓給組合形式**。
`obj.arr[i] = 1` 走 `var_assign(target = array_at(struct_at_member(obj, arr), i))`。

> **一個複合元件的存在條件，是它的每一格都真的裝得下自己那一格。
> 裝不下的時候，正確的做法是【讓給組合形式】，不是把它塞進去。**

## 判準：**這個分派是列舉式的還是扣除式的？**

```
列舉式   「變數名的、陣列的、成員的、指標的、……」   → 下一個必然被漏掉，而且是靜默的
扣除式   「左值是一個運算式」                      → 沒有下一個
```

左值的形狀是**開放集合**：`x` · `a[i]` · `a[i][j]` · `o.x` · `p->x` · `*q` ·
`a.b.c` · `f().x` · `d["k"]` · `(*p).x`……**每一種都是一個既有的運算式節點**。
把它們存成字串，等於把整個運算式文法壓進一個 `literal`。

## 🔴 症狀不是「壞掉」，是**假裝結構化**

```
存成字串     name: "o.x"      看起來成功了
渲成下拉     [變數 ▾]         而那個下拉列的是變數清單
使用者點一下                   成員存取被毀掉，而沒有任何東西出聲
```

> **同樣是「字串裝著文法」，會出事的是那個【被投影成選單】的。**

它同時違反 P6：**既不誠實也沒降級**——`cpp:var_assign_compound` 的宣告
逐字寫著 `nums[0] += 1` 會「誠實降級」，而 2026-08-25 實測**它沒有**，
它比對成功並把 `nums[0]` 當成變數名。根因是 2026-08-21 為了放行 `self.n += k`
拿掉了 `constraints`。

> **一個為了放行 A 而拿掉的限制，會同時放行沒有人想過的 B
> ——而那句「B 仍然被擋著」的註解不會有人回來改。**

## 執行面：**左值不是值，是「那一格」**

求值整個左邊會**讀出**那一格現在的值——而寫入要的是那一格本身。
所以每一顆賦值執行器都要拆開 target 節點：

```
member_at    → 接收者是 children.obj，欄位名是 properties.member
container_at → 容器是 children.target，鍵是 children.key
var_ref      → 就是環境裡那個名字
```

🔴 **而「每一顆各自拆」就是列舉式分派**。扣除式的做法是一個
**左值解析器**：給一顆 target 節點，回傳可讀可寫的那一格，
按 `componentId` 分派、可登記——加一種新形狀不改任何既有執行器。

## ⚠️ 它動的是語義詞彙本身

`principles.md:158` 逐字：

> 「**但語義詞彙本身的變更不在此列**（例如 `componentId` 改名）：那動的是真實，
> **沒有東西可以重建它**……這種變更 MUST 附**一次性的轉換**」

所以每一筆都要附載入時的轉換：舊存檔的 `name: "o.x"` 要被**解析**成巢狀節點
——而那個 parser 已經在（tree-sitter）。
