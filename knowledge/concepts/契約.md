# 契約（Contract）

**契約是「這顆元件什麼時候成立、保證什麼」那幾句話——而每一句都要說得出誰會因為它假了而叫。**

```
preconditions   我什麼時候能用          精化【脈絡 · 埠 · 參數】
postconditions  我保證產出什麼          精化【形態 · 行為 · 形式】
invariants      什麼永遠成立            🔴 宿主兩個：元件 ／ 組裝
```

**三視角投影：**

- **原則**：「還不會檢查」≠「錯了」（第三十二條護欄）——階梯的每一格都是這句話的一個位置。
- **願景**：跨域合流的**共同語**。硬體的 DRC、UI 的 a11y、ML 的效期，用同一組詞說。
- **經驗**：這個 repo 對「自洽而錯」的標準答案（正向錨點 ＋ 入口條件斷言）在契約上**逐字重現**。

## 🔴 契約不是第六槽，是加在槽上的精化

（2026-09-25 定案，走過「第六槽」與「橫跨五槽的第二維度」兩個錯答案。）

| | 問什麼 | 產物 |
|---|---|---|
| **槽** | 填得出嗎 | **剪枝力**——填不出就不是元件，剪掉 |
| **契約** | 填了之後有沒有人判 | **棘輪**——一個數得出來、只能往下的數字 |

叫它第六槽，剪枝規則就變成「填不出契約 ⟹ 不是元件」——而 349 顆今天一個判定者都沒有，它們全都是元件。**那是一條假的剪枝規則。**

型別上的形狀是 `{x : T // P x}`：**槽是 `T`，契約是 `P`。**

⚠️ **而「橫跨五槽的一個維度」也不對**——戳破它的是 `invariants`：

```
precondition   宿主：元件        判定在【一個點】（進入）
postcondition  宿主：元件的路     判定在【一個點】（離開）
invariant      🔴 宿主【兩個】    判定在【一段軌跡】／【整張網】
               Σ through(我的腳)=0      ← 住元件
               這條 net 只有一個 driver  ← 🔴 不屬於任何一顆元件（見 [組裝](組裝.md)）
```

> **「契約」這個詞底下的三個欄位，宿主是三個不同的主體。**

⚠️ 今天 `"invariants": []` 把兩個宿主混在一格；schema 要分得出「我自己判」與「我上交給組裝」。

## 主張是四元組

```json
{ "claim": "…", "why": "…", "witness": { "ok": "…", "violates": "…" }, "judge": "…" }
```

| 格 | 它擋住什麼 |
|---|---|
| `claim` | —— |
| `why` | 意圖寫在謂詞旁邊 ⟹ 不對齊是**局部可見**的，不必讀完整個系統 |
| `witness` | ① 量測有輸入 ② **空洞為真**擋住（pre 不可滿足就交不出見證）③ 🔴 意圖對齊看得見 |
| `judge` | 🔴 階梯是它算出來的；而它是 `null` 的那些，是這整個設計最該數的數字 |

### 🔴 而四元組少一格：**主張要有名字**（2026-10-02）

三類約束今天只有兩類**定址得到**：

```
postconditions   🟢 以路徑名為鍵   execute／generate／render／extract／formalize
invariants       🟢 有 name 欄位   { "name": "exclusive", … }
🔴 preconditions  ❌ 無名陣列       { claim, why, witness, judge }
```

而 `preconditions` 正是最需要被外部指名的那一類——前置條件是**跨出去**的那些
（`LtB index n`、`I(anode) ≤ If_max`），而 post／invariant 多半留在家裡。

⚠️ **退而用索引不行**，理由與我們對方程列名的要求同一條：

> 索引在重排之後會指到別的東西，而那是**靜默的**。

`preconditions[0]` 一樣：有人在前面插一條，所有指到它的東西就安靜地偏一格。

🔴 **而「用 claim 的內容雜湊當鍵」也不行，理由不顯然**：外部要問的問題是
「**這條約束的 claim 變了沒**」——而雜湊當鍵的話，claim 一變就是**另一個鍵**，
那個問題就變成「找不到」而不是「變了」。

> **要偵測一樣東西變了，它的鍵必須在它變的時候【不變】。**

⟹ 鍵必須是**身分**，不是內容。而身分在這個庫裡一向是具名的（`componentId`、
接點名、`invariants[].name`）——`preconditions` 是唯一的例外。

（起點：姊妹專案的事實檔要用 `componentId → { 約束名 → 雜湊 }` 定址，
而我們生不出那個約束名。）

🔴 **`witness` 的第三用途值得單獨記**：

```
「這個【例子】不是我要的意思」   人一眼看得出來
「這個【謂詞】不是我要的意思」   人看不出來
```

⟹ 見證要當成**給人讀的東西**，不只是餵給檢查器的輸入。

## 🔴 而 `judge` 旁邊要有 `assumes`——判決永遠是「在這些假設下」

（2026-09-26，與 cella 對出來的。它的 `Verdict` 也同步從 `Accept { certificate, … }`
改成 `Verdict { assumptions, outcome }`。）

`judge` 回答**誰判的**。而有一整類東西既不是判定者也不是主張，是**那個判決的前提**：

```
機器模型   「這條指令在這顆 MCU 幾 ns」—— 換一顆晶片,同一個判決給不同答案
效期      ML 的 `validOn` ／ `measuredAt` ／ `expiresWhen`
🔴 frame   並行之下的那一半：「我執行期間【沒有別人能改】obj」
```

🟢 **那一欄因此不是為了容納機器模型而加的，它收斂了三格**——而那正是這個 repo
決定要不要加一欄的判準：**看它讓幾個原本散著的東西歸位。**

### 🔴 而 `assumes` 為什麼存在，2026-09-30 才有一句話說得清楚

cella 那側把驗證的牆從「領域」改成「**演繹與經驗之間**」：

```
牆內   從前提推得出的主張    牆外   前提本身符不符合世界
跨牆   量測讀數以【帶來源、帶日期、會過期的假設】進去
```

⟹ **`assumes` 就是那道牆上的門。** 判定者只做牆內的事，而牆外的東西
（材料、量測、元件的 `ε`）**只能以假設的身分進來**，判決因此永遠是
「給定這些量測，結論成立」。

🔴 **而跨牆的宣告住在元件這邊，不是判定者那邊。** `ε` 有兩個讀者：

```
界的傳播    演繹 → 牆內 → 判定者讀它
漸進揭露    🔴 不是驗證,連牆都不在 —— 課文讀它,給學生看
```

一個欄位若被定義成判定者的輸入格式，第一個讀者（課文）就得去讀一個驗證器的
資料結構，而它只想知道「`delay(1000)` 不是剛好一秒」。

> **「跨牆」講的是它怎麼進去，沒有講它住哪裡。**

⚠️ **而「帶日期」不夠，要有東西會紅。** 一個帶著三個月前日期的假設，在傳染鏈上
長得跟今天的一模一樣。形狀借對照圖的 `engineHash`（引擎變了就紅），而判準要
**可檢查**，不只是說得出症狀：

```
說得出症狀   一份過期的誤差界,讀起來與一份有效的完全一樣       ← 診斷
跑得動的判準 同一證明在條件成立時與失效後,要得到【不同】判決    ← 可注入否證
```

經過見 [一條比我們自己的軸更好的牆](../draft/2026-09-30-一條比我們自己的軸更好的牆.md)。

### 🔴 而「這條約束變了」有兩種，要分得開

一條主張的身分若用內容雜湊，最直覺的做法是把 `claim` 與 `witness` 一起雜湊
——而那會把兩件完全不同的事壓成同一個訊號：

```
claim 變了      這是【另一條約束】        ⟹ 證明必須重做
witness 變了    規格沒變,是我們【多檢查了一點】 ⟹ 證明仍然有效
```

⚠️ **壓在一起的代價落在加反例的人身上**：加一個 `violates` 會讓所有證書失效，
於是**沒有人敢加反例**——而那正好毀掉 `witness` 存在的第三個理由
（意圖對齊看得見）。

🟢 **而失效的方向仍然要往多的那邊倒**，因為反方向的錯是靜默的：

```
過度失效   證書白白重算        吵的、便宜的
失效不足   一張過期的證書      🔴 讀起來與一張有效的完全一樣
```

⟹ 兩個雜湊，而不是一個放寬的雜湊。**「規格變了」要失效得乾淨，
「我們多檢查了一點」不該罰人。**

（2026-10-01 與 cella 對出來的。而前提是**證書要便宜到可以重算**
——一條要跑一次 SMT 才證得出來的約束，上面那句話就不成立了。）

⚠️ 最後那一條值得單獨說：`frame: []` 今天讀成「我不改東西」，並行之下要讀成
「我不獨佔任何東西」——**而那是對環境的假設，不是對我自己的主張**。它原本被歸在
`postconditions` 底下，而它其實屬於這一欄。

### 🔴 而它不只是誠實——**不帶假設的判決重播不了**

cella 花了一整天修「同一份輸入檢查兩次結果不同」，而它回頭看的結論逐字：

> 那些讓結果不同的東西，**全部都是沒有被寫進判決的假設**（模組的檢查順序、
> 上一個 session 殘留的型別表、用哪一份同名定義）。
> **一個不列假設的憑證，你沒辦法判斷兩次不同的判決是【發現了新東西】
> 還是【跑在不同的前提上】。**

⚠️ **而這對我們不是提醒，是帳單**——同一個形狀我們付過三次，每一次都是
「判決寫著『跟參照編譯器一樣』，而沒有寫【哪一台】」：

```
2026-09-17  本機 Apple clang 的 <set> 遞移帶進 <deque> —— CI 的 GNU g++ 不帶
2026-09-18  同一個坑,這次是 <queue> 與 <tuple>
2026-09-19  0.0/0.0 印出 nan（libc++）vs -nan（libstdc++）
```

🟢 當時的處方是**換掉判準**（NaN 的正負號未指定 ⟹ 改問 `c != c`）。
而那治了那一次——**列假設才治那一族**。

⚠️ 而 `assumes` 該掛在**判決本身**，不是只掛在「通過」那一側：**一個拒絕也可能是
條件化的**（「在這個機器模型下它超時」），而一個條件化的拒絕被讀成無條件的，
會讓人去改一段本來沒問題的程式。

## 🔴 階梯是判定者的函數，不是宣告的等級

```
L0   沒有判定者                  「寫下來了，而沒有任何東西會因為它假了而變紅」
L1   判定者是【元件或直譯器】       執行期
L2   判定者是【外部 oracle】       貴 ⟹ 取樣
L3   判定者是【型別檢查器】        全稱
```

> **你不宣告等級，等級是「誰判它」算出來的。**
> 宣告 `evidence: "L2"` 就是宣告一個會說謊的欄位。

🟢 順帶解掉兩件：

- `L3-elab` vs `L3-kernel` 不是等級的細分，是**兩個不同的判定者**
- 一條契約可以**同時**被直譯器判（L1）與被 cella 判（L3）⟹ **一條契約 ＋ 一組判定者，階梯是那組的最大值**

**而判定者來自不同的池：**

| | 判定者通常是 | 為什麼 |
|---|---|---|
| `precondition` | 🟢 一顆元件（導得出來） | 它是**輸入上的**謂詞，而輸入你手上就有 |
| `postcondition` | 🔴 另一條投影，或外部權威 | 「對」要**相對於別的東西**定義 |
| `invariant` | 🟡 一個引擎（型別檢查器／求解器） | 它是**全稱的**，不是對某一次的斷言 |

中間那一列是關鍵：**要檢查後置條件就得先知道答案；而如果你獨立知道答案，你就不需要那個實作了。** 所以它只有兩條路——① 輸出**自己的**可判定性質（「parse 得過」「載得進工作區」「取回的身分是我」），或 ② **跟參照對答案**（`execute ≡ g++`，很貴 ⟹ 取樣）。

## 🔴 而「取樣」有一格是空的，不是弱的

```
性質（property）          看【一次】執行就判得出來     「回傳值 = …」
🔴 超性質（hyperproperty） 要看【多次】執行【之間】     「不管輸入是什麼，花的時間一樣」
```

跑一千次都一樣快，**不代表第一千零一次一樣快**——那不是樣本不夠，是**那個性質不住在單次執行裡**。

⟹ **對超性質，L2 那一格是空的**：要嘛資訊流型別（L3），要嘛沒有。

> **「弱證據」與「不是證據」混在同一格裡的時候，前者會讓人以為多跑幾次就好。**

## 判定還有一個範圍，而它不是強弱

```
一個點      進入時 · 離開時                pre · post
一段區間    在我持有它的那段時間內           🔴 並行：frame 從「我改什麼」長成「我獨佔什麼」
一個效期    到某一天為止                    🔴 ML：判定會過期
```

⚠️ `frame: []` 今天讀成「我不改東西」；並行之下要讀成「我不獨佔任何東西」——**兩句不同的話**，而第二句在單執行緒下**恰好**也成立，所以今天看不出差別。

## 閉集 vs 謂詞：兩層，而規則是導出不要並存

**列舉值有剪枝力，謂詞沒有。** `law` 恰好兩個值，正因為它是閉集，填域的時候才量得出「UI 是唯一沒有守恆關係的域」——**那個觀察來自列舉，不來自謂詞**。換成自由謂詞之後，沒有人知道總共有幾種律，跨域那張地圖畫不出來，「加一種」從顯式決定變成一次 commit。

而 `pre` 這邊更危險，因為**讀閉集的不只一個消費者**：

```
positions      渲染器挑形態 · 第 126 條護欄
slots.allowed  工具箱能不能拖進去
accepts        連接層能不能連
params.values  下拉選單的選項來源
```

**工具箱沒辦法從一條全稱命題生出一個下拉選單。**

🟢 所以要兩層：

```
結構化的      閉集，多消費者讀得懂        ← 源，人寫
謂詞形式的    求解器讀得懂                ← 由上面【導出】，不手寫
                                        ＋ 表達不出來的才手寫（逃生艙）
```

🟢 **具名不變量**是兩者同時要的辦法：列舉留著，而每個值的定義從散文換成一條寫得出來的謂詞。寫出來之後有件事自己浮現——`exclusive`（持有者的基數限制 → 線性**邏輯**）與 `shared`（網上的方程組 → 線性**代數**）**不是同一種東西**，而它們今天並列在同一個欄位裡。

## `severity`：哪一級的判定是可接受的

L1（執行期檢查）的價值前提是「違反了還能重來」。兩個讀數同一天推翻了它的一半：

```
🔴 不可逆的動作     撞上去、馬達燒了 → 執行期檢查是【太晚】不是【便宜】
🟢 型別檢查變快了   cella 冷啟動 9,724 ms → 108–180 ms（改走快照）
                  每次編輯 **中位數約 140 ms**（六個實測 80·118·119·163·182·189）
                  ⟹ L3 從「離線的奢侈品」變成可以當主要檢查
```

⚠️ **而這個數字被更正過一次**（2026-09-25，cella 自己送來的）：
它原先報的是「80–119 ms，設計要求 <100 ms」——**那是六個裡挑出來的兩個**。
離互動級還差約 1.4 倍，不是 0。排優先序用 **140**，不是 100。

> **一份報告的語氣，是它沒有寫出來的那一欄
> ——而「選哪幾個當結論」正是那一欄。數字可以每一個都對。**

```
軟體 · 可重來      L1 仍然划算（而 L3 現在也負擔得起）
🔴 不可逆          L1 沒有用 —— L3，或者【物理上的攔截】（限位開關、力矩上限）
🔴 跨信任邊界       L1 永遠不能關（行程內可以在 release 關掉，跨網路不行）
```

⚠️ 而可靠度還有一維：**它在哪裡跑**。會自己跑的測試，只在它跑的那個環境裡有效——
`npm test`（Node／happy-dom）· e2e（真 Chromium）· VSCode 擴充（🔴 幾乎沒有自動化）。
**醜的、在所有平台上跑的間接判準 > 漂亮的、只在一個平台上跑的直接判準**，因為後者的沉默看起來跟通過一模一樣。

## 剪枝力：說不出判定者的，不是契約

```
今天的宣告   「這顆元件保證什麼」
要加的       「而那句話，【誰】會因為它假了而叫？」
```

> **剪枝力從「填得出五槽嗎」延伸到「說得出判定者嗎」——說不出的，不是一條契約。**

「這顆積木好懂」誰判？沒有人 ⟹ 它不是一條契約，是一個願望。
（而正確的處理不是刪掉它，是寫 `judge: "human"`——**寫明，不留白**。）

## 🔴 邊界：契約蓋不住的三格

**① 形態那一維結構上沒有 oracle。** `render` 的 post 寫得出「產出的 state 載得進工作區」，**寫不出「這顆積木的標籤沒有說謊」**。這不是還沒建，是結構性的（見 [等價與觀察集](等價與觀察集.md)）。而那正是 stack／queue 的 push 標籤說謊那次——**十八條護欄一條都不叫，學生第一眼看出來**。

**② 累積性，布林謂詞蓋不住。** 誤差累積（列印公差、數值漂移）不是「成立／不成立」，是一個會長大的量。它要的是 `|err| ≤ δ`（界），不是 `x > 0`。塞進 invariant 會得到一條**永遠為真直到突然為假**的謂詞。

**③ 規格與意圖不對齊。** 那是 validation 不是 verification，形式系統**結構上**到不了。而要加的那一格是：

> **保證對齊不是系統的責任，但「對齊壞了的時候有沒有東西會變紅」是。**

🔴 **三件事是同一個形狀，全都是「自洽而錯」：**

| | 症狀 |
|---|---|
| 空洞為真的契約 | 全綠，而它**什麼都沒驗** |
| 形式核的編碼漂了 | 全綠，而它驗的是**另一支程式** |
| 規格與意圖不對齊 | 全綠，而它驗的是**另一個意圖** |

處方是這個 repo 每一條護欄檔頭都有的那兩樣：**正向錨點 ＋ 入口條件斷言**。

> **一份「全部證明通過」的報告，先問那些命題裡有幾條是空洞為真的。**

⚠️ **證明不進存檔。** 語義樹與契約是真實、要存；證明是導出物，走 `engineHash` 那個已經在跑的機制——契約變了或驗證器版本變了，證書就過期。而第 218／219 刀的疤在這裡會再出現一次：**一個修好了的缺陷，在它的產物重產之前，讀數上與沒修一模一樣。**
