# 等價與觀察集

> 「這兩個東西一樣嗎」——**沒有無條件的答案**。
> 答案取決於**你允許誰去看**、**要求多準**、以及**多久能對一次答案**。

## 為什麼需要這個概念

系統裡到處都在宣稱「這兩個算同一個」，而每一處都用不同的方式在說，
彼此不知道對方存在：

| 哪裡 | 宣稱什麼 | 缺了什麼 |
|---|---|---|
| `abstractConcept` | 這顆可以降級成那顆 | **沒說在哪種問題底下還算對** |
| [投影](投影.md)的執行體選擇 | 「∀ 合法輸入，`A(input) ≡ B(input)`」 | 那個 `∀` 是不可判定的形式，沒有觀察集也沒有容差 |
| 元件該不該合併 | 這兩顆是同一個概念 | 相對於**當前**的測試才成立，而測試會增加 |
| 課程降級 | 對這一關的學生，A 可以當成 B | 只在**顯示**成立，卻被拿去**執行** |

第四列在 2026-08-08 炸出一顆真的 bug：`vector<int> v;` 被降級成 `int v;`，
執行時 `v[0]` 型別不符。**一個沒有標註適用範圍的等同關係，一定會被用到
它不成立的地方去。**

## 一、身分是內涵的，等價是外延的

| | 內涵 | 外延 |
|---|---|---|
| 是什麼 | 這顆元件**被定義成什麼** | 它在某組觀察下**表現成什麼** |
| 誰決定 | 宣告 | 量測 |
| 穩不穩 | **不可撤回**（id 進了使用者存檔） | **可修訂**（觀察集會長大） |
| 相對於誰 | 自己 | 情境 |

這一刀讓兩件看似矛盾的事並存：**「沒有絕對元件」與「id 必須穩定」講的是不同層。**

### 剪枝力①：合併是把可撤回的升格成不可撤回

> **外延等價是可以收回的觀察；內涵身分是收不回的承諾。**

「這兩顆行為一樣，合併吧」——那是拿當前觀察集下的一個觀察，去做一個
進了存檔就改不動的決定。觀察集會長大（加語言、加精度要求、硬體進來），
今天分不出來的兩顆明天可能分得出來，而那時撤不回。

→ **傾向少合併、多記對應**：身分保持分開（便宜、穩定），
等價當成邊記著（可修訂、可量測、**可退步**）。

### 剪枝力②：名字不必宣稱通用性

名字是內涵的，只需要對得起自己的定義。**「通用」是外延的，不住在名字裡。**

`cpp:string_find_first_not_of` 這個名字沒有錯——它誠實地命名了一個 C++ 的東西。
錯的是期待名字同時宣告它的外延範圍。

> **名字要說得出這顆元件自己是什麼，不必宣稱它跟誰一樣。**

見 [draft/元件命名重新設計](../draft/2026-08-08-元件命名重新設計.md)——
那份 draft 的第一版判定就是踩了這一條（用命名去表達通用性），已記為翻轉。

### 剪枝力③：同一個判斷，放哪一層決定它能不能被收回

這是上面那條的一般形式，而它有一個實例值得記住：

「Python 的 `list` 對應到哪顆既有元件」——

- 放在**身分層**（統一成一個 `lang:sequence_declare`，讓 Python 去對）→ **承諾**，
  進了存檔改不動
- 放在**轉換層**（`py:list_declare` 自成一顆，另寫一條轉換規範）→ **觀察**，
  錯了可以改、可以量、可以附損失刻畫

**同一個判斷，兩種放法，可撤回性完全不同。**

推薦「統一成一個大 scope」時很容易以為那避開了判斷——**它沒有，它只是把
判斷延後到下一個語言進來的那天，而那時它仍然是身分決定。**

## 二、等價的完整形式

不是「A 和 B 相同嗎」，而是：

> **在精度要求 ε、回饋週期 T 底下，能不能視為相同。**

### 判斷是算出來的，不是存起來的

```
情境會問的問題  ⊆  對應保住的問題   →   在這個情境下可以視為相同
```

存判斷是 元件² × 情境，必爆。**存兩邊的素材，判斷用算的**：
對應保住什麼（邊的數量，不是 N²）＋ 情境問什麼（一個情境一筆）。

這與「登錄表導出」是同一個動作（見 [history/029](../history/029-E項登錄表導出-清單不是碎裂是量測算錯了.md)）——
**別存導得出來的東西。**

### 「問題」的詞彙已經存在

完備性護欄的**五路**（lift／generate／render／extract／execute）就是
「系統會對一顆元件問的問題」。用它重看那顆 bug：降級**保住了 render**
（畫面沒壞）、**沒保住 execute**（`v[0]` 問不出答案）——而顯示情境只問
render，執行情境問 execute。**容差是為一個用途定的，卻被另一個用途用了。**

### 預設要保守

沒宣告 = 不可互換。只在有人真的要主張什麼時才寫——與
`declareNonComponent` 沒寫理由就擲例外同一種紀律（見 [執行機構](執行機構.md)）。

## 三、累積性是環路的性質，不是那一對的

```
總誤差 ≈ 每步誤差 × (經過時間 / 回饋週期) + 量測誤差
```

回饋週期趨近每一步時，右邊塌成 `每步誤差 + 量測誤差`——**累積性消失**。

所以「這個損失要不要緊」不是問這對元件，是問：**多久能拿到一次殘差。**

### semorphe 大部分是閉環的，而開環的地方正好在出事

雙向投影就是殘差量測；「⇄ 自動」把回饋週期壓到每次編輯。
**這是它敢用有損轉換而不出事的原因。**

兩處開環：

1. **存檔**——存下去、一週後打開，中間沒有回饋
2. **降級**——它**刻意產生一個不等於真實的東西，而沒有任何地方量那個差**

第 2 點就是那顆 bug 的真正成因。修法兩選一：降級後量一次殘差（閉環），
或**禁止開環進入需要精度的用途**（降級過的樹不准拿去執行）。

### 封閉系統 vs 開放系統

封閉系統（無外界影響）原則上模型可無限逼近；**開放系統的誤差不是模型
不夠好，是原理上消不掉**——有未建模的輸入，只能靠回饋界住。

軟體裡這條線也在：`lang:arithmetic` 封閉，`lang:input`／檔案串流／執行時間開放。

> **封閉的東西，等價可以用推理定；開放的東西，只能用「帶回饋的觀察」定。**

## 四、不可判定，但有希望：區別力是局部的

外延等價要對所有脈絡量化——一般情況不可判定。有希望的來源是：

> **如果 A 和 B 有差別，那個差別會在碰得到它們差異的觀察底下暴露。**

**這個賭注專案已經下了**——`fuzz-cpp-containers`／`fuzz-cpp-strings` 按模組
分組就是鄰域取樣。如果區別力不局部，這種分組毫無意義。

### 而它只涵蓋一半

| | 結構性的差別 | 累積性的差別 |
|---|---|---|
| 例子 | 能不能索引、有沒有順序 | 浮點精度、模型誤差、時序漂移 |
| 一步之內看得到 | ✓ | ✗ |
| 區別力 | 局部 | **非局部**（觀察在時間上遠，不在圖上遠） |
| 該用 | 鄰域取樣（fuzz、組合測試） | **界**（誤差上界、傳播分析） |

現在系統裡所有「等價」宣稱都是結構性的形狀（`abstractConcept` 是布林的）。
**硬體／數位孿生進來時第一個撐不住的就是這裡。**

⚠️ 小世界的另一半——幾跳可達——**幫你找到，也幫錯誤傳開**。
那個病有名字：**條件性正確**（單獨測都過，組合才壞）。

## 五、測試是在定義「相同」的解析度

不是在檢查對錯。加一支測試 = 把觀察集擴大一點 = 某些原本看起來相同的東西
會分開。

→ **「今天全綠」只說明在現有觀察集下沒有差別。**
那顆 `vector` bug 一直是綠的，因為沒有人在課程可見集合下觀察過。

## 與其他概念的關係

- [投影](投影.md)——執行體選擇的「外延等價」是這裡的**未加索引版本**
- [降級與認知邊界](降級與認知邊界.md)——降級是一個外延等價的宣稱，而它現在缺觀察集
- [元件](元件.md)——身分（內涵）與參數的界線；「差異是參數還是身分」的判準
- [執行機構](執行機構.md)——沒有觀察集的等價宣稱，是「規範沒有機械檢查」的一種
