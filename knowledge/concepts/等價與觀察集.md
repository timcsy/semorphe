# 等價與觀察集

> 「這兩個東西一樣嗎」——**沒有無條件的答案**。
> 答案取決於**你允許誰去看**、**要求多準**、以及**多久能對一次答案**。

## 為什麼需要這個概念

系統裡到處都在宣稱「這兩個算同一個」，而每一處都用不同的方式在說，
彼此不知道對方存在：

| 哪裡 | 宣稱什麼 | 缺了什麼 |
|---|---|---|
| `abstractConcept` | 這顆可以降級成那顆 | **沒說在哪種問題底下還算對** |
| [投影](投影.md)的執行體選擇 | 「∀ 合法輸入，`A(input) ≡ B(input)`」 | 那個 `∀` 是不可判定的形式，沒有觀察集也沒有容差 |
| 元件該不該合併 | 這兩顆是同一個概念 | 相對於**當前**的測試才成立，而測試會增加 |
| 課程降級 | 對這一關的學生，A 可以當成 B | 只在**顯示**成立，卻被拿去**執行** |

第四列在 2026-08-08 炸出一顆真的 bug：`vector<int> v;` 被降級成 `int v;`，
執行時 `v[0]` 型別不符。**一個沒有標註適用範圍的等同關係，一定會被用到
它不成立的地方去。**

## 一、身分是內涵的，等價是外延的

| | 內涵 | 外延 |
|---|---|---|
| 是什麼 | 這顆元件**被定義成什麼** | 它在某組觀察下**表現成什麼** |
| 誰決定 | 宣告 | 量測 |
| 穩不穩 | **不可撤回**（id 進了使用者存檔） | **可修訂**（觀察集會長大） |
| 相對於誰 | 自己 | 情境 |

這一刀讓兩件看似矛盾的事並存：**「沒有絕對元件」與「id 必須穩定」講的是不同層。**

### 剪枝力①：合併是把可撤回的升格成不可撤回

> **外延等價是可以收回的觀察；內涵身分是收不回的承諾。**

「這兩顆行為一樣，合併吧」——那是拿當前觀察集下的一個觀察，去做一個
進了存檔就改不動的決定。觀察集會長大（加語言、加精度要求、硬體進來），
今天分不出來的兩顆明天可能分得出來，而那時撤不回。

→ **傾向少合併、多記對應**：身分保持分開（便宜、穩定），
等價當成邊記著（可修訂、可量測、**可退步**）。

### 剪枝力②：名字不必宣稱通用性

名字是內涵的，只需要對得起自己的定義。**「通用」是外延的，不住在名字裡。**

`cpp:string_find_first_not_of` 這個名字沒有錯——它誠實地命名了一個 C++ 的東西。
錯的是期待名字同時宣告它的外延範圍。

> **名字要說得出這顆元件自己是什麼，不必宣稱它跟誰一樣。**

見 [draft/元件命名重新設計](../history/retired/2026-08-08-元件命名重新設計.md)——
那份 draft 的第一版判定就是踩了這一條（用命名去表達通用性），已記為翻轉。

### 剪枝力③：同一個判斷，放哪一層決定它能不能被收回

這是上面那條的一般形式，而它有一個實例值得記住：

「Python 的 `list` 對應到哪顆既有元件」——

- 放在**身分層**（統一成一個 `lang:sequence_declare`，讓 Python 去對）→ **承諾**，
  進了存檔改不動
- 放在**轉換層**（`py:list_declare` 自成一顆，另寫一條轉換規範）→ **觀察**，
  錯了可以改、可以量、可以附損失刻畫

**同一個判斷，兩種放法，可撤回性完全不同。**

推薦「統一成一個大 scope」時很容易以為那避開了判斷——**它沒有，它只是把
判斷延後到下一個語言進來的那天，而那時它仍然是身分決定。**

## 二、等價的完整形式

不是「A 和 B 相同嗎」，而是：

> **在精度要求 ε、回饋週期 T 底下，能不能視為相同。**

### 判斷是算出來的，不是存起來的

```
情境會問的問題  ⊆  對應保住的問題   →   在這個情境下可以視為相同
```

存判斷是 元件² × 情境，必爆。**存兩邊的素材，判斷用算的**：
對應保住什麼（邊的數量，不是 N²）＋ 情境問什麼（一個情境一筆）。

這與「登錄表導出」是同一個動作（見 [history/029](../history/029-E項登錄表導出-清單不是碎裂是量測算錯了.md)）——
**別存導得出來的東西。**

### 「問題」的詞彙已經存在

完備性護欄的**五路**（lift／generate／render／extract／execute）就是
「系統會對一顆元件問的問題」。用它重看那顆 bug：降級**保住了 render**
（畫面沒壞）、**沒保住 execute**（`v[0]` 問不出答案）——而顯示情境只問
render，執行情境問 execute。**容差是為一個用途定的，卻被另一個用途用了。**

### 預設要保守

沒宣告 = 不可互換。只在有人真的要主張什麼時才寫——與
`declareNonComponent` 沒寫理由就擲例外同一種紀律（見 [執行機構](執行機構.md)）。

## 三、累積性是環路的性質，不是那一對的

```
總誤差 ≈ 每步誤差 × (經過時間 / 回饋週期) + 量測誤差
```

回饋週期趨近每一步時，右邊塌成 `每步誤差 + 量測誤差`——**累積性消失**。

所以「這個損失要不要緊」不是問這對元件，是問：**多久能拿到一次殘差。**

### semorphe 大部分是閉環的，而開環的地方正好在出事

雙向投影就是殘差量測；「⇄ 自動」把回饋週期壓到每次編輯。
**這是它敢用有損轉換而不出事的原因。**

兩處開環：

1. **存檔**——存下去、一週後打開，中間沒有回饋
2. **降級**——它**刻意產生一個不等於真實的東西，而沒有任何地方量那個差**

第 2 點就是那顆 bug 的真正成因。修法兩選一：降級後量一次殘差（閉環），
或**禁止開環進入需要精度的用途**（降級過的樹不准拿去執行）。

### 封閉系統 vs 開放系統

封閉系統（無外界影響）原則上模型可無限逼近；**開放系統的誤差不是模型
不夠好，是原理上消不掉**——有未建模的輸入，只能靠回饋界住。

軟體裡這條線也在：`lang:arithmetic` 封閉，`lang:input`／檔案串流／執行時間開放。

> **封閉的東西，等價可以用推理定；開放的東西，只能用「帶回饋的觀察」定。**

## 四、不可判定，但有希望：區別力是局部的

外延等價要對所有脈絡量化——一般情況不可判定。有希望的來源是：

> **如果 A 和 B 有差別，那個差別會在碰得到它們差異的觀察底下暴露。**

**這個賭注專案已經下了**——`fuzz-cpp-containers`／`fuzz-cpp-strings` 按模組
分組就是鄰域取樣。如果區別力不局部，這種分組毫無意義。

### 而它只涵蓋一半

| | 結構性的差別 | 累積性的差別 |
|---|---|---|
| 例子 | 能不能索引、有沒有順序 | 浮點精度、模型誤差、時序漂移 |
| 一步之內看得到 | ✓ | ✗ |
| 區別力 | 局部 | **非局部**（觀察在時間上遠，不在圖上遠） |
| 該用 | 鄰域取樣（fuzz、組合測試） | **界**（誤差上界、傳播分析） |

現在系統裡所有「等價」宣稱都是結構性的形狀（`abstractConcept` 是布林的）。
**硬體／數位孿生進來時第一個撐不住的就是這裡。**

⚠️ 小世界的另一半——幾跳可達——**幫你找到，也幫錯誤傳開**。
那個病有名字：**條件性正確**（單獨測都過，組合才壞）。

## 五、測試是在定義「相同」的解析度

不是在檢查對錯。加一支測試 = 把觀察集擴大一點 = 某些原本看起來相同的東西
會分開。

→ **「今天全綠」只說明在現有觀察集下沒有差別。**
那顆 `vector` bug 一直是綠的，因為沒有人在課程可見集合下觀察過。

## 六、抽象概念是關係的產物，不是關係的前提

「哪些元件屬於同一個抽象概念」**不是人畫的分類，是從邊導出的**。

順序反過來的話，你會先畫好分類，然後**彎曲證據去符合它**。

> **一個抽象概念 = 某個容差底下的等價類。**

### 於是那個參數只有一個

| 場景 | 邊的兩端 | 邊是什麼 |
|---|---|---|
| **語言內** | `cpp:vector_size`／`cpp:string_length` | 同義操作 |
| **跨語言** | `cpp:vector_declare`／`py:list_declare` | 轉換規範 |
| **虛實** | LED 的簡單模型／熱模型／實體 | **保真度** |

三個場景同一個結構。而更重要的是：

> **教學的深淺、抽象的層級、模擬的保真度——是同一個參數：容差。**

- 粗容差 → 「序列」涵蓋一切有順序的 → **初學圖鑑**
- 細容差 → 分出隨機存取／循序存取 → **進階圖鑑**

**漸進揭露因此有了機械基礎**——現在的課程層級是手寫的，在這個模型下
「這一關該看到多粗的概念」是一個容差參數。

### 什麼是導出的、什麼是人寫的

| | 誰 |
|---|---|
| **成員**（哪些元件屬於這個概念） | **導出**（邊 ＋ 容差） |
| **邊**（哪兩顆可換、損失多少） | **量測** |
| 容差、名字、解釋、順序、例子 | 人 |

**人負責意義，機器負責邊界。**

⚠️ 護欄要管的是**來源**不是大小：**圖鑑每個條目的成員必須等於某個容差下的
等價類，不得手動增刪。** 單元素聚類是合法的——`cpp:pointer_declare` 只有 C++ 有，
而圖鑑寫「這個概念沒有其他語言的對應」本身就是有價值的教學內容。

### 一個免費的交叉檢查

聚類有**兩個獨立來源**：從**轉換邊**（量出來的）、從**命名詞彙**（人訂的操作字）。
它們應該一致，而**不一致代表其中一個是錯的**：

- 名字相同但沒有邊 → **命名在說謊**
- 有邊但名字不同 → 漏了一條命名整理，或那條邊是錯的

這條護欄的力量正好來自「**兩種量測方式的盲區不同**」。

## 七、數位孿生落在同一個框架裡

**保真度層級本身就是不同的元件**——`hw:led`（開關）／`hw:led_pwm`（亮度）／
`hw:led_thermal`（含熱降額）不是一顆元件的三個設定，是三顆元件加兩條帶損失的邊。

「這個模擬夠不夠好」＝「在這個情境的容差下，簡單模型和熱模型算不算同一個」。

### 實體那一端不在登錄表裡

實體不能被呼叫，只能被觀察。誠實的作法是把它當成一顆**參照元件**——
**行為由量測定義，不由宣告定義**（像測試的 oracle）。

而它天生是**偏的**：五路裡只在 `execute` 有意義，而且只有在你有感測器的時候。
它沒有 lift／generate／render。**五路的結構剛好表達得出這種偏**——
那個框架本來就允許「這條對應保住這幾路、不保那幾路」。

### 損失刻畫要長出第二種形態

| | 結構性 | 累積性 |
|---|---|---|
| 形狀 | **保住哪幾路**（離散集合） | **每步誤差 ＋ 界**（連續量） |
| 例子 | 能不能索引、有沒有順序 | 熱漂移、時序、模型誤差 |
| 怎麼查 | 鄰域取樣 | 誤差上界 ＋ 回饋週期 |

**現在系統裡全部是第一種**（`abstractConcept` 是布林的）。虛實那條線一定會逼出
第二種——而它逼出來的時候不是要重建框架，是**在邊上多一個欄位**。

> **這個框架真正的價值：讓「硬體進來」從架構風險變成資料擴充。**

## 八、相似度可以用來找候選，不能用來當事實

「用高維向量編碼元件特徵，內積找相似概念」——**放在檢索側是對的，放在真相側是錯的**。
與先驗那條規則同一件事：**決定「先看哪裡」安全，代替「看過了」危險。**

風險不對稱地往好的方向倒：向量爛了只是白量幾對，**它不可能製造出一條假的等價**。

### 一個具體的失敗模式，這個專案踩過

`cpp:stack_top` 與 `cpp:queue_front`：參數一樣、模板形狀一樣、五路一樣、子槽一樣。
**任何結構特徵向量都會說它們幾乎相同，而它們語義相反**（LIFO vs FIFO）。

而這不是假想——見 [episodes/學生說積木寫錯了](../episodes/2026-08-07-學生說積木寫錯了.md)。

> **結構相似度會系統性地把「形狀相同、意義相反」判成同一個。**

### 要編碼什麼

**不要文字嵌入**——名字的嵌入會把 `vector_size` 拉近 `vector_back`（同主體），
而不是 `string_length`（同操作），也就是回頭去撿我們正要整理的那些不一致。

**用從宣告導出的結構特徵**（`ParamSpec` 的 kind 組成、子槽、role／form、
五路存在與否、模板形狀）——**特徵是導出的，不是模型猜的**。

更強的是**行為指紋**（跑一遍，把輸出當指紋），完備性護欄已經做了一半，
差的是記下輸出。障礙是形狀不同的元件沒有共同輸入——那是第二步。

### 誠實：177 顆不需要向量檢索

全配對 15,576 對，任何度量都能暴力算完。**內積現在買不到速度**，
它的價值是**排序**；到第三方生態系（上千顆）才是搜尋。

### 而它可以被驗

四個同義群（大小／加入／取值／看某一端）就是現成的已知答案樣本。
**排不出已知同義群的向量是壞的**；把 stack/queue 也排上來的向量是**正常的**，
只是那證明了它不能當結論。

### 一個型別上的限制

邊帶著「保住哪幾路」（集合），內積給的是**純量**——它表達不了
「在 execute 等價、在 generate 不等價」。**向量在資訊上嚴格弱於邊**，
所以它永遠只能是索引，不可能升級成事實。這不是政策，是型別上的事。
