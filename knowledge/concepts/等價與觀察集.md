# 等價與觀察集

> 「這兩個東西一樣嗎」——**沒有無條件的答案**。
> 答案取決於**你允許誰去看**、**要求多準**、以及**多久能對一次答案**。

## 為什麼需要這個概念

系統裡到處都在宣稱「這兩個算同一個」，而每一處都用不同的方式在說，
彼此不知道對方存在：

| 哪裡 | 宣稱什麼 | 缺了什麼 |
|---|---|---|
| `abstractConcept` | 這顆可以降級成那顆 | **沒說在哪種問題底下還算對** |
| [投影](投影.md)的執行體選擇 | 「∀ 合法輸入，`A(input) ≡ B(input)`」 | 那個 `∀` 是不可判定的形式，沒有觀察集也沒有容差 |
| 元件該不該合併 | 這兩顆是同一個概念 | 相對於**當前**的測試才成立，而測試會增加 |
| 課程降級 | 對這一關的學生，A 可以當成 B | 只在**顯示**成立，卻被拿去**執行** |

第四列在 2026-08-08 炸出一顆真的 bug：`vector<int> v;` 被降級成 `int v;`，
執行時 `v[0]` 型別不符。**一個沒有標註適用範圍的等同關係，一定會被用到
它不成立的地方去。**

## 一、身分是內涵的，等價是外延的

| | 內涵 | 外延 |
|---|---|---|
| 是什麼 | 這顆元件**被定義成什麼** | 它在某組觀察下**表現成什麼** |
| 誰決定 | 宣告 | 量測 |
| 穩不穩 | **不可撤回**（id 進了使用者存檔） | **可修訂**（觀察集會長大） |
| 相對於誰 | 自己 | 情境 |

這一刀讓兩件看似矛盾的事並存：**「沒有絕對元件」與「id 必須穩定」講的是不同層。**

### 剪枝力①：合併是把可撤回的升格成不可撤回

> **外延等價是可以收回的觀察；內涵身分是收不回的承諾。**

「這兩顆行為一樣，合併吧」——那是拿當前觀察集下的一個觀察，去做一個
進了存檔就改不動的決定。觀察集會長大（加語言、加精度要求、硬體進來），
今天分不出來的兩顆明天可能分得出來，而那時撤不回。

→ **傾向少合併、多記對應**：身分保持分開（便宜、穩定），
等價當成邊記著（可修訂、可量測、**可退步**）。

### 剪枝力②：名字不必宣稱通用性

名字是內涵的，只需要對得起自己的定義。**「通用」是外延的，不住在名字裡。**

`cpp:string_find_first_not_of` 這個名字沒有錯——它誠實地命名了一個 C++ 的東西。
錯的是期待名字同時宣告它的外延範圍。

> **名字要說得出這顆元件自己是什麼，不必宣稱它跟誰一樣。**

見 [draft/元件命名重新設計](../history/retired/2026-08-08-元件命名重新設計.md)——
那份 draft 的第一版判定就是踩了這一條（用命名去表達通用性），已記為翻轉。

### 剪枝力③：同一個判斷，放哪一層決定它能不能被收回

這是上面那條的一般形式，而它有一個實例值得記住：

「Python 的 `list` 對應到哪顆既有元件」——

- 放在**身分層**（統一成一個 `lang:sequence_declare`，讓 Python 去對）→ **承諾**，
  進了存檔改不動
- 放在**轉換層**（`py:list_declare` 自成一顆，另寫一條轉換規範）→ **觀察**，
  錯了可以改、可以量、可以附損失刻畫

**同一個判斷，兩種放法，可撤回性完全不同。**

推薦「統一成一個大 scope」時很容易以為那避開了判斷——**它沒有，它只是把
判斷延後到下一個語言進來的那天，而那時它仍然是身分決定。**

### 剪枝力④：一個東西的兩面，是**形態**還是**兩顆元件**（2026-08-10）

同一個系統裡有兩對看起來很像的關係，而它們的處置**不一樣**：

| | 關係 | 怎麼安置 |
|---|---|---|
| 積木 ↔ 文字 | **互相決定** | **同一顆元件的兩個形態** |
| 模型 ↔ 實體 | **逼近** | **兩顆元件 ＋ 一條帶損失的邊** |

憑什麼不一樣？判準是：

> **能不能從一邊完整重建另一邊？**

改積木就改了文字，來回是不動點——那是「投影」的定義。
而改模型**不會改變那顆 LED**：實體有它自己的存在，模型只是逼近它。

用本節的詞彙說：**形態之間共享同一個內涵**（同一個定義的不同表示）；
**模型與實體是不同的內涵**，只靠**外延等價**連著——而外延等價相對於
觀察集與容差（見第二節）。

所以這不是兩套規則，是同一條線的兩側：

> **共享內涵 → 形態槽；只有外延等價 → 兩顆元件加一條邊。**

⚠️ 這條有真的剪枝力：它擋掉「把實體當成模型的一個 `fidelity: 'physical'` 設定」
那種寫法——那等於宣稱兩者共享內涵，而**內涵身分是收不回的承諾**（剪枝力①）。

## 二、等價的完整形式

不是「A 和 B 相同嗎」，而是：

> **在精度要求 ε、回饋週期 T 底下，能不能視為相同。**

### 判斷是算出來的，不是存起來的

```
情境會問的問題  ⊆  對應保住的問題   →   在這個情境下可以視為相同
```

存判斷是 元件² × 情境，必爆。**存兩邊的素材，判斷用算的**：
對應保住什麼（邊的數量，不是 N²）＋ 情境問什麼（一個情境一筆）。

這與「登錄表導出」是同一個動作（見 [history/029](../history/029-E項登錄表導出-清單不是碎裂是量測算錯了.md)）——
**別存導得出來的東西。**

### 「問題」的詞彙已經存在

完備性護欄的**五路**（lift／generate／render／extract／execute）就是
「系統會對一顆元件問的問題」。用它重看那顆 bug：降級**保住了 render**
（畫面沒壞）、**沒保住 execute**（`v[0]` 問不出答案）——而顯示情境只問
render，執行情境問 execute。**容差是為一個用途定的，卻被另一個用途用了。**

### 預設要保守

沒宣告 = 不可互換。只在有人真的要主張什麼時才寫——與
`declareNonComponent` 沒寫理由就擲例外同一種紀律（見 [執行機構](執行機構.md)）。

> **這一節與 §七 的思考現場**保留在
> [episodes/2026-08-08 等價的觀察集與回饋](../episodes/2026-08-08-等價的觀察集與回饋.md)
> ——那天使用者**連續四次重構了問題**，每一次都打掉前一次的結論。
> **探索順序本身是內容**：只留結論的話，看不出每一條為什麼是那樣。

## 三、累積性是環路的性質，不是那一對的

```
總誤差 ≈ 每步誤差 × (經過時間 / 回饋週期) + 量測誤差
```

回饋週期趨近每一步時，右邊塌成 `每步誤差 + 量測誤差`——**累積性消失**。

所以「這個損失要不要緊」不是問這對元件，是問：**多久能拿到一次誤差。**

> ⚠️ 本節到第七節前半講的「差」全部是**誤差**（模型與真值的差，只能比較）。
> 第七節後半的**殘差**是另一種東西（模型補得回去的補項）——
> 兩者的分界見第七節「殘差不等於誤差」。

### semorphe 大部分是閉環的，而開環的地方正好在出事

雙向投影就是誤差量測；「⇄ 自動」把回饋週期壓到每次編輯。
**這是它敢用有損轉換而不出事的原因。**

兩處開環：

1. **存檔**——存下去、一週後打開，中間沒有回饋
2. **降級**——它**刻意產生一個不等於真實的東西，而沒有任何地方量那個差**

第 2 點就是那顆 bug 的真正成因。修法兩選一：降級後量一次誤差（閉環），
或**禁止開環進入需要精度的用途**（降級過的樹不准拿去執行）。

### 封閉系統 vs 開放系統

封閉系統（無外界影響）原則上模型可無限逼近；**開放系統的誤差不是模型
不夠好，是原理上消不掉**——有未建模的輸入，只能靠回饋界住。

軟體裡這條線也在：`lang:arithmetic` 封閉，`lang:input`／檔案串流／執行時間開放。

> **封閉的東西，等價可以用推理定；開放的東西，只能用「帶回饋的觀察」定。**

## 四、不可判定，但有希望：區別力是局部的

外延等價要對所有脈絡量化——一般情況不可判定。有希望的來源是：

> **如果 A 和 B 有差別，那個差別會在碰得到它們差異的觀察底下暴露。**

**這個賭注專案已經下了**——`fuzz-cpp-containers`／`fuzz-cpp-strings` 按模組
分組就是鄰域取樣。如果區別力不局部，這種分組毫無意義。

### 而它只涵蓋一半

| | 結構性的差別 | 累積性的差別 |
|---|---|---|
| 例子 | 能不能索引、有沒有順序 | 浮點精度、模型誤差、時序漂移 |
| 一步之內看得到 | ✓ | ✗ |
| 區別力 | 局部 | **非局部**（觀察在時間上遠，不在圖上遠） |
| 該用 | 鄰域取樣（fuzz、組合測試） | **界**（誤差上界、傳播分析） |

現在系統裡所有「等價」宣稱都是結構性的形狀（`abstractConcept` 是布林的）。
**硬體／數位孿生進來時第一個撐不住的就是這裡。**

⚠️ 小世界的另一半——幾跳可達——**幫你找到，也幫錯誤傳開**。
那個病有名字：**條件性正確**（單獨測都過，組合才壞）。

## 五、測試是在定義「相同」的解析度

不是在檢查對錯。加一支測試 = 把觀察集擴大一點 = 某些原本看起來相同的東西
會分開。

→ **「今天全綠」只說明在現有觀察集下沒有差別。**
那顆 `vector` bug 一直是綠的，因為沒有人在課程可見集合下觀察過。

## 六、抽象概念是關係的產物，不是關係的前提

「哪些元件屬於同一個抽象概念」**不是人畫的分類，是從邊導出的**。

順序反過來的話，你會先畫好分類，然後**彎曲證據去符合它**。

> **一個抽象概念 = 某個容差底下的等價類。**

### 於是那個參數只有一個

| 場景 | 邊的兩端 | 邊是什麼 |
|---|---|---|
| **語言內** | `cpp:vector_size`／`cpp:string_length` | 同義操作 |
| **跨語言** | `cpp:vector_declare`／`py:list_declare` | 轉換規範 |
| **虛實** | LED 的簡單模型／熱模型／實體 | **保真度** |

三個場景同一個結構。而更重要的是：

> **教學的深淺、抽象的層級、模擬的保真度——是同一個參數：容差。**

- 粗容差 → 「序列」涵蓋一切有順序的 → **初學圖鑑**
- 細容差 → 分出隨機存取／循序存取 → **進階圖鑑**

**漸進揭露因此有了機械基礎**——現在的課程層級是手寫的，在這個模型下
「這一關該看到多粗的概念」是一個容差參數。

### 什麼是導出的、什麼是人寫的

| | 誰 |
|---|---|
| **成員**（哪些元件屬於這個概念） | **導出**（邊 ＋ 容差） |
| **邊**（哪兩顆可換、損失多少） | **量測** |
| 容差、名字、解釋、順序、例子 | 人 |

**人負責意義，機器負責邊界。**

⚠️ 護欄要管的是**來源**不是大小：**圖鑑每個條目的成員必須等於某個容差下的
等價類，不得手動增刪。** 單元素聚類是合法的——`cpp:pointer_declare` 只有 C++ 有，
而圖鑑寫「這個概念沒有其他語言的對應」本身就是有價值的教學內容。

### 一個免費的交叉檢查

聚類有**兩個獨立來源**：從**轉換邊**（量出來的）、從**命名詞彙**（人訂的操作字）。
它們應該一致，而**不一致代表其中一個是錯的**：

- 名字相同但沒有邊 → **命名在說謊**
- 有邊但名字不同 → 漏了一條命名整理，或那條邊是錯的

這條護欄的力量正好來自「**兩種量測方式的盲區不同**」。

## 七、數位孿生落在同一個框架裡

**保真度層級本身就是不同的元件**——`hw:led`（開關）／`hw:led_pwm`（亮度）／
`hw:led_thermal`（含熱降額）不是一顆元件的三個設定，是三顆元件加兩條帶損失的邊。

「這個模擬夠不夠好」＝「在這個情境的容差下，簡單模型和熱模型算不算同一個」。

### 實體那一端不在登錄表裡

實體不能被呼叫，只能被觀察。誠實的作法是把它當成一顆**參照元件**——
**行為由量測定義，不由宣告定義**（像測試的 oracle）。

而它天生是**偏的**：五路裡只在 `execute` 有意義，而且只有在你有感測器的時候。
它沒有 lift／generate／render。**五路的結構剛好表達得出這種偏**——
那個框架本來就允許「這條對應保住這幾路、不保那幾路」。

### 損失刻畫要長出第二種形態

| | 結構性 | 累積性 |
|---|---|---|
| 形狀 | **保住哪幾路**（離散集合） | **每步誤差 ＋ 界**（連續量） |
| 例子 | 能不能索引、有沒有順序 | 熱漂移、時序、模型誤差 |
| 怎麼查 | 鄰域取樣 | 誤差上界 ＋ 回饋週期 |

**現在系統裡全部是第一種**（`abstractConcept` 是布林的）。虛實那條線一定會逼出
第二種——而它逼出來的時候不是要重建框架，是**在邊上多一個欄位**。

> **這個框架真正的價值：讓「硬體進來」從架構風險變成資料擴充。**

### 投影之間不對稱：只有一個接得到外部的權威（2026-08-10）

根公理說「唯一真實，各式投影」——程式碼與積木**平等**地都是投影。
而它沒說的是：**只有一個投影連著外部的 oracle。**

| 域 | 模型（模擬） | 外部 oracle（實體） |
|---|---|---|
| 軟體 | 語義直譯器 | **`g++`** |
| 硬體 | 電路／機構模擬器 | **實體板子** |

這不推翻根公理，是補上它的**認識論那一面**：
語義樹是**本體上**的真實，而 `g++` 是**知識上**的權威。

> 這與上面第三節的「封閉的東西，等價可以用推理定；開放的東西，
> 只能用**帶回饋的觀察**定」是同一句話——`g++` 就是軟體域的那個回饋源。

**而這個環路已經在跑了**：29 個測試檔真的呼叫 `g++`，其中 19 個比的是
**直譯器輸出 vs `g++` 輸出**（模擬保真），3 個比的是
**`g++`(原碼) vs `g++`(產回去的碼)**（來回保義，兩邊都是實體）。
⚠️ 兩者混在同一批檔案裡而沒有被分開命名。

### 而「形態」那一維**結構上**沒有外部 oracle

| 積木的兩面 | 有外部 oracle 嗎 |
|---|---|
| **執行**（模擬得準不準） | ✅ `g++` |
| **形態**（好不好懂、標籤有沒有說謊） | ❌ **沒有** |

硬體那邊完全一樣：模擬器的**數值**可以拿實體對答案，
而 CAD 畫面**好不好用**沒有任何東西可以問。

> 所以「形態沒有內部 oracle」（[元件目錄與膠囊契約](../draft/retired/2026-08-07-元件目錄與膠囊契約.md) §八之二）
> 可以講得更準：**形態沒有外部 oracle，而那是結構性的，不是我們還沒建。**

這解釋了那次**十八條護欄一條都不叫**而學生第一眼看出來的事
（`stack`／`queue` 的 push 標籤說謊）——**那不是護欄不夠多，
是那一維沒有權威可問，只能問人。**

### 於是：**`g++` 就是軟體域的那顆參照元件**

上面兩小節各自成立，而中間缺一句話。把它們並排就看得出來：

| | 模型（**在**登錄表裡） | 參照元件（**不在**登錄表裡） |
|---|---|---|
| 軟體 | 元件的 `execute` 路 ＝ 語義直譯器 | **`g++`** |
| 硬體 | `hw:led` 的 `execute` 路 ＝ 模擬 | **實體 LED** |

`g++` 符合前面對實體那一端的每一條描述：**不能被呼叫成一顆元件、只能被觀察**；
**行為由量測定義不由宣告定義**；**天生是偏的**——五路裡只在 `execute` 有意義，
它沒有 lift／generate／render。

> **軟體域早就有「實體那一端」了，我們只是沒把 `g++` 當成元件。**

#### 這句話的實際回報：機制現在就能原型，不必等硬體

「把實體當參照元件」那套東西——一個身分、一份「保住哪幾路」的宣告、
一條帶損失的邊——**可以在 `g++` 上先做一遍**。

環路已經在跑了：**19 個測試檔比的正是「直譯器輸出 vs `g++` 輸出」**。
缺的只是把那個比較的結果**留下來**，而不是當成 pass/fail 用完就丟。

做完之後硬體進來時，那不是新架構，是**登錄表多一列**——
正好兌現本節結尾那句：**讓「硬體進來」從架構風險變成資料擴充。**

### 對硬體的一條預測：**軟體的安全來自「不開環」，而硬體不成立**

第三節記過：semorphe 敢用有損轉換而不出事，是因為「⇄ 自動」把回饋週期
壓到**每次編輯**——它從來不開環跑很久。

**實體回饋的週期是分鐘級**（燒錄、接線、量測），不是每次編輯。
所以硬體的模擬**一定會開環跑很久**，而軟體這邊的那個保護
——高回饋率讓累積性消失——**在硬體上不成立**。

> 這是一條現在就該記下的預測，不是等硬體進來才發現的事。
> 對應的處置在第三節已經有了：**開環的地方要嘛閉環（量誤差），
> 要嘛禁止開環進入需要精度的用途**。

### 模型 ＋ 殘差 ＝ 完整——而 `raw_code` 一直就是那條殘差通道

**P1 投影定理說「來回轉換無損」，而它一直被讀成「模型要理解一切」**
——於是殼、降級、`raw_code` 都像是失敗。

換一個讀法：

> **P1 不要求模型理解一切，只要求殘差補得齊。**

那與 FLAC（LPC 模型 ＋ 殘差 ＝ 無損）、Kalman（預測 ＋ 創新）是同一個結構。

#### 它已經實作了，只是沒被認出來是什麼

`src/core/lift/lifter.ts` 的 Level 4：

```ts
const raw = createNode('raw_code', {})
raw.metadata = {
  rawCode: node.text,          // 原文完整帶著
  confidence: 'raw_code',
  degradationCause: …,
  sourceRange: { … },          // 連位置都帶
}
```

`block-renderer.ts` 把它渲染成 `c_raw_code`——**萬用積木**。於是：
**沒有那顆元件，文字仍然還原得回來，`g++` 仍然編譯得過。**

> **`raw_code` 不是失敗模式，是殘差通道。**

#### 一個比「來回轉換綠不綠」精確的判準

> **殘差完不完整 ⟺ （模型 ＋ 殘差）還原得出原件嗎。**

來回轉換是它的一個必要條件，而這句話說得出**為什麼**它該綠——
不是因為模型好，是因為殘差齊。

#### 殘差不等於誤差——判準是「加回去能不能還原」

⚠️ **2026-08-10 修正。** 這一節第一版把兩種東西都叫殘差，而其中一句是循環論證：

> ~~模擬跑出一條曲線、實體量到另一條，差額就是殘差；模型 ＋ 殘差 ＝ 實際軌跡。~~

**那句話沒有內容。** 差額的定義就是「實際 − 模型」，所以「模型 ＋ 差額 ＝ 實際」
對**任何**差額恆真，包括完全沒用的差額——它看起來像結論，其實只是減法的移項。

兩個詞在統計與數值分析裡本來就分工，而那條線正好切在這裡：

| | 是什麼 | 加回去會怎樣 |
|---|---|---|
| **誤差** | 觀測 − **真值** | 加不回去。它只告訴你**錯了** |
| **殘差** | 觀測 − **模型擬合值** | **加得回去**，而且真的有人在加 |

而讓判準不循環的，是後面那半句：

> **殘差要被同一條路消費，不只是被拿來比較。**

查證（2026-08-10）：

```
raw_code   code-generator.ts:78  generators.set('raw_code', node => node.metadata.rawCode)
                                 產生那一路真的讀它、把原文吐回去   → 殘差 ✅
g++ 差額   src/ 裡 `g++` 出現 3 次，**全部是註解**
                                 沒有任何一行程式讀那個差額         → 誤差
```

#### 硬體那一側：**量測軌跡是誤差，不是殘差**

硬體沒有「原文」可以 carry——塞不進一顆 LED 的原始碼。而

> 「實體不能被呼叫，只能被觀察……**行為由量測定義，不由宣告定義**」

**模擬一條曲線、實體另一條，那個差額是誤差**——沒有人拿它去補模擬。

那硬體的**殘差**通道會長什麼樣？套用「被同一條路消費」：它該是
**「這一段我不模擬，交給實體跑」**的標記——與 `raw_code` 說
「這一段我不理解，交給 `g++` 編」同一個形狀。**那個東西現在還不存在。**

#### 三個現況缺口，第三個最危險

**① 執行那一路沒有殘差通道。** `raw_code` 進了直譯器就停
（`src/interpreter/` 裡一個 `raw_code` 都沒有）。套用同一個框架，它該有的形狀是
**「這一段我沒有執行」的標記**，而不是整個停——就像 `raw_code` 讓產生不停一樣。

**① 之補：執行那一路連誤差都沒在記**——`g++` 在 `src/` 只活在三行註解裡。
所以那一路缺的是**兩樣**：誤差沒有被記，殘差通道不存在。

**② 沒有任何基線在數這兩者。** 25 條基線裡 `raw_code` 只出現在課程清單與樣本裡，
**沒有一條在數「有多少東西掉進殘差通道」**。

**③ ⚠️ 殘差通道會讓缺口不痛。** `raw_code` 讓系統**不會壞**——文字照樣編得過、
來回照樣綠。**於是「模型不理解這個」變得無痛，而沒有人會去補模型。**

> 這與 **P6 誠實降級**是同一個張力的兩面：**降級讓系統活著，也讓缺口安靜。**

處方在框架裡是現成的——**這兩者都要被量**。而它們是**兩個不同的刻度**：

```
形態的**殘差**   有多少原始碼掉進 raw_code    ← 模型**不理解**的部分（補得回去）
行為的**誤差**   直譯器輸出與 g++ 差多少      ← 模型**理解錯**的部分（補不回去）
```

**兩個都沒有在記**，而合起來就是「這個模型有多接近實體」的完整刻畫。
硬體進來時換的只是 oracle——而**殘差那一格硬體目前是空的**（上一小節）。

> ⚠️ 兩者不可混成一個數字。殘差高只代表**模型還沒長到那裡**（系統仍然正確）；
> 誤差高代表**模型是錯的**（系統會騙人）。混起來的話，多蓋幾顆元件會讓
> 一個「會騙人」的數字看起來在改善。

##### 已量的起點（2026-08-10）

```
形態的殘差   0.23%（語法完整語料 467 段／74855 字元，殘差 169 字元、2 個節點）
```

⚠️ 這個數字的第一版是 **48.83%**，差 200 倍。差別**不在程式，在語料**——
820 段裡有 353 段是測試檔裡的**片段**（語法本來就不完整），
被當成了模型缺口。→ **量殘差的護欄，最難的那一步是語料分欄，不是量測本身。**

## 八、相似度可以用來找候選，不能用來當事實

「用高維向量編碼元件特徵，內積找相似概念」——**放在檢索側是對的，放在真相側是錯的**。
與先驗那條規則同一件事：**決定「先看哪裡」安全，代替「看過了」危險。**

風險不對稱地往好的方向倒：向量爛了只是白量幾對，**它不可能製造出一條假的等價**。

### 一個具體的失敗模式，這個專案踩過

`cpp:stack_top` 與 `cpp:queue_front`：參數一樣、模板形狀一樣、五路一樣、子槽一樣。
**任何結構特徵向量都會說它們幾乎相同，而它們語義相反**（LIFO vs FIFO）。

而這不是假想——見 [episodes/學生說積木寫錯了](../episodes/2026-08-07-學生說積木寫錯了.md)。

> **結構相似度會系統性地把「形狀相同、意義相反」判成同一個。**

### 要編碼什麼

**不要文字嵌入**——名字的嵌入會把 `vector_size` 拉近 `vector_back`（同主體），
而不是 `string_length`（同操作），也就是回頭去撿我們正要整理的那些不一致。

**用從宣告導出的結構特徵**（`ParamSpec` 的 kind 組成、子槽、role／form、
五路存在與否、模板形狀）——**特徵是導出的，不是模型猜的**。

更強的是**行為指紋**（跑一遍，把輸出當指紋），完備性護欄已經做了一半，
差的是記下輸出。障礙是形狀不同的元件沒有共同輸入——那是第二步。

### 誠實：177 顆不需要向量檢索

全配對 15,576 對，任何度量都能暴力算完。**內積現在買不到速度**，
它的價值是**排序**；到第三方生態系（上千顆）才是搜尋。

### 而它可以被驗

四個同義群（大小／加入／取值／看某一端）就是現成的已知答案樣本。
**排不出已知同義群的向量是壞的**；把 stack/queue 也排上來的向量是**正常的**，
只是那證明了它不能當結論。

### 一個型別上的限制

邊帶著「保住哪幾路」（集合），內積給的是**純量**——它表達不了
「在 execute 等價、在 generate 不等價」。**向量在資訊上嚴格弱於邊**，
所以它永遠只能是索引，不可能升級成事實。這不是政策，是型別上的事。
