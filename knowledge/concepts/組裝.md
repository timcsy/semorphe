# 組裝（Assembly）

**組裝是「多顆元件連起來之後才存在」的那一層真實。**它不是一顆比較大的元件，也不是元件的第六個槽——它是**第三個主體**：

```
元件   身分 · 埠 · 參數 · 形態 · 行為 · 形式 · pre/post/invariants
連接   結構（樹／有向邊／網）× 關係（組合／資訊／守恆）
組裝   🔴 全網不變量 · 契約聚合 · blame —— 本檔
```

**三視角投影：**

- **原則**：根公理已經寫死它——「在檔案內是樹，**在檔案間是圖，在系統間是超圖**」。組裝就是那個圖／超圖層，所以它不是新決定，是**還債**。
- **願景**：跨域合流的那一格。電氣 DRC、機械裝配干涉、韌體的 RAM 預算、ROS 的 QoS 相容——四個域的「連起來之後才壞」全部落在這裡。
- **經驗**：專案**獨立撞到兩次**同一件事——「per-元件的膠囊**裝不下全樹約束**」、「**硬體診斷掛在邊上**」（「LED 的陽極接到 GND」不屬於 LED，也不屬於 GND）。

## 剪枝力：一條約束是不是組裝的，有一句判準

> **消掉它只需要看一顆元件 ⟹ 它是元件的 invariant。
> 需要看整張網 ⟹ 它是組裝的。**

```
Σ through(我這幾支腳) = 0      只看 LED      → 元件
這條 net 只有一個 driver        要數全網      → 🔴 組裝
恰好一個父                      只看這條邊    → 元件（組合關係自帶）
Σ RAM(所有元件) ≤ 2048          要加總全網    → 🔴 組裝
```

⚠️ **而這條判準只回答「誰宣告它」，不回答「誰判它」**——那是兩個問題，混過一次（見下）。

## 它裝什麼：十八個域填過之後，數得出來的五類

| 類 | 形狀 | 哪個域送來的 |
|---|---|---|
| **守恆** | `Σ through = 0`、`across` 相等 | 電氣 · 熱流 · 力學 |
| **唯一性** | 「恰好一個 driver」「不浮接」 | 電氣 · ROS（一個 topic 的型別只能有一種） |
| 🔴 **預算** | `Σ ≤ B`——RAM、延遲、功耗、誤差累積 | 韌體 · 3D · 音訊 |
| 🔴 **動態** | 約束的是**執行期會變的圖**，不是靜態接線 | 機器人 · IoT |
| 🔴 **歷史** | 約束的是**變化的序列**，不是瞬時的圖（稽核軌跡） | 法規 · 金融 |

> **守恆與唯一性是 Σ=0 那一族；預算是 Σ≤B；而動態與歷史連「瞬時的圖」這個前提都不要。**

另外兩件也住這裡，而它們不是約束：

```
契約聚合   把 N 顆元件的 pre/post 合成整個組裝的 pre/post
blame     🔴 網壞了的時候，說得出是哪一顆／哪一條邊違約
```

## 判官的軸：**數得出來 vs 算得出來**，不是局部／全域

這張表曾經畫成「元件 → 型別檢查器／組裝 → 求解器」。**那個軸是錯的**，而兩格都判錯了：

|  | **結構／數得出來**（cella） | **數值／算得出來**（求解器） |
|---|---|---|
| **元件**（局部） | `exclusive` 獨佔 · 恰好一個父 | 🔴 局部克希荷夫 `Σ through(我的腳)=0` |
| **組裝**（全網） | 🔴 這條 net 只有一個 driver · 不浮接 | 全網克希荷夫 · 力平衡 |

- **局部克希荷夫不是型別檢查得掉的**——即使只看一顆元件的兩支腳，它仍是實數上的方程
- **「net 只有一個 driver」不是求解器的活**——那是**數 driver 的個數**，正是多重性 1

> **局部／全域決定的是【誰宣告它】，不決定【誰判它】。
> 真正的軸是：數得出來 → cella；算得出來 → 求解器。**

⚠️ 而 invariant 有**五種、四個判官**，第五個沒有主人：
結構 → cella · 資源 → cella · 守恆 → 求解器 · 時序 → cella 的 `timed`（今天 0 條）·
**誤差／漂移 → 🔴 沒有人**。

## 🔴 現況：零，而且是四個獨立的零

（2026-09-25 量的，349 顆元件。）

```
src/ 裡的 Edge／Net／Assembly 型別     0
component.json 有 "ports" 的          0 / 349
component.json 有 "relation" 的       0 / 349
component.json 有 "invariants" 的     0 / 349
```

今天的 `children: Record<string, Instance[]>` **全部是組合關係**，而組合是三種關係裡**唯一不需要組裝層**的那一種（樹的約束在節點上就消得掉）。所以「零」不是巧合：

> **我們實作的那一種關係，恰好是不需要這一層的那一種
> ——於是這一層的缺席，一年來沒有任何東西會因為它而變紅。**

⚠️ **這一檔今天最誠實的內容是一份缺口清單，而那是刻意的。**開它的理由不是這裡有成果，是「填了十八個域、**七次**確認需要組裝」這件事本身是讀數——不寫下來，下一次還會重新發現一遍。

## 它與「邊」的分工

```
邊（連接）   兩個埠之間，關係與律          🔴 今天 0 顆
組裝        整張網，跨越所有邊的敘述       🔴 今天不存在
```

「LED 的陽極接到 GND」是**邊**的診斷；「這條 net 有兩個 driver」是**組裝**的。
兩者今天都空著，而**邊要先有**——沒有邊就沒有網，沒有網就沒有全網約束。

## 一個不做的決定

**組裝不吃「累積性」。**契約是布林謂詞，而誤差累積（3D 列印的公差、ODE 的數值漂移）不是「成立／不成立」，是一個會長大的量。把它塞進 invariant 會得到一條**永遠為真直到突然為假**的謂詞。它要的是**預算**那一類（`Σ ≤ B`），不是不變量那一類。
