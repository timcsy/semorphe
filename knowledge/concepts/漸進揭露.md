# 漸進揭露（Progressive Disclosure）

同一個語義結構，在不同認知維度顯示不同的概念子集和結構範圍。**這是過濾，不是簡化**——語義結構始終完整，只是投影時隱藏超出層級的節點。

**三視角投影：**

- **原則**：P4——可見集合 = f(Topic, 概念層級, View Params)。
  ⚠️ **2026-08-13：其中「概念層級 ↔ Topic」的正交性被收回**——概念層級今天就是
  `levelTree` 的深度，不獨立於 Topic。見 [history/053](../history/053-P4補上過濾條件的來源.md)。
  （Topic ↔ View Params 仍正交，本檔 :132 的例子就是證據。）
- **願景**：Topic 系統讓同一語言服務課堂教學、嵌入式開發、競賽程式；終極形態是自舉的元教學
- **經驗**：理論上一維，實作上多維——不要試圖用單一 level 數字解決所有問題

## 兩個正交維度

### 概念層級（Concept Level）

概念層級是一個**樹狀結構**，而非線性序列。學習者從根節點出發，沿不同分支展開可見概念。

```
         L0（根）
        /    \
      L1a    L1b
      / \      \
   L2a  L2b   L2c
```

**倍增軟指引**：每往下一層，新增的可見積木數量約為上一層的兩倍。這是認知負載管理的**啟發式原則，不是硬約束**：

```
L0: ~8 個積木   （基礎 I/O、變數、條件、迴圈）
L1: ~16 個積木  （含 L0，新增函式、for、邏輯運算）
L2: ~32 個積木  （含 L0+L1，新增陣列、字串、進階特性）
L3: ~64 個積木  （含前述，新增泛型、元程式）
```

**分支可疊加**：樹的分支不互斥。學習者可同時啟用多個分支，看到的積木是所有已啟用分支的**聯集**。系統記住使用者已探索的分支，不強制選擇單一路徑。

早期是線性 L0→L1→L2 解鎖，2026-03-11 改為樹狀 + Topic，見 [history/008](../history/008-概念層級從線性改為樹狀加-topic.md)。

### 結構範圍（Structure Scope）

**開放非負整數序數**，N 越大越廣：`S0 語句 → S1 函式 → S2 檔案 → S3 模組 → S4 專案 → S5 系統 → SN ...`

組合形成學習路徑：初學者 L0×S0-S1 → 進階者 L1×S1-S2 → 高階者 L2×S2-S3 → 架構師 L2×S3-S5。

| Scope | 可編輯視圖（R0-R1） | 唯讀視圖（R2-R4） |
|-------|-------------------|------------------|
| S0-S1 | 積木、程式碼、鷹架視圖 | 流程圖、執行動畫、執行軌跡、敘事 |
| S2 | 程式碼、積木、語法高亮 | 檔案大綱、狀態機圖、型別資訊 |
| S3-S4 | — | 呼叫圖、依賴圖、類別圖、序列圖、資料流圖 |
| S5 | — | 系統拓撲圖、API 表面、協定 Schema |

## Topic（主題）

**同一語言在不同主題下，概念的層級樹、積木呈現、甚至積木的輸入欄位都可能不同。**

```
語言: C++
  ├─ Topic: 初學 C++
  │    L0: 變數、print(cout)、if、while      L1: 函式、for、陣列      L2: 指標、struct、STL
  ├─ Topic: Arduino
  │    L0: digitalRead、analogWrite、delay   L1: if、for、函式、中斷   L2: 類別、指標、感測器
  └─ Topic: 競賽程式
       L0: 快速 I/O、變數、陣列              L1: 排序、二分搜、遞迴    L2: DP、圖論、進階結構
```

三者共用同一套 C++ 語言模組（generator/lifter 不變），但投影方式完全不同。

**設計原則：**

1. **Topic 是純投影層概念，不污染語義層**。SemanticNode 不知道 Topic 的存在。Lifter 保持 **Topic-agnostic**——盡可能辨識所有概念，Topic 只在投影端決定哪些可見、如何呈現。

2. **Topic 可覆蓋 BlockSpec 到欄位層級**：

```
概念: print
  初學 C++：一個 VALUE 輸入，自動加 endl
  Arduino： 一個 VALUE 輸入 + SERIAL_PORT 下拉選單
  競賽程式：FORMAT 文字欄位 + 多個 ARG 輸入（printf 風格）
```

三者的 SemanticNode 都是 `print`。**SemanticNode 的 properties 存完整資訊**（語義上有意義的屬性都存），Topic 控制哪些屬性投影為積木欄位、哪些隱藏並用預設值。

3. **base + override 模型**：Topic 只定義與 base BlockSpec 不同的部分，沒有 override 就 fallback 到 base。這避免了 `(概念 × Topic × Level)` 的組合爆炸。

```typescript
interface Topic {
  id: string                         // 'cpp-beginner', 'cpp-arduino', 'cpp-competitive'
  language: string
  name: string
  levelTree: LevelNode
  blockOverrides?: Record<ConceptId, BlockOverride>
}
interface LevelNode {
  level: number
  label: string                      // 'L0: 基礎輸出入'
  concepts: ConceptId[]              // 這一層新增的概念
  children: LevelNode[]              // 分支路徑（可疊加）
}
interface BlockOverride {
  message?: string; tooltip?: string
  args?: BlockArg[]; renderMapping?: RenderMapping
}
```

## 概念表面形態（Surface Form）

概念層級控制**哪些概念可見**，表面形態控制**同一概念展示多少結構**。兩者正交：

```
概念: if
  F0 基礎形態：if (condition) { body }
  F1 擴展形態：if (condition) { body } else { body }
  F2 完整形態：if / else if / else if / ... / else
```

用 toolbox 的 `extraState` 預配置實現——同一積木類型配置不同初始結構，每個形態可獨立設定認知層級（如 F0/F1 在 L0，F2 在 L1）。

**與概念層級的區別**：概念層級在概念**之間**篩選（if 和 switch 是不同概念），表面形態在概念**內部**篩選（if 和 if-else 是同一概念的不同深度）。

## Toolbox 的多維度來源

```
積木是否存在於 Toolbox = f(Topic, P4 概念層級, View Params)

Topic（主題）    → 控制「層級樹的結構」和「積木的形狀覆蓋」
P4 Level         → 控制「在該 Topic 的層級樹中，使用者目前展開到哪一層」
View Params      → 控制「同一概念怎麼呈現」
  ├─ Code Style  → APCS 顯示 cout 積木，競賽顯示 printf 積木
  ├─ IO Pref     → iostream vs cstdio（與 Code Style 連動）
  └─ Language    → 決定語言專屬積木的可用集合
```

**Topic 與 View Params 正交，不應混合。**
⚠️ **而「概念層級」那一軸的正交性在 2026-08-13 被收回**——它是 `levelTree`
的深度，不是獨立於 Topic 的東西（見 [history/053](../history/053-P4補上過濾條件的來源.md)）。
下面這個例子**證明的正是前兩者**：`print` 在「初學 C++」Topic 的 L0 可見，積木有一個 VALUE 輸入；在「Arduino」Topic 的 L0 也可見，但多一個 SERIAL_PORT 下拉（Topic 的 BlockOverride）；投影為 cout 還是 printf 是 Code Style 決定的。

**workspace 上的既有積木不受層級切換影響**——只影響 toolbox 可用性。

## 層級轉換穩定性

鷹架的撤去必須是漸進的——Vygotsky 的原意是逐步減少支撐，不是瞬間抽走。

```
層級轉換不變式：
  ∀ concept C, level L₁ < L₂:
    如果 C 在 L₁ 可見，則 C 在 L₂ 的呈現（message、顏色、形狀）不變。
    L₁ → L₂ 的變化只來自新概念的加入，不來自舊概念的改變。
```

**推論：**

- **Message 穩定**：`if` 在 L0 叫「如果」，在 L1 仍然叫「如果」
- **差異可見**：新增概念應有視覺標記（「新」徽章或漸入動畫）
- **單調遞增**：toolbox 只增不減

這是 Sc4（最小驚訝）在層級維度上的直接推論：**學習者已建立的心智模型不應被層級切換破壞。**

| 層級 | Message 策略 | Tooltip 策略 |
|------|-------------|-------------|
| L0 | 完全口語 | 生活比喻 |
| L1 | 保留關鍵術語 | 技術說明 + 場景 |
| L2 | 可用更多術語 | 重點放在「什麼時候用」 |

## 基礎設施的漸進揭露（Program Scaffold）

程式的 boilerplate（includes、namespace 宣告、main 包裝、return 0）構成一個 **Program Scaffold**，全部是 Scope 3 的衍生投影，由 P4 統一控制可見性：

```
L0：完全隱藏 — 零認知負荷，學習者只看到自己寫的邏輯
L1：幽靈行（ghost lines） — 可見但自動管理，hover 顯示原因（「因為你用了 cout」）
L2+：使用者自行管理 — 缺失依賴觸發警告，不自動補全
```

依賴圖始終完整存在於語義樹中，P4 只控制哪些投影到可見 view 上。**統一的 scaffold 策略確保每個 boilerplate 項目不會各自變成 ad-hoc 特殊處理。**

## User Context（慣性）

使用者互動會累積隱式知識——偏好、習慣、決策歷史，統稱**慣性**。慣性**不改變投影定理的數學性質**，只影響 viewParams 未指定時的預設值推導。

```
Layer 0 語境慣性：同一 session 內，前面的操作影響後面的預設值（符號表、Style 延續）→ 記憶體
Layer 1 個體慣性：跨 session 的偏好和歷史（Style preset、操作頻率、決策記錄）→ localStorage
Layer 2 群體慣性：組織/班級的共享設定（編碼規範、概念白名單、自定義 pattern）→ 共享設定檔
```

**viewParams 解析順序（高→低）：**

```
① mandatory 群體設定（不可覆蓋）
② 使用者明確指定
③ 語境偵測（檔案自身的 style，由 detectStyle() 推斷）
④ recommended 群體設定
⑤ 個體慣性（歷史偏好）
⑥ 系統預設值
```

**語境偵測優先於個體慣性**——打開別人的程式碼時應尊重程式碼本身的 style。**群體設定優先於個體慣性**——團隊一致性比個人偏好重要。`mandatory` 是唯一使用者無法覆蓋的情況（如 instructor 限定 level ≤ 1）。

**角色意圖（Role Intent）**——不是使用者屬性，而是**當下的互動模式**：

| 角色 | 慣性策略 |
|------|---------|
| learner | 慣性 + 教育引導——可能主動打破慣性推薦新概念 |
| developer | 慣性 + 效率優先——尊重偏好，不主動干預 |
| reviewer | 群體設定優先——強調團隊規範 |
| instructor | 設定群體慣性——定義 level 上限和 style 規範 |
| explorer | 最少慣性——每次探索可能用完全不同的設定 |

**三種關鍵快取**：Style Resolution Cache（打開 printf 寫的程式碼時沿用 printf style）、User Decision Cache（跨語言轉換的選擇，粒度是 `(source_concept, target_language) → user_choice`）、Concept Familiarity Profile（依操作頻率調整 toolbox 佈局）。

**慣性不是原理**——它不改變根公理、P1-P4 中的任何一條。它是第三層的實踐策略：讓系統從「每次從零開始」變為「記住你是誰、你上次做了什麼」。

## 逆向操作：精密摩擦控制

P4 是「移除遮罩以揭露更多」；精密摩擦是逆向操作——**主動加入遮罩以製造挑戰**：

```
reveal(node)    = mask.remove(node)    // 漸進揭露：降低認知負荷
challenge(node) = mask.add(node)       // 精密摩擦：製造有效挑戰
```

目的不是讓學習變「容易」，而是讓「努力」變「精確」——消除無效痛苦，保留有效挑戰。當學習者對某模式的 round-trip 成功率達到閾值時，可遮蔽該概念的某些投影，迫使用更基本的積木重建。
