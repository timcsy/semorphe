# Feature Specification: 需要即時工作區的積木，名單由語言套件說

**Feature Branch**: `064-variable-dropdown-declaration` ｜ **Created**: 2026-08-06

## 為什麼做這個

中立性剩最後 1 筆：`Blockly.Blocks['cpp_string_at'] = { … }`。

它**不是雙重真相**——那個積木沒有 JSON 定義，而且不能有：它的「哪個字串」
欄位是一個下拉選單，選項要從**即時的工作區**算出來（「現在有哪些字串變數？」）。
那需要積木框架的 API。

所以建構程式碼住在介面層是**對的**。錯的是「**哪些積木要用這個機制**」也寫死
在那裡——一個 C++ 專屬身分留在呈現層，而換一種語言，取字元的積木叫別的名字。

| 誰 | 該提供什麼 |
|---|---|
| 介面層 | **機制**——怎麼建一個會掃工作區的下拉選單 |
| 語言套件 | **名單**——哪些積木要用它、欄位叫什麼、列哪一種型別的變數 |

## Requirements

- **FR-001**: 名單 MUST 由語言套件宣告
- **FR-002**: 介面層 MUST NOT 認得任何具體的積木身分
- **FR-003**: 「列哪一種變數」MUST 沿用 063 的概念宣告——加一個同類概念時自動涵蓋
- **FR-004**: 行為 MUST 完全不變
- **FR-005**: MUST 有測試釘住宣告真的推得到——**空清單與「介面層沒接上」產出完全一樣**，兩者都是積木沒被註冊，而那只有真的開啟編輯器才看得到

## Success Criteria

- **SC-001**: 中立性 **1 → 0**
- **SC-002**: 完備性各數字不變
- **SC-003**: 既有測試全數通過

## ⚠️ 零不等於語言獨立性成立

中立性歸零之後，護欄裡那條「數字不為零」的絆線會觸發。它是刻意埋的
（049），附註寫著「哪天真的歸零了，這條會提醒你把整條護欄的意義重新定位」。

重新定位有兩件事：

1. **健康檢查改成合成注入。** 用「真實存量為正」當健康訊號，在存量真的清完
   那天就會失效——那正是 `history/022` 的教訓：「護欄修好了它要量的東西，
   就是它的錨點爛掉的時候」。
2. **零只代表「身分」那一維乾淨了。** 語法耦合、直接 import、執行期才成立的
   耦合，這條護欄都看不見。見 `history/021`。
