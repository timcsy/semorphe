# 概念探索：C++ — I/O 操縱子（`flush` · `setw` · `setprecision` · `fixed`）

- 語言：cpp · 日期：2026-09-18 · 分支 `189-cpp-io-manipulators`

## 🔴 先決問題先答，而它**推翻了這一刀的前提**

題目說「`flush` 5 支」。逐支實測（空輸入）之後：

```
13_toj15.cpp      參照編譯器編不過（測試自己的問題）   我們 OK
13_toj15_2.cpp    參照編譯器編不過                     我們 OK
19_c123.cpp       跑得完                               我們 OK
19_e155.cpp       跑得完                               我們 OK
21_d518.cpp       跑得完                               我們 OK
15_nD_array_2.cpp 跑得完                               🔴 UNDEFINED_FUNC: setw
12_for_2.cpp      跑得完                               🔴 UNDEFINED_FUNC: setw
20_toj275.cpp     跑得完                               🔴 UNDECLARED_VAR: fixed
```

**那五支 `flush` 在空輸入下全部跑得完**——它們的 `flush` 在一個「讀到輸入才進去」的
分支裡，而語料探針**餵了輸入**，所以那裡才走得到。

> **一個「這一族有 N 支」的讀數，如果 N 是照【第一個錯誤】分的，
> 那它量到的是錯誤的順序，不是缺陷的分佈。**

🟢 **而重估之後這一刀【變大了】不是變小**——見第 ④ 題：
`formatDefaultPrecision` 有一個真缺陷，它影響的是**每一支印大數或小數的程式**。

| 真正會被這一刀救到的 | 支數 |
|---|---|
| `setw` | 2 |
| `fixed` ＋ `setprecision` | 1 |
| `flush`（餵了輸入才走到） | 2 |
| 🔴 **科學記號的格式**（下面 ④） | **語料量到 1 支「內容真的不同」，而母體是所有印浮點的程式** |

## 六個設計問題——**每一題都有出處**

判準的原文（`knowledge/concepts/元件代數.md:250`）：

```
🟢 是參數    引數個數相同、接點相同、角色相同——差別只有【一個值】
🔴 是身分    引數個數不同、或語義上做的事不同
```

### ① `flush` 與 `cpp:endl` —— **兩顆身分**

三項形狀**全部相同**（0 引數、0 接點、運算式）。而判準是 **OR**：
「引數個數不同、**或語義上做的事不同**」。

```
endl    換行 ＋ 送出      做兩件事
flush   只送出            做一件事
```

**做的事不同 ⟹ 是身分。** 那一條的另一半（引數個數）在這裡不適用。

⚠️ 而「為什麼 `container_iter` 可以把 `begin`／`end`／`rbegin`／`rend` 合成一顆」
的差別就在這裡——那顆的註解逐字：「**紀律相同（取得一個位置），差的只是哪一端**」。
取得位置是**同一個動作**，哪一端是一個值；而換行不是送出的一個值。

🟢 **`traits.lineBreak` 因此原封不動**——它是 `endl` 的性質，而 `flush` 沒有那個性質。
⚠️ 合成一顆的話那個 trait 會變成「依屬性的值而定」，而那是**第二份真相**的形狀。

### ② `setw(2)` 與 `setprecision(6)` —— **一顆身分 ＋ 一個屬性**

三項形狀全部相同（1 引數、1 接點、運算式），而**做的事是同一件**：
設定串流的一個輸出設定。差別是**設定哪一個**——那是一個值。

這正是「**量什麼不是身分，是參數**」那一條的形狀
（`readHumidity`／`readTemperature` → 一顆 ＋ `quantity`，22 顆 → 19 顆）。

🟢 **`cpp:stream_setting`**，屬性 `setting`：`width`／`precision`／`fill`。

⚠️ **作用範圍的差別不進語義樹**：`setw` 只影響下一項、`setprecision` 一直有效
——那是**那個設定的意思**，就像濕度與溫度回傳不同的東西一樣。
它住在 execute，不住在結構。

⚠️ 而參數化的**硬條件**成立：那個差別在程式碼裡是真的，所以屬性**必須被帶著**
（不帶的話 `setw` 會被改寫成 `setprecision`，而那會改掉學生的程式）。

### ③ `fixed` —— **第三顆身分**（而且它該連 `scientific` 一起收）

與 `setprecision` 比：**引數個數不同**（0 vs 1）⟹ 是身分。
與 `flush` 比：**做的事不同**（設一個旗標 vs 送出）⟹ 是身分。

而 `fixed` 與 `scientific` 之間：0 引數、0 接點、運算式，**做的是同一件事**
（設定數字的寫法），差別是**哪一種寫法** ⟹ 一顆 ＋ 屬性。

🟢 **`cpp:stream_number_style`**，屬性 `style`：`fixed`／`scientific`。

⚠️ **「語料只有 `fixed`，所以不要收 `scientific`」是錯的推論**：
`scientific` 不是一顆要不要做的元件，它是一個**列舉的值**。
而「沒有人接得住就不要補」那條判準講的是**產出**，不是列舉的值域
——一個只有一個值的列舉，會在第二個值出現時逼人開第二顆身分。

⚠️ 而 `fixed` 與 `setprecision` **不該合成一顆**，雖然語料裡它們只一起出現：
`setprecision(2)` 單獨用是合法且常見的（總共兩位有效數字），
而合成一顆會讓那個寫法**表達不出來**。**語料剛好怎麼寫，不是語義。**

### ④ 🔴 執行期做得到嗎 —— 做得到，而且查出一個**更大的缺陷**

**`cout` 的輸出走 `ctx.io.write(text)`**（`src/interpreter/io.ts:16`），
而它是 `stdout.push(text)` ＋ 立刻呼叫 callback——**沒有緩衝**。

🟢 所以 **`flush` 是一個真正的 no-op**，而那**不是敷衍**：
C++ 的 `flush` 在一個沒有緩衝的實作上本來就沒有可觀察的效果。
⚠️ 而它**仍然必須有一顆元件**——不然那五支語料的程式碼轉一圈回來會少掉它。

**`setw` 做得到**：`cpp:print` 的 execute 是一個 `for` 迴圈，逐項 `ctx.io.write`。
一個「待用的寬度」放在串流狀態上、由下一次寫入消耗掉即可。
⚠️ 串流狀態**不放在 `IOSystem`（核心）**——那是 C++ 的詞彙。
放在 cpp 膠囊的共用執行期，用 `WeakMap` 以 `ctx.io` 為鍵：**一次執行一份狀態**。
（中立性護欄：核心不得認得語言的東西。）

**`setprecision`／`fixed` 做得到，而這裡有一個真缺陷。**
數字變成文字的唯一一處是 `interpreter/types.ts` 的 `formatDefaultPrecision`，
而它與 g++ 比對之後：

| | g++ | 我們 |
|---|---|---|
| `double d = 1e9` | `1e+09` | **`1.00000e+9`** |
| `123456789.0` | `1.23457e+08` | **`1.23457e+8`** |
| `0.000012345` | `1.2345e-05` | **`1.2345e-5`** |

**兩個錯**：科學記號的尾數沒有去尾零、指數沒有補成兩位。

🔴 **而這正是那 7 支「內容真的不同」的其中一支**
（`AP325/7/7_5_TLE.cpp`：`1000000000` vs `1.00000e+9`）。
⚠️ 而它的母體**不是一支**——是**每一支印大數或小數的程式**。

⚠️ **`valueToString` 不可以整個吃下串流狀態**：它同時被**變數面板**
（`interpreter.ts:291`）與型別轉換（`:644`）呼叫，而那兩處不該受 `cout` 的設定影響。
→ 精度與寫法由 **`cpp:print` 自己**在寫出去之前套用。

### ⑤ 積木上的字

| 元件 | zh | en |
|---|---|---|
| `cpp:stream_flush` | **「立刻送出已經印出來的」** | **「Push out what has been printed」** |
| `cpp:stream_setting` | **「把輸出的 %1 設成 %2」**（下拉：寬度／小數位數／補位的字） | **「Set the output %1 to %2」** |
| `cpp:stream_number_style` | **「數字的寫法用 %1」**（下拉：固定小數／科學記號） | **「Write numbers in %1」** |

⚠️ **沒有一個把 `setw`／`flush` 寫在積木上**（標籤規範的速查表逐字列了 `func()` 那一類）。

🔴 **而「這顆積木該不該存在」這個可能性要正面回答**：
`flush` 在這個模擬器裡**沒有可觀察的效果**，所以它的 tooltip 必須誠實：

> 「在這個模擬器裡，印出來的東西本來就立刻看得到，所以這一塊不會改變任何輸出。
> 它存在是為了讓你的程式碼一字不差地轉回去——真正的 C++ 在等待輸入之前需要它。」

⚠️ 而它**必須存在**：Sc2 說積木只能表達原始碼裡有的東西，
反過來**原始碼裡有的東西也要表達得出來**——否則那五支語料轉一圈就少一行。

### ⑥ 不做什麼

| | 做／不做 | 理由 | 語料 |
|---|---|---|---|
| `setfill` | 🟢 **做**（當 `stream_setting` 的第三個值） | 它與 `setw` 是同一個動作的另一個設定，成本是列舉多一個值 | 0 |
| `scientific` | 🟢 **做**（當 `stream_number_style` 的第二個值） | 同上，見 ③ | 0 |
| `left`／`right`／`internal` | 🔴 **不做** | 它們是**對齊**，與「設一個值」不同動作；要另一顆身分，而產出沒有人接得住 | 0 |
| `boolalpha` | 🔴 **不做** | 同上，而且它改的是 `bool` 怎麼印——那一條今天是對的（印 1／0） | 0 |
| `cout.flush()` 的方法形式 | 🔴 **不做** | 語料全部是 `<< flush`；方法形式要另一條 lift 分支，而**它的產出與 `<< flush` 完全一樣** | 0 |

## 概念目錄

| 概念 | 語法 | 語義 | 積木輸入 | 降級 | 語料 |
|---|---|---|---|---|---|
| `cpp:stream_flush` | `cout << flush` | 立刻送出（此處無可觀察效果） | 0 | `var_ref` → `raw_expression` | 2 |
| `cpp:stream_setting` | `setw(n)` · `setprecision(n)` · `setfill(c)` | 設定串流的一個輸出設定 | 1 | `func_call` | 3 |
| `cpp:stream_number_style` | `fixed` · `scientific` | 設定數字的寫法 | 0 | `var_ref` → `raw_expression` | 1 |

⚠️ 三顆的 `owner` 都是 **`<iomanip>`**（`setw`／`setprecision`／`setfill`／`fixed` 都在那裡），
🔴 **而 `<iomanip>` 今天在工具箱裡沒有段落**——與 `<stdexcept>` 2026-09-18 撞到的
是**同一個形狀**，要一起補。

⚠️ 而 `flush` 在 C++ 裡屬於 `<ostream>`（`<iostream>` 帶進來）。
`cpp:endl` 的 `owner` 是 `(universal)`、`requires: ['<iostream>']`
——`stream_flush` 抄它，而**不要**蓋 `<iomanip>`。

## 建議實作順序

1. 🔴 **先修 `formatDefaultPrecision`**——它與新元件無關，而它影響最廣，
   且**修好之後才知道 `setprecision` 該接在哪裡**
2. `cpp:stream_flush`（最簡單，而且它證明「三顆的 lift 分派」走得通）
3. 串流狀態（`WeakMap` 以 `ctx.io` 為鍵）＋ `cpp:stream_setting`
4. `cpp:stream_number_style`
5. `<iomanip>` 的工具箱段落（與 `<stdexcept>` 同一個形狀）

## 跨語言對應

Python 的 `print(x, end='')` 與 `f"{x:.6f}"` **不是同一個概念**：
C++ 的操縱子改的是**串流的狀態**（下一項、或一直到被改掉），
而 Python 的是**那一次呼叫的引數**與**那一個字串的格式**。
⚠️ 接點結構不同（一個是串流上的獨立語句，一個是呼叫的參數）⟹ 身分分開。
🟢 而**積木上的字可以讀起來像**（「小數印到 %1 位」），那是跨語言的一致性。

## 需注意的邊界案例

- `cout << setw(2) << a << b;` —— `setw` **只影響 `a`**，`b` 不補寬度
- `setw` 的補位字預設是空白，而 `setfill('0')` 之後是 `0`——**兩個設定互相影響**
- `fixed << setprecision(6)` 與單獨的 `setprecision(6)` **意思不同**（見 ③）
- 🔴 **`cout << fixed;` 沒有印任何東西**——它是一個「只有副作用」的輸出項，
  而 `cpp:print` 的迴圈今天對每一項都 `write(...)`。那一格要**寫出空字串**，
  不是「不執行」（不執行的話副作用也沒了）
