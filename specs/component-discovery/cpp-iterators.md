# 概念探索：C++ — 迭代器一族

## 摘要

- 語言：C++
- 目標：`begin`／`end`／`*it`／`++it`／`it->`／`find`／`lower_bound`／`upper_bound`／`erase(it)`／`rbegin`
- 🔴 **拍板的結論**：**迭代器不是第三種指標，它就是實體式指標**——
  而缺的是**兩個運算子**與**六個回傳它的方法**，不是一個新的值種類。
- 建議新增元件：**7 顆**（全部 `cpp:` 語言特定）＋ **修 2 顆既有的**
- 建議歸屬：`cpp-advanced` 的 L2「STL 容器」與 L3

## 🔴 先回答那個設計問題——而答案是量出來的

這個直譯器有兩種指標（`src/interpreter/types.ts` 的 `offset` 註解）：

```
符號式   &x                    value 是變數名字串，走 pointerTargets
實體式   new／malloc／陣列退化   value 是【那串格子本身】，offset 說指到第幾格
```

而**容器在執行期就是一串格子**——`map` 是 `{type:'array', value:[pair 物件…], keyed:true}`、
`set` 是 `{type:'array', value:[…], allowsDuplicates}`。
`cpp:loop_range` 的執行器**直接走 `container.value`**，一個字都沒有轉換。

所以問題變成可量的：**實體式指標身上，迭代器要的動作有幾個已經成立？**

| 迭代器要的 | 對應的既有機制 | 實測 | g++ |
|---|---|---|---|
| `*it` | `cpp:pointer_deref` → `value[offset]`，**含範圍檢查** | ✅ 8 | 8 |
| `it + n` | 指標算術 | ✅ 8 | 8 |
| `it->first` | 成員存取（元素是 pair 物件） | ✅ 3 | 3 |
| 改了看得到（共用格子） | `*p = 1` → `a[0]` 變 1 | ✅ 1 | 1 |
| `&v[0]`（容器退化成指標） | `cpp:address_of` | ✅ 4 | 4 |
| `auto it = …` | `cpp:var_declare_auto` | ✅ | |
| 🔴 `++it`／`it++`／`it += n` | — | **TYPE_MISMATCH** | 8 |
| 🔴 `it != it2` | `cpp:compare` | **恆等於「相等」** | 1 |

> **迭代器在這個直譯器裡不是一個新東西。
> 它是一個已經存在的東西，少了兩個動作。**

### 🔴 而那兩個缺口各自有一個乾淨的根因

**① `++it` 走不了**：遞增那顆元件不認得 array 型別的值。
⚠️ 而 `p = p + 1` **是通的**——所以缺的只是「原地改」那幾個形式
（`++p`／`p++`／`p += n`），不是指標算術本身。

**② `it != it2` 恆假**：`cpp:compare` 最後走 `ctx.toNumber()`，
而 `toNumber` 對 array **刻意回 1**（那一行有註解：少了它，
`while (p != NULL)` 對剛配好的節點是假，「整條 Linked List 的走訪一圈都不跑」）。

於是兩個指標都變成 `1`，`1 !== 1` 為假：

```
int* p = a;  int* e = a + 3;      p != e  →  我們 0 ／ g++ 1
int* p = a;  int* q = b;          p != q  →  我們 0 ／ g++ 1   ← 連不同陣列都說相等
```

🔴 **這與同一個檔案上方那段註解講的是同一件事，只是晚了一個型別**：

> 原本一律走 `toNumber`，而 `Number('abc') || 0` 是 0——**兩個字串都變成 0，
> 於是 `==` 恆真、`!=` 恆假**。

**字串補過一次，而指標是 `toNumber` 壓平的下一個型別。**
⚠️ 修法不得破壞 `p != NULL`：那一條要的正是「有效指標 → 1」。
**指標對指標**要比（同一串格子嗎, offset 一不一樣）；**指標對 0** 才走 `toNumber`。

## 概念目錄

### `cpp-advanced` L2「STL 容器」 — 中級

| 概念名稱 | 語法 | 語義意義 | 積木輸入 | 通用/特定 | 降級路徑 | 備註 |
|---|---|---|---|---|---|---|
| `cpp:iter_begin` | `c.begin()` | 容器的**開頭位置** | 容器 | cpp | raw_code | 語料 33 次 |
| `cpp:iter_end` | `c.end()` | **結尾之後**的位置（不是最後一個） | 容器 | cpp | raw_code | 語料 30 次 |
| `cpp:iter_at` | `*it` | 這個位置上的元素 | 位置 | cpp | — | 🟢 **已經有了**（`cpp:pointer_deref`） |
| `cpp:iter_find` | `c.find(x)` | 找 x 的位置；沒有就是結尾之後 | 容器・值 | cpp | raw_code | 語料 8 次 |

### `cpp-advanced` L3 — 進階

| 概念名稱 | 語法 | 語義意義 | 積木輸入 | 通用/特定 | 降級路徑 | 備註 |
|---|---|---|---|---|---|---|
| `cpp:iter_lower` | `c.lower_bound(x)` | 第一個 **≥ x** 的位置 | 容器・值 | cpp | raw_code | 語料 5 次；⚠️ 與既有的 `cpp:range_find_lower`（三引數自由函式形式）是**兩個身分**，見下 |
| `cpp:iter_upper` | `c.upper_bound(x)` | 第一個 **> x** 的位置 | 容器・值 | cpp | raw_code | 語料 2 次 |
| `cpp:container_max` | `*s.rbegin()` | 有序容器裡**最大的那一個** | 容器 | cpp | raw_code | 🔴 **不是反向迭代器**——見下面的範圍決策 |

### 修既有的（不是新元件）

| 元件 | 改什麼 | 為什麼 |
|---|---|---|
| `cpp:increment`（與複合指定） | 認得 array 型別的值：`++p` 讓 offset +1 | 語料每一個走訪迴圈都要它 |
| `cpp:compare` | 指標對指標比（格子身分, offset） | 今天**恆等於相等**，而那讓每一個 `it != c.end()` 迴圈一次都不跑 |
| `cpp:container_erase` | `erase(位置)` 只刪一格 | 今天只認 `erase(鍵)`。⚠️ **同一個方法名，由引數型別決定**——不可拆成兩顆（登錄表對「同名兩個主人」當場拒絕） |

## 🔴 範圍決策：不做什麼，以及為什麼

### 🟠 反向迭代器（`rbegin`／`rend`）**不做**——而語料說服了我

`rbegin` 只出現在 **3 支**，而**每一處都長這樣**：

```cpp
*s.rbegin()                    // 集合裡最大的那一個
if (x <= *s.rbegin())
ls -= *l.rbegin();
```

**沒有任何一處拿它走訪。** 它們問的是一個值，不是一個位置。

> **一個名字出現七次，不代表那是七次同一件事。
> 先看它每一次被用來做什麼——這一次的答案是「七次都在問同一個問題」。**

🟢 所以做 `cpp:container_max`（「`s` 裡最大的元素」），**不做反向迭代器機構**。
⚠️ 而那個機構真做起來要在值上加一個方向旗標，**每一個運算子都要認它**
——`*`、`++`、`--`、比較、`erase`。一個「`++` 走錯方向」的實作是**靜默的錯答案**。

### 🟠 迭代器失效**不模擬**

C++ 的失效規則因容器而異（`vector` 的 `push_back` 可能讓全部失效、
`map`/`set` 的 `erase` 只讓被刪的那個失效）。用了失效的迭代器是 **UB**。

🔴 **而這一條有一個對判準的硬性後果**：一個不模擬失效的實作會讓某些 UB 程式
**碰巧跑對**——那**不得**被寫進「我們與 g++ 一致」的判準裡。

### 🟠 `it = s.erase(it++)` 這個寫法**做一半**

`erase(位置)` 會做，而且**回傳下一個位置**（我們的容器是一串格子，
刪掉第 i 格之後「下一個」正好還是第 i 格）。
⚠️ 但 `it++` 作為引數（後置遞增的**回傳舊值**語義）要 `++` 那一刀先做對。
兩者在這一刀裡都做，所以它會通——**而測試要釘住它，因為它靠的是兩件事同時對**。

### 🟠 `lower_bound` 的兩種形式是**兩個身分**

既有的 `cpp:range_find_lower` 是**三引數自由函式**（`lower_bound(a, a+n, x)`），
回傳的是**陣列上的位置**。而 `st.lower_bound(x)` 是**方法**，回傳容器上的位置。

⚠️ 探索報告（`cpp-container-ends`）當時判「明確不做，理由是它一個人到不了終點」
——**那個理由現在不成立了**：這一刀把終點（`*it`／`!= end()`／`erase(it)`）一起做。

🔴 而它們**不是同一顆的兩個形態**：自由函式那顆吃的是「兩個位置界定的範圍」，
方法這顆吃的是「一個容器」。**參數不同 ⟹ 身分不同。**

## 教育面：一顆「迭代器」積木在畫面上是什麼

🔴 **這一族要有積木，而它們的字一個「迭代器」都不出現。**

學生第一眼看到 `it` 會以為它是「一個元素」，而它是「一個**位置**」。
所以標籤用**位置**這個詞，而且**與容器綁在一起講**：

```
c.begin()        「%1 的開頭位置」
c.end()          「%1 的結尾之後」          ← 不是「最後一個」，那是最常見的誤解
*it              「%1 指的元素」            🟢 已經有了（解參考那顆）
c.find(x)        「在 %1 裡找 %2 的位置」
c.lower_bound(x) 「%1 裡第一個 ≥ %2 的位置」
*s.rbegin()      「%1 裡最大的元素」        ← 這一顆根本不提位置
```

⚠️ **「結尾之後」不能寫成「結尾」**：`end()` 指的是最後一個元素的**後面一格**，
而「`it != c.end()`」這個迴圈寫法的全部意義就在那個「之後」。
一顆寫著「結尾」的積木會讓學生寫出 `it != c.end()` 卻以為漏掉最後一個。

🟢 **而它們不進 `cpp-beginner`**：那一軌已經用範圍 for（`for (int x : v)`）
教走訪，而那是**對初學者更好的工具**。迭代器進 `cpp-advanced` 的 L2/L3
——那一軌的課文本來就在教 `set`／`map`／二分搜。

## 依賴關係圖

```
cpp:increment 認得指標   ←─ 無（修既有）
cpp:compare 比得出位置   ←─ 無（修既有）
      ↑                      ↑
cpp:iter_begin / iter_end ───┴── 兩者都要，否則走訪迴圈跑不動
cpp:iter_find            ←─ iter_end（找不到時回傳「結尾之後」）
cpp:iter_lower / iter_upper ←─ iter_end（同上）
cpp:container_erase 吃位置 ←─ iter_find（語料最常見的寫法是 erase(find(x))）
cpp:container_max        ←─ 無（它不需要位置這個概念）
```

## 建議實作順序

1. **`cpp:compare` 的指標比較** — 它是**其他每一條的前提**：不修的話任何
   `it != c.end()` 迴圈都一次不跑，而後面每一顆元件都會「看起來沒有效果」
2. **`cpp:increment` 認得指標** — 同上，走訪的另一半
3. **`cpp:iter_begin` ＋ `cpp:iter_end`** — 一起做，它們是一對
4. **`cpp:iter_find`** ＋ **`cpp:container_erase` 吃位置** — 語料最常見的組合
5. **`cpp:iter_lower` ＋ `cpp:iter_upper`**
6. **`cpp:container_max`**（`*s.rbegin()`）

⚠️ **1 與 2 必須先做完**，否則 3–6 的驗收會全部是「加了元件而程式還是不動」
——而那看起來像新元件壞了。

## 跨語言對應

| C++ | Python | 備註 |
|---|---|---|
| `c.begin()`／`c.end()` | `iter(c)`／`StopIteration` | 🟠 Python 的迭代器**不是位置**，它是一個會吐值的東西——**不是同一個概念**，不要做成等價邊 |
| `*it` | `next(it)` | 同上 |
| `c.find(x) != c.end()` | `x in c` | 🟢 這一對**是**同一個語義動作，而 Python 那側已經有 `in` |
| `*s.rbegin()` | `max(s)` | 🟢 同一個語義動作 |

## 需注意的邊界案例

- **空容器上的 `*c.begin()`** 是 UB（`begin() == end()`）。
  🟢 而我們**自然會出聲**：`pointer_deref` 的範圍檢查會丟索引越界。
  ⚠️ **那不得進判準**——g++ 在那裡沒有答案。
- **`c.end()` 的 offset 是 `length`**，而 `pointer_deref` 對它會丟越界——**那是對的**
  （解參考 `end()` 本來就是 UB）。要確認錯誤訊息**指得出是這件事**。
- **`find` 找不到時回傳 `end()`**，而 `end()` 是一個合法的值。
  🔴 所以 `find` **不得**在找不到時丟錯或回 null——那會讓
  `if (it != c.end())` 這個標準寫法整個失去意義。
- **容器被修改之後 offset 的意義會變**（刪掉第 i 格，原本指第 j>i 格的位置全部偏移一格）。
  🟠 那正是 C++ 的「失效」，而我們不模擬——見上面的範圍決策。
- **`erase(位置)` 回傳下一個位置**：我們 splice 之後「下一個」還是同一個 offset，
  所以回傳 `{同一串格子, 同一個 offset}`。⚠️ 而那**剛好對**，不是設計出來的
  ——要寫進註解，否則下一個人改 splice 的實作時不會知道有東西靠著它。

# 🔴 這份報告有一段是錯的——實作時才發現（2026-09-17）

## `cpp:container_iter` **早就存在**，而我把它提議成了新元件

它 2026-08-13 就做好了，已經在 `cpp-advanced` 的課程清單裡，而
**這份報告的核心結論一字不差寫在它自己的檔頭**：

> **不為迭代器發明第三種表示。** 指標算術（`it + 1`）、解參考（`*it`）、
> 相減（`it - v.begin()`）在那個表示上全都已經能跑。

也就是上面「🔴 先回答那個設計問題」那一整節，**是在重新推導一個已經拍板並實作的決定**。
而我之所以沒發現，是因為我從「語料缺什麼」往下查，沒有先問「這一族已經有誰」。

> **一次探索如果只從缺口出發，它會把既有的東西重新發明一次
> ——而重新發明出來的東西，與原來的那個【長得很像但不完全一樣】。**

⚠️ 而線索其實一路都在：命名詞彙表裡的 `iter` 條目逐字寫著
「`cpp:container_iter`（`v.begin()`／`v.end()`）……**哪一端是參數**」。
**我讀到那一行才發現的。**

## 所以真正缺的是什麼——量出來的

| 症狀 | 根因 | 修法的大小 |
|---|---|---|
| `for (auto it = v.begin(); …)` 整段掉進 raw code | **自動型別的變數宣告沒有宣告 `forLoopPart`**，而同族那顆一般的變數宣告有 | **一個宣告** |
| `lower_bound`／`upper_bound`／`rbegin` →「不是一個物件」 | 方法名沒登錄 | 一顆新膠囊 ＋ 既有那顆多認兩個值 |
| `find` → 回一個數字 | **字串的搜尋已經擁有這個方法名** | 方法分支 ＋ 容器自己宣告 `associative` |
| `erase(位置)` 刪成全部 | 同一個方法名的第三條分岔 | 依引數種類分岔 |
| `++it`／`it != it2` | `toNumber` 把兩者壓成同一個數字 | 兩個運算子（已於前一刀修） |

🔴 **第一個最值得記**，而它不是迭代器的問題：

> **同一族的兩顆元件，一顆宣告了某個性質而另一顆沒有——
> 那個差別不會有人發現，直到有人寫出只有後者能表達的程式。**

而錯誤訊息指著整段 `auto it=v.begin()`，學生會以為是 `begin()` 不支援。

## 反向迭代器：報告判「不做」，而實作時改判「做」

上面「🟠 反向迭代器不做」那一節的理由是
「真做起來要在值上加一個方向旗標，**每一個運算子都要認它**」。

實作時發現那個代價被高估了：**只有「往哪邊移」那一個地方要認它**
（解參考、比較、相減都與方向無關）。加起來是一個欄位 ＋ 一行：

```ts
const step = v.reverse ? -delta : delta
```

🟢 所以 `rbegin`／`rend` 一起做了，而且它們是**同一顆元件的 `which` 多兩個值**
（「哪一端是參數」這條規則本來就涵蓋得了它們）。

⚠️ 而**不做的代價會是靜默的**：`++rit` 往後走的話，一個由大到小的走訪
會安靜地變成由小到大——程式跑完、印出東西、順序是反的。

## 實作時量到而這一刀不做的

🟠 **`set<int> s{1,2,3}` 的大括號初始值被丟掉**（size 0，而 `vector` 的可以）。
   語料 **0 處**、課文 **0 處**——我那個測試是自己編的。記在這裡。
🟠 **`new int(5)` 的初始值被丟掉**（`*p` 給 0）。語料 0 處、課文 0 處。
   ⚠️ 兩者是同一個形狀：**lift 把一個初始值整個丟掉，而執行時看起來像「預設值」**。
