## ⑤ 先量：tree-sitter 怎麼看它（🔴 這一題的答案改變了整個問題）

```cpp
#define rep(i,n) for(int i=0;i<n;i++)
int main(){ rep(i,m) cin >> d2[i]; rep(k,4){ s += k; } }
```

```
preproc_function_def                 🟢 定義那一行【解得很乾淨】
  identifier «rep»
  preproc_params  (identifier «i», identifier «n»)
  preproc_arg  «for(int i=0;i<n;i++)»

compound_statement                   🔴 使用處被拆成【兩個並列的語句】
  expression_statement → call_expression «rep(i,m)»
  expression_statement → «cin >> d2[i]»        ← 迴圈主體變成【兄弟】，不是子節點
  expression_statement → call_expression «rep(k,4)»
  compound_statement   → «{ s += k; }»         ← 同上
```

🔴 **它不是 `ERROR`，它是一棵看起來合法的樹**——而那正是第 199 刀記過的那一種：

> **一個不做的決定，如果那個名字已經被認領，
> 它不會變成誠實降級——它會變成一個錯的答案。**

### 🔴 而今天的產出**已經在靜默地弄丟東西**（實測，這是這一刀最重要的讀數）

```
學生寫的        rep(i,m) s += i;
我們產回去      rep(i, m) += i;        🔴 【s 不見了】
學生寫的        rep(k,4){ s += k; }
我們產回去      rep(k, 4);             ← 多一個分號
                { s += k; }            ← 區塊掉出來變成一個裸區塊
```

lift 把 `rep(i,m)` 與 `s += i` **併成一顆** `cpp:var_assign_compound`
（target ＝ 那個呼叫、value ＝ `i`），`s` 整個蒸發。

⚠️ **執行那一路是誠實的**（`#define` 那一行變成 `unresolved` → `RUNTIME_ERR_UNRECOGNIZED_CODE`），
**而程式碼那一路不是**。一個學生把這支程式貼進編輯器、動一下積木，
**他的 `s` 就不見了**。

> **「這個東西我們不支援」如果只在【執行】那一路出聲，
> 那麼【程式碼】那一路的沉默就是一個錯的答案。**

## ① 墓碑：**維持否決，而更正它的理由**

`knowledge/history/014-墓碑目錄.md:23`「模擬 C preprocessor 來解決巨集」：

> **為什麼不選**：重新實現 C preprocessor 的正確性成本極高……
> **S0-S2 的教學場景根本不需要（學生程式碼不會用框架巨集）**。

**兩句話，一句對一句錯：**

| 那句話 | 判定 | 證據 |
|---|---|---|
| 「重新實現 C preprocessor 的正確性成本極高」 | 🟢 **仍然成立** | `#`／`##`／可變引數／遞迴／條件編譯互動——而語料一處都沒有 |
| 「學生程式碼不會用框架巨集」 | 🔴 **被語料證偽** | 218 支裡 **4 支**用函式形巨集 |

🟢 **而這一刀做的不是墓碑否決的那件事**：

```
墓碑否決的   實作一個 preprocessor：任意巨集、任意展開、文字層替換
這一刀做的   一條【證得出唯一讀法】的樹修復：
             ① 巨集在同一個翻譯單元裡定義過（拿得到 name/params/body）
             ② 代入之後那段文字【解得乾淨】（沒有 ERROR）
             ③ 兩者有一個不成立 ⟹ 回 null，走今天的降級（會出聲）
```

這正是 `ast-repairs.ts` 檔頭寫死的契約：
「**只准做『這段文字唯一合法的讀法就是這個』的重寫**」。
而 C 預處理器對一個已定義的巨集，展開結果**是唯一的**——這不是啟發式。

📌 **要在墓碑上補一筆**（動作項）：
> 2026-09-20：括號裡那個前提（「學生程式碼不會用框架巨集」）被語料證偽
> （218 支 4 支）。**否決仍然成立**——`specs/component-discovery/cpp-func-macro.md`
> 做的是一條有唯一讀法的樹修復，不是 preprocessor。

## ② 一字不差：**用既有的 `layoutHints`，而它的契約剛好就是這件事**

`src/core/types.ts:82` 的 `layoutHints` 檔頭逐字：

> **原文的排版偏好**——「這個節點在原始碼裡長什麼樣」，而語義不看它。
> **投影記住它，積木看不到它。**
> ⚠️ 使用者在積木那側改過之後這一格會不在，那時產出預設的排版
> ——**仍然正確**。排版的遺失不是語義的遺失。

**巨集屬於「同一個意思的兩種寫法」那一邊，與別名【不同】：**

```
別名   #define ll long long        `ll` 是學生取的【名字】     展開＝把名字拿掉   🔴 不做
CTAD   vector dp(…)               純粹的【省略】，沒有名字     補回去＝正規化     🟢 做（今天稍早）
巨集   rep(i,m) …                 同一個迴圈的【另一種拼法】   → layoutHints      🟢 這一刀
```

🟢 **而「積木改過之後 hint 就不在了」正是我們要的行為**（實測過同族：
`roundtrip-cpp-bits.test.ts` 的雙層括號那一段量到「走一趟積木之後 metadata 沒了」）：

```
沒碰積木     rep(i,m) s += i;                 🟢 一字不差
碰過積木     for (int i = 0; i < m; i++) …    🟢 誠實——因為迴圈的界線可能已經被改了
```

⚠️ 反過來才是缺陷：**留著 `rep(i,m)` 而界線被改過**，那是一句謊話。

### ⚠️ 要動的一格

`layoutHints?: Record<string, boolean>` → **`Record<string, boolean | string>`**
（要存 `"rep(i,m)"` 這串字）。今天唯一的消費者是 Python 的固定組合（布林），
放寬不影響它。**這是一個核心宣告的改動 ⟹ 要跑護欄。**

## ③ 身分還是參數：**使用處【兩者都不是】——它就是既有那顆**

`cpp:loop_count` 的宣告（`src/components/cpp/loop_count/component.json`）：

```
properties  var_name（識別字）· inclusive（enum）
slots       from · to · body
```

而語料那兩個巨集體**剛好落在這張表上**（實測 lift 結果）：

```
for(int i=0;i<n;i++)    →  loop_count { var_name:i, inclusive:FALSE }  from 0  to n
for(int i=1;i<=n;i++)   →  loop_count { var_name:j, inclusive:TRUE  }  from 1  to n
```

🟢 **所以使用處不新增身分、不新增屬性、不新增插槽**。
巨集的拼法住在 `metadata.layoutHints`，而那**不是 property**
——照它自己的檔頭：「積木上沒有這一格、學生不必知道」。

### 而**定義那一行**是一顆新身分

| | `cpp:define` | 🆕 `cpp:define_func` |
|---|---|---|
| AST | `preproc_def` | `preproc_function_def` |
| properties | `name`／`value` | `name`／`params`／`value` |
| 語義上做的事 | 宣告一個**具名常數**（或一個小名） | 宣告一個**可展開的樣板** |

照 `元件代數.md:250` 的判準：🔴 **「語義上做的事不同」⟹ 是身分**。
⚠️ 注意它**不適用**表裡那條「形式不是身分，是參數（`const int`／`#define`／裸 `int` → 一顆 ＋ style）」
——那三種做的是**同一件事**（宣告一個常數），而這兩種不是。

## ④ 展開在哪一層：**AST 修復層，而這個 repo 已經有那個掛鉤**

| 候選 | 判定 | 理由（有出處） |
|---|---|---|
| 文字層（parse 前替換） | ❌ | 來源位置全偏移；而且它**就是**墓碑否決的那件事 |
| **AST 修復層** | 🟢 **選它** | `src/core/lift/ast-repairs.ts` 正是為「這棵樹一開始就不是這段程式的樹」而存在，契約三條（回 null 是預設／不得換語義／不得遞迴）逐條對得上 |
| lift 層（別名表） | ❌ | `src/interpreter/aliases.ts` 檔頭逐字：「**帶參數的 `#define rep(i,n)` 不進這張表——那是一段程式，不是一個名字**」 |

🟢 **重解析不是新機制**：`src/languages/cpp/lang/misparse.ts:157` 已經自己開了一支
同語言的解析器（`parserFor` ＋ `reparseExpression`），並且**負責擦掉自己的痕跡**
（它插的那對括號）。這一刀擦痕跡的方式就是 ②（layoutHints）。

🟢 **而定義那一側的表已經有一格空著**：`LiftContextData.macroDefinitions`
（`src/core/types.ts:807`）——`addMacroDefinition` 今天**零個呼叫端**。
這一刀是它的第一個消費者。

### ⚠️ 從 ⑤ 讀出來的一個設計約束（stage 2 要照著做）

修復的形狀**跨兩個兄弟節點**（呼叫 ＋ 下一句），所以修復要掛在
**語句列的擁有者**（`compound_statement`／函式主體）上，不是掛在那個呼叫上。
掛在呼叫上的話，下一句會被**再 lift 一次**（重複）。

## ⑥ 不做什麼（每一條都有語料讀數）

| 不做 | 語料 | 理由 |
|---|---|---|
| `#define mp(a,b) make_pair(a,b)`（展開成**運算式**的函式形巨集） | **0 處** | 形狀不同（要嵌在運算式裡，不是語句前綴）。⚠️ 而它**不是不可能**——同一條修復以後可以長出運算式那一支 |
| `#define PIN_OF(i) …` | **0 處**（Arduino 盲測有） | 見下面的釘子覆核 |
| `#` 字串化 | **0 處** | 這才是「重新實現 preprocessor」的部分——墓碑仍然成立 |
| `##` 連接 | **0 處** | 同上 |
| 可變引數巨集 `...` | **0 處** | 同上 |
| 遞迴／自我參照巨集 | **0 處** | C 的規則本身就有「不重入」的特例，模擬它＝寫一個 preprocessor |
| 巨集在 `#if` 裡被重新定義 | **0 處** | 條件編譯 × 巨集的交互是墓碑的核心理由 |

### 🔴 釘子覆核：`tests/integration/fuzz-cpp-hardware.test.ts:631`

它寫著「`#define PIN_OF(i)` → 殘差 9，**而墓碑對函式巨集仍然成立**」。

**覆核結果：那根釘子的【結論】要改，【它自己】先不拔。**
- 「墓碑對函式巨集仍然成立」這句話**要改**——這一刀證明了函式形巨集裡
  「展開成語句前綴」那一支做得起來，而且不需要 preprocessor。
- 而 `PIN_OF(i)` 是**展開成運算式**的那一支（語料 0 處），這一刀不做。
- 📌 **動作項**：把那根釘子的觸發條件改寫成
  「**運算式位置的函式形巨集**那一刀」，並指向本報告。
  > **一根釘子如果寫著一個【已經不成立的理由】，
  > 它會在那個理由被推翻的那天繼續擋著。**

## 建議實作順序

1. **`cpp:define_func`（定義那一行）** — 沒有它，`#define` 那一行本身就讓執行停住
2. **`layoutHints` 放寬成 `boolean | string`** — 核心宣告，先做才擋得住 ②
3. **AST 修復：語句列裡的巨集呼叫** — 三種用法（單句／區塊／巢狀）
4. **產生器讀 `layoutHints.macroHeader`** — `cpp:loop_count` 的 generate
5. 語料重量 ＋ 那 3 支逐支再量

## 跨語言對應

**Python 沒有預處理器**，所以沒有對應的概念。
⚠️ 而**不要因此把它當成「C++ 專屬的髒東西」**：它在語義樹上的落點
（`cpp:loop_count` ＋ 一個排版註記）是**語言中立的**——
「同一個意思的另一種拼法」在 Python 那側對應的是 `a, b = 1, 2` 的括號，
而那正是 `layoutHints` 今天唯一的消費者。

## 需注意的邊界案例

1. 🔴 **巢狀**：`rep(i,m) rep(j,n) stmt;` — 修復要能吃自己的產物（而契約說**不得遞迴**）。
   處方：一次把**整串**語句列處理完，不要讓修好的樹再被同一條規則認領。
2. 🔴 **`A[i][j]` 在未修復的樹裡是壞的**（實測：`subscript_argument_list` 空的）。
   修好之後應該就對了——**要驗**，不要假設。
3. **巨集名與變數同名**：`rep` 如果也是一個變數，那個呼叫就不是巨集。
   處方：只認**同一個翻譯單元裡 `preproc_function_def` 定義過**的名字。
4. **引數裡有逗號**：`rep(i, f(a,b))` — 代入時要照括號深度切，不能直接 `split(',')`。
   語料 0 處，而**寫錯的代價是一個錯的答案**，所以要寫對。
5. **巨集的參數名與外層變數撞名**：C 的巨集是文字替換，**沒有衛生性**。
   照它的語義做（直接代入）就是對的——不要發明一個更聰明的。
6. **同名重複定義**：`cpp:define` 的執行器註解說「`declare` 會丟錯，而那是對的」。
   函式形要不要沿用，stage 2 判。
