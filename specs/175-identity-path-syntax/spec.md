# Feature Specification: 身分的階層與實例的路徑，在同一個字串上分得出來

**Feature Branch**: `175-identity-path-syntax`
**Created**: 2026-09-06
**Status**: Draft
**Input**: vision「🆕 分子：組合階層與粒度切換」（2026-09-03 升格）的第一個交付。驗收逐字：

> 🔴 護欄：實例路徑（`car.wheelFL.speed`）與身分階層（`python:numpy.linalg.solve`）
> **在同一個字串上分得出來**——注入一個歧義字串必須紅

而 vision 也寫了它為什麼排第一：

> 🔴 **①（路徑語法）排第一是因為它是唯一一個三個域都會用到、而且錯了要全改**
> 的東西；而它與身分階層**都用 `.`**，那個撞號要在寫任何宣告之前解掉。

---

## 這一刀在解什麼

**兩種完全不同的東西，將要用同一個符號。**

```
身分階層   python:numpy.linalg.solve    「這是【哪一種】東西」——型別側
實例路徑   car.wheelFL.speed            「這是【哪一個】東西」——實例側
```

而它們**都用 `.`**。今天不撞，因為兩邊都還沒有東西：實測**帶 `.` 的身分 0 顆**、
實例路徑那種東西**還不存在**。

🔴 **所以這一刀不是在加一個機制，是在把一條已經定了的規則變成會出聲的。**

`concepts/元件.md:185` 自己標著：

> **狀態：規則已定，尚未實作**（2026-08-13 三輪討論）。
> 今天 177 顆全是扁平的 `cpp:*`，**帶 `.` 的身分 0 顆**——語法位置空著。

而那正是 `concepts/執行機構.md` 的第一句：

> **一條規範沒有機械化的檢查，它本身就是殼——而殼看起來像完成。**

⚠️ **等到兩邊都有東西之後才解這個撞號，就要改三個域**——那是 vision 說
「錯了要全改」的意思。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一個字串，說得出它是哪一種 (Priority: P1)

任何拿到一個帶 `.` 的字串的地方（工具箱、登錄表、未來的裝配樹），
問一句就知道它指的是**一種東西**還是**一個東西**。

**Why this priority**: 那是這一刀的全部——三個域都會問這一句。

**Independent Test**: 餵幾個字串，比對答案。

**Acceptance Scenarios**:

1. **Given** `python:numpy.linalg.solve`，**When** 問它，**Then** 說「這是一個身分」
2. **Given** `car.wheelFL.speed`，**When** 問它，**Then** 說「這是一條實例路徑」
3. **Given** 一個**兩者都解讀得通**的字串，**When** 問它，
   **Then** 說「**歧義**」——⚠️ 而不是挑一個

### User Story 2 - 歧義會出聲，而不是被猜掉 (Priority: P1)

有人寫下一個分不出來的字串時，系統**當場說它分不出來**，
而不是選一個看起來合理的解讀。

**Why this priority**: 🔴 這是這一刀存在的理由。一個「猜一個」的判別器
會讓撞號**繼續存在而看不見**——直到兩個域各自建了一套解讀。

> **一個回答「是」或「否」的判別器，在遇到「兩者都可以」的時候
> 必須說出第三個答案——否則它會把一個未解的衝突報成一個已解的答案。**

**Acceptance Scenarios**:

1. **Given** 一個歧義的字串，**When** 護欄掃到它，**Then** 紅，
   而訊息**說得出為什麼歧義**
2. **Given** 現有的每一顆身分，**When** 護欄掃過，**Then** 一顆都不得被判成歧義
   （那是回歸的底線）

### User Story 3 - 階層的來源受限，而那條限制會被檢查 (Priority: P2)

身分裡的階層只能來自**語言自己的語義**（package、子模組），
不准表達**我們的分類**（`containers`、`math`）。

**Why this priority**: `concepts/元件.md:214` 的規則②，而它有前科
——[history/047](../../knowledge/history/047-模組是搬家的中途站不是終點.md)
「模組是搬家的中途站，不是終點」。

> **分類會變，而變了就是搬家。**

**Acceptance Scenarios**:

1. **Given** 一個身分的階層段落是我們發明的分類名，**When** 檢查，**Then** 紅

### Edge Cases

- 🔴 **沒有冒號而帶 `.` 的字串**——那是**歧義的核心案例**：
  `numpy.linalg.solve` 少了 `python:` 就與 `car.wheelFL` 長得一樣
- **只有冒號沒有 `.`**：那是今天的 332 顆，**必須全部判成身分**
- **`string::npos`** 這種帶 `::` 的：⚠️ 它是**程式碼裡的字面**，不是身分也不是路徑
- **空字串／只有一個 `.`／結尾是 `.`**：說得出「不合法」，而不是崩掉
- ⚠️ **`@someone:pkg.mod`**：第三方 scope 加階層——兩個機制要能疊

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 能判定一個字串是身分階層、實例路徑、或**兩者皆可解讀**
- **FR-002**: 判定 MUST 有**三種**結果，不得把「兩者皆可」壓成其中一種
- **FR-003**: 身分的階層 MUST 投影得出它的目錄位置與積木型別名
- **FR-004**: 護欄 MUST 擋住歧義的身分，並**說得出為什麼歧義**
- **FR-005**: 護欄 MUST 擋住「階層表達了我們的分類」
- **FR-006**: 既有的每一顆身分 MUST 仍然被判成身分（零回歸）
- **FR-007**: 判定 MUST NOT 依賴任何特定語言的知識

### Key Entities

- **身分**：`<擁有者>:<名字階層>`。⚠️ 擁有者那一段**一定在**，
  而它正是與實例路徑的分界
- **實例路徑**：`<實例>.<實例>.<屬性>`。今天不存在，而語法位置要先留好
- **判定結果**：三選一——身分／實例路徑／**歧義**

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三種答案各有至少一個標本，而它們**逐字**符合預期
- **SC-002**: `python:numpy.linalg.solve` 的目錄與積木型別投影**逐字正確**
- **SC-003**: 注入一個歧義字串 → 護欄紅，訊息裡有「為什麼」
- **SC-004**: `concepts/元件.md` 那三條規則，**每一條都有一支測試指得到它**
- **SC-005**: 現有 **332 顆**身分，被判成歧義的 = **0**
- **SC-006**: 判定那一支所在的地方，**語言名出現次數 = 0**

---

## Assumptions

- **A-001**: 判定回**三種**答案而不是一個是非。
  🔴 **理由**：「歧義」是這一刀真正要抓的東西，而一個是非會逼呼叫端
  **在兩個都不對的答案裡挑一個**。
- **A-002**: 分界用**擁有者那一段**（冒號前面）——身分一定有，實例路徑沒有。
  ⚠️ 而那讓「**沒有冒號而帶 `.`**」變成歧義的核心案例，那正是要盯的那一個。
- **A-003**: 「我們的分類」用一份**明文清單**來認（`containers`／`math` 那類），
  而不是猜。🔴 理由：猜的話它會誤傷語言真的有的模組名
  （Python 真的有 `math`）——⚠️ **而那正是這條規則最容易出錯的地方**。

---

## Out of Scope

- **實例路徑的資料結構**——`car.wheelFL.speed` 那種東西今天不存在，
  它是分子的 ②③④（Collapse-to-molecule · 鑽入 · 來回一致）
- **真的把某一顆膠囊改成帶 `.` 的身分**——那是 Python package 那一刀
- 鑽入 · 麵包屑 · 裝配樹
- ⚠️ **不做「自動修正歧義」**——歧義要**出聲**，不要被解掉。
  > **一個會自動解掉歧義的機制，會讓那個歧義永遠不被討論。**
