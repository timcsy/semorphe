# Feature Specification: `if_else` 跑不了

**Feature Branch**: `066-if-else-execute` ｜ **Created**: 2026-08-06

## 為什麼做這個

完備性護欄長期回報 `if_else.execute` 是 **❌ 缺**——五路 810 條裡**唯一的一個「缺」**。

直覺上那不可能：if/else 是核心控制流程，每個程式都在用。

**實測它是真的。** `if_else` 有概念定義、有產生器、有積木投影（使用者拖得到
那個積木），**就是沒有執行器**。拖它、產得出程式碼、按執行 → 未知概念。

會動的那個是**另一個概念**，子節點的名字不同。同一件事的兩個概念，只有一個
能跑。

> 「每次照量測行動的第一步，都要準備好推翻它」——而這次要推翻的是我自己
> 「這一定是誤報」的直覺，**不是護欄**。

## Requirements

- **FR-001**: `if_else` 的兩個分支 MUST 都能執行
- **FR-002**: 空的分支 MUST NOT 出錯
- **FR-003**: 語義 MUST 與另一個等價概念完全一致——**包含它們共有的缺陷**
- **FR-004**: 除錯與作用域的標註 MUST 與等價概念一致，否則使用者換一個積木就換一套行為
- **FR-010**: 既有測試全數通過

## Success Criteria

- **SC-001**: 五路完備性的「缺」**1 → 0**
- **SC-002**: 執行器清冊只多這一個，且記下新增理由
- **SC-003**: 既有測試全數通過

## Notes：一個順帶量到、但**不修**的既有缺陷

寫測試時發現：分支裡的宣告**會外洩到外層**——`executeBody` 不建子作用域，
而 `introduces_scope` 標註**沒有任何東西在讀**。

那不是本功能造成的，而修它會改變既有概念的行為。所以這次的斷言改成
「兩者一致」，並明說：**哪天作用域修好了，那支會因為兩者仍然一致而繼續通過
——它不是那個缺陷的釘子。** 缺陷本身另記。
