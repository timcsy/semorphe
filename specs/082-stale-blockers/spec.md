# Feature Specification: 過期的阻斷者——todo 上寫的那個早就修好了

**Feature Branch**: `082-stale-blockers` ｜ **Created**: 2026-08-06

## 為什麼做這個

64 支「只有名字的測試」裡，最大的阻斷者是「**陣列初始化列表在辨識時遺失**」
（17 支）。

**實測那個阻斷者不存在了。** `int a[3]={7,8,9}` 來回轉換正確、執行也正確。
050 修好了它，而**沒有人回頭看那些 todo**。

> 一個停用的測試會記住它當初為什麼被停用，**而它不會記住那個理由何時失效**。

## 而重新產生之後，它們抓到三個真 bug——沒有一個是 todo 上寫的那個

| 探測 | 實際 | 應該 |
|---|---|---|
| `char s[4]={'a','1','B',' '}` 印出 | `974966` | `a1B` |
| `isdigit('a')` | 真 | 假 |
| `isupper('B')` | **未定義函式** | 1 |

三個都與「陣列初始化列表遺失」無關。**todo 的阻斷者標記不只過期，方向也是
錯的。**

根因：
1. 初始值沒有轉成陣列的**元素型別**，於是字元字面留著數字碼
2. 字元分類函式用 `String(value).charAt(0)` 取字元——數字碼 97 取成 `'9'`，
   所以 `isdigit('a')` 回傳真。**程式跑完、印出東西、而它是錯的**

## 順帶：中立性的 0 不完整

那四個字元分類函式住在核心的直譯器裡，形式是**裸的物件鍵**
（`cpp_isalpha:` 而不是 `'cpp_isalpha'`）。

**中立性護欄只比對引號字串字面——它一筆都沒數到。**

那是「一條規範被機械化時，選了哪一維會消失在數字裡」的又一個面向：
不只維度（身分 vs 語法），**連同一維度的不同書寫形式都可能漏掉**。

已搬進 cctype 膠囊（那個模組的執行器欄位原本填著一個叫
`executorsStillInCore` 的佔位符——**名字本身就是那筆債的自白**）。

## ⚠️ 而我差點順手違反 P2

搬移時順手加了 `isalnum`／`isupper`／`islower`／`isspace`／`ispunct` 的執行器
——**而它們沒有概念定義、沒有辨識、沒有產生器、沒有積木**。

一條路的實作配上四條路的空白，正是 P2 五路完備性禁止的。已收斂回有完整五路
的兩個；要加其餘的是**五路一起加**，那是另一個功能。

## Requirements

- **FR-001**: 過期阻斷者的 todo MUST 重新產生成有本體的測試
- **FR-002**: 每一支 MUST 驗**執行結果**，不只驗來回轉換
- **FR-003**: 期望值 MUST 由**真的編譯器**決定，不得心算
- **FR-004**: 陣列初始值 MUST 轉成元素型別
- **FR-005**: 字元分類 MUST 正確處理以數字碼存放的字元
- **FR-006**: 字元分類的執行器 MUST 搬進膠囊
- **FR-007**: MUST NOT 新增沒有五路的概念

## Success Criteria

- **SC-001**: 只有名字的測試 **62 → 58**
- **SC-002**: 三個真 bug 修掉，且各有測試
- **SC-003**: 期望值全部由編譯器產生
- **SC-004**: 既有測試全數通過
