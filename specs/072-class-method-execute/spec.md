## 關鍵設計：方法裡的欄位怎麼存取

C++ 的方法直接寫欄位名（`x = 5`，不是 `this->x = 5`）。

天真的做法是**把欄位複製進方法的作用域、跑完再複製回去**——而那在**方法呼叫
方法**時是錯的：內層改的是自己那份副本。

這裡用的是：**方法的作用域直接用物件的欄位表當自己的變數表**。兩者都是同一種
對映結構，所以讀寫自動穿透，沒有副本、沒有複製回寫的時機問題。

方法本體跑在那之上的**子作用域**——否則方法的區域變數會落進物件變成欄位。

**兩件事各有一支測試釘住**，而「方法呼叫方法」那支就是為了讓複製回寫的實作在
那裡壞掉。

## 範圍

| 做 | 不做 |
|---|---|
| 類別定義、欄位、方法 | 存取控制（public／private 一視同仁） |
| 建構式（含參數） | 繼承、虛擬函式、純虛擬 |
| 方法呼叫（敘述與運算式兩個位置） | 運算子多載、解構式 |
| `this` | 靜態成員、指標取成員 |

剩下的**留在殼的清單裡繼續被數**。

## Requirements

- **FR-001**: 方法改的 MUST 是**這個實例**的欄位
- **FR-002**: 方法呼叫方法時，內層改的 MUST 是同一個實例
- **FR-003**: 方法的區域變數 MUST NOT 洩漏成欄位
- **FR-004**: 兩個實例的方法 MUST 互不影響
- **FR-005**: 呼叫不存在的方法 MUST 出聲
- **FR-006**: 建構式 MUST 在用它初始化時被呼叫
- **FR-007**: 核心 MUST NOT 為了分派而編一個沒有概念定義的假概念
- **FR-008**: 訊號類別 MUST 只有一份——複製成第二份的話 `instanceof` 一律為假
- **FR-009**: 真的實作了的概念 MUST 從空操作清單移除
