# Feature Specification: 改程式碼之後，沒動到的節點保住身分

**Feature Branch**: `369-stable-node-ids`
**Created**: 2026-11-09
**Status**: Draft
**Input**: vision 286〈操作者介面〉缺口②「穩定的節點身分」（history/334、355）。spec 220 量到：改程式碼會重新解析、每個節點都換新身分，於是改一個字也會讓所有待處理的提議過期。

## 背景

history/355：「改程式碼會重新 lift、全部換號 ⟹ 大部分提議過期。依形狀重新對位是『猜』，第一刀照實過期。」
這一刀把「對位」做成**不猜**的：只在對應關係唯一時沿用舊的身分，對不上的照舊換新、提議照實過期。
它也是同步協調器檔頭寫的「階段 5b（nodeId 穩定）」的前置。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 改了別處，提議還在 (Priority: P1)

AI 送來一個提議（刪掉某個 if）。人在接受之前，先在程式碼裡改了另一行（把 5 改成 6）。
提議仍是可接受的，差異以改過的程式重新算；接受後的結果包含人剛剛的修改。

**Independent Test**: 送一個提議 → 改程式碼裡無關的一行 → 提議仍可接受、差異反映新的那一行。

**Acceptance Scenarios**:

1. **Given** 一個待處理的提議，**When** 人改了程式碼中與提議無關的地方，**Then** 提議仍可接受。
2. **Given** 同上，**When** 人改的是提議指的那個節點本身的文字（例如改了 if 的條件），但它仍是同一種東西、在同一個位置，**Then** 提議仍可接受，差異以改過的為準。
3. **Given** 一個待處理的提議，**When** 人刪掉了提議指的那個節點，**Then** 提議過期（與今天相同）。

### User Story 2 - 換掉整支程式，提議全部過期 (Priority: P1)

套用範例、換目標或語言、課文帶進一支新的起始程式、匯入檔案——程式是**換掉**，不是改。
即使新程式恰好有形狀相同的部分，之前的提議都過期，不會套到新程式上。

**Acceptance Scenarios**:

1. **Given** 一個待處理的提議，**When** 套用一份範例（即使範例的骨架與原本相同），**Then** 提議過期、只能退回，且之後不會自己變回可接受。

### Edge Cases

- 兩句一模一樣的句子刪掉其中一句：剩下那句沿用哪一個身分？→ 以順序對位（最長共同子序列），確定的那些沿用；不確定的換新。
- 中間插入一句：前後沒動的句子都沿用。
- 一段裡同時有增有刪、數量不同：只對得出唯一對應的沿用，其餘換新。
- 同一個舊身分不得同時給兩個新節點。
- 元件換了（while 改成 for）：不沿用。

## Requirements *(mandatory)*

- **FR-001**: 程式碼重新解析成語義樹之後，系統 MUST 把新樹對到前一棵樹：根對根；同一個接點裡的子節點以順序對位，先對整棵子樹完全相同的，其餘只在「中間那一段兩邊數量相同、而且逐一是同一種元件」時對位。
- **FR-002**: 對上的節點 MUST 沿用前一棵樹的身分；對不上的保留新身分。一個舊身分最多給一個新節點。
- **FR-003**: 元件不同的節點 MUST NOT 沿用身分。
- **FR-004**: 程式被**換掉**（套用範例、換目標或語言、課文帶進起始程式、匯入）時，所有待處理的提議 MUST 標成過期，且不會因之後的檢查變回可接受。
- **FR-005**: 沿用身分 MUST NOT 改變程式碼、積木、執行的任何結果（只是身分）。

## Success Criteria *(mandatory)*

- **SC-001**: 改程式碼中與提議無關的一行之後，提議 100% 仍可接受（e2e）。
- **SC-002**: 套用範例後，待處理的提議 100% 過期（e2e）。
- **SC-003**: 全套測試與 e2e 不退步（身分沿用不改變任何投影）。

## Assumptions

- 對位只看結構（元件、屬性、接點），不看文字位置。
- 從積木改回來的路（抽取時沿用積木對應的身分）今天已經保住身分，不在這一刀。
