# 契約：一個宣告過的接點要走得完來回

**Date**: 2026-08-14

## 契約一：來回不掉東西

```
語義樹（接點有值）→ render → 積木 → extract → 語義樹
                                                └─ 那個值【還在】
```

- MUST：放得進去的，回得來
- MUST：**空的還是空的**——不得因為補了插槽而生出預設值
- MUST：一顆元件的**每個形態**都成立

## 契約二：三種子機制，三種修法

| 子機制 | 真相在哪 | 修法 |
|---|---|---|
| ① JSON 是唯一真相 | `forms/blocks.json` | 加 `input_value` ＋ `renderMapping.inputs` ＋ i18n |
| ② 有動態插槽沒對映 | 同上 | 加 `renderMapping.dynamicRules` |
| ③ 🔴 命令式註冊 | `block-registrar.ts` | **兩邊都改**——JSON 與命令式 |

⚠️ ③ 是 `CLAUDE.md` 記的**雙重真相**：
「修改任一方時**必須同步另一方**」。而第三十四條護欄在看它。

## 契約三：只新增，不改名不移除

```
新增 input    舊存檔沒有它 → Blockly 忽略 → ✅ 安全
改名／移除    🔴 舊存檔升不上來——本專案翻過車
```

⚠️ 而**仍要實測一次舊存檔**：測試綠不代表使用者的作品打得開。

## 契約四：數字下降要說得出是哪一種

```
實作了       積木真的能表達了        ✅ 真的進步
重新分類     把接點降級成參數        🔴 用宣告刷數字
```

`build-guardrail` 逐字：「**用宣告刷數字看起來會像進步**」。
