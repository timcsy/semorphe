# 契約二：存檔轉換

## 觸發

載入一份版本低於當前的存檔時。**localStorage 與匯入 JSON 走同一個入口。**

## 契約

```
migrate(v9存檔) -> v10存檔

前置：存檔的積木狀態裡每顆積木帶著舊型別字串
後置：每顆積木帶著新型別字串；語義樹、程式碼、其餘欄位一字未動
```

**必須成立的四件事**

| | 說明 | 怎麼驗 |
|---|---|---|
| C1 | 表上的每一個舊型別都被換掉 | 轉換後的存檔裡不含任何舊型別 |
| C2 | **冪等**——v10 再跑一次不變 | 轉換兩次的結果相同 |
| C3 | 表上沒有的型別**出聲** | 餵一顆未知型別，必須得到可辨識的失敗，不得靜默丟棄 |
| C4 | 語義樹不被碰 | 轉換前後的樹逐欄位相同 |

## ⚠️ 這是這個專案的第一次積木狀態遷移

既有的八個升級步驟**每一個都只改寫語義樹**。這次改的是投影那一側，
沒有先例可抄。

理由（規格開頭的 ③）：積木狀態被存起來、而且**載入時是主要還原來源**——

> **一個被存起來、而且載入時當作還原來源的投影，行為上就是真實。**

所以它適用「語義詞彙的變更 MUST 附一次性轉換」那條例外，
而不是「投影可重建所以不用管舊檔」。

## 回歸樣本

一份改名前的**真實**存檔必須留在專案裡，讓「舊檔還打得開」
**每次跑測試都被驗證**，而不只在改名當天被人工確認一次。
