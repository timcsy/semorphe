## 出發點：本來要清 5 個 import，而量了一次之後前提變了

原計畫是清掉「視圖／UI 直接 import `languages/cpp`」的 5 個點（護欄現值 3＋2）。

🔴 **而中立性護欄掃的是【概念身分】（`cpp:print`），不掃【積木型別】（`cpp_print`）。**

實測（本刀的第一步）：

```
護欄說          違規 0 筆
真實            中立範圍裡硬編了 44 筆【積木型別】
                src/core/block-input-names.ts        9 筆  ← 在【核心】
                src/core/projection/block-renderer.ts 2 筆  ← 在【核心】
                src/ui/block-registrar.ts            33 筆
```

> **一條護欄如果只掃一種拼法，另一種拼法的耦合就對它不存在。**

⚠️ 而它與 `history/015` 是**同一個病的第二次**：那次是「語言無關性從尚未驗證
到已知是破的」——**因為第一次真的去量了**。這次是同一句話換一個維度。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 🔴 報表不得說謊 (Priority: P1)

**驗收**：`RULE` 字串與實際判定一致；而**加一條斷言把它釘住**
（報表裡不得再出現「僅計語言專屬概念」這類已失效的措辭）。

### User Story 2 - 🔴 積木型別的耦合要被量到 (Priority: P1)

**驗收**：中立性護欄**同時**掃概念身分與積木型別；積木型別基線 **44**，只准降。
🟢 而它**不是**把 44 當違規報成紅的——**它是把一個看不見的東西變成有基線的數字**。

### User Story 3 - 5 個 import 清到 0 (Priority: P2)

⚠️ **降級成 P2，而理由要寫出來**：清完它們，中立範圍仍有 **44 筆**積木型別耦合。
**「Python 進來時這 5 個檔一行都不用改」是假的**——`block-registrar` 裡有
**40 顆命令式的 cpp 積木定義**，Python 一定要動它。

**驗收**：`視圖 import 語言 3 → 0`、`其餘 UI 檔 2 → 0`，基線一起下調並在 commit 說明。
