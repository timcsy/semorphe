# Feature Specification: 把核心從 `localStorage` 上拔下來

**Feature Branch**: `173-file-store-port`
**Created**: 2026-09-06
**Status**: Draft
**Input**: vision「🧾 未清的債」→「網頁版有檔案」的第二個驗收。逐字：

> 🔴 **驗收：`FileStore` 埠 ＋ 兩個實作**（記憶體／原生），
> **而 VSCode 那側不實作**（`vscode.workspace.fs` 就是）
> ——宿主獨立性的第三個實例

---

## 這一刀在解什麼

核心裡有 **9 處**直接呼叫 `localStorage`（`core/storage.ts` 與 `core/progress.ts`）。
而 `localStorage` 是**一個宿主的東西**——它在 Node 裡不存在，在 VSCode 的擴充主程序裡
不存在，在一個沒開 storage 的瀏覽器分頁裡會拋錯。

```
今天   核心 ──直接叫──> localStorage          🔴 綁死一個宿主
之後   核心 ──叫一個埠──> 誰實作那個埠由外面決定  🟢
```

> **一個「核心」如果它的存檔只在一個宿主上跑得起來，
> 那它不是核心，是那個宿主的一部分。**

🟢 而 VSCode 那側**今天就沒有用它**（實測：`src/vscode/` 零筆 `localStorage`
與 `StorageService`）——那側的真相是文件。所以這一刀不是去讓它實作，
**是別讓它有一天變成必須實作**。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 學生的東西還在 (Priority: P1)

學生關掉分頁、隔天打開，他的程式碼、積木擺放、上到哪一課、做對了哪幾題
——**一個都沒少**。

**Why this priority**: 這一刀是內部重構，而重構的驗收就是「外面看不出來」。
🔴 而這一條的失敗模式特別惡劣：**它安靜地丟資料**。

**Independent Test**: 存一份狀態、重載、比對每一個欄位。

**Acceptance Scenarios**:

1. **Given** 一份存好的狀態，**When** 重新載入，**Then** 每一個欄位逐字相同
2. **Given** 一份**舊版**的存檔，**When** 載入，**Then** 照舊升級（遷移路徑不變）
3. **Given** 一份壞掉的存檔，**When** 載入，**Then** 照舊拒絕**並備份**
   （「拒絕不得破壞原資料」那條規矩不得因為這一刀而鬆掉）
4. **Given** 做對過幾題，**When** 重新載入，**Then** 那幾個勾還在

### User Story 2 - 沒有 storage 的地方也跑得起來 (Priority: P2)

在一個沒有 `localStorage` 的環境（無痕模式擋掉、Node、未來的第三個宿主）
打開，**它不會崩，只是記不住**。

**Why this priority**: 今天的行為是**拋錯**（被 `try/catch` 吞掉），
而那讓「沒有 storage」與「存檔壞了」長得一樣。

**Independent Test**: 用記憶體那個實作跑一次完整的存／讀／刪。

**Acceptance Scenarios**:

1. **Given** 記憶體實作，**When** 存了再讀，**Then** 拿得回來
2. **Given** 記憶體實作，**When** 換一個新的實例，**Then** 是空的
   （它**不跨實例**——那正是「記憶體」的意思）

### User Story 3 - 下一個人加不回去 (Priority: P2)

任何人（或任何 AI）想在核心裡再寫一次 `localStorage.getItem`，會被護欄擋下來。

**Why this priority**: 沒有這一條，這一刀會在下一次「順手存一下」時被還原
——而**還原不會有人發現**，因為那一行在瀏覽器裡跑得好好的。

**Acceptance Scenarios**:

1. **Given** 現在的程式碼，**When** 跑護欄，**Then** 綠
2. **Given** 在核心注入一行 `localStorage.setItem(…)`，**When** 跑護欄，
   **Then** 紅，而訊息說得出是哪一個檔案哪一行

### Edge Cases

- **超過容量**：今天有 5MB 上限的檢查，而**真正的滿**是宿主拋
  `QuotaExceededError`——埠要能表達「寫失敗了」而不是靜靜回 `false`
- **同一把鑰匙兩個消費者**：`core/storage.ts` 與 `core/progress.ts`
  用的是**不同的鑰匙**（`semorphe-state` / `semorphe-progress`），
  而它們會共用同一個埠——⚠️ 埠不得假設「只有一份資料」
- **拒絕時的備份**：`storage.ts` 在拒絕一份存檔時會把原文搬到備份鑰匙。
  那條路**也要走埠**，否則「核心不碰 storage」只做到一半
- **列出鑰匙**：今天沒有人需要它。⚠️ 而 spec 的驗收寫著「讀／寫／刪／列」
  ——**列**要不要做，見 Assumptions

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 有一個**存放的埠**，而核心只透過它讀寫
- **FR-002**: 系統 MUST 提供**兩個實作**：一個記憶體的、一個瀏覽器本地的
- **FR-003**: 核心 MUST NOT 直接使用任何宿主的儲存 API
- **FR-004**: 護欄 MUST 擋住「核心直接用儲存 API」，並有注入測試
- **FR-005**: 存檔、載入、升級、拒絕備份、進度記錄的**行為逐字不變**
- **FR-006**: 寫入失敗 MUST 能被呼叫端知道（不得靜默成功）
- **FR-007**: 記憶體實作 MUST NOT 跨實例共用資料

### Key Entities

- **存放的埠**：一組「用一把鑰匙讀／寫／刪」的操作。
  ⚠️ **鑰匙是扁平的字串**，不是路徑——見 Assumptions A-001
- **記憶體實作**：測試用，也是沒有宿主儲存時的退路
- **瀏覽器本地實作**：網頁版今天的家

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 核心裡直接使用宿主儲存 API 的次數 = **0**（今天是 9）
- **SC-002**: **產品行為**逐字不變——既有的 **e2e 一條不改**而全數通過

  🔴 **這一條在實作中修正過**（憲章 IV：改要留下為什麼）。
  原本寫的是「既有的存檔測試**與** e2e 一條不改」，而跑下去有 6 支單元測試紅。
  它們紅的原因**不是行為變了**，是它們**靠全域的替身**：

  ```
  progress.test.ts        靠 localStorage.clear() 在測試之間重置
  storage-version.test.ts 把 globalThis.localStorage 換成一個 mock
  ```

  而這一刀把「存在哪」從**全域**變成**注入的**——那兩種替身因此失效。

  > **一個「測試一行都不改」的硬條件，在改動本身就是【換掉測試的替身機制】時
  > 是不可能成立的——而它讀起來像一個嚴謹的標準。**

  🟢 修正後的標準更誠實：**e2e 一條不改**（它跑真的瀏覽器，驗的是產品行為），
  而單元測試改成**注入一個記憶體實作**——它們因此不再依賴全域，
  ⚠️ **那是變好，不是妥協**。
- **SC-003**: 護欄的注入測試：注入一行 → 紅並指出檔案與行號
- **SC-004**: 記憶體實作走完一輪存／讀／刪／換實例，行為與宣告相符
- **SC-005**: VSCode 那側**仍然零個**存放實作（它不該因為這一刀多出工作）

## Assumptions

- **A-001**: 埠的形狀是**鍵值**，不是路徑樹。
  🔴 **理由**：今天的消費者是兩把扁平的鑰匙。路徑樹是為了**多檔案**，
  而那不在這一刀——憲章 I：「不得為假設性未來需求預留擴充」。
  ⚠️ 而多檔案來的那天，路徑就是一種鑰匙——這個形狀擋不到它。
- **A-002**: 既有的服務**用建構子注入**，不傳就是瀏覽器本地那個。
  🔴 **理由**：那讓既有的每一個呼叫點一行都不用改
  ——而「零行為變化」正是靠**不改呼叫點**才驗得出來。
- **A-003**: 「列出鑰匙」**不做**。今天零個消費者，而 FR 裡沒有它。
  ⚠️ 驗收原文寫著「讀／寫／刪／列」，而這一刀**刻意少一個**
  ——見 Out of Scope 的理由。

---

## Out of Scope

- **File System Access API 的實作**（驗收原文裡的「原生」那一個）
  ——它需要**使用者手勢**才叫得起來，而那讓端對端測試驗不到它。
  🔴 一個驗不到的實作與一個不存在的實作，在 CI 上長得一樣。
- **「列出鑰匙」那個操作**——零個消費者。
  > **一個埠上的操作如果沒有人叫它，它記的不是能力，是想像。**
- 多檔案 · side-car 檔案化 · 匯出 zip · `semorphe-state` 的資料遷移
  （那是這一項底下**另外幾條**驗收）
- 進度（`semorphe-progress`）的**格式**——這一刀只換它走哪條路
