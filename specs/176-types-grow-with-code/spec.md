# Feature Specification: 型別的下拉要跟著程式長

**Feature Branch**: `176-types-grow-with-code`
**Created**: 2026-09-06
**Status**: ✅ Implemented（2026-09-06）
**Input**: vision「開放值域的欄位要寫得出來」（2026-08-24 升格，使用者回報 `int**` 選不到）
**最後一條**未做的驗收，逐字：

> 驗收：選項跟著程式長——用過的型別會出現在其他積木的下拉裡
> （**導出的，不是宣告的**）

同一項的其餘三條都已兌現。

---

## 這一刀在解什麼

學生寫了一個自己的型別，然後**在下拉裡找不到它**。

實測（探針）：

```
程式：  struct Point { int x; int y; };  Point p;  unsigned int n = 5;
樹上：  Point | int | unsigned int
下拉：  int float double char bool string "long long"     🔴 少了兩個
```

⚠️ **而它不是一個正確性的 bug**：那個型別**打字寫得出來**
（`dynamic-dropdown-field` 早就「認不得的值不會被換掉」）。
壞的是**可發現性**——他知道自己宣告過 `Point`，而系統的清單不知道。

> **一份「這個欄位可以填什麼」的清單，如果它是宣告的而不是導出的，
> 那它描述的是【我們想到的】，不是【這支程式裡有的】。**

🟢 而機制**早就在了**：那份清單收的是一支函式（每次開下拉都重算），
而「掃出現在看得到什麼」有現成的先例——spec 149「名字的範圍」
做的正是同一件事，只是它掃的是**變數名**不是**型別名**。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 我宣告過的型別，我選得到 (Priority: P1)

學生寫了 `struct Point { … };`，然後拉一顆變數宣告積木
——`Point` **在型別的下拉裡**。

**Why this priority**: 這是那條驗收的全部，而它是使用者回報過的那一族
（`int**` 選不到）的最後一格。

**Independent Test**: 放一段用了自訂型別的程式，開那個下拉，看清單。

**Acceptance Scenarios**:

1. **Given** 程式裡有 `struct Point { … }; Point p;`，
   **When** 打開變數宣告的型別下拉，**Then** `Point` 在裡面
2. **Given** 程式裡有 `unsigned int n = 5;`，**When** 同上，
   **Then** `unsigned int` 在裡面
3. **Given** 回傳型別與參數型別的下拉，**When** 同上，**Then** 也看得到

### User Story 2 - 而內建的那幾個一個都不動 (Priority: P1)

沒有用過任何自訂型別時，下拉**逐字等於**今天那七個，**順序也一樣**。

**Why this priority**: 🔴 課程在依賴那個順序（第一個是 `int`）。
而一個「把清單重排」的改動會讓 66 課的截圖與說明全部對不上。

> **一份清單的順序，在有人照著它寫教材之後就是介面的一部分。**

**Acceptance Scenarios**:

1. **Given** 一支只用內建型別的程式，**When** 打開下拉，
   **Then** 逐字等於今天那七個，順序相同
2. **Given** 程式用了自訂型別，**When** 打開下拉，
   **Then** 內建那幾個**仍在原來的位置**，自訂的排在後面

### Edge Cases

- 🔴 **學生打錯字**（`itn x;`）：那個錯字會不會進下拉？見 Assumptions A-001
- **同一個型別用了很多次**：只出現一次
- **空程式／還沒同步**：下拉**等於內建清單**，不得是空的
- ⚠️ **從標頭來的型別**（`std::vector`）：**不在本項**——那要真的解析 `#include`
- 🔴 **容器與指標的 `type` 是【元素型別】，不是整串**（2026-09-06 量到）：

  ```
  vector<int> v;   → cpp:vector_declare 的 type 是 "int"
  int* p;          → cpp:pointer_declare 的 type 是 "int"
  ```

  ⚠️ **那是對的**（元件的身分本身帶著「它是容器／指標」），
  而它的後果是：**掃 `type` 拿不到 `vector<int>` 這種整串的型別名**。

  > **一個「用過哪些型別」的掃描，掃到的是【元素】而不是【容器】
  > ——因為容器那一層的資訊住在身分裡，不在屬性裡。**

  🟢 **這一刀接受那個界線**：它要解的是「自訂型別選不到」，
  而 `vector<int>` 有它自己的積木（`cpp:vector_declare`）。
  ⚠️ 而那條界線要**被釘住**，不然下一個人會以為掃描漏了東西

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 能從**現在這支程式的語義結構**列出用過的型別
- **FR-002**: 型別的下拉 MUST 是「內建清單 ∪ 程式裡用過的」
- **FR-003**: 內建的那幾個 MUST 保持原來的**順序與位置**
- **FR-004**: 用過的型別 MUST 排在內建的後面，且**不重複**
- **FR-005**: 列舉 MUST 讀**語義結構**，不得重新解析程式碼字串
- **FR-006**: 空程式時下拉 MUST 等於內建清單
- **FR-007**: 列舉那一支 MUST NOT 知道任何特定語言的型別名

### Key Entities

- **用過的型別**：這支程式的語義結構裡，宣告節點所帶的型別名集合
- **內建清單**：語言自己宣告的那幾個。⚠️ 它**不是**核心的知識

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `struct Point { … }; Point p;` 之後，`Point` 在型別下拉裡
- **SC-002**: `unsigned int n = 5;` 之後，`unsigned int` 在型別下拉裡
- **SC-003**: 只用內建型別時，下拉**逐字等於**今天那七個（含順序）——零回歸
- **SC-004**: 三個型別下拉（變數／回傳／參數）**都**跟著長
- **SC-005**: 列舉那一支所在的地方，**語言的型別名出現次數 = 0**
- **SC-006**: 護欄驗它讀的是語義結構——⚠️ **重新解析程式碼會是第二個真相**

---

## Assumptions

- **A-001**: 打錯字的型別（`itn`）**照樣進下拉**。
  🔴 **理由**：系統**分不出**「打錯字」與「還沒宣告的自訂型別」，
  而猜錯的代價**不對稱**：
  ```
  漏掉一個真的型別   學生選不到 → 那正是今天的 bug
  多一個錯字         多一列
  ```
- **A-002**: 列舉住在**核心**，而內建清單留在語言那一側。
  🔴 **理由**：「一棵樹上用過哪些型別」是核心問得出來的問題；
  「C++ 的內建型別有哪些」不是。
- **A-003**: 每次打開下拉都重算，不快取。
  ⚠️ 那個成本**已經被接受過**——變數名那份先例就是這樣做的。

---

## Out of Scope

- **型別積木**（`int` ＋ `*` ＋ `*` 那種組合式的）——vision 明說「不在本項」，
  它屬於指標與參考 UX
- **從標頭匯入的型別**——要真的解析 `#include`，是另一刀
- 其他語言
- ⚠️ **不做「猜學生想打什麼」**——見 A-001。
  > **一個會替使用者修正錯字的清單，會在它猜錯的時候把真的東西藏起來。**
