# Feature Specification: vector 的運算式初始值，以及那個從來不是 flake 的紅

**Feature Branch**: `096-vector-source-init` ｜ **Created**: 2026-08-07

## 為什麼做這個

缺陷帳裡三支 `[UNSUPPORTED:vector 的初始化列表語法尚無對應概念]`。
照慣例先量再信標籤——**三支沒有一支的標籤可以直接相信**：

| 支 | 標籤說的 | 實測 |
|---|---|---|
| fuzz_5 | 初始化列表尚無對應概念 | **過期**——094 早就做了，直接開回來就綠 |
| fuzz_9 | 同上 | **過期**——同上 |
| fuzz_1 | 同上 | **方向錯**——列表支援了，掉的是**函式呼叫**當初始值 |

照 fuzz_1 的標籤走，會去改一段已經正確的程式碼，而真正的缺口原封不動。

## 一、`vector<T> v = <運算式>`

`vector<string> words = splitWords(sentence)` 的初始值被丟掉：變數宣告成空的、
**產回去的程式碼也少了那一段**，於是來回轉換比對「成功」。只有真的跑起來
（索引越界）才會露出來。

五路：概念加 `source` 子節點（`min:0, max:1`）／辨識掛上去／產生器產回去／
執行器求值後接管內容（**複製，不共用**）。

叫 `source` 而不是 `init`：`children.init` 是 `children.initializer` 的子字串，
那個陷阱這個專案踩過。

### 範圍被一條紅擋住，而那條紅是對的

第一版對**所有**容器都掛 `source`，`roundtrip-cpp-utility` 立刻變紅——
`cpp_pair_declare` 的 `children` 是空的，收到一個未宣告的子節點。

那條紅是**既有缺陷被照出來**：`pair<int,string> p = make_pair(…)` 的初始值
本來就掉了，只是掉得**對稱**（辨識掉、產生也掉），所以來回轉換一直是綠的。

沒有一起修——`cpp_pair_declare` 標著 `skipPaths: ['execute']`（理由
「declarative」），接上初始值要連執行那一路一起做，那是另一個功能。
改成**從 JSON 讀哪些概念宣告了 `source`**，並用 `it.fails` 把 pair 那筆釘住：
缺陷還在＝綠且出聲，修好了＝紅並提醒拔釘子。用 `it.todo` 只會留下一個名字。

## 二、那個「已知的載入敏感 flake」不是 flake

`fuzz-cpp-*` 兩三個檔隨機變紅、單獨跑又全綠——這個解釋在這一輪被用過很多次。

實測：單次 `g++` 編譯 0.77 秒，每支測試編**兩次**（原始碼與產回去的程式碼），
而 vitest 預設逾時是 **5 秒**，全套並行時十個 worker 同時搶 CPU。

**它不是 flaky 的邏輯，是設太短的逾時。** 放寬到 60 秒之後，全套連兩次
**211 檔全綠、零 FAIL**——那是這一輪第一次真正的全綠。

先試 20 秒，仍逾時兩支；**量過才知道 60，不是猜的**。

放寬不會讓真的卡住逃掉：直譯器有 maxSteps 上限，執行產物那一步自己還有
5 秒 timeout。通過時這個數字不花任何時間。

> 每次「單獨跑就綠」的解釋，都讓下一次更容易略過真正的紅。

## Requirements

- **FR-001**: `cpp_vector_declare` MUST 接受一個運算式當初始值，掛在 `source`
- **FR-002**: 初始值 MUST 產得回去，且無初始值時 MUST NOT 多出 `=`
- **FR-003**: 執行時 MUST **複製**來源的內容，不得與來源共用同一個陣列
- **FR-004**: `source` MUST 只掛給**在 JSON 裡宣告了它**的概念——不得寫死清單
- **FR-005**: 元素列表 MUST 仍走 `values`；`vector<int> v(5)` 兩者 MUST 皆空
- **FR-006**: pair 的同型缺陷 MUST 用 `it.fails` 釘住，MUST NOT 只留註解
- **FR-007**: 期望值 MUST 由真的 `g++ -std=c++17` 決定
- **FR-008**: 逾時 MUST 依實測設定，MUST NOT 靠「單獨跑就綠」解釋紅

## Success Criteria

- **SC-001**: `vector-source-init.test.ts` 八支全綠（含四支負向、一支 `it.fails`）
- **SC-002**: 三支停用測試全部開回來，**測試本體一個字都沒改**
- **SC-003**: 停用測試 34 → 31，有測試本體 21 → 18
- **SC-004**: 全套 **211 檔全綠、零 FAIL**，連跑兩次一致
