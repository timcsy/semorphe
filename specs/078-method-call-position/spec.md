# Feature Specification: 方法呼叫的位置決定身分

**Feature Branch**: `078-method-call-position` ｜ **Created**: 2026-08-06

## 為什麼做這個

`x.f();` 單獨一行是**敘述**，`int a = x.f();` 裡的是**運算式**。系統有兩個概念
分別對應，而辨識器**永遠產出運算式版**——敘述位置的身分永遠拿不到。

後果不是「跑不動」（運算式版在敘述位置也執行得了），是**身分掉了**：
使用者拖一個「呼叫方法」的敘述積木、存檔、讀回來，它變成一個運算式積木。

而測試檔裡有一句標著 `architectural` 的註解說「辨識器產出的是運算式版」
——**同一天第二個把「還沒做」寫成「架構上如此」的標籤**。

## 判準來自語法樹，不用猜

呼叫節點的父節點是 `expression_statement` 就是敘述位置。

## Requirements

- **FR-001**: 敘述位置 MUST 得到敘述身分
- **FR-002**: 運算式位置 MUST 得到運算式身分——**只釘一個方向的話，「永遠回敘述版」也會過**
- **FR-003**: 已有專屬身分的容器／字串方法 MUST NOT 受影響
- **FR-004**: 那句假的 `architectural` 註解 MUST 更正

## Success Criteria

- **SC-001**: 四個方向各有測試（敘述／運算式／巢狀運算式／專屬身分不受影響）
- **SC-002**: 既有測試全數通過

## ⚠️ 殼的總數沒有下降，而那不是原地踏步

殼從 `cpp_method_call` **換到** `cpp_method_call_expr`，總數維持 7。

換掉的是兩種**性質不同**的東西：

| | 性質 |
|---|---|
| `cpp_method_call`（修掉的） | **真缺陷**——使用者存檔讀回來，積木會換一個 |
| `cpp_method_call_expr`（新出現的） | **量測假象**——合成器餵給辨識的輸入是產生器的輸出，而運算式版產出的是裸運算式，它不能單獨成立 |

**用真缺陷換量測假象是嚴格的改善，即使數字沒動。** 這一點寫進了基線的註記，
否則下一個人看到「7 → 7」會以為什麼都沒發生。

## 順帶發現：兩支測試斷言同一件事

`cpp_method_call` 與 `cpp_method_call_expr` 的身分測試**用完全相同的樣本**
（都是敘述位置）——也就是說運算式位置**從來沒有被測到**，而兩支測試看起來
像涵蓋了兩種情形。
