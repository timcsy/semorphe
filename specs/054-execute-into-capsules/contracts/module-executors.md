# 介面契約：模組的執行路

**消費者**：語言套件載入流程、核心執行引擎

---

## 模組提供

```ts
registerExecutors(register: (concept: string, executor: ConceptExecutor) => void): void
```

與既有的 `registerGenerators` / `registerLifters` **同形**——模組提供一個註冊函式，載入時被呼叫。

**必填。** 沒有執行器的模組交一個空函式並註明原因。

---

## 核心提供

執行器註冊表不變（`register` / `get`），已在上一輪加上重複計數。

新增一個查詢：

```ts
/** 有沒有任何語言套件推過執行器——用來分辨「概念未知」與「語言套件沒載入」 */
hasAnyExecutor(): boolean
```

---

## 行為契約

| 情況 | 行為 | 與現況 |
|---|---|---|
| 概念有執行器 | 執行 | **相同** |
| 概念宣告了刻意不執行 | 跳過 | **相同** |
| 概念未知，**且註冊表非空** | 回報未知概念 | **相同** |
| 概念未知，**且註冊表是空的** | 回報未知概念 **＋「可能是沒有載入語言套件」** | 新增 |

**前三列一字不改。** 第四列是現況錯誤訊息的補充，不是新的拒絕。

---

## 驗收契約

| 斷言 | 為什麼是這個形狀 |
|---|---|
| 搬移前後，執行引擎認得的概念集合**完全相同** | 漏一個就現形；輸出比對漏一個不會現形 |
| 集合**不得多**出來 | 多出來 = 重複註冊 |
| 五路完備性的執行欄「缺」未增加 | 對漏失最敏感的既有量測 |
| 語言中立性下降，且**下降可歸因到具體概念** | 只說「數字變小」等於沒說 |

**這一步不加嚴、不拒絕任何東西**，所以不需要回答「被拒絕的東西去哪了」。真正的風險是**無聲漏失**，主防線因此是集合比對。
