## User Scenarios & Testing *(mandatory)*

### User Story 1 - 學生在他已經在的地方看到積木 (Priority: P1)

一個學生已經在用 Arduino IDE 寫程式。他裝上這個擴充、重開 IDE，
**側邊多了一個面板，裡面有積木**。

**Why this priority**: 這是整個階段 6.13 的意義 ——
**不是多支援一個平台，是搬進他已經在的地方**。而燒錄與序列埠**本來就在**。

**Independent Test**: `.vsix` 丟進 `~/.arduinoIDE/plugins` → 重開 → 面板打得開、有一顆積木。

**Acceptance Scenarios**:

1. **Given** 一個裝了 Arduino IDE 的機器，**When** 把產出的 `.vsix` 放進
   `~/.arduinoIDE/plugins` 並重開，**Then** 擴充**載入了**（面板出現在介面上）。
2. **Given** 面板打開了，**When** 看畫布，**Then** 上面有**一顆積木**。
3. **Given** 那顆積木，**When** 問它是什麼，**Then** 🔴 **它是一顆真的 Semorphe 概念**
   ——說得出是哪一顆，而**不是一顆手寫的假積木**。

---

### User Story 2 - 而它要跑得順，不只是畫得出來 (Priority: P1)

學生拖那顆積木、縮放畫布 —— **它要跟得上手**。

**Why this priority**: 🔴 **這一條才是這一刀真正要否證的東西。**
一顆畫得出來而拖起來會頓的積木，等於這條路不通。

**Independent Test**: 拖一顆積木橫跨畫布、縮放兩次 —— 說得出「順不順」的**判準**。

**Acceptance Scenarios**:

1. **Given** 畫布上有積木，**When** 拖曳它，**Then** 它跟著游標移動而**不掉格**。
2. **Given** 畫布，**When** 縮放，**Then** 畫面重繪而**不留殘影**。
3. 🔴 **Given** 要回答「順不順」，**When** 寫下結論，**Then** 必須附上**判準**
   ——⚠️ 「看起來還好」**不算**。

---

### User Story 3 - 而網頁版一個字都不能退步 (Priority: P1)

**Why this priority**: 這個專案付過「兩條產出路徑」的學費
（`history/072`：`c-style-parity` 10/10 全綠，**而瀏覽器上仍然產出 `<iostream>`**）。
**加一個宿主最容易的失敗方式，是讓既有的那個安靜地壞掉。**

**Acceptance Scenarios**:

1. **Given** 擴充加進來了，**When** 跑全套，**Then** 現況 **4283** 全綠。
2. **Given** 同上，**When** 看護欄，**Then** **47 條基線一個數字都不動**、中立性 `total` 仍是 0。
3. **Given** 同上，**When** 跑典型 Arduino 探針，**Then** 殘差 **0.07%**、漂移 **0/20** 不變。

---

### Edge Cases

- **Arduino IDE 沒裝** → 那是**環境問題**，不是失敗。要說得出是哪一種。
- **擴充載入了而面板打不開** → 那是**一個發現**，要記下 Arduino IDE 的錯誤訊息。
- ⚠️ **畫布載得起來而拖起來會頓** → 🔴 **那是這一刀最重要的產出**，見 SC-007。
- **Blockly 的資源被 CSP 擋掉** → 記下實際的 CSP 錯誤，不要猜。
- ⚠️ **同一份程式碼在 VSCode 裡好、在 Arduino IDE 裡壞** → **兩邊都要記**，
  因為那會決定「宿主獨立性」這個閘門要驗幾個宿主。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 專案 MUST 產得出一個可安裝的擴充封包。
- **FR-002**: 擴充 MUST 在 Arduino IDE 裡提供一個**看得到的面板**。
- **FR-003**: 面板 MUST 顯示一個積木畫布，而畫布上 MUST 有**至少一顆積木**。
- **FR-004**: 🔴 那顆積木的定義 MUST **來自專案既有的積木登錄表**
  ——⚠️ **手寫一顆假的不算**：那樣這一刀證明不了「核搬得過去」。
- **FR-005**: 擴充的原始碼 MUST 放在**既有護欄掃得到的位置**。
  - 理由：「一條檢查如果自己維護一份『要看哪些檔』的清單，那份清單就是它的盲點」
    ——而本專案 2026-08-17 才因此付過一次。
- **FR-006**: 既有的網頁版 MUST NOT 有任何行為改變。
- **FR-007**: 型別檢查 MUST 涵蓋新增的擴充程式碼（不得靠排除它來過關）。

### Key Entities

- **擴充封包**：可以被 Arduino IDE 安裝的一個檔案。
- **面板**：宿主介面裡的一塊區域，我們的畫布住在裡面。
- **積木登錄表**：專案既有的「哪些概念長什麼樣」的唯一真相
  ——🔴 **這一刀要證明的正是「它到得了那個面板」**。

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 產出**一個**可安裝的擴充封包（今天是 0 個）。
- **SC-002**: 在**真的 Arduino IDE** 裡，面板打得開 —— **是／否**，而不是「應該可以」。
- **SC-003**: 畫布上的積木數 **≥ 1**，而它的概念身分**說得出來**。
- **SC-004**: 🔴 「畫布順不順」有一個**寫得出來的判準**與一個結論。
- **SC-005**: 既有測試 **4283** 全綠；**47 條護欄基線 0 個變動**；中立性違規 **0**。
- **SC-006**: 典型 Arduino 探針：殘差 **0.07%**、漂移 **0/20** —— **不得退步**。
- **SC-007**: 🔴 **而如果畫布跑不動，這一刀【仍然成功】** ——
  條件是：**如實記下來，並且不換一個更弱的驗收**。
  > **一個「不做就繞不過去」的否證，與一個「做到了」的交付，價值一樣。**

## 🟢 驗證順序（2026-08-17 使用者補充，**放寬了一步**）

使用者逐字：

> 「**ArduinoIDE 可以先用 VSCode Extension 測試就可以**」

```
第一段   VSCode          門檻低、裝得上、CSP 與 Webview 是 VSCode 的原生行為
第二段   Arduino IDE     🔴 而它才是這一刀的目的地（Theia，不是 VSCode）
```

⚠️ **這不是把 SC-002 換掉，是把它拆成兩段。**
第一段過了而第二段沒過，那本身就是一個發現
——`history/080`§五 逐字：「Theia 的 Webview 與 VSCode 的差異**沒有逐項比對過**」。

> **兩段都要記。因為「VSCode 好、Arduino IDE 壞」會決定
> 「宿主獨立性」這個閘門到底要驗幾個宿主。**

**查證的環境**（2026-08-17）：

```
/Applications/Visual Studio Code.app   ✅
~/.vscode/extensions/                  ✅
~/.arduinoIDE/                         ✅
```

## Assumptions

- Arduino IDE 已安裝在驗證的機器上（`~/.arduinoIDE/` 存在 —— 2026-08-17 查證過）。
- VSCode 也已安裝（同日查證）——🟢 **而它是第一段的驗證目標**。
- 擴充的安裝方式是「把封包放進 `plugins` 資料夾後重開」——
  使用者**已經用這條路出貨過兩個擴充**。
- 「一顆積木」用哪一顆不重要，**而它必須來自登錄表**。
- ⚠️ 效能判準沒有既有基準；本輪**建立第一個**，而它是探測不是護欄。

## 明確排除（防蔓延）

- 🔴 **雙向同步**、寫回檔案、讀 `.ino` 的內容 —— **一個字都不做**
- 🔴 **per-document 的分類落地** —— draft 分好的那 18 個欄位**本輪一個都不動**
- 程式碼面板那 21 處的處置（VSCode 裡它是**零份**，被原生編輯器取代）
- 工具箱、執行、診斷、多文件、發佈到任何市集
