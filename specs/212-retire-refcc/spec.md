# Feature Specification: 參照編譯器族退場（重構 6c-5）

**Feature Branch**: `256-retire-refcc`
**Created**: 2026-11-04
**Status**: Draft
**Input**: 重構 6c-5：參照編譯器族退場。6c-4 已刪 JS 直譯器（history/335），執行與判對錯只走 Cella；而 `npm test` 裡還有 21 支測試即時呼叫參照編譯器（g++／clang）。

## 背景

〈重構〉第 6 項的第五刀。參照編譯器族當初是用來檢查**我們的 JS 直譯器**的——它跑出來的東西要和真的編譯器一樣。直譯器刪掉之後，這一族有三種下場：

| 一支測試拿參照編譯器做什麼 | 數量（2026-11-04 盤點） | 下場 |
|---|---|---|
| 唯一的判準（期望輸出由 g++ 算出） | 5 支（stacks-queues、strings、time、macros、roundtrip-time） | 判準換成 Cella |
| Cella 對參照編譯器的交叉檢查（6c-2 留下來的） | 12 支 | 拿掉參照那一半，Cella 背書照舊 |
| 護欄族（量參照編譯器自己或它的用法） | 4 支 ＋ 1 支探針 | 依它實際守的東西：改量 Cella，或退場 |

代價是實際付過的：CI 與本機的編譯器不同造成過三次 CI 紅（history/251、262）；本機要一個標頭墊片才跑得起來，忘了設就大批假紅；逾時被殺掉的參照程式卡在核心狀態裡累積，曾讓 e2e 假紅（CLAUDE.md）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 開發者跑全套不再需要參照編譯器（Priority: P1）

開發者在任何一台機器上跑 `npm test`，不需要裝 C++ 編譯器、不需要設墊片環境變數；結果與 CI 一致。

**Why this priority**: 這是整刀的目的——判準只剩一個（Cella），本機與 CI 不再因為「是哪一台編譯器」而分岔。

**Independent Test**: 在一個沒有設墊片環境變數的 shell 跑全套，結果與設了的時候相同；一條護欄數出測試目錄裡（探針以外）零個檔呼叫參照編譯器。

**Acceptance Scenarios**:

1. **Given** 只用參照編譯器當判準的 5 支測試，**When** 改寫完成，**Then** 每一條原本的斷言都改由 Cella 背書（同一份程式、同一個期望輸出），沒有一條被刪掉而沒有說明。
2. **Given** 交叉檢查的 12 支，**When** 拿掉參照那一半，**Then** Cella 那一半的斷言一條不少。
3. **Given** 有人在 `npm test` 範圍內新加一支呼叫參照編譯器的測試，**When** 跑護欄，**Then** 紅，訊息指出是哪一個檔。

---

### User Story 2 - 課文的答案仍然對得起真正的 C++（Priority: P1）

授課老師的回饋（2026-09-21）：「要幫每一課所有題目會遇到的練習都加入執行比對」。原本由「g++ 跑參考解答 vs 課文寫的預期輸出」那條護欄守；它退場之後，這件事要由 Cella 守，**而且要是斷言，不是印出來的報表**。

**Why this priority**: 這是學生看得到的東西；護欄退場而沒有接手的，就是一個安靜消失的保證。

**Independent Test**: 把某一課的預期輸出故意改錯一個字，全套紅，訊息指出是哪一課。

**Acceptance Scenarios**:

1. **Given** 課文判決語料（109 支），**When** 跑全套，**Then** 每一支 Cella 判 accept 且輸出與課文的預期輸出逐字相同；不同的要嘛修課文、要嘛以有理由的釘子留下。
2. **Given** 一支 Cella 判 unknown 或 reject 的課文答案，**When** 跑全套，**Then** 它被明列（不算通過、也不被跳過）。

---

### User Story 3 - 「我們翻錯而 Cella 照錯的程式判 accept」仍然量得到（Priority: P2）

參照編譯器族唯一不可取代的價值：它是**獨立於我們的翻譯**的第三方。我們的 formalize 若把程式翻錯，Cella 會照錯的那一份判 accept，而只有拿原始碼給真的編譯器跑才看得出來。

**Why this priority**: 不在 `npm test` 裡也不影響日常，但它是唯一抓得到這一類缺陷的量尺；丟掉它等於宣告這一類不存在。

**Independent Test**: 用環境變數開一支探針，拿課文與學生語料各跑「原始碼給 g++」與「formalize 給 Cella」，輸出不同的列出來。

**Acceptance Scenarios**:

1. **Given** 沒開環境變數，**When** 跑全套，**Then** 這支探針跳過、不呼叫編譯器。
2. **Given** 開了環境變數而機器上沒有編譯器，**When** 跑它，**Then** 紅並說明缺什麼（不是安靜跳過）。

---

### Edge Cases

- 某條斷言的期望輸出是「g++ 當場算出來的」而不是寫死的字串：改寫時要把那個值固定下來（從 Cella 跑出來、並確認與當初 g++ 的一致），不能讓斷言變成「Cella 跑什麼都對」。
- 交叉檢查裡有幾條是 `knownCellaGap`（Cella 那側的已知缺陷）：參照那一半拿掉後，釘子的原因句子不變，修好時照樣會紅。
- 缺陷帳裡釘的是「直譯器或參照編譯器自己」的缺陷（例如本機與 CI 的編譯器差異）：那些釘子隨之刪除，並在基線 note 寫明。
- 依未指定行為的斷言（例如 NaN 的正負號）：Cella 的輸出依它宣告的假設（`assumes`），斷言要對齊假設，不是對齊某一台編譯器。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `npm test` 範圍內（測試目錄扣掉探針）**零個檔**呼叫參照編譯器；一條硬性零的護欄守著，含注入測試。
- **FR-002**: 只用參照編譯器當判準的測試，每一條斷言改由 Cella 背書；期望輸出寫死成字串（與當初參照編譯器的輸出一致的才寫，不一致的逐條判是誰的錯）。
- **FR-003**: 交叉檢查的測試拿掉參照那一半，Cella 那一半一條不少。
- **FR-004**: 課文答案 vs 課文預期輸出的比對改由 Cella 做，而且是**斷言**（硬性零或附理由的釘子），取代「g++ 跑課文答案」那條護欄。
- **FR-005**: 量參照編譯器自己的護欄（標頭不得手列、參照程式不得留孤兒、消毒器判定的錨點）隨參照編譯器的輔助一起退場；退場前確認它們沒有守著別的東西。
- **FR-006**: 保留一支 `npm test` 外的探針：同一份程式「原始碼給參照編譯器」對「formalize 給 Cella」，輸出不同的列出；環境變數開啟；開了而沒有編譯器時紅並說明。
- **FR-007**: CLAUDE.md 標 🪦 的三段改寫：操作（墊片、並行度、指令）刪掉，教訓的指名留著（指到 experience）；「什麼時候跑什麼」那張表裡依賴參照編譯器的列一起改。
- **FR-008**: CI 不再依賴參照編譯器：workflow 與文件裡的墊片設定拿掉；長測試腳本不再需要墊片環境變數。
- **FR-009**: 每一份動到的基線 note 寫明「6c-5：參照編譯器族退場」與數字的來由（語料變了，還是缺陷真的不見了）。

### Key Entities

- **判準（oracle）**：一條斷言的期望值從哪裡來。退場後只剩兩種：寫死的字串（人或 Cella 算出、人看過的）與 Cella 的判決。
- **交叉檢查探針**：npm test 外、環境變數開啟的量尺；量的是「我們的翻譯」而不是 Cella。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `npm test` 範圍內呼叫參照編譯器的檔數：21 → 0。
- **SC-002**: 在沒有墊片環境變數的 shell 跑全套，結果與 CI 相同（全綠）。
- **SC-003**: 課文 109 支的「Cella 輸出 vs 課文預期」比對由斷言守著；故意改錯一個字會紅。
- **SC-004**: 被改寫的斷言條數與改寫前相同（逐檔數得出來），沒有安靜消失的斷言。
- **SC-005**: 全套時間記錄並與 6c-4 之後的 14.8 分鐘對照。
- **SC-006**: CI（Deploy、Extension）合併後綠。

## Assumptions

- Cella 是判準：它自己對 clang 做差分測試（cella 那側的責任），所以「Cella 背書」等價於「對得起 C++ 標準」，未指定行為以它的 `assumes` 為準。
- 參照編譯器的輔助（`tests/helpers/run-cpp.ts`）只留給 FR-006 的探針；探針放在 `tests/probes/`，預設跳過。
- CI 的 runner 本來就有 g++（workflow 沒有另外安裝），所以 FR-008 是拿掉「依賴」與墊片設定，不是拿掉安裝步驟。
- 交叉檢查的 12 支在 6c-2 已經改由 Cella 背書，參照那一半拿掉不會降低它們對 semorphe 的覆蓋。
