## 出發點：一個查到的事實，不是一個計畫

```
grep -rn "targetRegistry|TargetRegistry" src e2e
→ src/core/target-registry.ts:13   （它自己）
→ 其餘 0 筆
```

上一刀交付的 `TargetRegistry` 與 `targets/{c,cpp}.json`，**產品消費者是零**。
唯一 import 它們的是 `tests/unit/target.test.ts`。
而 `e2e/c-target.spec.ts:48` 選的是**風格下拉選單**（`/C 風格|C Style/`），不是目標。

> `knowledge/concepts/執行機構.md:527` 逐字：
> **「建一個機制不等於它在運作。」**

那一節列了「機制有了，沒人接上」的**十個實例**（`:522`）。
🔴 **目標是第十一個，而它是現在進行式。**

⚠️ vision `:612` 說的「差一點發生」講的是**風格** `styles/c.json`
——那句話是對的，風格確實接上了選單。**而目標自己沒有。**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師選一次，而不是三次 (Priority: P1)

一位要教 C 語言的老師打開系統。他想要的是「**教 C**」，
而不是「課程清單選 X、風格選 Y、之後還要記得兩者要配對」。

**Why this priority**: 這是目標這個機制**存在的理由**。
沒有它，使用者要自己維護一份「哪些組合是合理的」的心智模型
——而那份模型今天只存在於使用者的腦袋裡。

**Independent Test**: 打開系統 → 在**一個**選單裡選「C 語言教學」
→ 課程清單與產出風格**同時**切換，不需要第二次操作。

**Acceptance Scenarios**:

1. **Given** 系統剛開啟（預設是 C++），**When** 使用者選「C 語言教學」，
   **Then** 產出的程式碼是 C（無 `iostream`／無 `using namespace`），
   **且**工具箱同時換成 C 的課程清單——**兩件事由一次選擇造成**。
2. **Given** 使用者選了「C 語言教學」，**When** 重新整理頁面，
   **Then** 仍然是「C 語言教學」（選擇被保存）。
3. **Given** 使用者選回「C++（預設）」，**When** 檢視產出，
   **Then** 與本功能之前的 C++ 產出**逐字相同**——🔴 C++ 不得退步。

---

### User Story 2 - C 裡不存在的東西，看不到 (Priority: P1)

一位剛學 C 的學生打開工具箱。他**不應該**看到 `cout`、`vector`、`string`
——那些東西在 C 裡**不存在**，看到它們只會讓他寫出編不過的程式。

**Why this priority**: 這是「選一次而不是三次」真正兌現的那三分之二。
🔴 上一刀的兩筆目標**指向同一個課程清單**，所以只省了選風格那一次。

**Independent Test**: 選「C 語言教學」→ 工具箱裡找不到 `cout`／`vector`；
選「C++（預設）」→ 找得到。

**Acceptance Scenarios**:

1. **Given** 選了「C 語言教學」，**When** 展開工具箱，
   **Then** 找不到任何**在 C 裡不存在**的概念。
2. **Given** 選了「C 語言教學」，**When** 拉一個「印出一句話」積木，
   **Then** 它產出 `printf`，而**不是**一個學生拿不到的東西。
3. **Given** 兩份課程清單，**When** 比較它們的概念集合，
   **Then** 🔴 **兩者不同**——相同的話這一刀又只兌現三分之一。

---

### User Story 3 - 下一個機制不會再躺一年 (Priority: P2)

未來某個人建了一個新的登錄表，交付當天測試全綠、文件寫得很清楚，
**而沒有任何產品程式碼呼叫它**。今天沒有任何東西會出聲。

**Why this priority**: `執行機構.md:539` 逐字：

> 「建一個唯一真相的機制時，同時交付**遷移**與**一條量採用率的護欄**。
> 既有的護欄問的都是『東西對不對』，**沒有一條問過『機制有沒有人用』**。」

⚠️ **那句話寫下之後又被撞了三次，而護欄始終沒蓋。** 本輪蓋它。

**Independent Test**: 把目標接上選單的那一行拿掉 → 護欄變紅並**指名**
`TargetRegistry`；接回去 → 綠。

**Acceptance Scenarios**:

1. **Given** 一個沒有產品消費者的登錄表，**When** 跑護欄，
   **Then** 它**變紅並指名**是哪一個。
2. **Given** 全部登錄表都有消費者，**When** 跑護欄，**Then** 綠。
3. **Given** 掃描找不到任何登錄表（工具壞了），**When** 跑護欄，
   **Then** 🔴 它**變紅**——空清單與零違規不得產出相同結果。

---

### Edge Cases

- **保存的選擇指向一個不存在的目標**（例如改名之後）→
  回退到預設目標，**而不是崩潰或空白畫面**。
- **保存的是舊格式**（只有課程清單 ID／只有風格 ID，本功能之前的存檔）→
  ⚠️ 必須仍然打得開。P8「不做向後相容」的範圍**不含存檔遷移**
  （見 `history/026`）。
- **一個目標指向不存在的課程清單或風格** → 登錄時就要出聲，不得靜默。
- **競賽課程清單**（`cpp-competitive`）今天沒有對應的目標 →
  ⚠️ 它不能因為本功能而**消失**（否則這是一個功能倒退）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓使用者用**單一一次選擇**同時決定課程清單與產出風格。
- **FR-002**: 使用者的選擇 MUST 被保存，重新整理後仍然生效。
- **FR-003**: 選擇一個目標 MUST 同時改變**工具箱可見的概念**與**產出的程式碼形狀**。
- **FR-004**: 系統 MUST 提供一份 C 專屬的課程清單，其中**不含**在 C 裡不存在的概念。
- **FR-005**: 兩份課程清單的概念集合 MUST 不同。
- **FR-006**: 系統 MUST 有一個機械化的檢查，能指出「**存在但沒有產品消費者**」的登錄表；
  該檢查的容忍度 MUST 是**零**。
  - 理由（`build-guardrail` 6.8 的判準）：「留一筆在那裡，這條規範還成立嗎？」
    留一個沒人用的登錄表，「機制在運作」這句話就是假的。
- **FR-007**: 該檢查 MUST 有一個**入口條件**，錨在「掃到幾個登錄表」這個**合成量**上。
  - ⚠️ **不得**錨在「零消費者的登錄表數」——那正是要推向零的東西
    （`build-guardrail` 第 2 步簽名一：**斷言的數字若是這條護欄想推向零的，錨就錯了**）。
- **FR-008**: 核心層 MUST NOT 認識任何具體目標——目標資料由語言套件在載入時注入。
- **FR-009**: 既有存檔 MUST 仍然打得開；認不得的選擇回退到預設。
- **FR-010**: C++ 那一側的產出 MUST NOT 改變。

### Key Entities

- **目標（target）**：一個**具名的組合**，四個欄位【恰好】是兩個引用（課程清單、風格）
  ＋ 兩個標籤（id、name）。
  🔴 **它不是新的抽象層**——每個欄位都說得出「它今天住在哪裡」（spec 134 SC-005）。
  ⚠️ 完整設計還有 `provides`／`reference` 兩格，**本輪不做**。
- **課程清單（topic）**：哪些概念在這個目標下可見（`levelTree`）。本輪新增 C 的那一份。
- **風格（style）**：排版與慣用法。本輪**不新增**，只是被目標引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 從打開系統到「畫面上是 C」，使用者的選擇次數是 **1 次**
  （本功能之前：**3 次**，且需要知道哪些組合合理）。
- **SC-002**: 選了 C 之後，工具箱裡**在 C 裡不存在**的概念數量是 **0**。
- **SC-003**: 兩份課程清單的概念集合差異 **> 0**。
- **SC-004**: 沒有產品消費者的登錄表數量是 **0**（本功能之前：**1**）。
- **SC-005**: 🔴 那條檢查在**接上之前必須是紅的**，並**逐項指名**
  （`build-guardrail` 6.5：先跑、確認紅、逐項指名、修好，**最後才產基線**）。
- **SC-006**: C++ 側產出與本功能之前**逐字相同**。
- **SC-007**: 既有全套測試全綠（現況 **4201**），既有 **46 條**護欄基線
  **一個數字都不動**；中立性護欄 `total` 仍是 **0**。
- **SC-008**: 🔴 **在真的瀏覽器上驗過**——不是只有測試綠。
- **SC-009**: 使用者可見的選擇器數量 **沒有增加**。
  ⚠️ 這是**反目標**：目標的意義是把三個選擇**收起來**，不是多加一個。

## Assumptions

- 「在 C 裡不存在的概念」以 spec 134 research Q2 數過的 **13 種標頭**那一族為準；
  ⚠️ 而本輪要**重數一次**——那個 13 是標頭數，不是概念數。
- 兩個目標（C 與 C++）足以驗證這個機制；**Arduino 是第三個，不在本輪**。
- 「單一一次選擇」的呈現方式（下拉選單／其他）由實作決定；
  規格只要求**次數是 1** 且**選擇器總數不增加**。

## 明確排除（防蔓延）

- 🔴 **Arduino**——它是第三個目標，**而本輪正是它的前置**。
- **`provides` / `reference` 兩格**——它們的消費者是 Arduino，
  而本輪不需要它們就驗得出目標有沒有生效。
- **`io_style` / `ioStyle` 命名收斂**（draft §四②，獨立一筆）。
- **不動 `cpp-beginner` 的內容**。
- **不新增任何風格**。
