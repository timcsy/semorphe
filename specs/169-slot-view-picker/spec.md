# Feature Specification: 每個槽自己選視圖，而復原不屬於任何一個槽

**Feature Branch**: `169-slot-view-picker`

**Created**: 2026-09-01

**Status**: Draft

**Input**: 使用者逐字：「我覺得現在工具列的邏輯有點怪怪的，**為何復原按鈕只跟積木**？
然後我希望**每個面板可以去選擇要哪一種視圖**，而不是現在只能用 tab 切換積木跟流程」。

## 它要解決什麼

上一刀（spec 168）做出了**對稱的槽**——四個投影各有自己的格子，沒有一個是特別的。
而「槽裡放什麼」仍然是**版面寫死的**，於是留下兩個歪的東西：

```
① 復原（↩↪）住在【積木那一欄】的快速列裡
   而 `doUndo` 早就問 `lastEditor` 走三條路（程式碼／流程／積木）
   ⟹ 行為是全域的，位置是局部的
   🟢 行動版已經把它搬到全域標頭了——【桌機是那個例外】

② 「積木／流程」是一對互斥的分頁，而程式碼沒有分頁
   ⟹ 使用者想在某一格看流程、另一格看程式碼，做不到
```

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 每個槽自己選要看什麼 (Priority: P1)

使用者點任何一個槽上方的分頁列，選「程式碼／流程／積木」，那一格就換成那個視圖。
**每一個槽的選項完全一樣**——沒有哪一格「只能是某一種」。

**Why this priority**: 這是使用者直接要的東西，而它是「沒有任何投影是特別的」這條線的終點。

**Independent Test**: 在「對照」把右邊那一格從積木換成流程，左邊仍是程式碼。

**Acceptance Scenarios**:

1. **Given** 任何版面，**When** 看每一個可見的槽，**Then** 它們的分頁列**選項完全相同**
2. **Given** 「對照」（兩個槽），**When** 把右槽改成流程，**Then** 右槽顯示流程、左槽不變
3. **Given** 任何槽，**When** 選一個**已經在別的槽**的視圖，**Then** 兩個槽對調
   （不是複製一份——同一個視圖不得同時出現在兩個槽）

### User Story 2 - 復原到處都按得到 (Priority: P1)

不論使用者在哪個版面、哪個槽顯示什麼，↩↪ 都在**同一個地方**（全域標頭）。

**Why this priority**: 它今天會**跟著積木欄一起消失**——而復原是對整份程式的動作。

**Independent Test**: 四個版面逐一套用，↩↪ 每一次都看得見，且不在任何投影欄裡。

**Acceptance Scenarios**:

1. **Given** 四個版面的任何一個，**Then** ↩↪ 看得見
2. **Given** 任何版面，**Then** ↩↪ **不在** 程式碼／流程／積木任何一格裡面
3. **Given** 在程式碼裡打了字，**When** 按 ↩，**Then** 復原的是程式碼那一次編輯
   （行為與今天逐字相同——這一刀只搬位置）

### User Story 3 - 主控台叫得回來 (Priority: P2)

槽的內容變成使用者選的之後，主控台有可能被換掉。它**必須有一個永遠在的入口**把它叫回來。

**Why this priority**: 上一刀的 I4 靠「版面宣告裡一定有 state」保證主控台不會消失。
槽可自由指派之後那個保證站不住了，而「程式在講話的地方找不到」是退步。

**Independent Test**: 把每一個槽都改成非主控台，然後用那個入口把主控台叫回來。

**Acceptance Scenarios**:

1. **Given** 使用者把所有槽都指派成別的視圖，**Then** 仍然有一個看得見的入口叫回主控台
2. **Given** 程式在執行而主控台沒有被顯示，**Then** 輸出**不會遺失**（回來時看得到）

### Edge Cases

- **槽比視圖少**（「對照」兩個槽、四個視圖）：看不到的兩個不是「不存在」，是沒被指派。
- **槽比視圖多**：不會發生（四個槽、四個視圖，而同一個視圖最多一個槽）。
- **切換版面**：槽的數量變了，而上一個版面的指派要**記得**——切走再切回來不得變樣。
- **行動版**：單槽，分頁列就是今天的行動版分頁列。**本刀不改行動版。**

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：每一個可見的槽 MUST 有一條分頁列，而**所有槽的選項完全相同**。
- **FR-002**：同一個視圖 MUST NOT 同時出現在兩個槽。選一個已在別處的視圖 ⟹ **兩槽對調**。
- **FR-003**：版面宣告 MUST 只決定**幾個槽與槽的形狀**；每一格放什麼變成**預設指派**。
- **FR-004**：↩↪ MUST 在全域標頭，且 MUST NOT 住在任何一個投影的容器裡。
- **FR-005**：↩↪ 的**行為**不變（仍然依 `lastEditor` 走三條路）——這一刀只搬位置。
- **FR-006**：主控台 MUST 永遠叫得回來。
  🟢 **實作時發現這由結構保證**：每一格的下拉都列著全部四層，所以不管現在誰在哪，
  使用者永遠選得到主控台。🪦 因此**不加**狀態列那一顆——
  加了反而讓主控台變成「那個有特權的」，而這條線的起點就是要消滅特權。
- **FR-007**：切走版面再切回來，指派 MUST 不變。
  ⚠️ **跨重新載入不保證**——版面本身今天也不存（一致，不是遺漏）。
- **FR-008**：分頁列上的字 MUST 走 i18n，MUST NOT 把內部識別字印上畫面。

### 明確不做（Out of Scope）

- **自由 docking**（拖放面板換位子）——槽的**位置與數量**仍然由版面決定。
- **改「清空」的歸屬**——它今天是積木的動作，而那是對的。
- **行動版的分頁列**——行動版是單槽，今天就有分頁列。
- **同一個視圖開兩份**（左右都放程式碼）。

### Key Entities

- **槽（Slot）**：版面上的一個格子。有位置與形狀（版面決定），以及**現在顯示哪一層**（使用者決定）。
- **指派（Assignment）**：`版面 id → (槽 → 層)`。有預設值（來自版面宣告），可被使用者覆寫。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：四個版面裡，↩↪ 的可見率是 **100%**。
- **SC-002**：任何版面下，**每一個可見槽的分頁列選項集合完全相同**（差異為 0）。
- **SC-003**：把一個槽改成另一個視圖，**其餘槽的位置與大小位移為 0**。
- **SC-004**：主控台在任何指派下都叫得回來（**100%**）。
- **SC-005**：切走版面再切回來，指派與離開時**完全相同**。

## Assumptions

🔴 **這五條是我取的預設值，而其中前兩條動到既有的規範——你一句話就可以改。**

1. **I3 降級**：左右從「語義」變成「**預設**是語義」。使用者可以把積木放左邊。
   ⚠️ 這是這一刀的代價，而它與這條線的起點一致（「不准使用者換」本身就是一種特別待遇）。
2. **主控台從「不得被關掉」改成「不得叫不回來」**：它可以被換掉，但狀態列／標頭
   永遠有一顆把它叫回來。第八十一條的 I4 要跟著改（它今天檢查的是版面**宣告**，
   而宣告仍然一定有 state——所以 I4 其實**不用動**，動的是「使用者能不能換掉它」）。
3. **同一個視圖最多一個槽**——選到已在別處的就**對調**。理由：兩份同樣的視圖是兩份狀態，
   而重的面板（Blockly）開兩份代價高、收益不明。
4. 🪦 ~~**指派跟著版面存**（`版面 id → 指派`）~~ —— **實作時發現不需要**：
   置換是**層 → 層**，與版面無關，所以**一份全域置換**就夠，
   而「切走再切回來不變」是它的推論不是額外功能。
   > **把規則寫進資料的形狀裡，就不必再寫一次規則。**
5. **「清空」留在原地**（積木的動作）。
