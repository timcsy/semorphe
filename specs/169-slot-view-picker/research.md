# Research：每個槽自己選視圖

## 決策 1：↩↪ 只在**桌機**搬進標頭，行動版一個字都不改

- **Decision**：桌機把 `#undo-slot` 從快速列移進 `header .toolbar-actions`；
  行動版維持現狀（它已經在 `#mobile-action-bar` 的最前面）。
- **Rationale**：
  - 🟢 這條原則**程式碼裡已經寫著**（`app-shell.ts` 行動版那段逐字）：
    「↩↪ 排在最前面，而且**不跟著快速列進積木那一格**：還原動的是語義樹，
    不是某一個投影」——**桌機只是沒有照做**。
  - 🔴 而行動版有一段實測過的病歷：第一版把 ↩↪ 塞進標頭的 `.toolbar-actions`，
    使用者在 390px 的真手機上截圖回報「**標頭被擠爆了**」。
    ⟹ **同一個位置在兩個寬度下不是同一個決定。**
- **Alternatives**：
  - 🪦 兩邊都搬進標頭——行動版已經證明會爆。
  - 🪦 留在快速列、讓快速列跟著看得見的那一欄走（2026-09-01 的現況）
    ——那是**治症狀**：它讓 ↩↪ 不消失，而沒有讓它不屬於任何一欄。

## 決策 2：槽的分頁列**由槽產生**，不是每個面板自己帶一條

- **Decision**：每一個槽容器的最上緣放一條 `slot-tabs`，選項來自
  `LAYER_ORDER` 過濾成「這個宿主有的層」。**四個槽共用同一份產生器。**
- **Rationale**：
  - 🟢 SC-002 要求「每一個可見槽的分頁列選項集合**完全相同**」——
    共用一份產生器讓它**不可能**不同。
  - 🔴 每個面板自帶一條的話，「選項一樣」就變成一條要靠人維護的規範，
    而這個專案已經有一句話講過它：**沒有機械檢查的規範就是殼**。
- **Alternatives**：🪦 沿用 `QuickAccessBar` 的那兩顆——它是**面板的**工具列，
  而分頁列是**槽的**。混在一起就回到「工具列住在它所操作的東西裡面」那個病。

## 決策 3：指派是 `版面 id → (層 → 層)` 的**置換**，不是 `槽 → 層`

- **Decision**：使用者的覆寫存成**層與層的對調**（`space ↔ relation`），
  套用時把 `areas` 裡的層依這張置換表換掉。
- **Rationale**：
  - 🟢 **槽沒有穩定的身分**（版面一換槽數就變），而**層有**。
    用「槽 → 層」會在切版面時找不到對應；用置換表則天然可攜。
  - 🟢 它也讓 FR-002（同一個視圖最多一個槽 ⟹ 選到已在別處的就對調）
    變成**定義本身**：置換就是對調。
  - 🟢 `areas` 一個字都不用改——六條不變式仍然驗**宣告**，而宣告仍然是預設。
- **Alternatives**：
  - 🪦 `槽索引 → 層`：切版面之後索引意義變了，等於資料遺失。
  - 🪦 直接改 `areas`：那會讓宣告變成使用者狀態，護欄就失去它要驗的東西。

## 決策 4：主控台的保證從「宣告裡一定有」擴成「叫得回來」

- **Decision**：第八十一條的 I4 **不動**（它驗的是宣告，而宣告仍然一定有 `state`）。
  新增的是：狀態列上一顆「主控台」——按了就把主控台換回**離它最近的那個槽**。
- **Rationale**：
  - 🔴 置換表可以把 `state` 換走（`state ↔ space`），於是畫面上可能沒有主控台。
    而「程式在講話的地方找不到」是退步。
  - 🟢 而**不必禁止**它被換走：禁止會讓主控台變成「那個不能動的特別的」
    ——正是這條線要消滅的形狀。**能換走 ＋ 叫得回來**才是對稱的。
- **Alternatives**：🪦 禁止換走 `state`——把它變成特別的那一個。

## 決策 5：明確不做

自由 docking · 改「清空」的歸屬 · 行動版分頁列 · 同一視圖開兩份。
