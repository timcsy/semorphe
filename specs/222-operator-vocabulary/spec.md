# Feature Specification: 操作者拿得到元件詞彙

**Feature Branch**: `370-operator-vocabulary`
**Created**: 2026-11-09
**Status**: Draft
**Input**: vision 286〈操作者介面〉缺口④「元件詞彙的對外格式」（history/334、355、356）。

## 背景

spec 220 讓外部操作者（AI）用結構操作送提議；而它要插入一個節點時，得自己知道「有哪些元件、各有哪些屬性與接點、接點收什麼」。
今天這些只住在各膠囊的 `component.json` 裡，外部拿不到——AI 只能猜名字，猜錯就被拒成「不認得的元件」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - AI 先問有哪些元件，再組提議 (Priority: P1)

AI 呼叫「詞彙」，拿到目前這個語言的每一顆元件：身分、能出現在語句還是運算式的位置、屬性（名字、種類、可選的值、預設）、接點（名字、收什麼、最多幾個）。
它照這份清單組出的節點，送出提議時不會因為「不認得」「接點不對」「屬性不對」被拒。

**Independent Test**: 拿詞彙裡的每一顆元件，照它宣告的位置組一個最小節點插進一支程式，提議都通過形態檢查（或因「必填的接點沒填」以外的原因被拒的數量為 0）。

**Acceptance Scenarios**:

1. **Given** 目前的語言是 C++，**When** 取詞彙，**Then** 每一筆都是 C++ 的元件，沒有別的語言的。
2. **Given** 目前的語言是 Python，**When** 取詞彙，**Then** 拿得到 Python 的元件（Python 的語言套件沒有宣告清單也一樣）。
3. **Given** 詞彙裡的一顆語句元件，**When** 照它的宣告組一個節點插進 main，**Then** 提議通過。

## Requirements *(mandatory)*

- **FR-001**: 系統 MUST 提供目前語言的元件詞彙，每一筆含：元件身分、可出現的位置（語句／運算式）、屬性（名字、種類、列舉值、是否必填、預設值）、接點（名字、收什麼、上限）。
- **FR-002**: 詞彙 MUST 與提議的形態檢查用同一份宣告（不另抄一份）。
- **FR-003**: 詞彙 MUST 只含目前語言的元件。
- **FR-004**: 詞彙是純資料（可序列化），經與提議相同的入口取得。

## Success Criteria *(mandatory)*

- **SC-001**: 依詞彙組出的最小節點，插入提議被拒成「不認得的元件／接點／屬性」的數量為 0。
- **SC-002**: 詞彙的筆數等於該語言宣告的元件數。

## Assumptions

- 第一版不帶說明文字與例子（標籤住在各膠囊的翻譯檔，鍵名依積木形態而定）——之後要給 AI 讀的說明另一刀。
