# Feature Specification: 學生看到的是代號，不是句子

**Feature Branch**: `126-runtime-message-and-lesson-2`
**Created**: 2026-08-15
**Status**: Draft
**路線圖位置**: 階段 6.9

## User Scenarios & Testing *(mandatory)*

一個剛學完第一課的學生，打錯一個字母就送出。系統**接受了那個程式並跑了它**
（那是對的——那不是語法錯誤），而執行到一半停下來，在輸出區印出一串
**他看不懂、也搜尋不到的代號**。

他不知道自己做錯了什麼，也不知道那是系統的問題還是他的問題。

⚠️ **而課本沒有辦法教他**：課文要寫「你會看到 ○○」的時候，作者只能照抄
那串代號——**等於把缺陷寫進教材**，而教材比程式碼更難改（它會被人記住）。

### User Story 1 - 停下來的時候，系統說的是人話 (Priority: P1)

學生的程式在執行中停下來時，畫面上出現的是**一句他讀得懂的話**。

**Why this priority**: 這是唯一一個「學生已經會撞到」的缺陷——它在
第一課的路徑上，而第一課已經有人走過。其餘兩個故事都建立在它之上。

**Independent Test**: 造一個會在執行中停下來的程式，看畫面上的字串。
不需要第二課、不需要護欄。

**Acceptance Scenarios**:

1. **Given** 一個會在執行中停下來的程式，**When** 學生按執行，
   **Then** 訊息是一句完整的中文句子，**且不含任何代號形狀的片段**
2. **Given** 同一個程式，**When** 切換到英文介面，
   **Then** 訊息是一句完整的英文句子（同樣不含代號）
3. **Given** 一個**沒有文案**的停止原因，**When** 它發生，
   **Then** 畫面上仍然是一句話（通用的那一句），🔴 **而不是把代號當退路**
4. **Given** 學生按了「停止」，**When** 執行中止，
   **Then** 那**不是**錯誤——畫面上不出現錯誤訊息

### User Story 2 - 這件事不會再從第三個地方冒出來 (Priority: P1)

有一條會變紅的檢查，守著「**推給使用者看的字串，不得長得像代號**」。

**Why this priority**: 🔴 **這是同一個病第二次發作**——同樣的缺陷
2026-08-14 才在另一個顯示點修過。而既有的那條檢查沒有接住它，
理由不是「漏了一族」：

```
既有檢查量的   文案【在不在】       ✅ 是綠的
而缺陷是       顯示端【有沒有查】    🔴 從來不查
```

> **文案齊全，而沒有人查它。**

沒有這一條，第三個顯示點會用同樣的方式再犯一次，而**沒有人會知道**。

**Independent Test**: 在任一個顯示點塞一個代號形狀的字串，檢查必須變紅
並**指名是哪一個顯示點**。

**Acceptance Scenarios**:

1. **Given** 所有把字串推給使用者的地方，**When** 檢查執行，
   **Then** 沒有任何一處會推出代號形狀的字串
2. **Given** 一個**合成的**違規顯示點，**When** 檢查執行，
   **Then** 變紅，**且訊息指名是哪一處**——不得只說「有違規」
3. **Given** 一段**正確的**顯示程式碼，**When** 檢查執行，
   **Then** 不報它（不亂報）
4. 🔴 **Given** 開發期才看得到的字串（日誌、內部訊息），**When** 檢查執行，
   **Then** **不報它**——⚠️ 一條會誤報的檢查會被人學會忽略，
   而那時它報的**真違規也一起被忽略**
5. **Given** 檢查本身，**When** 它執行，
   **Then** 它先斷言**掃到的顯示點數量**下限——⚠️ 錨在這個合成量上，
   證明輸入真的進來了

### User Story 3 - 第二課寫得出「你會看到什麼」 (Priority: P1)

有第二課，一個人照著它從第一課的成果走到一個新的、會跑的程式。
而課文裡**引用了系統真實的錯誤訊息**。

**Why this priority**: 🔴 **它是前兩個故事的消費者**。沒有它，
修好的訊息就是一個「機制有了沒人接上」——而那件事在這個專案
發生過至少三次，這會是第四次。

**Independent Test**: 一個人照著課文走完，程式跑得起來，輸出符合期望。

**Acceptance Scenarios**:

1. **Given** 第二課的資料夾，**When** 有人照著走，
   **Then** 走得完，而最後的程式跑得起來
2. **Given** 課文裡引用的每一則錯誤訊息，**When** 與系統實際輸出比對，
   **Then** **逐字相同**——🔴 不得是作者編的
3. **Given** 加入第二課這件事，**When** 檢查改了哪些檔，
   **Then** **沒有動到任何既有的共用檔**
4. **Given** 走完的過程，**When** 記錄卡點，
   **Then** 卡點逐條寫下，**含「因為知道答案而跳過的地方」**

### User Story 4 - 這一課明年還走得通 (Priority: P2)

有一個機械化的東西會在第二課走不通時變紅。

**Why this priority**: 第一課有了；沒有它，第二課會在某次改動後
**靜默地壞掉**。⚠️ 而它同時要回答一個開著的問題：
**每加一課就要手寫一支嗎**——如果答案是「要」，那個成本要被看見。

**Independent Test**: 把課文裡寫的某個預期值改掉一個，檢查必須變紅。

**Acceptance Scenarios**:

1. **Given** 第二課，**When** 走查執行，**Then** 課文寫的每一個
   可觀察結果都被驗證
2. **Given** 課文與實作分歧，**When** 走查執行，**Then** 變紅，
   而訊息說明是**課文或系統有一邊變了**
3. **Given** 「每加一課要不要手寫一支」，**When** 第二支寫完，
   **Then** 這個問題有一個**寫下來的答案**（含理由），不論答案是什麼

### Edge Cases

- 一則訊息**有文案但缺參數** → 顯示時該保留佔位符還是留白？
  🔴 **不得因此掉回代號**
- 停止原因是「使用者主動中止」→ ⚠️ 它不是錯誤，不該走錯誤的顯示路徑
- 🔴 **一個訊息同時經過兩種佔位符格式** → 兩套並存時，
  一個沒被替換的佔位符會直接出現在畫面上，**那與代號一樣糟**
- 檢查若把**開發期日誌**也當成使用者可見的字串 → 誤報，
  ⚠️ 而那會讓人學會忽略它
- 課文引用的訊息**與實際輸出逐字相同**，但**系統之後改了訊息** →
  US4 的走查必須抓到，否則課文會靜默地說謊
- 第二課的最後一個程式**不能執行**（例如犯了語法錯誤）→
  ⚠️ 那時走查該紅，而訊息要分得出是「課文錯了」還是「系統壞了」

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 執行中停下來時呈現給使用者的字串 MUST 是一句自然語言句子，
  MUST NOT 包含代號形狀的片段（全大寫加底線的識別字、大括號、百分號數字）。
- **FR-002**: 該規則 MUST 適用於**每一個**把執行期停止原因推給使用者的地方，
  MUST NOT 只修一處。
- **FR-003**: 找不到文案時 MUST 退回一句**通用的自然語言句子**，
  MUST NOT 退回代號。
- **FR-004**: 使用者主動中止 MUST NOT 被當成錯誤呈現。
- **FR-005**: 系統 MUST 有一條會變紅的檢查，判準錨在**顯示邊界**
  （誰把字串推給使用者），MUST NOT 錨在文案表是否完整
  ——⚠️ 後者今天已經是綠的，而缺陷仍然存在。
- **FR-006**: 該檢查 MUST 為硬性零（判準：留一筆「顯示代號」，
  這條規範就不成立），且 MUST 在報出違規時**指名是哪一處**。
- **FR-007**: 該檢查 MUST 斷言一個**入口條件**，錨在掃到的顯示點數量上
  ——一個什麼都沒掃到的檢查與一個回報零違規的健康檢查產出相同。
- **FR-008**: 第二課 MUST 是一個自成一體的資料夾，加它 MUST NOT
  修改任何既有的共用檔。
- **FR-009**: 第二課的課文引用系統訊息時 MUST 與實際輸出逐字相同。
- **FR-010**: 第二課 MUST 有一個機械化的走查，覆蓋課文寫的每一個
  可觀察結果，且失敗訊息 MUST 說明是**課文或系統有一邊變了**。
- **FR-011**: 「每加一課要不要手寫一支走查」MUST 有一個寫下來的答案與理由。
- **FR-012**: 走第二課撞到的卡點 MUST 逐條記下，
  含「因為知道答案而跳過的地方」。
- **FR-013**: 量測用的暫時檔 MUST 要嘛成為正式產出、要嘛刪除
  ——MUST NOT 留在測試目錄裡沒有歸屬。

### Key Entities

- **停止原因**：一個身分 ＋ 一組具名的值 ＋ 出事的位置。
  ⚠️ 今天它有一個「湊給人看」的字串欄位，**而那個欄位正是缺陷的來源**。
- **一課**：說明（人寫）＋ 期望輸出（一段文字）＋ 走查（機械的）。
- **顯示點**：把一個字串交給使用者眼睛的地方。**這是新檢查的量測單位。**

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 探針測過的 9 種第一課錯誤，**放行的那兩種**在畫面上呈現的
  字串**含代號片段的數量為 0**（今天是 2）。
- **SC-002**: 顯示代號的顯示點數 **= 0**，且該數字由一條會變紅的檢查守著。
- **SC-002b**: 🔴 **該檢查的誤報數 = 0**——被它報出來的每一處，
  都要說得出**使用者在什麼情況下會看到那個字串**。
  ⚠️ 說不出來的即為誤報，而**誤報比漏報更貴**：漏報讓一個缺陷活著，
  誤報讓**整條檢查**失去讀者。
- **SC-003**: 🔴 該檢查第一次執行**必須是紅的**——一開始就綠代表它沒量到東西
  （既有缺陷已實測存在，所以綠就是壞了）。逐項指名後才產基線。
- **SC-004**: 課文引用的錯誤訊息與系統實際輸出的**逐字不一致數 = 0**。
- **SC-005**: 一個人照著第二課走完的成功率 = 1/1，
  ⚠️ **而「沒有卡」必須被明確寫出來**，不得靠沉默推斷。
- **SC-006**: 卡點清單**條數 ≥ 0 而必須存在**，且分得出「說明的缺陷」
  與「工具做不到的事」——⚠️ 一份沒有分類的清單推導不出任何下一步。
- **SC-007**: 既有測試全綠、既有護欄基線**一個數字都不動**
  ——⚠️ 本功能不該改變任何既有量測。
- **SC-008**: 「每加一課要不要手寫一支」的答案**存在且有理由**。
  ⚠️ 如果答案是「要」，那個成本必須被寫成一個數字（每課幾支、多少行）。

## Assumptions

- **⑦⑧ 兩種錯誤被放行是對的**，本功能不改變它。它們不是語法錯誤
  （其中一種在語法上完全合法），該由另一條路線處理。
  🔴 **而本功能因此不會讓「寫錯的程式跑不起來」變好**——它只讓
  **停下來時說的話**變好。**不得宣稱前者。**
- **第二課不需要「起始狀態」機制**——它可以用「貼上這段」開場。
  ⚠️ **不要為了用機制而發明需求**，那正是本 spec 在治的病。
- **走查測試由作者走**，所以卡點清單**會低估**——與第一課同一個限制，
  而「因為知道答案而跳過的」必須另外標。
- **教材面板仍然沒有證據支持**，本功能不做。
- 佔位符格式的統一與否是**實作決定**，而不論選哪個，
  FR-001 的「畫面上不得出現未替換的佔位符」都成立。

## Out of Scope

- 任何面板（教材面板、圖鑑）
- 起始狀態的存檔機制
- 讓 ⑦⑧ 那兩種錯誤被擋下（那需要型別資訊，是另一條路線）
- 圖片、「用指的」互動
- 修改課程層級樹或主題設定
- 改善**編譯期**診斷訊息的措辭（本功能只管**執行期停下來**那一則）
