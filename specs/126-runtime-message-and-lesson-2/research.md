# Research：學生看到的是代號，不是句子

**Date**: 2026-08-15

本檔只記**查證過的地面真相**與**它推翻了什麼**。所有行號可 grep。

---

## Q1（checklist 的第一個問題）：佔位符兩套並存還是統一？

### 🔴 查證結果：**統一在全域上不可能**，而理由不在我們這邊

```
zh-TW／en 各 216 個鍵，含 % 的 17 個
  ├─ 11 個是 CPP_*_MSG0        🔴 Blockly 的積木文案——%1 是【Blockly 的格式】
  ├─  4 個是 RUNTIME_ERR_*      執行期停止原因
  └─  2 個其他（tooltip／輸入提示）
```

`CPP_VECTOR_PUSH_BACK_MSG0` 逐字：`在列表 %1 尾端加入 %2`。
**那是餵給 Blockly 的字串，它自己會替換 `%N`。** 我們改成 `{name}`
積木就長不出來了。

### 決策 1：**查表函式吃兩套佔位符**，不動任何既有文案

- **Rationale**：`{name}` vs `%N` 的選擇權**只有一半在我們手上**。
  ⚠️ 而 `src/i18n/messages.ts:47-51` 檔頭那段理由**仍然成立且要保留**：
  > 「佔位符是 `{name}`，刻意與 Blockly 的 `%1` 不同：診斷訊息的參數
  > **有名字**，而位置參數會讓「第二個是什麼」變成一個要去對照的問題。」

  → **新文案一律 `{name}`；`%N` 只是為既有的執行期文案讓路**，
    而那個「只是讓路」要寫在函式旁邊，否則下一個人會以為兩套等價。
- **Alternatives considered**：
  - **全域統一成 `{name}`** ❌ Blockly 的 11 筆改不了
  - **執行期訊息另開一個格式化函式** ❌ 兩個函式 ＝ 兩個會被忘記的地方，
    而這個 spec 治的就是「有一處沒查表」
  - **改 params 的鍵名（`'%1'` → `'name'`）** ❌ 要動約 40 個拋出點，
    ⚠️ 而那不會讓畫面變好一點——**成本全付在看不見的地方**

## Q2（🔴 整條護欄的成敗所在）：「顯示點」怎麼機械地認出來？

### 先看真實的量

```
new RuntimeError 拋出點            72 處
用到的停止原因身分                  10 種
  TYPE_MISMATCH 32／INDEX_OUT_OF_RANGE 11／UNDEFINED_FUNCTION 9
  UNDECLARED_VAR 6／DIVISION_BY_ZERO 4／ABORTED 4／其餘 6
```

### 🔴 而查證推翻了「只有一個缺陷」這個前提——實際有**三種**

| | 缺陷 | 實測 |
|---|---|---|
| ① | 顯示端不查表 | `execution-controller.ts:355`／`:412`／`:690` 直接推 `e.message` |
| ② | 🔴 **三個身分完全沒有文案** | `RUNTIME_ERR_ABORTED`／`UNKNOWN_CONCEPT`／`UNRECOGNIZED_CODE` |
| ③ | 🔴 **文案要兩個參數而只傳一個** | `型別不符：預期 %1，但得到 %2`，而 32 個拋出點**沒有一個傳 %2** |

**③ 的意思是：就算把 ① 修好，畫面上會出現**

```
型別不符：預期 array，但得到 %2
```

> **一個沒被替換的佔位符，與一個代號一樣糟——而它更難發現，
> 因為句子的其他部分是對的。**

⚠️ 而 ② 正是 spec 的 FR-003（找不到文案 MUST 退回一句通用的話）
**已經有三個真實的受害者**，不是假想。

### 決策 2：🔴 護欄量的是**產品行為**，不是原始碼裡的呼叫點

原本設想的做法是掃 `src/ui/` 找「把字串推給使用者的地方」。
⚠️ **那個做法會誤報，而誤報是這條護欄唯一的死法**（spec SC-002b）：
`src/` 裡到處都是開發期日誌，判準寬一格就會報一整片。

**改成**：列舉**每一個 (停止原因身分, 拋出點傳的參數) 組合**，
把它走一次**顯示路徑**，斷言結果是一句自然語句。

```
單位      一個 (身分, 參數) 組合          而不是「一行程式碼」
判準      結果不得含 RUNTIME_ERR_／%N／{name}／JSON 大括號
```

- **Rationale**：**開發期日誌永遠不會進入這個集合**——它們不經過顯示路徑。
  > **誤報的風險不是靠判準寫嚴來消除的，是靠【量測單位選對】來消除的。**
- ⚠️ **而它同時抓得到 ①②③ 三種**：不查表 → 出現 `RUNTIME_ERR_`；
  沒文案 → 沒有退路就出現代號；缺參數 → 出現 `%2`。
  **一個判準，三個缺陷**——而那正是「錨在顯示邊界不錨在文案表」的收穫。
- **Alternatives considered**：
  - **靜態掃 `src/ui/` 的顯示呼叫** ❌ 誤報（開發期日誌），
    而 `build-guardrail` 第 11 步：一條會誤報的護欄會被人學會忽略
  - **只檢查文案表的完備性** ❌ **今天它已經是綠的而缺陷還在**
    ——那正是第四十二條護欄沒接住這件事的原因
  - **用行號當鍵** ❌ `build-guardrail` 第 11 步逐字：
    「一個會因為程式碼往下移了幾行就報『新增違規』的鍵，報的不是違規，是 diff」

### 決策 3：入口條件錨在**拋出點數**（72）

- 掃到的 `RuntimeError` 拋出點數 ≥ 60。
- ⚠️ **它不隨修復下降**：修好一則訊息**不會少一個拋出點**。
  （`build-guardrail` 第三個簽名：「這個量會不會因為違規被修好而變小？」→ 不會。）
- 🔴 **不得錨在**「顯示代號的數量」——那正是要推向零的東西。

### 決策 4：硬性零，不是棘輪

`build-guardrail` 6.8 的三個問題：

| 問題 | 答案 |
|---|---|
| 留一筆規範還成立嗎？ | ❌ 「系統說的話是人話」留一個反例就是假的 |
| 修一筆要付多少？ | **便宜**——補一則文案／補一個參數，不改行為 |
| 別台機器一樣嗎？ | ✅ 純字串比對，沒有外部工具 |

→ **硬性零**。

## Q3：第二課教什麼？

### 決策 5：**第二課＝「記住一個數字」**，三個概念

```
變數      給一個值一個名字
指定      把新的值放進去（含用自己算自己）
印出變數  第一課的「印出」現在印的是一個【會變的東西】
```

**實測（`tests/probes/__l2probe.test.ts`）**：

```
第二課成品   int score = 90; score = score + 5; cout << "分數是 " << score;
             ✅ 輸出 "分數是 95\n"
```

- **Rationale**：與第一課**零重複**（main／印出／文字都當背景），
  而它**直接消費 US1**——

  ```
  打錯變數名（Score）  →  🔴 RUNTIME_ERR_UNDECLARED_VAR: {"%1":"Score"}
                          修好後 → 「變數 'Score' 尚未宣告」
  ```

  > **那則錯誤訊息本身就是這一課要教的東西。**
  > 「宣告」是什麼意思，最好的解釋是**沒宣告時系統說了什麼**。

  🔴 **所以課文寫得出「你會看到什麼」不是附加價值，是這一課的教學主軸**
  ——而那正是 spec 把 US1 排在 US3 前面的理由。

- **Alternatives considered**：
  - **讀使用者輸入（`cin`）** ❌ 走查要餵輸入，而第二課不該先撞到那個
  - **迴圈** ❌ 三個概念裝不下，而且沒有變數就講不了
  - **函式** ❌ 第一課刻意把 `main` 當背景帶過，第二課立刻回頭講它會**推翻第一課的處置**

### 🔴 而研究順手撞到一個**不在範圍內**的缺陷，記下來不修

```
忘了宣告   score = 90; cout << score;   →  ✅ 跑完，輸出 "90"
```

**C++ 拒絕這段程式**（assignment to undeclared identifier），
而我們的直譯器**默默把它創出來**。

⚠️ 那是使用者原話「**寫錯還能順利執行就是不合理的**」的同一族，
而它**不是語法錯誤**（tree-sitter 解得出來）——與 `Cout`／`<` 同一個地盤，
屬於階段 6.6 ⑤／6.7。

> **本 spec 不修它。而第二課的課文必須避開這個寫法**
> ——⚠️ 否則會教出一個「C++ 可以不宣告」的錯誤觀念。

---

## 決策彙總

1. **查表函式吃兩套佔位符**——`%N` 的選擇權有一半在 Blockly 手上
2. 🔴 **護欄的單位是 (身分, 參數) 組合，不是原始碼行**——誤報靠選對單位消除
3. **入口條件錨在拋出點數 72**（不隨修復下降）
4. **硬性零**（規範成立 ＋ 修一筆便宜 ＋ 無外部工具）
5. **第二課＝變數**，而**錯誤訊息是它的教學主軸**

## 風險與對策

| 風險 | 出處 | 對策 |
|---|---|---|
| 🔴 護欄誤報 → 被人學會忽略 | spec SC-002b、`build-guardrail` 11 | 量測單位選成「走過顯示路徑的結果」，開發期日誌**進不了那個集合** |
| 修好 ① 而 ③ 讓 `%2` 上畫面 | 本檔 Q2 實測 | 判準同時禁 `%N`——**一個判準抓三種** |
| 護欄第一次跑是綠的 | `build-guardrail` 6.5 | 今天實測有 ≥5 個 (身分,參數) 組合會出問題；**綠即為壞** |
| 第二課教出錯誤觀念 | 本檔 Q3 末 | 課文**避開未宣告指定**，而那條缺陷寫進 findings |
| 課文引用的訊息與系統分歧 | spec FR-009 | 走查測試**從系統實際輸出取值比對**，不比對我寫的字面 |
| 動到既有基線 | spec SC-007 | 只加文案與顯示端查表；⚠️ 而**補文案會不會動第四十二條護欄**要先確認 |
