# Feature Specification: 四個「印出來不對」的缺陷

**Feature Branch**: `091-value-representation` ｜ **Created**: 2026-08-06

## 為什麼做這個

六支 todo 的阻斷者各不相同（`cpp_char_literal`、`cpp_cast`、`cpp_sizeof`、
`cpp_enum`、`print`）。**追下去是同一類**：值算對了，**印出來或表示成別的東西**。

| 缺陷 | 直譯器 | g++ |
|---|---|---|
| 布林 | `true` | **`1`** —— C++ 預設不是 boolalpha |
| 字元變數 | `66` | **`B`** |
| `(char)66` | `66`（int） | **`B`** |
| `sizeof(a)` | `4`（一律預設） | **陣列的總位元組數** |
| 列舉常數 | **未宣告變數** | `5` |

**前四個都是「跑完、印出東西、而它是錯的」**——最難發現的那種。
第五個至少會中斷。

## `sizeof` 那個特別值得看

`sizeof(a)/sizeof(a[0])` 是 C++ 算陣列長度的**慣用寫法**。原本 `sizeof`
一律回預設值，於是那個式子**永遠回 1**——而 1 看起來像一個合理的數字。

## 列舉那個是一個錯的宣告

`cpp_enum` 被宣告成 `declarative`（刻意不執行）。**那個宣告是錯的**——
列舉要把常數放進作用域。

> 「刻意不執行」的理由**經不起一支會用到那些常數的程式**。

那正是 `history/018` 講的門檻：宣告要說得出理由，而理由要**站得住**。

## Requirements

- **FR-001**: 布林 MUST 印成 `1`／`0`，且 MUST 兩個方向都驗
- **FR-002**: 字元 MUST 印成字元，`(char)` 轉型 MUST 回字元型別
- **FR-003**: `(int)` 轉型 MUST NOT 被影響
- **FR-004**: `sizeof` 對變數 MUST 回它的位元組數，對型別名 MUST 維持原行為
- **FR-005**: 列舉常數 MUST 進作用域，未寫值的 MUST 從前一個 +1
- **FR-006**: 期望值 MUST 由**真的編譯器**決定

## Success Criteria

- **SC-001**: 只有名字的測試 **27 → 21**
- **SC-002**: 四個修正各有正反測試
- **SC-003**: 既有測試全數通過

## 順帶：四支測試的斷言記錄的是舊 bug

`toBe('true')` 那些斷言記錄的是**錯誤的輸出**。期望值已改為 g++ 實際印出的
東西，並在檔頭註明為什麼改。
