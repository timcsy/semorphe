# 契約：膠囊對系統

一顆膠囊是一個資料夾。系統對它的要求只有這幾條，**其餘一律不管**（薄協定）。

## 系統向膠囊要什麼

| # | 要求 | 違反時 |
|---|---|---|
| C1 | 資料夾根有 `component.json`，其 `conceptId` 格式為 `<scope>:<name>` | 載入時 throw |
| C2 | `conceptId` 的 scope／name 與資料夾路徑一致 | 護欄紅（來源核對） |
| C3 | `paths` 列出**全部五路**，沒有的寫 `null` ＋ `_<path>_why` 理由 | 護欄紅（宣告即紅燈） |
| C4 | `paths` 指到的檔案存在且匯出約定的註冊函式 | 載入時 throw |
| C5 | `labels/<locale>.json` 的鍵不得與其他膠囊相撞 | 合併時 throw |
| C6 | 有 `spec.test.ts`，含**至少一個正向與一個負向**斷言 | 護欄紅 |
| C7 | 該 `conceptId` **不得**出現在膠囊資料夾以外的非清單類檔案 | 護欄紅（就近性正向） |
| C8 | 膠囊資料夾內**不得**出現別顆元件的 `conceptId` | 護欄紅（就近性反向） |

## 膠囊向系統要什麼

| # | 保證 | 兌現處 |
|---|---|---|
| S1 | 我登錄的五路，系統會用；沒登錄的不會被偷偷補預設值 | `core/component/registry.ts` |
| S2 | 我的 `requires` 會變成產出碼的 `#include` 與工具箱的 owner 章 | 依賴解析 ＋ 工具箱 |
| S3 | 我的標籤會出現在 UI，鍵不變 | `core/component/labels.ts` |
| S4 | 刪掉我這個資料夾，其餘元件不受影響 | SC-006 |

## 這份契約**不管**什麼

- 膠囊內部怎麼分檔（`generate.ts` 要不要再拆）
- 實作用什麼寫法
- 註解、命名風格、檔案大小

> 理由：膠囊契約 §五紀律 1——「**共同測不得超出協定。**
> 在協定裡的可以測，不在協定裡的不是共同測。」
> 這擋掉最常見的退化：共同測慢慢變成風格警察。

## ⚠️ 本契約抓不到什麼

- **語義對不對**。C1–C8 全過的膠囊仍然可以做錯的事
  （前例：`stack`／`queue` 的 push 標籤說謊，十八條護欄一條都不叫，學生第一眼看出來）
- **形態的正確性**。標籤有沒有說出「作用在哪裡」，機器判不出來
- **跨元件的組合正確性**。單顆過不代表組合起來對（條件性正確）
