# Feature Specification: 參照元件的讀數要能重新量——殘差與誤差兩條基線

**Feature Branch**: `108-residual-error-baselines`
**Created**: 2026-08-10
**Status**: Draft
**Input**: 建量測機構 ＋ 兩條基線（形態的殘差、行為的誤差），並把 `runCpp` 從 2 份私有實作收成 1 份。

## 這個 spec 在還什麼債

專案宣稱「模型有多接近實體」是可量的，而**實際上沒有任何東西在量**。查證（2026-08-10）：

| 宣稱 | 實測 |
|---|---|
| 「19 個測試檔在算直譯器 vs `g++` 的差」 | ❌ **錯的，本 spec 更正它**。真的 shell out 的只有 2 個檔，而那 2 個比的是 `runCpp(gen1)` vs `runCpp(code)`——**兩邊都是 `g++`** |
| 自動比較「直譯器 vs `g++`」的檔案數 | **0** |
| 其餘 27 個檔的 `g++` 答案 | **人工量一次、凍進註解與預期字串**（例：`tests/integration/declare-family-semantics.test.ts:61` 的 `it('★ g++ 說是 123（不是 111）', …)`） |
| `runCpp` 工具 | **2 份私有重複實作** |

而一個凍結的讀數是**宣告**，不是量測——這正踩在 `knowledge/concepts/等價與觀察集.md`
自己的話上：「行為由量測定義，不由宣告定義」。回饋週期是無限大 ⇒ **開環**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 量得出「模型不理解多少」（Priority: P1）

維護者想知道**有多少原始碼掉進殘差通道**（`raw_code`）——那是模型還沒長到的地方。
今天沒有任何數字，所以「模型覆蓋率退步了」不會有人發現。

**Why this priority**：它是三項裡唯一**起點已知**（0.23%）且不依賴外部工具的，
可以獨立交付並獨立驗證。

**Independent Test**：跑該護欄，得到一個殘差率與**兩欄語料統計**；
把任一顆元件的 lift 規則拿掉，數字必須上升。

**Acceptance Scenarios**：

1. **Given** 現行程式碼，**When** 跑殘差護欄，**Then** 報出殘差率 ≤ 0.23%，
   且同時報出「語法完整 N1 段／語法有錯（片段）N2 段」兩欄
2. **Given** 有人讓某顆元件不再被辨識，**When** 跑護欄，**Then** 殘差率上升且**指名**是哪一段語料變成 `raw_code`
3. **Given** 語料換了一批，**When** 兩欄的比例改變，**Then** 報告要能讓人看出數字變動來自語料而非模型

### User Story 2 - 量得出「模型理解錯多少」（Priority: P1）

維護者想知道**直譯器與 `g++` 差在哪**。今天這個差只存在於 27 個檔的註解裡，
而註解不會在 `g++` 行為改變時變紅。

**Why this priority**：這是真正開環的那一半。與 US1 同級但**風險更高**
（誤差高＝系統會騙人，殘差高只是模型還沒長到）。

**Independent Test**：跑該護欄，得到不一致筆數；把直譯器某個運算子改錯，筆數必須上升。

**Acceptance Scenarios**：

1. **Given** 一批可執行語料，**When** 同時用直譯器與參照編譯器執行，
   **Then** 報出不一致筆數，**且逐筆指名**（哪一段、直譯器輸出什麼、參照輸出什麼）
2. **Given** 直譯器**跑不動**某段語料，**Then** 那一段記進「跑不動」欄，
   **不得**從分母裡消失
3. **Given** 環境沒有參照編譯器，**When** 跑護欄，**Then** **失敗**（紅），不得跳過
4. **Given** 首次執行，**Then** 結果**必須是紅的**且逐項指名，基線在確認之後才產生

### User Story 3 - 一份編譯執行工具（Priority: P2）

寫測試的人需要「編譯並執行一段 C++」時，今天要自己抄一份。

**Why this priority**：它是 US2 的前置，但**單獨也有價值**（消一份重複）。

**Independent Test**：搜尋 `tests/` 下的私有編譯實作，數量為 1。

**Acceptance Scenarios**：

1. **Given** 既有兩個檔各有一份私有實作，**When** 收攏完成，**Then** 只剩一份共用實作，
   且原本那兩個檔的測試結果**逐字不變**

### Edge Cases

- **語料篩選把差異濾掉**：若誤差只在「直譯器跑得動的」語料上量，等於先排除失敗
  → 跑不動的段數必須是**報告的一部分**
- **參照編譯器缺席**：必須紅，不得 skip（否則「看不見的缺陷」與「不存在的缺陷」長得一樣）
- **參照編譯器版本／旗標變動**：基線要記錄它們，否則數字漂移查不出原因
- **語料裡的片段**（語法本來就不完整）：不得計入殘差，且**必須另欄計數**
- **需要標準輸入的語料**：無法無人值守執行 → 歸入「跑不動」並註明原因
- **執行不終止的語料**：需有時限，逾時歸「跑不動」

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 量出並回報**形態的殘差率**——落入殘差通道的原始碼字元佔比。
- **FR-002**：殘差的語料 MUST 分成「語法完整」與「語法有錯（片段）」兩欄分別計數，
  且**只有語法完整的**計入殘差率。
- **FR-003**：系統 MUST 量出並回報**行為的誤差**——直譯器輸出與參照編譯器輸出不一致的筆數。
- **FR-004**：誤差報告 MUST 逐筆指名（語料、直譯器輸出、參照輸出），不得只給總數。
- **FR-005**：直譯器**跑不動**的語料 MUST 單獨計數並出現在報告裡，不得從分母消失。
- **FR-006**：參照編譯器不存在時，護欄 MUST 失敗，MUST NOT 跳過。
- **FR-007**：誤差基線 MUST 記錄參照編譯器的版本字串與編譯旗標。
- **FR-008**：殘差與誤差 MUST 是**兩條獨立基線**，MUST NOT 合併成單一數字或單一檔案。
- **FR-009**：兩條基線 MUST 為棘輪（只准下降），MUST NOT 為硬性零。
- **FR-010**：每條護欄 MUST 有自我否證聲明，且該聲明的斷言對象 MUST NOT 是這條護欄
  意圖推向零的計數。
- **FR-011**：每條護欄 MUST 有雙向注入驗證：壞輸入會被報出、好輸入不被誤報。
- **FR-012**：誤差護欄的**首次執行結果 MUST 為紅**，基線 MUST 在逐項指名並確認之後才產生。
- **FR-013**：專案 MUST 只有一份「編譯並執行 C++」的實作供測試使用。
- **FR-014**：基線檔 MUST 說明數字的**下降原因類別**（因為實作了／因為宣告或重新分類了）。

### Key Entities

- **殘差記錄**：語料段數（完整／片段）、總字元、殘差字元、殘差率、降級原因分佈
- **誤差記錄**：語料段數（跑得動／跑不動）、不一致筆數、逐筆明細、參照編譯器版本與旗標
- **語料**：從既有測試資產取得的 C++ 片段集合，帶「語法是否完整」標記

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：兩條基線存在且各自獨立，維護者能分別讀到「模型不理解多少」與「模型理解錯多少」。
- **SC-002**：殘差率 ≤ 0.23%，且報告同時顯示兩欄語料統計。
- **SC-003**：誤差的逐筆明細足以讓人不必重跑就知道差在哪。
- **SC-004**：「編譯並執行」的實作數量從 2 降到 1，且既有測試結果逐字不變。
- **SC-005**：移除任一參照編譯器 → 護欄變紅（而非變綠或跳過）。
- **SC-006**：誤差護欄的首次執行留下一筆**紅色且逐項指名**的紀錄。

## Assumptions

- 語料來源沿用既有測試資產中的 C++ 片段（與殘差首次量測同一批），不新建語料庫。
- 「不一致」以標準輸出的逐字比對（去除首尾空白）判定。
- 開發環境有參照編譯器；CI 若沒有，視為環境缺陷而非測試該容忍的情況。
- 殘差起點 0.23% 來自 2026-08-10 的實測，會在首次正式執行時重新確認。

## Out of Scope

- 把 27 個檔的凍結讀數改成即時量測（那是清償，不是機構）
- 執行那一路的殘差通道（「這一段我沒有執行」的標記）
- 硬體域的任何東西
- **改善**殘差或誤差本身——本 spec 只建立刻度

## 給實作者的警告（來自 `knowledge/skills/build-guardrail/SKILL.md`）

1. **第 2 步順序不可反**：自我否證聲明**先寫**，再寫量測。錨點挑合成輸入，
   不挑缺陷計數——語法簽名是 `expect(<缺陷計數>).toBeGreaterThan(0)`，
   那種錨**會在成功的那天變紅**。
2. **第 6.5 步**：誤差那條第一次跑一定紅。**先跑、確認紅、逐項指名、最後才產基線**。
   先產基線＝把現況封為合格。
3. **第 6.8 步**：兩條都用棘輪。誤差用硬性零會變成謊言——直譯器是教學用的，
   本來就不可能等於參照編譯器。
4. **⚠️ 已經犯過一次的錯**：殘差第一版量成 **48.83%**，正確值 **0.23%**，差 200 倍。
   **錯的不是程式，是語料**（820 段裡 353 段是片段）。
   → 這條護欄最難的一步是**語料分欄**，不是量測本身。
5. **⚠️ 不可混成一個數字**：殘差高＝模型還沒長到那裡（系統仍然正確）；
   誤差高＝模型是錯的（系統會騙人）。混起來的話，多蓋幾顆元件會讓一個
   「會騙人」的數字看起來在改善。
