# Spec 188：積木的收合是共享狀態的投影 ＋ 收合進存檔

**路線圖**：vision〈分子：組合階層與粒度切換〉「積木／程式碼的投影——訂閱同一個狀態」的**積木那一半**（程式碼的摺疊另一刀）
**前置**：spec 187（`granularity:request`／`granularity:collapsed`、持有者 `connectGranularity`）
**設計來源**：`knowledge/draft/2026-09-03-分子與粒度切換.md`——「積木 摺成一行 ＋ 一句摘要 🟢 Blockly 原生就會（只要訂閱那個狀態）」；
「A 不可以被叫成粒度切換……否則 B 到的那一天會有兩個收合機制」。

## 問題

今天 Blockly 原生的收合（右鍵「收合這一塊」）是第二個收合機制：
- 它只存在 `blocklyState` 裡，**從程式碼重畫積木就攤開**（重畫用的狀態由樹產出，樹沒有收合）。
- 流程面板（spec 187）收起來的，積木上看不到；反之亦然。
- 重新整理之後，流程的收合不見（187 刻意沒存）。

## 使用者故事

**US1（P1）** 在積木上收起一個迴圈 → 流程面板同一塊也收成框；在流程展開 → 積木也攤開。
**US2（P1）** 收起來之後在程式碼打一個字（積木重畫）→ 那塊**還收著**。
**US3（P1）** 重新整理 → 積木與流程都還收著。
**US4（P2）** 舊存檔（v24 以前）裡收著的積木，升級後不會被攤開——第一次同步時收編進共享狀態。

## 功能需求

- **FR-001** 積木面板訂閱 `granularity:collapsed`：每次語義更新之後、每次廣播之後，照狀態 `setCollapsed`
  （事件蓋 `BUS_GROUP`、不進復原堆疊——事件是非同步發的，旗標要蓋在造出事件的當下）。
- **FR-002** 使用者用 Blockly 的選單收／展（`BUS_GROUP` 以外的 `collapsed` 變更）→ `granularity:request`。
- **FR-003** 收編：積木上收著、狀態裡沒有、而上一次也不是照狀態收的 → 請求收合（舊存檔走這條）。
  別的視圖展開的（上一次照狀態收的）→ 跟著攤開，不收編。
- **FR-004** 存檔多一格 `collapsed?: { keys: string[] }[]`（v25，sideCar）——與 `flowLayout` 同性質：導不出來 ⟹ 狀態，
  存鑰匙、不吃 `codeHash`、對不上就安靜地掉。24 → 25 只改版號（不補空陣列）。自動載入與匯入兩條路都還原。

## 範圍外

- 程式碼面板的摺疊（Monaco folding 是按行的，要 `nodeId` → 行區間）——下一刀。
- 鑽入、麵包屑、多選。

## 驗收

- e2e `blocks-collapse-shared`：積木收 → 流程框；改值重畫 → 積木仍收；流程展開 → 積木攤開；存檔有那一筆鑰匙、版本 25；重新整理 → 兩邊仍收著。
- 單元：存檔欄位守恆（13 個欄位）。
