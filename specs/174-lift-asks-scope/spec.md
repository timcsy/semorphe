# Feature Specification: 讓 lift 樣式問得出「這個名字被宣告過嗎」

**Feature Branch**: `174-lift-asks-scope`
**Created**: 2026-09-06
**Status**: Draft
**Input**: `cpp:pin_constant` 的 lift 樣式 2026 年被拿掉，病歷逐字（那顆膠囊的 `_lift_why`）：

> 語料裡有 `enum Level { LOW = -1, MEDIUM = 0, HIGH = 1 };`，
> 而 `cout << LOW` 印出 **0** 而不是 **-1**。
>
> **一個靠「識別字的名字」認人的樣式，會把使用者自己宣告的名字搶走。**

處置是拿掉樣式，而代價明說了：「**correctness 贏 round-trip**」。

---

## 這一刀在解什麼

那個處置是對的，而它**不是唯一的解**——它只是當時做得到的那一個。

```
今天   樣式問「這個字叫 HIGH 嗎」          → 使用者宣告的 HIGH 被搶走
之後   樣式問「這個字叫 HIGH，【而且沒有人宣告過它】嗎」
```

判準本來就寫在那份病歷裡：**「沒有人宣告它，它才是環境提供的」**
——而那句話當時只在**執行期**做得到。

### 🔴 而同一份病歷有一句沒被驗證過的推測

> ⚠️ 既有的 `builtin_constant` 用同一個做法（`EOF`／`NULL` 靠名字 lift），
> 而**那些名字幾乎沒有人會重新宣告**——差別在這裡，不在做法。

2026-09-06 量過了（兩支探針）：**那句話不成立**。

| 量的 | 結果 |
|---|---|
| 使用者宣告 `enum Marker { EOF = -99 }` | `EOF` **仍然**被認成內建常數 |
| 執行 `cout << EOF` | 丟 `RUNTIME_ERR_DUPLICATE_DECLARATION` ——**出聲了，而它說錯原因**（使用者只宣告一次） |
| lift 期問「`LOW` 被宣告過嗎」 | **查不到**（列舉成員不進 declarations）——樣式今天就算想問也問不出來 |

> **一個「因為沒有人會這樣做所以安全」的理由，
> 保護的是常見情況——而 bug 住在別的地方。**

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 學生宣告了同名的東西，系統不搶它 (Priority: P1)

學生寫 `enum Level { LOW = -1, HIGH = 1 };`，然後印 `LOW`——**印出 -1**。

**Why this priority**: 這是那份病歷裡的原始傷害。今天它已經被「拿掉樣式」擋住了，
而這一刀**不得讓它回來**。

**Independent Test**: 跑那段程式，比對輸出。

**Acceptance Scenarios**:

1. **Given** `enum Level { LOW = -1 };`，**When** `cout << LOW`，**Then** 印出 `-1`
2. **Given** `enum Marker { EOF = -99 };`，**When** `cout << EOF`，
   **Then** 印出 `-99`——⚠️ **而不是丟「重複宣告」**
3. **Given** 學生在函式裡宣告 `int HIGH = 7;`，**When** 用它，**Then** 是他的那一個

### User Story 2 - 沒有人宣告時，它仍然是環境提供的 (Priority: P1)

學生寫 `pinMode(13, OUTPUT);`——`OUTPUT` 是**腳位常數**，積木上顯示成那顆積木。

**Why this priority**: 那是這些樣式**存在的理由**。修掉 US1 而讓 US2 壞掉，
等於把功能刪了。

**Acceptance Scenarios**:

1. **Given** 沒有人宣告 `EOF`，**When** 用它，**Then** 它是內建常數
2. **Given** 沒有人宣告 `HIGH`，**When** 用它，**Then** 它是腳位常數

### User Story 3 - 積木來回一趟不掉形狀 (Priority: P1)

學生從工具箱拖一顆 `HIGH` 積木 → 同步到程式碼 → 再同步回積木
——**它還是那顆 `HIGH` 積木**。

**Why this priority**: 🔴 **這才是這一刀真正的收益**。今天它會變成
「變數參照 HIGH」——而**每一個 Arduino 課的學生都會遇到**（自動同步一直在跑）。

那份病歷把它列為已知代價（「correctness 贏 round-trip」），
而這一刀讓兩者**不再互斥**。

**Acceptance Scenarios**:

1. **Given** 畫布上一顆 `HIGH` 腳位常數積木，**When** 以積木為準同步再以程式碼為準同步，
   **Then** 它仍然是腳位常數積木

### Edge Cases

- 🔴 **宣告的順序**：`enum` 寫在使用它的那一行**之前**（C++ 本來就要求如此），
  而 lift 是由上而下——所以問得到。⚠️ 而**寫在之後**的情況要說出它會怎樣
- 🔴 **作用域彈出**：在 `{ }` 裡宣告的名字，離開那個區塊之後**不再遮蔽**
  ——那正是 C++ 的規則，而系統要跟著
- **同名但不同種**：`enum` 成員與變數同名時以內層為準（既有的 `lookup` 已經這樣做）
- ⚠️ **樣式問了而查不到**：那是「沒有人宣告」，**不是**「不知道」
  ——兩者在這裡同義，而那是一個**刻意接受**的近似

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 樣式的比對條件 MUST 能表達「**這個名字必須沒有被宣告過**」
- **FR-002**: 比對的當下 MUST 知道目前作用域裡有哪些名字
- **FR-003**: 列舉成員 MUST 被算成「宣告過的名字」
- **FR-004**: 靠名字認人的樣式（內建常數、腳位常數）MUST 用那個條件
- **FR-005**: 沒有人宣告時，那些名字 MUST 仍然被認成環境提供的常數
- **FR-006**: 腳位常數的積木 MUST 撐得過一次「積木 → 程式碼 → 積木」

### Key Entities

- **名字的比對條件**：樣式用來認人的那組判斷。今天有「這個欄位等於某個字」
  與「這個欄位必須不存在」，這一刀加第三種
- **作用域**：lift 當下「有哪些名字被宣告過」。機制已存在，而**列舉成員沒進去**

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `enum Level { LOW = -1 }; cout << LOW;` 印出 **`-1`**
  （⚠️ 第三十二條護欄已經在驗這個案例——它**一條都不得改**）
- **SC-002**: `enum Marker { EOF = -99 }; cout << EOF;` 印出 **`-99`**，
  且**不丟任何錯**
- **SC-003**: 沒有宣告時 `EOF` 與 `HIGH` 仍然是內建／腳位常數
- **SC-004**: 一顆腳位常數積木走完「積木 → 程式碼 → 積木」之後**身分不變**
- **SC-005**: 既有的端對端測試**一條不改**而全數通過

---

## Assumptions

- **A-001**: 那個新條件叫「**必須沒有被宣告**」，形狀對齊既有的「必須不存在」。
  🔴 **理由**：既有那一格已經立下了「這一格說的是【必須沒有】」的形狀，
  而發明第二種說法會讓讀的人**要記兩套**。
- **A-002**: 「查不到」＝「沒有人宣告」。
  ⚠️ 那是一個**近似**：作用域的紀錄可能不完整（例如來自標頭的宣告）。
  🔴 而它偏向**安全的那一邊**——查不到時把它當成環境常數，
  與今天的行為相同；查得到時才改變行為。
- **A-003**: 只做 C++ 這一個語言的兩顆膠囊。其他語言沒有這個形狀的樣式。

---

## Out of Scope

- **沒有名字條件的那幾條樣式**（`true`／`false`／`nullptr`）
  ——它們是**關鍵字不是識別字**，語法上就搶不走
- **把 lift 改成兩趟掃描**（先收集所有宣告，再認人）
  ——那會解掉「宣告寫在使用之後」那個邊界情況，而它是更大的設計
- 其他語言的樣式
- 執行期那條「查不到宣告才問腳位常數表」的路徑——**它照舊**，
  而這一刀讓 lift 期與它**用同一個判準**
