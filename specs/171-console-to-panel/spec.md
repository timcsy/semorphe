# 功能規格：主控台回到 panel 區，而十字退場

**功能分支**：`171-console-to-panel`
**建立於**：2026-09-02
**狀態**：Draft

**輸入**（使用者逐字）：

> 「我們**捨棄十字**，然後讓最底下水平**完全展開**是放主控台（不同於現在
> 沒有完全展開），像是 VSCode 那樣，然後其他面板就在上面分割畫面，
> 這樣在**三個宿主環境都可以比較一致**。然後主控台可以**關閉或是開啟**，
> 行為跟 VSCode 那邊類似，然後把我們的主控台跟原生的綁在一起，
> 就是**多塞幾個 tab**，而不是走編輯視窗」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三個宿主的形狀一樣 (Priority: P1)

一個學生在網頁版練熟了版面，打開 VSCode 或 Arduino IDE，看到**同一個形狀**：
上面幾欄投影，底下一條全寬的主控台。

**為什麼是 P1**：這是使用者這一刀的目的（「三個宿主環境都可以比較一致」）。
而在此之前 Arduino IDE 上按「三欄」得到的是**四條擠在一起的窄欄**。

**獨立測試**：三個宿主宣告各跑一次，版面清單與可見的格子逐字相同。

**驗收情境**：

1. **Given** 任何一個宿主，**When** 打開版面選單，
   **Then** 看到**三張**（專注／對照／三欄），而且**沒有十字**。
2. **Given** Arduino IDE，**When** 按「三欄」，
   **Then** 編輯區排成三欄，**而且不跳任何「不支援」的警告**。
3. **Given** 任何一個宿主，**When** 主控台開著，
   **Then** 它是**全寬**的，橫跨所有欄。

### User Story 2 - 主控台可以關，而它叫得回來 (Priority: P1)

使用者把主控台關掉，畫面多出一塊空間。程式一有輸出，**它自己回來**。

**為什麼是 P1**：這是使用者明說的第二件事，而它取代了一條既有的硬性零
（「主控台一次都不准不見」）。

**獨立測試**：關掉主控台 → 執行一支會印東西的程式 → 它自己出現且印出來了。

**驗收情境**：

1. **Given** 主控台開著，**When** 使用者關掉它，**Then** 它不見了，
   而**其餘的版面不受影響**。
2. **Given** 主控台關著，**When** 程式印出一行，
   **Then** 主控台**自己回來**並顯示那一行。
3. **Given** 主控台關著，**When** 使用者從選單叫它，**Then** 它回來。
4. **Given** 主控台關著，**When** 程式在等 `cin`，
   **Then** 它自己回來，**而且輸入打得進去**。

### User Story 3 - 在 IDE 裡它與原生的東西並排 (Priority: P2)

在 VSCode／Arduino IDE 裡，主控台與「終端機」「問題」「輸出」**同一排**，
不是一個編輯器分頁。

**為什麼是 P2**：它是「一致」的實作方式，而 US1／US2 的價值不依賴它成立。

**獨立測試**：在 IDE 裡開主控台，它出現在下方那一區而不是編輯器區。

### Edge Cases

- 宿主**沒有** panel 區（網頁版）→ 底條由我們自己畫，行為相同。
- 主控台關著而程式**同時**輸出與等輸入 → 只回來一次，且輸入可用。
- 使用者把主控台拖去別的位置（IDE 允許）→ **不得**被我們搬回來。
- 版面切換時主控台是關的 → **切換不得把它打開**（那會覆蓋使用者的選擇）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：版面清單必須是**三張**（專注／對照／三欄），且每一張的編輯區
  **只有欄、沒有列**。
- **FR-002**：版面宣告**不得再包含主控台那一層**——它不是編輯區的一格。
- **FR-003**：主控台必須是**全寬**的一條，橫跨編輯區的所有欄。
- **FR-004**：主控台必須**關得掉**，而且**叫得回來**。
- **FR-005**：主控台關著時**有輸出就自己回來**——包含「程式在等輸入」。
- **FR-006**：切換版面**不得**改變主控台的開關狀態。
- **FR-007**：在有原生 panel 區的宿主上，主控台與原生的那些**同一排**。
- **FR-008**：三個宿主的版面清單與可見格子**逐字相同**。
- **FR-009**：系統**不得**再依賴任何「一次宣告整張版面」的宿主指令
  ——三張版面用「把一格顯示到第幾欄」就排得出來。

### Key Entities

- **版面預設**：`id`／`nameKey`／`areas`（**只含 element／relation／space**）。
- **主控台的可見狀態**：開／關 ＋「有輸出就回來」的規則。
  ⚠️ 它**不住在版面宣告裡**——版面不決定它開不開。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：三個宿主的版面清單**逐字相同**，且都是三張。
- **SC-002**：Arduino IDE 按任何一張版面，**不跳任何「不支援」的警告**
  （今天：三欄與十字都跳）。
- **SC-003**：**刪掉的行數 > 加上的行數**。
  ⚠️ 這一格是這一刀的**性質**：它是把一個不該存在的需求拿掉，
  而不是加一個功能。逐項退場清單見 Assumptions。
- **SC-004**：既有 e2e **除了十字那幾條之外一條都不改**——其餘行為逐字相同。
- **SC-005**：關掉主控台後執行一支會印東西的程式，**它自己回來**（可自動驗）。

## Assumptions

### 兩個拍板點（帶理由的預設）

**① 主控台與變數住在【一個】視圖裡，而不是兩個並排的原生分頁。**

使用者說「多塞幾個 tab」聽起來是兩個。而選一個的理由：

- 兩個視圖 ＝ 兩個獨立的執行環境，那會回到「**被餵的薄視圖**」那個形狀
  ——而它的傷 2026-09-01 記過：餵它的面板關掉之後**沒有人清它**，
  它停在最後一筆，看起來完全正常。
- 網頁版本來就是「**一格兩個分頁**」。一個視圖才與它**逐字相同**，
  而「三個宿主一致」正是這一刀的目的。

⚠️ 代價：那兩個分頁看起來是「我們的」，不是原生的。**可以之後再拆**
（拆成兩個是加法，合成一個是減法——先做減法）。

**② I4 的新說法**：主控台**可以關**，而它**必須叫得回來；有輸出時它自己回來**。

🔴 護欄要驗的是**後半**（叫得回來 ＋ 自動回來），不是前半。
「不准關」是一條**擋住使用者**的規範；「一定回得來」才是那條規範真正要保護
的東西——使用者**看不到程式在說什麼**。

### 其他

- 退場清單：`setEditorLayout` 那條路、分割指令的退路、能力探測、
  十字的 2×2 推導、主控台那一層在版面宣告裡的所有特例。
- 變數那一頁在 DAP 之前維持現況（與主控台同一個視圖的第二個分頁）。
- 已查證：Arduino IDE（Theia）支援 panel 區的 webview 視圖。

## Out of Scope

- 把主控台與變數拆成兩個原生分頁（見 Assumptions ①——之後可以再加）。
- DAP 的 Variables 視圖。
- 版面記憶（每份文件記住自己的版面）。
