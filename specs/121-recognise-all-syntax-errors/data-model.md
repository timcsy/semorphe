## 實體一：AST 節點的錯誤資訊

| | 今天 | 之後 |
|---|---|---|
| 實體 `ERROR` 節點 | ✅ 認得 | ✅ |
| `hasError` 傳播旗標 | 🔴 **不在介面裡** | 🟡 選用欄位 |

⚠️ **選用而非必要**，而理由不是「怕壞」：測試的假樹**描述的是一棵沒有錯誤的樹**，
省略它讀成 falsy 是**語義正確**的。
（而必要欄位在這裡沒有保護力——`tests/` 不在型別檢查範圍內。）

## 實體二：語法錯誤的標記

⚪ **形狀不變**（`degradationCause: 'syntax_error'` ＋ `confidence: 'inferred'` ＋ `rawCode`）。

改變的只有兩件：**什麼會被標記**（更多），與 **`rawCode` 裝什麼**（完整原文）。

## 實體三：三情境探測的時間上限

```
今天   300 秒    而實測負載下要 502～575 秒 → 時好時壞地紅
之後   900 秒    1.5 倍於最差實測
```

⚠️ 而數字旁 MUST 寫明：**上限是用來偵測卡死，不是用來強制速度**。
沒有那句話，下一個人會把它讀成「這支被允許跑 15 分鐘」。
