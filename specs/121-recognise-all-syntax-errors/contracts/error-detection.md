# 契約：什麼算「使用者寫錯了」

**Date**: 2026-08-14

---

## 契約一：兩種表示，一個判定

```
實體錯誤節點   解析器放了一個 ERROR 節點        ← 今天認得
傳播旗標       節點上帶「這底下有錯」的旗標      ← 🔴 今天漏掉
```

判定 MUST 認得**兩者**。

⚠️ 而旗標**會往上傳播**——最外層節點永遠帶著它。所以判定變寬之後，
**落點邏輯是唯一擋住「整棵樹被標記」的東西**。

---

## 契約二：落點邏輯**一行不改**

```
標記落在「最深的【已 lift】節點」上，而不是「最深的 AST 節點」
```

判準是**語義樹上有沒有子孫已經認領**——而那與「錯誤怎麼表示」無關。

⚠️ 所以本功能**不碰它**。若標記仍往上飄，那是落點邏輯的問題，
**而不是把判定改回去的理由**。

---

## 契約三：原文

```
今天   errs.join(' ') || node.text     → B 得到片段「1」
之後   node.text                        → 一律是那個節點的完整原文
```

⚠️ A／C 本來就會落到 `node.text`（它們沒有 ERROR 節點）
——**本功能是把 B 統一過去**，不是發明新規則。

---

## 契約四：另外兩種降級原因**完全不變**

```
unsupported             我們還沒長到      ← 一行不改
nonstandard_but_valid   認得但不標準      ← 一行不改
```

`determineDegradationCause` 的**順序不動**：先判語法錯誤，
所以那一格改了不影響後兩格。

---

## 契約五：🔴 安全網

**第四十三條護欄**（合法語料 55 段，誤標 0，棘輪基線 0）
MUST 在每一次改動後跑，且 MUST 維持 0。

> **這條契約不是「別忘了跑測試」——它是這個功能被允許存在的條件。**
> `history/017`：一道會拒絕的檢查，必須同時回答被拒絕的東西去哪了。
