## 出發點：階段 7 的目的已由人拍板改寫

`vision` 階段 7 逐字：

> **新的目的**：**拿第二個語言去【產生等價的證據】**，
> 順便量出**鄰域半徑在哪裡失效**。

🔴 **舊的目的（「驗證 `layer: universal`」）已作廢**——那個問法本身不成立：
通解是**算子**的性質不是**解**的性質，「某個東西是不是通用的」
在固定觀察集之前是**不良定義的**。（`layer` 那一格已於 spec `152` 退場。）

> **所以這一刀的判準是：結束時，等價類的清單長什麼樣？**
> **不是**「Python 能不能跑」。

## 🔴 研究階段已經量到的第一個事實

加**一顆**探針元件 `src/components/python/print/component.json`
（只有 `conceptId` ＋ `traits.ioRole`）之後跑全套：**25 個以上的測試檔當場紅**
——含 `audit-declared-props`／`audit-declared-slots`／`audit-component-id-integrity`／
十支 probes／大量 integration。

根因：

> **`allComponentDefs()` 掃的是 `src/components/*/*/component.json`
> ——於是【每一條吃元件清單的護欄】都假設了那些元件是 C++。**

⚠️ 而那**正是這一刀要買的東西**（`history/015` 逐字：「**Python 會直接繼承這些病**」）。
🔴 **「多少條檢查假設了元件是 cpp」是這一刀的第一個交付，不是障礙。**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 🔴 兩個語言的「輸出」落在同一類 (Priority: P1)

一個讀這個專案的人問：「`cout << x` 與 `print(x)` 在這個系統裡算不算同一件事？」

**驗收**：在觀察集 `{ioRole}` 下，`cpp:print` 與 `python:print` **落在同一類**，
而那份等價類清單**列得出來**（不是靠讀原始碼推論）。

### User Story 2 - 🔴 第一個分歧點是一個【位置】 (Priority: P1)

**驗收**：量測要指出**第一個不落在同一類的地方**，並且它是一個可以指著看的位置
（哪一顆概念／哪一個維度），**不是一句猜測**。

### User Story 3 - 🔴 C++ 一個字都不能變 (Priority: P1)

**驗收**：既有的 4733 支測試**一支都不變**；三個中立性維度（`0 / 33 / 0`）不得上升。

### Edge Cases

- **一顆 Python 元件會弄紅 25+ 檔** → ⚠️ 修法有兩種，**兩種都要先論證，不得默默選一個**：
  ```
  ① 那條檢查【真的該支援多語言】   → 判準放寬到「每個語言各自完整」
  ② 那條檢查【本來就只該掃 cpp】   → 判準收窄，並寫明為什麼
  ```
- **`python:print` 沒有積木／沒有執行期** → 那是**刻意的**；它此刻只是一個**有性狀的身分**
- **觀察集只有一個維度（`ioRole`）** → 那也是刻意的：**先有一條邊，再談半徑**

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：Python 的語法解析器 MUST **建得出來**，而**建置步驟要留下**
      （`npm run build:wasm:python`）。
      🔴 **而它此刻【不出貨】**——`e2e/shipped-assets.spec.ts` 的判準是
      「出貨的每一個 wasm，都要有人真的去要它」，而這一刀**明確排除**
      接上 Python 的 lift 路徑，所以**沒有人會去要它**。
      > **一個沒有人載入的 460 KB 資產，不是「準備好了」，是死重。**
      🟢 重開條件：Python 的 lift 路徑接上（那時它才有人要）。
- **FR-002**：MUST 存在一顆 `python:print`，宣告與 `cpp:print` 相同的 `ioRole`
- **FR-003**：MUST 有一支量測，在指定的觀察集下**列出等價類**
- **FR-004**：該量測 MUST 指出**第一個不落在同一類的地方**
- **FR-005**：🔴 每一條因為 Python 而紅的檢查 MUST 被**分類並處置**（① 支援／② 收窄），
      而**每一條都要寫得出理由**
- **FR-006**：🔴 C++ 既有行為 MUST 零變更

### Key Entities

- **等價類**：在某個觀察集下，性狀相同的一組概念身分
- **觀察集**：決定「相同」怎麼算的那組維度（本刀 ＝ `{ioRole}`）
- **分歧點**：第一個在該觀察集下無法歸入同一類的位置

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：等價類清單裡，**至少一類同時含 cpp 與 python 的成員**
- **SC-002**：**第一個分歧點**寫得出具體位置
- **SC-003**：因 Python 而紅的檢查 → **全部處置完，且各有理由**
- **SC-004**：C++ 既有測試 4733 支全綠；中立性 `0 / 33 / 0` 不上升

## 明確排除

- **完整的 Python 語言套件**——cpp 有 59 個 `.ts` ＋ 25 個 `.json`，
  照抄一份會**花掉整週而產出零個等價證據**
- **`block-registrar` 那 33 筆**——⚠️ 由這一刀**逼出來**（觀察它痛在哪），**不是先重寫**
- **Python 的執行期**、**工具箱切換**、**roundtrip 完整性**
- **`app.ts` 的 35 處組裝點**（要它歸零得走 manifest 外掛載入）

## Assumptions

- 觀察集先取 `{ioRole}` 一維——**先有一條邊，再談半徑**
- `python:print` 對應 Python 的 `print(...)`；⚠️ 而**它是不是真的與 `cout` 等價**
  正是這一刀要**產生證據**的事，不是前提

## 已知的坑

1. 🔴 **最大的風險是把「Python 能跑」當成目標**——判準：**等價類的清單長什麼樣？**
2. **兩種修法都要先論證**（支援多語言 vs 收窄判準）——不得默默選一個
3. **走使用者那條路**——`experience`「一個修好的投影，可能不在使用者走的那條路上」
4. ⚠️ **注入要編得過**，且要分辨「真的綠／真的紅／沒跑起來」（`build-guardrail` 第四種結局）
5. 🔴 **出貨的資產要有人要**——第一版把 wasm 放進 `public/` 就推了，
   而 `shipped-assets` 那支 e2e 當場紅（**我在它紅著的時候說了「已推送」**）。
   ⚠️ 判準不是「將來會用到」，是**現在有沒有人去要它**。
