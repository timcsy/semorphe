# Feature Specification: 版面——四張示意圖，而沒有任何一層是特別的

**Feature Branch**: `168-layout-thumbnails`

**Created**: 2026-08-31

**Status**: Draft

**Input**: 使用者逐字：「你現在把積木和流程用 tab 切換我不太喜歡，**因為這樣程式碼面板就變得比較特別了**」。

## 它要解決什麼

四個投影／面板各自宣告了自己的**層**（`element` 程式碼／`relation` 流程／
`space` 積木／`state` 主控台・變數），而版面今天是這樣：

```
程式碼   永久佔一欄
流程 ┐
積木 ┘  共用一欄，用分頁互斥
```

三個都是投影，而**只有一個不必跟別人搶位子**——被特別對待的那一個，
正是這個專案存在的理由要說「它不特別」的那一個（唯一真實，各式投影）。

⚠️ 它也違反了自己的宣告：`compare` 宣告 `[element, space]`，
而那一欄實際是「space **或** relation」——分頁把兩層塞進一格。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用圖挑版面，而不是用文字 (Priority: P1)

使用者點狀態列的版面那一格，看到**四張示意圖**（專注／對照／三欄／十字），
每一張畫出它有幾格、格子多大、哪一格放什麼。點下去就套用。

**Why this priority**: 這是使用者直接要的東西（「我是希望有佈局的示意圖來給使用者選」），
而且它是唯一一個**在選之前就看得懂**的選法——今天的文字列要讀完才知道差在哪。

**Independent Test**: 開啟版面選單 → 看到四張圖 → 點第三張 → 畫面變成三欄。
不需要任何其他故事完成。

**Acceptance Scenarios**:

1. **Given** 使用者在「對照」版面，**When** 打開版面選單，**Then** 看到四張示意圖，
   而「對照」那一張標示為目前
2. **Given** 版面選單開著，**When** 點「十字」那一張，**Then** 畫面變成四格
3. **Given** 任何一張圖，**Then** 圖上格子的數量與位置**與套用後的畫面一致**

### User Story 2 - 十字：四層各一格，而且切過去時東西不跳走 (Priority: P1)

使用者在大螢幕上想同時看到四層。切到「十字」之後：

```
┌─────┬─────┐
│程式碼│ 積木 │
├─────┼─────┤
│ 流程 │主控台│
└─────┴─────┘
```

**Why this priority**: 它是唯一一個**每一層都拿到同樣大小**的版面——也就是這一刀
要解決的那個不對稱的解答本身。而它與 P1 的示意圖互相需要（沒有圖就選不到它）。

**Independent Test**: 從「對照」切到「十字」，程式碼與積木的格子**左上角不動**，底下多出兩格。

**Acceptance Scenarios**:

1. **Given** 使用者在「對照」（程式碼｜積木），**When** 切到「十字」，
   **Then** 程式碼仍在左上、積木仍在右上——**兩者的左上角座標一個像素都沒動**
   ⚠️ 高度**會**變（積木在「對照」跨兩列、在「十字」佔一格），而那是十字的定義本身。
   要保證的是「**東西不跳走**」，不是「大小不變」
2. **Given** 「十字」版面，**Then** 四層各佔一格，四格等大
3. **Given** 「十字」版面的主控台那一格，**Then** 主控台與變數在那一格裡**用分頁切換**

### User Story 3 - 主控台不會被版面弄不見 (Priority: P2)

不論使用者選哪一張圖，「程式在講話的地方」都還在——只是位置不同
（三張在底部橫幅、十字在右下格）。

**Why this priority**: 它是一條**不變式**而不是新功能，但少了它，
把 `state` 交給版面決定就變成「版面可以關掉主控台」，那是退步。

**Independent Test**: 逐一套用四張圖，每一次都找得到主控台。

**Acceptance Scenarios**:

1. **Given** 四張圖的任何一張，**When** 套用，**Then** 主控台看得到
2. **Given** 「十字」，**When** 套用，**Then** 主控台在右下格而**不是**底部橫幅

### Edge Cases

- **視窗太窄時選了十字**：每格會小到不堪用。本刀**不自動切換**版面
  （那會讓「我選的版面」變成一句不算數的話），但要能手動切回去。
- **選了同一張圖**：不得重畫、不得閃爍。
- **主控台那一格內部**：變數分頁的內容不因版面改變而遺失。
- **`focus`（專注）只有一格**：它顯示哪一層，維持今天的行為（跟著使用者現在看的分頁），
  本刀不改。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：版面宣告 MUST 能表達**二維**排列（幾列、幾欄、哪一格放哪一層）。
  今天的 `layers: []` 是一維的，表達不出十字。
- **FR-002**：系統 MUST 提供四個版面：專注、對照、三欄、十字。
- **FR-003**：版面選單 MUST 以**示意圖**呈現每一個版面，而圖 MUST **從宣告產生**
  ——不得是手畫的圖檔或硬編的標記（手畫的會與宣告漂開）。
- **FR-004**：十字 MUST 是「程式碼｜積木 ／ 流程｜主控台」，四格等大。
- **FR-005**：從「對照」切到「十字」時，程式碼與積木的格子位置 MUST 不變。
- **FR-006**：`state`（主控台／變數）的**位置** MUST 由版面決定，
  而它 MUST NOT 被任何版面關掉。
- **FR-007**：十字的主控台格內，主控台與變數 MUST 以**分頁**切換（不再切一半）。
- **FR-008**：版面名稱與圖上的文字 MUST 走 i18n，MUST NOT 把內部識別字印上畫面。
- **FR-009**：三欄 MUST 維持 `程式碼│流程│積木` 的順序。
- **FR-010**：版面的左右順序 MUST 是固定的（語義），MUST NOT 提供鏡像版本。

### 明確不做（Out of Scope）

- **自由 docking**（拖放面板）——路線圖既有的排除仍然成立。
- **鏡像版面**（積木在左、程式碼在右）。
- **每個槽都有一模一樣的分頁列**——那是**下一刀**：先有對稱的槽，再談槽裡放什麼。
- 改三欄的順序。
- 行動版的版面（行動版是單槽，不在這一刀）。

### Key Entities

- **版面（Layout）**：一個具名的排列。有 id、i18n 名稱鍵，以及**一份二維的格子表**
  （每一格說出它放哪一層、佔幾列幾欄）。
- **層（Layer）**：`element` ／ `relation` ／ `space` ／ `state`，四個，已存在。
- **示意圖（Thumbnail）**：從版面的格子表算出來的圖，**不是另一份資料**。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：使用者能在**不讀任何文字說明**的情況下，從選單挑出「四格」的那個版面。
- **SC-002**：四個版面裡，主控台的可見率是 **100%**（四張都找得到）。
- **SC-003**：從「對照」切到「十字」，程式碼與積木格子的**左上角位移是 0**。
  ⚠️ 大小會變（積木從跨兩列變成一格）——那是十字的定義，不是缺陷。
- **SC-004**：新增一個版面只需要改**一份宣告**——示意圖、選單、套用三處都不用動。
- **SC-005**：十字裡四格的面積差異在 **±5%** 以內（「等大」是可量的）。

## Assumptions

- 桌機才有四張圖；行動版維持單槽（今天就是這樣）。
- 「專注」顯示哪一層維持現有行為，本刀不改。
- 分隔線仍可拖曳（既有能力），而拖曳後的比例不必跨版面記憶——
  切版面就回到該版面的預設比例。
- 十字的格子比例預設是均分（1:1 / 1:1），使用者可拖。
