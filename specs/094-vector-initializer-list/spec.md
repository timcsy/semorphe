# Feature Specification: vector 的初始化列表——四路裡壞了三路

**Feature Branch**: `094-vector-initializer-list` ｜ **Created**: 2026-08-06

## 為什麼做這個

`vector<int> v = {3,1,4}` 原本：

| 路 | 狀況 |
|---|---|
| 辨識 | 初始化列表**整段丟掉** |
| 產生 | 產回 `vector<int> v;` |
| 執行 | 空的向量 → `v[1]` 索引越界、`v.size()` 是 0 |

## ⚠️ 而來回轉換看起來「成功」

**辨識丟掉、產生也跟著少，於是來回轉換前後「一致」。**
產出的 `vector<int> v;` 是**合法程式**——編譯得過、跑得動，只是不是使用者
寫的那一段。

只有跑起來才會現形。那正是「只驗來回轉換抓不到」的典型，也是這個階段
反覆撞到的形狀（082 的字元陣列、084 的指標陣列、這裡）。

## Requirements

- **FR-001**: 辨識 MUST 接住初始化列表
- **FR-002**: 產生 MUST 把它產回去
- **FR-003**: 執行 MUST 用那些初始值
- **FR-004**: 沒有初始值時 MUST NOT 多出一對大括號
- **FR-005**: `vector<int> v(5)` 是**建構式呼叫**（`argument_list`），
  MUST NOT 被當成列表初始化
- **FR-006**: 期望值 MUST 由**真的編譯器**決定

## Success Criteria

- **SC-001**: 只有名字的測試 14 → 13
- **SC-002**: 產生與執行各有正反測試
- **SC-003**: 既有測試全數通過
