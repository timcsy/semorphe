# Feature Specification: 殼歸零——而護欄自己的錨點第四次爛掉

**Feature Branch**: `088-shells-to-zero` ｜ **Created**: 2026-08-06

## 為什麼做這個

完備性剩最後 2 個殼（`cpp_method_call_expr`、`cpp_lambda`），兩個都是量測假象
——它們的產出是**裸運算式**，當敘述放不成立。

087 試過「按角色一刀切」（把所有運算式角色的概念包進賦值），**失敗**：
殼從 2 變成 13，那 11 個原本是誠實的「判不出來」。

這一刀用**逐概念列**。代價是要維護一份清單，好處是**每一筆都可以單獨驗證
有沒有讓判定變差**。

## 結果

```
元件 178｜✅ 824｜📄 已宣告 41｜❔ 判不出來 25｜🈳 0｜❌ 0
```

**殼與缺同時歸零，而判不出來沒有增加。**

## ⚠️ 而護欄自己的錨點第四次爛掉

完備性有一支「殼與缺的總數不為零——零代表沒有真的量到東西」。
**它歸零了，所以那支變紅。**

那不是意外，是**設計上的必然**：

> 護欄修好了它要量的東西，就是它的錨點爛掉的時候。
> ——`knowledge/history/022`

**本階段第四次**（辨識歧義錨在 `declaration` 那群、雙重真相斷言「兩處都有
定義 > 10」、分類護欄錨在物件導向、這裡）。

改成**合成注入**：一個絕不會被實作的假概念，它的五路必然全缺。
外加一支對照組——沒有它，一個「什麼都判缺」的量測也會通過。

## Requirements

- **FR-001**: 需要賦值脈絡的概念 MUST **逐一列**，MUST NOT 按角色一刀切
- **FR-002**: 判不出來 MUST NOT 增加
- **FR-003**: 護欄的健康檢查 MUST 錨在合成輸入上
- **FR-004**: MUST 有對照組——否則「什麼都判缺」也會通過

## Success Criteria

- **SC-001**: 殼 **2 → 0**，缺維持 **0**
- **SC-002**: 判不出來維持 25
- **SC-003**: 既有測試全數通過
