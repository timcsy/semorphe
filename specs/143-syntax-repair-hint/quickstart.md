# 驗證指南：語法錯誤的修復提示

## ① 機械驗證

```bash
npx vitest run tests/integration/syntax-gap.test.ts
npx vitest run tests/unit/core/diagnostics.test.ts     # 既有的不得退步
npm test
```

**四種形狀各一條**（SC-001，⚠️ **逐形狀斷言，不從一個推論其他**）：

| 輸入 | 期望 |
|---|---|
| `void f() {⏎  int x = 1⏎  int y = 2;⏎}` | 缺 `;` @ 第 2 行第 12 欄 |
| `void f() {⏎  cout << "hi"⏎}` | 缺 `;` @ 第 3 行第 2 欄 |
| 巢狀區塊裡少分號 | 位置在**最內層**那一行 |
| `for (int i=0 i<3; i++)` | 缺 `;` @ 第 2 行第 15 欄 |

**兩條反向（US2，🔴 比正向重要）**：

```
一段正確的程式      → 語法診斷 0 個
void f(){ @@@ ### } → 有語法診斷，而【修復提示 0 個】，訊息與今天逐字相同
whlie (x) {}        → 🔴 不得出現「你是不是要打 while」
```

## ② 既有行為不得動

```
UNDECLARED_VAR_SUGGEST 的測試   一支都不變
Monaco 的波浪                    有 `at` 才縮到那一欄，沒有 `at` 照舊畫整行
```

## ③ 開瀏覽器（`verify-in-browser`）

| # | 這在測什麼 | 怎麼按 | 好／壞 |
|---|---|---|---|
| 1 | 學生看得到少在哪 | 貼 `int x = 1`（不加分號）→ 看程式碼那格 | 🟢 波浪**只在那一欄附近**，hover 說「少了 `;`」<br>🔴 波浪畫整行（那等於沒縮）或指錯行 |
| 2 | 積木側也說得出 | 看對應積木的 tooltip | 🟢 說得出「少了 `;`（第 N 行）」<br>🔴 只說「語法不完整」 |
| 3 | 🔴 **不亂報** | 把分號補回去 | 🟢 波浪**完全消失**<br>🔴 還在（診斷沒有被全集取代） |
| 4 | 🔴 **不亂猜** | 貼 `whlie (x) {}` | 🟢 只說語法不完整<br>🔴 出現「你是不是要打 while」 |
