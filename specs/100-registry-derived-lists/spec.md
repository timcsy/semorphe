# Feature Specification: 登錄表導出——使用者選得到的東西不該是手寫清單

**Feature Branch**: `100-registry-derived-lists`

**Created**: 2026-08-07

**Status**: Draft

**路線圖位置**: 階段 6.5 的 **E 項**（跳過 C 先做；vision 已註明 E 可與 C 並行）

## 為什麼是這個、為什麼現在

### 使用者實測發現的洞

097 做完多形態機制、測試全綠、**十七條護欄零上升**之後，使用者拖了一次積木，第一句話是：

> 「這樣會不會讓學生困擾找不到積木？」

會。變體積木做出來了，而**工具箱裡沒有**——學生只能拖中性版出來、接上變數、等它自己變。修法是兩行，但根因是：

> **工具箱的內容從來沒有人量過。** 五路完備管的是「這個元件的五條路都在」，不管「使用者找不找得到它」。

**「做得出來」與「拿得到」是兩件事，而所有既有的檢查都只量前者。**

### 它違反 P3

`principles.md:46`：

> 「系統可以在**不修改既有程式碼**的前提下加入新概念…擴充走 Layer 1（純 JSON）」

而現在加一顆元件要編輯 `toolbox-categories.ts` 的 `extraTypes`——097 加四顆變體時就編輯過。

---

## ⚠️ 先更正一處範圍：課程清單的「成員」是策展，不是碎裂

功能描述裡有一條驗收寫著「前兩大共用檔的元件提及數 **166／164 → 0**」，而同一份描述又說「`topics` 導出的是**結構**，**選擇**仍是宣告的資料」。**這兩句互相矛盾。**

讀了 `topics/cpp-beginner.json` 的實際結構之後，第二句是對的：

```
levelTree
  L0: 基礎          concepts: 19
    L1a: 函式與迴圈   concepts: 20
      L2a: 陣列與字串  concepts: 33
        L3a: STL 容器   concepts: 25
```

**那是一條教學漸進線。** 「`vector` 屬於 L3a 而不是 L0」是人的判斷，導不出來——導出它等於用演算法決定教學順序。

**所以 166／164 那兩個數字不會歸零，也不該歸零。** 真正錯的是**量測**：就近性護欄把它們算成「實作擴散」，而課程清單不是實作。

> 這與 097 的完備性 harness 是同一個形狀——**量測把不是那件事的東西算了進去**，而修法是修量測，不是刪資料。

## User Scenarios & Testing

### User Story 1 — 學生找得到每一顆積木 (Priority: P1)

一個學生在工具箱裡找「把元素加到佇列尾端」。**只要那顆積木存在，他就應該找得到。**

**Why this priority**：這是使用者實際回報的問題，也是這個功能存在的理由。

**Independent Test**：列出所有有積木投影的元件，逐一確認它在某個工具箱分類裡拿得到。

**Acceptance Scenarios**：

1. **Given** 一顆有積木投影的元件，**When** 打開工具箱，**Then** 它出現在某個分類裡
2. **Given** 一顆**中性形態**（型別查不到時的退路），**When** 打開工具箱，**Then** 它**不出現**——那不是一個選項
3. **Given** 工具箱裡的任一項，**When** 對照登錄表，**Then** 那個積木型別確實存在

---

### User Story 2 — 加一顆元件不必編輯任何清單 (Priority: P1)

維護者（或未來的社群貢獻者）新增一顆元件。他寫概念定義與積木投影，**不需要去任何清單裡登記它**。

**Why this priority**：這是 P3 的直接要求，也是「導出」與「把手寫換個地方」的分界線。

**Independent Test**：合成一顆新元件宣告，確認它**自動**出現在工具箱裡。

**Acceptance Scenarios**：

1. **Given** 一顆新宣告的元件（有積木投影、有分類），**When** 不編輯任何清單，**Then** 它出現在對應的工具箱分類
2. **Given** 同一顆元件，**When** 刪掉它的宣告，**Then** 工具箱裡也不再有它——**不留下懸空的項目**

---

### User Story 3 — 教學順序不被演算法決定 (Priority: P1)

課程設計者決定「`vector` 在 L3a、`cout` 在 L0」。那個判斷**必須留在人手上**。

**Why this priority**：導出得太多會刪掉教學設計，而那個損失不會有測試抓到——它只會讓課程變難教。

**Independent Test**：對照改動前後的課程清單，分組、順序、成員一字不差。

**Acceptance Scenarios**：

1. **Given** 改動前的課程清單，**When** 改動後重新產生，**Then** 每一層的標題、順序、成員完全相同
2. **Given** 課程清單引用一顆**不存在**的元件，**When** 檢查，**Then** **出聲**——那是清單爛掉了
3. **Given** 一顆新元件沒有被任何課程收錄，**When** 檢查，**Then** **報出來但不算違規**——沒收錄是策展決定，不是缺陷

## Requirements

### 工具箱：全導出

- **FR-001**: 每一顆有積木投影的元件 MUST 在某個工具箱分類裡拿得到
- **FR-002**: 工具箱 MUST NOT 指向不存在的積木型別
- **FR-003**: 加一顆元件 MUST NOT 需要編輯任何清單
- **FR-004**: **中性形態 MUST NOT 出現在工具箱**——它是型別查不到時的退路，不是選項（097 定下的原則）
- **FR-005**: 分類的**順序與標題** MUST 仍是宣告的資料——分類是教學設計

### 課程清單：策展保留，但不得爛掉

- **FR-006**: 課程清單的**成員** MUST 仍是人選的——MUST NOT 從登錄表導出
- **FR-007**: 課程清單引用不存在的元件 MUST 出聲
- **FR-008**: 未被任何課程收錄的元件 MUST 被報出，但 MUST NOT 算違規

### 量測

- **FR-009**: 就近性 MUST 把「清單」與「實作」分開計——課程清單不是實作擴散
- **FR-010**: 分類規則 MUST 可機械判定，MUST NOT 是一份檔名清單

### 不得退步

- **FR-011**: 工具箱與課程清單的產出 MUST 與改動前**一字不差**
- **FR-012**: 全套測試 MUST 綠；其餘護欄 MUST NOT 上升

## Success Criteria

- **SC-001**: 每一顆有積木投影的元件都在工具箱裡拿得到——**目前沒有任何檢查在看這件事**
- **SC-002**: 新增一顆合成元件，**不編輯任何清單**，它自動出現在工具箱
- **SC-003**: 工具箱與兩份課程清單的產出與改動前逐項相同（分組／順序／成員）
- **SC-004**: 就近性報表把課程清單歸為「清單」而非「實作」，且該分類有雙向注入測試
- **SC-005**: 全套測試綠，其餘護欄無一上升

## Out of Scope

- **C 項全部**：ParamSpec 結構化、資訊軸（邊）、componentId 型別化
- **膠囊搬家（F）**
- **課程內容的重新策展**——只改「怎麼表達」，不改「選了哪些」
- **圖鑑介面**：`元件.md` 說 toolbox 與 codex 是同一個東西，但做出圖鑑是硬體域併入時的事

## Assumptions

- **工具箱該顯示全部**：一顆使用者選得不到的元件，等於不存在。若某顆刻意不給使用者選，那要**明確宣告**（與 `skipPaths` 同一種紀律），不是靠「忘了加進清單」。
- **分類已經半導出**：`ToolboxCategoryDef` 已有 `registryCategories`（從積木 JSON 的 `category` 欄位拉）；手寫的是 `extraTypes`。所以這不是從零建，是**把 `extraTypes` 消掉**。
- **課程清單的層級是教學漸進線**：`L0 基礎 → L1a 函式與迴圈 → L2a 陣列與字串 → L3a STL`，那是人的判斷。

## Risks & Mitigations

| 風險 | 來源 | 緩解 |
|---|---|---|
| 導出後順序／分組變了 → 使用者找不到東西 | 順序是教學設計 | 先拍完整快照，逐項比對，一字不差才算過（SC-003） |
| 「導出」變成另一份手寫 | 只是換個檔案 | SC-002 用**合成元件**驗證自動出現 |
| 把課程清單當全集導出，刪掉教學設計 | 兩種清單混為一談 | FR-006 明訂成員是人選的 |
| 為了讓數字好看而改量測 | `history/018`「用宣告刷數字」 | FR-010 要求分類規則可機械判定；SC-004 要求雙向注入 |
| 全導出之後工具箱塞滿噪音 | 175 顆元件 | FR-004 排除中性形態；其餘若真的不該給使用者選，要**明確宣告**而不是省略 |
