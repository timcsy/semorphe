# 撞到的坑

> 2026-08-17，spec `134`。而**兩個最重要的坑都是「我以為不存在的東西已經存在」**。

## 🔴 一、plan 的實作順序被推翻：沒有欄位標得出「這是 C」

plan 寫「②（修 6/10）在③（target）之前——`c-style-parity` 不需要 target」。
**動手時發現那是錯的。** 四個風格實測：

```
io: printf          🔴 競賽也是——而它是 C++
namespace: explicit 🔴 google 也是——而它是 C++
兩者合取             今天只有 c 命中，而那是【巧合，不是宣告】
```

> **一個靠既有欄位合取推出來的身分，不是一個身分——
> 它只是今天剛好沒有別人命中。**

🟢 **而它反而證明了 target 的必要性**：`draft` 說 target 是「把三個既有欄位
綁成一個**具名的**組合」，而**「具名」不是便利——那個組合本身就是一個身分**。
沒有名字的時候，只能靠合取去猜它。

**處置**：規則錨在**風格自己的 `id`**（一個具名的宣告），順序改成 target 先。

## 🔴 二、「標頭名對映表今天不存在」——錯的，它是 19 筆，而且反向表也在

research Q2 說它不存在，spec 的 Key Entities 說它是「本功能唯一新增的資料」。
**兩者都錯。** `src/languages/cpp/header-aliases.ts` 有 `C_TO_CPP`（19 筆）
**與 `CPP_TO_C`（反向，已經建好）**。

⚠️ **而我兩次查證都沒找到它**：

```
第一次   grep requires   → 只看到元件宣告的【C++ 名字】
第二次   數 c* 那一族     → 數的是【元件宣告了什麼】，不是【系統認識什麼】
```

> **「這個東西存在嗎」與「這個東西被誰宣告」是兩個問題，
> 而我兩次都問了第二個。**

🟢 **所以本功能新增的資料是零** ——只多了一個 `toCHeader()` 包一層。

## ⚠️ 三、而 research Q2 那個「5 筆 vs 13 筆」的拆分仍然成立

雖然表已經存在，但**那個拆分本身是對的且有用**：

```
有兩個名字   5 種（c* 族）    → 對映表
在 C 裡不存在 13 種            → 🔴 那是【可見範圍】的責任，不是對映表的
```

而 10/10 通過**沒有用到那 5 筆的任何一筆**——中性語料裡沒有人 include `<cstdio>`。
⚠️ **所以標頭名轉換這一段【今天沒有測試在看】**，它只有在
「使用者手寫 `#include <cstring>` 且切到 C 目標」時才會走到。

## 🔴 四、**兩條產出路徑，而測試只走其中一條**——這一輪最貴的坑

`c-style-parity` 修到 **10/10**。**而開瀏覽器一看**：

```
#include <iostream>     🔴 C 裡沒有這個東西
using namespace std;    🔴 C 裡不合法
bool b = 1 == 2;        而 <stdbool.h> 沒補
printf("%d\n", b);      ✅ 只有這一行是對的
```

根因：`cpp:program` 有**兩條產出路徑**——**有鷹架的（UI 走）**與
**legacy 的（測試走）**。第一版只改了 legacy。

> **一份只走得到其中一條路徑的測試，會讓另一條路徑的缺陷全綠通過。**

⚠️ 而 `experience`「重構後開瀏覽器實測」正是為這一族寫的——**這一次是它抓到的**。
→ 收成 `e2e/c-target.spec.ts`，**兩條路徑都被釘住**。

## 🔴 五、而追下去撞到一個更深的根因：**宣告假設了一種產出風格**

補 `<stdio.h>` 時發現：`cpp:print` 的 `requires` 宣告的是 **`<iostream>`**
——**而它用 `printf` 產出時要的是 `<stdio.h>`**。

```
宣告   <iostream>          一顆元件說「我需要什麼」
產出   printf(...)         而那需要 <stdio.h>
```

⚠️ **`style-exceptions` 已經在【分析】同一件事**（`IO_PREF_TO_HEADER`），
**而產出這一側今天沒有人接**。

> **一顆元件宣告它需要什麼，而那個宣告【假設了一種產出風格】。**

🔴 本輪用最小的補法（照 `io_style` 補 `<stdio.h>`），**而根因留著**：
`requires` 應該是 `(概念, 風格) → 標頭`，而不是 `概念 → 標頭`。
⚠️ 那正是 `target` 完整設計裡 **`provides` 那一格**要解的事。

## 因為知道答案而跳過的地方

1. ~~UI 接上沒做~~ ✅ **做了**——而過程中發現 🔴 **`c.json` 從來沒進過選單**，
   它只活在測試裡。**本輪修好的 10/10，在接上選單之前沒有任何人拿得到。**
   ⚠️ 那正是「機制有了沒人接上」的**第六次**，而它差一點發生。
   （⚠️ 而 `Target` 型別本身**仍然沒有選單**——本輪接的是 C **風格**。
   target 的 UI 是下一輪。）
2. **`provides`／`reference` 兩格沒做**——spec 明確排除，而
   `target-dialect.ts` 檔頭寫了限定。
3. **`usesBool` 只看 `type === 'bool'` 與 true/false 字面值**
   ——⚠️ 沒有涵蓋 `bool` 出現在函式回傳型別或參數的情形。
4. **標頭名轉換沒有測試**（見上）。

```
② 「新增的資料」       1 張表 → 0

④ 兩個沒測到的路徑     標頭名轉換、bool 在簽章裡
```
