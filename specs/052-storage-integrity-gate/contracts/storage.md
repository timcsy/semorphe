# 介面契約：存檔服務

**消費者**：應用程式外殼（自動載入／自動存檔／匯入匯出）
**穩定性**：`load` / `save` / `importFromJSON` 的既有簽章**不改**（FR-042）

---

## 既有介面（不變）

| 方法 | 簽章 | 本功能的改動 |
|---|---|---|
| `save` | `(state: Partial<SavedState>) => boolean` | 內部改用展開合併；**行為只在「原本會丟欄位」時不同** |
| `load` | `() => SavedState \| null` | 內部委派給 `loadOutcome()`；**回傳合法存檔時行為完全相同** |
| `importFromJSON` | `(json: string) => SavedState \| null` | 改用共用判定；`version` 從「檢查存在」變為「檢查值」 |
| `clear` / `exportToBlob` / `downloadBlob` | 不變 | 無 |

### `load()` 的語義收窄（唯一的行為改動）

| 輸入 | 現況 | 本功能後 |
|---|---|---|
| 合法存檔、版本相同 | 回傳 | **回傳（相同）** |
| 版本較高 | 回傳 | `null`（並備份、並可查得原因） |
| 版本較低、有升級路徑 | 回傳（未升級） | 升級後回傳 |
| 版本較低、無升級路徑 | 回傳 | `null`（並備份） |
| 不是存檔形狀 | **原樣回傳** | `null`（並備份） |

**「回傳的東西可能不是存檔」是一種型別謊言。** 收窄它是本功能的目的，不是副作用。

---

## 新增介面

```ts
loadOutcome(): LoadOutcome
```

三態以上的載入結果（data-model 契約 2）。`load()` 是它的相容包裝。

**呼叫端契約**：想區分「沒有存檔」與「存檔被拒絕」的，用這個；只要狀態的，繼續用 `load()`。

---

## 判定模組（新檔）

```ts
judge(raw: unknown): VersionVerdict
CURRENT_VERSION: number
UPGRADES: Record<number, Upgrade>
SAVED_STATE_FIELDS: Record<keyof Required<SavedState>, 1>
```

**唯一性要求**：`load` 與 `importFromJSON` **都必須**經由 `judge`。
違反的偵測方式：兩條路徑對同一份輸入必須得到相同判定——這是一支測試（FR-010）。

---

## 護欄契約

**量什麼**：存檔完整性的違規數，分三類

| 類別 | 定義 | 目前基線 |
|---|---|---|
| 欄位不守恆 | 存入後讀不回原值的欄位數 | **2**（`blockStyleId`、`locale`）→ 目標 0 |
| 判定不一致 | 兩條讀取路徑對同一輸入判定不同的情形數 | **待量** → 目標 0 |
| 缺升級路徑 | `CURRENT_VERSION` 需要但未註冊的版本步數 | **0**（恆真，因為 `CURRENT_VERSION=1`） |

**棘輪**：三個數字皆只准下降。

**失效樣態聲明（FR-031）**：

> ⚠️ 如果「欄位不守恆」在修好之前**不是 2**，代表本護欄壞了，不是欄位沒問題。
> ⚠️ 如果「缺升級路徑」在 `CURRENT_VERSION > 1` 時仍是 0 而 `UPGRADES` 是空的，代表本護欄壞了。

**不檢測聲明（FR-032）**：

> 本護欄**不檢測**：存檔內容的語義正確性（語義樹是否可用）、瀏覽器本地儲存以外的後端、
> 存檔前先讀舊檔再合併所造成的污染傳播（已知、刻意留著、由另一支測試釘住）。

**自我驗證釘住的是理由（FR-033）**：

不只斷言「`blockStyleId` 被報為不守恆」，還要斷言**報出的理由是「存入後讀回為 undefined」**。

> 上一輪的教訓：051 的自我驗證測試通過了，但它只釘「這一群必須被報出來」。
> 結果護欄因為**正確的事實**得到了我**錯誤的結論**，而測試看不出差別。
> **一個因為錯誤理由而給出正確結果的護欄，看起來與健康的完全一樣。**
