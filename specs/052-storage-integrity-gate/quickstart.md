# 驗收指引：存檔完整性

跑法：

```bash
npx vitest run tests/unit/core/storage.test.ts \
              tests/unit/core/storage-version.test.ts \
              tests/integration/audit-storage-integrity.test.ts
npm test   # 全套，確認五項量測未上升
```

---

## 情境 0（先跑）：把「拒絕變成刪除」那條鏈跑出來

**這是實作的第一件事，不是最後一件。**

research F3 的四步鏈是**推理**，每一環都查證過程式碼，但沒有實際跑過。

- **跑得出來** → US3 的設計成立，往下做
- **跑不出來** → 有一環讀錯了，**US3 要重新設計**，不要照著寫

驗收：一支測試證明「放一份會被拒絕的存檔 → 觸發載入 → 觸發自動存檔 → 原資料消失」在**修好之前**確實會發生。

---

## 情境 1：兩個選擇下次還在

存一份帶 `blockStyleId` 與 `locale` 的狀態、讀回來。

**修好前**：兩個都是 `undefined`。
**修好後**：兩個都是原值。

## 情境 2：每一個欄位都守恆

存一份**填滿所有欄位**的狀態、讀回來、逐欄位比對。

失敗訊息必須**指名是哪個欄位**（FR-003）——只說「不相等」的話，讀的人還得自己去查。

**同時驗執行機構本身**：在 `SavedState` 加一個假欄位而不加進 `SAVED_STATE_FIELDS` → **應該編不過**。

## 情境 3：三種版本，三種結果

| 存檔版本 | 期望 |
|---|---|
| 高於當前 | 拒絕、備份、`too-new`、使用者看得到 |
| 低於當前且有升級路徑 | 升級後正常載入 |
| 低於當前且無升級路徑 | 拒絕、備份、`no-upgrade-path` |
| 等於當前 | 正常載入，**與現況完全相同** |

## 情境 4：不是存檔的東西

`{hello:'world'}`、`'not json'`、`{version:'abc'}`、缺必填欄位的物件 → 全部 `not-a-save`。

**反向**：合法存檔**多帶**一個不認得的欄位 → **必須通過**（FR-017），且該欄位在下次存檔後仍在。

## 情境 5：拒絕不等於丟掉

1. 放一份會被拒絕的存檔
2. 觸發載入 → 拒絕
3. 觸發自動存檔（模擬使用者動了積木）
4. **原始內容仍完整存在於備份鍵**
5. 使用者收到一則訊息，說得出「有一份存檔沒載入」與原因

## 情境 6：調版本號會出聲

把 `CURRENT_VERSION` 改成 2 而不註冊 `UPGRADES[1]` → **測試變紅**。

改完記得改回來——這是**手動驗一次**的情境，不是留在套件裡的測試。

## 情境 7：護欄自己不會安靜地量錯

- 報表開頭有失效樣態聲明與「不檢測什麼」
- 自我驗證測試釘住的是**理由**：不只斷言 `blockStyleId` 被報出來，還要斷言報出的**原因**是「存入後讀回為 undefined」
- 三個數字進基線，只准下降
