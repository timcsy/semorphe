# Feature Specification: 重新產生解鎖了的 todo——而它們立刻抓到一個真缺口

**Feature Branch**: `081-regenerate-oop-todos` ｜ **Created**: 2026-08-06

## 為什麼做這個

缺陷帳裡有 **64 支只有名字的測試**（`it.todo`，沒有測試本體）。它們與 21 支
「真的測試被關掉了」是**兩種東西**：後者修好缺口就能開回來，前者要**重新
產生**。

071–080 實作了整套物件導向，其中幾支 todo 的阻斷者已經不存在了。

## ⚠️ 重新產生，不是把 todo 改成 it

`it.todo('…')` 沒有測試本體。把它改成 `it('…', () => {})` 會讓缺陷帳的數字
下降而**什麼都沒多驗到**——那是用改標記刷數字。

每一支都要寫出真的程式、真的斷言。

## 而它們立刻抓到一個單元測試漏掉的真缺口

解構式那支重新產生之後**失敗了**：輸出是 `00-` 而不是 `21-`。

追下去：`a.n = 1;` 從**真實原始碼**辨識出來的形狀是
`var_assign { name: "a.n" }`——**點號編在名字字串裡**。而 071 的單元測試
手寫的是 `var_assign { name: 'p', member: 'x' }`。

**那個形狀沒有任何生產者。** 單元測試手寫節點時通過了，從真實原始碼跑卻
完全沒有效果——**「測試通過卻什麼都沒測到」，而這次是我自己的測試**。

> 手寫語義節點的測試，要用**生產者真正產出的形狀**。
> 手寫一個沒有人產出的形狀，測試會通過而什麼都沒驗到。

四個 OOP 單元測試檔已全部改用真實形狀。

## Requirements

- **FR-001**: 解鎖了的 todo MUST 重新產生成有本體的測試
- **FR-002**: MUST NOT 只把 `it.todo` 改成 `it`
- **FR-003**: 執行器 MUST 認得辨識器真正產出的成員指派形狀
- **FR-004**: 手寫節點的單元測試 MUST 改用真實形狀

## Success Criteria

- **SC-001**: 只有名字的測試 **64 → 62**
- **SC-002**: 重新產生的每一支都有真的程式與斷言，且**執行結果**被驗證
- **SC-003**: 既有測試全數通過
