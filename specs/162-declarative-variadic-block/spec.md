## 第 0 步：先治那支偶發

`bus-update-not-user-edit` 一個 session 裡紅了四次，單獨跑卻全過。
根因是**靠固定時間等**（`tick()` = 60ms），而重畫的「不記復原」窗口是
`requestAnimationFrame → setTimeout(0)` 關的。

而它非治不可：這一刀要跑幾十次全套，**一支會亂叫的測試會讓整個訊號不可信**
——專案自己的判準是「亂叫的護欄很快就會被忽略」。

三層修法 ＋ **對照實驗**（8 個 CPU 燒滿，load 42）：

```
修好的                      4/4 全過
對照組（預算改回 60ms）      2 紅 / 1 紅
```

🔴 第三層最值得記：**缺席斷言**（「堆疊仍是空的」）等不到正向訊號
→ 把窗口狀態做成**可觀察的**（`isRedrawWindowOpen()`），等它**真的關了**再斷言。

## 本體


→ 新增 `src/ui/variadic-block.ts`：依宣告建 `init`／`plus_`／`minus_`／
`saveExtraState`／`loadExtraState`。

## 🔴 判準：顯式選入，不從 `dynamicRules` 推論

第一版的判準是「有單一 `inputPattern` 且沒有 `message0`」——**太鬆**。
`cpp_vector_declare` 也符合，而它另有型別下拉與名稱欄位，
宣告式建構器會**把它們全部弄丟**——**而沒有任何測試在看標籤與欄位**
（工具箱快照只比 id 與順序）。

> **「符合這個形狀」不等於「只有這個形狀」。**

🟢 改成 `blockDef.builder === "variadic"`，一顆一顆選入，**每顆都開瀏覽器看**。
