# 撞到的坑

> 2026-08-15。spec `127`。

---

## 🔴 一、課文裡有一句話，是**系統做不到的**

第二課「換你了」原本逐字：

> 「⚠️ **一個小提醒**：如果你想再開一個名字（例如 `bonus`），
> 記得**前面要加 `int`**——不然就會看到第三步那句話。」

**實測（改之前）**：

```
int score = 90;
bonus = 5;                 ← 沒有 int
score = score + bonus;
→ ✅ 跑完，輸出 "分數是 95"    🔴 不會看到任何話
```

**卡的是說明還是工具**：**兩者都是**，而這一次**說明錯得比較重**。

> 🔴 **繞路是「不講」，這是「講錯」。**
> 一個學生照著做會發現「老師說會出錯，而它沒有」——
> **而那會讓他不再相信課文其餘的部分。**

⚠️ **它是怎麼混進去的**：寫課文的人（我）知道 C++ 的規則，
**而沒有去試系統做不做得到**。

🔴 **與 `126` findings 坑一是同一個病，同一輪**（「課文沒說要按那個鈕」）：

> **兩次都不是「寫錯字」，是【把自己知道的事當成系統會做的事】。**

**處置**：本功能讓那句話成真，並把它升格成**第五步**（讓學生真的試一次）。
⚠️ 而**更根本的處置**是走查測試——課文引用的每一句現在都被逐字釘住。

---

## 🔴 二、只把最後一行改成拋，行為**完全不會變**——而它看起來像修好了

舊寫法逐字（`scope.ts:44-51`）：

```ts
if (this.parent) {
  try {
    this.parent.get(name)      // ← 只為了「看看有沒有」
    this.parent.set(name, value)
    return
  } catch { /* not found in parent, fall through */ }
}
this.variables.set(name, value)   // ← 想改的是這一行
```

**改成拒絕之後 `parent.set()` 也會拋**，而那個 `catch` 把它吃掉，
控制流照樣掉到最後一行。

> **一個為了「看看有沒有」而存在的 try/catch，
> 在被查的那件事本身開始拋錯的那天，會靜靜地把新行為吃掉。**

⚠️ **而單元測試看不見它**——單元測試直接呼叫 `set`，不走那條遞迴路徑。
🔴 **所以 spec 要求驗證必須是「行為端」**（跑一段真的程式），
而那一條是在 plan 階段查出來的，不是撞出來的。

**處置**：拿掉 try/catch，改成單純遞迴——拋自然從最外層傳上來。
**淨減少程式碼。**

## ⚠️ 三、`findOwner()` 是一個看起來對而會靜默壞掉的捷徑

`Scope` 有一個現成的 `findOwner(name)`，用它可以寫得更短。
**而它只看 `variables`，不看 `refs`**（`scope.ts:57-60`）
——父層宣告的**引用別名**（`int& r`）會被判成未宣告。

**沒有撞到**，因為 plan 階段查了它。⚠️ 而基準表第四列（引用別名寫入 → `11`）
就是為它量的。

> **一個「更短的寫法」如果覆蓋範圍比原本窄，它省下的行數會用一個
> 靜默的錯誤付回來。**

## 🟢 四、FR-006：指標寫入那條路徑，**一起改沒事**

`pointer_assign/execute.ts:30` 有一個 `else ctx.scope.set(targetName, val)`
——那是唯一可能真的需要隱式建立的路徑。

**結論：它是防禦性的，不是功能性的。**

- **理由**：`&x` 這個運算**本身要求 `x` 已經宣告過**
  （`address_of` 走 `ctx.scope.get(name)`，讀不到就拋）
- **證據**：`int x = 1; int* p = &x; *p = 7;` → 改前改後**都輸出 `7`**
  （已收成 `tests/integration/undeclared-assign.test.ts` 的「不亂報」那組）

⚠️ **而它有一個沒被驗到的形狀**：`ctx.pointerTargets` 沒有那個名字、
而那個名字也不在任何作用域裡。**今天走不到，而如果哪天走得到，
它會拋而不是建立**——那是對的，只是**沒有測試釘住它**。

## 🟢 五、爆炸半徑的量測是準的（而它被寫成了驗收）

```
規劃階段量的   注入嚴格版跑全套 → 只有 1 支失敗
實作之後       npm test 4168 → 4175 全綠（+6 行為端 +1 單元）
```

⚠️ 而 spec 把它寫成 **SC-002**（「失敗數 = 1，大於 1 就停下來重新評估」）
而不是前提。

> **一個寫成前提的數字，在它變了的時候沒有任何東西會擋；
> 寫成驗收才會。而這個功能的整個賣點就是「它很便宜」
> ——便宜本身必須是可否證的。**

---

## 因為知道答案而跳過的地方

1. **第五步的「加回 `int`」那一步** → 我直接寫了正確版本，
   ⚠️ 而學生要**自己把 `int ` 打進去**——那個動作沒有被走過
2. **第五步之後「換你了」** → 兩步之間沒有停頓，
   而學生可能在第五步就累了
3. ⚠️ **「那一行永遠跑不到」那個限定** → 我寫進課文了，
   **而沒有讓學生試一次**（例如放進一個不成立的 `if`）
   ——🔴 那是一個**只有敘述沒有演練**的知識點

---

## 沒有卡的地方

- 三個概念的上限**沒有被打破**——第五步是概念一（宣告）的第二次演練
- 第三步與第五步的「同一句話」呼應**寫完就成立**，沒有回頭改
- 不亂報那三個形狀（指標／外層／引用）**一次都沒有紅過**
