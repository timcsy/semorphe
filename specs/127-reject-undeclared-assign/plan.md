# Implementation Plan: 指定給一個沒宣告的名字，必須停下來

**Branch**: `127-reject-undeclared-assign` | **Date**: 2026-08-15 | **Spec**: [spec.md](spec.md)

## Summary

`Scope.set` 找不到那個名字時**默默把它創出來**，而同一個類別的 `get` 為同一件事
拋錯。**讀會拋，寫不會。** 改成一致，拆掉唯一擋著的那支測試（它斷言的正是這個
缺陷，而**沒有寫理由**），並讓第二課從「繞路」變成「正面教」
——⚠️ **而課文裡有一句話今天是假的，本功能讓它成真**。

## Phase 0：Research

✅ 完成 → [research.md](research.md)。三個決策，其中兩個推翻了原本的設想：

- 🔴 **`catch` 會吞掉新行為**——只改最後一行的話，**行為完全不變，
  而它會看起來像修好了**
- 🔴 **課文有一句話今天是假的**（實測：`bonus = 5;` 不加 `int` → 輸出 `分數是 95`）

### 已量的基準（改之前，四個形狀）

```
課文那句提醒（bonus 不加 int）   ✅ 跑完，輸出 "分數是 95"   🔴 課文說會出錯 → 假的
指標寫入（&x 後 *p = 7）        ✅ 跑完，輸出 "7"           ← 改完必須還是這樣
外層作用域寫入（迴圈內改 n）      ✅ 跑完，輸出 "4"           ← 同上
引用別名寫入（int& r）           ✅ 跑完，輸出 "11"          ← 同上
```

⚠️ **後三個是「不亂報」那一側**（`build-guardrail` 第 9 步）——
它們今天綠、改完也必須綠，而**那比第一個更重要**。

## Phase 1：Design

### 唯一的行為改變

```
名字的查找鏈，收尾行為

之前   讀 → 找不到就【拋】        寫 → 找不到就【建立】   🔴 不一致
之後   讀 → 找不到就【拋】        寫 → 找不到就【拋】     ✅ 一致，同一則訊息
```

### 🔴 而寫法必須是遞迴，不是「只改最後一行」

```
本層有引用別名 → 委派給它指向的地方
本層有這個名字 → 寫入
有父層         → 交給父層（遞迴）——拋會自然從最外層傳上來
都沒有         → 拋
```

⚠️ **不得用 `findOwner()`**：它**只看變數不看引用別名**，
用它會讓「引用別名的寫入」靜默地被判成未宣告
——而上面的基準表第四列正是為它量的。

### 契約（本功能對外的一個承諾，與一句限定）

- **承諾**：對一個在任何可見範圍內都沒有宣告過的名字指定值，執行會停下來，
  訊息含那個名字，且**與讀的那一則相同**。
- 🔴 **限定**（FR-008，三處）：**這是執行期，不是編輯期。**
  一段有這個錯誤而**永遠跑不到那一行**的程式，仍然會「成功」。

### 第二課改兩處

```
① 「換你了」那句提醒   從【假的】變成【真的】——本功能讓它成立
② 第四步後加一小步     讓學生【真的試一次】不加 int，看系統怎麼說
```

⚠️ ② **不是第四個概念**——它是概念一（宣告）的第二次演練，
而第三步已經用「讀」的版本演練過一次。**三個概念的上限沒有被打破。**

## 實作順序（依賴決定）

```
① 先寫【行為端】的失敗測試（跑一段程式，斷言它會停）   ← TDD，而且必須是行為端
② 改 Scope.set（遞迴，拿掉 try/catch）
③ 那支擋牆測試改成斷言拒絕 ＋ 【寫下理由】
④ 🔴 檢查點：跑全套。失敗數 > 1 → 停下來重新評估（SC-002）
⑤ 指標／外層／引用三個形狀單獨驗（對照 Phase 0 的基準表）
⑥ 第二課兩處 ＋ 走查測試
⑦ 三處限定 ＋ findings
```

⚠️ **①必須是行為端**——`research` Q2：只看單元測試的話，
「`catch` 吞掉新行為」這個失敗模式**看不見**（單元測試直接呼叫 `set`，
不經過那條遞迴路徑）。
