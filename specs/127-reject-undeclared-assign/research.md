# Research：指定給一個沒宣告的名字，必須停下來

**Date**: 2026-08-15

本檔只記**查證過的地面真相**與**它推翻了什麼**。所有行號可 grep。

---

## Q1（checklist 的第一個問題）：指標寫入那條路徑要不要一起改？

### 那條路徑逐字

```
src/components/cpp/pointer_assign/execute.ts:29-30
  if (targetScope) targetScope.set(targetName, val)
  else ctx.scope.set(targetName, val)
```

`targetName` 來自 `ptrVal.value`——**符號式指標存的是「它指向哪個名字」**
（`int x; int* p = &x; *p = 7` → `targetName === 'x'`）。

### 決策 1：**一起改，不留例外**

- **Rationale**：`&x` 這個運算**本身要求 `x` 已經宣告過**
  ——`address_of` 走 `ctx.scope.get(name)`，讀不到就已經拋了。
  所以走到 `:30` 時 `targetName` **必然宣告過**，那個 `else` 分支
  **是防禦性的，不是功能性的**。
- ⚠️ **而「必然」是推論，不是量測**——所以 tasks 有一個**單獨的檢查點**
  （`build-guardrail`：「宣稱這 N 筆是同一個根因之前，
  在其中至少兩筆上分別驗過」）。
- **Alternatives considered**：
  - **保留隱式建立當例外** ❌ `specs/120` 的 research 記過：
    「**一個判準如果對某一側天然無作用，就不要為那一側寫例外
    ——例外會變成一個沒有人維護的分支**」
  - **先改主路徑，指標留到下一輪** ❌ 那會讓「同一件事有兩種行為」
    活在系統裡，而**沒有任何東西記得它**

## Q2（🔴 最可能默默壞掉的地方）：例外當控制流

### 今天的寫法逐字（`scope.ts:44-51`）

```ts
if (this.parent) {
  try {
    this.parent.get(name)      // ← 只為了「看看有沒有」
    this.parent.set(name, value)
    return
  } catch {
    // not found in parent, fall through
  }
}
this.variables.set(name, value)
```

🔴 **改成拒絕之後，那個 `catch` 會吞掉真正的錯誤**：
`parent.set()` 現在也會拋，而它拋的**正是我們要讓使用者看到的那一則**
——被 `catch` 吃掉之後，控制流會掉到最後那行，**行為完全沒變**。

> **一個為了「看看有沒有」而存在的 try/catch，
> 在被查的那件事本身開始拋錯的那天，會靜靜地把新行為吃掉。**

### 決策 2：**拿掉 try/catch，改成單純遞迴**

```
本層有 ref     → 委派
本層有這個名字 → 寫入
有父層         → 交給父層（遞迴）
都沒有         → 拋
```

- **Rationale**：遞迴讓「拋」自然從**最外層**傳上來，
  而中間每一層都不需要知道「找不到會怎樣」。
  ⚠️ **而它同時修掉了那個 catch**——不是順手，是**必須**。
- ⚠️ **不能改用 `findOwner()`**：那個方法**只看 `variables`，不看 `refs`**
  （`scope.ts:57-60`），而父層宣告的引用別名要靠 `refs` 才找得到。
  🔴 **用它會讓引用別名的寫入靜默地變成「未宣告」**。
- **Alternatives considered**：
  - **保留 try/catch，只在最後一行改成拋** ❌ 見上，**行為不會變**
    ——⚠️ 而它會**看起來像修好了**，那是最糟的一種
  - **加一個 `has(name)` 方法給 set 用** 🟡 可行，而遞迴更短且少一個 API

## Q3：第二課改哪一段？

### 🔴 而查證撞到一件比「改哪一段」更嚴重的事

第二課「換你了」逐字：

> 「⚠️ **一個小提醒**：如果你想再開一個名字（例如 `bonus`），
> 記得**前面要加 `int`**——不然就會看到第三步那句話。」

**那句話今天是假的。** `bonus = 5;` 不加 `int` **不會**看到第三步那句話
——它會**默默成功**。

> 🔴 **課文為了教一條對的規則，寫了一句系統做不到的話。**
> 而那比繞路更糟：繞路是「不講」，這是「講錯」。

⚠️ 它是怎麼混進去的：寫課文的人（我）知道 C++ 的規則，
**而沒有去試系統做不做得到**——與 `126` findings 的坑一（
「課文沒說要按那個鈕」）**同一個病，同一輪**。

### 決策 3：第二課改**兩處**，而不是一處

```
① 「換你了」的那句提醒   從【假的】變成【真的】——本功能讓它成立
② 第四步加一個小步驟     讓學生【真的試一次】不加 int，看系統怎麼說
```

- **Rationale**：② 不是新概念——它是**概念一（宣告）的第二次演練**，
  而第三步已經用「讀」的版本演練過一次。
  ⚠️ **三個概念的上限沒有被打破**（checklist 的 Q3 要求確認這件事）。
- 🔴 **而 ① 是必須的**：一句假的提醒留在課文裡，
  學生照著做會發現「老師說會出錯，而它沒有」——
  **那會讓他不再相信課文其餘的部分**。
- **Alternatives considered**：
  - **只改①，不加步驟** 🟡 便宜，⚠️ 而那讓這個修法**沒有正面的教學使用**
    ——課文只是不再說謊，而沒有用到新能力
  - **另開第三課講宣告** ❌ 宣告是第二課的概念一，搬走它第二課就空了

---

## 決策彙總

1. **指標寫入一起改**——`&x` 已經要求宣告過，那個分支是防禦性的
   ⚠️ 而「必然」是推論，tasks 有單獨的檢查點
2. 🔴 **拿掉 try/catch 改遞迴**——否則 `catch` 會吞掉新行為，
   而**看起來像修好了**
3. **第二課改兩處**——而其中一處是在**修一句假話**
