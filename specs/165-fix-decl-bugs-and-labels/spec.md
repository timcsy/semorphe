# spec 165：修兩個宣告缺陷 ＋ 定三個教學用語

**路線圖位置**：階段 7 第 0 刀餘下的 25 筆 ｜ **前一步**：spec 164
**skill**：`retire-imperative-block`（它的第一次正式使用）

## ⚠️ 範圍比 brief 說的小——而那是量出來的

brief 說「可變參數 ＋ 前置欄位可以解 5 顆」。**量完之後不成立**：

```
cpp_input                 82 行 ｜ 每個插槽有【模式狀態】（select/compose/custom）
cpp_func_call             73 行 ｜ 動態下拉 ＋ 可變參數 ＋ 重建標籤
cpp_func_call_expression  72 行 ｜ 同上
cpp_var_assign_compound   70 行 ｜ 依有沒有索引【重建自己】
cpp_var_assign            13 行 ｜ 🟢 只有動態下拉
```

> **「它們看起來是同一群」是報表的錯覺——報表印的是【差在哪】，不是【它有多複雜】。**

🟢 所以這一刀做**真的做得完的**，`prefixFields` 那個機制留給下一刀。

## 🔴 兩個宣告缺陷（不是選擇題）

**① `cpp_loop_count`：下拉選項寫死英文**

```json
"options": [["to (exclusive)", "FALSE"], ["to (inclusive)", "TRUE"]]
```

命令式是 `Blockly.Msg['U_COUNT_LOOP_TO_EXCL'] || '到（不含）'`——**會跟著語言走**。
> 學生把介面切成中文，這個下拉還是英文。

**② `cpp_array_assign`：一個假的下拉**

```json
"options": [["arr", "arr"]]      ← 寫死的單一選項
```

命令式是 `getWorkspaceArrayOptions()`——**列出工作區裡真的陣列**。
> 學生宣告了 `nums[10]`，這個下拉只選得到 `arr`。

⚠️ **而比對報表看不出這件事**：兩邊當時都只有一個 `arr`，於是它印成
「格,← vs 格 ←」，看起來只是空白差異。
> **一個比「當下的樣子」的比對，看不出「這個下拉是死的」。**

## 🟡 三個教學用語（人拍板 2026-08-20）

| 積木 | 選定 | 理由 |
|---|---|---|
| `cpp_loop_while` | **持續執行** | 與它自己的 tooltip 一致；「重複」和 `for` 的「重複」撞名，學生分不出兩個迴圈 |
| `cpp_block_comment` | **多行註解：** | 「多行」是初學者**看得到的事實**，「區塊」要先知道 C++ 的術語 |
| `cpp_raw_code` | **空的（無預設值）** | 預設值 `// raw code` 是英文，而且學生不知道要不要刪掉它 |

## 要做的

1. 修 ① ②（②需要一個新的下拉來源 `arrays`）
2. 套用三個用語
3. 比對通過的退場

## 明確排除

- **`prefixFields`**（可變參數 ＋ 前置欄位）——`cpp_func_call` 那群，**下一刀**
- **`cpp_input` 的三模式插槽**、**`cpp_var_assign_compound` 的重建**——各自是一種形狀

## 驗收

- [ ] 落差 17 → 更低；中立性 25 → 更低；雙重真相 26 → 更低
- [ ] 🔴 `cpp_array_assign` 的下拉在瀏覽器裡**列得出工作區真的陣列**（不是只有 `arr`）
- [ ] 🔴 `cpp_loop_count` 的下拉是**中文**
- [ ] 三個用語在瀏覽器裡看得到
- [ ] Block Style 切換前後一致

## 🔴 而比對護欄本身修了四個缺口——每一個都在指控宣告

這一刀有**一半的時間**花在修比對器，因為它一直說「宣告寫錯了」而其實不是：

| 缺口 | 症狀 | 真相 |
|---|---|---|
| `src/i18n/` 沒載 | 「變數,(自訂) vs `%{BKY_U_VAR_REF_LABEL}`」 | 訊息沒到齊 |
| `field_multilinetext` 沒註冊 | 「多行註解：,comment vs 多行註解：」 | **選用欄位**沒註冊，欄位整個沒建出來 |
| `field_dynamic_dropdown` 沒註冊 | 「把變數,⟨活下拉⟩,設成 vs 把變數,設成」 | **自訂欄位**沒註冊 |
| 比「欄位怎麼切」 | 「格,← vs 格 ←」 | **那是排版不是內容** |

> **比對之前，要先把【產品那側需要的每一樣東西】都備齊；少一樣，比對就會指控宣告。**

另加一條判準改動：**動態下拉比「它是不是活的」，不比當下的值**
（`isOptionListDynamic()`）——空工作區裡死的與活的看起來一樣。

## 🔴 一顆「比對說可刪」而**刻意沒刪**的

`cpp_raw_code` 的 `loadExtraState` 會依 `degradationCause` **換顏色與 tooltip**，
而**宣告只有一個固定的灰色**。

⚠️ **比對護欄看不到它**——它比的是「**剛建好的樣子**」，
而那段邏輯只在**載入既有積木時**才跑。

> **一個只比「剛建好的樣子」的比對，看不到「載入時才長出來的東西」。**
> **而「可刪」這個判定，只在這條護欄看得到的範圍內成立。**
