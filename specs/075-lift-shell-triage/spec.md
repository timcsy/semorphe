# Feature Specification: 11 個 lift 殼的分診——根因是三種，不是一種

**Feature Branch**: `075-lift-shell-triage` ｜ **Created**: 2026-08-06

## 為什麼做這個

完備性報表把 11 個 lift 殼歸成**同一個根因**：「回來的樹裡找不到原本的身分」，
並附一句「同一個根因造成的多個殼，是一個問題不是多個」。

**實測之後那句話是錯的。** 逐一把樣本餵進辨識器，根因有三種：

| 概念 | 實際辨識出什麼 | 判定 |
|---|---|---|
| 五個類別成員 | **正確**（包在類別裡時） | ❌ **量測誤判** |
| `if_else` | `if` | ✅ 身分缺口 |
| `cpp_method_call` | `cpp_method_call_expr` | ✅ 敘述／運算式錯位 |
| `cpp_string_clear` / `push_back` | `cpp_container_*` | ✅ 概念降級 |

## 這一刀只修量測誤判

護欄已經有「樣本不是合法的獨立程式 → 判不出來」的機制。但類別成員放在頂層
**解析得過**（語法剖析器很寬容），所以那道防線攔不住它們。

修法**不新增宣告**，重用既有的 `consumed-by-parent`——那個宣告的門檻已經很嚴
（要有逐一查證的證據測試），沿用它就沿用了那道門檻。而那句話對辨識一樣成立：
**它只在父節點裡出現，單獨合成一份樣本去量它，是在量一個不存在的位置。**

## Requirements

- **FR-001**: 宣告了 `consumed-by-parent` 的概念，lift MUST 判為「判不出來」而非殼
- **FR-002**: 數字 MUST 移到「判不出來」欄，**MUST NOT 移到「實作」欄**
- **FR-003**: 其餘的真殼 MUST 留著

## Success Criteria

- **SC-001**: 殼 **13 → 8**，判不出來 **20 → 25**——**兩個數字要一起看**
- **SC-002**: 既有測試全數通過

## 順帶量到的一件事，本功能不修

`cpp_string_clear` 降級成 `cpp_container_clear` 的註解寫著「**為了避免型別消歧
問題**」。

而辨識脈絡**有一整套作用域與型別追蹤**（`declare` / `getType` / `pushScope`
/ `lookup`）——**四個方法全部零呼叫者**。消歧的工具一直都在，只是從來沒有人
接上。

那是「機制有了，沒人接上」的又一個實例，而且註解把「沒插電」寫成了「做不到」。
接上它是另一刀。
