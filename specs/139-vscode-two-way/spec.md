## 🔴 本規格的性質：**一顆積木要開始有用**

```
第一刀（138）  證明了畫布在 VSCode 裡跑得動——16.7 ms，順
使用者第一句    「怎麼離網頁版的差這麼多」
```

> **一顆畫得出來但什麼都不能做的積木，證明完它的問題之後就只剩維護債。**
> （`history/069`§四：「一個原型……**它會偽裝成『已經有基礎』**」）

⚠️ **而這一刀是「一次做完」，那有一個特定的失敗方式** —— 見下一節。

---

## ⚠️ 一次做完的風險，寫在最前面

這個專案有一份病歷（`history/072`）：
`c-style-parity` **10/10 全綠，而瀏覽器上仍然產出 `<iostream>`**。

> **它不是因為某一項做錯了，是因為【一次做很多】時，
> 「每一項都有人看」與「整體有人看」不是同一件事。**

🔴 **所以本規格的使用者故事按【使用者做得到什麼】切，不按檔案切**，
而**每一個故事都必須自己獨立可驗**——
⚠️ 一個「要等全部做完才驗得了」的故事，就是切錯了。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 改積木，程式碼跟著變，而檔案沒有被整個換掉 (Priority: P1)

學生在畫布上改一顆積木的欄位，旁邊的程式碼**那一行**變了。
他按 Cmd+Z，**那一次修改**被退回去——不是整個檔案。

**Why this priority**: 這是「雙向」的第一個方向，而**沒有它其他都不算數**。

**Independent Test**: 改一個欄位 → 看變更的行數 → 按一次 Cmd+Z。

**Acceptance Scenarios**:

1. **Given** 一份開著的程式，**When** 改一顆積木的欄位，
   **Then** 🔴 **只有改到的那幾行變了**，其餘的行**一個字元都沒動**。
2. **Given** 剛改完，**When** 按一次 Cmd+Z，**Then** **只退回那一次積木修改**。
3. **Given** 剛改完，**When** 看游標與摺疊狀態，**Then** **沒有被重置**。
4. 🔴 **Given** 把積木拖到別的位置（程式碼沒有理由改變），
   **When** 看檔案，**Then** **檔案沒有變更**，而按 Cmd+Z **不會退掉上一次程式碼修改**。

---

### User Story 2 - 改程式碼，積木跟著變，而不會打起來 (Priority: P1)

學生（或 AI）在程式碼那側貼上一段程式，積木跟著重畫。
**而兩邊不會互相觸發成一個迴圈。**

**Why this priority**: 「AI 給的 Code 貼上來」是使用者說過的主場景。

**Independent Test**: 貼一段程式 → 積木重畫 → **而且停下來**。

**Acceptance Scenarios**:

1. **Given** 面板開著，**When** 在程式碼那側貼上一段程式，**Then** 積木重畫成對應的樣子。
2. 🔴 **Given** 積木剛把程式碼改掉，**When** 那個變更事件回來，
   **Then** 系統**認得出那是自己的回音**並忽略它——**而不是靠等待**。
3. **Given** 別的東西改了檔案（格式化、還原、另一個擴充），
   **When** 看畫布，**Then** 積木跟著更新。

---

### User Story 3 - 點一邊，另一邊亮起來 (Priority: P1)

學生點一顆積木，程式碼那側**對應的地方亮起來並捲到看得見**。
他把游標移到某一行，**對應的積木被選取**。

**Why this priority**: 這是「兩個視圖是同一個東西」這件事**唯一看得見的證據**。

**Independent Test**: 點一顆積木、移一次游標，各看另一側。

**Acceptance Scenarios**:

1. **Given** 畫布上有積木，**When** 點其中一顆，**Then** 程式碼對應處高亮且捲到可見。
2. **Given** 程式碼那側，**When** 把游標移到某一行，**Then** 對應的積木被選取。
3. ⚠️ **Given** 點了一顆**沒有對應原始碼位置**的積木，
   **When** 看程式碼側，**Then** 🔴 **要有明確的表現**（往上找最近的、或明說沒有）
   ——**不可以安靜地什麼都不發生**。
4. 🔴 **Given** 兩側互相觸發的可能，**When** 連續點擊與移動游標，
   **Then** **不會進入無窮迴圈**。

---

### User Story 4 - 單步執行，看著程式在積木上走過去 (Priority: P2)

學生按單步，**積木一顆一顆亮起來**，程式碼那側跟著走。

**Why this priority**: 使用者逐字定調——
「**執行一般就是使用者自己從 IDE 執行，而我們自己做的用意
更多是為了結合積木的高亮過程**」。
🔴 **所以這個故事的產出是「看見」，不是「跑完」。**

**Independent Test**: 單步三次，看積木高亮有沒有移動。

**Acceptance Scenarios**:

1. **Given** 一份程式，**When** 按單步，**Then** **當前的積木高亮**，再按一次**換下一顆**。
2. **Given** 單步中，**When** 看程式碼側，**Then** **對應的行也跟著走**。
3. **Given** 程式輸出了東西，**When** 看畫面，**Then** 找得到輸出。
4. **Given** 執行結束，**When** 看畫布，**Then** 高亮**被清掉**。

---

### User Story 5 - 老師設一次，全班的積木長得一樣 (Priority: P2)

老師在專案裡設定使用哪一個目標，學生打開就是對的
——**而 `.ino` 與 `.cpp` 可以不一樣**。

**Why this priority**: 這是教學場景要的東西，而它決定積木**長什麼樣**。

**Independent Test**: 設一次專案設定、開兩種副檔名的檔案。

**Acceptance Scenarios**:

1. **Given** 專案設定了目標，**When** 打開一個檔案，**Then** 積木照那個目標呈現。
2. 🔴 **Given** 專案設定裡對某個語言另外指定了目標，
   **When** 打開那個語言的檔案，**Then** **語言的設定勝出**。
3. **Given** 面板上的選單，**When** 改它，**Then** 專案設定跟著變
   ——⚠️ **而使用者看得出「這會寫進專案設定」**，不是偷偷改。

---

### User Story 6 - 它看起來像 Semorphe，而不是一塊空白畫布 (Priority: P2)

學生打開面板，**有工具箱可以拉積木**，畫布的樣子與網頁版一致。

**Why this priority**: 沒有工具箱就**沒辦法新增積木**——那讓前五個故事都只能改、不能寫。

**Independent Test**: 打開面板 → 看得到分類 → 從裡面拉一顆積木出來。

**Acceptance Scenarios**:

1. **Given** 面板開著，**When** 看畫布，**Then** 有工具箱，而分類與網頁版一致。
2. **Given** 工具箱，**When** 拉一顆積木到畫布，**Then** 程式碼跟著長出對應的一段。
3. **Given** 面板開著，**When** 看外觀，**Then** 深色、與編輯器主題不衝突。

---

### User Story 7 - 切走再切回來，我的畫布還在原位 (Priority: P3)

學生切到別的分頁再切回來，**捲動位置與縮放沒有跑掉**。

**Why this priority**: 面板跟著 active editor 走，而**每次都重排會讓人不敢切分頁**。

**Independent Test**: 捲動＋縮放 → 切走 → 切回來。

**Acceptance Scenarios**:

1. **Given** 調整過捲動與縮放，**When** 切到別的檔案再切回來，**Then** **還在原位**。
2. **Given** 一個還沒存檔的暫存分頁，**When** 存成一個檔案，
   **Then** 🔴 **視圖狀態跟著搬過去**——不是重來。

---

### User Story 8 - 而網頁版一個字都不能退步 (Priority: P1)

**Why this priority**: `history/072` 的病歷就是這個
——一條路徑全綠，**而另一條安靜地錯了**。⚠️ **這一刀動的東西比第一刀多得多。**

**Acceptance Scenarios**:

1. **Given** 全部做完，**When** 跑全套，**Then** 全綠。
2. **Given** 同上，**When** 看護欄，**Then** **基線一個數字都不動**、中立性違規 **0**。
3. **Given** 同上，**When** 跑典型 Arduino 探針，**Then** 殘差 **0.07%**、漂移 **0/20**。

---

### Edge Cases

- **檔案在畫布有未同步的改動時被外部改掉** → 🔴 要有明確的處置，**不可以安靜地擇一丟掉**。
- **一個語法不完整的檔案**（正在打字）→ 積木不該整片消失。
- **很大的檔案** → 切分頁的重建要有可接受的上限。
- ⚠️ **沒有對應原始碼位置的節點**（實測 1.5%）→ 高亮要有退路。
- **暫存分頁存檔那一刻** → 身分改變，而視圖狀態要跟著搬。
- **面板開著而所有編輯器都關掉** → 畫布該顯示什麼？
- **同一份文件開在兩欄** → 面板跟哪一個？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 積木的修改 MUST 只改寫**受影響的那一段**程式碼，MUST NOT 重寫整份檔案。
- **FR-002**: 一次積木修改 MUST 對應**恰好一個**復原步驟。
- **FR-003**: **不改變程式碼**的積木操作（例如搬動位置）MUST NOT 產生檔案變更。
- **FR-004**: 程式碼的改動 MUST 反映到積木上。
- **FR-005**: 系統 MUST 能分辨「自己造成的變更」與「外來的變更」，
  🔴 而那個分辨 MUST NOT 依賴**等待**——它必須依賴**身分**。
  - 理由：等待的長度是猜的，而那個猜測**沒有上界**。
- **FR-006**: 選取一側 MUST 讓另一側有對應的表現，兩側 MUST NOT 互相觸發成迴圈。
- **FR-007**: 找不到對應位置時 MUST 有明確的表現，MUST NOT 靜默無反應。
- **FR-008**: 單步執行 MUST 讓當前節點在積木與程式碼**兩側**都可見。
- **FR-009**: 組態 MUST 存在**使用者看得見、改得到、可進版控**的地方，
  且 MUST 支援**按語言覆寫**。
- **FR-010**: 面板上改組態 MUST 與 FR-009 那份設定**是同一份真相**。
- **FR-011**: 面板 MUST 提供工具箱，且分類與既有的網頁版一致。
- **FR-012**: 面板的視圖狀態 MUST 在文件之間切換時保留。
- **FR-013**: 既有的網頁版 MUST NOT 有任何行為改變。
- **FR-014**: 新增的程式碼 MUST 落在既有檢查掃得到的位置。

### Key Entities

- **文件**：使用者正在編輯的一份程式碼。⚠️ **不等於一個檔案**——它可能還沒存檔。
- **語義樹**：那份程式碼的意義。**兩個視圖投影的都是它。**
- **重寫範圍**：一次修改真正要覆蓋的那一段。
- **視圖狀態**：捲動、縮放、積木擺放 —— 🔴 **在這裡它是外觀，不是真相**。
- **組態**：目標／課程／風格 —— **一份，兩個地方看得到**。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 改一顆積木的欄位，變更的行數**中位數 ≤ 2**（今天是整份檔案）。
- **SC-002**: 一次積木修改 = **1** 個復原步驟（今天無此行為）。
- **SC-003**: 純搬動積木造成的檔案變更 = **0 行**。
- **SC-004**: 貼上一段程式後，積木重畫**且系統停止**——回音造成的重複更新 **0 次**。
- **SC-005**: 🔴 防迴圈的實作中，**依賴時間的等待 = 0 處**。
- **SC-006**: 點積木 → 程式碼高亮並可見；移游標 → 積木被選取。**雙向都成立**。
- **SC-007**: 單步 N 次，積木高亮換了 **N** 次，且程式碼側同步。
- **SC-008**: 設定一個專案層級的目標 ＋ 一個語言層級的覆寫，**兩者都生效**。
- **SC-009**: 工具箱分類數與網頁版**相同**。
- **SC-010**: 切走再切回來，捲動位置與縮放**完全一致**。
- **SC-011**: 🔴 網頁版：全套綠、**護欄基線 0 個變動**、探針殘差 **0.07%**、漂移 **0/20**。
- **SC-012**: ⚠️ **未存檔的暫存分頁**上，SC-001～SC-010 **全部同樣成立**。

### 🔴 而有兩類驗收我做不到，現在講清楚

```
🟢 我做得到   一切在測試裡驗得了的：範圍計算、身分比對、設定解析、回歸
🔴 我做不到   在 Electron 桌面應用裡【按鍵與拖曳】
```

**處置與第一刀相同**：交付物包含**自己會報狀態的畫面**
（改了幾行、是不是回音、目前哪個節點），讓交棒那一步**只需要照著看**。

> **一個做不到的驗收，處置是把它交出去並讓它變容易，
> 不是換一個我做得到的驗收。**

## Assumptions

- VSCode 與 Arduino IDE 都已安裝（2026-08-17 查證）。
- 第一刀的成果（面板、登錄表、`.vsix` 建置）**沿用**，不重做。
- 「一致」以現行網頁版為準；網頁版本身的缺陷**不在本輪修正範圍**。
- 使用者操作面板時**只服務一份文件**——本輪不做多文件。
