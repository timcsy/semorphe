## 🔴 一、我在規劃期量錯了一件事——**而它會讓 FR-001 靜默地錯**

### 量的是什麼

`tests/probes/edit-blast-radius.test.ts` 比的是：

```
generate(原樹)  ↔  generate(突變樹)
```

得到「欄位編輯中位 1 行、≤1 行 99.5%」。

### 🔴 而實際要寫的是**文件**，不是 `generate(原樹)`

```
文件的實際內容    使用者的排版：縮排 2 空格、空行、多行的 enum、註解位置
generate(原樹)    我們的排版：style preset 決定的縮排、空行被移除、enum 折成一行
```

`history/080`§三 逐字量過：「**內容保真 100%**（註解全在、`enum` 全在、
結構全在），**而差異全是排版**」。

⚠️ **所以那兩個文本不相等**，而拿 `generate(原樹)` 算出來的範圍
**套到文件上是錯的座標**——症狀是**改到不該改的行**，而且**不會報錯**。

> **我量到的是「第二次之後的編輯」，而我把它讀成了「所有編輯」。**

### Decision：**拿文件的實際文字去比**

```
rewriteSpan( document.getText(), generate(新樹) )
```

**Rationale**：範圍因此天生就是**文件座標**，不需要任何對齊。
**而第一次編輯的跨距會很大**（把使用者的排版換成我們的），
🟢 **那不是缺陷，是誠實**——我們**真的**改了那些行。
⚠️ 而**今天的行為（整份重寫）就是每次都這樣**，所以第一次編輯**沒有變差**。

```
第 1 次編輯   跨距 ≈ 整檔（＝ 今天的行為，沒有變差）
第 2 次之後   跨距中位 1 行（＝ 量到的那些數字）
```

**Alternatives considered**：
- 從 `sourceRange` 算 → ⚠️ 要求 `sourceRange` 100% 正確且結構變動時重算行號，
  而實測只有 98.5%。**多一個會壞的地方。**
- 先把文件正規化成我們的排版再開始 → 🔴 **開檔就改使用者的檔案**，不可接受。

🔴 **而 SC-001「中位 ≤ 2 行」因此要說清楚它量的是第 2 次之後** ——
plan 會把這一條寫進驗收，**不是偷偷改標準**。

### ⚠️ 由此浮出一個【本輪不解】的問題

「第一次編輯會重排使用者的檔案」——那正是 `concepts/投影.md` 把
**空行與縮排歸類為「呈現／可丟失」**的後果，而 `history/080`§三 已經標記
「**一個『可以丟失』的分類，前提是那個東西不屬於使用者**」。

**本輪不動那個分類**（那是 lift／generate 的事，不是宿主的事），
**而本輪讓它第一次真的咬到人**。記在這裡。

## 二、`code → blocks` 的解析跑在哪 —— **Webview**

```
Webview 裡跑    ⟹ 要 'wasm-unsafe-eval'（實測過）＋ wasm 檔進封包（約 3.6 MB）
主行程裡跑      ⟹ 🔴 esbuild/CJS 那個坑【回來】（registry.ts:22-48）
```

**Decision**：**Webview**。

**Rationale**：
1. 🔴 lift **需要膠囊登錄表**（`lift-pattern.json` 由 `import.meta.glob` 掃出），
   而那正是 CJS 坑的正中央。把 lift 放主行程 ＝ 主動踩坑。
2. 拆成「主行程 parse、Webview lift」要把 tree-sitter 的樹序列化過 `postMessage`
   ——**一棵樹幾千個節點，而它每次按鍵都要傳**。
3. `'wasm-unsafe-eval'` **嚴格窄於** `'unsafe-eval'`：它只放行 WebAssembly 編譯。

**代價（明說）**：
```
封包    456 KB → 約 4 MB（tree-sitter-cpp.wasm 3.4 MB ＋ web-tree-sitter.wasm 196 KB）
CSP     多一個 'wasm-unsafe-eval'
```

🔴 **而這正是 spec 說的那個「觸發時刻」** ——
規格寫「額外的執行期權限……**要到真的用到那個能力時才加**」。
**現在用到了。所以加它不是範圍蔓延，是條件成立。**

⚠️ **驗收要跟著加一條**：`'wasm-unsafe-eval'` **只有這一項**，
不得順手加 `'unsafe-eval'` 或放寬 `default-src`。

## 三、防迴圈：**身分比對，而它需要一個佇列不只是一個變數**

**Decision**：記**我們產生的 version 的集合**，不是「上一個 version」。

**Rationale**：一次積木編輯可能產生 **一個** document 版本，
但**連續快速編輯**會產生多個，而變更事件是**非同步**送達的。

```
只記上一個   🔴 兩次編輯連著發，第一次的回音回來時 lastVersion 已經是第二次的 → 誤判成外來
記一個集合   🟢 收到就從集合移除；集合空了代表所有回音都回來了
```

⚠️ **而集合要有上界**（避免永遠留著沒回來的），
🔴 **但上界不可以是時間** —— FR-005 明令。用**數量**（例如只留最近 N 個）。

> **「用身分不用時間」不是把 `setTimeout` 換個地方寫，
> 是讓正確性不再依賴任何一個猜出來的數字。**

**Alternatives considered**：布林旗標 ＋ `setTimeout`（PoC 的做法）——
`history/080`§五② 逐字：「**那些 `setTimeout` 就是症狀**」。

## 四、選取的防迴圈：**與 undo 同族，而解法不同**

點積木 → 照亮程式碼 → 游標動了 → 反查 → 選積木 → …

**Decision**：**用「最後一次是誰發動的」＋ 值相等就不再傳播**。

```
反查出來的 nodeId 與目前已選的相同 → 不做事（天然的不動點）
```

**Rationale**：🟢 選取是**冪等**的——與文字編輯不同，
「選同一個」與「不選」在效果上一樣。**所以值比對就夠，不需要身分或時間。**

⚠️ **而它與第三節不能共用一套機制**，因為文字編輯**不是**冪等的。
**兩個問題長得像，而它們的性質不同。**

## 五、範圍計算的演算法要**升格進 `src/`**

`rewriteSpan`（去頭去尾取中間）今天住在
`tests/probes/edit-blast-radius.test.ts`。

**Decision**：搬進 `src/core/projection/`，而**探針改成 import 它**。

**Rationale**：🔴 現在它要變成**生產路徑**，而一個生產演算法住在測試裡
＝ 兩份會漂移的東西。而探針改用同一份之後，
**那 407 筆量測就變成它的回歸測試**。

⚠️ **它不屬於 `src/vscode/`**：它與宿主無關（純文字比對），
而放進 `core/projection/` 讓網頁版哪天要用也拿得到。
🟢 **而 `core` 是中立目錄——這個函式不認識任何宿主，放得進去。**

## 六、設定：**一份宣告，兩個消費者**

```
擴充宣告 configuration        scope: "language-overridable"
讀        getConfiguration('semorphe', { uri, languageId })
面板的選單改它                 更新 workspace 層級
```

**Decision**：面板選單直接寫 **workspace** 層級，並在 UI 上標明。

**Rationale**：使用者拍板「面板內的選單直接改 workspace 設定」。
⚠️ **而「很意外」那個顧慮的處置是【標明】不是【不做】**——
選單旁邊要看得出它會影響整個專案。

🔴 **而讀設定要走 `onDidChangeConfiguration`**：老師改了 `settings.json`，
學生的面板**要自己更新**，不是重開才生效。

## 七、per-uri 視圖狀態：存哪、什麼時候搬

```
存    workspaceState，key = uri.toString()
內容  捲動位置／縮放／積木擺放（🔴 而它們是【外觀】不是真相）
```

⚠️ **暫存分頁存檔那一刻身分會變**（`untitled:Untitled-1` → `file:///…`）。

**Decision**：監聽文件被存成新檔的時機，把舊 key 的狀態**搬到新 key**。

**Rationale**：SC-012 要求暫存分頁上所有驗收同樣成立。
⚠️ 而 `onDidRenameFiles` **管不到這個**（那是檔案改名）
——要用「舊的關了、新的開了」那一對事件配對。
🔴 **這是本輪最容易漏的一格**，因為它只在「存檔」那一瞬間發生。

## 八、⚠️ 而有一件事本輪【變得更危險】，要先說

第一刀動的是**新檔案**。這一刀要動：

```

core/projection/             新增範圍計算
core/storage.ts              🔴 不動——但要確認 VSCode 這一側【不呼叫它】
```

🔴 **抽 `createDarkTheme()` 是唯一會動到網頁版程式碼的一步**，
而 `history/072` 的病歷正是「改了共用的東西，而只有一條路徑被驗」。

**處置**：那一步**單獨一個 commit**，且**改完立刻跑全套**
——不與其他改動混在一起，讓它出問題時對得出來。
