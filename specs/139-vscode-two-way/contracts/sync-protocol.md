# Contract：宿主 ↔ Webview 的同步協定

**Feature**: 139-vscode-two-way　**Date**: 2026-08-17

> 第一刀的協定是**空的**（`specs/138/contracts/webview-host.md`），
> 而那是刻意的：一條訊息都沒有就不需要防迴圈。
> 🔴 **這一刀把它打開，所以防迴圈的責任從「不存在」變成「要設計」。**

---

## 一、責任的分界——**而它是由「膠囊登錄表住哪」決定的**

```
主行程（Node）      文件的讀寫、設定、per-uri 狀態、生命週期
                    🔴 它【不認識】語義樹、不 parse、不 generate
Webview（瀏覽器）   parse ＋ lift ＋ generate ＋ 積木 ＋ 執行
                    🔴 膠囊登錄表住這裡（import.meta.glob 是 Vite 的轉換）
```

> **主行程之所以這麼薄，不是設計美學，是因為
> `core/component/registry.ts:22-48` 那個實測過的坑：
> 非 Vite 打包的宿主【載不到任何膠囊】，而且不報錯。**

⚠️ 於是有一條**硬規則**：

```
🔴 主行程不得 import 任何會碰到 src/components/ 的東西
```

---

## 二、訊息（**每一則都要說「誰是真相」**）

### 主行程 → Webview

| 訊息 | 內容 | 什麼時候 |
|---|---|---|
| `document` | 文件全文 ＋ 語言 ＋ 版本 ＋ uri | 切換文件、外來變更 |
| `config` | 解析好的組態（`PanelConfig`） | 開啟、設定變更 |
| `viewState` | per-uri 的外觀（可能沒有） | 切換文件 |
| `selection` | 游標所在的行 | 使用者移動游標 |
| `noDocument` | —— | 所有編輯器都關掉了 |

### Webview → 主行程

| 訊息 | 內容 | 什麼時候 |
|---|---|---|
| `applyEdit` | `RewriteSpan`（起訖行 ＋ 內容） | 積木改變了語義 |
| `viewStateChanged` | 捲動／縮放／擺放 | 使用者動了畫布外觀 |
| `revealNode` | `startLine` / `endLine` | 使用者點了積木 |
| `executionAt` | `nodeId` ＋ `follow` | 單步走到某個節點 |
| `configChanged` | 要改哪一格、改成什麼 | 使用者動了面板上的選單 |
| `ready` | 載入了幾顆膠囊、幾筆規格 | Webview 起來了 |

## 三、🔴 防迴圈：**兩個問題，兩套機制，不可共用**

### ① 文字編輯 —— **用身分**

```
主行程送出 applyEdit → 記下產生的 document version
變更事件進來 → version 在 pending 集合裡？
    在   → 回音，移除並停止
    不在 → 外來變更，送 `document` 給 Webview
```

⚠️ **必須是集合不是單一變數**：連續快速編輯產生多個版本，
而事件非同步送達。只記「上一個」會把先前的回音誤判成外來。

🔴 **上界用【數量】不用時間。** FR-005 明令，而它有病歷：
`experience.md:2866` 的等待版本自己標了「那個常數是猜的」。

> **加時間是在猜「回音應該多久之內回來」——而那個猜測沒有上界。**

### ② 選取 —— **用值相等**

```
反查出來的 nodeId 與目前已選的相同 → 不做事
```

🟢 **選取是冪等的**——「選同一個」與「不選」效果一樣，所以值比對就夠。

⚠️ **而它不可以套用①的機制**，因為文字編輯**不是**冪等的；
反過來①也不能用值比對，因為兩次相同的編輯是兩件事。

> **兩個問題長得像，而它們的性質不同。
> 用同一套機制蓋過去，就是把一個會壞的地方藏起來。**

## 四、CSP 的變動——**只加一項**

```
script-src  <source> 'wasm-unsafe-eval'      ← 🔴 本輪唯一的新增
```

**為什麼**：`code → blocks` 要在 Webview 裡跑 tree-sitter，
而 `WebAssembly.compile` 沒有它會丟 `CompileError`（2026-08-17 實測兩個方向）。

⚠️ **驗收要釘死**：
```
🔴 不得順手加 'unsafe-eval'（它嚴格更寬）
🔴 不得放寬 default-src
🔴 既有的五條（style/img/media/connect/font）一個字都不動
```

**而它為什麼現在才加**：spec 138 撿到這個坑時刻意沒加，理由逐字：
「**加一個還沒有人要用的權限，等於把它從『下一刀要處理的事』
變成『已經在那裡、沒有人記得為什麼』**」。
🟢 **現在用到了，所以觸發條件成立。**

## 五、設定的宣告

```
semorphe.target / topic / style / blockStyle / locale
scope: "language-overridable"    🔴 不宣告的話語言覆寫【安靜地不生效】
```

**讀**：以 `{ uri, languageId }` 為範圍解析。
**寫**（面板選單）：寫 **workspace** 層級，⚠️ **而 UI 上要看得出來**。
**監聽**：設定變更要即時反映——**老師改了，學生不用重開**。

## 六、`RewriteSpan` 的契約（**唯一可完整單元測的核心**）

```
輸入   before: string（🔴 文件的【實際文字】）
       after:  string（新產出的全文）
輸出   { startLine, endLine, text } | null（沒有差異）

規則   去掉共同的開頭行、去掉共同的結尾行，中間就是要覆蓋的範圍

保證   ① 套用結果 === after            （🔴 這一條是它的全部意義）
       ② before === after → null       （不產生空編輯）
       ③ 對「只差一行」的輸入 → 跨距 1
       ④ 純函式：同輸入同輸出，無狀態
```

🔴 **保證①是這個契約的靈魂**：範圍算錯的症狀是**改到不該改的行**，
而那**不會拋錯**。所以測試必須是「套用後與 `after` 逐字元相同」，
**不是「跨距看起來合理」**。

⚠️ **而 `before` 是文件文字這件事要寫進測試名稱**——
`research.md` 第一節記著我一開始拿錯了它。
