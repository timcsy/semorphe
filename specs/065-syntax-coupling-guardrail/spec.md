# Feature Specification: 語法耦合護欄——中立性看不見的那一維

**Feature Branch**: `065-syntax-coupling-guardrail` ｜ **Created**: 2026-08-06

## 為什麼做這個

中立性護欄今天歸零（216 → 0）。**但那不代表語言獨立性成立。**

清償途中發現核心層還有六處寫死 C 家族註解語法——產生 `//`、`/** */`、`/* */`，
行末標註，兩處認不得概念的退路，以及從原始碼**剝掉**它們的規則。
**中立性護欄一筆都數不到**，因為那六處一個元件身分都沒有。

> 「一條規範被機械化時，**選了哪一維會消失在數字裡**。」

那條原則本身也只寫了一個維度：「無 `languages/cpp/` import」。
**import 是一種形式，身分是另一種，語法是第三種。**

## Requirements

- **FR-001**: MUST 量核心與呈現層寫死的語言專屬語法記號
- **FR-002**: 判定 MUST 保守——同形於系統自身概念的記號歸「無法確定」，**單獨報、不計入安全**
- **FR-003**: 每個「確定」的記號 MUST 附「為什麼它不可能是別的東西」
- **FR-004**: 註解裡的記號 MUST NOT 計入——那是說明，不是產出
- **FR-005**: MUST 有雙向合成注入
- **FR-006**: MUST 在**已知答案的樣本**上驗過——靜態判斷的第一版會量錯
- **FR-007**: 自我否證聲明 MUST 錨在合成輸入上，不錨在真實狀態
- **FR-008**: MUST 說明「本護欄不檢測什麼」，且要寫**維度**不只寫範圍

## Success Criteria

- **SC-001**: 護欄存在、有基線、有雙向棘輪
- **SC-002**: 在 059 之前的真實程式碼上**抓得到**當時的耦合，在現在的同兩個檔上**回報乾淨**
- **SC-003**: 確定的語法耦合歸零
- **SC-004**: 既有測試全數通過
