# Feature Specification: 跨語言互轉第二對——C++ → Python（第一版）

**Feature Branch**: `362-cpp-to-python`
**Created**: 2026-11-08
**Status**: Draft
**Input**: User description: "跨語言互轉第二對：C++ → Python（第一版）……使用者把語言從 C++ 換到 Python 時，程式換成 Python 的寫法；兩邊交給 Cella 判，判決、輸出、assumes 相同才算沒有失真；意思會變的地方照實保留並說出原因；護欄：cpp-beginner 課文的 C++ 解答換成 Python 後判決相同。"

## 背景

第一對（C ↔ C++）兩個方向已經齊了（history/351）：換寫法的判準是「兩邊交給 Cella 判，判決、輸出、assumes 相同」，換不了的照實保留。
第二對換的是**不同語言族**——草稿〈Lean4 課程與跨語言互轉〉的原話：「意思會變的地方多（溢位、除法、別名）——機制在第 1 對驗過後才值得」。
今天把目標從 C++ 切到 Python 時，語意樹還是 C++ 的那一棵、只換了語言參數，學生看到的不是一支道地的 Python 程式。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 學過 C++ 入門的學生切到 Python，拿到一支同樣意思的 Python 程式 (Priority: P1)

學生寫好一支 C++ 入門程式（讀幾個數、用 if 與迴圈算出結果、印出來），在選單把目標換成 Python。
編輯器裡換成道地的 Python 寫法（`input()`、`print()`、`for … in range(…)`、list），積木也跟著換成 Python 的積木；
提示說出「換了幾行」。按執行，輸出與原本的 C++ 程式一樣。

**Why this priority**: 這是互轉第二對存在的理由——同一份意思投影到另一種語言；學生用自己熟的語言對照學新語言。

**Independent Test**: 拿 cpp-beginner 課文的 C++ 解答，各自換成 Python，兩邊交給 Cella 判（同一份輸入），判決與輸出相同。

**Acceptance Scenarios**:

1. **Given** 一支只用到入門子集的 C++ 程式（整數與浮點變數、if／else、while、計數 for、函式、cin／cout、陣列或 vector、字串），**When** 學生把目標換成 Python，**Then** 程式換成 Python 寫法，兩邊的 Cella 判決、輸出、assumes 相同。
2. **Given** 換好的 Python 程式，**When** 學生再改它、執行，**Then** 它就是一支普通的 Python 程式（積木、執行、判決都走 Python 那一套）。
3. **Given** 換寫法的過程，**When** 完成，**Then** 畫面上說出換了幾行。

---

### User Story 2 - 意思會變的地方照實保留，說出原因，不悄悄換成另一支程式 (Priority: P1)

C++ 與 Python 有些地方寫起來像、意思不同：整數會溢位（Python 不會）、整數除法與負數取餘數的規則不同、char 是整數、指標與類別在入門 Python 沒有對應。
遇到這些地方，系統**不換**（照原文保留），並說出卡在哪幾行、為什麼。

**Why this priority**: 換錯比不換糟——一支看起來是 Python、意思卻變了的程式，學生會學到錯的東西（P6 誠實降級）。這條與 US1 同樣是 P1：沒有它，US1 的「判決相同」只是運氣。

**Independent Test**: 準備一批「意思會變」的 C++ 程式（負數除法、溢位、char 運算、指標、類別），換到 Python：每一支都不換或只換確定沒問題的部分，並列出原因；已換的部分仍判決相同。

**Acceptance Scenarios**:

1. **Given** 一支用到負數整數除法或取餘數的 C++ 程式，**When** 換到 Python，**Then** 系統要嘛換成意思相同的 Python 寫法（並由判決相同證明），要嘛保留並說出原因——不得換成意思不同的 `//`／`%`。
2. **Given** 一支會整數溢位的 C++ 程式（判決帶溢位相關的 assumes 或 reject），**When** 換到 Python，**Then** 不換，說出「整數溢位」。
3. **Given** 一支用到指標、類別或樣板的 C++ 程式，**When** 換到 Python，**Then** 整支不換，說出卡住的那幾行。

---

### User Story 3 - 老師用護欄確認課文的解答都換得過去 (Priority: P2)

cpp-beginner 課文的每一支 C++ 解答，換成 Python 之後交給 Cella 判，判決與輸出和原本相同；換不了的列出原因。這份清單是常駐的檢查。

**Why this priority**: 第一對的驗收就是這個形狀（`c-to-cpp-verdict`、`cpp-to-c-verdict`）；它讓「換得過去」可以被量、會變紅。

**Independent Test**: 跑那支檢查，得到「換過去而判決相同」與「保留（附原因）」兩份清單，兩份加起來等於課文解答的總數。

**Acceptance Scenarios**:

1. **Given** cpp-beginner 課文的所有 C++ 解答，**When** 跑檢查，**Then** 每一支不是「換過去且判決相同」就是「保留且附原因」，沒有第三種。
2. **Given** 某一刀讓某個構造從保留變成換得過去，**When** 重跑檢查，**Then** 那幾支的判決仍相同（若出現新的 reject，先查我們送了什麼——experience〈翻不出是一層遮罩〉）。

---

### Edge Cases

- 切到 Python 時判決還沒暖好、拿不到型別：只換得動不需要型別的部分，其餘保留並照實說（同第一對）。
- 等型別的時候學生又改了程式或又換了目標：這一次作廢，不蓋掉學生剛做的事（同第一對）。
- 輸入格式：C++ 的 `cin >> a >> b` 跨行、同一行都讀得到；Python 的 `input()` 一次讀一行——換寫法必須讓同一份輸入讀出同樣的值，否則保留。
- 輸出格式：`cout` 預設的浮點印法與 Python `print` 不同（`1.5` vs `1.5`、`1e+06` vs `1000000.0`）——判決的輸出逐字相同才算換對。
- 字串與字元：`char` 參與運算（`c - 'a'`）不換；單純印出的字元可以換。
- 空程式、只有 main 的骨架：換成空的 Python 程式，不報錯。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 使用者把目標從 C++ 換到 Python 時，系統 MUST 嘗試把目前的程式換成 Python 寫法；換好的程式放進編輯器與積木，之後就是一支普通的 Python 程式。
- **FR-002**: 系統 MUST 只在「換了之後意思不變」時才換；判準是兩邊交給 Cella（C++ 家族與 Python 家族）判，判決、輸出、assumes 相同。
- **FR-003**: 系統 MUST 涵蓋入門子集：整數與浮點變數與運算、比較與邏輯、if／else、while、計數 for、函式定義與呼叫、讀入整數／浮點／字串、印出、陣列與 vector（→ list）、字串。
- **FR-004**: 意思會變的構造（整數溢位、負數的整數除法與取餘數、char 參與運算、指標、類別、樣板、子集以外的標準函式庫）系統 MUST 保留、不換，並說出卡住的行與原因。
- **FR-005**: 系統 MUST 以「整支程式」為換或不換的單位：若有任何一處必須保留，整支程式維持 C++（另一種語言裡不能混著留一行 C++），並說出卡住的行。
- **FR-006**: 系統 MUST 在換完時說出換了幾行；整支不換時說出原因清單。
- **FR-007**: 系統 MUST 提供一支常駐的檢查：cpp-beginner 課文的每一支 C++ 解答，換成 Python 後判決相同，或保留並附原因；兩份清單加起來等於解答總數。
- **FR-008**: 換寫法 MUST 只在使用者主動換目標時發生；課文固定目標的那條路不換（同第一對）。
- **FR-009**: 判決還沒準備好、拿不到型別時，系統 MUST 只換不需要型別的部分，其餘照 FR-005 處理並照實說。

### Key Entities

- **換寫法的結果**：換好的程式（或原樣）、換了幾行、保留的行與原因清單。
- **保留的原因**：一個卡住的構造（哪一行、哪一類：溢位、除法、char、指標、類別、樣板、子集以外）。
- **判決比對**：同一份輸入下兩邊的判決、輸出、assumes。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: cpp-beginner 課文的 C++ 解答，至少一半換得過去且判決相同；其餘每一支都附保留原因（沒有無原因的失敗）。
- **SC-002**: 換過去的程式，判決與輸出和原本逐字相同的比例是 100%（換錯的 = 0）。
- **SC-003**: 一批「意思會變」的反例（至少 6 種：負數除法、負數取餘數、溢位、char 運算、指標、類別），每一種都被保留並說出正確的原因類別。
- **SC-004**: 學生換目標後，3 秒內在編輯器看到換好的 Python 程式（或保留的說明）。
- **SC-005**: 換好的 Python 程式再轉一趟積木、回到程式碼，形狀不變（同一支程式）。

## Assumptions

- Cella 的 Python 家族判得出入門子集（python-beginner 課文已經在用它判決）；它是唯一的判準，沒有參照直譯器。
- 「入門子集」以 cpp-beginner 課文用到的構造為界；cpp-advanced 的構造不在第一版。
- 換寫法的入口沿用第一對的「換目標之後」那一條路（語言套件提供換法、app 只負責問型別、寫回兩個投影、說出結果）；跨語言時由「來源語言」那一側提供換法。
- 輸入的換法以「同一份輸入讀出同樣的值」為準；讀法差異大到無法保證時保留。
- 不做：Python → C++（下一版）、類別／指標／樣板／進階 STL。
