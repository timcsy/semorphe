# Phase 1 資料模型：宣告取代清單

## 契約 1：三種「空得有理」，理由必須寫進宣告

`skipPaths: ['execute']` 只說了「不走這條路」，沒說**為什麼**。而 research F2 顯示至少有兩種不同的理由，混在一起會誤導下一個人。

```ts
/** 一條路徑被刻意跳過的理由 */
export type SkipReason =
  | 'declarative'    // 這個概念在執行期沒有任何可觀察效果（註解、include、define）
  | 'consumed-by-parent'  // 有子槽，但由父概念的執行器負責（cpp_case ← cpp_switch）
```

宣告形式（`concepts.json`）：

```jsonc
{
  "conceptId": "comment",
  "skipPaths": ["execute"],
  "skipReasons": { "execute": "declarative" }
}
```

**不得只寫 `skipPaths` 不寫理由**——沒有理由的宣告就是把缺陷洗成設計。這由一支測試強制。

### 「還沒實作」沒有對應的值——那是刻意的

第三類（有子槽、沒人讀、跑起來會錯）**不得取得任何宣告**。它們維持「未宣告的空實作 → 殼」，繼續被完備性報表算進去，並進缺陷帳。

> **可宣告的理由只有兩個，是這個契約最重要的部分。** 若哪天有人想加第三個值，那就是在替「還沒做」找一個體面的名字。

---

## 契約 2：分類必須實測，不得靜態推斷

research F2b 已經證明靜態掃描會給出**反過來**的答案。

每個概念的分類必須由**一支能跑的最小程式**支持：

```
概念 → 最小 C++ 程式 → 直譯器執行 → 輸出
                                    ↓
                          與正確答案相同 → 可宣告（A 或 B）
                          不同 or 報錯   → 不得宣告（還沒實作）
```

**正確答案的來源**：人工寫定的期望輸出，寫在測試裡與程式碼並列。不用編譯器比對——那會把編譯器環境變成測試的相依，而本功能的判斷不需要那個精度。

**判不出來的**（例如概念無法單獨組成可執行程式）**歸入「不得宣告」**——保守方向與既有護欄一致。

## 契約 3：執行引擎讀宣告

```ts
// 目前：核心層一份 34 個概念名的清單
for (const c of ['cpp_include', …]) reg(c, noop)

// 之後：從概念註冊表讀
for (const def of conceptRegistry.all()) {
  if (def.skipPaths?.includes('execute')) reg(def.conceptId, noop)
}
```

**`skipPaths` 的定位因此改變**。它目前的型別註解寫著：

> 純資料、可選、**不影響任何執行期行為**，只有完備性護欄讀它。

那句話要改。它不再是文件，而是機制——這正是「把推斷改成宣告」。

**同一事實從兩處變一處**，順帶是「殺雙重真相」的一筆首付。

---

## 契約 4：執行器註冊表要看得見重複

research F8：`Map.set` 覆蓋，而核心層的清單在所有真實作之後跑，**關掉了四個能用的轉型實作**。

```ts
register(concept: string, executor: ConceptExecutor): void {
  // 目前：this.executors.set(concept, executor)  ← 靜默覆蓋
  // 之後：記錄重複，交由護欄量測
}
```

**不在註冊時報錯**——那會讓載入順序的既有相依炸開，屬於 `history/017` 說的「加嚴之前先回答被拒絕的東西去哪了」。本功能**只讓它可見**：重複註冊數進護欄與棘輪，逐一消除排在後面。

> 這是 051 的病換一個註冊表重演：同一個身分登記多次，勝負由載入順序決定。051 為 lift 規則建了歧義護欄；**執行器註冊表至今沒有任何東西在看**。

---

## 契約 5：除錯步驟改用語義標註

```jsonc
{ "conceptId": "var_declare", "annotations": { "debug_step": true } }
```

`annotations` 是既有欄位，且專案已規劃它作為「語言套件 ↔ 視圖套件的開放契約」。除錯器要在哪裡停，本來就是視圖層的關心。

**缺標註時的預設是「不停」**——與現況一致（清單外的概念本來就不停）。

---

## 契約 6：報表要分得出「宣告」與「實作」

完備性報表目前把「已宣告 skipPaths」直接算成 `implemented`。那讓兩種下降**看起來一樣**：

| 下降原因 | 意義 |
|---|---|
| 因為**實作**了 | 系統多會做一件事 |
| 因為**宣告**了 | 系統沒有變，只是我們終於說清楚它本來就不做 |

**混在一起的話，下一個人會用宣告刷數字。**

報表要分三欄：`實作` ／ `已宣告不提供（附理由）` ／ `殼`。棘輪照舊只看「殼」與「缺」。

---

## 本功能不新增任何概念

不動語義樹結構、不新增元件、不改概念的 children/properties。改的是**既有欄位的用途**與**兩份清單的位置**。
