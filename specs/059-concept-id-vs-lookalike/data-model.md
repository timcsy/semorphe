# Data Model & Contracts

## 實體

### 遮罩（Mask）

一個把「拼法像身分、實際不是」的字串從掃描視野中移除的規則。

| 欄位 | 意義 |
|---|---|
| 名稱 | 遮什麼位置 |
| 判準 | **為什麼那個位置永遠不可能是身分引用**——必須是語言規則，不是統計傾向 |
| 實測遮掉了什麼 | 逐項列出，且與違規清單比對過 |

**不變式**：每個遮罩都要能回答「它會不會遮掉真違規」，而答案必須來自**實測**，不是推論。遮罩 B 就是被這一問否決的。

### 兩欄報表

| 欄 | 意義 |
|---|---|
| **誤報修掉的** | 量測改了，系統沒變 |
| **真的搬走的** | 系統變了 |

**不變式**：這兩欄**不得相加後只呈現總數**。混在一起的話，修量測會看起來像進步——`history/018` 的直接處方。

## 契約

### 契約 1：遮罩的雙向注入（FR-003／FR-004）

| 注入 | 必須 |
|---|---|
| 一段真的引用了語言專屬概念身分的程式碼 | **仍被報出** |
| 一段拼法相同、位置屬於已遮罩型別的字串 | **不被報出** |

**兩支都要。** 少了第一支，一個「什麼都不報」的護欄會通過第二支。少了第二支，遮罩等於沒接上而沒有人知道。

這兩支**餵合成字串給掃描函式**，不掃真實檔案——真實檔案的狀態會被後續功能改掉，錨在上面的測試遲早爛。（`build-guardrail` 第 2 步；本專案本週已為此翻車兩次。）

### 契約 2：搬移前後產出完全相同（FR-013）

比對對象是**產生的程式碼文字**，不是「測試有沒有過」。搬移前先拍快照。

涵蓋：單行註解、多行區塊註解、文件註解（含 `@brief`／`@param`／`@return` 各種組合）。

### 契約 3：核心層零註解語法（FR-012）

搬移範圍是**兩處**，不只產生器：

| 位置 | 語法 |
|---|---|
| `src/core/projection/code-generator.ts` | `//`、`/** */`、`/* */`（產生） |
| `src/core/lift/lifter.ts` | `/^\/\/\s?/`、`/^\/\*\s?\|\s?\*\/$/`（剝除） |

第二處是 Phase 0 才發現的——**中立性護欄看不見它**，因為護欄只找身分字串、不找語法。

### 契約 4：沒有語言套件時的行為明確（FR-014）

不得無聲產出空字串。二擇一，並在測試中釘住選了哪一個。

### 契約 5：順序（FR-021）

```
修量測 → 量一次 → 搬投影 → 量一次 → 才改分層 → 量一次
```

三次量測分開 commit。中間態「數字已經好看、東西還沒動」如果被 commit，之後沒有人看得出來。
