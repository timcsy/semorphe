# 走第一課撞到的坑

> 2026-08-14。**這份清單是 spec `124` 真正的產出**（US2）。
> ⚠️ 走的人是作者——按 spec 的 Edge Cases，這份清單**會低估卡點**，
> 而「因為知道答案而跳過的地方」另外標。

---

## 🔴 一、`main` 在積木上不存在——而課本第一步靠它

**實測**：

```
打上 int main() { return 0; }  →  按「程式碼→積木」  →  積木數 = 0
再加一行 cout << "Hello!"      →  積木 = [print, literal_string, endl]
                                    🔴 沒有 main、沒有 return
```

**卡在哪一步**：第一步（「先讓程式有一個起點」）。
**卡的是說明還是工具**：🔴 **兩者都是**。

- 說明錯了：課本寫「👀 **看左邊**——積木出現了」，**而它不會出現**
- 而工具的行為是**刻意的**：積木側只呈現**語句**，`main` 是骨架不是內容

### ⚠️ 而這動搖的不只是一句話

第一課的教學設計是「**先建立起點，再往裡面放東西**」——
而積木側**看不到那個起點**。學生在積木側看到的是**懸空的三顆積木**。

> **「同一個程式的兩種樣子」這句話，在第一課的第一步就不完全成立
> ——程式碼側有 main，積木側沒有。**

🔴 **而這是這個產品最核心的宣稱**（唯一真實，各式投影）。
**第一課撞到它，不是巧合——第一課本來就會撞到最基本的東西。**

**繞過的方式**：把第一步改成「先寫一行會動的」，`main` 當作**背景**帶過，
而不是當作第一個概念教。

---

## 🟢 二、`#include` 與 `using namespace` 自動補上了

**實測**：學生只打了 `int main(){ cout << ... }`，
而執行後程式碼變成：

```cpp
#include <iostream>
using namespace std;
int main() { … }
```

**這是好事，而它改變了「三個概念」的算法**：
`include` 與 `using_namespace` 雖然在 L0 的 19 顆裡，
**但學生不需要學它們就能跑第一個程式**。

⚠️ 而它有一個**教學上的副作用**：學生會以為那兩行「本來就在」。
**第一課不解釋是對的，而第幾課要解釋是一個未決。**

---

## ⚠️ 三、開場是**完全空白**的

```
code: ""      blocks: 0
```

而按鈕列有 14 個（執行／自動／積木→程式碼／程式碼→積木／清空／檔案／複製／插入…）。

**卡的是工具**：一個新手面對兩個空框與 14 個按鈕，
**不知道要先動哪一個**。

⚠️ 而課本第一句就說「在程式碼那一側，打上這段」——**繞過了那個問題**。
**那是說明在替工具擦屁股**，而它有效。

> **一份好的說明可以蓋住一個不好的起點——而蓋住不等於解決。**

## 因為知道答案而跳過的地方（spec 要求特別標）

| 我跳過的 | 一個新手會卡在哪 |
|---|---|
| 「程式碼→積木」這個按鈕要按 | ⚠️ 我知道要按它。**課本有寫，而它是課本救的，不是工具救的** |
| 分號、引號 | 我不會漏。而漏了會怎樣**這一課沒有實測** |
| 執行按鈕在哪 | 我知道是「▶ 執行」 |
| 輸出跑到哪裡 | 我知道看下方。⚠️ **而課本沒說輸出會出現在哪** |

🔴 **最後一條是說明的缺陷**，而它是我因為知道答案才沒撞到的——**已補進課本**。

---

## 沒有卡的地方（明確寫出來）

- 第二步（加 `cout`）→ 積木正常出現，波浪 0，錯誤 0
- 第三步（執行）→ 輸出 `Hello!`，與 `goal.txt` 逐字相同

## 這份清單改變了什麼

```
① 課本第一步重寫             main 不當第一個概念教
② 課本補「輸出會出現在下方」   我因為知道答案而漏掉的
③ 🔴 而「兩種樣子」這句宣稱    在第一課就不完全成立——那要進知識庫
```

⚠️ **而面板需求仍然不足以判斷**——走一次只暴露了說明的缺陷，
**沒有暴露「需要一個教材面板」**。那需要**第二個人**走一遍。

# 🔴 使用者走過一遍了（2026-08-14，本檔最重要的一段）

> 逐字：「**我走過一遍了，OK，不過如果可以有圖片支援更好，
> 或是到時候如果直接跟 UI 結合，可能可以直接用指的**」

## 一、⚠️ 「OK」——而那是「沒有卡」的意思

spec 的 US2 場景 2 要求「沒有卡」必須被**明確寫出來**。

**這裡明確寫出來：一次都沒有真正卡住。** 課走得完，程式跑得起來。

⚠️ **而那讓上面那四處「我因為知道答案而跳過的地方」也一起沒被撞到**
——包括「分號漏掉會怎樣」（那一條到今天仍然**沒有實測**）。

## 二、🔴 而兩個回饋的【性質不同】，這個差別是本段的重點

```
圖片支援        「更好」          增益      不做也走得完
直接用指的      「到時候如果…」    增益 ＋ 未來式   同上
```

**兩個都不是卡點。** 沒有它們，課**照樣走得完**——而那已經被證實了。

> **一個「更好」與一個「走不下去」，在待辦清單上長得一樣，
> 而它們的優先序差一個數量級。**

⚠️ 所以這一段**不構成**「該做教材面板了」的證據。
它構成的是：**做了會更好，而它今天仍然不是瓶頸。**

## 三、而「用指的」命中了一個【被標為猜測】的設計

`knowledge/draft/2026-08-14-教材要如何呈現.md` §二 逐字：

> 「**教材的單位是「指一個節點」，不是「給一段文字」。**」

而 §八 把它標為**猜的**（「而學生可能根本不需要被指，他自己找得到」）。

**使用者獨立提出了同一件事。** 🟢 那把它從「作者的猜測」變成
「**至少有一個人想要**」——⚠️ **而仍然不是「有人因此卡住」**。

> **一個猜測被獨立提出，證明的是它【想得到】，不是它【必要】。**

## 四、🆕 而「圖片」是我沒預測到的

`draft` 的八節裡**一次都沒有提到圖片**。

⚠️ 而它有一個好消息：**圖片放在課的資料夾裡就好**，
不破壞「加一課 ＝ 新增一個資料夾，零編輯」。

```
lessons/01-印出一句話/
  lesson.md
  goal.txt
  images/…        ← 不影響任何既有檔案
```

🔴 **而它便宜到不需要新機制**——markdown 的圖片語法就夠了。
**這是三個候選裡唯一今天就能做而且零風險的。**

---

## 這一段改變了什麼

```
① 「沒有卡」被明確記錄            spec US2 的要求兌現
② 圖片 ＞ 用指的                  🔴 便宜、零風險、而且我沒預測到
③ 「用指的」從猜測 → 有人想要      而【仍然不是瓶頸】
④ ⚠️ 而「漏分號會怎樣」仍未實測    那是唯一還開著的空白
```
