# Feature Specification: 宣告的子節點名沒有人讀

**Feature Branch**: `067-declared-children-guardrail` ｜ **Created**: 2026-08-06

## 為什麼做這個

修 066 時撞見的：`var_declare` 的概念定義說「我有一個叫 `init` 的子節點」，
而它的**五條路全部讀 `initializer`**。兩邊都能跑、測試全綠，而那個宣告沒有
任何人讀。

**危險在於完備性護欄是照著概念定義合成節點的。** 它建了一個 `init` 子節點，
每一條路都看不到它，於是每一條路都拿預設值跑完，然後回報 ✅。

> **量測工具照著一份錯的宣告去合成輸入，就會量到一個不存在的東西。**

這是「殼」的一個新形狀：不是路徑空的，是**餵給路徑的東西是空的**。

## Requirements

- **FR-001**: MUST 量「概念宣告了某個子節點名，而原始碼裡沒有任何地方讀它」
- **FR-002**: 比對 MUST 加詞界——`children.init` 是 `children.initializer` 的子字串
- **FR-003**: MUST 有雙向合成注入，**外加一支專門釘詞界的**
- **FR-004**: MUST 說明本護欄不檢測什麼——它只抓「完全沒有人讀」，抓不到「讀錯地方」

## Success Criteria

- **SC-001**: 護欄存在、有基線、有雙向棘輪
- **SC-002**: 沒有人讀的宣告歸零
- **SC-003**: 既有測試全數通過

## 蓋起來立刻抓到的兩筆

`cpp_ifdef` / `cpp_ifndef` 的 `children` 寫成**陣列** `[{ body: … }]` 而不是
物件——其他每一個概念都是物件。合成器因此建出 `children: { "0": … }`，
而執行器讀 `children.body`。
