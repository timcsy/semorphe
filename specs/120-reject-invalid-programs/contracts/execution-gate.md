# 契約：執行閘門

**Date**: 2026-08-14

---

## 契約一：判定是一個純函式，住在核心

```
canExecute(tree) → { ok: true } | { ok: false, reason, nodeIds }
```

- MUST 只看 `syntax_error`（沿用 `DIAGNOSTIC_CAUSES`，**不另立一份清單**）
- MUST NOT 讀寫任何外部狀態
- MUST 回傳**哪些節點**造成拒絕——訊息要指得出位置

> **「哪些降級原因是使用者的錯」只能有一處定義。**
> 兩處的話，顯示與執行遲早會說不同的話。

---

## 契約二：閘門在 `ExecutionController`，不在直譯器

```
ExecutionController  知道「使用者按了執行」   → 🔴 閘門在這裡
Interpreter          只知道有人給了它一棵樹   → ❌ 不在這裡
```

**兩個理由**：

1. FR-004 要求的是**時機**（按執行才判），而直譯器不知道時機
2. ⚠️ **既有測試直接呼叫 `interpreter.execute(tree)`**
   ——放在那一層會擋掉一大片與本功能無關的測試

---

## 契約三：什麼時候【不】判定

```
編輯中               ❌ 不判定（波浪提示照舊，那是上一輪的事）
同步（程式碼↔積木）   ❌ 不判定
按執行               ✅ 判定
單步／繼續           ✅ 判定（它們也是「使用者要求執行」）
```

🔴 **這是本功能最大的風險點**：編輯中的程式大部分時間都是不合法的。

---

## 契約四：訊息

MUST 同時說出**為什麼**與**你的程式還在**（抄 `refusal-message` 的形狀）。
MUST NOT 只說「執行失敗」——那是無法行動的訊息。

|---|---|---|

⚠️ 除了 `behavior-error.json`，**其餘 42 條基線一個都不准動**。
