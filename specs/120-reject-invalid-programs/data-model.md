# Data Model：三個實體

**Date**: 2026-08-14

---

## 實體一：參照工具的失敗（US1 新增分類）

今天 `onlyInterpreterRuns` 是**一個數字**。之後：

| 類 | 意思 | 例 |
|---|---|---|
| `toolCannotRun` | **工具**跑不動 | 找不到標頭、環境問題 |
| `programIsIllegal` | 🔴 **編譯器看懂了而且拒絕** | 語法錯誤、未宣告、型別不符 |
| `unclassified` | ⚠️ **判不出來** | 訊息對不上任一判準 |

> **第三類不可省。** `build-guardrail` 第 5 步：判不出來就說判不出來，
> **且不計入安全**——為了讓數字好看而樂觀歸類，比沒有分類更糟。

⚠️ 分類判準**先在合成樣本上驗過**（第 6 步）：一段缺標頭的、一段真的不合法的。

## 實體二：執行閘門（新增）

```
輸入   一棵語義樹
輸出   可以跑 ／ 不可以跑（＋為什麼）
```

**判準沿用既有的常數**——「哪些降級原因是使用者的錯」只能有一處定義，
否則顯示與執行會漂移。

| 降級原因 | 顯示 | 執行 |
|---|---|---|
| `syntax_error` | Error | 🔴 **擋** |
| `unsupported` | Info | ✅ 放行——**我們的問題，不是使用者的** |
| `nonstandard_but_valid` | Info | ✅ 放行 |

⚠️ **積木側天然無作用**：積木不會有 `syntax_error` 標記。
**不為它寫例外**——例外會變成沒有人維護的分支。

## 實體三：拒絕訊息

形狀**已經存在**（`refusal-message.ts`，存檔載入那次），逐字：

> 「一定要說出兩件事：**為什麼**，以及**原檔還在不在**。」

執行版：

```
為什麼      這段程式有語法錯誤，還不能執行
還在不在    你的程式沒有被改動，補好之後再按一次執行
```

⚠️ **不可以只說「執行失敗」**——那是無法行動的訊息。
