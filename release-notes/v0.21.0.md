# Semorphe v0.21.0

> 上一版 v0.20.0（2026-09-13）到這一版，將近兩個月、三百多次合併。這一版最大的改變：**程式的執行與「對不對」的判斷，全部交給 Cella**（一個依照 C／C++ 標準語意運作的判斷引擎），semorphe 專心做積木、程式碼、流程圖之間的轉換。

## ✨ 亮點

### 執行改由 Cella 負責
- 按「執行」時，程式依照 C／C++ 標準的語意跑。原本的 JavaScript 模擬執行器已退場，所以模擬和真實編譯器結果不一致的問題不會再出現。
- **跑到一半出錯**（例如除以零、陣列越界）時，程式會停在出錯的那一塊、那一行，並用中文說明原因；之前印出的輸出還在，變數面板保留出錯當下的值。
- **除錯**：可以設中斷點、逐步執行，停下來時改一個變數的值再繼續。執行介面改成 DAP 的形狀，VSCode 擴充也走同一條路。
- 判斷不出來的情況（還不支援的寫法、跑太久）會照實說明，**不會假裝程式沒問題**。
- **Python** 也接上了 Cella。

### 寫程式的同時就檢查（不用按執行）
- 程式還在寫的時候，就會標出這些問題：
  - **未定義行為**：用到還沒有值的變數、讀寫到陣列外面、整數溢位、除以零……
  - **找不到的名字**：會提示「你是不是要寫 ○○」，或指出少引入了哪一個標頭檔。
  - **編譯不過**的寫法。
- 狀態列會顯示「判斷：N 個問題」，或「N 處判不出來」。
- 錯誤訊息大多是中文說明；其中「編譯不過」「型別接不上」等幾種目前還附著判斷引擎的英文原文——**下一版會全部改成好懂的中文**。

### Arduino
- 新增「硬體」分頁，**畫得出板子做了什麼**（每個腳位的變化）。
- 暫停時可以改感測器的輸入值，再繼續看程式怎麼反應。
- 板子相關的標頭檔一律寫回標準的名稱。

### 換風格，結果不變
- 把 `cout` 換成 `printf` 風格時，會**照每個值的型別**選格式：字元用 `%c`、小數用 `%g`、`long long` 用 `%lld`、字串用 `%s` 加上 `.c_str()`。原本一律寫 `%d`，字元會印成數字，小數會變成未定義行為。
- 判斷不出型別的那一行**保留 `cout`**，並在行尾註明原因，確保切換前後跑出來的結果一樣。
- `cin` 換成 `scanf` 時也照型別選格式；`while (cin >> x)` 會正確改寫成 `while (scanf(...) == 1)`。

### 積木
- **只算一次、結果不留下的運算式**（例如離散化常用的 `cc[a[i]];`）會包成一顆「算一次」積木，留在原本的位置。原本這種積木轉回程式碼時會跑到 `main` 外面。
- **收合**：積木可以收起來，程式碼也可以摺疊，兩邊同步。
- 這些寫法轉成積木再轉回來，**不再被悄悄改寫**：
  - `v.emplace_back(...)` 不再變成 `push_back`，`s.emplace(...)` 不再變成 `insert`；
  - Python 的集合推導式 `{x for x in xs}` 不再變成串列；
  - `struct` 裡的 `int x, y;` 不再消失；
  - Serial 的接收者不再遺失；
  - `switch` 裡空的 `case` 也能正確轉回。
- `for (int* p = begin(a); …)` 的第一格可以放指標宣告了。
- `std::string::npos` 寫成哪一種寫法都認得。

### 課程
- 「跟著做」每一步的積木對照圖全面重產。
- 第六課重新設計，次方與開根號回到「跟著做」。
- 課文的工具箱會補上解答需要用到的積木。

## 🔧 已知的限制
- **字串下標 `s[0]` 切成 `printf`**：判斷引擎給的型別還不對，這一行暫時保留 `cout`（引擎那邊已修好，等它發布新版）。
- **編譯錯誤的說明還很籠統**：目前只會說「這一句不合語言的規則」，判斷引擎正在把編譯錯誤細分成具體的種類（不是左值、型別不能相加、引數不合……），之後會補上更具體的中文說明。
