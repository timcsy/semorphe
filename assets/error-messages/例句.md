# 錯誤訊息的例句

> 由 `tests/integration/error-message-examples.test.ts` 產生——不要手改。每一種錯誤一支最小的程式，交給真的 Cella 判，
> 走產品同一條路（`toDiagnostics` → 兩側的文案），印出學生看到的字。改了文案或升了 Cella，這一頁會跟著變——看過再重產。

## 用到還沒有值的變數

```cpp
int main() {
    int total;
    cout << total;
}
```

判決：`reject`

- 積木：「total」還沒有值就拿來用了
- 程式碼：第 3 行：「total」還沒有值就拿來用了｜詳細資訊：C++17 [dcl.init]p12
  - 為什麼：變數宣告了但還沒給值，裡面是一個說不準的數字，拿它來算結果也說不準。
  - 試試看：宣告的時候就給一個值，例如 int total = 0;

## 除以零

```cpp
int main() {
    int a = 0;
    cout << 10 / a;
}
```

判決：`reject`

- 積木：「10 / a」除以零了
- 程式碼：第 3 行：「10 / a」除以零了｜詳細資訊：C++17 [expr.mul]p4
  - 為什麼：除數是 0 時，這個除法沒有答案；程式不能拿一個沒有答案的值繼續走。
  - 試試看：除之前先用 if 檢查除數是不是 0。

## 陣列越界

```cpp
int main() {
    int a[3];
    a[5] = 1;
}
```

判決：`reject`

- 積木：「a[5]」的索引是 5，可是只有 3 格（0 到 2）
- 程式碼：第 3 行：「a[5]」的索引 5 超出範圍——只有 3 格（0 到 2）｜詳細資訊：C++17 [expr.add]p4
  - 為什麼：陣列只有宣告的那幾格，編號從 0 開始；超過最後一格就是碰到別人的記憶體。
  - 試試看：檢查索引：大小是 n 的陣列，能用的是 0 到 n-1。

## 差一：用到最後一格的下一格

```cpp
int main() {
    int a[3];
    a[3] = 1;
}
```

判決：`reject`

- 積木：「a[3]」的索引是 3，最後一格是 2（只有 3 格）
- 程式碼：第 3 行：「a[3]」的索引 3 剛好在結尾之後——最後一格是 2｜詳細資訊：C++17 [expr.unary.op]p1
  - 為什麼：容器的結尾之後沒有東西，讀寫那裡就像陣列越界。
  - 試試看：確認迴圈或迭代器在 end() 之前就停下來。

## 整數溢位

```cpp
int main() {
    int x = 2147483647;
    x = x + 1;
    cout << x;
}
```

判決：`reject`

- 積木：「x + 1」：2147483647 + 1 超出 int 能放的範圍
- 程式碼：第 3 行：「x + 1」算的是 2147483647 + 1，超出 int 能放的範圍｜詳細資訊：C++17 [expr]p4
  - 為什麼：int 能放的數字有上限（大約 21 億），算超過了結果就壞掉了。
  - 試試看：數字可能很大的時候改用 long long。

## 找不到名字

```cpp
int main() {
    cout << score;
}
```

判決：`reject`

- 積木：找不到「score」這個名字——用之前要先宣告它
- 程式碼：找不到名字「score」——用之前要先宣告
  - 為什麼：C++ 要先宣告一個名字，才知道它是什麼、能做什麼。
  - 試試看：在用它之前先宣告，例如 int score = 0;——或檢查是不是打錯字。

## 名字打錯（有長得很像的）

```cpp
int main() {
    int total = 1;
    cout << totl;
}
```

判決：`reject`

- 積木：找不到「totl」這個名字——是不是要寫「total」？
- 程式碼：找不到名字「totl」——是不是要寫「total」？
  - 為什麼：名字差一個字也是不同的名字；這裡用的名字沒有宣告過。
  - 試試看：改成建議的那個名字。

## 大小寫打錯

```cpp
int main() {
    Cout << 1;
}
```

判決：`reject`

- 積木：找不到「Cout」這個名字——是不是要寫「cout」？
- 程式碼：找不到名字「Cout」——是不是要寫「cout」？
  - 為什麼：名字差一個字也是不同的名字；這裡用的名字沒有宣告過。
  - 試試看：改成建議的那個名字。

## 串流配錯運算子

```cpp
int main() {
    int x;
    cin < x;
}
```

判決：`reject`

- 積木：「cin」要配「>>」，不是「<」
- 程式碼：「cin」後面要接「>>」，這裡寫成了「<」
  - 為什麼：cout 用 << 把東西送出去，cin 用 >> 把東西讀進來，方向是固定的。
  - 試試看：把運算子換成建議的那一個。

## 等號左邊不是變數

```cpp
int main() {
    int a = 1, b = 2;
    a + b = 3;
}
```

判決：`reject`

- 積木：「a + b」不能放在等號左邊
- 程式碼：第 3 行：等號左邊要是一個變數，「a + b」是一個算出來的值
  - 為什麼：等號的意思是「把右邊的值放進左邊」；左邊要是一個放得下東西的地方，例如變數。
  - 試試看：把要算的式子移到右邊，例如 c = a + b;

## 呼叫時引數不合

```cpp
int f(int x) {
    return x;
}
int main() {
    f(1, 2);
}
```

判決：`reject`

- 積木：「f」的引數型別不合
- 程式碼：第 5 行：呼叫「f」的引數型別不合
  - 為什麼：呼叫函式時給的東西，數量和型別都要和函式宣告的參數對得上。
  - 試試看：對照函式的宣告，補上、拿掉或換掉引數。

## 重複宣告

```cpp
int main() {
    int a = 1;
    int a = 2;
}
```

判決：`reject`

- 積木：「a」已經宣告過了
- 程式碼：第 3 行：「a」在同一個範圍裡已經宣告過了——換一個名字，或拿掉前面的型別直接用它
  - 為什麼：同一個範圍裡，一個名字只能宣告一次；第二次就分不出是哪一個。
  - 試試看：要改它的值就直接寫 a = 2;（不要再寫型別）；要另一個變數就換個名字。

## 回傳值不合

```cpp
void f() {
    return 1;
}
int main() {
    f();
}
```

判決：`reject`

- 積木：void 函式不能回傳值
- 程式碼：函式宣告成 void（不回傳），這裡的 return 卻給了值
  - 為什麼：函式宣告的回傳型別，決定了 return 要不要帶值、帶什麼值。
  - 試試看：void 函式只寫 return;；有回傳型別的函式，每條路都要 return 一個值。

## 運算元型別不合

```cpp
int main() {
    string s = "a";
    int x = s * 2;
}
```

判決：`reject`

- 積木：std::string 和 int 不能用 * 運算
- 程式碼：第 3 行：「s * 2」——std::string 和 int 不能用 * 運算
  - 為什麼：不是每一種型別都能做每一種運算，例如字串不能乘以數字。
  - 試試看：先把值換成能運算的型別，或換一個運算。

## 型別轉不過去

```cpp
int main() {
    int x = "abc";
}
```

判決：`reject`

- 積木：const char * 不能轉成 int
- 程式碼：第 2 行：「int x = "abc"」是 const char *，這裡要的是 int，兩者不能互轉
  - 為什麼：這兩種型別之間沒有自動的轉法，C++ 不知道要怎麼變過去。
  - 試試看：換成這裡要的型別的值，或改變數的型別。

## 跑太久（可能是無窮迴圈）

```cpp
int main() {
    while (true) {
    }
}
```
