# 教案

一堂課是一個資料夾，裡面**兩個檔**：

```
lessons/<軌道>/<編號>-<課名>/
    lesson.json    宣告——編輯器讀它（要開哪些積木、釘住什麼、跑出來該是什麼）
    lesson.md      課文——學生讀它
```

## 六條軌道

| 軌道 | 章數 | 目標 | 給誰 |
|---|---|---|---|
| `cpp-beginner` | 15 | `cpp` | **從頭學程式**（C++） |
| `python-beginner` | 12 | `python` | **從頭學程式**（Python） |
| `arduino` | 14 | `arduino-uno`（第 11 課 `esp32`） | 硬體專題，自己就是入門 |
| `cpp-advanced` | 13 | `cpp-advanced` | 進階：排序／二分搜／STL／圖／DP |
| `c-bridge` | 5 | `c` | **C++ → C** 銜接 |
| `python-bridge` | 6 | `python` | **C++ → Python** 銜接 |

**每一個起點都預設從頭來。** 銜接與進階另外開軌——
所以 `python-beginner` 不假設你會別的語言，而 `python-bridge` 假設你會 C++。

### 編號

**每一軌各自從 `01` 開始，兩位數，不加字母前綴**
（資料夾名已經說明是哪一軌了）。

課文裡引用別課的規則：

```
同一軌      第 5 課
跨軌        C++ 入門第 5 課 · Arduino 第 5 課 · C 銜接第 3 課 · Python 銜接第 6 課
```

⚠️ **不要寫「第五課」**（中文數字）——兩種寫法混用時，
搜尋與批次改號都會漏掉其中一種。

## 為什麼只有兩個檔

> **程式碼只寫在 `lesson.md` 裡一份。**

`lesson.json` **不重複那段程式碼**。護欄從 `lesson.md` 的
`## 完成的樣子` 那一段 fenced block 把它抽出來跑，比對 `check.stdout`。

⚠️ 一份寫在兩處的程式碼，遲早會有一處是舊的，而**學生看到的永遠是舊的那一處**。

## `lesson.json`

```jsonc
{
  "title": "印出一句話",
  "estimate": "20 分鐘",
  "pins":  { "target": "cpp" },        // 選了這堂課，編輯器切成這個組態
  "components": ["cpp:func_def", …],   // 🔴 量出來的，不是寫出來的
  "tasks": [                            // 🔴 一課有好幾題（2026-09-04）
    { "id": "follow", "title": "跟著做",
      "check": { "stdout": "Hello!\n", "stdin": [] } },   // 🔴 也是量出來的
    { "id": "ex1", "title": "練習：再印一行" }             // ⚠️ 沒有 check ＝ 這一題判不了
  ]
}
```

### 🔴 `tasks`——一課有好幾題，而每一題各自有裁判

在此之前是一課一個 `check`，而學生一開始做練習題，寫的就是**另一支程式**：

```
學生：認真在做練習 2
裁判：還沒對——你的輸出是「1 2 3」，這一課要的是「Hello!」
```

> **一個會在學生做對事情時說他錯的裁判，比沒有裁判更糟。**

⚠️ **舊的 `check` 仍然讀得進來**（成為第一題「跟著做」），所以還沒寫 `tasks`
的課一個字都不用改。

三條規矩：

- **第一題永遠是「跟著做」**——它就是課文帶著學生做的那一支
- **`id` 這一課裡唯一**，而且**不得是空字串**（那是狀態列上「純練習」的值）
- **沒有 `check` 的題目仍然是題目**：「改用 `while` 寫」的輸出一模一樣，
  而這裡的規矩是〈只判輸出，不判寫法〉。那種題目該做的是**沉默**，不是說「對了」

### `kind: "arrange"`——把解答的積木打散，讓他排回去

```jsonc
{ "id": "ex1", "title": "練習：把印出總和的積木排回去",
  "kind": "arrange",
  "check": { "stdout": "15\n" } }     // 🔴 必填——排完按執行，由裁判說話
```

外部證據（`knowledge/concepts/認知鷹架.md`）：

> 把打散的程式碼排回去，**學習成效與「自己寫程式」相同，而只花 70% 的時間**。

而在這裡它幾乎是免費的——**積木本來就會卡榫、會拒絕接錯**，
而那些研究全部在用「文字行卡片」。

三條規矩：

- 🔴 **一定要有 `check`**——排完之後誰來說話？沒有它，他排完沒有任何人出聲
- 🔴 **一定要有 `solutions/<題目 id>.<副檔名>`**——打散的來源就是那份參考解答
  （護欄 `audit-lessons` 擋著）
- ⚠️ **打散的是【語句】，不是每一塊積木**：把 `cout << n << endl;` 拆成三塊
  不是「排回去」，是拼圖。巢狀迴圈**裡面**那幾句也留在原地

⚠️ 而打散是**確定性**的（種子是題目的身分）：學生重整理頁面不會換一題，
老師說「第三塊拖到最上面」時兩個人看到的是同一個畫面，而護欄驗得了它。

### `view`——這一題預設看哪一邊

```jsonc
{ "id": "rebuild", "title": "排回去", "kind": "arrange",
  "view": "blocks",             // ⚠️ 省略 ＝ 不動版面，學生看什麼就是什麼
  "check": { "stdout": "..." } }
```

```
"code"     專注在程式碼        抽象度 3
"compare"  程式碼與積木對照     抽象度 2
"three"    三欄                抽象度 2
"blocks"   專注在積木          抽象度 1
"flow"     專注在流程          抽象度 0
```

🔴 **它是建議，不是鎖。** 只在**換題那一刻**套用一次；學生接著自己改版面，
系統**不得**在下一次重畫時把它搶回去。

> **一個鎖，多數時候不是寫成鎖的。
> 它是一段「每次都重新套用預設值」的程式碼。**

外部證據是學習者控制的整合分析（`knowledge/concepts/認知鷹架.md`）：
**「sequence control is the only type that generally does not harm」**
——順序的控制權是唯一一種一般不會有害的；而**版面就是順序的控制權**。

#### 🔴 一課的 `view` 序列要是一條【語意波】

護欄 `audit-lesson-wave` 驗的不是「有沒有寫 view」，是**寫了的那幾課走的是不是一條波**：

```
compare(2) → blocks(1) → code(3)     ✅ 先下到具體，再回到抽象
compare(2) → blocks(1)               🔴 只下不上——「玩過了，但沒有學到」
code(3)    → compare(2) → blocks(1)  🔴 一路往下，最後停在最具體的地方
```

⚠️ **上升只有在下降之後才算數**：一課從頭到尾都在爬，那不是波，那是沒有解包過。
術語出自 Semantic Waves（Maton 的 LCT）——unpack 之後要 repack，
而 NCCE 的十條原則裡「**只解包不重打包**」被列為最常見的失誤。

⚠️ 只有一句話的課**排不了也波不動**（`movable < 2`）——那幾課不寫 `view`，
而護欄只看寫了的那些。

### `predict`——跑之前先叫他猜一下

```jsonc
{ "id": "follow", "title": "跟著做",
  "check": { "stdout": "1\n2\n3\n4\n5\n" },
  "predict": "iterations" }   // ⚠️ 省略 ＝ 自動判定；"none" ＝ 說出口的不問
```

```
"iterations"   猜這個迴圈會跑幾次   ⚠️ 樹上要【恰好一顆】迴圈才會問
"output"       猜它會印出什麼
"choice"       選擇題               ⚠️ 要一起寫 choices
"none"         這一題不問
省略           自動：一顆迴圈 → 跑幾次；沒迴圈而輸出 ≤ 3 行 → 輸出；其餘不問
               🔴 自動判定【不會】選中選擇題——只有作者寫了才有
```

#### `choices`——🔴 一個說不出誤解的干擾項，只是一個隨機的錯答案

```jsonc
"predict": "choice",
"choices": [
  { "text": "及格",           "correct": true },
  { "text": "不及格",         "why": "把 >= 讀成 <=——條件的方向反了" },
  { "text": "及格\n不及格",   "why": "以為 if 跟 else 兩邊都會跑（它們是【二選一】）" },
  { "text": "（什麼都沒印）", "why": "以為 75 沒有「符合」任何一個條件" }
]
```

學生選了錯的那一個之後，畫面上說的是那句 `why`——**「你選的那一個是：
把 >= 讀成 <=」**。沒有它，能說的只有「不對」。

> **選擇題的價值全在干擾項，而干擾項的價值全在它說得出哪一個誤解。**

三條會當場丟錯的規矩：**恰好一個 `correct`**、**每個干擾項都要有 `why`**、
**至少兩個選項**。而 `text` **就是輸出長什麼樣**（含換行），
不是「A. 五行數字」那種描述。

🔴 **目的是「他想過」，不是評量**——沒有分數、沒有猜對率，
而跳過的按鈕一直在。強迫產生的是 `aaa`，不是思考。

⚠️ 而它**只在題目模式下、程式改過之後的第一次執行**才問：
跑過一次他就知道答案了，再問是儀式。

### 🔴 `solutions/`——每一題練習的期望輸出，都要有人跑過

```
lessons/cpp-beginner/10-重複/
  lesson.json
  lesson.md
  solutions/ex1.cpp     ← ⚠️ 不進課文，靜態頁不產它，學生點不到
```

一份手打的 `check.stdout` 錯一個空格，那一題的裁判就會對**每一個做對的學生**
說他錯，而畫面上完全看不出來。

> **一個沒有人跑過的期望輸出，是一個還沒被發現的、會說錯話的裁判。**

兩道護欄各守一半：`audit-lessons` 驗檔案在不在，
`e2e/lessons.spec.ts`〈參考解答〉真的跑一次比對。

⚠️ 第一題不需要——它的解答就是課文裡的〈完成的樣子〉。

### 🔴 `components` 與 `stdout` 都是量出來的

寫課的人不要憑印象列。用 `e2e/measure-lesson-codes.spec.ts`
（餵 `.lesson-measure/codes.json`）真的跑一次，拿到的那份才算數。

實例：第一課憑印象是「`func_def` ＋ `print` ＋ `literal_string`」，
而實測多一顆 **`cpp:literal_number`**——`return 0;` 的那個 `0`。

護欄 `tests/integration/audit-lessons.test.ts`（存不存在）與
`e2e/lessons.spec.ts`（真的用到嗎、真的跑出那樣嗎）兩條一起守。

完整做法見 `knowledge/skills/write-lesson/SKILL.md`。

## 🔴 〈完成的樣子〉要寫**完整的程式**，含 `#include`

那一段就是課文頁上「對照」的左半——它與積木**逐字對得起來**，
所以鷹架那幾行（`#include`／`using namespace`）**要寫進去**。

⚠️ 少了它們的症狀不是報錯：積木上有那幾塊（淡的），而左邊沒有對應的行，
於是它們**沒有號碼可以對**——讀者看到的是「有幾塊積木沒有來源」。

🟢 而課文頁把〈完成的樣子〉那個程式碼框與對照**合併成一個**：
同一支程式不印兩次。

## 🔴 改了〈完成的樣子〉之後，要重產那張對照

每一課的靜態頁底下有一張「同一支程式，兩種看法」——**程式碼的每一行有一個號碼，
而那個號碼印在對應的積木上**。它是**產生**的，不是截圖：

```bash
npx playwright test tools/demo/record-blockmaps.spec.ts \
  --config=tools/demo/playwright.demo.config.ts
```

⚠️ **忘了重產不會安靜地過去**：第一百零二條護欄拿產生時記下的 `codeHash`
跟課文現在的〈完成的樣子〉比，不一樣就紅，而且說得出是哪一課。

> **一張手工截的圖是死的；一份腳本產的對照是活的——課文改了它會紅。**

⚠️ 而課文頁有一條硬性零：**不得載入任何 JavaScript**。所以那張圖是**靜態**的
——用編號配對，不是滑鼠。它在紙上、在手機上、在讀螢幕的人那裡都成立。

## `lesson.md` 的骨架

```
# <課名>
> <一句話：這堂課要做出什麼>   ·  ⏱ <時間>

## 你會學到三件事      ← 剛好三件，不多不少
## 開始之前            ← 前一課的成果／需要的東西
## 一、… 二、… 三、…   ← 有編號的步驟，每步一小段程式碼
## 完成的樣子          ← 🔴 護欄抽這一段去跑
## 換你了              ← 一個改造題，不給答案
## 這一課你做了什麼    ← 回頭看
## 如果卡住了          ← 症狀／原因對照表
```

「**三件事**」是刻意的上限——寫第四件的時候，那多半是下一課。
