# 護欄基線（Guardrail Baselines）

四條護欄的量測基線。每個檔對應一條護欄。

## 棘輪語義

| 情況 | 結果 |
|---|---|
| 量測結果 ⊆ 基線 | ✅ 通過 |
| 出現基線之外的項目 | ❌ 失敗，報表指名是哪一項 |
| 量測結果 ⊊ 基線（有改善） | ✅ 通過，報表提示可下調基線 |

**數字只准下降。**

## 放寬基線 = 一次 commit

調整這裡的任何檔案都是**顯式動作**，必須在 commit 訊息說明原因。
這是刻意的設計：基線的放寬要在版本歷史中看得見（spec FR-004）。

**明確不用 vitest snapshot**——`vitest -u` 會靜默更新所有快照，
等於「跑一下就自動接受惡化」，正好摧毀棘輪。

## 第一天是紅的，這是預期行為

四條護欄的初始數字都是正數（已知有違規、殼與停用測試存量）。
要求第一天綠等於沒有真的量到東西。護欄的形式是**報表 + 棘輪**，
不是通過／失敗。

## 檔案

| 檔 | 護欄 | 量什麼 |
|---|---|---|
| `neutrality.json` | 中立性 | 核心／呈現層有幾個檔硬編語言專屬元件身分 |
| `completeness.json` | 完備性 | 每元件五路是實作／殼／缺 |
| `defect-ledger.json` | 缺陷帳 | 停用測試的分類與阻斷者 |
| `locality.json` | 就近性 | 每元件的實作擴散度 |

詳見 `specs/049-audit-guardrails/contracts/README.md`。
