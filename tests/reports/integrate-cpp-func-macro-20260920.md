## 🎯 這一關最值錢的東西：**兩根死釘子**

逐條覆核停用測試時量到——兩根 `it.skip` 寫著**同一個錯的歸因**：

```
roundtrip-functions-io.test.ts:254   [BLOCKED:cpp:define]   #define MAX_SIZE 100
fuzz-cpp-functions-io.test.ts:277    [TOMBSTONE:014-…]      #define LIMIT …
```

兩根都說「直譯器不把 `#define` 展開進 scope」——而 `#define MAX_SIZE 100`
**要的不是展開**，是把一個具名常數綁進 scope，那件事 **2026-08-13 就做了**。

實測：翻成 `it` 之後**兩支直接綠**。

> **一根釘子如果把「這件事做不到」寫成「那座墓碑擋著」，
> 那麼做到的那天，沒有人會想到回來看它。**

⚠️ 而**同一個誤判被抄進了第二個檔案**——兩份互相佐證的證據，
來源是同一個人在同一天的同一個猜測。

⚠️ 兩根都是 `it.skip`（**有本體**），所以修好的那天它們**不會變紅**
——缺陷帳自己定義的 `DEADSKIP`：已修好卻沒開回來，白白損失覆蓋。

## 🔴 這一關新發現的：運算式位置的語法錯誤被靜默吞掉

```
位置          原文               產回去          出聲嗎
語句          x @@ 2;            x @@            🟢 UNRECOGNIZED_CODE
括號運算式    cout << (x @@ 2)   cout << (x)     🔴 安靜
宣告的初值    int x = @@@;       int x =         🔴 安靜，而整行壞掉
```

🔴 **它不是這一刀造成的，而是這一刀讓它現形**：盲測抓到「括號裡的逗號運算式」時，
根因正是 tree-sitter 給了一個 `ERROR` 節點**而沒有人看它**。
修好那一個之後，同一個形狀的其餘幾種才單獨露出來。

> **一個缺陷被另一個缺陷的錯誤訊息蓋住時，修好上面那個才會看見它。**

⚠️ **機構其實已經在了**：`lifter.ts` 的 `setConfidenceHigh` 會標上
`degradationCause: 'syntax_error'` ＋ `rawCode`——**而產生器不讀它**。

> **一個標記如果沒有任何投影去讀它，它記住的東西等於沒有被記住。**

釘成 `it.fails` ＋ 一支 ★ 錨點（語句位置那一路不得退步）。
**何時該修**：產生器讀 `degradationCause` 的那一刀。

### ③ `s[s.size()]`——三件都量過

```
真的越界（讀）    string s="ab"; s[3]     🟢 仍然出聲
剛好等於長度      string s="ab"; s[2]     🟢 回 0（g++ 也是）
寫進 s[size()]    s[2]='x'                🟢 仍然出聲（UB 沒有被一起放寬）
陣列的真越界      int a[2]; a[5]          🟢 仍然出聲
```

靜默回退護欄的**第六種形狀**（`邊界語義`）的相容表**只收「合法」**
——判成別的就是矛盾，而那條矛盾檢查會叫。

### ④ 誠實降級不會誤傷

```
不認得的名字 rep(2,3)     🟢 仍然是 cpp:func_call，跑出 5
語句位置的未知呼叫 g(7)   🟢 照舊
```

判準是「開頭是一個**已知的**函式形巨集呼叫」——一個不認得的名字本來就是函式呼叫。

### ⑤ 殘留的停用測試

`it.todo` **21**（這一刀沒有新增）· `it.fails` ＋1（上面那根）· **拔掉兩根死的**。
逐條覆核過與這一刀相關的四筆，其餘的阻斷條件仍然成立。

### ⑥ 抽象元件

`cpp:define_func` 的 `abstractComponent` 是 `null`，而 `_why` 寫了理由：
與同族那顆具名常數的巨集**做的事不同**（一個綁一個值，一個是可展開的樣板），
指同一個抽象父會讓「它們可以互換」這句話變成假的。✅ 一致。

### ⑦ `_why` 是理由不是描述，而且不含別顆元件的身分

```
define_func._properties_why   記著一個【被第 96 條護欄逼出來的】決定
                              （`required` ＋ 兩個不同的退路 ＝ 規格在說謊）
loop_count._traits_why        記著一個【承諾】：宣告了那個性狀
                              就等於承諾產生器讀得懂那個註記
```
🟢 就近性護欄綠（每個膠囊的 `_why` 裡只出現它自己的身分）。

### ⑧ 兩個動作項

- 墓碑補的那一筆 ✅ 讀起來是「**否決仍然成立**，而它的理由被證偽了一半」，
  並明說「**沒有解凍它，而是做了另一件事**」。
  ⚠️ 這一關順手修了它的一行：原文寫「三個條件缺一就**讓開**」，而第三關之後
  那叫**誠實降級**——記錄要跟得上程式碼。
- `fuzz-cpp-hardware.test.ts` 的釘子 ✅ 標記從 `[TOMBSTONE:…]` 改成
  `[UNSUPPORTED:運算式位置的函式形巨集]`，並寫了觸發條件。

### ⑨ 樹修復不會誤收

```
(x @@ 2)      hasError 而沒有頂層逗號    🟢 讓開（與今天逐字相同）
(f(1,2))      有逗號而沒有 error         🟢 讓開
((x=1,y=2), x+y)  巢狀                   🟢 展開正確，跑出 3
```

## 已知限制

1. **運算式位置的函式形巨集**（`SQ(3)` 嵌在算式裡）——墓碑那一側，已釘。
2. **運算式位置的語法錯誤產回去會少一段**——已釘（上面）。
3. **巨集體裡又呼叫另一個巨集**——誠實降級（原文一字不差），語料 0 處。
4. `cout << (…)` 的**雙層括號**——既有排版疣，三者都合法且都是不動點。
