## 🔴 探索階段推翻了自己的前提

這一刀被開成「`flush` 那一族（5 支）」。而先決問題（「這五支修完就跑得完了嗎」）
逐支實測的答案是：**五支全部跑得完**。它們的 `flush` 在一個「讀到輸入才進去」的
分支裡，空輸入下根本走不到。

> **一個「這一族有 N 支」的讀數，如果 N 是照【第一個錯誤】分的，
> 那它量到的是錯誤的順序，不是缺陷的分佈。**

🟢 **而重估之後這一刀變大了不是變小**——見下。

## 順帶修掉的：`cout` 的浮點格式，五個錯疊在一個函式裡

```
                g++          我們（舊）
1e9             1e+09        1.00000e+9      ① 科學記號的尾數沒去尾零
123456789.0     1.23457e+08  1.23457e+8      ② 指數沒補成兩位
0.000012345     1.2345e-05   0.000012345     ③ 切換門檻用 JS 的不是 C 的 %g
999999.5        1e+06        1000000         ④ 指數在【四捨五入之前】算
2.5 → 0 位      2            3               ⑤ 平手時 C 逢五取偶、JS 逢五進位
```

舊碼的註解逐字寫著「**直接沿用**」。

> **一個「直接沿用」的註解，說的是「我沒有比對過」。**

🔴 **母體不是一支語料**——是**每一支印大數或小數的程式**。
⑤ 特別難發現：`3.5 → 4` 兩邊一樣，`0.35 → 0.3` 兩邊也一樣（二進位裡它略小於 0.35）。

> **一個只在「剛好一半」時才不同的規則，
> 測資裡沒有整齊的數字就永遠不會紅。**

🟢 規則整段搬到 `src/interpreter/decimal.ts`（**核心**，因為它只講十進位不講 C++），
並且 `setprecision(n)` 用的是同一份——**位數是參數**。40 格常駐測試，
**每一個期望值都是問 g++ 來的**。

## 三顆的身分怎麼判的

判準原文（`元件代數.md:250`）：
```
🟢 是參數    引數個數相同、接點相同、角色相同——差別只有【一個值】
🔴 是身分    引數個數不同、或語義上做的事不同
```

| | 判 | 為什麼 |
|---|---|---|
| `flush` vs 既有的換行 | **兩顆** | 形狀全同，而**做的事不同**（一個換行＋送出，一個只送出）⟹ OR 的後半 |
| `setw`／`setprecision`／`setfill` | **一顆 ＋ 屬性** | 形狀全同、做的是同一件事（設一個輸出設定）⟹「量什麼不是身分，是參數」 |
| `fixed`／`scientific` | **一顆 ＋ 屬性**，而與上面那顆**分開** | 與帶值的**引數個數不同**（0 vs 1）⟹ 身分 |

⚠️ **`scientific` 語料 0 處而仍然收**：它不是一顆元件，它是一個**列舉的值**。
⚠️ **`fixed` 不與 `setprecision` 合成一顆**，雖然語料裡兩者只一起出現
——單獨的 `setprecision(2)` 是合法且常見的寫法。**語料剛好怎麼寫，不是語義。**

## 詞彙表逼出了更好的名字

探索報告定的是 `cpp:stream_*`，而 `stream`／`setting`／`style` **三個字都不在表裡**。
去查表才看到 **`io` 早就是主體**，而 `cpp:io_sync`／`cpp:io_tie` **就是同一族**。

> **一個逼你用既有詞彙的限制，會在你找不到詞的時候問你：
> 是這個詞不夠，還是這顆元件不該長這樣？**

這一次的答案是第三種：**它該長這樣，只是我把它放錯家族了**。

## ⚠️ 開發途中紅過的兩次，都是【我的檢查】的問題

| 症狀 | 根因 |
|---|---|
| 正向錨點紅（`cout << a << d` 印出 `" "`） | lift 樣式寫了 `match: '^(fixed\|scientific)$'`，而 `match` 是**比較方式**（`startsWith`）不是正規式 ⟹ 那條限制等於不存在，**每個識別字**都被搶走 |
| 第 72 條棘輪退步 26 → 27 | 新測資第一次讓 `'\n'` 進了語料，於是 `cpp:literal_char.char` 被判成「非原子」——**那是跳脫序列不是結構**，寫進判定 |

> **一個不存在的欄位不會報錯，它只會讓你以為那個限制生效了。**

## 🔴 而它指出了下一刀

`cin >> d2[i][j]` 那兩支的根因**不是輸入**，是 `int d2[x*2][7]`
——**二維陣列的維度是運算式**，而 `array_2d_declare` 用 `Number(properties.rows)`
讀它（`NaN` → 零列）。

⚠️ **一維那顆的 `size` 早就是接點**，二維這顆還是屬性——**同一個不對稱**。
⚠️ 而第七十二條**看不到它**：測資裡的維度永遠是數字字面值。
> **語料乾淨不代表模型對：它代表語料是照著模型長的。**
