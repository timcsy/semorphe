## 🔴 發現的 Bug：括號裡的逗號運算式

**輸入**（`fuzz_6`，我一輩子不會自己寫出來的一行）：

```
cout << MAX((x = 3, x + 1), 2) << " x=" << x << "\n";
```

| | |
|---|---|
| g++ | `4 x=3` |
| 我們 | `2 x=1` |

**根因不在巨集**——在 tree-sitter：

```
(x = 3, x + 1)   →  parenthesized_expression
                      assignment_expression
                        identifier x
                        ERROR ⟪3⟫          ← 那個 3 在這裡面
                        binary_expression x + 1
```

而**我們把那個 ERROR 安靜吞掉**：產出 `(x = x + 1)`——`3` 不見了、兩邊熔成一句，
而輸出是一個**型別正確、看起來合理的數字**。

> **一個解析器的 ERROR 節點如果沒有人看它，
> 它會變成一段「乾淨的樹」——而乾淨正是它活下來的原因。**

⚠️ 而**同一段文字在【語句位置】tree-sitter 解得完全正確**：

```
x = 3, x + 1;      語句位置   →  comma_expression      🟢
(x = 3, x + 1)     括號裡     →  assignment ＋ ERROR   🔴
return (x=3,x+1);  回傳位置   →  同樣錯
```

🟢 **修法**：`lang/misparse.ts` 的第三條樹修復——**把它搬到解得對的位置去重解**。
接手條件：節點是 `parenthesized_expression` · 它 `hasError` · 去掉外層括號後
**有一個頂層逗號** · 重解出來是一個乾淨的 `comma_expression`。缺一就讓開。

⚠️ **括號要自己記回去**（`layoutHints.parenthesized`）——這條路繞過了拆括號那個樣式，
不記的話 `cout << (x = 3, x + 1)` 會變成 `cout << x = 3, x + 1`，**那是另一支程式**。

📌 最小重現 6 條進了 `interpreter-matches-compiler`（含兩條 ★ 錨點：
語句位置的逗號、沒有逗號的括號，都不得被弄壞）。

而 `x = 3, x + 1` 兩個都不符——**它被我的過濾條件濾掉了**，不是被產生器丟掉的。

而 **macOS 沒有 `timeout`**——每一支都在那裡失敗，看起來像十支全錯。
