# 模糊測試報告 — C++ — 容器（2026-09-17）

## 摘要

- 語言：C++ ／ 難度：medium ／ 範疇：containers ／ 程式數：**10**
- 出題者：資訊隔離的代理（worktree，看不到原始碼），全部以 `g++ -std=c++17 -Wall`
  零警告編過、各跑三次輸出一致
- 成功執行（參照編譯器那一側）：**10/10**
- Round-trip PASS（產生的程式碼跑起來與 g++ 一樣）：**0/10**
- 語義樹殘差：**0/10 有 raw_code**；語義不動點：**10/10**

## 🔴 先講最重的一個讀數：0/10 不是「壞了十個地方」

十支全部**形狀完美**（lift 認得、產碼回得去、不動點穩），而**沒有一支跑得完**。
把死因攤開之後它們收斂成三族，而其中一族佔七支：

```
迭代器      7 支   ::iterator it = c.begin() / *it / ++it / it != c.end()
接收者      2 支   m[1].insert(5) · idx[key].push_back(…)  （被壓成文字的接收者）
型別轉換    1 支   string(names[i])
```

🔴 **而那七支是一個獨立的量測**：出題者看不到原始碼、沒有被提示過迭代器，
它只是照著 C++ 老師會寫的樣子寫。語料那一側**獨立**量到 `.begin(` 33 次、`.end(` 30 次。

> **兩個互不相關的來源指向同一個缺口，那不是巧合，是下一刀。**

## 抓到並【當場修好】的四個缺陷

### ① `map.insert({k, v})` 被擋掉——**我自己造的迴歸**

修 `multiset` 時我讓「接收者不是集合那一族」丟錯（為了不讓 `vector.insert`
被靜默去重排序）。而 `insert` 這個方法名**只有一個主人**，於是對照表也被擋在門外。

🟢 修法：對照表在執行期宣告 `keyed: true`，而 `insert` 讀它。
⚠️ 同時把 C++ 的語義補齊：`map::insert` 在鍵已存在時**什麼都不做**（覆蓋是 `m[k]=v` 的事）。

### ② `multiset::erase(key)` 只刪一個，而 C++ 刪【全部】

```
multiset<int> s; s.insert(4); s.insert(4); s.insert(7); s.erase(4);
g++ → size 1        我們 → size 2
```

🔴 **這一條在 `multiset` 不能留重複的年代是【對的】**：容器裡本來就只有一個，
「刪一個」與「刪全部」沒有差別。

> **一個「只有在另一個缺陷存在時才正確」的實作，
> 會在那個缺陷被修好的當天變成新的缺陷——而它不當掉，測試也全綠。**

### ③ 🔴 函式參數的型別，從來沒有被登記進 lift 的脈絡

```cpp
void tally(map<char,int>& om){ om['t']++; }   g++ 數一個字母
                                              我們 INDEX_OUT_OF_RANGE: 116
```

`m[k]` 要判成對照表還是陣列，判準是**根變數的型別**（`cpp:map_at` 的檔頭逐字：
「差別在律——陣列索引超出範圍是錯誤，對應表的鍵不存在是插入」）。
而那張「名字 → 型別」的表只收**宣告節點**，`recordDeclaration` 認的是
`<x>_declare` 那一族——**參數不在裡面**。

於是同一段程式在 `main` 裡是對的、搬進函式就壞了，而它壞成一個
**指著使用者沒寫錯的那一行的索引錯誤**。

> **一張「名字 → 型別」的表如果只收宣告，那麼每一個參數對它來說都不存在
> ——而函式正是「同一段程式碼換個地方寫」。**

🟢 修法：`func_def` 的 lift 在 `extractBody` **之前**推一層作用域、登記每個參數。
⚠️ 型別文字正規化成與宣告那一側同一個詞彙（`map<char,int>&` → `map`），
而「哪些名字是容器」**問登錄表**，不自己列一張會過期的清單。

### ④ 二維寫入沒有範圍檢查，留下 JS 的【洞】

```cpp
vector<map<int,int>> g(2);
g[0][1] = 5;        ← 這裡留下洞（第 0 格是 JS 的 hole，不是預設值）
g[0].count(1);      ← 這裡才爆，而且是 TypeError: Cannot read properties of undefined
```

一維那顆早就在檢查了，這裡沒有。

> **一個沒有範圍檢查的寫入，它的症狀不會出現在寫入那一行
> ——會出現在下一個走訪那個容器的人身上，而且是另一種語言的錯誤。**
