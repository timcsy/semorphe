## 🔴 發現：一個真的覆蓋缺口，而它直接打到「貼上 AI 生的程式碼」

盲測的第一輪只認出 **19** 顆接線。數了語料裡腳位到底怎麼被宣告：

```
const int LED_PIN = 13;   19 筆   🟢 認得
#define LED_PIN 13        10 筆   🔴 不認
int ledPin = 13;           3 筆   🔴 不認
```

**41% 的腳位宣告轉不成接線積木**——而 `#define` 是 Arduino 入門教材最常見的
寫法之一（「`#define` 不佔記憶體」那句話到處都是）。

### 處置：三種形式是**一個參數**，不是三顆概念

它們是同一件事（給這根腳一個名字），差別只在語法形式 → `style` 參數
（`const` / `define` / `plain`）。

🔴 **而它必須被帶著**：不記形式的話，學生貼進來的 `#define` 會在
**開一次積木之後**被靜默改寫成 `const int`——在 IDE 裡積木是會寫回 `.ino` 的。

> **一個不記得原文形式的 round-trip，會在使用者沒有要求的時候改掉他的檔案。**

⚠️ 而放寬 `const` **不會**讓誤認變多：擋住誤認的從來不是 `const`，
是「**這個名字有沒有被當腳位用**」。有一條測試專門守這件事
（`int counter = 0;` 不准被搶）。

修完之後：**19 → 32 筆**，殘差仍是 0.00%。

**猜錯 0 筆。** 而 `ENA`／`IN1`／`IN2`（L298N 馬達驅動）回 `unknown` 是**對的**
——名字裡真的沒有零件資訊，而**猜錯比猜不出來嚴重**：學生會照著錯的標籤
理解他的電路。
