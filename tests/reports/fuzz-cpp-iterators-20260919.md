## 🔴 缺陷一：`prev(it, 2)`——「語料 0 處」那個決定被翻面了

探索階段**明文決定不做**第二個引數：

> 「語料 0 處；同族的『移除』那顆做了一個常態留空的插槽，而瀏覽器驗收時它刺眼。」

盲測十支裡**兩支**用了它（`set` 上取倒數第二個、`map` 上往後跳兩格），
而**兩支都剛好死在那一行**——在那之前與 g++ **逐位元相同**。

```
判準              語料      盲測
prev(it, n)       0 處      2/10
```

> **一個「語料 0 處」的讀數量到的是【這批語料的人怎麼寫】，
> 不是【這個寫法有多常見】——而盲測的母體不一樣。**

**修法**：`count` 成為一個**常態留空的接點**（形狀抄同族已出貨的 `container_erase.key_end`）。
⚠️ 它是**同一顆身分**——C++ 的簽名是 `prev(it, n = 1)`，一個函式的預設引數，不是兩個多載。
⚠️ 刺不刺眼由**第六關**用眼睛判。

三個邊界都釘了測試：留空不得產出 `prev(it, 1)` · **負的格數**（`prev(it,-2)` ＝ 往後兩格，
所以不得取絕對值）· **反向的位置**上格數不得被翻兩次。

## 🔴 缺陷二：一個安靜的錯答

第七支是**合法的 C++**：它自己定義 `int count(const vector<int>&, int)`，
然後在同一支程式裡呼叫 `std::count(v.begin(), v.end(), 3)`。

```
g++   3
我們   2     std::count 退回裸名 → 撞上使用者那顆兩參數的 count
             → 綁前兩個、丟掉第三個 → 回一個型別正確而錯的整數
```

**它不會出聲。**

> **一個「引數對不上就少綁幾個」的呼叫，
> 在遇到同名多載的時候不會報錯——它會回一個錯的答案。**

**修法**（`cpp:func_call/execute.ts`）：**引數比參數多的時候，那不是這一顆函式。**
判準是 C++ 的事實——使用者定義的函式沒有可變引數，所以「給的比宣告的多」
在任何合法的程式裡都不成立。
⚠️ **反方向是合法的**（預設引數），那一段不在這條閘裡，而且有正向錨點釘著。

⚠️ 這個缺陷**只有在撞到同名的標準函式時才露得出來**——單獨的
`f(1,2,3)` 在 g++ 那邊根本編不過，所以判準第一層（「這一段是合法的 C++ 嗎」）
會把它排掉。**是盲測那支【合法的】程式把它逼出來的。**

### 🔴 `distance` 推翻了探索報告的第二個決定

探索報告寫著「不做：語料 0 處，而且有等價寫法 `it - v.begin()`（今天能跑）」
——**而那個等價寫法只在隨機存取的容器上成立**。`set`／`map` 上沒有 `-`，
所以 `distance` 在那些容器上是**唯一的寫法**，而那正是盲測五支用它的地方。
