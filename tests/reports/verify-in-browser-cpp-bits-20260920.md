## ⑧ 英文抓到的那一個——而它正是這支 skill 說會漏掉的形狀

```
zh  建立一排位元 · 整排改值 · 問整排 · 整排換個樣子     四個都是動詞短語
en  Create bit row · Set whole row · Ask the row · Row as
                                                  ^^^^^^ 🔴 半句，不是動詞短語
```

`Row as` 單獨立在流程節點的標題列上時讀不成一句話，而同族的慣例是
`C-string to int`／`C-string to double`。改成 **`Convert bit row`**。

⚠️ **中文那一側四個全對**——只看中文會全綠。
> **一個 fallback 與正解長得一樣的驗收，等於沒有驗收。**

## ② 用問的寫的判定，跟眼睛看到的不一樣（而這次是【更好】）

`blocks-without-name-decisions.json` 記的是「MSG0 是 `%1 %2`，積木上固定的字一個都沒有」。
而畫面上讀到的是：

```
變數 bs  [全部都是 0 ▾]  嗎
```

**「嗎」是一個獨立的固定標籤**（查活的積木：`FieldDropdown「全部都是 0」＋ FieldLabel「嗎」`）。
Blockly 會把三個選項共同的**結尾**抽出來變成一個 label——三個選項都以「嗎」收尾，
於是它自己補了一個句尾字。積木讀起來是一句完整的問句。

⚠️ 英文那一側沒有共同結尾（`has any 1`／`is all 0`／`is all 1`），所以**真的一個固定字都沒有**
——而它仍然讀得成一句述詞。兩邊都過。

> **一個「用問的」量出來的宣告，與畫面上長出來的東西可以不一樣
> ——而這一次差在渲染器替它多做了一件事。**

## ① 兩個常態留空的插槽——判定是「維持原樣」，而理由是前例

```
建立 8 個位元的一排 bs 複製自 ▢      洞在句尾，後面沒有字收尾
把 變數 bs 第 ▢ 格 設為 1 ▾          洞在句中，後面有「格」收尾  🟢 照第 197 刀的尺，過
```

句尾那個確實懸著。**而它與已經出貨的 `container_erase` 是同一個形狀**：

```
從 %1 移除 %2 到 ▢                  cpp:container_erase，今天就長這樣
建立 %1 個位元的一排 %2 複製自 ▢     cpp:bits_declare
```

只改這一顆會在「常態留空的句尾插槽」這一族內部製造不一致，
而**那個不一致本身就是缺陷會被漏掉的原因**（接收者空值那一條的教訓逐字如此）。
🔴 **何時該改**：這一族一起改的那一刀（mutation 或第二個形態），不是單挑一顆。

## 🆕 printf 那條投影——只有切到那個風格才看得見

這一輪開瀏覽器時，工作區的 `currentIoPreference` 停在 `cstdio`（上一次的 localStorage）。
動一下積木，產出的是：

```c
printf("%d %d %d\n", bs, bs.count(), bs.any());
printf("%d %d\n",   t.to_string(), t.to_ulong());
```

`%d` 配 `bitset`、配 `std::string`——**編不過**。

🔴 **而它與一排位元無關**。同一台儀器上換一段只有 string 與 double 的程式：

```
cout << s << d << "\n";   →   printf("%d%d\n", s, d);
```

`cpp:print/generate.ts` 對**每一個非字串字面值**一律寫 `%d`，而
`GeneratorContext` 裡**沒有型別表**（只有 `_structNames`）。整族的限制，不是這一刀的。

🟢 **產品自己會警告**：貼進大量 `cout` 時出橫幅「程式碼大量使用 cout/cin，
但目前風格為 printf/scanf」＋一鍵切換。所以它不是靜默的。

已釘成 `it.fails`（`[UNSUPPORTED:產碼那一側沒有型別表]`），缺陷帳誠實上調 64 → 65。

> **一條投影只在某一種風格下壞掉時，
> 任何不切到那個風格的驗收都會是綠的。**

## ④ 走一趟積木回來——三次真的操作，三次都對

用**真的 UI**（不是合成事件）在畫面上切下拉、拖積木：

```
METHOD 設為 1 → 歸零     程式碼 bs.set(3);  → bs.reset(3);   🟢
METHOD 歸零  → 設為 1    程式碼 bs.reset(3);→ bs.set(3);     🟢
把 POS 那顆 3 拖走        程式碼 bs.set(3);  → bs.set();      🟢 **不是 set(0)**
```

🔴 最後那一條補成了常駐測試（`roundtrip-cpp-bits.test.ts`，67 → **76 支**）：
它渲染 `bs.set(3)`、**把 Blockly 狀態裡的 `POS` 接點刪掉**（使用者拖走那顆積木的樣子）、
再走 extract → 產碼，斷言不得是 `set(0)`。

⚠️ 之前三次**合成**的拖曳都拔不動子積木——那是工具的限制，不是產品的。
真的 `left_click_drag` 一次就成功。
