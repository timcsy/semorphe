## 🔴 修掉的三個

### Bug 1：數字字面的後綴被吃成 `NaN`，而不出聲

```
5            🟢 5          0xFF   🟢 255
5L / 7U / 1.5f / 4294967295UL    🔴 全部 NaN
```

`Number('5L')` 是 `NaN`——一路往下傳成 `NaN 0 / NaN 0 / …` 這種
**看起來像功能壞掉、而其實是一個字面值沒被讀懂**的輸出。

> **一個回 `NaN` 而不出聲的求值，會讓錯誤出現在離根因很遠的地方。**

**修法**：剝掉後綴（⚠️ 十六進位不能剝，`0xFF` 的 `F` 是數字），
而**讀不懂就丟錯**，不回 `NaN`。
**影響範圍遠大於 Arduino**——`5L`／`1.5f` 是一般 C++ 寫法。

### Bug 2：`Serial.print(v, 3)` 的第二個引數被靜默丟掉

輸出是 `-50` 而不是 `-50.000`。

> **一個被靜默丟掉的引數，症狀是「輸出格式不對」，
> 而那看起來像格式化的 bug，不像「我根本沒收到那個參數」。**

**修法**：`format` 接點 ＋ 三路（lift／generate／execute）都接上。
⚠️ `HEX`／`BIN` 那種**進位**沒做——它們是具名常數，而這裡只認得數字。

### Bug 3：`const`／`static` ＋ 陣列宣告，安靜地產出錯樹

```
int t[2] = {7,8};          🟢
const int t[2] = {7,8};    🔴 initializer 整個【不見了】→ 之後 t[1] 是 TYPE_MISMATCH
static int t[2] = {7,8};   🔴 名字變成 `t[2]` → 之後查 t 是 UNDECLARED_VAR
```

⚠️ **而兩者的 lift 殘差都是 0**——辨識層說它看懂了。

> **兩顆宣告概念都把「陣列」這件事吃掉了，而各自吃掉的方式不同
> ——一個丟掉初始值，一個把 `[2]` 當成名字的一部分。**

**本輪只做誠實降級**（P6）：安靜的錯樹 → **看得見的缺口**
（`cpp:raw_code`、殘差可見、訊息指名到那一行）。
🔴 完整支援是另一輪——它要一顆概念帶得動修飾詞，**那是概念代數的問題**。
