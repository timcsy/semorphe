## 🔴 這一輪最重要的讀數：同一個判斷被推翻【四次】

探索報告用「語料 0 處」拒絕了四件事，而盲測四件都用上了：

```
prev(it, n) 的第二個引數     第 197 刀被推翻   盲測 2/10
bs.set(i) 的帶位置形式        這一刀被推翻      多支 ＋ 🔴【安靜的錯答】
to_ulong() / to_string()     這一刀被推翻      4/10
cout << bs                   這一刀被推翻      1/10 ＋ 印出 `[array]`
```

> **「語料 0 處」量到的是【這批語料的人怎麼寫】，
> 不是【這個寫法有多常見】——而它在兩刀內錯了四次。**

### 🔴 而其中一次不只是缺功能

```
bs.set(3)    g++ 印 11（第 3 格是 1、總共 1 個）
             我們印 18（引數被丟掉 ⟹ 整排設成 1、總共 8 個）
```

因為「不做」的那個方法名**已經被登錄到型別分派表**，所以它不會降級，會答錯。

> **一個「不做」的決定，如果那個名字已經被認領，
> 它不會變成誠實降級——它會變成一個錯的答案。**

## 九個當場修掉的缺陷

| # | 缺陷 | 根因 |
|---|---|---|
| ① | `0xDEADBEEFUL` 讀不懂（拋錯） | 「十六進位不剝後綴」那條規則的理由**只對 `f` 成立**，而 `u`／`l` 不是數字 |
| ② | `0xDEADBEEF` 被判成 double，印 `3.73593e+09` | 判準看 `e`／`E`，而**十六進位裡的 `E` 是一個數字** |
| ③ | 🔴 `bs.set(3)` 把**整排**設成 1 | 帶引數的形式沒有落點，引數被丟掉 |
| ④ | `typedef bitset<8> Row; Row r;` 的方法認不出來 | `getType` 對別名回 C++ 基底名（`bitset`），容器宣告那條回身分推導名（`bits`）——**每一顆既有元件的兩個名字剛好相同，所以這個分歧一直看不見** |
| ⑤ | `using X = Y;` 完全沒被記下來 | 它的執行器是一個 **noop** ＋ `skipPaths`，而同族的 `typedef` 早就登記別名 |
| ⑥ | `bitset<K>` 整句掉進 `raw_code` | 裸識別字的樣板引數被包在一層 `type_descriptor`，而 lift 一個型別節點的結果是 `raw_code` |
| ⑦ | `cout << bs` 印出 `[array]` | 一個**內部字串漏到使用者眼前** |
| ⑧ | 三個問句（`any`／`none`／`all`）不存在 | 探索報告拒絕過 |
| ⑨ | 三種換法（`to_ulong`／`to_ullong`／`to_string`）不存在 | 同上 |

⚠️ **①②④⑤⑥⑦ 六個與 `bitset` 無關**——它們是被這一族「照出來」的。

> **一個一直成立的巧合（④），在第一個反例出現時看起來會像是那個反例的錯。**

## 🟠 五根釘子（每一根都寫了「為什麼不是現在」＋「何時該修」）

| 釘子 | 為什麼不是現在 |
|---|---|
| `bits_test`（`bs.test(i)`） | `bs[i]` 是**完全等價**的寫法而且今天就能跑；多一顆積木做同一件事是認知負載 |
| `bits_construct`（`bitset<8>(0xF0)`／`("1010")`） | 「內建型別的建構」整條路，**與第 197 刀那根 `string_construct` 同族**——兩根一起拔 |
| `bits_scan`（`__builtin_ctz`／`clz`／`parity`） | 三顆語義各不同，一起做才不會留下「同一族做了一半」 |
| 別名型別的大小是識別字 | `defaultValue` 從**型別字串**解析大小而沒有 scope；⚠️ 直接宣告是好的（大小是接點）——**兩條路徑對同一件事有兩個答案** |
| 運算式接收者（`mk().count()`） | 與 `d[i].reset()` 是**同一根釘子的第二個形狀** |
