# Round-Trip 測試結果：C++ — 迭代器一族

- 日期：2026-09-17
- 目標：`begin`／`end`／`rbegin`／`rend`／`find`／`lower_bound`／`upper_bound`／
  `erase(位置)`／`*it`／`++it`／`it->`
- 語料：使用者學生的 218 支競賽練習，其中 **28 支**用到這一族

## 真語料（那 28 支）

| 面向 | 結果 |
|---|---|
| ① 那幾個方法不得變成別的東西 | **28/28** |
| ② 語義不動點 | **28/28** |
| ③ `auto it = …` 掉進 raw code | **0 支**（修之前是每一支） |

## 🔴 而 ①②③ 在修之前【也會是綠的】

`auto it = v.begin()` 掉進 raw code 之後，那一段的**文字原樣保留**
——產碼吐得回去、不動點也穩。

> **分得出來的只有兩樣：語義樹裡的身分，與跑出來的東西。**

這是這個工作階段第三次遇到同一件事（容器種類、重複性、迭代器），
而它每一次都讓「形狀的面向」給出一個漂亮而無意義的數字。

## ④ 行為：語料重量的第七、八輪

```
             六輪   七輪   八輪
兩邊都跑完   128 → 132 → 133
🟢 一致      114 → 118 → 120
🔴 內容不同   10 →  10 →   9    ← 🔴 這一欄第一次動
解譯器出錯    46 →  42 →  41
```

⚠️ **第七輪只降 4，而這一族原本估 16**——因為修好之後那些程式**往後走**，
撞到別的東西（`begin(array)` 的自由函式形式、`prev`、巢狀接收者）。
探索報告警告過的那句話應驗了一半：

> 一個概念如果它的產出沒有人接得住，補上它不會讓任何一支程式跑起來
> ——它只會讓失敗的位置往後移。

🟢 而**六族「X（不是一個物件）」全部消失**（`st` 4 支、`ms`／`l`／`s`／`bs`／`ABC` 各 1）。

## 🔴 第七輪暴露出三個【疊在同一支語料上】的新缺陷

它們在這一族能跑之前**看不見**，因為程式在更早的地方就停了。全部來自 `AP325/4/4_15.cpp`：

```cpp
#define x first
multiset<pair<int,int>> st;
auto it = st.lower_bound({p[i].y - d, (int)-2e9});
while (it != st.end() && it->x <= p[i].y + d) { … }
```

| # | 缺陷 | 症狀 |
|---|---|---|
| ① | **集合不記元素型別** | `st.insert({a,b})` 把一對值存成陣列 ⟹ `it->first` 說「不是一個結構」 |
| ② | **比較規則不認一對值** | 它們的字面是 `[object Map]` ⟹ 每一對都「相等」⟹ **有序容器根本沒有排序** |
| ③ | **查找把每一格拆開只比第一個** | 那個判準是為對照表寫的（條目是鍵值對） |

🔴 **① 的形狀**：同族那顆在末端加入的元件早就走 `evalInitializer`（帶著元素型別），
而插入那顆走裸的求值。**同一族的兩顆，一顆知道另一顆不知道。**

🔴 **② 的形狀**：

> **一條「其餘比字面」的退路，在遇到一個沒有字面的型別時不會報錯
> ——它會讓每一次比較都回 0，而那看起來像「本來就同序」。**

🔴 **③ 的形狀**：

> **一個「看起來像什麼就當成什麼」的判準，
> 會在「裝的東西剛好長那樣」的容器上答錯——而那正是語料在寫的東西。**

🟢 修法：比較規則收斂成**一處**（`compareValues`，排序與查找共用）
——否則「放進去的順序」與「找出來的位置」會對不上。
而「要不要拆開比」的判準改成問容器自己（`keyed`），不是看那一格長什麼樣。
