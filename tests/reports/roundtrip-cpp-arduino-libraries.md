## 🔴 為什麼回歸那一節比正向那一節重要

這一批改了兩個**共用**的東西：

```
① container_iter 的判準   → 影響【每一個】 .begin()
② 環境常數表 ＋11 個名字   → 影響【每一個】查不到宣告的識別字
```

⚠️ 而它們的失敗形狀都是**安靜地不一樣**：`str.begin()` 變成別的東西不會報錯，
只是積木長得不一樣；`DHT11` 被搶走不會報錯，只是印出來的數字不對。

> **一個改動如果它的失敗形狀是「安靜地不一樣」，
> 那麼保護它的測試必須先於它存在。**

🔴 **A-2 是那個判準的關鍵測試**：第一版用「這個型別有沒有主」來擋，
而 `string` 有主 → `str.begin()` 會被弄壞。改成問**擁有者**（硬體宣告
`owner: '(arduino)'`）才對。

## 🔴 發現並修好一個真的 bug：最令人困惑的解析

```cpp
#define DHTPIN 2
DHT dht(DHTPIN, DHT11);     ← tree-sitter 解析成【函式宣告】
DHT dht(2, DHT11);          ← 引數是字面量時才解析成變數定義
```

⚠️ **真編譯器沒有這個問題**：前置處理器先把 `DHTPIN` 換成 `2`。
而 tree-sitter **不做前置處理**。

> **一個解析器如果少了一個階段，它會在那個階段本來會消掉的地方看到歧義。**

而那是 **DHT 教學最典型的寫法**——不修的話那一族程式全部認不出來。
🟢 修法是「型別是一個登錄過的具體型別 → 那不會是函式的回傳型別」。

## 一個刻意不認的：`#define DHTPIN 2` 不變成接線積木

它沒有被當腳位用（沒進 `pinMode`／`digitalWrite`…），它進的是 **DHT 的建構參數**。
而那根腳位**已經寫在**「宣告溫濕度感測器」那顆積木上了。

> **一個資訊已經在別的積木上時，再認一次不是更完整，是更吵。**
