# 瀏覽器驗收：`cpp:pointer_step`（管線 197・階段六）

2026-09-19｜分支 `197-cpp-iter-step`｜**前五關全綠、而還沒有人用眼睛看過**

## 一句話

> **這一關抓到的東西，五關 7568 支測試一支都沒看到——因為它印在 tooltip 上。**

## 🔴 抓到的：積木上的字留著沒人渲染的 markdown

滑鼠停在新積木上：

```
給出移動之後的那個位置，而**原本那個位置不動**。「幾格」留空時就是一格。
                        ↑↑              ↑↑
```

**Blockly 的 tooltip 是純文字**，它不渲染 markdown——`**` 原樣印給學生看。

而量了之後才知道不是一顆的問題：**349 句 tooltip 裡有 10 句**含 `**`，
其中多數是同一批新元件留下的（I/O 操縱子 3 顆 · 範圍那一族 2 顆 ·
位置那一族 2 顆 · 優先佇列 · 文件註解 · Python 的取子字串）。

> **一個在膠囊註解裡正確的寫法，搬到隔壁那個標籤檔就變成使用者看得到的雜訊
> ——而兩邊都是同一個人寫的，所以沒有人會在寫的時候發現。**

🟢 **處置**：11 個檔的 10 句全部清掉，**並蓋第一百二十三條護欄**
（`audit-label-markdown`，硬性零 ＋ 兩條注入自證）。
⚠️ 理由是 `CLAUDE.md` 逐字的「**補一個實例不會讓下一個不發生**」。
⚠️ 判準**只認 `**`**：單星號是乘號、底線在識別字裡到處都是
——一條認得太多的護欄會逼人改沒問題的那些，而那種護欄會被改成讓它閉嘴的樣子。

## ① 那個常態留空的插槽——**這一關是送來判它的，而判決是：留著**

```
中文   [變數 it ▾] 往 [後 ▾] 移 (▢) 格 指向的值 (*)
英文   [it] moved [forward] by (▢)
```

探索階段**明文決定不做**第二個引數，理由是「同族的『移除』那顆做了一個常態留空的
插槽，而瀏覽器驗收時它刺眼」。而階段四的盲測十支裡兩支用了 `prev(it, 2)`，決定被翻面。

**用眼睛看的結論**：

| | 空著的時候讀起來 |
|---|---|
| `cpp_container_erase`（已出貨） | `從 [s] 移除 (…) 到 (▢)` ← **洞懸在句尾**，像沒寫完 |
| `cpp_pointer_step`（新） | `[it] 往 [後] 移 (▢) 格` ← **「格」把句子收尾了** |

🟢 中文那一側**比已出貨的前例好讀**。
⚠️ 而**英文那一側沒有那個優勢**：`moved back by (▢)` 的洞在句尾，與 `container_erase` 同形。
🟢 tooltip 補得上（「『幾格』留空時就是一格」／「Leaving the count empty means one step」），
而**那句話確認過在畫面上看得到**（滑鼠停上去就出來）。

**判決：不改成 mutation。** 一致性站得住，而 tooltip 說得清楚。

## ② 拿得到嗎——🟢 而它差點被一個假讀數騙過去

第一次量到「工具箱裡沒有它」。**而正向錨點救了這個讀數**：同族的
`container_iter`／`container_erase`／`pointer_deref` **三顆也都不在**
——那是當時停在「01-預備」那一課，工具箱 ＝ 那一課的清單。

> **一個「東西不見了」的讀數，要先排除「你根本沒開它」。**

切到自由練習之後：**228 顆積木 · 12 個分類**，而 `cpp_pointer_step` 出現在
**函式 · 陣列與列表 · 對應與集合 · 堆疊與佇列** 四格
——**與同族的 `cpp_container_iter` 一模一樣的四格**。

🟠 **而它落在「函式」那一格，是一個既有的開放問題**（`(core)` ＋ containers
那批 16 顆都在那裡），不是這一刀造成的。

⚠️ **沒有任何一課的清單裡有它**（`grep pointer_step lessons/` ＝ 0）。
那**不是缺陷**：自由練習拿得到，而把它加進某一課需要那一課的程式碼真的用到它
（e2e 有一條在比對「宣告的元件 ＝ 程式碼真的用到的元件」）。**那是編輯決定，不是這一刀。**

## ④ 走一趟積木回來——**真的用 UI 操作**，三格全對

⚠️ **程式化 `setFieldValue` 不觸發同步**（坑⑤，當場撞到：積木變了而程式碼沒變）。
所以下面全部是真的點下拉、真的拖曳：

```
切下拉到「後」        → *next(it, 2)      🟢 方向跟上了
把「2」拖出插槽        → *next(it)        🟢 【不是 next(it, 1)】
另一顆保持填 2        → *next(it, 2)      🟢
其餘三顆保持留空       → prev(...)        🟢
```

🔴 那第二條是這一刀最難發現的一種：產出 `next(it, 1)` 也**完全合法、跑起來也一樣**
——只是那不是使用者寫的那一行。

## ⑤⑥ 貼一段真程式，跑一次

```cpp
set<int> s = {4, 8, 15, 16, 23, 42};
cout << *prev(s.end()) << "\n";
auto it = s.find(16);
cout << *prev(it, 2) << " " << *next(it, 2) << "\n";
vector<int> v{3,1,4,1,5};
sort(v.begin(), prev(v.end()));
for (int x : v) cout << x;  cout << "\n";
s.erase(prev(s.end()));  cout << s.size();
```

```
瀏覽器   42 / 8 42 / 11345 / 5
g++      42 / 8 42 / 11345 / 5      ← 一模一樣
```

五顆 `cpp_pointer_step` 全部認對（3 顆留空、2 顆填 2、1 顆 `next`），**降級 0 顆**。

⚠️ **而我在給這一關的輸入裡把預期輸出寫成 `13145` 並註明「已驗」——那句話不實**，
我沒有跑過。`sort(v.begin(), prev(v.end()))` 只排前四格，`5` 留在原地 ⟹ `11345`。
> **一份「這是量出來的」的宣稱，本身也要是量出來的。**

⚠️ 另外踩到坑③：第一次貼的時候 `document.execCommand('selectAll')` 沒生效，
畫面上出現**兩個 `main`**。那是量測錯誤，不是產品缺陷——換成真的 `cmd+a` 就對了。

## ⑦ 流程視圖 — 中英各看一次

```
zh   取移動後的位置   位置 / 幾格
en   Moved position   Position / Count
```

🟢 兩邊**不同**（所以不是 fallback 與正解重合的那種假驗收）。
⚠️ 而「取相鄰位置」這個舊標題是這一刀改掉的——**能跳 N 格之後「相鄰」就過期了**。
`FLOW_SLOT_COUNT` 也是這一刀補的（新接點原本沒有詞）。

🟠 **既有、不是這一刀**：`container_iter` 的流程標題是「取迭代位置」／`Iterator`
——而「迭代器」那三個字在積木標籤上是禁止的。流程視圖是另一個表面，
且那顆不是這一刀動的，記在這裡不改。
